# **@ModelAttribute vs model.addAttribute**

## **1) 의미 차이 (핵심)**

두 가지는 하는 일은 비슷해 보이지만, **누가 언제** 데이터를 `Model`에 담는지 그 주체와 시점이 다릅니다.

- **`@ModelAttribute("form") BookForm form`**: **스프링이** 메서드를 실행하기 **전에** 자동으로 `Model`에 담아줍니다.
- **`model.addAttribute("form", form);`**: **개발자가** 메서드 안에서 **직접** `Model`에 담습니다.

쉽게 말해 `@ModelAttribute`는 **자동**이고, `model.addAttribute`는 **수동**입니다.

## **2) 이름(default) 규칙**

- @ModelAttribute에 이름을 안 주면 **클래스명 카멜케이스**가 기본 이름이에요.
    - 예) @ModelAttribute BookForm form → 모델 키는 "bookForm"
- Thymeleaf에서 \<form th:object="${form}">를 쓰면,
    - 파라미터를 @ModelAttribute("form")로 받거나,
    - 혹은 model.addAttribute("form", form)로 이름을 **맞춰**줘야 합니다.
- 이름이 안 맞으면 흔한 오류:
    - Neither BindingResult nor plain target object for bean name 'form' available as request attribute

## **3) 언제 무엇을 쓰나**

- **GET(폼 진입)**

```java
@GetMapping("/books/new")
public String createForm(Model model) {
    model.addAttribute("form", new BookForm()); // 빈 폼을 뷰에 보냄
    return "books/createForm";
}
```
    
- **POST(폼 제출)**

```java
@PostMapping("/books/new")
public String create(@Valid @ModelAttribute("form") BookForm form,
                     BindingResult binding) {
    if (binding.hasErrors()) return "books/createForm"; // 이미 model에 "form"으로 들어있음
    // 성공 로직...
    return "redirect:/books";
}
```

- 여기서 **다시 model.addAttribute 할 필요 없음** (이미 들어가 있음).
    - BindingResult는 **반드시 바로 뒤**에 둬야 합니다.

# **같이 헷갈리는 것들 한 번에 구분**

|**구분**|**데이터 출처/형식**|**바인딩**|**모델 추가**|**주용도**|
|---|---|---|---|---|
|@ModelAttribute (파라미터)|폼 필드/쿼리파라미터 (urlencoded, multipart)|✅|✅(자동)|서버 템플릿 기반 폼 처리|
|model.addAttribute|서버에서 만든 객체|❌|✅|GET 화면 진입 시 빈 폼, 화면에 추가 데이터 싣기|
|@RequestParam|단일 값(문자, 숫자 등)|✅ (단일 타입)|❌|쿼리 파라미터 한두 개 받기|
|**(기본 동작)** BookForm form (애노테이션 없이, 복합타입)|폼/쿼리파라미터|✅ (@ModelAttribute와 동일)|✅(기본 이름: bookForm)|편의 문법|
|@RequestBody|**JSON/XML** 요청 본문|✅(HTTP 메시지 컨버터)|❌|REST API 바디 바인딩|
|RedirectAttributes (addFlashAttribute)|서버가 만든 임시 값|❌|리다이렉트 후 1회 노출|PRG 패턴에서 성공/실패 메시지 전달|
|@SessionAttributes / @SessionAttribute|세션 저장/조회|-|세션|다단계 폼(위저드) 등|

> 기억하기: **폼 제출(서버 템플릿)** → @ModelAttribute

> **JSON API** → @RequestBody

> **GET 화면 진입** → model.addAttribute로 폼 백잉 객체 실어 보내기

## **자주 나는 실수 체크리스트**

- BindingResult를 **검증 대상 바로 뒤**에 두었나?

    (@Valid @ModelAttribute BookForm form, BindingResult result)

- 뷰의 th:object="${form}"와 **모델 키 이름**이 일치하나?
- POST에서 @ModelAttribute로 받았는데 **또 addAttribute를 중복**으로 넣고 있지 않나?
- JSON 요청인데 @ModelAttribute로 받으려 해 400이 나지 않나? → **@RequestBody**로 전환
- 리다이렉트 시 모델 값이 사라져 당황? → RedirectAttributes.addFlashAttribute 사용

#### ### 1. `@ModelAttribute("form") BookForm form` (자동 세팅)

이 코드는 컨트롤러 메서드의 파라미터에 사용되며, 스프링에게 두 가지 일을 동시에 시킵니다.

1. **"`BookForm` 객체를 하나 만들어줘."**
2. **"그리고 그 객체를 `Model`에 'form'이라는 이름으로 자동으로 담아줘."** (`model.addAttribute("form", new BookForm())` 코드를 대신 실행해 줌)

주로 **폼(Form) 데이터를 서버로 제출(`POST`) 받을 때** 사용됩니다. HTML 폼의 데이터가 `BookForm` 객체에 자동으로 채워지고(데이터 바인딩), 이 객체가 다시 화면으로 넘어갈 때 `Model`에 담겨서 사용됩니다 (예: 입력 값 검증 실패 시, 입력했던 내용을 그대로 보여주기 위해).

#### ### 2. `model.addAttribute("form", form);` (수동 세팅)

이 코드는 개발자가 **명시적으로** `Model`에 데이터를 담을 때 사용합니다.

주로 **뷰에 보여줄 데이터를 DB에서 조회해서 전달할 때**처럼, 개발자가 직접 생성하거나 조회한 데이터를 `Model`에 담아야 하는 경우에 씁니다. 지난번 `updateItemForm` 예제처럼 DB에서 조회한 `item`의 내용으로 `form` 객체를 채운 뒤, 이 `form`을 뷰로 전달할 때 사용했습니다.

> **결론:** `@PostMapping`처럼 **화면에서 넘어온 데이터를 받을 때는** 파라미터에 `@ModelAttribute`를 쓰고, `@GetMapping`처럼 **화면에 보여줄 데이터를 만들어서 넘겨줄 때는** 메서드 안에서 `model.addAttribute`를 쓴다고 생각하면 이해하기 쉽습니다.

### ## 이와 같이 헷갈릴 수 있는 다른 개념 쌍

#### ### 1. `@Controller` vs. `@RestController`

|구분|`@Controller`|`@RestController`|
|---|---|---|
|**역할**|**뷰(View)를 반환** (HTML 페이지)|**데이터(Data)를 반환** (JSON, XML)|
|**반환값**|`String` (뷰 템플릿 이름)|객체, 리스트 (데이터 그 자체)|
|**비유**|레스토랑 셰프 (완성된 요리 제공)|정육점 주인 (날것의 재료 제공)|

#### ### 2. `@RequestParam` vs. `@PathVariable`

|구분|`@RequestParam`|`@PathVariable`|
|---|---|---|
|**역할**|**쿼리 파라미터** 값을 가져옴|**경로 변수(Path Variable)** 값을 가져옴|
|**URL 예시**|`/items**?name=apple&page=1**`|`/items**/{itemId}**` (예: `/items/100`)|
|**용도**|정렬, 페이징, 검색 등 **부가적인 조건**|리소스(데이터)를 **직접 식별**하는 값|

#### ### 3. JPA `find()` vs. `createQuery()`

|구분|`find()`|`createQuery()`|
|---|---|---|
|**역할**|**PK로 단 건** 조회|**JPQL로 조건** 검색 (주로 여러 건)|
|**조회 순서**|**1차 캐시 → DB**|**DB → 1차 캐시**|
|**비유**|도서 번호로 책 찾기|"컴퓨터" 키워드로 책 검색하기|
