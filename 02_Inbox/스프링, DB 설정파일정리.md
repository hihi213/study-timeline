## 📝 정리
> 여기에 나의 언어로 재작성
- **`build.gradle` (프로젝트 빌드설정)**
    
    Spring Boot 프로젝트를 구축하는 데 필요한 외부 라이브러리(JPA, PostgreSQL 드라이버 등) 목록과 프로그램 빌드 방식을 관리하는 파일입니다. 여기에 필요한 의존성(부품)을 적어두면, 빌드 도구인 Gradle이 알아서 인터넷에서 다운로드하고 프로젝트에 연결해 줍니다.
    
      
    
- **`application.properties` (Spring Boot 내부설정)**
    
    우리가 작성한 Spring Boot 프로그램이 실제로 동작할 때 필요한 내부 환경을 설정하는 파일입니다. "어떤 주소의 DB에 연결할지(URL)", "접속 아이디와 비밀번호는 무엇인지", "서버 포트 번호는 몇 번을 쓸지" 등 애플리케이션 구동에 필요한 핵심 옵션값들을 지정합니다.
    
      
    
- **`compose.yaml` (도커 설정)**
    
    방금 전 학습하신 도커(Docker) 시스템을 제어하는 설정 파일입니다. 다운받을 DB 이미지의 종류, 포트 연결(Port Mapping) 정보, 데이터를 저장할 볼륨(Volume) 설정 등을 이 파일에 명시해 둡니다. 매번 복잡한 도커 명령어를 터미널에 칠 필요 없이, 이 설계도 하나만 실행하면 필요한 DB 컨테이너 환경이 한 번에 구축됩니다.
    
      
    

요약하자면 `build.gradle`은 **스프링 부트를 조립할 부품 목록**, `application.properties`는 **완성된 스프링 부트의 설정 리모컨**, `compose.yaml`은 **스프링 부트가 사용할 외부 DB 방을 만들어주는 도커 건축 도면**입니다.


## 확장자가 다른이유

개발 도구마다 '만든 사람(주체)'과 '가장 중요하게 생각하는 목적'이 다르기 때문입니다.

  

직업마다 최적화된 문서 양식이 다른 것(회계사는 엑셀, 소설가는 워드, 건축가는 캐드)과 완전히 같은 이치입니다. 각 파일 확장자가 왜 그 형태를 선택했는지 살펴보면 다음과 같습니다.

  

- **`.gradle` (동적인 프로그래밍 목적)**
    - 빌드 도구인 Gradle 전용 확장자입니다.
    - 단순히 글자만 적는 게 아니라, 조건문(if)이나 반복문(for) 같은 **코드가 실행되어야 할 때**가 많습니다. 그래서 설정 파일임에도 프로그래밍 언어(Groovy나 Kotlin)의 문법을 사용할 수 있도록 특수하게 만들어진 양식입니다.
- **`.properties` (단순하고 직관적인 `키=값` 구조)**
    - Java 생태계에서 수십 년간 써온 전통적인 설정 파일 양식입니다.
    - `spring.datasource.url=주소` 처럼 **가장 단순하고 직관적인 1:1 매칭 구조**를 가지고 있어, 복잡한 로직 없이 값만 뚝딱 읽어오기 위해 사용합니다. (참고로 요즘은 Spring Boot에서도 계층 구조가 보기 편한 `application.yml`을 많이 쓰는 추세입니다.)
- **`.yaml` (인프라 구조를 그리기 좋은 계층 형태)**
    - Docker를 포함한 최근의 인프라/클라우드 생태계(DevOps)에서 표준처럼 쓰이는 양식입니다.
    - 서버, DB, 네트워크 등 여러 대의 컴퓨터 구성을 표현해야 하므로, 들여쓰기(띄어쓰기)를 이용해 **복잡한 포함 관계와 계층 구조를 시각적으로 한눈에 알아보기 쉽게** 설계되었습니다.
        
          
        

요약하자면, 각 도구가 태어난 시기와 목적에 맞춰 가장 효율적인 문서 양식을 채택하다 보니 여러 확장자가 공존하게 된 것입니다.
