## 정리
- 객체의 참조와 DB의 FK는 독립적이다. 객체의 참조 방향은 개발자의 선택이다
- JPA의 “양방향”은 **한 개 FK를 양쪽 엔티티에서 탐색 가능하게 만든 편의**라고 이해하면 된다.
- JPA와 상관없이 DB에서는 A와 B가 서로를 가리키는 양방향참조가 없다(중복생겨서 걍 없다고 생각하자)
	- DB가 갖는 건 **한쪽에서 다른 쪽 PK를 가리키는 외래키(FK)** 뿐이고, “반대 방향”은 **스키마 개념이 아니라 쿼리 조회(JOIN) 개념**이야.
- 객체: 객체간의 참조로 관계를 표시, 즉 참조(필드)로 연결
	- 1: N:
		- 객체1: list로 N의 객체타입을 여러개 담는다 :1 → N 탐색용 뷰
		- 객체N: 1 타입의 참조변수를 선언: N → 1 실제 연결(주인)
	- 1: 1: :
		- 양뱡향인경우: 서로 타입의 참조변수를 선언
		- 단방향인경우: 한쪽만 참조변수를 선언
			- (어느 쪽을 주인으로 둘지에 따라 FK 위치가 달라짐
	- N: N: :
		- 양쪽이 서로를 컬렉션(set/list)으로 가짐
			- [자세한설명-다대다매핑구현(JoinTable)](다대다매핑구현(JoinTable).md)
		- 근데 실무에서는 연결 엔티티를 추가로 만들어서 N:1, 1:N으로 분해함(왜냐면 두엔티티의 관계에 관한 필드추가하기 위해서)
- DB: FK(외래키)/제약을 이용해 데이터를 연결
	- 1: N: : N테이블에 1의 pk를 참조하는 FK컬럼을 둠
	- 1: 1:  
		- 일반적: 한쪽테이블에 FK+한행만 가리키도록 강제하는 UNIQUE제약 추가
		- 제약더 강화: 부모가 FK를 PK로 사용
	- N: N:
		- 조인 테이블 필요: 중간테이블없이 표현 불가함
## **보너스: JPA 매핑 짚고 가기**
- **JPA/Hibernate는, 연관관계를 DB에 반영할 때, 주인쪽을 변경한다.
    - 1:N 기본 패턴: @ManyToOne(N측, 주인) + @OneToMany(mappedBy=...)(1측, 거울)
    - 1:1: **FK 가진 쪽**에 @JoinColumn(주인), 반대편은 mappedBy
    - N:N: 학습용 @ManyToMany @JoinTable, 실무는 **연결 엔티티**로 분해
- **객체 단방향 1:1**이라도 @JoinColumn을 둔 쪽이 **FK 주인**이 됩니다(그 테이블에 FK가 생김).
    반대로 **공유 PK**를 쓰려면 자식쪽에 @MapsId를 사용.
