# SQL
## 1. DISTINCT (중복 제거) 행 수 계산

- **`SELECT DEPT FROM EMP;`**
    - **원리**: 조건에 맞는 모든 행의 `DEPT`(부서) 값을 그대로 가져옵니다.
    - **결과 행 수**: 원래 테이블의 **전체 데이터 행 수**와 같습니다.
- **`SELECT DISTINCT DEPT FROM EMP;`**
    - **원리**: 가져온 결과에서 **중복된 값들을 딱 1개만 남기고 전부 압축 제거**합니다.
    - **주의할 점**: 만약 부서 컬럼에 `NULL`이 존재한다면, `NULL`도 하나의 종류로 취급되어 **`NULL` 데이터 1행이 결과에 포함**됩니다.
        

## 2. 집계 함수와 NULL 처리 원리 (초특급 단골 함정)

> ⚠️ **핵심 공식**: `NULL`은 **없는 값**이므로 조건 비교나 일반 집계 연산에서 무조건 **제외(무시)**됩니다.

- **`COUNT(*)`**
    - **원리**: 테이블의 **행(Row)의 개수 자체**를 세는 함수입니다.
    - **특징**: 특정 컬럼의 값이 `NULL`이든 아니든 상관없이, 존재하기만 하면 **무조건 카운트에 포함**합니다.
- **`COUNT(COLUMN)`**
    - **원리**: 지정된 컬럼에 **실제 데이터가 채워져 있는 행의 개수**만 셉니다.
    - **특징**: 해당 컬럼의 값이 **`NULL`인 행은 카운트에서 제외**합니다.
- **`SUM(COLUMN)`, `AVG(COLUMN)`**
    - **`SUM`**: `NULL`을 0 취급하는 것이 아니라, 연산 대상에서 아예 뺀 뒤 합산합니다.
    - **`AVG`**: **가장 많은 오답이 나오는 구간**입니다. 전체 행 수가 5개이고 `NULL`이 2개, 숫자가 3개(10, 20, 30)라면 `AVG`는 $60 \div 5 = 12$가 아니라, `NULL` 행 2개를 완전히 제외한 $60 \div 3 = 20$이 됩니다. (분모가 데이터가 있는 행 수로 바뀜)
        

## 3. WHERE, GROUP BY, HAVING 조건 적용 순서

쿼리가 실행되는 내부 메커니즘 순서를 알아야 연산 결과 데이터가 누락되지 않습니다.

> **실행 순서**: `FROM` $\rightarrow$ `WHERE` (개별 필터링) $\rightarrow$ `GROUP BY` (그룹화) $\rightarrow$ `HAVING` (그룹 필터링) $\rightarrow$ `SELECT` $\rightarrow$ `ORDER BY`

- **WHERE 적용 전후**:
    - `WHERE`절은 `GROUP BY`로 묶이기 **전**에 실행됩니다. 즉, 개별 행들을 먼저 쳐내서 걸러낸 다음, 남은 데이터들만 가지고 그룹을 만듭니다.
- **HAVING**:
    - `GROUP BY`에 의해 묶인 **그룹 전체 통계 결과(SUM, AVG 등)에 조건을 걸 때** 사용합니다. `WHERE`절에는 집계 함수를 쓸 수 없으므로 반드시 `HAVING`에 써야 합니다.
        

## 4. 비교 및 필터링 연산자 핵심

- **`LIKE`**: 문자열 패턴 매칭
    - `%` (모든 문자 대용), `_` (딱 한 글자 대용) 기호의 위치와 개수를 파악해 필터링합니다.
- **`IN (A, B, C)`**: 리스트 매칭
    - 괄호 안의 값 `A` 또는 `B` 또는 `C` 중 **하나라도 일치하면** 참이 됩니다 (`OR` 연산과 동일).
- **`BETWEEN A AND B`**: 범위 매칭
    - **`A` 이상 `B` 이하**의 범위를 가져옵니다. 이때 시작값 `A`와 끝값 `B`가 반드시 결과에 포함(포함 관계)된다는 점을 잊지 마세요.
- **`IS NULL` / `IS NOT NULL`**:
    - 데이터베이스에서 `NULL`은 `= NULL`로 비교할 수 없습니다. 반드시 `IS NULL`이라는 전용 연산자로만 걸러낼 수 있습니다.
        

## 5. 조인(JOIN)에 따른 행 수 변화 (계산 문제 최다 출제)

두 테이블을 병합할 때 데이터 구조 매칭에 따라 행이 늘어나거나 사라지는 규칙입니다.

- **내부 조인 (INNER JOIN)**
    - **규칙**: 조인 조건(예: `A.ID = B.ID`)이 **양쪽 테이블 모두에 매칭되는 행만** 결과로 살아남습니다.
    - **행의 감소**: 한쪽에만 존재하고 반대쪽에 매칭되는 ID가 없는 데이터는 결과창에서 **완전히 삭제**되어 행 수가 줄어듭니다.
- **외부 조인 (LEFT / RIGHT OUTER JOIN)**
    - **규칙**: 방향이 지정된 원본 테이블(예: `LEFT`이면 왼쪽 테이블)의 데이터는 **매칭 여부와 상관없이 무조건 100% 살려둡니다.**
    - **NULL의 생성**: 만약 오른쪽 테이블에 매칭되는 짝꿍 데이터가 없다면, 그 칸들을 전부 `NULL`로 채워서 출력 테이블에 유지합니다. (행 수가 원본 이하로 줄어들지 않음)
- **조인으로 인해 행이 증가하는 경우 (다대다 1:N 매칭)**
    - 회원 테이블의 `ID` 1개에 대해, 구매 테이블에 해당 `ID`로 구매한 내역이 3건 존재한다면 조인 결과 화면에는 이 회원의 정보가 **3줄로 복사되어(행 증가)** 출력됩니다.
        

## 6. 서브쿼리 (Subquery) 결합 풀이법

- 괄호 안에 들어있는 **인라인 서브쿼리를 먼저 실행**해서 결과 데이터(단일값 또는 리스트)를 구합니다.
- 구한 결과값을 바깥쪽 메인 쿼리에 상수나 리스트 형태로 그대로 대입한 뒤, 최종 메인 쿼리를 수행하여 행 수를 세면 출제자의 함정을 완벽히 피할 수 있습니다.
    

**💡 시험장 실전 팁:**

SQL 결과 행 수 계산 문제를 만나면, 시험지 여백에 테이블의 데이터 상태를 간략하게 동그라미나 기호로 직접 매칭(선 긋기)해가며 푸세요. 특히 `COUNT`나 `AVG` 연산 시 **`NULL`이 적힌 행 위에 엑스(`X`)표를 쳐서** 카운트 분모에서 기계적으로 제외하는 연습을 해두시면 오답률을 0%로 만들 수 있습니다!

## 1. DDL (데이터 정의어) - CREATE / ALTER TABLE

### 1) CREATE TABLE 구조와 기본키·외래키 선언

가장 출제 빈도가 높으며, 문법이 조금이라도 틀리면 오답 처리되므로 아래 형식을 통째로 기억해야 합니다.


```sql
CREATE TABLE 자식테이블 (
    ID INT NOT NULL,
    NAME VARCHAR(20),
    PARENT_ID INT,
    CONSTRAINT PK_자식 PRIMARY KEY (ID),
    CONSTRAINT FK_자식_부모 FOREIGN KEY (PARENT_ID) REFERENCES 부모테이블(부모ID)
);
```

- **암기 필수 (외래키 제약조건 세트 지정 구조)**:

```sql
    CONSTRAINT 제약조건명 FOREIGN KEY (자식컬럼) REFERENCES 부모테이블(부모컬럼)
```
- 컬럼 선언문 맨 뒤에 쉼표(`,`)를 누락하거나, `REFERENCES`의 스펠링을 틀리는 감정 요소를 주의하세요.
- 옵션 지정: 부모 테이블의 데이터 삭제/수정 시 연쇄 반응을 일으키는 `ON DELETE CASCADE` 또는 `ON UPDATE SET NULL` 문구도 꼬리표처럼 붙어 나올 수 있습니다.
	

### 2) ALTER TABLE (테이블 구조 변경)

- **컬럼 추가**: `ALTER TABLE 테이블명 ADD 컬럼명 데이터타입;`
- **컬럼 변경(수정)**: `ALTER TABLE 테이블명 MODIFY 컬럼명 데이터타입;` (또는 DBMS에 따라 ALTER COLUMN)
- **컬럼 삭제**: `ALTER TABLE 테이블명 DROP COLUMN 컬럼명;`
    

## 2. DML (데이터 조작어) - INSERT, UPDATE, DELETE

데이터를 가공할 때 명령어별로 맵핑되는 고유의 매개 키워드(`INTO`, `SET`, `FROM`)를 혼동하지 않는 것이 중요합니다.

- **INSERT (데이터 삽입)**
    - 문법: `INSERT INTO 테이블명(컬럼1, 컬럼2) VALUES (값1, 값2);`
    - 주의: 컬럼 선언을 생략하면 테이블 구조 순서대로 모든 값을 명시해야 합니다. 문자에 홑따옴표(`'값'`)를 누락하지 마세요.
- **UPDATE (데이터 수정)**
    - 문법: `UPDATE 테이블명 SET 컬럼명 = 바꿀값 WHERE 조건식;`
    - 주의: **`SET`** 키워드가 반드시 와야 합니다. `WHERE`절을 누락하면 테이블의 전체 행이 모두 변경되는 대참사가 일어나므로 조건의 범위를 확실히 확인하세요.
- **DELETE (데이터 삭제)**
    - 문법: `DELETE FROM 테이블명 WHERE 조건식;`
    - 주의: **`FROM`** 키워드가 반드시 들어갑니다. (`DELETE * FROM …` 처럼 별표를 넣으면 오답 처리됩니다.)
        

## 3. DCL (데이터 제어어) - GRANT, REVOKE

권한을 주거나 뺏는 명령어로, 대상 전치사(`TO`, `FROM`)가 목적에 맞게 매칭되는지 구별해야 합니다.

- **GRANT (권한 부여)**
    - 문법: `GRANT 권한 ON 대상 TO 사용자;`
    - 예시: `GRANT SELECT, INSERT ON EMP TO KIM;` (KIM에게 EMP 테이블의 조회, 삽입 권한 부여)
- **REVOKE (권한 회수)**
    - 문법: `REVOKE 권한 ON 대상 FROM 사용자;`
    - 예시: `REVOKE INSERT ON EMP FROM KIM;` (KIM으로부터 EMP 테이블의 삽입 권한을 뺏음)
        

## 4. TCL (트랜잭션 제어어) - COMMIT, ROLLBACK, SAVEPOINT

트랜잭션 ACID 특성과 맞물려 데이터의 물리적 저장 시점을 조절하는 제어어입니다.

- **COMMIT**: 트랜잭션 내의 모든 연산이 성공적으로 완료되었음을 선언하고, 변경된 내용을 **데이터베이스에 영구적으로 반영**하는 명령어입니다.
- **ROLLBACK**: 트랜잭션 실행 중 오류가 발생했거나 비정상 종료되었을 때, 지금까지 수행한 **모든 연산 작업을 취소하고 트랜잭션 시작 이전의 상태로 되돌리는** 명령어입니다.
- **SAVEPOINT (저장점)**: 트랜잭션이 길어질 때 중간에 복귀 시점(정착지)을 지정하는 명령어입니다.
    - 지정: `SAVEPOINT 포인트명;`
    - 부분 취소: `ROLLBACK TO 포인트명;` 을 실행하면 트랜잭션 전체를 취소하지 않고, 해당 SAVEPOINT를 지정한 시점까지만 부분적으로 롤백합니다.
        

**💡 시험장 문법 실수 방지 팁:**

수기 작성 문제에서 `INSERT INTO`, `UPDATE SET`, `DELETE FROM`에서 각 짝꿍 단어인 `INTO` / `SET` / `FROM`을 뒤섞어 쓰지 않도록 주의하세요. 특히 외래키를 정의하는 3줄 구조(`CONSTRAINT` - `FOREIGN KEY` - `REFERENCES`)는 토씨 하나 틀리지 않고 백지에 바로 손코딩할 수 있을 때까지 써보며 눈에 익혀두는 것이 핵심입니다!

# 언어
## C언어
### 1. 배열과 포인터의 등가 관계 (가장 많이 출제되는 공식)

1. `배열이름`은 배열의 시작 주소(0번지 주소) 한개를 의미합니다.
2. `&배열이름`은 배열의 총 주소라 여기다가 +1를 하면 배열을 벗어난 다음 요소에 접근합니다. 그래서 포인터 증감에 적합하지 않습니다.

아래의 표현은 완벽하게 같은 공간(값)을 가리킵니다.

- **공식**: `arr[i]` $\equiv$ `*(arr + i)` $\equiv$ `p[i]` $\equiv$ `*(p + i)`
- **주의할 점**: 포인터 변수 `p`가 `arr + 1`을 가리키고 있다면 `p[-1]`은 `arr[0]`의 값이 됩니다. 마이너스 인덱스 표현이 시험에 자주 나오므로 당황하지 마세요.

### 2. 포인터 증감과 주소 이동

포인터에 숫자를 더하거나 빼는 것은 "그 자료형의 크기만큼 칸을 이동한다"는 뜻입니다.

- `p++` 또는 `p = p + 1`: 현재 가리키는 곳에서 다음 칸(다음 요소)으로 이동합니다.
- `*p++`: 현재 `p`가 가리키는 곳의 값을 먼저 사용한 뒤, `p` 주소를 다음 칸으로 이동합니다.
	- 참고로 후위 `++`가 `*`보다 높다 컴퓨터가 이를 `*(p++)`로 해석해서 ㄱㅊ한거다.
- `(*p)++`: 주소는 움직이지 않고, 현재 `p`가 가리키는 곳의 **실제 값**을 1 증가시킵니다.

### 3. 문자 배열과 문자열 (`\0`)

C언어에서 문자열의 끝에는 반드시 눈에 보이지 않는 널 문자(`\0`, 정수값 0)가 들어있습니다.

```C
char str[] = "LOVE"; // 실제 메모리에는 'L', 'O', 'V', 'E', '\0' 총 5칸 저장
```

- **출력 형식에 따른 차이**:
    - `printf("%s", str);` $\rightarrow$ 주소부터 시작해서 **`\0`을 만날 때까지** 문자열 전체를 출력합니다.
    - `printf("%c", *str);` $\rightarrow$ 그 주소에 있는 **딱 문자 1개**('L')만 출력합니다.
    - 만약 중간에 `str[2] = '\0';`을 실행하면, `%s`로 출력 시 "LO"까지만 출력되고 종료됩니다.

### 4. 반복문 안에서 배열값 변경 (디버깅 표 그리기)

시험장에서 반드시 변수 추적 표(Trace Table)를 그려서 풀어야 하는 유형입니다.

- **예시 코드 흐름 추적**:

```C
int a[3] = {10, 20, 30};
for(int i = 0; i < 3; i++) {
    a[i] = a[i] + 5;
}
```

- **시험장 머릿속/시험지 구석 표**:

| 루프 순서 | `i` 값 | `a[i]` 기존 값 | 연산 및 변경 후 `a` 배열 상태                        |
| :---- | :---- | :---------- | :----------------------------------------- |
| 1회전   | 0     | `a[0] = 10` | `10 + 5 = 15` $\rightarrow$ `{15, 20, 30}` |
| 2회전   | 1     | `a[1] = 20` | `20 + 5 = 25` $\rightarrow$ `{15, 25, 30}` |
| 3회전   | 2     | `a[2] = 30` | `30 + 5 = 35` $\rightarrow$ `{15, 25, 35}` |

### 5. 구조체와 구조체 포인터

구조체 멤버에 접근할 때 **일반 변수냐 포인터 변수냐**에 따라 기호가 달라집니다.

- **일반 구조체 변수**: `.` (점)을 사용 $\rightarrow$ `obj.member`
- **구조체 포인터 변수**: `->` (화살표)를 사용 $\rightarrow$ `ptr->member`
- **등가 관계 공식**: `ptr->member` $\equiv$ `(*ptr).member`
- **구조체 배열 포인터**: `(ptr+1)->member`는 구조체 배열의 다음 요소(다음 사람)의 멤버를 가리킵니다.

### 6. 함수에 배열·포인터 전달 (Call by Address / 주소 전달)

함수에 일반 변수를 넘기면 값이 복사되어 함수 안에서 아무리 바꿔도 원본이 안 바뀝니다(값에 의한 호출). 하지만 배열이나 포인터(주소)를 넘기면 함수 안에서 바꾼 값이 **원본 배열에도 그대로 반영**됩니다

```c
void modify(int *arr) {
    arr[0] = 99; // 주소를 타고 원본을 바꿈
} //만약에 매걔변수가 포인터가 아닌 일반 변수 int arr이였다면 원본 안바뀜
int main() {
    int data[2] = {1, 2};
    modify(data); // 배열 이름을 넘김 (주소 전달)
    // data[0]은 99로 바뀌어 있음!
}
```

### 7. 2차원 배열의 인덱스 계산 (포인터 시점)

행단위 탐색(a) -> ‘배열 전체크기’만큼 점프해 특정 행의 "시작주소"를 가리킴
열단위 탐색(`*(a+i)`) ->‘값 타입크기’만큼 점프해 "실제 값"을 가리킴

- `a[i][j]` $\equiv$ `*(*(a + i) + j)`
	- **`*(a + i)`** $\rightarrow$ `i`번째 행의 **"시작 주소"** (포인터)
	- **`*(*(a + i) + j)`** $\rightarrow$ `i`번째 행, `j`번째 열의 **"실제 값"**
- 포인터 변수 `int *p = a[1];` 이라고 선언하면, `p`는 **1행 0열(`a[1][0]`)의 주소**를 가리키는 1차원 포인터가 되고, `p[1]`은 `a[1][1]`의 값을 의미하게 됨

### 8. 전위·후위 증감 연산자 (`++x` vs `x++`)

한 줄에 연산이 겹쳐서 나올 때 값을 치환하는 타이밍이 다릅니다.

- **전위 (`++x`)**: **먼저 1을 증가**시키고, 그 줄의 다른 연산이나 출력을 수행합니다.
- **후위 (`x++`)**: 현재 값을 먼저 사용(출력)하고, 해당 줄의 실행이 완전히 끝난 직후(세미콜론 `;`을 지날 때)에 1을 증가시킵니다.

```c
int x = 3;
printf("%d", x++); // 3이 먼저 출력되고, x는 4가 됨
printf("%d", ++x); // 4에서 먼저 1 증가해 5가 되고, 5가 출력됨
```

### 9. 출력 형식 (printf 단골 포맷)

출력 포맷을 잘못 읽으면 다 풀어놓고 오답을 적게 됩니다.

- **`%d`**: 10진수 정수 출력
- **`%x`**: 16진수 소문자 출력 (예: 10 $\rightarrow$ `a`, 15 $\rightarrow$ `f`)
- **`%o`**: 8진수 정수 출력 (예: 8 $\rightarrow$ `10`)
- **`%c`**: 문자 1개 출력
- **`%s`**: 문자열 출력 (`\0` 직전까지)
- **`%f`**: 소수점 아래 **6자리**까지 출력 (다음자리인 7자리에서 반올림)
- 기본값: 우측정렬, 소숫점 아래는 0, 전체자리지정시 나머지는 공백(빈칸)
$$\%\text{[-/0] [전체 자릿수] . [소수점 자릿수] f}$$
- **`-`** (좌측정렬): 전체 칸 수를 지정했을 때 왼쪽으로 붙여서 출력합니다.
- **`0`** (0으로채우기): 남는 앞 공백 대신 `0`으로 채웁니다.
- `전체 자릿수`: 소수점(`.`)을 포함한 **전체 출력 칸 수**를 지정.
- `.소숫점 자릿수` : 지정한 자릿수 바로 다음자리에서 반올림해 출력

**`%010.2f`** 로 10.12611111를 출력-> `0000010.13`
- 전체 10칸 확보, 남는 앞 자리를 0으로 채움
printf("%05d\n", 12); // "00012"
### 10. 함수 포인터 (구조 읽기)

선언문이 복잡해 보이지만 가리키는 대상과 매개변수만 매칭하면 끝납니다.
```c
반환타입 (*포인터이름)(매개변수타입1, 매개변수타입2, …);
``` 

`int (*pf)(int);`
1. **괄호 안을 먼저 봅니다**: `(*pf)` $\rightarrow$ `pf`는 포인터 변수구나!
2. **오른쪽 괄호를 봅니다**: `(int)` $\rightarrow$ 매개변수로 `int`형 데이터 1개를 받는 함수를 가리키는구나!
3. **맨 왼쪽을 봅니다**: `int` $\rightarrow$ 이 함수는 실행 후 `int`형 결과를 반환하는구나!

- **실제 매칭 코드**:

```c
int square(int n) { return n * n; }
int main() {
    int (*pf)(int) = square; // pf가 square 함수를 가리킴
    printf("%d", pf(5));     // square(5)를 호출한 것과 같음. 출력: 25
}
```

## java
### 1. 상속 시 생성자 호출 순서 (상향식 호출)

자식 객체를 생성하면, 자식 생성자가 먼저 호출되기는 하지만 내부적으로 **부모 생성자가 먼저 실행**된 후 자식 생성자의 코드가 실행됩니다.

- **규칙**: 자식 생성자 첫 줄에 `super()`가 생략되어 있는 것과 같습니다.
- **순서**: 부모 클래스 생성자 실행 $\rightarrow$ 자식 클래스 생성자 실행.
 
### 2. 오버라이딩과 동적 바인딩

- **정의**: 부모가 가진 메서드를 자식이 똑같은 모양(이름, 매개변수)으로 재정의하는 것입니다.
- **동적 바인딩**: 컴파일 시점이 아니라, 실행 시점(Runtime)에 실제 생성된 객체의 오버라이딩된 메서드가 호출되는 현상입니다.

### 3. 오버로딩과 컴파일 시점 메서드 선택

- **정의**: 한 클래스 내에서 **메서드 이름은 같으나 매개변수의 개수나 타입이 다른** 메서드를 여러 개 정의하는 것입니다.
- **선택 기준**: **컴파일 시점**에, 코드를 호출할 때 전달한 **인자(Parameter)의 선언된 타입**을 기준으로 실행할 메서드가 결정됩니다.

### 4. 부모 타입 참조변수와 자식 객체 (다형성 시험 단골)

```Java
Parent obj = new Child(); // 부모 타입 변수로 자식 객체를 참조
```

- **`Parent` (좌항)**: **참조변수의 타입 (그릇)** $\rightarrow$ 접근할 수 있는 영역(범위)을 결정합니다.
- **`Child` (우항)**: **실제 생성된 인스턴스 (알맹이)** $\rightarrow$ 실제 실행되는 메서드의 주체를 결정합니다.

이 구문이 등장하면 아래 **두 가지 공식을 기계적으로 적용**해야 합니다.

> 1. **인스턴스 메서드**: **실제 객체(new 뒤에 있는 자식 클래스)의 오버라이딩 메서드**가 무조건 실행됩니다.
> 2. **멤버 변수(필드)**: 실제 객체가 아닌 **참조 변수(선언문 앞의 부모 타입)에 선언된 필드**에 접근합니다.

```java
class Parent {
    int x = 10;
    void show() { System.out.println("Parent"); }
}
class Child extends Parent {
    int x = 20; // 필드 숨김 (Hiding)
    void show() { System.out.println("Child"); } // 오버라이딩 (Overriding)
}

public class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        
        System.out.println(p.x); // 출력: 10 (참조변수가 Parent 타입이므로 Parent의 필드 호출)
        p.show();                // 출력: "Child" (실제 인스턴스가 Child이므로 Child의 오버라이딩 메서드 호출)
    }
}
```
### 5. static 멤버 vs 인스턴스 멤버

- **static (클래스 멤버)**: 객체 생성 없이 클래스명으로 접근하며, **메모리에 단 하나만 존재**하여 모든 객체가 공유합니다. (이름표에 주소가 적혀있지 않고 static 영역에 고정)
- **인스턴스 멤버**: `new`를 통해 생성된 객체(인스턴스)마다 독립적으로 가지는 변수와 메서드입니다.
- **주의**: static 메서드 내부에서는 인스턴스 변수나 인스턴스 메서드를 사용할 수 없습니다 (객체가 아직 안 태어났을 수도 있기 때문).
    

### 6. 필드 숨김(Field Shadowing)과 메서드 오버라이딩의 차이

부모와 자식에 같은 이름의 필드(변수)와 메서드가 동시에 존재할 때:

- **메서드**: 오버라이딩이 적용되어 **자식 메서드가 부모 메서드를 완전히 덮어씌웁니다(오버라이딩)**.
- **필드**: 오버라이딩되지 않고 단순히 가려집니다(Shadowing). 따라서 **참조 변수의 타입이 부모면 부모 필드가, 자식이면 자식 필드**가 독립적으로 출력됩니다.

### 7. super 키워드

- **`super`**: 자식 클래스에서 부모 클래스의 멤버(필드, 메서드)에 접근할 때 사용합니다.
- **`super()`**: 부모 클래스의 생성자를 호출할 때 사용하며, 반드시 **자식 생성자의 첫 줄**에만 위치해야 합니다.
    

### 8. 추상 클래스(Abstract Class)와 인터페이스(Interface)

- **추상 클래스 (`abstract`)**: `extends`로 상속하며, 단일 상속만 가능합니다. 추상 메서드를 하나라도 가지면 반드시 추상 클래스로 선언해야 합니다.
- **인터페이스 (`interface`)**: `implements`로 구현하며, 다중 구현이 가능합니다.
    - 인터페이스 내의 모든 변수는 자동으로 `public static final` (상수)이 됩니다. 그러므로 선언과 동시에 초기화를 해야합니다
	    - `int a = 10;` 필수, 공백 선언 시 컴파일 에러
    - 인터페이스 내의 일반 메서드는 자동으로 `public abstract` (추상 메서드)가 됩니다.

### 9. 예외처리와 finally

`try-catch-finally` 구조에서 가장 중요한 것은 **`finally` 블록의 절대적 실행**입니다.

- **규칙**: `try` 혹은 `catch` 블록 안에 `return`문이 실행되더라도, **메서드가 완전히 종료되기 전에 `finally` 블록의 코드가 무조건 실행**되고 나서 최종 반환됩니다.
    

### 10. 문자열 연결 시 연산 순서 (단골 함정)

`+` 연산자는 **왼쪽에서 오른쪽**으로 차례대로 연산하며, **하나라도 문자열이 섞이면 그 이후는 문자열 연결**이 됩니다.

- `System.out.println(3 + 4 + "Java");` $\rightarrow$ `7 + "Java"` $\rightarrow$ **`"7Java"`**
- `System.out.println("Java" + 3 + 4);` $\rightarrow$ `"Java3" + 4` $\rightarrow$ **`"Java34"`**
    

### 11. 배열 및 객체 참조 (Call by Reference)

Java는 항상 변수에 담긴 '값'을 전달하지만, **배열이나 객체는 주소값(참조값)이 복사**되어 넘어갑니다.

- 메서드 내부에서 매개변수로 받은 배열의 요소를 수정하면(`arr[0] = 100;`), 메서드 호출이 끝난 뒤에도 **원본 배열의 값이 변경**되어 있습니다.
- 단, 함수 내부에서 매개변수에 **새로운 객체를 통째로 대입**하면(`arr = new int[5];`), 메인 함수의 원본 참조와는 연결이 끊어지기 때문에 원본 객체에는 아무런 영향을 주지 않습니다.

## python

### 1. 슬라이싱 (Slicing)과 음수 인덱스

가장 직관적이면서도 실수하기 쉬운 단골 출제 영역입니다.

#### 기본 공식: `[start:end:step]`

- **`start`**: 시작 인덱스 (포함)
- **`end`**: 끝 인덱스 (**미포함**, 즉 `end - 1` 까지만 가져옴)
- **`step`**: 주소 이동 간격 (기본값은 `1`, 음수이면 역방향으로 이동)

#### 음수 인덱스 구조

오른쪽 끝(마지막 요소)이 `-1`부터 시작해서 왼쪽으로 갈수록 번호가 작아집니다.

```text
인덱스:   0    1    2    3    4
값  : ['A', 'B', 'C', 'D', 'E']
음수idx:  -5   -4   -3   -2   -1
```

#### 역방향 슬라이싱 핵심 예시

- **$[::-1]$**: 처음부터 끝까지 **역순으로 1칸씩** 뒤집어 출력
	$\rightarrow$ `['E', 'D', 'C', 'B', 'A']`
- **$[::-2]$**: 처음부터 끝까지 **역순으로 2칸씩** 건너뛰며 출력
	$\rightarrow$ `['E', 'C', 'A']`
- **$[3:0:-1]$**: 인덱스 `3`부터 시작하여 `0` 바로 앞(`1`)까지 역순으로 이동 $\rightarrow$ `['D', 'C', 'B']`

### 2. 리스트의 별칭(Alias) vs 얕은 복사(Shallow Copy)

메모리 주소의 변화를 추적하는 아주 중요한 개념입니다.

#### 단순 대입 (`b = a`)

- **동일한 주소(객체)를 공유**합니다 (이름만 다를 뿐 같은 객체).
- `b[0] = 99`로 바꾸면 원본 `a[0]`도 `99`로 바뀝니다.
    

#### 얕은 복사 (`b = a[:]` 또는 `b = a.copy()`)

- 껍데기(1차원 구조)는 **서로 다른 새로운 리스트**가 생성됩니다.
- 따라서 `b[0] = 99`로 바꿔도 원본 `a`에는 아무런 영향이 없습니

#### ⚠️ 주의: 중첩 리스트일 때의 얕은 복사

- `a = [1, [2, 3]]`과 같이 내부에 또 다른 리스트가 들어있는 경우, `b = a[:]`를 실행해도 내부 리스트 `[2, 3]`의 주소값까지는 새롭게 복사되지 않고 공유됩니다.
- 이 상태에서 `b[1][0] = 99`를 실행하면 원본 `a`도 `[1, [99, 3]]`으로 변경됩니다.
    

### 3. 리스트 컴프리헨션 (List Comprehension)

반복문과 조건문을 한 줄로 압축하여 새 리스트를 생성하는 기법입니다.

```Python
# 기본 구조: [표현식 for 변수 in 반복가능객체 if 조건식]
arr = [i * 2 for i in range(5) if i % 2 == 0]
```

- **해석 단계**:
    
    1. `range(5)`에 의해 `0, 1, 2, 3, 4`가 대상이 됨
    2. `if i % 2 == 0` 필터링에 의해 짝수 `0, 2, 4`만 통과
    3. `i * 2` 연산을 거쳐 최종 결과 생성 $\rightarrow$ `[0, 4, 8]`
        

### 4. 가변 객체(Mutable)의 파라미터 전달

파이썬은 참조 투과적인 객체 전달 방식을 사용하여, 함수에 가변 객체(리스트, 딕셔너리, 집합 등)를 인수로 보내면 **함수 내부에서 조작한 결과가 원래 객체에 직접 반영**됩니다.

```Python
def update_list(lst):
    lst.append(4) # 원본 리스트에 요소를 추가함

my_list = [1, 2, 3]
update_list(my_list)
print(my_list) # 출력: [1, 2, 3, 4]
```

### 5. `range()` 함수 범위 계산

반복 횟수를 잡을 때 아주 중요합니다.

- `range(end)`: `0`부터 `end-1`까지 1씩 증가
- `range(start, end)`: `start`부터 `end-1`까지 1씩 증가
- `range(start, end, step)`: `start`부터 `end-1`까지 `step`만큼씩 증가/감소
    

### 6. `split()`과 `join()`

문자열 변환 및 가공 연산의 대표 주자입니다.

- **`split()`**: 특정 구분자를 기준으로 문자열을 잘라 **리스트로 반환**합니다 (기본값은 공백).
    
    ```Python
    "A-B-C".split("-") # 결과: ['A', 'B', 'C']
    ```
    
- **`join()`**: 리스트 안의 문자열 요소를 특정 구분자로 **합쳐서 하나의 문자열**로 만듭니다.
    
    ```Python
    "/".join(['A', 'B', 'C']) # 결과: "A/B/C"
    ```
    

### 7. 주요 자료구조 특징 비교

|**자료구조**|**선언 기호**|**중복 허용 여부**|**특징 (시험 출제 포인트)**|
|---|---|---|---|
|**리스트 (List)**|`[1, 2]`|허용|수정 가능(Mutable), 인덱싱 가능|
|**튜플 (Tuple)**|`(1, 2)`|허용|**수정 불가능(Immutable)**|
|**딕셔너리 (Dict)**|`{'key': 'val'}`|키 중복 불가|Key-Value 쌍 구조, 순서 없음|
|**집합 (Set)**|`{1, 2}`|**중복 불가**|순서 없음, 중복 값 추가 시 자동 제거|

### 8. 리스트 요소 추가 방법 차이 (`append` vs `extend` vs `+=`)

문법은 비슷해 보여도 묶이는 방식이 완전히 다릅니다.

```Python
a = [1, 2]
```

- **`a.append([3, 4])`**: 리스트 자체를 통째로 하나의 원소로 추가합니다.
    $\rightarrow$ `[1, 2, [3, 4]]` (이중 리스트 구조로 확장)
    
- **`a.extend([3, 4])`**: 반복 가능한 대상의 요소를 꺼내어 개별적으로 병합합니다.
    $\rightarrow$ `[1, 2, 3, 4]`
    
- **`a += [3, 4]`**: 내부적으로는 `extend()`와 똑같이 동작합니다.
    $\rightarrow$ `[1, 2, 3, 4]`
    

### 9. 클래스 구조와 상속 기본 규칙

자바나 C++과 다른 파이썬만의 고유 문법을 묻습니다.

- **인스턴스 선언**: `new` 예약어가 없으며 클래스 이름을 함수처럼 직접 호출합니다.
- **생성자 메서드**: `__init__(self)`가 인스턴스 생성 시 자동으로 수행됩니다.
- **첫 번째 매개변수 `self`**: 메서드를 호출한 인스턴스 자신을 가리키는 파라미터로 반드시 정의해 주어야 합니다.

```Python
class Parent:
    def __init__(self):
        self.val = "부모"

class Child(Parent): # 괄호 안에 부모 클래스 명시하여 상속
    def __init__(self):
        super().__init__() # 부모의 생성자 직접 호출
        self.val = "자식"
```

**💡 파이썬 시험장 핵심 팁:**

파이썬의 실행 결과를 물어볼 때 가장 흔히 저지르는 실수는 쉼표(`,`)나 괄호(대괄호 `[]`, 소괄호 `()`, 중괄호 `{}`)를 출력 양식에 잘못 포함하거나 생략하는 것입니다. `print(리스트)`를 실행하면 대괄호 `[…]`와 쉼표가 전부 출력되지만, 반복문 내에서 개별 요소를 하나씩 뽑아 출력하면 다르게 나온다는 것을 잊지 마세요!
