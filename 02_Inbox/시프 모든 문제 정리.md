## [Q1] 리눅스 환경에서 실행 중인 프로세스를 키보드 단축키인 'Ctrl + C'를 입력하여 강제 종료시켰다. 이때 커널이 해당 프로세스에 전달하는 시그널(Signal)의 명칭을 기술하시오.

### 📝 시험장 제출용 정답 (핵심 암기본)

- **정답:** **`SIGINT`** (Signal Interrupt)
	- 키보드 인터럽트를 통해 프로세스를 전송 직후 즉시 종료(Terminate)시키는 시그널임.

## [Q2] 유닉스/리눅스 시스템 프로그래밍 중 시그널 집합 변수인 `sigset_t sigst;`에 특정 시그널인 `SIGQUIT`을 추가하고자 한다. 올바른 POSIX 표준 시스템 콜 함수와 인자 형태를 기술하시오.

### 📝 시험장 제출용 정답 (핵심 암기본)

- **정답:** **`sigaddset(&sigst, SIGQUIT);`**
	- sig+add(기능)+set, 첫번째인자는 `&`
- 시그널 집합에 개별 시그널을 추가하는 표준 함수
- 기존 집합 변수의 내부 값을 직접 변경해야 하므로 주소 연산자(`&`)를 붙여 참조(포인터) 형태로 넘겨줘야함

## [Q4] 유닉스 시스템에서 알람 시그널과 관련해 고정밀 타이머 기능(`setitimer`)을 제공한다. 이 중 실제 시간(조직 시간)을 기준으로 정밀하게 측정하여 시스템 우수 시간 만료 시 `SIGALRM` 시그널을 발생시키는 타이머의 종류(상수명)를 기술하시오.

### 📝 시험장 제출용 정답 (핵심 암기본)

- **정답:** **`ITIMER_REAL`**
- 실제 현실 세계의 흐름 시간(Wall-clock time)을 기준으로 타이머를 구동하여 만료 시 `SIGALRM`을 던지는 상수

### 🔍 상세 설명 및 이해 가이드

간격 타이머(`Interval Timer`)의 세 가지 종류와 매핑되는 시그널을 구별하는 고난도 문제입니다.

```markdown
 [타이머 상수별 발생 시그널 매핑 리스트]
  1. ITIMER_REAL    ──▶ 실제 흐르는 현실 시간 기준 ──▶ [SIGALRM] 발생 (정답)
  2. ITIMER_VIRTUAL ──▶ 프로세스의 사용자 모드 CPU 시간 ──▶ [SIGVTALRM] 발생
  3. ITIMER_PROF    ──▶ 사용자+커널 모드 전체 CPU 시간  ──▶ [SIGPROF] 발생
```

## [Q1] mmap() 함수로 메모리를 매핑할 때 지정하는 인자 중에서, 다른 프로세스와 메모리 변경 내용을 공유하도록 지정하기 위해 사용하는 플래그(flags) 값을 기술하시오.

### 📝 시험장 제출용 정답 (핵심 암기본)

- **정답:** **`MAP_SHARED`**
- **개념:** 매핑된 영역의 데이터 변경 내용을 다른 프로세스들과 공유하고, 최종적으로 원본 파일에도 반영하도록 설정하는 플래그임.
    

### 🔍 상세 설명 및 이해 가이드

`mmap()` 시스템 콜의 핵심 인자인 플래그를 구별하는 문제입니다.

```markdown
 [mmap 플래그별 작동 매커니즘 차이]
  1. MAP_PRIVATE ──▶ 메모리 변경 시 나만 복사본을 가짐 (Copy-on-Write, 원본 유지)
  2. MAP_SHARED  ──▶ 메모리 변경 내용이 공유 메모리 영역 및 원본 파일에 실시간 반영 (IPC 활용)
```

- **시험장 오답 방지 팁:** 보기 중에 `MAP_ANONYMOUS`와 헷갈리면 안 됩니다. `MAP_ANONYMOUS`는 대응하는 파일 없이 순수 메모리 공간만 할당받을 때 쓰는 특수 플래그이며, "메모리를 공유"한다는 단어가 지문에 나오면 무조건 짝꿍은 `MAP_SHARED`입니다.

## [Q2] 서로 다른 CPU 아키텍처 간에 데이터를 정확히 전송하기 위해, 호스트 바이트 순서로 된 32비트(Long형) 데이터를 네트워크 표준 바이트 순서인 '빅 엔디언(Big Endian)'으로 변환하고자 할 때 사용하는 올바른 함수명을 기술하시오.

### 📝 시험장 제출용 정답 (핵심 암기본)

- **정답:** **`htonl()`** (Host to Network Long)
- **이유:** 호스트(`h`)에서 네트워크(`n`) 방향으로 데이터를 변환하며, IP 주소와 같은 32비트 대용량 데이터를 다루므로 대형(Long)을 뜻하는 `l`이 결합된 `htonl`을 사용해야 하기 때문임.
    

### 🔍 상세 설명 및 이해 가이드

엔디언 변환 함수의 조합 원리를 묻는 단골 문제입니다.

```markdown
 [바이트 순서 변환 함수 네이밍 공식]
  - h : Host (내 컴퓨터 바이트 순서)
  - n : Network (네트워크 표준 순서 = 빅 엔디언)
  - s : Short (16비트 - 포트 번호용)
  - l : Long (32비트 - IP 주소용)
 ─────────────────────────────────────────
  ▶ "호스트에서 네트워크로 32비트 이동" ──▶ h + to + n + l ──▶ [htonl()]
```

## [Q6] TCP와 UDP의 차이점은 무엇이며 용도는 어떻게 구별하는가?

### 📝 시험장 제출용 정답 (핵심 암기본)

- **TCP와 UDP의 차이점:**
* **TCP:** 연결 지향형 프로토콜로, 3-Way Handshaking을 통해 연결을 설정한 후 데이터를 전송하며 신뢰성 있는 데이터 전송(흐름 제어, 혼잡 제어)을 보장함.
- **UDP:** 비연결 지향형 프로토콜로, 연결 설정 과정 없이 독립적인 데이터그램 단위로 전송하며 **신뢰성은 낮으나 전송 속도가 빠름.**
- **용도 구별:**
    - **TCP 용도:** 데이터의 유실이 치명적인 서비스 (예: **웹 통신(HTTP), 파일 전송(FTP), 이메일(SMTP)**)
    - **UDP 용도:** 일부 데이터가 유실되더라도 실시간성이 더 중요한 서비스 (예: **실시간 스트리밍, 온라인 게임, DNS 조회, 화상 통화**)

### Q6. 시그널 핸들러의 재진입 가능성(Reentrancy)과 작성 방법
---
- **개념**: 시그널은 비동기적으로 아무 때나 발생하므로, 메인 루틴이 어떤 함수를 실행하던 중에 갑자기 멈추고 시그널 핸들러가 실행될 수 있습니다. 이때 핸들러 내부에서 메인 루틴이 쓰던 함수를 똑같이 또 호출해도 문제가 없는 성질을 재진입 가능(Reentrant)이라고 합니다.
- **작성 방법**: 시그널 핸들러는 반드시 **비동기 시그널 안전한 함수만 사용**하도록 작성해야 합니다.
    - 핸들러 내부에서는 `malloc()`, `printf()`, 전역 변수처럼 내부적으로 정적(Static) 버퍼나 락(Lock)을 공유하는 함수를 쓰면 안 됩니다.
	    - 메인 루틴이 `printf`를 하던 중 시그널이 터져 핸들러가 또 `printf`를 부르면 데드락이나 데이터 오염이 발생함
    - 따라서 핸들러 내부에서는 오직 지역 변수만 사용하거나, `write()` 같은 로우 레벨 시스템 호출만 사용해야 안전합니다.
### Q1. `mmap()` 시스템 호출을 사용하는 목적과 용도
- **성능 최적화**: 일반적인 파일 입출력인 `read()`, `write()`는 커널 공간의 버퍼와 유저 공간의 버퍼 간에 데이터를 복사하는 과정(콘테스트 스위칭)이 필요합니다. 반면 `mmap()`은 파일의 내용을 유저 가상 메모리 공간에 직접 매핑하므로 이 복사 과정이 생략되어 **대용량 파일 읽기/쓰기 속도가 획기적으로 빨라집니다.**
