수정본의 세부 목차를 문서에 나온 순서대로 검토하면서 다음을 판단해줘.

1. 수정본이 1일 차 이론 회상용 노트의 목적에 맞게 수정되었는지
2. 60점 합격 전략과 배정된 학습시간에 비해 내용이 과하거나 부족하지 않은지
3. 원본에 있던 핵심 질문 중 수정본에서 빠뜨린 것이 있는지
4. 수정본의 답안이 아래 답안 작성 원칙을 준수하는지
5. C·Java·Python·SQL에서는 코드 문항이 문제풀이 노트와 불필요하게 중복되는지
    

전체 수정본을 다시 작성하지 말고, **실제로 유지·수정·통합·삭제·복원해야 할 항목만 선별**해줘.

# 진행 방식

수정본의 첫 번째 세부 목차부터 시작하여, 한 번의 답변에서 **완결성 있게 검토할 수 있는 세부 목차까지 최대한 많이 진행**해줘.

다음 원칙을 지켜줘.

- 세부 목차 하나의 검토를 끝낸 뒤 다음 세부 목차로 넘어간다.
- 응답 분량이 부족하면 세부 목차 중간에서 끊지 않는다.
- 남은 분량이 부족하면 다음 세부 목차를 얕게 시작하지 말고 멈춘다.
- 후속 요청에서는 이미 검토한 세부 목차를 반복하지 않는다.
- 원본과 수정본의 구성이 다르면 수정본의 세부 목차를 기준으로 원본의 관련 질문을 대응시킨다.
- 문제풀이 노트는 해당 주제와 직접 관련된 내용이 있을 때만 비교한다.
- 문제가 없는 항목은 짧게 확인하고, 수정·통합·삭제·복원이 필요한 항목에 출력량을 우선 배분한다.
- 아직 검토하지 않은 부분을 추측하여 전체 노트에 대한 결론을 내리지 않는다.
    

한 번의 답변에서 모든 세부 목차를 검토하지 못했다면, 답변 마지막에 다음 두 가지만 알려줘.

- 이번에 검토를 마친 마지막 세부 목차
- 다음에 이어서 검토할 세부 목차
    

모든 세부 목차의 검토가 끝났다면 전체 노트를 다시 출력하지 말고, 그때만 전체 분량·영역별 균형·노트 간 역할 분리·최종 수정 우선순위를 종합해줘.

# 세부 목차별 검토 기준

## 1. 수정 목적 달성 여부

다음을 확인해줘.

- 질문만 보고 정답과 핵심 개념을 능동적으로 회상할 수 있는가
- 질문이 직접적이고 무엇을 답해야 하는지 명확한가
- 정답이나 핵심 용어가 첫 문장에 바로 제시되는가
- 정답 뒤에 문제 해결에 필요한 핵심 설명이 적절히 붙어 있는가
- 비슷한 질문이 불필요하게 반복되지 않는가
- 지나친 압축으로 핵심 원리나 구별 기준이 빠지지 않았는가
- 시험에 필요하지 않은 세부사항까지 확장되지 않았는가
    

단순히 좋고 나쁨을 평가하지 말고, **실제 제한시간 안에 빠르게 회상하며 사용할 수 있는 노트인지** 판단해줘.

## 2. 분량과 중요도의 적합성

다음을 고려해 과하거나 부족한지 판단해줘.

- 학습 계획에서 해당 영역에 배정된 시간
- Must-Do와 끝까지 유지할 내용
- 시간이 부족할 때 삭제할 내용
- 해당 영역의 완료 기준
- 질문 수와 답변 길이
- 예상 1회독 시간
- 질문 간 중복
- 핵심 내용과 세부 내용의 비중
- 실제 회상 난이도와 학습 부담
    

질문 수가 많다는 이유만으로 과하다고 판단하지 말고, **답변 길이와 중복을 포함한 실제 학습 부담**을 기준으로 판단해줘.

## 3. 원본 대비 핵심 누락

원본과 수정본을 항목별로 실제 비교하여, 삭제된 질문 가운데 다음 기준에 해당하는 내용만 선별해줘.

- 학습 계획의 Must-Do 범위인가
- 기출 문제 해결에 필요한 핵심 원리인가
- 수정본의 다른 질문으로 충분히 대체되지 않는가
- 혼동하기 쉬운 개념의 구별 기준인가
- 코드나 SQL 결과를 결정하는 규칙인가
- 단답형 출제 가능성이 높은 핵심 용어인가
- 삭제하면 해당 주제의 이해 흐름이 끊기는가
    

모든 삭제 질문을 복원하려 하지 말아줘.

복원이 필요한 항목에는 다음을 제시해줘.

- 원본의 핵심 내용
- 수정본의 대체 질문 존재 여부
- 복원이 필요한 이유
- 중요도: `반드시 복원 / 가능하면 복원`
- 바로 붙여 넣을 질문과 답안
    

복원할 필요가 없는 삭제 내용은 전부 나열하지 말고 주요 유형과 이유만 간단히 정리해줘.

## 4. 문제풀이 노트와의 중복

C·Java·Python·SQL에서는 수정본의 코드 문항과 문제풀이 노트를 실제로 비교해줘.

단순히 코드가 있다는 이유만으로 중복이라고 판단하지 말고 다음을 구분해줘.

- 개념을 설명하기 위한 짧은 예시
- 답을 바로 확인하기 위한 최소 확인 문제
- 손으로 실행 과정을 추적해야 하는 독립 문제
- 문제풀이 노트와 같은 코드나 사고 과정을 반복하는 문제
- 수정본에서 삭제해도 이론 회상에 문제가 없는 문제
    

중복되거나 과한 항목은 다음 중 하나로 판정해줘.

- 그대로 유지
- 답안 속 짧은 예시로 축소
- 코드 없는 개념 질문으로 변경
- 다른 질문과 통합
- 문제풀이 노트로 이동
- 삭제
    

## 5. 답안 작성 원칙

수정본의 답안이 다음 원칙을 지키는지 확인해줘.

- 정답이나 핵심 용어를 첫 문장에 즉시 제시한다.
- 정답 뒤에 시험 문제 해결에 직접 도움이 되는 핵심 설명 한 문장을 덧붙인다.
- 핵심 설명은 출제 단서·핵심 역할·동작 원리·구별 기준·조건이나 예외 중 가장 필요한 내용을 우선한다.
- 단순 용어 대응이고 혼동 가능성이 낮으면 정답만 짧게 써도 된다.
- 정답을 표현만 바꾸어 반복하는 문장은 넣지 않는다.
- 시험 범위를 넘어가는 장황한 실무 설명은 넣지 않는다.
- 다른 질문에서 별도로 다룰 내용을 과도하게 끌어오지 않는다.
- 정확성을 떨어뜨리는 비유는 사용하지 않는다.
- 조건이나 예외를 생략하면 틀린 설명이 되는 경우에는 반드시 포함한다.
- `항상`, `절대`, `무조건` 같은 표현은 실제로 성립할 때만 사용한다.
- 코드 결과 문제는 결과값을 먼저 제시하고, 결과를 결정한 핵심 규칙을 짧게 설명한다.
- SQL 문법 문제는 핵심 문법을 먼저 제시하고, 키워드의 위치와 역할을 필요한 만큼만 설명한다.
- 답변은 지나치게 압축하지도, 여러 문단으로 장황하게 늘리지도 않는다.
    

사소한 문체 취향은 지적하지 말고, 다음처럼 실제 학습에 영향을 주는 문제만 선별해줘.

- 첫 문장만으로 정답을 확인하기 어려움
- 설명이 길어 빠른 회상을 방해함
- 설명이 너무 짧아 혼동되는 개념을 구별하지 못함
- 부정확하거나 예외를 무시한 단정
- 질문과 답이 정확히 대응하지 않음
- 문제풀이 노트와 불필요하게 중복되는 해설
- 시험 범위 밖의 설명으로 학습 부담을 늘림

# 출력 방식

각 세부 목차에서는 다음 내용을 중심으로 정리해줘.

1. 현재 구성과 분량이 적절한지
2. 반드시 수정·통합·삭제해야 할 질문이나 답안
3. 원본에서 반드시 또는 가능하면 복원할 질문
4. 문제풀이 노트와 직접 중복되는 내용
5. 답안 작성 원칙을 실질적으로 위반한 항목
6. 바로 붙여 넣을 수 있는 수정안
7. 해당 세부 목차의 최종 판정  
    `그대로 사용 가능 / 일부 수정 후 사용 / 대폭 축소 필요 / 핵심 보충 필요`
    

수정할 필요가 없는 질문은 나열하지 마.  
세부 목차 전체를 다시 작성하지 말고, **실제로 교체하거나 추가할 문구만 제시**해줘.

### Java에서 반드시 끝낼 것

- 부모 생성자 → 자식 생성자 실행 순서
- 부모 타입 참조변수와 자식 객체
- 필드는 선언 타입, 오버라이딩 메서드는 실제 객체
- 오버로딩은 선언된 매개변수 타입
- `static` 공유 여부
- `return`이 있어도 `finally` 실행
- 재귀 반환 순서
    

### Python에서 반드시 끝낼 것

- `[start:end:step]`
- `[::-1]`, `[::-2]`
- `b=a`와 `b=a[:]`
- 중첩 리스트의 얕은 복사
- 함수에서 리스트를 수정했을 때 원본 변화
- `append`, `extend`, `+=`
- `split`, `join`
    

### SQL에서 반드시 끝낼 것

- `COUNT(*)`와 `COUNT(컬럼)`
- `AVG`에서 NULL 제외
- `WHERE → GROUP BY → HAVING`
- 내부·외부 조인의 행 변화
- 서브쿼리 안쪽부터 계산
- 외래키 문법 직접 작성
- `INSERT INTO`, `UPDATE SET`, `DELETE FROM`
- `GRANT TO`, `REVOKE FROM`
    

### 2일 차 완료 기준

- Java 대표 문제 6개 중 4개 이상
- Python 대표 문제 6개 중 4개 이상
- SQL 결과 계산 5문제 중 4개 이상
- SQL 직접 작성 4문제 중 3개 이상
- C는 새 학습 없이 기존 감각 유지

## 마지막 반나절 — 2026년 1회 실전 점검

**순수 학습 120분**

### 1. 2026년 1회 전체 풀이 — 70분

정답과 해설을 가리고 20문제를 풉니다.

- 1차 제한: 문제당 **3분**
- 막히면 `△` 표시 후 즉시 이동
- 마지막 10분에 △ 문제만 재도전
- 모든 문제에 `확신 / 추측 / 모름` 표시
- 답을 몰라도 관련 용어 또는 추정 답을 적기
    

2026년 1회는 코드, SQL·DB, CIDR, 보안, 패턴, 요구사항, 테스트가 섞여 있어 지금까지 공부한 A범위의 최종 혼합 점검에 적합합니다.

### 2. 채점 및 오답 분류 — 20분

오답을 다음 다섯 분야로만 분류합니다.

- 언어
- SQL·DB
- 네트워크
- 보안
- 테스트·설계·요구사항
    

맞혔지만 추측한 문제도 오답처럼 표시합니다.

### 3. 최약점 한 영역 보정 — 20분

오답이 가장 많은 **한 영역만** 보충합니다.

- 언어 → 수제비 해당 언어 기출 2문제
- SQL·DB → 수제비 기출 3문제
- 네트워크 → 서브넷 2문제
- 보안 → 시나리오 단답 10개
- 설계·테스트 → 단답 15개
    

두 번째 약점까지 손대지 않습니다.

### 4. 마지막 백지 인출 — 10분

노트를 보지 않고 다음을 적습니다.

- 정규화 단계와 제거 대상
- 외래키 SQL 문법
- 하향식–스텁 / 상향식–드라이버
- 응집도·결합도 순서
- 대표 패턴 식별 단서
- CIDR 계산 순서
- 자주 틀린 보안 공격 5개
