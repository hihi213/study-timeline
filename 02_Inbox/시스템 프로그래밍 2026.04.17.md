## 📝 정리

## 1. 프로세스 종료 및 핸들러: "어떻게 떠날 것인가"

프로세스가 종료될 때 커널은 자원을 회수합니다. 하지만 **'어떤 수준에서 정리를 하고 갈 것인가'**에 따라 사용하는 함수가 달라집니다.

| **구분**        | **exit()**                     | **_exit()**                       |
| ------------- | ------------------------------ | --------------------------------- |
| **종류**        | 표준 C 라이브러리 함수 (`<stdlib.h>`)   | 시스템 콜 (System Call, `<unistd.h>`) |
| **사용자 수준 버퍼** | **모두 Flush함**                  | **비우지 않음** (출력 데이터가 유실될 수 있음)     |
| **종료 핸들러**    | `atexit`, `on_exit`로 등록된 함수 호출 | **호출하지 않고 종료**                    |
| **임시 파일 정리**  | 표준 I/O 스트림(tmpfile 등)을 닫고 정리함  | 정리 작업 없이 종료                       |
> Flush: 화면에 printf등으로 버퍼의 모든 내용을 출력해 비운다.

> main함수 끝: 무조건 `exit()`
> **자식 프로세스를 종료할 땐: `_exit()`**를 부모가 가진 I/O 버퍼 내용을 자식이 중복해서 출력하는 문제를 막기위해 써야한다.


| **함수**          | **핵심 설명 및 차이점**                                                                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`exit()`**    | **정상 종료 (Standard C):** 모든 I/O 버퍼를 비우고(Flush) 즉 화면에 printf등으로 버퍼의 모든 내용을 출력하고, 등록된 핸들러(`atexit` 혹은 `on_exit`)를 실행한 뒤 마지막에 `_exit()`를 호출하여 커널에 실제 종료를 알립니다. |
| **`_exit()`**   | **즉시 종료 (System Call):** 핸들러 호출이나 버퍼 정리 없이 커널이 즉시 자원을 회수합니다. 보통 `fork()` 후 자식 프로세스 종료 시 사용합니다.                                                             |
| **`atexit()`**  | **종료 작업 예약:** 프로세스 종료 시 자동으로 실행될 함수, 핸들러를 등록합니다. (인자 전달 불가, LIFO 구조)                                                                                       |
| **`on_exit()`** | **확장형 예약:** 종료 상태값(status)과 사용자 지정 인자를 핸들러에 전달할 수 있는 GNU 확장 함수입니다. (어떤 상태로 종료(`exit` 인자값)되는지 핸들러가 알 수 있습니다.)                                               |

## 2. exec 함수군: "exec 성공 = 돌아오지 않는 강을 건넘"

현재 프로세스의 메모리공간을 **새로운 실행 파일로 완전히 덮어쓰는** 함수들입니다. 호출이 성공하면 기존코드의 하단 부분을 진행하지 않습니다. 실패했을 때만 돌아와 하단 코드들이 실행됩니다.

| **접미사**               | **설명**                                                           |
| --------------------- | ---------------------------------------------------------------- |
| **`l` (List)**        | 인자를 List(나열되게)으로 하나씩 직접 전달합니다. list이므로 마지막은 반드시 `NULL`로 끝나야 합니다. |
| **`v` (Vector)**      | 인자를 배열(Vector/Array)에 담아서 통째로 전달합니다.  (인자 개수가 유동적일때 유리)          |
| **`p` (Path)**        | 실행 파일을 찾을 때 환경 변수 `PATH`를 참조합니다. (경로 없이 파일명만 써도 됨)               |
| **`e` (Environment)** | 새로운 프로그램에 부모의 환경 변수 대신 환경 변수를 직접 지정할 수 있습니다.                     |



**[함수 조합 예시]**

- **`execlp("ls", "ls", "-al", NULL);`**
    - `p`: `PATH`에서 `ls` 위치 검색.
    - `l`: 인자를 나열하여 전달.
	    - `l` 계열 함수를 쓸 때는 인자 리스트의 끝에 반드시 `NULL`을 넣어 컴퓨터에게 "여기까지가 인자다"라고 알려줘야 합니다.
- **`execve("/bin/ls", argv, envp);`**
    - 기본 시스템 콜 형태.
    - `v`: 배열로 인자 전달.
    - `e`: 사용자 정의 환경 변수 적용.

---
### 실무 보안 및 환경 상식

1. **ls는 실행 파일이다:** `execlp("ls", …)`를 호출하는 것은 `/bin/ls` 경로에 있는 실행 파일을 실행하는 것입니다.
2. **PATH의 중요성:** `p`가 붙은 함수는 시스템 설정(`$PATH`)에 등록된 디렉터리만 뒤집니다. 보안상의 이유로 **현재 디렉터리(`.`)는 기본 검색 대상에서 제외**되는 경우가 많습니다.
    
    - `execlp("my_prog", …)` → **실패** (PATH에 없으므로)
    - `execl("./my_prog", …)` → **성공** (상대 경로로 직접 지칭)
        
3. **상속되는 정보:** `exec`를 해도 **PID, PPID, 현재 작업 디렉터리(CWD), 열려 있는 파일 디스크립터** 등은 그대로 유지됩니다. 그래서 `ls`가 현재 폴더의 내용을 출력할 수 있는 것입니다.

## 3. 프로세스 동기화: 부모-자식 조율 (표 7-4)

부모 프로세스가 자식 프로세스의 종료를 기다리고, 자식이 남긴 **종료 상태값(Exit Status)** 을 받아줘야합니다 이를 하지 않으면 자식은 **좀비 프로세스(Zombie Process)**가 됩니다.

|**함수**|**핵심 기능 및 활용**|
|---|---|
|**`wait()`**|자식 프로세스 중 **어느 하나라도** 종료될 때까지 부모를 대기(Block)시킵니다. **좀비 프로세스 방지**의 핵심입니다.|
|**`waitpid()`**|특정 `PID`를 가진 자식을 지정해서 기다릴 수 있습니다. `WNOHANG` 옵션을 주면 자식이 안 끝났어도 부모가 자기 할 일을 계속하는 **비차단 모드**가 가능합니다.|
|**`waitid()`**|`waitpid`보다 더 세밀한 제어(프로세스 그룹 단위 대기 등)가 필요할 때 사용하는 현대적인 함수입니다.|

## 🏁 요약: 프로세스 생명 주기 흐름도

1. **`fork()`**: 부모와 똑같은 복제본 자식을 생성합니다.
	- **부모에게 전달되는 정보:** 자식의 PID 이를 통해 부모는 "내가 낳은 자식이 누구인지" 알게 됩니다.
	- **자식에게 전달되는 정보:** 숫자 `0`. 그래서 0일때 조건문으로 자식이 수행할 작업을 프로그래밍한다.
2. **`exec()` 계열**: 자식이 복제본 코드를 버리고 새로운 프로그램으로 탈바꿈합니다.
3. **`exit()`**: 자식이 업무를 마치고 종료 상태값을 남기며 사라집니다.
4. **`wait()`**: 부모가 자식의 종료를 확인하고 시스템 자원을 완전히 정리해줍니다.
