## 📌 파이프(Pipe) 프로세스 간 통신 핵심 요약

### 1. 파이프 생성과 파일 기술자(FD) 공유

- `pipe(fd)` 호출 시 커널에 파이프가 생성되며, 두 개의 파일 기술자가 할당됩니다.
    - `fd[0]`: **읽기(수신) 전용** 포트
    - `fd[1]`: **쓰기(전송) 전용** 포트
- **복사 메커니즘**: 파이프 생성 후 `fork()`를 실행하면, 자식 프로세스는 부모의 메모리를 그대로 복사하므로 **동일한 파일 기술자(`fd[0]`, `fd[1]`)를 공유**하게 됩니다.
    

### 2. 하나의 파이프로 양방향 통신이 불가능한 이유

- 파이프는 데이터의 **송신자를 구별하지 못합니다.**
- 하나의 파이프로 부모와 자식이 번갈아 쓰려고 하면, 자기가 쓴 데이터를 자기가 다시 읽는 **자가 수신 오류**나 양쪽 모두 대기 상태에 빠지는 데드락(Deadlock)이 발생합니다.
- 따라서 파이프는 본질적으로 **단방향(Half-Duplex) 통신**이며, 한쪽이 '쓰기'를 하면 반대편은 '읽기'만 가능합니다.
    

### 3. 올바른 양방향 통신 구현 (파이프 2개 개설)

서로 데이터를 주고받는 완전한 양방향 통신을 원할 때는 반드시 **2개의 파이프를 독립적으로 생성**해야 합니다.

1. **파이프 A**: 부모 $\rightarrow$ 자식 전송용 통로
2. **파이프 B**: 자식 $\rightarrow$ 부모 전송용 통로
    

### 4. 혼선 방지를 위한 파일 기술자 정리 (`close`)

데이터 꼬임과 오동작을 막기 위해, 통신 방향이 결정되면 **사용하지 않는 파일 기술자는 반드시 `close()`로 닫아주어야 합니다.**

- **부모 $\rightarrow$ 자식 단방향 통신 시 FD 정리 규칙**:
    - **부모 프로세스**: 읽기 용도인 `fd[0]`를 닫고(`close`), 쓰기 용도인 **`fd[1]`만 사용**
    - **자식 프로세스**: 쓰기 용도인 `fd[1]`을 닫고(`close`), 읽기 용도인 **`fd[0]`만 사용**
        

**💡 시험 출제 팁:** 서술형 문제에서 "파이프 통신 시 `close()`를 호출해야 하는 이유"를 묻는다면 "프로세스 간 데이터 혼선을 방지하고, 읽기/쓰기 종단(End of File)을 명확히 하여 블로킹(멈춤) 현상을 막기 위함"이라고 답변하시면 완벽합니다.

- **프로세스 간 복사와 단방향 통신**:
    - 파이프를 생성한 후 `fork()` 함수를 수행하여 자식 프로세스를 생성하면, 자식 프로세스는 부모의 메모리를 그대로 복사하므로 동일한 파일 기술자(`fd[0]`, `fd[1]`)를 가지게 됩니다.
    - 파이프는 데이터의 송신자를 구별하지 못하므로, 하나의 파이프로 번갈아 쓰려고 하면 오류가 난다 그래서 **단방향(Half-Duplex) 통신**이므로, **한쪽 프로세스가 데이터를 '전송(쓰기)'하면 반대편 프로세스는 '수신(읽기)'만 가능**하다
    - 서로 주고받는 양방향 통신을 원할시엔 **파이프를 2개 생성**해야 합니다.
		1. 부모 -> 자식 전송용
		2. 자식 -> 부모 전송용
    - 부모와 자식 프로세스 간에 혼선이 생기지 않도록 파일 기술자들을 정리(`close`)해야 합니다.
    - **부모 $\rightarrow$ 자식 통신 시**: 부모 프로세스는 읽기 용도인 `fd[0]`를 닫고(`close`) 쓰기 용도인 `fd[1]`만 사용합니다. 반대로 자식 프로세스는 쓰기 용도인 `fd[1]`을 닫고 읽기 용도인 `fd[0]`만 사용하여 통신을 이룹니다.


### 1-2. 이름 있는 파이프 (Named Pipe, FIFO)

- **특징**: FIFO라고도 불리는 이름 있는 파이프는 파일 시스템에 물리적으로 존재하며 `p`라는 기호로 나타납니다.
- 터미널에서 `ls -F` 옵션으로 확인해 보면 파일명 뒤에 파이프를 나타내는 기호(`|`)가 붙어서 출력되는 것을 볼 수 있습니다.
- 일반 파이프와 마찬가지로 단방향 통신을 하며, **저수준 파일 입출력 방식**인 `read()`와 `write()` 함수를 이용하여 통신하게 됩니다.

## 2. System V IPC (메시지 큐, 공유 메모리, 세마포어)

### 2-1. IPC의 계보 및 개요

- 역사적으로 BSD 계열의 유닉스에서 인터넷 및 네트워크 통신 프로토콜을 개발했다면, **System V(시스템 5) 계열 유닉스**에서는 내부 프로세스 간 통신인 **IPC(Inter-Process Communication)** 형태를 발전시켰습니다. 요즘은 인터넷이 대세이므로 BSD 계열의 판정승이라 볼 수도 있지만, 리눅스를 포함한 현대 OS는 System V IPC 기법도 완벽히 동시 제공합니다.
- System V IPC의 3대 핵심 요소는 메시지 큐(Message Queue), 공유 메모리(Shared Memory), 세마포어(Semaphore)입니다.
    

### 2-2. IPC 객체 제어의 핵심: 키(Key)와 식별자(ID)

- IPC 객체들을 사용하려면 시스템 내부적으로 객체를 생성해야 하는데, 이때 핵심 요소가 바로 키(Key)와 식별자(ID)입니다.
- **부모-자식 프로세스 간**: 굳이 파일 이름이 필요 없고, 상수로 `IPC_PRIVATE`을 지정하여 프라이빗하게 공유할 수 있습니다. 이 경우에는 키 생성 함수인 `ftok()`을 쓸 필요가 없습니다.
- **서로 다른 독립된 프로세스 간**: 공통의 객체에 접근해야 하므로, 시스템에 실제 존재하는 특정 파일의 경로명(Pathname)과 임의의 숫자(프로젝트 ID)를 조합하여 동일한 키를 만들어냅니다. 이때 사용하는 함수가 `ftok()`입니다.
- 서버와 클라이언트가 같은 경로명과 숫자를 지정하면 동일한 식별자를 얻어 통신할 수 있습니다.
- **보안 문제**: 이 키 값을 설정 파일 등에 저장해 공유하곤 하는데, 만약 해킹 프로그램이나 의도치 않은 다른 프로세스가 이 키를 알아내면 메시지를 가로채거나 훔쳐볼 수 있으므로 철저한 관리가 필요합니다.
- **관리 명령**: 시스템 내에서 가동 중인 IPC 상태를 확인하는 명령어로 `ipcs`가 있으며, 자원을 직접 삭제하는 **`ipcrm`** 명령어 등이 제공됩니다.
    

### 2-3. IPC 3대 요소별 특징

1. **메시지 큐 (Message Queue)**: 파이프와 유사하지만, 파이프가 시냇물처럼 경계 없이 데이터를 보내는 스트림(Stream) 기반이라면 메시지 큐는 메시지 단위(패킷 단위)로 동작합니다. 마치 우편함에 편지를 하나씩 넣고 읽어내는 방식과 같습니다.
2. **공유 메모리 (Shared Memory)**: 한 프로세스의 메모리 일부 영역을 다른 프로세스와 공유하는 방식입니다. 독립된 두 프로세스가 동일한 물리 메모리 공간을 매핑하여 직접 쓰고 읽으므로 IPC 방식 중 속도가 가장 빠릅니다.
3. **세마포어 (Semaphore)**: 여러 프로세스가 동시에 공유 메모리에 데이터를 읽고 쓰다 보면 데이터 오염이나 손실이 발생할 수 있습니다. 이를 방지하기 위해 프로세스 간 동기화(Synchronization) 및 순서를 제어해 주는 기법입니다. 통신 수단이라기보다는 임계 영역(Critical Section) 진입 통제 장치입니다. 운영체제 커널이 프로세스들에게 한정된 자원을 분배하고 회수할 때도 이 개념을 씁니다.
    

### 2-4. 세마포어의 작동 원리 (P 함수와 V 함수)

세마포어는 네덜란드 컴퓨터 과학자 다익스트라가 제안한 P 함수(Wait/Lock)와 V 함수(Signal/Unlock)라는 기본 개념으로 동작합니다.

- **P 함수 (잠금 단계)**: 크리티컬 섹션(중요 처리 영역)에 들어가기 전에 문을 잠그는 역할입니다. 세마포어의 초기 설정값이 보통 1인데, P 함수는 세마포어 값이 0이 아닐 때 값을 1 감소시켜 0으로 만들고 안으로 진입합니다. 만약 값이 이미 0이면 다른 프로세스가 문을 열어줄 때까지 대기(Wait)합니다.
- **V 함수 (해제 단계)**: 처리를 끝내고 나오면서 잠금을 해제하는 역할입니다. 세마포어 값을 다시 1 증가시키고, 자원이 해제되었음을 친절하게 알려줍니다. 만약 대기 큐(Queue)에서 기다리고 있는 프로세스가 있다면 첫 번째 프로세스를 깨워줍니다(`Wakeup`).

## 3. 네트워크 소켓 프로그래밍 (Socket Programming)

### 3-1. 네트워크 구조 모델 (ISO 7 Layer $\rightarrow$ TCP/IP 4 Layer)

- 네트워크를 처음 공부할 때 ISO 7 계층(Seven Layer)을 마주하면 어렵다는 선입견이 생기지만, 이를 이해하면 네트워크가 재미있어집니다.
- 현대 인터넷 표준인 **TCP/IP 모델**에서는 이 7개 계층을 **4개(또는 5개) 계층**으로 압축하여 사용합니다. (대세는 4계층 모델)
- **하위 계층 (네트워크 접속 및 하드웨어 계층)**: 유선 랜(LAN), 무선 랜(Wi-Fi), 랜 카드 컨트롤 등 물리적인 연결을 관장합니다.
- **네트워크 계층 (인터넷 계층)**: 패킷이 전달되는 복잡한 경로를 담당하며, 라우터(Router) 장비가 이 계층에서 동작합니다. 대표적인 프로토콜로 **`IP`**, `ARP`, `ICMP` 등이 있습니다. (네트워크 설계 실습 등에서 주로 다룸)
- **전송 계층 (Transport Layer)**: 하나의 컴퓨터 안에서 신뢰성 있는 데이터 전송을 관장하며, `TCP`와 **`UDP`** 프로토콜이 여기에 속합니다.
- **응용 계층 (Application Layer)**: 사용자에게 직접 서비스를 제공하는 최상위 계층입니다. 웹 브라우저(`HTTP`), 이메일(`SMTP`), 호스트명을 IP로 바꿔주는 **`DNS`**, 파일 송수신의 `FTP` 등이 있습니다.
- ※ _주의: 이 5대/4대 계층 분류는 네트워크 리뷰이므로 시스템 프로그래밍 시험 문제로 깊게 출제되지는 않으나, 개념적으로는 반드시 파악하고 있어야 합니다._
    

### 3-2. 전송 계층 핵심 프로토콜 비교 (기말고사 필수)

우리가 작성하는 서버/클라이언트 응용 프로그램은 이 전송 계층의 도움을 받아 통신하므로 TCP와 UDP의 차이를 명확히 알아야 합니다.

|**특징**|**TCP (Transmission Control Protocol)**|**UDP (User Datagram Protocol)**|
|---|---|---|
|**연결 방식**|연결 지향형 (전화 걸 때처럼 사전 연결 필요)|비연결형 (사전 연결 설정 없음)|
|**신뢰성**|**높음** (패킷 수신 확인, 재전송, 속도 제어 수행)|**낮음** (수신 확인 안 함, 분실 시 책임 안 남)|
|**상수 표현**|`SOCK_STREAM` (스트림 방식)|`SOCK_DGRAM` (데이터그램 방식)|
|**주 용도**|신뢰성이 중요한 일반 데이터 통신|데이터 유실 감수하더라도 속도가 중요한 서비스|

### 3-3. 네트워크 주소 체계 (IP 주소와 포트 번호)

- **소켓(Socket)의 정의**: **IP 주소와 포트(Port) 번호를 결합한 것**이 곧 소켓입니다. 소켓 인터페이스는 응용 프로그램과 TCP 계층을 연결하는 API 창구 역할을 하므로, 내부의 복잡한 패킷 구조를 신경 쓰지 않고 통신 앱을 만들 수 있게 해줍니다.
- **IP 주소**: 컴퓨터 고유의 물리적 주소입니다. 32비트 숫자(IPv4)로 표현되며 주소를 외우기 어렵기 때문에 수원대학교(`suwon.ac.kr`), `.net`, `.com` 같은 호스트명 및 도메인명을 사용합니다.
- **DNS와 etc/hosts**: 리눅스는 URL 주소를 찾을 때 먼저 내부 파일인 `/etc/hosts`를 뒤지고, 거기에 정보가 없다면 전역 관리 시스템인 DNS 서버에 조회를 요청합니다. 이 조회 순서는 시스템 내부 설정 파일에 지정되어 있습니다.
- **포트 번호 (Port Number)**: IP 주소가 '특정 컴퓨터'를 찾아간다면, 컴퓨터 안에서 동시에 실행 중인 여러 통신 프로세스(웹브라우저, 카카오톡, 유튜브 등) 중 '어떤 프로세스에 메시지를 전달할지 구별하는 번호'입니다.
    - 16비트 정수 형태를 지니며 범위는 `0 ~ 65535`입니다.
    - **0 ~ 1023 (Well-known Ports)**: 이미 잘 알려진 응용 프로그램이 선점한 포트이므로 프로그램 작성 시 사용하면 안 됩니다. (예: SSH는 22번, HTTP 웹은 80번). 이 목록은 `/etc/services` 파일에 등록되어 있습니다.
    - **1024 ~ 65535**: 우리가 일반적인 프로그래밍 실습 시 자유롭게 사용할 수 있는 포트 범위입니다.
        

### 3-4. 바이트 순서 (Byte Order)

- 컴퓨터가 메모리에 숫자를 저장하는 방식은 빅 엔디언(Big-Endian)과 리틀 엔디언(Little-Endian)으로 나뉩니다.
- 인텔 계열 프로세서는 뒤의 바이트를 메모리 앞에 먼저 저장하는 리틀 엔디언(`HBO`: Host Byte Order)을 사용하는 반면, **네트워크 통신 규격은 무조건 빅 엔디언(`NBO`: Network Byte Order)으로 고정**되어 있습니다.
- 따라서 통신으로 데이터를 송수신할 때는 호스트 바이트 순서를 네트워크 바이트 순서로 변환해 주는 엔디언 변환 함수(`htons`, `ntohs`, `htonl`, `ntohl`)를 반드시 호출해야 프로그램의 호환성이 유지됩니다.
    

### 3-5. 소켓 인터페이스 10대 핵심 함수 및 호출 순서 (★무조건 출제)

서버와 클라이언트 프로그램이 실행될 때 각 함수가 호출되는 전체 메커니즘과 플로우 차트를 통째로 외워야 합니다. 빈칸 채우기 형식으로 출제될 가능성이 매우 높습니다.

#### 1) 핵심 함수 10가지 요약

- `socket()`: 서버와 클라이언트 공통으로 소켓 파일 기술자를 최초 생성합니다.
- `bind()`: **[서버 전용]** 생성된 소켓에 특정 IP 주소와 포트 번호를 결합합니다.
- `listen()`: **[서버 전용]** 클라이언트의 연결 요청을 받을 준비를 마쳤음을 커널에 알리고 대기 상태로 들어갑니다.
- `accept()`: **[서버 전용]** 클라이언트의 연결 요청을 최종적으로 수락합니다. (성공 시 통신용 소켓 새로 반환)
- `connect()`: **[클라이언트 전용]** 지정한 서버의 IP와 포트로 접속 요청을 보냅니다. 서버의 `accept()`와 맞물려 성공 시 통신이 개시됩니다.
- `send()` / `recv()`: TCP 연결 모드에서 데이터를 송수신합니다.
- `sendto()` / `recvfrom()`: UDP 비연결 모드에서 상대방 주소를 지정해 데이터를 송수신합니다.
- `close()`: 통신이 끝난 후 소켓 자원을 정리하고 종료합니다.
