## Topic. 구조체 배열과 포인터 (Struct Array & Pointer)

구조체 문법의 핵심은 **"지금 다루는 것이 실체(Value)인가, 주소(Address)인가?"**를 파악하는 것입니다. 이 선언 형태가 접근 연산자, 메모리 관리, 그리고 연산 방식 전체를 지배합니다.

### 1. 🚦 핵심 원칙: 선언이 연산자를 결정한다

변수가 메모리에 존재하는 **데이터 덩어리**인지, 그것을 가리키는 **참조자**인지에 따라 사용하는 연산자가 달라집니다.

| **기준**     | **Case A: 구조체 변수 (Value)**           | **Case B: 구조체 포인터 (Address)**                            |
| ---------- | ------------------------------------ | -------------------------------------------------------- |
| **선언 형태**  | **`struct [타입] c;`**                 | **`struct [타입] *p;`**                                    |
| **성격**     | 데이터 덩어리 (실체)                         | 메모리 주소값 (참조)                                             |
| **접근 연산자** | **점 (`.`)**                          | **화살표 (`->`)**                                           |
| **접근 방식**  | **Direct Access**<br>(Base + Offset) | **Indirect Access**<br>(Dereference $\to$ Base + Offset) |
| **코드 예시**  | `c.num = 1;`                         | `p->num = 1;`                                            |

> **Note:** `p->num`은 `(*p).num`의 **문법적 설탕(Syntactic Sugar)**입니다. **역참조(`*`) 후 멤버 접근(`.`)**을 수행하는 과정을 기호 하나로 축약한 것입니다

---

### 2. 🏗️ 메모리 구조와 크기 (Memory & Size)

#### ① 오개념 경계: 포인터 크기의 불변성

> **"구조체 덩어리가 커지면, 포인터 변수의 크기도 커지는가?" $\to$ NO!**

- **구조체 포인터:** 구조체 멤버가 아무리 많아도(100Byte든 1GB든), 포인터는 **'시작 주소'**만 담으므로 크기가 고정됩니다.
    - **32bit 시스템:** 4 Byte
    - **64bit 시스템:** 8 Byte

#### ② 배열 선언 시 메모리 배치 비교

다음 선언이 있다고 가정할 때:

```C
struct Card {
    char *name; // 4 bytes (32bit)
    int num;    // 4 bytes
}; // Total size: 8 bytes
```

1. **구조체 배열 (`struct Card deck[20];`)**로 선언
    
    - **내용:** 실제 구조체 덩어리 20개.
    - **할당:** $8 \text{ Bytes} \times 20 = 160 \text{ Bytes}$가 **물리적으로 연속 할당**됩니다.
    - **접근:** `deck[0].name`, `deck[1].name` (인덱스로 접근)
        
2. **구조체 포인터 (`struct Card *ptr;`)**로 선언
    - **내용:** 주소값 1개.
    - **할당:** **4 Byte** (주소 저장용)만 할당됩니다. 가리킬 대상(실체)은 별도로 존재해야 합니다.
    - **접근:** `ptr->name`

### 3. ⚠️ 문법: 연산자 우선순위 (Operator Precedence)

포인터 연산 실수 1위 영역입니다. **점(`.`)과 화살표(`->`)는 별(`*`)보다 강력합니다.**

|**순위**|**연산자**|**설명**|**결합 방향**|
|---|---|---|---|
|**1순위**|`.` `->` `()` `[]`|**멤버 접근**, 함수, 인덱스|좌 $\to$ 우|
|**2순위**|`*` `++` `--` `&`|**역참조**, 증감, 주소|**우 $\to$ 좌**|

#### 접근 문법 정리

- **❌ 틀린 표현:** `*k.name`
    - 해석: `*(k.name)` $\to$ `k`는 포인터인데 점이 `*`보다 먼저 실행되어 주소가 아닌 멤버를 역참조하려 함
- **✅ 맞는 표현:** `(*k).name`
    - 해석: `k`를 먼저 역참조하여 실체를 구한 뒤(`.`) 멤버에 접근.
- **⭐ 추천 표현:** **`k->name`**
    - `(*k).`을 축약한 직관적인 문법

---

### 4. ⚔️ 실무 패턴: 임시 포인터 활용 (Iterator Strategy)

배열을 포인터로 순회(`ptr++`)할 때 가장 중요한 원칙은 **"원본 시작 주소(Head)를 잃어버리지 않는 것"**입니다.

- **Bad Case:** `head` 자체를 `++` 해버리면 리스트의 처음으로 돌아갈 수 없습니다.
- **Good Case:** `head`는 고정하고, `cur`를 복사해서 움직입니다.

```C
struct Card deck[3];          // [실체]
struct Card *head = deck;     // [Anchor] 기준점 (이동 금지)
struct Card *cur = head;      // [Cursor] 순회용 (복사본)

// cur가 움직여도 head는 0번 인덱스를 계속 가리킴
while(cur->name != NULL) {
    printf("%s", cur->name);
    cur++; 
}
```

### 5. 🔍 심화: 복합 연산 정복 (Value vs Pointer)

이 예시를 이해하기 위해서는 **메모리 선언 상태**가 전제되어야 합니다.

#### 📝 시나리오 설정 (Declaration)

```C
// [전제 상황]
char str_buf[] = "Alice";  // 수정 가능한 문자열 배열 (주소: 0x100 ~ )
struct Card c = { str_buf, 1 }; 
struct Card *d = &c;       // d는 c를 가리키는 포인터
```

이제 `d->name`은 `0x100`("Alice"의 'A')을 가리키고 있습니다.

#### (1) `*(d->name++)` : 포인터 이동 (Traversing)

> **"현재 글자를 읽고, 포인터를 다음 칸으로 이동하라"**

1. **`d->name`**: `d`가 가리키는 멤버 `name`(주소 `0x100`)에 접근.
2. **`++` (후위)**: `name`이 가진 **주소값**을 `0x101`로 증가 예약.
3. **`*` (역참조)**: 증가 전 주소(`0x100`)에 있는 값 **'A'**를 반환.
4. **결과 반영**: 연산 후 `d->name`은 이제 `'l'`(`0x101`)을 가리킴.
    
    - **용도:** 문자열을 한 글자씩 순서대로 읽을 때 사용.
        

#### (2) `(*d->name)++` : 값 변경 (Modifying)

> **"현재 위치의 글자 자체를 +1 하라"**

1. **`d->name`**: `d`가 가리키는 멤버 `name`(주소 `0x100`)에 접근.
2. **`*` (역참조)**: 우선순위 괄호`()`로 인해 먼저 역참조 $\to$ 값 **'A'**를 가져옴.
3. **`++` (후위)**: 가져온 문자 값 'A'(65)를 **'B'(66)**로 변경.
4. **결과 반영**: 메모리의 `str_buf` 내용이 `"Alice"` $\to$ **`"Blice"`**로 영구 변경됨. 주소 위치는 그대로 `0x100`.
    
    - **용도:** 데이터 자체를 조작(암호화, 대소문자 변환 등)할 때 사용.
