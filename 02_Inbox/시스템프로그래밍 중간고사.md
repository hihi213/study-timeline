### 📝 연습 문제 06

> [!question] 문제 06
> 시스템 호출과 라이브러리 함수의 차이점을 동작 과정 비교를 통해 설명하시오.

> [!check]- 정답 및 해설
> >
> **1. 기본 개념 차이**
> * **시스템 호출 (System Call)**: 운영체제의 **커널(Kernel)**이 제공하는 서비스에 접근하기 위한 인터페이스입니다. 하드웨어 제어 등 특권 권한이 필요한 작업을 수행합니다.
> * **라이브러리 함수 (Library Function)**: 프로그래밍 언어에서 제공하는 공통 함수들의 집합(예: `libc`)으로, 미리 작성된 코드를 호출하여 사용합니다.
> 
> **2. 동작 과정 비교**
>
> | 구분 | 시스템 호출 | 라이브러리 함수 |
> | :--- | :--- | :--- |
> | **실행 모드** | **커널 모드 (Kernel Mode)**로 전환됨 | **사용자 모드 (User Mode)**에서 실행됨 |
> | **진입 방식** | 소프트웨어 인터럽트(Trap)를 통해 커널 진입 | 일반적인 함수 호출 방식을 따름 |
> | **성능** | 모드 전환(Context Switching) 비용으로 인해 상대적으로 느림 | 모드 전환이 없어 상대적으로 빠름 |
> | **커널 의존성** | 커널에 직접 요청하여 수행 | 일부 함수는 내부적으로 시스템 호출을 사용하지만, 아닌 경우도 있음 |
>
> **3. 예시**
> * **라이브러리 함수**: `printf()`, `strlen()`, `malloc()`
> * **시스템 호출**: `write()`, `read()`, `fork()`, `exit()`
> * *참고: `printf()` 라이브러리 함수는 내부적으로 화면 출력을 위해 `write()` 시스템 호출을 이용합니다.*

### 💻 실습 과제 10

> [!question] 실습 과제 10
> [예제 1-1]을 수정해 `errno` 번호뿐만 아니라 오류 메시지도 출력되도록 코드를 수정하시오. (ex1_10.c)
>
> **<힌트>**
> 1. `perror()`와 `strerror()` 함수를 이용한다.
> 2. `strerror()` 함수를 사용하기 위해서 `<string.h>` 파일을 include 한다.

> [!check]- 정답 및 해설 (코드 구현)
>
> ```c
> #include <stdio.h>
> #include <errno.h>    // errno 변수 사용을 위해 필요
> #include <string.h>   // strerror() 함수 사용을 위해 필요
> #include <fcntl.h>    // open() 함수와 O_RDONLY 상수를 위해 필요
> #include <unistd.h>
> 
> int main() {
>     int fd;
> 
>     // 존재하지 않는 파일을 열어 오류 강제 발생
>     if ((fd = open("test.txt", O_RDONLY)) == -1) {
>         // 1. errno 번호 출력
>         printf("errno=%d\n", errno);
> 
>         // 2. perror() 사용: 인자로 전달한 문자열 뒤에 콜론(:)과 오류 메시지 자동 출력
>         perror("ex1_10.c");
> 
>         // 3. strerror() 사용: errno 번호를 인자로 받아 해당 오류 문자열 반환
>         printf("test.txt: %s\n", strerror(errno));
>     }
> 
>     return 0;
> }
> ```
>
> **해설:**
> * **`perror(const char *s)`**: 사용자가 정의한 문자열(`s`)을 먼저 출력하고, 현재 `errno`에 해당하는 시스템 오류 메시지를 표준 오류(stderr)로 출력합니다.
> * **`strerror(int errnum)`**: `errno` 번호를 넘겨주면 그에 해당하는 오류 메시지 문자열을 리턴해줍니다. 이걸 문자열타입으로 받아서 자유롭게 수정이 가능하다.

### 📝 연습 문제 11

> [!question] 문제 11
> `gcc`로 소스 코드를 컴파일해 실행 파일인 `ex11.exe`를 만들었다. `ls` 명령으로 확인하면 `ex11.exe`가 보이는데, `ex11.exe`를 실행하면 파일을 찾을 수 없다고 한다. 무엇이 문제이고 어떻게 해결할 수 있는지 설명하시오.

> [!check]- 정답 및 해설
> **정답: 현재 디렉터리가 `PATH` 환경 변수에 포함되어 있지 않기 때문이며, `./ex11.exe`와 같이 경로를 명시하여 실행해야 합니다.**
>
> **해설:**
> * **원인:** 리눅스/유닉스 쉘은 명령어를 입력받으면 `PATH` 환경 변수에 등록된 디렉터리들을 순서대로 검색하여 실행 파일을 찾습니다. 보안상의 이유로 현재 디렉터리(`.`)는 기본적으로 `PATH`에 포함되지 않습니다. 따라서 파일이 현재 위치에 있더라도 이름만 입력하면 쉘은 이를 찾지 못해 "명령어를 찾을 수 없음(command not found)" 또는 "파일을 찾을 수 없음" 메시지를 출력합니다.
> * **해결 방법:** > 1. **상대 경로 사용**: 현재 디렉터리를 의미하는 `./`를 파일명 앞에 붙여 **`./ex11.exe`**라고 입력합니다.
>     1. **절대 경로 사용**: 파일의 전체 경로(예: `/home/ubuntu/Source/ch1/ex11.exe`)를 입력합니다.
>     2. **PATH 수정**: 권장되지는 않지만, `PATH=$PATH:.` 명령으로 현재 디렉터리를 경로에 추가할 수도 있습니다.

### 📝 연습 문제 12

> [!question] 문제 12
> 프로그램 프로그램 실행하는 도중에 정수값 200개를 저장할 수 있도록 메모리를 할당하려면 어떻게 해야 할까?

> [!check]- 정답 및 해설
> **정답: `malloc()` 또는 `calloc()` 함수를 사용하여 동적 메모리 할당을 수행합니다.**
>
> **해설:**
> * **동적 메모리 할당**: 프로그램 실행 중(Runtime)에 필요한 메모리 크기를 결정하여 힙(Heap) 영역에 할당받는 방식입니다.
> * **구현 예시**:

>   ```
> * 사용이 끝난 메모리는 반드시 `free(ptr);`를 호출하여 해제해야 메모리 누수(Memory Leak)를 방지할 수 있습니다.

### 💻 실습 과제 13

> [!question] 실습 과제 13
> [예제 1-3]에서 인자로 받은 두 정수의 뺄셈을 계산해 리턴하는 `subnum()` 함수를 `subnum.c` 파일로 만들고 `Makefile`을 수정해 실행 파일을 생성한 뒤 실행 결과를 확인하시오. (실행파일: ex1_13.out)

> [!check]- 정답 및 해설 (코드 구현 및 빌드)
>
> **1. subnum.c 작성**
> ```c
> // subnum.c
> int subnum(int a, int b) {
>     return (a - b);
> }
> ```
>
> **2. main.c 수정 (extern 선언 추가)**
> ```c
> #include <stdio.h>
> 
> extern int addnum(int a, int b);
> extern int subnum(int a, int b);
> 
> int main() {
>     int ret;
>     ret = addnum(1, 5);
>     printf("Sum 1~5 = %d\n", ret);
>     ret = subnum(1, 5);
>     printf("1-5 = %d\n", ret);
>     
>     return 0;
> }
> ```
>
> **3. Makefile 수정 (빌드 규칙)**
> ```makefile
> # Makefile 예시
> ex1_13.out: main.o addnum.o subnum.o
> 	gcc -o ex1_13.out main.o addnum.o subnum.o
> 
> main.o: main.c
> 	gcc -c main.c
> addnum.o: addnum.c
> 	gcc -c addnum.c
> subnum.o: subnum.c
> 	gcc -c subnum.c
> 
> clean:
> 	rm -f *.o ex1_13.out
> ```
>
> **해설:**
> * **분할 컴파일**: 각 기능을 별도의 `.c` 파일로 나누어 작성하면 코드 관리가 용이해집니다. `gcc -c` 명령어로 각각의 목적 파일(`.o`)을 먼저 생성합니다.
> * **링킹(Linking)**: 생성된 여러 목적 파일들을 하나로 묶어 실행 파일(`ex1_13.out`)로 만드는 과정입니다.
> * **Makefile 활용**: 파일이 늘어날수록 수동 컴파일이 번거로워지므로, `make` 도구를 사용하여 변경된 파일만 효율적으로 재빌드할 수 있습니다.

> [!question] 실습 과제 08
> 현재 디렉터리를 기억하고 있다가 다른 디렉터리로 이동해 작업한 후 원래 디렉터리로 돌아오도록 프로그램을 작성하시오. (ex2_08.c)

>

> #include <stdio.h>

>

>     char origin_path[1024];
>     char current_path[1024];
> 
>     // 1. 원래 디렉터리 위치 기억 (getcwd)

>         perror("getcwd");
>         exit(1);
>     }

> 
>     // 2. 다른 디렉터리(suwon)로 이동 (chdir)

>         perror("chdir to suwon");
>         exit(1);
>     }
> 
>     // 3. 이동한 디렉터리 작업 수행 및 출력
>     getcwd(current_path, sizeof(current_path));
>     printf("** in dir: %s\n", current_path);

>         exit(1);

>     printf("2. dir=%s\n", current_path);

### 💻 실습 과제 09

> [!question] 실습 과제 09
> `getcwd()`와 `chdir()` 함수가 오류를 리턴할 때 처리하는 코드를 추가해 예제를 작성하시오. (ex2_09.c)

>

>

>     char buf[1024];

>         perror("chdir");
>         exit(1);

### 📝 연습 문제 06

> [!question] 문제 06
> 다른 파일 시스템에 있는 파일의 하드 링크를 생성하려면 어떤 오류 메시지가 발생하는지 확인하시오.

> [!check]- 정답 및 해설
> >
> **발생 오류 메시지:**
> `ln: '[파일명]' => '[경로]' 하드링크 만들기 실패: 명령을 허용하지 않음` (또는 영문 환경에서 `Invalid cross-device link`)
>
> **해설:**
> * **하드 링크의 제약**: 하드 링크는 동일한 파일 시스템 내의 **inode 번호**를 공유하는 방식입니다. inode 번호는 파일 시스템마다 독립적으로 관리되므로, 서로 다른 파일 시스템(예: 다른 파티션이나 외부 드라이브) 간에는 하드 링크를 생성할 수 없습니다.
> * **해결책**: 파일 시스템 경계를 넘어서 링크를 만들고 싶다면 **심볼릭 링크(Soft Link)**를 사용해야 합니다. 심볼릭 링크는 inode가 아닌 경로명을 저장하므로 파일 시스템의 제약을 받지 않습니다.
> * **오류 코드**: 시스템 내부적으로는 `EXDEV` 오류 코드가 발생합니다.

>         exit(1);
>     }
> 
>     // 3. 대상 파일 열기 (쓰기 전용, 없으면 생성, 있으면 초기화)
>     wfd = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);

>         perror("Dest Open");
>         close(rfd);
>         exit(1);
>     }
> 
>     // 4. 원본에서 읽어서 대상 파일에 쓰기 (Copy)
>     while ((n = read(rfd, buf, sizeof(buf))) > 0) {
>         if (write(wfd, buf, n) != n) { //읽어온만큼 같은 바이트

>             break;
>         }
>     }
> 
>     close(rfd);
>     close(wfd);

>         exit(1);
>     }
> 
>     // 2. 파일 열기 (고수준 입출력 fopen)

>         perror("fopen");
>         exit(1);
>     }
> 
>     // 3. fgetc를 사용하여 파일 끝(EOF)까지 한 글자씩 읽기

>             find = 1;
>             printf("Found = %c\n", (char)c);
>         }
>     }
> 
>     // 4. 검색 결과 확인
>     if (find == 0) {
>         printf("Not Found\n");
>     }
> 
>     fclose(fp);
>     return 0;
> }
> ```
>
> **해설:**
> * **`fgetc(FILE *fp)`**: 파일 포인터로부터 한 문자를 읽어 `int` 형으로 반환합니다. 파일의 끝에 도달하면 `EOF`(-1)를 반환합니다.

### 💻 실습 과제 07

> [!question] 실습 과제 07
> 사용자 이름을 입력받아 해당 사용자의 암호 변경 시간을 연, 월, 일 형태로 출력하는 프로그램을 작성하시오. (ex5_07.c)
> ※ `/etc/shadow` 파일은 root 권한으로만 읽을 수 있으므로 `sudo`로 실행시킬 것.

> [!check]- 정답 및 해설 (코드 구현)
>
> ```c
> #include <shadow.h>
> #include <stdio.h>
> #include <stdlib.h>
> #include <time.h>

>

>     }
> 
>     printf("Login Name : %s\n", spw->sp_namp);
>     printf("Last Change : %ld\n", spw->sp_lstchg);

>     // sp_lstchg는 1970-01-01(Epoch) 이후 경과한 '일수'임
>     // 초 단위로 변환 필요 (1일 = 24 * 60 * 60 초)

> 명령행 인자로 PID를 입력받아 해당 프로세스가 속한 프로세스 그룹 ID(PGID), 세션 ID(SID)를 출력하는 프로그램을 작성하시오. 명령행 인자로 지정한 PID가 0이면 현재 프로세스를 대상으로 PPID와 PGID, 세션 ID를 구한다. (ex6_07.c)

> [!check]- 정답 및 해설 (코드 구현)
>
> ```c
> #include <sys/types.h>
> #include <unistd.h>
> #include <stdio.h>
> #include <stdlib.h>
> 
> int main(int argc, char *argv[]) {
>     pid_t pid;
> 
>     if (argc != 2) {
>         fprintf(stderr, "Usage: %s PID\n", argv[0]);
>         exit(1);
>     }
> 
>     pid = (pid_t)atoi(argv[1]);
> 
>     // 1. 인자가 0인 경우 현재 프로세스 정보 출력
>     if (pid == 0) {
>         pid = getpid();
>         printf("PPID : %d\n", (int)getppid());
>     }
> 
>     // 2. 특정 PID(혹은 현재 PID)의 정보 출력
>     printf("PID : %d\n", (int)pid);
>     printf("PGID : %d\n", (int)getpgid(pid));
>     printf("SID : %d\n", (int)getsid(pid));
> 
>     return 0;
> }
> ```
>
> **해설:**
> > * **식별자 체계**:
> * **PID**: 프로세스 고유 번호.

> * **SID**: 로그인 세션 내의 모든 프로세스 그룹을 포함하는 상위 개념.
> * **함수 사용**: `getpgid(pid)`와 `getsid(pid)`는 인자로 넘겨준 특정 프로세스의 ID를 조회할 수 있게 해줍니다. 0번 인자를 넣었을 때 현재 프로세스의 `PPID`(부모 PID)를 함께 확인하는 것은 프로세스 계층도를 파악하기 좋은 연습입니다.

> [!question] 문제 01
> 다음과 같이 `fork()` 함수로 자식 프로세스를 생성했다. 이 중 자식 프로세스가 수행하는 부분은?
>
> ```c
> int main() {
>     pid_t pid;
>     switch (pid = fork()) {
>         case -1 :
>             printf("-1\n");
>             break;
>         case 1 :
>             printf("1\n");
>             break;
>         case 0 :
>             printf("0\n");
>             break;
>         default :
>             printf("default\n");
>             break;
>     }
> }
> ```
> ① case -1
> ② case 1
> ③ case 0
> ④ default

> [!check]- 정답 및 해설
> **정답: ③ case 0**
>
> **해설:**
> * `fork()` 함수는 호출 시 새로운 프로세스(자식)를 생성하며, 반환값에 따라 부모와 자식을 구분합니다.
>     * **0**: 자식 프로세스에게 반환됩니다.
>     * **0보다 큰 값 (자식의 PID)**: 부모 프로세스에게 반환됩니다.
>     * **-1**: 프로세스 생성 실패 시 반환됩니다.
> * 따라서 자식 프로세스는 `pid` 값이 `0`이 되므로 `case 0` 문을 수행하게 됩니다.

### 💻 실습 과제 06

> [!question] 실습 과제 06
> `fork()` 함수를 사용해 자식 프로세스에서는 현재 디렉터리의 절대 경로를 출력하고 부모 프로세스에서는 현재 디렉터리의 내용을 출력하는 프로그램을 작성하시오. (ex7_06.c)

> [!check]- 정답 및 해설 (코드 구현)
>
> ```c
> #include <sys/types.h>
> #include <sys/wait.h>
> #include <unistd.h>
> #include <stdlib.h>
> #include <stdio.h>
> 
> int main() {
>     pid_t pid;
> 
>     switch (pid = fork()) {
>         case -1 : /* fork 실패 */
>             perror("fork");
>             exit(1);
>             break;
>         case 0 : /* 자식 프로세스: pwd 실행 */
>             printf("Child Process - My PID:%d, My Parent's PID:%d\n", (int)getpid(), (int)getppid());
>             system("pwd");
>             printf("End of fork\n"); // 자식 프로세스의 종료 지점
>             exit(0);
>             break;
>         default : /* 부모 프로세스: ls 실행 */
>             printf("Parent process - My PID:%d, My Parent's PID:%d, My Child's PID:%d\n", (int)getpid(), (int)getppid(), (int)pid);
>             wait(NULL); // 자식이 끝날 때까지 대기하여 출력이 섞이지 않게 함
>             system("ls");
>             printf("End of fork\n"); // 부모 프로세스의 종료 지점
>             break;
>     }
>     return 0;
> }
> ```
>
> **해설:**
> * `fork()` 이후 `case 0`은 **자식**이 수행하며, `system("pwd")`를 통해 절대 경로를 출력합니다.
> * `default`는 **부모**가 수행하며, 자식의 PID를 알고 있습니다. `system("ls")`를 통해 디렉터리 목록을 출력합니다.
> * 실행 예시와 같이 출력이 깔끔하게 나오도록 `wait(NULL)`을 사용하여 부모가 자식의 작업 완료를 기다리게 구성할 수 있습니다.

### 💻 실습 과제 08

> [!question] 실습 과제 08
> 07번에서 생성한 자식 프로세스가 종료하기를 기다리도록 `waitpid()` 함수를 사용해 작성하시오. (ex7_08.c)

> [!check]- 정답 및 해설 (코드 구현)
>
> ```c
> #include <sys/types.h>
> #include <sys/wait.h>
> #include <unistd.h>
> #include <stdlib.h>
> #include <stdio.h>
> 
> int main() {
>     pid_t pid;
>     int status;
> 
>     switch (pid = fork()) {
>         case -1 : 
>             perror("fork");
>             exit(1);
>             break;
>         case 0 : /* 자식 프로세스 */
>             printf("--> Child Process\n");
>             if (execl("/usr/bin/who", "who", (char *)NULL) == -1) {
>                 perror("execl");
>                 exit(1);
>             }
>             break;
>         default : /* 부모 프로세스 */
>             printf("--> Parent process\n");
>             printf("Parent still wait…\n");
>             // 자식 프로세스(pid)가 종료될 때까지 대기
>             while (waitpid(pid, &status, WNOHANG) == 0) {
>                 // 자식이 종료되지 않았을 때 부모가 수행할 작업이 있다면 여기에 작성
>                 sleep(1); 
>             }
>             break;
>     }
>     return 0;
> }
> ```
>
> **해설:**
> * **`waitpid(pid, &status, options)`:**
>     * 첫 번째 인자로 기다릴 대상인 자식의 `pid`를 지정합니다.
>     * `WNOHANG` 옵션을 사용하면 자식 프로세스가 종료되지 않았어도 블로킹되지 않고 `0`을 반환하여 부모가 다른 작업을 병행할 수 있게 합니다. (실행 예시의 흐름을 맞추기 위해 사용 가능)
> * 이 코드를 통해 부모 프로세스는 자식이 `who` 명령 수행을 마칠 때까지 기다린 후 종료됩니다.
