## ⚡️ 코딩테스트 필살기 N의 크기와 '행동'에 따른 알고리즘 선택 가이드

> **💡 핵심 철학: 시간 복잡도의 진짜 의미**
> 시간 복잡도는 단순히 for 문을 몇 번 썼느냐가 아니라
  **"데이터 1개를 마주했을 때, 어떤 행동(Action)을 취하느냐"**, 즉 원소 하나가 겪는 사건의 총합으로 결정됩니다.

- O(1): 데이터를 쳐다보지도 않고 주소로 찾아감.
- $\log_2N$: 데이터를 다 보지 않고, 절반씩 버림.
- O(N): 데이터를 하나씩 성실하게 확인 함.
- 정렬함수 sort() 를 쓴다: $N\log_2N$ 확정
	- 그래서 정렬한번이라도 하면 $N\log_2N$으로 껑충 최고복잡도가 올라간다
	- 그렇다고 직접구현한다면 $N^2$ 으로 올라가니 구현은 하지 말자 (정렬함수는 최고의 개발자가 깍아만든 알고리즘..)

### 1. 🎯 N의 크기 & 본질적 행동 매핑 테이블

이 표는 $N$의 크기를 보고 $\rightarrow$ 내가 취해야 할 **행동(Action)**을 결정하는 지도입니다.

| **입력 크기 (N)**         | **허용 복잡도**      | **핵심 액션 (Intuition)**                        | **대표 알고리즘 및 도구**                            |
| --------------------- | --------------- | -------------------------------------------- | ------------------------------------------- |
| **제한 없음**             | $O(1)$          | **[즉시 접근]** 주소(key)로 바로                      | Hash Map/Set, 인덱스 접근, 상수 수학 공식(1부터 N까지 합 등) |
| **$10^9$ 이상** (10억)   | $O(\log N)$     | **[범위 좁히기]** 매번 절반씩 버리기                      | 이분 탐색(Binary Search), 유클리드 호제법              |
| **$10^7$ 이하** (1000만) | $O(N)$          | **[단순 순회]** 한 번씩만 훑기                         | 투 포인터, 슬라이딩 윈도우, Greedy, 1차원 DP             |
| **$10^6$ 이하**         | $O(N \log N)$   | **[정렬/분할]** 나누고($\log N$) 합치며 정렬($N$)하기      | Quick/Merge Sort, 우선순위 큐(Heap), Dijkstra    |
| **$2,000$ 이하**        | $O(N^2)$        | **[관계 확인]** 나와 나머지 모두를 비교                    | 2중 For문, 2차원 DP, BFS/DFS(인접 행렬)             |
| **$500$ 이하**          | $O(N^3)$        | **[3중 탐색]** 모든 경유지 거쳐 확인                     | 플로이드-워셜(Floyd-Warshall), 행렬 곱셈              |
| **$20$ 이하**           | $O(2^N), O(N!)$ | **[전수 조사]** 모든 경우의 수(뽑거나, 안뽑거나 / 줄세우기) 다 해보기 | 백트래킹(Backtracking), 순열/조합, 비트마스크            |

### 2. 🧠 '행동'으로 이해하는 알고리즘 검증법
로직을 구현하기 전, 다음 **3가지 행동**을 최종 점검하세요.

**① 루프안의 메서드 호출이 무거운지 확인**

- **현상:** `for`문 내부에 `list.remove(0)`, `contains()`, `indexOf()` 사용.
- **판단:** 겉은 $O(N)$이나 실제로는 $O(N) \times O(N)$ 행동입니다.
- **해결:** $N=10^5$ 이상이라면 반드시 `Set`, `Map`, `Deque` 등 $O(1)$ 자료구조로 교체해야 합니다.
    

**② 데이터가 크면 이분탐색하세요**
- 연산 부하가 큰 선형 탐색 대신 탐색 범위를 절반씩 축소하는 **$O(\log N)$ 기반의 이분 탐색**이 설계의 필수 요건입니다

**③ 정렬을 수행하기 전, $N \times \log_2 N$** 값이 **$10^8$(1억 번) 이내인지 계산하자
 
- 복잡도 계산할 때 $\log N$은 다음과 같다
	- $N = 1,000$ ($10^3$) $\rightarrow$ **10**
	- $N = 1,000,000$ ($10^6$) $\rightarrow$ **20**
	- $N = 1,000,000,000$ ($10^9$) $\rightarrow$ **30**

> 예시: $N=100$만 일 때 $O(N \log N)$ 알고리즘의 연산 횟수는?
> $\rightarrow$ $100$만 $\times$ $20$ = 2,000만 번 (1억보다 작으므로 통과!)

## 🚀 시간 복잡도 계산의 핵심: "루프 횟수"가 아닌 "데이터의 일생"

### 1️⃣ 왜 $O(n^2)$이 아닌가? (분할 상환 분석)

단순히 루프가 중첩된 것만 보지 말고, **전체 실행 과정에서 각 원소가 겪는 총 사건의 횟수**를 세어야 합니다. 이를 **분할 상환 분석(Amortized Analysis)**이라고 합니다.

- **외벽 (`for`문):** 배열의 모든 원소를 한 번씩 방문합니다. ($n$번)
- **내벽 (`while`문):** 스택에서 조건을 만족하는 원소를 꺼냅니다.
- **핵심 포인트:** 어떤 원소든 스택에 **들어가는 것(Push) 한 번, 나오는 것(Pop) 한 번**이 그 원소의 일생입니다.
- **결론:** 원소 $n$개가 각각 최대 한 번씩 들어갔다 나오므로, `while`문의 총 실행 횟수는 $n$번을 넘을 수 없습니다. 따라서 전체 시간 복잡도는 $O(n + n) = O(2n)$, 즉 **$O(n)$**이 됩니다.

## 💡 시간 복잡도 오해를 바로잡는 3가지 관점

### 1. 포인터의 이동 방향 (Two Pointers / Sliding Window)

중첩 루프라도 내부 루프의 인덱스(포인터)가 **앞으로만 전진**하고 뒤로 돌아가지 않는다면 $O(n)$입니다.

- 예: 슬라이딩 윈도우에서 오른쪽 포인터가 갈 때 왼쪽 포인터도 따라가기만 한다면, 각 포인터는 최대 $n$번 움직입니다.
### 2. 자료구조의 상태 변화 (Monotonic Stack / Queue)

자료구조에 원소가 추가되고 삭제되는 **총 횟수**가 배열의 크기에 비례하는지 확인하세요.

- `while`문이 한 번의 `for` 루프에서 여러 번 돌더라도, 다른 루프에서는 아예 안 돌 수도 있습니다. 전체를 합쳤을 때 원소의 개수($n$)를 넘지 않는다면 $O(1)$복잡도입니다.

### 3. "평균"이 아닌 "총합"으로 계산하기

- **오해:** "각 `for` 루프마다 `while`이 최대 $n$번 돌 수 있으니 $n \times n = n^2$이다."
- **진실:** "특정 루프에서 `while`이 많이 돌았다면, 스택이 비워졌으므로 다음 루프들에서는 `while`이 거의 돌지 않는다. **전체 $n$번의 `for` 루프 동안 실행된 `while`의 총 횟수 합계는 $n$이다.**"
## ⚠️ 언어별 주의사항 (함정 카드)

알고리즘은 맞는데 시간 초과(TLE)가 난다면?

- **Java:**
    - `Scanner` 금지 $\rightarrow$ `BufferedReader` 사용.
    - 문자열 잦은 덧셈 금지 $\rightarrow$ `StringBuilder` 사용.
- **Python:**
    - `input()` 금지 $\rightarrow$ `sys.stdin.readline` 사용.
    - $N=10^6$일 때 `Python3`가 느리면 `PyPy3`로 제출.
    - 재귀 깊이가 깊으면 `sys.setrecursionlimit()` 필수 설정.
- **C++:**
    - `cin`, `cout` 사용 시 `ios::sync_with_stdio(0), cin.tie(0)` 필수.
    - `endl` 금지 $\rightarrow$ `\n` 사용.
