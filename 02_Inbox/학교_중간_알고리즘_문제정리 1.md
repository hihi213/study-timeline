## 주관식 10문항

### S1. 자료구조와 알고리즘을 함께 배워야 하는 이유를 2문장으로 설명하라.

<details>
<summary>정답 보기</summary>
자료구조는 데이터의 **형태와 연산 비용**을, 알고리즘은 그 위에서의 **절차와 성능**을 규정한다. 같은 알고리즘이라도 선택한 자료구조에 따라 시간·공간 복잡도가 달라지므로 두 영역은 불가분이다.
</details>

------

### S2. float a = 3.14; 실행 시 코드/데이터/스택/힙 중 어디에 무엇이 놓이는가?

<details>
<summary>정답 보기</summary>
기계어는 **코드**, 리터럴/상수는 **데이터**, 지역변수 `a`는 **스택**에 위치한다. 동적할당이 없으므로 **힙**은 사용하지 않는다.
</details>

------

S3. 선형 vs 비선형 자료구조의 차이와 각 대표 예 2개씩.

<details>
<summary>정답 보기</summary>
선형은 순차 구조(예: 배열, 연결 리스트/스택/큐), 비선형은 계층·관계 구조(예: 트리, 그래프/해시)를 표현한다.
</details>

------

### S4. 배열 vs 연결 리스트 선택 기준을 “데이터 규모/변동성/접근 패턴” 관점에서 요약하라.

<details>
<summary>정답 보기</summary>
규모 고정·임의접근 많으면 **배열**, 크기 가변·중간 삽입/삭제 빈번하면 **연결 리스트**가 유리하다(단, 위치 탐색 비용은 별도).
</details>

------

### S5. 원형 큐로 배열 큐의 비효율을 어떻게 제거하는가?

<details>
<summary>정답 보기</summary>
`front/rear`를 모듈러로 회전시켜 물리적 이동 없이 **논리적 이동**만 수행하므로 `dequeue`가 O(1)이 된다.
</details>

------

### S6. 힙이 일반 큐와 다른 정책과 그 장점 1가지.

<details>
<summary>정답 보기</summary>
FIFO가 아닌 **우선순위 기반** 처리다. 가장 중요한 작업을 먼저 처리해 **응답 지연**을 줄인다.
</details>

------

### S7. 포인터의 타입 정보가 중요한 이유를 한 문단으로 설명하라.

<details>
<summary>정답 보기</summary>
타입은 역참조 시 **얼마나 읽고(크기)** **어떻게 해석**할지를 규정한다. 같은 주소도 `int *`와 `char *`로 읽으면 결과가 달라져, 잘못된 타입은 메모리 오독·오류를 야기한다.
</details>

------

### S8. 아래 코드가 오류인 이유를 설명하고, 올바르게 바꿔라.

register int a = 7;
int *p = &a;

<details>
<summary>정답 보기</summary>

</details>

------

### S9. *p++와 (*p)++의 의미 차이를 정확히 기술하라.

<details>
<summary>정답 보기</summary>
`*p++`는 현재 `*p` 값을 사용한 뒤 **포인터**를 다음 원소로 이동(`*(p++)`). `(*p)++`는 포인터는 그대로 두고 **가리키는 값**을 1 증가.
</details>

## **주관식 10문항**

### **S1. 연속 메모리와 배열의 주소 계산을 짧게 설명하라.**

<details><summary>정답 보기</summary>

- 배열은 동일 타입 원소가 **연속 메모리**에 저장된다.  
- 주소 공식: `addr(a[i]) = base + i * sizeof(T)` → 임의 접근 O(1).

</details>

-----

### **S2. int a1,a2,a3; 대신 int a[3];을 쓰면 포인터 순회가 쉬운 이유를 설명하라.**

<details><summary>정답 보기</summary>

- 배열은 연속이 보장되어 `p=a; p+1, p+2`로 순회 가능.  
- 개별 변수는 연속 보장X → 각 주소를 따로 알아야 함.

</details>

-----

### **S3. C의 2차원 배열 a[m][n]에서 a[i][j]의 주소를 식으로 써라.**

<details><summary>정답 보기</summary>

- **행 우선**: `addr(a[i][j]) = base + (i*n + j) * sizeof(T)`.

</details>

-----

### **S4. malloc이 **void***를 반환하는 이유와 C에서 캐스팅이 선택사항인 이유를 설명하라.**

<details><summary>정답 보기</summary>

- 어떤 타입의 블록인지 알 수 없으므로 **타입 미정 주소**(`void*`) 반환.  
- C에서는 `void*` → `T*` **암시적 변환 허용**(대입 가능), 필요 시 명시 캐스팅 사용.

</details>

-----

### **S5. 이중 포인터가 실무에서 필요한 대표 상황 2가지를 써라.**

<details><summary>정답 보기</summary>

- (1) 포인터 자체를 수정해야 할 때(예: 리스트 **헤드** 변경).  
- (2) 동적 2D 구조/포인터 배열 관리 시(주소→주소→값).

</details>

-----

### **S6. 함수 호출 스택에서 복귀 주소가 어떻게 관리되는지 2–3문장으로 요약하라.**

<details><summary>정답 보기</summary>

- 호출 시 **복귀 주소/매개변수/지역변수**가 스택 프레임으로 push.  
- 함수가 `return`하면 프레임이 pop되고 **복귀 주소**가 PC에 복원되어 호출 지점 다음 명령으로 복귀.

</details>

### **S7. 초기화되지 않은 포인터를 역참조하면 위험한 이유와 예방 방법을 쓰라.**

### **S8. 값 호출 vs 참조(포인터) 호출의 차이를 swap으로 설명하라.**

📘 **교재식 요약 — 원형 이중 연결 리스트의 ‘원형’ 의미는?**

- **‘원형(circular)’의 정의**

마지막 노드의 next가 **첫 노드**를, 첫 노드의 prev가 **마지막 노드**를 가리켜 **양방향으로 고리가 닫혀 있음**을 뜻합니다.

→ 즉, 어느 노드에서든 next(또는 prev)를 계속 따라가면 **언젠가 다시 출발 노드로 되돌아옵니다.**

- **헤드 포인터가 꼭 마지막 노드를 가리켜야 하나요?**

**아닙니다.**

- (1) **비센티넬(non-sentinel)**: 보통 head가 첫 노드를 가리키고, tail이 마지막 노드를 가리킵니다.
- (2) **Tail-as-head 변형**: 편의를 위해 head를 마지막 노드에 두고 head->next로 첫 노드에 O(1) 접근하기도 합니다.
- (3) **센티넬(더미) 헤드 노드**: head는 **데이터 없는 더미 노드**이고, 빈 리스트일 때 head->next == head 및 head->prev == head가 됩니다.

➜ ‘원형’의 의미는 **링크 구조가 원형**이라는 사실이지, **헤드 포인터의 위치**(첫/마지막/더미)를 강제하지 않습니다.

- **핵심 불변식(invariant)**

모든 노드 p에 대해 **p->next->prev == p** 그리고 **p->prev->next == p** 가 항상 성립해야 합니다.

(더미 헤드가 있으면 head에도 동일하게 적용)

### **S1. “원형 이중 연결 리스트의 ‘원형’ 의미”와 “헤드가 마지막 노드를 가리키는가”의 관계를 2–3문장으로 설명하라.**

<details><summary>정답 보기</summary>

‘원형’은 **링크 구조가 닫힌 고리**임을 뜻한다(마지막→첫, 첫→마지막). 헤드 포인터가 어디를 가리키는지는 구현 선택으로, 첫 노드/마지막 노드/더미 헤드 모두 가능하다. 즉, **원형≠헤드가 마지막을 가리킨다는 의미**는 아니다.

</details>

### **S2. 이중 연결 리스트 중간 삽입(노드 before 뒤)에 필요한 4단계 포인터 갱신을 순서대로 쓰라.**

<details><summary>정답 보기</summary>

`new->prev = before;  new->next = before->next;  before->next->prev = new;  before->next = new;`  

(기존 다음 노드 참조를 먼저 보존하고 마지막에 `before->next`를 바꿈)

</details>

<details><summary>정답 보기</summary>

(1) `rem->prev->next = rem->next;  rem->next->prev = rem->prev;` → **논리적 분리**  

(2) `free(rem);` → **물리적 해제**(누수 방지)

</details>

**보너스 메모 (수업 포인트 연결)**

- **폴더 = 일반 트리(N-ary)**: 자식 수가 가변이라 이진 트리보다 일반 트리가 자연스럽습니다.

간단한 1차 배열 표현: parent\[i](루트는 -1).

- **트리의 1차 배열 표현**: 완전 이진 트리는 **인덱싱 공식**으로 매우 효율적(힙). 일반 트리는 parent[]나 firstChild/nextSibling(자식-형제) 표현(배열 인덱스)으로도 구현 가능합니다.
- **원형 이중 연결 리스트**: ‘원형’은 **링크의 고리**, 헤드의 위치는 **설계 선택**(첫/마지막/더미). 더미를 쓰면 **경계조건**이 크게 단순화됩니다.
- **이중 포인터(**phead)**: 함수 안에서 **헤드 포인터 자체 변경**이 필요할 때 사용.
.

📌 **빠른 정리 (오개념 방지)**

- **안정 정렬(Stable)**: **삽입, 버블** / **불안정 정렬(Unstable)**: **선택, 쉘**
- **시간 복잡도(대표)**
- 선택: 항상 O(n²) (비교 ≈ n(n-1)/2, 교환 ≤ n-1)
- 삽입: 최선 O(n)(이미 정렬), 평균/최악 O(n²)
- 버블: **기본 구현**은 항상 O(n²) (최적화로 한 패스 무교환 시 조기종료를 넣으면 최선 O(n))
- 쉘: 간격(sequence)에 의존 (≈ O(n^1.5) 관용, 최악 O(n²)까지, 좋은 간격은 더 빠름)
- **내부/외부 정렬**: RAM 안에서 하는 정렬 = 내부 / 디스크(보조기억)까지 쓰는 대용량 정렬 = 외부(대개 부분정렬 *→* 다방향 병합)
- **핵심 불변식**
- 선택: i번째 패스 이후, **앞쪽 i+1개 구간이 정렬/확정**
- 삽입: i번째 삽입 이후, **앞쪽 i+1개가 정렬된 상태**
- 버블: k번째 패스 이후, **뒤쪽 k개가 확정(가장 큰 k개)**
- 쉘: 각 gap에 대해 **각 부분열이 삽입정렬로 정렬됨** (gap 축소 반복)

1. 배열의 본질과 효율성
 * 배열의 핵심 (1교시): 배열의 존재 이유는 **'동일한 자료형'**의 데이터들을 **'연속된 메모리 공간'**에 저장함을 보장하는 것입니다. (반면 int a1, a2 같은 개별 변수는 연속성이 보장되지 않습니다.)
 * 효율적인 접근 (1교시): 이 '연속성' 덕분에 CPU는 배열의 시작 주소(베이스 레지스터)와 인덱스(인덱스 레지스터)를 하드웨어 수준에서 빠르게 계산(시작주소 + 인덱스 * 자료형크기)하여 $O(1)$로 접근할 수 있습니다.
 * 2차원 배열 (2교시): 2차원 배열 a[m][n]은 논리적으로는 격자지만, 실제 메모리에는 a[0][0]부터 a[m-1][n-1]까지 1차원으로 연속되게 저장됩니다 (행 우선 순서).
 * 희소 행렬 (2교시): 대부분 0인 행렬을 2차원 배열로 저장하면 심각한 메모리 낭비가 발생합니다. 이때는 0이 아닌 값만 (행, 열, 값)을 멤버로 갖는 구조체 배열로 저장하여 메모리를 절약합니다. (단, 접근 시간은 희생됩니다.)
1. 포인터의 개념과 위험성
 * 포인터의 본질 (1, 3교시): 포인터 변수 자체는 메모리 주소를 저장하기 위한 고정된 크기(예: 4바이트)의 공간일 뿐입니다. int*나 char* 같은 포인터의 타입은 해당 주소에서 몇 바이트를(4바이트 vs 1바이트) 어떻게 읽을지를 컴파일러에 알려주는 약속입니다.
 * void* 포인터 (2, 3교시): malloc이 반환하는 것처럼 '타입이 정해지지 않은' 주소를 의미하며, (int*)처럼 명시적 형 변환을 통해 어떤 타입으로든 변환될 수 있습니다.
 * 배열 이름 = 상수 포인터 (1, 3교시): 배열의 이름(a)은 그 자체로 시작 주소를 가리키는 상수 포인터입니다. 따라서 a[2] = 5;는 가능하지만, a = …;처럼 주소 값 자체를 바꾸려는 시도는 불가능합니다.
 * C의 취약점 (1, 3교시):
   * Bounds Checking 없음: int a[4]; 선언 후 a[5]에 접근해도 오류를 내지 않아 심각한 취약점이 됩니다.
   * 초기화되지 않은 포인터: int *p; 선언 직후 *p = 5;처럼 사용하면, p의 쓰레기 주소 값이 시스템 영역을 침범해 치명적 오류를 유발할 수 있습니다.
1. 메모리 관리 (정적 vs 동적)
 * 메모리 4대 영역 (3교시): 프로그램 메모리는 4개 영역으로 나뉩니다.
   * 코드(Code): 실행할 기계어 명령어
   * 데이터(Data): 전역 변수, 정적(static) 변수
   * 힙(Heap): malloc으로 할당되는 동적 메모리 공간
   * 스택(Stack): 함수 호출 시 사용되는 지역 변수, 매개변수
 * 정적 vs 동적 할당 (2교시): int a;는 컴파일 시 스택에 할당되며 '이름'이 있습니다. 반면 malloc()은 프로그램 실행 중 힙(Heap) 영역에 할당되며, '이름'이 없고 오직 반환된 '주소'로만 접근해야 합니다.
 * 메모리 누수 (Memory Leak) (2교시): malloc()으로 할당한 힙 메모리는 반드시 free()로 해제해야 합니다. 이를 잊으면 해당 메모리는 재부팅 전까지 아무도 못 쓰는 '사라진 공간'이 되며, 이를 메모리 누수라고 합니다.
 * C vs Java (2교시): C는 개발자가 malloc/free로 직접 메모리를 관리해야 하지만, Java는 **가비지 컬렉터(GC)**가 자동으로 사용하지 않는 메모리를 회수합니다.
1. 함수와 포인터 (호출 방식과 스택)
 * 값에 의한 호출 (Call by Value) (3교시): swap(i, j)는 i와 j의 '값'을 복사해서 전달합니다. 함수 내에서 복사본을 바꿔도 원본 i, j는 절대 바뀌지 않습니다.
 * 참조에 의한 호출 (Call by Reference) (3교시): C에서는 포인터를 사용해 swap(&i, &j)처럼 '주소'를 전달합니다. 함수는 *p (역참조)를 통해 원본 i, j의 값을 직접 수정할 수 있습니다.
   * (참고: 40MB짜리 큰 구조체를 복사 없이 4바이트 주소만 전달하는 효율적인 방식이기도 합니다.)
 * 함수 호출과 스택 (3교시): main이 swap을 호출하면, swap이 끝난 뒤 돌아와야 할 main의 다음 명령어 주소(복귀 주소)와 swap의 지역 변수(temp)가 **스택(Stack)**에 쌓입니다(Push). swap이 종료되면 스택에서 이 정보들을 꺼내(Pop) main의 실행을 이어가며, 이는 LIFO(Last-In, First-Out) 구조입니다.

1교시: 구조체(Struct)의 개념과 활용
 * 구조체(struct): 학번, 이름, 학과처럼 서로 다른 자료형의 변수들을 하나의 논리적 단위로 묶는 사용자 정의 자료형입니다. (동일 자료형의 묶음인 배열과 다릅니다.)
 * 함수 전달 방식:
   * 값에 의한 호출 (Call by Value): 구조체 전체를 '복사'하여 전달합니다. 함수 내에서 값을 변경해도 원본은 안전하게 보존됩니다.
   * 참조에 의한 호출 (Call by Reference): 구조체의 '주소(포인터)'를 전달합니다. 함수 내에서 원본 값을 직접 수정할 수 있습니다.
 * 활용 예시 (다항식 표현):
   * 배열 방식: coef[5] = 10처럼 인덱스를 지수로 매핑합니다. 덧셈 알고리즘은 간단하지만, x^1000 + 1과 같은 희소 다항식의 경우 심각한 메모리 낭비를 초래합니다.
   * 구조체 방식: 0이 아닌 항만 (계수, 지수) 쌍으로 저장하여 메모리 효율성을 높입니다. (단, 덧셈 알고리즘은 더 복잡해집니다.)
 * 자기 참조 구조체 (Self-referential Structure): struct list_node { …; struct list_node* link; };와 같이, 구조체 내부에 자기 자신과 동일한 타입의 포인터를 멤버로 갖는 구조입니다. 이는 연결 리스트를 구현하는 핵심 기반이 됩니다.
2교시: 리스트 구현 (배열 vs. 연결 리스트)
 * 배열 기반 리스트:
   * 단점: 크기가 고정되며, 중간에 원소를 삽입/삭제할 때 비효율적인 오버헤드가 발생합니다.
   * 삽입/삭제 로직: 삽입 시에는 데이터 유실을 막기 위해 맨 뒤 원소부터 뒤로 밀어야 하고, 삭제 시에는 빈 공간을 메우기 위해 앞 원소부터 앞으로 당겨야 합니다.
 * 연결 리스트 (Linked List):
   * 구조: 1교시의 자기 참조 구조체를 **노드(Node)**로 사용하며, malloc을 통해 동적으로 생성됩니다.
   * 장점: 크기가 유동적이며, 삽입/삭제 시 데이터를 옮길 필요 없이 포인터 연결만 변경하므로 매우 효율적입니다 (O(1)).
   * 단점: 구현이 복잡하고, free()를 호출하지 않으면 **메모리 누수(memory leak)**가 발생할 수 있습니다.
 * 종류: 단순(단방향), 원형(순환), 이중(양방향) 연결 리스트가 있습니다.
3교시: 연결 리스트의 핵심 연산 (삽입과 삭제)
 * 삽입 (Insertion):
   * 핵심 원리: 포인터 연결 순서가 매우 중요합니다.
   * 올바른 순서:
     * new_node->link = before->link; (새 노드가 먼저 기존의 다음 노드를 가리키게 합니다.)
     * before->link = new_node; (이전 노드가 새 노드를 가리키도록 연결을 변경합니다.)
   * 만약 순서가 바뀌면 before 노드 뒤의 모든 노드에 대한 연결 정보가 유실됩니다.
 * 삭제 (Deletion):
   * 핵심 원리: 두 단계로 이루어집니다.
     * before->link = removed->link; (이전 노드가, 삭제할 노드의 '다음' 노드를 가리키도록 연결을 변경하여 삭제할 노드를 우회합니다.)
     * free(removed); (우회된 노드의 메모리를 반드시 해제하여 메모리 누수를 방지합니다.)
 * 삽입 시나리오: head == NULL(빈 리스트), p == NULL(맨 앞), p != NULL(중간/끝)의 세 가지 경우를 모두 고려해야 합니다.
1. head == NULL (빈 리스트에 삽입)

- 상황: 리스트에 노드가 하나도 없는 상태입니다.
- 처리:

1. 새 노드(new_node)가 유일한 노드가 됩니다.
2. head 포인터가 새 노드를 가리키게 합니다 (head = new_node).
3. 새 노드의 링크는 NULL이 됩니다 (new_node->link = NULL).
4. p == NULL (리스트의 맨 앞에 삽입)

- 상황: 리스트는 존재하지만(head != NULL), 맨 앞에 삽입해야 하는 경우입니다. (이전 노드 p가 NULL입니다.)
- 처리:

1. 새 노드의 링크가 기존의 첫 번째 노드(head가 가리키던 노드)를 가리키게 합니다 (new_node->link = head).
2. head 포인터가 새 노드를 가리키도록 갱신합니다 (head = new_node).
3. p != NULL (리스트의 중간 또는 끝에 삽입)

- 상황: 가장 일반적인 경우로, p 노드 바로 뒤에 삽입합니다.
- 처리: (연결 순서가 중요합니다)

1. 새 노드가 p의 다음 노드를 먼저 가리키게 합니다 (new_node->link = p->link).
2. p 노드가 새 노드를 가리키게 합니다 (p->link = new_node).

연결 리스트의 진화와 최종 형태
단순 연결 리스트는 **이전 노드 탐색(O(n))**과 **끝 노드 추가(O(n))**가 비효율적입니다. 이 문제를 해결하기 위해 다음과 같이 진화했습니다.
 * 원형 연결 리스트: 마지막 노드가 첫 노드를 가리킵니다. 헤드 포인터가 마지막 노드를 가리키게 만들면, 리스트의 양 끝(맨 앞, 맨 뒤)에 **O(1)**로 접근할 수 있게 됩니다.
 * 이중 연결 리스트: 노드에 **이전 노드를 가리키는 포인터(llink)**를 추가하여 양방향 탐색이 가능해졌습니다. 이로써 이전 노드 탐색이 **O(1)**로 해결됩니다.
 * 최종 형태 (원형 이중 연결 리스트 + 더미 노드): 실무에서 가장 널리 쓰이는 방식입니다. 데이터가 없는 **더미 노드(헤드 노드)**를 추가하여, 리스트가 비어있을 때조차 더미 노드가 자기 자신을 가리키게 만듭니다.
이 최종 형태의 가장 큰 장점은, "빈 리스트에 삽입", "맨 앞에 삽입" 등 복잡한 경계 조건(Edge Case) 처리가 사라진다는 것입니다. 모든 삽입/삭제 연산이 '두 노드 사이에서의 조작'이라는 하나의 로직으로 통일되어 코드가 매우 간결하고 안정적이게 됩니다.
이중 연결 리스트의 핵심 연산
 * 삽입 연산: 총 4개의 포인터 연결 순서가 매우 중요합니다. 특히, 기존 노드의 다음 연결(before->rlink)을 새 노드로 바꾸는 작업은 반드시 마지막 단계에 수행해야 합니다. 순서를 어기면 기존 리스트의 연결 정보가 유실됩니다.
 * 삭제 연산: 삭제할 노드의 이전 노드와 다음 노드가 서로를 직접 가리키게 하여 논리적으로 분리합니다. 그 후, 반드시 free()를 호출하여 해당 노드의 메모리를 반환해야 **메모리 누수(Memory Leak)**를 막을 수 있습니다.
 * 응용 (다항식 덧셈): 각 노드에 **(계수, 지수)**를 저장하여 다항식을 표현할 수 있습니다. 두 리스트를 순회하며 지수를 비교하는 규칙을 적용하여 효율적으로 덧셈 결과를 만들 수 있습니다.
트리(Tree) 자료구조 🌲
 * 트리가 필요한 이유: 배열이나 리스트 같은 선형 구조로는 가계도나 파일 디렉터리 같은 계층적 관계를 표현하기 어렵습니다. 트리는 이런 비선형 데이터를 다루기 위해 사용됩니다.
 * 이진 트리(Binary Tree)를 배우는 이유:
   * 일반 트리는 자식 수가 가변적이라 표준화된 구현이 어렵습니다.
   * 이진 트리는 자식 노드를 최대 2개(left, right)로 제한하여, struct와 두 개의 포인터로 간단하게 구현할 수 있어 표준으로 사용됩니다.
 * 이진 트리의 종류:
   * 포화 이진 트리: 모든 레벨이 꽉 찬 완벽한 삼각형 형태.
   * 완전 이진 트리: 마지막 레벨은 왼쪽부터 채워져 있고, 그 외 모든 레벨은 꽉 찬 형태. (힙(Heap)이 대표적)
   * 편향 이진 트리: 한쪽으로만 치우쳐 연결 리스트와 유사한 형태. (트리 알고리즘의 최악 성능)
 * 이진 트리의 구현 방법:
   * 배열 (Array): 완전 이진 트리에 매우 효율적입니다. 인덱스 계산(부모: i/2, 자식: 2*i, 2*i+1)만으로 부모/자식에 빠르게 접근할 수 있습니다.
   * 연결 리스트 (Linked List): 가장 일반적이고 유연한 방법입니다. malloc을 통해 동적으로 노드를 생성하고 포인터로 연결하여 메모리를 효율적으로 사용합니다.

2025-10-16 정렬 알고리즘 요약 🗂️
1. 정렬(Sorting)의 기본 개념
 * 정의: 데이터를 특정 '키(key)' 값을 기준으로 오름차순이나 내림차순으로 나열하는 기술입니다.
 * 평가: 모든 상황에 최적인 알고리즘은 없습니다. 데이터의 양, 초기 상태, 메모리 제약 등에 따라 적합한 방식을 선택해야 합니다. (예: 퀵 정렬은 평균적으로 빠르지만 최악의 경우 O(n²)가 될 수 있습니다.)
 * 분류:
   * 내부 정렬(Internal Sort): 모든 데이터를 메인 메모리(RAM)에 올려서 정렬합니다.
   * 외부 정렬(External Sort): 데이터가 너무 커서 보조 기억 장치(디스크)를 사용해 분할/정렬/병합합니다.
1. O(n²) 정렬 알고리즘
선택 정렬 (Selection Sort)
 * 원리: 정렬되지 않은 부분에서 **최솟값(min)을 '선택'**하여, 정렬된 부분의 맨 뒤(현재 순회의 시작 위치)에 있는 값과 **교환(swap)**합니다.
 * 특징:
   * 시간 복잡도: 데이터 상태와 무관하게 **항상 O(n²)**입니다. (최솟값을 찾기 위해 매번 전체를 비교해야 합니다.)
   * 안정성: **불안정 정렬(Unstable Sort)**입니다. 멀리 떨어진 원소와의 교환으로 인해 동일한 값의 순서가 바뀔 수 있습니다.
삽입 정렬 (Insertion Sort)
 * 원리: 이미 정렬된 부분 집합 S에, 정렬되지 않은 부분 U의 원소를 하나씩 꺼내어 올바른 위치에 **'삽입(insert)'**합니다. (카드 패를 정렬하는 것과 유사합니다.)
 * 특징:
   * 시간 복잡도: 역순일 때 최악 O(n²)이지만, **이미 정렬된 상태(최선)에서는 O(n)**의 매우 빠른 성능을 보입니다.
   * 동작: 원소를 삽입할 공간을 만들기 위해 다른 원소들을 뒤로 한 칸씩 **이동(shift)**시키는 연산이 필요합니다.
버블 정렬 (Bubble Sort)
 * 원리: 인접한 두 원소만을 계속 비교하여, 순서가 맞지 않으면 **교환(swap)**합니다. 한 번의 순회(pass)가 끝나면 가장 큰 값이 맨 뒤로 이동합니다.
 * 특징:
   * 시간 복잡도: 데이터 상태와 무관하게 **항상 O(n²)**입니다.
   * 장점: 구현이 모든 정렬 알고리즘 중 가장 간단하고 직관적입니다.
1. 개선된 정렬: 쉘 정렬 (Shell Sort)
 * 개념: 삽입 정렬을 개선한 알고리즘입니다.
 * 원리:
   * 처음에는 큰 '간격(gap)' (예: n/2)을 설정합니다.
   * 이 간격만큼 떨어져 있는 원소들끼리 묶어 부분 집합을 만들고, 각 부분 집합에 대해 삽입 정렬을 수행합니다. (이때 원소들이 자신의 최종 위치 근처로 빠르게 이동합니다.)
   * 간격을 점차 줄여가며(예: gap / 2) 이 과정을 반복합니다.
   * 마지막에 간격이 1이 되면, 배열은 '거의 정렬된' 상태가 됩니다.
   * '거의 정렬된' 배열에 대해 삽입 정렬(간격 1)을 수행하면 O(n)에 가깝게 매우 빠르게 정렬이 완료됩니다.
 * 성능: 삽입 정렬의 O(n²)를 평균 O(n^1.5) 정도로 크게 개선합니다. (성능은 '간격 순서'에 따라 달라집니다.)

1. 배열의 본질과 효율성
 * 배열의 핵심 (1교시): 배열의 존재 이유는 **'동일한 자료형'**의 데이터들을 **'연속된 메모리 공간'**에 저장함을 보장하는 것입니다. (반면 int a1, a2 같은 개별 변수는 연속성이 보장되지 않습니다.)
 * 효율적인 접근 (1교시): 이 '연속성' 덕분에 CPU는 배열의 시작 주소(베이스 레지스터)와 인덱스(인덱스 레지스터)를 하드웨어 수준에서 빠르게 계산(시작주소 + 인덱스 * 자료형크기)하여 $O(1)$로 접근할 수 있습니다.
 * 2차원 배열 (2교시): 2차원 배열 a[m][n]은 논리적으로는 격자지만, 실제 메모리에는 a[0][0]부터 a[m-1][n-1]까지 1차원으로 연속되게 저장됩니다 (행 우선 순서).
 * 희소 행렬 (2교시): 대부분 0인 행렬을 2차원 배열로 저장하면 심각한 메모리 낭비가 발생합니다. 이때는 0이 아닌 값만 (행, 열, 값)을 멤버로 갖는 구조체 배열로 저장하여 메모리를 절약합니다. (단, 접근 시간은 희생됩니다.)
1. 포인터의 개념과 위험성
 * 포인터의 본질 (1, 3교시): 포인터 변수 자체는 메모리 주소를 저장하기 위한 고정된 크기(예: 4바이트)의 공간일 뿐입니다. int*나 char* 같은 포인터의 타입은 해당 주소에서 몇 바이트를(4바이트 vs 1바이트) 어떻게 읽을지를 컴파일러에 알려주는 약속입니다.
 * void* 포인터 (2, 3교시): malloc이 반환하는 것처럼 '타입이 정해지지 않은' 주소를 의미하며, (int*)처럼 명시적 형 변환을 통해 어떤 타입으로든 변환될 수 있습니다.
 * 배열 이름 = 상수 포인터 (1, 3교시): 배열의 이름(a)은 그 자체로 시작 주소를 가리키는 상수 포인터입니다. 따라서 a[2] = 5;는 가능하지만, a = …;처럼 주소 값 자체를 바꾸려는 시도는 불가능합니다.
 * C의 취약점 (1, 3교시):
   * Bounds Checking 없음: int a[4]; 선언 후 a[5]에 접근해도 오류를 내지 않아 심각한 취약점이 됩니다.
   * 초기화되지 않은 포인터: int *p; 선언 직후 *p = 5;처럼 사용하면, p의 쓰레기 주소 값이 시스템 영역을 침범해 치명적 오류를 유발할 수 있습니다.
1. 메모리 관리 (정적 vs 동적)
 * 메모리 4대 영역 (3교시): 프로그램 메모리는 4개 영역으로 나뉩니다.
   * 코드(Code): 실행할 기계어 명령어
   * 데이터(Data): 전역 변수, 정적(static) 변수
   * 힙(Heap): malloc으로 할당되는 동적 메모리 공간
   * 스택(Stack): 함수 호출 시 사용되는 지역 변수, 매개변수
 * 정적 vs 동적 할당 (2교시): int a;는 컴파일 시 스택에 할당되며 '이름'이 있습니다. 반면 malloc()은 프로그램 실행 중 힙(Heap) 영역에 할당되며, '이름'이 없고 오직 반환된 '주소'로만 접근해야 합니다.
 * 메모리 누수 (Memory Leak) (2교시): malloc()으로 할당한 힙 메모리는 반드시 free()로 해제해야 합니다. 이를 잊으면 해당 메모리는 재부팅 전까지 아무도 못 쓰는 '사라진 공간'이 되며, 이를 메모리 누수라고 합니다.
 * C vs Java (2교시): C는 개발자가 malloc/free로 직접 메모리를 관리해야 하지만, Java는 **가비지 컬렉터(GC)**가 자동으로 사용하지 않는 메모리를 회수합니다.
1. 함수와 포인터 (호출 방식과 스택)
 * 값에 의한 호출 (Call by Value) (3교시): swap(i, j)는 i와 j의 '값'을 복사해서 전달합니다. 함수 내에서 복사본을 바꿔도 원본 i, j는 절대 바뀌지 않습니다.
 * 참조에 의한 호출 (Call by Reference) (3교시): C에서는 포인터를 사용해 swap(&i, &j)처럼 '주소'를 전달합니다. 함수는 *p (역참조)를 통해 원본 i, j의 값을 직접 수정할 수 있습니다.
   * (참고: 40MB짜리 큰 구조체를 복사 없이 4바이트 주소만 전달하는 효율적인 방식이기도 합니다.)
 * 함수 호출과 스택 (3교시): main이 swap을 호출하면, swap이 끝난 뒤 돌아와야 할 main의 다음 명령어 주소(복귀 주소)와 swap의 지역 변수(temp)가 **스택(Stack)**에 쌓입니다(Push). swap이 종료되면 스택에서 이 정보들을 꺼내(Pop) main의 실행을 이어가며, 이는 LIFO(Last-In, First-Out) 구조입니다.
