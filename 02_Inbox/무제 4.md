# [Security] 네트워크 및 애플리케이션 공격 체계도

## 1. 자원 소모형 공격 (Availability & Flooding)

시스템이 보유한 유한한 자원(대역폭, 메모리, 스레드 등)을 고갈시켜 정상적인 서비스를 불가능하게 만드는 공격입니다.

| **분류**              | **공격명**              | **기술적 메커니즘**                                                                   | **핵심 방어 전략**                                                        |
| ------------------- | -------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| **L3/L4 (Network)** | **UDP Flooding**<br> | 대량의 무의미한 UDP 패킷을 전송하여 네트워크 회선 대역폭(Bandwidth)을 점유.                              | 대역폭 확장, Anycast 도입, 트래픽 세척(Scrubbing Center).                       |
| **L4 (Transport)**  | **SYN Flooding**     | TCP 3-Way Handshake 중 ACK를 보내지 않고 Half-Open 상태를 유지하여 접속 대기열(Backlog Queue) 고갈. | **SYN Cookie** 활성화, Backlog Queue 크기 확장, TCP Keep-alive 설정 최적화.     |
| **L3 (ICMP)**       | **Smurf Attack**     | IP스푸핑(출발지 IP를 타겟 IP로 위조)하여 ICMP Echo를 브로드캐스트 전송, 타겟에게 응답 패킷을 집중시킴.             | 라우터에서 IP Directed Broadcast 차단, ICMP 패킷 필터링.                        |
| **L7 (App)**        | **Slowloris**        | HTTP 헤더의 끝(`\r\n\r\n`)을 보내지 않고 매우 느리게 패킷을 보내 웹 서버의 Connection Pool(스레드)을 점유.   | 요청 타임아웃(Timeout) 단축, **Reverse Proxy(Nginx 등)** 도입, IP당 동시 접속 수 제한. |

## 2. 위조 및 기만 공격 (Identity & Spoofing)

식별 정보(IP, MAC, DNS 등)를 조작하여 신뢰받는 대상으로 위장하거나 데이터의 흐름을 왜곡하는 공격입니다.

|**분류**|**공격명**|**기술적 메커니즘**|**핵심 방어 전략**|
|---|---|---|---|
|**L3 (Network)**|**IP Spoofing**|패킷의 Source IP 주소를 신뢰할 수 있는 내부 IP로 위조하여 접근 제어(ACL)를 무력화.|**Ingress/Egress Filtering**, 소스 주소 무결성 검증.|
|**L2 (Datalink)**|**ARP Spoofing**|공격자의 MAC 주소를 게이트웨이 등의 IP와 매핑시킨 위조 ARP 패킷을 살포하여 패킷을 가로챔(Sniffing).|ARP 테이블의 정적(Static) 설정, **DAI(Dynamic ARP Inspection)** 지원 스위치 사용.|
|**L7 (App)**|**DNS Spoofing**|가짜 DNS 응답을 실제 서버보다 먼저 도착하게 하여 사용자를 악성 IP(Phishing site)로 유도.|**DNSSEC** 도입, 중요 통신 시 목적지 서버 인증서 확인(HTTPS).|

## 3. 연결 및 권한 탈취 공격 (Hijacking)

이미 수립된 논리적 세션의 주도권을 가로채어 공격자가 정당한 사용자로 행세하는 공격입니다.

### TCP 세션 하이재킹 (L4)

- **설명:** 통신 중인 클라이언트와 서버 사이의 **시퀀스 번호(SEQ)**를 탈취 및 예측하여 중간에 패킷을 주입하고 연결을 가로챔.
- **방어:** 전송 구간 암호화(SSL/TLS), Sequence Number 무작위화 강도를 높인 OS 커널 사용.
    

### HTTP 세션 하이재킹 (L7)

- **설명:** 사용자의 브라우저 쿠키에 저장된 **Session ID**를 스니핑이나 XSS를 통해 탈취하여 사용자의 로그인 세션을 도용.
- **방어:** **HTTPS(SSL/TLS)** 필수 적용, 쿠키 속성(`HttpOnly`, `Secure`) 설정, 세션 타임아웃 설정 및 중복 로그인 방지.

## 4. 규모의 확장: DoS vs DDoS
> DDoS는 **"수천 대의 PC가 동원된(DDoS)"** + **"SYN Flooding(공격 기술)"**과 같은 방식으로 표현됩니다.

이 분류는 공격의 '방법'이 아닌 '수행 규모'에 따른 구분입니다.

- **DoS (Denial of Service):** 단일 소스(1:1)에서 발생하는 공격.
    (예: 1대의 PC로 수행하는 SYN Flooding)
- **DDoS (Distributed DoS):** 전 세계에 분산된 좀비 PC(Botnet)를 이용해 **동시 다발적**으로 Flooding 공격을 수행.
    - **방어:** 단일 서버 설정으로는 방어가 불가능하며, ISP 수준의 트래픽 세척 서비스나 Cloudflare/AWS Shield 같은 **글로벌 DDoS 방어 솔루션**이 필수적입니다.

## 💡 요약 및 인사이트 (Senior's Note)

백엔드 엔지니어로서 가장 경계해야 할 부분은 **애플리케이션 계층(L7)의 공격**입니다. 하부 계층(L2~L4) 공격은 인프라 팀이나 클라우드 벤더의 보안 장비(WAF, IPS)가 주로 담당하지만, **Slowloris**나 **HTTP 세션 하이재킹**은 개발자의 코드와 서버 설정에 직접적인 영향을 받기 때문입니다.

- **L4 이하 방어:** 인프라 설정(Firewall, Kernel Tuning)의 영역.
- **L7 방어:** 애플리케이션 보안(HTTPS, Cookie Policy, Input Validation)의 영역.
