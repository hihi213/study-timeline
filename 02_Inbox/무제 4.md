## 1. [Topic: 현재 디렉토리 획득 `getcwd()` 상세]

- **Definition:** 현재 프로세스의 절대 경로를 `buf`에 복사합니다.
- **Classification:** **Library Function** (glibc에서 시스템 콜을 래핑하여 편의성 제공)
    

### 🏗️ 동작 원리 및 API 상세

- **버퍼 메커니즘:** - 마지막에 널 문자(`\0`)를 포함하여 총 `size`만큼의 데이터를 `buf`에 저장합니다.
    - **Return:** 성공 시 `buf`의 시작 주소 반환, 실패 시 `NULL` 반환.
- **메모리 관리:** - 만약 `buf` 자리에 `NULL`을 전달하여 시스템이 자동 할당하게 했다면, 사용 후 반드시 **`free()`**를 호출하여 메모리 누수를 방지해야 합니다.
    

---

## 2. [Topic: 디렉토리 이동 `chdir()`]

- **Definition:** 프로세스의 현재 작업 디렉토리(CWD)를 지정한 `path`로 변경합니다.
- **Classification:** **System Call** (커널의 `task_struct` 정보를 직접 수정)
    

### 🏗️ 동작 원리 및 주의사항

- **Scope:** 변경된 디렉토리는 **해당 프로세스 내부**에서만 유효합니다.
- **Persistence (중요):** - 프로그램이 종료된 후, 프로그램을 실행했던 **쉘(부모 프로세스)의 위치는 변하지 않습니다.**
    - **이유:** 자식 프로세스는 부모의 환경을 복사해오지만, 자식의 환경 변화(CWD 변경 등)는 부모에게 역으로 영향을 줄 수 없기 때문입니다.
        

### 💻 실제 실습 구현 (`chdir_ex.c`)

**1) Source Code**

C

```sql
#include <stdio.h>
#include <unistd.h>

int main() {
    char buf[1024];

    // 1. 이동 전 경로 확인
    getcwd(buf, sizeof(buf));
    printf("이동 전: %s\n", buf);

    // 2. 디렉토리 이동 (System Call)
    if (chdir("/tmp") == -1) {
        perror("chdir 실패");
        return 1;
    }

    // 3. 이동 후 경로 확인
    getcwd(buf, sizeof(buf));
    printf("이동 후: %s\n", buf);

    return 0;
}
```

**2) 컴파일 및 실행 결과**

Bash

```sql
$ gcc -o chdir_ex chdir_ex.c
$ ./chdir_ex

# 실행 결과
이동 전: /home/hyeon/projects
이동 후: /tmp

$ pwd
# 출력: /home/hyeon/projects (쉘의 위치는 그대로임 확인)
```

## 📌 Deep-Dive & CS Interview

> [!faq]Q. 왜 `cd` 명령어는 별도의 프로그램이 아니라 쉘의 내장 명령어(Built-in)인가요?
>
> **🗣️ 핵심 답변:** 일반적인 외부 프로그램으로 실행하면 `chdir()` 시스템 콜이 **자식 프로세스 내에서만 적용**되고 종료되므로, 우리가 사용하는 쉘의 디렉토리를 바꿀 수 없기 때문입니다.
>
> **📚 로직 보강:** 따라서 쉘 자체의 현재 위치를 바꾸기 위해서는 쉘 프로세스가 직접 `chdir()`을 호출해야 하며, 이 때문에 `cd`는 쉘 내장 명령어로 구현되어 있습니다.
