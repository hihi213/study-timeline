## Topic 1. 원형 연결 리스트 (Circular Linked List)

### 1. 🏗️ 빌드업 (Why & Context)

> 단순 연결 리스트(Singly Linked List)는 "뒤로 돌아갈 수 없다"는 치명적인 단점이 있다.

- **문제 제기:**
    - 단순 연결 리스트에서 특정 노드를 지나치면, 다시 그 전 노드로 돌아가기 위해 **Head부터 다시 탐색($O(N)$)**해야 한다.
    - 마지막 노드의 링크가 `NULL`로 끝나면 리스트의 끝에 도달했을 때 더 이상 갈 곳이 없다.
- **핵심 아이디어:**
    - "만약 마지막 노드가 다시 첫 번째 노드를 가리키게 한다면?" (Ring 구조)
    - "Head 포인터의 위치를 기가 막힌 곳(마지막 노드)으로 옮긴다면 연산이 얼마나 쉬워질까?"
        

### 2. Concept

> **"Head를 마지막 노드(Last Node)에 두는 것이 '신의 한 수'다."**

1. **기본 정의**:
    
    - 마지막 노드의 링크 필드가 `NULL`이 아닌 **첫 번째 노드**를 가리키는 리스트.
    - 하나의 노드에서 링크를 계속 따라가면 리스트 내의 모든 노드를 접근할 수 있음.
        
2. **최적화된 구조 (Modified Circular Linked List)**:
    
    - **일반적 접근**: `Head` -> `First Node`.
        - 이 경우 리스트의 **마지막(Rear)**에 노드를 삽입하려면 `Head`부터 끝까지 순회해야 하므로 $O(N)$ 시간 소요.
    - **최적화 접근**: **`Head` -> `Last Node`**.
        - `Head`: 마지막 노드(Rear)를 가리킴.
        - `Head->link`: 첫 번째 노드(Front)를 가리킴.
        - **장점**: 리스트의 **맨 앞(Front)**과 **맨 뒤(Rear)** 모두에 $O(1)$로 접근 가능.
            - 맨 앞 접근: `Head->link`
            - 맨 뒤 접근: `Head`
                

### 3. Code 구현 (C언어)

교수님은 `phead`(헤드 포인터의 포인터)를 사용하여 리스트가 비어있는 경우와 아닌 경우를 구분하여 설명하였습니다.

**핵심 시나리오: 리스트 처음에 노드 삽입하기**



```C
typedef struct Node {
    int data;
    struct Node* link;
} Node;

// head: 리스트의 마지막 노드를 가리키는 포인터
// node: 새로 삽입할 노드
void insert_front(Node** phead, Node* node) {
    // Case 1: 리스트가 비어있는 경우 (Head가 NULL)
    if (*phead == NULL) {
        *phead = node;          // 헤드가 새 노드를 가리킴
        node->link = node;      // 새 노드가 자기 자신을 가리킴 (원형 형성)
    }
    // Case 2: 리스트가 비어있지 않은 경우
    else {
        // (*phead)는 마지막 노드(Last)
        // (*phead)->link는 현재 첫 번째 노드(First)
        
        node->link = (*phead)->link; // 1. 새 노드의 링크가 기존 첫 노드를 가리키게 함
        (*phead)->link = node;       // 2. 마지막 노드의 링크가 새 노드를 가리키게 함
        
        // 주의: Head 위치는 변경하지 않음 (여전히 기존 Last를 가리켜야 함)
        // 만약 insert_last였다면 여기서 *phead = node; 한 줄만 추가하면 됨.
    }
}
```

#### ⚠️ 구현 및 이해의 포인트

1. **더블 포인터(`Node** phead`) 사용 이유**:
    
    - 함수 내부에서 `Head` 포인터 자체의 값(주소)을 변경해야 할 수도 있기 때문(Call by Reference).
    - _Tip_: 가독성을 위해 `phead`라는 별도 변수를 두어 "변하지 않는 기준점"처럼 활용하기도 함.
        
2. **삽입 로직의 효율성**:
    
    - `insert_front`와 `insert_last`의 코드 차이는 **단 한 줄**(`head` 포인터를 이동시키느냐 마느냐)이다.
    - 단순 연결 리스트였다면 `insert_last`는 $O(N)$이었겠지만, 이 구조에서는 $O(1)$이다.

## Topic 2. 이중 연결 리스트 (Doubly Linked List)

### 1. 🏗️ 빌드업 (Why & Context)

> 단순/원형 연결 리스트도 여전히 "내 바로 앞(Predecessor)"을 찾는 것은 비효율적이다.

- **문제 제기:**
    - 단순/원형 연결 리스트는 단방향(`link`)이다.
    - 내 바로 앞의 노드를 삭제하거나 참조하려면, 다시 `Head`부터 시작해서 $O(N)$만큼 순회해야 한다.
    - 리스트가 1억 개의 노드를 가진다면, 바로 앞을 보기 위해 1억 번을 돌아야 하는 셈이다.
- **해결책:**
    - "노드 하나가 **앞(Left/Prev)**과 **뒤(Right/Next)** 주소를 모두 가지고 있으면 어떨까?"
    - 여기에 **헤드 노드(Dummy Node)** 개념을 추가하여 코너 케이스(빈 리스트 처리)를 없앤다.
        

### 2. Concept

> **"나의 왼쪽의 오른쪽은 나이고, 나의 오른쪽의 왼쪽도 나이다."**

1. **노드 구조 (Node Structure)**:
    
    - 3가지 필드 필요: `llink` (왼쪽/이전), `data`, `rlink` (오른쪽/다음).
    - 공간 복잡도는 증가하지만, 양방향 탐색 속도($O(1)$)를 얻는 트레이드오프.
        
2. **헤드 노드 (Head Node) vs 헤드 포인터**:
    
    - **헤드 포인터**: 첫 번째 노드를 가리키는 변수.
    - **헤드 노드 (Dummy Node)**: 데이터를 담지 않고 **오직 삽입/삭제 로직을 단순화**하기 위해 존재하는 '가짜 노드'.
    - _효과_: 리스트가 비어있더라도 최소한 헤드 노드 하나는 존재하므로, "삭제할 노드가 없는 경우" 등의 예외 처리가 줄어든다.
        
3. **환영 이중 연결 리스트 (Circular Doubly Linked List)**:
    
    - 이중 연결 리스트의 양 끝을 서로 연결하고, 헤드 노드를 포함시킨 형태.
    - 불변식 (Invariant): 리스트 내 어떤 노드 $p$에 대해서도 다음 등식이 항상 성립한다.
        
        $$p \rightarrow llink \rightarrow rlink == p \rightarrow rlink \rightarrow llink == p$$
        

### 3. Code & Logic Verification

> 교수님은 포인터가 얽혀있는 관계를 주소값 예시를 들어 증명했습니다.

**1) 구조체 정의**



```C
typedef struct DNode {
    int data;
    struct DNode* llink; // Left Link (Previous)
    struct DNode* rlink; // Right Link (Next)
} DNode;
```

**2) 논리적 검증 (주소값 Tracing)**

- **상황**: 노드 A(100번지), 노드 B(200번지), 노드 C(300번지)가 연결됨.
- **현재 $p$**: 노드 B (200번지)를 가리킴.
    

|**노드(주소)**|**llink 값**|**rlink 값**|**비고**|
|---|---|---|---|
|**A (100)**|…|200 (B)|B의 앞|
|**B (200)**|100 (A)|300 (C)|**현재 $p$**|
|**C (300)**|200 (B)|…|B의 뒤|

- **검증 1 ($p \rightarrow llink \rightarrow rlink$)**:
    
    1. $p$ (200번지)의 `llink`는 **100번지(A)**.
    2. 100번지(A)의 `rlink`는 **200번지**.
    3. 결국 **자기 자신(B)**으로 돌아옴.
        
- **검증 2 (복잡한 포인터 체이닝)**:
    - 강의 중 예시: `$p \rightarrow llink \rightarrow llink \rightarrow rlink \rightarrow rlink$`
    - 해석: (B) $\rightarrow$ 왼쪽(A) $\rightarrow$ 왼쪽(Pre-A) $\rightarrow$ 오른쪽(A) $\rightarrow$ 오른쪽(B).
    - 결론: 연결만 잘 되어 있다면 아무리 왔다 갔다 해도 길을 잃지 않는다.

## Topic 1. 이중 연결 리스트의 연산 (Insertion & Deletion)

### 1. 🏗️ 빌드업 (Why & Context)

> "순서가 생명이다. 하나만 잘못 연결해도 미아(Dangling Pointer)가 발생한다."

- **핵심 문제:**
    - 이중 연결 리스트는 노드 하나당 `llink`, `rlink` 두 개의 팔을 뻗고 있다.
    - 새로운 노드를 삽입할 때, 기존 노드들의 팔을 먼저 놓아버리면(덮어쓰면), 연결할 대상의 주소를 잃어버리는 사고가 발생한다.
- **해결 원칙:**
    - **"내 것(New Node)부터 먼저 채워라."**
    - 새로운 노드의 링크들을 먼저 연결한 뒤, 기존 노드들의 링크를 수정해야 안전하다.
        

### 2. Concept & Logic

#### A. 삽입 연산 (`insert_node`)

- **시나리오**: `before` 노드와 그 다음 노드 사이에 `new_node`를 삽입.
- **Step-by-Step (반드시 지켜야 할 순서)**:
    
    1. `new_node->llink = before;` (내 왼쪽 팔로 `before`를 잡는다)
    2. `new_node->rlink = before->rlink;` (내 오른쪽 팔로 `before`의 원래 뒷 녀석을 잡는다)
        
        - _주의_: 이때 `before->rlink`를 먼저 덮어쓰면 뒷 녀석 주소가 날아감.
            
    3. `before->rlink->llink = new_node;` (뒷 녀석이 나를 가리키게 한다)
    4. `before->rlink = new_node;` (앞 녀석(`before`)이 나를 가리키게 한다)
        

#### B. 삭제 연산 (`delete_node`)

- **시나리오**: `removed` 노드를 삭제.
- **Logic**:
    - `removed`의 **왼쪽 노드**(`removed->llink`)가 `removed`의 **오른쪽 노드**를 가리키게 함.
    - `removed`의 **오른쪽 노드**(`removed->rlink`)가 `removed`의 **왼쪽 노드**를 가리키게 함.
    - `free(removed)`로 메모리 해제.
- **예외 처리**:
    - 삭제하려는 노드가 **헤드 노드(Dummy Node)**인 경우 삭제를 거부해야 한다. (헤드 노드는 리스트의 기준점이므로 삭제 불가)
        

### 3. Code 구현 (C언어)


```C
// 이중 연결 리스트 삽입 연산
// before: 삽입할 위치의 바로 앞 노드
// new_node: 새로 삽입할 노드
void dinsert(DNode* before, DNode* new_node) {
    // 1. 새로운 노드의 링크 설정 (안전 확보)
    new_node->llink = before;
    new_node->rlink = before->rlink;

    // 2. 기존 노드들의 링크 수정
    // 뒷 노드의 왼쪽 팔을 new_node로 연결
    before->rlink->llink = new_node; 
    // 앞 노드의 오른쪽 팔을 new_node로 연결
    before->rlink = new_node;        
}

// 이중 연결 리스트 삭제 연산
// head: 헤드 노드 (삭제 불가 기준)
// removed: 삭제할 노드
void ddelete(DNode* head, DNode* removed) {
    // 예외 처리: 헤드 노드는 삭제할 수 없음
    if (removed == head) return;

    // 링크 우회 연결 (removed를 건너뜀)
    removed->llink->rlink = removed->rlink; // 내 앞 노드가 내 뒷 노드를 가리킴
    removed->rlink->llink = removed->llink; // 내 뒷 노드가 내 앞 노드를 가리킴

    // 메모리 해제
    free(removed);
}
```

## Topic 2. 다항식 덧셈 (Polynomial Addition)

### 1. 🏗️ 빌드업 (Why & Context)

> "배열은 낭비가 심하다. $1000x^{1000} + 1$ 같은 식을 생각해보라."

- **문제 제기**:
    - 다항식을 배열로 구현하면 최고차항(degree)만큼의 크기가 필요하다.
    - $x^{1000}$ 항이 있으면, 중간항이 없어도 1000칸의 배열을 잡아야 하는 희소(Sparse) 문제 발생.
- **해결책**:
    - **연결 리스트**를 사용하여 `(계수, 지수, 링크)` 형태의 노드로, **실제로 존재하는 항만 저장**한다.
        

### 2. Concept (Algorithm Logic)

두 다항식 $A$와 $B$를 더하여 $C$를 만드는 과정 ($C = A + B$)

1. **포인터 설정**: $p$(다항식 A의 항), $q$(다항식 B의 항)를 가리킴.
2. **비교 순회 (While Loop)**: $p$와 $q$가 모두 `NULL`이 아닐 때까지 반복.
    
    - **Case 1 ($p.exp == q.exp$): 지수가 같을 때**
        - 두 계수를 더한다 (`sum = p.coef + q.coef`).
        - `sum`이 0이 아니면 결과 리스트 $C$에 추가.
        - $p$와 $q$ 모두 다음 항으로 이동.
    - **Case 2 ($p.exp > q.exp$): A의 지수가 클 때**
        - $p$항을 그대로 $C$에 복사.
        - $p$만 다음 항으로 이동 ($q$는 대기).
    - **Case 3 ($p.exp < q.exp$): B의 지수가 클 때**
        - $q$항을 그대로 $C$에 복사.
        - $q$만 다음 항으로 이동.
            
3. **잔여 처리**:
    
    - 루프 종료 후, 아직 남아있는 다항식의 나머지 항들을 몽땅 $C$ 뒤에 붙인다.

## Topic 3. 트리(Tree)와 이진 트리(Binary Tree)

### 1. 🏗️ 빌드업 (Why & Context)

> "선형 자료구조(Stack, Queue, List)로는 '계층(Hierarchy)'을 표현할 수 없다."

- **문제 제기:**
    - 파일 시스템(디렉토리), 조직도, 가계도 등은 1:1 관계가 아닌 **1:N (계층적) 관계**를 가진다.
    - 이를 배열이나 단순 연결 리스트로 구현하려면 매우 비효율적이다.
- **핵심 아이디어의 단초:**
    - "자료구조를 평면이 아닌 입체적(가지치기) 형태로 만들자."
    - **Why Binary Tree? (왜 하필 이진 트리인가?)**
        - 일반 트리(General Tree)는 자식 노드가 N개일 수 있다.
        - 자식이 3개인 노드, 5개인 노드, 0개인 노드가 섞여 있다면, **구조체(`struct`)를 표준화(규격화)하기 어렵다.**
        - **"모든 노드의 자식을 최대 2개로 제한하자."** $\rightarrow$ `Left`, `Right` 포인터만 있으면 모든 트리를 표현할 수 있으며, 구현이 **표준화(Standardization)**된다.
            

### 2. Concept

#### A. 트리의 용어 정의

- **차수(Degree)**:
    - **노드의 차수**: 특정 노드가 가진 자식 노드의 수.
    - **트리의 차수**: 트리 내 모든 노드 중 **가장 큰 차수**.
- **높이(Height)**: 루트에서 가장 깊은 단말 노드(Leaf)까지의 레벨 수.
- **포레스트(Forest)**: 서브 트리(Subtree)들의 집합. (루트를 제거하면 숲(Forest)이 남는다.)
    

#### B. 이진 트리 (Binary Tree)의 정의

1. **정의**: 모든 노드가 **최대 2개**의 서브 트리(왼쪽, 오른쪽)를 갖는 트리. (차수가 2 이하)
2. **재귀적 성질**: 루트를 제외한 왼쪽 서브 트리와 오른쪽 서브 트리 역시 이진 트리여야 한다. (공집합도 이진 트리로 간주)
3. **수치적 성질 (높이가 $h$일 때)**:
    
    - **최소 노드 개수**: $h$개 (한 줄로 늘어선 경우).
    - **최대 노드 개수**: $2^h - 1$개 (꽉 채워진 경우).
    - **높이와 노드 수($n$)의 관계**: $n \le 2^h - 1$ $\leftrightarrow$ $h \ge \log_2(n+1)$.

## Topic 4. 이진 트리의 종류와 표현법

### 1. 이진 트리의 분류 (Types)

트리의 형태에 따라 저장 방식과 효율성이 달라지므로 명확한 구분이 필요합니다.

|**종류**|**정의 및 특징**|**비고**|
|---|---|---|
|**포화 이진 트리**<br><br>  <br><br>(Full Binary Tree)|높이가 $h$일 때, 노드 개수가 정확히 $2^h - 1$개인 트리.|모든 레벨이 꽉 차 있음.|
|**완전 이진 트리**<br><br>  <br><br>(Complete Binary Tree)|높이가 $h$일 때, $h-1$ 레벨까지는 꽉 차 있고, 마지막 레벨은 **왼쪽부터 순서대로** 채워진 트리.|**힙(Heap)** 구현의 기반. 중간에 빈틈이 없어야 함.|
|**편향 이진 트리**<br><br>  <br><br>(Skewed Binary Tree)|모든 노드가 왼쪽(또는 오른쪽) 자식만 가지는 트리.|사실상 **연결 리스트**와 동일. 탐색 효율 최악 ($O(N)$).|

### 2. Code 구현: 배열(Array) vs 연결 리스트

교수님은 트리를 구현하는 두 가지 방법 중, **배열 표현법**의 인덱스 규칙을 강조하셨습니다.

#### A. 배열 표현법 (Array Representation)

> 주로 **완전 이진 트리**나 **포화 이진 트리**에서 사용됩니다.

- **인덱스 규칙 (루트 노드를 `index 1`로 가정 시)**:
    - 부모 노드 인덱스: $i$
    - **왼쪽 자식** 인덱스: $2 \times i$
    - **오른쪽 자식** 인덱스: $(2 \times i) + 1$
- **장점**: 인덱스 연산만으로 부모-자식 이동 가능.
- **단점**: 편향 트리인 경우, 사용하지 않는 메모리 공간(낭비)이 너무 많아짐.
    

#### B. 연결 리스트 표현법 (Linked List Representation)

> 일반적인 트리 구현 방식입니다.



```C
typedef struct TreeNode {
    char data; // 데이터
    struct TreeNode* left;  // 왼쪽 자식
    struct TreeNode* right; // 오른쪽 자식
} TreeNode;
// 자식이 없으면 해당 링크에 NULL을 할당하여 구현의 통일성 유지
```

## Topic 1. 이진 트리의 구현 I: 배열 (Array)

### 1. 🏗️ 빌드업 (Why & Context)

> "인덱스 0번을 비워두는 작은 센스가 수식을 직관적으로 만든다."

- **핵심 전략:**
    - 배열은 **완전 이진 트리(Complete Binary Tree)**나 **포화 이진 트리(Full Binary Tree)**일 때 가장 효율적이다. (빈 공간이 없으므로)
    - 인덱스 계산을 편하게 하기 위해 **Index 0은 사용하지 않고(Dummy), Root를 Index 1에 배치**한다.
        

### 2. Concept & Formula

**노드 $i$를 기준으로 한 인덱스 공식** (Root가 1일 때)

1. **부모 노드 찾기 (Parent)**:
    
    - $\text{Parent}(i) = \lfloor \frac{i}{2} \rfloor$ (정수 나눗셈)
    - 예: Index 3의 부모 $\rightarrow 3/2 = 1.5 \rightarrow 1$ (Root)
    - 예: Index 11의 부모 $\rightarrow 11/2 = 5.5 \rightarrow 5$
        
2. **왼쪽 자식 찾기 (Left Child)**:
    
    - $\text{Left}(i) = 2 \times i$
    - 예: Index 5의 왼쪽 자식 $\rightarrow 10$
        
3. **오른쪽 자식 찾기 (Right Child)**:
    
    - $\text{Right}(i) = 2 \times i + 1$
    - 예: Index 5의 오른쪽 자식 $\rightarrow 11$
        

### 3. Trade-off (장단점)

- **장점**: 인덱스 연산만으로 $O(1)$ 접근 가능, 포인터 저장 공간 불필요.
- **단점**:
    - **편향 트리(Skewed Tree)**일 경우, $2^k$에 해당하는 인덱스만 쓰이고 나머지는 낭비됨 (메모리 효율 급감).
    - **크기 고정**: 배열 선언 시 크기가 정해지므로, 실행 중 확장이 어렵다.

## Topic 2. 이진 트리의 구현 II: 연결 리스트 (Linked List)

### 1. 🏗️ 빌드업 (Why & Context)

> "배열의 크기 제약과 메모리 낭비를 해결하기 위해 동적 할당을 사용한다."

- **핵심 아이디어**:
    - 노드와 노드 사이를 **포인터(링크)**로 연결한다.
    - 데이터가 들어올 때마다 `malloc`으로 메모리를 할당하므로 불필요한 낭비가 없다.
        

### 2. Code 구현 (C언어)

C

```sql
#include <stdio.h>
#include <stdlib.h>

typedef struct TreeNode {
    int data;
    struct TreeNode* left;
    struct TreeNode* right;
} TreeNode;

int main() {
    // 1. 노드 생성 (메모리 할당)
    TreeNode* n1 = (TreeNode*)malloc(sizeof(TreeNode));
    TreeNode* n2 = (TreeNode*)malloc(sizeof(TreeNode));
    TreeNode* n3 = (TreeNode*)malloc(sizeof(TreeNode));

    // 2. 데이터 설정
    n1->data = 10; // Root
    n2->data = 20; // Left Child
    n3->data = 30; // Right Child

    // 3. 링크 연결 (핵심)
    // n1의 left 포인터에 n2의 '주소'를 저장
    n1->left = n2;  
    n1->right = n3; 

    // 4. Leaf 노드의 링크 처리 (NULL)
    n2->left = NULL;
    n2->right = NULL;
    n3->left = NULL;
    n3->right = NULL;

    return 0;
}
```

### 3. ⚠️ 주의사항 (오개념 경계)

- **포인터 연결의 의미**:
    - `n1->left = n2;` 코드를 작성할 때, 그림상으로 선을 긋는 것이라고 단순히 생각하면 안 된다.
    - 정확한 의미: `n1` 구조체 내부의 `left`라는 변수 공간에 `n2`가 가리키고 있는 **메모리 주소값(0x100 등)**을 복사해 넣는 것이다.
    - 시험에서 그림을 그릴 때, `n2` 변수 자체를 가리키는 것이 아니라 `n2`가 가리키는 **실제 힙(Heap) 영역의 노드**를 가리키도록 그려야 한다.

> [!faq]Q. 이진 트리를 배열로 구현할 때 Index 0을 비워두는 이유는?
>
> 🗣️ 핵심 답변
>
> 인덱스 연산의 직관성과 효율성 때문입니다.
>
> Root를 Index 1에 두면, 어떤 노드 $i$의 왼쪽 자식은 $2i$, 오른쪽 자식은 $2i+1$, 부모는 $i/2$라는 매우 간단한 수식으로 접근할 수 있습니다. 0번부터 시작하면 수식에 보정값($+1, -1$)이 들어가 연산이 복잡해집니다.

> [!faq]Q. 연결 리스트로 구현된 트리에서 Leaf Node 처리는 어떻게 하는가?
>
> 🗣️ 핵심 답변
>
> 자식 노드가 없는 Leaf Node의 left, right 포인터에는 반드시 NULL을 할당해야 합니다.
>
> 이를 통해 재귀 탐색이나 순회(Traversal) 시 **종료 조건(Base Case)**으로 활용하여 무한 루프나 메모리 참조 오류를 방지할 수 있습니다.
