## 🇰🇷 한국어 번역: 메모리 구조와 동적 메모리 할당

메모리는 우리 시스템에서 중요하고 핵심적인 자원이며, 메모리 아키텍처, 운영체제가 메모리를 관리하는 방식, 그리고 프로그래머로서 우리가 메모리에 접근하는 방식을 아는 것은 항상 좋습니다.

이번 강의에서는 **동적 메모리** 개념에 대해 논의하고 C 또는 C++를 사용하여 동적 메모리를 다루는 방법을 알아볼 것입니다.

일반적인 아키텍처에서 프로그램이나 애플리케이션에 할당되는 메모리는 **네 가지 세그먼트**로 나눌 수 있습니다.

---

### 메모리의 4가지 세그먼트

1. **텍스트 세그먼트(Text Segment)**: 메모리의 한 세그먼트는 실행해야 할 **명령어(instructions)**를 저장하도록 할당됩니다.
2. **데이터 세그먼트(Data/Global Variable Segment)**: 다른 섹션은 모든 **정적(static) 또는 전역(global) 변수**를 저장합니다. 이 변수들은 함수 내부에 선언되지 않으며, 애플리케이션이 실행되는 전체 수명 주기를 가지며, 애플리케이션이 실행되는 동안 언제 어디서든 접근 가능합니다.
3. **스택(Stack)**: 메모리의 한 섹션은 **함수 호출**에 대한 모든 정보와 모든 **지역 변수(local variables)**를 저장하는 데 사용됩니다. 지역 변수는 함수 내부에 선언되며, 함수가 실행되는 동안에만 존재합니다.
4. **힙(Heap)**: 이 네 번째 세그먼트인 힙을 왜 사용하는지는 잠시 후에 다시 논의하겠습니다.
    

**텍스트 세그먼트, 전역 변수 세그먼트, 스택**의 세 세그먼트에 할당된 메모리 양은 애플리케이션이 실행되는 동안 **증가하지 않습니다**.

---

### 프로그램 실행 시 스택 사용 방식

먼저 프로그램이 실행될 때 이 세 가지 메모리 세그먼트가 어떻게 사용되는지 이해해 봅시다. 여기에 간단한 C 프로그램이 있습니다. 우리는 숫자의 제곱을 반환하는 함수 `Square`를 가지고 있습니다. 두 개의 인자 `x`와 `y`를 받아 $x$ 더하기 $y$의 제곱을 반환하는 또 다른 함수 `Square of Sum`이 있습니다. 그리고 `main` 메서드에서 두 인자 `a`와 `b`를 전달하여 이 함수 `Square of Sum`을 호출하고 있습니다.

이제 이 프로그램이 실행될 때 메모리에서 어떤 일이 발생하는지 봅시다.

녹색 직사각형은 **스택**으로 예약된 메모리이고, 주황색 직사각형은 **정적/전역 변수 섹션**으로 예약된 메모리라고 가정해 봅시다.

프로그램이 실행을 시작하면, 먼저 `main` 메서드가 호출됩니다. `main` 메서드가 호출되면 **스택**에서 `main`의 실행을 위해 일정량의 메모리가 할당됩니다. 이 할당된 메모리 영역을 `main` 메서드를 위한 **스택 프레임(Stack Frame)**이라고도 부릅니다. 모든 지역 변수, 인자, 그리고 이 함수가 어디로 되돌아가야 하는지에 대한 정보(복귀 주소)가 이 스택 프레임 내에 저장됩니다. 메서드에 대한 스택 프레임의 크기는 프로그램이 컴파일될 때 계산됩니다.

이 변수 `total`은 전역 변수이므로 전역 변수 섹션에 위치해야 합니다 (함수 내부에 선언되지 않았기 때문에 어디서든 접근 가능합니다).

이제 `main`이 `Square of Sum` 메서드(`SOS`로 줄여 쓰겠습니다)를 호출하면, `Square of Sum` 호출을 위한 스택 프레임이 할당되고, 지역 변수 `x`, `y`, `z`는 이 스택 프레임에 위치합니다.

이제 `Square of Sum`이 `Square` 함수를 호출하면 (`Square`를 `SQ`로 줄여 씁니다), `Square`를 위한 또 다른 스택 프레임이 할당되고 그 자체의 지역 변수를 가질 것입니다.

프로그램 실행 중 어느 시점에서든, 스택의 맨 위에 있는 함수가 실행 중이며, 나머지는 잠시 멈춰(paused) 위에 있는 함수가 무언가를 반환하기를 기다린 후 실행을 재개합니다.

이것이 바로 **호출 스택(Call Stack)**이라고 불리는 것입니다. (중첩된 메서드 호출을 보여주기 위해 프로그램 로직을 이렇게 작성했습니다.)

현재 우리가 특정 명령문(예: `Square` 내부)을 실행 중이라고 가정해 봅시다. 이 단계에서 호출 스택은 이 세 가지 메서드(`main`, `Square of Sum`, `Square`)를 가집니다.

이제 `Square` 메서드가 완료되면, 우리는 `Square of Sum` 내의 특정 명령문으로 되돌아갑니다. `Square` 함수가 반환되는 즉시 **스택 메모리에서 제거(cleared off)**되며, 이제 `Square of Sum` 함수가 실행을 재개합니다.

다시 `Square of Sum`이 완료되면, 제어권은 `total = Square of Sum(…)` 라인으로 이동하고 `main`이 다시 재개됩니다. 이제 `main`은 `printf`를 호출할 것이고, `printf`는 다시 스택의 맨 위로 올라갑니다. `printf`가 완료되면 제어권은 다시 `main`으로 돌아오고, `main`도 완료됩니다.

`main`이 완료되면 프로그램도 종료됩니다. 결국 전역 변수도 제거됩니다. (이 프로그램에서는 `total` 변수를 전역으로 유지할 필요가 없었지만, 개념을 이해하기 위해 전역 변수를 사용했습니다. 전역 변수는 여러 함수에서 필요하고 프로그램의 전체 수명 동안 필요한 경우에만 할당해야 하며, 그렇지 않으면 메모리 낭비입니다.)

---

### 스택의 한계와 스택 오버플로우

여기서 한 가지 더 지적해야 할 점이 있습니다. 프로그램이 시작될 때 운영체제는 일정량의 예약된 공간(예: 1MB)을 **스택**으로 할당하지만, 스택 프레임과 지역 변수의 실제 할당은 **실행 시간(runtime)**에 스택에서 발생합니다.

만약 함수 호출이 계속되어 (예: A가 B를 호출, B가 C를 호출, …) **호출 스택이 스택을 위해 예약된 메모리를 초과**하게 되면, 이를 **스택 오버플로우(Stack Overflow)**라고 하며 이 경우 프로그램이 **충돌(crash)**하게 됩니다. 스택 오버플로우의 일반적인 경우는 잘못된 **재귀(recursion)**를 작성하여 프로그램이 무한히 재귀에 빠지는 경우입니다.

따라서 스택에는 몇 가지 **제한 사항**이 있습니다.

- 스택에 할당된 메모리는 실행 시간 동안 **증가하지 않습니다**. 애플리케이션은 스택에 더 많은 메모리를 요청할 수 없습니다.
- 스택으로의 메모리 할당 및 해제는 정해진 규칙(함수 호출 시 **푸시(Push)**, 종료 시 **팝(Pop)**)에 따라 이루어지므로, 스택에 있는 변수의 범위를 조작하는 것은 **불가능**합니다.
- 지역 변수로 배열과 같은 **큰 데이터 타입**을 선언해야 하는 경우, 배열의 크기를 **컴파일 시점(compile time)**에만 알 수 있어야 합니다. 실행 시간 동안 일부 매개변수를 기반으로 배열 크기를 결정해야 하는 시나리오에서는 스택에 문제가 발생합니다.

### 힙(Heap)의 도입

이러한 모든 문제, 즉 큰 메모리 덩어리를 할당하거나, 원하는 시간 동안 변수를 메모리에 유지하는 등의 문제를 해결하기 위해 **힙(Heap)**이 있습니다.

스택과 달리 애플리케이션의 **힙은 고정되어 있지 않습니다**. 크기는 애플리케이션 수명 주기 동안 **변동**할 수 있으며, 메모리 할당 및 해제에 정해진 규칙이 없습니다.

프로그래머는 힙에서 얼마나 많은 메모리를 사용할지, 애플리케이션 수명 주기 동안 데이터를 메모리에 언제까지 유지할지 **완전히 제어**할 수 있으며, 시스템 자체의 메모리가 고갈되지 않는 한 **힙은 계속 커질 수 있습니다**. 이것은 또한 위험한 일이며, 이 때문에 힙을 사용할 때는 정말 주의해야 합니다.

힙은 때때로 **자유 메모리 풀(free pool of memory)** 또는 **자유 저장소(free store of memory)**라고도 불립니다. 우리는 힙에서 원하는 만큼 얻을 수 있습니다.

힙이 운영체제, 언어 런타임 또는 컴파일러에 의해 어떻게 구현되는지는 컴퓨터 아키텍처의 문제입니다. 그러나 프로그래머로서 힙을 추상화하여 보는 방식은, **우리가 필요에 따라 유연하게 사용할 수 있는 하나의 큰 자유 메모리 풀**이라는 것입니다.

**힙**은 또한 **동적 메모리(Dynamic Memory)**라고 불리며, 힙을 사용하는 것을 **동적 메모리 할당(Dynamic Memory Allocation)**이라고 합니다.

### C/C++에서 힙 사용하기 (동적 메모리 할당)

이제 C 또는 C++ 프로그램에서 힙을 사용하는 방법을 봅시다. (여기서 지적해야 할 한 가지는, **힙**이 하나의 **데이터 구조**이기도 하지만, 여기서 사용되는 **힙**이라는 용어는 **메모리의 큰 자유 풀**을 의미하는 것일 뿐이며 데이터 구조로서의 힙과는 **전혀 관련이 없다**는 것입니다.)

C에서 동적 메모리를 사용하려면 네 가지 함수 `malloc`, `calloc`, `realloc`, 그리고 `free`에 대해 알아야 합니다. C++에서 동적 메모리를 사용하려면 두 가지 연산자 `new`와 `delete`에 대해 알아야 합니다. C++는 C의 상위 집합이므로 이 네 가지 함수도 C++에서 사용할 수 있지만, C++ 프로그래머는 주로 `new`와 `delete`를 사용합니다.

#### C 스타일 코드 (malloc/free)



```C
// int a; // 지역 변수, 스택에 할당됨.
int *p = (int*)malloc(sizeof(int));
```

힙에 공간을 예약하거나 할당받으려면 `malloc` 함수를 호출해야 합니다. `malloc` 함수는 힙에 할당할 메모리 크기를 **바이트 단위**로 요청합니다. `malloc(sizeof(int))`라고 하면, 4바이트 크기의 메모리 블록(일반적인 정수 크기)을 힙에 예약하고, `malloc`은 이 블록의 **시작 주소에 대한 포인터**를 반환합니다. `malloc`은 `void` 포인터를 반환하므로, `int *p`에 저장하기 위해 **형 변환(typecasting)**을 합니다.

**`p` 자체는 `main`의 지역 변수이므로 스택 프레임에 할당됩니다.** `p`는 힙에 있는 4바이트 블록의 주소(예: 200)를 저장합니다.



```C
*p = 10;
```

힙에 있는 메모리를 사용하는 유일한 방법은 **참조(reference)**를 통하는 것입니다. `malloc`은 단지 힙에서 빈 공간을 찾아 예약하고 포인터를 돌려줄 뿐이며, 이 블록에 접근하는 유일한 방법은 함수에 지역적인 포인터 변수를 사용하는 것입니다.



```C
p = (int*)malloc(sizeof(int)); // 두 번째 malloc 호출
*p = 20;
```

두 번째 `malloc` 호출을 하면, 힙에 또 다른 4바이트 블록이 할당됩니다(예: 주소 400). 이 주소를 다시 변수 `p`에 저장합니다. 이제 `p`는 400을 가리킵니다.

**중요한 점:** 이전 블록(주소 200)은 **여전히 힙에 남아 있으며** 자동으로 해제되지 않습니다. 이는 불필요한 메모리 소비이므로, 동적으로 할당된 메모리 블록 사용이 완료되면 **프로그래머가 반드시 해제**해야 합니다.


```C
free(p_old); // p_old는 첫 번째 malloc 주소를 저장했어야 함.
// 또는
free(p); // 현재 p가 가리키는 주소 해제
```

`malloc`으로 할당된 모든 메모리는 `free` 함수를 호출하여 해제됩니다. `free`에는 메모리 블록의 시작 주소에 대한 포인터를 전달합니다.

**힙의 특징:**

- 힙에 할당된 것은 스택처럼 함수가 완료될 때 **자동으로 해제되지 않습니다**.
- 전역 변수처럼 애플리케이션의 전체 수명 동안 유지될 필요가 없습니다.
- **프로그래머가 해제 시점을 제어**할 수 있습니다.
    

**배열 할당:** 힙에 배열을 저장하려면, 총 배열 크기에 해당하는 메모리 블록을 `malloc`으로 요청합니다. 예를 들어, 20개의 정수 배열을 원한다면 $20 \times \text{sizeof}(\text{int})$ 바이트를 요청합니다. 힙에 20개의 정수를 위한 연속된 블록이 할당되고, 우리는 그 **시작 주소(배열의 기본 주소)**를 얻게 됩니다. 이후 `p[0]`, `p[1]` 등으로 배열처럼 사용할 수 있습니다.

**에러 처리:** `malloc`이 힙에서 빈 블록을 찾지 못해 메모리 할당에 실패하면 **`NULL`을 반환**합니다. 따라서 적절한 에러 처리를 위해 이를 알아야 합니다.

#### C++ 스타일 코드 (new/delete)

C++에서는 `malloc`과 `free` 대신 **`new`와 `delete` 연산자**를 사용합니다.



```C++
int *p = new int; // malloc 대신 new 사용
*p = 10;
delete p; // free 대신 delete 사용
```

**배열 할당/해제:**


```C++
int *p = new int[20]; // 배열 할당 시 크기를 대괄호 안에
delete[] p; // 배열 해제 시 delete와 대괄호를 함께 사용
```

`new`와 `delete` 연산자는 **타입 안전성(type safe)**이 있습니다. `malloc`처럼 `void` 포인터를 반환하여 형 변환을 할 필요가 없으며, 특정 타입의 포인터를 반환합니다.
