## 📜 원본 맥락
![]({S}%20인프런%20그린코딩%2052시간%20풀스택+%20Gemini.md#^sflg2x)

자바스크립트는 한줄씩 번역,실행하는 인터프리터 방식인데 왜 전체 코드를 그전에 한번 쓱 흝어봐서 호이스팅이 발생해?

---
## 정리
- 자바스크립트엔진은 실행전에 전체 코드를 빠르게 스캔
	- 이 단계에서 선언문들을 찾아내어 메모리에 먼저 기록, 이걸 호이스팅이라고 한다
	- 실제로 코드의 위치를 물리적으로 바꾸는게 아니라 메모리에 먼저 기록하는것이 호이스팅이다.
	- 자바스크립트 엔진은 코드를 실행하기 전, 해당 스코프를 훑으며 `function hello`나 `var a` 같은 선언을 먼저 찾습니다. 그리고 'hello'라는 이름은 함수를, 'a'라는 이름은 변수를 가리킨다고 **메모리 환경에 미리 기록**해 둡니다.
	- 이후 코드를 한 줄씩 실행하다가 `hello()`를 만나면, 실제 코드 위치와 상관없이 메모리에 이미 기록된 `hello` 함수를 찾아 실행하는 것입니다.
- 그리고난뒤 코드의 첫줄로 돌아와 한줄씩 순서대로 코드를 실행
	- 이때 `a = 10` 같은 할당문을 만나 값을 저장하거나, `hello()` 같은 함수를 호출하는 등의 실제 동작이 일어납니다.
	- 이미 준비 단계에서 변수와 함수의 존재를 파악해두었기 때문에, 에러 없이 코드를 실행할 수 있습니다
- 현대의 자바스크립트 엔진은 실행의 효율성을 높이기 위한 준비작업(호이스팅)을 한다 그러나 자바처럼 실행파일 자체를 만들기 위한 별도의 엄격한 과정은 아니기 떄문에 인터프리터 언어의 특징이 더 강하게 나타나는 것이다.
