# 2회
### 📝 소프트웨어 설계 문제 은행 (Obsidian 용)

> [!note]- 1. 소프트웨어 설계 시 구축된 플랫폼의 성능 특성 분석에 사용되는 측정 항목이 아닌 것은? (① 응답시간 ② 가용성 ③ 사용률 ④ 서버 튜닝)
>
> **정답:** ④ 서버 튜닝
>
> **해설:**
>
> 서버 튜닝(Server Tuning)은 성능을 개선하기 위한 **활동**이지, 성능을 측정하는 지표(Metric)가 아닙니다. 측정 항목에는 응답시간(Response Time), 가용성(Availability), 사용률(Utilization), 처리량(Throughput) 등이 있습니다.

> [!note]- 2. 자료 흐름도(DFD)의 각 요소별 표기 형태의 연결이 옳지 않은 것은? (① Process : 원 ② Data Flow : 화살표 ③ Data Store : 삼각형 ④ Terminator : 사각형)
>
> **정답:** ③ Data Store : 삼각형
>
> **해설:**
>
> DFD에서 데이터 저장소(Data Store)는 평행선(두 줄)이나 한쪽이 트인 직사각형으로 표기합니다. 삼각형은 주로 제어 흐름이나 다른 도식에서 사용됩니다.

> [!note]- 3. UML 모델에서 사용하는 Structural Diagram에 속하지 않은 것은? (① Class Diagram ② Object Diagram ③ Component Diagram ④ Activity Diagram)
>
> **정답:** ④ Activity Diagram
>
> **해설:**
>
> Activity Diagram은 시스템의 동적인 흐름을 나타내는 **행위 다이어그램(Behavioral Diagram)**에 속합니다. 1, 2, 3번은 정적인 구조를 나타내는 구조 다이어그램입니다.

> [!note]- 4. 애자일 방법론에 해당하지 않는 것은? (① 기능 중심 개발 ② 스크럼 ③ 익스트림 프로그래밍 ④ 하둡)
>
> **정답:** ④ 하둡
>
> **해설:**
>
> 하둡(Hadoop)은 대용량 데이터를 분산 처리하기 위한 **오픈 소스 프레임워크**입니다. 애자일(Agile)은 소프트웨어 개발 방법론의 한 종류입니다.

> [!note]- 5. 리팩토링(Refactoring)을 하는 목적으로 옳은 것은? (① 산출물 버전 관리 ② 새로운 코드 설계 기술 ③ 기능 추가 ④ 내부 구조 개선)
>
> **정답:** ④ 소프트웨어의 기능 변경 없이 내부 구조만을 개선하여 소프트웨어를 보다 이해하기 쉽고, 수정하기 쉽도록 만들기 위함이다.
>
> **해설:**
>
> 리팩토링의 핵심은 **"외부적 기능 변경 없이"** 내부의 코드 구조를 효율적으로 개선(가독성 향상, 유지보수 용이)하는 것입니다.

> [!note]- 6. UI 시스템의 상태와 사용자의 지시에 대한 효과를 보여주어 명령 진행 상황을 해석할 수 있도록 도와주는 것은? (① Feedback ② Posture ③ Module ④ Hash)
>
> **정답:** ① Feedback
>
> **해설:**
>
> 피드백(Feedback)은 사용자의 작용에 대해 시스템이 반응하는 것을 의미하며, 현재 상태를 사용자에게 즉각적으로 알려주는 역할을 합니다.

> [!note]- 7. 하향식 설계 방법과 상향식 설계 방법에 대한 비교 설명으로 가장 좋지 않은 것은? (① 하향식은 통합이 간단하다 ② 하향식은 초기 단계에 세부 사항이 필요하다 ③ 상향식은 하위 모듈부터 설계한다 ④ 상향식은 기능 추가가 쉽다)
>
> **정답:** ② 하향식 설계에서 레벨이 낮은 데이터 구조의 세부 사항은 설계 초기 단계에서 필요하다.
>
> **해설:**
>
> 하향식(Top-down) 설계는 상위 레벨에서 시작하여 점진적으로 구체화하므로, 초기 단계에서는 하위의 세부 사항보다는 **전체적인 구조와 인터페이스 정의**에 집중합니다.

> [!note]- 8. 소프트웨어 아키텍처 구축 절차를 올바른 순서대로 나열한 것은? (A: 검증 및 승인, B: 요구사항 분석, C: 아키텍처 설계, D: 아키텍처 분석)
>
> **정답:** B -> D -> C -> A
>
> **해설:**
>
> 1. 요구사항 분석 (B)
>     
> 2. 아키텍처 분석 (D)
>     
> 3. 아키텍처 설계 (C)
>     
> 4. 검증 및 승인 (A)
>     
>     수식 예시: $Step = 4$ 단계 순차 진행
>

> [!note]- 9. 객체지향에서 정보 은닉과 가장 밀접한 관계가 있는 것은? (① Encapsulation ② Class ③ Method ④ Instance)
>
> **정답:** ① Encapsulation (캡슐화)
>
> **해설:**
>
> 캡슐화는 데이터와 데이터를 처리하는 함수를 하나로 묶는 것으로, 외부에서 직접적인 접근을 제한하여 정보를 은닉하는 목적을 가집니다.

> [!note]- 10. 객체 지향 소프트웨어 공학에서 하나 이상의 유사한 객체들을 묶어서 하나의 공통된 특성을 표현한 것은? (① 트랜잭션 ② 클래스 ③ 시퀀스 ④ 서브루틴)
>
> **정답:** ② 클래스 (Class)
>
> **해설:**
>
> 클래스는 객체들을 생성하기 위한 청사진(Template)이며, 공통된 속성과 행위를 정의한 집합체입니다.

> [!note]- 11. GoF(Gang of Four)의 디자인 패턴에서 행위 패턴에 속하는 것은? (① Builder ② Visitor ③ Prototype ④ Bridge)
>
> **정답:** ② Visitor
>
> **해설:**
>
> - Builder, Prototype: 생성 패턴
>     
> - Bridge: 구조 패턴
>     
> - Visitor: 행위 패턴
>     

> [!note]- 12. CASE 도구에 대한 설명으로 거리가 먼 것은? (① 자동화 도구 ② 문서 자동화 제공 ③ 커뮤니케이션 증대 ④ 2000년대 이후 객체지향에만 한정 활용)
>
> **정답:** ④ 2000년대 이후 소개되었으며, 객체지향 시스템에 한해 효과적으로 활용된다.
>
> **해설:**
>
> CASE(Computer Aided Software Engineering) 도구는 1980년대부터 사용되었으며, 특정 방법론(객체지향 등)에만 한정되지 않고 다양한 개발 환경에서 자동화를 위해 사용됩니다.

> [!note]- 13. UI 설계 원칙에서 누구나 쉽게 이해하고 사용할 수 있어야 한다는 것은? (① 유효성 ② 직관성 ③ 무결성 ④ 유연성)
>
> **정답:** ② 직관성 (Intuitiveness)
>
> **해설:**
>
> 직관성은 사용자가 별도의 교육 없이도 시스템의 기능을 쉽게 파악하고 사용할 수 있는 성질을 의미합니다.

> [!note]- 14. 효과적인 모듈화 설계 방법으로 가장 거리가 먼 것은? (① 결합도 강하게, 응집도 약하게 ② 복잡도 줄이기 ③ 유지보수 용이 ④ 적절한 모듈 크기)
>
> **정답:** ① Coupling은 강하게 Cohesion는 약하게 설계한다.
>
> **해설:**
>
> 좋은 소프트웨어 설계는 **결합도(Coupling)를 낮게(Loose), 응집도(Cohesion)를 높게(Strong)** 설계하는 것입니다.

> [!note]- 15. 객체 지향 기법에서 클래스에 속한 각각의 객체를 의미하는 것은? (① Instance ② Message ③ Method ④ Module)
>
> **정답:** ① Instance
>
> **해설:**
>
> 인스턴스는 추상적인 클래스로부터 실제 메모리에 할당되어 구체화된 실체를 의미합니다.

> [!note]- 16. 럼바우의 객체 지향 분석과 거리가 먼 것은? (① 기능 모델링 ② 동적 모델링 ③ 객체 모델링 ④ 정적 모델링)
>
> **정답:** ④ 정적 모델링
>
> **해설:**
>
> 럼바우(Rumbaugh)의 분석 기법(OMT)은 객체 모델링(Object), 동적 모델링(Dynamic), 기능 모델링(Functional)의 3개 단계로 이루어집니다.

> [!note]- 17. 다음 내용이 설명하는 디자인 패턴은? (객체 생성 인터페이스 정의, 인스턴스 결정은 서브클래스, Virtual-Constructor 패턴) (① Visitor ② Observer ③ Factory Method ④ Bridge)
>
> **정답:** ③ Factory Method 패턴
>
> **해설:**
>
> 팩토리 메서드 패턴은 상위 클래스에서 인터페이스를 정의하고, 실제 어떤 클래스를 생성할지는 하위 클래스에서 결정하도록 위임하는 패턴입니다.

> [!note]- 18. 정형 기술 검토(FTR)의 지침으로 틀린 것은? (① 의제 제한 ② 논쟁 제한 ③ 문제 영역 명확화 ④ 참가자 수 제한 없음)
>
> **정답:** ④ 참가자의 수를 제한하지 않는다.
>
> **해설:**
>
> FTR은 효율적인 검토를 위해 참가자의 수를 3~5명 정도로 적절히 제한해야 합니다.

> [!note]- 19. 요구사항 명세 기법에 대한 설명으로 틀린 것은? (① 비정형은 자연어 기반 ② 비정형은 Z 기법 사용 ③ 정형은 수학적 원리 사용 ④ 정형이 더 간결함)
>
> **정답:** ② 비정형 명세 기법은 사용자의 요구를 표현할 때 Z 비정형 명세 기법을 사용한다.
>
> **해설:**
>
> Z 명세 기법은 수학적 집합론과 논리를 바탕으로 하는 **정형(Formal)** 명세 기법의 대표적인 예입니다.

> [!note]- 20. 주어진 한 모듈(Module)을 제어하는 상위 모듈 수를 나타내는 것은? (① Fan-out ② Coupling ③ Fan-in ④ Cohesion)
>
> **정답:** ③ Fan-in
>
> **해설:**
>
> - Fan-in: 어떤 모듈을 사용하는(제어하는) 상위 모듈의 수
>     
> - Fan-out: 어떤 모듈이 사용하는(제어하는) 하위 모듈의 수
>     

> [!note]- 21. 자료 흐름도(DFD)를 작성하는데 지침이 될 수 없는 항목은? (① 변환 시 새 이름 부여 ② 입력이 있어야 출력 발생 ③ 저장소 입력 시 반드시 출력 표시 ④ 상위/하위 자료 흐름 일치)
>
> **정답:** ③ 자료 저장소에 입력 화살표가 있으면 반드시 출력 화살표도 표시되어야 한다.
>
> **해설:**
>
> 자료 저장소(Data Store)는 데이터를 단순히 기록하기만 하거나(입력만 있음), 읽기만 할(출력만 있음) 수도 있으므로 반드시 쌍으로 존재해야 하는 것은 아닙니다.

> [!note]- 22. 다음 중 스크럼(Scrum) 방법론에서 일반적으로 하지 않는 활동은? (① 제품 백로그 작성 ② 사용자 스토리 기반 계획 ③ 스프린트 회고 ④ PM 단독 평가)
>
> **정답:** ④ 프로젝트 완료 후 모든 업무를 PM이 단독 평가한다.
>
> **해설:**
>
> 스크럼은 팀 중심의 수평적 문화입니다. 평가는 스프린트 리뷰와 회고를 통해 팀 전체가 참여하며, 특정 관리자가 단독으로 평가하지 않습니다.

> [!note]- 23. 요구사항 명세서를 미리 배포하여 사전 검토한 후 짧은 회의를 통해 오류를 검출하는 검토 방법은? (① 빌드 검증 ② 동료 검토 ③ 워크스루 ④ 개발자 검토)
>
> **정답:** ③ 워크스루 (Walkthrough)
>
> **해설:**
>
> 워크스루는 개발자가 주체가 되어 명세서를 사전에 배포하고, 짧은 회의를 통해 논리적 오류를 찾아내는 비정형 검토 방법입니다.


> [!note]- 25. UI 설계 도구 중 디자인과 사용 방법 평가를 위해 실제 제품과 흡사하게 만든 정적인 모형은? (① Prototype ② Mockup ③ Storyboard ④ Wireframe)
>
> **정답:** ② Mockup (목업)
>
> **해설:**
>
> 목업은 정적인 형태의 모형으로 디자인과 구성 요소를 확인하는 용도입니다. 반면 스토리보드는 흐름과 페이지 이동을 시각화한 문서입니다.

> [!note]- 26. XP(eXtreme Programming)의 5가지 핵심 가치에 해당하지 않는 것은? (① 용기 ② 단순성 ③ 피드백 ④ 정형성)
>
> **정답:** ④ 정형성
>
> **해설:**
>
> XP의 5가지 핵심 가치는 **의사소통(Communication), 단순성(Simplicity), 피드백(Feedback), 용기(Courage), 존중(Respect)**입니다.

> [!note]- 27. 스크럼 개발 프로세스에서 개발을 완료하기까지 남은 작업량을 시각적으로 보여주는 그래프는? (① Gantt Chart ② Burn-down Chart ③ Pert Chart ④ Flow Chart)
>
> **정답:** ② Burn-down Chart (소멸 차트)
>
> **해설:**
>
> 소멸 차트는 시간이 지남에 따라 남아있는 작업량(스토리 포인트 등)이 줄어드는 과정을 보여줍니다.

> [!note]- 28. 객체지향 기법 중 상위 클래스의 모든 속성과 메소드를 하위 클래스가 그대로 물려받는 특징은? (① 다형성 ② 캡슐화 ③ 상속성 ④ 추상화)
>
> **정답:** ③ 상속성 (Inheritance)
>
> **해설:**
>
> 상속은 이미 정의된 상위 클래스의 기능을 하위 클래스가 재사용하고 확장할 수 있게 해주는 핵심 개념입니다.

### 💻 [소프트웨어 개발] 문제 은행

> [!note]- 1. 중위 표기법(Infix)의 수식 $(A＋B)_C＋(D＋E)$을 후위 표기법(Postfix)으로 옳게 표기한 것은? (① AB＋CDE_＋＋ ② AB＋C_DE＋＋ ③ ＋AB_C＋DE＋ ④ ＋*＋ABC＋DE)
>
> **정답:** ② AB＋C*DE＋＋
>
> **해설:**
>
> 1. $(A+B)$를 후위로: $AB+$
>     
> 2. $(AB+)*C$를 후위로: $AB+C*$
>     
> 3. $(D+E)$를 후위로: $DE+$
>     
> 4. 전체 수식: $(AB+C*) + (DE+) \rightarrow AB+C*DE++$
>     

> [!note]- 2. 블랙박스 테스트 기법으로 거리가 먼 것은? (① 기초 경로 검사 ② 동치 클래스 분해 ③ 경계값 분석 ④ 원인 결과 그래프)
>
> **정답:** ① 기초 경로 검사
>
> **해설:**
>
> 기초 경로 검사(Basic Path Testing)는 대표적인 **화이트박스 테스트** 기법입니다. 나머지 2, 3, 4번은 입력값의 유효성이나 명세를 기반으로 하는 블랙박스 테스트 기법입니다.

> [!note]- 3. 디지털 저작권 관리(DRM)의 기술 요소가 아닌 것은? (① 크랙 방지 기술 ② 정책 관리 기술 ③ 암호화 기술 ④ 방화벽 기술)

> [!note]- 4. 단위 테스트를 통해 알 수 없는 것은? (① 전체 시스템 정상 작동 여부 ② 모듈 기능 수행 여부 ③ 논리적 오류 검출 ④ 인터페이스 결함)

>
> **해설:**
>
> 단위 테스트는 개별 모듈이나 컴포넌트의 기능을 검증하는 단계입니다. 전체 시스템의 통합적 작동 여부는 통합 테스트나 시스템 테스트 단계에서 확인합니다.

> [!note]- 5. 프로그램 코드 품질 향상을 위해 눈으로 확인하고 검사하는 기법은? (① 코드 인스펙션 ② 단위 테스트 ③ 성능 테스트 ④ 부하 테스트)

> [!note]- 6. 알고리즘 설계 기법으로 거리가 먼 것은? (① Divide and Conquer ② Greedy ③ Static Block ④ Backtracking)

### 🗄️ [데이터베이스 구축] 문제 은행

> [!note]- 1. SQL의 분류 중 DDL에 해당하지 않는 것은? (① UPDATE ② ALTER ③ DROP ④ CREATE)
>
> **정답:** ① UPDATE
>
> **해설:**
>
> UPDATE는 데이터를 조작하는 **DML(Data Manipulation Language)**입니다. ALTER, DROP, CREATE는 데이터 정의어(DDL)입니다.

> [!note]- 2. "연락번호"가 Null 값이 아닌 "사원명"을 검색하는 SQL 질의로 옳은 것은? (① !＝NULL ② ＜＞＝NULL ③ IS NOT NULL ④ DON'T NULL)
>
> **정답:** ③ SELECT 사원명 FROM 회사원 WHERE 연락번호 IS NOT NULL;
>
> **해설:**
>
> SQL에서 NULL 값을 체크할 때는 비교 연산자(<code>=</code>)가 아닌 `IS NULL` 또는 `IS NOT NULL` 키워드를 사용해야 합니다.

> [!note]- 3. 트랜잭션의 연산은 모두 반영되든지 아니면 전혀 반영되지 않아야 한다는 특성은? (① Durability ② Share ③ Consistency ④ Atomicity)
>
> **정답:** ④ Atomicity (원자성)
>
> **해설:**
>
> 원자성은 트랜잭션 내의 작업들이 부분적으로 성공해서는 안 되며, "All or Nothing"의 원칙을 지켜야 함을 의미합니다.

> [!note]- 4. 병행 제어의 로킹(Locking) 단위에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ② 로킹 단위가 작아지면 로킹 오버헤드가 감소한다.
>
> **해설:**
>
> 로킹 단위가 작아지면 관리해야 할 잠금의 수가 많아지므로 **오버헤드가 증가**합니다. 대신 데이터베이스 공유도(병행성)는 높아집니다.

> [!note]- 5. 뷰(View)에 대한 설명으로 틀린 것은? (① 뷰 위에 뷰 정의 가능 ② DML 제약 따름 ③ ALTER로 변경 불가 ④ 기본 테이블 제거 시 뷰 유지)
>
> **정답:** ④ 뷰가 정의된 기본 테이블이 제거되어도 뷰는 그대로 있다.
>
> **해설:**
>
> 뷰는 실제 데이터를 갖지 않는 가상 테이블이므로, 정의 기반이 되는 **기본 테이블이 삭제되면 해당 뷰를 사용할 수 없게 됩니다.**

> [!note]- 6. 릴레이션에 대한 설명으로 거리가 먼 것은? (① 시간에 따라 변함 ② 튜플 상이함 ③ 원자 값 저장 ④ 튜플 간 순서 있음)
>
> **정답:** ④ 한 릴레이션에 포함된 튜플 사이에는 순서가 있다.
>
> **해설:**
>
> 릴레이션 내의 **튜플들 사이에는 정해진 순서가 없습니다.** 데이터의 집합으로 취급되기 때문입니다.

> [!note]- 7. 관계 대수에 대한 설명으로 틀린 것은? (① 연산 집합 ② 일반/순수 구분 ③ 연산 순서 명시 ④ 비절차적 방법)
>
> **정답:** ④ 원하는 정보와 그 정보를 어떻게 유도하는가를 기술하는 비절차적 방법이다.
>
> **해설:**
>
> 관계 대수는 "어떻게(How)" 데이터를 가져올지 명시하는 **절차적(Procedural)** 방법입니다. 비절차적 방법은 관계 해석(Relational Calculus)입니다.

> [!note]- 8. 데이터베이스 설계 과정 중 개념적 설계 단계에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ③ 트랜잭션 인터페이스를 설계한다.
>
> **해설:**
>
> 트랜잭션 인터페이스 설계는 주로 **논리적 설계** 단계에서 수행되며, 구체적인 설계는 물리적 설계 단계로 이어집니다. 개념적 설계는 ERD 작성과 스키마 설계에 집중합니다.

> [!note]- 9. 데이터베이스의 무결성 규정(Integrity Rule)과 관련한 설명으로 틀린 것은?
>
> **정답:** ③ 정식으로 허가 받은 사용자가 아닌 불법적인 사용자에 의한 갱신으로부터 보호한다.
>
> **해설:**
>
> 불법적인 사용자로부터 데이터를 보호하는 것은 **보안(Security)**의 영역입니다. 무결성은 권한이 있는 사용자가 실수로 잘못된 데이터를 입력하는 것을 방지하는 기술입니다.

> [!note]- 10. 3행 4열 테이블의 Degree와 Cardinality는? (① D:4, C:3 ② D:3, C:4 ③ D:3, C:12 ④ D:12, C:3)
>
> **정답:** ① Degree : 4, Cardinality : 3
>
> **해설:**
>
> - Degree(차수): 속성(Column)의 수 <code>=</code> 4
>     
> - Cardinality(기수): 튜플(Row)의 수 <code>=</code> 3
>     

> [!note]- 11. 기본키 값의 속성 값이 널(Null)값이 아닌 원자 값을 갖는 성질은? (① 개체 무결성 ② 참조 무결성 ③ 도메인 무결성 ④ 유일성)
>
> **정답:** ① 개체 무결성 (Entity Integrity)
>
> **해설:**
>
> 개체 무결성은 기본키(Primary Key)는 NULL일 수 없고 중복될 수도 없다는 제약 조건입니다.

> [!note]- 12. E-R 다이어그램 기호와 의미 연결이 틀린 것은? (① 사각형-개체 ② 삼각형-속성 ③ 선-연결 ④ 마름모-관계)
>
> **정답:** ② 삼각형 - 속성
>
> **해설:**
>
> E-R 다이어그램에서 **속성은 타원(Ellipse)**으로 표기합니다.

> [!note]- 13. 모든 튜플에 대해 유일성은 만족시키지만 최소성은 만족시키지 못하는 키는? (① 후보키 ② 기본키 ③ 슈퍼키 ④ 외래키)
>
> **정답:** ③ 슈퍼키 (Super Key)
>

>

> [!note]- 14. 다음 관계 대수식을 SQL로 옳게 표현한 것은? $\pi_A (\sigma_P (r1 \Join r2))$
>
> **정답:** ② select A from r1, r2 where P;
>
> **해설:**
>
> - $\sigma_P$: Selection (조건 P, WHERE 절)
>     
> - $\pi_A$: Projection (추출 속성 A, SELECT 절)
>     
> - $r1 \Join r2$: Join (테이블 r1, r2)
>     

> [!note]- 15. 후보키가 튜플 식별을 위해 만족해야 하는 두 가지 속성은? (① 중복성 ② 최소성 ③ 참조성 ④ 동일성)

>
> **해설:**
>

> [!note]- 16. SQL에서 GRANT 문 사용 시 부여받은 권한을 다른 사용자에게 다시 부여할 수 있는 옵션은? (① WITH ADMIN OPTION ② WITH GRANT OPTION ③ CASCADE ④ RESTRICT)
>
> **정답:** ② WITH GRANT OPTION
>
> **해설:**
>
> DCL 명령인 GRANT에서 `WITH GRANT OPTION`을 명시하면, 권한을 부여받은 사용자가 그 권한을 제3자에게 전파할 수 있는 자격을 갖게 됩니다.

> [!note]- 17. 릴레이션 R과 S에서 공통 속성 A에 대해 $\pi_A(R) \cup \pi_A(S)$ 연산을 수행한 결과의 의미는?
>
> **정답:** 릴레이션 R의 A 속성 값들과 릴레이션 S의 A 속성 값들을 합쳐 중복을 제거한 집합
>
> **해설:**
>
> Projection($\pi$)으로 특정 속성만 추출한 뒤 합집합($\cup$) 연산을 수행하면, 두 테이블의 해당 속성 데이터가 합쳐지며 수학적 집합 정의에 따라 중복값은 하나만 남습니다.

> [!note]- 18. 정규화 단계 중 모든 결정자가 후보키인 상태를 의미하며, 보이스-코드 정규형이라고 불리는 것은? (① 1NF ② 2NF ③ 3NF ④ BCNF)
>
> **정답:** ④ BCNF
>
> **해설:**
>
> BCNF(Boyce-Codd Normal Form)는 3차 정규형을 강화한 것으로, 릴레이션의 모든 결정자가 후보키인 상태를 만족해야 합니다.
>
> 수식 조건: $Determinant = Candidate Key$

> [!note]- 7. HRN 방식으로 스케줄링 할 경우, 처리되는 작업 순서로 옳은 것은?
>
> **정답:** ③ D → B → C → A
>
> **해설:**
>
> HRN(Highest Response-ratio Next) 우선순위 계산식:
>
> $Priority = \frac{Wait + Service}{Service}$
>
> - A: $(5 + 20) / 20 = 1.25$
>     
> - B: $(40 + 20) / 20 = 3.0$
>     
> - C: $(15 + 45) / 45 = 1.33$
>     
> - D: $(20 + 2) / 2 = 11.0$
>     
>     우선순위 숫자가 큰 순서대로 수행됩니다 ($D > B > C > A$).
>

>
> 목적지 IP 주소는 3계층인 **IP 헤더**에 포함되는 정보입니다. TCP 헤더(4계층)에는 포트 번호, 순서 번호, 응답 번호, 윈도우 크기 등이 포함됩니다.

> [!note]- 2. 다음 중 비선점형 스케줄링 기법이며 가장 먼저 도착한 프로세스를 먼저 처리하는 방식은? (① RR ② SRT ③ FIFO ④ MLQ)
>
> **정답:** ③ FIFO (First-In First-Out)
>
> **해설:**
>
> FIFO(또는 FCFS)는 대기 큐에 도착한 순서대로 CPU를 할당하는 가장 단순한 비선점 스케줄링 방식입니다.

### 🏗️ [정보시스템 구축 관리] 문제 은행

> [!note]- 1. 고객과의 의사소통, 위험 분석, 구축, 평가 과정을 반복하며 대규모 프로젝트에 유리한 모형은? (① 프로토타입 ② 폭포수 ③ 나선형 ④ RAD)
>
> **정답:** ③ 나선형(Spiral) 모델
>
> **해설:**
>
> 나선형 모델은 보기에 설명된 대로 **위험 분석**을 가장 중요시하며, 점진적으로 완성도를 높여가는 방식입니다. 대규모 및 고위험 시스템 개발에 적합합니다.

> [!note]- 2. 나선형 모델의 4가지 주요 활동이 순서대로 나열된 것은? (Ⓐ계획 Ⓑ평가 Ⓒ개발 Ⓓ위험분석)
>
> **정답:** ② Ⓐ-Ⓓ-Ⓒ-Ⓑ 순으로 반복
>
> **해설:**
>
> 나선형 모델의 표준 순서는 **계획 수립(Planning) $\rightarrow$ 위험 분석(Risk Analysis) $\rightarrow$ 개발 및 검증(Engineering) $\rightarrow$ 고객 평가(Customer Evaluation)**입니다.

> [!note]- 3. 소프트웨어 비용 추정 모형(Estimation Models)이 아닌 것은? (① COCOMO ② Putnam ③ Function-Point ④ PERT)
>
> **정답:** ④ PERT
>
> **해설:**
>
> PERT는 프로젝트의 **일정 관리(Scheduling)** 및 진척 관리를 위한 도구입니다. 1, 2, 3번은 비용 및 노력을 추정하는 모델입니다.

> [!note]- 4. 소프트웨어 프로젝트 관리에 대한 설명으로 가장 옳은 것은?
>
> **정답:** ④ 주어진 기간 내에 최소의 비용으로 사용자를 만족시키는 시스템을 개발
>
> **해설:**
>
> 프로젝트 관리의 궁극적인 목표는 한정된 자원(시간, 비용, 인력)을 효율적으로 활용하여 품질 요건을 만족하는 결과물을 완성하는 것입니다.

> [!note]- 5. CMM(Capability Maturity Model) 모델의 5단계 레벨로 옳지 않은 것은? (① 최적 단계 ② 관리 단계 ③ 정의 단계 ④ 계획 단계)
>
> **정답:** ④ 계획 단계
>
> **해설:**
>
> CMM 단계: 초기(Initial) $\rightarrow$ 관리(Managed) $\rightarrow$ 정의(Defined) $\rightarrow$ 정량적 관리(Quantitatively Managed) $\rightarrow$ 최적화(Optimizing). '계획 단계'는 표준 레벨 명칭에 없습니다.

> [!note]- 6. 차세대 이동통신, 홈네트워킹 등 대규모 디바이스 네트워크 생성에 최적화된 기술은? (① SDP ② VPN ③ LAN ④ Mesh Network)
>
> **정답:** ④ Mesh Network (망형 네트워크)
>
> **해설:**
>
> 메쉬 네트워크는 각 노드가 다른 노드들과 직접 연결되어 망 형태를 이루는 기술로, 확장성이 좋고 특정 노드 장애 시에도 우회 경로를 통해 통신이 가능합니다.

> [!note]- 7. WAS(Web Application Server)가 아닌 것은? (① JEUS ② JVM ③ Tomcat ④ WebSphere)
>
> **정답:** ② JVM
>
> **해설:**
>
> JVM(Java Virtual Machine)은 자바 프로그램을 실행하기 위한 가상 머신(환경)입니다. JEUS, Tomcat, WebSphere는 동적 콘텐츠를 처리하는 웹 애플리케이션 서버입니다.

> [!note]- 8. 오픈 소스 기반 분산 컴퓨팅 플랫폼으로 빅데이터를 효율적으로 저장/처리하는 것은? (① 하둡 ② 비컨 ③ 포스퀘어 ④ 멤리스터)
>
> **정답:** ① 하둡(Hadoop)
>
> **해설:**
>
> 하둡은 여러 개의 저렴한 컴퓨터를 하나로 묶어 대용량 데이터를 처리하는 분산 파일 시스템(HDFS)과 맵리듀스(MapReduce) 프레임워크를 제공합니다.

> [!note]- 9. 정보보안의 3대 요소에 해당하지 않는 것은? (① 기밀성 ② 휘발성 ③ 무결성 ④ 가용성)
>
> **정답:** ② 휘발성
>
> **해설:**
>
> 보안의 3요소(CIA): **기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)**입니다.

> [!note]- 10. 공개키 암호화 방식에 대한 설명으로 틀린 것은?
>
> **정답:** ① 공개키로 암호화된 메시지는 반드시 공개키로 복호화해야 한다.
>
> **해설:**
>
> 공개키(Public Key)로 암호화한 데이터는 오직 그에 대응하는 **비밀키(Private Key)**로만 복호화할 수 있습니다. (비대칭성)

> [!note]- 11. 백도어 탐지 방법으로 틀린 것은? (① 무결성 검사 ② 닫힌 포트 확인 ③ 로그 분석 ④ SetUID 파일 검사)
>
> **정답:** ② 닫힌 포트 확인
>
> **해설:**
>
> 백도어는 주로 통로를 열어두기 때문에 **열린 포트(Open Port)**를 확인해야 합니다. 닫힌 포트는 외부와 연결되어 있지 않으므로 탐지와 무관합니다.

> [!note]- 12. 위험 유형이 다른 하나는? (① 스위치 재밍 ② 서버 팜 ③ 물리적 위험 ④ 기술적 위험)
>
> **정답:** ② 서버 팜 (Server Farm)
>
> **해설:**
>
> 서버 팜은 다수의 서버를 모아놓은 시설/환경을 의미하는 용어이며, 그 자체로 공격이나 위험 유형을 뜻하지 않습니다.

> [!note]- 13. 고전적 생명주기 모형으로 선형 순차적 모델이라고도 불리는 것은? (① 폭포수 모형 ② 애자일 모형 ③ 컴포넌트 기반 ④ 6GT 모형)
>
> **정답:** ① 폭포수 모형 (Waterfall Model)
>
> **해설:**
>
> 한 단계가 끝나야 다음 단계로 넘어가는 가장 전통적이고 고전적인 모델입니다.

> [!note]- 14. COCOMO 모델의 프로젝트 유형으로 거리가 먼 것은? (① Organic ② Semi-detached ③ Embedded ④ Sequential)
>
> **정답:** ④ Sequential
>
> **해설:**
>
> COCOMO의 규모별 유형: 소규모(Organic), 중규모(Semi-detached), 대규모/복잡형(Embedded) 3가지입니다.

> [!note]- 15. 가상 세계가 현실 세계에 흡수된 형태이며 진보된 개념의 가상현실 서비스는? (① AaaS ② Grid ③ Metaverse ④ Splogger)
>
> **정답:** ③ Metaverse (메타버스)
>
> **해설:**
>
> 가상, 초월을 뜻하는 'Meta'와 우주를 뜻하는 'Universe'의 합성어로, 사회·경제·문화 활동이 이루어지는 가상 세계를 의미합니다.

> [!note]- 16. 하둡(Hadoop)과 관계형 데이터베이스(RDBMS) 간 데이터를 전송하는 도구는? (① Apnic ② Topology ③ Sqoop ④ SDB)
>
> **정답:** ③ Sqoop (스쿱)
>
> **해설:**
>
> Sqoop은 **SQL-to-Hadoop**의 약자로, 구조화된 데이터를 하둡으로 가져오거나 내보내는 전송 도구입니다.

> [!note]- 17. 소프트웨어 개발 방법론의 테일러링(Tailoring) 설명으로 틀린 것은?
>
> **정답:** ① 프로젝트 수행 시 예상되는 변화를 배제하고 신속히 진행하여야 한다.
>
> **해설:**
>
> 테일러링은 프로젝트의 특성이나 상황에 맞춰 방법론을 **유연하게 조정**하는 과정이므로, 변화를 배제하는 것이 아니라 변화를 수용하고 최적화하는 활동입니다.

> [!note]- 18. 네트워크 제어부와 데이터 전달부를 분리하여 소프트웨어로 제어하는 기술은? (① SDN ② NFS ③ Network Mapper ④ AOE)
>
> **정답:** ① SDN (Software Defined Networking)
>
> **해설:**
>
> 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 분리하여 중앙 집중식으로 네트워크를 관리하는 차세대 기술입니다.

> [!note]- 19. 침입자를 유인하여 공격기법 정보를 수집하기 위해 의도적으로 설치한 시스템은? (① Apache ② Hadoop ③ Honeypot ④ MapReduce)
>
> **정답:** ③ Honeypot (허니팟)
>
> **해설:**
>
> '꿀단지'라는 뜻으로, 해커를 유인해 공격을 분석하고 추적하기 위해 만든 가짜 시스템입니다.

> [!note]- 20. ICMP 특성을 악용하여 특정 사이트에 집중적으로 데이터를 보내 불능으로 만드는 공격은? (① TearDrop ② Smishing ③ Qshing ④ Smurfing)
>
> **정답:** ④ Smurfing (스머핑)
>
> **해설:**
>
> IP 브로드캐스트와 ICMP Echo Request를 이용해 수많은 응답 패킷이 대상 시스템에 쏟아지게 하는 DoS 공격의 일종입니다.

> [!note]- 21. 물리적 보안에 해당하는 내용으로 가장 적절하지 않은 것은?
>
> **정답:** ④ 조직 내 정보보안의 정책과 절차 수립
>
> **해설:**
>
> 정책 및 절차 수립은 **관리적 보안**에 해당합니다. 1, 2, 3번처럼 장비, 공간, 출입을 직접 통제하는 것이 물리적 보안입니다.

> [!note]- 22. 큰 숫자를 소인수 분해하기 어렵다는 점을 이용한 공개키 암호 알고리즘은? (① DES ② ARIA ③ SEED ④ RSA)
>
> **정답:** ④ RSA
>
> **해설:**
>
> RSA는 소인수 분해 문제의 수학적 복잡성을 기반으로 설계된 가장 대표적인 비대칭 암호화 알고리즘입니다. (DES, SEED 등은 대칭키 방식입니다.)

> [!note]- 23. 외부 접속 시 인가 여부를 점검하여 허용/거부하는 접근제어 유틸리티는? (① tcp wrapper ② trace checker ③ token finder ④ change detector)
>
> **정답:** ① tcp wrapper
>
> **해설:**
>
> TCP 래퍼는 호스트 기반의 네트워크 접근 제어 도구로, `/etc/hosts.allow`와 `/etc/hosts.deny` 파일을 통해 접속을 필터링합니다.

> [!note]- 24. 윈도우와 리눅스 간의 상호 운용을 돕는 소프트웨어가 아닌 것은? (① Samba ② OpenSSH ③ Cygwin ④ Microsoft Office)
>
> **정답:** ④ Microsoft Office
>
> **해설:**
>
> MS Office는 문서 작성 도구입니다. Samba(파일 공유), OpenSSH(원격 접속), Cygwin(리눅스 환경 제공)은 두 운영체제 간의 기술적 호환을 돕는 도구들입니다.
