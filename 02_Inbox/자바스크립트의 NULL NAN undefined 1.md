## 정리
### 📊 요약: 세 가지 원시값 '없음'의 비교 (NAN은 NUMBER 타입의 값이다. null NaN은 타입)

| **구분** | **null**                    | **NaN**                | **undefined**           |
| ------ | --------------------------- | ---------------------- | ----------------------- |
| **의미** | "의도적으로 비어있음" (값 없음)         | "숫자 아님" (잘못된 숫자 **값**) | "아직 할당된 적 없음" (값 없음)    |
| **타입** | 버그로 `object`로 표시하나, 본질은 원시값 | **`number`**           | `undefined`             |
| **주체** | **프로그래머** (명시적 할당)          | **엔진** (숫자 연산 실패 시 반환) | **엔진** (변수 초기화 시 자동 할당) |

### 1. 💎 `null`: 의도적인 '빈 값' (원시 값)

이것이 바로 자바스크립트가 "값이 없음"을 표현하기 위해 만든 **첫 번째 원시 값**입니다.

- **행위의 주체:** **프로그래머**
- **왜 원시 값인가?:** 프로그래머가 "이 변수는 존재하지만, **의도적으로 비어있다**"는 상태를 명시하기 위해 할당하는 '기본 값'으로 설계되었습니다.
- **사용 예시:**

    ```JavaScript
    // 사용자가 아직 로그인하지 않아서 '유저 객체'가 없음을 명시
    let currentUser = null;
    ```
    
- **유명한 버그:** 자바스크립트 초창기 버그로, `typeof null`을 실행하면 `object`가 반환됩니다. (원래는 `null`이 나와야 함) 하지만 `null`은 객체가 아닌 원시 값이 맞습니다.
    
---

### 2. 🧮 `NaN`: 실패한 '숫자 연산' (숫자 타입)

이것은 "값이 없음"과는 전혀 관련이 없습니다. `NaN`은 **"Not-a-Number"** 의 약자입니다.

- **행위의 주체:** **JavaScript 엔진 (런타임)**
- **정의:** 수학적으로 **정의할 수 없는 계산 결과**를 나타내는 **'숫자(Number) 타입'** 의 특별한 값입니다.
- **발생 예시:**
    
    ```JavaScript
    // "hello"라는 글자를 숫자로 바꾸려다 실패함
    let num = parseInt("hello"); // num은 NaN이 됨
    
    // 0을 0으로 나누는, 수학적으로 정의되지 않는 연산
    let result = 0 / 0; // result는 NaN이 됨
    ```
    
- **중요한 사실:** `NaN`은 스스로를 포함한 그 어떤 값과도 같지 않습니다. (`NaN === NaN`은 `false`입니다.) 그리고 **`typeof NaN`은 `number`입니다.**
    

---

### 3. ❓ `undefined`: '정의되지 않음' (원시 값)

이것이 "값이 없음"을 표현하는 자바스크립트의 **두 번째 원시 값**입니다.

- **행위의 주체:** **JavaScript 엔진 (런타임)**
- **정의:** 변수는 선언되었으나, **아무 값도 할당되지 않은** '초기 상태'를 나타냅니다.
- **발생 예시:**
    
    ```JavaScript
    let name;
    // 'name'이라는 변수 공간은 확보했으나, 값이 할당된 적 없음
    // 이 때 name의 값은 undefined임
    console.log(name); // undefined
    ```
