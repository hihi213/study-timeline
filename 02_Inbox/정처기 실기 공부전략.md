## 1. 4일 전체 공부 전략

최근 기출 분석상 프로그래밍이 가장 큰 비중을 차지하고, 그다음이 네트워크·보안, SQL·DB, 설계·테스트 영역입니다. 특히 2026년 1회는 기존보다 Python·SQL·보안·설계 문제가 고르게 분산됐습니다.

따라서 16시간 전략은 다음과 같습니다.

- **점수 확보:** Java·Python 코드 추적, SQL 작성·결과 계산, 빈출 이론 단답
- **부분 방어:** C 포인터, 서브넷 계산, 보안 공격 시나리오
- **최소 방어:** 운영체제·리눅스, 인터페이스·패키징
- **포기 대상:** 영역 전체가 아니라, 어려운 문제를 완전히 이해하려는 깊이
    

목표 득점 구조는 대략 다음과 같이 잡는 것이 현실적입니다.

> 코드 4~5문제 + SQL·DB 3문제 + 네트워크·보안 2~3문제 + 설계·테스트 2~3문제

# 4. 시간표로 바꿀 때의 원칙

## 하루 배치 순서

집중력이 필요한 영역부터 시작합니다.

1. **코드 추적 또는 SQL**
2. **C·서브넷 등 취약 실전**
3. **보안·DB·테스트 단답**
4. **짧은 혼합 복습**
    

하루 전체를 코드만 하거나 이론만 하는 방식은 피하는 것이 좋습니다. 매일 A등급 영역을 섞어야 특정 분야에 과몰입해 다른 점수를 놓치는 것을 막을 수 있습니다.

## Must-Do와 Nice-to-Have 구분

### Must-Do

- Java·Python 최근 코드 문제
- SQL 최근 문제
- C 포인터·배열·구조체 최소 훈련
- 서브넷 계산
- 보안 공격 시나리오
- 테스트·응집도·결합도·대표 패턴
- DB 핵심 단답
    

### Nice-to-Have

- C 함수 포인터·동적 메모리 추가 문제
- 운영체제 계산
- 리눅스 명령어
- 디자인 패턴 추가
- 인터페이스·패키징·UI
    

시간표에서는 **전체 시간의 약 80%를 Must-Do에 고정**하고, Nice-to-Have는 Must-Do 완료 후에만 넣는 것이 안전합니다. 하루 분량이 밀리면 Nice-to-Have를 삭제하고, 다음 날 Must-Do 분량을 두 배로 늘리지 않아야 합니다.
