### 중간내용
정렬: 순서대로 재배열 하는것
키: 자료를 정렬할때의 기준

- 선택정렬: 비정렬끼리 비교해 그중 가장 작은값/큰값을 비정렬의 맨 앞자리와 교환한다.
	- 예: `[2(a), 2(b), 1]` 정렬 시, 1과 2(a)를 교환하면 `[1, 2(b), 2(a)]`가 되어 2의 순서가 바뀜
	- 이미 정렬되어있는경우가 최악의 경우
- 삽입정렬: 비정렬된 원소를 정렬된 원소들과 비교해 삽입한다.
	- 그자리에 있던 요소는 뒤로 밀린다
	- 값이 같은 데이터가 2개 있을 때, 정렬 후에도 그 순서가 유지
	- 정렬된 경우 빠르다.
- 버블정렬
	- 인접한 두 데이터 비교
- 쉘정렬: 삽입정렬+ 간격개념
	1. 간격을 설정하고 서로 간격 거리만큼 떨어진 요소들을 집합으로 묶는다.
	2. 여러 집합 각각 집합내부에서만 삽입 정렬을 한다.  
	- 간격을 절반으로 줄이고 반복하다 간격이 1이 되면 전체를 대상으로 마지막으로 삽입정렬을 한다.

### '분할 정복(Divide and Conquer)' 방식을 사용해 대용량 데이터에 좋은 정렬.

#### **A. 퀵 정렬 (Quick Sort)**

- 임의의 기준값(Pivot)을 선정하고, 이를 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽으로 **교환(Swap)하여 분할(Partition)**합니다. 이후 나뉜 두 영역에 대해 재귀적으로 동일한 분할 작업을 반복하여 정렬을 완료합니다.
- **특징:** **평균적으로 가장 빠릅니다.** 하지만 피벗을 잘못 잡으면(이미 정렬된 경우 등) 최악의 경우 $O(n^2)$이 되어 느려질 수 있습니다.
    

#### **B. 병합 정렬 (Merge Sort)**

- **배열을 최소 단위(1개)가 될 때까지 물리적으로 반으로 나눈(Divide) 후, 분할된 두 값을 비교해 **별도의 임시 공간에 순서대로 병합(Merge)**합니다. 분할된 조각들이 하나로 합쳐질 때까지 이 과정을 반복합니다.
- **특징:** 데이터의 상태와 무관하게 항상 $O(n \log n)$을 보장합니다. 단, 데이터를 합칠 때 추가적인 메모리 공간이 필요합니다.
    

#### **C. 힙 정렬 (Heap Sort)**

- **원리:** 배열을 '부모 노드가 자식보다 큰' **최대 힙(Max Heap)** 구조로 변환하여 0번 인덱스(Root)에 최댓값을 위치시킵니다. 이 최댓값을 배열의 맨 끝 요소와 교환하고 힙의 크기를 줄인 뒤, 다시 힙 구조를 맞추는 과정을 반복합니다.
- **특징:** 추가 메모리가 거의 필요 없고 항상 좋은 성능을 보이지만, 실제로는 퀵 정렬보다 조금 느린 편입니다

## 1. 한눈에 보는 비교 (VS)

| **특징**     | **인접 행렬 (Adjacency Matrix)**               | **인접 리스트 (Adjacency List)**                                   |
| ---------- | ------------------------------------------ | ------------------------------------------------------------- |
| **구조**     | 2차원 배열 (`adj[N][N]`)                       | 포인터 배열 + 연결 리스트                                               |
| **공간 복잡도** | $O(V^2)$ (정점 수의 제곱)                        | $O(V + E)$ (정점 + 간선 수)                                        |
| **접근 속도**  | **$O(1)$** (바로 인덱스 접근)                     | $O(degree(v))$ (리스트 순회 필요)                                    |
| **적합한 상황** | 간선이 많은 **밀집 그래프 (Dense)**                  | 간선이 적은 **희소 그래프 (Sparse)**                                    |
| **구현 난이도** | 쉬음 (배열 인덱싱)                                | 약간 복잡 (포인터 조작, malloc)                                        |
| **방향성 특징** | **무방향:** 대칭 행렬  <br>**방향:** 행합(진출), 열합(진입) | **무방향:** 노드 2개 생성 ($u \to v, v \to u$)<br>**방향:** 진출 차수 기준 연결 |

- "왜 사이클이 생기면 안 되는가?" (최소 비용 조건 위배)
	    - 트리(Tree)'의 정의 자체가 **사이클이 없는 연결 그래프**이기 때문입니다.
	    - 사이클이 존재한다는 것은 두 정점을 잇는 경로가 2개 이상이라는 뜻이고 이는 최소비용 조건이 성립하지 않습니다(간선 하나만있어도 연결상태 유지됨)
