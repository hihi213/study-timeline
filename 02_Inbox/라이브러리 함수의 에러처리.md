## 정리
> 여기에 나의 언어로 재작성

- **`errno`** : 오류원인 번호로 저장하는 전역변수
- **`strerror()` 함수** :errno에 저장된 오류번호 -> 시스템이 정의한 오류메세지로 변환만
- **`perror()` 함수** : errno에 저장된 오류번호 -> 사용자가 정의한 오류메세지도 덧붙여 변환뒤 출력까지

## 1. `errno`란 무엇인가?

`errno`는 시스템 콜(System Call)이나 표준 라이브러리 함수가 실행 중 **오류를 일으켰을 때 그 원인을 기록하는 전역 변수**입니다. (현대적인 멀티스레드 환경에서는 스레드별로 독립적으로 관리됩니다.)

- **동작 원리:** 함수가 실패하면 `-1`이나 `NULL`을 반환하고, 동시에 `errno`라는 보관함에 구체적인 "오류 번호"를 집어넣습니다.
- **휘발성:** 다른 함수가 실행되면 `errno` 값이 덮어씌워질 수 있으므로, 오류 발생 직후에 확인하거나 다른 변수에 복사해두는 것이 원칙입니다.
    

---

## 2. 오류 번호 `2` (ENOENT)의 의미

사용자가 예시로 든 `ENOENT`는 시스템 프로그래밍에서 가장 자주 마주치는 오류 중 하나입니다.

> __#define ENOENT 2 /_ No such file or directory _/__

- **해석:** "해당 파일이나 디렉터리가 존재하지 않음"을 의미합니다.
- **발생 상황:** 존재하지 않는 경로의 파일을 열려고 하거나(`open`), 삭제하려 할 때(`unlink`), 혹은 `access()`로 존재 여부를 확인할 때 발생합니다.
    

---

## 3. `access()` 함수에서의 오류 활용

`access()` 함수는 프로세스가 특정 파일에 대해 읽기, 쓰기, 실행 권한이 있는지 또는 파일이 존재하는지 확인하는 도구입니다.

### 주요 오류 코드 상세 설명

|**오류 코드**|**의미**|**상세 내용**|
|---|---|---|
|**EACCES**|Permission denied|경로는 존재하지만, 해당 파일에 접근할 **권한**이 없음.|
|**ENOENT**|No such file|경로에 있는 파일이 **존재하지 않음**.|
|**ENOTDIR**|Not a directory|경로의 구성 요소 중 하나가 디렉터리가 아님.|
|**ELOOP**|Too many levels|심볼릭 링크가 너무 많이 꼬여 있거나 무한 루프에 빠짐.|
|**ENAMETOOLONG**|Name too long|파일 이름이나 경로의 길이가 시스템 제한을 초과함.|

---

## 4. 실무 팁: 헤더를 직접 뒤지지 않는 방법

매번 `/usr/include/…` 경로를 찾아가며 숫자를 확인하는 것은 번거롭습니다. 리눅스 환경에서는 더 세련된 도구들을 제공합니다.

1. **`strerror()` 함수:** 코드 내에서 `errno` 숫자값을 사람이 읽을 수 있는 문자열(예: "No such file…")로 변환해줍니다.
2. **`perror()` 함수:** "사용자 정의 메시지 + 오류 메시지"를 표준 에러(stderr)로 즉시 출력합니다.
    
    
    
    ```C
    if (access("myfile.txt", F_OK) == -1) {
        perror("Error checking file"); // 출력: Error checking file: No such file or directory
    }
    ```
    
3. **`errno` 커맨드:** 터미널에서 `errno -l` 또는 `errno 2` 명령어를 사용하면 즉시 정의를 확인할 수 있습니다. (설치 필요: `sudo apt install errno`)
