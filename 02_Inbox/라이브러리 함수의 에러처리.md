## 정리
> 여기에 나의 언어로 재작성

- **`errno`** : 오류원인 번호로 저장하는 전역변수
- **`strerror()` 함수** :errno에 저장된 오류번호 -> 시스템이 정의한 오류메세지로 변환만
- **`perror()` 함수** : errno에 저장된 오류번호 -> 사용자가 정의한 오류메세지도 덧붙여 변환뒤 출력까지

## 1. `errno`란 무엇인가?

`errno`는 시스템 콜(System Call)이나 표준 라이브러리 함수가 실행 중 **오류를 일으켰을 때 그 원인을 기록하는 전역 변수**입니다. (현대적인 멀티스레드 환경에서는 스레드별로 독립적으로 관리됩니다.)

- **동작 원리:** 함수가 실패하면 `-1`이나 `NULL`을 반환하고, 동시에 `errno`라는 보관함에 구체적인 "오류 번호"를 집어넣습니다.
- **휘발성:** 다른 함수가 실행되면 `errno` 값이 덮어씌워질 수 있으므로, 오류 발생 직후에 확인하거나 다른 변수에 복사해두는 것이 원칙입니다.


### 운영체제별 정의 위치

시스템마다 에러 코드가 정의된 헤더 파일의 경로가 조금씩 다릅니다.

|**구분**|**주요 헤더 파일 경로**|**특징**|
|---|---|---|
|**Linux**|`asm-generic/errno-base.h`|1~34번 (기본 에러: EPERM, ENOENT 등)|
||`asm-generic/errno.h`|35번 이후 (확장 에러: ETIMEDOUT 등)|
|**Unix/macOS**|`/usr/include/sys/errno.h`|POSIX 표준 준수, 시스템별 고유 코드 포함 가능|
---

## 2. 오류 번호 `2` (ENOENT)의 의미

사용자가 예시로 든 `ENOENT`는 시스템 프로그래밍에서 가장 자주 마주치는 오류 중 하나입니다.

> __#define ENOENT 2 /_ No such file or directory _/__

- **해석:** "해당 파일이나 디렉터리가 존재하지 않음"을 의미합니다.
- **발생 상황:** 존재하지 않는 경로의 파일을 열려고 하거나(`open`), 삭제하려 할 때(`unlink`), 혹은 `access()`로 존재 여부를 확인할 때 발생합니다.
    

---

## 3. `access()` 함수에서의 오류 활용

`access()` 함수는 프로세스가 특정 파일에 대해 읽기, 쓰기, 실행 권한이 있는지 또는 파일이 존재하는지 확인하는 도구입니다.

### 주요 오류 코드 상세 설명

|**오류 코드**|**의미**|**상세 내용**|
|---|---|---|
|**EACCES**|Permission denied|경로는 존재하지만, 해당 파일에 접근할 **권한**이 없음.|
|**ENOENT**|No such file|경로에 있는 파일이 **존재하지 않음**.|
|**ENOTDIR**|Not a directory|경로의 구성 요소 중 하나가 디렉터리가 아님.|
|**ELOOP**|Too many levels|심볼릭 링크가 너무 많이 꼬여 있거나 무한 루프에 빠짐.|
|**ENAMETOOLONG**|Name too long|파일 이름이나 경로의 길이가 시스템 제한을 초과함.|

## 4. 실무 팁: 헤더를 직접 뒤지지 않는 방법

매번 `/usr/include/…` 경로를 찾아가며 숫자를 확인하는 것은 번거롭습니다. 리눅스 환경에서는 더 세련된 도구들을 제공합니다.

#### ① 터미널 도구 활용 (`errno` 패키지)

가장 빠르고 직관적인 방법입니다. 번호나 이름으로 즉시 검색이 가능합니다.

- **설치 (Ubuntu 기준):** `sudo apt install errno`
- **사용 예시:**

    ```Bash
    $ errno 2
    # ENOENT 2 No such file or directory (파일이나 디렉토리가 없음)
    
    $ errno EACCES
    # EACCES 13 Permission denied (권한 거부)
    ```

#### ② C 언어 표준 함수 활용 (코딩 시)

프로그램 실행 중에 발생하는 에러를 사용자에게 친절하게 설명할 때 사용합니다.

- **`strerror(errno)`**: 숫자로 된 에러 코드를 해당 언어(시스템 설정)의 **설명 문자열**로 반환합니다.
- **`perror("사용자 메시지")`**: `사용자 메시지: 에러 설명` 형태로 **표준 에러 출력(stderr)**에 즉시 출력합니다.

    ```C
    if (fd == -1) {
        perror("파일 열기 실패"); // 출력: 파일 열기 실패: No such file or directory
    }
    ```

#### ③ 매뉴얼 페이지 (`man`)

인터넷 검색 없이 전체 목록과 상세 설명을 확인하는 가장 정확한 문서입니다.

- **명령어:** `man errno`
- **내용:** 해당 시스템에서 지원하는 모든 `E…` 매크로 이름과 번호, 의미가 나열됩니다.

---

### 💡 요약 및 팁

- **숫자보다는 매크로 이름(`EPERM`, `EINVAL` 등)을 기억하세요.** 운영체제마다 숫자는 다를 수 있지만 이름은 표준화되어 있어 호환성에 좋습니다.
- **실패 직후에 확인하세요.** `errno`는 다른 함수가 호출되면 값이 덮어씌워질 수 있으므로, 에러 발생 직후에 값을 저장하거나 출력해야 합니다.

## 요약

시스템 콜이 실패했을 때 **"왜 실패했지?"**라는 질문에 대한 답변이 들어있는 곳이 `errno`입니다. 헤더 파일은 그 답변들을 모아놓은 **사전**과 같으며, `access()`와 같은 함수는 이 사전에 정의된 단어들을 사용해 개발자에게 상황을 보고합니다.
