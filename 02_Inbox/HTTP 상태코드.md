HTTP 상태 코드(Status Code)는 서버가 클라이언트의 요청을 처리한 결과를 3자리 숫자로 알려주는 약속입니다.

맨 앞자리 숫자에 따라 5가지 범주(1xx~5xx)로 나뉘며, 백엔드/프론트엔드 실무에서 자주 쓰이는 핵심 상태 코드를 깔끔하게 정리해 드릴게요.

## 1xx : Informational (정보 전달)

요청을 받았으며 작업을 계속 진행 중임을 나타냅니다. (실무 개발에서 직접 다룰 일은 거의 없습니다.)

- **`100 Continue`**: 요청의 시작 부분이 잘 수신되었으니 계속해서 나머지 요청을 보내라는 의미.
- **`101 Switching Protocols`**: 클라이언트가 요청한 프로토콜 전환(예: HTTP ➔ WebSocket)을 서버가 승인함.
    

## 2xx : Successful (성공)

클라이언트의 요청이 성공적으로 수신되어 처리되었음을 나타냅니다.

|**상태 코드**|**명칭**|**의미 및 주요 활용 상황**|
|---|---|---|
|**`200`**|**OK**|**[가장 기본]** 요청 성공. (조회 데이터 반환, 일반적인 성공 응답)|
|**`201`**|**Created**|**[생성 성공]** 새로운 리소스 생성 완료. (회원가입, 게시글 작성 성공 등)|
|**`202`**|**Accepted**|**[접수 완료]** 요청이 접수되었으나 아직 처리가 완료되지 않음. (비동기/배치 작업)|
|**`204`**|**No Content**|**[내용 없음]** 요청은 성공했으나 응답 바디에 보낼 데이터가 없음. (삭제, 로그아웃, 수정 성공)|

## 3xx : Redirection (리다이렉션)

요청을 완료하기 위해 클라이언트가 추가적인 동작(다른 주소로 이동 등)을 취해야 함을 나타냅니다.

|**상태 코드**|**명칭**|**의미 및 주요 활용 상황**|
|---|---|---|
|**`301`**|**Moved Permanently**|**[영구 이동]** 요청한 URL이 새 주소로 완전히 이동함. (SEO 캐싱 대상)|
|**`302`**|**Found**|**[일시 이동]** 요청한 URL이 임시로 변경됨.|
|**`304`**|**Not Modified**|**[캐시 사용]** 마지막 요청 이후 변경된 내용이 없음. (브라우저가 기존 캐시 재사용)|
|**`307`**|**Temporary Redirect**|HTTP 메서드(POST/GET)를 바꾸지 않고 임시로 리다이렉트.|
|**`308`**|**Permanent Redirect**|HTTP 메서드를 바꾸지 않고 영구적으로 리다이렉트.|

## 4xx : Client Error (클라이언트 오류)

클라이언트의 요청에 잘못된 문법, 유효하지 않은 데이터, 권한 부족 등의 문제가 있어 서버가 처리할 수 없음을 나타냅니다.

|**상태 코드**|**명칭**|**의미 및 주요 활용 상황**|
|---|---|---|
|**`400`**|**Bad Request**|**[잘못된 요청]** 입력값 검증(Validation) 실패, 필수 파라미터 누락, JSON 형식 오류.|
|**`401`**|**Unauthorized**|**[미인증]** 로그인 필요, 세션/토큰 만료, 잘못된 인증 정보.|
|**`403`**|**Forbidden**|**[권한 없음]** 로그인은 되었으나 해당 리소스에 접근할 권한이 없음. (예: 일반 유저가 관리자 페이지 접근)|
|**`404`**|**Not Found**|**[존재하지 않음]** 요청한 URL 경로나 데이터(ID)를 찾을 수 없음.|
|**`405`**|**Method Not Allowed**|**[메서드 불허]** API 경로엔 존재하나 잘못된 HTTP 메서드로 요청함. (예: POST 경로에 GET 요청)|
|**`408`**|**Request Timeout**|**[요청 시간 초과]** 서버가 클라이언트의 요청 전송을 기다리다 시간을 초과함.|
|**`409`**|**Conflict**|**[충돌]** 서버의 현재 상태와 충돌 발생. (예: 이미 가입된 이메일로 중복 가입 시도)|
|**`422`**|**Unprocessable Entity**|문법은 맞으나 비즈니스 로직상 처리할 수 없는 데이터일 때.|
|**`429`**|**Too Many Requests**|**[요청 횟수 초과]** 일정 시간 내에 너무 많은 요청을 보냄. (DDoS 방어 / API Rate Limit)|

## 5xx : Server Error (서버 오류)

클라이언트의 요청은 정상이지만, 서버 내부적인 문제(버그, 다운 등)로 인해 처리에 실패했음을 나타냅니다.

|**상태 코드**|**명칭**|**의미 및 주요 활용 상황**|
|---|---|---|
|**`500`**|**Internal Server Error**|**[서버 내부 에러]** 서버 코드에서 처리되지 않은 예외(NullPointer, Exception 등) 발생.|
|**`502`**|**Bad Gateway**|**[게이트웨이 오류]** 게이트웨이/프록시 서버가 뒷단의 메인 서버로부터 잘못된 응답을 받음.|
|**`503`**|**Service Unavailable**|**[서비스 이용 불가]** 서버가 과부하 상태이거나 정기 점검 중이라 응답 불가능.|
|**`504`**|**Gateway Timeout**|**[게이트웨이 시간초과]** 뒷단 서버의 처리가 너무 오래 걸려 게이트웨이가 타임아웃을 냄.|

### 💡 백엔드/프론트엔드 실무 필수 요약 6가지

1. **`200 OK`**: 성공적으로 조회/처리가 완료되었을 때
2. **`201 Created`**: 새로운 데이터 생성(`POST`)에 성공했을 때
3. **`204 No Content`**: 삭제(`DELETE`)에 성공했거나 반환할 바디 데이터가 없을 때
4. **`400 Bad Request`**: 클라이언트가 파라미터나 JSON 데이터를 잘못 입력했을 때
5. **`401 Unauthorized`**: 로그인하지 않았거나 세션/토큰이 만료되었을 때
6. **`403 Forbidden`**: 로그인은 했지만 접근 권한(Role)이 없을 때
