### **Q7.** 시그널에 대한 설명 중 틀린 것 혹은 다른 것을 고르는 문제
#### 시그널의 정의와 특징

- **개념**: 시그널은 일종의 소프트웨어적인 인터럽트(Interrupt)입니다.
- **용도**: 프로그래머 입장에서는 단순한 소프트웨어 인터럽트 처리라기보다는, **프로세스 간 통신에서 동기(Synchronization)를 맞추는 신호** 등의 용도로 활용성이 훨씬 높은 부분입니다.
- **메커니즘**: 소프트웨어적으로 발생하는 인터럽트를 운영체제가 감지하여, 해당 인터럽트가 발생한 프로세스에게 전달하는 메커니즘입니다.
- **비동기성**: 시그널은 비동기적(Asynchronous)으로 발생합니다. 즉, 프로세스가 준비되지 않은 상태일지라도 언제 어디서나 발생과 동시에 전달됩니다.

#### 시그널 수신 시 처리 방법 (기본 동작 및 핸들러)

- **기본 동작 (Default Action)**: 우리가 아무런 설정을 하지 않으면 이미 정의된 기본 동작을 수행하며, **대부분은 프로세스를 종료**하는 것입니다.
- **무시 또는 일시 중지**: 무조건 종료할 수 없는 특수한 경우(예: 하위 프로세스가 상위 프로세스를 강제 종료하려 할 때 이를 다 받아주면 운영체제 구조가 무너지므로)에는 아예 무시하거나, 잠시 중지했다가 후에 재개하는 등의 기본 동작을 수행합니다. 이는 시스템 테이블에 정의되어 있습니다. 프로세스가 모든 시그널을 무시하도록 설정하면 시그널이 아예 전달되지 않습니다.
- **시그널 핸들러(Signal Handler)**: 프로그래머가 지정된 함수를 설정하여, 특정 시그널이 오면 해당 함수를 호출하도록 만드는 방법입니다.
    - **동작 방식**: 시그널은 소프트웨어적 인터럽트이므로, 시그널을 받으면 현재 하던 작업을 딱 세이브(처리 작업을 중지)하고 시그널 핸들러를 호출하여 실행한 뒤, 핸들러가 끝나면 다시 원래 하던 일로 돌아가 계속 작업을 시작합니다.
    - **설정 함수**: 한 번만 유효한 시그널 핸들러를 설치할 수도 있고, 한 번 설정하면 모든 시그널에 대해 계속 유효하게 만들 수도 있습니다. 관련 함수로는 `sigaction()` 등 다양한 함수들이 있습니다. 함수의 세부적인 기능 자체를 외우기보다는 전반적인 개념과 처리 방식을 이해해야 합니다.

## 2. 메모리 매핑(Memory Mapping) 관련 문제 핵심 해설


### Q1. `mmap()` 시스템 호출을 사용하는 목적과 용도
`mmap()`은 프로세스의 가상 메모리 공간에 파일을 직접 매핑하는 시스템 호출로, 커널과 사용자 공간 사이의 데이터 복사 과정을 생략한다 그래서 프로세스 간 공유 메모리를 구축하거나 대용량 파일의 고속 I/O 용도로 사용된다.


### Q2. `msync()` 시스템 호출의 용도
`mmap()`을 통해 메모리에 매핑된 데이터의
변경 내용을 실제 하드디스크로 동기화해줘서,
시스템 다운시 데이터 유실을 막는다.

- `mmap()`을 통해 메모리의 내용을 변경하더라도, 운영체제는 효율성을 위해 이를 즉시 하드디스크에 저장하지 않고 메모리에만 유지할 때가 많습니다.
### **Q3.** 메모리 매핑에 대한 설명 중 옳은 것 혹은 틀린 것을 고르는 문제 대비
- **개념**: 예전에는 공유된 파일을 동시에 오픈(`open`)하고 그것을 라이트(`write`)하는 방식을 썼지만, 메모리 매핑은 파일 자체를 직접 핸들링하지 않습니다. **파일 자체와 메모리를 일대일로 매핑(Mapping)시켜서 메모리를 직접 액세스하면, 그것이 파일에 자동으로 적용되는 방식**을 취합니다.
- **기본 프로세스**:
    1. 열린 파일을 `mmap()`이라는 함수를 이용해 메모리에 매핑합니다.
    2. 매핑된 메모리 영역(포인터나 배열 개념으로 선언된 영역)의 데이터를 대상으로 작업을 수행합니다. 예를 들어 캐릭터 포인터(`char*`)가 있다면 포인터의 주소만 변경해서 메모리 값을 쉽게 읽어올 수 있습니다.
    3. `read()`나 `write()` 같은 파일 입출력 함수를 번거롭게 이용하지 않고 직접 메모리를 제어할 수 있으며, **메모리 매핑을 한 후에는 파일을 클로즈(`close`)해도 변경된 내용이 파일에 계속 적용**됩니다.

### Q2. `pipe()` 시스템 호출 시 리턴되는 2개의 파일 기술자(FD) 배열의 역할

- `pipe(int fd[2])` 함수가 성공하면 파이프가 생성되면서 크기가 2인 정수형 배열에 두 개의 파일 기술자(FD)를 넣어 리턴해 줍니다.
    - **`fd[0]`**: **읽기 전용 (Read End)** 파이프 출구
    - **`fd[1]`**: **쓰기 전용 (Write End)** 파이프 입구
- _암기 팁: 0은 입력(가장 먼저 읽음), 1은 출력(가장 먼저 씀)_
### Q3. 이름 없는 파이프(Anonymous)와 이름 있는 파이프(Named, FIFO)의 사용 상황 비교

- **이름 없는 파이프**: 부모-자식 프로세스처럼 **혈연관계(상속 관계)가 있는 프로세스 간 통신**에 사용됩니다. `fork()`를 하기 전에 생성해야 자식이 파일 기술자를 복사받을 수 있기 때문입니다.
- **이름 있는 파이프 (FIFO)**: 파일 시스템에 실제 이름(경로명)이 존재하므로, **아무런 혈연관계가 없는 완전히 독립된 프로세스 간 통신**에 사용됩니다.

### Q4. 파이프 사용에 적합한 시나리오와 적합하지 않은 시나리오 (서술형/선택형)

- **적합한 시나리오**: 단방향 통신, 부모와 자식프로세스간 데이터 전달
- **적합하지 않은 시나리오**: 양방향 통신, 데이터 구조화가 필요한경우
## 2. System V IPC 관련 문제 정답 및 해설

### 혹시 모를 기타 문제
- #### 통신의 2가지 분류
	- IPC: **동일한 시스템(호스트)** 내부의 프로세스 간 데이터 통신.
	- 네트워크 통신: **서로 다른 시스템** 간에 네트워크를 경유하는 통신.
- #### IPC의 역사와 기술적 한계 극복
	- **초창기 유닉스 파이프**: 특수 파일이나 공통 메모리를 이용해 통신함.
	- **파일 통신의 한계와 해결 (mmap)**: 디스크 파일 I/O 속도 저하 문제를 해결하기 위해, 파일을 메모리에 매핑(`mmap`)하여 통신 속도를 획기적으로 개선함.
	- **공유 메모리의 보안 문제**: 과거처럼 임의의 특정 메모리 주소를 직접 지정하는 방식은 보안 위험이 커 현대 OS에서는 **운영체제(OS)의 통제 하에 관리**함.
	- 현대 OS는 계보(BSD/리눅스)와 상관없이 **System V IPC를 완벽히 지원**한다
- 대용량 데이터 전송뿐만 아니라, **시그널이나 세마포어 상태 값 같은 단순한 정수형 데이터를 주고받으며 동기화를 맞추는 것**도 넓은 의미의 IPC에 포함됨.
- #### System V IPC의 3대 핵심 요소: 메시지 큐, 공유 메모리, 세마포어
	- 메시지 큐 : 메세지 단위로 동작 (파이프는 스트림)
	- 공유 메모리: 한 프로세스의 메모리영역을 다른 프로세스와 공유
	- 세마포어: 동기화 및 순서를 제어해주는 기법
- #### 네트워크 통신
	- 요즘엔 TCP/IP가 표준이며, 소켓라이브러리만 사용한다

### Q1. 메시지 큐와 공유 메모리 옳고 틀린것
- **메시지 큐**: 파이프와 달리 데이터를 시냇물처럼 보내지 않고, 고정된 크기의 메시지 단위(패킷 단위)로 쪼개어 우편함에 넣듯 통신합니다. 경계가 명확하므로 읽는 쪽에서 메시지별로 끊어 읽기 편합니다..
- **공유 메모리 (Shared Memory)**: 두 프로세스의 가상 주소 공간이 동일한 물리 RAM 영역을 가리키도록 매핑합니다. 최초 연결(`shmat`) 이후에는 커널을 거치지 않고 **유저 공간에서 직접 메모리에 접근하기 때문에 IPC 기법 중 속도가 가장 빠릅니다.** 단, OS가 동기화를 지원하지 않으므로 데이터 오염 방지 장치가 필수적입니다. (구현한게 mmap)
- **메시지 큐 (Message Queue)**: 커널 메모리 영역에 링크드 리스트 형태의 큐를 생성하여 데이터를 주고받습니다. 파이프와 달리 연속된 바이트가 아니라 **사용자가 정의한 구조체(Packet) 단위로 데이터의 경계(Boundary)를 명확히 유지**합니다. 시스템 콜(`msgsnd`, `msgrcv`)을 거치므로 복사 오버헤드가 발생하지만, 커널이 자동 동기화를 해주므로 안전합니다.

### Q2. 독립된 프로세스 간 공유 메모리 통신 시 데이터 오염을 막기 위한 동기화 기법

| **기법**   | **핵심 키워드**             | **한 줄 요약**                        |
| -------- | ---------------------- | --------------------------------- |
| **세마포어** | `semop()`, 카운터, P/V 연산 | 자원 개수를 카운팅하며 0이 되면 프로세스를 대기시킴     |
| **뮤텍스**  | `Lock`/`Unlock`, 상호 배제 | 오직 하나의 프로세스만 열쇠(Lock)를 쥐고 자원에 접근함 |
| **시그널**  | `kill()`, 이벤트 알림       | 프로세스 간에 특정 신호를 주고받으며 실행 순서를 제어함   |


### Q3. 서로 다른 프로세스끼리 공유메모리를 통하여 통신하는 경우에 동기화를 위한 방법은? (talker와 listener 동작 방식 참고)

- **Talker (송신측/서버역할)**: `ftok()`으로 키 생성 $\rightarrow$ `shmget()`으로 공유 메모리 객체 생성 $\rightarrow$ `shmat()`로 프로세스에 메모리 첨부(Attach) $\rightarrow$ 메모리에 데이터 쓰기.
- **Listener (수신측/클라이언트역할)**: 동일한 키값으로 `shmget()` 및 `shmat()` 수행 $\rightarrow$ 메모리에 적힌 내용 읽기 $\rightarrow$ `shmdt()`로 분리(Detach) $\rightarrow$ 필요시 `shmctl(IPC_RMID)`로 자원 삭제.


```C
/* [시그널 핸들러 함수]
 * Talker가 보낸 SIGUSR1 시그널을 수신했을 때 호출됩니다.
 * 특별한 내부 로직은 없지만, 이 핸들러가 실행되면서 대기 상태(sigsuspend)를 깨우는 역할을 합니다. */
void handler(int dummy) {
    // 아무것도 하지 않고 리턴하여 sigsuspend를 종료시킴
}

int main() {
    key_t key;
    int shmid;
    void *shmaddr;
    char buf[1024];
    sigset_t mask;

    /* 1. IPC 키 및 공유 메모리 생성 */
    // ftok: 동일한 경로와 ID를 이용해 고유한 IPC 키를 생성 (Talker와 일치해야 함) file to key
    key = ftok("shmfile", 1); 
    
    // shmget: 1024바이트 크기의 공유 메모리 세그먼트 생성
    // IPC_CREAT: 존재하지 않으면 새로 생성, 0666: 읽기/쓰기 권한 부여
    shmid = shmget(key, 1024, IPC_CREAT | 0666);
    
    /* 2. 시그널 마스크 설정 (동기화 준비) */
    // sigfillset: 모든 시그널을 마스크(블록) 후보로 설정
    sigfillset(&mask);
    
    // sigdelset: 마스크에서 SIGUSR1을 제외 (즉, SIGUSR1 시그널만 받겠다는 의미)
    sigdelset(&mask, SIGUSR1);
    
    // signal: SIGUSR1 시그널이 오면 위에서 정의한 handler 함수를 실행하도록 등록
    signal(SIGUSR1, handler);

    /* 3. 동기화 - Talker의 신호 대기 */
    printf("Listener wait for Talker\n");
    
    // sigsuspend: 설정한 mask를 적용하고 프로세스를 블록(대기) 상태로 전환.
    // Talker가 데이터를 쓰고 SIGUSR1 시그널을 보내줄 때까지 여기서 멈춰서 기다립니다.
    sigsuspend(&mask); 

    /* 4. 동기화 해제 후 공유 메모리 데이터 읽기 */
    printf("Listener Start =====\n");
    
    // shmat: 생성된 공유 메모리를 현재 프로세스의 가상 주소 공간에 연결(Attach)
    shmaddr = shmat(shmid, NULL, 0); 
    
    // strcpy: Talker가 공유 메모리에 작성해 둔 데이터를 buf로 복사(읽기)
    strcpy(buf, shmaddr);            
    printf("Listener received : %s\n", buf);

    /* 5. Talker에게 보낼 응답 작성 및 마무리 */
    // strcpy: 공유 메모리 공간에 새로운 응답 메시지("Have a nice day\n")를 작성
    strcpy(shmaddr, "Have a nice day\n"); 
    
    // sleep: Talker 프로세스가 'ipcs -mo'(공유 메모리 상태 확인)를 실행할 시간을 벌어주기 위해 3초간 대기
    sleep(3); 
    
    // shmdt: 사용이 끝난 공유 메모리의 연결을 해제(Detach)
    shmdt(shmaddr); 
    
    return 0;
}
```

// 실행 시 명령행 인자(Argument)로 Listener의 PID를 받아야 합니다. (예: ./talker [Listener_PID])
int main(int argc, char **argv) {
    key_t key;
    int shmid;
    void *shmaddr;
    char buf[1024];

    // 실행 인자가 부족할 경우 예외 처리
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <Listener_PID>\n", argv[0]);
        exit(1);
    }

    /* 1. Listener가 생성한 공유 메모리 접근 */
    // ftok: Listener와 동일한 파일명, 동일한 ID(1)를 사용하여 같은 IPC 키를 생성
    key = ftok("shmfile", 1);
    
    // shmget: 이미 생성된 공유 메모리의 식별자(ID)를 얻어옴 (플래그를 0으로 설정)
    shmid = shmget(key, 1024, 0); 
    
    /* 2. 공유 메모리에 데이터 쓰기 */
    // shmat: 공유 메모리를 현재 Talker 프로세스의 주소 공간에 연결(Attach)
    shmaddr = shmat(shmid, NULL, 0); 
    
    // strcpy: 연결된 공유 메모리 공간에 인사말 메시지를 복사(쓰기)
    strcpy(shmaddr, "Hello, I'm talker\n"); 

    /* 3. 동기화 - Listener에게 데이터 작성이 완료됨을 알림 */
    // kill: 첫 번째 인자로 받은 Listener의 PID(atoi로 정수 변환)로 SIGUSR1 시그널을 보냄.
    // 이 시그널을 통해 대기 중이던 Listener가 깨어나서 공유 메모리를 읽기 시작함.
    kill(atoi(argv[1]), SIGUSR1); 
    
    // sleep: Listener가 데이터를 읽고 응답("Have a nice day\n")을 다시 공유 메모리에 쓸 때까지 2초간 대기
    sleep(2);

    /* 4. Listener의 응답 확인 */
    // strcpy: Listener가 공유 메모리에 새로 써놓은 답장 데이터를 buf로 복사
    strcpy(buf, shmaddr);
    printf("Listener said : %s\n", buf); 

    /* 5. 자원 정리 및 공유 메모리 삭제 */
    // system: 현재 시스템의 공유 메모리 상태 및 연결된 프로세스 정보(ipcs -mo)를 터미널에 출력
    system("ipcs -mo");
    
    // shmdt: Talker 프로세스에서 공유 메모리 연결을 해제(Detach)
    shmdt(shmaddr); 
    
    // shmctl: IPC_RMID 플래그를 사용하여 커널 시스템에서 공유 메모리 자원 자체를 완전히 삭제
    // (보통 서버나 클라이언트 중 마지막으로 끝나는 프로세스가 자원을 정리함)
    shmctl(shmid, IPC_RMID, NULL); 

    return 0;
}

### Q2. 소켓 프로그래밍을 위해서 알고 있어야 할 정보들은?

### Q3. 소켓의 주소 구조체(`sockaddr_in`)를 구성하고 있는 정보들은?
> 인터넷 소켓 프로그래밍에서 주소를 지정할 때 쓰는 핵심 구조체입니다.

주소체계 포트번호 ip

1. **주소 체계 (sin_family):** 네트워크 주소 종류 (IPv4는 `AF_INET`)
2. **포트 번호 (sin_port):**: 프로세스 식별 (`htons()`로 빅엔디언으로 변환)
3. **IP 주소 (sin_addr):** 컴퓨터 식별 32비트 IPv4 주소
	- (문자열 IP 주소를 `inet_addr()` 등을 이용해 바이너리로 변환하여 대입)
4. **패딩 (sin_zero):** 전체 구조체 크기를 맞추기 위한 여백 배열

### Q3. `socket()` 시스템 호출이 성공적으로 수행되었을 때 커널로부터 최종적으로 반환되는 것

- **정답: 소켓 디스크립터 (SD)**
- 일반 파일 입출력이 파일을 제어할수있는 FD 반환하듯이 소켓을 제어할수있는 양수 값을 반환합니다. 실패 시 `-1`을 반환합니다.

### Q4. 소켓 생성 시 타입을 `SOCK_STREAM`과 `SOCK_DGRAM`으로 설정했을 때의 각각의 의미와 매칭 프로토콜

- **`SOCK_STREAM`**: **TCP 프로토콜**이다. 연결 지향형, 데이터 전송 순서 보장, 높은 신뢰성, 경계 없음(Byte Stream).
- **`SOCK_DGRAM`**: **UDP 프로토콜**이다. 비연결형, 순서 및 수신 여부 보장 안 함, 빠른 전송 속도, 데이터 경계 있음(Datagram).

### Q6. TCP 서버, 클라이언트 애플리케이션 소켓 함수 호출 순서 (무조건 빈칸 출제)

- **서버(Server) 호출 순서**:
    
    1. ` socket(AF_INET, SOCK_STREAM, 0)⁠` : 주소체계, 소켓타입, 프로토콜 인자로 소켓 생성
    2. `bind(server_fd, (struct sockaddr *)&server_addr, sizeof(server_addr))` : 소켓에 IP/Port 번호 결합 (서버 소켓에 주소 부여)
    3. `listen(server_fd, 5)` : 연결 요청 대기 상태 설정 (클라이언트 접속을 받을 준비한다. 단 하나만 존재)
    4. `accept(server_fd, (struct sockaddr *)&client_addr, &client_addr_len)` : 클라이언트 연결 요청 수락 (성공시 실제 통신용 전담 소켓을 매번 생성한다.)
    5. `recv(client_fd, buffer, sizeof(buffer), 0)` / `send(client_fd, message, strlen(message)` : 데이터 송수신
    6. `close(fd)` : 소켓 종료
    
- **클라이언트(Client) 호출 순서**:
    
    1. ` ⁠socket(AF_INET, SOCK_STREAM, 0)⁠` : 소켓 생성
    2. `connect(sock_fd, (struct sockaddr *)&server_addr, sizeof(server_addr))` : 서버에 연결 요청 (서버의 `accept()`와 연결됨)
    3. `send()` / `recv()` : 데이터 송수신
    4. `close(fd)` : 소켓 종료

### 1. 서버(Server) 소스코드
 * **주요 특징:** bind로 주소를 묶고, listen으로 대기한 뒤, accept가 성공하면 **새로운 통신용 소켓(client_fd)**을 반환받아 데이터를 주고받습니다.
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

#define PORT 8080
#define BUFFER_SIZE 1024

int main() {
    int server_fd, client_fd;
    struct sockaddr_in server_addr, client_addr;
    socklen_t client_addr_len = sizeof(client_addr);
    char buffer[BUFFER_SIZE] = {0};
    char *message = "안녕하세요, 클라이언트님! 서버에 연결되었습니다.";

    // 1. socket(): 서버 소켓 생성 (IPv4, TCP 프로토콜)
    server_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (server_fd < 0) {
        perror("소켓 생성 실패");
        exit(EXIT_FAILURE);
    }

    // 주소 구조체(sockaddr_in) 설정 (3가지 정보)
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;                // 주소 체계 (IPv4)
    server_addr.sin_addr.s_addr = INADDR_ANY;        // IP 주소 (현재 PC의 IP 자동 매핑)
    server_addr.sin_port = htons(PORT);              // 포트 번호 (엔디언 변환 필수!)

    // 2. bind(): 소켓에 IP/Port 번호 결합
    if (bind(server_fd, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("Bind 실패");
        close(server_fd);
        exit(EXIT_FAILURE);
    }

    // 3. listen(): 연결 요청 대기 상태 설정 (동시 대기 큐 크기: 5)
    if (listen(server_fd, 5) < 0) {
        perror("Listen 실패");
        close(server_fd);
        exit(EXIT_FAILURE);
    }
    printf("서버: 포트 %d에서 클라이언트 접속을 대기 중입니다...\n", PORT);

    // 4. accept(): 클라이언트 연결 요청 수락 (실제 통신용 client_fd 생성)
    client_fd = accept(server_fd, (struct sockaddr *)&client_addr, &client_addr_len);
    if (client_fd < 0) {
        perror("Accept 실패");
        close(server_fd);
        exit(EXIT_FAILURE);
    }
    printf("서버: 클라이언트가 연결되었습니다!\n");

    // 5. send() / recv(): 데이터 송수신
    // 데이터 송신 (Server -> Client)
    send(client_fd, message, strlen(message), 0);
    
    // 데이터 수신 (Client -> Server)
    int valread = recv(client_fd, buffer, BUFFER_SIZE - 1, 0);
    if (valread > 0) {
        printf("클라이언트로부터 받은 메시지: %s\n", buffer);
    }

    // 6. close(): 소켓 종료
    close(client_fd); // 통신용 소켓 닫기
    close(server_fd); // 대기용 서버 소켓 닫기
    return 0;
}

```
### 2. 클라이언트(Client) 소스코드
 * **주요 특징:** 대기(bind/listen) 과정 없이, 생성 직후 서버의 IP와 포트를 향해 connect를 던집니다.
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

#define PORT 8080
#define BUFFER_SIZE 1024

int main() {
    int sock_fd = 0;
    struct sockaddr_in server_addr;
    char buffer[BUFFER_SIZE] = {0};
    char *message = "반갑습니다 서버님! 저는 클라이언트입니다.";

    // 1. socket(): 클라이언트 소켓 생성
    sock_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (sock_fd < 0) {
        printf("\n 소켓 생성 실패 \n");
        return -1;
    }

    // 연결할 서버의 주소 구조체 설정
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(PORT); // 서버의 포트 번호와 일치해야 함
    
    // IP 주소 문자열("127.0.0.1")을 32비트 이진 네트워크 주소로 변환하여 대입
    if (inet_pton(AF_INET, "127.0.0.1", &server_addr.sin_addr) <= 0) {
        printf("\n 잘못된 주소 또는 지원하지 않는 주소입니다. \n");
        return -1;
    }

    // 2. connect(): 서버에 연결 요청 (서버의 accept와 매칭됨)
    if (connect(sock_fd, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        printf("\n 서버 연결 실패 (서버가 켜져 있는지 확인하세요) \n");
        return -1;
    }
    printf("클라이언트: 서버 연결에 성공했습니다!\n");

    // 3. send() / recv(): 데이터 송수신
    // 데이터 수신 (Server -> Client)
    int valread = recv(sock_fd, buffer, BUFFER_SIZE - 1, 0);
    if (valread > 0) {
        printf("서버로부터 받은 메시지: %s\n", buffer);
    }

    // 데이터 송신 (Client -> Server)
    send(sock_fd, message, strlen(message), 0);

    // 4. close(): 소켓 종료
    close(sock_fd);
    return 0;
}

```
### 💡 시험에 무조건 나오는 코드 매칭 포인트
 1. **htons(PORT)**: 포트 번호를 대입할 때 그냥 8080을 넣으면 안 되고, 엔디언 변환 함수인 htons를 반드시 씌워야 합니다.
 2. *_(struct sockaddr _)&server_addr__: bind나 connect 함수는 범용 주소 구조체 타입인 struct sockaddr * 형변환(캐스팅)을 요구하므로 강제로 변환해서 넣어주어야 합니다.
 3. **accept의 인자**: accept(server_fd, ...)처럼 대기하고 있던 '서버 소켓'을 첫 번째 인자로 주어야 하며, 성공하면 '새로운 소켓 식별자'를 반환한다는 흐름을 눈여겨보세요!
