### 🔥 [최종 암기] 리눅스 명령어 & 출력 대응표

## 중요
- **MAC 주소 (Physical Address)**: **고정된 물리적 주소**
- **IP 주소 (Logical Address)**: 컴퓨터를 식별하는 **논리적 주소**.
- **포트 번호 (Port Number)**: 프로그램(프로세스) 구분하는 번호.
    - 예: 웹 서비스(HTTP)는 80번 포트 사용.
- 시스템의 모~든 프로세스 상세 확인 (관리자 필수 명령어)
	- ps -ef
-  CPU, 메모리 사용률까지 포함해서 보기 (aux)
	- ps aux

| **옵션**         | **신호 이름**   | **의미 및 동작**                              |
| -------------- | ----------- | ---------------------------------------- |
| **`kill -2`**  | **SIGINT**  | **인터럽트**. 키보드 **`Ctrl + C`**와 동일.        |
| **`kill -9`**  | **SIGKILL** | **강제 종료**. 프로세스가 거부할 수 없음. (무조건 죽음)      |
| **`kill -15`** | **SIGTERM** | **정상 종료**. `kill` 명령어의 **기본값(Default)**. |
- 좀비 프로세스의 경우 9번 시그널을 받아도 종료되지 않을 수 있다.
#### 정규 패턴식
| **기호**  | **이름**      | **의미**       | **시험 예시 패턴** | **해석**                                  |
| ------- | ----------- | ------------ | ------------ | --------------------------------------- |
| **`^`** | 캐럿 (Caret)  | **행의 시작**    | `^root`      | **root**로 시작하는 줄                        |
| **`$`** | 달러 (Dollar) | **행의 끝**     | `sh$`        | **sh**로 끝나는 줄                           |
| **`.`** | 닷 (Dot)     | **임의의 한 글자** | `r..t`       | r과 t 사이에 **아무거나 2글자** 있음 (root, rest 등) |
- `^$` : **빈 줄** (시작하자마자 끝남)
- `.*` : **모든 문자열** (아무 문자(`.`)가 0번 이상 반복(`*`))
	- a\*b 일땐 aaaaaaab를 찾아라 이런 의미
- `[0-9]*` : 숫자가 있어도 되고 없어도 되는 패턴
	- 대괄호안의 ^는 not의 개념
- `^#` : 주석 처리된 줄 (#으로 시작)

#### 2. 권한 설정 (`chmod`, `umask`) - 계산 문제 주의
`명령 [특수 권한] [소유자] [그룹] [기타]`
- 읽고 쓰고 실행 순으로 4,2,1
- 특수권한
	- 4: 실행시 파일소유자 권한으로 실행
		- 소유자 x의 위치에 s로 표시 `-rwsr-xr-x`
	- 2: 실행시 파일그룹 권한으로 실행
		- 그룹 x의 위치에 s로 표시 `-rwxr-xr-x`
	- 1: stickybit 누구나 쓸수있지만, **삭제는 파일 주인만** 가능.
		- `chmod 1777 [디렉토리]`  
		- 기타 사용자 x위치에 `t`로 표시됨 (`drwxrwxrwt`)
- umask : 파일/디렉터리를 **새로 만들 때만** 자동반영됨
	- `umask [문자나 숫자로 설정]` 이제 앞으로 666(파일) 777(디렉토리)에서 이 숫자를 뺀채 생성된다.
		- 파일은 실행권한이 빼진 666이 기본임 디렉토리의 x는 실행보단 진입권한을 의미함
- 이미 존재하는 파일을 권한설정하는법
	- 숫자로 설정
		- `chmod 600 파일이름` 나만읽고 쓰기
	- 문자로 설정
		- `chmod [대상] [연산자] [권한] 파일이름`
		- `chmod ug+w,o-x 파일이름` **u**ser와 **g**roup에 쓰기 권한을 추가하고, **o**thers에서 실행 권한을 제거

#### 3. 파일 검색 & 찾아서 실행 (`find`) - 문법 주의

`find [경로] [찾을방법옵션] [찾은후 동작\;]`
- 찾을방법 옵션
	- `-name 파일명`
	- `-type 타입명` 디렉토리는 d로 일반파일은 f로
	- `-user 소유자명`
	- `-perm 권한숫자`
	- `-size 크기`
- `find [경로] -empty` 빈파일찾기(크기가 0)
- 찾은후 동작
	- `-exec`: 묻지 않고 바로 실행
	- `-ok`: 실행할지 사용자에게 물어봄 (y/n)
	- `{}`: 찾은 파일명이 들어가는 자리
	- `\;`: 명령어의 끝을 알림 (반드시 써야 함)

```bash
# [실습] 현재 디렉토리(.)에서 모든 'linux.txt'를 찾아 'data.txt'로 이름 변경(mv)
find . -name linux.txt -exec mv {} data.txt \;

# [실습] 찾고 삭제함(이때 다시 물어봄)
find . -name "*.tmp" -ok rm {} \;
```

**01. 로그인 셸 변경 시 `chsh -s dash user1` 오류 원인?**

- **답:** ④ 바꾸려는 셸을 절대 경로로 지정한다.
- **한줄 핵심:** `chsh` 명령어 사용 시 셸의 이름만 쓰는 것이 아니라 **절대 경로(예: `/bin/dash`)**를 입력해야 합니다.
- 쉘을 다시 기본으로 복구하는 명령어는 chsh 만 치면된다.

**02. `ls a?.exe` 실행 시 제외되는 파일은?**

- **답:** ① `a.exe`
- **한줄 핵심:** 와일드카드 `?`는 **정확히 한 글자**에만 대응하므로, 문자 사이에 글자가 없는 `a.exe`는 매칭되지 않습니다.
    

**03. `echo '"$SHELL"'` 출력 결과는?**

- **답:** ② `"$SHELL"`
- **한줄 핵심:** **작은따옴표(`'`)**는 내부의 모든 문자(특수문자 `$` 포함)를 문자열 그대로 취급합니다.
    

**04. 셸 변수 TEST를 서브 셸에서도 사용하려면?**

- **답:** ④ `export TEST`
- **한줄 핵심:** `export` 명령어를 사용해야 지역 변수가 **환경 변수**로 전환되어 서브 셸에 상속됩니다.
    

**05. 사용자 계정의 로그인 셸을 저장하고 있는 파일은?**

- **답:** ② `/etc/passwd`
- **한줄 핵심:** `/etc/passwd`는 사용자 정보(셸 포함)를 담고 있으며, 비밀번호는 `/etc/shadow`에 저장됩니다.
    


**06. `ls /tmp >> a.txt` 실행 결과는?**

- **답:** ④ 기존 내용은 남아 있고, `/tmp` 디렉터리의 내용이 추가된다.
- **한줄 핵심:** `>>` 리다이렉션 연산자는 기존 내용을 덮어쓰지 않고 파일 끝에 내용을 **추가(Append)**합니다.
    

**07. 계정의 기본 프롬프트가 저장되는 환경 변수는?**

- **답:** ① `PS1`
- **한줄 핵심:** `PS1`은 기본 프롬프트 모양을 설정하며, `PS2`는 명령어가 길어질 때 나타나는 2차 프롬프트입니다.
    

**08. 셸의 세 가지 주요 기능?**

- **답:** 명령어 해석기 기능, 프로그래밍(스크립트) 기능, 사용자 환경 설정(세션 관리) 기능
- **한줄 핵심:** 셸은 커널과 사용자 사이에서 명령을 해석하고, 프로그램을 실행하며, 환경을 관리합니다.
    

**09. 특수문자 `*`와 `?`의 차이?**

- **답:** `*`는 길이 0 이상의 모든 문자열과 매칭, `?`는 정확히 1개의 문자와 매칭
- **한줄 핵심:** `*`는 '모두', `?`는 '한 글자'를 의미하는 와일드카드입니다.
    

**10. 특수문자 `"`, `'`, `의 차이?**

- **답:** `"`는 변수($) 해석 허용, `'`는 모든 문자 그대로 출력, ` (백틱)은 명령어 실행 결과로 치환
- **한줄 핵심:** 큰따옴표는 변수를 치환해주지만, 작은따옴표는 문자 그대로, 백틱은 명령 실행 결과를 가져옵니다.
    

**11. 표준 입출력 장치란?**

- **답:** 표준 입력(0: 키보드), 표준 출력(1: 모니터), 표준 에러(2: 모니터)
- **한줄 핵심:** 리눅스에서 프로그램이 기본적으로 데이터를 읽고(Input) 쓰는(Output/Error) 통로입니다.
    

**12. `>` 사용 시 기존 파일 덮어쓰기 방지 방법?**

- **답:** `set -o noclobber` 만 치고 엔터 다음 명령부터 적용됨
- **한줄 핵심:** `noclobber` 옵션을 켜면 리다이렉션(`>`)으로 인해 기존 파일이 실수로 덮어씌워지는 것을 막습니다.
    

**13. 상세 정보는 `ls.out`, 오류는 `ls.err`에 저장하는 명령?**

- **답:** `ls -l > ls.out 2> ls.err`
- **한줄 핵심:** 표준 출력은 `>`(또는 `1>`)로, 표준 에러는 `2>`를 사용하여 각각 다른 파일로 보냅니다.


**14. `env` 결과에서 특정 환경 변수(예: SHELL)만 골라 출력하려면?**

- **답:** `env | grep SHELL`
- **한줄 핵심:** 파이프(`|`)로 `env`의 출력을 넘기고, `grep`으로 원하는 문자열을 필터링합니다.
    

**15. 배시셸 초기화 파일의 이름과 특징?**

- **답:** `/etc/profile`(전체 사용자용 초기화파일), `~/.bash_profile`(개인 초기화 파일), `~/.bashrc`(개인 셸 실행파일)
- **한줄 핵심:** 시스템 전역 설정은 `/etc`에, 사용자별 설정은 홈 디렉터리(`~`)의 숨김 파일로 저장됩니다.
    

**16. 확장자가 txt인 모든 파일명 출력?**

- **답:** `ls *.txt`
- **한줄 핵심:** 와일드카드 `*`는 모든 문자열을 의미하므로 `.txt`로 끝나는 모든 파일을 매칭합니다.
    

**17. 현재 디렉터리에서 숫자로 시작하는 파일 상세 정보 출력?**

- **답:** `ls -l [0-9]*`
- **한줄 핵심:** `[0-9]`는 숫자 한 글자를 의미하며, `*`와 조합해 숫자로 시작하는 파일들을 찾습니다.
    

**18. 확장자가 c인 모든 파일을 /tmp로 복사?**

- **답:** `cp *.c /tmp`
- **한줄 핵심:** `cp` 명령어에도 와일드카드를 사용하여 여러 파일을 한 번에 지정할 수 있습니다.

### **1. 객관식 문제 (선택형)**

#### **01. 프로세스의 PPID를 확인하기 위한 명령으로 옳은 것은?**

- **[정답 내용]**: `ps -f`
- **[한줄 핵심]**: `ps` 명령만으로는 PID만 나오지만, `-f`(Full format) 옵션을 사용해야 **PPID(부모 프로세스 ID)**와 UID 등 상세 정보가 출력된다.
    

#### **02. 사용자 han1과 관련된 프로세스의 정보를 확인하는 명령을 옳지 않은 것은?** (틀린 것 고르기)

- **[정답 내용]**: `ps -pu han1`
- **[한줄 핵심]**: `ps` 명령어에서 `-p` 옵션은 **PID(숫자)**를 인자로 받으므로, 사용자 이름으로 검색할 때는 `-p`를 빼고 **`ps -u han1`** 또는 **`ps -fu han1`**이라고 써야 한다.
    

#### **03. [2]번 작업을 포그라운드 작업으로 전환하기 위한 명령으로 옳은 것은?**
[1 ]+ 실행중 sleep 100 &
[2 ]- 실행중 fin d / -name passwd > pw.dat 2>&1 &
- **[정답 내용]**: `fg %2`
- **[한줄 핵심]**: 백그라운드에 있는 작업을 포그라운드로 가져올 때는 **`fg %작업번호`** 형식을 사용한다.
    

#### **05. 다음 중 프로세스에 대한 설명으로 옳지 않은 것은?** (틀린 것 고르기)

- **[정답 내용]**: 프로세스에는 UID라는 번호가 있다.
- **[한줄 핵심]**: 프로세스를 식별하는 고유 번호는 **PID**이며, UID는 해당 프로세스를 실행한 '사용자'의 식별 번호일 뿐 프로세스 자체의 ID는 아니다.
    

#### **06. 명령을 백그라운드 작업으로 실행시키기 위해 명령 다음에 추가하는 특수문자는 무엇인가?**

- **[정답 내용]**: `&`
- **[한줄 핵심]**: 명령어의 맨 끝에 앰퍼샌드(**`&`**)를 붙이면 해당 명령은 백그라운드에서 실행된다. (예: `find / -name test &`)

### **2. 주관식/서술형 문제**

#### **08. 일반 프로세스와 데몬 프로세스의 차이를 설명하시오.**

- **[정답 내용]**: 일반 프로세스는 터미널을 통해 사용자와 상호작용하며 실행되지만, **데몬 프로세스는 백그라운드에서 실행되며 특정 서비스를 제공하기 위해 대기**하는 프로세스이다.
- **[한줄 핵심]**: 데몬(Daemon)은 사용자의 입력 없이 시스템 서비스를 위해 백그라운드에 상주하는 프로세스이다.
    

#### **09. ps -f 명령의 결과가 다음과 같을 때 프로세스의 부모-자식 관계를 설명하시오.**
UID PID PPID C STIME TTY TIME CMD
user1 15761 15721 … vi /etc/hosts
user1 15721 15710 … sh
user1 15710 15701 … -bash_

- **[정답 내용]**: 부모 프로세스인 **`-bash`(15710)**가 자식 프로세스 **`sh`(15721)**를 실행했고, `sh`가 다시 자식 프로세스 **`vi`(15761)**를 실행했다.
- **[한줄 핵심]**: 프로세스 목록에서 **PPID(Parent PID)**가 가리키는 숫자가 바로 그 프로세스의 부모 PID이다.
    

#### **10. guest 사용자가 실행한 프로세스를 모두 찾으려고 할 때 사용할 수 있는 명령은 무엇인가?**

- **[정답 내용]**: `ps -u guest` (또는 `pgrep -u guest -l`)
- **[한줄 핵심]**: **`-u`** 옵션을 사용하면 특정 사용자가 실행시킨 프로세스만 필터링하여 볼 수 있다.
    

#### **11. PID가 5000인 프로세스를 kill 5000으로 종료하려는데 종료되지 않는다. 이 프로세스를 강제로 종료하려면 어떻게 해야 하는지 설명하시오.**

- **[정답 내용]**: `kill -9 5000`
- **[한줄 핵심]**: 일반 종료(15번)가 안 될 때는 **`-9` (SIGKILL)** 시그널을 사용하여 프로세스를 즉시 강제 종료시킨다.
    

#### **12. 주기적으로 프로세스들의 상태를 살펴볼 수 있는 방법에 대해 설명하시오.**

### **1. 쉘(Shell)과 환경 설정**

- **쉘의 개념과 종류**
    - **정의:** 사용자와 커널사이의 인터페이스(명령어 해석기).
    - **로그인 쉘 vs 서브 쉘:**
        - 로그인 쉘: 로그인 시 자동 실행되는 쉘.
        - 서브 쉘: 쉘 내부에서 실행된 자식 쉘.`sh`로 실행, `exit` 시 이전 쉘로 복귀.
        - **핵심:** 환경 변수는 서브 쉘에 상속되지만, 쉘 변수는 상속되지 않음.
- **내장명령어 vs 외장명령어**
    - **내장:** 쉘 자체 포함기능(`cd` 등). 별도 파일x(whereis로 못찾음)
    - **외장:** `/bin` 등에 별도 파일로 존재(`ls`, `pwd` 등). 실행 시 자식 프로세스 생성(`fork`).
- **인용 부호(Quotes)의 동작 차이**
    - `' '` (작은따옴표): 모든 문자열을 문자로 취급 (변수 해석 X).
    - `" "` (큰따옴표): `$`, `` ` ``, `\` 는 해석하여 기능 작동.
    - `` ` ` `` (백쿼트): 명령어로 실행 후 결과 반환.
- **환경 설정 파일의 실행 순서 (중요)**
    - **전역(Global):** `/etc/profile` (모든 사용자 공통)
    - **지역(Local):** `~/.profile`(전역) → `~/.bashrc` (사용자)
    - **적용:** 로그인 시 전역 → 지역 순서로 실행. 수정 후 `source` 명령어로 즉시 적용.
	    - cat ~/.profile 으로 확인,
	    - cat ~/.별칭파일생성
	    - source ~/.bashrc로 즉시적용
### **2. 파일 시스템과 권한 (Permissions)**

- **권한의 이해와 표기**
    - **구조:** 파일 유형(1) + 소유자(3) + 그룹(3) + 기타(3) = 총 10자리.
    - **표기:** `r`(4), `w`(2), `x`(1).
    - **디렉터리의 `x` 권한:** 해당 디렉터리에 '진입(cd)' 할 수 있는 권한.
    - 권한확인 ls -l 파일이름
- **Umask (유마스크)**
    - **원리:** 파일/디렉터리 생성 시 **'제외할 권한'**을 설정.
    - **계산:** (파일 최대 666 / 디렉터리 최대 777) - Umask 값 = 최종 권한.
- **특수 권한 (Special Permissions) ★**
    - **SetUID (4000):** 실행 시 **파일 소유자(Root 등)의 권한**으로 실행 (`s`로 표기). 예: `passwd`.
    - **SetGID (2000):** 실행 시 파일 소유 그룹의 권한으로 실행.
    - **Sticky Bit (1000):** 디렉터리에 설정. 누구나 생성 가능하나 **삭제는 소유자만** 가능 (`t`로 표기). 예: `/tmp`.
        

### **3. 프로세스(Process)와 스레드(Thread)**

- **프로세스 vs 스레드 비교 (서술형/객관식 유력)**
    - **프로세스:** 독립된 메모리 자원 할당. 안정성 높음. 통신 어려움(IPC 필요).
    - **스레드:** 프로세스 내 흐름. 자원(Code, Data, Heap) 공유. 통신 쉬움. 문맥 교환 빠름.
- **프로세스 생명 주기**
    - **Fork:** 부모 프로세스 복제 (생성).
    - **Exec:** 새로운 코드 실행.
    - **Exit:** 종료 신호 발송.
    - **Wait:** 부모가 자식의 종료 확인 및 자원 회수.
- **특수 프로세스 상태**
    - **좀비(Zombie):** 종료됐으나 부모가 `wait` 하지 않아 테이블에 남아있는 상태.
    - **고아(Orphan):** 부모가 먼저 죽은 자식. `systemd`(PID 1)가 입양.
    - **데몬(Daemon):** 백그라운드에서 대기하는 서비스(웹 서버 등). TTY(터미널)가 없음.
        

### **4. 입출력 제어 및 시스템 관리**

- **표준 입출력 (File Descriptor)**
    - 0(stdin), 1(stdout), 2(stderr).
    - **리다이렉션 차이:** `>` (덮어쓰기), `>>` (추가), `2>` (에러만 저장).
    - `/dev/null`: 데이터를 버리는 곳 (블랙홀).
- **사용자 관리 파일 보안**
    - `/etc/passwd`: 계정 정보. 누구나 읽기 가능 (`rw-r--r--`).
    - `/etc/shadow`: **암호화된 비번**. Root만 읽기 가능 (`r--------`). 보안을 위해 분리됨.
- **사용자 전환 차이 (`su` vs `sudo`)**
    - `su`: 계정 자체를 전환 (로그인). 환경변수까지 바꾸려면 `su -` 필수.
    - `sudo`: 관리자 권한을 **일시적으로 빌림**. 로그 남기기 좋음.
        

### **5. 데이터 표현 및 검색 원리**

- **문자 코드 체계**
    - **ASCII:** 7비트.
    - **Unicode (UTF-8):** 전 세계 문자 통합, 가변 길이.
- **비교 명령어 차이**
    - `cmp 피알1 파일2`: 바이너리 **바이트(Byte)** 단위 비교. 최초로 달라지는 점 알려줌
	- `diff 파일1 파일2`: 텍스트 **행(Line)** 단위 비교해 change, delete, add를 알려줌
		- `diff3 [파일1] [파일2] [파일3]`
- **검색 명령어의 동작 방식 차이**
    - `find [경로] [조건] [동작]`: 이 파일 찾아줘
	    - 디렉터리를 직접 뒤짐 (느림, 정확, 기능 많음).
	    - `find /home -name "*.txt"`
    - `whereis [명령어]` :환경변수 무시하고 **시스템의 표준 디렉터리** 를 뒤져서, 실행 파일뿐만 아니라 **소스 코드, 매뉴얼 파일**까지 한번에 찾아줌
	    - `whereis ls`
    - `which [명령어]` : **환경 변수 `$PATH`** 에 적힌곳에서만, 엔터를 쳤을 때 **실제로 실행되는 파일** 하나만 딱 찾는다
	    - `which -a ls` 숨겨진 경로까지 모두 찾음

### **2. 데이터 자르기 : `cut` vs `split`**

> **"파일을 쪼개는데, 방식이 다름"**

#### **① `cut` (열 추출)**

- **개념:** 파일 내용을 **세로(열, Column)**로 잘라냅니다.
- **핵심:** 필요한 **데이터 필드**만 뽑아낼 때 씁니다.
- **필수 옵션 (시험 유력):**
    - **`-d` (Delimiter)**: 구분자 지정 (기본은 탭, `/etc/passwd`는 `:`).
    - **`-f` (Field)**: 몇 번째 필드를 가져올지 지정.
    - _예시:_ `cut -d : -f 1 /etc/passwd` (구분자(:)를 기준으로 2번째 필드만 추출 ->사용자 아이디만 쏙 뽑아옴)
        

#### **② `split` (파일 분할)**

- **개념:** 파일 내용을 **가로(행, Line)** 또는 **크기**로 뚝뚝 끊어서 여러 파일로 만듭니다.
- **핵심:** **용량이 너무 큰 로그 파일** 등을 작게 나눌 때 씁니다.
- **특징:** 파일명을 지정 안 하면 `xaa`, `xab`… 식으로 자동 생성됨.
- **필수 옵션:**
    - **`-l`**: 줄 수 단위로 자름 (예: 1000줄씩).
    - **`-b`**: 바이트(용량) 단위로 자름 (예: 10MB씩).

### **3. 데이터 붙이기 : `paste`**

> **"엑셀에서 옆에 열을 붙이는 것과 같음"**

- **개념:** 두 파일의 내용을 **가로(수평)**로 합칩니다.
- **비교 (중요 ★):**
    - **`cat`**: 파일을 **세로(위아래)**로 합침. (1번 파일 끝에 2번 파일 붙임)
    - **`paste`**: 파일을 **가로(옆)**로 합침. (1번 파일 첫 줄 옆에 2번 파일 첫 줄 붙임)
- **구분자:** 합칠 때 사이에 기본적으로 **탭(Tab)**이 들어갑니다.

### **📝 시험 직전 한 줄 요약**

1. **`diff`**: **텍스트**가 어디가 다른지 줄 단위 확인.
2. **`cmp`**: **바이너리**가 어디가 다른지 바이트 단위 확인.
3. **`split`**: 너무 큰 파일을 **여러 개로 쪼갬** (`xaa`, `xab`…).
4. **`cut`**: 원하는 **열(세로)만** 쏙 뽑아냄 (`/etc/passwd` 아이디 추출).
5. **`paste`**: 두 파일을 **옆으로 나란히** 붙임 (`cat`은 위아래).

```bash
# 1. 'bash'라는 단어가 포함된 모든 프로세스 PID 검색
pgrep bash

# 2. 이름이 정확히 'bash'인 프로세스만 검색 (-x)
pgrep -x bash

# 3. PID와 이름을 같이 출력 (-l)
pgrep -l bash

# 4. 특정 사용자(user1)의 프로세스 중 이름까지 같이 보기
pgrep -l -u user1
```
