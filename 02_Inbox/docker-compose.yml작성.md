	- 로컬에서 데이터 유지란?
		- Docker 컨테이너는 삭제 시 내부 데이터가 함께 소멸되는 휘발성(Ephemeral)을 가집니다. 이를 방지하기 위해 **볼륨(Volume)**을 사용하여 데이터의 생명주기를 컨테이너와 분리합니다.

### **1. Docker Image & Container (이미지와 컨테이너)**

이 둘의 관계는 **자바의 클래스와 인스턴스(객체)** 관계와 매우 흡사합니다.

#### **Docker Image (클래스)**

- **정의:** 컨테이너를 실행하기 위해 필요한 모든 파일(OS 라이브러리, 실행 파일, 설정 등)을 포함한 **읽기 전용(Read-only) 템플릿**입니다.
- **특징:**
    - **불변성:** 이미지는 한 번 생성되면 변하지 않습니다.
    - **레이어 구조:** 베이스 이미지(예: Ubuntu) 위에 필요한 파일들이 층층이 쌓여 하나의 이미지를 이룹니다.
    - **역할:** 저장소(Docker Hub)에 저장되고 다운로드되는 **파일 그 자체**입니다.
        

#### **Docker Container (인스턴스)**

- **정의:** 이미지를 메모리에 로드하여 실제로 실행시킨 **프로세스(Process)**입니다.
- **특징:**
    - **격리성:** 호스트 OS와 격리된 별도의 파일 시스템과 네트워크 공간을 가집니다.
    - **쓰기 가능:** 이미지 위에 얇은 **'쓰기 가능한 레이어(Writable Layer)'**를 한 장 덮어 씌운 상태입니다. 컨테이너 안에서 파일을 생성하거나 수정하면 이 레이어에 저장됩니다.
    - **수명:** 프로세스가 죽으면 컨테이너도 중지됩니다.
        

> **핵심 요약:**
>
> - **Image**: 실행 불가능한 파일 덩어리 (프로그램 설치 파일)
> - **Container**: 실제로 실행 중인 프로그램 (실행된 프로세스)
>

### **2. Port Forwarding (포트 포워딩)**

컨테이너는 자신만의 독립적인 네트워크(IP주소와 포트)를 가집니다. 외부(내 컴퓨터)에서 이 격리된 공간으로 접속하려면 **'문(Port)'을 연결**해줘야 합니다.

#### **구조: `HOST_PORT : CONTAINER_PORT`**

`docker-compose.yml`에서 `5432:5432`라고 적는 것은 **매핑(Mapping)**을 의미합니다.

- **왼쪽 (Host Port):** 내 컴퓨터(Host)가 리스닝할 포트입니다.
- **오른쪽 (Container Port):** 컨테이너 내부에서 프로그램(PostgreSQL)이 리스닝하고 있는 포트입니다.
    

#### **동작 원리**

1. 사용자가 DBeaver로 `localhost:5432`에 접속 요청을 보냅니다.
2. Docker 데몬이 내 컴퓨터의 5432번 포트로 들어온 신호를 잡습니다.
3. 이 신호를 연결된 컨테이너 내부의 5432번 포트로 **전달(Forwarding)**합니다.
4. 컨테이너 내부의 PostgreSQL이 요청을 받습니다.
    

> Why?
>
> 이 설정이 없으면 컨테이너 내부는 완벽히 밀폐되어 있어, 내 컴퓨터에 설치된 DBeaver나 브라우저가 접속할 방법이 없습니다.

### **3. Environment Variables (환경 변수)**

소프트웨어를 실행할 때 필요한 **설정 값(Configuration)**을 코드나 이미지 안에 박아넣지 않고, **실행 시점에 주입(Injection)**하는 방식입니다.

#### **Docker Compose에서의 역할**

`docker-compose.yml`의 `environment` 섹션은 컨테이너가 시작될 때 **OS 환경 변수**를 설정해줍니다.



```YAML
environment:
  POSTGRES_USER: myuser      # DB 접속 ID
  POSTGRES_PASSWORD: secret  # DB 접속 비번
```

#### **기술적 흐름**

1. **Compose 실행:** `docker-compose up`을 하면 YAML 파일을 읽습니다.
2. **변수 주입:** 컨테이너를 생성할 때 리눅스 환경 변수(`env`) 영역에 위 값들을 등록합니다.
3. **애플리케이션 초기화:** PostgreSQL 프로세스가 켜지면서 `System.getenv("POSTGRES_PASSWORD")` 처럼 환경 변수를 읽어옵니다.
4. **동작 결정:** 읽어온 값을 이용해 초기 데이터베이스의 비밀번호를 설정합니다.
    

> **핵심 장점:**
>
> - **보안:** 소스 코드에 비밀번호를 하드코딩하지 않아도 됩니다.
>     
> - **유연성:** 같은 이미지라도 환경 변수만 바꾸면 '개발용 DB', '운영용 DB'로 다르게 동작시킬 수 있습니다.
