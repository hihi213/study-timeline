## **2025-09-19, 1교시 — 개선본**

Ubuntu는 다른 Linux 배포판(예: Red Hat, SUSE)과 달리 초기 `root` 계정 로그인을 기본적으로 비활성화하여 보안을 강화했습니다. 현재 여러분이 사용하는 계정은 일반 사용자 계정이며, `sudo` 명령을 통해 임시로 관리자 권한을 얻는 방식입니다. `root` 계정으로 직접 작업하면 시스템에 치명적인 손상을 줄 수 있어, 복구가 불가능한 상황이 발생할 수 있습니다. Ubuntu는 사용자 생성 시 `root`라는 이름의 계정을 만들지 못하도록 막고 있습니다.

터미널 창을 종료하는 방법에는 `Ctrl+D`를 누르거나 `exit` 명령을 입력하는 것이 일반적입니다. (실습) Linux 환경에서는 가급적 마우스 사용을 최소화하는 것이 좋습니다.

터미널 프롬프트는 사용자의 권한 상태를 나타냅니다. 일반 사용자는 `$` 기호로 표시되고, `root` 권한을 얻으면 `#` 기호로 변경됩니다. `#` 프롬프트 상태에서는 `rm`과 같이 파일을 영구적으로 삭제하는 명령어 사용에 각별한 주의가 필요합니다. 시스템이 재차 확인하더라도 습관적으로 `y`를 누르는 실수를 피해야 합니다.

프롬프트는 일반적으로 `사용자명@호스트명:현재경로$` 형태로 구성됩니다. 물결표시(`~`)는 현재 사용자의 홈 디렉터리를 의미합니다. `pwd` 명령을 입력하면 현재 작업 중인 디렉터리의 전체 경로(예: `/home/사용자명`)를 확인할 수 있습니다. (실습)

명령줄 편집 시 유용한 단축키가 있습니다. `Ctrl+W`는 단어 단위로 삭제하고, `Ctrl+U`는 현재 입력 중인 줄 전체를 삭제합니다. (실습)

Linux 명령어는 `명령어 [옵션] [인자]` 구조를 가집니다. 예를 들어 `date`를 입력하면 현재 날짜와 시간이 출력됩니다. (실습) `ls /tmp`와 같이 명령 뒤에 인자를 붙여 특정 대상에 대한 작업을 수행할 수 있습니다. (실습) 옵션은 보통 `-` 또는 `--` 기호로 시작하며, 명령어의 동작을 변경합니다. `ls -l`은 파일의 상세 정보를, `ls -al`은 숨김 파일을 포함한 모든 파일의 상세 정보를 보여줍니다. (실습)

명령어의 사용법이 궁금할 때는 `man` (manual) 명령을 사용합니다. `man ls`를 입력하면 `ls` 명령어에 대한 매뉴얼을 볼 수 있습니다. (실습) 매뉴얼 내에서는 엔터 키로 한 줄씩, 스페이스 바로 한 페이지씩 이동할 수 있으며, `q` 키를 눌러 종료합니다. (실습) `man pwd`를 통해 `pwd` 명령어의 옵션(`-P`, `-L` 등)을 확인할 수 있고, `pwd -P`처럼 옵션을 적용해 실행할 수 있습니다. (실습)

자주 사용하는 기본 명령어는 다음과 같습니다.

- `clear`: 터미널 화면을 깨끗하게 정리합니다. (실습)
- `ls`: 현재 디렉터리의 파일 및 디렉터리 목록을 보여줍니다. (실습) `ls -a`는 숨김 파일(이름이 `.`으로 시작)을 포함하여 보여줍니다. (실습)
- Windows의 `dir` 명령어와 유사하며, `.`은 현재 디렉터리, `..`은 상위 디렉터리를 의미합니다. 이 표기법은 Linux에서도 동일합니다.

명령줄에서는 탭(`Tab`) 키를 이용한 자동 완성 기능을 적극적으로 활용하는 것이 좋습니다. 파일이나 디렉터리 이름의 일부를 입력하고 탭 키를 누르면 나머지 부분이 자동으로 완성되거나 가능한 목록이 표시되어 오타를 줄일 수 있습니다. (실습)

사용자 계정의 비밀번호를 변경하려면 `passwd` 명령을 사용합니다. (실습) 현재 비밀번호를 입력한 후 새 비밀번호를 두 번 입력하면 변경이 완료됩니다. 보안을 위해 여러 사이트에서 동일한 비밀번호를 사용하는 것을 피하고, 사이트별로 특정 패턴을 적용하여 비밀번호를 관리하는 것이 안전합니다.

## 2025-09-19, 1교시 — 개념

### 한 줄 요약

리눅스 시스템의 기본 보안 모델(`root`와 `sudo`), 터미널 제어, 명령어 구조 및 필수 명령어(`ls`, `pwd`, `man`, `passwd`)의 사용법을 학습합니다.

### 핵심 TL;DR

- **`root` 계정**: 시스템의 모든 권한을 가진 관리자 계정으로, Ubuntu에서는 보안을 위해 기본적으로 비활성화되어 있습니다.
- **`sudo`**: 일반 사용자가 `root`의 권한을 일시적으로 빌려 명령을 실행할 때 사용하며, 권한 오남용을 방지합니다.
- **프롬프트 기호**: 일반 사용자는 `$` 프롬프트, `root` 사용자는 `#` 프롬프트를 가지므로 현재 권한 상태를 항상 확인해야 합니다.
- **명령어 구조**: 모든 명령어는 기본적으로 `명령어 [옵션] [인자]` 형태로 구성되며, 옵션과 인자는 생략 가능할 수 있습니다.
- **`man` 페이지**: `man [명령어]` 형식으로 특정 명령어의 공식 설명서(Manual)를 조회할 수 있으며, `q` 키로 종료합니다.
- **터미널 제어**: `Ctrl+D` 또는 `exit`로 세션을 종료하고, `clear`로 화면을 정리하며, `Ctrl+U`(줄 삭제), `Ctrl+W`(단어 삭제)로 입력을 편집합니다.
- **디렉터리 약어**: `~`(홈 디렉터리), `.`(현재 디렉터리), `..`(상위 디렉터리)는 경로 탐색 시 매우 유용합니다.
- **탭 자동 완성**: 명령어, 파일, 디렉터리 이름 입력 시 `Tab` 키를 누르면 오타를 줄이고 입력 속도를 크게 향상시킬 수 있습니다.
- **절대/상대 경로**: 경로는 루트(`/`)에서 시작하는 **절대 경로**와 현재 위치 기준의 **상대 경로**로 구분하여 표현합니다.
- **`passwd`**: 현재 로그인한 사용자의 비밀번호를 변경하는 명령어입니다.

### 표현 = 표준 용어

- **`root`**: 시스템의 모든 자원에 접근하고 수정할 수 있는 최고 관리자 계정.
- **`sudo` (Super User Do)**: 일반 사용자가 허가된 관리자 명령을 자신의 암호로 실행할 수 있게 하는 프로그램.
- **Shell Prompt**: 셸이 사용자로부터 명령을 입력받을 준비가 되었음을 알리는 표시 (`$`, `#`).
- **`man` (Manual)**: 리눅스 시스템의 온라인 명령어 설명서.
- **Home Directory (`~`)**: 각 사용자에게 할당된 개인적인 파일 저장 공간.
- **Absolute Path (절대 경로)**: 파일 시스템의 루트 디렉터리(`/`)부터 시작하는 전체 경로.
- **Relative Path (상대 경로)**: 현재 작업 디렉터리(`.`)를 기준으로 한 상대적인 경로.

### 정석 보강 (canon-std)

root 계정과 sudo

root는 시스템 전체를 제어하는 절대 권한을 가지므로 작은 실수가 시스템 전체의 장애로 이어질 수 있습니다. 반면, sudo는 /etc/sudoers 파일에 정의된 정책에 따라 특정 사용자에게 제한된 관리자 권한을 부여합니다. 이는 작업 기록을 남기고(journalctl 또는 관련 로그 파일), 권한 오용을 막는 최소 권한 원칙(Principle of Least Privilege)을 구현하는 핵심적인 보안 기능입니다.

### 실수·함정

1. `#` 프롬프트 상태인 것을 잊고 `rm -rf /` 같은 치명적인 명령을 실행하는 경우.
2. `sudo` 없이 권한이 필요한 명령(예: 시스템 설정 변경)을 실행하고 "Permission denied" 오류를 만나는 경우.
3. 명령어 옵션을 붙여 쓰거나(`ls-l`), `-` 기호를 빠뜨리는 실수.
4. 파일이나 디렉터리 이름에 오타를 내고 `Tab` 자동 완성을 시도하지 않아 시간을 낭비하는 경우.
5. `man` 페이지를 연 뒤 종료하는 `q` 키를 몰라 터미널을 강제 종료하는 경우.
6. `cd ..` (상위)와 `cd .` (현재)의 의미를 혼동하는 경우.
7. 새 비밀번호 설정 시 너무 단순하여 시스템 정책에 거부되는 경우.
8. `exit`를 입력하려다 실수로 `exir` 등 오타를 내는 경우.

## 2025-09-19, 1교시 — 질문

**[Q1] Ubuntu에서 `root` 계정으로 바로 로그인할 수 없는 이유는 무엇이며, 관리자 작업은 어떻게 수행해야 하나요? | 태그: 권한/UMASK/특수비트**

- **모범답(강의 기준)**: 보안 강화를 위해 기본적으로 `root` 로그인이 막혀 있습니다. 관리자 작업이 필요할 때는 일반 계정에서 `sudo` 명령어를 사용하여 임시로 권한을 얻어 수행합니다.
- **정석체크(면접 30초)**: Ubuntu는 `root` 계정을 비활성화하여 비인가 접근 및 시스템 손상 위험을 줄이는 보안 모델을 채택합니다. `sudo`는 `/etc/sudoers` 정책에 따라 허가된 사용자에게 최소한의 권한을 부여하며, 모든 관리자 활동을 로깅하여 책임 추적성을 보장합니다.

**[Q2] 터미널 프롬프트의 `$`와 `#` 기호는 각각 무엇을 의미하며, 왜 중요한가요? | 태그: 셸/리다이렉션/FD**

- **모범답(강의 기준)**: `$`는 일반 사용자 계정, `#`는 `root`(관리자) 계정을 의미합니다. `#` 상태에서는 시스템을 파괴할 수 있는 명령도 경고 없이 실행될 수 있으므로 현재 권한이 무엇인지 항상 확인해야 합니다.
- **정석체크(면접 30초)**: 셸 프롬프트는 현재 세션의 권한 수준을 알려주는 핵심 지표입니다. `$`는 일반 사용자 권한을, `#`는 슈퍼유저 권한을 나타내므로, 사용자는 `rm -rf`와 같은 파괴적인 명령 실행 전에 프롬프트를 확인하여 치명적인 실수를 방지해야 합니다.

**[Q3] 처음 보는 리눅스 명령어의 정확한 사용법이나 옵션을 어떻게 확인할 수 있나요? | 태그: 셸/리다이렉션/FD**

- **모범답(강의 기준)**: `man [명령어]`를 입력하여 해당 명령어의 공식 매뉴얼(manual)을 열람할 수 있습니다. 매뉴얼 탐색 후에는 `q` 키를 눌러 종료합니다.
- **정석체크(면접 30초)**: `man` 페이지는 명령어의 시놉시스, 설명, 옵션 등을 제공하는 가장 신뢰도 높은 내장 문서입니다. 대부분의 명령어는 `--help` 옵션을 통해서도 필수 사용법 요약을 빠르게 확인할 수 있으며, 이는 `man`보다 간결한 정보를 제공할 때가 많습니다.

**[Q4] `ls`, `ls -l`, `ls /tmp` 명령어의 차이점은 무엇인가요? | 태그: 파일·디렉터리**

- **모범답(강의 기준)**: `ls`는 현재 디렉터리의 목록을 기본 형태로 보여줍니다. `ls -l`은 `-l`(long) 옵션을 추가하여 목록을 상세 정보(권한, 소유자, 크기 등)와 함께 보여주며, `ls /tmp`는 인자로 `/tmp`를 지정하여 현재 위치가 아닌 해당 디렉터리의 내용을 보여줍니다.
- **정석체크(면접 30초)**: 명령어의 동작은 옵션과 인자에 의해 결정됩니다. 옵션(`-l`)은 명령어의 출력 형식이나 행동 방식을 바꾸고, 인자(`/tmp`)는 명령어의 대상을 지정합니다. 이 구조를 이해하는 것은 모든 CLI(Command-Line Interface) 작업의 기본입니다.

**[Q5] 비밀번호를 변경한 후, 변경이 성공했는지 어떻게 확인할 수 있나요? | 태그: 사용자/그룹/쿼터**

- **모범답(강의 기준)**: 현재 터미널 세션을 종료(`exit`)하고 새로 접속하거나, PuTTY 같은 다른 클라이언트를 통해 변경된 새 비밀번호로 로그인을 시도해 보면 됩니다.
- **정석체크(면접 30초)**: 가장 확실한 검증은 인증(authentication)을 다시 시도하는 것입니다. 현재 세션을 로그아웃하고 새 비밀번호로 재로그인하거나, `su - [사용자명]` 명령을 실행하여 비밀번호 입력을 통해 인증이 성공하는지 즉시 확인할 수 있습니다.

## **2025-09-19, 1교시 — 실습**

**[S1] 터미널 기본 제어 — 세션 종료 및 화면 정리**

- **단계요약**: 1) `clear`를 입력하여 화면의 모든 텍스트를 지웁니다. 2) `exit` 명령을 입력하거나 `Ctrl+D`를 눌러 터미널 세션을 종료합니다.

**[S2] 명령어 줄 편집 — 단축키를 이용한 빠른 수정**

- **단계요약**: 1) 임의의 긴 문장(예: `ubuntu linux is fun`)을 입력합니다(엔터 제외). 2) `Ctrl+W`를 눌러 단어 단위로 삭제되는 것을 확인합니다. 3) `Ctrl+U`를 눌러 줄 전체가 삭제되는 것을 확인합니다.

**[S3] 기본 정보 조회 — 현재 시간, 위치, 파일 목록 확인**

- **단계요약**: 1) `date`를 입력해 현재 날짜와 시간을 확인합니다. 2) `pwd`를 입력해 현재 작업 중인 디렉터리의 전체 경로를 확인합니다. 3) `ls`를 입력해 현재 디렉터리의 파일과 하위 디렉터리 목록을 확인합니다.

**[S4] `ls` 명령어 활용 — 옵션과 인자로 출력 제어**

- **단계요약**: 1) `ls -l`을 입력해 파일 목록을 상세 정보(권한, 소유자 등)와 함께 봅니다. 2) `ls -al`을 입력해 숨김 파일(`.`)을 포함한 모든 파일의 상세 정보를 봅니다. 3) `ls /tmp`와 같이 특정 경로를 인자로 지정해 해당 위치의 목록을 봅니다.

**[S5] `man` 페이지 사용법 — 명령어 설명서 조회**

- **단계요약**: 1) `man ls`를 입력하여 `ls` 명령어의 공식 설명서를 엽니다. 2) 스페이스 바로 페이지를 넘기거나 화살표 키로 스크롤합니다. 3) `q` 키를 눌러 설명서를 종료합니다.

**[S7] 사용자 비밀번호 변경 — `passwd` 명령어 사용**

- **단계요약**: 1) `passwd`를 입력하고 엔터를 칩니다. 2) 현재 비밀번호를 입력합니다. 3) 새로운 비밀번호를 두 번 입력하여 변경을 완료합니다.

## **2025-09-19, 2교시 — 개선본**

파일 시스템(filesystem)이란 파일의 생성, 저장, 관리에 대한 규칙과 구조를 정의한 것입니다. 물리적인 디스크(HDD, SSD)를 어떻게 분할하고 데이터를 어떤 단위(블록 크기)로 저장하고 불러올지 결정합니다. 예를 들어 Windows의 NTFS나 FAT가 대표적인 파일 시스템이며, 포맷 시 할당 단위 크기를 지정하는 것은 한 번에 읽고 쓸 데이터 블록의 크기를 정하는 것입니다.

Linux 파일 시스템은 크게 **슈퍼블록(Superblock)**, **아이노드 테이블(Inode Table)**, **데이터 블록(Data Blocks)** 세 부분으로 구성됩니다.

(그니까 Linux파일은 1. 슈퍼블록 2. 아이노드 3. 데이터블록 이렇게 3가지요소로 존재)

- **슈퍼블록**: 전체 파일 시스템의 요약 정보(총 블록 수, 아이노드 개수, 블록 크기 등)를 담고 있습니다.
- **아이노드(Inode)**: 데이터블록주소+메타데이터(파일 이름을 제외한) 저장
	- 파일 하나하나에 대한 상세 메타데이터를 저장합니다. 파일의 종류, 권한, 소유자, 크기, 생성 시간 및 데이터 블록의 주소 정보가 포함됩니다. 파일 이름은 아이노드에 저장되지 않습니다.
- **데이터 블록**: 파일의 실제 내용(content)이 저장되는 공간입니다.

아이노드는 데이터 블록의 주소를 포인터처럼 가리킵니다. 데이터 용량이 클 경우, 직접 블록 포인터 외에도 블록 주소 목록을 가리키는 간접 블록 포인터(이중, 삼중 포인터와 유사한 개념)를 사용하여 효율적으로 데이터 위치를 관리합니다.

교수님은 "메모장에 입력한 글이 파일로 저장되기까지 어떤 일이 일어나는가?"라는 면접 질문을 예시로 들며 파일 시스템의 중요성을 강조했습니다. 이 질문에 답하기 위해서는 파일 시스템(NTFS, ext4 등), 블록킹/논블록킹 I/O, 가상 메모리 등 운영체제에 대한 깊이 있는 이해가 필요하다고 설명했습니다.

Linux에서 주로 사용하는 파일 시스템은 `ext`(Extended Filesystem) 계열입니다. `ext3`에서 **저널링(journaling)** 기능이 도입되어 시스템 장애 시 로그를 기반으로 파일 시스템을 신속하게 복구할 수 있게 되었고, 현재 널리 쓰이는 `ext4`는 매우 큰 볼륨(최대 1 엑사바이트)과 파일을 지원합니다.

물리 디스크에 생성되는 파일 시스템 외에, 메모리상에서 특수 목적으로 사용되는 **가상 파일 시스템(Virtual Filesystem)**도 있습니다. 시스템의 커널 상태 정보를 보여주는 `/proc`이나 임시 파일을 저장하는 `tmpfs` 등이 이에 해당합니다. `ls -a /tmp` 명령으로 임시 디렉터리의 내용을 확인할 수 있습니다. (실습)

Linux에서는 모든 것을 파일로 취급합니다.

- **일반 파일 (`-`)**: 텍스트, 이미지, 실행 파일 등 데이터를 담고 있는 파일.
- **디렉터리 (`d`)**: 파일들의 목록을 담고 있는 특수한 파일.
- **심볼릭 링크 (`l`)**: 원본 파일을 가리키는 바로 가기 파일.
- **장치 파일 (`b`, `c`)**: `/dev` 디렉터리 안에 있으며, 하드디스크나 터미널 같은 하드웨어 장치를 나타내는 파일. `ls /dev`로 장치 파일 목록을 볼 수 있습니다. (실습)

파일이나 디렉터리의 정보는 `ls -l` 명령으로 확인할 수 있으며, 맨 앞의 숫자는 **아이노드 번호**입니다. `ls -i` 또는 `ls -il` 명령을 사용하면 아이노드 번호를 명시적으로 볼 수 있습니다. (실습)

`ls -l`의 출력 결과에서 `drwxr-xr-x`와 같은 부분은 접근 권한을 의미합니다. 이는 세 부분으로 나뉩니다.

1. **소유자 (User)**: `rwx` (읽기, 쓰기, 실행 가능)
2. **그룹 (Group)**: `r-x` (읽기, 실행 가능)
3. **그 외 (Others)**: `r-x` (읽기, 실행 가능)

각 권한은 숫자로도 표현할 수 있습니다: `r`(4), `w`(2), `x`(1). 따라서 `rwx`는 7, `r-x`는 5, `rw-`는 6이 됩니다. `rwxr-xr-x`는 `755` 권한이 됩니다. 이를 통해 특정 파일에 대한 사용자별 접근을 세밀하게 제어할 수 있습니다.

Linux의 최상위 디렉터리는 루트(`/`)이며, `cd /`와 `ls -al`을 통해 주요 시스템 디렉터리를 볼 수 있습니다. (실습) 사용자들의 개인 공간은 `/home` 디렉터리 아래에 각자의 계정명으로 생성됩니다. (실습) 서버 관리자는 이 위치에 새 사용자 계정을 추가하고, 사용자는 접속 후 `passwd` 명령으로 자신의 비밀번호를 변경하여 시스템을 사용하게 됩니다.

## 2025-09-19, 2교시 — 개념

### 한 줄 요약

리눅스 파일 시스템의 핵심 구성 요소인 아이노드(Inode)와 데이터 블록의 구조를 이해하고, 파일 종류와 `rwx` 권한 체계를 학습합니다.

### 핵심 TL;DR

- **파일 시스템(Filesystem)**: 디스크에 파일을 어떻게 저장하고 관리할지에 대한 규칙과 구조이며, Windows의 NTFS, Linux의 `ext4` 등이 있습니다.
- **물리적 디스크와 논리적 파티션**: 하나의 물리적 하드디스크는 C:, D: 와 같은 여러 개의 논리적 파티션으로 나눌 수 있으며, 각 파티션마다 파일 시스템을 독립적으로 포맷할 수 있습니다.
- **Linux FS 3요소**: 파일 시스템은 ①전체 정보 요약본인 **슈퍼블록**, ②파일의 메타데이터 목록인 **아이노드 테이블**, ③실제 데이터가 담긴 **데이터 블록**으로 구성됩니다.
- **아이노드(Inode)**: 파일의 속성(권한, 소유자, 크기, 시간, 데이터 블록 주소)을 담은 '주민등록증'과 같습니다. 단, **파일 이름은 아이노드에 포함되지 않습니다.**
- **디렉터리 파일**: 디렉터리 역시 특수한 파일이며, 그 내용물은 '파일명-아이노드 번호'의 목록입니다.
- **"모든 것은 파일이다"**: Linux에서는 일반 데이터 파일(`-`)뿐만 아니라 디렉터리(`d`), 바로 가기(`l`), 하드웨어 장치(`b`, `c`) 등 모든 것을 파일로 취급합니다.
- **파일 권한 (`rwx`)**: 파일 접근 권한은 **소유자(User), 그룹(Group), 그 외(Other)** 세 종류의 사용자에 대해 **읽기(r), 쓰기(w), 실행(x)** 권한으로 정의됩니다.
- **8진수 권한 표기**: `r=4`, `w=2`, `x=1`의 값을 합산하여 권한을 숫자로 표현합니다. 예를 들어, `rwxr-xr-x`는 `755`가 됩니다.
- **저널링(Journaling)**: `ext3`부터 도입된 기능으로, 파일 시스템 변경 이력을 기록하여 시스템 장애 시 빠르고 안정적인 복구를 지원합니다.

### 표현 = 표준 용어

- **Filesystem**: 파일을 디스크에 어떻게 구성하고 관리할지에 대한 체계. (예: `ext4`, NTFS, FAT32)
- **Inode (Index Node)**: 파일의 메타데이터(권한, 소유자, 크기, 데이터 블록 주소 등)를 담고 있는 고유한 데이터 구조.
- **Superblock**: 파일 시스템 전체의 상태와 정보를 담고 있는 블록.
- **Data Block**: 파일의 실제 내용이 저장되는 디스크 상의 기본 단위 공간.
- **Journaling**: 파일 시스템 변경 사항을 로그에 기록하여 데이터 일관성을 유지하고 복구 속도를 높이는 기능.
- **Permissions (`rwx`)**: 파일에 대한 읽기(Read), 쓰기(Write), 실행(Execute) 권한.
- **Symbolic Link (`symlink`)**: 원본 파일이나 디렉터리를 가리키는 바로 가기 형태의 특수 파일.

### 정석 보강 (canon-std)

아이노드(Inode)의 역할과 구조

아이노드는 파일 시스템 객체(파일, 디렉터리)를 설명하는 핵심 데이터 구조입니다. 파일명과 실제 데이터를 제외한 모든 메타데이터를 저장하며, 각 파일은 고유한 아이노드 번호를 가집니다. 디렉터리는 '파일명'과 '아이노드 번호'를 매핑하는 테이블 역할을 하는 특수 파일입니다. 사용자가 rm 명령으로 파일을 삭제하면 실제로는 디렉터리에서 파일명 엔트리가 제거되고 아이노드의 링크 카운트가 1 감소하며, 이 카운트가 0이 될 때 비로소 아이노드와 관련 데이터 블록이 해제됩니다.

### 실수·함정

1. 파일 이름이 아이노드(Inode) 내부에 저장된다고 오해하는 것 (이름은 디렉터리 파일에 저장됨).
2. 파일과 디렉터리에 부여된 `x`(실행) 권한의 의미를 혼동하는 것 (파일의 `x`는 실행, 디렉터리의 `x`는 접근/진입 허용).
3. 보안상 위험에도 불구하고 편의를 위해 파일 권한을 `777`로 설정하는 습관.
4. `ls -l` 출력에서 첫 글자인 파일 종류(`-`, `d`, `l` 등)의 의미를 간과하는 것.
5. `/proc`, `/dev` 와 같은 가상 파일 시스템의 파일들을 일반 파일처럼 임의로 수정하려 시도하는 것.
	- 참고로 `/proc`, `/dev`이건 명령어가 아니라 절대경로
6. 심볼릭 링크(`l`) 원본이 삭제되었을 때, 링크 파일이 깨진 상태(broken link)로 남는 것을 인지하지 못하는 것.

## 2025-09-19, 2교시 — 질문

**[Q1] Linux 파일 시스템을 구성하는 세 가지 핵심 요소는 무엇이며, 각 요소는 어떤 역할을 담당하나요? | 태그: 파일시스템/마운트**

- **모범답(강의 기준)**: **슈퍼블록(Superblock)**, **아이노드(Inode)**, **데이터 블록(Data Block)**입니다. 슈퍼블록은 파일 시스템 전체의 요약 정보, 아이노드는 개별 파일의 속성 정보(메타데이터), 데이터 블록은 실제 파일 내용을 저장합니다.
- **정석체크(면접 30초)**: 이 세 구성요소는 디스크를 구조화하는 기본 틀입니다. 슈퍼블록 손상은 파일 시스템 마운트 실패로 이어질 수 있고, 아이노드는 파일의 존재를 증명하며, 데이터 블록은 파일의 실체입니다. 파일명은 아이노드가 아닌, 해당 파일이 속한 디렉터리 파일의 데이터 블록에 저장됩니다.

**[Q2] 파일의 '신분증'이라 불리는 아이노드(Inode)에는 어떤 정보가 저장되며, 반대로 저장되지 **않는** 핵심 정보는 무엇인가요? | 태그: 파일시스템/마운트**

- **모범답(강의 기준)**: 파일 종류, 권한, 소유자, 크기, 시간 정보, 그리고 실제 데이터가 저장된 데이터 블록의 주소가 저장됩니다. 가장 중요한 것은 **파일의 이름**은 아이노드에 저장되지 않는다는 점입니다.
- **정석체크(면접 30초)**: 파일명은 해당 파일이 속한 디렉터리 파일의 내용에 '파일명-아이노드 번호' 쌍으로 저장됩니다. 이 분리 구조 덕분에 하나의 파일(하나의 아이노드)이 여러 이름(하드 링크)을 가질 수 있으며, 파일 이동(`mv`) 시 데이터 블록을 직접 옮기지 않고 디렉터리 엔트리만 수정하여 매우 빠르게 처리됩니다.

**[Q3] `ls -l` 결과에 나오는 `rwxr-xr-x`와 같은 권한은 어떻게 해석하며, 이를 `755` 같은 숫자로 변환하는 원리는 무엇인가요? | 태그: 권한/UMASK/특수비트**

- **모범답(강의 기준)**: `rwx`는 각각 읽기(read), 쓰기(write), 실행(execute) 권한이며, 순서대로 **소유자, 그룹, 그 외 사용자**의 권한을 나타냅니다. `r=4`, `w=2`, `x=1` 값을 더하여 숫자로 표현하므로 `rwx`는 7, `r-x`는 5가 되어 `755`로 변환됩니다.
- **정석체크(면접 30초)**: 이 9비트 권한 모드는 Unix 계열 시스템의 핵심 보안 기능입니다. 특히 디렉터리의 경우 `x` 권한은 해당 디렉터리로 접근(진입)할 권한을 의미하며, `r` 권한은 디렉터리 내 파일 목록을 읽을 권한을 뜻합니다. 따라서 디렉터리에 `x` 권한이 없으면 `r` 권한이 있어도 내용물을 볼 수 없습니다.

**[Q4] (면접 질문) "메모장에 입력한 글이 파일로 저장되기까지 컴퓨터 내부에서는 어떤 일이 일어나나요?"라는 질문의 핵심 답변 요소는 무엇인가요? | 태그: 파일시스템/마운트**

- **모범답(강의 기준)**: 이 질문은 파일 시스템(NTFS, `ext4`)의 동작 원리, 블록킹/논블록킹 I/O, 가상 메모리 등 운영체제의 종합적인 지식을 요구합니다. 사용자의 입력이 메모리에 기록되고, 저장 명령 시 파일 시스템 API를 통해 아이노드와 데이터 블록이 할당되어 디스크에 기록되는 과정을 설명해야 합니다.
- **정석체크(면접 30초)**: 좋은 답변은 사용자 공간(애플리케이션)에서 커널 공간으로 시스템 호출(system call, 예: `write()`)이 일어나는 과정을 포함해야 합니다. 커널은 파일 시스템 드라이버를 통해 빈 데이터 블록을 찾고 사용자 데이터를 버퍼 캐시를 거쳐 디스크에 씁니다. 마지막으로 파일명과 아이노드 번호를 디렉터리 파일에 기록하여 작업을 완료합니다.

## **2025-09-19, 3교시 — 개선본**

### Linux의 디렉터리 구조는 최상위인 루트 디렉터리(`/`)부터 시작합니다. 주요 디렉터리는 다음과 같습니다.

- `/boot`: 부팅에 필요한 커널 파일
- `/etc`: 시스템의 각종 설정 파일
- `/dev`: 키보드, 디스크 등 장치를 나타내는 특수 파일
- `/home`: 일반 사용자들의 홈 디렉터리가 생성되는 공간
- `/root`: `root` 관리자 계정의 전용 홈 디렉터리 (일반 사용자의 홈 디렉터리가 있는 `/home`과는 다름)
- `/usr`: 사용자들이 사용하는 대부분의 명령어와 라이브러리, 문서 등이 위치
- `/tmp`: 임시 파일 저장 공간

### 경로를 표현하는 방식에는 **절대 경로**와 **상대 경로**, 두 가지가 있습니다.

- **절대 경로 (Absolute Path)**: 항상 루트 디렉터리(`/`)에서 시작하여 목표 지점까지의 전체 경로를 명시합니다. (예: `/home/user/Documents`)
- **상대 경로 (Relative Path)**: 현재 작업 중인 디렉터리를 기준으로 목표의 위치를 표현합니다. `.`(현재 디렉터리)과 `..`(상위 디렉터리) 기호를 사용합니다. (예: 현재 위치가 `/home/user`일 때 `cd Documents`)

경로 이동 및 확인에 사용되는 기본 명령어는 다음과 같습니다.

- `pwd` (Print Working Directory): 현재 작업 중인 디렉터리의 위치를 절대 경로로 보여줍니다. (실습)
- `cd` (Change Directory): 디렉터리를 이동하는 명령어입니다.
    - `cd`만 입력하면 어느 위치에 있든 현재 사용자의 홈 디렉터리(`~`)로 즉시 이동합니다. (실습)
    - `cd ..`는 상위 디렉터리로 이동하며, `cd ../..`처럼 연달아 사용하여 여러 단계 위로 이동할 수 있습니다. (실습)

디렉터리의 내용을 확인하는 `ls` 명령어에는 다양한 옵션이 있습니다. 옵션의 순서는 관계없으며 `-alF`처럼 붙여 쓸 수 있습니다.

- `-a` (all): `.`으로 시작하는 숨김 파일을 포함한 모든 파일을 보여줍니다.
- `-l` (long): 파일의 종류, 권한, 소유자, 크기, 수정 시간 등 상세 정보를 보여줍니다.
- `-F` (classify): 파일 종류에 따라 이름 뒤에 기호(`/`: 디렉터리, `*`: 실행 파일, `@`: 심볼릭 링크)를 붙여줍니다.
- `-R` (recursive): 현재 디렉터리뿐만 아니라 모든 하위 디렉터리의 내용까지 재귀적으로 보여줍니다. `ls -R`을 실행해 보세요. (실습)

ls -l 명령의 출력 형식은 다음과 같습니다.

\[파일종류]\[권한] \[링크수] \[소유자] \[그룹] \[크기] \[수정시간] \[파일명]

- **파일 종류**: `-`(일반 파일), `d`(디렉터리), `l`(심볼릭 링크) 등으로 표시됩니다.

디렉터리를 생성하고 삭제하는 명령어는 `mkdir`과 `rmdir`입니다.

- `mkdir [디렉터리명]`: 새로운 디렉터리를 생성합니다. `mkdir d1 d2`처럼 공백으로 구분하여 여러 개를 동시에 만들 수 있습니다. (실습)
- `mkdir -p [경로]`: 중간 경로의 디렉터리가 존재하지 않아도 자동으로 생성하며 하위 디렉터리까지 한 번에 만듭니다. `mkdir -p TMP/mid/work`를 실행해 보세요. (실습)
- `rmdir [디렉터리명]`: **비어 있는** 디렉터리만 삭제할 수 있습니다. 내용물이 있는 디렉터리를 `rmdir`로 삭제하려고 하면 오류가 발생합니다. (실습)

Linux는 강력한 권한 관리 시스템을 가지고 있습니다. 일반 사용자는 자신의 홈 디렉터리(`~`) 내에서만 파일을 생성하거나 삭제할 수 있는 권한을 가집니다. 상위 디렉터리인 `/home`이나 다른 시스템 디렉터리에서 `mkdir` 명령을 실행하면 'Permission denied' 오류가 발생하는데, 이는 해당 공간의 소유자가 `root`이기 때문입니다. (실습) 사용자가 디렉터리를 생성하면 기본적으로 `755` (`rwxr-xr-x`) 권한이 부여되어, 소유자는 모든 작업을 할 수 있지만 다른 사용자들은 읽고 접근만 가능하도록 설정됩니다.

## **2025-09-19, 3교시 — 개념**

### 한 줄 요약

리눅스의 디렉터리 구조와 절대/상대 경로를 이해하고, `cd`, `ls`, `mkdir`, `rmdir` 등 파일 시스템 탐색 및 관리 핵심 명령어를 학습합니다.

### 핵심 TL;DR

- **경로 구분**: 경로 표현에는 루트(`/`)에서 시작하는 **절대 경로**와 현재 위치(`.` `..`) 기준의 **상대 경로**가 있습니다.
- **루트 디렉터리 구분**: 시스템의 최상위인 루트 디렉터리(`/`)와 `root` 사용자의 홈 디렉터리인 `/root`는 다른 공간입니다.
- **`pwd`**: `Print Working Directory`의 약자로, 현재 작업 위치를 **절대 경로**로 보여줍니다.
- **`cd` 단축키**: `cd` 명령어만 입력하면 현재 위치와 상관없이 즉시 자신의 홈 디렉터리(`~`)로 이동하는 매우 유용한 기능입니다.
- **`ls` 주요 옵션**: `-a`(전체), `-l`(상세), `-F`(종류 표시), `-R`(하위 포함) 등 옵션을 조합하여(`ls -alF`) 원하는 정보를 효율적으로 얻을 수 있습니다.
- **`mkdir -p`**: `-p` (parents) 옵션은 여러 단계의 하위 디렉터리를 한 번에 생성해야 할 때 중간 디렉터리까지 자동으로 만들어주는 강력한 기능입니다.
- **`rmdir`의 제약**: `Remove Directory` 명령어는 **내용이 비어 있는 디렉터리만** 삭제할 수 있습니다.
- **권한의 실제**: 사용자는 자신의 홈 디렉터리(`~`) 내에서만 자유롭게 파일을 생성/수정/삭제할 수 있으며, 그 외 시스템 영역에서는 'Permission denied' 오류를 마주하게 됩니다.
- **대소문자 구분**: Linux는 대소문자를 엄격하게 구분하므로 `file.txt`와 `File.txt`는 완전히 다른 파일로 취급됩니다.

### 표현 = 표준 용어

- **Absolute Path (절대 경로)**: 파일 시스템의 루트(`/`) 디렉터리부터 시작하는 완전한 경로.
- **Relative Path (상대 경로)**: 현재 작업 디렉터리를 기준으로 `.`(현재)와 `..`(상위)를 이용해 표현하는 경로.
- **`pwd` (Print Working Directory)**: 현재 작업 중인 디렉터리 경로를 출력하는 명령어.
- **`mkdir` (Make Directory)**: 새 디렉터리를 생성하는 명령어.
- **`rmdir` (Remove Directory)**: 비어 있는 디렉터리를 삭제하는 명령어.
- **Recursive (`-R`)**: 특정 작업을 해당 디렉터리뿐만 아니라 모든 하위 디렉터리에 대해 반복적으로 수행하는 옵션.
- **Case-Sensitive (대소문자 구분)**: `FileA`와 `filea`를 서로 다른 파일로 인식하는 시스템의 특성.

### 정석 보강 (canon-std)

절대 경로와 상대 경로의 사용

절대 경로는 시스템의 루트(/)부터 시작하는 고유한 주소이므로, 스크립트나 시스템 설정 파일처럼 실행 위치에 관계없이 항상 동일한 대상을 참조해야 할 때 필수적입니다. 반면 상대 경로는 현재 위치를 기준으로 간결하게 경로를 지정할 수 있어, 터미널에서 대화형으로 작업할 때의 생산성을 크게 높여줍니다. 이 두 가지를 상황에 맞게 사용하는 것이 효율적인 CLI(Command-Line Interface) 활용의 핵심입니다.

### 실수·함정

1. 절대 경로를 입력할 때 맨 앞의 `/`를 빠뜨려 상대 경로로 오인되는 경우.
2. 내용물이 있는 디렉터리를 `rmdir`로 삭제하려다 'Directory not empty' 오류를 만나는 것.
3. 자신의 홈 디렉터리(`~`)가 아닌 곳에서 `mkdir`를 시도하고 'Permission denied' 오류에 당황하는 것.
4. `cd`만 입력하면 홈으로 가는 단축키를 모르고 항상 `cd /home/username`처럼 전체 경로를 입력하는 습관.
5. 대소문자를 구분하지 않는 Windows 환경의 습관으로 파일명을 잘못 입력하는 경우.
6. `mkdir -p a/b/c`의 편리함을 모르고 `mkdir a`, `cd a`, `mkdir b`... 순으로 여러 번 명령을 실행하는 것.

**[Q1] `cd /etc`와 `cd etc` 명령어는 어떻게 다르게 동작하며, 각각 어떤 종류의 경로 지정 방식에 해당하나요? | 태그: 파일·디렉터리**

- **정석체크(면접 30초)**: 절대 경로는 항상 `/`로 시작하여 경로의 유일성을 보장하므로 스크립트 등에서 안정적입니다. 상대 경로는 현재 위치를 기준으로 하므로 대화형 셸 환경에서 타이핑을 줄여주지만, 실행 위치에 따라 결과가 달라질 수 있어 주의가 필요합니다. 이 둘을 구분하는 것은 CLI의 가장 기본적인 규칙입니다.

- **모범답(강의 기준)**: `cd`를 아무런 인자 없이 입력하고 엔터를 치면, 현재 위치가 어디든 즉시 사용자의 홈 디렉터리(`~`)로 이동합니다.
- **정석체크(면접 30초)**: 이 기능은 셸에 내장된 편의 기능으로, `cd` 명령어에 인자가 없을 경우 환경 변수 `$HOME`에 지정된 경로로 이동하도록 설정되어 있기 때문입니다. 이는 복잡한 경로를 `cd ../../..` 등으로 거슬러 올라가거나 `cd /home/username` 전체를 입력할 필요를 없애 작업 효율을 크게 높여줍니다.

**[Q3] 디렉터리 생성/삭제 시 `mkdir -p` 옵션과 `rmdir` 명령어의 핵심 규칙은 무엇인가요? | 태그: 파일·디렉터리**

- **모범답(강의 기준)**: `mkdir -p a/b/c`는 최종 목표(`c`)뿐만 아니라 존재하지 않는 중간 경로(`a`, `b`)까지 자동으로 함께 생성해줍니다. `rmdir`은 안전을 위해 **비어 있는 디렉터리만** 삭제하도록 설계되었습니다.
- **정석체크(면접 30초)**: `mkdir -p`는 스크립트 등에서 필요한 경로를 확실하게 생성할 때 유용합니다. 내용물이 있는 디렉터리를 삭제하려면 `rm -r` (recursive) 명령어를 사용해야 하지만, 이 명령어는 매우 강력하고 복구가 불가능하므로 사용에 각별한 주의가 필요합니다. `rmdir`의 제약은 사용자의 실수를 방지하는 중요한 안전장치 역할을 합니다.

**[Q4] 왜 내 홈 디렉터리(`~`) 안에서는 `mkdir`가 잘 되는데, 한 단계 위인 `/home`에서는 'Permission denied' 오류가 발생하나요? | 태그: 권한/UMASK/특수비트**

- **모범답(강의 기준)**: Linux 시스템에서 일반 사용자는 기본적으로 자신의 홈 디렉터리 내부에서만 파일을 쓰고 수정할 권한을 가집니다. `/home` 디렉터리는 `root` 사용자가 소유하고 관리하므로, 일반 사용자가 그곳에 디렉터리를 만들 권한이 없기 때문입니다.
- **정석체크(면접 30초)**: 이는 파일 시스템의 소유권(ownership)과 권한(permission) 모델 때문입니다. 모든 파일과 디렉터리에는 소유자가 있으며, `ls -l`로 확인 시 `w`(write) 권한이 해당 사용자에게 부여되어 있어야만 내용 변경이 가능합니다. 이러한 엄격한 권한 관리는 다중 사용자 환경에서 시스템의 안정성과 보안을 유지하는 핵심 요소입니다.
