## 정리

병행: 일과 육아를 병행하다

병렬: 나란히 서 있는 줄

### 1) 부족 포인트 스캔

- **동시성(Concurrency)과 병렬성(Parallelism) 개념 혼동**: 두 용어가 모두 '동시에 처리된다'는 뉘앙스를 가지지만, 사용하는 **하드웨어 자원(CPU 코어)**의 차이로 인해 구분된다는 점을 놓치고 있습니다.
- **처리 시간과 실행 순간의 차이 불이해**: 병행은 시간의 '느낌'을, 병렬은 시간의 '실제 순간'을 다룬다는 점을 구분하지 못하고 있습니다.

---

### 2) 핵심 개념 요약

- **병렬성 (Parallelism)**: **두 개 이상의 작업을 실제로 동시에 실행**하는 것을 의미합니다.
    - **정의**: 작업을 **물리적으로 동시 실행**하여 처리 속도를 높입니다.
    - **핵심**: 반드시 **멀티 코어(Multi-core) CPU** 환경이 필요합니다. 각 코어가 서로 다른 작업을 동시에 처리합니다.
- **병행성 (Concurrency)**: **단일 코어(Single-core) 환경에서도** 여러 작업이 동시에 진행되는 것처럼 보이게 만드는 것을 의미합니다.
    - **정의**: CPU 코어가 아주 짧은 시간 간격으로 여러 작업을 **번갈아 가며(Interleaving)** 처리합니다.
    - **핵심**: **시분할(Time-sharing)** 또는 **문맥 교환(Context Switching)** 기술을 사용합니다. 사용자는 동시에 실행되는 것처럼 느낍니다.

---

### 3) 용어 매핑

- **'병렬' = '물리적 동시성'**: 한 순간에 두 가지 작업이 실제로 진행되는 상태입니다. (실제 동시에 실행)
- **'병행' = '논리적 동시성'**: 짧은 시간 동안 여러 작업을 번갈아 실행하여 동시에 진행되는 것처럼 보이는 상태입니다. (동시 실행처럼 보임)

---

### 4) 사고 틀 & 판단 기준

1. **자원 기반 판단**:
    
    - **CPU 코어 개수**: 작업이 **1개의 코어**에서 처리되는가? → **병행**
    - **CPU 코어 개수**: 작업이 **2개 이상의 코어**에서 처리되는가? → **병렬**
        
2. **실행 순간 판단**:
    
    - **시간 t**에서 작업 A와 B가 **모두 실행 중**인가? → **병렬**
    - **시간 t**에서 작업 A만 실행되고, **시간 t+dt**에서 작업 B가 실행되는가? → **병행**
        
3. **목표 판단**:
    
    - 목표가 **처리량(Throughput)** 극대화인가? → **병렬** (더 많은 작업을 더 빠르게 완료)
    - 목표가 **응답성(Responsiveness)** 향상인가? → **병행** (사용자가 지연을 느끼지 않게 함)

---

### 5) 체크 질문(자가 점검)

- 싱글 코어 CPU 환경에서는 **병렬** 처리가 가능한가요?
- **문맥 교환(Context Switching)**은 **병렬** 처리에 필수적인 요소인가요?
- 작업 A와 B가 동시에 시작하여 동시에 끝났다면, 이는 반드시 **병렬** 처리의 결과인가요?
- 웹 브라우저가 여러 탭에서 작업을 진행할 때, 이는 주로 **병렬**성인가요, **병행**성인가요? (힌트: 사용자 경험)
