## 📝 정리

 JPA 엔티티에서 기본 생성자의 접근 제어자를 `protected`로 설정하는 이유 중 “프록시(Proxy) 생성과 상속”에 관련된 메커니즘을 상세히 설명해 드리겠습니다.

---

### 1. 지연 로딩(Lazy Loading)과 프록시의 필요성

연관 관계가 있는 객체(예: 주문과 회원)를 조회할 때, 당장 사용하지 않는 데이터까지 한 번에 DB에서 긁어오면 심각한 성능 저하가 발생합니다.

* 이를 해결하기 위해 JPA는 실제 DB 조회를 실제로 해당 객체의 데이터를 사용하는 시점까지 미룹니다. 이를 **지연 로딩**이라고 합니다.
* 하지만 자바 변수에는 어떤 형태로든 참조 객체가 들어가 있어야 `null` 예외가 발생하지 않습니다.
* 따라서 JPA(하이버네이트)는 실제 엔티티 대신 껍데기 역할을 하는 가짜 객체, 즉 ‘프록시(Proxy)’를 먼저 넣어둡니다.

---

### 2. 하이버네이트는 프록시를 어떻게 만들까? (CGLIB 바이트코드 조작)

하이버네이트는 런타임에 **CGLIB(Code Generation Library)** 같은 바이트코드 조작 라이브러리를 사용해 프록시 클래스를 동적으로 생성합니다.

이때 프록시 객체는 기존 원본 엔티티를 상속(extends)받아 만들어집니다.

```java
// 하이버네이트가 런타임에 동적으로 만들어내는 가짜 프록시 클래스의 개념적 구조
public class Item$HibernateProxy$abc123 extends Item {
    
    private Item target = null; // 실제 엔티티를 가리킬 참조

    public Item$HibernateProxy$abc123() {
        super(); // ★ 핵심: 부모 클래스(Item)의 기본 생성자를 호출해야 함!
    }

    @Override
    public String getName() {
        if (this.target == null) {
            // 실제 DB를 조회해서 진짜 Item 객체를 가져옴 (프록시 초기화)
            this.target = fetchFromDb(); 
        }
        return this.target.getName();
    }
}

```

---

### 3. 자바 언어의 상속 규칙과 `protected`의 역할

자바 문법상 자식 클래스의 인스턴스를 생성할 때는 **반드시 부모 클래스의 생성자가 먼저 호출**되어야 합니다.

* 생성자에서 `super(…)`를 명시하지 않으면 컴파일러는 부모의 기본 생성자인 `super()`를 자동으로 호출합니다.
* 만약 원본 엔티티 클래스인 `Item`의 기본 생성자를 `private`으로 지정해 버리면:
* `Item` **외부에서 생성된** 자식 클래스(`Item$HibernateProxy…`)는 부모의 `private` 생성자에 접근할 수 없습니다.
* 결과적으로 상속 구조를 갖는 프록시 객체 자체를 인스턴스화할 수 없어 런타임 에러가 발생합니다.
* 따라서 동적으로 생성되는 자식 프록시 클래스가 부모의 기본 생성자를 호출할 수 있도록 최소 **`protected`** (또는 `package-private`) 이상의 가시성을 열어두어야 합니다.

---

### 4. 왜 `public`이 아니라 하필 `protected`일까?

* **`public`으로 열어둘 경우:**
외부 비즈니스 코드(서비스나 컨트롤러) 어디에서든 `new Item()`처럼 필드 값(`name`, `quantity` 등)이 채워지지 않은 **불완전하고 빈 객체를 무분별하게 생성**할 수 있게 됩니다. 이는 객체의 무결성을 해치는 원인이 됩니다.
* **`protected`로 제한할 경우:**
* 상속받은 프록시 객체와 동일 패키지 내부에서는 접근이 가능하므로 JPA의 동작 요구 조건을 충족합니다.
* 반면 일반적인 외부 패키지의 비즈니스 로직에서는 `new Item()` 호출이 컴파일 시점에 차단되므로, 유효한 데이터가 필수인 생성자(`public Item(String name, Integer quantity)`)만 강제하여 안전한 코드를 유지할 수 있습니다.
