===하단이 맘에 안들어 하단부터 재구조화해서 재정리해줘==

`printf("Mode: %o\n", (unsigned int)statbuf.st_mode);` 코드는 단순한 출력이 아니라 데이터 왜곡을 막기 위한 **기술적 안전장치**입니다.

### ① 8진수 포맷($\%o$)과 3비트 단위 매핑

- 리눅스 권한은 `r`, `w`, `x` 3비트 단위로 작동합니다.
- 8진수($2^3 = 8$) 한 자리는 정확히 이 3비트 뭉치 하나와 일대일 대응하므로, 10진수보다 권한 상태를 훨씬 직관적으로 확인할 수 있습니다.
- 그래서 `printf`의 `%o` 서식 지정자를 사용하여 정수 데이터를 8진수 문자열로 출력합니다.

### ② 부호 확장(Sign Extension) 방지

- **현상:** 일반 파일(`S_IFREG`)을 식별하는 비트는 최상위 비트(MSB)가 `1`입니다.
- **위험:** 이를 부호 있는 정수(`signed int`)로 취급하여 비트 수가 더 큰 자료형으로 확장할 경우, CPU는 최상위 비트 `1`을 음수 부호로 오해하여 앞부분을 모두 `1`로 채워버립니다.
- **결과:** 원래 `100644`가 나와야 할 자리에 `ffff…`로 시작하는 쓰레기 값이 출력됩니다.
    

### ③ 제로 확장(Zero Extension)을 통한 무결성 확보
- `st_mode`의 실제 타입인 `mode_t`는 시스템마다 크기(16비트, 32비트 등)가 다르기 때문에 데이터가 큰 단위로 옮겨질 때 **데이터 오염(부호 확장)**이 일어날 위험이 있는데, 이를 **`unsigned int` 캐스팅**을 통해 **제로 확장**으로 강제함으로써 원본 비트 값을 안전하게 지켜내는 것입니다
- 제로 확장: 비트 확장 시 부호와 상관없이 앞부분을 무조건 `0`으로 채운다.

### 2. 파일 종류 판별: 비트 연산 vs 매크로

`st_mode`의 상위 4비트에는 파일의 종류가 기록되어 있습니다 이 데이터만 분리해내기 위한 방법으론 가독성을 위해 **매크로 사용**이 권장됩니다.

- **비트 마스크 방식:** `st_mode` 값과 `S_IFMT`(8진수 0170000)를 비트 AND(`&`) 연산하면 파일 종류를 나타내는 비트만 남습니다. 이 결과값을 미리 정의된 파일 타입 상수들과 비교합니다.
	- `S_IFREG`: 일반 파일 (Regular File)
	- `S_IFDIR`: 디렉터리 (Directory)
	- `S_IFLNK`: 심볼릭 링크 (Symbolic Link)
	- `S_IFCHR`: 문자 장치 (Character Device)
    - 예: `(mode & S_IFMT) == S_IFDIR` (디렉터리인가?)
- **매크로 함수 방식:** 내부적으론 비트 마스크연산을 수행하지만, 사용자에게는 `true(1)` 또는 `false(0)`의 불리언 값을 반환하는 함수 형태로 제공됩니다.
	- `S_ISREG(m)`: 일반 파일 여부 반환
	- `S_ISDIR(m)`: 디렉터리 여부 반환
	- `S_ISLNK(m)`: 심볼릭 링크 여부 반환
	- `S_ISCHR(m)`: 문자 장치 파일 여부 반환
```C
// 1. 매크로 함수를 사용한 직관적인 방식
if (S_ISREG(statbuf.st_mode)) 
    printf("Regular File\n");

// 2. 매크로 내부의 실제 비트 마스크 연산 방식 (동일한 동작)
if ((statbuf.st_mode & S_IFMT) == S_IFREG) 
    printf("Regular File\n");
```

### 3. 접근 권한(rwx) 추출 및 문자열 변환

파일의 접근 권한은 `st_mode`의 **하위 9비트**에 기록되어 있습니다. 이는 다시 **소유자(User), 그룹(Group), 기타 사용자(Others)**의 3비트씩 세 그룹으로 나뉩니다.

#### 1. 개별 권한 비트 검사 (Bitwise AND)

특정 권한이 활성화되어 있는지 확인하려면 시스템 정의 상수와 비트 AND(`&`) 연산을 수행합니다. 연산 결과가 **0이 아니면** 해당 권한이 있는 것으로 판단합니다.

- **소유자(User):** `S_IRUSR`(읽기), `S_IWUSR`(쓰기), `S_IXUSR`(실행)
- **그룹(Group):** `S_IRGRP`(읽기), `S_IWGRP`(쓰기), `S_IXGRP`(실행)
- **기타(Others):** `S_IROTH`(읽기), `S_IWOTH`(쓰기), `S_IXOTH`(실행)

#### 2. 기호(Symbolic) 문자열 변환 로직

각 비트의 위치를 순차적으로 검사하여, 권한이 있으면 해당 문자(`r`, `w`, `x`)를, 없으면 하이픈(`-`)을 배열에 채워 넣습니다.

- **변환 순서:** 파일 종류(1자) + 소유자 권한(3자) + 그룹 권한(3자) + 기타 권한(3자) = **총 10자**


    ```c
    char res[11];
    res[0] = S_ISDIR(mode) ? 'd' : '-';
    res[1] = (mode & S_IRUSR) ? 'r' : '-';
    res[2] = (mode & S_IWUSR) ? 'w' : '-';
    // … 이런 방식으로 9비트를 모두 체크
    ```

### 4. 사용자 정보 및 시간의 시각화

숫자로 된 메타데이터를 사람이 읽을 수 있는 텍스트로 바꾸는 과정입니다.

- **ID to Name:** `st_uid`, `st_gid` (숫자) → `getpwuid()`, `getgrgid()` 함수를 통해 문자열로 변환
- **Epoch to String:** `st_mtime` (초 단위) → `localtime()`으로 구조체 변환 후 `strftime()`으로 원하는 날짜 포맷을 만듭니다.

```C
// 1. UID/GID를 문자열 이름으로 변환 (pwd.h, grp.h 사용)
struct passwd *pw = getpwuid(statbuf.st_uid);
printf("Owner Name: %s\n", pw->pw_name);

// 2. Epoch Time을 표준 날짜 형식으로 변환 (time.h 사용)
char time_str[20];
strftime(time_str, 20, "%Y-%m-%d %H:%M", localtime(&statbuf.st_mtime));
printf("Last Modified: %s\n", time_str);
```


> [!TIP]
>
> **왜 8진수인가요?**
>
> 권한은 3비트(r, w, x)씩 끊어서 관리하기 때문입니다. 2진수 3개는 8진수 숫자 1개($2^3 = 8$)와 정확히 일치하므로, `0644` 같은 8진수 표기법이 직관적입니다.
