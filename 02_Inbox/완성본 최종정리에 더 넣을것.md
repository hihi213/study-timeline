# 📂 [System Programming] stat 구조체와 파일 메타데이터 분석

`stat()` 시스템 콜은 하드디스크의 **아이노드(Inode)**에 저장된 파일의 메타데이터를 읽어와 사용자 영역의 **stat 구조체**에 복사하는 과정입니다. 커널이 넘겨주는 0과 1의 **원시 비트(Raw Bits)**를 개발자가 유의미한 정보로 **해석(Interpretation)**하는 것이 핵심입니다.

---

## 1. stat 구조체 핵심 필드 가이드

| **필드명**              | **의미**       | **데이터 타입 (크기)**                   | **구현 로직 및 출력 방식 (서식 지정자)**                                                                                                           |
| -------------------- | ------------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **st_mode**          | 파일 종류 및 권한   | `mode_t`<br>(32 bit이나 16 bit만 사용) | **로직**: 비트 마스크(`&`)로 플래그 추출 후 상수 비교 또는 `S_ISxxx` 매크로 사용.<br><br>**출력**: 부호 확장 방지를 위해 `(unsigned int)` 캐스팅, 가독성을 위해 **`%o`**(8진수)로 출력 |
| **st_size**          | 파일 크기 (Byte) | `off_t`  <br>(64 bit)             | **로직**: 64비트 정수 크기 이므로 `long long` 타입 유지<br><br>**출력**: `(long long)` 캐스팅 후 **`%lld`** 사용.                                           |
| **st_mtime**         | 최종 수정 시간     | `time_t`<br>(64 bit)              | **로직**: `localtime()`으로 구조체 분해 후 `strftime()`으로 문자열로 변환.<br><br>**출력**: 결과값은 **`%s`**(문자열), 원시 데이터는 **`%lld`** 사용.                   |
| **st_uid** / **gid** | 사용자 / 그룹 ID  | `uid_t` / `gid_t`  <br>(32 bit)   | **로직**: `getpwuid()` 또는 `getgrgid()`로 실제 이름 문자열 치환.<br><br>**출력**: 이름은 **`%s`**, 원시 데이터는 제로 확장을 고려해 **`%u`**(부호 없는 10진수) 사용.         |
| **st_ino**           | 아이노드 번호      | `ino_t`<br>(64 bit)               | **로직**: 파일 시스템 내 고유 식별 번호로 파일 동일성 판별 로직에 활용.<br><br>**출력**: **`%llu`** 또는 **`%lu`**(부호 없는 64비트 정수) 사용.                               |
| **st_nlink**         | 하드 링크 수      | `nlink_t`  <br>(32/64 bit)        | **로직**: 참조 카운트 데이터. `unlink()` 호출 시 이 값이 0이면 데이터 실제 삭제 로직<br><br>**출력**: 시스템 환경에 따라 **`%lu`** 또는 **`%u`** 사용.                        |


## 2. st_mode 비트 필드(16비트) 구조 분석

`st_mode`는 하나의 정수 안에 여러 정보를 밀어 넣은 **비트 집합**입니다.

### 🏗️ 비트 레이아웃

|**비트 범위**|**15 ~ 12**|**11 ~ 9**|**8 ~ 6**|**5 ~ 3**|**2 ~ 0**|
|---|---|---|---|---|---|
|**역할**|**파일 종류**|**특수 권한**|**소유자(U)**|**그룹(G)**|**기타(O)**|
|**상세**|일반, 디렉터리 등|SetUID/GID, Sticky|r w x|r w x|r w x|


- **`mode_t` (16~32 bit):** 8진수로 읽어야 하므로 **`%o`**
- **`off_t` / `time_t` (64 bit):** 8바이트 정수이므로 **`%lld`** (캐스팅 포함)
- **`uid_t` / `gid_t` (32 bit):** 부호 없는 정수이므로 **`%u`**
- **`ino_t` (64 bit):** 고유 번호이므로 보통 **`%lu`** 또는 **`%llu


### 🔍 파일 종류 판별: 비트 마스크 vs 매크로

커널에서 받은 `st_mode`에서 파일 형식을 추출하는 두 가지 방식입니다.

- **A. 비트 마스크 방식:** `$statbuf.st_mode \ \& \ S\_IFMT$` 연산을 통해 하위 12비트를 0으로 지우고 상위 4비트만 남겨 비교합니다.
    - `S_IFMT` (Mask): `1111 0000 0000 0000` (8진수 `0170000`)
- **B. 매크로 함수 방식 (권장):** 가독성이 높고 내부적으로 마스크 연산을 수행하여 `True/False`를 반환합니다.

| **파일 종류** | **비트 마스크 상수**    | **매크로 함수**   | **표시(ls)** |
| --------- | ---------------- | ------------ | ---------- |
| 일반 파일     | `S_IFREG` (1000) | `S_ISREG(m)` | `-`        |
| 디렉터리      | `S_IFDIR` (0100) | `S_ISDIR(m)` | `d`        |
| 심볼릭 링크    | `S_IFLNK` (1010) | `S_ISLNK(m)` | `l`        |
| 문자 장치     | `S_IFCHR` (0001) | `S_ISCHR(m)` | `c`        |

## 3. 권한(rwx) 추출 및 문자열 변환 로직

하위 9비트를 3비트씩 끊어 `ls -l` 형태의 문자열로 만드는 과정입니다.

> **작동 원리:** 특정 위치의 비트가 1인지 확인하기 위해 **비트 AND(&)** 연산을 수행합니다. 결과가 0이 아니면 권한이 있는 것입니다.



```C
char res[11];
mode_t mode = statbuf.st_mode;

// 1. 파일 종류 (삼항 연산자 활용)
res[0] = S_ISDIR(mode) ? 'd' : (S_ISLNK(mode) ? 'l' : '-');

// 2. 접근 권한 (비트 AND 연산 반복)
res[1] = (mode & S_IRUSR) ? 'r' : '-'; // 소유자 읽기
res[2] = (mode & S_IWUSR) ? 'w' : '-'; // 소유자 쓰기
res[3] = (mode & S_IXUSR) ? 'x' : '-'; // 소유자 실행
// … 그룹(GRP), 기타(OTH)도 동일 패턴 적용
res[10] = '\0';
```

## 4. 인간 친화적인 데이터 변환 (ID & 시간)

숫자 형태의 커널 데이터를 텍스트로 치환하여 사용자에게 보여줍니다.

### ① 사용자/그룹 이름 (ID → Name)


커널은 숫자로만 관리하므로 시스템 DB(`/etc/passwd`, `/etc/group`)를 조회해야 합니다.

- **사용자:** `struct passwd *pw = getpwuid(statbuf.st_uid);` → `pw->pw_name`
- **그룹:** `struct group *gr = getgrgid(statbuf.st_gid);` → `gr->gr_name`

### ② 시간 정보 변환 (Epoch → String) 재정리

커널이 제공하는 시간 데이터는 **Epoch Time**(1970년 1월 1일 00:00:00 UTC 이후 흐른 시간)이라는 정수형태의 원시 데이터입니다. 이를 우리가 읽을 수 있는 문자열로 변환하는 과정은 **"규격화 → 분해 → 포맷팅"**의 단계를 거칩니다.

---

#### 1. 데이터 소스별 단위 차이 (가장 중요한 체크포인트)

가장 먼저 확인해야 할 것은 커널에서 가져온 데이터가 **'초'** 단위인지 **'일'** 단위인지입니다.

|**구분**|**소스 데이터 (struct)**|**데이터 단위**|**핵심 변환 로직**|
|---|---|---|---|
|**파일 정보**|`statbuf.st_mtime`|**초 (Seconds)**|변환 없이 즉시 사용 가능|
|**비밀번호 정보**|`spw->sp_lstchg`|**일 (Days)**|**`* 86400`** (24h × 60m × 60s) 연산 필수|

> **Why?** `/etc/shadow`는 저장 공간을 아끼기 위해 시/분/초가 불필요한 날짜 데이터를 '일' 단위로 저장하도록 설계되었습니다. 반면, 파일 시스템(`stat`)은 수정 시점이 초 단위로 정밀해야 하므로 표준 Epoch 초를 사용합니다.

---

#### 2. 공통 시간 처리 파이프라인 (4단계)

단위가 다르더라도 결국 `time_t`(초 단위 정수)로 맞추기만 하면 이후 과정은 모두 동일합니다.

1. **규격화 (Normalize)**: 어떤 출처의 데이터든 **초(Seconds)** 단위인 `time_t` 타입으로 통일합니다.
2. **분해 (Decompose)**: `localtime()` 함수를 사용하여 큰 정수를 년, 월, 일, 시, 분, 초 멤버를 가진 `struct tm` 구조체로 쪼갭니다.
3. **포맷 (Format)**: `strftime()` 함수를 사용하여 구조체 데이터를 사용자가 원하는 문자열 형식(예: `2024-05-20`)으로 치환합니다.
4. **출력 (Output)**: 최종적으로 완성된 버퍼(문자열)를 화면에 출력합니다.
    

---

#### 3. 통합 구현 예시 로직

```C
#include <time.h>
#include <stdio.h>

void print_time_logic(long raw_data, int is_days) {
    time_t seconds;
    struct tm *tm_ptr;
    char buf[20];

    // [1단계] 규격화: 일 단위라면 초 단위로 변환
    if (is_days) seconds = (time_t)raw_data * 86400;
    else         seconds = (time_t)raw_data;

    // [2단계] 분해: 정수 -> 구조체(struct tm)
    tm_ptr = localtime(&seconds);

    // [3단계] 포맷팅: 구조체 -> 문자열
    strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M", tm_ptr);

    // [4단계] 출력
    printf("Result: %s\n", buf);
}
```

---

#### 💡 실무형 요약 (Cheat Sheet)

- **`time_t`**: 64비트 정수 (초 단위).
- **`struct tm`**: 인간이 이해하는 시간 컴포넌트들의 집합.
- **`localtime()`**: "초를 가져가서 구조체로 나눠줄게." (포인터 반환)
- **`strftime()`**: "구조체를 가져가서 이쁘게 그려줄게." (버퍼에 저장)
## 🛠️ 실무 요약 (Summary)

> **커널 데이터 처리 프로세스**
>
> **비트 연산**을 통한 정보 추출 → **시스템 함수**를 통한 의미 부여(치환) → **포맷팅** 출력

- **Tip:** C언어에서 `0755`처럼 숫자 앞에 `0`을 붙이면 **8진수**로 인식되며, 이는 권한 비트를 다룰 때 매우 직관적입니다.
- **주의:** `stat()`은 심볼릭 링크의 대상을, `lstat()`은 링크 자체의 정보를 가져온다는 점을 기억하세요.
