- **RAM과 메모리는 비슷하나 의미하는 바가 다르다:**
	- RAM: 휘발성 하드웨어 장치 그 자체
	- 메모리: 운영체제(OS)는 물리적 RAM 주소가 아닌 '가상 주소'를 통해 관리하는 공간

## 운영체제의 메모리 격리 (통신이 필요한 이유)
> 프로세스 간에는 철저한 메모리 격리가 물리적으로 이루어지기 때문에, 프로세스끼리 통신하기 위해서는 파이프나 파일 시스템 같은 별도의 매개체가 필요합니다.

- 현대 운영체제는 가상 메모리 시스템을 통해 각 프로세스에게 독립된 주소 공간을 부여하고 물리적으로 완전히 격리합니다.
- 이 가상 메모리공간은 보안을 위해 유저공간과 커널영역으로 또 분리됩니다.
- 즉 타 프로세스의 유저영역과 커널영역을 침범할 수 없습니다.
- **fork()의 독립성:** `fork()`로 생성된 자식 프로세스 역시 부모와 동일한 데이터를 복사받지만 **독립된 주소 공간**을 가지므로, 직접 부모의 메모리를 물리적으로 침범할 수 없습니다.

## 하드디스크 파일 시스템 구조

프로세스 간 가상 메모리는 철저히 격리되어 있지만, 하드디스크 파일 시스템은 경로명만 알면 모든 프로세스가 공통으로 접근할 수 있는 '공유 이정표' 역할을 합니다.

- **디렉토리 엔트리 (dentry):** `파일 이름` - `아이노드(inode) 번호` 쌍을 매핑하여 문자열로 저장합니다.
- **아이노드 (inode):** 파일의 속성 정보와 실제 데이터 위치를 가리키는 포인터(데이터 블록 주소)를 저장합니다.
- **데이터 블록 (Data Block):** 하드디스크 상에 실제 파일의 내용(데이터)이 물리적으로 저장되는 공간입니다.

## 3. 리눅스 파이프(Pipe) 기초 메커니즘

파이프는 프로세스 간 데이터를 주고받기 위한 통로 기능을 가진, 특수한 '파일'입니다

- **파일 기술자 (FD) 할당:** `pipe(fd)` 시스템 콜 호출 시 커널 내부에 파이프가 생성되며, 크기가 2인 정수 배열에 FD가 담겨 리턴됩니다.
    - **`fd[0]`:** 읽기(수신) 전용 포트 ➔ 파이프의 **출구**
    - **`fd[1]`:** 쓰기(전송) 전용 포트 ➔ 파이프의 **입구**
- **특수 파일 취급:** 터미널에서 `ls -l` 명령어로 확인 시 파일 유형의 맨 앞 글자가 `p`로 표시됩니다.
- **연속적 바이트 스트림:** 데이터 간의 구분이 없이, 쓰는 대로 연속적으로 흘러가는 스트림(Stream) 방식으로 동작합니다.
- **저수준 I/O 제어:** 파일 시스템 콜인 `read()`와 `write()`를 사용하여 데이터를 송수신합니다.

## 4. 파이프의 2가지 종류: 이름 없는 파이프 vs 이름 있는 파이프

### ① 이름 없는 파이프 (Anonymous Pipe)

- **생성 및 소멸:** 파일 시스템에 등록(이름/경로)되지 않고 커널 RAM에 임시 생성됩니다. 관련 FD가 모두 닫히면 즉시 소멸되는 휘발성을 가집니다.
- **접근 방식:** 이름이 없으므로 오직 프로세스 내부의 주소록인 **FD 테이블 번호**로만 제어할 수 있습니다.
- **통신 범위 (부모-자식 한정):** `fork()`를 통해 FD 테이블을 복사(상속)되기에 자식은 직접적으로 커널 메모리를 침범하지않고, 상속받은 FD를 통해 OS에 합법적인 대리 수행 요청(read/write)을 하여 부모와 통신합니다.

**"모든 프로세스는 격리 정책 때문에 타 프로세스의 커널 영역을 직접 만질 수 없다(자식도 마찬가지). 하지만 자식은 `fork()` 시 부모의 FD 테이블을 복사받기 때문에, 이 열쇠를 매개로 시스템 콜을 호출하여 OS의 중재 하에 커널 RAM 버퍼를 합법적으로 공유할 수 있는 것이다."**

### ② 이름 있는 파이프 (Named Pipe / FIFO)

독립된 프로세스들이 파일 시스템의 동일한 '경로명'을 인자로 `open()`을 요청하여 격리를 우회하고 통신하는 방식입니다. 터미널에서 `ls -F`로 확인 시 파일명 뒤에 기호 `|`가 붙습니다.

#### ① 일반 파일 (Regular File)
> 커널은 파일 타입에 따라 RAM 내부에서 데이터를 다르게 처리합니다.
- 디스크 상의 아이노드 내 **데이터 블록 주소 포인터**에 실제 파일 내용이 저장될 하드디스크의 물리 블록 주소가 저장되어 있습니다.
- 저장흐름: 유저 메모리의 데이터를 커널 RAM(페이지 캐시) 영역에 복사-> 아이노드의 활성화된 **데이터 블록 포인터**를 추적해 하드디스크의 **데이터 블록에 실제 내용을 최종적으로 영구 저장**
#### ② 이름 있는 파이프 (FIFO)
- **포인터의 전환**: 커널은 아이노드 내 파일 타입을 보고 파이프(`p`)임을 확인하면, 디스크 블록 포인터를 비활성화합니다. 그 대신, 커널 RAM 내부에 공간을 마련하고 이를 가리키는 **`i_pipe` 구조체 포인터를 활성화**하여 주소를 저장합니다.
- **실시간 흐름 및 소멸 메커니즘**:
    - 프로세스가 **Write** 호출: 유저 메모리의 데이터가 **`i_pipe`가 가리키는 커널 RAM(파이프 버퍼/링 버퍼) 공간에 복사**되어 기록됩니다.
    - 프로세스가 **Read** 호출: `read()`를 호출하는 즉시 커널 RAM 버퍼에 있던 데이터를 **읽기 요청을 한 프로세스의 유저 메모리로 복사해 준 뒤, 커널 RAM 내부의 해당 데이터는 즉시 지워서 비웁니다.**
- 즉 파이프는 디스크에 최종적으로 영구저장하는 절차가 없습니다
	- 그래서 데이터 블록 주소 포인터에는 NULL이나 0를 저장합니다.
## 5. 파이프 통신 규칙 및 주의사항

### 단방향(Half-Duplex) 통신의 본질

파이프는 데이터를 '누가 썼는지' 송신자를 구별하지 못합니다. 따라서 하나의 파이프로 번갈아 쓰려고 하면 치명적인 오류가 발생하므로 **한쪽은 쓰기만, 반대편은 읽기만** 해야 합니다.

- **자가 수신 오류:** 부모가 데이터를 쓰고 바로 읽으려 할 경우, 자식이 읽기 전에 자신이 쓴 데이터를 스스로 다시 읽어버리는 버그가 발생합니다.
- **데드락 (Deadlock):** 양쪽 프로세스가 동시에 `read()`를 시도하면 서로 데이터가 오기만을 영원히 기다리며 멈춰버립니다.
    

### ⚠️ 올바른 양방향 통신 및 `close()` 규칙

완전한 쌍방향 통신을 위해서는 **반드시 2개의 파이프를 독립적으로 생성**해야 합니다. 데이터 혼선과 무한 대기(블로킹)를 막기 위해 사용하지 않는 FD는 반드시 `close()`로 닫아야 합니다.

- **[정석] 부모 ➔ 자식 단방향 통신 시 FD 정리 방법**
    - **부모 프로세스:** 읽기 포트 `fd[0]`을 `close()` 하고, 쓰기 포트 `fd[1]`만 사용하여 송신.
    - **자식 프로세스:** 쓰기 포트 `fd[1]`을 `close()` 하고, 읽기 포트 `fd[0]`만 사용하여 수신.
        

## 💡 시험장 들어가기 전 최종 암기 공식

1. **`fd[0]`** = 읽기 (Read / 파이프의 출구)
2. **`fd[1]`** = 쓰기 (Write / 파이프의 입구)
3. **이름 없는 파이프:** 파일 시스템 이름 없음 ➔ RAM에만 존재 ➔ `fork()`를 통한 FD 테이블 상속자(혈연관계)만 접근 가능
4. **이름 있는 파이프(FIFO):** 디스크엔 이름과 inode만 존재 (데이터 블록 포인터 = NULL) ➔ `open()` 시 `i_pipe` 포인터 활성화 ➔ 독립 프로세스 간 시스템 콜을 매개로 커널 RAM 버퍼 공유 통신
