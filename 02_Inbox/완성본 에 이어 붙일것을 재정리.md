## 2. `st_mode` 해석의 핵심: 데이터 무결성 보장

`stat` 구조체의 데이터를 출력하거나 가공할 때, 가장 먼저 마주하는 관문은 "비트 데이터를 어떻게 오염 없이 뽑아낼 것인가"입니다.

### ① 2진수 -> 8진수 포맷팅 `%o`의 이유

리눅스 권한은 **r, w, x**라는 3비트 단위로 작동합니다. 8진수($2^3 = 8$) 한 자리는 정확히 이 3비트와 **1:1 매핑**되므로, 10진수보다 권한 상태를 확인하기 훨씬 직관적입니다.

- **예:** `0644` → `6(rw-)`, `4(r--)`, `4(r--)`

### ② 부호 확장(Sign Extension)의 함정과 해결책

컴퓨터가 비트 수가 적은 자료형(`mode_t`)을 큰 자료형(`int`)으로 옮길 때 발생하는 물리적 현상을 제어해야 합니다.

- **문제점 (Sign Extension):** 일반 파일(`S_IFREG`)의 식별 비트는 최상위 비트(MSB)가 `1`입니다. 이를 단순히 `int`로 변환하면 CPU는 이를 '음수'로 오해하여 빈 공간을 모두 `1`로 채워버려 쓰레기 값이 발생합니다.
- **해결책 (Zero Extension):** 출력 시 `(unsigned int)`로 강제 캐스팅하면, 앞부분을 무조건 `0`으로 채워 비트의 원형을 보존합니다.

> [!tip] **💡 안전한 출력 코드**
>
> ```C
> printf("File Mode: %o\n", (unsigned int)statbuf.st_mode); 
> ```

## 3. 파일 종류 판별: 가독성 vs 원리

`st_mode` 상위 4비트에 숨겨진 파일의 정체를 밝히는 두 가지 방법이 있습니다.

|**구분**|**비트 마스크(Bit Mask) 방식**|**매크로 함수(Macro) 방식**|
|---|---|---|
|**작동 원리**|`st_mode & S_IFMT` (AND 연산)|내부적으로 마스크 연산 후 불리언 반환|
|**가독성**|낮음 (비트 연산 이해 필요)|**높음 (직관적인 이름)**|
|**상수 예시**|`S_IFREG`, `S_IFDIR`, `S_IFLNK`|`S_ISREG()`, `S_ISDIR()`, `S_ISLNK()`|

**코드 비교:**


```C
// [원리] 비트 마스크 방식: 종류 비트만 추출하여 비교
if ((statbuf.st_mode & S_IFMT) == S_IFDIR) printf("디렉터리입니다.\n");

// [권장] 매크로 방식: 더 직관적이고 실수를 줄임
if (S_ISDIR(statbuf.st_mode)) printf("디렉터리입니다.\n");
```

## 4. 접근 권한(rwx) 추출 및 기호 변환

`ls -l` 명령어가 보여주는 `-rwxr-xr-x` 형태의 문자열을 만드는 핵심 로직입니다. 하위 9비트를 3비트씩 끊어서 검사합니다.

### ① 개별 권한 비트 검사 (Bitwise AND)

각 권한 비트 위치에 해당하는 상수와 `&` 연산을 수행하여 결과가 0이 아니면 권한이 있는 것입니다.

- **User:** `S_IRUSR`, `S_IWUSR`, `S_IXUSR`
- **Group:** `S_IRGRP`, `S_IWGRP`, `S_IXGRP`
- **Others:** `S_IROTH`, `S_IWOTH`, `S_IXOTH`
    

### ② 기호(Symbolic) 문자열 조립 로직

10글자의 배열(`res[11]`)을 준비하고 순차적으로 비트를 체크하여 문자를 채웁니다.

```C
char res[11] = "----------"; // 기본값 설정

// 1. 파일 종류 표시
if (S_ISDIR(mode)) res[0] = 'd';
else if (S_ISLNK(mode)) res[0] = 'l';

// 2. 권한 비트 순차 매핑 (반복문 또는 조건문)
if (mode & S_IRUSR) res[1] = 'r';
if (mode & S_IWUSR) res[2] = 'w';
if (mode & S_IXUSR) res[3] = 'x';
// … (Group, Others 동일 로직 반복)
```

## 5. 메타데이터의 시각화: ID와 시간 변환

숫자 뭉치인 UID, GID, Time 정보를 사람이 읽을 수 있는 텍스트로 치환합니다.

### ① ID → 이름 변환 (Owner/Group)

커널은 숫자로 관리하지만, 사용자는 이름(`root`, `user1`)을 원합니다. 시스템 DB(`etc/passwd`, `/etc/group`)를 조회하는 함수를 사용합니다.

- **사용 함수:** `getpwuid()` (사용자), `getgrgid()` (그룹)
- **헤더:** `<pwd.h>`, `<grp.h>`
    

### ② Epoch Time → 날짜 문자열 변환

`st_mtime`은 1970년부터 흐른 '초' 단위 숫자입니다. 이를 포맷팅합니다.

```C
// 1. UID를 이름으로 변환
struct passwd *pw = getpwuid(statbuf.st_uid);
printf("Owner: %s\n", pw->pw_name);

// 2. 초 단위를 날짜 포맷으로 변환
char time_buf[25];
struct tm *t = localtime(&statbuf.st_mtime);
strftime(time_buf, sizeof(time_buf), "%Y-%m-%d %H:%M", t);
printf("Modified: %s\n", time_buf);
```

---

**정리하자면:** `stat` 구조체를 다루는 것은 **"비트 마스크를 통해 원하는 조각을 골라내고(Selection), 적절한 타입으로 포맷팅(Formatting)하여 사용자에게 보여주는 과정"**입니다.

이제 이 지식을 바탕으로 직접 `ls -l` 명령어를 직접 구현해 보시는 건 어떨까요? 관련하여 특정 파일의 권한을 변경하는 `chmod` 시스템 콜 구현 방법이 궁금하시면 말씀해 주세요!
