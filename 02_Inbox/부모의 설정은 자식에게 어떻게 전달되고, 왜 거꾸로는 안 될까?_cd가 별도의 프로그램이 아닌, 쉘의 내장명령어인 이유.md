## 📝 나의언어
모든 프로세스는 자신만의 독립된 PCB와 메모리 공간을 가집니다.
따라서 **자식 프로세스**가 자신의 상태(CWD 등)를 변경하더라도, 이는 부모 프로세스의 PCB에 절대로 영향을 줄 수 없습니다.

- `ls`, `mkdir`, `rm`등의 일반적인 명령어는 쉘과 별도의 프로그램으로, 쉘이 자식 프로세스로 생성(fork)시켜 대행시켜 실행합니다. 그리고 작업이 끝나면 자식은 사라지고 쉘(부모) 제어권과 작업결과만 얻습니다.
- 따라서 자식 프로세스에서 `chdir`을 호출해 위치를 바꿔도, 그 프로세스가 종료되어 부모로 돌아가면 부모의 위치는 그대로 유지됩니다.
- 그래서 터미널의 위치를 실제로 옮기려면, 자식이 아닌 **쉘 프로세스 자신이 직접 `chdir()`을 호출**해야 합니다. 그래서 `cd`는 별도의 프로그램이 아닌 쉘 프로세스가 직접 `chdir()`을 호출하는 **내장 명령어(Built-in)**로 설계된 것입니다.

## 상세 정리

## 1. 프로세스의 독립적 구조 (PCB와 가상 메모리)

모든 프로세스는 운영체제로부터 독립적인 자원을 할당받습니다.

- **PCB (Process Control Block):** 프로세스 식별자(PID), 프로세스 상태, **현재 작업 디렉토리(CWD)**, 열린 파일 디스크립터 목록 등을 저장하는 커널 내의 자료구조입니다.
- **가상 메모리 공간 (Virtual Address Space):** Stack, Heap, Data, Code 영역으로 나뉘며, 한 프로세스가 다른 프로세스의 메모리 영역에 직접 접근하는 것은 하드웨어 수준(MMU)에서 차단됩니다.
    

---

## 2. 외부 명령어와 내장 명령어의 실행 차이

### 외부 명령어 (External Commands: `ls`, `mkdir`, `rm` 등)

1. **`fork()` 호출:** 쉘 프로세스를 복제하여 새로운 자식 프로세스를 생성합니다.
2. **`exec()` 호출:** 자식 프로세스의 메모리 공간을 해당 명령어의 바이너리 코드로 덮어씁니다.
3. **상태 변경:** 자식 프로세스가 `chdir()` 등을 호출해 자신의 PCB 내 CWD 값을 변경하더라도, 이는 **자식 프로세스의 PCB**에만 국한됩니다.
4. **종료:** 자식이 종료되면 해당 PCB와 메모리 공간은 커널에 의해 회수되며, 부모(쉘)의 PCB는 아무런 변화가 없습니다.
    

### 내장 명령어 (Built-in Commands: `cd`, `export`, `exit` 등)

- 별도의 프로세스를 생성(`fork`)하지 않습니다.
- **쉘 프로세스 자신이 직접** 시스템 콜을 호출하여 **자신의 PCB** 정보를 수정하거나 메모리 변수를 조작합니다. 따라서 실행 후 쉘의 상태가 실제로 유지됩니다.
    

---

## 3. 부모의 설정이 자식에게 전달되는 이유 (상속의 기작)

부모의 환경 변수나 설정이 자식에게 전달되는 것은 '실시간 동기화'가 아니라 **'생성 시점의 스냅샷 복사'**이기 때문입니다.

1. **데이터 복제:** `fork()` 시스템 콜이 실행될 때, 운영체제는 부모 프로세스의 PCB와 메모리 내용을 자식 프로세스에게 그대로 복사합니다. 이 과정에서 부모가 가진 **환경 변수(Environment Variables)** 배열도 함께 복사됩니다.
2. **Copy-on-Write (COW):** 효율성을 위해 실제 물리 메모리는 공유하다가, 자식이 데이터를 수정하려 할 때 비로소 별도의 메모리 공간을 생성하지만, 논리적으로는 이미 복사된 상태로 시작합니다.
3. **단방향성:** 복사가 완료된 후에는 부모와 자식의 메모리 주소 체계가 논리적으로 완전히 분리됩니다. 따라서 **생성 이후 부모가 바꾼 설정은 자식에게 전달되지 않으며**, 자식이 바꾼 설정 또한 부모에게 전달될 수 없습니다.
    

---

### 요약

- **격리:** 자식이 부모를 바꿀 수 없는 이유는 **서로 다른 PCB**를 사용하기 때문입니다.
- **상속:** 자식이 부모의 설정을 받는 이유는 **`fork()` 시점에 부모의 데이터를 그대로 복제**받아 시작하기 때문입니다.
- **내장 명령어:** 쉘 자신의 PCB를 수정해야 하는 작업은 반드시 쉘 내부에서 직접 수행해야 합니다.
