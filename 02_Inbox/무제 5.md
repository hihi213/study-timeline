## 🛠️ exec 함수군 접미사 명명 규칙 (Naming Convention)

`exec` 뒤에 붙는 글자들은 **"인자를 어떻게 넘길 것인가?"**와 **"프로그램을 어디서 찾을 것인가?"**를 결정하는 일종의 레시피입니다.

| **접미사** | **의미**          | **기술적 설명**            | **핵심 포인트**            |
| ------- | --------------- | --------------------- | --------------------- |
| **l**   | **List**        | 인자를 하나씩 나열하여 전달       | 마지막은 반드시 `NULL`로 마침표! |
| **v**   | **Vector**      | 인자를 문자열 배열(Array)로 전달 | 인자 개수가 유동적일 때 유리함     |
| **p**   | **Path**        | 환경 변수 `PATH`를 참조      | 파일명만 써도 시스템이 알아서 찾아줌  |
| **e**   | **Environment** | 환경 변수를 직접 설정          | 부모의 환경 변수 대신 새 환경을 부여 |

## 🔍 실행 파일 탐색 및 메커니즘의 진실

### 1. `ls`는 명령어이기 이전에 '파일'입니다.

우리가 터미널에 치는 `ls`는 고유 명사가 아니라 `/bin/ls`에 위치한 **실행 가능한 바이너리 파일**입니다. `execlp("ls", …)`라고 호출하는 것은 "시스템아, 네가 알고 있는 경로(PATH)에서 `ls`라는 파일을 찾아 실행해줘"라는 정식 요청입니다.

### 2. 찾는 위치는 현재 폴더(CWD)가 아니라 PATH입니다. (`p`의 역할)

`execlp`에서 `p`가 붙으면 시스템은 현재 내가 있는 폴더를 보는 것이 아니라, 환경 변수 `PATH`에 등록된 디렉터리들(`/bin`, `/usr/bin` 등)을 순서대로 뒤집니다.

**🛡️ 보안 상식:** 리눅스는 보안상 현재 폴더(`.`)를 기본 검색 경로에 넣지 않습니다. 만약 누군가 악의적으로 만든 가짜 `ls`를 현재 폴더에 두었을 때, 시스템이 이를 먼저 실행하는 사고를 방지하기 위함입니다.

### 3. 왜 실행 후에도 현재 위치가 유지될까요?

`exec`는 프로세스의 옷(코드, 데이터, 스택)만 갈아입히는 것입니다. 기존 프로세스의 **현재 작업 디렉터리(CWD)** 정보는 커널이 그대로 유지해주기 때문에, 새로 불려온 `ls`도 내가 작업하던 폴더의 내용을 올바르게 출력할 수 있습니다.

## 💡 직접 만든 파일 실행하기 (실전 팁)

직접 만든 프로그램 `my_prog`를 실행할 때 발생하는 차이를 이해하면 완벽합니다.

- `execlp("my_prog", …);` $\rightarrow$ **실패** (시스템 `PATH` 목록엔 내 폴더가 없으니까요.)
- `execl("./my_prog", …);` $\rightarrow$ **성공** (경로를 직접 찍어줬으므로 `p` 없이도 정확히 찾아갑니다.)

## 📂 함수 조합별 특징 및 사용법

### 1. 인자 전달 방식 (l vs v)

- **execl (List):** 인자 개수가 고정적이고 적을 때 직관적입니다.
    
    C
    
    ```sql
    execl("/bin/ls", "ls", "-l", NULL);
    ```
    
- **execv (Vector):** 인자가 많거나 배열에 미리 담겨 있을 때 사용합니다.
    
    C
    
    ```sql
    char *args[] = {"ls", "-l", NULL};
    execv("/bin/ls", args);
    ```
    

### 2. 경로 탐색 여부 (p)

- **execlp / execvp:** 파일의 절대 경로를 몰라도 됩니다.
    
    C
    
    ```sql
    execlp("ls", "ls", "-l", NULL); // "/bin/ls"라고 안 써도 됨
    ```
    

### 3. 환경 변수 설정 (e)

- **execve / execle:** 부모에게서 물려받은 환경 변수 외에 특수한 환경을 설정하고 싶을 때 사용합니다.
    
    C
    
    ```sql
    char *env[] = {"USER=admin", "PATH=/usr/bin", NULL};
    execve("/bin/ls", args, env);
    ```

## ⚠️ 핵심 주의사항 (이것만은 꼭!)

1. **프로세스 대체:** `exec` 호출이 성공하는 순간, 그 이후의 코드는 메모리에서 사라집니다. **"exec 성공 = 돌아오지 않는 강을 건넘"**이라고 생각하세요. 실패했을 때만 아래 코드가 실행됩니다.
2. **첫 번째 인자의 관례:** $argv[0]$에 해당하는 첫 번째 인자에는 관례적으로 **실행 파일 이름 자체**를 넣어줍니다. (예: `execlp("ls", "ls", …)`에서 두 번째 "ls")
3. **NULL 종료:** `l` 계열 함수를 쓸 때는 인자 리스트의 끝에 반드시 `NULL`을 넣어 컴퓨터에게 "여기까지가 인자다"라고 알려줘야 합니다.

|---|---|---|
|**전달 방식**|**l / v**|"인자를 하나씩 나열할까(List), 배열로 묶어줄까(Vector)?"|
|**탐색 방식**|**p**|"파일의 정확한 경로를 아는가, 아니면 이름만 아는가(Path)?"|
|**환경 설정**|**e**|"부모의 설정을 그대로 쓸까, 내가 새로 정의할까(Environment)?"|
