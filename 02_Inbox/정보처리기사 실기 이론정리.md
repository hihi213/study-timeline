# DB 핵심이론

## 1. 데이터베이스 설계 단계 (순서 및 특징)

순서 배열이나 각 단계의 결과물(산출물)을 묻는 형태로 출제됩니다.

> **요구사항 분석 $\rightarrow$ 개념적 설계 $\rightarrow$ 논리적 설계 $\rightarrow$ 물리적 설계 $\rightarrow$ 구현**

- **개념적 설계**: 사용자 요구사항을 추상화하여 인간이 이해할 수 있는 구조로 변환하는 단계입니다.
    - **"트랜잭션 모델링"**, **"E-R 다이어그램(개체-관계도) 산출"**, **"DBMS 독립적"**(DBMS종류 상관없이 공통으로 적용될 설계를 한다)
- **논리적 설계**: 개념적 구조를 컴퓨터가 처리할 수 있는 특정 DBMS 구조에 맞게 변환하는 단계입니다.
    - **"테이블 설계(스키마 변환)"**, **"관계 데이터 모델 매핑"**, **"정규화 수행-> 무결성 확보"**
- **물리적 설계**: 논리적 구조를 저장장치(디스크)에 물리적인 파일 구조로 저장할 수 있도록 변환하는 단계입니다.
    - **"저장 레코드 양식"**(디스크 할당방식을 결정), **"인덱스 설계"**, **"접근 경로(Access Path) 결정"**, **"성능(반응시간, 공간효율) 고려"**
>저장레코드 양식
>- 고정길이 레코드 : 모든 행의 크기를 똑같이 고정
>- 가변길이 레코드 : 데이터크기에 맞춰 레코드를 유동적으로 조정 (varchar 타입 활용)
## 2. 관계 데이터 모델의 기본 용어 구별

테이블 구조를 던져주고 빈칸을 채우거나 수치를 계산하는 유형입니다.

- **튜플 (Tuple / 행 / 레코드)**: 테이블의 가로줄에 해당하는 개체 하나를 구성하는 속성들의 집합입니다.
- **속성 (Attribute / 열 / 컬럼)**: 데이터베이스를 구성하는 가장 작은 논리적 단위이자 파일의 필드에 해당합니다.
- **도메인 (Domain)**: 하나의 속성이 가질 수 있는 "동일한 타입의 원자값들의 범위(집합)"입니다.
- **차수 (Degree)**: 한 릴레이션(테이블)을 구성하는 "속성(열)의 전체 개수"입니다.
- **카디널리티 (Cardinality)**: 한 릴레이션(테이블)에 들어있는 "튜플(행)의 전체 개수"입니다. (INSERT/DELETE에 의해 수시로 변함)
- **스키마 (Schema)**: 데이터베이스의 구조와 제약 조건에 관한 전반적인 명세를 정의한 틀입니다.
- **인스턴스 (Instance)**: 스키마에 따라 실제 데이터베이스 힙에 저장된 구체적인 값(데이터)들의 집합입니다.

## 3. 키(Key)의 종류와 제약 조건

성격과 정의를 한 단어로 구별하는 것이 중요합니다.

- **슈퍼키 (Super Key)**: 유일성은 만족하지만, 최소성은 만족하지 못하는 키입니다. (예: 학번 + 이름 조합)
- **후보키 (Candidate Key)**: 튜플을 유일하게 식별할 수 있는 속성으로, **유일성과 최소성을 모두 만족**해야 합니다.
- **기본키 (Primary Key)**: 후보키 중에서 특별히 선정된 주 키로, **중복값과 NULL 값을 가질 수 없습니다.**
- **대체키 (Alternate Key)**: 후보키 중에서 기본키로 선택받지 못하고 남은 나머지 키들을 뜻합니다.
- **외래키 (Foreign Key)**: 다른 테이블의 기본키를 참조하는 속성으로, 테이블 간의 연결 고리 역할을 합니다.

### 데이터 무결성 제약 조건 3종

- **개체 무결성 (Entity Integrity)**: 기본키(Primary Key)는 어떠한 경우에도 **NULL 값을 가질 수 없고, 중복될 수 없다**는 규칙입니다.
- **참조 무결성 (Referential Integrity)**: 외래키 값은 참조하는 테이블의 기본키 값과 무저건 일치하거나, 아예 **NULL 값이어야 한다**는 규칙입니다.
- **도메인 무결성 (Domain Integrity)**: 특정 속성의 값이 정의된 도메인의 **지정된 범위를 벗어날 수 없다**는 규칙입니다. (예: 학점 속성에 문자 입력 불가)
    

## 4. 함수적 종속성 (Functional Dependency)

속성 $X$의 값에 따라 속성 $Y$의 값이 오직 하나로만 결정될 때, "$Y$는 $X$에 함수적으로 종속된다($X \rightarrow Y$)"고 합니다.

- **완전 함수적 종속**: 복합 기본키 $(A, B)$ 전체가 있어야만 어떤 속성 $C$가 결정되는 경우입니다.
- **부분 함수적 종속**: 복합 기본키 $(A, B)$ 중 **오직 일부 속성($A$ 또는 $B$)에만** 속성 $C$가 종속되는 경우입니다. (정규화 타깃)
- **이행적 함수적 종속**: $A \rightarrow B$ 이고 $B \rightarrow C$ 일 때, 결과적으로 **$A \rightarrow C$ 관계가 성립**되는 건너뛰기식 종속 현상입니다.
    

## 5. 이상 현상 (Anomaly) 및 정규화 (Normalization) 단계

설명을 읽고 어떤 이상 현상인지, 혹은 어떤 정규화 단계인지 영문 약어나 숫자를 채우는 단답형 위주로 준비합니다.

### 릴레이션의 이상 현상 (3가지)

- **삽입 이상**: 데이터를 추가할 때 원하지 않는 불필요한 정보까지 억지로 함께 삽입해야만 하는 현상입니다.
- **삭제 이상**: 특정 튜플을 삭제할 때, 관계없는 다른 유용한 정보까지 연쇄적으로 함께 유실(삭제)되는 현상입니다.
- **갱신 이상**: 튜플의 일부 값을 수정할 때 데이터의 불일치(모순)가 발생하여 정보가 모호해지는 현상입니다.
    

### 🌟 정규화 단계를 결정하는 종속성 제거 공식 (핵심)

- **1정규형 (1NF)**: 테이블의 모든 속성 값이 "원자값(Atomic Value)"으로만 구성되도록 분해하는 단계 (도메인이 원자값)
- **2정규형 (2NF)**: 1NF를 만족하면서, 기본키가 아닌 모든 속성의 "부분 함수적 종속을 제거"하여 "완전 함수적 종속"으로 만드는 단계
- **3정규형 (3NF)**: 2NF를 만족하면서, 기본키가 아닌 모든 속성의 "이행적 함수적 종속을 제거"하는 단계
- **보이스-코드 정규형 (BCNF)**: 3NF를 만족하면서, 테이블 내의 "모든 결정자가 후보키"가 되도록 강제하는 단계 (후보키가 아닌 결정자 제거)
    

🌟 **정규화 전체 암기 공식:** **"도 - 부 - 이 - 결 - 다 - 조"**
1. **1NF (도):** 도메인이 **원자값**으로 구성
2. **2NF (부):** **부분 함수적 종속 제거** (완전 함수적 종속 관계 확립)
3. **3NF (이):** **이행적 함수적 종속 제거**
4. **BCNF (결):** **결정자이면서 후보키가 아닌 것 제거**
5. **4NF (다):** **다치 종속** 제거
6. **5NF (조):** **조인 종속** 제거

## 6. 트랜잭션의 특성 (ACID)

- **원자성 (Atomicity)**: 트랜잭션의 연산은 데이터베이스에 **모두 반영되든지(Commit), 아니면 전혀 반영되지 않아야(Rollback)** 합니다.
- **일관성 (Consistency)**: 트랜잭션이 성공적으로 완료된 후에도 데이터베이스는 언제나 고유한 제약 조건과 고정된 규칙을 만족해야 합니다.
- **격리성 / 고립성 (Isolation)**: 둘 이상의 트랜잭션이 동시에 병행 실행될 때, 어떤 트랜잭션도 다른 트랜잭션의 중간 연산 결과에 직접 끼어들거나 참조할 수 없습니다.
- **영속성 / 지속성 (Durability)**: 성공적으로 완료된 트랜잭션의 결과는 시스템에 영구적으로 반영되어, 시스템 장애가 발생하더라도 데이터가 손실되지 않아야 합니다.
    

## 7. 뷰(View)와 인덱스(Index)의 목적

- **뷰 (View)**: 하나 이상의 기본 테이블로부터 유도된 "가상 테이블"입니다. 독립적인 인덱스를 가질 수 없으며, 사용자에게 필요한 데이터만 골라 보여줌으로써 **보안성과 유연성, 편의성을 제공**하는 것이 주 목적입니다.
- **인덱스 (Index)**: 데이터 검색 성능을 향상시키기 위해 사용하는 "색인 구조"입니다. 테이블 레코드의 포인터를 정렬하여 가지고 있으며, 데이터 **검색(SELECT) 속도를 획기적으로 향상**시키는 것이 최우선 목적입니다. (과도한 인덱스는 오히려 INSERT/UPDATE 성능을 저하시키므로 주의)

시험장 지문에서 "결정자이면서 후보키가 아닌 것 제거" 라는 멘트가 보이면 망설임 없이 **BCNF**를 기입하시고, 행과 열의 개수를 계산할 때 차수(열의 개수)와 카디널리티(행의 개수)를 뒤바꿔 쓰지 않도록 마지막 순간까지 주의를 집중하시기 바랍니다!

# 테스트·모듈·설계·요구사항 단답

## 1. 애플리케이션 테스트 단계 (V-모델)

소프트웨어 개발 단계에 대응하여 순차적으로 진행되는 테스트 단계입니다.

- **단위 테스트 (Unit Test)**: 구현 단계에서 코딩 직후 **모듈이나 컴포넌트**를 대상으로 인터페이스, 외부 입출력, 로컬 데이터 등을 최소 단위로 검증합니다.
- **통합 테스트 (Integration Test)**: 단위 테스트가 끝난 모듈들을 결합하여 **모듈 간의 인터페이스 및 상호작용**이 올바른지 검증합니다.
- **시스템 테스트 (System Test)**: 전체 시스템이 **실제 환경과 유사한 환경**에서 요구사항을 완벽히 만족하는지 기능적/비기능적 요구사항을 모두 검증합니다.
- **인수 테스트 (Acceptance Test)**: 사용자(고객)의 관점에서 계약된 요구사항을 만족하는지 확인하고 인수를 결정하는 테스트입니다 (알파/베타 테스트가 여기에 속함).

## 2. 하향식 vs 상향식 통합 테스트

모듈들을 합쳐 나갈 때 위에서 아래로 가느냐, 아래에서 위로 가느냐의 차이입니다.

### 1) 하향식 통합 테스트 (Top-Down)

- 제어의 시작점인 **최상위 모듈부터** 점진적으로 하위 모듈들을 통합해 나갑니다.
- 아직 개발되지 않은 **하위 모듈의 역할을 임시로 수행**해 줄 가짜 모듈인 스텁(Stub)이 필요합니다.

### 2) 상향식 통합 테스트 (Bottom-Up)

- 가장 기초가 되는 **최하위 모듈부터** 단계별로 결합하여 상위 모듈로 올라갑니다.
- 상위 모듈이 아직 개발되지 않은 상태이므로, 하위 모듈들을 실제로 구동시키고 테스트 데이터를 입력/출력 제어해 줄 가상의 상위 대역 모듈인 **드라이버(Driver)**가 필수적입니다.

> 💡 **시험장 암기 공식!**
>
> - **하·스** : **하**향식은 **스**텁 (하향식 테스트, 하위 모듈 대체)
>     
> - **상·드** : **상**향식은 **드**라이버 (상향식 테스트, 상위 모듈 대체)
>     

## 3. 화이트박스 vs 블랙박스 테스트

프로그램의 내부 구조(소스 코드)를 알고 보느냐, 모르고 기능만 보느냐의 차이입니다.

|**구분**|**화이트박스 테스트 (White-Box)**|**블랙박스 테스트 (Black-Box)**|
|---|---|---|
|**관점**|소스 코드의 **구조와 로직**을 직접 검증|내부 구조는 보지 않고, **입출력 결과(기능)** 위주 검증|
|**대상**|경로 검증, 데이터 흐름, 제어 구조 등|명세 기반 검증, 비정상 입력값 필터링 확인 등|
|**유형**|구문(문장)·결정(분기)·조건·조건/결정 커버리지 등|동등 분할, 경계값 분석, 결정 테이블, 상태 전이 등|

## 4. 화이트박스 커버리지 (결정, 조건 구별하기)

자주 꼬아서 내는 서술형/빈칸 단골 주제입니다.

_예시 조건문_: `if (A > 0 && B < 0)`

- **문장(구문) 커버리지 (Statement Coverage)**: 프로그램 내부의 **모든 문장**이 최소한 한 번은 실행되도록 구성합니다.
- **결정(분기) 커버리지 (Decision/Branch Coverage)**: 전체 조건식 `(A > 0 && B < 0)`의 결과가 **True(참)가 되는 케이스와 False(거짓)가 되는 케이스**를 적어도 한 번씩 수행합니다.
- **조건 커버리지 (Condition Coverage)**: 전체 조건식 내의 개별 조건식 `(A > 0)`과 `(B < 0)`이 **각각 True/False**를 적어도 한 번씩 가지도록 테스트 데이터를 설계합니다 (전체 결과 상관없음).
- **조건/결정 커버리지 (Condition/Decision Coverage)**: **개별 조건식**도 각각 True/False가 되도록 하고, **전체 결정식** 또한 True/False가 한 번씩 나오도록 조합하여 완벽을 기합니다.
    

## 5. 맥케이브(McCabe) 순환 복잡도

제어 흐름 그래프에서 소스 코드의 복잡성을 수학적으로 측정하는 공식입니다. 계산 문제로 한 문제씩 꼬박꼬박 등장합니다.

### 공식

$$순환 복잡도= E - V + 2$$

- $E$: 화살표의 개수 (Edge, 간선)
- $V$: 동그라미의 개수 (Node, 정점)
    

> 💡 **수식이 헷갈릴 때 비기(祕技)**
>
> - 그래프가 나눈 **면(영역)의 개수 + 1**을 하거나, **조건문(if, while 등)의 개수 + 1**을 하면 똑같은 값이 나옵니다! (시간 단축용 검산 팁)

## 6. 블랙박스 테스트 기법 (대표 2가지)

- **동등 분할 (Equivalence Partitioning, 동치 분할)**: 입력 데이터를 결과가 유사할 것 같은 도메인별(유효값/무효값)로 등분한 뒤, 각 그룹의 대표값을 무작위로 한 개씩 뽑아 테스트하는 기법입니다.
- **경계값 분석 (Boundary Value Analysis)**: 결함이 주로 입력값의 경계 부근에서 발생한다는 사실을 이용해, 경계값(최솟값, 최댓값, 경계 바로 직전·직후의 값)을 집중적으로 선택하여 테스트하는 기법입니다.
    

## 7. 테스트 오라클 (Test Oracle)

테스트 결과가 올바른지 판단하기 위해 사전에 정의된 올바른 결과(참값)를 제공하고 비교하는 메커니즘입니다.

- **참(True) 오라클**: 모든 입력값에 대하여 기대하는 결과를 완벽히 제공하는 오라클 (미션 크리티컬 시스템에 적용)
- **샘플링(Sampling) 오라클**: 모든 입력이 아닌 특정 몇 개의 **대표 입력값**에 대해서만 예상 결과를 제공하는 오라클
- **휴리스틱(Heuristic) 오라클**: 특정 입력값의 올바른 결과를 제공하고, 나머지 입력값들에 대해서는 수학적·직관적 추정을 통해 타당성을 판단하는 오라클
- **일관성(Consistent) 오라클**: 애플리케이션 변경 시 이전 버전의 실행 결과와 현재 버전의 실행 결과를 비교하여 모순이 없는지 확인하는 오라클
    

## 8. 결함(Defect), 오류(Error), 실패(Failure) 구별

서술형 채점에서 매우 까다롭게 체크되는 표준 명칭입니다.

- **오류 (Error, 실수)**: 개발자, 기획자 등 **사람의 잘못된 행위나 오해**로 인해 발생한 문제 원인입니다.
- **결함 (Defect / Bug / Fault)**: 오류(Error)의 결과로 **소스 코드, 설계 문서 등에 실제로 남겨진 불완전한 요소나 문제점** 코드 내의 버그", "문서 내의 불일치",
- **실패 (Failure)**: 결함(Defect)이 포함된 코드가 실행되면서 시스템이 **원래 요구된 기능/명세를 수행하지 못하고 오작동하는 현상** "기대 결과와 실제 결과의 불일치", "시스템 중단", "런타임 오동작"

## 응집도, 결합도

## 1. 대원칙 (소프트웨어 설계 지향점)

좋은 소프트웨어 설계를 위해 모듈을 나눌 때는 이 공식만 기억하세요.

- **응집도는 높을수록(Strong) 좋음** (모듈 내부 요소들이 똘똘 뭉쳐있어야 함)
- **결합도는 낮을수록(Weak) 좋음** (모듈끼리 서로 간섭하지 않고 독립적이어야 함)

## 2. 응집도(Cohesion) 유형 정리

> **강함(좋음)** $\rightarrow$ 기능적 $\rightarrow$ 순차적 $\rightarrow$ 교환적 $\rightarrow$ 절차적 $\rightarrow$ 시간적 $\rightarrow$ 논리적 $\rightarrow$ 우연적 $\rightarrow$ **약함(나쁨)**

- **기능적 응집도 (Functional Cohesion)**
    - **키워드**: 단일 기능, 하나의 기능 수행
    - **설명**: 모듈 내부의 모든 요소가 단 하나의 단일 기능(목적)만을 수행하도록 구성된 상태
    - **예시:** 삼각함수 `sin(x)` 계산 모듈, 제곱근 계산 함수
- **순차적 응집도 (Sequential Cohesion)**
    - **키워드**: 이전요소 출력값을 입력값으로 사용
    - **설명**: 모듈 내의 **한 요소의 출력 결과가 다음 요소의 입력값으로 바로 사용**되는 구조
    - **예시:** 파일에서 텍스트를 읽어온 뒤(출력), 곧바로 문법을 검사(입력)하는 모듈
- **교환적(통신적) 응집도 (Communication Cohesion)**
    - **키워드**: 동일한 입출력, 동일 데이터 처리
    - **설명**: 서로 다른 작업을 수행하지만, **동일한 입력 데이터나 출력 데이터를 공유**하여 처리하는 모듈
    - **예시:** 동일한 학생 성적 데이터를 기반으로 총점을 계산하고, 학점도 산출하고, 석차도 구하는 모듈
- **절차적 응집도 (Procedural Cohesion)**
    - **키워드**: "정해진 순서/절차대로 수행", "순서도(Flowchart)의 제어 흐름"
    - **설명**: 데이터 공유 여부와 상관없이, 정해진 실행 순서나 절차(순서도 흐름)에 따라 순차적으로 동작하는 모듈
    - **예시:** 문을 열고 $\rightarrow$ 방에 불을 켜고 $\rightarrow$ 컴퓨터를 부팅하는 모듈
- **시간적 응집도 (Temporal Cohesion)**
    - **키워드**: 특정 시간, 초기화, 종료 처리
    - **설명**: 기능적 연관성은 없으나, **특정 시간대나 시점에 한꺼번에 실행되어야 한다는 이유**로 묶인 모듈
    - 프로그램 구동 시 환경변수 로딩, DB 커넥션 풀 생성, 화면 렌더링을 한 번에 처리하는 `init()` 함수
- **논리적 응집도 (Logical Cohesion)**
    - **키워드**: 논리적으로 유사, switch문, 유사 기능 묶음
    - **설명**: 논리적으로 비슷한 성격의 기능들을 한 모듈에 모아두고, **전달받는 매개변수(Flag) 값에 따라 분기하여 처리**하는 형태
    - 하나의 `output()` 함수 안에 매개변수로 1이 오면 화면 출력, 2가 오면 파일 저장, 3이 오면 프린터 출력을 하도록 만든 구조
- **우연적 응집도 (Coincidental Cohesion)**
    - **키워드**: 무관한 구성, 연관성 없음
    - **설명**: 아무런 기능적, 시간적, 논리적 연관성 없이 **단순히 모듈 크기를 줄이거나 우연히 함께 모아놓은** 최악의 상태
    - **예시:** 의미 없이 중복 코드를 묶어둔 `util_dump()` 함수

> 💡 **응집도 순서 암기 공식**
>
> **"기-순-교-절-시-논-우"**
> (기순이가 교절에서 시논(시골 논)으로 우연히 갔다)

- **순차적 vs 절차적 구분:**
    - **순차적:** 앞의 **출력** $\rightarrow$ 뒤의 **입력** (데이터 의존성 有)
    - **절차적:** 데이터 상관없이 단순히 실행 순서(Step 1, Step 2…)만 따름
- **교환적 vs 기능적 구분:**
    - **기능적:** 오직 **1개의 일**만 처리
    - **교환적:** 일은 여러 개를 하지만 **다루는 데이터가 동일**

## 3. 결합도(Coupling) 유형 정리

> **약함(좋음)** $\rightarrow$ 자료 $\rightarrow$ 스탬프 $\rightarrow$ 제어 $\rightarrow$ 외부 $\rightarrow$ 공통 $\rightarrow$ 내용 $\rightarrow$ **강함(나쁨)**


**자 · 스 · 제 · 외 · 공 · 내**
(자스민이 제 외투를 공용으로 냈다)

- **자료 결합도 (Data Coupling)**
    - **키워드**: 파라미터(인수), 값만 전달
    - **설명**: 모듈 간에 오직 순수한 데이터 값(파라미터/인수)만을 주고받는 형태
    - **예시:** `add(int a, int b)` 함수에 숫자 2개만 넘겨주고 결과값을 반환받는 경우
- **스탬프 결합도 (Stamp Coupling)**
    - **키워드**: 자료구조, 배열, 객체, 동일한 구조 전달
    - **설명**: 모듈 간에 단순 값이 아니라 **배열, 레코드, 구조체, 객체 등의 자료구조**를 통째로 전달하는 형태
    - **주의점:** 받는 모듈이 그 객체 안의 일부 필드만 쓰더라도 객체 전체를 넘겨야 하므로, 자료구조의 변경이 영향을 줄 수 있습니다.
    - **예시:** 학생의 나이만 필요한 함수인데 `Student` 객체 전체를 인자로 넘기는 경우
- **제어 결합도 (Control Coupling)**
    - **키워드**: 제어 요소, flag(플래그), 동작을 지시
    - **설명**: 한 모듈이 다른 모듈에게 처리 방식을 제어하는 신호(Flag, 제어 코드, 스위치 등)를 넘겨주는 형태
    - **주의점:** 호출하는 쪽에서 호출받는 쪽의 내부 로직 흐름을 알고 지시하는 셈이므로 모듈의 독립성이 떨어집니다.
    - **예시:** `printData(data, printType)`에서 `printType` 값에 따라 출력 형태를 분기하도록 제어 신호를 넘기는 경우
- **외부 결합도 (External Coupling)**
    - **키워드**: 외부 선언, 외부 프로토콜, 외부 변수 참조
    - **설명**: 모듈들이 소프트웨어 외부 환경(외부 선언 데이터, 통신 프로토콜, 장치 인터페이스 등)을 공유하여 참조하는 형태
    - **예시:** 두 모듈이 외부 설정 파일이나 외부 시스템 통신 포맷을 공유하여 연동하는 경우
- **공통(공유) 결합도 (Common Coupling)**
    - **키워드**: 전역 변수 공유, 공통 데이터 영역
    - **설명**: 여러 모듈이 시스템 내부의 **전역 변수(Global Variable)나 공용 데이터 영역**에 직접 접근하는 형태
    - **주의점:** 전역 변수 하나를 수정하거나 잘못 건드리면 이를 참조하는 모든 모듈이 동시에 영향을 받습니다.
    - **예시:** 여러 함수가 하나의 `static global` 변수를 읽고 쓰는 경우
- **내용 결합도 (Content Coupling)**
    - **키워드**: 다른 모듈의 내부 기능/자료 직접 참조/수정
    - **설명**: 한 모듈이 **다른 모듈의 내부 데이터나 내부 명령 코드를 직접 참조하거나 수정**하는 최악의 형태
    - **주의점:** 캡슐화가 완전히 파괴된 상태로, 모듈의 분리 자체가 무의미합니다
    - **예시:** 한 모듈 내부에서 다른 모듈의 비공개(private) 변수에 직접 접근하거나 내부 코드로 강제 점프(goto)하는 경우
        

> 💡 **결합도 순서 암기 공식**
>
> **"자-스-제-외-공-내"** (이것도 앞글자를 따서 외우시면 순서 배치나 강약비교 문제 해결에 완벽합니다!)

시험에서는 각 유형에 대한 설명(정의)을 지문으로 제시하고 **이것이 어떤 응집도/결합도에 해당하는지 빈칸에 단답형으로 작성**하는 문제가 주로 출제되므로, 위의 "키워드"를 지문에서 찾아서 정답 매칭 연습을 하시면 막힘없이 풀어내실 수 있습니다!

## 디자인 패턴
## 1. 생성 패턴 (Creational Patterns)

**객체의 생성 과정과 조합을 캡슐화**하여, 프로그램 내에서 객체가 생성되고 참조되는 방식을 유연하게 관리하기 위한 패턴군입니다.

객체를 직접 `new` 연산자로 하드코딩해 생성하면 변경에 취약해지므로, 이를 별도의 메커니즘으로 분리해 코드의 결합도를 낮추는 것이 핵심 목적입니다.


### 1. 추상 팩토리 (Abstract Factory)

- **특징:** 구체적인 클래스를 명시하지 않고, 연관된 여러 종류의 객체 묶음(제품군)을 통째로 생성하기 위한 일관된 인터페이스를 제공하는 패턴
- **시험 키워드:** "연관된 객체들의 군(Family) 생성", "키트(Kit) 형태 인터페이스", "제품군 단위 생성"
- **예시:** OS별 GUI 컴포넌트를 지원할 때, 버튼과 체크박스를 개별적으로 생성하지 않고 `WindowsFactory`는 `WindowsButton`과 `WindowsCheckbox`를 한 묶음으로 생성하며, `MacFactory`는 `MacButton`과 `MacCheckbox`를 한 묶음으로 생성하도록 만드는 경우

### 2. 빌더 (Builder)

- **특징:** 복잡한 객체의 생성 과정과 표현 방법을 분리하여, 동일한 생성 절차를 거치더라도 매개변수 조합에 따라 다양한 형태의 결과 객체를 구성할 수 있게 하는 패턴
- **시험 키워드:** "복합 객체의 단계별 생성", "생성 과정과 표현의 분리", "매개변수가 많은 복잡한 인스턴스 구성"
- **예시:** 생성자 파라미터가 10개 이상인 `User` 객체를 만들 때, `new User(…)` 대신 `User.builder().name("Kim").email("a@b.com").age(25).build()`처럼 메서드 체이닝을 통해 필요한 속성만 선택적으로 주입하여 최종 불변 객체를 생성하는 경우

### 3. 팩토리 메서드 (Factory Method)

- **특징:** 객체 생성을 위한 인터페이스(추상 메서드)를 상위 클래스에 선언해 두고, 실제로 어떤 구체 클래스의 인스턴스를 생성할지는 하위 서브클래스가 오버라이딩하여 결정하도록 위임하는 패턴
- **시험 키워드:** "인스턴스 생성을 서브클래스에 위임", "가상 생성자(Virtual-Constructor)", "오버라이드 기반 생성"
- **예시:** 상위 프레임워크 클래스인 `LogManager`는 추상 메서드 `createLogger()`를 호출해 로깅 흐름만 제어하고, 실제 파일에 기록할지 콘솔에 기록할지는 이를 상속받은 `FileLogManager`가 `FileLogger` 객체를 반환하고 `ConsoleLogManager`가 `ConsoleLogger` 객체를 반환하도록 위임하는 경우
### 4. 프로토타입 (Prototype)

- **특징:** 객체 생성 시 `new` 키워드로 처음부터 필드를 채우는 비용이 크거나 초기화 로직이 무거울 때, 이미 존재하는 원형 객체를 메모리 상에서 복제(Clone)하여 새로운 객체를 생성하는 패턴
- **시험 키워드:** "원형(Prototype) 인스턴스 복제", "객체 복사", "Clone 메서드"
- **예시:** 외부 DB에서 복잡한 연산 결과를 조회해 대량의 설정값을 적재해 둔 `Config` 인스턴스를 매 요청마다 새로 DB 조회를 거쳐 생성하지 않고, 자바의 `Cloneable` 인터페이스나 `clone()` 메서드를 호출하여 깊은 복사(Deep Copy)한 뒤 일부 값만 바꿔 재사용하는 경우
### 5. 싱글톤 (Singleton)

- **특징:** 애플리케이션 라이프사이클 동안 특정 클래스의 인스턴스가 오직 1개만 생성되도록 제한하고, 어디서든 동일한 인스턴스에 접근할 수 있도록 전역적인 진입점을 제공하는 패턴
- **시험 키워드:** "오직 하나의 인스턴스만 보장", "전역 접근점 제공", "Private 생성자와 Static 인스턴스"
- **예시:** 스프링 컨테이너의 기본 빈(Bean) 스코프 등록 방식이나, 여러 쓰레드가 동시에 접근하더라도 단 하나의 풀(Pool)만 유지해야 하는 `DatabaseConnectionPool` 클래스에서 생성자를 `private`으로 막고 `getInstance()` 호출 시 동일한 객체 주소값만 반환하도록 구현하는 경우
## 2. 구조 패턴 (Structural Patterns)

클래스나 객체들을 조합하여 더 큰 구조를 만들고, 서로 다른 인터페이스를 가진 객체들이 함께 일할 수 있도록 돕는 패턴입니다.

### 3) Adapter (어댑터)

- **해결 문제**: 서로 다른 인터페이스를 가져 호환되지 않는 클래스들이 협업할 수 있도록 중간에서 인터페이스를 변환해 줍니다.
- **지문 식별 단서**: **"인터페이스 호환성"**, **"중간 연결"**, **"래퍼 (Wrapper) 패턴"**, **"변환기"**
    

### 4) Bridge (브릿지)

- **해결 문제**: 추상화된 개념(Interface)과 실제 구현부(Implementation)를 분리하여 서로 독립적으로 확장할 수 있도록 설계합니다.
- **지문 식별 단서**: **"추상화와 구현의 분리"**, **"독립적인 확장"**
    

### 5) Decorator (데코레이터)

- **해결 문제**: 기존 객체를 수정하거나 상속받지 않고, 객체에 동적으로 새로운 책임(기능)을 덧붙이고 확장할 때 사용합니다.
- **지문 식별 단서**: **"동적인 기능 추가"**, **"상속 대신 객체 결합"**, **"스킨을 입히듯이 확장"**
    

### 6) Proxy (프록시)

- **해결 문제**: 어떤 객체에 대한 접근을 제어하거나, 실제 객체를 대신하여 대리 역할을 수행하는 중간 제어 수단이 필요할 때 사용합니다.
- **지문 식별 단서**: **"대리자"**, **"접근 제어"**, **"흐름 제어"**, **"네트워크 연결/대체제"**
    

## 3. 행위 패턴 (Behavioral Patterns)

객체 간의 상호작용, 알고리즘 분배, 그리고 역할 분담을 효율적으로 정의하는 패턴입니다.

### 7) Observer (옵저버)

- **해결 문제**: 한 객체의 상태 변화를 감지하여 일대다(1:N) 의존 관계에 있는 다른 여러 객체에 변경 사항을 자동으로 전파하고자 할 때 사용합니다.
- **지문 식별 단서**: **"일대다(1:N) 의존성"**, **"상태 변화 자동 통지"**, **"이벤트 수신처 등록"**
    

### 8) Strategy (스트레티지 / 전략)

- **해결 문제**: 동일 계열의 여러 알고리즘을 각각 캡슐화하여 구현해 두고, 필요에 따라 실행 중에 동적으로 알고리즘을 교체하여 사용할 수 있게 합니다.
- **지문 식별 단서**: **"알고리즘군 정의 및 캡슐화"**, **"동적 알고리즘 교체"**, **"실행 중에 교환 가능"**
    

### 9) State (스테이트 / 상태)

- **해결 문제**: 객체 자신의 상태 변화에 따라 내부 동작 방식을 변경하도록 제어하며, 마치 객체의 클래스가 변하는 것처럼 보이게 설계합니다.
- **지문 식별 단서**: **"상태에 따른 행동 변화"**, **"객체 스스로 상태 관리"**, **"조건문 대체"**
    

### 10) Template Method (템플릿 메서드)

- **해결 문제**: 상위 클래스에서 알고리즘의 골격(전체 뼈대)만 정의하고, 세부적인 단계의 구체적 구현은 하위 클래스에서 상속을 통해 재정의하도록 합니다.
- **지문 식별 단서**: **"알고리즘의 뼈대(골격) 정의"**, **"하위 클래스에서 구체적 단계 구현"**, **"일부 단계의 재정의"**
    

시험장에서 지문 분석 시, 위의 **"지문 식별 단서"** 단어가 문장 안에 한 단어라도 보인다면 망설임 없이 해당 디자인 패턴 이름을 영문(또는 국문)으로 기입하시면 단번에 정답을 확보할 수 있습니다!

## 요구사항
정보처리기사 실기 시험에서 최신 기출 트렌드로 급부상한 **"요구사항 확인"** 단원의 핵심 요약 정리입니다.

이 영역은 지문에서 예시를 던져주고 그것이 어떤 개념에 해당하는지 고르는 단답형이나, 개념 간의 차이점을 구별하는 문제로 출제됩니다.

## 1. 기능 요구사항 vs 비기능 요구사항 (단골 출제)

시스템이 무엇을 해야 하는지(기능)와 어떻게 작동해야 하는지(품질/제약)를 구별하는 유형입니다.

- **기능 요구사항 (Functional Requirements)**
    - **정의**: 시스템이 실제 제공해야 하는 **기능, 입력, 출력, 데이터, 연산**에 대한 요구사항입니다.
    - **지문 식별 단서**: ~기능을 제공해야 한다, ~를 계산해야 한다, ~를 입력받아 ~를 출력한다.
    - **예시**: 사용자는 로그인을 할 수 있어야 한다, 장바구니에 상품을 담으면 금액이 합산되어야 한다.
- **비기능 요구사항 (Non-functional Requirements)**
    - **정의**: 시스템의 성능, 보안, 품질, 제약사항 등 **품질적 속성 및 시스템 구축 환경**에 대한 요구사항입니다.
    - **지문 식별 단서**: 성능, 보안, 가용성, 호환성, 제약조건, 시스템 환경
    - **예시**: 결제 요청은 3초 이내에 완료되어야 한다(성능), 개인정보는 암호화하여 저장되어야 한다(보안).
        

## 2. 요구사항 개발 프로세스 (순서 및 정의)

요구사항을 처리하는 4단계의 고유 순서와 각 단계의 특징을 묻습니다.

> **도출(Elicitation) $\rightarrow$ 분석(Analysis) $\rightarrow$ 명세(Specification) $\rightarrow$ 검증(Verification)**

- **1단계: 요구사항 도출 (Elicitation / 수집)**
    - **핵심**: 이해관계자(고객, 개발자 등) 간의 소통을 통해 요구사항이 어디에 있고 어떻게 수집할지 결정하는 단계입니다.
    - **방법**: 인터뷰, 설문조사, 브레인스토밍, 워크숍, **워크플로우 분석** 등
- **2단계: 요구사항 분석 (Analysis)**
    - **핵심**: 도출된 요구사항 중 모호하거나 충돌하는 부분을 해결하고, 요구사항의 타당성을 조사하여 비용과 일정을 할당하는 단계입니다.
    - **방법**: 자료 흐름도(DFD), 자료 사전(DD) 등 **요구사항 분석 모델링** 수행
- **3단계: 요구사항 명세 (Specification)**
    - **핵심**: 분석된 요구사항을 바탕으로 체계적으로 검토, 평가, 승인될 수 있도록 문서화(요구사항 명세서 작성)하는 단계입니다.
    - **특징**: 설계자가 이해하기 쉽도록 정밀하고 명확하게 기록해야 합니다.
- **4단계: 요구사항 검증 (Verification / 확인)**
    - **핵심**: 작성된 요구사항 명세서가 사용자의 요구를 만족하는지, 모순이 없는지, 표준에 맞게 작성되었는지 **검토하고 확인**하는 단계입니다.
    - **방법**: **동료 검토(Peer Review), 워크스루(Walkthrough), 인스펙션(Inspection)**
        

## 3. 비기능 요구사항의 주요 품질 특성 분류

비기능 요구사항 설명에서 등장하는 핵심 키워드별 세부 속성 매칭입니다.

- **성능 (Performance)**: 시스템의 처리량, 반응 시간, 자원 효율성 등을 의미합니다. (예: "1초 이내 응답")
- **보안성 (Security)**: 권한이 없는 사용자의 접근을 차단하고 데이터의 무결성과 기밀성을 유지하는 능력입니다. (예: "암호화")
- **신뢰성 (Reliability)**: 시스템이 소프트웨어 결함 없이 **주어진 기간 동안 오류 없이 동작**할 수 있는 확률입니다.
- **가용성 (Availability)**: 사용자가 원하는 시점에 **정상적으로 서비스를 제공**할 수 있는 능력(가동률)입니다. (예: "365일 24시간 중단 없는 서비스")
- **운영 (Operation)**: 시스템 운영 시 필요한 제약이나 지침입니다.
- **자원 (Resource)**: 하드웨어 메모리, CPU, 네트워크 대역폭 등 시스템이 사용하는 리소스 한계입니다.
- **이식성 (Portability)**: 다양한 하드웨어나 운영체제(OS) 환경에서도 **쉽게 변형되어 구동될 수 있는 능력**입니다.
- **유지보수성 (Maintainability)**: 결함이 발생했을 때 얼마나 **쉽게 수정, 변경, 확장**할 수 있는가에 대한 능력입니다.
    

## 4. 요구사항 추적성 (Traceability)

- **정의**: 요구사항의 제안부터 시작하여 분석, 명세, 설계, 구현, 테스트에 이르기까지 **소프트웨어 생명주기(SDLC) 전 과정에서 요구사항의 변경과 발전 과정을 추적할 수 있는 능력**입니다.
- **시험 출제 포인트**: 시스템 변경 시 파급 효과를 분석하거나, 특정 요구사항이 누락되지 않고 제대로 구현·테스트 되었는지 검증하기 위해 "요구사항 추적 매트릭스(추적표)"를 활용한다는 설명이 나오면 정답은 추적성(Traceability)입니다.
    

시험장에서 이론 단답형 지문에 "기능적 요구", "비기능적 요구" 등의 명칭을 적을 때 철자에 유의하시고, 4대 프로세스(도출-분석-명세-검증)의 순서를 배열하거나 빈칸을 채우는 문제를 최우선으로 선별하여 복습하시기 바랍니다!

# 프로토콜, 계층

## 1. 서브넷 마스크 비트 수($/n$)와 8진수 공식

IP 주소는 총 32비트이며, 8비트씩 4개의 옥텟(마디)으로 구분됩니다. 서브넷 마스크의 $/n$ 표기법(CIDR)은 "앞에서부터 1의 개수가 $n$개 있다"는 뜻입니다.

- **풀이 요령**: $n$을 8로 나누어 어느 옥텟(마디)에서 분할이 일어나는지 찾습니다.
    - `/24` $\rightarrow$ `255.255.255.0` (앞의 3마디가 255로 꽉 찬 상태)
    - `/26` $\rightarrow$ 앞의 3마디는 `255.255.255`이고, **마지막 4번째 옥텟**에서 변형이 일어남 ($26 - 24 = 2$비트 사용)

### 서브넷 값 암기표
마지막 옥텟 마디를 10진수로 치환합니다.
- 1비트 ($/25$) $\rightarrow$ `1 0 0 0 0 0 0 0` -> **128** ($2^7$)
- 2비트 ($/26$) $\rightarrow$ `1 1 0 0 0 0 0 0` -> **192** ($2^7$+$2^6$)
- 3비트 ($/27$) $\rightarrow$ `1 1 1 0 0 0 0 0` -> **224** ($2^7$+$2^6$+$2^5$)
- 4비트 ($/28$) $\rightarrow$ `1 1 1 1 0 0 0 0` -> **240** ($2^7$+$2^6$+$2^5$+$2^4$)

## 2. 호스트 비트 수와 블록 크기 계산 (핵심 키(Key))

모든 문제 풀이의 출발점은 "블록 크기(구간 간격)"를 구하는 것입니다.

- **호스트 비트 수**: 전체 32비트에서 서브넷 비트($n$)를 뺀 나머지 공간입니다.
    - 공식: $\text{호스트 비트 수} = 32 - n$
    - 예시: `/26` 이면 호스트 비트는 $32 - 26 = 6$비트입니다.
- **블록 크기(마디의 크기)**: 하나의 서브넷이 차지하는 전체 IP의 개수(범위 간격)입니다.
    - 공식 1: $2^{\text{호스트 비트 수}}$
    - 공식 2: $256 - \text{해당 마디의 서브넷 마스크 값}$
    - 예시 (`/26` 일 때): $2^6 = 64$ 또는 $256 - 192 = \mathbf{64}$ (즉, 64개씩 구간이 끊어짐)
        

## 3. 네트워크 / 브로드캐스트 / 사용 가능 호스트 도출 기법

**실전 예제**: `192.168.1.100/26` 데이터가 주어졌을 때 핵심 요소를 도출해 보겠습니다.

1. **구간(블록) 나누기**: 블록 크기가 `64`이므로, 마지막 마디는 64 배수로 구간이 쪼개집니다.
    
    - [1구간] 0 ~ 63
    - [2구간] **64 ~ 127** $\leftarrow$ 문제의 정수 `100`이 이 구간에 속함!
    - [3구간] 128 ~ 191
        
2. **네트워크 주소**: 해당 구간의 **가장 첫 번째 주소**입니다.
    
    - 결과: `192.168.1.64`
        
3. **브로드캐스트 주소**: 해당 구간의 **가장 마지막 주소**입니다.
    
    - 결과: `192.168.1.127`
        
4. **사용 가능한 첫 번째 호스트**: 네트워크 주소의 바로 다음 번호($+1$)입니다.
    
    - 결과: `192.168.1.65`
        
5. **사용 가능한 마지막 호스트**: 브로드캐스트 주소의 바로 앞 번호($-1$)입니다.
    
    - 결과: `192.168.1.126`
        
6. **사용 가능한 총 호스트 수**: 전체 블록 크기에서 네트워크 주소와 브로드캐스트 주소 2개를 제외합니다.
    
    - 공식: $2^{\text{호스트 비트 수}} - 2$
    - 결과: $64 - 2 = \mathbf{62}$개
        

## 4. 두 IP가 같은 네트워크인지 판별하는 방법

시험에서 무조건 출제되는 응용 유형입니다.

- **판별 공식**: 두 IP 주소 각각에 대해 위에서 배운 방식으로 **"네트워크 주소"를 도출한 뒤, 그 값이 서로 완벽히 일치하는지** 비교합니다.
    

> **예시**: A: `192.168.1.45/26`과 B:`192.168.1.70/26`은 같은 네트워크인가?
>
> 1. **조건 확인**: 두 IP 모두 `/26`이므로 0의 개수는 6개.
> 2. **블록 크기**: 2^6 = **64** (64개씩 끊어지는 동네)
> 3. **네트워크 범위 쪼개기 (64의 배수)**:
>    - [0번 동네] 0 ~ 63
>    - [1번 동네] 64 ~ 127
> 4. **두 IP의 위치 확인**:
>    - A: 끝자리 **45**가 속한 구간: 0 ~ 63 ➔ 네트워크 주소(**가장 첫 번째 주소**): 192.168.1.0
>    - B: 끝자리 **70**이 속한 구간: 64 ~ 127 ➔ 네트워크 주소: 192.168.1.64
> 
> 🎯 **결론**: 두 IP의 네트워크 주소가 다르므로 "다른 네트워크에 속한다"가 정답입니다.

**💡 시험장 문제풀이 팁:**

문제를 받으면 서브넷 비트 수만 보고 "256에서 그 값을 뺀 숫자(블록 크기)"를 시험지 여백에 먼저 적으세요. 그 숫자의 배수(0, 64, 128…)를 나열한 뒤 주어진 IP의 마지막 자리가 어느 서브셋 경계선 사이에 안착하는지만 찾으면, 굳이 이진수로 일일이 변환하지 않고도 10초 만에 실수를 제로화하여 완벽한 정답을 적어낼 수 있습니다. LNG 단답형 빈칸 채우기에 절대 낚이지 마세요!

1. **경계 옥텟을 찾는다**: 서브넷 마스크에서 255도 아니고 0도 아닌 마디의 위치.
2. **경계값을 구한다**: 주어진 IP 주소에서 '경계 옥텟' 자리에 적혀 있는 숫자 그대로 가져오기.
3. **블록 크기를 구한다**: 256 - [경계 옥텟의 10진수 서브넷 마스크 값]
4. **네트워크 범위를 쪼갠다**: 0부터 시작해서 블록 크기를 계속 더해가며 배수를 나열한다.
5. **시작값을 구한다**: 쪼갠 범위(배수) 중 '경계값'보다 작거나 같으면서 가장 큰 숫자를 선택한다.
6. **네트워크 주소 마무리**: 경계 옥텟 자리에 '시작값'을 넣고, 그 뒤에 남은 영역은 모두 0으로 채운다.

💡 **브로드캐스트 주소 구하기 규칙**
- 경계 옥텟 자리에는 **[다음 범위 시작값 - 1]**을 넣는다.
- 그 뒤에 남은 호스트 영역이 있다면 모두 가장 큰 숫자인 **255**로 채운다.

## 1. OSI 7계층 핵심 요약 (장비 및 프로토콜 매칭)

지문에서 계층의 설명, 대표 장비, 프로토콜을 던져주고 계층명이나 영문 약어를 채우는 유형입니다.

- **7계층 - 애플리케이션(응용) 계층** : 사용자가 네트워크에 접근할 수 있도록 인터페이스 제공. (HTTP, HTTPS, FTP, DNS, SSH, DHCP)
- **6계층 - 프레젠테이션(표현) 계층** : 데이터의 암호화, 압축, 구문 변환 및 포맷 결정. (JPEG, MPEG)
- **5계층 - 세션 계층** : 송수신 호스트 간의 프로세스 연결 설정, 유지, 동기 제어. (RPC, NetBIOS)
- **4계층 - 전송 계층** : 프로세스 간의 **종단 간(End-to-End) 신뢰성 있고 투명한 데이터 전송** 보장. 장비: **L4 스위치** / 프로토콜: **TCP, UDP**
- **3계층 - 네트워크 계층** : 단말기 간의 데이터 전송을 위한 **최적의 경로 선택(라우팅) 및 패킷 전달**. 장비: **라우터, L3 스위치** / 프로토콜: **IP, ARP, RARP, ICMP**
- **2계층 - 데이터 링크 계층** : 물리적 회선을 통하여 인접한 노드 간의 **신뢰성 있는 정보 전송(흐름 제어, 오류 제어)** 보장. 장비: **브리지, 스위치(L2)** / 프로토콜: **HDLC, PPP**
- **1계층 - 물리 계층** : 전송 매체를 통해 비트 스트림을 전기적 신호로 변환하여 물리적 전송. 장비: **허브, 리피터**
    

## 2. TCP vs UDP 비교

- **TCP (Transmission Control Protocol)**
    - **키워드**: **연결 지향형**, **신뢰성 보장**, **흐름 제어 / 혼잡 제어**, 가상 회선 방식, 양방향 전송
- **UDP (User Datagram Protocol)**
    - **키워드**: **비연결형**, 신뢰성 없음, **속도 빠름**, 스트리밍/실시간 서비스, 비트 위주의 패킷 전송, 헤더 구조가 단순함
        

## 3. TCP 핸드셰이크 제어 플래그 흐름

정확한 제어 플래그(`SYN`, `ACK`, `FIN`)의 송수신 순서를 매칭할 수 있어야 합니다.

### 1) TCP 3-Way Handshake (연결 설정 시)

1. **클라이언트 $\rightarrow$ 서버**: `SYN` (연결 요청)
2. **서버 $\rightarrow$ 클라이언트**: `SYN + ACK` (요청 수락 및 서버측 연결 요청)
3. **클라이언트 $\rightarrow$ 서버**: `ACK` (서버 요청 수락 및 연결 완료)
    

### 2) TCP 4-Way Handshake (연결 종료 시)

1. **클라이언트 $\rightarrow$ 서버**: `FIN` (연결 종료 요청)
2. **서버 $\rightarrow$ 클라이언트**: `ACK` (종료 요청 수신 확인, 남아있는 데이터 전송 대기)
3. **서버 $\rightarrow$ 클라이언트**: `FIN` (서버측 종료 준비 완료 및 종료 요청)
4. **클라이언트 $\rightarrow$ 서버**: `ACK` (최종 확인 후 소켓 완전히 닫힘)
    

## 4. 핵심 네트워크 프로토콜 구별 단서

- **ARP (Address Resolution Protocol)**
    - **구별 단서**: 논리적 주소인 **IP 주소를 물리적 주소인 MAC 주소로 변환**하는 프로토콜.
- **RARP (Reverse ARP)**
    - **구별 단서**: 호스트가 자신의 물리적 주소(**MAC 주소)를 알고 있을 때, 논리적 IP 주소를 서버로부터 알아내기 위해 사용**하는 프로토콜.
- **DNS (Domain Name System)**: 도메인 네임(문자)을 IP 주소(숫자)로 상호 변환해 주는 분산 데이터베이스 시스템.
- **DHCP (Dynamic Host Configuration Protocol)**: 네트워크 호스트에게 **IP 주소를 동적으로 자동 할당**해 주는 프로토콜.
- **ICMP (Internet Control Message Protocol)**: IP 패킷 전송 중 발생하는 **오류 보고 및 진단**을 위해 메시지를 제어하는 프로토콜 (대표 명령어로 `ping`이 있음).
- **HTTP vs HTTPS**: HTTP는 평문 전송으로 보안에 취약함. 여기에 **SSL/TLS 암호화 프로토콜을 결합**하여 보안을 강화한 프로토콜이 **HTTPS** (포트번호: HTTP는 `80`, HTTPS는 `443`).
- **SSH (Secure Shell)**: 암호화 메커니즘이 없는 Telnet, Rsh 등을 대체하여 **원격 호스트에 안전하게 접속**하기 위해 암호화 및 인증을 지원하는 프로토콜 (포트번호: `22`).
    

## 5. 라우팅 프로토콜 (IGP 내부 라우팅 분류)

자율 시스템(AS) 내부에서 경로를 설정하는 프로토콜의 대조적인 특징입니다.

- **RIP (Routing Information Protocol)**
    - **핵심 키워드**: **거리 벡터(Distance Vector)** 알고리즘, **홉 카운트(Hop Count)** 기준(최대 15홉 제한, 16홉은 도달 불가능), 소규모 네트워크용, 벨만-포드 알고리즘 기반.
- **OSPF (Open Shortest Path First)**
    - **핵심 키워드**: **링크 상태(Link State)** 알고리즘, **다익스트라(Dijkstra) 최단 경로** 알고리즘 기반, 대규모 네트워크용, 네트워크 변화 발생 시에만 갱신 정보 전송.
        

## 6. HDLC 프레임 및 동작 모드 (기출 핵심)

데이터 링크 계층의 대표적인 비트 위주 프로토콜입니다.

### 1) HDLC 프레임 종류 (3가지)

- **정보 프레임 (I-Frame, Information Frame)**: 사용자 데이터(제어 정보 포함)를 전달하거나 피기백킹을 통한 수신 확인(ACK)을 수행할 때 사용.
- **감독 프레임 (S-Frame, Supervisory Frame)**: 정보 프레임의 전송 흐름 제어, 오류 제어(응답, 거부 등)를 위해 사용 (실제 사용자 데이터는 미포함).
- **비번호 프레임 (U-Frame, Unnumbered Frame)**: 링크의 **연결 설정 및 해제, 비정상 오류 회복** 등 링크 제어 관리 목적으로 사용 (순서 번호가 없음).
    

### 2) HDLC 동작 모드 (3가지)

- **정규 응답 모드 (NRM, Normal Response Mode)**: 종속국(Subordinate)은 주국의 허가(Poll)가 있을 때만 송신할 수 있는 불균형 구성 모드.
- **비동기 응답 모드 (ARM, Asynchronous Response Mode)**: 종속국이 주국의 허가 없이도 송신을 개시할 수 있는 불균형 구성 모드.
- **비동기 균형 모드 (ABM, Asynchronous Balanced Mode)**: 혼합국(주국+종속국 권한)끼리 구성되어, **누구나 허가 없이 대등하게 송신**할 수 있는 균형 구성 모드 (가장 널리 쓰임).
    

## 7. 오류 제어 및 정정 기술 (CRC, 패리티, 해밍코드)

- **CRC (Cyclic Redundancy Check, 순환 중복 검사)**
    - **특징**: 다항식 코드를 이용하여 에러를 검출하는 방식으로, **데이터 링크 계층에서 가장 널리 사용되는 강력한 오류 검출 기법**.
- **패리티 비트 (Parity Bit)**
    - **특징**: 1비트의 오류만 검출(정정 불가)할 수 있는 기법으로, 1의 개수를 짝수(우수) 또는 홀수(기수)로 맞춰 전송.
- **해밍 코드 (Hamming Code)**
    - **특징**: 수신 측에서 **오류를 스스로 검출하고 '직접 정정(Correction)'까지 가능**한 전방 오류 수정(FEC) 방식의 대표적인 코드.
        

최근 기출문제 분석에 입각했을 때 영문 약어(ABM, ABM의 균형 모드 여부, S-Frame 명칭 등)나 특정 프로토콜의 주소 변환 관계를 정확하게 매칭하는 주관식 단답형 문장 위주로 복습을 진행하시기 바랍니다!

# 보안

## 1. 웹 애플리케이션 공격 유형

주로 웹 서버, 데이터베이스, 브라우저 간의 취약점을 파고드는 공격입니다.

- **SQL Injection (SQL 삽입)**
    - **공격 대상**: 데이터베이스(DB) 및 웹 애플리케이션
    - **대표 행위**: 입력창에 악의적인 SQL 구문을 삽입하여 DB 데이터를 무단 조회, 수정, 삭제함
    - **구별 단서**: **"입력값 검증 부재"**, **"악의적인 SQL 구문"**, **"DB 쿼리문 변경"**
- **XSS (Cross-Site Scripting, 크로스 사이트 스크립팅)**
    - **공격 대상**: 일반 사용자(웹 브라우저)
    - **대표 행위**: 게시판 등에 악성 스크립트를 삽입하여 이를 열람한 다른 사용자의 쿠키/세션을 탈취함
    - **구별 단서**: **"악성 스크립트"**, **"사용자 브라우저에서 실행"**, **"쿠키 및 세션 탈취"**
- **CSRF (Cross-Site Request Forgery, 사이트 간 요청 위조)**
    - **공격 대상**: 특정 웹 사이트의 서버 (사용자의 권한 대행)
    - **대표 행위**: 사용자가 자신의 의지와 무관하게 공격자가 의도한 행위(비밀번호 변경, 송금 등)를 특정 웹 서버에 요청하도록 변조함
    - **구별 단서**: **"사용자가 의도하지 않은 요청"**, **"수정/등록/송금 등 특정 행위 강제"**, **"XSS와의 차이점: 타깃이 브라우저가 아닌 서버"**
- **디렉터리 순회 (Directory Traversal)**
    - **공격 대상**: 웹 서버 파일 시스템
    - **대표 행위**: 파일 경로에 `../` 과 같은 상위 디렉터리 이동 문자를 삽입하여 비공개 시스템 파일에 강제 접근함
    - **구별 단서**: **"파일 경로 조작"**, **"`../` 또는 `..\` 문자"**, **"시스템 외부 파일 접근"**
        

## 2. 네트워크 및 인프라 공격 유형

네트워크 프로토콜의 취약점이나 자원(Resource)의 한계를 고갈시키는 공격입니다.

- **SYN Flooding**
    - **공격 대상**: 서버의 연결 가용성 (TCP 핸드셰이크 세션)
    - **대표 행위**: 대량의 SYN 패킷만 보내고 ACK를 보내지 않아 서버의 접속 대기 큐(Backlog Queue)를 가득 채워 마비시킴
    - **구별 단서**: **"TCP 3-Way Handshake"**, **"SYN 패킷 대량 전송"**, **"ACK 미전송(Half-Open)"**, **"접속 대기 큐 고갈"**
- **세션 하이재킹 (Session Hijacking)**
    - **공격 대상**: 인증된 정상 사용자의 '세션(Session)'
    - **대표 행위**: 정상적인 인증을 거쳐 연결된 사용자-서버 간의 세션 ID를 가로채어 정상 사용자인 척 권한을 도용함
    - **구별 단서**: **"세션 ID 탈취"**, **"인증 단계 통과 후 가로채기"**, **"로그인 이후 연결 도용"**
- **스니핑 (Sniffing)**
    - **공격 대상**: 네트워크 상에 흐르는 데이터 패킷
    - **대표 행위**: 수동적으로 네트워크 트래픽을 도청하여 비밀번호 등 민감 정보를 몰래 엿봄
    - **구별 단서**: **"도청"**, **"수동적 공격"**, **"Promiscuous(무차별) 모드"**
- **스푸핑 (Spoofing)**
    - **공격 대상**: 네트워크 식별 정보 (IP, MAC, DNS 등)
    - **대표 행위**: 자신의 식별 정보를 신뢰할 수 있는 다른 대상으로 위장(속임)하여 시스템 변조나 권한을 획득함
    - **구별 단서**: **"눈속임/위장"**, **"자신의 identity를 변경"**
        

### ⚠️ 스푸핑 세부 유형 구별하기

|**유형**|**공격 대상**|**대표 행위**|**결정적 구별 단서**|
|---|---|---|---|
|**ARP 스푸핑**|LAN 내부 호스트의 MAC 주소 테이블|기짜 ARP 응답을 보내 공격자의 MAC 주소를 서버/라우터 주소인 것처럼 속임|**"LAN 내부(동일 네트워크)"**, **"MAC 주소 위장"**, **"위조된 ARP 응답"**|
|**DNS 스푸핑**|DNS 네임 서버 또는 클라이언트 캐시|도메인 이름에 대한 IP 주소 요청 시 가짜 IP 주소를 응답하여 피싱 사이트로 유도|**"도메인 네임"**, **"가짜 IP 주소 응답"**, **"DNS 캐시 포이즈닝"**|

## 3. 시스템 및 자원 공격 유형

운영체제(OS), 메모리 구조, 프로세스 실행 타이밍의 버그를 악용하는 공격입니다.

- **버퍼 오버플로 (Buffer Overflow)**
    - **공격 대상**: 메모리의 스택(Stack) 또는 힙(Heap) 영역
    - **대표 행위**: 정해진 버퍼의 크기보다 더 큰 데이터를 입력하여 인접한 메모리를 덮어쓰고, 반환 주소(Return Address)를 조작하여 악성 코드를 실행함
    - **구별 단서**: **"메모리 공간 초과"**, **"반환 주소(Return Address) 변조"**, **"스택/힙 영역"**
- **레이스 컨디션 (Race Condition / 경쟁 조건)**
    - **공격 대상**: 멀티스레드/멀티프로세스 환경의 실행 순서
    - **대표 행위**: 두 개 이상의 프로세스가 공통 자원에 동시 접근할 때 생기는 실행 타이밍의 틈(Gap)을 악용하여 권한을 탈취함
    - **구별 단서**: **"동시 접근(경쟁)"**, **"실행 순서 및 타이밍 악용"**
- **심볼릭 링크 공격 (Symbolic Link Attack)**
    - **공격 대상**: 파일 시스템의 링크 구조
    - **대표 행위**: 레이스 컨디션을 결합하여 임시 파일이 생성되는 순간, 이를 삭제하고 관리자 권한 파일로 연결되는 심볼릭 링크를 생성하여 엉뚱한 중요 파일을 수정하게 만듦
    - **구별 단서**: **"임시 파일 확인과 실제 사용 사이의 틈(TOCTOU)"**, **"바로 가기 파일 생성"**, **"권한 상승 및 중요 파일 변조"**
        

## 4. 사회공학 및 타깃형 공격 유형

기술적 취약점보다는 사람의 심리, 공급 가치 사슬, 특정 집단을 노리는 공격입니다.

- **워터링홀 (Watering Hole)**
    - **공격 대상**: 특정 기업이나 조직의 임직원 그룹
    - **대표 행위**: 표적이 자주 방문하는 정상 웹 사이트를 미리 감염시켜 두고, 표적이 방문했을 때 악성코드에 감염되도록 기다리는 덫을 놓음
    - **구별 단서**: **"사자 접견 구역(우물가)"**, **"표적이 자주 방문하는 사이트 감염"**, **"매복 공격"**
- **스피어피싱 (Spear Phishing)**
    - **공격 대상**: 특정 개인이나 정해진 타깃 조직의 담당자
    - **대표 행위**: 일반 불특정 다수가 아닌, 신뢰할 수 있는 지인이나 협력업체 정품 메일로 가장하여 정교하게 조준된 악성 메일을 보냄
    - **구별 단서**: **"특정 개인/조직 정밀 조준"**, **"정교한 악성 이메일"**, **"창(Spear)으로 찌르듯 공격"**
- **공급망 공격 (Supply Chain Attack)**
    - **공격 대상**: 최종 타깃 소프트웨어의 개발/제조/배포 공급망 과정
    - **대표 행위**: 소프트웨어 개발사의 빌드 서버나 업데이트 서버에 침투하여 정상적인 정품 소프트웨어 배포 패키지에 악성코드를 숨겨 배포함
    - **구별 단서**: **"개발 프로세스 침투"**, **"정상 업데이트 파일에 삽입"**, **"공급 가치 사슬 악용"**
- **랜섬웨어 (Ransomware)**
    - **공격 대상**: 사용자의 데이터 파일 전체
    - **대표 행위**: 파일을 복호화할 수 없도록 암호화한 뒤, 이를 인질로 삼아 돈을 요구함
    - **구별 단서**: **"파일 암호화"**, **"몸값(Ransom) 요구"**
- **스케어웨어 (Scareware)**
    - **공격 대상**: 사용자의 심리적 공포심
    - **대표 행위**: 가짜 바이러스 감염 경고창을 띄워 사용자를 겁준 뒤, 가짜 백신 소프트웨어를 구매하도록 유도함
    - **구별 단서**: **"공포심 유발"**, **"가짜 경고"**, **"허위 프로그램 구매 유도"**
        

시험장에서 문제를 만났을 때는 지문 전체를 독해하려 하지 마시고, 위의 **"결정적 구별 단서"** 단어가 튀어나오는지 스캔한 후 정답 명칭을 매칭하시면 헷갈리지 않고 정확히 답을 기입하실 수 있습니다!

정보처리기사 실기 시험의 소프트웨어 개발 보안 구축 단원에서 반드시 출제되는 **"보안 및 인증 핵심 메커니즘"** 요약 정리입니다.

이전 지침에 따라 **이미지는 일절 첨부하지 않고**, 오직 텍스트 기반의 명확한 설명과 결정적 식별 키워드로만 깔끔하게 정리해 드립니다.

## 1. 보안의 3대 요소 (단골 출제)

지문에서 예시 상황을 제시하고 어떤 요소가 침해되었는지 묻는 단답형 문제 유형입니다.

- **기밀성 (Confidentiality)**
    - **핵심**: 인가된(권한이 있는) 사용자만 정보에 접근할 수 있도록 제한하는 특성입니다.
    - **지문 식별 단서**: **"인가된 사용자만 접근"**, **"암호화"**, **"도청 차단"**
- **무결성 (Integrity)**
    - **핵심**: 정보가 인가되지 않은 방법으로 변경, 위조, 변조되지 않고 정확성과 완전성이 유지되는 특성입니다.
    - **지문 식별 단서**: **"오직 인가된 방법으로만 변경"**, **"위·변조 방지"**, **"해시 함수 검증"**
- **가용성 (Availability)**
    - **핵심**: 권한이 있는 사용자가 필요로 할 때 언제든지 시스템이나 데이터에 접근하여 사용할 수 있는 특성입니다.
    - **지문 식별 단서**: **"원하는 시점에 정상 사용"**, **"중단 없는 서비스"**, **"백업 / DoS 공격 방어"**
        

## 2. 인증(Authentication) vs 인가(Authorization)

서로 묶여서 오답을 유도하는 개념이므로 명확하게 분리해야 합니다.

- **인증 (Authentication)**
    - **개념**: 시스템에 접근하려는 사용자가 **"진짜 그 사람이 맞는지" 신원을 확인**하는 과정입니다.
    - **예시**: 아이디/비밀번호 입력, 공인인증서 검증, 생체인식(지문, 홍채)
- **인가 (Authorization)**
    - **개념**: 인증된 사용자에게 "특정 자원에 접근할 수 있는 권한을 부여"하는 과정입니다.
    - **예시**: 일반 사용자는 글읽기만 가능하고, 관리자는 시스템 설정을 바꿀 수 있는 권한을 가짐
        

## 3. 주요 인증 기술 (OTP, OAuth)

- **OTP (One-Time Password, 일회용 패스워드)**
    - **개념**: 무작위로 생성되는 **단 한 번만 사용할 수 있는 패스워드** 생성 시스템입니다.
    - **특징**: 고정된 비밀번호의 취약점(재전송 공격 등)을 보완하기 위해 사용하며, 동기화 방식(시간 동기식, 이벤트 동기식)이 존재합니다.
- **OAuth (Open Authorization)**
    - **개념**: 인터넷 사용자들이 비밀번호를 제공하지 않고, **다른 웹사이트 상의 자신들의 정보에 대해 접근 권한을 부여**할 수 있는 개방형 표준 프로토콜입니다.
    - **지문 식별 단서**: **"토큰 기반 권한 부여"**, **"간편 로그인(구글/카카오 계정으로 로그인)"**, **"API 접근 권한 대행"**
        

## 4. 접근 통제(Access Control) 3대 모델

자원에 접근할 수 있는 규칙을 정의하는 소프트웨어 보안의 기본 모델입니다.

- **DAC (Discretionary Access Control, 임의적 접근 통제)**
    - **핵심**: 자원의 **"소유자"가 자신의 판단에 따라** 다른 사용자에게 접근 권한을 부여합니다.
    - **지문 식별 단서**: **"소유자 중심"**, **"신원(Identity) 기반"**, **"권한 양도 가능"**
- **MAC (Mandatory Access Control, 강제적 접근 통제)**
    - **핵심**: 주체의 보안 등급과 객체의 보안 부류를 비교하여 **"시스템(관리자)"이 강제적으로 권한을 제어**합니다.
    - **지문 식별 단서**: **"보안 등급(상/중/하)"**, **"규칙/정책 기반"**, **"주체와 객체의 등급 비교"**
- **RBAC (Role-Based Access Control, 역할 기반 접근 통제)**
    - **핵심**: 사용자의 신원이 아닌, 조직 내에서 담당하는 **"역할(Role)"에 권한을 할당**하고 사용자를 그 역할에 맵핑합니다.
    - **지문 식별 단서**: **"직무/역할 기반"**, **"인사이동 시 유연한 대처"**, **"다산적 권한 관리 용이"**
        

## 5. 대칭키 vs 비대칭키(공개키) 암호화 알고리즘

암호화와 복호화에 사용하는 키의 성격에 따른 분류입니다.

- **대칭키 암호화**
    - **특징**: 암호화 키와 복호화 키가 "동일"합니다. 속도가 빠르지만 키 배송(전송) 문제가 발생합니다.
    - **알고리즘 종류**: **AES, DES, 3DES, SEED, ARIA, LEA** (영문 약어 단답형 대비)
- **비대칭키(공개키) 암호화**
    - **특징**: 암호화 키(공개키)와 복호화 키(개인키)가 **"서로 다릅니다"**. 키 관리가 쉽고 안전하지만 연산 속도가 느립니다.
    - **알고리즘 종류**: **RSA, ECC(타원곡선), ElGamal, Diffie-Hellman**
        

## 6. 해시 함수, 전자서명, 인증서

- **해시 함수 (Hash Function)**
    - **개념**: 임의의 길이를 가진 메시지를 입력받아 고정된 길이의 고유한 문자열(해시값)로 출력하는 단방향 함수입니다.
    - **특징**: 복호화가 불가능한 **단방향성**, 입력이 조금만 바뀌어도 결과가 완전히 바뀌는 **쇄도 효과**가 있으며, 알고리즘으로 **SHA-256, MD5** 등이 있습니다.
- **전자서명 (Digital Signature)**
    - **개념**: 송신자의 **"개인키"로 메시지를 암호화**하여 송신자가 진짜 본인임을 증명하고 부인을 방지하는 기술입니다.
    - **지문 식별 단서**: **"송신자 개인키로 암호화"**, **"수신자는 송신자의 공개키로 복호화"**, **"부인 방지(Non-repudiation)"**
- **인증서 (Digital Certificate)**
    - **개념**: 공개키에 대한 소유권을 검증하기 위해 신뢰할 수 있는 제3기관(CA)이 발행한 보증서입니다. 표준 규격으로 **X.509**가 자주 출제됩니다.
        

## 7. ISMS-P (정보보호 및 개인정보보호 관리체계)

- **개념**: 기업이 주요 정보자산을 보호하기 위해 수립·운영하는 정보보호 관리체계가 인증기준에 적합한지 심사하여 인증하는 제도입니다.
- **시험 출제 포인트**: 기본 3대 영역을 묻거나 빈칸을 채우는 형식으로 유도됩니다.
    
    1. 관리체계 수립 및 운영
    2. 보호대책 요구사항
    3. 개인정보 처리 단계별 요구사항
        

## 8. 시큐어 코딩(Secure Coding) 가이드 기본 원칙

소프트웨어 개발 보안 가이드에서 정하는 개발 단계별 기본 준수 보안 항목입니다.

- **입력데이터 검증 및 표현**: 프로그램 입력값에 대한 검증 누락이나 부적절한 형식으로 인해 발생하는 취약점 방지 (예: SQL Injection, XSS 방어)
- **보안 기능**: 인증, 인가, 암호화, 권한 관리 등을 부적절하게 구현했을 때 발생하는 취약점 방지
- **시간 및 상태**: 병렬 처리 시스템이나 멀티프로세스 환경에서 동시 자원 접근 시 발생하는 취약점 방지 (예: 레이스 컨디션 방어)
- **에러 처리**: 에러 메시지에 내부 시스템 구조나 디버깅 정보 등 민감한 정보가 노출되지 않도록 제어하는 원칙
- **코드 오류**: 타입 변환 오류, 부적절한 메모리 해제 등 개발자의 실수로 인해 발생하는 버그성 취약점 방지 (예: 널 포인터 역참조 방지)
- **캡슐화**: 내부 데이터나 핵심 로직이 외부에 부적절하게 노출되지 않도록 클래스를 은닉하고 묶어주는 원칙
