## 📝 정리

### 세션 하이재킹: 공격자가 인증된 사용자의 세션 ID를 탈취하여 재사용해 가장하는 공격
> 통신 중인 클라이언트와 서버 사이에서 **시퀀스 번호를 동기화하여 가로채서
- 시퀀스 번호: 패킷에 들어있는 데이터의 순서를 보장하기 위한번호
- 1. 모니터링
- 2. 공격자는 다음 패킷에 들어갈 시퀀스 번호를 계산
- 3. 공격자가 클라이언트보다 먼저 서버에 패킷을 보내서 시퀀스 번호를 높여버려 자신을 정상으로 인식시키고 실제 클라이언트의 요청을 무시하게 함
- 4. 탈취한 $SEQ$와 $ACK$ 번호를 사용하여 가공된 TCP 패킷을 서버에 전송하며 실제 클라이언트의 세션을 사용

네트워크 전송 계층의 핵심인 **TCP 연결 수립 과정(3-Way Handshake)**과 이를 공략하는 **세션 하이재킹**의 핵심 메커니즘을 백엔드 개발자 관점에서 체계적으로 요약해 드립니다.

## 🤝 TCP 3-Way Handshake: 연결의 시작

3-Way Handshake는 두 호스트가 데이터를 주고받기 전, 서로의 존재를 확인하고 **시퀀스 번호(Sequence Number)**를 동기화하는 과정입니다.

| **단계**  | **주체** | **플래그**       | **설명**                                     |
| ------- | ------ | ------------- | ------------------------------------------ |
| **1단계** | 클라이언트  | **SYN**       | 서버에게 연결 요청 및 자신의 초기 시퀀스 번호($ISN$) 전송       |
| **2단계** | 서버     | **SYN + ACK** | 요청 수락 확인 및 서버의 $ISN$ 전송 (클라이언트 번호 + 1로 응답) |
| **3단계** | 클라이언트  | **ACK**       | 서버의 번호를 확인하고 최종 연결 수립 (서버 번호 + 1로 응답)      |

> **💡 핵심 요약**
>
> "나 연결해도 돼? (**SYN**)" → "응, 나도 준비됐어. 확인했니? (**SYN-ACK**)" → "응, 확인했어. 시작하자! (**ACK**)"의 3단계 논리 구조입니다.

## 🏴‍☠️ TCP 세션 하이재킹: 연결의 탈취

이미 성립된 TCP 세션의 허점(시퀀스 번호의 신뢰성)을 이용해 공격자가 사용자를 가장하는 공격입니다.

### 1단계: 탐색 및 모니터링 (Sniffing)

- **핵심:** 통신 경로 중간에서 패킷을 가로채 현재 흐르고 있는 **IP, 포트 번호, 그리고 시퀀스 번호($SEQ$, $ACK$)**를 파악합니다.
- 공격자는 이 데이터를 확보해야 다음 단계를 설계할 수 있습니다.
    

### 2단계: 시퀀스 번호 계산 및 예측 (Calculation)

- **핵심:** 스니핑한 정보를 바탕으로 **서버가 다음에 받아들일 시퀀스 번호**를 정확히 계산합니다.
- TCP는 숫자가 논리적으로 맞으면 보낸 이가 누구인지 확인하지 않는다는 점을 악용합니다.
    

### 3단계: 클라이언트 비동기화 (Desynchronization)

- **핵심:** 진짜 클라이언트보다 먼저 **가짜 패킷**을 보내 서버의 시퀀스 번호를 높여버립니다.
- **결과:** 서버는 공격자를 정상으로 인식하게 되고, 뒤늦게 도착한 진짜 클라이언트의 요청은 "이미 처리된 번호"로 간주되어 무시됩니다.
    

### 4단계: 세션 장악 및 명령 주입 (Injection)

- **핵심:** 완전히 동기화된 시퀀스 번호를 사용하여 공격자가 직접 서버에 악성 페이로드(명령어)를 전송합니다.
- 서버는 공격자의 패킷을 정상적인 세션의 연속으로 신뢰하여 의심 없이 실행합니다.

### 🛡️ 백엔드 개발자를 위한 보안 팁

전송 계층에서의 하이재킹은 시퀀스 번호를 예측하는 것에서 시작됩니다. 이를 근본적으로 방어하기 위해서는 **애플리케이션 계층에서의 암호화(SSL/TLS)**가 필수입니다. 데이터가 암호화되어 있다면 공격자가 시퀀스 번호를 맞춰 패킷을 주입하더라도 서버에서 복호화에 실패하여 공격이 무력화됩니다.


네트워크 전송 계층에서 신뢰성 있는 연결을 수립하는 **3-Way Handshake**와 그 신뢰성의 허점을 공략하는 **TCP 세션 하이재킹**의 핵심 과정을 요약하여 정리합니다.

| **2단계** | 서버     | **SYN + ACK** | 요청 수락 확인 및 서버의 $ISN$ 전송 (클라이언트 번호 + 1로 응답) |

## 2. TCP 세션 하이재킹 4단계 핵심 요약

이미 연결이 수립(Established)된 세션에서 공격자가 시퀀스 번호를 가로채 정상 사용자를 밀어내고 세션을 탈취하는 과정입니다.

### 1단계: 탐색 및 스니핑 (Sniffing)

- **동작:** 공격자가 통신 경로 사이에 위치하여 클라이언트와 서버 간의 패킷 흐름을 모니터링함.
- **핵심:** 양측의 IP 주소, 포트 번호, 그리고 현재 통신 중인 **시퀀스 번호($SEQ$) 및 응답 번호($ACK$)** 정보를 획득함.
    

### 2단계: 시퀀스 번호 예측 (Calculation)

- **동작:** 스니핑한 데이터를 분석하여 서버가 다음에 받아들일 시퀀스 번호를 계산함.
- **핵심:** TCP가 패킷의 신원을 확인하는 유일한 수단인 '번호의 논리적 연속성'을 공략함.
    

### 3단계: 클라이언트 비동기화 (Desynchronization)

- **동작:** 공격자가 클라이언트보다 먼저 **위조된 패킷(Null Data 등)**을 보내 서버의 시퀀스 번호를 업데이트함.
- **핵심:** 서버는 공격자를 정상으로 인식하며, 이후 도착하는 실제 클라이언트의 패킷은 "이미 처리된 번호" 혹은 "잘못된 번호"로 간주되어 무시(Drop)됨.
    

### 4단계: 명령 주입 및 세션 장악 (Injection)

- **동작:** 서버와 동기화된 시퀀스 번호를 사용하여 공격자가 가공된 TCP 패킷을 직접 전송함.
- **핵심:** 서버는 공격자의 패킷을 신뢰하여 의심 없이 실행하며, 공격자는 탈취한 세션을 통해 시스템 권한 획득 등 악성 행위를 수행함.

## 🛡️ 대응 방안 요약

- **시퀀스 번호 난수화:** OS 커널 수준에서 $SEQ$ 번호 예측을 불가능하게 무작위 생성함.
- **암호화 프로토콜 적용:** **SSL/TLS(HTTPS)** 등을 사용하여 데이터를 암호화함. 데이터가 암호화되면 공격자가 시퀀스 번호를 맞춰 패킷을 주입하더라도 복호화 과정에서 무결성 검증에 실패하여 차단됨.

---

## **1. TCP 3-Way Handshake 핵심 요약**

3-Way Handshake의 핵심 목적은 통신 양단이 데이터를 정확한 순서로 주고받기 위해 **시퀀스 번호(Sequence Number)를 동기화**하는 것입니다.

|**단계**|**플래그**|**동작 및 의미**|**비고**|
|---|---|---|---|
|**1단계**|**SYN**|클라이언트가 서버에 접속 요청을 보내며 자신의 초기 시퀀스 번호($ISN$)를 전달함.|"나 연결할게, 내 번호는 $A$야."|
|**2단계**|**SYN+ACK**|서버가 요청을 수락하며 자신의 $ISN$을 전송함. 응답 번호($ACK$)는 $A+1$로 설정함.|"알았어, 내 번호는 $B$고, 네 $A$번 잘 받았어."|
|**3단계**|**ACK**|클라이언트가 서버의 번호를 확인했다는 응답($B+1$)을 보내며 연결을 최종 수립함.|"확인했어, 이제 통신 시작하자."|

---

## **2. TCP 세션 하이재킹 4단계 핵심 요약**

이미 연결이 수립(Established)된 상태에서 공격자가 시퀀스 번호를 탈취하여 클라이언트의 권한을 뺏는 과정입니다.

### **1단계: 탐색 및 스니핑 (Sniffing)**

공격자가 통신 경로 사이에 침투하여 클라이언트와 서버 간에 오가는 패킷을 실시간으로 감시합니다.

- **핵심:** 현재 세션에서 사용 중인 **IP 주소, 포트 번호, 시퀀스 번호($SEQ$) 및 응답 번호($ACK$)**를 확보합니다.
    

### **2단계: 시퀀스 번호 예측 (Calculation)**

확보한 데이터를 분석하여 서버가 다음에 받아들일 시퀀스 번호($Next\_SEQ$)를 정확히 계산합니다.

- **핵심:** TCP가 보낸 사람의 신원을 확인하지 않고 **'번호의 연속성'**만 신뢰한다는 점을 이용합니다.
    

### **3단계: 클라이언트 비동기화 (Desynchronization)**

공격자가 실제 클라이언트보다 먼저 위조된 패킷을 전송하여 서버의 시퀀스 번호를 강제로 높여버립니다.

- **핵심:** 서버는 공격자를 정상으로 인식하게 되며, 이후 도착하는 실제 클라이언트의 패킷은 **"이미 처리된 번호"**로 간주되어 무시(Drop)됩니다.
    

### **4단계: 명령 주입 및 세션 장악 (Injection)**

서버와 완전히 동기화된 시퀀스 번호를 사용하여 공격자가 직접 악성 페이로드(명령어)를 서버에 전송합니다.

- **핵심:** 서버는 공격자의 패킷을 정상적인 세션의 연장선으로 신뢰하여 실행하며, 공격자는 탈취한 세션으로 시스템을 제어합니다.
