## 응용계층: HTTP 세션 하이재킹_인증된 사용자의 세션ID를 탈취해 재사용하여 가장하는 공격
HTTP 프로토콜의 **무상태성(Stateless)**을 보완하기 위해 도입된 '세션 ID'를 공격 대상으로 합니다.
- **작동 방식:** 사용자가 로그인한 후 서버로부터 발급받은 **Session ID(주로 쿠키에 저장)**를 스니핑, XSS(Cross-Site Scripting), 혹은 물리적 탈취를 통해 가로챕니다.
- **결과:** 공격자는 탈취한 세션 ID를 자신의 브라우저 쿠키에 삽입하여 해당 사용자의 권한을 획득합니다.
- **방어 전략:**
	* 쿠키에 `HttpOnly` 및 `Secure` 플래그 설정
    - 세션 타임아웃 및 동시 접속 제어
    - 로그인 시마다 세션 ID 재생성

## 전송계층: TCP 세션 하이재킹_인증된 사용자의 시퀀스번호를 탈취하여 가장하는 공격

이미 인증을 마친 사용자(Client)와 서버 사이의 **시퀀스 번호(Sequence Number)**를 가로채, 공격자가 사용자의 권한을 그대로 이어받는 전송 계층 공격입니다.

### 1. 공격의 근본적 원인: "무결성 검증의 부재"

TCP는 패킷을 받을 때 다음 세 가지 정보가 일치하면 정당한 사용자로 간주합니다.

- **Source IP / Port**: 어디서 왔는가?
- **Destination IP / Port**: 어디로 가는가?
- **Sequence Number (SEQ)**: 순서가 맞는가?
    

> **핵심 문제:** TCP 헤더에는 보낸 이가 진짜인지 확인하는 **암호화된 신분증(Token)**이 없어서, 번호만 맞추면 커널은 의심 없이 데이터를 수락합니다.
---
### 2. TCP 3-Way Handshake와 시퀀스 번호

세션 수립 시 양단간의 논리적 통로를 만들기 위해 시퀀스 번호를 동기화합니다.
> 요청(**SYN**)
> 응답(ACK)
> 시퀀스번호(ISN) : 자신을 식별하기위한 번호

1. 클라이언트가 **SYN** 요청: 클라이언트의 ISN를 임의로 생성해 전송
2. 서버가 ACK와 SYN를 함께 전송
	- ACK 응답: 클라이언트 ISN에다가 1를 더한 값을 수락 응답으전송
	- **SYN** 요청: 서버도 자신의 ISN를 임의로 생성해 전송
3. 클라이언트가 ACK 응답: 받은 서버의 ISN에 1을 더해 전송하며 세션이 연결됨
- 이후 통신에서는 전송하는 바이트 크기만큼 시퀀스 번호를 증가시키며 데이터의 누락 및 순서를 검증합니다.
---

### 3. 세션 하이재킹 4단계 프로세스

공격의 핵심은 **"클라이언트보다 먼저 서버가 대기 중인 번호를 주입하여 주도권을 뺏는 것"** 입니다.

| **단계**       | **주요 행위**                           | **결과**                    |
| ------------ | ----------------------------------- | ------------------------- |
| **탐색 및 스니핑** | 통신 경로에서 패킷을 실시간 감시하며 SEQ, ACK 번호 탈취 | 현재 세션 정보 확보               |
| **번호 예측**    | 서버가 다음에 기다릴 시퀀스 번호를 계산              | 주입할 패킷 설계 완료              |
| **비동기화**     | 위조 패킷을 주입해 서버의 시퀀스 번호를 강제로 높임       | **실제 클라이언트 패킷은 무시(Drop)** |
| **세션 장악**    | 서버와 동기화된 번호로 악성 명령(Payload) 전송      | 공격자가 클라이언트 권한 획득          |

---

### 4. 핵심 방어 전략: HTTPS 사용(SSL/TLS)

세션 하이재킹을 원천 차단하기 위해서는 전송 계층 위에 **암호화 계층**을 추가해야 합니다.

- **암호화의 효과**: 공격자가 시퀀스 번호를 알아내어 패킷을 주입하더라도, 패킷 내부의 **데이터가 암호화**되어 있습니다.
- **무결성 검증**: 서버는 수신한 패킷을 복호화하는 과정에서 키가 맞지 않거나 데이터가 조작되었음을 즉시 감지하고 차단합니다.

## 공격기법 - 서비스거부(Dos) 및 위장 공격
### 스푸핑(Spoofing): 신뢰받는 사용자인것처럼 데이터 패킷의 헤더정보를 위조해 위장 공격
- IP 스푸핑: 자신의 IP를 신뢰받는 내부 IP주소로 위장
- ARP 스푸핑: IP를 MAC으로 변환하는 ARP 프로토콜을 속여 자신의 MAC(하드웨어) 주소를 신뢰하게 업데이트
- DNS 스푸핑: 사용자가 주소를 브라우저에 입력해 시스템이 DNS 서버에 실제 IP를 물을때 DNS 서버가 응답전에 빠르게 위조된 응답으로 속임
### SYN Flooding: SYN 패킷만 대량 전송해 연결대기자원을 고갈시키는 Dos 공격
- SYN 패킷만 대량 전송해 서버가 SYN+ACK로 응답해도 마지막 ACK를 안보내 서버가 타임아웃까지 대기하느라 새로운 사용자의 SYN 요청을 수락할수없게 함

### DDoS : 다수의 공격자로 동시에 트래픽 발생시키는 분산(Distributed) Dos
- 대역폭공격: 네트워크 회선 용량 초과하게하는 데이터 전송
- 자원소모공격: SYN FLOODING

### Slowloris: 장기간 HTTP 연결로 서버의 '동시'접속자원을 소모시켜 서비스거부(Dos)시키는
- HTTP 헤더의 끝을 알리는 빈줄을 전송하지 않으면서 계속 의미없는 요청을 보내 적은 트래픽으로 동시접속자원을 점유

## IP주소와 서브넷마스크를 주고, 수신할수있는 ip 주소들을 구해라
### 📘 주요 용어 정리
 
- **IP 주소 (IP Address):** 네트워크상에서 장치가 가지는 고유한 논리적 주소입니다.
- **서브넷 (Subnet):** 하나의 커다란 네트워크를 효율적으로 관리하기 위해 더 작은 단위로 분할한 **부분 망**입니다.
- **서브넷 마스크 (Subnet Mask):** IP 주소에서 어디까지가 **네트워크 주소**이고, 어디서부터가 **호스트(기기) 주소**인지를 구분하는 기준점입니다.
- **네트워크 주소 (Network ID):** 해당 서브넷의 **시작 주소**이며, 네트워크 자체를 대표하는 주소이므로 개별 장치에 할당할 수 없습니다.
- **브로드캐스트 주소 (Broadcast ID):** 해당 서브넷에 속한 **모든 장치에 동시에 데이터를 전송**하기 위해 사용하는 마지막 주소입니다. 이 또한 개별 장치에는 할당할 수 없습니다.

### 문제 **IP: 192.168.35.10 / Mask: 255.255.252.0** 일때 수신할수있는 ip 주소들을 구해라
[ip주소와 서브넷마스크와 유효주소구하기 정리](ip주소와%20서브넷마스크와%20유효주소구하기%20정리.md)

### 1단계: 마스크 분석을 통한 변동 마디(Octet) 식별
- **서브넷 마스크 (Subnet Mask):** IP 주소에서 어디까지가 **네트워크 주소**이고, 어디서부터가 **호스트(기기) 주소**인지를 구분하는 기준점입니다.
- 서브넷 마스크에서 $0$이 아닌 숫자가 끝나는 지점이 네트워크와 호스트가 나뉘는 경계입니다.
- **마스크 확인:** `255.255.252.0`
- **경계 식별:** 첫 번째와 두 번째 마디(255.255)는 꽉 차 있는 고정 영역입니다. **세 번째 마디(252)**에서 비트 분할이 일어나므로, 세 번째와 네 번째 마디가 호스트 범위를 결정하는 변동 구간이 됩니다.

### 2단계: 블록 크기(Block Size) 산출
- 블록크기: 하나의 서브넷이 가질 수 있는 IP 가짓수(네트워크 증분값)를 계산합니다
- **계산:** $256 - 252 = 4$
	- 256: 8비트로 표현가능한 최대 가짓수
- **의미:** 계산된 결과값 **4**는 블록 크기를 의미합니다. 이는 세 번째 마디가 4씩 증가하며 새로운 네트워크가 시작됨을 뜻합니다. ($0, 4, 8, \dots, 32, 36, \dots$)

### 3단계: 네트워크 주소(Network ID) 산출
네트워크 주소: 서브넷의 시작주소
주어진 IP($192.168.35.10$)가 속한 '그룹의 시작 번호'를 블록 크기로 연산해 찾습니다.

- **계산 과정:**
	1. 세 번째 마디 숫자(35)를 블록 크기(4)로 나눕니다: $35 \div 4 = 8.75$
    1. 소수점을 버린 정수값(8)에 다시 블록 크기를 곱합니다: $8 \times 4 = \mathbf{32}$
- **최종연산결과 32:** 해당 IP가 속한 서브넷의 **네트워크 주소(Network ID)**입니다.
- 즉 이 IP가 속한 서브넷의 시작 주소(Network ID)는 192.168.**32**.0입니다.

### 4단계: 브로드캐스트 주소(Broadcast ID) 산출
브로드캐스트 주소: 설명
해당 그룹의 '가장 마지막 번호'를 찾습니다.
네트워크 주소인 **32**에 블록 크기 **4**를 더한 후, 주소 할당의 인덱스 보정을 위해 **1**을 차감합니다.

- **계산 과정:** $(32 + 4) - 1 = \mathbf{35}$
- **결과:** 세 번째 마디의 마지막 숫자는 **35**입니다. 여기에 네 번째 마디의 최대 가짓수인 **255**를 결합합니다.
- **최종 결과:** 이 서브넷의 가장 마지막 주소인 브로드캐스트 주소(Broadcast ID)는 **192.168.35.255**입니다.
- **통신 특징:** 이 범위 내에 있는 IP들끼리는 별도의 라우터 없이 서로 통신(브로드캐스팅 수신 포함)이 가능합니다.

### 5단계: 수신 가능한 IP 범위 확정 (최종 적용)
네트워크 내의 모든 장치는 이 범위 안의 IP를 가집니다.

- **전체 범위:** $192.168.32.0$ ~ $192.168.35.255$
- **유효 호스트 범위:** 192.168.32.1 ~ 192.168.35.254 (기기에 직접 할당된 주소들)

---
### **결론: 문제 풀이 적용**

1. **세 번째 마디:** $32, 33, 34, 35$ 중 하나여야 함
2. **네 번째 마디:** $0$ ~ $255$ 사이의 숫자여야 함

## 4. 보안의 3요소(CIA) 관점의 분류

공격이 정보 보안의 어떤 가치를 훼손하느냐에 따른 분류입니다.

1. **가용성(Availability) 공격:** 서비스를 중단시키는 것이 목적 (**DDoS, SYN Flooding, Slowloris**).
2. **무결성(Integrity) 공격:** 데이터를 변조하는 것이 목적 (**스푸핑**, 세션 하이재킹).
3. **기밀성(Confidentiality) 공격:** 정보를 훔치는 것이 목적 (Sniffing, SQL Injection).

## 💡 요약 (Senior's Note)

질문하신 내용의 퍼즐을 맞춰보면 다음과 같습니다.

- **SYN Flooding**은 공격의 **'수단'** (TCP의 허점을 찌름).
- **DDoS**는 공격의 **'규모'** (수많은 장비를 동원함).
- **Spoofing**은 공격의 **'속임수'** (신분을 위조함).
- **Slowloris**는 공격의 **'정밀함'** (적은 양으로 연결을 점유함).
    

이 분류 체계를 이해하고 있으면, 나중에 클라우드 환경(AWS 등)에서 인프라를 설계할 때 **WAF(L7 방어)**를 쓸지, **Shield(L3/L4 방어)**를 쓸지 판단하는 기준이 됩니다.

## 공격기법 매커니즘
### Flooding: 넘치게 보내는 공격방식
- UDP Flooding : 네트워크 파이프 자체를 가득 채워 마비시켜 대역폭 고갈
- SYN Flooding : 서버가 연결을 유지하기 위해 할당하는 자원을 소모해 서비스거부(Dos)시키는 프로트콜 고갈
	- SYN 패킷만 대량 전송해 서버가 SYN+ACK로 응답해도 마지막 ACK를 안보내 서버가 타임아웃까지 대기하느라 새로운 사용자의 SYN 요청을 수락할수없게 함
### 프로토콜의 허점이나 처리 조직 악용
- **Slowloris:** 장기간 HTTP 연결로 서버의 '동시'접속자원을 소모시켜 서비스거부(Dos)시키는
	- HTTP 헤더의 끝을 알리는 빈줄이 없는 형태로 적은 트래픽으로 동시접속자원을 점유
- **Smurf Attack:** ICMP 응답을 공격 대상에게 집중시키는 기법.

### 스푸핑(Spoofing): 신뢰받는 사용자인것처럼 데이터 패킷의 헤더정보를 위조해 위장 공격
- IP 스푸핑: 자신의 IP를 신뢰받는 내부 IP주소로 위장
- ARP 스푸핑: IP를 MAC으로 변환하는 ARP 프로토콜을 속여 자신의 MAC(하드웨어) 주소를 신뢰하게 업데이트
- DNS 스푸핑: 사용자가 주소를 브라우저에 입력해 시스템이 DNS 서버에 실제 IP를 물을때 DNS 서버가 응답전에 빠르게 위조된 응답으로 속임


## 최종 정리


# [Security] Network & Application Attack Classification

보안 공격은 크게 **가용성 파괴(자원 소모)**, **논리적 허점 악용**, **신뢰 관계 위조**의 세 가지 관점으로 분류할 수 있습니다.

## 1. 가용성 파괴 및 대역폭 고갈 (Flooding)

시스템의 처리 용량을 초과하는 트래픽을 주입하여 서비스를 마비시키는 공격입니다.

| **공격명**          | **대상 계층** | **핵심 메커니즘**             | **주요 특징**                                               |
| ---------------- | --------- | ----------------------- | ------------------------------------------------------- |
| **UDP Flooding** | L3/L4     | 대량의 UDP 패킷 전송           | 네트워크 대역폭(Bandwidth) 자체를 가득 채워 마비시킴                      |
| **SYN Flooding** | L4 (TCP)  | 3-Way Handshake 미완료     | 서버의 Backlog Queue 자원을 고갈시켜 새로운 연결 수립 방해                 |
| **Smurf Attack** | L3 (ICMP) | ICMP Echo + IP Spoofing | 증폭(Amplification) 공격. 위조된 IP로 브로드캐스트하여 타겟에게 응답 패킷을 집중시킴 |

---

## 2. 프로토콜 및 세션 로직 악용 (Logic Exploitation)

프로토콜의 통신 규약이나 세션 관리 메커니즘의 취약점을 이용해 권한을 탈취하거나 자원을 점유합니다.

### 2.1. 세션 하이재킹 (Session Hijacking)

- **TCP 세션 하이재킹 (L4):** 통신 중인 패킷의 **시퀀스 번호(SEQ)**를 탈취/예측하여 가로채는 공격.
- **Application 세션 하이재킹 (L7):** HTTP 쿠키에 저장된 **세션 ID**를 탈취하여 정당한 사용자로 위장.
    

### 2.2. 저속 연결 공격 (Low & Slow Attack)

- **Slowloris (L7):** HTTP 헤더의 끝(`\r\n\r\n`)을 보내지 않고 연결을 유지하여 웹 서버의 **Connection Pool(Worker Thread)**을 점유.
    

---

## 3. 식별 정보 및 신뢰 관계 위조 (Spoofing)

데이터 패킷의 헤더 정보를 조작하여 신뢰받는 개체로 위장합니다.

- **IP 스푸핑 (L3):** 공격자의 IP 주소를 신뢰할 수 있는 내부 IP로 위조하여 접근 제어(ACL) 우회.
- **ARP 스푸핑 (L2):** 로컬 네트워크에서 MAC 주소를 위조하여 패킷 흐름을 공격자로 유도 (MITM 공격의 기초).
- **DNS 스푸핑 (L7):** 위조된 DNS 응답을 보내 사용자를 가짜 서버(Phishing) IP로 연결 유도.
    

---

## 4. 실행 규모에 따른 구분: DoS vs DDoS

공격의 '방식'이 아닌 '형태'에 따른 구분입니다.

- **DoS (Denial of Service):** 단일 공격 소스(1:1)에서 발생하는 서비스 거부 공격.
- **DDoS (Distributed DoS):** 전 세계에 분산된 봇넷(Botnet)을 동원하여 **Flooding** 등의 공격을 수행. 현대의 대부분의 대규모 공격은 DDoS 형태를 띱니다.

## 💡 Senior's Note: 엔지니어링 관점의 방어 전략

분류를 마쳤다면, 백엔드 개발자로서 각 계층별 '방어 가이드'를 함께 기억해야 합니다.

1. **L3/L4 방어 (네트워크 레벨):**
    
    - **SYN Cookie** 활성화: Backlog Queue가 가득 차기 전에도 연결 요청을 식별.
    - **Anycast** 및 **DDoS Scrubbing**: 대규모 트래픽을 분산 처리하고 악성 패킷만 정화.
        
2. **L7 방어 (애플리케이션 레벨):**
    
    - **SSL/TLS (HTTPS)**: 데이터 암호화를 통해 스니핑 및 세션/시퀀스 번호 탈취 원천 차단.
    - **HttpOnly/Secure Flag**: 브라우저 스크립트를 통한 세션 ID 탈취(XSS) 방지.
    - **Rate Limiting**: 동일 IP에서의 과도한 요청(Slowloris 등)을 Nginx나 API Gateway 수준에서 차단.
