## 응용계층: HTTP 세션 하이재킹_인증된 사용자의 세션ID를 탈취해 재사용하여 가장하는 공격
HTTP 프로토콜의 **무상태성(Stateless)**을 보완하기 위해 도입된 '세션 ID'를 공격 대상으로 합니다.
- **작동 방식:** 사용자가 로그인한 후 서버로부터 발급받은 **Session ID(주로 쿠키에 저장)**를 스니핑, XSS(Cross-Site Scripting), 혹은 물리적 탈취를 통해 가로챕니다.
- **결과:** 공격자는 탈취한 세션 ID를 자신의 브라우저 쿠키에 삽입하여 해당 사용자의 권한을 획득합니다.
- **방어 전략:** 
	* 쿠키에 `HttpOnly` 및 `Secure` 플래그 설정
    - 세션 타임아웃 및 동시 접속 제어
    - 로그인 시마다 세션 ID 재생성

## 전송계층: TCP 세션 하이재킹_인증된 사용자의 시퀀스번호를 탈취하여 가장하는 공격

이미 인증을 마친 사용자(Client)와 서버 사이의 **시퀀스 번호(Sequence Number)**를 가로채, 공격자가 사용자의 권한을 그대로 이어받는 전송 계층 공격입니다.

### 1. 공격의 근본적 원인: "무결성 검증의 부재"

TCP는 패킷을 받을 때 다음 세 가지 정보가 일치하면 정당한 사용자로 간주합니다.

- **Source IP / Port**: 어디서 왔는가?
- **Destination IP / Port**: 어디로 가는가?
- **Sequence Number (SEQ)**: 순서가 맞는가?
    

> **핵심 문제:** TCP 헤더에는 보낸 이가 진짜인지 확인하는 **암호화된 신분증(Token)**이 없어서, 번호만 맞추면 커널은 의심 없이 데이터를 수락합니다.
---

### 2. TCP 3-Way Handshake와 시퀀스 번호

세션 수립 시 양단간의 논리적 통로를 만들기 위해 시퀀스 번호를 동기화합니다.
> 요청(**SYN**)
> 응답(ACK)
> 시퀀스번호(ISN) : 자신을 식별하기위한 번호

1. 클라이언트가 **SYN** 요청: 클라이언트의 ISN를 임의로 생성해 전송
2. 서버가 ACK와 SYN를 함께 전송
	- ACK 응답: 클라이언트 ISN에다가 1를 더한 값을 수락 응답으전송
	- **SYN** 요청: 서버도 자신의 ISN를 임의로 생성해 전송
3. 클라이언트가 ACK 응답: 받은 서버의 ISN에 1을 더해 전송하며 세션이 연결됨
- 이후 통신에서는 전송하는 바이트 크기만큼 시퀀스 번호를 증가시키며 데이터의 누락 및 순서를 검증합니다.
---

### 3. 세션 하이재킹 4단계 프로세스

공격의 핵심은 **"클라이언트보다 먼저 서버가 대기 중인 번호를 주입하여 주도권을 뺏는 것"** 입니다.

| **단계**       | **주요 행위**                           | **결과**                    |
| ------------ | ----------------------------------- | ------------------------- |
| **탐색 및 스니핑** | 통신 경로에서 패킷을 실시간 감시하며 SEQ, ACK 번호 탈취 | 현재 세션 정보 확보               |
| **번호 예측**    | 서버가 다음에 기다릴 시퀀스 번호를 계산              | 주입할 패킷 설계 완료              |
| **비동기화**     | 위조 패킷을 주입해 서버의 시퀀스 번호를 강제로 높임       | **실제 클라이언트 패킷은 무시(Drop)** |
| **세션 장악**    | 서버와 동기화된 번호로 악성 명령(Payload) 전송      | 공격자가 클라이언트 권한 획득          |

---

### 4. 핵심 방어 전략: HTTPS 사용(SSL/TLS)

세션 하이재킹을 원천 차단하기 위해서는 전송 계층 위에 **암호화 계층**을 추가해야 합니다.

- **암호화의 효과**: 공격자가 시퀀스 번호를 알아내어 패킷을 주입하더라도, 패킷 내부의 **데이터가 암호화**되어 있습니다.
- **무결성 검증**: 서버는 수신한 패킷을 복호화하는 과정에서 키가 맞지 않거나 데이터가 조작되었음을 즉시 감지하고 차단합니다.

> **💡 요약 (Senior's Note)**
>
> 세션 하이재킹은 **"번호 맞추기 게임"**입니다. TCP가 번호의 연속성만 보고 신뢰한다는 약점을 파고드는 것이죠. 따라서 번호만 맞춘다고 해결되지 않도록 **SSL/TLS 암호화**를 통해 데이터 자체의 진위 여부를 검증하는 것이 가장 확실한 대응책입니다. 암호화된 세션에서는 공격자가 번호를 맞춰 패킷을 주입하더라도 복호화 키가 없어 무결성 검증 단계에서 즉시 차단되기 때문입니다.

# 세션 하이재킹 (Session Hijacking) 개요

세션 하이재킹은 인증된 사용자의 세션 식별 정보(Session ID 또는 Sequence Number)를 탈취 및 재사용하여, 서버로 하여금 공격자를 정당한 사용자로 오인하게 만드는 공격입니다. 공격이 발생하는 계층에 따라 크게 두 가지로 분류됩니다.

## 1. Application Layer: HTTP 세션 하이재킹

HTTP 프로토콜의 **무상태성(Stateless)**을 보완하기 위해 도입된 '세션 ID'를 공격 대상으로 합니다.

- **공격 지점:** OSI 7계층 중 Application Layer
- **작동 방식:** 사용자가 로그인 후 서버로부터 발급받은 `Session ID`(주로 쿠키에 저장)를 스니핑, XSS(Cross-Site Scripting), 혹은 물리적 탈취를 통해 가로챕니다.
- **결과:** 공격자는 탈취한 세션 ID를 자신의 브라우저 쿠키에 삽입하여 해당 사용자의 권한을 획득합니다.
- **방어 전략:** 
	* 쿠키에 `HttpOnly` 및 `Secure` 플래그 설정
    - 세션 타임아웃 및 동시 접속 제어
    - 로그인 시마다 세션 ID 재생성

---

## 2. Transport Layer: TCP 세션 하이재킹

이미 인증을 마친 클라이언트와 서버 사이의 **시퀀스 번호(Sequence Number)**를 가로채 전송 계층에서 연결 주도권을 확보하는 공격입니다.

### 2.1. 취약점의 근본 원인: "무결성 검증의 부재"

TCP는 기본적으로 신뢰성 있는 전송을 지향하지만, 패킷 자체에 대한 **신원 인증 메커니즘**이 부족합니다. 커널은 다음 세 가지 정보가 일치하면 정당한 패킷으로 수용합니다.

1. **Source IP / Port**
2. **Destination IP / Port**
3. **Sequence Number (SEQ):** 패킷의 순서 정보
    

TCP 헤더에는 암호화된 신분 증명 수단이 없으므로, 공격자가 실시간으로 패킷을 스니핑하여 올바른 번호만 맞추면 시스템은 이를 신뢰하게 됩니다.

### 2.2. TCP 3-Way Handshake와 SEQ 동기화

연결 수립 시 양단은 논리적 통로를 위해 시퀀스 번호를 동기화합니다.

1. **Client $\to$ Server (SYN):** 클라이언트가 임의의 초기 시퀀스 번호($ISN_c$) 생성 후 전송
2. **Server $\to$ Client (SYN + ACK):** 서버가 클라이언트 번호에 1을 더한 값($ISN_c + 1$)을 수락(ACK)하고, 자신의 번호($ISN_s$)를 전송
3. **Client $\to$ Server (ACK):** 서버 번호에 1을 더한 값($ISN_s + 1$)을 전송하며 세션 연결 완료
    

이후 통신에서는 전송하는 바이트 크기만큼 시퀀스 번호를 증가시키며 데이터의 누락 및 순서를 검증합니다.

### 2.3. 세션 하이재킹 4단계 프로세스

공격의 핵심은 **"클라이언트보다 먼저 서버가 대기 중인 번호를 주입하여 주도권을 뺏는 것"**입니다.

|**단계**|**주요 행위**|**결과**|
|---|---|---|
|**1. 스니핑**|통신 경로에서 패킷을 감시하여 현재 SEQ, ACK 번호 탈취|현재 세션 상태 정보 확보|
|**2. 번호 예측**|서버가 다음에 수용할 시퀀스 번호를 계산|주입할 위조 패킷 설계 완료|
|**3. 비동기화**|위조 패킷을 주입해 서버의 SEQ 번호를 강제로 높임|실제 클라이언트의 패킷은 순서 불일치로 Drop|
|**4. 세션 장악**|서버와 동기화된 번호로 악성 페이로드(Payload) 전송|공격자가 클라이언트의 Shell 권한 등 획득|

---

## 3. 핵심 대응 전략: SSL/TLS (HTTPS)

TCP 세션 하이재킹을 원천 차단하기 위해서는 전송 계층 위에 **암호화 및 무결성 계층**을 추가해야 합니다.

- **암호화:** 공격자가 스니핑을 통해 시퀀스 번호를 알아내더라도, 패킷 내부의 데이터가 암호화되어 있어 내용을 파악하거나 수정할 수 없습니다.
- **무결성 검증 (MAC):** SSL/TLS는 메시지 인증 코드(MAC)를 통해 패킷의 조작 여부를 검증합니다. 공격자가 번호만 맞춰 패킷을 주입하더라도, 복호화 과정에서 무결성 검증에 실패하므로 서버는 이를 즉시 차단합니다.
    

> **[Senior's Note]**
>
> TCP 하이재킹은 네트워크 스택(Kernel level)에서 발생하는 하위 계층 공격이고, HTTP 세션 하이재킹은 애플리케이션 로직에서 발생하는 상위 계층 공격입니다. 현대적인 인프라에서는 **SSL/TLS 적용**이 이 두 가지 공격을 동시에 방어하는 가장 강력한 표준입니다.
