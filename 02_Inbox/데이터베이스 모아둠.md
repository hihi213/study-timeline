### ⚠️ [필수] FK(외래키) 생성 시 감점 방지 템플릿

시험에서 테이블 생성(CREATE TABLE) 시 FK에 아래 키워드를 빠뜨리면 감점됩니다.

- **임의의 이름 자동 생성 문제:** `CONSTRAINT`를 안 쓰면 DB가 `SYS_C001234` 같은 랜덤 이름을 붙여서, 에러 발생 시 어느 테이블 관계인지 파악이 불가능합니다.
    

SQL

```sql
-- 테이블 생성 시 FK 작성 표준 가이드
CREATE TABLE Orders (
    orderid INTEGER PRIMARY KEY,
    custid INTEGER,
    bookid INTEGER,
    saleprice INTEGER,
    orderdate DATE,
    -- 외래키 지정 필수 포맷 (제약조건명, 참조테이블, 캐스케이드)
    CONSTRAINT fk_orders_customer FOREIGN KEY (custid) REFERENCES Customer(custid) ON DELETE CASCADE,
    CONSTRAINT fk_orders_book FOREIGN KEY (bookid) REFERENCES Book(bookid) ON DELETE CASCADE
);
```

    ```sql
    -- 대한민국 거주 고객 UNION 주문 이력이 있는 고객 이름
    ```

    ```sql
    SELECT b.bookname
    FROM Orders o, Book b
    WHERE o.bookid = b.bookid
    GROUP BY b.bookid, b.bookname

    ```
    
- **(4) 박지성이 구매한 도서의 출판사와 같은 출판사에서 도서를 구매한 고객의 이름 (박지성 제외)**

    ```sql
    SELECT DISTINCT name
    FROM Customer customer, Orders orders, Book book
    WHERE customer.custid = orders.custid 
      AND orders.bookid = book.bookid
      AND name NOT LIKE '박지성'
      AND publisher IN (
          SELECT publisher 
          FROM Customer customer, Orders orders, Book book
          WHERE customer.custid = orders.custid 
            AND orders.bookid = book.bookid
            AND name LIKE '박지성'
    ```

## 2. 테이블 동적 생성 및 구조 변경 (첨부 2번 관련)

> **교수님 Pick:** 각 라인(한 줄씩) 실행 시 무엇이 생성되고 어떻게 변하는지 서술형/추적 문제 출제!

SQL

```sql
-- Line 1-4: CTAS (Create Table As Select)
CREATE TABLE profession_T AS 
  SELECT profession FROM my_contacts
  GROUP BY profession
  ORDER BY profession;
```

- **실행 결과:** `my_contacts` 테이블에서 `profession` 컬럼을 가져와 중복을 제거(`GROUP BY`)하고 정렬(`ORDER BY`)한 뒤, **`profession`이라는 단일 컬럼만 가진 새로운 테이블 `profession_T`를 생성**하고 데이터를 집어넣습니다. (이 시점에는 PK나 id 컬럼이 없음)
    

SQL

```sql
-- Line 5-7: 테이블 구조 변경 (id 컬럼 추가 및 PK 지정)
ALTER TABLE profession_T
  ADD id INTEGER NOT NULL AUTO_INCREMENT FIRST,
  ADD PRIMARY KEY(id);
```

- **실행 결과:** 1. `profession_T` 테이블의 맨 첫 번째 위치(`FIRST`)에 `id`라는 이름의 정수형(`INTEGER`) 컬럼을 추가합니다.
    
    1. 이 값은 자동으로 1씩 증가(`AUTO_INCREMENT`)하며 빈 값을 허용하지 않습니다(`NOT NULL`).
    2. 동시에 `id` 컬럼을 이 테이블의 기본키(PRIMARY KEY)로 지정합니다.
    

## 3. 데이터베이스 모델링 및 설계 이론

### ❶ '최신여부' 컬럼 유무에 따른 모델링 차이 (★서술형 대비)

|**구분**|**최신여부 컬럼이 있을 때**|**최신여부 컬럼이 없을 때**|
|---|---|---|
|**장점**|**조회 속도 향상 (성능 Up)**<br><br>  <br><br>- 매번 복잡한 날짜 비교나 정렬 연산 없이 해당 컬럼이 'Y'인 데이터만 즉시 조회 가능.|**데이터 무결성 유지, 저장공간 절약**<br><br>  <br><br>- 데이터가 변경되어도 추가적인 업데이트 연산이 필요 없어 입력/수정/삭제가 깔끔함.|
|**단점 및 특징**|**데이터 변경 시 업데이트 필요**<br><br>  <br><br>- 새로운 최신 데이터가 들어오면 기존 데이터의 '최신여부'를 'N'으로 바꾸는 추가 연산 필요.<br><br>  <br><br>- **해결책:** **트리거(Trigger)를 사용하여 이 프로세스를 자동화**함.|**조회 속도 저하**<br><br>  <br><br>- 항상 최신 데이터를 찾기 위해 `MAX(날짜)`나 `ORDER BY DESC LIMIT 1` 등의 무거운 서브쿼리/정렬을 수행해야 함.|

### ❷ 기본키(PK) 선정 원칙

- **보안성 규칙:** **기본키는 데이터 보안이 요구되지 않는 값이어야 한다.**
- **이유:** 주민등록번호, 계좌번호 등 개인정보나 보안이 중요한 데이터를 PK로 삼으면 시스템 내 다른 테이블(FK)에 무분별하게 노출되어 보안 취약점이 발생합니다. 따라서 식별자로 쓰기 적절하지 않으며, 대체재로 비즈니스 의미가 없는 인조키(예: 일련번호 `id`)를 사용하는 것이 좋습니다.
    

**남은 10시간 동안 팁:** 위의 SQL 쿼리 타이핑 실수를 줄이기 위해 `CONSTRAINT`, `REFERENCES`, `CASCADE` 철자를 확실히 외우시고, `profession_T` 테이블이 변하는 순서(1단계: profession 컬럼 생성 -> 2단계: id 컬럼 맨 앞에 추가 후 PK 지정)를 머릿속으로 시뮬레이션해 보세요. 시험 잘 보세요!

## 1. 무결성 제약조건(표 9-1) 기반 테이블 생성 (SQL)

교재 사진의 '표 9-1. 무결성 제약조건 정의' 명세서에 따른 테이블 생성 쿼리입니다.

- **주의 포인트:** 1. `주민번호`가 아닌 비즈니스 식별자인 `사원번호`, `부서번호`, `프로젝트번호` 등을 기본키로 잡아야 합니다.
    
    1. 외래키 제약조건 위반 시 에러 추적을 위해 명시적인 제약조건 이름(`CONSTRAINT`)을 정의해야 감점을 피합니다.
    

SQL

```sql
-- 1. 부서 테이블 생성
CREATE TABLE 부서 (
    부서번호 VARCHAR(10) PRIMARY KEY,
    부서명 VARCHAR(30) NOT NULL,
    위치 VARCHAR(50)
);

-- 2. 사원 테이블 생성 (부서번호를 외래키로 참조)
CREATE TABLE 사원 (
    사원번호 VARCHAR(10) PRIMARY KEY,
    사원명 VARCHAR(30) NOT NULL,
    주민번호 VARCHAR(14) UNIQUE, -- 보안이 요구되므로 PK가 아닌 UNIQUE 제약으로 설정
    직급 VARCHAR(20) DEFAULT '사원',
    급여 INTEGER CHECK (급여 >= 0), -- 도메인 무결성 제약조건
    부서번호 VARCHAR(10),
    -- 외래키 설정 (감점 방지 필수 형식)
    CONSTRAINT fk_사원_부서 FOREIGN KEY (부서번호) 
        REFERENCES 부서(부서번호) ON DELETE SET NULL
);

-- 3. 프로젝트 테이블 생성
CREATE TABLE 프로젝트 (
    프로젝트번호 VARCHAR(10) PRIMARY KEY,
    프로젝트명 VARCHAR(50) NOT NULL,
    예산 INTEGER
);

-- 4. 사원_프로젝트 테이블 생성 (다대다 관계 해소용 교차 테이블)
CREATE TABLE 사원_프로젝트 (
    사원번호 VARCHAR(10),
    프로젝트번호 VARCHAR(10),
    참여시간 INTEGER,
    PRIMARY KEY (사원번호, 프로젝트번호), -- 복합 기본키
    -- 외래키 설정 2개
    CONSTRAINT fk_사원프로젝트_사원 FOREIGN KEY (사원번호) 
        REFERENCES 사원(사원번호) ON DELETE CASCADE,
    CONSTRAINT fk_사원프로젝트_프로젝트 FOREIGN KEY (프로젝트번호) 
        REFERENCES 프로젝트(프로젝트번호) ON DELETE CASCADE
);
```

## 2. ERD 분석: 생성될 테이블 및 릴레이션 스키마 단순화 (그림 9-19)

보내주신 ER 다이어그램(그림 9-19)을 분석하여 물리적 데이터베이스 모델로 사상(Mapping)한 결과입니다.

### ❶ 생성될 테이블 및 관계 분석

1. **사원(Employee) 테이블:** 개체(Entity) 타입에서 유도됩니다. `사원번호`가 기본키가 됩니다.
2. **부서(Department) 테이블:** 개체 타입에서 유도됩니다. `부서번호`가 기본키가 됩니다.
3. **프로젝트(Project) 테이블:** 개체 타입에서 유도됩니다. `프로젝트번호`가 기본키가 됩니다.
4. **소속 관계 (사원 - 부서):** `N:1 (다대일)` 관계이므로, '다(N)' 쪽에 해당하는 **사원 테이블에 부서번호(FK) 컬럼을 추가**하여 연결합니다.
5. **참여 관계 (사원 - 프로젝트):** `M:N (다대다)` 관계이므로, 릴레이션 스키마 단순화를 위해 두 개체의 기본키를 결합한 **새로운 교차 테이블(`사원_프로젝트`)을 생성**해야 합니다.
    

### ❷ 릴레이션 스키마 단순화 (시험 제출용 기본 포맷)

> 밑줄은 기본키(PK), 이탤릭체(또는 밑줄 밑에 설명)는 외래키(FK)를 의미합니다.

- **부서** (부서번호, 부서명, 위치)
- **사원** (사원번호, 사원명, 주민번호, 직급, 급여, _부서번호_)
    - _부서번호_: 부서(부서번호) 참조
- **프로젝트** (프로젝트번호, 프로젝트명, 예산)
- **사원_프로젝트** (사원번호, 프로젝트번호, 참여시간)
    - _사원번호_: 사원(사원번호) 참조, _프로젝트번호_: 프로젝트(프로젝트번호) 참조
        

## 3. 그림 9-20번 과제 해결 가이드

그림 9-20번 문항은 주어진 입력 매개변수를 바탕으로 데이터를 안전하게 다루고 제어하는 **저장 프로시저(Stored Procedure)** 구현 과제입니다. 시험 문제 유형으로 변형되어 출제될 확률이 매우 높습니다.

### 과제 요구사항 핵심 분석 및 구현 (MySQL 기준)

신규 사원을 배치하거나 프로젝트 참여 이력을 동적으로 추가/갱신하는 프로시저의 정석 구조입니다.

SQL

```sql
DELIMITER //

CREATE PROCEDURE P_사원프로젝트등록(
    IN in_사원번호 VARCHAR(10),
    IN in_프로젝트번호 VARCHAR(10),
    IN in_참여시간 INTEGER
)
BEGIN
    -- 1. 예외 처리 정의 (필요 시): 참조 무결성 오류 등을 방지하기 위함
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        -- 오류 발생 시 롤백 수행
        ROLLBACK;
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '데이터 처리 중 오류가 발생하여 취소되었습니다.';
    END;

    -- 트랜잭션 시작
    START TRANSACTION;

    -- 2. 비즈니스 로직 수행
    -- 이미 해당 사원이 해당 프로젝트에 참여 중인지 체크 후 Insert 또는 Update 수행
    IF EXISTS (SELECT 1 FROM 사원_프로젝트 WHERE 사원번호 = in_사원번호 AND 프로젝트번호 = in_프로젝트번호) THEN
        -- 이미 존재하면 참여시간 누적 업데이트
        UPDATE 사원_프로젝트 
        SET 참여시간 = 참여시간 + in_참여시간
        WHERE 사원번호 = in_사원번호 AND 프로젝트번호 = in_프로젝트번호;
    ELSE
        -- 존재하지 않으면 새로 신규 등록
        INSERT INTO 사원_프로젝트 (사원번호, 프로젝트번호, 참여시간)
        VALUES (in_사원번호, in_프로젝트번호, in_참여시간);
    END IF;

    -- 완료 시 커밋
    COMMIT;
END //

DELIMITER ;
```

### 💡 서술형 대비 추가 팁 (`그림 9-20` 프로시저 실행 방법)

만약 시험 문제에서 작성한 프로시저를 실행(호출)하는 구문을 쓰라고 한다면 아래와 같이 작성하세요.

SQL

```sql
-- 사원번호 'E001'인 사원을 프로젝트 'P003'에 10시간 참여하도록 등록하는 호출문
CALL P_사원프로젝트등록('E001', 'P003', 10);
```

벼락치기인 만큼 **`CONSTRAINT [제약명] FOREIGN KEY (…) REFERENCES …`** 구문 구조를 종이에 2~3번 직접 써보면서 손에 익히시는 것을 강력히 추천합니다. 시험 잘 치르시기 바랍니다!

## 1. 정규화(Normalization)를 하는 이유와 이상현상

### ❶ 정규화의 정의

정규화는 데이터의 **중복을 제거**하고, 함수적 종속성(FD, Functional Dependency)을 분석하여 테이블을 올바른 구조로 분해하는 과정입니다.

> **💡 한 줄 요약:** 정규화를 하지 않아 데이터가 중복되면 데이터베이스에 **이상현상(Anomaly)**이 발생하여 데이터 무결성이 깨지기 때문에 정규화를 합니다.

### ❷ 데이터 중복이 유발하는 3대 이상현상 (Anomaly)

보내주신 예시(박지성 학생의 수강 기록)처럼 테이블이 제대로 분해되지 않고 하나로 뭉쳐 있으면 다음과 같은 치명적인 결함이 생깁니다.

- **삭제 이상 (Deletion Anomaly):** * **상황:** '수학' 수강 기록만 지우려고 `DELETE`를 실행함.
    - **문제점:** 박지성의 학번, 학과, 대학교 정보가 담긴 행(Tuple) 전체가 삭제되어, 박지성이 우리 학교 학생이라는 정보 자체가 시스템에서 사라집니다. (의도하지 않은 정보까지 연쇄 삭제됨)
- **삽입 이상 (Insertion Anomaly):** * **상황:** 신입생 '손흥민'이 입학해서 학번, 이름, 학과를 등록하려고 함.
    - **문제점:** 아직 수강 신청을 하지 않아서 '과목명'과 '강의실' 자리에 `NULL`을 넣어야 하거나, 수강 신청을 하기 전까지는 학생 등록 자체가 불가능해집니다.
- **수정/갱신 이상 (Update Anomaly):** * **상황:** 박지성의 학과가 '컴퓨터학과'에서 '소프트웨어학과'로 변경됨.
    - **문제점:** 박지성이 수강하는 모든 과목의 행을 찾아 전부 수정해야 합니다. 만약 일부 행만 수정하고 누락하면, 동일한 학생이 서로 다른 학과로 조회되는 **데이터 불일치** 현상이 일어납니다.
        

## 2. FD(함수적 종속성)와 FD 다이어그램 작성법

> **교수님 Pick:** 시험 문제에서 FD 다이어그램을 올바르게 그리는 것이 핵심 포인트입니다!

### ❶ 함수적 종속성(FD)의 개념

어떤 릴레이션에서 $X$의 값이 고정되면 $Y$의 값도 무조건 하나로 결정될 때, "$Y$는 $X$에 함수적으로 종속된다"라고 하며, **$X \rightarrow Y$** 로 표기합니다. (이때 $X$는 결정자, $Y$는 종속자)

- **교수님 예시 분석:** `학번 \rightarrow (이름, 학년, 학과)`
    - 학번을 알면 이름을 단 하나로 특정할 수 있다. ($학번 \rightarrow 이름$)
    - 학번을 알면 학년을 알 수 있다. ($학번 \rightarrow 학년$)
    - 학번을 알면 학과를 알 수 있다. ($학번 \rightarrow 학과$)
        

### ❷ 시험 대비 FD 다이어그램 그리는 법

기본키(결정자)를 왼쪽이나 위쪽에 배치하고, 화살표($\rightarrow$)를 통해 어떤 컬럼이 어떤 컬럼을 결정짓는지 시각적으로 명확하게 그려야 합니다.

```sql
[ 학번 ] ───▶ [ 이름 ]
   │
   ├───▶ [ 학년 ]
   │
   └───▶ [ 학과 ]
```

_(※ 시험지에는 사각형 박스를 그리고 화살표를 깔끔하게 연결해 주세요.)_

## 3. 프로시저(Procedure) 생성 및 호출 문법 (핵심 요약)

데이터베이스에서 여러 줄의 SQL 문을 하나의 함수처럼 묶어서 실행하는 프로시저를 만들 때는 문법의 시작과 끝을 알리는 `DELIMITER` 설정이 필수적입니다.

### ❶ 프로시저 작성 표준 템플릿

SQL

```sql
-- 1. 구문 종료 문자를 // 로 변경 (세미콜론이 프로시저 내부에서 쓰이기 때문)
DELIMITER //

CREATE PROCEDURE InsertStudent(
    IN in_학번 INT,
    IN in_이름 VARCHAR(20),
    IN in_학과 VARCHAR(20)
)
BEGIN
    -- 실행할 SQL문 작성
    INSERT INTO 학생(학번, 이름, 학과) 
    VALUES (in_학번, in_이름, in_학과);
END //

-- 2. 구문 종료 문자를 다시 세미콜론(;)으로 원상복구
DELIMITER ;
```

### ❷ 프로시저 호출(실행) 방법

작성한 프로시저에 데이터를 집어넣고 실행할 때는 `CALL` 키워드를 사용합니다.

SQL

```sql
-- CALL 프로시저이름(데이터);
CALL InsertStudent(501, '박지성', '컴퓨터학과');
```

|**구분**|**호출(실행) 방법**|**주요 용도 및 특징**|

### ❸ 커서 (Cursor) 핵심 메커니즘

- **끝단 처리:** 더 이상 읽을 데이터가 없을 때(`NOT FOUND`) 루프를 빠져나가도록 `CONTINUE HANDLER`를 설정합니다.
    

## 3. 호스트 랭귀지 연동: 파이썬 (PyMySQL)

> **교수님 Pick:** 과거 자바(JDBC) 중심에서 현재는 **파이썬 연동**이 대세이므로 파이썬 코드를 확실히 익혀둘 것! `execute()` 명령어 암기 필수.

### ❶ 파이썬 DB 연동 기본 5단계 프로세스

1. `pymysql.connect(...)` 로 DB **커넥션 열기**
2. `conn.cursor()` 로 **커ursor 객체 생성**
3. `cursor.execute(SQL스트링)` 으로 SQL 문 **실행** (★핵심 명령어)
4. `cursor.fetchall()` 로 결과 데이터 **인출(Fetch)** 및 활용
5. 사용 종료 후 `cursor.close()`, `conn.close()` 로 **자원 해제** (안 닫으면 서버 커넥션이 꽉 차서 다운됨)
    

### ❷ 파이썬 표준 연동 코드 (주요 부가설명 포함)

Python

```sql
import pymysql

# 1. 접속 정보 설정 (호스트명 에러 시 '127.0.0.1' IP 직접 입력)
# 교재에는 passwd, db로 되어있어도 최신 버전은 password, database 풀네임 권장 (줄 그어짐 방지)
conn = pymysql.connect(
    host='127.0.0.1',
    user='root',         # 일반적인 관리자 계정
    password='1234',     # 본인 패스워드
    database='madang',   # 대상 DB 이름
    port=3306,           # MySQL 기본 포트번호 (오라클과 다름)
    charset='utf8'
)

try:
    cursor = conn.cursor()
    sql = "SELECT * FROM Book;" # SQL문 끝에 세미콜론(;) 포함 스트링 생성
    
    # SQL 실행 (★시험 유의 명령어)
    cursor.execute(sql) 
    
    # 결과 왕창 가져오기
    data = cursor.fetchall()
    
    # 출력 포맷 처리 (%s 대신 중괄호 포맷팅 활용)
    # 꺽쇠(<)는 왼쪽 정렬, 숫자 등은 오른쪽 정렬하여 가독성 확보
    print("{:<10} {:<30}".format("도서번호", "도서명"))
    for row in data:
        print("{:<10} {:<30}".format(row[0], row[1]))

finally:
    # 데이터베이스 연결은 사용 후 "가장 빨리" 끊어야 서버 부하가 없음!
    cursor.close()
    conn.close()
```

## 2. [★시험 적중] 학생(Student) 예제로 보는 기능별 핵심 코드

교수님이 수업 중 판서로 띄워둔 학생 테이블 기반의 펑션, 프로시저, 트리거의 핵심 메커니즘입니다. 소스 코드를 가리고 특징만 물어보는 서술형에 대비하세요.

### ❶ 사용자 정의 함수: `get_grade` (성적 등급 계산)

- **기능:** 학생의 `score`(점수)를 입력받아 조건문(`IF-ELSE`)을 거쳐 $A, B, C, D$ 같은 `v_grade`(등급)를 반환(`RETURN`)하는 함수.
- **시험 포인트:** 펑션은 반드시 하나의 값을 `RETURN`해야 하며, `SELECT`문 안에서 호출됨.
    

### ❷ 저장 프로시저: `student_list` (학생 목록 조회)

- **기능:** `BEGIN-END` 블록 내부에 학생 테이블의 학번(`id`), 이름(`name`), 점수(`score`)를 한 번에 불러오는 `SELECT`문이 통째로 들어있음.
- **시험 포인트:** 단순 조회를 수행하며, 파이썬에서 호출할 때는 라이브러리에 따라 `CALL` 명령어나 별도의 프로시저 호출 메소드를 사용함.
    

### ❸ 트리거 (Trigger): `score_log` 테이블 기록 (★100% 출제)

교수님이 "조건절(`AFTER UPDATE`)을 지워도 코드만 보고 업데이트용 트리거임을 알아채야 한다"고 강조한 파트입니다.

- **핵심 키워드:** `OLD`와 **`NEW`**
    - **`OLD.score`:** 업데이트되기 전의 기존 점수
    - **`NEW.score`:** 업데이트되어 새로 들어온 점수
- **출제 원리:** 하나의 트리거 내부에서 **`OLD`와 `NEW`가 동시에 사용되는 것은 오직 `UPDATE` 이벤트가 발생했을 때뿐**임. (삽입 시에는 `NEW`만, 삭제 시에는 `OLD`만 존재)
- **동작:** 학생 점수가 수정되는 순간(`UPDATE`), 트리거가 자동으로 실행되어 `score_log` 테이블에 학번, 변경 전 점수, 변경 후 점수, 갱신 시간(`NOW()`)을 인서트함.
    

## 3. 파이썬(PyMySQL 등) vs 자바(JDBC) 연동 비교

### ❶ 파이썬 환경의 특징

- 포트 번호는 **`3306`**(MySQL 기본값)으로 고정되어 있음. 에러가 난다고 임의로 바꾸면 절대 안 됨.
- DB 이름(`database='school'`)이나 계정 정보가 일치하지 않으면 커넥션 리퓨즈(`Connection Refused`) 에러가 발생함.
- **`cursor.execute()` 하나로 범용 실행:** 파이썬은 쿼리나 업데이트 구분 없이 `execute()` 메소드로 통용하여 처리해 주므로 자바에 비해 코드가 매우 간결함.
    

### ❷ 자바(JDBC) 환경의 특징 (★차이점 비교 출제 가능)

자바는 파이썬과 달리 훨씬 엄격하고 복잡한 단계를 거치며, **수행하는 SQL의 종류에 따라 사용하는 메소드가 엄격히 분리**됩니다.

- **드라이버 로드 필수:** `Class.forName("com.mysql.jdbc.Driver");` 구문으로 드라이버를 메모리에 먼저 올려야 함.
- **기능별 메소드 분리 (리턴 타입이 다름):**
    - **`executeQuery()`:** `SELECT`문 실행 시 사용. 결과 데이터 뭉치인 **`ResultSet`** 구조를 리턴함.
    - **`executeUpdate()`:** `INSERT`, `UPDATE`, `DELETE` 등 데이터 변경 시 사용. 반환할 데이터가 없으므로 변경된 행의 개수인 `int`(정수)를 리턴함.

## 📊 3. 프로시저 vs 펑션 vs 트리거 (핵심 차이점)

|---|---|---|
|**프로시저 (Procedure)**|`CALL 프로시저명(매개변수);`|`IF-ELSE`, `LOOP` 등 복잡한 로직을 처리. 호스트 프로그램에서 호출하여 사용하기 가장 적합함.|

|**트리거 (Trigger)**|단독 실행 **불가** (`INSERT`, `UPDATE`, `DELETE` 시 자동 실행)|무결성 체크, 기본값 제공, 로그 저장 등에 사용. 서버 부하 방지를 위해 **아주 짧고 간단하게** 작성해야 함.|

## 📝 4. 커서 (Cursor) 동작 원리

커서는 `SELECT` 문의 결과 집합을 담아두는 메모리 공간(파일)입니다.

1. **DECLARE:** 커서를 선언.
2. **OPEN:** 커서를 열고 준비.
3. **FETCH:** `FETCH` 명령어를 통해 한 줄(Row)씩 데이터를 가져옴. (루프를 돌며 `NOT FOUND`가 될 때까지 반복)
4. **CLOSE:** 다 쓰면 반드시 닫아야 함.

## 2. 데이터베이스 설계 및 모델링 이론

**❶ 정규화와 이상현상 (Anomaly)**

- **정규화 목적:** 데이터 중복을 제거하여 삽입, 삭제, 갱신 이상현상을 방지하기 위함.
- **삭제 이상 예시:** '수학' 수강 기록만 지우려다 해당 학생의 기본 정보(학번, 이름 등) 행 전체가 삭제되어 학생 데이터 자체가 날아가는 치명적 결함.
- **함수적 종속성 (FD):** 어떤 속성 $X$를 알면 $Y$를 무조건 알 수 있을 때 $X \rightarrow Y$ 로 표기. (예: 학번 $\rightarrow$ 이름, 학년, 학과). 시험에서 FD 다이어그램 작성 시 결정자(학번)에서 종속자로 화살표를 명확히 그릴 것.
    

**❷ 테이블 기본키(PK) 및 컬럼 설계**

- **보안성 규칙:** 주민번호 같은 민감한 개인정보는 절대 PK로 사용하면 안 됨. (대체키 사용 후 주민번호는 `UNIQUE` 제약조건으로 처리).
- **최신여부 컬럼 유무 비교:**
    - **있을 때:** 데이터 조회 속도가 빠름. 단, 새 데이터 입력 시 기존 데이터의 최신여부를 'N'으로 바꾸는 업데이트 연산이 발생함 (이때 **트리거**를 써서 자동화함).
    - **없을 때:** 입력/수정은 편하지만, 가장 최신 데이터를 찾기 위해 무거운 정렬이나 서브쿼리가 필요해 조회가 느림.
        

## 3. SQL 문법 및 테이블 구조 변경 (감점 주의 구간)

**❶ 외래키(FK) 설정 필수 문법**

- 테이블 생성 시 아래 포맷을 반드시 지켜야 감점되지 않음. `CONSTRAINT`를 안 쓰면 DB가 임의의 이름(SYS_어쩌구)을 붙여 나중에 에러 추적이 불가능함.
- 문법: `CONSTRAINT 제약조건명 FOREIGN KEY (컬럼명) REFERENCES 부모테이블(컬럼명) ON DELETE CASCADE`
    

**❷ 테이블 동적 생성 (CTAS) 및 구조 변경**

- 1단계: `CREATE TABLE A AS SELECT 컬럼 FROM B GROUP BY …`
    
    $\rightarrow$ B테이블에서 중복을 제거한 단일 컬럼만 가진 새 테이블 A를 만듦. (이 시점엔 PK 없음)
    
- 2단계: `ALTER TABLE A ADD id INTEGER NOT NULL AUTO_INCREMENT FIRST, ADD PRIMARY KEY(id);`
    
    $\rightarrow$ A테이블 맨 첫 번째 위치에 1씩 자동 증가하는 `id` 컬럼을 만들고, 이를 기본키(PK)로 지정함.
    

## 4. 스토어드 프로그램 (DB 고급 기능)

**❶ 스토어드 프로그램을 사용하는 이유 (출제 1순위)**

- 호스트 프로그램(파이썬, 자바) 코드 안에 `SELECT`, `UPDATE` 같은 날것의 SQL과 테이블/컬럼명이 그대로 노출되는 것을 막기 위함 (보안 및 DB 보호).
- 실행 권한 제어가 가능하며, DB를 모르는 개발자도 프로시저 호출만으로 에러 없이 개발 가능.
    

**❷ 프로시저 vs 펑션 vs 트리거 비교**

- **프로시저:** 복잡한 조건/반복 로직 처리. 외부에서 `CALL 프로시저명(데이터);` 로 호출.
- **펑션:** 단일 값을 계산해서 반환(`RETURN`). `SELECT`문 안에서 쓰임. 내부에서 변수 대입 시 반드시 **`SET`** 키워드를 써야 함.
- **트리거:** 직접 호출 불가. `INSERT`, `UPDATE`, `DELETE` 이벤트 발생 시 자동 실행. 로그 기록이나 무결성 체크용으로 쓰이며, DB 부하를 막기 위해 아주 짧게 작성해야 함.
    - **★핵심 판별법:** 트리거 소스코드 내부에 **`OLD`** (변경 전 데이터)와 **`NEW`** (변경 후 들어올 데이터)가 **동시에 쓰였다면 무조건 `UPDATE` 전용 트리거**임.
        

**❸ 커서 (Cursor)**

- `SELECT` 결과를 담아두는 메모리 공간.
- 동작 순서: `DECLARE` (선언) $\rightarrow$ `OPEN` (열기) $\rightarrow$ **`FETCH`** (루프를 돌며 한 줄씩 읽기) $\rightarrow$ `CLOSE` (다 쓰면 무조건 닫기).
    

## 5. 호스트 언어 연동 (파이썬 vs 자바)

**❶ 파이썬 (PyMySQL) 연동**

- 포트 번호는 **3306**으로 고정.
- **통합 실행:** `cursor.execute(SQL문)` 하나로 조회, 수정, 삭제 쿼리를 모두 실행 가능해서 코드가 단순함.
- 결과 가져오기: `cursor.fetchall()` 로 한 번에 다 가져와서 반복문으로 출력.
- **★필수 마무리:** 데이터를 변경(`UPDATE`, `INSERT`)했다면 반드시 **`conn.commit()`** 을 해야 진짜 저장됨. 다 쓴 후에는 **`cursor.close()`**, **`conn.close()`** 를 무조건 해줘야 서버가 다운되지 않음.
    

**❷ 자바 (JDBC) 연동 (파이썬과의 차이점)**

- `Class.forName(…)` 으로 드라이버 로드 과정이 선행되어야 함.
- **명령어 분리:**
    - 조회(`SELECT`): `executeQuery()` 사용 $\rightarrow$ 리턴 형태는 `ResultSet`
    - 변경(`UPDATE/INSERT/DELETE`): `executeUpdate()` 사용 $\rightarrow$ 리턴 형태는 변경된 행의 갯수인 숫자(`int`)
        

## 6. 파이썬 웹 연동 (Flask 프레임워크)

- 아파치 같은 무거운 웹 서버 없이 `pip install flask` 만으로 가볍게 웹 구동.
- **디렉토리 구조 규칙:** 메인 파이썬 파일(`index.py`)이 있는 곳 하위에 반드시 **`templates`** 라는 이름의 폴더를 만들고, 그 안에 HTML 파일들을 넣어야 화면이 뜸.
- **데이터 바인딩:** 파이썬에서 DB에서 빼온 데이터를 `render_template('파일명.html', 데이터)` 함수를 통해 웹 브라우저로 던져줌. 접속은 `127.0.0.1:5000` 으로 확인.
