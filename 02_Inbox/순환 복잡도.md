제시해주신 내용은 토마스 맥케이브(Thomas McCabe)가 제안한 순환 복잡도(Cyclomatic Complexity, $V(G)$)입니다. 소프트웨어공학의 화이트박스 테스트 기법에서 프로그램의 논리적 복잡도를 정량적으로 측정하고, 최소 몇 개의 독립적인 실행 경로(테스트 케이스)가 필요한지 계산할 때 사용합니다.

  

### 1. 기본 공식: $V(G) = E - N + 2$

(기호 혼동을 방지하기 위해 노드는 보통 $N$으로 표기하지만, 제시하신 공식의 $V$와 같은 의미입니다.)

  

- **$E$ (Edges, 간선/화살표):** 제어 흐름의 방향을 나타내는 선의 총개수
- **$N$ (Nodes, 노드/정점):** 명령문, 연산, 분기점 등을 나타내는 원의 총개수
- **$+2$:** 시작 노드에서 종료 노드로 이어지는 연결 성분(Connected Component)의 기본 가중치 ($P=1$ 기준 공식: $E - N + 2P$)
    
      
    

**예시 상황:**

  

- 노드($N$)가 5개, 간선($E$)이 7개인 제어 흐름 그래프가 주어졌다면:
    
      
    
    $$V(G) = 7 - 5 + 2 = 4$$
    

### 2. 비기(祕技) 1: 영역(Region)의 개수

평면 그래프(간선들이 서로 교차하지 않게 그린 그래프)에서는 **"닫힌 면(영역)의 수 + 1"** 또는 "외부 영역을 포함한 전체 영역의 수"로 즉시 구할 수 있습니다.

  

- **원리 (오일러 다면체 정리):** 평면 그래프에서 면(영역)의 개수 $R$은 오일러 공식에 의해 다음과 같은 관계를 갖습니다.
    
      
    
    $$V - E + R = 1 \implies R = E - V + 1$$
    
    여기에 가장 바깥쪽 빈 공간(외부 영역) 1개를 포함하면 총 영역 수는 $R + 1 = E - V + 2$가 되어 순환 복잡도와 정확히 일치합니다.
    
      
    
- **실전 적용법:**
    - 간선들로 둘러싸인 내부 닫힌 공간(방)의 개수를 센 뒤 **$+ 1$** (외부 영역)을 더합니다.
    - 예: 화살표로 닫힌 방이 3개 있다면 $\rightarrow 3 + 1 = 4$
        
          
        

### 3. 비기(祕技) 2: 판정 노드(Predicate Node) 기준: $P + 1$

실기 시험에서 제어 흐름 그래프 대신 **C언어/Java 소스 코드**가 주어지고 순환 복잡도를 구하라고 할 때 가장 빠르고 정확한 방법입니다.

  

- **판정 노드($P$):** 조건에 따라 흐름이 2개 이상으로 갈라지는 **분기 조건문**의 개수
    - `if`, `while`, `for`, `case` 등이 해당합니다.
- **복잡도 공식:**
    
      
    
    $$V(G) = P + 1$$
    
- **주의할 점 (복합 조건식):** 조건문 안에 논리 연산자(`&&`, `||`)가 들어가 분기가 추가로 발생하면 각각을 개별 조건문(판정 노드)으로 카운트해야 합니다.
    - 예: `if (a > 0 && b > 0)` $\rightarrow$ 조건이 2개이므로 $P = 2$로 계산 $\rightarrow V(G) = 2 + 1 = 3$
        
          
        

### 시험장 실전 팁 요약

1. **그래프가 주어졌을 때:**
    
      
    
    가장 먼저 $E - N + 2$로 계산하고, 화살표로 둘러싸인 **면의 개수 + 1**로 1초 만에 검산합니다.
    
      
    
2. **소스 코드가 주어졌을 때:**
    
      
    
    굳이 그래프를 그리지 말고, 조건 분기문(`if`, `for`, `while` 등)의 개수를 센 뒤 $+ 1$을 합니다.
