## C언어
### 1. 배열과 포인터의 등가 관계 & 포인터 증감과 주소 이동

> **핵심 가이드:** 배열명 단독 사용은 1차원 포인터(`&a[0]`)와 같으며, `*(p-1)`이나 `p[-1]`이 지시하는 주소와 값의 변화를 따라갈 수 있어야 합니다.

```c
#include <stdio.h>
int main(){
    int a[3] = {1, 2}; 
    int *p = a + 1;   
    
    printf("%d %d %d\n", a[0], a[1], a[2]);
    printf("%d %d %d\n", *a, *(a+1), *(a+2));
    printf("%d %d %d\n", *(p-1), *p, *(p+1));
    printf("%d %d %d\n", p[-1], p[0], p[1]);
    return 0;
}
```

> [!NOTE]- [실행 결과]
> 1 2 0
> 1 2 0
> 1 2 0
> 1 2 0
>
> 해설
> int a[3] = {1, 2}; 크기가 3인 배열에 1, 2가 저장되고 남은 칸은 0으로 초기화됨
> int \*p = a + 1; // p는 a[1]의 주소를 가리킴
>

### 2. 2차원 배열의 인덱스 계산 & 포인터 배열

> **핵심 가이드:** 2차원 배열에서 각 행의 주소를 포인터 배열(`*p[3]`)에 어떤 순서로 대입했는지 파악하고, 참조 연산자(`*`)가 붙었을 때의 값 변화를 묻는 단골 유형입니다.

```c
#include <stdio.h>
int main(){
    int a[3][2] = {{1, 2}, {3, 4}, {5, 6}};
    int *p[3] = {a[2], a[0], a[1]}; 
    
    printf("%d %d %d\n", a[0][0], a[1][0], a[2][0]);
    printf("%d %d %d\n", *a[0], *a[1], *a[2]);
    printf("%d %d %d\n", p[1][0], p[2][0], p[0][0]);
    printf("%d %d %d\n", *p[1], *p[2], *p[0]);
    return 0;
}
```

> [!NOTE]- [실행 결과]
>
> 1 3 5
> 1 3 5
> 1 3 5
> 1 3 5
>
> [해설]
> int \*p[3] = {a[2], a[0], a[1]}; // p[0]은 3행, p[1]은 1행, p[2]은 2행을 가리킴

### 3. 문자 배열과 문자열

```c
#include <stdio.h>
int main(){
    char *p = "KOREA";
    
    printf("%s\n", p);   
    printf("%s\n", p+3);  
    printf("%c\n", *p);   
    printf("%c\n", *(p+3));
    printf("%c\n", *p+2);   
    return 0;
}
```

> [!NOTE]- [실행 결과]
> KOREA
> EA
> K
> E
> M
>
> **핵심 가이드:** `%s` 형식을 사용할 때는 포인터가 가리키는 주소부터 `\0`(NULL) 문자를 만날 때까지 연속 출력하고, `%c`일 때는 해당 포인터가 가리키는 단 한 문자만 출력한다는 점에 주의해야 합니다. 마지막 `*p + 2` 처럼 아스키코드 값 자체에 연산을 수행하는 꼼수도 자주 출제됩니다.
### 4. 구조체와 구조체 포인터

```c
#include <stdio.h>
struct Student{
    char gender;
    int age;
};

int main() {
    struct Student s = {'F', 21};
    struct Student *p = &s;
    
    printf("%c %d\n", s.gender, s.age);
    printf("%c %d\n", (&s)->gender, (&s)->age);
    printf("%c %d\n", p->gender, p->age);
    printf("%c %d\n", (*p).gender, (*p).age);
    printf("%c %d\n", p[0].gender, p[0].age);
    return 0;
}
```

> [!NOTE]- [실행 결과]
> F 21
> F 21
> F 21
> F 21
> F 21
> > 원래 멤버 접근은 포인터가 가리키는 실제값으로 가서 접근해야 하므로 `(*ptr).member` 형식을 써야 하지만,
>
> > **역참조 기호 `*`보다 멤버 접근 연산자 `.`의 우선순위가 더 높기 때문에 매번 귀찮게 괄호 `()`를 감싸주어야 하는 번거로움을 해결하기 위해** 그 축약형인 화살표 연산자(`->`)를 사용합니다.
> >
> > `(*p).member`나 `p[0].member` 표기법이 모두 동일한 값을 가리킨다는 등가 관계를 묻습니다.

### 5. 함수 포인터의 기본 선언·대입·호출

```c
#include <stdio.h>
void fn1(){ 
    printf("fn1 함수\n"); 
}
int fn2(int a){ 
    printf("fn2 함수:%d\n", a); 
    return 0; 
}

int main(){
    void (*pf1)();    
    int (*pf2)(int);   
    
    fn1();
    fn2(5);
    
    pf1 = fn1;         
    pf2 = fn2;
    
    pf1();             
    pf2(2);            
    return 0;
}
```

> [!NOTE]- [실행 결과]
>
> fn1 함수
> fn2 함수:5
> fn1 함수
> fn2 함수:2
>
> **핵심 가이드:** 선언문 모양이 복잡해 보이지만 `void (*pf1)()`는 매개변수와 반환값이 없는 함수를 가리키는 포인터 변수라는 점만 읽어낼 수 있으면 쉽게 풀립니다.
>
> void (\*pf1)(); // 반환값 void, 매개변수 없는 함수 포인터
> int (\*pf2)(int); // 반환값 int, 매개변수 int 1개인 함수 포인터
> pf1(); // 함수 포인터로 호출 -> fn1 함수
> pf2(2); // 함수 포인터로 호출 -> fn2 함수:2

### 6. 전위·후위 증감 연산

```c
#include <stdio.h>
int main(){
    int x = 3, y = 3;
    printf("%d", x++); 
    printf("%d", x);   
    printf("%d", ++y); 
    printf("%d", y);  
    return 0;
}
```

> [!NOTE]- [실행 결과]
>
> 3444
>
> **핵심 가이드:** `x++`(후위 연산)은 현재 줄의 명령(출력)을 먼저 수행한 뒤 값이 증가하고, `++y`(전위 연산)은 값을 먼저 증가시킨 뒤 다음 명령을 수행합니다.

### 1. 상속 시 생성자 호출 순서 & super()

```java
class Parent {
    Parent() {
        System.out.print("A");
    }
    Parent(int x) {
        System.out.print("B" + x);
    }
}

class Child extends Parent {
    Child() {
        super(3);
        System.out.print("C");
    }
    Child(int x) {
        System.out.print("D" + x);
    }
}

public class Main {
    public static void main(String[] args) {
        Child c1 = new Child();
        Child c2 = new Child(5);
    }
}
```

### 정답 및 해설

- **실행 결과**: `B3CAD5`
- **핵심 해설**:
    - `new Child()` 실행 시 결과: `B3C`
    - `Child()` 생성자가 호출됩니다.
	    - 내부에서 `super(3)`을 명시적으로 호출하므로 부모의 `Parent(int x)` 생성자가 먼저 실행되어 **B3**이 출력됩니다.
	    - 이후 자식 생성자의 나머지 코드인 **C**가 출력됩니다.
    - `new Child(5)` 실행 시 결과: **`AD5`**
	    - `Child(int x)` 생성자가 호출됩니다. 이 생성자 첫 줄에는 `super(…)`나 `this(…)`가 생략되어 있으므로, 컴파일러가 자동으로 부모의 기본 생성자 호출문인 **`super();`** 를 삽입합니다.
		- 그래서 부모의 기본 생성자인 `Parent()`가 호출되어 `A`가 먼저 출력되고, 이후 자식 생성자의 나머지 코드인 `D5`가 출력됩니다.

## 2. 부모 타입 참조변수와 자식 객체 (필드 숨김 vs 메서드 오버라이딩)

### 문제

Java

```java
class Parent {
    int x = 10;
    void show() {
        System.out.print("ParentShow");
    }
}

class Child extends Parent {
    int x = 20;
    void show() {
        System.out.print("ChildShow");
    }
}

public class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        System.out.print(p.x + "-");
        p.show();
    }
}
```

### 정답 및 해설

- **실행 결과**: `10-ChildShow`
- **핵심 해설**:
    - 필드(멤버 변수)는 참조 변수의 선언 타입(부모 타입 `Parent`)을 따릅니다. 따라서 `p.x`는 부모 클래스에 정의된 `10`을 가리킵니다.
    - **인스턴스 메서드**는 참조 변수의 타입과 관계없이 실제 생성된 객체(자식 객체 `Child`)를 기준으로 작동하여 오버라이딩된 메서드가 호출됩니다. 따라서 `p.show()`는 자식 클래스에서 재정의된 `ChildShow`를 출력합니다.
        

## 3. 오버로딩(Overloading)의 컴파일 시점 메서드 선택

### 문제

Java

```java
class Printer {
    void print(Object obj) {
        System.out.print("Object ");
    }
    void print(String str) {
        System.out.print("String ");
    }
}

public class Main {
    public static void main(String[] args) {
        Printer p = new Printer();
        Object obj = "Hello";
        String str = "World";
        
        p.print(obj);
        p.print(str);
    }
}
```

### 정답 및 해설

- **실행 결과**: `Object String`
- **핵심 해설**:
    - 오버로딩(Overloading)은 **컴파일 시점**에 결정되며, 참조 변수의 **선언 타입을 기준**으로 어떤 메서드를 실행할지 매핑합니다.
    - `obj` 변수에 실제 담긴 객체는 문자열(`"Hello"`)이지만, 변수의 선언 타입이 `Object`이므로 `print(Object obj)` 메서드가 선택되어 `Object` 가 출력됩니다.
    - `str` 변수는 선언 타입이 `String`이므로 `print(String str)` 메서드가 실행되어 `String` 이 출력됩니다.
        

## 4. static 변수·메서드와 인스턴스 멤버의 접근 관계

### 문제

Java

```java
class Counter {
    static int count = 0;
    int localCount = 0;

    Counter() {
        count++;
        localCount++;
    }
    
    static void printCount() {
        System.out.print(count);
    }
}

public class Main {
    public static void main(String[] args) {
        Counter c1 = new Counter();
        Counter c2 = new Counter();
        
        Counter.printCount();
        System.out.print("-");
        System.out.print(c2.localCount);
    }
}
```

### 정답 및 해설

- **실행 결과**: `2-1`
- **핵심 해설**:
    - `static` 변수(`count`)는 클래스에 단 하나만 존재하며 모든 인스턴스가 공유합니다. 인스턴스가 2번 생성(`new Counter()`)되었으므로 `count`는 2가 됩니다.
    - 인스턴스 변수(`localCount`)는 각 객체마다 개별적으로 할당됩니다. `c2` 객체가 생성될 때 독립된 `localCount`가 1로 증가했으므로 `c2.localCount`는 `1`이 됩니다.
        

## 5. 예외처리와 finally의 실행 흐름

### 문제

Java

```java
public class Main {
    static void test(int num) {
        try {
            if (num == 0) {
                throw new ArithmeticException();
            }
            System.out.print("A");
        } catch (ArithmeticException e) {
            System.out.print("B");
            return;
        } finally {
            System.out.print("C");
        }
        System.out.print("D");
    }

    public static void main(String[] args) {
        test(0);
        System.out.print("-");
        test(1);
    }
}
```

### 정답 및 해설

- **실행 결과**: `BC-ACD`
- **핵심 해설**:
    - `test(0)` 실행 시: `num`이 0이므로 예외가 발생하여 `catch` 블록으로 이동하고 **B**가 출력됩니다. `catch` 내부에 `return` 문이 있어 메서드가 즉시 종료되려 하지만, **`finally` 블록은 무조건 실행**되어야 하므로 **C**를 출력한 후 메서드가 완전히 종료됩니다. (결과: `BC`)
    - `test(1)` 실행 시: 예외가 발생하지 않으므로 `try` 안의 **A**가 출력되고, `finally` 안의 **C**가 출력된 후 정상 흐름으로 빠져나와 **D**가 출력됩니다. (결과: `ACD`)

### 8. 추상 클래스와 인터페이스의 다형성 구현

```Java
interface Vehicle {
    void run();
}

abstract class Car implements Vehicle {
    public void run() {
        System.out.print("Car Run-");
        sound();
    }
    abstract void sound();
}

class Sedan extends Car {
    void sound() {
        System.out.print("Vroom");
    }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v = new Sedan();
        v.run();
    }
}
```

### 정답 및 해설

- **실행 결과**: `Car Run-Vroom`
- **핵심 해설**:
    - `Sedan` 객체는 `Car`를 상속받고 `Vehicle` 인터페이스를 간접 구현하므로, 부모 인터페이스 타입인 `Vehicle v` 참조변수에 자식 객체를 대입할 수 있습니다.
    - `v.run()`을 호출하면 실제 생성된 객체 타입의 메서드를 추적해 갑니다. `Sedan`은 `run()`을 오버라이딩하지 않았으므로, 부모 클래스인 `Car` 클래스의 `run()`이 실행되어 Car Run-이 출력됩니다.
    - `run()` 내부에서 호출되는 추상 메서드 `sound()` 역시 오버라이딩 규칙에 따라 실제 생성된 하위 객체인 `Sedan`의 정의를 따라가므로 **Vroom**을 실행 및 출력합니다.
        

## 4. Java: 재귀함수(Recursive)의 연산 흐름

```Java
public class Main {
    static int fn(int n) {
        if (n <= 1) {
            return 1;
        }
        return n + fn(n - 1);
    }

    public static void main(String[] args) {
        System.out.print(fn(4));
    }
}
```

### 정답 및 해설

- **실행 결과**: `10`
- **핵심 해설**:
    - `fn(4)`는 `4 + fn(3)`을 호출합니다.
    - `fn(3)`은 `3 + fn(2)`를 호출합니다.
    - `fn(2)`는 `2 + fn(1)`을 호출합니다.
    - `fn(1)`은 기저 조건(`n <= 1`)에 따라 `1`을 반환하고 재귀 탈출을 시작합니다.
    - 역으로 합산되는 계산식은 다음과 같습니다:
        - $fn(2) = 2 + 1 = 3$
        - $fn(3) = 3 + 3 = 6$
        - $fn(4) = 4 + 6 = 10$
    - 따라서 최종 호출 값은 **10**이 됩니다.

    - `a[1:5:2]`: 인덱스 1부터 4까지 2의 간격(step)으로 추출하므로 `[20, 40]`이 출력됩니다.
    - `a[::-1]`: 간격이 음수(`-1`)이면 역순으로 슬라이싱하므로 뒤집힌 리스트 전체가 출력됩니다.
    - `a[::-2]`: 맨 뒤에서부터 시작하여 왼쪽 방향으로 2칸씩 건너뛰며 추출하므로 `[60, 40, 20]`이 됩니다.
    - `a[-4:-1]`: 음수 인덱스는 끝에서부터 `-1, -2, -3, -4` 순으로 부여됩니다. 즉 `a[-4]`는 `30`이고 `a[-1]`은 `60`입니다. 슬라이싱 범위는 마지막 인덱스 직전까지이므로 `[30, 40, 50]`이 출력됩니다.
        

## 2. 리스트의 별칭(얕은 복사) & 중첩 리스트

### 문제

Python

```python
a = [[1, 2], [3, 4]]
b = a
c = a[:]

b[0][0] = 9
c[1] = [99, 99]

print(a)
```

### 정답 및 해설
참고 > 파이썬 인터프리터는 리스트를 출력할 때 쉼표 뒤에 무조건 공백을 한 칸 띄웁니다. 붙여서 출력하지 맙시다
- **실행 결과**: `[[9, 2], [3, 4]]`
- **핵심 해설**:
    - `b = a`는 완전히 주소값 자체를 넘기는 별칭(단순 대입)이므로, `b[0][0]`의 변경은 원본 `a`에 그대로 반영됩니다.
    - `c = a[:]`는 얕은 복사(Slicing) 방식입니다. 1차원 요소인 `a[0]`, `a[1]` 리스트의 주소를 복사해 오기 때문에, 중첩된 내부 요소가 아닌 바깥쪽 요소를 교체하는 `c[1] = [99, 99]` 연산은 원본 `a[1]`에 영향을 주지 못합니다.
    - 결과적으로 원본 `a`에서는 첫 번째 행의 요소만 변경되어 `[[9, 2], [3, 4]]`가 남게 됩니다.

## 4. 가변 객체를 함수에 전달했을 때 원본 변경

### 문제

Python

```python
def fn(x, y):
    x.append(4)
    y = y + [4]

a = [1, 2, 3]
b = [1, 2, 3]

fn(a, b)
print(a, b)
```

### 정답 및 해설
> 파이썬에서 `print(a, b)`처럼 인자를 쉼표로 구분하여 출력하면, 화면에는 두 리스트 사이에 **공백(Space)이 한 칸** 들어간 상태로 출력됩니다. 붙여서 쓰지 맙시다.
- **실행 결과**: `[1, 2, 3, 4] [1, 2, 3]`
- **핵심 해설**:
    - 파이썬은 **객체 참조 전달(Call by Object Reference)** 방식을 채택합니다. 가변(Mutable) 객체인 리스트를 함수에 인자로 넘기면 동일한 메모리 주소를 공유합니다.
    - `x.append(4)`는 원본 리스트의 메모리 공간에 값을 직접 추가하므로 함수 호출 후 원본인 `a`가 변경됩니다.
    - 반면 `y = y + [4]` 연산자는 새로운 리스트인 `[1, 2, 3, 4]`를 생성한 후 변수 `y`에 대입(재할당)하는 과정입니다. 이는 원본인 `b` 객체에는 아무런 영향을 주지 않습니다.

## 6. 리스트 메서드 (append vs extend vs +=)

### 문제

Python

```python
a = [1, 2]

b.extend([3, 4])
c += [3, 4]

```

### 정답 및 해설

    - `extend(iterable)`는 전달받은 연속 데이터의 **모든 요소를 하나씩 꺼내어** 리스트 끝에 이어 붙여 확장합니다.
    - `+=` (덧셈 누적 대입) 연산자는 내부적으로 `extend()`와 완전히 동일한 원리로 동작하므로 개별 요소들이 풀려서 누적 추가됩니다.
        

## 7. 클래스·상속의 기본 실행 구조

## 3. WHERE, GROUP BY, HAVING, ORDER BY의 처리 순서

### 문제

SQL

```sql
-- [Query 3]
SELECT DEPTNO, SUM(SAL)
FROM EMP
WHERE DEPTNO IS NOT NULL
GROUP BY DEPTNO
HAVING SUM(SAL) >= 2500
ORDER BY DEPTNO DESC;
```

### 정답 및 해설

- **[Query 3] 결과**:

|**DEPTNO**|**SUM(SAL)**|
|---|---|
|10|4500|

- **핵심 해설**:
    - **실행 순서**: `FROM` $\rightarrow$ `WHERE` $\rightarrow$ `GROUP BY` $\rightarrow$ `HAVING` $\rightarrow$ `SELECT` $\rightarrow$ `ORDER BY`
        
    
    1. **`WHERE`**: `DEPTNO`가 `NULL`인 JUNG을 먼저 걸러내어 사원 4명만 남깁니다.
    2. **`GROUP BY`**: 부서별(`10`번, `20`번) 그룹을 묶어 합산합니다.
        
        - 10번 부서의 `SUM(SAL)` = $3000 + 1500 = 4500$
        - 20번 부서의 `SUM(SAL)` = $2000 + NULL = 2000$
            
    3. **`HAVING`**: 그룹화된 결과 중 합계가 2500 이상인 그룹만 필터링하므로 `20`번 부서($2000$)가 탈락합니다.
    4. **`ORDER BY`**: 남은 `10`번 부서의 데이터가 최종 정렬되어 출력됩니다.

- **핵심 해설**:
    - **`INSERT`**: `INSERT INTO 테이블명 (컬럼1, 컬럼2) VALUES (값1, 값2)` 형식을 따릅니다. `INTO`와 `VALUES` 키워드를 빠뜨리지 않도록 주의합니다.
    - **`UPDATE`**: `UPDATE 테이블명 SET 컬럼 = 값 WHERE 조건` 형식을 따릅니다. `SET` 키워드 위치와 특정 행만 변경하기 위해 필요한 `WHERE` 조건을 정확히 기술해야 합니다.
    - **`DELETE`**: `DELETE FROM 테이블명 WHERE 조건` 형식을 따릅니다. `DELETE * FROM` 이나 `DELETE COLUMNS` 같은 잘못된 표현을 쓰지 않도록 `FROM` 키워드와의 연계를 숙지해야 합니다.
        

## 3. ALTER TABLE (컬럼 추가, 변경, 삭제)

### 문제

SQL

```sql
-- [Query 3-1]
ALTER TABLE STUDENT ADD PHONE VARCHAR(15);

-- [Query 3-2]
ALTER TABLE STUDENT MODIFY NAME VARCHAR(30) NOT NULL;

-- [Query 3-3]
ALTER TABLE STUDENT DROP COLUMN PHONE;
```

### 정답 및 해설

- **핵심 기능**: 이미 존재하는 테이블의 구조(스키마)를 변경합니다.
- **핵심 해설**:
    - **컬럼 추가 (`ADD`)**: `ALTER TABLE 테이블명 ADD 컬럼명 데이터타입` 구조를 가지며 `COLUMN` 키워드는 쓰지 않습니다.
    - **컬럼 변경 (`MODIFY` / `ALTER`)**: `ALTER TABLE 테이블명 MODIFY 컬럼명 데이터타입` 구조를 가지며, DBMS에 따라 `ALTER COLUMN`을 사용하기도 하나 정보처리기사 채점 기준상 수제비 교재에 기술된 `MODIFY`를 기본으로 기억해 두는 것이 안전합니다.
    - **컬럼 삭제 (`DROP COLUMN`)**: 컬럼을 삭제할 때는 `DROP` 단독이 아니라 `DROP COLUMN 컬럼명`과 같이 `COLUMN` 키워드를 반드시 명시해 주어야 합니다.
        

## 4. DCL (GRANT, REVOKE)

### 문제

SQL

```sql
-- [Query 4-1]
GRANT SELECT, INSERT ON STUDENT TO HONG;

-- [Query 4-2]
REVOKE SELECT, INSERT ON STUDENT FROM HONG;
```

### 정답 및 해설

- **핵심 기능**: 데이터 제어어로, 유저에게 권한을 부여하거나 회수합니다.
- **핵심 해설**:
    - **`GRANT` (권한 부여)**: `GRANT 권한 ON 대상 TO 유저` 구조를 가집니다. 전치사 `TO`를 사용한다는 점이 핵심입니다.
    - **`REVOKE` (권한 회수)**: `REVOKE 권한 ON 대상 FROM 유저` 구조를 가집니다. 전치사 `FROM`을 사용해 대상 유저로부터 빼앗아 온다는 의미를 가집니다.
        

## 5. 트랜잭션 제어 (COMMIT, ROLLBACK, SAVEPOINT)

### 문제

SQL

```sql
-- [SQL 실행 흐름]
UPDATE STUDENT SET NAME = 'A' WHERE STU_ID = 1;
SAVEPOINT S1;

UPDATE STUDENT SET NAME = 'B' WHERE STU_ID = 2;
SAVEPOINT S2;

UPDATE STUDENT SET NAME = 'C' WHERE STU_ID = 3;
ROLLBACK TO S1;

COMMIT;
```

### 정답 및 해설

- **최종 반영 상태**: `STU_ID = 1`의 이름만 `'A'`로 최종 변경 및 확정 반영됩니다.
- **핵심 해설**:
    
    1. 첫 번째 업데이트 후 `S1` 지점을 저장합니다.
    2. 두 번째 업데이트 후 `S2` 지점을 저장합니다.
    3. 세 번째 업데이트를 진행한 뒤 `ROLLBACK TO S1`을 실행합니다.
    4. 이에 따라 `S1` 지점 이후에 발생했던 모든 작업(두 번째, 세 번째 업데이트)들이 완전히 취소되고 `S1` 저장 시점으로 타임슬립을 하게 됩니다.
    5. 마지막으로 `COMMIT`을 통해 `S1`까지의 정상 작업(첫 번째 업데이트)만 물리 디스크에 영구적으로 확정 반영합니다.
