노트 제목만큼이나 중요한 것이 바로 그 노트를 뒷받침하는 '자료'들의 이름입니다. 파일명 규칙은 장기적으로 시스템의 안정성과 검색 용이성을 결정하는 중요한 요소이며, 특히 **링크가 깨지는 것을 방지**하고 **데이터를 미래에도 안전하게 보존**하는 데 결정적인 역할을 합니다.

각 파일의 '역할'이 다르므로, PDF와 이미지의 명명 전략은 달라야 합니다.

- **PDF 파일:** 직접 검색하고 참조하는 '정보 자산'이므로, **사람이 이해하기 좋은 정보**를 담아 수동으로 이름을 부여합니다.
- **이미지 파일:** 대부분 노트 안에 삽입되어 '보여지는' 요소이므로, **컴퓨터가 관리하기 좋은 고유성**을 담아 자동으로 이름을 부여합니다.

### 1. PDF 파일: 나의 '디지털 도서관' 서고 정리법

PDF 파일은 당신의 지식 공장에 들어오는 '원자재'이자, 당신의 '디지털 도서관'에 꽂히는 책입니다. 따라서, 도서관의 도서 관리법처럼 명확하고 일관된 규칙을 따르는 것이 좋습니다. 이 파일들은 `01_Sources/` 폴더에 저장됩니다.

#### 추천 형식: `저자(혹은 출처)년도 - 핵심 제목.pdf`

- **저자년도:** 학술 자료를 관리하는 가장 표준적인 방식입니다. 파일 탐색기에서 저자별, 그리고 연도순으로 정렬되어 보기 좋습니다. 저자가 명확하지 않은 공식 문서 등은 출처(기관명)를 사용합니다.
- **핵심 제목:** 책이나 논문의 전체 제목을 다 쓸 필요 없이, 내용을 명확히 알 수 있는 핵심 키워드만 사용합니다.

#### 실제 예시

- `Tanenbaum2021 - Computer Networks.pdf`
- `Martin2008 - Clean Code.pdf`
- `Oracle2024 - Java SE 22 Documentation.pdf`
- `Google2017 - Attention Is All You Need.pdf` (논문 예시)

#### 왜 이 방식인가?

1. **일관성과 정렬:** 파일 목록이 저자-연도순으로 깔끔하게 정렬됩니다.
2. **정보성:** 파일명만 봐도 누가, 언제, 무엇에 대해 쓴 자료인지 즉시 파악할 수 있습니다.
3. **연결성:** 이 파일명 규칙은 이전에 정한 **소스 노트 제목 형식(`[S] 저자년도 - 제목`)과 완벽하게 일치**합니다. `[S] Tanenbaum2021 - Computer Networks.md` 노트가 `Tanenbaum2021 - Computer Networks.pdf` 파일을 참조한다는 관계가 명확해져 인지적 부담이 줄어듭니다.

### 2. 이미지 파일: '자동화'로 완성하는 노트의 시각적 조각들

이미지는 노트의 일부로 삽입되는 '부품'입니다. 따라서 우리가 직접 파일명을 고민할 필요가 전혀 없습니다. 이 작업은 **플러그인을 통해 완전히 자동화**하여, "이 파일 이름 뭘로 하지?"라는 사소한 마찰조차 제거하는 것이 핵심입니다. 이 파일들은 `_Attachments/` 폴더에 저장됩니다.

#### 추천 형식: `노트제목_YYYYMMDDHHmmss.png`

- **노트제목:** 이미지가 어떤 노트에 속해있는지 명확한 문맥을 제공합니다. 만약 링크가 깨지더라도 파일명만 보고 어느 노트의 이미지였는지 쉽게 추적할 수 있습니다.
- **YYYYMMDDHHmmss (날짜시간초):** **파일 이름의 절대적인 고유성을 보장**합니다. `screenshot.png` 와 같은 이름으로 저장하다가 파일을 덮어쓰는 끔찍한 실수를 원천적으로 방지합니다.

#### 자동화 설정 방법 (강력 추천)

1. **커뮤니티 플러그인 설치:** `설정` > `커뮤니티 플러그인` > `탐색`에서 `Paste image rename` 플러그인을 찾아 설치하고 활성화합니다.
    
2. **플러그인 설정:** `설정` > `Paste image rename`으로 이동합니다.
    
3. **Image name pattern 설정:** 아래와 같이 입력합니다.
    
    ```
    {{fileName}}_{{date:YYYYMMDDHHmmss}}
    ```
    
4. **설정 완료!** 이제 당신이 할 일은 그저 노트에 이미지를 복사-붙여넣기(`Ctrl+V`) 하는 것뿐입니다.
    
    예를 들어, `TCP 3-way-handshake` 노트에 스크린샷을 붙여넣으면, 플러그인이 자동으로 파일명을 `TCP 3-way-handshake_20250624144530.png` 와 같이 만들어서 `_Attachments/` 폴더에 저장해 줍니다.
    


**"Set it and forget it."** 한 번만 설정해두면 당신은 다시는 이미지 파일명에 대해 고민할 필요가 없습니다. 고민과 결정의 단계를 제거하고, 오직 '붙여넣기'라는 행동만 남기는 것. 이것이 바로 마찰을 줄이고 창작의 흐름을 유지하는 가장 좋은 방법입니다.

### 마지막 조언: 파일명에 한글 사용에 대하여

현대 운영체제는 파일명에 한글(유니코드)을 잘 지원합니다. 하지만, **장기적인 안정성과 호환성을 생각한다면 파일명 자체에는 영문, 숫자, 하이픈(-), 언더스코어(_)만 사용하는 것을 권장**합니다.

- **이유:** 나중에 Git으로 버전을 관리하거나, 웹에 노트를 게시하거나, 다른 도구와 연동할 때 예기치 않은 인코딩 문제로부터 자유로워질 수 있습니다.
- **적용:**
    - PDF: `저자년도-Title.pdf` (O)
    - 이미지: `NoteTitle_Timestamp.png` (O)
    - **노트 제목 자체 (`TCP 3-way-handshake.md`)는 한글을 자유롭게 사용해도 괜찮습니다.** 옵시디언이 내부적으로 잘 처리해 줍니다. 여기서 말하는 것은 첨부되는 '파일'의 이름입니다.

이 규칙들을 통해 당신의 '지식 공장'은 시간이 지나 데이터가 쌓여도 흔들림 없는 안정적인 기반을 갖추게 될 것입니다.
