#### **1. 시스템 개요 및 핵심 철학**

본 시스템은 정보를 단순 저장하는 것을 넘어, 체계적인 파이프라인을 통해 새로운 지식과 결과물을 '생산'하는 것을 목표로 하는 '지식 공장(Knowledge Factory)' 모델입니다.

핵심 운영 철학은 **'이원화 전략(Two-Mode Strategy)'**으로, 모든 지식 활동을 아래 두 가지 모드로 명확히 분리하여 인지적 부담을 최소화합니다.

- **수집 모드 (Capture Mode):** 외부 정보를 마찰 없이 시스템 내부로 가져오는 데만 집중하는 단계. (판단과 분석을 배제)
    
- **사색 모드 (Contemplation Mode):** 수집된 정보를 가공, 연결, 종합하여 의미 있는 지식으로 만드는 데 집중하는 단계. (새로운 정보 유입을 차단)

### **2. 시스템 구성 요소 및 데이터 흐름**

시스템은 4가지 핵심 노트 유형으로 구성되며, 정보는 아래 순서로 정제 및 가공됩니다.

#### **2.1. 소스 노트 (Source Note)**

- **역할/목적:** 하나의 외부 정보원(책, 논문 PDF, 아티클 등)에서 발췌한 모든 유의미한 정보 조각들을 **원본의 맥락을 보존한 채 그대로 보관하는 1차 아카이브**입니다.
    
- **시스템 비유:** 고고학의 **'발굴 일지(Excavation Log)'**. 발굴 현장에서 나온 모든 유물 조각의 위치와 상태를 빠짐없이 기록한 원본 기록입니다.
    
- **핵심 속성:**
    
    - **Raw & Unfiltered:** 가공되지 않은 날것의 데이터.
        
    - **Context-Preserving:** 각 정보 조각은 원본 소스의 정확한 위치(`page`, `selection` 등)로 돌아갈 수 있는 링크를 포함합니다.
        
    - **1:1 Mapping:** 하나의 소스 파일은 하나의 소스 노트에 대응됩니다.
        
- **입력 (Input):** `PDF++` 등의 도구를 통해 외부 정보원에서 가져온 모든 하이라이트 텍스트 및 사용자 주석(Comment).
    
- **출력 (Output):** 사용자에 의해 선택된 텍스트 블록. `노트 작성기(Note Composer)`의 '추출' 기능을 통해 개념 노트로 이동합니다.
    

#### **2.2. 개념 노트 (Concept Note)**

- **역할/목적:** 여러 소스에서 수집된 정보 조각들을 사용자의 언어로 **재구성하고 종합하여, 하나의 명확하고 원자적인(Atomic) 아이디어를 설명하는 핵심 지식 단위**입니다.
    
- **시스템 비유:** 발굴된 원석을 다듬어 만든 **'보석(Gemstone)'** 또는 다른 구조물을 만드는 데 쓰이는 **'레고 블록(Lego Brick)'**.
    
- **핵심 속성:**
    
    - **Synthesized:** 사용자의 관점과 언어로 재가공된 정보.
        
    - **Atomic:** 노트 하나는 오직 하나의 아이디어나 개념만을 다룹니다.
        
    - **Evidence-Based:** 모든 주장은 각주(Footnote) 형식을 통해 소스 노트의 특정 블록을 근거로 제시하여 신뢰성을 확보합니다.
        
- **입력 (Input):** 소스 노트에서 추출된 텍스트 블록, 다른 개념 노트와의 연결, 사용자의 독창적인 생각.
    
- **출력 (Output):** 상위 주제를 구성하기 위해 MOC로 향하는 링크. 최종 결과물(글, 발표)을 만드는 데 사용되는 핵심 재료.
    

#### **2.3. MOC (Map of Content)**

- **역할/목적:** 특정 주제에 대해 흩어져 있는 **여러 개념 노트를 논리적인 순서와 구조에 따라 연결하고, 전체적인 맥락을 조망하는 상위 레벨의 '지도'**입니다.
    
- **시스템 비유:** 박물관의 **'전시관 안내도(Museum Map)'** 또는 책의 **'목차(Table of Contents)'**.
    
- **핵심 속성:**
    
    - **Structural:** 내용보다는 구조와 연결에 집중합니다.
        
    - **Navigational:** 특정 주제에 대한 진입점(Entry Point) 및 탐색 경로를 제공합니다.
        
    - **Topic-Oriented:** 하나의 MOC는 하나의 큰 주제 영역을 담당합니다.
        
- **입력 (Input):** 충분히 성숙하고 정제된 개념 노트들의 링크.
    
- **출력 (Output):** 주제에 대한 거시적 관점, 새로운 아이디어 연결을 촉발하는 사고의 작업대.

### **3. 핵심 자동화**

- 이 시스템의 데이터 흐름은 주로 옵시디언 코어 플러그인 **'노트 작성기(Note Composer)'**를 통해 자동화됩니다.
    
    - **추출 (Extract):** 소스 노트의 원시 데이터를 개념 노트 템플릿에 맞춰 자동으로 생성하고 연결합니다.
        
    - **병합 (Merge):** 유사한 개념 노트들을 하나의 노트로 통합하여 지식의 밀도를 높입니다.
### **4. 핵심 구현 상세 (Key Implementation Details)**

시스템의 안정적이고 효율적인 운영을 위해 아래와 같은 구조와 규칙을 채택합니다.

#### **4.1. 폴더 구조 (Folder Structure)**

본 시스템은 '주제'가 아닌, 정보의 '처리 상태'와 '역할'에 따라 폴더를 최소한으로 구성합니다.

- `01_Sources/`: 모든 **소스 노트**를 보관합니다.
    
- `02_Notes/`: 모든 **개념 노트**와 **MOC**를 보관하는 메인 작업 공간입니다.
    
- `03_Assets/`: 이미지, 원본 PDF 등 모든 첨부 파일이 저장되는 폴더입니다.
    
- `99_System/`: 모든 **템플릿 파일**과 스크립트 파일을 보관합니다.
    

#### **4.2. 노트 명명 규칙 (Note Naming Conventions)**

- **소스 노트:** `[S] {소스 제목}` 또는 `YYYY-MM-DD_{소스 제목}`. (예: `[S] 지식 공장 시스템 설명서`)
    
- **개념 노트:** `{개념 이름}` (예: `뽀모도로 기법`)
    
- **MOC:** `MOC - {주제 이름}` (예: `MOC - 생산성`)

#### **4.4. 주요 자동화 설정 요약 (Key Automation Settings Summary)**

- **PDF++:**
    
    - **복사 포맷:** `- {{text}} ([[{{file.path}}#page={{page}}&selection={{position.join(',')}}]])` 로 설정하여, 소스 노트에는 순수한 텍스트와 링크만 아카이빙합니다.
        
- **노트 작성기 (Note Composer):**
    
    - **추출 후 텍스트:** `새 파일에 링크`로 설정하여 소스 노트와 개념 노트의 연결성을 자동 생성합니다.
        
    - **템플릿 파일 위치 (상황별 변경):**
        
        - **평소(새 개념 노트 생성 시):** `_Templates/T - 개념 노트.md`로 설정합니다.
            
        - **기존 노트에 각주만 추가 시:** 설정을 잠시 `_Templates/T - 추출용 각주.md`로 변경하고 '추출' 기능을 실행합니다.
            
    - **파일 병합:** 비슷한 개념 노트를 하나로 합쳐 지식의 밀도를 높이는 데 사용합니다.
