MOC의 주제 범위를 정하는 가장 좋은 방법은 **책의 목차**를 만든다고 생각하는 것입니다. 너무 크지도, 너무 작지도 않은 적절한 중간 지점을 찾는 것이 중요합니다.

가장 쉬운 규칙은 **"이 주제에 대해 할 말이 3개 이상인가?"** 라고 스스로에게 물어보는 것입니다.

---

### MOC 주제 범위 예시 (큰 것부터 작은 것 순서)

MOC는 폴더처럼 여러 단계의 깊이를 가질 수 있습니다.

#### 🌳 레벨 1: 최상위 MOC (가장 큰 주제)

이것은 당신의 관심사 중 가장 큰 기둥들입니다. 인생의 큰 카테고리라고 생각하면 쉽습니다.

- `MOC - 생산성`
    
- `MOC - 건강`
    
- `MOC - 프로그래밍`
    
- `MOC - 투자`
    

#### 🌿 레벨 2: 중간 MOC (중간 주제)

최상위 MOC를 좀 더 구체적인 하위 주제로 나눈 것입니다.

- `MOC - 생산성` 아래에:
    
    - `MOC - 시간 관리 기법`
        
    - `MOC - 목표 설정`
        
    - `MOC - 지식 관리` (바로 이 주제입니다!)
        
- `MOC - 프로그래밍` 아래에:
    
    - `MOC - 파이썬`
        
    - `MOC - 웹 개발 기초`
        

#### 🌱 레벨 3: 실무 MOC (작고 구체적인 주제)

중간 MOC를 더 잘게 나누어, 특정 프로젝트나 기술에 집중하는 MOC입니다.

- `MOC - 지식 관리` 아래에:
    
    - `MOC - 옵시디언 플러그인`
        
    - `MOC - PARA 메소드`
        
- `MOC - 파이썬` 아래에:
    
    - `MOC - 데이터 분석 라이브러리`
        
    - `MOC - 웹 크롤링`

### ## 언제, 어떤 레벨의 MOC를 만들어야 할까?

**처음에는 레벨 2나 레벨 3의 작은 MOC부터 시작하는 것이 가장 좋습니다.**

예를 들어, `[[뽀모도로 기법]]`, `[[GTD]]`, `[[아이젠하워 매트릭스]]` 라는 개념 노트를 만들었다면, 이들을 묶어줄 `MOC - 시간 관리 기법` (레벨 2)을 만드는 식입니다.

나중에 `MOC - 시간 관리 기법`, `MOC - 목표 설정` 같은 중간 MOC들이 여러 개 생기면, 그때 가서야 이들을 모두 묶어줄 최상위 MOC인 `MOC - 생산성` (레벨 1)을 만들어도 전혀 늦지 않습니다.

**결론:** 처음부터 거대한 주제로 시작하지 마세요. 구체적이고 작은 주제에 대한 개념 노트가 3~5개 쌓이면, 그것들을 묶어주는 **작은 MOC**를 만드는 것부터 시작하는 것이 가장 쉽고 효과적인 방법입니다.
