### 소스/노트 제목을 위한 3가지 황금률

어떤 노트를 작성하든, 아래 3가지 원칙을 항상 기억하세요.

1. **연결하기 쉬울 것 (Easy to Link):** 글을 쓰다가 자연스럽게 떠올려 `[[` 안에 입력할 수 있는 이름이어야 합니다.
2. **찾기 쉬울 것 (Easy to Find):** `Ctrl+O`로 검색할 때 키워드 몇 글자만으로도 바로 찾을 수 있어야 합니다.
3. **한눈에 파악될 것 (Easy to Understand):** 제목만 봐도 노트의 내용과 종류가 짐작되어야 합니다.

이 원칙에 따라, 노트의 '종류'별로 추천하는 제목 형식은 다음과 같습니다.

### 각 형식에 대한 상세 설명 및 Best Practice

#### 1. 개념 노트 (가장 중요!)

- **원칙:** 위키피디아의 항목 제목처럼 짓는다고 생각하세요. 간결하고 명확하게 해당 개념의 본질을 담아야 합니다.
- **Best Practice:**
    - **구체적으로 작성하세요:** '알고리즘' (X) → '퀵 정렬 알고리즘' (O)
    - **필요하면 괄호로 구분하세요:** 개념이 중복될 수 있다면, `환경변수 (리눅스)` 와 `환경변수 (윈도우)` 처럼 괄호를 사용해 맥락을 명시해 주세요.
    - **질문 형태로도 가능합니다:** '좋은 API 디자인이란 무엇인가?' 와 같이 탐구하고 싶은 질문 그 자체를 제목으로 삼을 수도 있습니다.

#### 2. 소스 노트

- **원칙:** 이 노트는 당신의 생각이 아닌, '원본 자료'에 대한 메타데이터와 하이라이트를 담는 곳임을 명확히 해야 합니다.
- **Best Practice:**
    - **`[S]` 접두사:** 검색 시 `-[S]` 옵션을 주면 모든 소스 노트를 제외하고 순수 개념 노트만 검색할 수 있어 매우 유용합니다.
    - **파일명 일치:** `01_Sources/` 폴더의 PDF 파일명과 소스 노트의 제목을 일치시키면 혼란을 방지할 수 있습니다. (`Tanenbaum2021 - Computer Networks.pdf` → `[S] Tanenbaum2021 - Computer Networks.md`)

#### 3. MOC (내용의 지도)

- **원칙:** 이 노트가 해당 주제의 '허브' 역할을 한다는 것을 명확히 해야 합니다.
- **Best Practice:**
    - **`MOC` 접미사:** 제목 끝에 항상 'MOC'를 붙여 일관성을 유지하세요.
    - **계층적 MOC:** 더 큰 주제는 상위 MOC로 묶을 수 있습니다. 예를 들어, `프로그래밍 MOC` 노트 안에 `[[자바 MOC]]`, `[[파이썬 MOC]]` 등을 링크할 수 있습니다.

### 절대 피해야 할 제목 형식 (Anti-Patterns)

- **날짜 사용 금지 (데일리 노트 제외):** `2025-06-24 API 설계.md` (X)
    - **이유:** 노트의 가치는 생성된 날짜가 아니라 그 내용 자체에 있습니다. 날짜는 노트의 재사용성과 연결성을 심각하게 저해합니다. 날짜 정보는 파일 속성이나 템플릿으로 자동 기록하면 충분합니다.
- **특수문자 사용 금지:** `네트워크/TCP.md` (X)
    - **이유:** 슬래시(`/`), 콜론(`:`) 등은 파일 시스템에서 문제를 일으킬 수 있으며, 링크 생성 시 혼란을 줍니다.
- **지나치게 일반적인 제목:** `노트.md`, `아이디어.md` (X)
    - **이유:** 나중에 이 제목만 보고는 내용을 절대 유추할 수 없으며, 검색과 연결이 거의 불가능해집니다.

이 명명 규칙은 처음에는 조금 어색하게 느껴질 수 있지만, 몇 번만 의식적으로 적용하면 곧 당신의 '두 번째 뇌'에 내장된 습관이 될 것입니다. 이 규칙이 당신의 지식 공장이 혼돈에 빠지지 않도록 지켜주는 든든한 가드레일이 되어줄 것입니다.
