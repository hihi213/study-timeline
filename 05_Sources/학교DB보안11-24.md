## Step 1. JDBC 핵심 복습 & PreparedStatement - DB보안 1교시_2025.11.24

### Goal & Preconditions

- **Goal**: SQL Injection 방지 및 가독성 향상을 위해 `PreparedStatement`의 사용법을 이해한다.
- **Preconditions**: Oracle DB 연결 설정 완료.
    

### Concept

- **PreparedStatement**: SQL 문장을 미리 컴파일하여 DB에 전송하고, 변수 부분만 나중에 `?`(Place holder)로 바인딩하는 방식.
- **Statement vs PreparedStatement**:
    - `Statement`: `String sql = "SELECT * FROM T WHERE ID='" + id + "'";` (문자열 결합, 가독성 낮음, 보안 취약)
    - `PreparedStatement`: `String sql = "SELECT * FROM T WHERE ID = ?";` (가독성 높음, 성능 유리, 보안 우수)
        

### Build & Execute

#### Logic

1. SQL문에 변수가 들어갈 자리를 `?`로 작성.
2. `con.prepareStatement(sql)`로 객체 생성.
3. `pstmt.setString(1, 값)`, `pstmt.setInt(2, 값)` 등으로 데이터 바인딩.
4. `executeQuery()`(조회) 또는 `executeUpdate()`(변경) 실행.
    

### 💡 Interview

> [!faq]- Q. Statement와 PreparedStatement의 차이점은?
>
> 🗣️ 핵심 답변
>
> Statement는 SQL문을 매번 완벽한 문자열로 만들어 실행하므로 캐싱 효율이 낮고 SQL Injection에 취약합니다. 반면 PreparedStatement는 쿼리 구조를 미리 컴파일해두고 변수만 바인딩(?)하므로 성능이 우수하고 특수문자 처리를 자동으로 해주어 보안성이 높습니다.
>
> **📚 꼬리질문 대비**
>
> - **Example**: `' OR '1'='1` 같은 공격을 막을 수 있습니다.
>

## Step 2. GUI 프로젝트 구조 분석 (Skeleton Code) - DB보안 1교시_2025.11.24

### Goal & Preconditions

- **Goal**: 교수님이 제공한 `DB_MemTable.java`의 레이아웃과 이벤트 처리 흐름을 파악한다.
    

### Concept

- **Layout Manager**:
    - **BorderLayout**: 동/서/남/북/센터로 영역을 나눔. (Center: `JTable`, West: 입력 필드, North: 버튼)
    - **JTable**: DB 데이터를 엑셀처럼 보여주는 컴포넌트. `DefaultTableModel`을 통해 데이터를 관리함.
- **Modularization (모듈화)**: `DBConn()`과 `DBClose()`를 별도 메소드로 분리하여 코드 중복을 제거함.
    

### Build & Execute

#### Logic (Code Analysis)

1. **Main Frame**: `JFrame` 상속, `JTable`(데이터 표시), `JPanel`(입력 폼), `JButton`(동작 트리거).
2. **Event Listener**: `MyAction` 클래스에서 버튼 클릭(`actionPerformed`) 감지 → 각 기능(`funAdd`, `funDel` 등) 호출.
3. **Update Dialog**: 수정 기능은 별도의 `JDialog`(`UpdateDialog` 클래스)를 띄워 처리.
    

#### **Pitfalls**

- ⚠️ **OracleDataSource 사용**: `DriverManager.getConnection()` 대신 `OracleDataSource` 객체를 사용하여 URL과 계정 정보를 설정함. (기능은 동일하나 방식이 다름)
- ⚠️ **Thread Safety**: Swing은 기본적으로 **Single Thread** 모델이므로, DB 작업이 너무 오래 걸리면 화면이 멈출 수 있음(이번 예제는 간단해서 무시).

## Step 3. 조회(Select) 및 추가(Add) 구현 - DB보안 1교시_2025.11.24

### Goal & Preconditions

- **Goal**: `funSelect()`로 테이블에 DB 데이터를 뿌리고, `funAdd()`로 새 데이터를 DB에 넣는다.
- **Preconditions**: `STUDENT` 테이블이 존재해야 함.
    

### Build & Execute

#### Logic

1. **funSelect (조회)**
    
    - `DBConn()` 연결.
    - `SELECT * FROM STUDENT` 실행.
    - `JTable`의 모델(`DefaultTableModel`)을 초기화(기존 행 삭제).
    - `rs.next()`로 반복하며 `model.addRow()` 수행.
    - `DBClose()`.
        
2. **funAdd (추가)**
    
    - 입력 필드(`tfs[]`)에서 값 추출.
    - `INSERT INTO STUDENT VALUES(?, ?, ?)` SQL 작성.
    - `PreparedStatement` 파라미터 바인딩.
    - `executeUpdate()` 실행.
    - 성공 시 UI 테이블에도 `addRow`하여 DB 재조회 없이 즉시 반영(UX 향상).
        

#### Code (Implementation)

Java

```Java
// 조회 기능 구현
void funSelect() {
    try {
        DBConn();
        // 모델 초기화 (기존 데이터 삭제)
        DefaultTableModel model = (DefaultTableModel) table.getModel();
        model.setRowCount(0); 

        String sql = "SELECT * FROM STUDENT ORDER BY STU_ID";
        stmt = con.createStatement();
        rs = stmt.executeQuery(sql);

        while (rs.next()) {
            String id = rs.getString("STU_ID");
            String name = rs.getString("NAME");
            String addr = rs.getString("ADDRESS");
            // JTable 모델에 행 추가
            model.addRow(new Object[]{id, name, addr});
        }
    } catch (Exception e) {
        System.out.println("Select Error: " + e.getMessage());
    } finally {
        DBClose();
    }
}

// 추가 기능 구현
void funAdd() {
    try {
        DBConn();
        String sql = "INSERT INTO STUDENT (STU_ID, NAME, ADDRESS) VALUES (?, ?, ?)";
        pstmt = con.prepareStatement(sql);
        
        // UI 텍스트필드에서 값 가져오기 (tfs[0]:학번, tfs[1]:이름, tfs[2]:주소)
        String id = tfs[0].getText().trim();
        String name = tfs[1].getText().trim();
        String addr = tfs[2].getText().trim();

        pstmt.setString(1, id);
        pstmt.setString(2, name);
        pstmt.setString(3, addr);
        
        int res = pstmt.executeUpdate();
        if (res > 0) {
            // DB 성공 시 화면에도 추가
            DefaultTableModel model = (DefaultTableModel) table.getModel();
            model.addRow(new Object[]{id, name, addr});
            
            // 입력창 비우기
            for(JTextField tf : tfs) tf.setText("");
        }
    } catch (Exception e) {
        System.out.println("Insert Error: " + e.getMessage());
    } finally {
        DBClose();
    }
}
```

#### **Pitfalls**

- ⚠️ **PK 중복 에러**: 이미 존재하는 학번을 입력하고 '추가'를 누르면 `ORA-00001` 발생. `try-catch`에서 에러 메시지를 콘솔로 확인해야 함.
- ⚠️ **화면 갱신**: DB에만 넣고 화면(`JTable`)에 추가 안 하면 사용자는 버튼을 눌러도 반응이 없다고 생각함. 반드시 `model.addRow` 또는 `funSelect()` 재호출 필요.

## Step 4. 삭제(Delete) 및 수정(Update) 구현 - DB보안 1교시_2025.11.24

### Goal & Preconditions

- **Goal**: `JTable`에서 선택한 행을 삭제하거나(`funDel`), 별도의 팝업창(`UpdateDialog`)을 띄워 수정(`funUpdate`)한다.
- **Preconditions**: `JTable`에 데이터가 조회된 상태여야 하며, 사용자가 특정 행을 클릭(Select)한 상태여야 한다.
    

### Concept

- **Data Synchronization (데이터 동기화)**: DB에서 데이터를 지웠으면 화면(`JTable`)에서도 즉시 지워야 하고, 수정했으면 화면도 갱신되어야 한다. 이를 위해 DB 작업 성공 여부(`executeUpdate` > 0)를 확인 후 UI 모델(`DefaultTableModel`)을 조작한다.
- **Primary Key Constraint (PK 제약)**: 수정 시, 식별자인 '학번(PK)'은 변경하지 못하도록 UI에서 비활성화(`setEnabled(false)`) 처리해야 데이터 무결성이 깨지지 않는다.
    

### Build & Execute

#### Logic (Delete)

1. **행 선택 확인**: `table.getSelectedRow()`가 `-1`이면 선택된 행이 없는 것이므로 경고 메시지 출력 후 중단.
2. **PK 추출**: 선택된 행의 0번째 컬럼(학번) 값을 가져온다 (`getValueAt`).
3. **DB 삭제**: `DELETE FROM STUDENT WHERE STU_ID = ?` 실행.
4. **UI 삭제**: DB 삭제 성공 시 `model.removeRow(row)`를 호출하여 화면에서 즉시 제거.
    

#### Logic (Update)

1. **다이얼로그 호출**: `funUpdate()`는 선택된 행의 데이터를 담아 `UpdateDialog` 객체를 생성 및 표시(`setVisible(true)`).
2. **UI 제어**: 다이얼로그 생성자에서 학번 필드(`tfs[0]`)를 `setEnabled(false)`로 설정하여 수정 불가 처리.
3. **DB 수정 (Dialog 내부)**: '수정' 버튼 클릭 시 `UPDATE STUDENT SET NAME=?, ADDRESS=? WHERE STU_ID=?` 실행.
4. **UI 갱신**: 수정 완료 후 다이얼로그를 닫고, 부모 창의 데이터를 새로고침(`funSelect` 재호출 권장)하거나 모델 값을 직접 변경.
    

#### Code (Implementation)

Java

```Java
// 삭제 기능 구현
void funDel() {
    if (row == -1) {
        JOptionPane.showMessageDialog(this, "삭제할 레코드를 선택하세요.");
        return;
    }
    
    // 사용자 확인 (선택 사항)
    int confirm = JOptionPane.showConfirmDialog(this, "정말 삭제하시겠습니까?", "삭제", JOptionPane.YES_NO_OPTION);
    if (confirm != JOptionPane.YES_OPTION) return;

    try {
        DBConn();
        String sql = "DELETE FROM STUDENT WHERE STU_ID = ?";
        pstmt = con.prepareStatement(sql);
        
        // JTable 모델에서 현재 선택된 행의 '학번(Index 0)' 가져오기
        DefaultTableModel model = (DefaultTableModel) table.getModel();
        String selectedId = (String) model.getValueAt(row, 0);
        
        pstmt.setString(1, selectedId);
        
        int res = pstmt.executeUpdate();
        if (res > 0) {
            model.removeRow(row); // 화면에서도 삭제
            row = -1; // 선택 초기화
        }
    } catch (Exception e) {
        System.out.println("Delete Error: " + e.getMessage());
    } finally {
        DBClose();
    }
}

// 수정 기능 (다이얼로그 호출)
void funUpdate() {
    if (row == -1) {
        JOptionPane.showMessageDialog(this, "수정할 레코드를 선택하세요.");
        return;
    }
    // UpdateDialog 생성 시 현재 프레임(this)을 부모로 전달
    new UpdateDialog(this).setVisible(true);
}
```

#### **Pitfalls**

- ⚠️ **선택 없이 버튼 클릭**: 사용자가 리스트를 클릭하지 않고 '삭제'나 '수정'을 누르면 `ArrayIndexOutOfBoundsException`이나 `-1` 인덱스 에러가 발생함. 반드시 `row == -1` 체크 로직이 필요.
- ⚠️ **PK 수정 시도**: SQL문에서 `SET STU_ID = ?` 처럼 PK까지 수정하려 하면, 참조 무결성이나 아키텍처 상 문제가 발생할 수 있음. PK는 `WHERE` 절 조건으로만 사용해야 함.
    

### 💡 Interview

> [!faq]- Q. executeQuery와 executeUpdate의 차이는?
>
> 🗣️ 핵심 답변
>
> executeQuery는 SELECT문과 같이 데이터를 조회할 때 사용하며 결과로 ResultSet 객체를 반환합니다. 반면, executeUpdate는 INSERT, UPDATE, DELETE와 같이 데이터를 변경할 때 사용하며, 결과로 **영향받은 행의 개수(int)**를 반환합니다.

## 기타 핵심 (Etc & Tips) - DB보안 2025.11.24

### 1) OracleDataSource vs DriverManager

- 기존 예제에서는 `DriverManager.getConnection()`을 썼지만, 이번 소스에서는 `OracleDataSource` 객체를 사용했습니다.
- **OracleDataSource**: 오라클에서 제공하는 JDBC 표준 구현체로, Connection Pool 설정 등을 더 세밀하게 제어할 수 있는 방식입니다. (기능적 결과는 동일)
    

### 2) 과제 가이드 (Assignment)

- **목표**: 오늘 배운 `DB_MemTable.java` 코드를 템플릿으로 사용하여, **본인만의 주제(예: 도서 관리, 제품 관리 등)**로 테이블을 설계하고 GUI 프로그램을 완성할 것.
- **필수 변경 사항**:
    
    1. 테이블 설계 (STUDENT 대신 다른 테이블)
    2. `header` 배열 (컬럼명 변경)
    3. `PreparedStatement`의 `?` 개수 및 바인딩 로직 수정
        

### Prof’s Comment

> "자바 GUI 코딩이 기억 안 날까 봐 디자인 코드는 제가 제공했습니다. 여러분은 `DBConn`, `funSelect` 같은 **DB 연동 로직(CRUD)** 부분을 직접 채워 넣으셔야 합니다. 다음 주에는 이걸 응용해서 다른 주제로 만들어오는 것이 과제입니다."

<summary>Q1. 보안 관점에서 Statement보다 PreparedStatement를 반드시 사용해야 하는 이유는 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
PreparedStatement는 쿼리를 미리 컴파일(Pre-compile)하고 입력값을 단순 데이터(Parameter)로 바인딩하기 때문에, 해커가 악의적인 SQL 구문을 삽입하는 SQL Injection 공격을 원천적으로 차단할 수 있습니다.
<br><br>
[📚 상세 설명]
<br>
- **Statement:** 쿼리와 데이터를 문자열 결합(`&quot;…&quot; + id + &quot;…&quot;`)으로 처리합니다. 이 과정에서 특수문자(`&#39; OR &#39;1&#39;=&#39;1`)가 SQL 명령어로 인식되어 보안 취약점이 발생합니다.
<br>
- **PreparedStatement:**
<br>
    1. **Pre-compilation:** 쿼리의 문법을 먼저 분석해 둡니다.
<br>
    2. **Binding:** 입력값은 단순 리터럴 값으로만 취급되며, 절대 실행 가능한 코드로 변환되지 않습니다.
<br>
    3. Performance: 반복 실행 시 캐싱 효과로 성능도 더 우수합니다.
        
</details>


<details>

<summary>Q2. JDBC 코딩 시 close()를 finally 블록에서 수행해야 하는 이유는 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
DB 연결 자원(Connection)은 한정되어 있기 때문에, 예외(Error) 발생 여부와 관계없이 반드시 자원을 해제하여 메모리 누수(Memory Leak) 및 서비스 거부(DoS) 상황을 방지하기 위함입니다.
<br><br>
[📚 상세 설명]
<br>
- **Resource Leak:** `close()`를 하지 않으면 DB 세션이 계속 열려있게 되어, 허용된 최대 접속자 수(Max Connections)를 초과하게 됩니다. 이로 인해 새로운 사용자가 접속하지 못하는 장애가 발생합니다.
<br>
- Why Finally?: try 블록 내에서 에러가 발생하면 그 아래 코드는 실행되지 않지만, finally 블록은 무조건 실행되므로 자원 해제에 가장 안전한 위치입니다.
<br>
</details>
    

<details>

<summary>Q3. executeQuery()와 executeUpdate()의 차이점은 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
수행하는 SQL의 성격과 반환(Return) 타입이 다릅니다. executeQuery()는 데이터 **조회(SELECT)**용으로 ResultSet을 반환하며, executeUpdate()는 데이터 **변경(INSERT, UPDATE, DELETE)**용으로 **변경된 행의 개수(int)**를 반환합니다.
<br><br>
[📚 상세 설명]
<br>
- **executeQuery():** `SELECT` 문 실행 시 사용. 결과 집합(`ResultSet`)을 리턴하므로 `next()` 메서드로 데이터를 탐색해야 합니다.
<br>
- executeUpdate(): DML(Data Manipulation Language) 실행 시 사용. 실행 결과 몇 개의 행이 영향을 받았는지 정수형(int)으로 알려주므로, 성공 여부(result &gt; 0)를 판단하는 데 사용됩니다.

</details>
    

<details>

<summary>Q4. ResultSet의 next() 메서드의 역할과 동작 방식은?</summary>
<br>
[🗣️ 핵심 요약]
<br>
next()는 **커서(Cursor)**를 다음 행(Row)으로 이동시키는 역할을 합니다. 데이터가 존재하면 true를 반환하여 루프를 돌게 하고, 더 이상 데이터가 없으면 false를 반환하여 조회를 종료합니다.
<br><br>
[📚 상세 설명]
<br>
- **초기 상태:** 커서는 첫 번째 데이터의 '이전(Before First)'을 가리키고 있습니다.
    <br>
- 동작: rs.next()를 호출해야 비로소 첫 번째 실제 데이터(Row 1)를 가리키게 되며, 이때 getInt()나 getString()으로 데이터를 꺼낼 수 있습니다. 이를 File Pointer와 유사한 개념으로 이해하면 쉽습니다.
