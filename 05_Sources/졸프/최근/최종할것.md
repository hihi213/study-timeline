## **0) 먼저 핵심만 요약**

- **스택 잠금**: Java 21 + Spring Boot 3.x, Postgres 16, JPA, JWT(Access 7일), SSE(폴백 폴링), Docker Compose, React+Vite+TS, Vitest/RTL/Playwright. 
- **계약 우선**: OpenAPI 스펙을 **단일 진실(SSOT)** 로 두고 백/프론트/테스트가 전부 여기에 맞춰 움직입니다. 엔드포인트·스키마는 서비스 정의와 도메인 모델의 용어를 그대로 씁니다(새 용어·새 컬럼 금지 → 문서부터 업데이트).
- **MVP 범위 고정(냉장고 중심)**: 회원가입(관리자 승인), JWT 로그인, 칸·포장·물품 CRUD, 검사 세션/조치/제출, 알림(앱 내), 벌점 제재(정책 표면화). 푸시 고도화·SSE 협업 고도화·관리자 대시보드는 시간 남으면. 
- **AI 혼선 최소화 규칙**: (1) 문서→요구 재진술→AI가 “무엇을, 왜, 어디에” 쓸지만 설명(코드 X) → (2) 파일/클래스 뼈대와 주석 생성 → (3) 당신이 구현 → (4) AI의 리뷰·테스트 보강. 매 스텝의 마지막은 **기능 테스트**로 닫습니다. 
- **배포 준비**: 로컬=Compose, 스테이징/프로덕션 분리, CI 최소 파이프라인(lint/test/docker build).

## **1) 대략적인 전체 과정(당신 상황 맞춤 리라이트)**

1. **서비스 정의·도메인 모델 동결 (Day 1~2)**
    
    - 서비스 정의서의 _Must_ 범위를 냉장고 기능으로 확정: 계정 승인, JWT, 거주자 포장/물품, 검사 세션/조치/제출, 알림(앱 내), 벌점 정책 노출. 푸시 고도화·대시보드·고급 SSE는 _Should_. 
    - 도메인 모델의 엔티티/관계(Users/FridgeBundles/FridgeItems/InspectionSessions/Actions/Notifications/Rooms/Compartments 등)와 상태코드 테이블을 확정. DB는 소프트 삭제, ID는 BIGINT/GUID, TIMESTAMPTZ. 

2. **기술 가이드 정렬 (Day 2)**
    
    - 인증: Access 토큰 7일, 헤더 Authorization: Bearer, RBAC 매핑(/api/admin/**, /api/inspector/**, /api/fridge/**) 고정. 
    - 트랜잭션 단위: 서비스 레이어, 검사 세션 잠금→UUID 반환, 제출 시 통합 롤백 보장. 
    - 실시간: 기본 SSE, 실패 시 5초 폴링 폴백. 
    - 운영: Docker Compose, CI(lint/test/docker build), 로그/백업, .env 보안. 

3. **OpenAPI 계약서 작성(SSOT)**
    
    - 엔드포인트/리퀘스트/리스폰스/에러코드/권한을 문서 기준으로 정의. (예: /auth/login, /admin/users/approvals, /fridge/bundles, /inspections/sessions, /notifications 등)
    - 계약이 곧 테스트/프론트/백엔드의 기준선.

4. **레포 분리 & 템플릿 설치**
    
    - dormmate-backend / dormmate-frontend / (선택) dormmate-infra/docs
    - 백엔드: Spring Boot 3, Gradle, Flyway(V1__init.sql부터), Testcontainers, MockMvc. 프론트: Vite+React+TS, Vitest/RTL, Playwright. 

5. **Taskmaster(MCP)로 태스크 분해**
    
    - 모든 태스크의 마지막 체크리스트에 “기능 테스트 통과”를 넣고, 태스크 정의에 **어떤 화면/엔드포인트/데이터 상태가 성공인지**를 명시. 

6. **백엔드 선개발 → 프론트 통합**
    
    - 백엔드는 도메인/계약 순서대로 얇은 수직 슬라이스로 쌓고, 각 슬라이스 끝마다 MockMvc+Testcontainers 통합 테스트. 프론트는 MSW로 OpenAPI 기반 목서버 → 실제 API 전환.

7. **컨테이너라이즈 & 스테이징 배포 → E2E → 프로덕션**
    
    - Compose로 로컬=스테이징 유사화, Playwright E2E, 마지막 주에 스테이징→프로덕션 전개.

- **설계 설명(코드 금지)**
    
    > “Spring Boot 3 기준으로 어떤 클래스/DTO/엔드포인트가 _필요한지_만 말해. 파일 경로와 역할, 트랜잭션 경계, 예외 코드를 써. 실제 코드는 쓰지 마.”
    
- **주석 스텁 생성**
    
    > “지금 설명한 파일들을 _빈 클래스/테스트 파일_로 만들고, 각 메서드에 주석으로 사양(입력/출력/예외/테스트 케이스 ID)을 적어.”
    
- **리뷰·비판 패스**
    
    > “내 구현을 _문서/계약_과 비교해 불일치, 누락, 과설계를 지적하고 테스트 케이스를 추가해.”

## **5) 백엔드 우선 수직 슬라이스(파일/테스트 “설명만”)**

1. **인증·권한**

2. **칸/라벨·포장/물품**
    
    - /fridge/compartments/:id/bundles(등록/목록), /fridge/bundles/:id/items 등
    - 규칙: 칸 잠금 중 수정 금지, 라벨 풀 업데이트, 소프트 삭제. 테스트: 용량 초과/라벨 재사용.

4. **알림**
    
    - /notifications(목록/읽음), 스케줄러(09:00 임박/만료 묶음). 테스트: dedupe/TTL/읽음 규칙.

## **7) AI 착란/오류를 줄이는 10가지 운영 규칙**

1. **문서가 먼저**: 새 요구·컬럼·상태코드는 문서부터 업데이트. 코드 생성은 그 다음.
2. **OpenAPI가 계약**: DTO/상태코드/에러는 전부 OpenAPI 기준으로만 말하기.
3. **“코드 금지” 단계 유지**: 설계·주석 스텁 단계에서 절대 코드 금지.
4. **용어 통일**: Bundle/Item/Session/Action 등 도메인 용어만 사용. 
5. **작은 슬라이스**: 엔드포인트 1~2개 단위로 PR.
6. **예외 먼저**: 권한 없음/잠금 중/라벨 고갈/용량 초과/중복 알림 등 실패 경로부터 명시. 
7. **테스트로 닫기**: 모든 태스크의 마지막은 기능 테스트 통과 캡처(또는 로그) 첨부. 
8. **버전 고정**: Spring Boot/Gradle/PG 드라이버 버전 명시, 의존성 자동 업그레이드 금지.
9. **SSE는 ‘기본+폴백’**: 실시간은 덤, 실패 시 폴링으로 전환해 업무 지속. 
10. **관찰 가능성**: 감사 로그/딜리버리 상태/락 소거 등 운영 로그 넣기.

## **8) 위험요소와 우회 전략**
