## Topic 1. C언어의 특성 (자료형과 메모리 표현)

### 1. 🏗️ 빌드업 (Why & Context)

> 시스템 레벨에서 데이터가 어떻게 저장되는지 이해해야 알고리즘의 효율성을 논할 수 있다.

- **배경:** 알고리즘은 결국 개념을 시스템(하드웨어)에 명령어로 나열하는 과정이다. 현대 언어(Java, Python)와 달리 C언어는 하드웨어 제어(Memory, Pointer)와 밀접하므로, 시스템 관점의 이해가 선행되어야 한다.
- **핵심 질문:** `float a = 3.14;`라고 썼을 때, 실제 메모리에는 3.14라는 숫자가 그대로 저장될까? 아니면 0과 1의 어떤 패턴으로 변환될까?
    
### Concept

> **"Data Type은 메모리의 0과 1을 해석하는 틀(Template)이다."**

1. **C언어 자료형의 특징 (Java와의 차이)**
    - **정수형 (`int`):** C언어 표준은 `int`의 크기를 고정하지 않음. 시스템(CPU/OS)의 **Word Size**에 따라 결정됨.
	    - 16bit 시스템 → 2byte
	    - 32bit 시스템 → 4byte
	    - 64bit 시스템 → 4byte (호환성을 위해 보통 4byte 유지, `long`은 8byte일 수 있음)
    - **Boolean 부재:** C언어는 `true/false` 타입이 없다. `0`은 거짓(False), `0이 아닌 모든 수`는 참(True)으로 간주한다.
    - **문자열(String) 부재:** C언어는 문자형(`char`)만 존재하며, 문자열은 `char` 배열이나 포인터로 처리한다. 유니코드가 아닌 ASCII 기반으로 설계되었기 때문에 `char`를 '작은 정수형'처럼 사용하여 연산이 가능하다.
    
2. **실수(Float)의 저장 방식 (IEEE 754)**
    
    - 메모리에는 정수와 실수가 전혀 다른 방식으로 저장된다.
    - `float` 타입은 **부호(Sign, 1bit) + 지수(Exponent, 8bits) + 가수(Mantissa, 23bits)** 구조로 비트가 쪼개져 저장된다.
    - 따라서 `int`로 읽을 때와 `float`로 읽을 때, 같은 메모리 주소라도 완전히 다른 값이 해석된다.
        

### Code 구현

- **메모리 해석 차이 확인 (Type Casting)**

```C
#include <stdio.h>

int main() {
    float f = 3.14f;
    // 같은 메모리 공간을 int 포인터로 접근하여 값을 읽으면?
    int *i_ptr = (int*)&f; 
    
    printf("Float value: %f\n", f);
    // 3.14가 아닌, IEEE 754 비트 패턴을 정수로 해석한 거대한 값이 출력됨
    printf("Int interpretation: %d\n", *i_ptr); 
    
    // 비트 패턴 확인 (16진수)
    printf("Hex raw data: 0x%X\n", *i_ptr);
    
    return 0;
}
```

- **⚠️ 주의사항:**
    - C언어는 배열 인덱스 초과(Out of Index) 시에도 에러를 띄우지 않고 인접 메모리 값을 읽어버리는 보안 취약점(Buffer Overflow 등)이 있다. 이는 최근 미 국방성 등에서 C언어를 기피하는 원인이 되기도 함.

## Topic 2. 프로그램 실행 과정과 메모리 구조

### 1. 🏗️ 빌드업 (Why & Context)

> "작성한 코드가 실행될 때, 변수는 어디에 존재하는가?"

- **문제 제기:** 단순히 코딩만 하는 것이 아니라, 컴파일된 목적 코드가 운영체제(OS)에 의해 메모리에 로드되는 과정을 이해해야 최적화가 가능하다.
- **핵심 아이디어:** 프로그램 내장 방식(Stored Program Concept)에 따라 코드는 메모리에 적재되어야 실행된다.
    

### Concept

> **"메모리의 4가지 영역 (Code, Data, Heap, Stack)"**

운영체제는 프로그램을 실행할 때 메모리 공간을 4가지로 구획한다.

| **영역**          | **설명**                        | **저장되는 데이터 예시**                  |
| --------------- | ----------------------------- | -------------------------------- |
| **Code (Text)** | 실행할 명령어(Machine Code)가 저장되는 곳 | 컴파일된 함수 본문, 제어문 등 (Read-Only)    |
| **Data**        | 프로그램 시작 시 할당, 종료 시 해제         | 전역 변수(Global), 정적 변수(Static)     |
| **Stack**       | 함수 호출 시 생성, 리턴 시 자동 해제        | 지역 변수(Local), 매개변수, 리턴 주소        |
| **Heap**        | 프로그래머가 필요할 때 할당/해제 (동적 메모리)   | `malloc()`, `free()`를 통한 런타임 데이터 |

### Code 구현

- **변수 종류별 메모리 위치**

```C
#include <stdio.h>
#include <stdlib.h>

int global_var = 10; // [Data 영역]

void function(int param) { // param: [Stack 영역]
    int local_var = 20;    // [Stack 영역]
}

int main() {
    int *heap_var = (int*)malloc(sizeof(int)); // heap_var 포인터 자체는 Stack, 가리키는 공간은 [Heap 영역]
    *heap_var = 30;
    
    free(heap_var);
    return 0;
}
```

## Topic 3. 선형 자료구조 Queue와 시뮬레이션

### 1. 🏗️ 빌드업 (Why & Context)

> "평균의 함정에 빠지지 말 것."

- **문제 제기:** 한강 공원 화장실에 줄을 서는 시뮬레이션을 만든다고 가정하자.
- **가정:**
    - 화장실 이용 시간: 평균 1분.
    - 사람 도착 간격: 평균 2분.
- **직관적 오해:** "들어오는 속도(2분/명)보다 처리 속도(1분/명)가 빠르니까, 대기열(Queue)은 생기지 않거나 의자가 필요 없을 것이다."
    

### Concept

> **"평균(Average) vs 분포(Distribution)"**

1. **Queue (큐):** FIFO(First-In First-Out) 구조의 선형 자료구조. 입구(Rear)와 출구(Front)가 다르다.
2. **시뮬레이션의 역설 (M/M/1 Queue 이론):**
    
    - 평균값은 전체 데이터를 뭉뚱그린 것이다.
    - 실제 상황에서는 어떤 사람은 1초 만에 나오고, 어떤 사람은 60분을 쓸 수 있다 (불규칙성).
    - 특정 시점에 도착이 몰리고 처리가 지연되면 대기열은 순식간에 폭발할 수 있다.
    - **결론:** 평균 처리 속도가 도착 속도보다 빨라도, **분산(Variance)** 때문에 이론상 **무한대의 버퍼(의자)**가 필요할 수 있다.
    - 이는 로또 번호 예측(이전 사건이 독립 사건에 영향을 주지 않음, Memoryless Property)과 유사한 확률적 개념이다.
        

### Code 구현

- **Circular Queue 기본 구조 (C언어)**

```C
#define MAX_QUEUE_SIZE 5

typedef struct {
    int data[MAX_QUEUE_SIZE];
    int front, rear;
} Queue;

void init_queue(Queue *q) {
    q->front = 0;
    q->rear = 0;
}

// 포화 상태: (rear + 1) % MAX == front
// 공백 상태: rear == front
void enqueue(Queue *q, int item) {
    if ((q->rear + 1) % MAX_QUEUE_SIZE == q->front) {
        // Queue Full Error
        return;
    }
    q->rear = (q->rear + 1) % MAX_QUEUE_SIZE;
    q->data[q->rear] = item;
}
```

### 💡 Interview

> [!faq]- Q. C언어에서 int형의 크기는 4바이트로 고정인가?
>
> 🗣️ 핵심 답변
>
> 아닙니다. C언어 표준에서 int의 크기는 **시스템 의존적(System Dependent)**입니다.
>
> 16비트 시스템에서는 2바이트, 32비트 이상 시스템에서는 통상 4바이트를 사용하지만, 이는 절대적인 규칙이 아니므로 이식성(Portability)을 고려할 때 주의해야 합니다.
>
> **📚 꼬리질문 대비**
>
> - **Q: 그렇다면 크기가 보장되는 정수형을 쓰려면?**
>     
> - A: `<stdint.h>`에 정의된 `int32_t`, `int64_t` 등 고정 너비 정수형(Fixed-width integer types)을 사용해야 합니다.
>     

> [!faq]- Q. 평균 서비스 시간이 평균 도착 시간보다 짧다면, 대기열(Queue)은 무한히 늘어나지 않는가?
>
> 🗣️ 핵심 답변
>
> 반드시 그렇지는 않지만, **분산(Variance)**에 의해 일시적으로 대기열이 폭증할 수 있습니다.
>
> 큐이론(Queueing Theory)에 따르면 도착과 서비스가 불규칙한 분포(예: 푸아송 분포)를 따를 경우, 여유 용량이 있어도 대기 행렬이 형성될 수 있으며, 최악의 경우 버퍼 오버플로우가 발생할 수 있습니다. 이를 해결하기 위해 단순 평균이 아닌 **최악의 경우(Worst Case)**를 고려한 버퍼 설계가 필요합니다.

> 
> 

> [!faq]- Q. 컴퓨터 구조 관점에서 '프로그램 내장 방식'이란 무엇이며, 보안상 어떤 의미가 있는가?

## Topic 1. Array vs Linked List (System Level Analysis)

### 1. 🏗️ 빌드업 (Why & Context)

> 단순한 정의 암기가 아닌, 하드웨어(레지스터) 관점에서의 동작 원리 이해가 필요하다.

- **문제 제기:** 배열은 왜 선언과 동시에 크기가 고정되며, 링크드 리스트는 왜 유연한가?
- **핵심 아이디어:**
    - **배열(Array):** 연속된 메모리 공간 + 인덱스 기반 접근.
    - **링크드 리스트(Linked List):** 불연속 메모리 공간 + 포인터 기반 접근.
- **교수님의 강조(Rant):** 4학년이 되어도 배열이 하드웨어 레벨에서 어떻게 주소를 찾아가는지(Base Register + Index Register) 모르면 안 된다.
    

### Concept

> **"Memory Access Mechanism"**

**1) 배열 (Array)**

- **구조:** 메모리 상에 **연속적**으로 할당됨.
- **접근:** 인덱스(Index)를 통해 $O(1)$의 시간 복잡도로 임의 접근(Random Access) 가능.
    - 원리: `Base Address + (Index * DataSize)` 로 물리 주소 즉시 계산.
- **단점:**
    - 선언 시 크기 고정 (Static Allocation).
    - 사용하지 않는 공간은 낭비됨 (Memory Leak과 유사한 비효율).
    - 중간 삽입/삭제 시 데이터 이동(Shift) 필요 → $O(N)$.
        

**2) 연결 리스트 (Linked List)**

- **구조:** 데이터와 **포인터(Link)**로 구성된 노드(Node)들의 집합. 메모리에 불연속적으로 산재함.
- **접근:** 시작 노드(Head)부터 순차적으로 탐색해야 함 → 탐색 시간 $O(N)$.
- **장점:**
    - 필요할 때마다 `malloc`으로 동적 할당하므로 메모리 효율적.
    - 중간 삽입/삭제 시 포인터만 변경하면 됨 → $O(1)$ (단, 위치를 찾은 후).
- **변형:**
    - **Doubly Linked List:** 양방향 탐색 가능 (앞 노드 주소도 저장).
    - **Circular Linked List:** 마지막 노드가 처음을 가리킴.

### Code 구현

- **Linked List Node & Dynamic Allocation (C언어)**

```C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node* next; // 다음 노드를 가리키는 포인터
} Node;

int main() {
    // 런타임에 필요한 만큼만 메모리 할당 (Heap 영역)
    Node* head = (Node*)malloc(sizeof(Node)); 
    head->data = 10;
    head->next = NULL;

    // 필요 없으면 해제 (메모리 누수 방지)
    free(head);
    return 0;
}
```

## Topic 2. Stack & Queue (OS & Network Context)

### 1. 🏗️ 빌드업 (Why & Context)

> "자료구조는 현실 세계의 모델링이자, 시스템 성능 차이를 극복하는 완충 장치다."

- **Stack의 본질:** 되돌아갈 곳을 기억해야 할 때 (함수 호출, 인터럽트).
- **Queue의 본질:** 처리 속도가 다른 두 시스템 사이의 버퍼 (Buffering).
    

### Concept

> **"Interrupt Handling & Buffering"**

1. **Stack (LIFO - Last In First Out)**
    
    - **활용 예시 (OS):**
        - **인터럽트(Interrupt) 처리:** 카톡 알림 등 인터럽트 발생 시, 현재 CPU가 실행 중인 명령어 주소(**Program Counter**, PC)를 스택에 저장(Push). 인터럽트 처리 후 스택에서 꺼내(Pop) 복귀.
        - **함수 호출:** 지역 변수와 리턴 주소를 저장.
    - **구조:** 입출구가 하나인 통, `Top` 포인터를 이용하여 Push/Pop 수행.
        
2. **Queue (FIFO - First In First Out)**
    
    - **활용 예시 (Network/HW):**
        - **속도 차이 극복:** CPU(고속)와 프린터(저속) 사이의 **Spooling**.
        - **네트워크:** 라우터의 패킷 버퍼링, TCP 세그먼트 처리.
        - **인간의 뇌:** 이해 속도보다 강의 속도가 빠르면 "대기열(Queue)"에 넣고 나중에 처리
    - **구조:** 입구와 출구가 분리, `Rear`(삽입 위치)/ `Front`(삭제 위치) 포인터 사용.
### Implementation Issue (Circular Queue)

> **"왜 배열로 만든 큐는 원형(Circular)이어야 하는가?"**

- **선형 큐(Linear Queue)의 문제:**
    - `dequeue`로 데이터가 빠져나가면 앞쪽 공간이 비지만, 인덱스(`rear`)는 계속 뒤로 이동.
    - 앞쪽 빈 공간을 재사용하려면 남은 데이터를 모두 앞으로 당겨야 함(Shift 연산, 비효율적).
- 해결책: **원형 큐 (Circular Queue)**
    - **Modulo 연산 (%)**을 사용하여 인덱스를 회전시킴.
    - `Next_Rear = (Rear + 1) % MAX_SIZE`

### Code 구현

```C
// 원형 큐(Circular Queue)의 인덱스 계산 로직
#define MAX_SIZE 10

int queue[MAX_SIZE];
int front = 0, rear = 0;

void enqueue(int data) {
    // 꽉 찼는지 확인 (여유 공간 1개를 두는 방식)
    if ((rear + 1) % MAX_SIZE == front) {//full로 간주
        printf("Queue Overflow\n");
        return;
    }
    rear = (rear + 1) % MAX_SIZE; // 순환 구조 핵심
    queue[rear] = data;
}

int dequeue() {
    if (front == rear) {
        printf("Queue Underflow\n");
        return -1;
    }
    front = (front + 1) % MAX_SIZE; // 순환 구조 핵심
    return queue[front];
}
```

## Topic 3. 비선형 자료구조와 Heap

### 1. 🏗️ 빌드업 (Why & Context)

> "우선순위가 필요한 세상."

- **트리/그래프:** 계층 구조나 연결 관계(회로, 지도)를 표현.
- **힙(Heap):** 큐는 공평하지만(FIFO), 응급 상황(앰뷸런스)에서는 **새치기(Priority)**가 필요하다.
    

### Concept

> **"Modeling Reality"**

1. **Tree & Binary Tree**
    
    - 구현: 포인터로 연결할 수도 있지만, **완전 이진 트리**는 **배열**로 구현하는 것이 효율적이다.
        - 부모 인덱스: $i$
        - 왼쪽 자식: $2 \times i$
        - 오른쪽 자식: $2 \times i + 1$
            
2. **Graph (Directed vs Undirected)**
    
    - **무방향(Undirected):** 집 $\leftrightarrow$ 학교 (왕복 가능).
    - **방향(Directed):** 선수과목 이수 체계 (1학년 과목 $\rightarrow$ 4학년 과목, 역주행 불가).
        
3. **Heap (Priority Queue)**
    
    - **목적:** 일반적인 큐(FIFO)와 달리, 들어온 순서가 아니라 **중요도(Key 값)**가 높은 데이터가 먼저 나감.
    - **응용:** OS 스케줄링(중요 프로세스 먼저 처리), 네트워크 패킷 우선순위 처리.
        
### Code 구현 (개념적 구조)

```C
// 힙은 보통 '배열'을 사용하여 구현함 (인덱스 계산의 용이성)
// 부모 인덱스: i/2, 왼쪽 자식: 2*i, 오른쪽 자식: 2*i + 1

#define MAX_ELEMENT 200
typedef struct {
    int heap[MAX_ELEMENT];
    int heap_size;
} HeapType;

// 삽입 연산 (Up-Heap Bubble): 맨 끝에 넣고 부모와 비교하며 올라감
void insert_max_heap(HeapType *h, int item) {
    int i = ++(h->heap_size);
    
    // 부모보다 내가 더 크면 부모를 끌어내림 (트리 타고 올라가기)
    while ((i != 1) && (item > h->heap[i/2])) {
        h->heap[i] = h->heap[i/2];
        i /= 2;
    }
    h->heap[i] = item; // 최종 위치에 저장
}
```

### 💡 Interview

> [!faq]- Q. 배열(Array)과 링크드 리스트(Linked List)를 하드웨어(CPU/Memory) 관점에서 비교하시오.
>
> 🗣️ 핵심 답변

>
> 반면, 링크드 리스트는 힙(Heap) 영역에 불연속적으로 할당되며, 다음 노드의 주소를 포인터를 통해 참조(Dereference)해야 하므로 접근 시 CPU 캐시 히트율(Cache Hit Rate)이 낮고 탐색에 $O(N)$이 소요됩니다.

> [!faq]- Q. 배열로 큐(Queue)를 구현할 때 발생하는 문제점과 해결 방안은?
>
> 🗣️ 핵심 답변
>
> 선형 배열로 큐를 구현하면, 데이터 삭제(Dequeue) 후 앞쪽 공간이 비더라도 rear 포인터가 계속 증가하여 False Overflow(공간이 있는데 꽉 찼다고 인식)가 발생합니다.
>
> 이를 해결하기 위해 데이터를 앞으로 당기는(Shift) 연산을 하면 비효율적이므로, 인덱스를 순환시키는 **원형 큐(Circular Queue)**를 사용하여 나머지 연산(Modulo)으로 앞쪽 빈 공간을 재사용합니다.

> [!faq]- Q. 일반 큐(Queue)와 힙(Heap)의 결정적 차이와 힙의 실제 사용 사례는?
>
> 🗣️ 핵심 답변
>
> 일반 큐는 FIFO(선입선출) 구조로 들어온 순서대로 처리되지만, 힙은 **우선순위 큐(Priority Queue)**를 구현하기 위한 자료구조로, 입력 순서와 무관하게 키 값이 가장 크거나 작은 데이터가 먼저 나옵니다.
>
> 운영체제의 프로세스 스케줄링이나 네트워크 라우터의 긴급 패킷(QoS) 처리에 주로 사용됩니다.

## Topic 1. 포인터의 본질 (Pointer Essence)

### 1. 🏗️ 빌드업 (Why & Context)

> "포인터는 어렵지 않다. 주소값을 담는 변수일 뿐이다."

- **문제 제기:** 많은 학생들이 `int`, `struct`는 이해하면서 포인터만 나오면 어려워한다. `int *p`, `struct Node *p`가 전혀 다른 것처럼 보이기 때문이다.
- **핵심 아이디어:** 변수의 타입(Type)과 상관없이, 모든 포인터 변수는 **메모리 주소**를 저장하며, 32비트 시스템 기준 그 크기는 **무조건 4바이트**로 동일하다.
    

### Concept

> **"Pointer Size is Fixed, Interpretation Varries."**

1. **포인터의 크기 ($4$ Bytes):**
    
    - `char *c_ptr`, `int *i_ptr`, `double *d_ptr`, `struct BigStruct *s_ptr` 모두 크기는 **4바이트**다. (32bit 시스템 기준).
    - **이유:** 32비트 CPU가 관리할 수 있는 주소 공간이 $2^{32}$ ($4GB$)이므로, 주소값 자체를 표현하는 데 32비트(4바이트)가 필요하기 때문이다.
    - _참고:_ 64비트 시스템에서는 8바이트지만, 학습 및 레거시 호환 설명에서는 4바이트를 기준으로 설명함.
        
2. **타입(Type)의 존재 이유:**
    
    - 주소값 크기가 같다면 왜 `int*`, `float*`로 구분하는가?
    - **해석(Interpretation) 때문:** 주소에 찾아갔을 때, 그 비트 패턴을 정수로 읽을지, IEEE 754 실수로 읽을지, 몇 바이트(1 vs 4 vs 8)를 읽을지 결정하기 위함이다.
        

### Code 구현

- **포인터 크기 확인**
    

```C
#include <stdio.h>

struct Huge {
    int data[1000]; // 4000 bytes struct
};

int main() {
    int *i_ptr;
    char *c_ptr;
    struct Huge *s_ptr;

    // 모두 4 (32bit) 또는 8 (64bit) 출력. 타입에 따라 변하지 않음.
    printf("Size of int*: %d\n", sizeof(i_ptr)); 
    printf("Size of char*: %d\n", sizeof(c_ptr));
    printf("Size of struct*: %d\n", sizeof(s_ptr));
    
    return 0;
}
```

## Topic 2. 포인터 연산과 배열 (Pointer Arithmetic)

### 1. 🏗️ 빌드업 (Why & Context)

> "배열의 이름은 상수 포인터(Constant Pointer)다."

- **배경:** `ptr++`는 되는데 `arr++`는 왜 에러가 나는가?
- **핵심 구분:** 변수(Variable)와 상수(Constant)의 차이.
    

### Concept

> **"L-value vs R-value / Scale Factor"**

1. **배열 이름 vs 포인터 변수:**
    
    - `int *ptr`: 주소값을 바꿀 수 있는 **변수**. (`ptr++` 가능)
    - `int arr[10]`: 메모리에 고정된 위치를 가리키는 **상수 포인터**. (`arr = &b` 불가, `arr++` 불가). 컴파일 시점에 주소가 고정됨.
        
2. **포인터 연산의 스케일링 (Scaling):**
    
    - `ptr + 1`은 물리적으로 $1$바이트 증가가 아니라, `sizeof(type)`만큼 증가한다.
    - `char *`에서 `+1` $\rightarrow$ 주소 $+1$ 증가.
    - `int *`에서 `+1` $\rightarrow$ 주소 $+4$ 증가.
        
3. **연산자 우선순위 (Operator Precedence):**
    
    - `*ptr++`의 해석:
        
        1. 후위 증감 연산자(`++`)가 간접 참조(`*`)보다 우선순위가 높음.
        2. `ptr`이 가리키는 주소값이 증가함 (포인터 이동).
        3. 하지만 후위 연산이므로, 수식의 결과값은 **이동 전의 주소를 참조(`*`)한 값**.
        4. _결과:_ 값 리턴 후 포인터 이동.
            

### Code 구현

- **배열 이름 증감 불가 증명**
    

```C
int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    int *ptr = arr;

    ptr++;    // OK: ptr은 변수이므로 값 변경 가능. (이제 arr[1] 가리킴)
    // arr++; // Compile Error: 'lvalue required'. arr은 상수이므로 대입 불가.
    
    return 0;
}
```

## Topic 3. 구조체 (Structure)와 자기 참조

### 1. 🏗️ 빌드업 (Why & Context)

> "자료구조의 핵심, 노드(Node)를 만들기 위한 준비."

- **문제:** 링크드 리스트를 만들려면 내 다음 데이터가 어디 있는지 가리켜야 한다.
- **해결:** 구조체 안에 **자신과 똑같은 타입의 포인터**를 멤버로 포함시킨다.
    

### Concept

> **"Self-Referential Structure"**

1. **자기 참조 구조체:**
    
    - `struct Node` 안에 `struct Node *next;`가 존재.
    - 무한 루프 정의가 아니다. `struct Node` 전체를 포함하는 게 아니라, **주소(4바이트)**만 포함하기 때문에 크기가 확정 가능하다.
        
2. **익명 구조체의 함정 (Anonymous Struct):**
    
    - 태그(이름)가 없는 구조체 `struct { int x; } a, b;` 선언 시, 컴파일러는 `a`와 `b`를 **서로 다른 타입**으로 인식한다. 반드시 태그(`struct Point`)를 명시해야 재사용 및 타입 호환이 가능하다.
        
3. **멤버 접근 연산자:**
    
    - `variable.member` (점 연산자): 일반 변수일 때.
    - `pointer->member` (화살표 연산자): 포인터 변수일 때.
        

### Code 구현

- **Linked List Node 정의**
    

```C
struct Node {
    int data;
    struct Node *next; // 자기 참조: 다음 노드의 주소 저장
}; // 태그(Node)가 있어야 재사용 가능
```

## Topic 4. `void*`와 형 변환 (Generic Pointer)

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 주소를 담을 수 있는 만능 주머니."

- **문제:** `malloc` 함수는 사용자가 `int`를 원할지 `struct`를 원할지 모른다. 어떤 타입의 주소를 리턴해야 하는가?
- **해결:** 타입이 정해지지 않은 `void*`를 리턴하고, 사용자가 알아서 변환(Casting)해 쓰도록 한다.
    

### Concept

> **"Type Safety & Casting"**

1. **포인터 간 형 변환:**
    
    - `int` $\leftrightarrow$ `char` 값 간에는 자동 형 변환이 일어난다.
    - 그러나 `int*` $\leftrightarrow$ `char*` 포인터 간에는 **자동 형 변환이 금지**된다. (참조 크기가 달라 위험함).
        
2. **`void*` (Generic Pointer):**
    
    - 유일하게 모든 포인터 타입과 호환되는 포인터.
    - 역참조(`*ptr`)나 연산(`ptr++`)은 불가능하다. (크기를 모르기 때문).
    - `malloc`의 리턴 타입이 `void*`인 이유다.
        

### Code 구현

- **malloc과 Casting**
    

```C
#include <stdlib.h>

int main() {
    // malloc은 void* 반환 -> (int*)로 명시적 형 변환 권장 (C++ 호환 및 가독성)
    int *ptr = (int*)malloc(sizeof(int) * 10);
    
    // void* 상태에서는 연산 불가
    void *v_ptr = ptr;
    // v_ptr++; // Error: void 포인터의 크기는 알 수 없음 (컴파일러에 따라 1로 처리하기도 함)
    
    free(ptr);
    return 0;
}
```

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.09.04

- **포인터 퀴즈:** `struct A { int a; char *b; struct A *c; }`의 크기는?
    - `int`(4) + `pointer`(4) + `pointer`(4) = 12 bytes. (Padding 제외 시). 구조체가 아무리 복잡해도 내부 포인터 멤버는 무조건 4바이트다.
- **메모리 제한:** 32비트 OS 시절 4GB 램 제한이 있었던 이유는 포인터가 표현할 수 있는 주소의 한계($2^{32}$) 때문이었다.
    

### 💡 Interview

> [!faq]- Q. \*ptr++와 (\*ptr)++의 차이점을 설명하시오.
>
> 🗣️ 핵심 답변
>
> 연산자 우선순위의 차이입니다.
>
> _ptr++는 후위 증감 연산자(++)가 간접 참조(_)보다 우선순위가 높으므로, 포인터 변수 ptr의 주소값이 증가하고, 식의 결과는 증가 전 위치의 값을 반환합니다.
>
> 반면 (*ptr)++는 괄호로 인해 간접 참조가 먼저 수행되므로, ptr이 가리키는 메모리의 실제 값(Value)이 1 증가하며 포인터의 주소는 변하지 않습니다.

> [!faq]- Q. 배열의 이름 arr과 포인터 ptr의 결정적 차이는 무엇인가? (arr++가 안 되는 이유)
>
> 🗣️ 핵심 답변
>
> 배열의 이름 arr은 메모리 할당 시 시작 주소가 고정된 **상수 포인터(Constant Pointer)**이기 때문에 R-value로만 사용 가능하며 값을 변경할 수 없습니다.
>
> 반면 ptr은 주소값을 저장하는 **변수(Variable)**이므로 다른 주소를 대입하거나 증감 연산(++)을 통해 가리키는 위치를 변경할 수 있습니다.

> [!faq]- Q. void* 포인터란 무엇이며 왜 사용하는가?
>
> 🗣️ 핵심 답변
>
> void\*는 구체적인 자료형이 결정되지 않은 범용 포인터입니다.
>
> 주로 malloc과 같이 메모리 할당 시 사용자가 어떤 데이터 타입을 사용할지 미리 알 수 없는 경우, 주소값만 전달하기 위해 사용합니다. 사용 시에는 반드시 목적에 맞는 구체적인 포인터 타입(int*, struct* 등)으로 **형 변환(Casting)**해야 역참조 및 포인터 연산이 가능합니다.
