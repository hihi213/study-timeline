## **2025-09-05, 1교시 — 개선본**

오늘 다룰 내용은 시스템에 Linux를 포팅하고 올리는 과정입니다. 아마 예상보다 빨리 끝날 수도 있습니다. 해당 작업을 진행하고, Linux가 어떤 것인지 기본적인 개념을 알아보는 시간을 갖겠습니다.

Linux는 새로운 운영 체제(OS)입니다. 지금까지 여러분은 Windows 환경에서 프로그래밍하고 여러 도구를 사용해왔지만, Linux는 그와는 다른 새로운 운영 체제에 관한 이야기입니다. 처음 사용해보는 사람들은 매우 불편하다고 느낄 수도 있습니다. macOS나 Windows처럼 다양한 응용 프로그램이 풍부한 환경이 아니기 때문입니다. 오히려 개발자 환경에 더 가깝다고 생각하는 것이 이해하기 편할 것입니다.

실습 중에는 `vi` 편집기를 사용하게 될 텐데, 이때 많은 분이 불편함을 느낄 수 있습니다. Visual Studio, VS Code, Eclipse 등 대부분의 최신 개발 환경에서는 마우스로 커서를 이동하는 방식에 익숙해져 있기 때문입니다. `vi` 편집기를 처음 접하면 '왜 이렇게 번거로운 것을 사용해야 하나'라는 생각이 들 수 있습니다. 하지만 `vi` 편집기가 손에 익숙해지면 마우스 없이 키보드만으로 모든 작업을 처리할 수 있어 매우 편리합니다.

Linux 환경 자체도 지금까지 사용해 온 환경과는 많이 다르고, 심지어 게임도 거의 없어 흥미를 붙이기 어려울 수 있습니다. 또한, 대부분이 Windows 환경에 너무 익숙해져 있어 굳이 Linux까지 배워야 할 필요성을 느끼지 못할 수도 있습니다. 하지만 Linux는 단순한 응용 프로그램을 실행하는 개념이 아니라, 대형 서버를 다루기 위한 운영 체제라는 관점에서 접근해야 합니다.

Linux는 오픈 소스(Open Source) 운영 체제입니다. 소스 코드가 공개되어 있어 누구나 내용을 확인하고 수정할 수 있습니다. 배포판을 공개하며 "사용자들이 원하는 대로 자유롭게 고쳐서 사용하라"는 정책을 유지했고, 저작권 문제에서 자유로웠기 때문에 지금까지 발전해올 수 있었습니다.

운영 체제(OS)란 무엇일까요? OS는 하드웨어를 완벽히 알지 못하는 사용자가 프로그램을 설치하거나 실행하고, 파일을 저장하는 등의 작업을 할 수 있도록 돕는 소프트웨어입니다. 즉, OS는 하드웨어와 응용 프로그램 사이의 **인터페이스(Interface)** 역할을 합니다. 인터페이스란 서로 다른 두 시스템을 연결하는 '접점'을 의미합니다. 예를 들어, 스마트폰의 충전 포트는 스마트폰과 전원 사이의 인터페이스입니다.

이처럼 OS는 응용 프로그램 개발자가 하드웨어의 복잡한 메커니즘을 몰라도 프로그램을 개발하고 실행할 수 있게 해줍니다. 사용자가 프로그램을 실행하면 OS가 하드디스크에 저장된 프로그램을 메모리(RAM)로 올리는 등의 자원 할당 및 관리 작업을 모두 처리합니다. 이 과정은 Windows와 Linux 환경이 메커니즘의 차이는 있지만 본질적으로 동일합니다.

운영 체제의 주요 역할 중 하나는 CPU, 메모리와 같은 시스템 자원을 효율적으로 관리하는 것입니다. 예를 들어 CPU에 병목(bottleneck)이 발생했을 때 이를 어떻게 해결할지, 또는 메모리 사용 시 발생하는 블로킹(blocking) 문제를 어떻게 처리할지 등을 결정합니다. 또한 NTFS, FAT와 같은 파일 시스템 포맷 방식을 관리합니다. 여러분의 PC는 여러분이 직접 관리할 수 있어야 합니다. 하드웨어를 직접 파손하지 않는 이상, 소프트웨어적인 문제는 대부분 해결할 수 있습니다. 다양한 프로그램을 설치해보고, 블루 스크린을 직접 띄워보기도 하면서 스스로 해결하는 경험을 쌓아야 합니다.

컴퓨터에 대해 잘 모르면 수리 업체에 맡겼을 때 불필요한 비용이 발생할 수 있습니다. CPU나 RAM 같은 부품이 교체되어도 모를 수 있으니, 수리를 맡기기 전에는 주요 부품의 사진이나 시리얼 번호를 기록해두는 것이 좋습니다.

Windows 운영 체제는 부팅 시 많은 자원을 차지합니다. OS의 핵심인 커널(kernel)이 메모리에 상주하며, 그 위에서 사용자의 프로세스들이 동작합니다. 작업 관리자를 열어보면 수많은 프로세스가 실행 중인 것을 볼 수 있는데, 이 프로세스들은 모두 시스템 자원을 소모합니다. (실습) 예를 들어 4GB RAM을 장착한 PC에서 Windows는 부팅만으로도 상당량의 메모리를 사용하며, 여기에 응용 프로그램을 실행하면 시스템이 느려질 수밖에 없습니다.

컴퓨터 네트워크에서는 세 가지 종류의 주소 체계를 사용합니다. 첫째는 인터넷 통신에 필수적인 **IP 주소**입니다. 데이터를 주고받기 위해서는 발신지와 목적지의 IP 주소가 필요합니다. 로컬 테스트에 사용되는 `127.0.0.1`과 같은 루프백(loopback) 주소도 여기에 포함됩니다.

둘째는 **MAC 주소(물리적 주소)**입니다. 이는 네트워크 카드(LAN card)에 고정된 48비트의 고유 주소로, 제조사에서 칩에 직접 설정하여 출시합니다. 명령 프롬프트(CMD)를 실행해 보세요. (실습) 그 창에 `ipconfig /all`을 입력하면 자신의 PC에 설정된 IP 정보와 함께 물리적 주소를 확인할 수 있습니다. (실습) 앞의 3바이트는 제조사 번호, 뒤의 3바이트는 제품의 일련번호입니다.

셋째는 **포트 번호(Port Number)**입니다. IP 주소가 컴퓨터를 식별한다면, 포트 번호는 그 컴퓨터 내에서 실행 중인 특정 프로세스(프로그램)를 식별하는 접근점 역할을 합니다. 예를 들어, 웹 서비스를 제공하는 HTTP 데몬(daemon)은 보통 80번 포트를 사용합니다. 1024번까지의 포트는 잘 알려진 서비스들(Well-known ports)을 위해 예약되어 있어 일반 사용자는 쓸 수 없습니다. 서버가 외부의 공격을 받을 때, 방화벽에서 대부분의 포트를 차단하지만 웹 페이지 접속을 위해 80번 포트는 열어두어야 하는 것처럼, 포트 관리는 매우 중요합니다.

## **2025-09-05, 1교시 — 개념**

1.  **한 줄 요약**
    운영 체제(OS)는 하드웨어와 사용자 사이의 핵심 인터페이스이며, Linux는 자원 관리와 개방성이 특징인 서버 중심의 강력한 오픈 소스 OS입니다.

2.  **핵심 TL;DR**
    * **운영 체제(OS)**는 복잡한 하드웨어 제어를 추상화하여 사용자와 응용 프로그램이 컴퓨터를 쉽게 사용하도록 돕는 **인터페이스**입니다.
    * **Linux**는 Windows와 달리 응용 프로그램보다 개발 및 서버 환경에 특화된 오픈 소스 운영 체제입니다.
    * `vi` **편집기**는 마우스 없이 키보드만으로 모든 작업을 수행하는 텍스트 편집기로, 숙달 시 매우 효율적입니다.
    * **오픈 소스**는 소스 코드가 공개되어 누구나 수정하고 재배포할 수 있는 모델로, Linux 발전의 핵심 동력입니다.
    * **커널(Kernel)**은 OS의 핵심으로, 시스템 부팅 시 메모리에 상주하며 모든 하드웨어와 프로세스를 직접 제어합니다.
    * **시스템 자원 관리**는 OS의 주요 역할로, CPU, 메모리, 저장 공간 등을 여러 프로세스가 효율적으로 사용하도록 조율합니다.
    * 네트워크 통신에는 **IP 주소**(네트워크 식별), **MAC 주소**(장치 고유 식별), **포트 번호**(프로세스 식별)라는 3가지 주소 체계가 사용됩니다.
    * OS 철학의 차이로, **iOS**는 폐쇄적이고 단일 하드웨어에 최적화된 반면, **Android(Linux 기반)**는 개방적이며 다양한 하드웨어에 맞춰 제조사가 최적화합니다.

3.  **표현 = 표준 용어**
    * **운영 체제 (Operating System, OS)**: 컴퓨터 하드웨어와 소프트웨어 자원을 관리하는 시스템 소프트웨어.
    * **인터페이스 (Interface)**: 서로 다른 두 시스템이나 객체 사이의 상호작용을 위한 접점 또는 규약.
    * **커널 (Kernel)**: 운영 체제의 가장 핵심적인 부분으로, 시스템의 모든 것을 완전히 통제함.
    * **프로세스 (Process)**: 실행 중인 프로그램을 나타내는 인스턴스. OS로부터 자원을 할당받음.
    * **IP 주소 (IP Address)**: 네트워크상의 장치를 식별하기 위한 논리적 주소.
    * **MAC 주소 (MAC Address)**: 네트워크 인터페이스 카드(NIC)에 할당된 고유한 물리적 주소.
    * **포트 번호 (Port Number)**: 하나의 IP 주소 내에서 특정 프로세스를 식별하기 위한 숫자.
    * **오픈 소스 (Open Source)**: 소스 코드를 공개해 누구나 자유롭게 사용, 수정, 배포할 수 있는 소프트웨어 또는 개발 모델.

4.  **정석 보강 (canon-std)**
    운영 체제(OS)는 컴퓨터 하드웨어 자원을 독점적으로 관리하고, 응용 프로그램에 일관된 실행 환경을 제공하는 필수 시스템 소프트웨어입니다. 핵심 구성요소인 **커널(Kernel)**은 메모리에 상주하며 CPU 스케줄링, 메모리 할당, 파일 시스템 접근, 장치 드라이버 제어 등 모든 저수준(low-level) 작업을 담당합니다. OS는 이처럼 복잡한 하드웨어를 추상화하여, 응용 프로그램이 시스템 호출(System Call)이라는 표준화된 인터페이스를 통해 자원을 요청하고 사용할 수 있도록 합니다.

5.  **실수·함정**
    * `C:` 드라이브, `D:` 드라이브가 반드시 별개의 물리적 하드디스크를 의미하는 것은 아닙니다. (하나의 디스크를 나눈 **파티션**일 수 있음)
    * IP 주소만으로 통신이 완료된다고 생각하기 쉽지만, 실제 데이터 전달에는 MAC 주소와 포트 번호가 필수적입니다.
    * `vi` 편집기는 단순히 오래되고 불편한 도구가 아니라, 숙련된 사용자에게는 매우 빠르고 강력한 도구입니다.
    * Linux는 해커나 전문가만 쓰는 어려운 OS가 아니라, 서버, 임베디드 시스템, 클라우드 환경의 표준입니다.
    * 컴퓨터가 느릴 때 무조건 RAM 용량만 문제 삼는 것은 잘못된 접근일 수 있습니다. (OS의 프로세스 및 자원 관리 효율이 더 중요할 수 있음)

**[Q1] 운영 체제(OS)의 근본적인 역할은 무엇이며, 왜 '인터페이스'라고 불리는가? | #부팅/systemd**
* **모범답(강의 기준):** OS는 사용자가 컴퓨터의 복잡한 하드웨어 구조를 몰라도 응용 프로그램을 쉽게 실행하고 파일을 관리할 수 있도록 중간에서 모든 것을 처리해주며, 하드웨어와 사용자 사이의 '접점' 역할을 하므로 인터페이스라고 부릅니다.
* **정석체크(면접 30초):** 운영 체제는 하드웨어 자원을 독점적으로 관리하고 추상화하여 응용 프로그램에 일관된 실행 환경을 제공하는 시스템 소프트웨어입니다. 커널을 통해 프로세스, 메모리, I/O를 제어하며, 사용자는 셸(Shell)이나 GUI를 통해 시스템과 상호작용하므로 양측을 잇는 인터페이스로 기능합니다.

**[Q2] 네트워크 통신에서 IP 주소, MAC 주소, 포트 번호가 각각 필요한 이유는 무엇인가? | #네트워킹/SSH**
* **모범답(강의 기준):** IP 주소는 인터넷상에서 컴퓨터를 찾기 위해, MAC 주소는 로컬 네트워크 내에서 실제 기기를 특정하기 위해, 포트 번호는 해당 기기 내에서 실행 중인 특정 프로그램(프로세스)을 찾아 통신하기 위해 필요합니다.
* **정석체크(면접 30초):** 세 주소는 통신 계층(OSI 7 Layer)이 다르기 때문에 모두 필요합니다. **MAC 주소**는 2계층(Data Link)에서 물리적 장비를, **IP 주소**는 3계층(Network)에서 네트워크상의 호스트를, **포트 번호**는 4계층(Transport)에서 해당 호스트의 특정 프로세스를 식별하여 최종 통신 경로를 완성합니다.

## **2025-09-05, 2교시 — 개선본**

오늘의 주된 목표는 여러분의 PC에 Ubuntu를 설치하는 것입니다. 하지만 40여 명이 동시에 서버에 접속하여 다운로드해야 하므로 서버가 느려질 것이 우려됩니다.

운영 체제는 크게 6가지 정도의 기능을 수행합니다. 첫 번째는 **프로세스(Process) 관리**입니다. 프로세스가 생성될 때마다 ID를 부여하고, CPU 스케줄링을 통해 자원을 할당합니다. CPU는 여러 프로세스를 매우 짧은 시간 단위(Quantum Time)로 나누어 번갈아 실행시키는데, 이를 **라운드 로빈(Round-Robin)** 방식이라고 합니다. 이 때문에 사용자 눈에는 여러 프로그램이 동시에 실행되는 것처럼 보입니다. 특정 프로세스에 더 많은 실행 시간을 부여하는 것을 가중치 라운드 로빈(Weighted Round-Robin) 방식이라고 하며, 이러한 CPU 스케줄링은 운영 체제의 가장 중요한 기능 중 하나입니다.

두 번째는 **메모리(Memory) 관리**입니다. C언어에서 전역 변수는 데이터 영역에, 지역 변수는 스택 영역에 할당되며, `malloc`이나 `calloc`을 사용한 동적 할당은 힙 영역에서 이루어집니다. 동적으로 할당된 메모리는 사용 후 반드시 `free`를 통해 해제해주어야 메모리 누수(leak)를 막을 수 있습니다. 또한, RAM이 부족할 경우 하드디스크의 일부를 메모리처럼 사용하는 **가상 메모리(Virtual Memory)** 기술도 운영 체제가 관리합니다.

세 번째는 **파일 시스템(File System) 관리**입니다. 디스크를 포맷할 때 `NTFS`나 `exFAT` 같은 방식을 선택하는데, 이는 데이터를 저장하는 블록(Block)의 크기와 관련이 있습니다. 예를 들어 할당 단위 크기를 4096바이트로 설정하면, 2바이트짜리 작은 파일을 저장해도 4096바이트 공간 전체를 차지하게 되어 공간 낭비가 발생합니다. 반면, 영상과 같이 용량이 큰 파일을 주로 저장한다면 블록 크기를 크게 잡는 것이 헤드 이동을 줄여 접근 속도를 향상시킬 수 있습니다.

하드디스크에 데이터를 쓰고 지우다 보면 하나의 파일이 여러 조각으로 나뉘어 저장되는데, 이를 **단편화(Fragmentation)**라고 합니다. 이 조각난 파일들을 한곳으로 모아 디스크 접근 속도를 높이는 작업을 **디스크 조각 모음(Defragmentation)**이라고 합니다. 하지만 SSD는 HDD와 저장 방식이 달라 조각 모음을 수행하면 오히려 수명이 단축될 수 있으므로 절대 해서는 안 됩니다.

또한, 바탕화면에 너무 많은 파일이나 바로가기를 두면 부팅 시 시스템이 해당 정보들을 모두 메모리로 불러오기 때문에 성능이 저하될 수 있습니다. 특히 실행 파일 자체를 바탕화면에 두는 것은 부팅 속도를 크게 늦추는 원인이 됩니다.

네 번째는 **입출력(I/O) 장치 관리**입니다. 초창기 Linux에서는 새로운 장치를 연결하면 파일로 인식하여 사용자가 직접 **마운트(mount)** 해줘야 했습니다. 지금은 대부분 자동으로 인식되지만, 이처럼 장치와의 상호작용을 제어하는 것도 OS의 역할입니다. PC 조립 시 연결하는 비프음 스피커는 부팅 시 발생하는 오류 코드를 소리로 알려주므로, 시스템 문제를 진단하는 데 매우 중요합니다.

운영 체제는 **커널 모드(Kernel Mode)**와 **사용자 모드(User Mode)**로 작동합니다. 커널 모드에서는 하드웨어 자원에 직접 접근할 수 있지만, 일반 응용 프로그램이 실행되는 사용자 모드에서는 반드시 **시스템 콜(System Call)**을 통해 커널에 자원을 요청해야 합니다.

커널의 구조는 **모놀리식 커널(Monolithic Kernel)**과 **마이크로 커널(Microkernel)**로 나뉩니다. 모놀리식 커널은 OS의 모든 기능이 하나의 큰 프로그램으로 통합된 구조로, 속도가 빠르지만 크기가 크다는 단점이 있습니다. Linux, Unix, Windows가 이 방식을 사용합니다. 반면, 마이크로 커널은 핵심 기능만 남기고 나머지 기능은 사용자 모드에서 실행하는 방식으로, 안정적이고 크기가 작지만 구조가 복잡합니다. macOS가 대표적인 예입니다.

Unix 시스템은 C언어로 개발되었기 때문에, 시스템 프로그래밍을 깊이 이해하려면 C언어 학습이 필수적입니다. Unix는 처음부터 다중 사용자(Multi-user) 및 다중 작업(Multi-tasking)을 지원하도록 설계되었습니다. 이는 각 사용자의 계정이 완벽히 분리되어 서로의 파일에 접근할 수 없다는 것을 의미하며, 여러 작업을 동시에 안정적으로 처리할 수 있습니다. 또한, 루트 디렉터리(`/`)를 최상위로 하는 **계층적 파일 시스템** 구조를 가집니다.

과거에는 워크스테이션이나 메인프레임 같은 고성능 컴퓨터에서 Unix를 사용했지만, 현재는 대부분 **클라우드 컴퓨팅(AWS 등)** 환경으로 이전되었습니다. 다만 은행, 국방부 등 높은 안정성이 요구되는 시스템에서는 여전히 메인프레임을 사용하는데, 이는 일반 PC와 달리 24시간 365일 무중단 운영을 보장하는 내구성 때문입니다.

### 1. 한 줄 요약

운영 체제는 CPU 스케줄링, 메모리 관리, 파일 시스템 제어 등 핵심 기능을 통해 시스템 자원을 효율적으로 관리하며, 커널 설계 방식과 사용자 권한 분리는 OS의 안정성과 성능을 결정합니다.

---
### 2. 핵심 TL;DR
* **OS의 핵심 기능**은 **프로세스, 메모리, 파일 시스템, 입출력(I/O) 장치**의 네 가지를 관리하는 것입니다.
* **CPU 스케줄링**은 여러 프로세스에 CPU 시간을 잘게 쪼개(Quantum Time) 번갈아 할당하여, 사용자에게는 여러 프로그램이 **동시에 실행되는 것처럼** 보이게 합니다. (**라운드 로빈** 방식)
* **메모리 관리**는 RAM이 부족할 때 하드디스크를 임시 메모리로 쓰는 **가상 메모리** 기술과, 프로그래머가 직접 메모리를 할당하고(`malloc`) 해제(`free`)하는 **동적 할당**을 포함합니다.
* **파일 시스템 관리**에서 **할당 단위(블록) 크기**는 파일 저장 효율에 영향을 주며, HDD의 물리적 파일 조각화는 **디스크 조각 모음**으로 해결하지만 **SSD에서는 절대 사용하면 안 됩니다.**
* 시스템은 하드웨어 직접 제어가 가능한 **커널 모드**와 응용 프로그램이 실행되는 **사용자 모드**로 분리되며, 두 영역 간의 통신은 **시스템 콜(System Call)**을 통해서만 이루어집니다.
* **모놀리식 커널**(Linux, Windows)은 모든 기능이 통합되어 빠르지만 크고, **마이크로 커널**(macOS)은 핵심 기능만 남아 안정적이지만 구조가 복잡합니다.
* **Unix/Linux**는 C언어 기반의 **다중 사용자(Multi-user)** 및 **다중 작업(Multi-tasking)** 시스템으로, 강력한 권한 관리와 계층적 파일 구조가 특징입니다.
* **시스템 비프음(Beep Code)**은 PC 부팅 시 하드웨어(RAM, 파워 등)의 이상 유무를 진단하는 중요한 신호입니다.

---
### 3. 표현 = 표준 용어
* **프로세스 관리 (Process Management)**: OS가 실행 중인 프로그램을 생성, 스케줄링, 제어 및 종료하는 기능.
* **CPU 스케줄링 (CPU Scheduling)**: 다수의 프로세스가 CPU를 효율적으로 사용하도록 할당 순서와 방식을 결정하는 기법.
* **가상 메모리 (Virtual Memory)**: 실제 RAM보다 더 큰 메모리 공간을 사용자에게 제공하기 위해 디스크 공간을 활용하는 기술.
* **시스템 콜 (System Call)**: 사용자 모드의 응용 프로그램이 커널 모드의 기능(예: 파일 열기)을 사용하기 위한 공식적인 요청 인터페이스.
* **모놀리식 커널 (Monolithic Kernel)**: 운영 체제의 주요 서비스가 모두 커널이라는 단일 코드 블록 내에 통합된 구조.
* **마이크로 커널 (Microkernel)**: 커널의 기능을 최소화하고 대부분의 서비스를 사용자 공간의 서버 프로세스로 구현하는 구조.
* **디스크 단편화 (Disk Fragmentation)**: 파일이 디스크 상의 비연속적인 공간에 분산되어 저장되는 현상.
* **마운트 (Mount)**: 저장 장치나 파일 시스템을 특정 디렉터리에 연결하여 접근 가능하게 만드는 과정.

---
### 4. 정석 보강 (canon-std)
**커널 모드와 사용자 모드**는 CPU가 실행할 수 있는 명령어 수준을 제한하여 시스템을 보호하는 하드웨어적 보안 기능입니다. **커널 모드(Supervisor Mode)**에서는 모든 CPU 명령어와 하드웨어 자원에 직접 접근할 수 있으며, 운영 체제의 핵심 코드(커널)가 이 모드에서 실행됩니다. 반면, **사용자 모드(User Mode)**에서는 응용 프로그램이 실행되며, 하드웨어 접근이나 메모리 직접 관리 같은 중요한 명령어 사용이 금지됩니다. 프로그램이 파일 읽기 등 커널의 도움이 필요할 때 **시스템 콜**을 발생시켜 잠시 커널 모드로 전환되고, 작업이 끝나면 다시 사용자 모드로 복귀하여 시스템 안정성을 유지합니다.

---
### 5. 실수·함정
* 여러 프로그램이 **실제로 동시에** 실행된다고 생각하는 것. (실제로는 CPU가 매우 빠르게 프로세스들을 **전환**하며 실행함)
* **SSD를 디스크 조각 모음**하는 것. (HDD와 달리 성능 향상이 없고, 불필요한 쓰기 작업으로 셀 수명만 단축시킴)
* 바탕화면에 파일을 많이 두는 것이 **성능에 영향이 없다**고 생각하는 것. (부팅 시 모든 항목을 로드하므로 시스템 시작 속도를 저하시킴)
* C언어에서 `malloc`으로 할당한 메모리는 프로그램이 끝나면 **자동으로 해제**될 것이라고 가정하는 것. (명시적으로 `free`를 호출하지 않으면 **메모리 누수**가 발생함)
* 모든 운영 체제의 커널 구조가 **비슷할 것**이라고 생각하는 것. (모놀리식과 마이크로 커널은 안정성, 성능, 확장성 측면에서 근본적인 차이가 있음)

* **모범답(강의 기준):** CPU가 매우 짧은 시간 단위(Quantum Time)로 여러 프로세스를 빠르게 번갈아 가며 실행하기 때문입니다. 각 프로세스는 아주 잠깐씩만 실행되지만, 전환 속도가 워낙 빨라 사람 눈에는 모든 프로그램이 끊김 없이 동시에 동작하는 것처럼 보입니다.
* **정석체크(면접 30초):** 운영 체제의 스케줄러가 정해진 시간 할당량(Time Slice)만큼 각 프로세스에 CPU 사용 권한을 부여하고, 시간이 다 되면 현재 프로세스의 상태를 저장(Context Switching)한 뒤 다음 프로세스로 전환합니다. 이 시분할(Time-sharing) 기법을 통해 단일 CPU 코어에서도 다중 작업(Multi-tasking) 환경을 구현합니다.

**[Q2] 시스템 보호를 위해 커널 모드와 사용자 모드를 분리하는 이유는 무엇이며, 이 둘은 어떻게 상호작용하는가? | #부팅/systemd**
* **모범답(강의 기준):** 응용 프로그램이 하드웨어 자원에 직접 접근하여 시스템을 망가뜨리는 것을 막기 위해 분리합니다. 사용자 모드의 프로그램은 하드웨어 제어가 필요할 때 '시스템 콜'이라는 정식 요청을 보내 커널에 작업을 위임하는 방식으로 상호작용합니다.
* **정석체크(면접 30초):** **모드 분리**는 시스템의 안정성과 보안을 위한 핵심적인 하드웨어 보호 장치입니다. 사용자 모드에서는 제한된 명령어만 실행 가능하며, 파일 입출력이나 네트워크 통신 등 특권이 필요한 작업은 반드시 **시스템 콜 인터페이스**를 통해 커널에 요청해야 합니다. 이 요청 시 하드웨어 트랩(trap)이 발생하여 커널 모드로 전환되고, 작업 완료 후 다시 사용자 모드로 복귀합니다.

**[Q3] 모놀리식 커널(Linux)과 마이크로 커널(macOS)의 핵심적인 차이점과 장단점은 무엇인가? | #부팅/systemd**
* **모범답(강의 기준):** **모놀리식**은 모든 OS 기능이 하나의 큰 커널에 포함되어 속도가 빠르지만 크기가 큽니다. 반면 **마이크로**는 최소한의 핵심 기능만 커널에 남기고 나머지는 외부 모듈로 분리하여 안정적이고 작지만, 모듈 간 통신 때문에 상대적으로 느릴 수 있습니다.
* **정석체크(면접 30초):** 핵심 차이는 커널에 포함되는 기능의 범위입니다. 모놀리식 커널은 모든 드라이버와 서비스가 커널 공간에서 직접 통신하여 **성능**이 우수하지만, 하나의 오류가 시스템 전체를 중단시킬 수 있습니다. 마이크로 커널은 대부분의 서비스를 사용자 공간에서 실행시켜 **안정성과 확장성**이 높지만, 프로세스 간 통신(IPC) 오버헤드로 인해 성능 저하가 발생할 수 있습니다.

**[Q4] 디스크 조각 모음은 어떤 원리이며, 왜 HDD에는 유용하지만 SSD에는 해로운가? | #파일시스템/마운트**
* **모범답(강의 기준):** 디스크에 흩어져 있는 파일 조각들을 물리적으로 연속된 공간에 재배치하여, 헤드가 데이터를 읽기 위해 움직이는 거리를 최소화하는 원리입니다. SSD는 기계적으로 움직이는 헤드가 없고 데이터 위치에 따른 접근 속도 차이가 없으므로 효과가 없는 반면, 불필요한 쓰기 작업만 늘려 셀의 수명을 단축시키기 때문에 해롭습니다.
* **정석체크(면접 30초):** **HDD**는 물리적인 플래터 회전과 헤드 이동으로 데이터를 탐색하므로, 단편화된 파일을 연속적으로 재배열하면 탐색 시간(Seek Time)이 줄어 성능이 향상됩니다. 하지만 **SSD**는 낸드 플래시 메모리에 전기 신호로 직접 접근하므로 물리적 위치가 성능에 영향을 주지 않으며, 오히려 조각 모음 시 발생하는 대량의 쓰기 작업이 셀의 쓰기 수명 제한(P/E Cycle)을 빠르게 소진시켜 장치를 손상시킵니다.

**[Q5] C언어에서 동적으로 할당한 메모리를 `free()`로 해제하지 않으면 어떤 문제가 발생하는가? | #패키지/압축/빌드**
* **모범답(강의 기준):** 프로그래머가 `free()`를 호출하지 않으면, 해당 메모리 영역은 프로그램이 종료될 때까지 계속 점유된 상태로 남습니다. 다른 프로그램에서는 이 영역을 볼 수도, 사용할 수도 없게 되어 시스템 전체적으로 사용 가능한 메모리가 줄어드는 문제가 발생합니다.
* **정석체크(면접 30초):** `free()`를 호출하지 않으면 **메모리 누수(Memory Leak)**가 발생합니다. 이는 할당된 힙(Heap) 메모리에 대한 포인터를 잃어버려 더 이상 접근하거나 해제할 수 없게 된 상태로, 해당 메모리는 어떤 프로그램도 사용할 수 없는 유휴 공간으로 남습니다. 이 현상이 누적되면 시스템의 가용 메모리가 고갈되어 결국 성능 저하나 시스템 장애로 이어질 수 있습니다.

## **2025-09-05, 3교시 — 개선본**

Linux는 공개 소프트웨어(Open Source)입니다. 핵심인 커널(Kernel)을 공개하여 누구나 코드를 수정하고 개선할 수 있도록 했습니다. 이는 개발자 입장에서 매우 이례적인 결정이었지만, "오류가 있다면 사용자들이 직접 고쳐서 사용하라"는 개념으로 배포되면서 폭넓게 발전할 수 있었습니다.

Linux의 주요 특징은 다음과 같습니다.

첫째, **Unix와의 호환성**이 매우 높습니다. Unix 명령어를 거의 그대로 사용할 수 있어, 개인 PC에 Linux를 설치하여 Unix 환경을 학습하는 용도로 활용할 수 있습니다.

둘째, **서버용 운영 체제**로 설계되었습니다. 다중 사용자(Multi-user)와 다중 프로세스(Multi-process) 환경을 완벽하게 지원하므로, 여러 사용자가 동시에 접속하여 다양한 작업을 처리하는 서버에 매우 적합합니다.

셋째, 과거에는 텍스트 기반(CLI)이었으나, **GNOME**과 같은 GUI(그래픽 사용자 인터페이스) 환경이 도입되면서 Windows처럼 마우스 클릭만으로도 쉽게 사용할 수 있게 되었습니다.

Linux의 구조는 하드웨어를 직접 제어하는 **커널**이 있고, 그 위에 사용자의 명령어를 해석하여 커널에 전달하는 **셸(Shell)**이 위치합니다. 우리는 주로 Bash(Bourne-Again Shell) 셸을 사용하게 될 것입니다.

Linux에는 수많은 배포판(Distribution)이 존재하며, 크게 Debian, Slackware, Red Hat 계열로 나뉩니다. 과거에는 Red Hat이 시장을 주도했으나, 현재는 **Ubuntu**, **CentOS**, **Fedora** 등이 널리 사용되고 있습니다. 우리는 이 중에서 **Ubuntu**를 사용하여 실습을 진행할 것입니다.

배포판 버전 뒤에 **LTS(Long-Term Support)**가 붙는 경우가 있는데, 이는 최소 5년 이상 장기적으로 보안 업데이트와 유지보수를 지원하는 안정화 버전을 의미합니다.

실습에서는 기존 Windows가 설치된 PC에 Linux를 직접 설치하는 대신, **가상 머신(Virtual Machine)**을 사용할 것입니다. **VMware**와 같은 소프트웨어를 이용해 Windows 내에 독립된 가상 컴퓨터를 만들고, 그 위에 Ubuntu 운영 체제를 설치할 계획입니다.

Linux는 연결된 모든 장치를 파일로 인식하는 특징이 있습니다. 따라서 가상 머신에 설치된 Linux 안에서는 기존 Windows의 파일이나 디렉터리에 접근할 수 있습니다. 하지만 반대로 Windows에서는 가상 머신 내에 설치된 Linux의 파일 시스템을 볼 수 없습니다.

### 1. 한 줄 요약

Linux는 Unix와 높은 호환성을 가진 오픈 소스 서버 운영 체제로, 다양한 배포판이 존재하며 Windows 환경에서는 가상 머신(VM)을 통해 안전하게 설치하고 사용할 수 있습니다.

---
### 2. 핵심 TL;DR
* **Linux의 특징**: 소스가 공개된 **오픈 소스**이며, **Unix 명령어와 호환**되어 서버 환경 학습에 적합합니다.
* **서버 지향 설계**: 여러 사용자가 동시에 접속하고 작업하는 **다중 사용자(Multi-user)** 환경을 기본으로 지원합니다.
* **셸(Shell)과 커널(Kernel)**: 사용자가 명령어를 입력하는 인터페이스가 **셸**(예: `Bash`)이고, 셸이 받은 명령을 해석해 하드웨어를 제어하는 핵심이 **커널**입니다.
* **GUI 환경**: 과거에는 텍스트 기반이었으나, **GNOME**과 같은 그래픽 인터페이스가 등장하여 Windows처럼 편리하게 사용할 수 있습니다.
* **배포판(Distribution)**: Linux 커널에 다양한 소프트웨어를 조합하여 만든 운영체제 패키지로, **Ubuntu**, **CentOS**, **Fedora** 등이 유명합니다.
* **LTS (Long-Term Support)**: '장기 지원 버전'을 의미하며, 최소 5년간 안정적인 업데이트를 보장하여 기업 및 서버 환경에서 선호됩니다.
* **가상 머신 (Virtual Machine)**: 기존 OS(Windows) 위에 에뮬레이션으로 동작하는 가상의 컴퓨터를 만들어, 파티션 변경 없이 안전하게 다른 OS(Linux)를 설치하는 기술입니다.
* **CLI vs GUI**: 명령어를 직접 입력하는 CLI(`ipconfig`) 방식과 아이콘을 클릭하는 GUI(네트워크 속성창) 방식 모두 장단점이 있으며, 개발자는 양쪽 모두에 익숙해질 필요가 있습니다.

---
### 3. 표현 = 표준 용어
* **오픈 소스 (Open Source)**: 소프트웨어의 소스 코드를 공개하여 누구나 자유롭게 사용, 수정, 배포할 수 있도록 하는 원칙 또는 그 소프트웨어.
* **셸 (Shell)**: 사용자와 운영 체제 커널 사이의 인터페이스 역할을 하는 명령어 해석기. (예: `Bash`)
* **배포판 (Distribution / Distro)**: Linux 커널과 시스템 관리 도구, 각종 응용 프로그램을 묶어 사용자가 쉽게 설치할 수 있도록 만든 패키지.
* **LTS (Long-Term Support)**: 장기간에 걸쳐 안정성과 보안 업데이트를 보장하는 소프트웨어 버전.
* **가상 머신 (Virtual Machine, VM)**: 물리적 컴퓨터 시스템 위에 소프트웨어로 구현된 가상의 컴퓨터 시스템.
* **GNOME**: Linux 데스크톱 환경을 위한 GUI를 제공하는 대표적인 오픈 소스 프로젝트.
* **Unix 호환성 (Unix Compatibility)**: Unix 시스템의 표준, 명령어, 동작 방식을 따르는 특성.

---
### 4. 정석 보강 (canon-std)
**가상 머신(Virtual Machine)**은 물리적 하드웨어 한 대에서 여러 개의 독립된 운영 체제를 동시에 실행할 수 있게 하는 소프트웨어 기술입니다. **하이퍼바이저(Hypervisor)**라 불리는 VM 관리 소프트웨어(예: VMware, VirtualBox)가 호스트 OS로부터 CPU, 메모리, 저장 공간 등 자원을 할당받아 가상화된 하드웨어를 생성합니다. 이 가상 하드웨어 위에 게스트 OS(예: Ubuntu)를 설치하면, 게스트 OS는 자신이 독립된 컴퓨터에서 실행되는 것처럼 작동하며 호스트 시스템과 완전히 격리되어 시스템 변경 없이 안전한 테스트 및 개발 환경을 제공합니다.

---
### 5. 실수·함정
* **Linux는 하나**라고 생각하는 것. (Linux는 '커널'의 이름이며, 사용자는 Ubuntu, Fedora 등 수많은 '배포판' 중 하나를 선택해 사용함)
* **Linux는 명령어(CLI)로만** 써야 한다고 생각하는 것. (GNOME, KDE 등 현대적인 GUI 환경을 통해 매우 편리하게 사용 가능함)
* Linux를 설치하려면 반드시 **Windows를 삭제하거나 디스크를 나눠야 한다**고 생각하는 것. (가상 머신을 사용하면 기존 환경에 아무런 영향을 주지 않고 설치할 수 있음)
* **Unix와 Linux를 동일한 것**으로 착각하는 것. (Linux는 Unix의 철학과 설계를 본뜬 'Unix-like' 운영 체제이지만, 소스 코드는 완전히 별개로 개발되었음)
* **LTS가 아닌 버전은 불안정하다**고 생각하는 것. (최신 버전은 새로운 기능을 먼저 체험할 수 있는 버전이며, LTS는 장기적인 안정성에 초점을 맞춘 버전일 뿐임)

* **정석체크(면접 30초):** Linux는 강력한 **권한 관리 모델**을 통해 사용자와 프로세스를 철저히 분리하여 시스템 안정성을 보장합니다. 또한, 적은 자원으로도 안정적인 서비스가 가능하고, 원격 관리를 위한 **SSH**와 같은 강력한 도구를 기본 제공하므로 서버 운영에 최적화되어 있습니다.

**[Q2] Linux 시스템에서 '셸(Shell)'과 '커널(Kernel)'의 역할은 어떻게 구분되는가? | #셸/리다이렉션/FD**
* **모범답(강의 기준):** **커널**은 하드웨어를 직접 제어하는 운영 체제의 핵심이며, **셸**은 사용자가 입력한 명령어(예: `ls`, `cd`)를 해석해서 커널에 전달해주는 명령어 해석기이자 사용자와 커널 사이의 인터페이스입니다.
* **정석체크(면접 30초):** 둘은 실행되는 공간부터 다릅니다. **커널**은 보호된 커널 공간(Kernel Space)에서 실행되며 모든 시스템 자원을 관리하는 운영 체제의 심장입니다. **셸**은 사용자 공간(User Space)에서 실행되는 응용 프로그램의 일종으로, 사용자의 명령을 커널이 이해할 수 있는 시스템 콜로 변환해주는 역할을 수행합니다.

---
**[Q3] 'Linux 배포판(Distribution)'이란 무엇이며, Ubuntu와 CentOS는 어떤 관계인가? | #패키지/압축/빌드**
* **모범답(강의 기준):** 배포판이란 Linux 커널에 특정 소프트웨어들과 설정들을 묶어서 사용자가 쉽게 설치할 수 있도록 만든 패키지입니다. Ubuntu는 Debian 계열 배포판이고, CentOS는 Red Hat 계열 배포판으로, 기반이 되는 계열이 서로 다릅니다.
* **정석체크(면접 30초):** Linux 커널은 OS의 핵심일 뿐, 그 자체로 완전한 운영 체제는 아닙니다. **배포판**은 이 커널에 GNU 유틸리티, GUI, 패키지 관리 시스템(`apt`, `yum`) 등을 조합한 완성된 OS이며, **Ubuntu**는 사용 편의성에 중점을 둔 Debian 기반 배포판, **CentOS**는 Red Hat Enterprise Linux와 완벽히 호환되는 서버용 배포판입니다.

---
**[Q4] 소프트웨어 버전에서 LTS(Long-Term Support)가 의미하는 바는 무엇이며, 어떤 경우에 선택해야 하는가? | #패키지/압축/빌드**
* **모범답(강의 기준):** LTS는 '장기 지원 버전'이라는 의미로, 최소 5년과 같이 약속된 기간 동안은 제조사가 책임지고 보안 업데이트 등을 지원해주는 버전입니다. 잦은 시스템 변경이 어려운 안정적인 운영이 필수적인 서버나 기업 환경에서 선택하는 것이 좋습니다.
* **정석체크(면접 30초):** **LTS**는 새로운 기능 추가보다는 **안정성과 예측 가능성**에 초점을 맞춘 버전입니다. 장기간에 걸쳐 보안 패치와 버그 수정이 보장되므로, 한번 구축하면 오랫동안 변경 없이 사용해야 하는 프로덕션 서버, 임베디드 시스템, 또는 기업용 데스크톱 환경에 절대적으로 권장됩니다.

---
**[Q5] 기존 Windows 환경에 Linux를 설치할 때, 가상 머신(VM)을 사용하는 가장 큰 장점은 무엇인가? | #파일시스템/마운트**
* **모범답(강의 기준):** 실제 하드디스크의 파티션을 변경하는 위험한 작업 없이, 기존 Windows를 그대로 유지한 채 그 위에 독립된 가상 컴퓨터를 만들어 안전하게 Linux를 설치하고 사용할 수 있다는 점이 가장 큰 장점입니다.
* **정석체크(면접 30초):** 가장 큰 장점은 **격리(Isolation)**와 **안전성**입니다. 게스트 OS(Linux)는 호스트 OS(Windows)와 분리된 샌드박스 환경에서 실행되므로, Linux 내부에서 발생하는 오류나 작업이 Windows 시스템에 전혀 영향을 주지 않습니다. 또한, 스냅샷 기능으로 특정 시점의 시스템 상태를 쉽게 저장하고 복원할 수 있어 테스트에 매우 유용합니다.
