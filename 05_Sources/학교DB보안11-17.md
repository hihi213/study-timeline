## 정리# 0. 수업 개요 - DB보안 1교시_2025.11.17

### 오늘의 Workflow

- **Step 1)** Data Modeler 환경 설정 (Browser & Design Save)
- **Step 2)** 물리적 모델링: 테이블(Relational) 설계 (User/Buy)
- **Step 3)** 관계 설정: 식별/비식별 및 FK(Foreign Key) 구성
- **Step 4)** 배포: DDL 생성(Generation) 및 DB 적용
- **Step 5)** 역공학(Reverse Engineering): Data Dictionary Import (EMP/DEPT)
    

### 오늘의 실습 연결고리 (Flow Summary)

- **"설계부터 구현까지"**: 요구사항 분석(메모장) → **SQL Developer Modeler로 시각화(물리 모델)** → **DDL 자동 생성** → **DB에 실제 테이블 생성**
- **"기존 DB 시각화"**: 이미 존재하는 `EMP`, `DEPT` 테이블을 역으로 불러와 ERD(관계도)를 추출하는 방법 학습.

## Step 1. Data Modeler 환경 설정 - DB보안 1교시_2025.11.17

### Goal & Preconditions

- **Goal**: SQL Developer 내장 도구인 'Data Modeler'를 활성화하고 작업 공간(.dmd)을 저장한다.
- **Preconditions**: SQL Developer 실행 상태.
    

### Concept

- **Data Modeler**: DB 설계를 위한 CASE 툴. 개념/논리/물리 모델링을 지원하며, SQL Developer에 내장되어 있어 별도 설치(ERWin 등) 없이 사용 가능.
- **Browser (브라우저)**: 모델링 객체(테이블, 관계, 도메인 등)를 트리 구조로 관리하는 패널.
    

### Build & Execute

#### Logic

1. `보기(View)` 메뉴 → `Data Modeler` → `브라우저` 선택.
2. 좌측 패널에 브라우저 탭 생성 확인.
3. `제목 없음` 우클릭 → `디자인 저장(Save Design)` → 파일명 `model`로 저장 (확장자 `.dmd`).
4. **Relational Model(관계형 모델)** 노드 우클릭 → `표시(Show)`하여 빈 캔버스 오픈.
    

#### **Pitfalls**

- ⚠️ **저장 시점**: 작업을 다 하고 저장하기보다, 시작하자마자 `디자인 저장`을 눌러 `.dmd` 파일을 생성해두는 것이 안전함.
- ⚠️ **모델링 레벨**: 수업에서는 시간 관계상 '개념/논리 모델'을 건너뛰고 바로 **'관계형 모델(물리 모델)'** 탭에서 작업을 시작함.

## Step 2. 물리적 모델링 (테이블 생성) - DB보안 1교시_2025.11.17

### Goal & Preconditions

- **Goal**: 요구사항(메모장)을 분석하여 `USER_TBL`(고객)과 `BUY_TBL`(구매) 테이블을 GUI로 설계한다.
- **Preconditions**: Relational Model 캔버스가 열려 있어야 함.
    

### Concept

- **Physical Modeling (물리 모델링)**: 실제 DB에 적용될 테이블명, 컬럼명, 데이터 타입(VARCHAR2, NUMBER), PK 등을 구체적으로 명시하는 단계.
    

### Build & Execute

#### Logic

1. **도구 모음**에서 `새 테이블(New Table)` 아이콘 클릭 → 캔버스 클릭.
2. **속성 창(Properties)** 진입:
    
    - **일반(General)**: 이름 `USER_TBL` 입력.
    - **열(Columns)**:
        - `USER_NAME` (PK), `BIRTH_YEAR`, `ADDR`, `MOBILE` 추가.
        - 데이터 타입 및 크기 지정.
        - `PK` 체크박스로 기본키 설정, `Mandatory`(필수/NOT NULL) 체크.
            
3. 동일한 방식으로 `BUY_TBL` 생성 (컬럼: `PROD_NAME`, `PRICE` 등).
    

#### **Pitfalls**

- ⚠️ **속성 창 잘림 현상**: 윈도우 해상도에 따라 속성 창의 하단(세부 설정)이 안 보일 수 있음. 창 크기를 늘려서 확인 필요.
- ⚠️ **PK 설계 관행(Real World vs Class)**:
    - **수업**: 편의상 `USER_NAME`이나 `MOBILE`을 PK로 잡는 경우가 있음.
    - **실무**: 이름/전화번호는 중복/변경 가능성이 있으므로 반드시 `USER_ID` 또는 `SEQ`(일련번호)를 별도 인조키(Artificial Key)로 생성해야 함.
        

### 💡 Interview

> [!faq]- Q. 논리적 모델링과 물리적 모델링의 차이는?
>
> 🗣️ 핵심 답변
>
> 논리적 모델링은 비즈니스 관점에서 엔터티와 관계를 정의하며 한글 명칭과 식별자를 사용하는 반면, 물리적 모델링은 실제 DB 구축을 위해 영문 테이블명, 컬럼의 데이터 타입(VARCHAR2 등), 인덱스, 파티셔닝 등을 구체적으로 설계하는 단계입니다.
>
> **📚 꼬리질문 대비**
>
> - **Why**: 물리 모델링은 DBMS 성능과 직결되므로 정규화/반정규화 결정이 중요합니다.
>

## Step 3. 관계 설정 (FK) - DB보안 1교시_2025.11.17

### Goal & Preconditions

- **Goal**: `USER_TBL`(부모)과 `BUY_TBL`(자식) 간의 참조 관계(FK)를 설정한다.
    

### Concept

- **Foreign Key (외래키)**: 두 테이블 간의 관계를 연결하는 다리. 자식 테이블의 FK 값은 부모 테이블의 PK에 존재하거나 NULL이어야 함(참조 무결성).
    

### Build & Execute

#### Logic

1. 도구 모음에서 `새 외래 키(New Foreign Key)` 아이콘 클릭.
2. **자식 테이블(`BUY_TBL`)** 클릭 → 드래그 → **부모 테이블(`USER_TBL`)** 클릭.
    
    - (참고: 교수님 설명은 "참조하는 쪽에서 참조되는 쪽으로" 흐름)
        
3. **외래 키 속성** 확인:
    
    - 이름 자동 생성 (예: `USER_TBL_FK`).
    - `참조된 열(Referenced Column)`: 자동으로 부모의 PK가 매핑됨.
    - `삭제 규칙(Delete Rule)`: `NO ACTION` (기본값) 확인. (필요 시 `CASCADE`, `SET NULL` 설정).
        

#### **Pitfalls**

- ⚠️ **클릭 순서**: 툴마다 드래그 방향(부모→자식 vs 자식→부모)이 다를 수 있음. SQL Developer는 연결 후 속성창에서 '상위 테이블(Parent)'과 '하위 테이블(Child)'이 올바르게 매핑되었는지 반드시 재확인해야 함.

## Step 4. DDL 생성 및 배포 - DB보안 1교시_2025.11.17

### Goal & Preconditions

- **Goal**: GUI로 그린 모델을 실제 SQL 코드(`CREATE TABLE …`)로 변환하고 DB에 실행한다.
    

### Build & Execute

#### Logic

1. **DDL 생성**: 툴바의 `DDL 생성(Generate DDL)` 아이콘(원기둥 모양) 클릭.
2. **옵션 확인**: `Generate` 버튼 클릭 → SQL 스크립트 자동 생성됨 확인.
3. **저장**: `.ddl` 파일로 저장 (예: `model_schema.ddl`).
4. **실행 (Deployment)**:
    
    - SQL Developer 워크시트에서 저장한 `.ddl` 파일 열기.
    - **접속**: `-- 접속: TEST_USER` (실습 계정 선택).
    - `스크립트 실행(F5)` 버튼 클릭.
        

#### Code (Generated Example)

```SQL
-- DDL 생성 예시
CREATE TABLE USER_TBL (
    USER_NAME VARCHAR2(20) NOT NULL,
    -- … 기타 컬럼
    CONSTRAINT USER_TBL_PK PRIMARY KEY (USER_NAME)
);

CREATE TABLE BUY_TBL (
    -- …
    USER_NAME VARCHAR2(20) NOT NULL,
    CONSTRAINT BUY_TBL_FK FOREIGN KEY (USER_NAME) 
    REFERENCES USER_TBL (USER_NAME)
);
```

### 검증

```SQL
-- 테이블 생성 확인
SELECT table_name FROM user_tables 
WHERE table_name IN ('USER_TBL', 'BUY_TBL');
```

## Step 5. 역공학 (Reverse Engineering) - DB보안 1교시_2025.11.17

### Goal & Preconditions

- **Goal**: 이미 존재하는 `EMP`, `DEPT` 테이블을 불러와서 ERD를 그린다.
    

### Concept

- **Reverse Engineering**: 구현된 시스템(DB)을 분석하여 설계도(ERD)를 역으로 추출하는 기법. 레거시 시스템 분석 시 필수적.
    

### Build & Execute

#### Logic

1. 메뉴 `파일(File)` → `데이터 모델러` → `임포트(Import)` → `데이터 딕셔너리(Data Dictionary)`.
2. **접속 선택**: `TEST` 계정 (또는 EMP가 있는 계정) 선택.
3. **객체 선택**: 테이블 목록에서 `EMP`, `DEPT` 체크 후 `다음`.
4. **완료**: 자동으로 관계선이 연결된 ERD가 생성됨.
    

#### **Pitfalls**

- ⚠️ **FK 누락**: DB에 FK 제약조건(`CONSTRAINT`)이 실제로 걸려있지 않다면, 임포트 시 관계선이 그려지지 않음. (실무에서는 성능상 FK를 물리적으로 걸지 않는 경우가 많아 주의 필요).

# 0. 수업 개요 - DB보안 2교시_2025.11.17

### 오늘의 Workflow

- **Step 1)** 개발 환경 준비 (Eclipse, JDK, JDBC Driver 다운로드)
- **Step 2)** JDBC 라이브러리 연동 (Eclipse Build Path 설정)
- **Step 3)** DB 데이터 준비 (실습용 테이블 생성 및 데이터 삽입 - `STUDENT`, `DEPARTMENT`)
- **Step 4)** Java-Oracle 연동 테스트 (Connection Check)
    

### 오늘의 실습 연결고리 (Flow Summary)

- **"설계(1교시)에서 구현(2교시)으로"**: 앞서 설계한 모델을 바탕으로, 실제 응용 프로그램(Java)에서 데이터베이스(Oracle)에 접속하여 데이터를 조회하는 **JDBC(Java Database Connectivity) 기초 환경**을 구축합니다.
- **"Middle-ware 개념"**: Java와 Oracle은 서로 다른 언어를 쓰기 때문에, 중간에서 통역사 역할을 하는 **JDBC Driver(ojdbc.jar)**가 필수적임을 이해하고 설정합니다.

## Step 1. JDBC 드라이버 설정 (Eclipse) - DB보안 2교시_2025.11.17

### Goal & Preconditions

- **Goal**: Java 프로젝트에서 Oracle DB와 통신할 수 있도록 `ojdbc` 라이브러리를 등록한다.
- **Preconditions**: Eclipse IDE 및 JDK 설치 완료, `ojdbc8.jar` (또는 해당 버전) 파일 다운로드 완료.
    

### Concept

- **JDBC Driver (OJDBC)**: Java 프로그램이 Oracle DB에 접속할 수 있게 해주는 API 구현체(라이브러리). `.jar` 파일 형태이며, 프로젝트의 **Build Path(Classpath)**에 등록되어야 JVM이 이를 인식하고 로드할 수 있습니다.
    

### Build & Execute

#### Logic

1. **프로젝트 생성**: Eclipse에서 `OracleDB_Exam` (또는 임의명) Java Project 생성.
2. **라이브러리 폴더 구성**:
    
    - 프로젝트 우클릭 -> `New` -> `Folder` -> 이름: `lib`
    - 다운로드 받은 `ojdbcX.jar` 파일을 `lib` 폴더에 복사(Ctrl+C) & 붙여넣기(Ctrl+V).
        
3. **Build Path 등록**:
    
    - `lib` 폴더 안의 `.jar` 파일 우클릭 -> `Build Path` -> `Add to Build Path`.
    - **확인**: 프로젝트 탐색기(Package Explorer)에 `Referenced Libraries` 항목이 생기고 그 안에 jar 파일이 들어갔는지 확인.
        

#### **Pitfalls**

- ⚠️ **단순 복사 vs Build Path**: `lib` 폴더에 파일을 넣기만 하고 **Build Path 추가를 안 하면** 코드는 작성되지만 실행 시 `ClassNotFoundException` 에러가 발생합니다. (가장 흔한 실수)
- ⚠️ **버전 호환성**: JDK 버전과 Oracle DB 버전에 맞는 Driver를 써야 합니다. (보통 JDK 8 이상이면 `ojdbc8.jar` 사용).

## Step 2. 실습 데이터 준비 (SQL) - DB보안 2교시_2025.11.17

### Goal & Preconditions

- **Goal**: Java 프로그램이 조회할 `DEPARTMENT`(학과)와 `STUDENT`(학생) 테이블을 생성하고 기초 데이터를 넣는다.
- **Preconditions**: SQL Developer 접속 (`TEST_USER` 등 본인 실습 계정).
    

### Concept

- **Seed Data**: 애플리케이션 테스트를 위해 초기에 넣어주는 기초 데이터.
    

### Build & Execute

#### Logic

- 기존 `TEST` 계정(혹은 본인 계정)에 접속하여 아래 스크립트를 실행합니다. (교수님 카톡 공유 코드 복원)
    

#### Code

```SQL
-- 접속: 본인 실습 계정 (예: TEST_USER)

-- 1. 학과 테이블 생성
CREATE TABLE DEPARTMENT (
    DEPT_ID     VARCHAR2(10),
    DEPT_NAME   VARCHAR2(30) NOT NULL,
    OFFICE      VARCHAR2(30),
    CONSTRAINT PK_DEPARTMENT PRIMARY KEY(DEPT_ID)
);

-- 2. 학생 테이블 생성
CREATE TABLE STUDENT (
    STU_ID      VARCHAR2(20),
    NAME        VARCHAR2(30) NOT NULL,
    ADDRESS     VARCHAR2(50),
    CONSTRAINT PK_STUDENT PRIMARY KEY(STU_ID)
);

-- 3. 데이터 삽입 (학과)
INSERT INTO DEPARTMENT VALUES('920', '컴퓨터공학과', '201호');
INSERT INTO DEPARTMENT VALUES('923', '산업공학과', '207호');
INSERT INTO DEPARTMENT VALUES('925', '전자공학과', '308호');

-- 4. 데이터 삽입 (학생)
INSERT INTO STUDENT VALUES('1292001', '김광식', '서울');
INSERT INTO STUDENT VALUES('1292002', '김정현', '서울');
INSERT INTO STUDENT VALUES('1292003', '김현정', '대전');

-- 5. 확정
COMMIT;
```

#### **Pitfalls**

- ⚠️ **PK 중복**: 스크립트를 두 번 실행하면 `PK_DEPARTMENT`, `PK_STUDENT` 제약조건 위반 에러(`ORA-00001`)가 발생합니다. 이미 테이블이 있다면 `DROP` 후 재생성하거나 `INSERT`만 건너뛰어야 합니다.

## Step 3. Java 연동 테스트 (Connect Check) - DB보안 2교시_2025.11.17

### Goal & Preconditions

- **Goal**: Java 코드로 DB에 접속하여 데이터를 가져오는지 확인(Console 출력)한다.
- **Preconditions**: Step 1(라이브러리), Step 2(데이터) 완료.
    

### Concept

- **DriverManager.getConnection()**: JDBC URL, 사용자 ID, 비밀번호를 이용해 실제 DB 세션(Connection 객체)을 획득하는 핵심 메서드.
    

### Build & Execute

#### Logic

1. Eclipse에서 `DBConnectTest.java` 클래스 생성 (메인 메서드 포함).
2. 접속 정보 변수 설정 (`url`, `id`, `pw`).
3. `Class.forName()`으로 드라이버 로딩.
4. `DriverManager.getConnection()`으로 연결.
5. `Connection` 성공 시 "접속 성공" 메시지 출력.
    

#### Code (Boilerplate)

```Java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class DBConnectTest {
    public static void main(String[] args) {
        // 1. 접속 정보 (본인 환경에 맞게 수정)
        // 포트(1521)와 SID(xe 또는 orcl) 확인 필수
        String url = "jdbc:oracle:thin:@localhost:1521:xe"; 
        String id = "TEST_USER"; // 본인 계정 ID
        String pw = "1234";      // 본인 계정 PW

        Connection conn = null;
        
        try {
            // 2. 드라이버 로딩
            Class.forName("oracle.jdbc.driver.OracleDriver");
            System.out.println("드라이버 로딩 성공");

            // 3. 연결
            conn = DriverManager.getConnection(url, id, pw);
            System.out.println("DB 접속 성공: " + conn);
            
            // (선택) 데이터 조회 테스트
            // … (Statement 작성 부분)

        } catch (ClassNotFoundException e) {
            System.err.println("드라이버 파일(jar)이 Build Path에 없습니다.");
            e.printStackTrace();
        } catch (SQLException e) {
            System.err.println("DB 연결 정보(URL, ID, PW)를 확인하세요.");
            e.printStackTrace();
        } finally {
            // 4. 자원 해제
            try { if(conn != null) conn.close(); } catch(Exception e) {}
        }
    }
}
```

#### **Pitfalls**

- ⚠️ **Copy & Paste 문자 깨짐**: 강의 중 언급된 것처럼, 카카오톡이나 웹에서 코드를 복사해서 Eclipse에 붙여넣으면 **이중 따옴표(" ")**가 특수문자(Smart Quotes)로 변환되어 들어가는 경우가 있습니다.
    - **증상**: 코드에 빨간 줄(Syntax Error)이 생김.
    - **해결**: 따옴표를 지우고 직접 다시 타이핑해야 합니다.
- ⚠️ **계정 정보 불일치**: `TEST_USER`가 아닌 본인이 만든 계정명(`TEST_KMJ` 등)을 써야 하는데, 예제 코드를 그대로 써서 `ORA-01017` (ID/PW 불일치) 에러가 자주 발생합니다.

>

<details>

<summary>Q1. (보안) 왜 사용자 테이블의 PK로 '전화번호'를 쓰지 않고 굳이 '회원번호'를 새로 만드나요?</summary>
<br>
[🗣️ 핵심 요약]

전화번호는 **개인정보(PII)**이며 변경 가능성이 있기 때문입니다. 보안과 성능을 위해 비즈니스 의미가 없는 **대리 키(Surrogate Key)**를 사용하는 것이 표준입니다.
<br><br>
[📚 상세 설명]

1. **개인정보 노출 위험:** 전화번호를 PK로 쓰면, 자식 테이블(FK)이나 로그 파일에 전화번호가 평문으로 여기저기 저장됩니다.
    <br>
2. **불변성(Immutability) 위배:** PK는 영원히 변하지 않아야 가장 좋지만, 전화번호는 변경될 수 있습니다. PK가 바뀌면 관련된 모든 FK 데이터를 업데이트해야 하는 오버헤드가 발생합니다.
    <br>
3. 성능: 문자열(VARCHAR)보다 숫자형(NUMBER) 시퀀스가 인덱싱 및 조인 성능이 더 우수합니다.
    <br>
    </details>
    

<details>

<summary>Q2. (무결성) 부모 테이블(User)의 데이터를 삭제할 때 '참조 무결성 위배' 에러가 나는 이유는?</summary>

  

[🗣️ 핵심 요약]

자식 테이블(Buy)이 해당 부모 데이터를 **참조(FK)**하고 있기 때문입니다. 이를 방치하고 부모만 삭제하면 자식 데이터는 **고아(Orphan)**가 되어 데이터 무결성이 깨집니다.

  
  

[📚 상세 설명]

- **해결 방법 1 (삭제 제한):** 자식 데이터를 먼저 삭제하거나 FK 연결을 끊은 후 부모를 삭제합니다. (가장 안전)
- **해결 방법 2 (Cascade):** `ON DELETE CASCADE` 옵션을 사용하여 부모 삭제 시 자식도 자동 삭제되게 합니다. (편리하지만 실수로 대량 데이터 손실 위험)
- 보안 관점: 실무에서는 중요한 로그(구매 이력 등)가 사라지지 않도록 CASCADE 사용을 엄격히 제한하거나, 논리적 삭제(Logical Delete, status=&#39;N&#39; 업데이트)를 주로 사용합니다.
    
    </details>
    

<details>

<summary>Q3. (공학) Forward Engineering과 Reverse Engineering의 차이는?</summary>
<br>
[🗣️ 핵심 요약]

**Forward(순공학)**는 모델(설계도)을 짜서 DB를 구축하는 것이고, **Reverse(역공학)**는 이미 있는 DB에서 설계도를 추출해내는 것입니다.
<br><br>
[📚 상세 설명]

- **Forward:** `ERD 설계 → DDL 생성 → DB 구축`. (신규 개발 시 사용)
- Reverse: DB 딕셔너리 스캔 → ERD 복원. (레거시 시스템 분석, 보안 감사, 문서화 작업 시 필수)
    
</details>
    

<details>

<summary>Q4. (JDBC 보안) 소스 코드에 DB ID/PW를 하드코딩하면 안 되는 이유는?</summary>
<br>
[🗣️ 핵심 요약]

소스 코드가 형상 관리 시스템(Git)이나 서버에 업로드될 때 **자격 증명(Credential)**이 평문으로 노출될 수 있기 때문입니다.
<br><br>
[📚 상세 설명]

- **보안 위협:** 공격자가 소스 코드를 입수하면 즉시 DB에 접속하여 데이터를 탈취하거나 파괴할 수 있습니다.
- **대응 방안:**
    
    1. **환경 변수(OS Environment Variable)** 사용.
    2. 권한이 제한된 **설정 파일(Properties)** 별도 관리.
    3. 암호화된 Vault 시스템 연동.
