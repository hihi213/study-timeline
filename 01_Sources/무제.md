# Week 2 — 냉장고(사용자) 핵심 CRUD 체크리스트

**A. 스코프 고정**

* [ ] 칸 라벨 규칙 확정: `R1/R2/R3/F1`
* [ ] 식별자 규칙 확정: `{칸라벨-###}` 예) `R1-101`
* [ ] 유일성 불변식 정의: `(compartment_id, item_number)`는 `status='ACTIVE' AND deleted_at IS NULL`에서만 유니크
* [ ] 소프트 삭제 정책 확정: `bundles.deleted_at`, `sub_items.deleted_at`
* [ ] 조회 범위 정의: 임박(D-0/1), 만료(D+N), 식별자 검색

**B. DB 마이그레이션(Flyway: `V2__cold_storage_core.sql`)**

* [ ] 테이블 생성: `floors`, `refrigerators`, `compartments`, `bundles`, `sub_items`
* [ ] ENUM 생성: `bundle_status('ACTIVE','REMOVED')`, `sub_item_status('STORED','CONSUMED')`
* [ ] 부분 유니크 인덱스 생성: `bundles(compartment_id,item_number)` WHERE `status='ACTIVE' AND deleted_at IS NULL`
* [ ] 쿼리 인덱스 생성: `bundles(owner_user_id)`, `bundles(expires_at)`
* [ ] 시드 데이터 삽입: `floors(2~5)` → 각 층 `refrigerators` 1대 → 각 냉장고 `compartments(R1,R2,R3,F1)`
* [ ] 마이그레이션 적용 확인(Flyway 로그/DB 스키마 확인)
* [ ] (선택) `pg_trgm` 확장 및 `bundles(name)` trigram 인덱스 생성

**C. 백엔드 — 엔티티/리포지토리/서비스**

* [ ] 엔티티 매핑: `Refrigerator`, `Compartment`, `Bundle`, `SubItem`
* [ ] 리포지토리 구현:

  * [ ] `BundleRepository.findMyBundles(userId, pageable)`
  * [ ] `searchByIdentifier(compartmentId,itemNumber)` 또는 `searchByLabelAndNumber(label, number, floorNo)`
* [ ] 서비스 규칙 구현:

  * [ ] 등록 시 (칸+번호) **ACTIVE 충돌 → 409 CONFLICT**
  * [ ] 수정 시 칸 이동(MOVE) 정책 구현(충돌 시 실패)
  * [ ] 삭제 시 `deleted_at` 설정(소프트 삭제)
  * [ ] 만료/임박 D-Day 계산(서버 일자 기준)
* [ ] N+1 방지: `@EntityGraph` 또는 `JOIN FETCH` 적용
* [ ] 페이징 응답: `Page<BundleListView>` 프로젝션 구성
* [ ] DTO 정의:

  * [ ] `BundleCreateReq { floorNo, label, itemNumber, name, memo, expiresAt, qty }`
  * [ ] `BundleListItem { id, label, itemNumber, name, expiresAt, dday, qtyTotal, qtyStored }`
* [ ] API 스켈레톤 구현:

  * [ ] `POST /api/items` (묶음+서브아이템 생성)
  * [ ] `GET /api/my-items?page=&size=&filter=expiring|expired`
  * [ ] `GET /api/items/search?identifier=R1-123&floor=3`
  * [ ] `PUT /api/items/{bundleId}` (수정/이동)
  * [ ] `DELETE /api/items/{bundleId}` (소프트 삭제)

**D. 프론트 — UI/흐름**

* [ ] 등록 다이얼로그: 칸 선택(R1\~R3/F1) + 번호(###) + 수량 stepper + 만료일 입력
* [ ] “내 물품” 목록: 페이징 + 임박 우선 정렬
* [ ] D-Day 배지 색상: rose(D+N), amber(D-0/1), emerald(정상)
* [ ] 식별자 검색(`R1-123`) → 결과 행 포커스/스크롤
* [ ] 번호 충돌 시 모달 표시(이번 스프린트는 **자동 새 번호 제공 안 함**)

**E. 유효성/권한**

# Week 3 — 검사 세션(동시 2인) 1차 체크리스트

**A. 스코프 고정**

* [ ] 범위 확정: 세션 **생성/참여/종료(또는 취소)** — 제출/벌점/알림은 후속 주차
* [ ] 동시 참여자 **최대 2명(슬롯 1,2)** 정책 확정
* [ ] **쓰기 차단(423 Locked)**: 진행중 세션의 **해당 층** 냉장고에 사용자 쓰기 금지
* [ ] 행동 타입 정의: `PASS / WARNING / DISCARD / NO_STICKER_DISCARD`(+ 사유/대상/검사자/시각)
* [ ] 검사 대상 기준: **만료품** + **마지막 검사일이후 추가/변경분**

**B. DB 마이그레이션(Flyway: `V3__inspection_core.sql`)**

* [ ] 테이블 생성: `inspection_sessions`, `inspection_participants`, `inspection_actions`
* [ ] 진행중 세션 단일 보장: `uq_floor_open_session` (WHERE `status='IN_PROGRESS'`)
* [ ] 참여자 슬롯 제약: `PRIMARY KEY(session_id, slot)` + `slot IN (1,2)`
* [ ] 중복 참여 방지: `uq_session_inspector` (`session_id, inspector_id`)
* [ ] 액션 조회 인덱스: `ix_actions_session`, `ix_actions_bundle`
* [ ] 변경 탐지 준비: `bundles.updated_at`(없으면 추가) + 인덱스
* [ ] 만료 탐지 인덱스 확인: `bundles(expires_at)`
* [ ] Flyway 적용 확인 및 롤백 불가 원칙 점검(Forward-only)

**C. 서비스 규칙 & 트랜잭션**

* [ ] 세션 생성: 동일 층 `IN_PROGRESS` 존재 시 **409** 매핑
* [ ] 참여자 추가: **원자적 트랜잭션**으로 빈 슬롯 배정, 중복 참여 차단
* [ ] 쓰기 차단 가드: 물품 등록/수정/삭제 전 **층 오픈 세션 존재 여부** 확인 → **423** (결과 5\~10초 캐시)
* [ ] 행동 기록: 검사자별 액션을 독립적으로 저장(원자성 보장)
* [ ] 상태 전이: `END`/`CANCEL` 시 `ended_at` 세팅
* [ ] 동시성 방어는 **DB 유니크/PK**를 최종 방어선으로 활용

**D. API 스펙**

* [ ] `POST /api/inspections/sessions` (req: `{ floorNo }`, res: `{ sessionId, floorNo, startedAt, status }`, 권한 `INSPECTOR`)
* [ ] `POST /api/inspections/sessions/{id}/participants` (req: `{ inspectorId?, preferredSlot? }`, res: 참가자 목록, 권한 `INSPECTOR`)
* [ ] `POST /api/inspections/sessions/{id}/actions` (req: `{ bundleId|null, tempLabel|null, action, reason }`, 권한 `INSPECTOR`)
* [ ] `PATCH /api/inspections/sessions/{id}/end` (권한: 생성자 또는 참여자)
* [ ] `PATCH /api/inspections/sessions/{id}/cancel` (권한: 생성자)
* [ ] `GET /api/inspections/sessions/{id}/candidates?filter=expired|changed`
* [ ] Swagger 보안 스키마(JWT) 연결 및 요청/응답 스키마 문서화

**E. 검사 대상 조회/필터 구현**

* [ ] 만료품: `expires_at < CURRENT_DATE`
* [ ] 변경분: `bundles.updated_at >= session.started_at OR bundles.created_at >= session.started_at`
* [ ] 후보 응답 필드: `owner, label, itemNumber, name, expiresAt, dday, lastUpdated`

**F. 프론트(층별장 UI v1)**

* [ ] 세션 생성 → 참여/퇴장 → 액션 기록 플로우 화면
