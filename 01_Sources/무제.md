## 📨 HTTP 요청 메시지 구조 상세 정리

HTTP 요청은 서버에 "무엇을, 어떻게, 어떤 데이터를 가지고" 처리해달라고 요청하는 구조화된 문서입니다.

### 1️⃣ 두 번째 영역: 헤더 (Headers)

헤더는 메시지 전송과 본문 처리에 필요한 **부가 정보(Metadata)**를 담고 있습니다.

- **Host (필수):** 요청이 전송되는 **도메인명** 또는 **IP 주소**.
    - **핵심:** HTTP/1.1에서 유일한 **필수 헤더**입니다. 하나의 IP 주소에서 여러 도메인을 운영하는 '가상 호스팅'을 가능하게 합니다.
- **Content-Type:** 바디(Body)에 담긴 **데이터의 형식** 명시.
    - 예: `application/json` (JSON 데이터), `text/html` (HTML 문서).
- **Content-Length (핵심 추가):** 바디 데이터의 **전체 크기(Byte 단위)**.
    - **주의:** 사용자가 적어주신 "서버가 읽을 길이를 알려주는 것"은 `Content-Type`이 아니라 이 헤더의 역할입니다. 서버는 이 값을 보고 바디 데이터를 어디까지 읽을지 결정합니다.
- **Accept (핵심 추가):** 서버로부터 **응답받기를 원하는 데이터 형식** 명시.
    - `Content-Type`은 내가 보내는 형식, `Accept`는 내가 받고 싶은 형식입니다.
- **Authorization:** 클라이언트의 **인증 정보**.
    - 주로 `Bearer <Token>` 형식을 사용하여 로그인 여부를 증명합니다.
- **User-Agent:** 요청을 보낸 **클라이언트 소프트웨어(브라우저, OS 등) 정보**.
    - 통계 수집이나 브라우저별 최적화된 화면을 제공할 때 사용합니다.
        

---

### 2️⃣ 세 번째 영역: 공백 줄 (Empty Line)

- **역할:** 헤더의 끝과 바디의 시작을 알리는 **유일한 구분자**입니다.
- **중요성:** HTTP 명세상 이 줄이 누락되면 서버는 바디 데이터를 헤더의 연장선으로 인식하여 `400 Bad Request` 에러를 발생시킵니다.
    

---

### 3️⃣ 네 번째 영역: 바디 (Body)

서버에 실제로 전달하고자 하는 **핵심 데이터(Payload)**가 담기는 공간입니다.

- **데이터 형식:** 주로 **JSON** 형식을 사용하며, 헤더의 `Content-Type`과 일치해야 합니다.
- **메서드별 특징:**
    - **POST / PUT / PATCH:** 자원을 생성하거나 수정할 때 사용하므로 **바디가 반드시 존재**합니다.
    - **GET / DELETE:** 자원을 조회하거나 삭제할 때 사용하며, 관례상 **바디를 사용하지 않고** URL의 경로(Path)나 쿼리 스트링(Query String)을 통해 데이터를 전달합니다.
        

---

### 💡 요약: 헤더와 바디의 유기적 관계

> 클라이언트가 **Body**에 JSON 데이터를 담아 보낼 때는, 반드시 헤더에 **Content-Type**(`application/json`)과 **Content-Length**(데이터 크기)를 명시해야 서버가 데이터를 안전하게 꺼내 쓸 수 있습니다.
