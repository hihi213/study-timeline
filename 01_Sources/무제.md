## Topic 1. 데이터 마스킹 프로시저 구현

### 1) 📌 One-Liner (면접 즉답)

- 애플리케이션 레벨의 암호화 대신, **DB 프로시저 내부에서 부분 문자열 처리(`SUBSTR`)를 수행하여 중요 정보를 마스킹**한 후 반환할 수 있습니다. `(Data Masking)`
    

### 2) 📘 Theory & Policy (개념 & 정책)

- **정의**: 데이터 마스킹(Data Masking)이란 원본 데이터를 보여주지 않고, 일부를 가리거나 변형하여 출력하는 기법입니다.
- **Security Boundary**: **Data Presentation Layer**. DB에 저장된 실제 값은 그대로두되, 사용자에게 전달되는 시점에 정보를 숨깁니다.
- **Policy**: "개인정보(이름, 주민등록번호 등)는 권한이 없는 사용자에게 평문으로 노출되어서는 안 된다."
    

### 3) 🛡️ Security Audit (취약점 및 권장사항)

- **Attack Surface**: `SELECT` 권한이 있는 사용자가 테이블을 직접 조회할 경우 마스킹되지 않은 원본 데이터가 노출됨.
- **Best Practice**:
    - 테이블 직접 접근 권한(`SELECT`)을 회수.
    - 마스킹 로직이 포함된 **프로시저나 뷰(View)에만 실행 권한(`EXECUTE`)** 부여.
        

### 4) 💻 SQL Workflow (실습 로그)

(Scenario: `userTBL`의 이름을 첫 글자만 남기고 나머지는 `00`(또는 `**`)으로 마스킹하여 출력하는 프로시저 작성)

SQL

```Java
-- 1. [Setup] 실습용 테이블 및 데이터 생성 (카카오톡 공유 코드)
CREATE TABLE userTBL (
    userID CHAR(8) NOT NULL PRIMARY KEY,
    userName NVARCHAR2(10) NOT NULL,
    birthYear NUMBER(4) NOT NULL,
    addr NCHAR(2) NOT NULL,
    mobile1 CHAR(3), mobile2 CHAR(8),
    height NUMBER(3), mDate DATE
);

-- 데이터 삽입 (생략: 입력된 10건 INSERT 문 수행)
COMMIT;

-- 2. [Implementation] 마스킹 프로시저 생성
CREATE OR REPLACE PROCEDURE print_user_masked (
    p_id IN userTBL.userID%TYPE
) IS
    v_name userTBL.userName%TYPE;
    v_birth userTBL.birthYear%TYPE;
BEGIN
    -- ID로 조회하여 변수에 저장
    SELECT userName, birthYear 
      INTO v_name, v_birth 
      FROM userTBL 
     WHERE userID = p_id;
    
    -- 마스킹 처리 및 출력 (예: 이승기 -> 이00)
    DBMS_OUTPUT.PUT_LINE('이름: ' || SUBSTR(v_name, 1, 1) || '00');
    DBMS_OUTPUT.PUT_LINE('생년: ' || v_birth);
END;
/
```

- **Verification (검증)**
    

SQL

```Java
-- 출력 설정 활성화
SET SERVEROUTPUT ON;

-- 프로시저 실행 (JYP 조회)
EXEC print_user_masked('JYP');
-- 결과: 이름: 조00 / 생년: 1950 (확인 완료)
```

### 5) 💡 Interview Shot (신입 면접 대비)

> [!faq]Q. DB에서 %TYPE을 사용하는 이유는 무엇인가요?

> 🗣️ 핵심 답변
>
> 테이블 컬럼의 데이터 타입이 변경되더라도, PL/SQL 변수의 타입도 자동으로 동기화되어 유지보수성과 안정성을 높이기 위함입니다.
>
> **📚 꼬리질문 대비**
>
> - **Example**: `userTBL.userID%TYPE`으로 선언하면, 추후 `userID`가 `CHAR(8)`에서 `VARCHAR2(20)`으로 바뀌어도 코드를 수정할 필요가 없습니다.

## Topic 2. PL/SQL 소스 코드 난독화 (Wrapping)

### 1) 📌 One-Liner (면접 즉답)

- **`DBMS_DDL.CREATE_WRAPPED`** 패키지를 사용하면 PL/SQL 소스 코드를 난독화하여, `USER_SOURCE` 딕셔너리 조회 시 **로직이 보이지 않게 보호**할 수 있습니다. `(Source Code Security)`
    

### 2) 📘 Theory & Policy (개념 & 정책)

- **정의**: Wrapping(래핑)은 PL/SQL 소스 코드를 바이너리 형태나 암호화된 텍스트로 변환하여 저장하는 기술입니다.
- **Security Boundary**: **Intellectual Property & Logic Security**. DB 관리자(DBA)나 개발자가 소스 코드를 조회해도 내부 로직(특히 암호화 키, 민감한 비즈니스 로직)을 볼 수 없게 합니다.
- **Architecture**: 일반적인 컴파일 시 `Data Dictionary`(`USER_SOURCE`)에 평문 텍스트가 저장되지만, Wrapping 시 난독화된 16진수 문자열 형태로 저장됩니다.
    

### 3) 🛡️ Security Audit (취약점 및 권장사항)

- **Attack Surface**: 프로시저 내부에 하드코딩된 **비밀번호, 암호화 키, 혹은 취약한 로직**이 평문으로 노출될 위험.
- **Best Practice**: 민감한 로직이 포함된 패키지나 프로시저는 반드시 `WRAP` 유틸리티나 `DBMS_DDL.CREATE_WRAPPED`를 통해 배포.
    

### 4) 💻 SQL Workflow (실습 로그)

(Scenario: 앞서 만든 프로시저의 소스 코드를 `USER_SOURCE`에서 조회해도 볼 수 없도록 난독화하여 재생성)

SQL

```Java
-- 1. [Pre-check] 난독화 전 소스 확인
SELECT text FROM user_source WHERE name = 'PRINT_USER_MASKED';
-- 결과: CREATE OR REPLACE PROCEDURE … (평문 노출됨)

-- 2. [Implementation] DBMS_DDL.CREATE_WRAPPED를 이용한 난독화
-- (강의에서는 문자열 연결 연산자 || 를 사용하여 DDL 문장을 조립함)
DECLARE
    v_ddl VARCHAR2(32767);
BEGIN
    v_ddl := 'CREATE OR REPLACE PROCEDURE print_user_encrypted ( ' ||
             '   p_id IN userTBL.userID%TYPE ) IS ' ||
             '   v_name userTBL.userName%TYPE; ' ||
             '   v_birth userTBL.birthYear%TYPE; ' ||
             'BEGIN ' ||
             '   SELECT userName, birthYear INTO v_name, v_birth ' ||
             '     FROM userTBL WHERE userID = p_id; ' ||
             '   DBMS_OUTPUT.PUT_LINE(''Secret Name: '' || SUBSTR(v_name, 1, 1) || ''**''); ' ||
             'END;';
             
    -- 이 함수가 DDL을 실행함과 동시에 소스를 암호화하여 저장함
    SYS.DBMS_DDL.CREATE_WRAPPED(v_ddl); 
END;
/
```

- **Verification (검증)**
    

SQL

```Java
-- 1. 프로시저 실행 확인 (동작은 정상이어야 함)
EXEC print_user_encrypted('LSG');
-- 결과: Secret Name: 이** (정상 동작)

-- 2. 소스 코드 노출 여부 확인 (Data Dictionary)
SELECT text 
  FROM user_source 
 WHERE name = 'PRINT_USER_ENCRYPTED';
```

- 🚨 **Result**: `TEXT` 컬럼의 내용이 `CREATE OR REPLACE PROCEDURE… wrapped … abcd…`와 같이 **알 수 없는 난독화 문자열**로 출력됨을 확인.

### 🧩 Residual Knowledge (자투리 지식)

- **(문법/팁) 슬래시(`/`)의 의미**: SQL Developer나 SQL*Plus 워크시트에서 PL/SQL 블록(BEGIN~END) 작성을 마쳤으니 **컴파일(실행)하라**는 종료 신호입니다.
- **(보안)**: 관리자(`SYS`, `SYSTEM`)조차도 Wrapped 된 프로시저의 원본 소스는 복호화하여 볼 수 없습니다. (소스 원본 파일 관리가 중요함).
