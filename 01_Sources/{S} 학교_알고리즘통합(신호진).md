### **개념 콘솔리데이션 (Consolidation)**

* `자료구조 (Data Structure)` = 데이터를 컴퓨터 시스템에 효율적으로 저장하고 관리하는 방법.
* `포인터 (Pointer)` = 다른 변수의 **메모리 주소 값**을 저장하기 위한 변수.
* `배열 (Array)` = 동일 자료형의 데이터를 **연속된 메모리**에 저장하는 정적 자료구조.
* `연결 리스트 (Linked List)` = 데이터와 포인터를 담은 **노드(Node)**를 동적으로 연결한 비연속적 자료구조.
* `자기 참조 구조체 (Self-Referential Structure)` = 구조체 내부에 자기 자신 타입의 포인터를 멤버로 포함하여, 연결 리스트나 트리를 구현하는 핵심 요소.
* `동적 메모리 할당 (Dynamic Memory Allocation)` = `malloc`, `free`를 통해 프로그램 실행 중 **힙(Heap) 영역**의 메모리를 직접 관리하는 기법.
* `스택 (Stack)` = **LIFO(Last-In, First-Out)** 원칙을 따르는 자료구조.
* `큐 (Queue)` = **FIFO(First-In, First-Out)** 원칙을 따르는 자료구조.
* `힙 (Heap)` = **우선순위 큐(Priority Queue)** 구현을 위한 완전 이진 트리 기반의 자료구조.
* `void 포인터 (void*)` = 특정 타입에 구애받지 않는 범용 주소 저장소. `malloc`의 반환 타입.

**개념 연결 맵:**
하드웨어(CPU/메모리) → C언어(자료형/주소) → **포인터(주소 저장 변수)** → 기본 자료구조(배열 vs. **연결 리스트**) → 자기 참조 구조체(연결 리스트 구현 기반) → 추상 자료형(스택/큐/힙) → **알고리즘(효율적 문제 해결)**

### **오해·에러 로그**

* **증상**: `arr++` 코드가 컴파일되지 않는다.
    * **원인**: 배열의 이름은 주소를 변경할 수 없는 **상수 포인터**이다.
    * **해결**: `arr`이 아닌 별도의 포인터 변수 `ptr`에 주소를 복사한 뒤 `ptr++`를 사용해야 한다. `[3, P09]`
* **증상**: `register` 변수의 주소를 포인터에 저장하려 하면 컴파일 오류가 발생한다.
    * **원인**: `register` 변수는 메모리가 아닌 CPU 레지스터에 할당될 수 있으며, 레지스터는 메모리 주소가 없다.
    * **해결**: `register` 키워드를 제거하여 변수를 일반 메모리에 할당해야 한다. `[2, P04]`
* **증상**: `sizeof(struct card)`는 408바이트인데, `sizeof(struct card*)`는 4바이트가 나온다.
    * **원인**: 전자는 구조체 전체의 크기, 후자는 **주소 값**을 저장하는 포인터 변수 자체의 크기이다.
    * **해결**: 포인터의 크기는 가리키는 대상의 크기와 무관하며, 시스템의 주소 체계(32bit/64bit)에 따라 결정됨을 이해해야 한다. `[3, P05]`
* **증상**: "평균 2분에 한 명 도착, 처리 시간 평균 1분"일 때 대기열이 없을 것이라 예측했지만, 시뮬레이션 시 무한히 길어진다.
    * **원인**: **'평균'**은 '일정함'을 의미하지 않는다. 순간적인 요청 폭주가 시스템 처리 용량을 초과할 수 있다.
    * **해결**: 평균값 대신 포아송 분포 등 실제 현상에 가까운 확률 모델을 사용하여 시뮬레이션해야 한다. `[1, P12]`
* **증상**: `*ptr++`와 `(*ptr)++`의 결과가 다르다.
    * **원인**: 연산자 우선순위의 차이. 전자는 포인터의 주소를 증가시키고, 후자는 포인터가 가리키는 값을 증가시킨다.
    * **해결**: 괄호를 사용하여 연산의 순서를 명확히 하거나, 연산자 우선순위 표를 참고하여 의도에 맞게 코드를 작성한다. `[3, P08]`

### **Carry-over (다음 수업 준비)**

* **미해결 질문 및 검증 과제**
    * 교수님께서 매년 출제하지만 아무도 맞히지 못했다는 '포인터 옮기기' 문제는 정확히 어떤 것인가?
    * 배열 기반 큐의 `dequeue` 성능을 `O(1)`로 개선하는 **원형 큐(Circular Queue)**를 직접 구현하고, 연결 리스트 큐와 성능을 비교 검증할 필요가 있다.

* **핵심 복습 과제**
    1.  `*ptr++`, `(*ptr)++`, `++*ptr`, `*++ptr`의 차이점을 코드 예시와 함께 설명하기.
    2.  '데이터 검색'과 '중간 삽입/삭제'가 빈번할 때 배열과 연결 리스트 중 어떤 것이 유리한지 그 이유를 시간 복잡도와 함께 설명하기.
    3.  `malloc`이 `void*`를 반환하는 이유와, 이를 `(int*)` 등으로 명시적 형 변환해야 하는 이유 설명하기.

* **다음 수업 예고 질문**
