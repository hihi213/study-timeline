### 3) 📚 핵심 개념 3개
1.  **배열의 메모리 모델 (Array Memory Model)**
    * 동일한 타입의 원소들을 물리적으로 연속된 메모리 공간에 저장함을 보장하는 정적 자료구조.
2.  **포인터와 주소 연산 (Pointers and Address Arithmetic)**
    * 메모리 주소를 다루는 도구로, 배열의 연속된 구조 위에서 타입의 크기만큼 주소를 이동하며 모든 원소를 효율적으로 탐색하게 해준다.
3.  **메모리 관리와 안정성 (Memory Management and Safety)**
    * C언어는 경계 검사, 동적 할당 해제(`free`), 포인터 초기화 등 메모리 관련 책임을 프로그래머에게 위임하며, 이를 소홀히 할 경우 심각한 시스템 오류가 발생할 수 있다.
* **개념 연결맵**:
    **배열의 메모리 모델**은 데이터의 물리적 연속성을 보장한다. → 이 연속성 덕분에 **포인터와 주소 연산**을 통해 $O(1)$의 효율적인 원소 접근이 가능하다. → 그러나 C언어는 **메모리 관리와 안정성**(경계 검사 부재, 수동 해제)을 프로그래머에게 위임하므로, 포인터를 잘못 사용하면 시스템 전체에 영향을 미칠 수 있다.

## **2025-09-18 — 최종(1~3교시 통합)**

### 1. 하루 TL;DR (5줄)

사용자 정의 자료형인 **구조체(struct)**의 기본 개념과 함수 호출 방식을 학습했습니다. 이를 바탕으로 **배열 기반 리스트**와 **연결 리스트**의 구현상 장단점을 비교 분석했습니다. 배열 리스트는 구현이 간단하나, 삽입/삭제 시 **데이터 이동 오버헤드**와 **고정된 크기**가 단점입니다. 연결 리스트는 **동적 할당**으로 크기가 유연하고 삽입/삭제가 효율적이지만, **포인터 구현**이 복잡하고 **메모리 누수** 위험이 있습니다. 마지막으로, 연결 리스트의 핵심인 **포인터 조작(삽입/삭제 순서)**과 **세 가지 삽입 경우(빈 리스트, 맨 앞, 중간)** 처리 로직을 집중적으로 다루었습니다.

---

### 2. 🔥 필수 질문 Top-5

1. **배열 기반 리스트와 연결 리스트의 가장 큰 차이점은 무엇이며, 각각 어떤 상황에 더 유리한가요?**
    
    - **핵심**: 메모리 할당 방식(정적 vs 동적)과 그로 인한 접근/삽입/삭제 연산의 시간 복잡도 차이를 이해하는 것이 중요. 조회가 잦으면 배열, 수정이 잦으면 연결 리스트가 유리.
        
2. **연결 리스트에 새 노드를 삽입할 때, 포인터 할당 순서가 중요한 이유는 무엇이며, 올바른 순서는 무엇인가요?**
    
    - **핵심**: 잘못된 순서는 리스트의 뒷부분에 대한 주소(연결)를 유실시켜 데이터를 잃게 만듦. `새 노드->다음` 연결을 먼저 확보한 후, `이전 노드->새 노드` 연결을 해야 함.
        
3. **연결 리스트에서 발생할 수 있는 '메모리 누수(memory leak)'란 무엇이며, 왜 반드시 피해야 하나요?**
    
    - **핵심**: `malloc`으로 할당하고 `free`로 해제하지 않은 메모리는 프로그램이 끝날 때까지 사용할 수 없는 공간으로 남아, 시스템 자원을 고갈시키는 치명적인 버그임.
        
4. **연결 리스트의 삽입 함수를 구현할 때, '빈 리스트', '맨 앞 삽입', '중간 삽입'의 세 가지 경우를 나누어 처리해야 하는 이유는 무엇인가요?**
    
    - **핵심**: `헤드 포인터(head pointer)`의 값을 직접 변경해야 하는지 여부가 달라지기 때문. 맨 앞/빈 리스트 삽입은 헤드 포인터를 갱신해야 하는 예외 케이스(edge case)임.
        
5. **단일 연결 리스트에서 특정 노드를 삭제하기 위해 반드시 알아야 하는 정보는 무엇이며, 이 정보는 어느 노드가 가지고 있나요?**
    
    - **핵심**: 삭제할 노드의 '이전 노드(선행 노드)'에 대한 포인터가 반드시 필요함. 단방향 구조상 이전 노드만이 삭제할 노드의 주소를 가지고 있기 때문.

### 3. 📚 핵심 개념 3개

- **구조체(Struct)**: 타입이 다른 여러 변수를 하나의 논리적 단위로 묶는 사용자 정의 자료형.
- **배열 기반 리스트**: 물리적으로 연속된 메모리(배열)를 사용해 리스트를 구현하는 정적 방식.
- **연결 리스트**: 자기 참조 구조체(노드)를 포인터로 연결하여 리스트를 구현하는 동적 방식.

[개념 연결맵]

구조체(Struct) → (활용) → 배열 기반 리스트 (정적, O(1) 접근) VS 연결 리스트 (동적, O(1) 삽입/삭제)

### 4. 💻 주요 실습 요약

    - **단계요약**: 1) `항(term)`과 `다항식(polynomial)` 구조체 정의 → 2) 두 다항식의 항을 지수 기준으로 비교하는 반복문 작성 → 3) 경우에 따라(A>B, A<B, A\==B) 결과 배열에 항 추가/계수 합산 → 4) 남은 항들을 결과에 복사.
- **[S2] 배열 기반 리스트 ADT 구현** — 목적: 정적 배열을 사용하여 리스트의 기본 연산(삽입, 삭제, 조회 등)을 직접 코딩하여 동작 원리를 이해.
    - **단계요약**: 1) `배열`과 `length`를 갖는 구조체 정의 → 2) `is_full`, `is_empty` 함수 구현 → 3) `add` 함수(뒤에서부터 이동) 구현 → 4) `delete` 함수(앞에서부터 덮어쓰기) 구현.
- **[S3] 단일 연결 리스트 역순(Reverse) 알고리즘 분석** — 목적: 세 개의 포인터를 사용하여 리스트의 링크를 역방향으로 바꾸는 과정을 단계별로 추적하고 이해.
    - **단계요약**: 1) `p`, `q`, `r` 포인터 초기 상태 설정 → 2) 반복문 내에서 각 포인터의 값과 노드 `link`의 변화를 추적 → 3) 포인터 재설정 로직이 어떻게 역연결을 만드는지 설명 → 4) 최종 `head`가 될 변수 확인.

## **2025-10-02 — 최종(1~3교시 통합)**

### 하루 TL;DR (5줄)

단순 연결 리스트의 탐색 및 삽입/삭제 비효율성을 원형 및 이중 연결 리스트로 해결하는 방법을 학습했습니다. 특히 이중 연결 리스트의 포인터 재설정 순서와 같은 핵심 구현 원리를 파악하고, 헤드 노드를 통해 코드의 복잡성을 낮추는 기법을 확인했습니다. 이후 선형 구조의 한계를 넘어 계층적 데이터를 다루는 비선형 구조로 전환하여, 트리의 기본 개념과 용어를 익혔습니다. 구현이 용이한 이진 트리에 집중하며, 이를 배열과 연결 리스트로 구현하는 두 방법의 원리와 장단점을 비교 분석하며 하루 학습을 마쳤습니다.

### 🔥 필수 질문 Top-5

1. **이중 연결 리스트 삽입 시 포인터 연결 순서가 왜 중요하며, 특히 주의해야 할 점은 무엇인가요?**
    
    - 기존 노드의 포인터 정보를 먼저 변경하면 원래 연결된 노드의 주소를 잃기 때문입니다. 특히 `before->rlink = new_node`와 같이 기존 노드의 포인터를 덮어쓰는 작업은 가장 마지막에 수행해야 합니다.
        
2. **구현이 복잡한 일반 트리(General Tree) 대신, 이진 트리를 집중적으로 배우는 이유는 무엇인가요?**
    
    - 노드마다 자식 수가 다른 일반 트리는 구조체 표준화가 어렵습니다. 자식 노드를 최대 2개로 제한하는 이진 트리는 구조를 고정할 수 있어 구현과 연산 알고리즘 학습이 매우 용이하기 때문입니다.
        
3. **이중 연결 리스트 구현 시 헤드 노드(더미 노드)를 사용하는 이유는 무엇인가요?**
    
    - 리스트가 비어있을 때 발생하는 NULL 포인터 예외 등 경계 조건(edge case) 처리를 없애기 위함입니다. 헤드 노드가 항상 존재함으로써, 모든 삽입/삭제 연산을 일반적인 경우로 통일시켜 코드의 복잡도를 낮춥니다.
        
4. **이중 트리를 구현하는 두 대표적인 방법인 배열과 연결 리스트의 장단점을 비교하시오.**
    
    - **배열**은 완전 트리일 때 메모리 효율이 높고 부모/자식 접근이 `O(1)`로 빠르지만, 크기 고정과 메모리 낭비가 단점입니다. **연결 리스트**는 크기가 유연하고 삽입/삭제가 용이하지만, 포인터로 인한 추가 메모리가 들고 특정 노드 접근이 `O(n)` 또는 `O(log n)`입니다.
        
5. **이진 트리를 배열로 구현할 때, 특정 노드 인덱스 `i`로 부모와 자식 노드를 찾는 방법은 무엇인가요?**
    
    - 루트를 인덱스 1에 저장했을 때, 부모는 `i / 2`, 왼쪽 자식은 `2 * i`, 오른쪽 자식은 `2 * i + 1`의 산술 연산만으로 빠르게 찾을 수 있습니다.

### 📚 핵심 개념 3개

- **이중 연결 리스트**: 각 노드가 선행(prev) 및 후속(next) 노드 포인터를 모두 가져 양방향 탐색이 가능한 리스트.
- **헤드 노드 (더미 노드)**: 데이터 없이 리스트의 시작점 역할만 하여, 빈 리스트 등 경계 조건 처리를 단순화하는 특수 노드.
- **이진 트리**: 각 노드의 자식이 최대 2개(left, right)로 제한되어 구조가 표준화된 계층형 자료구조.
