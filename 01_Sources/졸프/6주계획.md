# DormMate 최종 MVP 범위 정리 (v1.0)

**개발 기간**: 6주 (126시간) | **개발 인원**: 1인 | **목표**: 냉장고 관리 핵심 기능 검증

## MVP 포함 기능 ✅

### 1. 인증 및 사용자 관리 (Week 1-2: 42시간)

**회원가입 및 로그인**
- 호실 번호, 개인 번호, 이메일, 비밀번호 입력
- JWT 토큰 발급 (7일 유효)
- Spring Security 기반 인증

**역할 기반 접근 제어 (RBAC)**
- RESIDENT: 기숙사생 (자기 물품만 접근)
- INSPECTOR: 층별장 (검사 권한)
- ADMIN: 관리자 (전체 제어)

**프로필 조회**
- 내 정보, 호실, 역할 확인
- 로그인 시 자동 호실-칸 매핑

### 2. 냉장고 물품 관리 (Week 3-4: 42시간)

**묶음 등록 시스템** ✅
- 단일 품목도 묶음(Bundle) 1개로 처리
- 데이터 모델: `FridgeBundle` (묶음) + `BundleItem` (개별 품목)
- 수량 1에서 증가 → 동적 폼 배열 생성 (React Hook Form useFieldArray)
- 입력 항목: 대표 품목명, 대표 메모(선택), 품목별 개별유통기한,
- JPA Cascade로 자동 일괄 저장

**식별번호 자동 발급** ✅
- 묶음당 1개 식별번호 발급 (개별 품목 X)
- 형식: {슬롯번호}{라벨번호 3자리} (예: 1005, 4123)
- 슬롯별 사용 가능한 번호 자동 조회 및 할당
- REMOVED 상태 번호 자동 재사용

**물품 조회**
- 내 물품 목록 (최신순 정렬)
- 필터: 전체/임박(3일 이내)/만료
- 검색: 품목명 부분 일치, 식별번호 정확 검색

**물품 수정 및 삭제**
- 품목명, 유통기한, 메모 수정가능
- 본인 물품만 접근 (RBAC 검증)
- 소프트 삭제 (상태 REMOVED)

**칸 배정 로직**
- 호실 번호 기반 자동 배정
- 냉장 칸 3개: 8호실씩 배분 (slot 1-3)
- 냉동 칸 1개: 전체 24호실 공용 (slot 4)

### 3. 검사 시스템 (Week 5: 17시간)

**동시 2인 검사** ✅
- 칸 단위 검사 세션 생성
- 최대 2명 검사자 자동 합류 (동일 세션 ID 공유)
- SSE(Server-Sent Events)로 실시간 상태 동기화
- ConcurrentHashMap 메모리 세션 관리 (Redis 불필요)
- 검사 중 해당 칸 물품 수정 금지 (락 메커니즘)

**검사 조치 처리**
- ⚠️ 경고: 정보 불일치(INFO_MISMATCH), 보관 불량(STORAGE_ISSUE)
- 🗑️ 폐기: 유통기한 만료(EXPIRED), 미등록 물품(UNREGISTERED)
- 조치 사유 메모 입력 (선택)
- 실시간 UI 업데이트 (다른 검사자에게 전파)

**검사 결과 제출**
- 최종 제출 시에 DB 일괄 저장 (중간 상태는 메모리만)
- 통계 자동 집계 (경고/폐기 건수)
- 조치받은 사용자에게 알림 자동 생성
- 검사 이력 저장 (검사자, 일시, 조치 내역)

### 4. 알림 시스템 (Week 5: 4시간)

**유통기한 알림**
- 매일 09:00 KST 배치 실행 (Spring @Scheduled)
- 3일 이내 임박 물품알림
- 사용자별 알림 생성 (인앱 전용)
- 하루 1회 제한 (묶음 알림)

**검사 결과 알림**
- 검사 제출 즉시 생성
- 경고/폐기 조치 물품 보유 사용자에게만 전달
- 알림 내용: 경고 물품 N개, 조치물품 N개

**알림 조회 및 읽음 처리**
- 미읽음 알림 배지 (최대 9+ 표시)
- 냉장고 메인 진입 시 자동 읽음 처리
- 24시간 자동 만료

### 5. 관리자 기능 (Week 6: 10시간)

**자원 관리**
- 냉장고 유닛 조회 (층별 4칸 구조)
- 호실별 칸 배분 현황 확인
- 층별장 임명/해제 (INSPECTOR 역할 부여)

**전체 조회**
- 모든 물품 조회 (층/칸/호실 필터)
- 검사 이력 조회 (검사자, 일시, 통계)
- 사용자 목록 및 역할 관리

### 6. 배포 및 인프라 (Week 6: 11시간)

**호스팅**
- AWS Lightsail 단일 인스턴스
- Nginx 리버스 프록시 + HTTPS (Let's Encrypt)
- PostgreSQL 데이터베이스

**보안**
- CORS 화이트리스트 설정
- JWT 인증 강제
- RBAC 엔드포인트 보호

- Flyway (마이그레이션)

- SSE (Server-Sent Events)
- @Scheduled (배치 스케줄링)

- TanStack Query (데이터 페칭)

- React Hook Form + useFieldArray
- EventSource API (SSE 클라이언트)
### 인프라
- AWS Lightsail (단일 인스턴스)
- Nginx (HTTPS, CORS)
- Let's Encrypt (SSL)

## 핵심 차별화 요소

**1. 묶음 관리의 단순화**
- 단일/묶음 구분 없이 모두 Bundle로 통일
- 묶음당 스티커 1장으로 관리 효율성 극대화

**2. 실시간 협업 검사**
- 층별장 2명이 동시 검사 가능
- 중복 조치 방지로 검사 시간 단축

**3. 자동화된 운영**
- 식별번호 자동 발급
- 유통기한 알림 자동 배치
- 호실-칸 매핑 자동화

## 성공 지표 (MVP 검증 기준)

**기능 검증**
- 물품 등록 완료율 > 95%
- 검사 세션 오류율 < 5%
- 알림 발송 정확도 > 98%

**사용성 검증**
- 묶음 등록 평균 시간 < 2분
- 2인 검사 평균 소요 시간 < 단독 검사의 60%
- 사용자 만족도 > 4.0/5.0

**기술 검증**
- API 응답 시간 < 500ms (95 percentile)
- SSE 연결 안정성 > 99%
- 동시 접속 30명 처리 가능

이 MVP 범위는 **냉장고 핵심 가치(물품 관리 + 검사 + 알림)**를 6주 내 검증 가능한 수준으로 최적화하였으며, 실제 기숙사 운영 문제를 해결하면서 백엔드 개발자 포트폴리오로 활용 가능한 완성도를 목표로 합니다.

# DormMate MVP 유저 및 층별장 시나리오

## 1. 기숙사생(유저) 시나리오

### 회원가입 및 로그인
- 기숙사웹사이트 접속
- 회원가입: 호실 번호(예: 201), 개인 번호(1~3), 이메일, 비밀번호 입력
- 인증 후 로그인 성공, JWT 토큰 발급 및 세션 시작

### 냉장고 물품 등록(묶음)
- "물품 등록" 클릭 후 대표이름, 대표메모 입력후 수량 1에서 증가 (예: 3개)->세부품목 폼
- 각 품목 정보 입력 후 제출 버튼 클릭
- 서버에서 묶음으로 등록, 스티커 코드(식별번호) 자동 발급
- 스티커 출력 화면에서 발급번호 확인 및 스티커 부착
- 내 물품 목록에서 등록한 품목과 식별번호 확인

### 냉장고 물품 조회 및 관리
- 내 물품 목록 표시 (최신순 정렬)
- 유통기한 기준 필터 적용(임박, 만료 등)
- 특정 품목명 또는 식별번호 정확 검색
- 품목 수정 (명칭, 유통기한, 메모) 또는 삭제(상태 REMOVED)
- 이전 냉장고 점검이후 이름, 유통기한 수정시 해당 개별 품목은 다음 검사시 상단에 표시됨

### 알림 수신 및 확인
- 매일 오전 9시 유통기한 임박 알림 수신
- 검사 결과(경고/폐기) 알림 확인 후 상세내용 확인 가능
- 알림 내역 탭에서 읽음 처리 및 히스토리 조회

***

## 2. 층별장(INSPECTOR) 시나리오

### 로그인 및 검사 준비
- 층별장 계정으로 로그인
- 배정된 층/칸 냉장고 접속
- 검사 세션 시작 (칸 단위)
- 서버에 검사 세션 생성, 1차 검사자로 등록
- 다른 검사자(2인째)가 같은칸 검사시작을 누를경우 동일 칸 검사 시 세션 합류

### 검사 중 물품 확인 및 조치
- 검사 가능한 칸 내의 모든 물품 조회
- 물품별 상태 확인 (미검사, 검사 중, 검사 완료)
- 경고 조치: 정보 불일치, 보관 불량, DB엔 등록되었지만 스티커 없는경우
- 폐기 조치: 유통기한 만료, 미등록 물품 즉시 폐기 등록
	- 이때 미등록 물품은 DB에 등록하지 않은 물품이므로 검사자가 품목이름을 입력해 폐기 등록을한다
- 검사 중 해당 칸 물품의 일반 수정/등록 불가 (락 적용)

### 동기화 및 협업
- SSE 실시간 상태 동기화로 다른 검사자의 조치 즉시 반영
- UI ‘검사 완료’ 탭에서 본인 및 타 검사자 조치 분리 표시
- 중복 검사 방지, 진행 상황 실시간 파악

### 검사 결과 제출 및 종료
- 모든 물품 검사 완료 시 최종 제출 버튼 활성화
- 검사 결과 서버 전송, DB에 최종 반영
- 조치받은 사용자에게 알림 자동 발송
- 검사 세션 종료 후 락 해제, 물품 수정 가능
- 검사 이력 통계 조회(경고 건수, 폐기 건수)

***

## 3. 관리자(ADMIN) 시나리오

### 관리자 로그인 및 대시보드 접속
- 관리자 계정 로그인
- 전체 층 냉장고, 사용자, 검사 이력 대시보드 조회

### 층별장 임명 및 해제
- 특정 층, 칸 냉장고에 층별장 임명 (INSPECTOR 권한 부여)
- 임명 변경 시 알림 발송 및 역할 재부여

### 검사 결과 및 물품 관리
- 전체 등록 물품, 검사 이력 조회(필터링 지원)

### 시스템 설정 및 배포 관리
- 알림 배치 스케줄링 관리
- 서버 상태 모니터링 및 배포

***

|      | 검사 이력 및 물품 관리 | 필터링, 보고서 생성                        |

### **알림 정책(정리)**
- **세탁실**:
	- [세탁실 ]종료 5분 전, 상태변경(관리/신고), 정정 알림
- **냉장고**: 유통기한 임박(하루 1회 묶음), 점검 결과(경고/벌점), 점검일 변경
- **도서관**:
	- 반납 전/당일, 연체알림
	- 예약: 대출 가능, 예약 만료 자동취소
- **다목적실**: 시작/종료 전, 노쇼 신고 알림
- **시스템/관리**: 상벌점 변동, (임명/공지 **미발송**: 밴드앱과 중복되어 제거)

## 알림구현

웹페이지는 메인화면, 냉장고,다목적실,도서관,세탁실메인화면으로 구성되어있다.

메인화면에는 당일 사용하는 다목적실의 정보와 현재 사용중/ 종료알림 신청한 세탁실기기의 정보와 메세지 읽음여부 표시하며 각 클릭시 해당 상태제어를 할수있는 버튼과 해당 기기에 관련된 알림/메세지가 표시되는 팝업이 뜬다.

알림을 표시하는건 4가지 방법이 있다

1. 백그라운드 푸시알림
2. 메인화면에서 다목적실, 세탁실기기의 메세지 읽음여부 표시 아이콘으로 기기 상태팝업으로 이동을 유도해 상세 팝업에서 메세지를 읽게함
3. 메인페이지의 종모양 알림버튼
4. 메인화면, 냉장고,다목적실,도서관,세탁실메인화면으로 이동하는 하단탭에서의 뱃지 표시
사용자가 **관련 정보에대해 파악했다고 판단가능한 페이지나 팝업에 진입하는 순간**, 시스템은 해당 알림을 자동으로 '읽음'으로 변경한다.

이미 관리자와 기숙사생들은 band라는 채팅, 게시물 앱으로 소통하고있다.

4가지 알림방법은 읽음 상태가 아닐때 활성화 할려고 한다. 해당알림을 유저의 피곤함 없이 어떻게 표시하려고 한 결과물은 다음과 같다
