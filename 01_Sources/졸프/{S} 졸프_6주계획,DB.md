## 6주 배포 MVP

- 포함: 냉장고 전 흐름, DB-락, SSE, 벌점, 최소 관리자, 배포.
- 제외: **Web Push**, Redis 분산락, Items v2, TRGM, 고급 대시보드.
- 컷리스트: Week4 통계 위젯→텍스트 수치. D-1 스케줄러→앱 진입 시 계산.

### **Week 1: 기반**

- 목표: 프로젝트·보안·DDL 골격 확정.
- 과업
    - Spring Boot 3(Java 21), Gradle, 멀티 프로필(dev/prod).
    - Flyway 적용 + **Fix Pack** 마이그(역할명 정합, resource_locks TTL=5m, event_log.actor_user_id/reason).
    - Security + JWT + RBAC(ADMIN_ROOT/ADMIN/INSPECTOR/RESIDENT).
    - CI 기초: 빌드·이미지 생성까지만.
- 게이트: 로그인 샘플 200/403, Flyway clean→migrate 무오류.

### **Week 2: 냉장고 등록·조회**

- 목표: 입주자 핵심 흐름 확보.
- 과업
    - 모델: **resources(FRIDGE_COMP)**, **item_bundles**만. SNNN= resource_id+label_no 런타임 생성.
    - API: 내 물품 등록(단일/묶음), 내 목록/상세, D-1 임박 조회.
    - 유일성: 활성 상태 (resource_id,label_no) 부분 UNIQUE.
    - event_log 적재(actor, reason 포함).
- 게이트: “등록→목록→상세” e2e, 100건 로컬 P95<150ms.

### **Week 3: 점검·리비전·벌점**

- 목표: 층별장 업무 플로우 완성.
- 과업
    - 점검 세션/참여/결과 + 리비전 트리거(사유 필수).
    - **DB 논리 락**: resource_locks + TTL 5분. 동시 2인 세션 제약.
    - 벌점: penalties_original/adjustments + 합산 뷰.
- 게이트: 제출 후 수정 시 사유 미제공 422, 리비전 버전 증가 확인.

### **Week 4: 실시간(SSE)·UX 최소**

- 목표: 포그라운드 실시간 반영.
- 과업

- 게이트: 탭 2개 동시 갱신, 네트워크 단절 후 자동 재접속.

### **Week 5: 관리자·안정화**

## 6주 DB

```sql
-- =========================================================
-- Dorm Convenience System — 1st-run clean DDL (PG ≥ 11)
-- v2 채택( item_groups + item_units ), 무결성/경합/권한 보강 포함
-- 규칙:
--   • 시간: UTC(timestamptz). 표시 변환은 클라이언트(KST).
--   • 핵심 무결성은 DB가 보장. 비즈니스 정책은 애플리케이션에서 처리.
--   • 스티커: S(칸순번/종류)+NNN. DB는 NNN(=label_no) 1..999만 관리.
-- =========================================================
BEGIN;

-- 0) Extensions -------------------------------------------------------------
-- citext: 대소문자 무시 로그인/이메일 고유성
-- btree_gist: EXCLUDE 등 확장 대비(향후 시간 겹침 등)
-- pg_trgm: 이름/메모 TRGM 검색 가속(데이터 증가 시 효과)
CREATE EXTENSION citext;
CREATE EXTENSION btree_gist;
CREATE EXTENSION pg_trgm;

-- 1) Users / Roles ----------------------------------------------------------
CREATE TABLE users (
  user_id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username      CITEXT NOT NULL UNIQUE,         -- 로그인 ID(대소문자 무시)
  email         CITEXT UNIQUE,                  -- 알림용(선택)
  password_hash TEXT   NOT NULL,                -- Argon2id/bcrypt 해시
  display_name  TEXT   NOT NULL,                -- 표시명
  is_active     BOOLEAN NOT NULL DEFAULT TRUE,  -- 비활성 시 로그인 차단
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE roles (
  role_id SMALLINT PRIMARY KEY,                 -- 고정 역할 ID
  name    TEXT NOT NULL UNIQUE,
  CHECK (name IN ('ADMIN_ROOT','ADMIN','INSPECTOR','RESIDENT'))
);

INSERT INTO roles(role_id, name) VALUES
  (0,'ADMIN_ROOT'),(1,'ADMIN'),(2,'INSPECTOR'),(3,'RESIDENT')
ON CONFLICT DO NOTHING;

CREATE TABLE user_roles (
  user_id    BIGINT    NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  role_id    SMALLINT  NOT NULL REFERENCES roles(role_id) ON DELETE CASCADE,
  granted_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY(user_id, role_id)
);

-- 2) Resources --------------------------------------------------------------
-- 칸 단위 리소스. v2에선 FRIDGE_COMP만 사용.
-- comp_kind + position_order는 스티커 S 계산 근거. FRIDGE_COMP에 필수.
CREATE TABLE resources (
  resource_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  type        TEXT    NOT NULL CHECK (type IN ('FRIDGE_COMP')),
  label       TEXT    NOT NULL,                                       -- 운영 라벨(예: 냉장1)
  status      TEXT    NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE','OUT_OF_SERVICE')),
  floor_code  TEXT    NOT NULL,
  position_order SMALLINT,
  comp_kind   TEXT CHECK (comp_kind IS NULL OR comp_kind IN ('FRIDGE','FREEZER')),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(type, label),
  CHECK (type <> 'FRIDGE_COMP' OR (comp_kind IS NOT NULL AND position_order IS NOT NULL))
);
CREATE INDEX idx_resources_floor ON resources(floor_code);

-- 상태 매핑(원시 상태 → 표준 코드)
CREATE TABLE state_codes ( code TEXT PRIMARY KEY );
INSERT INTO state_codes(code) VALUES
  ('AVAILABLE'),('IN_USE'),('RESERVED'),('DONE'),
  ('UNAUTHORIZED_USE'),('ERROR_REPORTED'),('OUT_OF_SERVICE')
ON CONFLICT DO NOTHING;

CREATE TABLE resource_state_map (
  type TEXT NOT NULL,
  raw_status TEXT NOT NULL,
  code TEXT NOT NULL REFERENCES state_codes(code),
  PRIMARY KEY(type, raw_status)
);
INSERT INTO resource_state_map(type, raw_status, code) VALUES
  ('FRIDGE_COMP','ACTIVE','AVAILABLE'),
  ('FRIDGE_COMP','OUT_OF_SERVICE','OUT_OF_SERVICE')
ON CONFLICT DO NOTHING;

-- 3) Items v2 ---------------------------------------------------------------
-- item_groups: 스티커 1장에 대응하는 "묶음" 행. 활성(removed_at IS NULL) 동안 (resource_id, label_no) 유일.
-- item_units : 개별 유닛(부분소비는 유닛 제거로 표현).
CREATE TABLE item_groups (
  group_id      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  resource_id   BIGINT NOT NULL REFERENCES resources(resource_id) ON DELETE RESTRICT,
  owner_user_id BIGINT REFERENCES users(user_id) ON DELETE SET NULL,
  label_no      INTEGER NOT NULL CHECK (label_no BETWEEN 1 AND 999), -- 스티커 NNN
  group_name    TEXT    NOT NULL,
  memo          TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  removed_at    TIMESTAMPTZ,                                         -- 전량 제거(폐기/소진)
  replaced_by_group_id BIGINT REFERENCES item_groups(group_id) ON DELETE SET NULL,  -- 교체 대상(신규)
  CHECK (replaced_by_group_id IS NULL OR removed_at IS NOT NULL)      -- 교체 연결 전 제거 필수
);
-- 활성 라벨 유일(+즉시 재사용)
CREATE UNIQUE INDEX ux_item_groups_label_active
  ON item_groups(resource_id, label_no) WHERE removed_at IS NULL;

CREATE TABLE item_units (
  unit_id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  group_id    BIGINT NOT NULL REFERENCES item_groups(group_id) ON DELETE CASCADE,
  seq_no      INTEGER NOT NULL CHECK (seq_no > 0),                    -- 1..N
  name        TEXT    NOT NULL,                                       -- 개별명
  expires_on  DATE    NOT NULL,                                       -- 개별 유통기한
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  removed_at  TIMESTAMPTZ,
  UNIQUE (group_id, seq_no)
);
CREATE INDEX idx_item_units_group   ON item_units(group_id);
CREATE INDEX idx_item_units_expires ON item_units(expires_on) WHERE removed_at IS NULL;

-- (보강) 라벨 교체 정합성: 동일 칸·동일 라벨만 허용
CREATE OR REPLACE FUNCTION ensure_group_replacement_consistency()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE rid BIGINT; lno INT;
BEGIN
  IF NEW.replaced_by_group_id IS NOT NULL THEN
    SELECT resource_id, label_no INTO rid, lno FROM item_groups WHERE group_id = NEW.replaced_by_group_id;
    IF rid IS DISTINCT FROM NEW.resource_id OR lno IS DISTINCT FROM NEW.label_no THEN
      RAISE EXCEPTION '교체 대상은 동일 칸·동일 라벨이어야 합니다';
    END IF;
    IF NEW.removed_at IS NULL THEN
      RAISE EXCEPTION '교체 설정 전 removed_at이 필요합니다';
    END IF;
  END IF;
  RETURN NEW;
END$$;

CREATE TRIGGER trg_item_group_replace_ck
BEFORE UPDATE ON item_groups
FOR EACH ROW WHEN (OLD.* IS DISTINCT FROM NEW.*)
EXECUTE FUNCTION ensure_group_replacement_consistency();

-- (보강) 비활성 그룹에 유닛 추가 금지
CREATE OR REPLACE FUNCTION ensure_unit_group_active()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE v_removed TIMESTAMPTZ;
BEGIN
  SELECT removed_at INTO v_removed FROM item_groups WHERE group_id = NEW.group_id;
  IF v_removed IS NOT NULL THEN
    RAISE EXCEPTION 'removed_at이 설정된 그룹에는 유닛을 추가/갱신할 수 없습니다';
  END IF;
  RETURN NEW;
END$$;
CREATE TRIGGER trg_unit_group_active_ins BEFORE INSERT ON item_units
FOR EACH ROW EXECUTE FUNCTION ensure_unit_group_active();
CREATE TRIGGER trg_unit_group_active_upd BEFORE UPDATE ON item_units
FOR EACH ROW EXECUTE FUNCTION ensure_unit_group_active();

-- (유틸) 그룹 종료 시 유닛 일괄 제거 타임스탬프 주입
CREATE OR REPLACE FUNCTION close_item_group(p_group_id BIGINT)
RETURNS VOID LANGUAGE plpgsql AS $$
BEGIN
  UPDATE item_groups SET removed_at = COALESCE(removed_at, now())
  WHERE group_id = p_group_id;

  UPDATE item_units SET removed_at = COALESCE(removed_at, now())
  WHERE group_id = p_group_id AND removed_at IS NULL;
END$$;

-- (유틸) 해당 칸의 다음 사용가능 라벨 NNN(최솟값 빈자리) 조회
CREATE OR REPLACE FUNCTION next_free_label(p_resource_id BIGINT)
RETURNS INTEGER LANGUAGE sql STABLE AS $$
WITH used AS (
  SELECT label_no FROM item_groups
  WHERE resource_id = p_resource_id AND removed_at IS NULL
),
seq AS (
  SELECT gs AS n FROM generate_series(1,999) AS gs
)
SELECT MIN(n) FROM seq s
LEFT JOIN used u ON u.label_no = s.n
WHERE u.label_no IS NULL;
$$;

-- 4) Inspection -------------------------------------------------------------
-- 세션: 자원당 동시 1개(IN_PROGRESS). 제출 시 타임스탬프 필수.
CREATE TABLE inspection_sessions (
  session_id    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  resource_id   BIGINT NOT NULL REFERENCES resources(resource_id) ON DELETE RESTRICT,
  started_by    BIGINT NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  status        TEXT  NOT NULL CHECK (status IN ('IN_PROGRESS','SUBMITTED','CANCELED')),
  started_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  ended_at      TIMESTAMPTZ,
  submitted_by  BIGINT REFERENCES users(user_id) ON DELETE SET NULL,
  submitted_at  TIMESTAMPTZ,
  CHECK (status <> 'SUBMITTED' OR (submitted_at IS NOT NULL AND ended_at IS NOT NULL)),
  CHECK (status <> 'IN_PROGRESS' OR (submitted_at IS NULL AND ended_at IS NULL))
);
CREATE UNIQUE INDEX ux_inspection_res_inprog
  ON inspection_sessions(resource_id) WHERE status='IN_PROGRESS';

-- 참여자: 세션별 최대 2인, 1좌석 1인
CREATE TABLE inspection_participants (
  participant_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id     BIGINT NOT NULL REFERENCES inspection_sessions(session_id) ON DELETE CASCADE,
  user_id        BIGINT NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  seat_no        SMALLINT NOT NULL CHECK (seat_no IN (1,2)),
  joined_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (session_id, seat_no),
  UNIQUE (session_id, user_id),
  UNIQUE (participant_id, session_id)  -- 수행자-세션 컴포지트 FK용
);

-- 결과: 그룹 또는 유닛 참조. NO_STICKER면 둘 다 NULL.
CREATE TABLE inspection_results (
  result_id    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id   BIGINT NOT NULL REFERENCES inspection_sessions(session_id) ON DELETE CASCADE,
  group_id     BIGINT REFERENCES item_groups(group_id) ON DELETE SET NULL,
  unit_id      BIGINT REFERENCES item_units(unit_id) ON DELETE SET NULL,
  performer_participant_id BIGINT NOT NULL REFERENCES inspection_participants(participant_id) ON DELETE RESTRICT,
  action       TEXT NOT NULL CHECK (action IN ('PASS','WARNING','DISCARD','DISCARD_WITH_PENALTY')),
  violation_type TEXT CHECK (violation_type IS NULL OR violation_type IN ('EXPIRED','NO_STICKER','PACKAGING_DEFECT','INFO_MISMATCH')),
  note         TEXT,
  performed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  version      INTEGER NOT NULL DEFAULT 1,
  CHECK (
    (action='PASS' AND violation_type IS NULL)
 OR (action='WARNING' AND violation_type IS NOT NULL)
 OR (action IN ('DISCARD','DISCARD_WITH_PENALTY') AND violation_type IS NOT NULL)
  )
);

-- (보강#1) 수행자-세션 정합성
ALTER TABLE inspection_results
  ADD CONSTRAINT fk_ir_participant_session
  FOREIGN KEY (performer_participant_id, session_id)
  REFERENCES inspection_participants(participant_id, session_id);

-- (보강) 결과-아이템 참조 정합성 + 세션-리소스 일치
CREATE OR REPLACE FUNCTION ensure_result_item_refs()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE v_gid BIGINT; v_session_res BIGINT; v_item_res BIGINT;
BEGIN
  SELECT resource_id INTO v_session_res FROM inspection_sessions WHERE session_id = NEW.session_id;

  IF NEW.violation_type = 'NO_STICKER' THEN
    IF NEW.group_id IS NOT NULL OR NEW.unit_id IS NOT NULL THEN
      RAISE EXCEPTION 'NO_STICKER는 group_id/unit_id 없이 기록해야 합니다';
    END IF;
  ELSE
    IF NEW.group_id IS NULL AND NEW.unit_id IS NULL THEN
      RAISE EXCEPTION 'group_id 또는 unit_id 중 하나는 필수입니다';
    END IF;

    IF NEW.unit_id IS NOT NULL THEN
      SELECT group_id INTO v_gid FROM item_units WHERE unit_id = NEW.unit_id;
      IF NOT FOUND THEN
        RAISE EXCEPTION '존재하지 않는 unit_id입니다';
      END IF;
      IF NEW.group_id IS NOT NULL AND NEW.group_id <> v_gid THEN
        RAISE EXCEPTION 'unit_id는 지정된 group_id에 속해야 합니다';
      END IF;
      -- 유닛의 리소스
      SELECT resource_id INTO v_item_res FROM item_groups WHERE group_id = v_gid;
    ELSE
      -- 그룹만 지정된 경우의 리소스
      SELECT resource_id INTO v_item_res FROM item_groups WHERE group_id = NEW.group_id;
      IF NOT FOUND THEN
        RAISE EXCEPTION '존재하지 않는 group_id입니다';
      END IF;
    END IF;

    IF v_item_res IS DISTINCT FROM v_session_res THEN
      RAISE EXCEPTION '검사 세션의 리소스와 결과 대상 리소스가 다릅니다';
    END IF;
  END IF;

  RETURN NEW;
END$$;

CREATE TRIGGER trg_ir_item_refs_ck
BEFORE INSERT OR UPDATE ON inspection_results
FOR EACH ROW EXECUTE FUNCTION ensure_result_item_refs();

-- 결과 불변성 + 리비전 적재
CREATE OR REPLACE FUNCTION ensure_session_not_submitted()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE st TEXT;
BEGIN
  SELECT status INTO st FROM inspection_sessions
  WHERE session_id = COALESCE(NEW.session_id, OLD.session_id)
  FOR UPDATE;
  IF st='SUBMITTED' THEN
    RAISE EXCEPTION '이미 제출된 검사 세션입니다(결과 불변)';
  END IF;
  RETURN COALESCE(NEW, OLD);
END$$;

CREATE OR REPLACE FUNCTION trg_audit_ir_update()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE v_status TEXT; v_reason TEXT; v_user BIGINT;
BEGIN
  SELECT status INTO v_status FROM inspection_sessions WHERE session_id = NEW.session_id;
  v_reason := current_setting('app.change_reason', true);
  IF current_setting('app.user_id', true) IS NOT NULL THEN
    v_user := current_setting('app.user_id')::BIGINT;
  END IF;
  IF v_status='SUBMITTED' AND (v_reason IS NULL OR btrim(v_reason)='') THEN
    RAISE EXCEPTION '제출된 검사결과 수정에는 사유(app.change_reason)가 필요합니다';
  END IF;
  INSERT INTO inspection_result_revisions(result_id, session_id, changed_by, reason, prev_row, new_row)
  VALUES (OLD.result_id, OLD.session_id, v_user, v_reason, to_jsonb(OLD), to_jsonb(NEW));
  NEW.version := OLD.version + 1;
  RETURN NEW;
END$$;

CREATE TRIGGER trg_ir_block_ins BEFORE INSERT ON inspection_results
  FOR EACH ROW EXECUTE FUNCTION ensure_session_not_submitted();
CREATE TRIGGER trg_ir_audit_upd BEFORE UPDATE ON inspection_results
  FOR EACH ROW WHEN (OLD.* IS DISTINCT FROM NEW.*)
  EXECUTE FUNCTION trg_audit_ir_update();
CREATE TRIGGER trg_ir_block_del BEFORE DELETE ON inspection_results
  FOR EACH ROW EXECUTE FUNCTION ensure_session_not_submitted();

CREATE TABLE inspection_result_revisions (
  rev_id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  result_id  BIGINT NOT NULL REFERENCES inspection_results(result_id) ON DELETE CASCADE,
  session_id BIGINT NOT NULL REFERENCES inspection_sessions(session_id) ON DELETE CASCADE,
  changed_by BIGINT REFERENCES users(user_id) ON DELETE SET NULL,
  changed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  reason     TEXT,
  prev_row   JSONB NOT NULL,
  new_row    JSONB NOT NULL
);

-- (보강#7) 세션 상태 전이 가드: 제출 시 타임스탬프 자동 주입, 역전이 금지
CREATE OR REPLACE FUNCTION enforce_session_state_transitions()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  IF OLD.status IN ('SUBMITTED','CANCELED') AND NEW.status <> OLD.status THEN
    RAISE EXCEPTION '제출/취소된 세션은 상태 변경 불가';
  END IF;

  IF NEW.status='SUBMITTED' AND OLD.status <> 'SUBMITTED' THEN
    NEW.submitted_at := COALESCE(NEW.submitted_at, now());
    NEW.ended_at     := COALESCE(NEW.ended_at, now());
  END IF;

  IF NEW.status='IN_PROGRESS' AND (NEW.submitted_at IS NOT NULL OR NEW.ended_at IS NOT NULL) THEN
    RAISE EXCEPTION 'IN_PROGRESS 상태에서는 submitted_at/ended_at이 NULL이어야 합니다';
  END IF;

  RETURN NEW;
END$$;

CREATE TRIGGER trg_is_state_transition
BEFORE UPDATE ON inspection_sessions
FOR EACH ROW EXECUTE FUNCTION enforce_session_state_transitions();

-- 5) Resource logical locks --------------------------------------------------
-- 목적: 점검/운영 중 쓰기 차단의 "근거" 데이터. 실제 423 응답은 미들웨어에서 판단.
-- 만료 기반 단일 락. UPSERT로 만료 시 점유권 인계 허용.
CREATE TABLE resource_locks (
  lock_id        BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  resource_id    BIGINT NOT NULL REFERENCES resources(resource_id) ON DELETE CASCADE,
  holder_user_id BIGINT NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  reason         TEXT    NOT NULL,                                              -- 예: 'INSPECTION_IN_PROGRESS'
  expires_at     TIMESTAMPTZ NOT NULL DEFAULT now() + interval '5 minutes',
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(resource_id)
);
CREATE INDEX idx_resource_locks_expire ON resource_locks(expires_at);

CREATE OR REPLACE FUNCTION acquire_resource_lock(p_resource_id BIGINT, p_holder_user_id BIGINT, p_reason TEXT, p_ttl_seconds INT DEFAULT 300)
RETURNS BIGINT LANGUAGE plpgsql AS $$
DECLARE v_id BIGINT;
BEGIN
  INSERT INTO resource_locks(resource_id, holder_user_id, reason, expires_at)
  VALUES (p_resource_id, p_holder_user_id, p_reason, now() + make_interval(secs => p_ttl_seconds))
  ON CONFLICT (resource_id) DO UPDATE
    SET holder_user_id = EXCLUDED.holder_user_id,
        reason         = EXCLUDED.reason,
        expires_at     = EXCLUDED.expires_at,
        created_at     = GREATEST(resource_locks.created_at, now())
  WHERE resource_locks.expires_at <= now()
  RETURNING lock_id INTO v_id;

  IF v_id IS NULL THEN
    RAISE EXCEPTION 'Lock is held and not expired';
  END IF;
  RETURN v_id;
END$$;

-- 6) Penalties ---------------------------------------------------------------
-- 원본 벌점은 불변, 조정은 별도 테이블. 합산 뷰 제공.
CREATE TABLE penalties_original (
  penalty_id  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id     BIGINT NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  inspection_result_id BIGINT REFERENCES inspection_results(result_id) ON DELETE SET NULL,
  violation_type TEXT NOT NULL,
  points      INTEGER NOT NULL CHECK (points > 0),

);

CREATE OR REPLACE FUNCTION block_penalty_mutation()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION '원본 벌점은 수정/삭제할 수 없습니다';
END$$;
CREATE TRIGGER trg_po_block_upd BEFORE UPDATE ON penalties_original
  FOR EACH ROW EXECUTE FUNCTION block_penalty_mutation();
CREATE TRIGGER trg_po_block_del BEFORE DELETE ON penalties_original
  FOR EACH ROW EXECUTE FUNCTION block_penalty_mutation();

CREATE TABLE penalties_adjustments (
  adj_id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id      BIGINT  NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  delta_points INTEGER NOT NULL CHECK (delta_points <> 0),
  reason       TEXT    NOT NULL,
  created_by   BIGINT  NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE OR REPLACE VIEW v_penalties_totals AS
WITH po AS (
  SELECT user_id, SUM(points) AS original_points
  FROM penalties_original
  GROUP BY user_id
),
pa AS (
  SELECT user_id, SUM(delta_points) AS adjusted_points
  FROM penalties_adjustments
  GROUP BY user_id
)
SELECT u.user_id,
       COALESCE(po.original_points, 0) AS original_points,
       COALESCE(pa.adjusted_points, 0) AS adjusted_points,
       COALESCE(po.original_points, 0) + COALESCE(pa.adjusted_points, 0) AS total_points
FROM users u
LEFT JOIN po ON po.user_id = u.user_id
LEFT JOIN pa ON pa.user_id = u.user_id;
```

DB 시나리오

아래는 스키마가 “무엇을 할 때 DB가 무엇을 보장/자동화/차단하는지”를 초보자도 이해하기 쉽게 기능별로 풀어쓴 가이드야.

(용어 한줄 요약: **칸=resource**, **스티커 NNN=label_no(1~999)**, **묶음=group(스티커 1장)**, **유닛=unit(개별 아이템)**)

---

# **0) 계정·권한**

**무엇**: 사용자 만들고 역할(RBAC) 붙이기

**DB가 하는 일**

- users.username/email 대소문자 무시 고유(중복 자동 차단).
- user_roles로 여러 역할 부여 가능.
    
    **실패/오류 매핑**: 중복(UNIQUE) → 409

---

# **1) 냉장칸(리소스)**

**무엇**: 냉장/냉동 칸 정의

**DB가 하는 일**

- resources는 FRIDGE_COMP만 허용, 이때 comp_kind(FRIDGE/FREEZER)와 position_order 필수(CHECK).
- 층/칸 라벨 인덱스로 빠른 조회.
    
    **실패**: 잘못된 유형/상태(CHECK) → 422

---

# **2) 스티커·라벨 규칙**

**무엇**: 칸 안에서 스티커 NNN(1~999)만 유일하면 됨

**DB가 하는 일**

- item_groups(resource_id, label_no)는 **활성(removed_at IS NULL)** 동안만 유일(파셜 UNIQUE). → 사용 중인 스티커만 충돌 체크, 비활성 되면 즉시 재사용 가능.
- 다음 빈 번호 추천: next_free_label(resource_id)가 1~999 중 비어있는 최솟값 반환.
- 표시용 힌트 뷰: v_item_group_labels(S 접두사는 앱에서 결정).

**실패**: 같은 칸에서 같은 NNN를 동시에 쓰려면 UNIQUE 충돌 → 409

---

# **3) 물품 등록(묶음/유닛)**

**흐름(권장 트랜잭션)**

1. 앱이 next_free_label(:rid) 호출 → NNN 추천
2. item_groups에 **묶음**(스티커 1장) INSERT
3. item_units에 **유닛**들 INSERT(1..N, 각 expires_on 필수)

**DB가 하는 일**

- seq_no>0, label_no 1..999 같은 기본 규칙 체크.
- 비활성(removed_at 설정)된 그룹에 유닛 추가/수정 시 트리거가 차단.

**실패**: 범위 위반/없는 그룹 참조(CHECK/FK) → 422

---

# **4) 소비(부분/전체)**

**부분 소비**: 유닛 하나 먹음 → 그 item_units.removed_at=now()만 기록

**전체 제거**: 묶음 다 비움 → close_item_group(:gid) 호출

→ 그룹의 removed_at 주입 + 남은 유닛들의 removed_at도 일괄 주입

**가드**: ensure_unit_group_active 트리거가 **끝난 그룹**에 유닛 추가/갱신을 막음 → 422

---

# **5) 라벨 교체(스티커 재사용, 이력 남기기)**

**목표**: 같은 칸·같은 NNN에 새 묶음으로 교체(히스토리 연결)

**트랜잭션 순서**

1. 기존 그룹: removed_at=now()
2. 새 그룹: **동일 (resource_id,label_no)** 로 INSERT
3. 기존 그룹: replaced_by_group_id=신규 group_id 업데이트

**가드(트리거)**: 교체 대상은 **동일 칸·동일 NNN**, 그리고 기존 그룹이 **이미 종료**되어야 함 → 불일치 시 422

---

# **6) 검색·만료 정렬·리스트**

**무엇**: 이름/메모/유닛명으로 빠르게 찾기, 만료 임박 정렬

**DB가 하는 일**

- TRGM 인덱스(group_name,memo,item_units.name)로 모호 검색 가속.
- expires_on WHERE removed_at IS NULL 인덱스로 “남아있는 것만” 만료순 정렬 빠르게.

---

# **7) 검사(점검) 운영 전반**

**사전 잠금(경합 완화)**

- acquire_resource_lock(:rid,:uid,'INSPECTION_IN_PROGRESS', ttl) 시도
    - 잠금 만료 전이면 예외 발생 → 앱이 423으로 매핑

**세션/참여**

- inspection_sessions: 한 칸당 **동시에 1개**만 IN_PROGRESS 가능(파셜 UNIQUE).
- inspection_participants: 좌석 1,2로 최대 2명, 좌석/사용자 중복 자동 차단.

**결과 기록**

- inspection_results 한 건마다: 수행자(참여자), 대상(그룹 또는 유닛), 조치/위반 유형 기록.
- 트리거 ensure_result_item_refs가 자동 검증:
    - NO_STICKER면 group_id/unit_id **금지**
    - unit_id가 주어지면 해당 group_id와 **일치**해야 함
    - 결과 대상의 **리소스(칸)**가 세션의 리소스와 **같아야** 함

**제출/종료**

- 세션 상태 SUBMITTED로 바꾸면 트리거가 submitted_at/ended_at 자동 주입.
- SUBMITTED/CANCELED로 간 뒤엔 **되돌릴 수 없음**(가드).

**제출 후 수정(감사 이력)**

- 제출된 결과를 고치려면 DB 세션 변수에 사유 app.change_reason (그리고 가능하면 app.user_id)를 넣어야 함.
- 수정하면 inspection_result_revisions에 **이전/이후 전체 행**이 JSON으로 적재되고 version++.

---

# **8) 벌점(원본 불변 + 조정 분리)**

**원본 벌점**: penalties_original(points>0) — **절대 수정/삭제 불가**(트리거 차단)

**조정**: penalties_adjustments(delta_points≠0, reason, created_by) — 가감 기록

**조회**: v_penalties_totals로 **원본+조정 합계** 한 번에 확인

---

# **9) 이벤트 로그(SSE/감사 공용 저장소)**

**무엇**: 중요한 사건을 JSONB로 기록

**DB가 하는 일**

- event_log INSERT 중심 사용 권장(UPDATE/DELETE 제한 권장).
- 타입/시간 인덱스로 실시간 스트림 필터 고속.
- RLS 정책: 읽기/쓰기(INSERT)만 허용하도록 정책 포함.

---

# **10) 운영 권한(접속 롤)**

- dcs_app: 일반 테이블 SELECT/INSERT/UPDATE/DELETE, 단 event_log는 INSERT/SELECT만, penalties_original 수정/삭제 금지.
- dcs_read: 읽기 전용(+ 로그 열람), 원본 벌점 수정권한 없음.
- **관리자 자동 시드**: SET app.admin_password_hash='…' 설정된 경우에만 admin 계정/역할 삽입.

---

# **11) 에러 코드 매핑(앱에서 이렇게 바꿔 주면 됨)**

- **409**: UNIQUE 충돌(라벨 중복, 검사 세션 동시 생성, 좌석 중복 등)
- **422**: CHECK/FK/트리거 위반(규칙 불일치 메시지 상세)
- **423**: 리소스 잠금 보유 중(만료 전) → acquire_resource_lock 실패를 매핑
- **429**: 레이트 제한(앱/게이트웨이에서 처리)

---

# **12) 동시성 안전 팁(현장 운용용)**

- **라벨 배정/교체**는 한 트랜잭션으로 처리(가능하면 pg_advisory_xact_lock(resource_id)로 앱 측 상호배제).
- **검사 중 쓰기 경합**은 resource_locks로 근거 남기고, 앱 미들웨어가 423 반환.
- 리스트·검색은 이미 인덱스로 최적화(추가 튜닝 없이 충분히 빠름).

---

이 정도만 지켜도, **칸 내부 스티커 유일성/즉시 재사용**, **검사 동시성·정합성 보장**, **벌점 원본 불변·감사 이력 보존**이 전부 DB 레벨에서 자동으로 지켜져. 앱은 “언제 무엇을 호출할지”와 “오류 코드를 사용자에게 어떻게 보여줄지”에만 집중하면 돼.

# **ADMIN**

- 계정·역할
    - 사용자 생성: INSERT users … RETURNING user_id
    - 역할 부여/해제: INSERT/DELETE user_roles
- 리소스(칸)
    - 생성/수정: INSERT/UPDATE resources(FRIDGE_COMP는 comp_kind+position_order 필수)
    - 상태 전환: status IN ('ACTIVE','OUT_OF_SERVICE')
    - 삭제: 참조 있으면 RESTRICT
- 라벨 운영
    - 다음 라벨 조회: SELECT next_free_label(:rid)
    - 강제 종료: SELECT close_item_group(:gid) → 즉시 재사용 가능
    - 교체 이력 연결: UPDATE item_groups SET replaced_by_group_id=:new WHERE removed_at IS NOT NULL
- 락 운영
    - 획득/인계: SELECT acquire_resource_lock(:rid,:uid,'...',300)
    - 정리: DELETE FROM resource_locks WHERE expires_at<now()
- 검사 감사
    - 세션 상태 가드 자동(트리거)
    - 제출 후 수정 시 리비전 확인: SELECT * FROM inspection_result_revisions WHERE result_id=:id
- 벌점 정책
    - 원본 생성은 검사 결과 기반(penalties_original, 불변)
    - 조정: INSERT penalties_adjustments(user_id, delta_points, reason, created_by)
    - 합산: SELECT * FROM v_penalties_totals WHERE user_id=:uid
- 이벤트 로그
    - 기록: INSERT event_log(type, resource_id, …, data)
    - SSE 조회: SELECT * FROM event_log WHERE type='…' AND created_at>:cursor ORDER BY created_at
- 오류 매핑
    - 라벨 충돌 409, 규칙 위반 422, 점유/검사 중 423

# **INSPECTOR**

- 점검 세션 수명주기
    - 락: acquire_resource_lock(:rid,:insp,'INSPECTION_IN_PROGRESS',300)
    - 시작: INSERT inspection_sessions(resource_id, started_by,'IN_PROGRESS') RETURNING session_id
    - 참여자: INSERT inspection_participants(session_id, user_id, seat_no)
    - 결과 기록:
        - PASS: INSERT inspection_results(session_id, group_id|unit_id, performer_participant_id, 'PASS', NULL)
        - 위반: … action IN('WARNING','DISCARD','DISCARD_WITH_PENALTY'), violation_type IN('EXPIRED','PACKAGING_DEFECT','INFO_MISMATCH')
        - 무라벨: violation_type='NO_STICKER' 이면 group_id,unit_id 둘 다 NULL
        - 가드: 수행자-세션 FK, 세션-대상 리소스 일치 트리거, unit→group 일치 트리거
    - 제출: UPDATE inspection_sessions SET status='SUBMITTED', submitted_by=:insp

        → 트리거가 submitted_at/ended_at 자동 세팅, 역전이 금지

    - 제출 후 정정: SET LOCAL app.change_reason='…'; SET LOCAL app.user_id=:insp; UPDATE inspection_results …

        → 리비전 적재, 삭제/삽입 차단

- 벌점 생성
    - 원본: INSERT penalties_original(user_id, inspection_result_id, violation_type, points)
    - 합산 확인: SELECT * FROM v_penalties_totals WHERE user_id=:uid
- 조회
    - 만료 임박 유닛: … FROM item_units WHERE removed_at IS NULL AND expires_on<=CURRENT_DATE+2
    - 세션 타임라인: SELECT action, violation_type, performed_at FROM inspection_results WHERE session_id=:sid ORDER BY performed_at

# **RESIDENT**

- 등록(단일 등록 포함)
    - 라벨 배정: pg_advisory_xact_lock(42,:rid); SELECT next_free_label(:rid)
    - 그룹 생성: INSERT item_groups(resource_id, owner_user_id, label_no, group_name, memo)
    - 유닛 1개: INSERT item_units(group_id, 1, name, expires_on)

        N개면 seq_no=1..N

- 소비·정리
    - 부분소비: UPDATE item_units SET removed_at=now() WHERE group_id=:gid AND seq_no=:n AND removed_at IS NULL
    - 전량 제거: SELECT close_item_group(:gid)(그룹·남은 유닛 일괄 종료)
- 라벨 교체
    - ① 기존 그룹 removed_at=now() → ② 동일 (resource_id,label_no)로 새 그룹 INSERT → ③ 이전 그룹 replaced_by_group_id=새 id

        → 트리거가 동일 칸·라벨만 허용

- 조회
    - 내 활성 스티커: SELECT * FROM v_item_group_labels WHERE resource_id=:rid ORDER BY label_no
    - 내 이력: SELECT * FROM item_groups WHERE owner_user_id=:uid ORDER BY created_at DESC
    - 내 벌점: SELECT * FROM v_penalties_totals WHERE user_id=:uid
- 제약·예외
    - 활성 중 (resource_id,label_no) 유일(부분 유니크). 충돌 시 409
    - 비활성 그룹에 유닛 추가 금지(트리거)
    - label_no 범위 1..999. 포화 시 next_free_label=NULL → 운영 청소 후 재시도

핵심 보장 요약

- 스티커 유일성: (resource_id,label_no) WHERE removed_at IS NULL
- 검사 정합성: 수행자-세션 FK, 세션-리소스·유닛-그룹 일치 트리거
- 결과 불변성: 제출 후 UPDATE만 허용, 리비전 적재. INSERT/DELETE 차단
- 벌점 불변성: penalties_original UPDATE/DELETE 트리거 차단
- 동시성: 라벨 배정 자문락, 자원 락 만료 인계 UPSERT

맞다. 아래 시나리오로 재정리한다. DB 제약·트리거 기준이며 앱에서 에러코드 매핑만 한다.

# **전제**

- 라벨 배정은 트랜잭션+자문락 사용: pg_advisory_xact_lock(42, :resource_id).
- close_item_group는 “유닛→그룹” 순서로 동작하도록 수정(또는 트리거 완화). 본 시나리오는 유닛→그룹 기준.

# **시나리오 A: 물품 등록·소비·교체**

## **A-1 등록(묶음+유닛 생성)**

1. 트랜잭션 시작 → SELECT pg_advisory_xact_lock(42, :rid);
2. SELECT next_free_label(:rid)로 NNN 확보.
3. INSERT item_groups(resource_id, owner_user_id, label_no, group_name, memo)
4. 유닛 개수만큼 INSERT item_units(group_id, seq_no, name, expires_on)
5. 커밋.

- 실패 포인트: (resource_id,label_no) WHERE removed_at IS NULL 충돌 → 409.

## **A-2 부분소비(유닛 1개 제거)**

- UPDATE item_units SET removed_at=now() WHERE unit_id=:uid AND removed_at IS NULL
- 트리거 ensure_unit_group_active가 “종료된 그룹에 신규추가/일반갱신”을 차단. 제거 목적의 removed_at 설정은 허용되도록 트리거 완화했음을 전제.

## **A-3 전량제거(묶음 종료)**

- SELECT close_item_group(:gid);
    - 내부: UPDATE item_units … removed_at=now() → UPDATE item_groups … removed_at=now()
- 결과: 라벨 즉시 재사용 가능(유니크 파셜 인덱스).

## **A-4 라벨 교체(동일 칸·동일 NNN)**

1. 트랜잭션 시작, 자문락 획득.
2. 기존 그룹 UPDATE item_groups SET removed_at=now() WHERE group_id=:old_gid
3. 새 그룹 INSERT item_groups(resource_id=:rid, label_no=:nnn, …)
4. 기존 그룹 UPDATE item_groups SET replaced_by_group_id=:new_gid WHERE group_id=:old_gid
5. 커밋.

- 트리거 ensure_group_replacement_consistency가 동일 칸·동일 라벨을 강제.

# **시나리오 B: 검사 운영**

## **B-1 검사 시작**

1. 앱이 근거잠금: SELECT acquire_resource_lock(:rid, :uid, 'INSPECTION_IN_PROGRESS', 300);
    
    - 만료 시 점유권 인계, 미만료 시 예외. 실제 423 응답은 앱이 반환.

2. INSERT inspection_sessions(resource_id, started_by, status='IN_PROGRESS')

## **B-2 검사원 참여**

- 좌석 1,2에 한해 INSERT inspection_participants(session_id, user_id, seat_no)
- 유니크 제약으로 2인 초과·좌석 중복 차단.

## **B-3 결과 기록**

- INSERT inspection_results(session_id, group_id?, unit_id?, performer_participant_id, action, violation_type, note)
- 트리거 ensure_result_item_refs가 다음 검증 수행:
    - NO_STICKER면 group_id/unit_id 금지.
    - unit_id↔group_id 소속 일치.
    - 결과 대상의 리소스 = 세션 리소스.

## **B-4 제출**

- UPDATE inspection_sessions SET status='SUBMITTED', submitted_by=:uid
    - 트리거가 submitted_at/ended_at 자동 주입, 역전이 차단.
- 제출 후 결과 수정 시:
    - 세션 GUC SET LOCAL app.change_reason='…'; SET LOCAL app.user_id=:uid;
    - UPDATE 허용되며 inspection_result_revisions에 스냅샷 적재, version+1.

# **시나리오 C: 벌점**

- 위반에 따른 벌점 생성은 앱 로직:
    - INSERT penalties_original(user_id, inspection_result_id, violation_type, points)
    - 원본은 수정/삭제 금지 트리거로 보호.
- 조정:
    - INSERT penalties_adjustments(user_id, delta_points, reason, created_by)
- 조회:
    - SELECT * FROM v_penalties_totals WHERE user_id=:uid

# **시나리오 D: 이벤트 로그**

- 주요 사건마다 앱이 기록:
    - 예) INSERT event_log(type, resource_id, floor_code, correlation_id, data, actor_user_id, reason)
- 권장: INSERT 전담. RLS 정책으로 SELECT/INSERT만 허용.

# **시나리오 E: 검색·표시**

- 라벨 표시 힌트:
    - SELECT * FROM v_item_group_labels WHERE resource_id=:rid;
    - 앱이 S 접두사(F/Z 등) 조합.
- 이름/메모 검색은 TRGM 인덱스 사용:
    - … WHERE group_name ILIKE '%키워드%' 또는 memo ILIKE …

# **시나리오 F: 오류 매핑(앱)**

- 409: 라벨 충돌, 좌석/참여자 유니크 충돌.
- 422: CHECK/FK 위반, 트리거 검증 실패 메시지.
- 423: 리소스 잠금 보유 중(앱이 판단).
- 429: 레이트 리밋(앱 계층).

# **시나리오 G: 역할별 최소 권한 흐름**

- RESIDENT: A-1/2/3/4, E, 일부 D 기록.
- INSPECTOR: B-1/2/3/4, E, D 기록.
- ADMIN: 리소스 시드/상태 변경, 권한 부여, 벌점 조정, 로그·통계 조회.

이대로 운영하면 DB 제약이 핵심 무결성을 강제하고, 앱은 락·에러코드·벌점생성만 담당하면 된다.

이 데이터베이스 스키마는 단순한 데이터 저장을 넘어 **스스로 규칙을 강제하고 데이터의 무결성을 지키도록 설계**되었습니다. 이 스키마에 담긴 모든 시나리오를 기능 단위로 설명해 드릴게요.

## 1. 사용자 및 물품 관리 (일상적인 사용) 🧑‍🍳

사용자가 냉장고에 물품을 등록하고 소비하는 가장 기본적인 시나리오입니다.

- **물품 등록**: 사용자가 앱에서 특정 냉장고 칸(예: '냉장1')을 선택하면, 시스템은 `next_free_label()` 함수를 호출해 사용 가능한 가장 작은 스티커 번호(예: 1번)를 자동으로 추천합니다. 사용자가 '요거트 3개' 묶음을 등록하면, DB는 먼저 `item_groups` 테이블에 '1번 스티커'를 가진 묶음 정보를 생성한 후, '요거트'라는 개별 물품 3개를 `item_units` 테이블에 생성하고 방금 만든 '1번 스티커 묶음'에 소속시킵니다.
- **물품 소비 (부분/전체)**:
    - **부분 소비**: 사용자가 요거트 1개를 먹으면, 해당하는 `item_units` 행의 `removed_at` 필드에 현재 시간을 기록합니다. 묶음(`item_groups`)은 그대로 유지됩니다.
    - **전체 소비**: 사용자가 묶음 전체를 비우면, `close_item_group()` 함수가 호출됩니다. 이 함수는 묶음(`item_groups`)과 그 안에 남은 모든 물품(`item_units`)의 `removed_at` 필드를 한 번에 기록하여 깔끔하게 처리합니다.
- **스티커(라벨) 재사용 및 이력 관리**:
    - '1번 스티커' 묶음이 `removed_at`으로 비활성화되면, 다른 사용자가 '냉장1' 칸에 새 물품을 등록할 때 다시 '1번'을 사용할 수 있습니다. (`ux_item_groups_label_active` 인덱스가 이를 보장합니다.)
    - 만약 사용자가 기존 스티커를 새 물품으로 교체하면, DB는 이전 `item_groups` 행에 있는 `replaced_by_group_id` 필드에 새 묶음의 ID를 기록합니다. 이를 통해 **어떤 스티커가 어떤 물품으로 교체되었는지 이력을 추적**할 수 있습니다.

## 2. 검사 및 제재 (관리/감독) 🕵️

검사원(층별장)이 냉장고를 점검하고 규칙 위반 사항을 처리하는 시나리오입니다.

- **검사 시작 및 동시 접근 방지**: 검사원이 특정 칸의 점검을 시작하면, 앱은 `acquire_resource_lock()` 함수를 호출합니다. 이 함수는 해당 칸(`resource_id`)에 **'잠금'**을 설정하여, 검사가 진행되는 동안 다른 사용자가 물품 정보를 수정하지 못하도록 막습니다. 만약 다른 사람이 이미 잠금을 걸었고 아직 만료되지 않았다면, 새로운 잠금은 실패합니다 (경합 방지).
- **검사 진행 및 결과 기록**:
    - 시스템은 공식적인 검사 기록인 `inspection_sessions`를 생성하고, 검사원을 `inspection_participants`로 등록합니다.
    - 검사원은 위반 사항을 `inspection_results`에 기록합니다. 이때 DB는 여러 **논리적 오류를 스스로 검증**합니다.
        - **NO_STICKER**: 스티커 없는 물품을 기록할 땐 `group_id`나 `unit_id`가 없어야 합니다.
        - **자원 일치**: '냉장1'을 검사하는 세션에서 '냉장2'에 있는 물품을 결과로 기록할 수 없습니다. (`ensure_result_item_refs` 트리거가 차단)
- **검사 제출 및 벌점 부과**:
    - 검사원이 최종 보고서를 제출하면, `inspection_sessions`의 상태가 `SUBMITTED`로 변경되고 **종료 시간이 자동으로 기록**됩니다.
    - 벌점이 필요한 위반 사항(`DISCARD_WITH_PENALTY`)이 있었다면, `penalties_original` 테이블에 **원본 벌점 기록**이 생성됩니다. 이 기록은 **절대 수정하거나 삭제할 수 없습니다.** (`block_penalty_mutation` 트리거가 보호)
    - 만약 관리자가 벌점을 조정해야 한다면, `penalties_adjustments` 테이블에 별도로 '조정 내역'(예: -1점)을 추가합니다. 사용자의 최종 벌점은 `v_penalties_totals` 뷰를 통해 원본과 조정을 합산하여 확인합니다.

## 3. 데이터 무결성 및 시스템 안정성 (DB 자체 보호) 🛡️

이 스키마의 핵심으로, 애플리케이션의 버그나 잘못된 요청으로부터 데이터를 보호하는 시나리오입니다.

- **논리적 오류 원천 차단**:
    - **"죽은 묶음에 물품 추가 금지"**: `removed_at`이 설정된 `item_groups`에 새로운 `item_units`를 추가하려는 시도는 `ensure_unit_group_active` 트리거에 의해 차단됩니다.
    - **"상태 변경 규칙 강제"**: `SUBMITTED`(제출됨) 상태인 검사 세션을 다시 `IN_PROGRESS`(진행 중)로 되돌리려는 시도 등, 정해진 상태 흐름을 거스르는 변경은 `enforce_session_state_transitions` 트리거가 막습니다.
    - **"수정 시 사유 필수"**: 제출된 검사 결과를 수정하려면, 반드시 수정 사유(`app.change_reason`)를 DB 세션 변수로 설정해야 합니다. 사유 없이는 `trg_audit_ir_update` 트리거가 수정을 거부합니다.
- **모든 변경 이력 추적**: 제출된 검사 결과가 (사유를 명시하고) 수정될 경우, `trg_audit_ir_update` 트리거는 `inspection_result_revisions` 테이블에 **변경 전과 후의 데이터를 JSON 형태로 기록**하여 완벽한 감사 추적을 가능하게 합니다.
- **중앙화된 이벤트 기록**: 물품 등록, 검사 시작 등 시스템의 모든 주요 사건은 `event_log` 테이블에 기록됩니다. 이 로그는 나중에 사용자에게 실시간 알림(SSE)을 보내거나, 시스템 장애 발생 시 원인을 추적하는 데 사용될 수 있습니다.

## 4. 시스템 운영 및 확장 (편의 기능 및 권한) ⚙️

시스템을 더 편리하게 사용하고 안전하게 운영하기 위한 시나리오입니다.

- **편의 기능 제공**:
    - `v_item_group_labels` 뷰는 DB에 저장된 `label_no`와 칸의 순서 정보를 조합하여, 앱에서 사용할 스티커 번호(예: `1001`)를 미리 계산해 보여주는 등 편의를 제공합니다.
    - `pg_trgm` 익스텐션과 관련 인덱스들은 사용자가 물품 이름으로 검색할 때 빠른 검색 속도를 보장합니다.
- **역할 기반 권한 관리**:
    - 데이터베이스에 `dcs_app`(쓰기/읽기 가능)과 `dcs_read`(읽기 전용) 역할을 미리 정의해두고, 각 역할에 맞는 권한을 부여합니다.
    - 이를 통해 애플리케이션 서버는 `dcs_app` 계정으로 DB에 접속하고, 데이터 분석이나 모니터링 툴은 `dcs_read` 계정으로 접속하게 하여 **권한을 최소화하고 보안을 강화**합니다.

좋아. 스키마가 강제하는 규칙을 기준으로, 기능(사용 흐름) 단위로 “무엇을/어떻게/어디서 막는지”만 간결히 정리할게.

# **1) 계정·역할**

- 목적: 로그인·RBAC.
- 테이블: users, roles, user_roles (+ citext로 ID/메일 유일).
- 흐름: 사용자 생성 → 역할 부여.
- 실패: 중복(UNIQUE) → 409.

# **2) 냉장칸(리소스)**

- 목적: 칸 식별 및 스티커 접두사 S 계산 근거.
- 테이블: resources (유형=FRIDGE_COMP 고정), 상태 매핑 state_codes,resource_state_map.
- 무결성: FRIDGE_COMP면 comp_kind·position_order 필수(CHECK).
- 실패: 상태/유형 오입력(CHECK) → 422.

# **3) 스티커/라벨 정책**

- 목적: 칸 내부에서 NNN(1..999)만 유일, 즉시 재사용.
- 테이블/인덱스: item_groups + 파셜 유니크 ux_item_groups_label_active.
- 유틸: next_free_label(resource_id)로 최소 가용 NNN 추천.
- 표시: v_item_group_labels(S 힌트 제공).

# **4) 물품 등록(v2: 그룹/유닛)**

- 목적: 묶음(스티커=group) 아래 개별 유닛 관리.
- 테이블: item_groups(group_name, label_no, …), item_units(seq_no, expires_on, …).
- 흐름:
    
    1. (권장) 트랜잭션 + next_free_label()로 NNN 결정
    2. INSERT item_groups …
    3. INSERT item_units … (1..N)

- 실패: 라벨 충돌(유니크) → 409, 라벨 범위·seq_no·날짜(CHECK) → 422.

# **5) 부분소비·전량제거**

- 부분소비: UPDATE item_units SET removed_at=now() WHERE unit_id=? AND removed_at IS NULL.
- 전량제거: SELECT close_item_group(:gid) → 남은 유닛 removed_at 주입 후 그룹 종료.
- 가드: 종료된 그룹에 유닛 추가/수정 시 트리거 ensure_unit_group_active가 차단(422).

# **6) 라벨 교체(동일 칸·동일 NNN)**

- 흐름(한 트랜잭션):
    
    1. 기존 그룹 removed_at=now()
    2. 새 그룹 INSERT … (same resource_id, label_no)
    3. 기존 그룹 replaced_by_group_id=신규ID

- 가드: 트리거 ensure_group_replacement_consistency가 “동일 칸·동일 라벨 + 기존이 종료됨” 강제(422).

# **7) 검색·표시**

- 빠른 검색: TRGM 인덱스(group_name, memo, 유닛 name).
- 만료 임박: item_units(expires_on) 파셜 인덱스.
- 라벨 목록: idx_item_groups_resource_label_covering 커버링 인덱스.

# **8) 검사(점검) 운영**

- 잠금(근거 데이터): resource_locks + 함수 acquire_resource_lock(rid, uid, reason, ttl)
    - 만료 전 보유 중이면 예외 → 앱에서 423 반환.
- 세션: inspection_sessions(status='IN_PROGRESS') (자원당 동시 1개, 파셜 유니크).
- 참여: inspection_participants(좌석 1,2 / 2인 제한, 유니크로 강제).
- 결과 기록: inspection_results
    - 무결성 트리거 ensure_result_item_refs:
        - NO_STICKER면 group_id/unit_id 금지
        - unit_id↔group_id 소속 일치
        - 결과 대상 리소스 = 세션 리소스
    - 수행자-세션 정합성: 컴포지트 FK(performer_participant_id, session_id).
- 제출: 세션 status='SUBMITTED' → 트리거가 submitted_at/ended_at 자동 주입, 역전이 금지.
- 제출 후 수정: 세션 GUC(app.change_reason, app.user_id) 필요, 리비전 inspection_result_revisions 적재+버전 증가.

# **9) 벌점**

- 원본: penalties_original(user_id, inspection_result_id, violation_type, points>0)
    - 수정/삭제 전면 금지 트리거.
- 조정: penalties_adjustments(delta_points ≠ 0, reason, created_by).
- 합산: v_penalties_totals로 원본+조정 합계 조회.

# **10) 이벤트 로그(SSE/감사)**

- 기록: event_log(type, …, data JSONB) — INSERT 전담 권장.
- 인덱스: type, created_at DESC 등 스트림 필터 최적화.
- RLS/권한: SELECT/INSERT만 허용(정책 포함).

# **11) 권한 모델(운영 롤)**

- dcs_app: 스키마 사용 + 테이블 CRUD(일부 예외), event_log는 SELECT/INSERT만.
- dcs_read: 읽기 전용(+ 로그 열람), 원본 벌점 수정권한 없음.
- 시드: 관리자 계정은 SET app.admin_password_hash가 있을 때만 자동 생성.

# **12) 에러 매핑(앱 레이어 권장)**

- 409: 유니크 충돌(라벨/좌석/참여자 등 경합).
- 422: CHECK/FK/트리거 위반 메시지(규칙 불일치).
- 423: 리소스 잠금 보유 중(만료 전) — 앱이 해석해 반환.
- 429: 레이트 제한(앱/게이트웨이).

# **13) 동시성 팁**

- 라벨 배정·교체는 트랜잭션으로 묶고(가능하면 pg_advisory_xact_lock(resource_id)),

    검사 중 쓰기 경합은 resource_locks + 앱 미들웨어에서 423로 차단.

이렇게 쓰면, **칸 내부 라벨 유일성/즉시 재사용**, **검사 동시성·이력 보존**, **벌점 원본 불변/조정 분리**가 전부 DB에서 보장되고, 앱은 UX·오류코드·권한 흐름만 담당하면 된다.
