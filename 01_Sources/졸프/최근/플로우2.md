**목적:** AI가 DormMate 프로젝트를 "이해"하게 만들기

### 📄 `PROJECT_CONTEXT.md` 작성

```markdown
# DormMate 프로젝트 컨텍스트

## 1. 프로젝트 개요
- 이름: DormMate
- 목적: 대학 기숙사 공용 냉장고 관리 시스템
- 사용자: 기숙사생 200명, 층별장 10명, 관리자 2명
- 핵심 기능: 물품 등록, 검사, 알림

## 2. 기술 스택
- Backend: Spring Boot 3.1, Java 17
- DB: PostgreSQL 14
- 인증: JWT (Refresh Token 없음)
- 실시간: SSE (WebSocket 아님)
- Frontend: React (AI 생성 90%)

## 3. 코딩 컨벤션
- 네이밍: camelCase (Java), snake_case (DB)
- 패키지 구조: com.dormmate.{domain}.{layer}
- 예외: Custom Exception with ErrorCode enum
- 응답: ResponseEntity<ApiResponse<T>>
- 로깅: @Slf4j, 중요 로직만

## 4. 도메인 모델 핵심
- FridgeUnit (냉장고) → Compartment (칸) → LabelPool (라벨)
- FridgeBundle (포장) → FridgeItem (물품)
- 스티커 코드: compartmentId-labelNumber (예: 104-005)
- 라벨 발급: SKIP LOCKED로 동시성 제어

## 5. 비즈니스 규칙
- 검사는 최대 2명 동시 진행
- 검사 중 칸 잠금 (다른 사용자 수정 불가)
- 물품 삭제는 소프트 삭제 (deleted_at)
- 알림 TTL 24시간, 자동 만료

## 6. 금지 사항
- Refresh Token (Phase 2)
- WebSocket (SSE 사용)
- 복잡한 상태 관리 (Redux 등)
- Audit Log 자동화 (Phase 2)

## 7. 현재 완료된 것
- DB 스키마 확정
- seed.sql 작성 완료
- 환경 구축 완료

## 8. 졸전 발표 핵심
- 라벨 발급 동시성 (SKIP LOCKED)
- SSE 실시간 검사
- 200명 확장성 설계
```

**이 문서를 매 AI 대화 시작에 제공!**

## 🟢 Phase 1: 기능별 설계 문서 작성 (기능당 30분)

**목적:** 구현 전에 "무엇을 만들 것인가" 명확히 하기

### 예시: `FEATURE_LABEL_ACQUISITION.md`

```markdown
# 기능 설계: 라벨 발급

## 1. 비즈니스 요구사항
- 사용자가 물품 등록 시 스티커 코드 자동 발급
- 동시 요청 시 중복 없이 각자 다른 번호
- 칸마다 1~50번 범위 관리
- 라벨 부족 시 명확한 에러

## 2. 기술 요구사항
- PostgreSQL FOR UPDATE SKIP LOCKED 사용
- 트랜잭션 격리 수준: READ_COMMITTED
- 응답 시간 p95 < 100ms
- 동시 요청 20개 처리 가능

## 3. API 명세
### POST /api/labels/acquire
Request:
{
  "compartmentId": 1
}

Response:
{
  "labelNumber": 5,
  "labelCode": "1-005",
  "expiresIn": 600  // 10분 후 자동 반환 (미사용 시)
}

Error:
- 404: 칸 없음
- 409: 라벨 부족

## 4. 데이터베이스
Table: label_pool
- PK: (compartment_id, label_number)
- status: 0=AVAILABLE, 1=IN_USE
- last_used_bundle_id: FK

## 5. 테스트 시나리오
1. 단일 요청 성공
2. 동시 20개 요청 → 모두 다른 번호
3. 라벨 부족 시 예외
4. 트랜잭션 롤백 시 라벨 복구

## 6. 학습 목표
- SKIP LOCKED 원리 완벽 이해
- 동시성 제어 실험
- Pessimistic Lock 장단점

## 7. 예상 발표 질문
Q1: 왜 SKIP LOCKED?
Q2: 라벨 부족 시?
Q3: 롤백 시 라벨은?
```

## 3. 내 언어로 재작성

**AI 코드에 내 주석 추가:**

**AI 생성 (Before):**
```java
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query(value = "SELECT * FROM label_pool WHERE ...", nativeQuery = true)
Optional<LabelPool> acquireLabel(@Param("compartmentId") Long id);
```

**내 주석 추가 (After):**
```java
/**
 * 라벨 발급 with 동시성 제어
 * 
 * 내가 이해한 것:
 * - @Lock은 JPA 수준의 락
 * - PESSIMISTIC_WRITE는 비관적 락 (DB 행 잠금)
 * - FOR UPDATE SKIP LOCKED는 PostgreSQL 문법
 * - 다른 트랜잭션이 잠근 행은 건너뛰고 다음 행 선택
 * 
 * 실험 결과:
 * - SKIP LOCKED 없음: 10명 동시 요청 시 5초
 * - SKIP LOCKED 있음: 10명 동시 요청 시 0.3초
 * 
 * 발표 답변 준비:
 * Q: "왜 SKIP LOCKED?"
 * A: 순차 대기 대신 병렬 처리로 17배 빠름
 */
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query(value = """
    SELECT * FROM label_pool 
    WHERE compartment_id = :compartmentId 
    AND status = 0
    ORDER BY label_number 
    LIMIT 1 
    FOR UPDATE SKIP LOCKED
    """, nativeQuery = true)
Optional<LabelPool> acquireLabel(@Param("compartmentId") Long compartmentId);
```
