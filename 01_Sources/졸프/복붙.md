현재의 정보(현실에서 변경가능성 있음을 고려해 확장성 고려)

거주기간은 최대 1년이며 중도 퇴사가 가능하다.

기숙사는 2층~5층이 숙소이고,   2층은 남성이 머물고, 3,4,5층은 여성이 머문다 입사생은 거주호실과 개인번호로 구별한다. 한층당 총 24개의 호실이 있으며(201~224,301~324,401~424,501~524) 한층당 최대 호실 2개는 1인실(장애인실)이나, 나머지 대다수는 3인실이다. 따라서 개인번호는 대부분 3번까지 부여된다. (예시: 201-1, 201-2, 201-3) 층마다  냉장칸 3칸, 냉동칸 1칸으로 이루어진 냉장고 한대씩 할당되어있다. 냉동칸 1칸은 해당층의 24호실 공용이고,해당층의 8호실씩 냉장한칸씩을 공용으로 사용한다 층마다 해당층의 기숙사생을 층별장으로 임명하여 해당층의 냉장고 관리, 검사, 벌점부여 등의 권한을 준다.  

여기다가 층별장 2명 임명하고, 같은 검사 동시에 실시할때 누가 어떤 물품을 검사완료했는지 구별가게 하려함

세탁실은 다른 건물에 두개의 방만이 존재한다. 모든 여성(3~5층)이 다같이 하나의 여성세탁실(세탁기7+건조기6)을 이용하고, 모든남성 (2층) 은 하나의 남성세탁실(세탁기6+건조기2)을공유한다 이때 부가적으로 남성 세탁실에는 이불건조기 2대가 있는데 이 2대는 남녀공용으로 모두가 사용한다

다목적실과 도서관은 모든 기숙사생이 이용할수있다.

# **DormMate – 통합 정리**

> **최상위 목표**: 중견기업이상 취업을 목표로하는 백엔드 지망자가 혼자서 진행하는 첫 프로젝트로서 구현 요소를 최대한 줄이되, 실사용에 필요한 핵심만 정확히 제공. 공통화/표준화로 재사용성을 극대화하고, 역할 기반 접근 제어와 추적 가능성을 기본값으로 한다.

## **1) 요약 스택**

- **프론트**: React(TypeScript) · Vite · Tailwind · shadcn/ui · TanStack Query · PWA
- **백엔드**: Spring Boot **Java 21** · Spring Security(JWT) · Spring Data JPA · PostgreSQL · Flyway · Actuator
- **실시간**: **SSE**(단일 스트림)
- **인프라**: **AWS Lightsail**(+ Nginx 리버스 프록시)
- **모니터링/로그**: **Sentry** (Phase A: Prometheus+Grafana)
- **보안**: HTTPS, CORS 화이트리스트, 레이트리밋(nginx 또는 Bucket4j 중 1)
- **캐시/세션/메시징**: **미도입**(단일 인스턴스 기준). 다중 인스턴스 전환 시 Redis(PubSub) 도입.

> 선택 근거: 초기 트래픽·운영 복잡도 최소화. 비용·학습부담 절감.

- 개발환경
- **M1 MacBook**
- **IntelliJ IDEA / VS Code**
- **Postman** – API 테스트
- **DBeaver** – DB 관리
- **Obsidian** – 설계/문서 관리

## 기능

### 관리자 공통

- **자원 관리**: 유닛 추가/편집/삭제, 유저 이용권한 할당.
- **자원 상태 일괄변경**: 다중 선택 → 상태 전환(냉장고 칸/세탁기/다목적실 공통).
- **벌점 조정**, **층별장을 기숙사생 내부에서 임명/해제**.
- **다목적실 강제 예약**: 날짜 제한 없이 날짜 예약가능
- **휴관 모드**:

    - 활성화 시 **일반 사용자 로그인 제한**.

    - 휴관 시작 시 **냉장고 물품 일괄 소프트 삭제**.

### 냉장고

- **사용자 기능**

    - 단일 품목 또는 여러 품목을 한 번에 등록하는 묶음 등록기능-> 등록시 식별번호 발급되고 사용자는 식별번호를 적은 스티커를 물품에 부착해야한다.

    - **번호 재사용**: 해당 번호가 `REMOVED`면 즉시 재사용 가능.

    - 조회: 기본 "내 물품", 필터(임박/만료), **식별번호 검색**.

    - 상태 변경: `부분 소비`, `전량 제거`

    - 물품정보 수정

- **층별장(검사자) 기능**

    - **검사 모드**: 검사 시작 시 해당 칸 **잠금**(사용자 수정 불가, TTL 5분).

    - **동시 검사**: 2명 동시 가능, **검사자별 처리 이력** 분리 기록.

    - **조치**: `⚠️ 경고`(정보 불일치/보관 불량/스티커 미부착-DB엔 존재), `🗑️ 폐기`(유통기한 지남/DB에 없는 미부착).

    - **미부착 처리**: 미등록 물품도 즉시 폐기 등록 가능.

    - **결과 제출/수정**: 제출 시 통계/알림 발송. **제출 후 수정 가능(이력기록)**.

### 6.2 세탁실 (상세구현에서 자세히 정의함)

### 6.3 도서관

- **사용자**: 제목/저자/도서번호 검색
- 인기/신규 탭(최근 N주 대출수·등록일 정렬)
- **원스톱 팝업**에서 대출/반납/연장/예약.
- **알림/벌점**: 반납일 **5일 전 알림**, 연체 시 **자동 벌점**.
- **경량화**: **예약 대기열은 1명만** 허용.
- 관리자 자원관리 상세정의: 도서 등록/수정/분실/삭제.

### 6.4 다목적실

- **타임라인 뷰**로 시간대별 예약 현황, **10분 단위** 예약.
- **예약 정책**: **매주 월요일** 해당 주간 예약 오픈.
- **합석**: **뱃지 표시만**(자동 매칭 보류).
- **신고**: 미등록사용/노쇼 **원클릭 신고** → 상대방 1회 알림 + **관리자 큐** 적재(벌점은 수동 처리).
- **강제 예약(관리자)**: 사용자 다이얼로그 **재사용** + 관리자 스위치.

### 6.5 마이페이지

- **간단 통계 위젯**: 이번 주 이용 횟수/시간, 벌점 변화(막대 2~3개, 쿼리/캐시 단순).
- **통합 이력**: 전체/세탁/도서/다목적실/냉장고/상벌점 필터. (성능 필요 시 상벌점 별도 페이지 분리 고려)
- **설정**: 상벌점 내역, 알림 수신 여부, 세탁 프리셋 등.
- 단일품목일시 단일품목단위/묶음일시 묶음 단위 고유 **식별번호 자동 발급**
- 단일품목: 이름, 메모, 유통기한 입력 수량은 1로 선택되어있음
- 이때 수량을 증가시키면 묶음이되고 세부수정 버튼이 활성화되고 숫자만큼 물품이 생성됨
- 기존입력했던 이름->묶음이름, 기존입력했던 메모->묶음메모
- 개별이름, 개별유통기한, 기존입력했던 이름, 유통기한으로 자동 입력되고 세부수정 버튼시 수정하고 최종 등록 가능
- 최근 검사일 이후 물품정보 수정시 다음 검사일때 자동분류됨

### 세탁실

- 사용자 흐름

    1. 세탁실 메인 페이지의 대시보드에서 **바로 사용 가능** 기기 상단 그룹 + 진행바/남은시간이 표시됨을 확인

    2. 기기클릭시 상세팝업이 뜨고: 

    - INUSE인 경우

    - 그 기기에대해 유저가 보낸 메세지 목록 표시

    - 사용중인 사람이 읽음 여부가 표시됨

- 자신이 설정에서 설정한 알림전송여부 간략히 표시
- 종료알림을 꺼놓았습니다. 라는 간단한 텍스트만 보이고 실제 수정은 설정앱에서 수정하게 하기

    - 타인의 사용인경우

    - 종료 알림 신청 또는 **남은시간 정정**(정정 시 원사용자에게 알림, 종료 알림 자동 보정).

    - 자신의 사용인경우

    - 남은시간 정정(알림x)

    - AVAILABLE 상태인경우

    - **사용 등록**: 기본시간(세탁기 38분 / 건조기 50분), **1분/10분 단위 증감**, 개인 **프리셋 저장**(옵션).

    - **미등록 사용(UNAUTHORIZED_USE)** 발견 시 대신 남은시간 등록(종료 알림 **기본 비활성**). 설정 시간 경과 시 자동 `AVAILABLE`.

    - 이전 사용자에게 다음엔 **필터 청소 요청**(필터 청소는 **건조기만** 해당)

- DONE인경우

    -  `DONE` 후 5분 경과 시

        - **"기다리고 있어요" 알림(1회성)** 또는 **"세탁물 빼놨어요" 알림**(+ 강제 `AVAILABLE`). 활성화

    3. **고장 신고**: 누구나 가능 → `ERROR_REPORTED`(사용 차단, 신고자/사유 기록). 관리자가 접수 시 `OUT_OF_SERVICE`.

- **상태 정의**

    - **기본**: `AVAILABLE` (사용 가능) → `IN_USE` (사용 중) → `DONE` (완료) → `AVAILABLE`

- 특수: `UNAUTHORIZED_USE`(미등록 사용 등록: 타임스탬프 경과 시 자동 복귀), `ERROR_REPORTED`(신고됨), `OUT_OF_SERVICE`(관리자 확정 비활성). `OUT_OF_SERVICE` (사용 중지)
- 관리자 수동 제어 시, 해당 기기 사용자에게 별도 알림 전송.
- **경량화/가드레일**

    - **남은시간 정정은 ±10분범위**

    - 관리자 수동 제어 시, 해당 기기 사용자에게 **별도 알림**.

## 알림구현

웹페이지는 메인화면, 냉장고,다목적실,도서관,세탁실메인화면으로 구성되어있다.

메인화면에는 당일 사용하는 다목적실의 정보와 현재 사용중/ 종료알림 신청한 세탁실기기의 정보와 메세지 읽음여부 표시하며 각 클릭시 해당 상태제어를 할수있는 버튼과 해당 기기에 관련된 알림/메세지가 표시되는 팝업이 뜬다.

알림을 표시하는건 4가지 방법이 있다

1. 백그라운드 푸시알림
2. 메인화면에서 다목적실, 세탁실기기의 메세지 읽음여부 표시 아이콘으로 기기 상태팝업으로 이동을 유도해 상세 팝업에서 메세지를 읽게함
3. 메인페이지의 종모양 알림버튼
4. 메인화면, 냉장고,다목적실,도서관,세탁실메인화면으로 이동하는 하단탭에서의 뱃지 표시

사용자가 **관련 정보에대해 파악했다고 판단가능한 페이지나 팝업에 진입하는 순간**, 시스템은 해당 알림을 자동으로 '읽음'으로 변경한다.

이미 관리자와 기숙사생들은 band라는 채팅, 게시물 앱으로 소통하고있다.

4가지 알림방법은 읽음 상태가 아닐때 활성화 할려고 한다. 해당알림을 유저의 피곤함 없이 어떻게 표시하려고 한 결과물은 다음과 같다

#### 4. 탭 읽음

- 값: 미읽음 수(최대 9+), 점 표시 허용.
- 규칙: 관련 화면 진입 시 소거. 24시간 경과 시 자동 만료 가능.
- 냉장고탭: (유통기한 임박 묶음이 있다면 오전 9시 이후 기준 1회/폐기물품이 있다면 영속)
- 도서관탭: (대출/도서/예약 임박 묶음이있다면 기준 1회(확인시 사라짐)/연체묶음이 있다면 영속)
- 냉장고: 임박 묶음은 매일 09:00 1회 생성 확인시 소거. 폐기 알림은 해제 전까지 유지.
- 도서관: 임박·당일·예약 가능 묶음은 매일 09:00 1회 생성 확인 시 소거. 연체는 해결 전까지 유지.

```sql
-- PostgreSQL ≥ 13
BEGIN;

-- =========================================================
-- [공통 확장] 텍스트 비교/부분검색
-- =========================================================
CREATE EXTENSION IF NOT EXISTS citext;   -- 대소문자 무시 문자열
CREATE EXTENSION IF NOT EXISTS pg_trgm;  -- TRGM 기반 부분 일치 검색
-- btree_gist는 미사용. EXCLUDE 제약 도입 시에만 설치.

-- =========================================================
-- [RBAC] 계정·권한 (MVP)
-- =========================================================
CREATE TABLE users (                               -- 사용자 기본
  user_id        BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username       CITEXT NOT NULL UNIQUE,           -- 로그인 ID(대소문자 무시)
  email          CITEXT UNIQUE,                    -- 이메일(선택)
  password_hash  TEXT   NOT NULL,                  -- 비밀번호 해시
  display_name   TEXT   NOT NULL,                  -- 표시명
  gender         TEXT   CHECK (gender IN ('M','F')),-- 향후 접근정책 확장용(선택)
  is_active      BOOLEAN NOT NULL DEFAULT TRUE,    -- 비활성 플래그
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE roles (                               -- 역할 마스터
  role_id  SMALLINT PRIMARY KEY,
  name     TEXT NOT NULL UNIQUE
           CHECK (name IN ('ADMIN_ROOT','ADMIN','INSPECTOR','RESIDENT'))
);
INSERT INTO roles(role_id,name) VALUES
 (0,'ADMIN_ROOT'),(1,'ADMIN'),(2,'INSPECTOR'),(3,'RESIDENT')
ON CONFLICT DO NOTHING;

CREATE TABLE user_roles (                          -- 사용자↔역할 N:M
  user_id BIGINT   NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  role_id SMALLINT NOT NULL REFERENCES roles(role_id),
  PRIMARY KEY (user_id, role_id)
);

-- =========================================================
-- [층/층별장] 거주 이력은 생략. “층”만 정의 + 층별장 2명 슬롯.
-- =========================================================
CREATE TABLE floors (                               -- 숙소 층
  floor_no SMALLINT PRIMARY KEY,                    -- 2,3,4,5
  gender   TEXT NOT NULL CHECK (gender IN ('M','F')) -- 해당 층 거주 성별(현실 규칙)
);
INSERT INTO floors(floor_no,gender) VALUES (2,'M'),(3,'F'),(4,'F'),(5,'F')
ON CONFLICT DO NOTHING;

CREATE TABLE floor_head_assignments (               -- 층별장 임명(동시 2명)
  assign_id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  floor_no    SMALLINT NOT NULL REFERENCES floors(floor_no),
  user_id     BIGINT   NOT NULL REFERENCES users(user_id),
  slot        SMALLINT NOT NULL CHECK (slot IN (1,2)), -- 2 슬롯 고정
  assigned_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  revoked_at  TIMESTAMPTZ                               -- NULL=활성
);
CREATE UNIQUE INDEX ux_floor_slot_active
  ON floor_head_assignments(floor_no, slot)
  WHERE revoked_at IS NULL;                              -- 슬롯당 활성 1명
CREATE UNIQUE INDEX ux_floor_head_user_active
  ON floor_head_assignments(floor_no, user_id)
  WHERE revoked_at IS NULL;                              -- 동일 유저 중복 방지

-- =========================================================
-- [자원 공통] 자원/상태스냅샷/이력 (세탁실·도서관 미도입이지만 공통 레일은 유지)
-- =========================================================
CREATE TABLE resources (                             -- 공용 자원(칸/기기/방 등)
  resource_id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  kind          TEXT NOT NULL CHECK (kind IN ('FRIDGE_COMPARTMENT')), -- MVP=칸만
  name          TEXT NOT NULL,                        -- 표기명(예: 냉장1)
  floor_no      SMALLINT REFERENCES floors(floor_no), -- 소속 층
  access_scope  TEXT NOT NULL DEFAULT 'ALL'           -- 이용 범위(확장 포인트)
                CHECK (access_scope IN ('MEN','WOMEN','ALL')),
  display_order SMALLINT,                             -- UI 정렬
  attrs         JSONB  NOT NULL DEFAULT '{}'::jsonb,  -- 가벼운 속성(JSON)
  is_active     BOOLEAN NOT NULL DEFAULT TRUE,        -- 사용/중지
  UNIQUE(kind, floor_no, name)
);

CREATE TABLE resource_status (                        -- 현재 상태 스냅샷
  resource_id BIGINT PRIMARY KEY
             REFERENCES resources(resource_id) ON DELETE CASCADE,
  status      TEXT NOT NULL CHECK (status IN
             ('AVAILABLE','IN_USE','DONE','UNAUTHORIZED_USE','ERROR_REPORTED','OUT_OF_SERVICE')),
  since       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_resource_status_status ON resource_status(status); -- 상태별 조회

CREATE TABLE resource_status_events (                 -- 상태 변경 이력(append-only)
  event_id      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  resource_id   BIGINT NOT NULL
               REFERENCES resources(resource_id) ON DELETE CASCADE,
  from_status   TEXT,
  to_status     TEXT NOT NULL,
  actor_user_id BIGINT REFERENCES users(user_id),     -- 조작자(NULL=시스템)
  payload       JSONB NOT NULL DEFAULT '{}'::jsonb,   -- 사유/메모 등
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_rse_resource ON resource_status_events(resource_id, created_at DESC);

-- [트리거] 자원 생성 시 스냅샷 초기화(AVAILABLE)
CREATE OR REPLACE FUNCTION trg_resources_init_status() RETURNS trigger AS $$
BEGIN
  INSERT INTO resource_status(resource_id, status, since)
  VALUES (NEW.resource_id, 'AVAILABLE', now())
  ON CONFLICT (resource_id) DO NOTHING;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS resources_init_status ON resources;
CREATE TRIGGER resources_init_status
AFTER INSERT ON resources
FOR EACH ROW EXECUTE FUNCTION trg_resources_init_status();

-- [트리거] 이력 입력 → 스냅샷 동기화
CREATE OR REPLACE FUNCTION trg_rse_apply_snapshot() RETURNS trigger AS $$
BEGIN
  INSERT INTO resource_status(resource_id, status, since)
  VALUES (NEW.resource_id, NEW.to_status, NEW.created_at)
  ON CONFLICT (resource_id)
  DO UPDATE SET status = EXCLUDED.status, since = EXCLUDED.since;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS rse_apply_snapshot ON resource_status_events;
CREATE TRIGGER rse_apply_snapshot
AFTER INSERT ON resource_status_events
FOR EACH ROW EXECUTE FUNCTION trg_rse_apply_snapshot();

-- =========================================================
-- [냉장고] 층별 냉장고 + 칸(자원 자동 매핑)
--   * “층=접근범위”만 사용. 1층당 냉장칸×3, 냉동칸×1 시드.
-- =========================================================
CREATE TABLE fridges (                                -- 층별 냉장고(1대 권장)
  fridge_id  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  floor_no   SMALLINT NOT NULL UNIQUE REFERENCES floors(floor_no),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
INSERT INTO fridges(floor_no) VALUES (2),(3),(4),(5)
ON CONFLICT DO NOTHING;

CREATE TABLE compartments (                            -- 냉장고 칸
  compartment_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  fridge_id      BIGINT  NOT NULL
                 REFERENCES fridges(fridge_id) ON DELETE CASCADE, -- 냉장고 삭제 시 칸 삭제
  position_order SMALLINT NOT NULL CHECK (position_order >= 1),   -- 1..N
  kind           TEXT    NOT NULL CHECK (kind IN ('FRIDGE','FREEZER')),
  name           TEXT,                                           -- 예: 냉장1, 냉동
  resource_id    BIGINT                                          -- resources와 1:1
);
CREATE UNIQUE INDEX uq_freezer_per_fridge
  ON compartments(fridge_id) WHERE kind='FREEZER';                -- 냉동칸 1개 제한

-- [트리거] 칸 INSERT 시 resources 자동 생성 및 연결
CREATE OR REPLACE FUNCTION compartment_autoresource_ins() RETURNS trigger AS $$
DECLARE v_floor smallint; v_name text; v_res bigint;
BEGIN
  SELECT floor_no INTO v_floor FROM fridges WHERE fridge_id = NEW.fridge_id;
  v_name := COALESCE(NEW.name,
            CASE WHEN NEW.kind='FRIDGE' THEN '냉장' || NEW.position_order ELSE '냉동' END);

  INSERT INTO resources(kind, name, floor_no, display_order, access_scope, attrs)
  VALUES ('FRIDGE_COMPARTMENT', v_name, v_floor, NEW.position_order, 'ALL', '{}'::jsonb)
  RETURNING resource_id INTO v_res;

  NEW.resource_id := v_res;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_compartment_autoresource_ins ON compartments;
CREATE TRIGGER trg_compartment_autoresource_ins
BEFORE INSERT ON compartments
FOR EACH ROW
WHEN (NEW.resource_id IS NULL)
EXECUTE FUNCTION compartment_autoresource_ins();

-- [트리거] 칸 정보 변경 → 자원 동기화
CREATE OR REPLACE FUNCTION compartment_autoresource_upd() RETURNS trigger AS $$
DECLARE v_floor smallint; v_name text;
BEGIN
  SELECT floor_no INTO v_floor FROM fridges WHERE fridge_id = NEW.fridge_id;
  v_name := COALESCE(NEW.name,
            CASE WHEN NEW.kind='FRIDGE' THEN '냉장' || NEW.position_order ELSE '냉동' END);

  UPDATE resources
     SET name = v_name,
         floor_no = v_floor,
         display_order = NEW.position_order
   WHERE resource_id = NEW.resource_id;

  RETURN NEW;
END $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_compartment_autoresource_upd ON compartments;
CREATE TRIGGER trg_compartment_autoresource_upd
AFTER UPDATE OF name, position_order, kind ON compartments
FOR EACH ROW
WHEN (NEW.resource_id IS NOT NULL)
EXECUTE FUNCTION compartment_autoresource_upd();

-- [시드] 각 층 냉장칸×3 + 냉동칸×1 생성
INSERT INTO compartments (fridge_id, position_order, kind, name)
SELECT fr.fridge_id, pos,
       CASE WHEN pos <= 3 THEN 'FRIDGE' ELSE 'FREEZER' END,
       CASE WHEN pos <= 3 THEN CONCAT('냉장',pos) ELSE '냉동' END
FROM fridges fr
CROSS JOIN generate_series(1,4) AS pos
ON CONFLICT DO NOTHING;

ALTER TABLE compartments

ALTER TABLE compartments
  ADD CONSTRAINT fk_comp_resource FOREIGN KEY (resource_id)
  REFERENCES resources(resource_id) ON DELETE CASCADE; -- 칸 삭제 시 자원도 정리
ALTER TABLE compartments
  ADD CONSTRAINT uq_comp_resource UNIQUE(resource_id);

  group_note     TEXT,

-- [트리거] 라벨 short_code 유지(칸 position_order + label_no)
CREATE OR REPLACE FUNCTION fn_compute_shortcode(p_compartment_id BIGINT, p_label INT)
RETURNS TEXT LANGUAGE plpgsql STABLE AS $$
DECLARE v_pos SMALLINT;
BEGIN
  SELECT position_order INTO v_pos FROM compartments WHERE compartment_id = p_compartment_id;
  IF v_pos IS NULL THEN
    RETURN NULL;
  END IF;
  RETURN v_pos::text || lpad(p_label::text, 3, '0');
END $$;

CREATE OR REPLACE FUNCTION trg_ig_set_shortcode() RETURNS trigger AS $$
BEGIN
  NEW.short_code := fn_compute_shortcode(NEW.compartment_id, NEW.label_no);
  RETURN NEW;
END $$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS ig_set_shortcode ON item_groups;
CREATE TRIGGER ig_set_shortcode
BEFORE INSERT OR UPDATE OF compartment_id, label_no ON item_groups
FOR EACH ROW EXECUTE FUNCTION trg_ig_set_shortcode();

-- [트리거] 칸 번호 변경 시 관련 라벨 short_code 갱신
CREATE OR REPLACE FUNCTION trg_comp_update_shortcode() RETURNS trigger AS $$
BEGIN
  IF NEW.position_order <> OLD.position_order THEN
    UPDATE item_groups ig
       SET short_code = fn_compute_shortcode(ig.compartment_id, ig.label_no)
     WHERE ig.compartment_id = NEW.compartment_id;
  END IF;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER comp_update_shortcode
AFTER UPDATE OF position_order ON compartments
FOR EACH ROW EXECUTE FUNCTION trg_comp_update_shortcode();

-- [권한 트리거] 해당 층 층별장 또는 ADMIN만 세션 생성
CREATE OR REPLACE FUNCTION trg_inspection_auth() RETURNS trigger AS $$
DECLARE v_floor smallint; v_is_head int; v_is_admin int;
BEGIN
  SELECT f.floor_no INTO v_floor
  FROM compartments c JOIN fridges f ON f.fridge_id = c.fridge_id
  WHERE c.compartment_id = NEW.compartment_id;

  SELECT COUNT(*) INTO v_is_head
  FROM floor_head_assignments
  WHERE floor_no = v_floor AND user_id = NEW.inspector_id AND revoked_at IS NULL;

  SELECT COUNT(*) INTO v_is_admin
  FROM user_roles ur JOIN roles r ON r.role_id = ur.role_id
  WHERE ur.user_id = NEW.inspector_id AND r.name IN ('ADMIN','ADMIN_ROOT');

  IF v_is_head = 0 AND v_is_admin = 0 THEN
    RAISE EXCEPTION 'inspector % is not authorized for floor %', NEW.inspector_id, v_floor;
  END IF;
  RETURN NEW;
END $$ LANGUAGE plpgsql;
```
