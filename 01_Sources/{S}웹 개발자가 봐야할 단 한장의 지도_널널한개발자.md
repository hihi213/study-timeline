### **3. 작성하신 내용의 기술적 교정**

작성해주신 메모에서 **오개념을 바로잡아** 정리하면 다음과 같습니다.

- **"URL은 컴퓨터 구분, URI는 내부 식별" (X) → 수정 (O)**
    - **URL** 전체가 '인터넷상의 자원 위치'를 나타냅니다.
    - URL의 **도메인(Host)** 부분이 네트워크상의 **컴퓨터(서버)를 식별**합니다.
    - URL의 **경로(Path)** 부분이 컴퓨터 **내부의 특정 리소스**를 식별합니다.
- **"웹에서 리소스란 파일이다" (△) → 수정 (O)**
    - 초기 웹에서는 `.html`, `.jpg` 같은 실제 **파일**을 의미했습니다.
    - 현대의 웹(REST API 등)에서는 파일뿐만 아니라 데이터베이스의 데이터, 서비스의 기능 등 **추상적인 정보 단위**를 모두 리소스라고 부릅니다.

### **1. 리소스 (Resource)**
과거 웹에선 컴퓨터의 리소스란 파일로, 식별하고자 하는 **정보 생성의 기본 단위**
> 원래 리소스는 데이터, 서비스 등 모든 자원을 뜻하지만, 현재는 이해를 돕기 위해 **'파일'**로 간주합니다.
### **2. URI와 URL의 관계**

리소스를 가리키는 주소 체계의 포함 관계입니다.

- **구조**: **URI ⊃ URL** (URI가 상위 개념)
- **URI (Uniform Resource Identifier)**: 위치(URL) + 이름(URN) 식별방식
	- 인터넷상에서 리소스를 고유하게 **식별(Identifier)** 하는 방식.
- **URL (Uniform Resource Locator)**: 특정한 파일 위치
	- 리소스의 식별을 '위치'로 하는 방식
	- "저 컴퓨터의 저 폴더에 있는 저 파일"이라고 **위치 전체를 다 가리키는 것** (컴퓨터 + 내부 위치)
- URN (Uniform Resource Name): 특정한 파일의 고유 이름
	- 리소스의 식별을 **'이름'**으로 하는 방식
	- **위치(URL)가 바뀌어도 변하지 않는 고유한 ID**
	    - 파일이 다른 폴더나 서버로 이사를 가도(URL 변경), 그 파일 자체의 고유한 이름(URN)은 그대로 유지됨.
	    - **예시**: 책의 **ISBN** (어느 서점(URL)에 있든 책의 고유 번호(URN)는 똑같음)

### **3. URL의 구성 요소와 식별 단계**

URL은 **`프로토콜://호스트/경로`** 구조를 통해, 먼저 컴퓨터를 찾고 그 안의 리소스를 찾는 순서로 동작합니다.

| **단계** | **구성 요소 (예시)**                      | **식별 대상**    | **기술적 동작 원리**                                                                                           |
| ------ | ----------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------- |
| **1**  | **호스트** (Host)<br>`www.naver.com`   | **컴퓨터 (서버)** | • **외부 식별**: 인터넷 네트워크상에서 특정 컴퓨터(서버) 한 대를 찾습니다.<br><br>• DNS를 통해 도메인이 **IP 주소**로 변환됩니다.                  |
| **2**  | **경로** (Path)<br>`/news/index.html` | **내부 리소스**   | • **내부 식별**: 찾아낸 서버 내부에서 구체적인 자원을 가리킵니다.<br>• 운영체제의 절대 경로(예: `C:\Data\...`) 개념이 웹 서버의 논리적 주소로 매핑된 것입니다. |

> 참고 (경로의 생략)
>
> www.naver.com처럼 뒤의 구체적인 파일명(index.html)을 생략해도 접속되는 이유는 웹 서버의 설정(Directory Index) 때문입니다. 서버는 경로까지만 요청받을 경우 약속된 기본 파일을 자동으로 응답합니다.
