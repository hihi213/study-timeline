# 냉장고 시스템 과업지시서

> **목표 요약**: 10주 안에 "냉장고 모듈"을 단독 운영 가능한 수준(MVP)으로 구현한다. **Week1**에 로그인(최소)과 RBAC 훅을 마련해 물품/검사/벌점 개발이 바로 가능하도록 하고, **Week8–10** 안정화 이후 여유가 있으면 회원가입을 도입한다(데모는 회원가입 없이도 가능).

---

## 0. 전제(이미 준비되었다고 가정)

- 설정 분리: `application-{local,dev,prod}.yml`과 비밀정보 분리
    
- 인증/인가: JWT(Access/Refresh) + RBAC(`ADMIN/INSPECTOR/USER`)
    
- 공통 응답/전역 예외 처리, Swagger/OpenAPI 자동 문서
    
- PWA 지원(오프라인/푸시 알림) — 본 과업은 **알림 파이프라인은 모의(옵션)**
    

> **주의**: 본 문서에서는 Week1에 **로그인(최소)** 구현을 과업으로 포함함. (회원가입은 Week8–10 옵션)

---

## 1. 범위(스코프)

### 1.1 반드시 포함(MVP)

- **층/호실/칸** 모델링: 한 층당 `R1, R2, R3, F1` (냉장/냉동 구획)
    
- **식별 규칙**: 표시 문자열 `{칸라벨}-{###}` (예: `R1-123`), 스티커는 **숫자만**
    
- **아이템**: 묶음(bundle)과 서브아이템(sub_items), `status='ACTIVE'`에서 **(compartment_id, item_number) 부분 유니크**
    
- **사용자 기능**: 등록/조회, 프리셋 액션 `ADJUST`(일부 소비) / `REMOVE_ALL`(전량 제거) / `REPLACE`
    
- **검사(inspection_session)**: 참여자 ≤ 2명, 태그(유통기한 지남 / 세션 시작 이후 변경), 세션 중 해당 **층 쓰기 423 차단**, 조치 `[통과/경고/폐기(+벌점)/스티커 미부착 폐기]`, **단일 제출자** 집계/알림(모의)
    
- **벌점 정책**: 제출로 생성된 **원본 벌점은 불변**, `ADMIN`만 **조정(delta)**, 최종=원본+조정합
    
- **이벤트/로그 영구보존**: `domain_events`(상태 변화 사실) / `activity_logs`(누가, 무엇을, 결과)
    
- **번호 충돌/이동**: `MOVE` 시 충돌 → `AUTORENUMBER` 또는 `409`; `REPLACE`는 **동일 칸만**
    
- **휴관(maintenance)**: 휴관 중 USER/INSPECTOR 로그인 차단(ADMIN만), 휴관 시작 시 **물품 일괄 소프트 삭제 배치** 실행
    

### 1.2 제외(포스트-MVP)

- 실시간 채널 기본화(SSE/웹소켓) — **폴링 기본**
    
- 고급 리포트/CSV 내보내기, 대량 업로드
    
- 고급 알림 시나리오(실 FCM 연동) — 기본은 **아웃박스에 모의 SENT** 기록

## 3. 핵심 정책(놓치면 안 되는 규칙)

- **식별/유일성**: 표시 `{라벨}-{###}`; `(compartment_id, item_number)`는 `status='ACTIVE'`에서만 유니크
    
- **번호 이동**: `MOVE` 충돌 시 `AUTORENUMBER` or **409**; `REPLACE`는 동일 칸만
    
- **검사**: 세션 당 참여자 ≤ 2; 세션 중 해당 층 사용자 **쓰기 423**; **단일 제출자**
    
- **벌점**: 제출로 생성된 **원본**은 불변; `ADMIN`만 **조정** 가능; 합산 = 원본+조정합
    
- **삭제**: 묶음/서브아이템은 **소프트 삭제**, 로그/이벤트는 영구보존(FK `SET NULL`)
    
- **휴관**: USER/INSPECTOR 로그인 차단, ADMIN만; 시작 시 물품 **일괄 소프트삭제 배치**
    
- **D-Day 색상**: 정상=emerald, 임박(오늘/D-1)=amber, 만료=D+N=rose

## 4. 데이터 모델(요약 스펙)

> 상세 ERD는 리포지토리 `/docs/erd/`에 포함. 아래는 핵심 제약만 발췌.

- `bundles`: id, user_id, compartment_id, item_number(###), name, expires_at, status(`ACTIVE|REMOVED`), deleted_at
    
    - **부분 유니크**: (compartment_id, item_number) WHERE status='ACTIVE'
        
- `sub_items`: id, bundle_id(FK), qty, unit, deleted_at
    
- `inspection_sessions`: id, floor_id, started_at, submitted_at(NULL이면 진행중), created_by
    
    - **층별 동시 진행 1개 선택**(비즈니스 규칙), 참여자 테이블로 ≤ 2명 강제
        
- `inspection_actions`: id, session_id, bundle_id(NULL 허용: 스티커 미부착), actor_id, outcome, reason, created_at
    
- `penalties_original`: id, user_id, session_id, points, reason, created_at (**불변**)
    
- `penalties_adjustments`: id, user_id, delta, reason, created_by, created_at
    
- `domain_events`: id, type, payload(jsonb), actor_id NULL, resource_ref, created_at (**영구**)
    
- `activity_logs`: id, actor_id, action, target, result, ip, ua, created_at (**영구**)

## 5. API 계약(요약)

- **인증**: Bearer JWT
    
- **공통 에러**: 400/401/403/404/409/422/423 — 본문 `{code, message, details?}`
    

### 5.1 Bundles

- `POST /api/fridge/bundles` → 201
    
- `GET /api/fridge/bundles?mine=&floor=&compartment=&q=` → 200
    
- `POST /api/fridge/bundles/{id}/adjust|remove-all|replace` → 200
    
- `POST /api/fridge/bundles/{id}/move` {target_compartment, strategy} → 200/409
    

### 5.2 Inspection

- `POST /api/inspections/sessions` {floor_id} → 201
    
- `POST /api/inspections/{id}/join|leave` → 200/409
    
- `GET /api/inspections/{id}/items?tag=expired|changed_since` → 200
    
- `POST /api/inspections/{id}/actions` → 201
    
- `POST /api/inspections/{id}/submit` → 200/409 (단일 제출자)
    

### 5.3 Penalties & Logs

- `GET /api/penalties?user=me` → 200 (합산)
    
- `POST /api/admin/penalties/{userId}/adjustments` → 201 (ADMIN)
    
- `GET /api/admin/logs/{activity|events}` → 200
    

### 5.4 Maintenance

- `POST /api/admin/maintenance/start|end` → 200 (시작 시 일괄 소프트삭제 배치 트리거)

- 성능: 목록/태그 조회 p95 < 300ms(@dev 기준), 오류율 < 1%
    
- 동시성: 검사 세션 참여 경합에서 **≤ 2 보장**, 세션 중 층 쓰기 423
    
- 보안: 역할 기반 인가(@PreAuthorize), 관리자 엔드포인트 분리(`/api/admin/**`)

- 이식성: Docker Compose 로컬 기동 스크립트 제공

## 8. 시연(데모) 시나리오

1. 시드 로드(층 2F/3F, `R1,R2,R3,F1`, 계정 3종)
    
2. 사용자 A: R1-123 등록(D+1), 사용자 B: R2-045 등록(D-1)
    
3. 검사 세션(3F) 생성 → 두 INSPECTOR 동시 참여
    
4. `expired` 필터 → B 항목 **폐기(+벌점)**
    
5. 스티커 없는 물품 → **임시 등록 후 즉시 폐기**
    
6. **제출(단일 제출자)** → 벌점 원본 생성, 알림(모의 SENT) 기록
    
7. 벌점 화면에서 합산 확인 → ADMIN **조정** 추가 후 합산 변경
    
8. 번호 충돌 시연: C가 R1-123 등록 시도 → 409 → `AUTORENUMBER` 성공
    
9. 휴관 on → USER/INSPECTOR 로그인 차단, ADMIN만 허용
    
10. 로그/이벤트 조회로 조치/벌점/알림 기록 확인
