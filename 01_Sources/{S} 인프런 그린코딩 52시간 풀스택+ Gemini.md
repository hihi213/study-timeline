- **영역 간의 통신 방식**

		- **백엔드 ↔ 데이터베이스**  
			- '데이터베이스 커넥션'라는 논리적인 통로를 통해 연결되며, **SQL 쿼리**로 직접 통신합니다.
			- 데이터베이스 커넥션
				- 애플리케이션이 데이터베이스 서버와 통신하여 SQL 쿼리를 보내고 그 결과를 받아올 수 있도록 하는 전용 통신 링크입니다. 
				- 보안을 위해 애플리케이션은 반드시 이 커넥션을 통해서만 데이터베이스에 명령을 내릴 수 있습니다.
		- **프론트엔드 ↔ 백엔드**
			- HTTP/HTTPS라는 '공통 언어'로 연결되며, 이때 교환되는 데이터의 형식과 절차는 API라는 구체적인 인터페이스 규칙에 따라 정의된다
	- HTTP/HTTPS: 웹의 공용어  
		- HTTP(HyperText Transfer Protocol)는 웹 브라우저와 서버가 데이터를 주고받기 위해 사용하는 **기본적인 약속이자 언어**입니다. 이 언어는 다음과 같은 보편적인 문법 규칙을 가집니다.
		- 1. **메시지 구조**: 요청과 응답이 따라야 하는 정해진 양식
			- 요청과 응답은 각각 정해진 순서(시작 줄, 헤더, 본문)를 가집니다.
		- 2. **요청 메소드** : 행동을 나타내는 동사 
			- `GET`(조회), `POST`(생성), `PUT`(수정), `DELETE`(삭제) 등 어떤 행동을 할지 나타냅니다.
		- 3. **상태 코드**: 요청에 대한 결과
			- `200 OK`(성공), `404 Not Found`(찾을 수 없음), `500 Server Error`(서버 문제) 등 요청에 대한 결과를 알려줍니다.
	- API: 복잡한 시스템의 내부를 숨기고, 외부와는 정해진 방식으로만 소통하게 해주는 **'인터페이스'** 제공이 존재 목적
		- API는 **한 프로그램이 다른 프로그램의 기능이나 데이터가 필요한 모든 순간**에 동작하는 필수적인 소통 창구 인터페이스이다.
			- API가 없던 시절, 프로그램들은 서로 **독립적인 섬**과 같았습니다. 다른 프로그램의 기능을 사용하려면, 그 내부 데이터베이스 구조나 코드를 직접 알아야 했습니다. 이는 매우 비효율적이고 보안에도 심각한 문제를 야기했습니다.
			-  API는 이 문제를 해결하기 위해 각 서비스가 제공하는 **공식 '메뉴판'이자 '리모컨'**과 같은 역할을 합니다. 우리는 TV 내부 회로를 몰라도 리모컨 버튼만 누르면 기능을 사용하듯, 개발자는 다른 서비스의 내부를 몰라도 **API라는 약속된 접점(Interface)**을 통해 원하는 기능을 안전하고 쉽게 연결할 수 있습니다.
				-  즉, **HTTP가 언어의 문법이라면, API는 그 언어로 작성된 '주문서' 또는 '사용 설명서'**와 같습니다.
		- API는 HTTP라는 포괄적인 통신 규칙을 기반으로, 다음과 같은 구체적인 세부 규칙을 정의하여 명확한 인터페이스를 만듭니다.
			- **엔드포인트 (Endpoint)**: 어디로 요청할 것인가?
				- 기능에 접근할 수 있는 고유한 주소(URL)입니다.
				- `https://api.example.com/users`와 같이 HTTP만으로는 알 수 없는 **'어디로'** 요청해야 하는지에 대한 정보를 제공합니다.
			- **데이터 형식** (Data Format): 무엇을 주고받을 것인가?
				- 요청하고 응답받을 데이터의 구체적인 구조입니다.
				- 주로 **JSON (`{ "key": "value" }`)** 형식을 사용하며, **'무엇을'** 보내고 받아야 하는지를 명확히 합니다.
			- **요청 메소드 규칙(Method Rules)**:어떻게 요청할 것인가?
				- 특정 엔드포인트에 어떤 HTTP 메소드를 사용해야 하는지를 정의합니다.
				- 예: 사용자 정보 조회는 `GET`, 신규 사용자 생성은 `POST`를 사용하도록 약속합니다.
		- **데이터 전송**
			- 위 정보들을 담은 데이터 집합체가 API 규칙에 따라 프론트엔드와 백엔드 사이를 오고 갑니다.
- **각 영역별 기술 스택**
	- 각 영역은 자신의 역할에 가장 적합한 다른 컴퓨터 언어와 기술을 사용합니다.
		- **프론트엔드**: **JavaScript**
		- **백엔드**: **Java**, Python, Node.js 등
		- **데이터베이스**: **SQL** (MySQL, PostgreSQL과 같은 시스템에서 사용)            
- **주소(URL)와 로컬호스트**
	- 데이터는 출발지와 도착지가 필요하며, 이는 **URL**로 표현됩니다.
	- 개발 환경에서 각 영역은 고유한 주소(URL)를 가집니다.
		- **프론트엔드**: `localhost:5500`
		- **백엔드**: `localhost:8080`
		- **데이터베이스**: `localhost:3306`
	- **`localhost`**는 '내 컴퓨터'를 의미하며, 서버 소프트웨어를 설치하면 개인 컴퓨터도 서버 역할을 수행할 수 있습니다

- **백엔드 (Backend)**: 화면 뒤에서 데이터를 처리하는 서버.

    - **주소 예시**: `localhost:8080`
        
- **데이터베이스 (Database)**: 데이터 저장하는 창고.
    - **역할**: 모든 데이터의 영구적인 저장 및 관리

    - **관리 도구**: MySQL Workbench
    - **주소 예시**: `localhost:3306` (MySQL 기준)

### 3. API, CSR, SSR의 관계
분리된 프론트엔드와 백엔드가 통신하기 위해 **API(Application Programming Interface)**라는 통신 규칙이 필요합니다. 이 API를 활용하는 방식은 서버가 브라우저에 무엇을 보내주는지에 따라 나뉩니다
- **데이터 흐름**: 프론트엔드는 API 규칙에 따라 데이터를 요청하고, 백엔드는 이 요청을 받아 데이터를 가공(처리)하여 데이터베이스와 통신한 후, 그 결과를 다시 프론트엔드에 전달합니다.

- **SSR (Server-Side Rendering)**  **완성된 웹 페이지(HTML)를** 보낸다
	- 동작 방식: 서버가 데이터베이스 조회와 데이터 가공을 모두 마친 후, **완성된 HTML 문서**를 만들어 브라우저에 전달합니다.
	- 브라우저는 API를 호출할 필요 없어 첫 페이지 로딩이 빠릅니다.
    - 전통적인 웹 개발 방식(SI 업체, 전자정부프레임워크 등)에서 많이 사용됩니다
    
- **CSR (Client-Side Rendering)**: **순수한 데이터(JSON)를** 받는다
	- **동작 방식**:브라우저가 API를 통해 서버로부터 **JSON 형태의 데이터**만 받은 뒤, 자바스크립트를 사용해 직접 화면을 그립니다.
	- **주요 기술**: 이 방식에서는 주로 **REST API**라는 설계 스타일을 따르며, **JSON** 데이터 형식을 사용합니다.
		- RestAPI: 자원을 URL로 표현하고, HTTP Method(GET, POST 등)로 해당 자원을 다루는 방식을 말합니다.
		- **JSON**: REST API를 통해 데이터를 주고받을 때 사용하는 가벼운 텍스트 형식(`{key:value}`)입니다
	- 프론트엔드와 백엔드가 명확히 분리되며, 최신 웹 앱(메타, 스타트업 등)에서 많이 사용됨 (대기업, 스타트업)

### 4. 백엔드 개발의 핵심 패러다임: 객체 지향 프로그래밍 (OOP)
백엔드를 구성하는 Java와 같은 언어는 객체 지향 프로그래밍이라는 설계 철학을 따릅니다.
- **객체 지향 프로그래밍(OOP)이란?** 현실 세계의 사물이나 개념을 **'객체(Object)로'**  모델링하여 프로그램을 만드는 방식입니다. 이때 객체는 관련된 **데이터(속성)와** **행동(메서드)을** 하나로 묶은 단위입니다.
    - **비유**: '붕어빵 틀'이 **클래스(Class, 설계도)이고**, 그 틀로 찍어낸 '붕어빵'이 **객체(Object, 실제 제품)입니다.**
- **OOP의 목적** OOP는 코드를 재사용하고, 관련 기능들을 덩어리로 묶어 **관리를 쉽게** 하며, 프로그램을 더 안정적이고 논리적으로 만들기 위해 사용됩니다. Java가 보안에 강하고 안정적인 이유도 이러한 객체 지향 설계의 특징(예: 캡슐화) 덕분입니다.

	- **`<table>`** 표 전체를 감싸는 컨테이너
		- **`<tr>` (Table Row)** 표 안의 **가로 한 줄(행)**을 만듭니다. _(엑셀 비유: 1행, 2행 등 가로 한 줄)_
		- **`<td>` (Table Data)** 행(`<tr>`) 안에 들어가는 각각의 **셀(칸)**을 만듭니다. 실제 내용이 이 안에 들어갑니다. _(엑셀 비유: A1, B1 등 개별 칸)_
		    - **`colspan` 속성**: 하나의 셀이 지정된 숫자만큼 **여러 개의 가로 칸(열)을 합치도록** 만듭니다. 엑셀의 '셀 병합'과 같습니다.
- **`<ul>` (Unordered List)** 순서가 중요하지 않은 목록 전체를 감싸는 컨테이너 태그입니다.
- **`<ol>` (Ordered List)** 순서가 중요한 목록 전체를 감싸는 컨테이너 태그로, 일반적으로 숫자나 알파벳으로 순서가 매겨집니다.
	- **`<li>` (List Item)** `<ul>`이나 `<ol>` 내부에 사용되어 목록의 개별 항목을 정의합니다.
		- **목록 스타일 변경** CSS의 `list-style` 속성을 사용하면 목록 항목 앞에 붙는 기호(마커)를 변경하거나 `none` 값으로 제거할 수 있습니다
		- **중첩 목록 (Nested Lists)** `<li>` 태그 내부에 다른 `<ul>`이나 `<ol>`을 포함시켜 계층적인 목록 구조를 만들 수 있습니다
		- **`document.createElement("li")`**: `<li>` 태그에 해당하는 새로운 DOM 요소(객체)를 메모리에 생성합니다.
		- **`listItem.innerText = "명언"`**: 생성된 `<li>` 요소 객체에 "명언"이라는 텍스트 내용을 추가합니다. (`<li>명언</li>` 형태가 됨)
		- **`listElement.appendChild(listItem)`**: `listItem` 요소를 `listElement`(`<ul>` 등)의 마지막 자식으로 추가하여 화면에 실제로 보이게 합니다.

- ##### 1. css박스모델: 태그 크기를 표현하는 디자인적 요소
	- content: 내용물
	- padding: 뽁뽁이
	- border: 상자 두께
	- margin: 다른 상자들 사이의 간격
- ##### 2. `box-sizing`: 박스 크기 계산 방식
	요소의 `width`와 `height`를 어디까지 계산할지 정하는 속성입니다.
	- **`content-box` (기본값)**: content 자체 크기로 width, height가 매겨짐(Padding과 Border가 추가되면 박스 크기가 늘어남)
	- **`border-box`**: Padding과 border를 포함한 크기로 width, height가 매겨짐
		- 대부분의 경우 이 방식을 사용하면 레이아웃을 예측하기 쉬워 개발이 편리해집니다.
	-  하위태그는 부모설정을 따라간다
- ##### 3. display 속성: 요소의 배치 방식
	- 태그마다 display 기본 설정이 다르기 때문에 블로그 찾아가서 알아내기
	- **`block`**
	    - 항상 **새로운 줄**에서 시작하며, 가로 너비 전체(100%)를 차지합니다.
	    - `width`, `height`, `margin`, `padding` 속성을 모두 자유롭게 사용할 수 있습니다.
	- **`inline`**
	    - 줄을 바꾸지 않고, 문장의 일부처럼 다른 요소와 **같은 줄**에 배치됩니다.
	    - `width`와 `height` 속성이 **적용되지 않습니다.**
	- **`inline-block`**
	    - `inline`처럼 같은 줄에 배치되지만, `block`처럼 `width`, `height` 속성을 자유롭게 사용할 수 있습니다.
- ##### 4. position: 태그 위치 지정 속성
	- CSS `position` 속성은 `top`, `left`, `right`, `bottom` 좌표 속성과 함께 사용하여 요소의 위치를 정밀하게 제어합니다. 좌표를 적용하려면, `position` 값을 기본값인 `static`이 아닌 다른 값으로 변경해야 합니다.
	- `static` (기본값)
		- 모든 요소의 기본값으로, 일반적인 문서 흐름에 따라 배치됩니다.
		- `top`, `left` 등의 **좌표 속성이 적용되지 않습니다.**
	- relative : 
		- **원래 자신이 있던 위치**를 기준으로 좌표가 적용됩니다.
		- 다른 요소에 영향을 주지 않고 자기 자리에서만 살짝 이동하고 싶을 때 사용합니다.
	- absolute : 
		- **`position`이 `static`이 아닌 가장 가까운 부모 요소**를 기준으로 좌표가 적용됩니다.
		- 만약 기준이 될 부모가 없으면, 문서 전체(`body`)가 기준이 됩니다.
	- fixed: 스크롤을 내려도 계속 그위치를 고수하는 포지션
- ##### 5. Flexbox: 자식 요소 정렬하기
	Flexbox는 **부모 요소(Flex Container)**에 `display: flex;`를 적용하여, 그 안의 **자식 요소(Flex Items)**들을 쉽고 유연하게 정렬하는 방식입니다.
	
	`display: flex;`를 적용하면 부모 컨테이너는 여전히 **블록 레벨 요소**로서 **자신이 위치한 가로 공간을 100% 차지**하게 됩니다. 이는 Flex Container가 자식 요소들을 정렬할 수 있는 **넓은 기준 공간**을 확보한다는 의미이며, 이를 바탕으로 `justify-content` (가로 정렬)와 `align-items` (세로 정렬) 등의 속성을 사용하여 자식 요소들을 원하는 방식으로 배치할 수 있게 됩니다.
	- **`justify-content`**: 메인 축(**가로**) 정렬
	    - 자식 요소들을 **수평 방향**으로 어떻게 정렬할지 결정합니다.
	    - **주요 값**: `center`(가운데), `flex-start`(시작점), `flex-end`(끝점), `space-between`(양 끝에 붙고 사이 간격 동일) 등
	- **`align-items`**: 교차 축(**세로**) 정렬
	    - 자식 요소들을 **수직 방향**으로 어떻게 정렬할지 결정합니다.
	    - **주요 값**: `center`(가운데), `flex-start`(시작점), `flex-end`(끝점) 등
	    - **참고**: `align-items: center`가 제대로 동작하려면, 부모 컨테이너에 정렬할 수 있는 `height` 값이 있어야 합니다.
- 높이는 Vh를 사용하자
	- `100vh`는 현재 보이는 브라우저 화면의 전체 높이
- .클래스:focus
	- 포커스됐을때의 속성 조절

	-  **너비(width)가 지정된 block 요소를 부모 요소 안에서 수평으로 가운데 정렬**
	-  첫 번째 값은 **상하(위아래)**, 두 번째 값은 **좌우** 여백을 의미
- 할것
	- 고정 단위인 `px` 대신 상대 단위인 `rem`을 사용
	- `*` 선택자를 이용해 모든 요소에 `box-sizing: border-box;`를 적용하여, `padding`과 `border`가 요소의 너비에 포함되도록 계산 방식을 통일
	- **CSS 변수 도입 (`--primary-color`)**: 반복적으로 사용되는 색상 값을 변수로 만들어, 나중에 색상 테마를 변경할 때 변수 하나만 수정하면 되도록 **유지보수성** 높이기.

### 1. 자바스크립트의 문법: 변수와 데이터 타입
- 자바스크립트란? :웹브라우저에서 실행되는 유일한 언어
- 자바스크립트는 **Java의 폭발적인 인기에 편승하기 위해 이름만 유사하게 지어졌을 뿐**, 문법이나 동작 방식에서 **거의 관련이 없는 별개의 언어**
- **변수 선언 키워드**: `var`, `let`, `const`
	- 저장공간을 만들어라는 역할을 가진 3가지 종류
	- var -> `var`는 이전 문법으로, **함수 스코프**를 가지며, **선언 전에 접근해도 `undefined`로 초기화되는 '호이스팅' 특성**으로 인해 예측하기 어려운 동작이나 잠재적인 버그를 유발할 수 있어 **현업에서는 사용을 강력히 비추천**하며, 대신 `let`과 `const`를 사용합니다
	- let
	- const
- 데이터 타입의 종류: 원시vs참조
	- 원시데이터타입: 스택에 값이 기록됨
	- 참조데이터타입: 힙에 값이 기록되고, 스택에 주소가 기록됨
- 자바스크립트는 동적타이핑 형식이다.
	- 동적타이핑이란 사용자가 값을 대입하고 대입한 데이터 타입에 따라 사용자가 선언한 변수의 타입이 결정되는것을 말한다.
- 원시타입과 참조타입의 메모리 저장방식 차이
	- 모든 변수는 메모리의 스택(Stack) 공간에 생성됩니다.
	- 원시 타입 값이 할당되면 그 값 자체가 스택에 기록 
	- 변수에 참조 타입 값이 할당되면 데이터의 본체는 메모리의 힙(Heap)에 별도로 생성되고, 변수는 그 힙의 메모리 주소를 저장합니다
- 원시타입 종류
	- Number (정수, 실수)
	- String (문자, 문자열)
	- Boolean (참, 거짓)
	- Undefined (초기화하지 않고 선언만한 변수에 저장되는 타입)
	- Null (의도적으로 비어있음을 표현하는 타입)
- 참조타입 종류
	- let obj={}
		- '문자열' 키로 데이터에 접근할때
		-  데이터의 순서가 중요하지 않을때
		- `let obj={}`: 사실 `let obj = new Object();`의 축약형입니다. **객체를 생성하는 가장 일반적이고 권장되는 방식**입니다.
	- let map= new Map();
		- '모든타입'키로 데이터에 접근
		- 데이터의 삽입순서도 중요하고, 데이터의 추가/삭제가 빈번할때
	- let array=\[]
		- '순서숫자' 인덱스 키로 데이터에 접근
		- 순서가 중요한 모든 타입의 데이터 목록 
		- `let array=[]`: 사실 `let array = new Array();`의 축약형입니다. **배열을 생성하는 가장 일반적이고 권장되는 방식**입니다.
	- let set= new Set()
		- 키x
		- 컬렉션 안의 모든 값을 고유하게 유지하고 싶을때(중복 제거)
		- 특정값이 컬렉션 안에 존재하는지 여부를 빠르게 확인하고 싶을때
		- let set= new Set(\[1,2,3,3]) : 배열 안 요소를 하나씩 꺼내 set에 추가
		- set.add(\[1, 2, 3, 3]); :배열 자체를 한 요소로 추가
		- set의 몇번째 데이터 조회하는법 : 배열로 변경해 인덱스 조회
			- let array =Array.from(set);

### 2. 자바스크립트 데이터 다루기: 연산, 비교, 형변환
- ++변수: 원본을 변형후 사용
- 변수++ : 원본 사용후 변형
- (임시적)형변환: 연산자의 규칙따라 자바스크립트 엔진이 자동으로 변환
	- 피연산자 하나라도 문자열이면 다른값 문자열로 만든다.
- (명시적)형변환: 함수를 이용해 개발자가 직접 
	- Number("10") ->10
	- Boolean("가") -> true //비어있지 않고, falsy값이 아니면 true
	- Boolean(0) ->false //falsy값을 boolean으로 바꾸면 false
	- falsy 값: "false", 0, "", '', null, undefined, NaN 
		- NAN 이되는 경우
			- 0/0
			- **숫자 타입이 아닌 값을 `Number()` 함수로 변환하려 할 때** (예: `Number("hello")`)
			- **어떤 숫자 값과 `NaN`을 연산할 때** (예: `5 + NaN`, `undefined + 10`처럼 `undefined`가 `NaN`으로 변환되어 연산될 때도 포함)
- 자바스크립트의 == 와 ===
	-  변수를 선언할 때(`var`, `let`, `const`) 타입을 명시적으로 지정하지 않고, 값이 할당될 때 타입이 결정되는 **동적 타입**의 자바스크립트에서는 형변환을 하고 비교해야 같은 값인지 알수있다.
	- == 타입을 바꾼 후에 값이 같은가? (비교하기전 형변환) 
	- === 타입과 값이 모두 같은가 (형변화 하지않고 비교)
- 자바의 ==
	- 자바스크립트와 다르게 자바는 컴파일시점에 변수의 타입이 이미 선언시에 쭉 타입 고정이 되어있는 정적타입 언어이다 
	- 그래서 타입이 다른것 자체가 불일치이기에 컴파일에러가 발생한다. 즉 == 자체가 형변환 하지않고 비교역할이다. 
	- 이때 참조타입끼리 비교할때 == 하면 같은 메모리 주소를 가리키는지 확인하는거고, ,equals이면 두 객체의 실제 값이 같은지 확인하는거다.

### 3. 자바스크립트 코드흐름 제어하기: 조건문과 반복문

- switch: '하나의 변수'가 가질 수 있는 정해진 값들에 따라 다른 동작을 처리할때 효과적 
	- switch 일치하는 case를 찾으면 그지점부터 코드를 실행한다
		- 그렇기 때문에 해당 case에 break가 없으면 아래 case일치여부는 상관없이 모두 실행한다
	- default : 일치하는 case가 없는경우 실행됨
		- 상단 케이스에 break가 없는경우 항상 실행됨
- for: 정해진 횟수만큼 반복할때
- while: 특정 조건이 만족하는 동안에만 계속 반복할때
- do while: 처음부터 거짓이라도 한번 일단 실행한다음에서야 while처럼 동작

### 4. 자바스크립트 데이터 묶음 다루기: 배열
- 배열: 여러 데이터 타입의 값들을 하나의 변수에 순서대로 저장하는 자료구조
- 배열 선언방법
	- 1: 대괄호 \[]를  사용
		- let numbers=\[1,2,3];
		- 빈 배열 선언해서 값 채워넣기
			- let emptyArray=\[];
	- 2: Array(생성자 함수)를 이용
		- `let numbers = new Array(1, 2, 3);` (값을 직접 초기화)
		- `let emptyArr = new Array(5);` (**길이가 5인 빈 배열 생성, 요소는 `undefined`**)
			- 숫자 하나만 인자로 주었을 때는 길이로 간주된다.
			- `new Array()`는 인자의 개수나 타입에 따라 동작이 달라질 수 있어 혼란을 줄 수 있으므로 일반적으로 `[]` 리터럴 사용이 권장
- 배열의 특징
	- 배열은 순서가 있고, 그 순서(인덱스)로 배열의 요소에 접근한다.
- 자바스크립트에서만의 배열의 특징 
	- 다양한 데이터 타입을 한번에 동시에 넣을수 있다
		- let datas = \[1,"안녕",true];
- 배열은 참조타입이라 변수에는 힙(Heap) 메모리에 저장된 실제 데이터의 주소가 저장됩니다.
	- 스택에 데이터주소를 저장하고, 힙에 실제데이터를 저장한다
- 배열을 다루기: 배열은 데이터를 저장 관리하기에 CRUD개념을 기반으로 동작한다
	- CREATE 생성
		- `arr.push(data)`: 배열의 **맨 뒤**에 요소 추가
		- `arr.unshift(data)`: 배열의 **맨 앞**에 요소 추가
	- READ 조회
		- `arr[index]`: 해당 인덱스의 요소 조회
	- UPDATE 수정
		- `arr[index] = data`: 해당 인덱스의 요소를 새로운 데이터로 변경
	- DELETE 삭제
		- `arr.pop()`: 배열의 **맨 뒤** 요소 제거
		- `arr.shift()`: 배열의 **맨 앞** 요소 제거
	- 중간에 요소 추가, 삭제, 교체 한번에 하는 splice
		- **`arr.splice(startIndex, deleteCount, item1, item2, ...)`**
			- `startIndex`: 조작을 시작할 인덱스
			- `deleteCount`: 삭제할 요소의 개수
			- `item1, ...`: 추가할 요소들
- 자바스크립트에서 많이 쓰이는 배열관련 함수 map, filter
	- map: 모든요소를 '변환'해 새 배열 생성
		- `map` 메소드는 "각 요소를 어떻게 **변환**할지"에 대한 설명서(콜백 함수)를 인자로 받습니다.
		- 배열의 모든 요소를 순회하면서, 주어진 콜백 함수를 적용하여 **완전히 새로운 모습의 배열**을 반환합니다.
		- 1. 항상 새로운 배열을 반환(원본배열 변화x)
		- 2. 새 배열의 길이는 원본과 같다
		- 3. 콜백 함수는 각 요소를 **변환한 새로운 값**을 반환(`return`)해야 합니다.
		```JavaScript
		const numbers = [1, 2, 3, 4];
		const doubledNumbers = numbers.map(num=> num * 2);
		/*엣날방식
		const doubledNumbers = numbers.map((num) => {
		  return num * 2;
		});
		*/
		console.log(doubledNumbers); // [2, 4, 6, 8]
		console.log(numbers);        // [1, 2, 3, 4] (원본은 그대로)
		```
	- filter: 조건에 맞는 요소만 '선별'해 새 배열 생성
		- `filter` 메소드는 "각 요소를 어떻게 **검사**할지"에 대한 설명서(콜백 함수)를 인자로 받습니다.
		- 배열의 모든 요소를 순회하면서, 콜백 함수의 결과가 `true`인 요소들만 모아 새로운 배열을 반환합니다.
		- 1. 항상 새로운 배열을 반환(원본배열 변화x)
		- 2. 새로운 배열의 길이는 원본보다 같거나 작다
		- 3. 콜백 함수는 각 요소를 테스트하여 **`true` 또는 `false`**를 반환(`return`)해야 합니다.
		```JavaScript
		const numbers = [1, 2, 3, 4, 5, 6];
		//최근방식
		const evenNumbers = numbers.filter(num => num % 2 === 0);
/*엣날방식(함수)
numbers.filter((num) => {
		  return num % 2 === 0;
		});
		*/
		console.log(evenNumbers); // [2, 4, 6]
		console.log(numbers);     // [1, 2, 3, 4, 5, 6] (원본은 그대로)
		```
- 추가 탐구 forEach: 모든 요소에 대해 '행동'만 수행
	- `forEach` 메소드는 "각 요소로 **무슨 행동**을 할지"에 대한 설명서(콜백 함수)를 인자로 받습니다.
	- 배열의 모든 요소를 순회하면서, 각 요소에 대해 주어진 콜백 함수를 실행합니다. 
	- `map`이나 `filter`처럼 새 배열을 만드는 것이 아니라, 단순히 배열의 각 요소를 사용하여 **외부에 영향을 주는 작업(Side Effect)**(예: 콘솔 출력, DOM 조작)을 수행할 때 사용합니다.
	- `forEach` 자체의 반환 값은 항상 **`undefined`**이며, 콜백 함수 내에서 `return`으로 무언가를 반환하더라도 그 값은 **완전히 무시**됩니다.
- 추가 자바스크립트 내장함수
	- 객체를 만드는 생성자(Constructor)이지만, 함수처럼 호출하면 **타입 변환**을 수행
	- ##### 1. `String()`: 모든 타입을 문자열로 변환
	- 2. `Boolean()`: `true` 또는 `false`로 변환
	- 3. `Object()`: 원시 타입을 객체로 변환
	- 4. Number(): 다른 타입의 값을 **숫자**로 변환
	- map과의 활용예시
		- \['10', '20', '30'].map(Number); // 결과 \[10, 20, 30]
		- `numbers.map(item => Number(item))`과 `numbers.map(Number)`는 완전히 동일하게 동작하며, 후자가 훨씬 간결한 표현
- 자바스크립트는 배열 객체에서 이러한 메서드를 직접 호출할 수 있지만, 자바에서는 배열(Array)이나 리스트(List)를 먼저 **스트림(Stream)으로 변환**한 뒤에 `map`, `filter` 등을 사용하고, 최종적으로 다시 리스트나 배열로 결과를 수집(`collect`)하는 과정이 필요합니다

### 5. 자바스크립트 코드의 조직화: 스코프와 함수
- 스코프: 코드가 유효하게 작용하는 범위를 의미하며, 변수와 함수마다 소속되는 스코프 규칙이 다르다
	- 블록 스코프: {} 중괄호로 둘러싸인 범위
		- let, const, (function 선언문)
	- 함수 스코프: function 키워드로 생성된 함수 내부 전체 범위
		- var, function 선언문
			- `function` 선언문은 원칙상 블록 스코프지만, 실제 동작은 함수 스코프처럼 동작하므로 이렇게 기억하는 것이 안전합니다.
- 자바스크립트 엔진이 코드를 **한 줄씩 실행하기 전에, 먼저 전체 코드를 한번 쓱 훑어보면서 호이스팅함 
	- 이때 호이스팅이란: 코드의 위치를 물리적으로 바꾸는게 아니라 변수와 함수의 선언을 메모리에 미리 기록하는 과정이다. 이 호이스팅은 **항상 자신이 속한 스코프의 범위 안에서만** 일어남.
	[[../00_Inbox/자바스크립트는 한줄씩 번역,실행하는 인터프리터 방식인데 왜 전체 코드를 그전에 한번 쓱 흝어봐서 호이스팅이 발생해?|자바스크립트는 한줄씩 번역,실행하는 인터프리터 방식인데 왜 전체 코드를 그전에 한번 쓱 흝어봐서 호이스팅이 발생해?]] 
	- var : 함수스코프 
		- 호이스팅: 선언부만 함수 스코프의 최상단으로 호이스팅되고 즉시 undefined로 초기화됨
			- 함수 안에서 선언되면 그 함수 내부에, 함수 밖 최상위에서 선언되면 전역
		- 해당 선언줄에 도달하기전에 접근해도 에러가 발생하지 않고 undefined 값을 가진다.
	- let, const: 블록스코프
		- 호이스팅: 블록 스코프의 최상단으로 선언부가 호이스팅되고 초기화되지 않고 접근할수없음 (이 구간을 **TDZ**라함) 
		- 결과: 변수가 선언됬던 원래 줄에 도달하기전 접근하면 ReferenceError발생 
			- let a; 이라면, 해당 줄에 도달하면 undefined로 초기화됨
			- let a=10; 이라면 해당줄에 도달하면 10으로 초기화됨
	- function 선언: 블록스코프
		- 호이스팅: 예외적으로 {}안에서 선언될때 엣날자바스크립트와 호환성을 위해서 함수 스코프까지 영향력을 가지게됨 (그래도 자신이 선언된 함수 밖으로는 나가지 않음)
			- 함수 선언식은 같은 이름으로 여러 번 선언하면 **나중에 선언된 함수가 이전 함수를 경고 없이 덮어씁니다.** 이는 예상치 못한 버그로 이어질 수 있습니다
		- const 변수1= function(){}
			- 변수1의 선언만 호이스팅되고, 해당 줄 이후부터 호출가능
			- const로 선언하고 값을 할당한뒤 다시 값을 할당하면 에러가 발생해 실수를 막아줌
			- 즉 if와 for 같은 블록 내에서는 function 선언하는 대신에 함수 표현식(변수에 함수저장)을 사용하는게 더 안전하다
- 함수란 재사용 가능한 코드 묶음이다.
	- 자바의 함수: 클래스에 묶여있는 메소드
		- 1. 함수형 인터페이스 타입의 변수에 람다식을 할당할 수 있다
			- [[00_Inbox/람다식이 뭐길래 함수처럼 동작하지?.md|람다식이 뭐길래 함수처럼 동작하지?]]
	- 자바스크립트의 함수: 독립적으로 존재하며 값처럼 다룰수있는 객체를 함수라고 한다 
		- 1. 변수에 함수를 직접 저장할수있다
			- 저장후 변수() 이러면 함수 호출
		- 2. 다른 함수의 인자로 전달할수있다
			- 인자로 전달된 함수는 해당 함수 내부에서 **명시적으로 호출(`인자명()`)될 때 실행**됩니다
			- 콜백함수: 다른 함수의 매걔변수로 전달되어 그 다른 함수 내부에서 나중에 호출되는 함수
				- 콜백함수는 비동기처리의 도구로 많이 쓰인다
				- 비동기 처리: 시간이 걸리는 작업을 기다리지 않고, 다른 작업을 먼저 처리하는 방식 
		- 3. 다른 함수의 결과값으로 반환(return)할수있다
			- 즉 반환값으로 선언된 함수를 받아 나중에 써먹을수있다
			- 참고로 return 함수가 아니라 return 함수() 이렇게하면 1.함수를 실행 2. 그 함수의 반환값을 반환하라는 의미임
		- 변수에 저장 유무와 상관없이 값처럼 다룰수있다.
- 함수를 정의하는 3가지 방법
	- 함수 선언식: function 키워드와 함수이름을 사용해 정의
		- function 이름(){}
	- 함수 표현식: 함수를 만들어 변수에 값처럼 할당
		- const 변수= function(){}
		- 함수이름 필요없음
	- 화살표 함수: 최신문법 function대신해 =>를 사용하며  this를 다루는 방식에 차이
		- const 변수= (매걔변수) =>{}
- 자바의 this : 메소드가 소속된 클래스의 인스턴스를 가리키는걸로 고정
- 자바스크립트의 this : 함수가 어디에 소속했는지가 아니라 누가 호출했냐에 따라 달라짐 
	- 함수 호출 시 **점(`.`)이 있으면 `this`는 점 앞의 객체**입니다.
		- 객체1.함수(); 의 형태로 호출하면, 호출한 주체가 객체1이기 때문에
	- 함수 호출 시 **점(`.`)이 없으면 `this`는 `window`**입니다.
		- 함수(); 의 형태로 호출되면, 호출한 주체가 명확하지 않기때문에 전역객체(window)를 this로 함
	- **화살표 함수는** 이 모든 규칙을 무시하고, **자신이 만들어진 곳의 `this`**를 씁니다.
		- 호출방식과 상관없이 화살표 함수의 this는 자기가 만들어진 장소의 this를 그대로 가져다 쓴다
	- 예시
		- person.sayHello(); 일땐 sayHello 내부의 this는 
			- person를 가리키게되고,
		- const hi = person.sayHello; hi(); 일땐 sayHello 내부의 this는 
			- window를 가리킨다
			- hi 변수에 sayHello 함수 자체를 저장한것이다

### 6. 자바스크립트 코드의 조직화: 예외처리
실행하는 도중 예기치 않은 문제(에러)가 발생하면 프로그램은 멈추게 됩니다. **예외 처리**는 이러한 에러가 발생할 가능성이 있는 코드를 미리 예측하고, 에러가 발생하더라도 프로그램이 멈추지 않고 대처할 수 있도록 만드는 안정적인 프로그래밍 방식입니다. 
- `try...catch`의 기본 개념
	- **`try` 블록**: 에러가 발생할 것으로 예상되는 코드를 이 안에 작성합니다.
	- **`catch` 블록**: `try` 블록 내에서 에러가 발생하는 순간, `catch` 블록이 실행됩니다. 
		- 에러에 대한 정보는 catch의 매개변수에 저장합니다
		- 개발자는 이 매개변수(Exception 객체) **`message`나 `name` 같은 속성을 분석**하여 오류의 원인을 파악하고, 사용자에게 안내 메시지를 보여주거나 서버에 오류를 기록하는 등의 후속 조치를 취할 수 있습니다.
	
- `finally`의 역할
	- **`finally` 블록**: `try` 블록의 코드 실행이 끝나면, **에러 발생 여부와 관계없이 항상 실행**되는 코드 블록입니다. 주로 작업 후 리소스를 정리하는 등의 코드를 작성할 때 사용됩니다.
	
- 동작 예시
	
	```JavaScript
	try {
	  // 1. 에러가 발생하지 않는 코드
	  let result = 10 / 0; // JS에서는 오류가 아니며, Infinity를 반환
	  console.log(result); // 오류가 아니니 다음줄실행해 "Infinity" 출력
	
	  // 2. 에러가 발생하는 코드
	  let user = undefined;
	  console.log(user.name); // 여기서 TypeError 발생! 즉시 catch 블록으로 이동
	  
	  // 아래 코드는 실행되지 않음
	  console.log("이 코드는 실행되지 않습니다.");
	
	} catch (error) {
	  // 3. 에러 처리
	  // error 객체는 name과 message 같은 속성을 가짐
	  console.log("오류가 발생했습니다: " + error.message);
	
	} finally {
	  // 4. 항상 실행
	  console.log("이 코드는 항상 실행됩니다.");
	}
	```
	
- 실행 결과
	```
	Infinity
	오류가 발생했습니다: Cannot read properties of undefined (reading 'name')
	이 코드는 항상 실행됩니다.
	```
### 7. 자바스크립트 객체 심화: 복사
- **값에 의한 복사 (Copy by Value)**: 원시 타입을 복사할 때 일어납니다.
- **참조에 의한 복사 (Copy by Reference)**: 참조 타입을 ` = `로 할당할 때 일어납니다.
- **얕은 복사 (Shallow Copy) / 깊은 복사 (Deep Copy)**: 모두 참조 타입의 '진짜 데이터'를 복사하고 싶을 때 사용하는 **별도의 복사 기법**입니다.
#### 7_1. 모든 복사를 이해하려면, 데이터 타입이 메모리에 어떻게 저장되는지 먼저 알아야 합니다.핵심은 **"모든 변수는 일단 스택(Stack)에서 시작한다"** 는 점입니다.
1. 변수가 선언되면, 그 변수를 위한 공간이 메모리의 **스택(Stack) 영역**에 할당됩니다.
2. 이 공간에 저장되는 내용은 데이터의 타입에 따라 달라집니다
	- **원시 타입 (Primitive Types)**
		- `Number`, `String`, `Boolean`, `null`, `undefined`
		- 할당된 스택 공간에 **값 자체가** 직접 저장됩니다.
		- `let score = 100;` 이면, `score`라는 스택 공간에 `100`이라는 값 자체가 기록됩니다.
	- **참조 타입 (Reference Types)**
		- `Object`, `Array`, `Map`, `Set` 등
		- 데이터의 **본체**는 별도의 공간인 **힙(Heap) 영역**에 저장됩니다.
		- 스택 공간에는 이 힙에 저장된 데이터의 **메모리 주소(참조 값)**만 기록됩니다.
		- `let user = { name: "Kim" };` 이면, `user`라는 스택 공간에는 힙에 생성된 `{ name: "Kim" }` 객체의 메모리 주소가 기록됩니다.	    
#### 7_2 기본 복사 방식: 값 복사 vs. 주소 복사
`let b = a;` 와 같이 ` = ` 할당 연산자를 사용했을 때, 데이터 타입에 따라 복사되는 대상이 다릅니다.

- **값에 의한 복사 (원시 타입)**
	- 스택에 저장된 **값 자체를 복사**하여 새로운 공간을 만듭니다.
	- 따라서 두 변수는 완전히 독립적이며, 서로에게 영향을 주지 않습니다. **일반적으로 생각하는 '복사'**가 이것입니다.
	
	```JavaScript
	let a = 100;
	let b = a; // 스택에 있던 100이라는 값을 복사해 b에 새로 할당
	
	b = 200;
	
	console.log(a); // 100 (영향 없음)
	console.log(b); // 200
	```
	
- **참조에 의한 복사 (참조 타입)**
	- 스택에 저장된 **메모리 주소만 복사**합니다.
	- 결과적으로 두 변수는 힙에 있는 **똑같은 실제 데이터를 가리키게(참조하게) 됩니다.**
	- 그래서 한쪽에서 데이터를 수정하면, 다른 쪽에도 **영향을 미칩니다.**
	
	```JavaScript
	const a = { one: 1, two: 2 };
	let b = a; // a가 가리키는 메모리 주소'만' b에 복사
	
	b.one = 3; // b를 통해 실제 데이터 수정
	
	// a와 b는 같은 데이터를 가리키므로, a를 확인해도 수정된 내용이 보임
	console.log(a); // { one: 3, two: 2 }
	console.log(b); // { one: 3, two: 2 }
	```    
#### 7_3 '진짜' 복사하기: 얕은 복사와 깊은 복사	
- 참조 타입의 원본을 유지하면서 **새로운 복사본**을 만들고 싶을 때 사용하는 기법입니다.
- **얕은 복사 (Shallow Copy)**
	- 객체나 배열을 **한 단계까지만** 복사합니다.
	- 내부에 또 다른 객체나 배열(참조 타입)이 있다면, 그 부분은 **주소만 복사**합니다.
	- **방법**: `const b = { ...a };` (스프레드 문법), `Object.assign({}, a)`
		
	```JavaScript
	const a = { x: 1, inner: { y: 2 } };
	const b = { ...a }; // 얕은 복사
	
	b.x = 10;
	b.inner.y = 20;
	
	console.log(a.x);       // 1 (원시 타입은 영향 없음)
	console.log(a.inner.y); // 20 (내부 객체는 주소를 공유하므로 영향 있음)
	```
	
- **깊은 복사 (Deep Copy)**
	- 내부에 중첩된 모든 객체와 배열까지 재귀적으로 복사하여 **완전히 독립된 복사본**을 만듭니다.
	- 방법 1: Lodash 라이브러리 사용 (추천)
			가장 안정적이고 편리한 방법은 `lodash` 라이브러리의 `cloneDeep` 메서드를 사용하는 것입니다
		- [[00_Inbox/객체 출력시 주의할점.md|객체 출력시 주의할점]] 
		- ^i9n9t8
			```JavaScript 
			//lodash라이브러리 불러오기
			import _ from 'lodash';
			
			const originalObject = {
				name: 'black',
				address: { city: 'SEOUL' }
			};
			//`import _ from 'lodash';` 구문은 lodash 라이브러리 전체를 가져와서 `_` 라는 이름의 변수에 할당하라는 의미입니다. 따라서 함수를 호출할 때도 `_`를 사용해야 합니다.
			const deepCopiedObject = _.cloneDeep(originalObject);
			
			deepCopiedObject.address.city = "BUSAN";
			
			// 깊은 복사된 객체를 수정해도 원본은 전혀 영향을 받지 않습니다.
			console.log(originalObject.address.city); // "SEOUL"
			console.log("\n"+ originalObject);//문자열로 더하면 암시적 변환이되어  [object object] 출력이 되고 객체 내부 출력이 되지 않는다

			``` 
		
	-  방법 2: `JSON.parse(JSON.stringify())` 활용
		라이브러리 없이 간단하게 깊은 복사를 구현하는 방법입니다. 객체를 JSON 문자열로 변환했다가 문자열을 바탕으로 새로운 객체를 만들어 저장하는 원리입니다. ^aa5c4o
		
		```JavaScript
		const a = { one: 1, two: 2 };
		const c = JSON.parse(JSON.stringify(a)); // 깊은 복사
		
		c.one = 9999;
		
		console.log(a.one); // 1 (원본에 영향을 주지 않음)
		```
		
		**⚠️ 주의:** 이 `JSON` 방식은 함수, `undefined`, `Set` 등 JSON으로 변환할 수 없는 속성들은 모두 사라지는 치명적인 단점이 있어, 실제 프로젝트에서는 `lodash`와 같은 라이브러리 사용이 권장됩니다
		[[../00_Inbox/JSON메소드모두정리|JSON메소드모두정리]]

### 8. 자바스크립트 객체 심화: 상속
- 자바의 클래스 상속 vs 자바스크립트의 프로토타입 상속
	- 자바의 클래스 상속
		- 클래스가 다른 클래스를 설계도처럼 물려받음
		- extends 키워드를 사용하여 관계설정
		- **정적 (Static)**: 컴파일 시점에 상속 관계가 고정됨
	- 자바스크립트의 프로토타입 상속
		- 객체가 다른 객체를 직접 물려받음
			- 객체가 다른객체로부터 직접 속성과 메소드를 물려받아 코드를 재사용
		- Object.create(), 생성자 함수로 관계 설정
		- 동적: 실행중에도 상속관계 변경 가능
- 자바스크립트의 프로토타입이란?
	- 다른 객체에게 속성과 기능(메서드)을 물려주는 **원본(부모) 객체**입니다. 자바스크립트의 모든 객체는 속성을 `{key: value}` 쌍으로 가지며, 프로토타입 역시 이 규칙을 따르는 일반 객체입니다.
		- 예를 들어, `{ sound: function() { ... } }` 와 같은 형태가 됩니다. 
- 자바스크립트의 상속 핵심 원리: 프로토타입 체인
	- 어떤 객체의 속성을 찾을 때 그 객체에 해당 속성이 없으면, 자바스크립트는 그 객체의 프로토타입(부모)으로 계속 거슬러 올라가며 속성을 찾습니다. 이 연결고리를 **프로토타입 체인**이라고 합니다.
	- 이 체인의 종점에는 모든 객체의 최상위 조상인 **`Object.prototype`**이 있습니다.
		- **일반 객체 → `Object.prototype`**
			- 모든 일반 객체는 `Object.prototype`으로부터 **`hasOwnProperty()`**, **`toString()`**, **`isPrototypeOf()`** 와 같은 객체의 기본적인 핵심 메서드들을 물려받습니다.
		- **함수 → `Function.prototype` → `Object.prototype`**
			- 모든 함수는 일차적으로 `Function.prototype`으로부터 **`call()`**, **`bind()`**, **`apply()`** 와 같은 함수 고유의 메서드를 물려받습니다.
			- 그리고 `Function.prototype` 또한 객체이므로, 그 부모인 `Object.prototype`으로부터 `hasOwnProperty()`, `toString()` 등의 최종 기능을 물려받습니다.
- 프로토타입 상속 관계 생성
	- 핵심은 '어떤 객체를 부모로 삼을지'와 '부모 객체에 어떤 기능을 추가할지'입니다
	- **방법 1: `Object.create(부모객체)`로 상속하기** 
		- 주어진 `부모객체`를 프로토타입으로 삼는 새로운 빈 객체를 생성하고, 그 메모리 주소를 반환합니다.
		```JavaScript
		const animal = { // 부모 객체 (프로토타입)
			sound() {
				console.log("동물이 소리를 냅니다.");
			}
		}; ^aa5c4o
		
		const dog = Object.create(animal); // animal을 부모로 하는 dog 객체 생성 (animal를 부모로 삼는 빈객체를 생성하고, 메모리주소를 dog 변수에 저장한다)
		dog.sound(); // "동물이 소리를 냅니다." -> 부모의 기능을 물려받음
		```
	- **방법 2: 생성자 함수와 `new` 키워드로 상속하기** 
		- '객체 설계도' 역할을 하는 생성자 함수와 `new` 키워드를 사용하여 가장 체계적으로 상속을 구현합니다.
		1. **생성자 함수(설계도)를 정의하고, 프로토타입에 공통 기능을 추가합니다.**
			- 객체1.prototype.변수1 : 객체1에 변수1(함수의 주소를 담은)를 추가합니다
			```JavaScript
			// 1. '차'를 만드는 생성자 함수(설계도) 정의
			function Car(name) {
			  this.name = name;
			}
			// 2. 설계도의 프로토타입에 공통 기능 추가
			// Car.prototype이라는 객체에 drive라는 속성을 추가합니다.
			Car.prototype.drive = function() {
			  console.log(this.name + '가 운전합니다.');
			};
			```
			
		2. **`new` 키워드로 객체를 생성합니다.** `new` 키워드는 내부적으로 다음 네 가지 일을 수행하며 상속 관계를 자동으로 완성합니다.
			- 1. 새로운 빈 객체(`{}`)를 만듭니다.
			- 2. 새 객체의 프로토타입을 **생성자 함수의 `prototype` 속성**에 연결합니다.
				- `새객체.__proto__ = 생성자함수.prototype`
			- 3. 생성자 함수 실행 및 `this` 바인딩
				- 생성자 함수를 호출하면서, 함수 내의 `this`가 새로 만들어진 객체를 가리키도록 설정합니다.
			- 4. 별도의 반환 구문이 없으면, 이렇게 완성된 새 객체를 반환합니다.
			```JavaScript
			// 3. new 키워드로 객체 생성
			const myCar = new Car('쏘나타'); // new가 마법을 부리는 시점!
			myCar.drive(); // 쏘나타가 운전합니다.
			```
	- 위험: 내장 프로토타입 직접 확장하기
		- 모든 객체의 최상위 조상인 `Object.prototype`에 직접 기능을 추가하면, 모든 객체가 해당 기능을 상속받아 사용할 수 있게 됩니다.
		```JavaScript
		// 모든 객체의 조상인 Object.prototype에 sayHello 메소드 추가
		Object.prototype.sayHello = function() {
		  console.log("안녕하세요!");
		};
		
		const person = { name: "블랙" };
		person.sayHello(); // 출력: 안녕하세요!
		```
		- **⚠️ 경고**: 이 방법은 매우 강력하지만, 다른 코드나 라이브러리와 충돌을 일으킬 수 있어 실제 프로젝트에서는 **절대 사용해서는 안 되는 위험한 방식**입니다.	
		- 내장 프로토타입 수정 금지*`Object.prototype`, `Array.prototype` 등 내장 객체의 프로토타입을 직접 수정하는 것은 다른 코드나 라이브러리와 충돌을 일으킬 수 있어 절대 피해야 합니다.
- 프로토타입 조회: `Object.getPrototypeOf(객체)`
	- 객체의 부모(프로토타입)가 누구인지 명시적으로 확인할 수 있습니다.
	- `Object.getPrototypeOf()`의 결과는 조회하는 대상의 종류에 따라 달라집니다. 하나의 객체는 단 하나의 직계 부모만 가집니다.
	 -  1. `Object.create()`로 생성한 경우
		`Object.create()`의 인자로 전달된 객체가 그대로 프로토타입이 됩니다.
		```JavaScript
		const animal = { sound() {} };
		const dog = Object.create(animal);
		
		// dog의 직계 부모는 animal 객체입니다.
		console.log(Object.getPrototypeOf(dog) === animal); // true
		```
	- 2. 생성자 함수(`new`)로 생성한 경우
		`new` 키워드는 생성자 함수의 `.prototype` 속성을 객체의 프로토타입으로 자동 설정합니다.
		```JavaScript
		function Car(name) { this.name = name; }
		const myCar = new Car('쏘나타');
		
		// myCar의 직계 부모는 Car.prototype 객체입니다.
		console.log(Object.getPrototypeOf(myCar) === Car.prototype); // true
		```
	- 3. 객체 리터럴({})로 생성한 경우
		`{}` 와 같은 객체 리터럴로 생성된 객체는 기본적으로 모든 객체의 최상위 조상인 `Object.prototype`을 프로토타입으로 가집니다.
		```JavaScript
		const person = { name: "블랙" };
		
		// person의 직계 부모는 Object.prototype 객체입니다.
		console.log(Object.getPrototypeOf(person) === Object.prototype); // true
		```

### 9. 브라우저와 상호작용: DOM(Document Object Model)
- DOM: **웹 문서(Document)의 모든 요소를 객체(Object)처럼 다룰 수 있게 만든 계층구조모델"**
	- Document: HTML 문서 전체.
	- **Model**:  복잡한 현실 세계의 사물이나 구조를 **이해하고 다루기 쉽게 단순화하여 표현한 것** 여기서의 모델은 웹 문서의 구조를 나무 형태로 표현했다
- HTML 파일 자체는 정적인 구조를 가진 단순한 텍스트에 불과합니다. 이 때문에 과거에는 동적인 자바스크립트가 웹 페이지의 구조를 알거나 수정할 방법이 없었습니다.
- 이 문제를 해결하기 위해, 브라우저는 HTML 문서를 읽어들여 각 태그를 메모리 안의 **'객체'**로 재구성합니다. 이렇게 만들어진 객체들의 나무와 같은 구조가 바로 DOM입니다.
	1. **생성**: 브라우저가 HTML 코드를 한 줄씩 읽으면서, 각 태그(`<h1>`, `<p>` 등)에 해당하는 객체를 만들어 나무(Tree) 형태로 메모리에 구성합니다. 이 나무 구조가 바로 DOM입니다.
	2. **접근 및 조작**: 자바스크립트는 `document` 객체를 통해 DOM 트리에 접근하고, 다음과 같은 메서드로 특정 요소를 선택하여 내용을 바꾸거나 스타일을 수정합니다.
		- **`document.getElementById('ID')`**
			- 고유한 `id` 속성을 사용하여 **단일 HTML 요소 객체**를 찾습니다.
			```JavaScript
			const title = document.getElementById("title");
			// title 변수에는 id가 "title"인 요소 객체가 저장됩니다.
			```
		- **`document.getElementsByClassName('클래스명')`**
			- 주어진 `class` 이름을 가진 **모든 요소**를 찾아 **HTMLCollection(유사 배열)**에 담아 반환합니다.
			- 하나만 반환해 바로 접근가능한 다른 메서드와는 달리 배열에 담아 반환하기에 인덱스로 접근해야한다.
				- const helperText = inputGroup.getElementsByClassName("helperText")[0]
				- 하나만 있는 요소라도 인덱스\[0]를 통해서 접근하기
			```JavaScript
			const texts = document.getElementsByClassName("text");
			// texts 변수에는 class가 "text"인 모든 요소들이 유사 배열 형태로 저장됩니다.
			// 개별 요소에 접근하려면 인덱스를 사용합니다: texts[0]
			```
		- **`document.querySelector('선택자')`**
			- **CSS 선택자 문법**을 사용하여 요소를 찾습니다.
			- 일치하는 요소가 여러 개여도 **첫 번째 요소 하나만** 반환하는 것이 특징입니다.
			- 구체적이고 복잡한 조건으로 단 하나의 요소를 정확히 찾아야 할 때 `querySelector`는 필수적
			```JavaScript
			// 태그 이름으로 찾기
			const titleByTag = document.querySelector("h1");
			
			// ID로 찾기
			const titleById = document.querySelector("#title");
			
			// 클래스로 찾기 (첫 번째 요소만)
			const textByClass = document.querySelector(".text");
			
			//응용1. 자손선택
			//div 태그 안에 있는 .item 클래스
			document.querySelector('div .item');
			//응용2. 속성선택
			//type이 text인 input 태그
			//(공백): '~의 안에 있는' 또는 '~의 후손인' 이라는 관계를 의미합니다.
			document.querySelector('input[type="text"]');
			//응용3. 구조가상클래스
			//첫번째 li 태그
			document.querySelector('li:first-child')
			```
			
	3. **반영**: 자바스크립트가 DOM 객체를 변경하면, 브라우저가 그 변화를 감지하여 즉시 화면에 다시 그립니다(rendering).

### 10. 비동기 프로그래밍
#### 1. 왜 비동기 처리가 필요한가? (동기와 비동기)
- 자바스크립트는 기본적으로 **하나의 스레드(Single Thread)** 에서 코드를 순차적으로 처리하는 **동기(Synchronous)** 방식으로 동작합니다. 
	- 즉, 한 번에 하나의 작업만 처리하며 특정 작업이 끝날 때까지 다음 코드는 실행되지 않고 대기합니다.
    ```JavaScript
    // 동기 방식: for문의 10억 번의 연산이 끝날 때까지 "2. 끝"은 실행되지 않고 멈춰있습니다.
    console.log("1. 시작");
    for(let i = 0; i < 1000000000; i++) {} 
    console.log("2. 끝"); 
    ``` 
    
- **비동기(Asynchronous) 처리의 필요성** 
	- 만약 서버에서 데이터를 가져오는 API 호출처럼 시간이 오래 걸리는 작업을 동기 방식으로 처리하면, 데이터가 올 때까지 웹 페이지 전체가 멈추는(Blocking) 문제가 발생합니다. 이를 해결하기 위해 **비동기(Asynchronous)** 방식이 필요합니다.
    - 비동기 처리는 **해당 작업을 백그라운드(Web API)에 위임하고, 엔진은 완료를 기다리지 않고 바로 다음 코드로 넘어가는 방식**으로 프로그램의 흐름이 멈추지 않게 하는 핵심 메커니즘입니다
	- **주요 비동기 작업 예시**: 
		- API 호출 (`fetch`)
		- 타이머 설정(`setTimeout`, `setInterval`)
			- 브라우저가 백그라운드에서 시간을 세다가 약속된 시간이 되면 예약된 작업을 실행
---

#### 2. 비동기처리방식의 발전 : Callback → Promise → async/await
##### **2.1. 콜백 함수 (Callback)**: 비동기처리의 가장 초기 방식
- 다른 함수의 인자로 전달되어, 특정 작업이 끝난 후에야 실행되는 함수입니다.  
- **실전 예시: jQuery의 `ajax`**
    - `fetch`가 표준화되기 전에는 주로 jQuery 라이브러리의 `ajax` 함수가 사용되었습니다. 이 방식은 콜백 함수를 직접 전달하여 성공과 실패를 처리합니다.
        ```JavaScript
		// jQuery를 사용한 동일한 API 호출
		// 이 방식은 콜백 함수를 직접 전달하여 성공과 실패를 처리합니다.
		$.ajax({
		    url: "https://api.example.com/data",
		    type: "GET",
		    dataType: "json",
		    success: function(response){ console.log("성공: ", response); }, // 성공 시 콜백
		    error: function(error){ console.log("실패: ", error); }     // 실패 시 콜백
		});
        ```
- **한계: 콜백 기반 코드가 중첩되면 가독성, 유지보수성이 매우 떨어지는 **콜백 헬** 문제가 발생합니다.
##### **2.2. 프로미스 (Promise)** : 콜백 헬(코드중첩) 해결
- 프로미스는 **비동기 작업의 최종 완료 또는 실패를 나타내는 객체**입니다. 이 객체는 다음 세 가지 상태 중 하나를 가집니다. 
	- 즉시 결과를 알 수 없는 작업(예: 네트워크 요청, 타이머)에 대해 "나중에 결과가 나오면 내 상태변화를 통해 알려줄께 성공하면 결과물을 담고, 실패하면 에러를 담을테니 그때 확인해"라고 약속하는 개념입니다
- **Promise의 3가지 상태**
    1. **대기 (Pending)**: 비동기 작업이 아직 끝나지 않은 초기 상태
    2. **이행 (Fulfilled)**: 비동기 작업이 성공적으로 완료되어 결과값을 담은 상태
    3. **거부 (Rejected)**: 비동기 작업이 실패해 에러를 담은 상태
	- Promise는 초기에 **'대기'** 상태이며, 비동기 작업의 결과에 따라 **'이행'** 또는 **'거부'** 상태로 단 한 번만 변경됩니다.결정된 상태는 다시 변하지 않습니다.
- 사용법
	- `new Promise()`로 Promise 객체을 생성하고, Promise의 상태 변화에 따라 이후 처리할 메서드를 체이닝합니다
		- **`.then()`**: Promise가 '이행' 상태가 되었을 때 실행될 성공 결과값을 받을 콜백 함수를 등록합니다.
		- **`.catch()`**: Promise가 '거부' 상태가 되었을 때 실행될 실패 에러를 받는 콜백 함수를 등록합니다.
		- **`.finally()`**: Promise의 성공 또는 실패 여부와 관계없이 항상 실행될 콜백 함수를 등록합니다
- 예시: 피자 시뮬레이션 ^minmtx
	```JavaScript
	//선언문
	function orderPizza() {
		return new Promise((resolve, reject) => {
			setTimeout(() => {//2초가 지난 후 실행 시작
				let success = true; // 피자 제작 성공 여부 
				if (success) {
					resolve("피자 제작 성공!"); // 성공 시, Promise를 '이행' 상태로 변경, 결과 전달
				} else {
					reject("피자 제작 실패!"); // 실패 시, Promise를 '거부' 상태로 변경, 이유 전달
				}
			}, 2000);
		});
	}
	//실행코드
	orderPizza() 
	  .then(result => console.log(result))
	  .catch(error => console.log(error))   
	  .finally(() => console.log("주문 종료")); 
	```
	-	##### Promise의 비동기 동작 원리 (이벤트 루프)
		`Promise` 내부의 비동기 코드는 자바스크립트 엔진과 브라우저(Web API), 그리고 이벤트 루프가 협력하여 다음과 같은 순서로 동작합니다.
		1. **함수 호출 및 Promise 체인 생성** 
			- `orderPizza()` 함수가 호출되면, 즉시 `new Promise()`가 실행되어 **'대기(Pending)' 상태의 Promise 객체(A)가 반환**됩니다. 
			- 이어서 반환된 객체에 `.then()`, `.catch()` 같은 후속 처리 메서드가 **메서드 체이닝** 방식으로 연결됩니다.
			    - **메서드 체이닝**: 각 후속 메서드(`.then`, `.catch`)가 호출될 때마다 Promise 객체를 받고 또다른 **새로운 Promise 객체(B, C, ...)를 반환**하기 때문에, 코드를 기차처럼 계속 연결할 수 있습니다.
			    -  [[00_Inbox/누가 Promise를받나 (메서드체이닝).md|누가 Promise를받나 (메서드체이닝)]]  
		2. **Web API로 비동기 작업 위임** 
			- Promise 생성자 함수 내부의 `setTimeout`은 자바스크립트 엔진이 직접 처리하지 않고, 브라우저의 **Web API**에게 "설정한시간 후에 이 함수를 실행해줘"라고 작업을 위임한 뒤 즉시 다음 다른 코드로 넘어갑니다.
		3. **태스크 큐(Task Queue) 등록** 
			- Web API는 백그라운드에서 2초 타이머를 작동시킨 후, `setTimeout`에 전달되었던 콜백 함수(여기서는 `resolve`나 `reject`를 포함한 함수)를 **태스크 큐**라는 대기열로 보냅니다.
		4. **이벤트 루프**는 호출 스택이 비어 있는지 계속 확인합니다
			- **이벤트 루프**는 **호출 스택(Call Stack)** 이 비워지면(모든 동기 코드가 실행 완료되면), **태스크 큐** 에서 가장 오래된 작업을 호출 스택으로 가져와 실행시킵니다.
		5. **Promise 상태 변경 및 마이크로태스크 큐 등록** 
			- 호출 스택으로 옮겨진 콜백 함수가 실행되어 `resolve()`가 호출되는 순간, 첫 번째 Promise(A)의 상태가 '대기'에서 **'이행(Fulfilled)'**으로 바뀝니다. 
			- 이때, 이 상태 변경을 감지한 `.then()`에 등록된 콜백 함수는 일반 태스크 큐가 아닌, 우선순위가 더 높은 **마이크로태스크 큐**에 들어갑니다.
		6. **최종 실행** 
			- 이벤트 루프는 태스크 큐를 확인하기 전에 **항상 마이크로태스크 큐를 먼저 확인하고 비웁니다.** 
			- 따라서 마이크로태스크 큐에 있던 `.then()`의 콜백 함수가 즉시 호출 스택으로 옮겨져 최종적으로 실행됩니다.
			
##### **2.3. async / await** : `Promise` 가독성, 작성방식 개선
- 기존 Promise: 실행흐름이 위에서 아래가 아니다
- `await`를 사용하여 Promise의 결과가 나올 때까지 함수의 실행을 잠시 멈췄다가 순차적으로 진행함 그래서 코드에 적힌 순서와 실제 실행 순서가 같아 보여 가독성 굿
	**예시: 피자 주문하기**
    ```JavaScript
async function fetchPizza() {
    console.log("피자 주문 시작");
    try {
     // 1. orderPizza() Promise가 완료될 때까지 여기서 실행을 멈춥니다.
        const result = await orderPizza();
	// 2. Promise가 성공하면, 결과값이 result에 담겨 다음 줄이 실행됩니다.
        console.log(result);
    } catch (error) {
	// 3. 만약 Promise가 실패하면, catch 블록으로 즉시 이동합니다.
        console.log(error);
    } finally {
        console.log("주문 종료");
    }
}

fetchPizza();
    ```
- **`async`**: 함수 앞에 붙이면, 해당 함수는 항상 `Promise`를 반환합니다.
- **`await`**: `async` 함수 안에서만 사용 가능하며, `Promise`가 완료될 때까지 함수의 실행을 **일시 정지**하고 기다립니다. 
	- Promise가 성공하면 그 결과값을, 실패하면 에러를 반환합니다.
    - **중요** `await`는 `async` 함수 내부의 흐름만 멈출 뿐, 프로그램 전체는 진행되므로 **비동기적인 특성은 그대로 유지**됩니다.
    - `.then(result => ...)` **→** `const result = await ...`
- **에러 처리**: `Promise`의 `.catch()`와 달리, 일반적인 동기 코드처럼 `try...catch` 구문을 사용하여 에러를 직관적으로 처리할 수 있습니다.
	- `.catch(error => ...)` **→** `catch (error) { ... }``

#### 3. 실전예제-`fetch` API 
	2단계 Promise와 에러 처리
`fetch` API는 **두 단계의 Promise**로 동작하는 비동기 통신 인터페이스입니다. 
1) 응답에 대한 정보를 담고있는 헤더를 먼저 받고 
2) 실제 데이터인, 응답 본문(body)을 읽는 과정이 분리되어 있습니다.
---
#### 1단계 Promise: `fetch(url)` → `Response` 객체

`fetch(url)`는 호출 즉시 **첫 번째 `Promise`를**  반환합니다.
- 이 Promise는 서버로부터 **헤더(headers)가 도착**하면 즉시 이행(resolve)되며, 결과값으로 `Response` 객체를 반환합니다.
- **중요**: 이 단계에서는 아직 실제 데이터(body)를 모두 다운로드한 것이 아닙니다.
- 네트워크 연결 실패 시에만 `catch` 블록으로 넘어가고, `404 Not Found`나 `500` 서버 에러 같은 **HTTP 에러는 성공으로 간주**합니다.
---
#### **2단계 Promise: `response.json()` → 실제 데이터

`Response` 객체의 본문(body)은 바로 사용할 수 없는 **스트림(Stream)** 형태입니다. `response.json()` 메서드는 이 스트림을 끝까지 읽어 JavaScript 객체로 변환하는 작업을 수행합니다.
- 이 읽기/변환 과정은 비동기 작업이므로 **두 번째 `Promise`를** 반환합니다.
- 이 Promise가 최종적으로 이행되면, 우리가 실제로 사용하려는 JavaScript 객체를 얻게 됩니다.
    
---
#### 에러 처리 핵심: `response.ok`

`fetch`는 네트워크 에러만 감지하므로, HTTP 에러는 `response.ok` (상태 코드가 200-299 범위인지 확인) 속성을 통해 **반드시 수동으로 확인**해야 합니다. `!response.ok`일 경우, `throw new Error(...)`를 사용하여 의도적으로 에러를 발생시켜 `catch` 블록에서 처리해야 합니다.
#### **데이터 변환 흐름**
1. **서버 : JavaScript 객체**
	- `{ "id": 1, "user": "Alice" }`
2. **네트워크 전송 : JSON 텍스트**
	- `'{ "id": 1, "user": "Alice" }'`
3. **클라이언트 (`.json()` 실행 후)**: 다시 JavaScript 객체
	-  `{ "id": 1, "user": "Alice" }`

```JavaScript
async function getUserData() {
    const url = 'https://jsonplaceholder.typicode.com/users/1';
    
    try {
        // 1단계 Promise: HTTP 응답 헤더를 기다려 Response 객체를 받음
        const response = await fetch(url);

        // HTTP 에러 처리: `ok`가 false이면 에러를 발생시켜 catch 블록으로 보냄
        if (!response.ok) {
            throw new Error(`HTTP error! Status: ${response.status}`);
        }

        // 2단계 Promise: 응답 본문을 모두 읽어 JavaScript 객체로 변환
        const userData = await response.json();

        // 최종 데이터 사용
        console.log(userData);

    } catch (error) {
        // 네트워크 에러 또는 위에서 발생시킨 HTTP 에러를 여기서 처리
        console.error('Failed to fetch data:', error);
    }
}

getUserData();
```

## 프론트 :REACT
### 1. React란 무엇인가?

#### React는 라이브러리인가, 프레임워크인가?

리액트는 공식적으로 **라이브러리(Library)** 입니다. 둘의 가장 큰 차이는 **'코드의 제어권'이** 누구에게 있느냐입니다.

- **라이브러리 (React)**
    - **제어권**: 개발자
    - **설명**: 개발자가 필요할 때마다 라이브러리의 기능을 가져와 사용하는 방식입니다. 코드의 전체적인 흐름은 개발자가 직접 관리합니다.
        
- **프레임워크 (Spring Boot, Vue)**
    - **제어권**: 프레임워크
    - **설명**: 프레임워크가 정해놓은 규칙과 흐름 안에서 개발자가 코드를 작성하는 방식입니다. 프레임워크가 코드를 호출하고 실행합니다.
        
> 리액트는 때때로 생태계(ecosystem)가 워낙 방대하여 프레임워크에 가깝다고 불리기도 하지만, 핵심은 라이브러리라는 점에서 시작하는 것이 중요합니다.

---

#### React란?: SPA를 위한 자바스크립트 라이브러리

리액트는 사용자 인터페이스(UI)를 만들기 위한 **자바스크립트 라이브러리**입니다. 개발자가 코드의 전체 흐름을 제어하며 필요할 때 리액트의 기능을 가져와 사용하는 방식입니다.

리액트의 가장 큰 목표는 사용자와의 상호작용이 많은 현대적인 **싱글 페이지 애플리케이션(SPA)을** 효율적으로 개발하는 것입니다.

#### SPA vs. MPA: 왜 React가 필요한가?

리액트의 필요성을 이해하려면, 웹 페이지를 구성하는 두 가지 방식을 알아야 합니다.

| 구분     | **MPA (Multi Page Application)**            | **SPA (Single Page Application)**               |
| ------ | ------------------------------------------- | ----------------------------------------------- |
| **개념** | 여러 개의 HTML 파일로 구성된 전통적인 방식                  | **단 하나의 HTML 파일**로 구성된 현대적인 방식                  |
| **동작** | 페이지 이동 시, 서버에서 새 HTML을 받아와 **페이지 전체를 새로고침** | 변경이 필요한 데이터만 서버에서 받아와, **화면의 특정 부분만 동적으로 업데이트** |
| **단점** | 잦은 새로고침으로 인한 비효율 및 좋지 않은 사용자 경험             | 초기 로딩이 상대적으로 느릴 수 있고, 구조가 복잡해짐                  |
- 암기팁 
	- SPA (Single Page Application): **"하나의(Single) HTML 페이지"** 로 전체 웹사이트를 구성하는 방식
	- MPA (Multi Page Application) **"여러 개의(Multi) HTML 페이지"** 로 전체 웹사이트를 구성하는 방식

- **과거: MPA (Multi Page Application)**
    - 전통적인 웹사이트는 여러 개의 HTML 페이지로 구성된 **MPA**였습니다. 페이지를 이동할 때마다 전체가 새로고침되었습니다.
- **새로운 방식: SPA (Single Page Application)**
    - 더 나은 사용자 경험을 위해, 페이지 새로고침 없이 내용만 바뀌는 **SPA**가 등장했습니다.
    - 하지만 **바닐라 자바스크립트**만으로 복잡한 SPA를 만드는 것은 매우 어렵고 코드가 복잡해지는 문제가 있었습니다.
- **리액트의 등장**
    - **리액트(React)는** 바로 이 **SPA를 더 쉽고 효율적으로 만들기 위해** 등장한 라이브러리입니다.

---

### 2. React의 4가지 핵심 특징

리액트는 아래 4가지 특징을 통해 복잡한 SPA를 효율적으로 만들고 관리합니다.

#### **1. 컴포넌트(Component) 기반 구조**
- **개념**: 웹사이트의 UI를 **독립적인 부품(퍼즐 조각)으로** 나누어 개발하는 방식입니다. 각 컴포넌트는 자신만의 기능과 모양을 가지며, 보통 하나의 JavaScript 파일로 만들어집니다.
- **역할**: 이 컴포넌트들을 조립하여 하나의 완성된 웹 페이지를 만듭니다. 덕분에 코드의 **재사용성**이 높아지고, 특정 기능만 수정하거나 관리하기가 매우 쉬워집니다.
- **컴포넌트(Component)란?** 웹 페이지의 UI를 구성하는 **독립적이고 재사용 가능한 부품**입니다. React는 이러한 컴포넌트들을 조립하여 하나의 완전한 애플리케이션을 만듭니다.
#### **2. 가상돔(Virtual DOM)과 성능 최적화**

- **문제점**: 자바스크립트로 실제 DOM(웹페이지의 구조)을 직접 조작하는 것은 매우 느리고 비효율적인 작업입니다.
- **동작 방식**:
    1. 데이터에 변화가 생기면, 먼저 **가상 DOM**에 변경 사항을 적용합니다.
    2. 리액트는 이전의 가상 DOM과 변경된 가상 DOM을 **비교(Diffing)**하여 바뀐 부분을 찾아냅니다.
    3. 마지막으로, 이 **바뀐 부분만 실제 DOM에 딱 한 번 적용**합니다.
- **핵심 목표**: 불필요한 DOM 수정을 최소화하여 랜더링을 최소화해 **애플리케이션의 성능을 최적화**하는 것이 주된 목적입니다.

#### **3. 선언형(Declarative) 프로그래밍**
- **개념**: "어떻게" 처리할지 과정을 일일이 코드로 명령하는 것이 아니라, "어떤 모습이어야 하는지(결과)"를 코드로 **선언**하면 리액트가 그 과정은 알아서 처리하는 방식입니다.
- **비유 (내비게이션)**:
    - **명령형 (바닐라 JS)**: "좌회전하세요. 500m 직진 후 우회전하세요..." (과정을 순서대로 지시)
    - **선언형 (리액트)**: "서울역으로 가자." (최종 목적지만 선언)
- **역할**: 개발자는 데이터 상태에 따라 UI가 어떤 모습이어야 하는지만 정의하면 됩니다. 복잡한 UI 변경 과정을 리액트가 담당하므로 코드가 훨씬 간결하고 예측 가능해집니다.

#### **4. 단방향 데이터 바인딩 (One-way Data Binding)**
리액트 애플리케이션은 컴포넌트들이 **트리(Tree) 구조**로 구성되어 있습니다. 하나의 최상위 컴포넌트에서 시작하여, 그 아래로 여러 **부모-자식 관계**의 컴포넌트들이 계층적으로 연결됩니다.

이 구조 때문에 리액트의 데이터는 폭포수처럼 항상 위에서 아래로, 즉 **부모 컴포넌트에서 자식 컴포넌트로만 전달**되는 중요한 특징을 가집니다. 이 데이터는 **`props`** 라는 통로를 통해 전달되며, 자식은 부모로부터 받은 데이터를 직접 수정할 수 없습니다.

- **이 방식의 장점**
    - **예측 가능성**: 데이터의 출처가 항상 부모로 명확하기 때문에, 앱이 복잡해져도 데이터 흐름을 추적하고 문제의 원인을 찾기가 매우 쉽습니다.
    - **안정성**: 자식 컴포넌트가 부모나 다른 컴포넌트의 상태를 마음대로 바꿀 수 없어, 예기치 않은 부작용(side effect)을 방지하고 코드의 안정성을 높입니다.

### 4. React 프로젝트 구조와 렌더링 원리 ⚙️

React 애플리케이션의 동작을 이해하려면, 프로젝트를 구성하는 **핵심 파일들의 역할**과 이들이 상호작용하여 화면을 그리는 **렌더링 과정**을 알아야 합니다.

---
#### 1. 핵심 파일 및 폴더 역할
 React 앱은 크게 세 가지 핵심 영역으로 나뉘어 각자의 역할을 수행합니다.
 - 📁 `public` 폴더와 📄`index.html`
	- **`public` 폴더**: 이미지, 폰트 등 별도의 처리 없이 원본 그대로 사용될 **정적 파일(Static Assets)을** 저장하는 공간입니다.
		- 이 폴더의 파일들은 웹 서버에 배포 시, `https://내웹사이트.com/파일이름`처럼 직접 URL로 접근할 수 있습니다.
	- **`index.html`**: React 애플리케이션의 유일한 HTML 문서이자 브라우저가 최초로 불러오는 **진입점(Entry Point)** 입니다. 이 파일의 가장 핵심적인 역할은 React 앱이 그려질 아래의 `div` 요소를 제공하는 것입니다.
	    ```HTML
	    <div id="root"></div>
	    ```
	    
	    이 `div` 요소가 바로 **루트 DOM 노드(Root DOM Node)**, 즉 React가 제어할 DOM의 최상위 요소가 됩니다.
- 📁 `src` 폴더와 핵심 소스 코드
	- **`src` 폴더**: 컴포넌트, 스타일, 로직 등 **애플리케이션의 모든 핵심 소스 코드**가 위치하는 공간입니다.
		- 개발자는 컴포넌트, 스타일, 로직 등 대부분의 파일을 이곳에서 작성합니다.
	- **📄 `App.js` : 최상위 컴포넌트**
	    - 애플리케이션 UI의 가장 큰 틀을 구성하는 **루트 컴포넌트(Root Component)** 입니다.
	    - 모든 하위 컴포넌트들은 이 `App` 컴포넌트 내부에 조립되어 하나의 UI를 형성합니다.
	    - `export default App;` 구문을 통해 `App` 컴포넌트를 다른 파일에서 `import` 할 수 있도록 외부로 내보냅니다.
	        - **`export` (내보내기)**: `App` 컴포넌트를 "공개" 상태로 만듭니다.
			- **`default`**: 이 파일에서는 `App` 컴포넌트가 **대표**라는 의미입니다
	- **📄 `index.js` : 애플리케이션의 연결고리**
	    - JavaScript 코드의 실행이 시작되는 **시작점(Entry Point)** 으로, 텅 빈 HTML(`index.html`)과 동적인 React 컴포넌트(`App.js`)를 연결하는 역할을 합니다.
	    - `public/index.html`의 `<div id="root">`를 찾아, 그 안에 `<App />` 컴포넌트를 그려 넣으라고(렌더링) 명령합니다.
		- 이 파일의 코드는 크게 두 부분으로 나뉩니다.
			1. 상단부분 **`import`**: `React`, `ReactDOM`, `<App />` 등 필요한 기능들을 불러옵니다.
			2. 본문부분 **렌더링**: 불러온 `ReactDOM`을 사용하여 `<App />` 컴포넌트를 실제 웹 페이지에 그립니다
- 📁 `node_modules`와 의존성 관리
	
	- **`package.json`**: 프로젝트 메타정보와 실행에 필요한 **라이브러리(의존성) 목록**을 기록하는 설정 파일입니다.
	    - 다른개발자에게 package.json 파일만 공유합니다. npm install 명령어 하나로 동일한 node_modules 폴더를 복원할 수 있습니다.
	- **`package-lock.json`**: 설치된 라이브러리들의 **정확한 버전**을 기록하여, 모든 개발 환경에서 동일한 버전의 패키지를 사용하도록 보장합니다. (npm이 자동 관리)
	- **`node_modules` 폴더**: `npm install` 시 `package.json`과 `package-lock.json`을 바탕으로 **실제 라이브러리 파일들이 설치되는 공간**입니다. 용량이 매우 커서 Git으로 관리하지 않습니다.

#### 2. React 렌더링 과정

이제 위 파일들이 어떻게 상호작용하여 화면을 렌더링하는지 3단계로 나누어 살펴보겠습니다.

##### **1단계: HTML 파싱 및 DOM 생성**

사용자가 웹사이트에 접속하면 브라우저는 `public/index.html` 파일을 받아옵니다. 그 후, 텍스트로 된 HTML 문서를 **파싱(Parsing)**하여 자바스크립트가 제어할 수 있는 객체 구조인 **DOM(문서 객체 모델)**을 메모리에 생성합니다. 이 단계에서 `<div id="root"></div>`는 생성되지만 내부는 비어있습니다. 그러므로 화면에는 아무것도 보이지 않습니다
- **파싱(Parsing)**: 텍스트로 된 문서를 브라우저가 이해하고 사용할 수 있는 구조(DOM)로 변환하는 과정
##### **2단계: JavaScript 실행 및 React 연결**

`index.html`을 파싱하던 브라우저는 `<script>` 태그를 만나 **번들링된 JavaScript 파일**을 실행합니다. 이 코드의 시작점은 `src/index.js`이며, 이 파일이 React 애플리케이션을 DOM에 연결하는 모든 작업을 수행합니다.
- 번들: `src` 폴더의 모든 자바스크립트 파일이 하나로 합쳐진 파일 
##### **3단계: `ReactDOM`으로 컴포넌트 렌더링**

DOM이 준비되고 필요한 모듈이 모두 로드되면, `index.js`는 `ReactDOM` 라이브러리를 사용하여 실제 화면을 그립니다. 아래는 이 과정을 한눈에 보여주는 `index.js`의 전체 코드입니다.

```JavaScript
// src/index.js

// 1. 필요한 라이브러리 불러오기
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App'; // 렌더링할 최상위 컴포넌트

// 2. 렌더링할 DOM 요소 선택
const rootElement = document.getElementById('root');

// 3. React Root 생성
const root = ReactDOM.createRoot(rootElement);

// 4. 컴포넌트 렌더링 실행
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

> **코드 동작 요약**
> 
> 1. **`import`**: `React`, `ReactDOM`, `<App/>` 등 필요한 모듈을 불러옵니다.
>     
> 2. **DOM 요소 선택**: `document.getElementById('root')`로 HTML의 렌더링 위치를 찾습니다.
>     
> 3. **React Root 생성**: 찾은 DOM 요소를 `ReactDOM.createRoot()`에 전달하여 React가 제어할 전용 공간을 만듭니다. 이 `root` 객체는 UI를 그리는 `render()` 메서드를 가집니다.
>     
> 4. **렌더링 실행**: `root.render()`에 최상위 컴포넌트인 `<App />`을 전달하여 실제 DOM에 UI를 그려 넣습니다.
> 	이 명령이 실행되는 즉시, React는 `<App />` 컴포넌트부터 시작하는 모든 컴포넌트 트리를 실제 DOM(`#root`) 내부에 삽입합니다.
>
### **5. React 핵심 문법과 도구**
JavaScript 파일(`App.js`) 안에서 HTML과 비슷한 코드를 자유롭게 작성할 수 있는 이유는 다음과 같은 핵심 문법과 도구 덕분입니다.

#### **1. JSX: JavaScript를 위한 구문 확장**

JSX는 JavaScript 파일 내에서 UI 구조를 시각적으로 표현하기 위해 HTML과 유사한 마크업을 사용할 수 있게 하는 특별한 문법입니다.

```JavaScript
function App() {// in App.js
  return (
    <div className="App">Hello, React!</div>
  );
}
```

- **주요 기능**:
    1. JavaScript 함수 안에서 HTML과 비슷한 코드를 `return` 할 수 있게 합니다.
    2. `App.js`와 같은 컴포넌트 파일을 `<App />` 형태의 태그로 사용할 수 있게 합니다.
- **특징**: JSX는 코드의 가독성을 높이지만, 브라우저가 직접 실행할 수는 없습니다. 실행 전에 반드시 '바벨'을 통해 순수 JavaScript로 변환되어야 합니다.
#### **2. 바벨(Babel): JavaScript 컴파일러**

**바벨(Babel)은** JSX나 최신 JavaScript 문법을 구형 브라우저에서도 호환되는 표준 JavaScript 코드로 변환(컴파일)해주는 도구입니다.다.

- **역할**:
    1. **JSX 변환**: `<div />`와 같은 JSX 코드를 브라우저가 이해할 수 있는 `React.createElement()` 함수 호출로 변환합니다
	2. **버전 호환성**: 화살표 함수, `const/let` 등 최신 최신 JavaScript 문법을 구형 브라우저에서도 동작하는 코드(ES5)로 변환하여 호환성을 확보합니다.
- **동작 방식**: Create React App이나 Vite 같은 개발 환경에서는 코드를 저장하거나 실행할 때마다 바벨이 자동으로 동작합니다. 개발자는 별도의 설정 없이 편리하게 최신 문법을 사용할 수 있습니다.
#### JSX 작성 핵심 규칙 ✍️

React의 UI를 작성하는 JSX는 HTML과 비슷해 보이지만, JavaScript 위에서 동작하기 때문에 반드시 지켜야 할 몇 가지 중요한 문법 규칙이 있습니다.

---
##### 1. 컴포넌트는 대문자로 시작해야 합니다.

React는 태그의 첫 글자가 **소문자이면 일반 HTML 태그(`div`, `span` 등)로, 대문자이면 직접 만든 React 컴포넌트(`MyComponent`)로** 인식합니다.
- **올바른 예시**:
    ```JavaScript
    function MyButton() { // 컴포넌트 이름은 대문자로 시작
      return <button>I'm a button</button>;
    }
    
    function App() {
      return (
        <div>
          <MyButton /> {/* 컴포넌트 사용 시에도 대문자로 시작 */}
        </div>
      );
    }
    ```
---
##### 2. 하나의 최상위 요소만 반환해야 합니다.

컴포넌트가 반환(return)하는 JSX 코드는 반드시 **하나의 태그로 감싸져 있어야 합니다.** 여러 개의 태그를 나란히 반환할 수 없습니다.
- **잘못된 예시 (Error)**:
    ```JavaScript
    return (
      <h1>제목</h1>
      <p>내용</p> // <h1>과 <p>가 동등한 위치에 있어 에러 발생
    );
    ```
- **올바른 예시**:
    ```JavaScript
    return (
      <div> {/* 하나의 div로 감싸기 */}
        <h1>제목</h1>
        <p>내용</p>
      </div>
    );
    ```
> **Tip: 불필요한 div를 피하고 싶을 때** 💡 실제 렌더링 시 불필요한 `<div>` 태그를 만들고 싶지 않다면, 비어있는 태그인 **Fragment (`<>...</>`)**를 사용하세요.
```JavaScript
return ( 
	<> 
		<h1>제목</h1> 
		<p>내용</p> 
		</> 
		);
```
---

##### 3. 모든 태그는 닫혀있어야 합니다.

HTML과 달리, JSX에서는 모든 태그가 반드시 닫혀있어야 합니다.
- **일반 태그**: `<div>`는 `</div>`로 닫습니다.
- **내용이 없는 태그**: `<br>`, `<img>`, `<input>` 등은 반드시 **셀프 클로징 태그 (`/>`)**로 닫아주어야 합니다.
    ```JavaScript
    // HTML에서는 <br>도 가능하지만, JSX에서는 <br />만 가능합니다.
    return (
      <>
        첫 번째 줄<br />
        <img src="path/to/image.jpg" alt="예시 이미지" />
        <input type="text" />
      </>
    );
    ```
---
##### 4. `class` 대신 `className`을 사용합니다.

JSX에서 CSS 클래스를 지정할 때는 `class`가 아닌 **`className`** 속성을 사용해야 합니다. `class`는 JavaScript에서 클래스를 선언하는 **예약어(reserved keyword)**이기 때문입니다.

```JavaScript
// App.js
function App() {
  return <div className="greeting">Hello, React!</div>;
}

// App.css
// .greeting { color: blue; }
```
---
##### 5. JavaScript 표현식은 `{}` 안에 작성합니다.
JSX 내부에서 변수나 간단한 계산 등 JavaScript 코드를 사용하고 싶을 때는 **중괄호 `{}`**로 감싸주어야 합니다.
- **주석 처리**: 주석 또한 JavaScript이므로, `{/* 주석 내용 */}` 형태로 작성합니다.
- **규칙**: `{}` 안에는 변수, 함수 호출, 계산식 등 **결과가 값으로 나오는 표현식(Expression)**만 사용할 수 있습니다. (`if`문, `for`문 같은 문(Statement)은 직접 사용할 수 없습니다.)
```JavaScript
function UserProfile({ user }) {
  const a = 10;
  const b = 20;

  return (
    <div>
      {/* user 객체의 name 프로퍼티를 동적으로 표시 */}
      <h1>{user.name}님, 환영합니다.</h1>

      {/* 간단한 계산식 사용 */}
      <p>계산 결과: {a} + {b} = {a + b}</p>
    </div>
  );
}
```
### 6. React 개발 규칙: "하나의 파일, 하나의 컴포넌트"

React 개발에는 강제는 아니지만, 거의 모든 개발자가 따르는 중요한 규칙이 있습니다.

> **하나의 컴포넌트 파일(예: `App.js`)에는 반드시 하나의 컴포넌트 함수만 작성한다.**

이 규칙을 지키면 코드의 구조가 명확해지고, 특정 컴포넌트를 찾거나 수정하기가 매우 쉬워져 유지보수성이 크게 향상됩니다.

- 개발이란 기존 기술들을 바탕으로 **'어떻게 하면 데이터와 화면을 더 안정적이고 효율적으로 연결할까?'** 라는 고민을 해결해 나가는 과정임

### 7.`useState`: React 컴포넌트의 기억 장치 💡

React에서 **상태(State)**는 컴포넌트가 기억해야 할 **'바뀔 수 있는 데이터'입니다**. 사용자의 입력, API 응답 등 동적인 정보를 담는 그릇이며, React는 이 상태가 변경될 때마다 화면을 자동으로 다시 그려(리렌더링) 변경 사항을 UI에 반영합니다.

`useState`는 함수형 컴포넌트에서 이러한 상태를 만들고 관리하게 해주는 React의 가장 기본적인 Hook입니다.

#### `useState` 사용법
`useState`는 컴포넌트의 렌더링 과정에서 호출되며, **상태 값**과 그 값을 **업데이트하는 함수**를 배열 형태로 반환합니다.
```JavaScript
const [state, setState] = useState(initialValue);
```
- **`state`**: **현재 렌더링**에서의 상태 값입니다. 이 값은 해당 렌더링 주기 동안 절대 변하지 않는 **읽기 전용 값(스냅샷)입니다.**
- **`setState`**: 상태 값을 **업데이트하는 함수**입니다. 이 함수를 호출하면 React에게 다음 렌더링을 예약합니다.
- **`initialValue`**: 상태의 **초기값**입니다. 이 값은 컴포넌트가 **최초 렌더링될 때 단 한 번만** 사용됩니다.

- ###### **호출 순서에 따른 과정** (아직 몰라두됨)
	1. **`useState(initialValue)` 실행**: 컴포넌트가 렌더링될 때 `useState` 함수가 먼저 호출됩니다. React는 이 함수를 통해 상태를 저장할 공간을 만들고, 인자로 받은 `initialValue`를 그 공간의 **초기값**으로 설정합니다.
    
	2. **배열 반환**: `useState`는 `[ 현재값, 상태변경함수 ]` 형태의 배열을 반환합니다.
	    - **최초 렌더링 시**: `[ initialValue, 상태변경함수 ]`
	    - **이후 렌더링 시**: `[ 현재_상태값, 상태변경함수 ]`
        
	3. **배열 디스트럭처링**: 반환된 배열의 요소들이 `state`와 `setState` 변수에 순서대로 할당됩니다.
	    - `state` 변수에는 **현재 렌더링 시점의 상태 값**이 담깁니다. (읽기 전용)
	    - `setState` 변수에는 **상태를 변경(업데이트)하는 함수**가 담깁니다.
---

#### `useState`의 동작 원리:  스냅샷과 업데이트 예약

`useState`의 동작을 이해하는 핵심은 **"상태 업데이트는 즉시가 아니라 예약된다"**는 것입니다.

##### 1. 상태는 렌더링 시점의 스냅샷이다
`state` 변수는 특정 렌더링이 시작될 때의 값으로 **고정(fixed)**됩니다. 마치 사진을 찍는 것처럼, 해당 렌더링 주기 안에서는 그 값이 변하지 않습니다.
##### 2. 상태 업데이트는 '예약'이다

`setState` 함수(예: `setCount(1)`)는 현재 렌더링의 `state` 값을 직접 바꾸지 않습니다. 대신, **"다음 렌더링 때 이 값으로 바꿔주세요"** 라고 React에게 **업데이트를 예약**하는 역할을 합니다.
- `setState`가 즉시, 동기적으로 상태를 변경한다면, 하나의 함수가 실행되는 도중에 상태 값이 계속해서 바뀌게 됩니다.
##### 3. 업데이트는 '일괄 처리(Batching)'된다
이벤트 핸들러 내에서 `setState`가 여러 번 호출되더라도, React는 이를 즉시 처리하지 않고 **하나의 작업으로 묶어 단 한 번의 리렌더링만 수행**합니다. 이는 불필요한 렌더링을 막아 성능을 최적화하고, 상태의 일관성을 유지하기 위함입니다 
- 브라우저에서 DOM(Document Object Model)을 변경하는 작업은 상대적으로 많은 연산이 필요한, 비용이 비싼 작업입니다.
```JavaScript
function handleClick() {
  setCount(count + 1); // 리렌더링 예약 (count는 아직 이전 값)
  setCount(count + 1); // 리렌더링 예약 (count는 여전히 이전 값)
  // 이 함수가 끝나면, React는 count를 한 번만 증가시켜 리렌더링합니다.
}
```
####  올바른 상태 업데이트 방법

##### 1. 다음 상태 값을 직접 전달하기

새로운 상태가 이전 상태와 무관할 때 사용합니다.

```JavaScript
const [name, setName] = useState('Guest');
// ...
setName('John'); // name을 'John'으로 업데이트 예약
```
##### 2. 함수를 전달하기 (Functional Update) ✨

**이전 상태 값에 의존**하여 다음 상태를 결정할 때는 반드시 함수를 전달해야 합니다. 이는 '일괄 처리' 시 발생할 수 있는 문제를 방지하는 가장 안전하고 정확한 방법입니다.

```JavaScript
const [count, setCount] = useState(0);

function handleIncrease() {
  // 👎 잘못된 방법: setCount(count + 1);
  
  // 👍 올바른 방법: 이전 상태(c)를 받아와 새로운 상태를 반환
  setCount(c => c + 1); 
  setCount(c => c + 1); // 이렇게 두 번 호출하면 count가 2 증가합니다.
}
```
`setState`에 함수를 전달하면, React는 그 함수를 나중에 실행할 때 최신 상태 값을 인자(위 예제의 `c`)로 넣어줍니다.

---
#### 주의할 점: 무한 렌더링 ⚠️

`setState` 함수를 컴포넌트의 본문에서 직접 호출하면 **무한 렌더링 루프**에 빠집니다.

```JavaScript
function MyComponent() {
  const [name, setName] = useState('');
  
  setName('React'); // 렌더링될 때마다 상태 변경을 '예약'함 -> 무한 루프!
  
  return <div>{name}</div>;
}
```
- **무한 렌더링 과정**:
    1. **첫 렌더링**: `setName('React')` 호출 → 다음 렌더링 예약.
    2. **두 번째 렌더링**: `name`이 'React'가 되지만, 또다시 `setName('React')` 호출 → 다음 렌더링 또 예약.
    3. **무한 반복**: 이 과정이 반복되다가 "Too many re-renders" 에러가 발생합니다.
> **결론**: 상태 변경 함수(`setState`)는 반드시 **이벤트 핸들러(`onClick` 등)나 `useEffect` 훅 내부**와 같이, 특정 조건 하에서만 호출해야 합니다.

### 8. React 이벤트 처리: `onChange`와 `onClick`

#### 1. `onChange`: 사용자 입력 실시간 감지 ⌨️

`onChange`는 `<input>`, `<textarea>` 등 입력 요소의 **값이 변경될 때마다** 발생하는 이벤트입니다. 사용자의 키보드 입력 하나하나를 감지하여 React의 **상태(State)와 동기화**하는 데 사용됩니다.

##### 핵심 패턴: 제어 컴포넌트 (Controlled Component)

`onChange`로 입력 값을 상태에 저장하고, 그 상태를 다시 `<input>`의 `value` 속성에 연결하는 방식을 **제어 컴포넌트**라고 합니다. 이 패턴을 통해 데이터의 흐름을 React가 완벽하게 통제하여 예측 가능하고 안정적인 폼(Form)을 만들 수 있습니다.

- **`e.target.value`**: 이벤트 핸들러 함수는 **이벤트 객체(`e`)**를 인자로 받습니다. `e.target`은 이벤트가 발생한 DOM 요소(여기서는 `<input>`)를 가리키며, `e.target.value`는 그 요소의 현재 값을 의미합니다.
---
#### 2. `onClick`: 사용자 클릭 액션 실행 🖱️

`onClick`은 `<button>`, `<div>` 등 특정 요소를 사용자가 **마우스로 클릭**했을 때 발생하는 이벤트입니다. 보통 `onChange`를 통해 업데이트된 상태 값을 **사용**하여 특정 액션을 실행하는 데 쓰입니다.

---
#### 통합 예시: 이름 입력받아 인사하기

아래는 `onChange`로 사용자의 입력을 받아 상태를 업데이트하고, `onClick`으로 그 상태를 사용해 환영 메시지를 띄우는 전체 코드입니다.
```JavaScript
import React, { useState } from 'react';

function GreetingComponent() {
  // 1. 상태(State) 선언
  const [name, setName] = useState(''); // 사용자가 입력할 이름을 저장하는 상태
  const [greeting, setGreeting] = useState(''); // 최종 인사 메시지를 저장하는 상태

  // 2. onChange 이벤트 핸들러
  //    - input 값이 바뀔 때마다 name 상태를 업데이트합니다.
  const handleNameChange = (e) => {
    setName(e.target.value);
  };

  // 3. onClick 이벤트 핸들러
  //    - 버튼 클릭 시, 현재 name 상태를 사용해 greeting 상태를 업데이트합니다.
  const handleGreetClick = () => {
    if (!name) {
      alert('이름을 입력해주세요!');
      return;
    }
    setGreeting(`${name}님, 환영합니다!`);
  };

  // 4. JSX 렌더링
  return (
    <div>
      {/* value와 onChange를 연결하여 '제어 컴포넌트'로 만듭니다. */}
      <input
        type="text"
        value={name}
        onChange={handleNameChange}
        placeholder="이름을 입력하세요"
      />
      
      <button onClick={handleGreetClick}>인사하기</button>

      {/* greeting 상태에 값이 있을 때만 메시지를 보여줍니다. */}
      {greeting && <h1>{greeting}</h1>}
    </div>
  );
}

export default GreetingComponent;
```
> **핵심 흐름 요약**
> 1. **`onChange`**: 사용자가 입력창에 글자를 입력하면 `name` 상태가 실시간으로 변경됩니다.
> 2. **`onClick`**: 사용자가 '인사하기' 버튼을 클릭하면, 현재 `name` 상태에 저장된 값을 가져와 `greeting` 상태를 업데이트합니다.
> 3. **리렌더링**: `greeting` 상태가 변경되었으므로 컴포넌트가 리렌더링되고, 화면에 환영 메시지가 나타납니다.
### 9. useEffect로 컴포넌트 초기 동작 제어
#### React 렌더링의 핵심 원칙: 순수성
React 컴포넌트의 주된 임무는 `props`와 `state`를 기반으로 UI를 **렌더링**하는 것입니다. 이때 좋은 React 코드는 **"렌더링의 순수성"을** 지켜야 합니다.
- **순수한 렌더링이란?** 🧪
	- **입력(`props`, `state`)이 같으면 항상 동일한 출력(JSX)을 반환**해야 합니다.
	- 렌더링 과정에서 어떠한 **부수 효과(Side Effects)**도 일으키지 않아야 합니다.
- 렌더링의 순수성이 중요한 이유 (안봐도 됨)
	1. 렌더링이 순수하면 UI는 오직 `props`와 `state`에 의해서만 결정됩니다. 이는 코드의 동작을 예측하기 쉽게 하고 버그를 찾아 해결하는 것을 용이하게 합니다.
	2. React는 `props`와 `state`가 변하지 않았을 때, **불필요한 렌더링을 건너뛰는(skip) 최적화**를 수행합니다.
	3. 최신 React는 여러 개의 렌더링 작업을 동시에 수행하는 등의 복잡한 기능을 위해선, 작업들간의 간섭을 막아야 합니다
	- 과거 클래스 컴포넌트 시절에는 부수 효과들을 `componentDidMount`(첫 렌더링 후), `componentDidUpdate`(업데이트 후), `componentWillUnmount`(컴포넌트 제거 전) 같은 여러 생명주기 메소드에 흩어져서 작성해야 했습니다. `useEffect`는 이 모든 부수 효과들을 **하나의 통일된 API**로 통합함으로써, 함수형 컴포넌트에서 부수 효과를 더 직관적이고 효율적으로 관리할 수 있게 만들었습니다.
하지만 실제 애플리케이션에서는 API 요청, 타이머 설정, 이벤트 리스너 등록 등 렌더링과 직접 관련 없는 작업, 즉 **부수 효과**가 반드시 필요합니다.

`useEffect`는 바로 이 **부수 효과를 React의 렌더링 흐름에서 분리하여 처리**하기 위해 탄생한 Hook입니다. 

`useEffect`의 핵심 역할은 **"React 컴포넌트를 외부 시스템과 동기화(synchronize)하는 것"입니다.**

---
#### `useEffect` 사용법과 동작 원리

`useEffect`는 **셋업(setup) 함수**와 **의존성 배열** 두 인자를 받으며, 컴포넌트가 렌더링된 후(DOM 업데이트가 완료된 직후)에 실행됩니다.
```JavaScript
useEffect(() => {
  // 1. 실행할 동기화(Side Effect) 코드 (셋업)
  
  return () => {
    // 2. 뒷정리(Cleanup) 코드 (선택 사항)
  }
}, [/* 3. 의존성 배열 */]);
```
- **① 셋업 함수**: 실행하려는 부수 효과 코드를 작성합니다. (예: API 요청, 이벤트 리스너 등록)
- **② 뒷정리 함수 (Cleanup)**: 셋업 함수가 반환하는 함수로, 부수 효과를 "청소"할 때 사용됩니다. (예: 타이머 해제, 이벤트 리스너 제거)
- **③ 의존성 배열**: 이 배열에 포함된 값들이 변경될 때만 셋업 함수가 다시 실행됩니다. 
---
#### 의존성 배열(Dependency Array) 사용법 3가지
의존성 배열을 어떻게 설정하느냐에 따라 `useEffect`의 실행 시점이 달라집니다.
##### 1. 배열을 생략하는 경우 (거의 사용 안 함)
```JavaScript
useEffect(() => {
  // 컴포넌트가 렌더링될 때마다 매번 실행
});
```
- **실행 시점**: 최초 렌더링 및 **모든 리렌더링 시마다** 항상 실행됩니다.
- **주의**: 상태 변경 코드를 포함하면 무한 루프에 빠질 수 있어 사용을 지양해야 합니다.

##### 2. 빈 배열(`[]`)을 전달하는 경우
```JavaScript
useEffect(() => {
  // 컴포넌트가 처음 렌더링될 때 딱 한 번만 실행
  console.log('최초 마운트 시 1회 실행됩니다.');
}, []);
```

- **실행 시점**: 컴포넌트가 **최초 렌더링(마운트)된 직후, 딱 한 번만** 실행됩니다.
- **주요 용도**: 처음 한 번만 필요한 초기 데이터 로딩(API 호출), 이벤트 리스너 등록 등 "컴포넌트가 처음 나타날 때"의 로직에 사용됩니다.
##### 3. 배열에 특정 값(`[name]`)을 전달하는 경우
```JavaScript
useEffect(() => {
  // name 상태가 변경될 때마다 실행
  console.log(`이름이 ${name}으로 변경되었습니다.`);
}, [name]);
```
- **실행 시점**: 최초 렌더링 시 한 번 실행되고, 그 이후에는 **의존성 배열 안의 `name` 상태가 변경될 때마다** 다시 실행됩니다.
- **주요 용도**: 특정 `props`나 `state`가 변경될 때마다 관련 작업을 다시 수행해야 할 때 사용됩니다.

#### 뒷정리 함수 (Cleanup Function) 🧹

`useEffect`에서 등록한 부수 효과는 컴포넌트가 사라질 때(unmount) 정리해주지 않으면 메모리 누수나 버그의 원인이 될 수 있습니다.

**뒷정리 함수**는 `useEffect`의 셋업 함수가 **반환하는 함수**이며, 이 역할을 수행합니다.

```JavaScript
useEffect(() => {
  // 셋업: 타이머 시작
  const timerId = setInterval(() => {
    console.log('타이머 실행 중...');
  }, 1000);

  // 뒷정리: 컴포넌트가 사라질 때 타이머 해제
  return () => {
    clearInterval(timerId);
    console.log('타이머가 정리되었습니다.');
  };
}, []); // 최초 1회만 실행 및 정리
```
##### **뒷정리 함수는 언제 실행될까요?**
1. **컴포넌트가 화면에서 사라질 때 (Unmount)**: 메모리 누수를 방지합니다.
2. **`useEffect`가 다시 실행되기 직전**: 의존성이 변경되어 새로운 셋업 함수가 실행되기 전에, 이전의 부수 효과를 먼저 정리합니다. 이는 부수 효과가 중복으로 쌓이는 것을 방지합니다.

## React 나중에 볼것
 - ### Vite(React) 기본 폴더 구조 설명
	- **핵심 차이**:
	    - `index.html`의 위치(루트),
	    - 심플하고 커스터마이즈 가능한 `src` 구조,
	    - 명확히 분리된 설정(vite.config.js)  
	        등이 Vite의 특징입니다.
	#### 1. `node_modules` 폴더: 라이브러리 저장소
	
	- **역할**: Vite와 React를 포함한 모든 외부 라이브러리가 설치되는 장소입니다.
	- **생성 과정**: `npm install` 혹은 `yarn` 실행 시 의존성들이 여기에 설치됩니다.
	- **특징**: 용량이 매우 크고, `.gitignore`에 포함되어 있어 코드 공유 시 제외됩니다.
	#### 2. `public` 폴더: 정적 자원 관리
	
	- **역할**: favicon 또는 일부 정적 이미지, 파일 등을 보관하는 곳입니다.
	- **특이점**:
	    - Vite 프로젝트에선 이 폴더 안 내용이 별도 빌드 처리 없이 그대로 공개 경로(`/`)로 서비스됩니다.
	    - 기본적으로 `favicon.ico` 하나만 존재하거나 아예 비어 있을 수 있음.
	#### 3. `index.html` 파일 (루트 디렉토리에 위치)
	
	- **역할**:
	    - Vite 프로젝트의 가장 큰 특징은, `index.html`이 `public` 폴더가 아닌 프로젝트 최상위(루트)에 있다는 점입니다.
	    - 이 파일 내의 `<div id="root"></div>`(혹은 `id="app"`)는 React 앱이 실제로 마운트되는 진입점 역할을 합니다.
	    - Vite는 특별한 플러그인 없이도 이 HTML을 개발/배포 환경에서 자체 처리합니다.
	#### 4. `src` 폴더: 개발의 중심
	
	- **역할**: 모든 TypeScript/JavaScript 코드, 컴포넌트, 스타일, 비즈니스 로직 등이 이곳에서 작성됩니다.
	- **기본 파일**:
	    - `main.jsx` (또는 `main.tsx`): 가장 상위 렌더링 파일. `index.html`의 `div#root`에 React 앱을 마운트합니다.
	    - `App.jsx` (또는 `App.tsx`): 최상위 React 컴포넌트.
	    - `assets/` 폴더: 기본적으로 로고 등 몇몇 파일이 있을 수 있음.
	- **구조적 특징**:
	    - CRA 대비 불필요한 파일이 거의 없음(예: 테스트 파일, 설명 주석 등 미포함)
	    - 구조가 매우 심플해서 개발자가 원하는 형태로 쉽게 확장, 커스텀 가능
	#### 5. 기타 주요 파일
	- **vite.config.js**:
	    - Vite의 환경설정 파일. 플러그인 추가, 별도 빌드 옵션, 경로 별칭 등 다양한 개발자 맞춤 환경을 손쉽게 적용할 수 있습니다.
	- **package.json**: 프로젝트 정보, 의존성, 실행 스크립트 관리.
	- **.gitignore**, **README.md** 등: CRA와 동일하게 프로젝트 설정/설명 용도로 존재.
	#### 정리: Vite(React) 프로젝트 연결 방식
	1. **루트의 `index.html`**이 `<div id="root"></div>`를 마련합니다.
	2. **`src/main.jsx`에서** `ReactDOM.createRoot(document.getElementById('root'))`로 `<App />`을 그려넣습니다.
	3. 모든 React 컴포넌트, 비즈니스 로직, 스타일은 `src/` 폴더 내에서 관리합니다.
	    
	#### 폴더 도식 예시
	my-vite-app/ 
		├── node_modules/ 
		├── public/ 
		│   └── favicon.ico 
		├── src/ 
		│   ├── assets/ 
		│   │   └── logo.svg 
		│   ├── App.jsx 
		│   └── main.jsx 
		├── index.html       <-- CRA와 다르게 루트에 위치! 
		├── package.json 
		├── vite.config.js 
		├── .gitignore 
		└── README.md`
