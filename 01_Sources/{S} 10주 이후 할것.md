# P0 — 프로덕션 하드닝(운영 안정화 · 보안 · 데이터)

## 운영/관측

* [ ] **SLO 선언**: 가용성(예: 99.9%), p95 지연, 오류율 목표 수립 및 대시보드 반영
* [ ] **알림 룰**: SLO 위반, 워커 지연(outbox/due\_tasks), 5xx/Deadlock, 락 체류 알람
* [ ] **런북 확장**: DB 장애/마이그 실패/락 교착/알림 적체/큐 재처리 절차
* [ ] **백업·복구 리허설**: 자동 백업 주기 확인 + 복구 연습(샘플 데이터로 검증)

## 보안/권한

* [ ] **토큰 수명·회전**: Access/Refresh 로테이션, `kid`/JWKS, **역할 변경 시 즉시 무효화(토큰버전)**
* [ ] **시크릿 관리**: 로컬 dotenv, 스테이징/프로덕션은 Secret Manager
* [ ] **입력 검증 고도화**: DTO/JSON Schema → 에러 카탈로그 1:1 매핑
* [ ] **RLS(행 수준 보안)**: 민감 테이블(아이템·벌점) 본인/권한 범위만 조회

## 데이터/스키마

* [ ] `resources` **서브타입 테이블** 도입(냉장 칸/세탁기/건조기/스터디룸/도서 속성 분리)
* [ ] `allocations` **EXCLUDE 제약** 재검증(타임존 UTC, 겹침 금지 범위 명시)
* [ ] **아카이브/보존정책**: `activity_logs / domain_events / outbox` TTL & 파티셔닝 설계
* [ ] **마이그 다운 전략 문서화**: 파괴적 변경은 단계적 릴리즈(컬럼 추가→채움→전환→드롭)

# P1 — 기능 확장(모듈별 심화)

## 냉장고(검사)

* [ ] **검사 리포트 PDF/CSV** 내보내기(칸/층/기간별)
* [ ] **NO\_STICKER 흐름 개선**: 미등록 폐기시 현장기입 필드 UX + 통계(반복 위반자)
* [ ] **권한 위임**: 층별장 교체/휴가 시 임시 권한 위임(만료 자동 회수)

## 세탁실

* [ ] **대신 남은시간 등록(UNAUTHORIZED\_USE)** → 자동 `AVAILABLE` 복귀 타이머
* [ ] **종료-5분 알림** 정확화(정정 반영) + **필터 청소 알림(건조기만)**
* [ ] **미회수 대응**: “기다리는 중”/“빼놓음” 알림 & 강제 `AVAILABLE` 전환 감사 로그

## 도서관

* [ ] **대출/반납/연장/예약** 완결 + D-3 알림 → **연체 벌점 자동 부과**
* [ ] **도서 관리**: 바코드/QR(Optional), 분실 처리, 카테고리/태그

## 스터디룸

* [ ] **주간 예약 오픈(월 00:00)** 스케줄러 + 슬롯 상한/취소 규칙
* [ ] **합석 가능 뱃지** 및 대기열(옵션)

## 마이페이지

* [ ] **통합 타임라인**(domain\_events 기반) + **개인 통계**(월/학기)
* [ ] 벌점 원본/조정 합산 뷰, 알림 수신 설정

# 공통 거버넌스/품질

## 테스트/품질

* [ ] **경합 테스트 스위트**: 번호 충돌·2인 동시에 제출·락 경합·Idempotency 재플레이
* [ ] **계약 테스트**: OpenAPI 스냅샷 회귀 + 429/423/409/422 케이스 고정
* [ ] **퍼지/프로퍼티 기반 테스트**: 상태머신 전이 유효성

## 배포/릴리즈

* [ ] **릴리즈 정책**: 세맨틱 버저닝, deprecation 가이드(헤더로 사전 공지)
* [ ] **피처 플래그**: 모듈별 롤아웃/롤백 플랜(스위치·가드)
* [ ] **카나리**(옵션): 읽기 트래픽 부분 전개, 에러율/지연 모니터링 연동

* [ ] **PII 분류·마스킹**: 로그/이벤트/백업에서 개인식별자 비가시화
* [ ] **감사 로그 보존/열람 정책**: 관리자 접근 로깅, 엑셀 내보내기 권한 제한

# “바로 만들 수 있는” 추가 스키마/이슈 템플릿

### 스키마(+)

* `resource_fridge_comp(comp_id, fridge_id, position_order, type)`
* `resource_washer(washer_id, brand, cycle_defaults ...)` / `resource_dryer(...)`
* `resource_studyroom(room_id, capacity, equipment ...)`
* `resource_book(book_id, isbn, author, tags ...)`
* `allocations(...)`(RESERVATION/USAGE/LOAN, 상태·겹침 제약 재확인)
* `penalties_original(source_type,source_id)` 확장(BOOK\_OVERDUE 등)
* `outbox(event_id, type, dedup_key, status, attempts, last_error)`
* `due_tasks(task_id, run_at, kind, payload, status, attempts)`

### 이슈 템플릿(요지)

* **배경/문제** → **수용 기준(AC)** → **스키마/API 변경** → **롤백/마이그 전략** → **관측 포인트(로그/메트릭/알림)**

# 권장 진행 순서(요약)

1. **P0**로 운영/보안/데이터 가드레일을 먼저 단단히 → 사고 복구·관측 가능 상태 확보
2. **P1**로 모듈 심화 + 플랫폼(멱등/아웃박스/락) 고도화 → 세탁/도서/스터디룸 확장
3. **P2**로 UX·PWA·성능·비용 최적화 → 사용자 만족/운영 비용 균형
