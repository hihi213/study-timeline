# 25년 1회차

### 🏛️ [소프트웨어 설계] 문제 은행 (Obsidian 용)

> [!note]- 1. 애자일(Agile) 개발 방법론의 특징에 해당하지 않는 것은? (① 개인과 상호작용 ② 실행되는 소프트웨어 ③ 고객과의 협업 ④ 공정하고 정형화된 프로세스)
>
> **정답:** ④ 공정하고 정형화된 프로세스
>
> **해설:**
>
> 애자일은 프로세스나 도구보다는 **개인과 상호작용**을, 방대한 문서보다는 **실행되는 소프트웨어**를, 계약 협상보다는 **고객과의 협업**을, 계획 준수보다는 **변화에 대한 대응**을 중시합니다.

> [!note]- 2. 소프트웨어 생명주기 모형 중 위험 분석(Risk Analysis) 단계를 추가하여 대규모 시스템 개발에 적합한 모형은? (① 폭포수 모형 ② 프로토타입 모형 ③ 나선형 모형 ④ RAD 모형)
>
> **정답:** ③ 나선형(Spiral) 모형
>
> **해설:**
>
> 나선형 모형은 폭포수와 프로토타입의 장점에 **위험 분석** 기능을 추가한 것으로, 계획 $\rightarrow$ 위험 분석 $\rightarrow$ 개발 $\rightarrow$ 평가의 순서를 반복하며 점진적으로 개발합니다.

> [!note]- 3. 디자인 패턴 중 생성(Creational) 패턴에 해당하는 것은? (① Adapter ② Prototype ③ Bridge ④ Facade)
>
> **정답:** ② Prototype
>
> **해설:**
>
> - 생성 패턴: Singleton, Factory Method, Abstract Factory, Builder, **Prototype**
>     
> - 구조 패턴: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy
>     
> - 행위 패턴: Observer, State, Strategy, Command, Visitor 등
>     

> [!note]- 4. 요구사항 개발 프로세스의 순서로 옳은 것은?
>
> **정답:** 요구사항 도출 $\rightarrow$ 요구사항 분석 $\rightarrow$ 요구사항 명세 $\rightarrow$ 요구사항 확인(검증)
>
> **해설:**
>
> 1. 도출(Elicitation): 이해관계자로부터 요구사항 수집
>     
> 2. 분석(Analysis): 상충되는 요구사항 해결 및 범위를 할당
>     
> 3. 명세(Specification): 문서를 작성(SRS)
>     
> 4. 확인(Validation): 요구사항이 고객의 의도와 일치하는지 검토
>     

> [!note]- 5. 객체지향의 특징 중 하나로, 하위 클래스가 상위 클래스의 속성과 메서드를 물려받는 것은? (① 캡슐화 ② 정보 은닉 ③ 다형성 ④ 상속)
>
> **정답:** ④ 상속(Inheritance)
>
> **해설:**
>
> 상속은 코드의 재사용성을 높여주며, 상위 클래스의 특성을 하위 클래스가 그대로 사용하거나 확장할 수 있게 합니다.

> [!note]- 6. 모듈 간의 결합도(Coupling)에 대한 설명 중 틀린 것은? (① 제어 결합도는 모듈 간의 제어 신호를 전달할 때 발생한다 ② 데이터 결합도가 가장 결합도가 높다)
>
> **정답:** ② 데이터 결합도가 가장 결합도가 높다.
>
> **해설:**
>
> 데이터 결합도(Data Coupling)는 모듈 간 인터페이스가 매개변수를 통해서만 이루어지는 경우로, 결합도가 가장 **낮고(약하고)** 가장 좋은 형태입니다. 결합도가 가장 높은 것은 내용 결합도(Content Coupling)입니다.

> [!note]- 7. 소프트웨어 프로젝트 비용 산정 기법 중 원시 코드 라인 수를 이용하는 기법은? (① Delphi 기법 ② LOC 기법 ③ COCOMO 기법 ④ Putnam 기법)
>
> **정답:** ② LOC(Line of Code) 기법
>
> **해설:**
>
> LOC 기법은 각 기능별 비관치, 낙관치, 기대치를 측정하여 예측치를 구하고 이를 바탕으로 비용을 산정하는 하향식 산정 기법입니다.

> [!note]- 8. 총 라인이 30,000라인이고 개발자가 5명이며, 인당 월평균 300라인을 개발할 때 LOC 기법에 따른 개발 기간은?
>
> **정답:** 20개월
>
> **해설:**
>
> 1. 월평균 총 생산량: $5명 \times 300라인/월 = 1,500라인/월$
>     
> 2. 총 개발 기간: $30,000라인 / 1,500라인 = 20개월$
>     
>     수식 표현: $Duration = \frac{Total\ LOC}{Devs \times Avg\ LOC}$
>     

> [!note]- 9. 위험 분석(관리)의 일반적인 순서로 옳은 것은?
>
> **정답:** 위험 식별 $\rightarrow$ 위험 분석 $\rightarrow$ 위험 계획 수립 $\rightarrow$ 위험 감시(조치)
>
> **해설:**
>
> 먼저 어떤 위험이 있는지 찾아내고(식별), 그 영향력을 평가한 뒤(분석), 어떻게 대응할지 정하고(계획), 실제로 징후를 모니터링하며 관리(감시)합니다.

> [!note]- 10. 소프트웨어 아키텍처 구축 절차로 옳은 것은?
>
> **정답:** 요구 사항 분석 $\rightarrow$ 아키텍처 분석 $\rightarrow$ 아키텍처 설계 $\rightarrow$ 검증 및 승인
>
> **해설:**
>
> 시스템의 비즈니스 목적을 분석한 뒤, 구조적 제약 사항을 파악(분석)하고 설계에 들어가는 순서로 진행됩니다.

> [!note]- 11. 서비스 지향 아키텍처(SOA) 기반 애플리케이션을 구성하는 층이 아닌 것은? (① 표현층 ② 프로세스층 ③ 제어 클래스층 ④ 비즈니스층)
>
> **정답:** ③ 제어 클래스층
>
> **해설:**
>
> SOA의 계층 구조는 일반적으로 표현층(Application), 프로세스층(Business Process), 서비스층, 비즈니스층 등으로 구성됩니다. 제어 클래스는 주로 MVC 패턴이나 상세 설계 단계의 개념입니다.

> [!note]- 12. COCOMO 모형에 대한 설명으로 옳지 않은 것은? (① 결과는 Man-Month로 나타난다 ② 보헴이 제안하였다 ③ 비용 견적의 유연성이 높다 ④ 프로젝트 모드는 Object, Dynamic, Function이다)
>
> **정답:** ④ 프로젝트 개발 유형에 따라 Object, Dynamic, Function의 3가지 모드로 구분한다.
>
> **해설:**
>
> COCOMO의 개발 유형(Mode)은 **Organic(소규모), Semi-detached(중규모), Embedded(대규모)**의 3가지입니다. 보기에 제시된 Object, Dynamic, Function은 럼바우(Rumbaugh) 분석 기법의 단계입니다.

> [!note]- 13. 접근이 어려운 객체와 연결하려는 객체 사이에서 대리자 역할을 수행하는 디자인 패턴은? (① Facade ② Proxy ③ Adapter ④ Bridge)
>
> **정답:** ② 프록시(Proxy) 패턴
>
> **해설:**
>
> 프록시 패턴은 실제 객체에 대한 접근을 제어하거나 기능을 가로채기 위해 대리 객체를 사용하는 패턴입니다.

> [!note]- 14. 디자인 패턴 중 행위적(Behavioral) 패턴에 속하지 않는 것은? (① Command ② Observer ③ Prototype ④ State)
>

>
> **해설:**
>
> 프로토타입 패턴은 **생성(Creational) 패턴**에 해당합니다. 행위 패턴은 객체 간의 상호작용이나 책임 분산을 정의합니다.

> [!note]- 15. 인터페이스 구현 검증 도구 중 Ruby를 사용하는 애플리케이션 테스트 프레임워크는? (① FitNesse ② STAF ③ NTAF ④ Watir)

>     
> - **STAF:** 분산 환경의 테스트 자동화 프레임워크

> [!note]- 16. EAI(Enterprise Application Integration)의 구축 유형으로 옳지 않은 것은? (① Point-to-Point ② Hub <code>&</code> Spoke ③ Message Bus ④ Tree)
>
> **정답:** ④ Tree
>
> **해설:**
>
> EAI 구축 유형에는 점대점(Point-to-Point), 허브 앤 스포크(Hub <code>&</code> Spoke), 메시지 버스(Message Bus/ESB), 하이브리드(Hybrid)가 있습니다.

> [!note]- 17. 미들웨어 솔루션의 유형에 포함되지 않는 것은? (① WAS ② Web Server ③ RPC ④ ORB)
>
> **정답:** ② Web Server
>
> **해설:**
>
> 웹 서버(Apache, Nginx 등)는 클라이언트의 요청에 따라 정적 콘텐츠를 제공하는 서버 소프트웨어이며, 보통 미들웨어는 애플리케이션 간의 연결이나 데이터 교환을 돕는 WAS, RPC, MOM 등을 의미합니다.


> [!note]- 18. 인터페이스 구현 검증 도구에 대한 설명으로 옳지 않은 것은? (① FitNesse ② STAF ③ NTAF ④ xUnit)
>
> **정답:** ② STAF
>
> **해설:**
>
> - **STAF:** 서비스 기반의 분산 환경 테스트 프레임워크입니다.
>     
> - **Watir:** Ruby를 사용하는 애플리케이션 테스트 프레임워크입니다. (보기 2번은 Watir에 대한 설명임)
>     
> - **FitNesse:** 웹 기반 테스트케이스 설계 및 실행 도구입니다.
>     
> - **NTAF:** Naver에서 FitNesse와 STAF을 통합한 자동화 프레임워크입니다.
>     
> - **xUnit:** 다양한 언어(JUnit, NUnit 등)를 지원하는 단위 테스트 프레임워크입니다.
>     

> [!note]- 19. EAI(Enterprise Application Integration)의 구축 유형으로 옳지 않은 것은? (① Point-to-Point ② Hub <code>&</code> Spoke ③ Message Bus ④ Tree)
>
> **정답:** ④ Tree
>
> **해설:**
>
> EAI의 주요 구축 유형은 다음과 같습니다.
>
> 1. **Point-to-Point:** 1대1 단순 연결 방식
>     
> 2. **Hub <code>&</code> Spoke:** 중앙 허브를 통한 집중 방식
>     
> 3. **Message Bus (ESB):** 미들웨어를 두어 서비스 중심으로 통합하는 방식
>     
> 4. **Hybrid:** 허브 앤 스포크와 메시지 버스의 혼합 방식
>     
>     Tree 방식은 일반적인 EAI 구성 유형에 포함되지 않습니다.
>     

> [!note]- 20. 미들웨어 솔루션의 유형에 포함되지 않는 것은? (① WAS ② Web Server ③ RPC ④ ORB)
>
> **정답:** ② Web Server
>
> **해설:**
>
> 미들웨어는 서로 다른 애플리케이션이나 컴포넌트 간의 원활한 통신을 돕는 소프트웨어입니다.
>
> - **WAS (Web Application Server):** 동적 콘텐츠 처리를 위한 서버
>     
> - **RPC (Remote Procedure Call):** 원격 프로시저 호출
>     
> - **ORB (Object Request Broker):** 객체 지향 미들웨어
>     
>     반면, **Web Server**는 클라이언트의 요청에 따라 정적인 콘텐츠(HTML, CSS 등)를 제공하는 도구로, 보통 미들웨어 범주보다는 서버 소프트웨어 자체로 분류됩니다.
>     

> [!note]- 21. 소프트웨어 설계 시 구축된 플랫폼의 성능 특성 분석에 사용되는 측정 항목이 아닌 것은? (① 응답시간 ② 가용성 ③ 사용률 ④ 서버 튜닝)
>
> **정답:** ④ 서버 튜닝(Server Tuning)
>
> **해설:**
>
> 서버 튜닝은 성능을 최적화하기 위한 **행위**이며, 측정 항목은 응답시간, 가용성, 사용률, 처리량(Throughput) 등이 해당합니다.

> [!note]- 22. 애자일(Agile) 방법론에 해당하지 않는 것은? (① 기능 중심 개발 ② 스크럼 ③ 익스트림 프로그래밍 ④ 모듈 중심 개발)
>
> **정답:** ④ 모듈 중심 개발
>
> **해설:**
>
> 모듈 중심 개발은 일반적인 설계 원칙이며, 애자일의 구체적인 방법론에는 스크럼(Scrum), XP(XP), FDD(기능 중심 개발), Lean 등이 있습니다.

> [!note]- 23. 하향식 설계 방법과 상향식 설계 방법에 대한 비교 설명으로 가장 옳지 않은 것은?
>
> **정답:** ② 하향식 설계에서 레벨이 낮은 데이터 구조의 세부 사항은 설계 초기 단계에서 필요하다.
>
> **해설:**
>
> 하향식(Top-down) 설계는 최상위 기능을 먼저 정의하고 점진적으로 구체화하므로, 하위 레벨의 세부 사항은 초기 단계보다는 **후반부**에 구체화됩니다.

> [!note]- 24. 유스케이스 다이어그램(Use Case Diagram)에 관련된 내용으로 틀린 것은?
>
> **정답:** ① 시스템과 상호작용하는 외부시스템은 액터로 파악해서는 안 된다.
>
> **해설:**
>
> 유스케이스 다이어그램에서 액터(Actor)는 시스템을 사용하는 사람뿐만 아니라, 시스템과 연동되는 **외부 시스템**도 포함될 수 있습니다.

> [!note]- 25. UML에서 시스템의 동작을 표현하는 행위(Behavioral) 다이어그램에 해당하지 않는 것은? (① 유스케이스 ② 시퀀스 ③ 활동 ④ 배치)
>
> **정답:** ④ 배치 다이어그램(Deployment Diagram)
>
> **해설:**
>
> 배치 다이어그램은 물리적 노드의 구성과 연결을 나타내는 **구조(Structural) 다이어그램**입니다.

> [!note]- 26. ISO 25010 소프트웨어 품질 요구사항 중 이식성(Portability)의 하위 특성이 아닌 것은?
>
> **정답:** 준수성(Compliance)을 제외한 나머지: 적용성, 설치성, 대체성, 공존성 등
>
> **해설:**
>
> 이식성은 소프트웨어가 한 환경에서 다른 환경으로 옮겨질 수 있는 능력을 의미하며, 적용성(Adaptability), 설치성(Installability), 대체성(Replaceability), 공존성(Co-existence) 등이 세부 항목입니다.

> [!note]- 27. 응집도의 종류 중 기능 요소들이 어떠한 의미 있는 연관 관계도 없이 무작위로 구성된 경우의 응집도는? (① Functional ② Sequential ③ Logical ④ Coincidental)
>
> **정답:** ④ Coincidental Cohesion (우연적 응집도)
>
> **해설:**
>
> 우연적 응집도는 모듈 내부의 요소들이 서로 관련 없는 기능을 수행하는 경우로, 응집도가 가장 **낮고(나쁘고)** 유지보수가 어렵습니다.

> [!note]- 28. NS(Nassi-Shneiderman) 차트에 대한 설명으로 거리가 먼 것은?
>
> **정답:** ③ 주로 화살표를 사용하여 논리적인 제어 구조로 흐름을 표현한다.
>
> **해설:**
>
> NS 차트는 화살표를 사용하지 않고 박스 형태의 도형을 중첩하여 논리를 표현합니다. 이를 통해 GOTO 문 사용을 억제하고 구조적 프로그래밍을 돕습니다.

> [!note]- 29. 소프트웨어 아키텍처와 관련한 설명으로 틀린 것은?
>
> **정답:** ① 파이프 필터 아키텍처에서 데이터는 파이프를 통해 양방향으로 흐르며, 오버헤드가 발생하지 않는다.
>
> **해설:**
>
> 파이프 필터(Pipe-Filter) 패턴에서 데이터 흐름은 **단방향**이며, 각 필터에서 데이터를 변환할 때 데이터 변환 및 전송 오버헤드가 발생할 수 있습니다.

> [!note]- 30-1. GoF(Gang of Four)의 디자인 패턴에서 행위 패턴에 속하는 것은? (① Builder ② Visitor ③ Prototype ④ Bridge)
>
> **정답:** ② Visitor
>
> **해설:**
>
> - Builder, Prototype: 생성 패턴
>     
> - Bridge: 구조 패턴
>     
> - Visitor: 행위 패턴
>     

> [!note]- 30-2. 미들웨어(Middleware)에 대한 설명으로 틀린 것은?
>
> **정답:** ② 미들웨어의 서비스 이용을 위해 사용자가 내부 동작을 쉽게 확인할 수 있어야 한다.
>
> **해설:**
>
> 미들웨어는 사용자나 응용 프로그램에게 내부의 복잡한 동작을 숨기는 **투명성(Transparency)**을 제공해야 하므로, 내부 동작을 굳이 알 필요가 없는 '블랙박스' 형태가 바람직합니다.

> [!note]- 31. 정형 기술 검토(FTR)의 지침으로 틀린 것은? (① 의제 제한 ② 논쟁 제한 ③ 문제 영역 명확화 ④ 참가자 수 무제한)
>
> **정답:** ④ 참가자의 수를 제한하지 않는다.
>
> **해설:**

> [!note]- 32. 마스터-슬레이브(Master-Slave) 아키텍처에 대한 설명으로 틀린 것은?
>

>
> **해설:**
>
> 일반적으로 마스터 프로세스가 작업을 분산하고 제어하지만, 실제 데이터 수집이나 연산 등의 작업은 **슬레이브 프로세스**가 담당하여 수행합니다.

> [!note]- 33. 알고리즘의 골격은 부모 클래스에서 정의하고, 세부 단계는 자식 클래스에서 재정의하도록 하는 패턴은? (① Factory ② Adapter ③ Strategy ④ Template Method)
>
> **정답:** ④ Template Method 패턴
>
> **해설:**
>

> [!note]- 34. 요구 사항 모델링 과정에서 사용되는 다이어그램이 아닌 것은? (① DFD ② UML ③ E-R ④ AVL)
>

>
> **해설:**
>

> [!note]- 35. 유스케이스(Use Case) 구성 요소 간의 관계에 포함되지 않는 것은? (① 연관 ② 확장 ③ 구체화 ④ 일반화)

>
> **해설:**
>
> 유스케이스의 주요 관계는 연관(Association), 포함(Include), 확장(Extend), 일반화(Generalization)입니다. 구체화는 주로 클래스와 인터페이스 간의 관계에서 사용됩니다.

> [!note]- 36. UML의 사물(Things) 분류에 속하지 않는 것은?

>
> **해설:**
>
> UML 사물은 구조(Structural), 행동(Behavioral), 그룹(Grouping), 주해(Annotation) 사물로 나뉩니다. 이 외의 항목은 사물이 아닙니다.

> [!note]- 37. 매일 15분간 진행하며 프로젝트 진행 상황과 문제점을 공유하는 스크럼 활동은?

>

> [!note]- 38. UML 다이어그램 중 동적 다이어그램(Dynamic Diagram)이 아닌 것은? (① 시퀀스 ② 활동 ③ 상태 ④ 배치)
>
> **정답:** ④ 배치 다이어그램(Deployment Diagram)
>
> **해설:**
>
> 배치 다이어그램은 시스템의 물리적 정적 구조를 나타내는 **구조(Structural)** 다이어그램입니다.

> [!note]- 39. 결합도(Coupling)의 종류에 해당하지 않는 것은? (① 기능 결합 ② 내용 결합 ③ 공통 결합 ④ 외부 결합)
>
> **정답:** ① 기능 결합
>
> **해설:**
>
> '기능(Functional)'은 결합도가 아니라 **응집도(Cohesion)**의 최상위 단계인 '기능적 응집도'를 의미합니다. 결합도의 종류에는 내-공-외-제-스-데(내용, 공통, 외부, 제어, 스탬프, 데이터)가 있습니다.

> [!note]- 40. 소프트웨어 아키텍처 4+1 뷰(View)의 구성요소가 아닌 것은? (① 구현 뷰 ② 배치 뷰 ③ 물리 뷰 ④ 논리 뷰)
>
> **정답:** ③ 물리 뷰
>
> **해설:**
>
> 표준 4+1 뷰는 논리(Logical), 프로세스(Process), 구현(Implementation/Development), 배치(Deployment/Physical) 뷰와 유스케이스(Use Case) 뷰로 구성됩니다. 문맥상 '물리 뷰'가 정답(제외)인 경우가 많으나, 배치 뷰를 물리 뷰라고 부르기도 하므로 보통 '프로세스 뷰'가 빠진 것을 찾는 문제로 자주 출제됩니다.


> [!note]- 41. 데이터와 함수를 하나로 묶어 외부와 경계를 만들고 필요한 인터페이스만 노출하는 과정은? (① 메시지 ② 캡슐화 ③ 다형성 ④ 상속)
>
> **정답:** ② 캡슐화(Encapsulation)
>
> **해설:**
>
> 캡슐화는 정보 은닉을 가능하게 하며, 데이터와 메서드를 하나로 묶어 객체의 세부 구현 내용을 외부에 감추는 것을 의미합니다.

> [!note]- 42. 객체에게 어떤 행위를 하도록 지시하는 명령은? (① Class ② Instance ③ Object ④ Message)
>
> **정답:** ④ Message (메시지)
>
> **해설:**
>
> 메시지는 객체 간의 상호작용을 위한 수단으로, 수신 객체에게 특정 연산을 수행하도록 요청하는 신호입니다.

> [!note]- 43. 럼바우(Rumbaugh)의 객체지향 분석 절차를 가장 바르게 나열한 것은? (① 객체→동적→기능 ② 객체→기능→동적 ③ 기능→동적→객체 ④ 기능→객체→동적)

>     
> 2. **동적 모형(Dynamic):** 상태 변화 및 흐름(상태 다이어그램 활용)
>     
> 3. **기능 모형(Functional):** 데이터 변환 과정(DFD 활용)
>     

> [!note]- 44. 하나 이상의 유사한 객체들을 묶어서 하나의 공통된 특성을 표현한 것은? (① 트랜잭션 ② 클래스 ③ 시퀀스 ④ 서브루틴)

> [!note]- 45. 속성과 연산(Operation)을 클래스 안에 묶어서 하나로 취급하는 개념은? (① Inheritance ② Class ③ Encapsulation ④ Association)

>

> [!note]- 46. 소프트웨어 아키텍처의 구축 절차로 옳은 것은? (ㄱ. 분석 ㄴ. 요구사항 ㄷ. 설계 ㄹ. 검증)

>

> [!note]- 47. 비용 산정 기법 중 산정 요원과 조정자에 의해 산정하는 방법은? (① 기능 점수 ② LOC ③ COCOMO ④ 델파이 기법)

>

> [!note]- 48. 원시 코드 라인 수의 비관치, 낙관치, 기대치를 사용하여 비용을 산정하는 기법은? (① Effort Per Task ② 전문가 감정 ③ 델파이 ④ LOC 기법)

> [!note]- 49. 아키텍처 설계 과정의 올바른 순서는? (㉮목표 ㉯타입 ㉰스타일 ㉱동작작성 ㉲검토)

> [!note]- 50. 자료 흐름도(DFD)의 각 요소별 표기 형태의 연결이 옳지 않은 것은? (① Process:원 ② Data Flow:화살표 ③ Data Store:삼각형 ④ Terminator:사각형)

> [!note]- 51. 선행 조건, 결과 조건, 불변 조건 등을 포함하는 컴포넌트 설계 방식은? (① 협약 ② 프로토콜 ③ 패턴 ④ 관계)

> [!note]- 52. 소프트웨어 공학에서 워크스루(Walkthrough)에 대한 설명으로 틀린 것은?

> [!note]- 53. DFD(Data Flow Diagram)에 대한 설명으로 틀린 것은? (① 버블 차트 ② 구조적 분석 ③ 시간 흐름 표현 ④ 요소 4가지)

> [!note]- 55. 메시지 순서에 초점을 맞춰 시간 순서에 따른 객체 간 상호작용을 보여주는 UML 다이어그램은? (① 클래스 ② 순차 ③ 배치 ④ 컴포넌트)

> [!note]- 56. UI 설계 시 오류 메시지나 경고 지침으로 가장 거리가 먼 것은? (① 이해 용이 ② 회복 설명 ③ 부정적 내용 알림 ④ 텍스트로만 전달)

> [!note]- 57. 프로젝트 말기에 새로운 인원을 추가 투입하면 프로젝트가 더욱 지연된다는 법칙은? (① Putnam ② Mayer ③ Brooks ④ Boehm)

### 💻 [소프트웨어 개발] 문제 은행

> [!note]- 1.1 해싱(Hashing)에서 키 값을 주소로 변환하기 위해 사용하는 함수를 무엇이라 하는가? (① 인덱스 함수 ② 해시 함수 ③ 포인터 함수 ④ 주소 함수)
>
> **정답:** ② 해시 함수
>
> **해설:**
>
> 해싱은 해시 함수(Hash Function)를 이용하여 키(Key) 값을 주소(Address)로 변환하는 기법입니다. 수식으로 표현하면 $Address = hash(Key)$와 같습니다.

> [!note]- 1.2 다음 중 정적 분석(Static Analysis) 도구의 특징으로 옳지 않은 것은? (① 소스 코드를 실행하지 않고 분석한다 ② 코딩 표준 준수 여부를 확인한다 ③ 실제 실행 중 발생하는 결함을 찾는다 ④ 자료 흐름이나 복잡도를 분석한다)
>
> **정답:** ③ 실제 실행 중 발생하는 결함을 찾는다.
>
> **해설:**
>
> 실제 실행 중에 발생하는 메모리 누수나 실행 오류 등을 찾는 것은 **동적 분석(Dynamic Analysis)** 도구의 특징입니다. 정적 분석은 실행 없이 코드 자체를 분석합니다.

> [!note]- 1.3 퀵 정렬(Quick Sort)에 대한 설명으로 옳은 것은? (① 최악의 시간 복잡도는 $O(N \log N)$이다 ② 분할 정복 알고리즘을 사용하며 피벗(Pivot)을 기준으로 분할한다 ③ 이미 정렬된 데이터에서 가장 빠르다 ④ 안정적인(Stable) 정렬 알고리즘이다)
>
> **정답:** ② 분할 정복 알고리즘을 사용하며 피벗(Pivot)을 기준으로 분할한다.
>
> **해설:**
>
> 퀵 정렬은 피벗(기준값)을 설정하여 두 부분으로 나누어 정렬하는 방식입니다. 최악의 시간 복잡도는 $O(N^2)$이며, 이미 정렬된 데이터에서 피벗 선택에 따라 성능이 저하될 수 있는 불안정 정렬입니다.

> [!note]- 1.4 다음 중 비선형 자료구조(Non-Linear Structure)로만 묶인 것은? (① 스택, 큐 ② 리스트, 배열 ③ 트리, 그래프 ④ 데크, 스택)

> - **비선형 구조:** 트리(Tree), 그래프(Graph) (데이터가 계층적이거나 망 형태로 연결됨)
>     

> [!note]- 1.5 스택(Stack)의 응용 분야가 아닌 것은? (① 수식의 후위 표기법 변환 ② 운영체제의 작업 스케줄링 ③ 서브루틴의 복귀 주소 저장 ④ 깊이 우선 탐색(DFS) 구현)

> [!note]- 17. 다음 트리를 전위 순회(Preorder Traversal)한 결과는? (루트: +, 왼쪽 서브트리: * / * / A / B, 오른쪽 서브트리: * / C / D / E 형태일 때)

>

>

>
> **해설:**
>

### 🗄️ [데이터베이스 구축] 문제 은행

> [!note]- 1. 트랜잭션(Transaction)이 가져야 할 4대 특성(ACID)에 해당하지 않는 것은? (① Atomicity ② Concurrency ③ Isolation ④ Durability)
>
> **정답:** ② Concurrency
>
> **해설:**
>
> 트랜잭션의 특성은 **원자성(Atomicity), 일관성(Consistency), 격리성(Isolation), 영속성(Durability)**입니다. 병행성(Concurrency)은 여러 트랜잭션이 동시에 실행되는 성질을 의미하며, 이를 관리하는 것이 병행 제어입니다.

> [!note]- 2. 정규화(Normalization)의 목적으로 옳지 않은 것은? (① 데이터 표현 가능화 ② 재구성 필요성 감소 ③ 이상 현상 야기 ④ 검색 알고리즘 효율화)
>
> **정답:** ③ 중복을 배제하여 삽입, 삭제, 갱신 이상의 발생을 야기한다.
>
> **해설:**
>
> 정규화의 목적은 데이터 중복을 최소화하여 삽입, 삭제, 갱신 시 발생하는 **이상(Anomaly) 현상을 방지**하는 것입니다.

> [!note]- 3. 분산 데이터베이스 목표 중 사용자가 데이터의 물리적 위치를 몰라도 논리적 입장에서 처리할 수 있는 성질은? (① Failure ② Concurrency ③ Location ④ Replication)
>
> **정답:** ③ Location Transparency (위치 투명성)
>
> **해설:**
>
> 위치 투명성은 액세스하려는 데이터의 실제 저장 위치를 사용자가 알 필요가 없는 성질을 의미합니다.

> [!note]- 4. 릴레이션(Relation)에 대한 설명으로 거리가 먼 것은? (① 시간에 따라 변함 ② 튜플 상이함 ③ 원자 값 저장 ④ 튜플 간 순서 있음)
>
> **정답:** ④ 한 릴레이션에 포함된 튜플 사이에는 순서가 있다.
>
> **해설:**
>
> 릴레이션을 구성하는 **튜플(Tuple) 사이에는 정해진 순서가 없습니다.** 데이터의 집합으로 취급하기 때문입니다.

> [!note]- 5. SQL 구문에서 "Having" 절은 반드시 어떤 구문과 함께 사용되어야 하는가? (① GROUP BY ② ORDER BY ③ UPDATE ④ JOIN)
>
> **정답:** ① GROUP BY
>
> **해설:**
>
> `HAVING` 절은 `GROUP BY` 절에 의해 생성된 그룹에 대한 조건을 지정할 때 사용됩니다.

> [!note]- 6. SELECT 절에서 중복되는 레코드를 제거하기 위해 사용하는 키워드는? (① GROUP BY ② DISTINCT ③ UPDATE ④ JOIN)
>
> **정답:** ② DISTINCT
>
> **해설:**
>
> `DISTINCT` 키워드는 조회 결과에서 중복된 행을 하나만 남기고 제거할 때 사용합니다.

> [!note]- 7. 소스 시스템에서 데이터를 추출하여 변환 후 타겟 시스템에 적재하는 과정을 의미하는 용어는?
>
> **정답:** ETL (Extraction, Transformation, Loading)
>
> **해설:**
>
> 데이터 웨어하우스나 데이터 마트 구축 시 필수적인 과정으로, 데이터의 **추출(Extract), 변환(Transform), 적재(Load)**를 의미합니다.

> [!note]- 8. 로킹(Locking) 기법에 대한 설명으로 틀린 것은? (① 로킹 단위 존재 ② 단위 작으면 병행성 낮아짐 ③ DB도 단위 가능 ④ 단위 크면 오버헤드 감소)
>
> **정답:** ② 로킹 단위가 작아지면 병행성 수준이 낮아진다.
>
> **해설:**
>
> 로킹 단위가 작아지면 병행 제어가 더 세밀해지므로 **병행성(공유도) 수준은 높아집니다.** 대신 관리할 로크(Lock)가 많아져 오버헤드는 증가합니다.

> [!note]- 9. 정규화 단계 중 제2정규형(2NF)에서 제3정규형(3NF)으로 가기 위해 제거해야 하는 것은? (① 부분 함수 종속 ② 이행적 함수 종속 ③ 결정자/후보키 불일치 ④ 다치 종속)
>
> **정답:** ② 이행적 함수 종속 (Transitive Functional Dependency)
>
> **해설:**
>
> - 1NF $\rightarrow$ 2NF: 부분 함수 종속 제거
>     
> - 2NF $\rightarrow$ 3NF: **이행적 함수 종속 제거**
>     
> - 3NF $\rightarrow$ BCNF: 결정자이면서 후보키가 아닌 것 제거
>     

> [!note]- 10. 레코드(Record)를 기준으로 테이블을 분할하여 서로 다른 디스크에 위치시키는 기술은?
>
> **정답:** 수평 분할 (Horizontal Partitioning)
>
> **해설:**
>
> 행(Row)을 기준으로 나누는 방식이며, 특정 범위의 레코드를 주로 액세스할 때 성능 향상을 위해 사용합니다.

> [!note]- 11. 버전 관리 항목 중 저장소에 새로운 버전의 파일로 갱신하는 것을 의미하는 용어는? (① 형상 감사 ② 롤백 ③ 단위 테스트 ④ 체크인)
>
> **정답:** ④ 체크인 (Check-In)
>
> **해설:**
>
> 수정된 파일을 중앙 저장소에 기록하여 새로운 버전을 생성하는 과정을 `Check-In`이라고 합니다.

> [!note]- 12. 학적 테이블에서 전화번호가 Null 값이 아닌 학생명을 모두 검색하는 SQL 구문은?
>
> **정답:** ③ SELECT 학생명 FROM 학적 WHERE 전화번호 IS NOT NULL;
>
> **해설:**
>
> 데이터베이스에서 `NULL` 값의 유무를 확인할 때는 비교 연산자(<code>=</code>, `!=`) 대신 `IS NULL` 또는 `IS NOT NULL`을 사용해야 합니다.

> [!note]- 13. 정규화(Normalization) 과정에 대한 설명으로 적절하지 않은 것은? (① 개념적 설계 이전 수행 ② 구조 안정성 최대화 ③ 이상 현상 방지 ④ 재구성 필요성 감소)
>
> **정답:** ① 데이터베이스의 개념적 설계 단계 이전에 수행한다.
>
> **해설:**
>
> 정규화는 일반적으로 개념적 설계(ERD 작성)를 마친 후, 이를 테이블 형태의 스키마로 변환하는 **논리적 설계** 단계에서 수행합니다.

> [!note]- 14. 릴레이션의 모든 튜플에 대해 유일성은 만족시키지만 최소성은 만족시키지 못하는 키는? (① 후보키 ② 기본키 ③ 슈퍼키 ④ 외래키)
>
> **정답:** ③ 슈퍼키 (Super Key)
>
> **해설:**
>
> 슈퍼키는 튜플을 고유하게 식별할 수는 있지만(유일성), 굳이 필요 없는 속성까지 포함할 수 있어 최소성을 만족하지 못할 수 있습니다.


### ➕ 추가 생성 문제 (요청 키워드 반영)

> [!note]- 16. 사용자 그룹에게 부여받은 권한을 다른 사용자에게 다시 부여할 수 있도록 허용하는 옵션은? (① WITH ADMIN OPTION ② WITH GRANT OPTION ③ CASCADE ④ RESTRICT)
>
> **정답:** ② WITH GRANT OPTION
>
> **해설:**
>
> `GRANT` 명령 시 이 옵션을 추가하면 권한을 받은 사용자가 다른 사람에게도 동일한 권한을 부여할 수 있게 됩니다.

> [!note]- 17. 릴레이션 R(속성 A, B)과 S(속성 A, C)가 있을 때, 각 릴레이션에서 A 속성값만 뽑아 합집합을 구하는 관계 대수식은?
>
> **정답:** $\pi_A(R) \cup \pi_A(S)$
>
> **해설:**
>
> 특정 속성을 추출하는 프로젝션($\pi$) 연산 후, 집합 연산자인 합집합($\cup$)을 적용합니다.

> [!note]- 18. 모든 결정자가 후보키여야 한다는 조건을 만족해야 하는 정규형은? (① 2NF ② 3NF ③ BCNF ④ 4NF)
>
> **정답:** ③ BCNF (Boyce-Codd Normal Form)
>
> **해설:**
>
> 강한 제3정규형이라고도 하며, 결정자 함수 종속 관계에서 모든 결정자가 후보키인 상태를 의미합니다.
>
> 수식 표현: $Determinant \subseteq Candidate\ Key$


> [!note]- 21. 테이블에 새로운 레코드를 삽입하기 위한 SQL문(INSERT INTO)의 기본 형식으로 옳은 것은?
>
> **정답:** `INSERT INTO 테이블명(속성1, 속성2, …) VALUES (값1, 값2, …);`
>
> **해설:**
>
> 데이터를 삽입할 때는 `INSERT INTO` 뒤에 대상 테이블과 속성을 명시하고, `VALUES` 뒤에 실제 저장할 값을 순서대로 나열합니다. 모든 속성에 값을 넣을 경우 속성명 생략이 가능합니다.

> [!note]- 22. SQL의 분류 중 DDL(Data Definition Language)에 해당하지 않는 것은? (① UPDATE ② ALTER ③ DROP ④ CREATE)
>
> **정답:** ① UPDATE
>
> **해설:**
>
> `UPDATE`는 테이블 내의 데이터를 수정하는 **DML(Data Manipulation Language)**입니다. `ALTER`, `DROP`, `CREATE`는 스키마나 테이블의 구조를 정의하는 DDL입니다.

> [!note]- 23. 트랜잭션의 연산은 DB에 모두 반영되든지 아니면 전혀 반영되지 않아야 한다는 특성은? (① Durability ② Share ③ Consistency ④ Atomicity)
>
> **정답:** ④ Atomicity (원자성)
>
> **해설:**
>
> 원자성은 "All or Nothing" 원칙을 의미합니다. 트랜잭션 도중 오류가 발생하면 지금까지 실행한 모든 연산을 취소하고 초기 상태로 되돌려야(Rollback) 합니다.

> [!note]- 24. SQL문에서 SELECT에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ② 검색 결과에 중복되는 레코드를 없애기 위해서 WHERE 절에 'DISTINCT' 키워드를 사용한다.
>
> **해설:**
>
> 중복 제거를 위한 `DISTINCT` 키워드는 `WHERE` 절이 아니라 **`SELECT` 절** 바로 뒤에 위치해야 합니다. (예: `SELECT DISTINCT 속성명 FROM …`)

> [!note]- 25. 트랜잭션의 주요 특성(ACID)에 해당하지 않는 것은? (① Isolation ② Consistency ③ Atomicity ④ Distribution)
>
> **정답:** ④ Distribution (분산성)
>
> **해설:**
>
> 트랜잭션의 4대 특성은 **원자성(Atomicity), 일관성(Consistency), 격리성(Isolation), 영속성(Durability)**입니다.

> [!note]- 26. 뷰(View)에 대한 설명으로 틀린 것은? (① 뷰 위에 뷰 정의 가능 ② 조작 시 제약 따름 ③ ALTER로 변경 가능 ④ 테이블 제거 시 자동 제거)
>
> **정답:** ③ 뷰의 정의는 기본 테이블과 같이 ALTER 문을 이용하여 변경한다.
>
> **해설:**
>
> 일반적으로 뷰(View)는 `ALTER` 문을 사용하여 구조를 변경할 수 없습니다. 대신 `DROP` 후 `CREATE`를 다시 하거나, `CREATE OR REPLACE VIEW` 구문을 사용하여 덮어쓰는 방식을 사용합니다.

> [!note]- C언어: 문자열 처리 함수와 기능의 연결이 틀린 것은? (① strlen ② strcpy ③ strcmp ④ strrev)

> **해설:**

> - `strcmp`: 두 문자열을 **비교**하는 함수입니다. (같으면 0 반환)

> - **문자열 연결**을 수행하는 함수는 `strcat(s1, s2)`입니다.

> [!note]- C언어: 연산자 우선순위가 가장 낮은 것은? (① 산술 연산자 ② 관계 연산자 ③ 논리 연산자 ④ 대입 연산자)
>
> **정답:** ④ 대입 연산자 (<code>=</code>)
>
> **해설:**
>
> 연산자 우선순위는 일반적으로 **증감(++, --) $\rightarrow$ 산술 $\rightarrow$ 관계 $\rightarrow$ 논리 $\rightarrow$ 대입** 순입니다. 대입 연산자는 모든 계산이 끝난 후 값을 저장해야 하므로 가장 후순위입니다.

> [!note]- Python: input().split("t")를 활용한 출력 결과는? (입력값: ‘19t94')
>
> **정답:** ① 19 94
>
> **해설:**
>
> 1. `split("t")`에 의해 '19t94'는 `['19', '94']`라는 리스트가 됩니다.
>     
> 2. `map(int, …)`가 각 요소를 정수로 변환하여 $a = 19, b = 94$가 할당됩니다.
>     
> 3. `print(a, b)` 실행 시 두 변수 사이 공백을 두고 `19 94`가 출력됩니다.
>     

> [!note]- JAVA: 연산자 우선순위가 가장 낮은 것은? (① -- ② % ③ <code>&</code> ④ <code>=</code>)
>
> **정답:** ④ <code>=</code> (대입 연산자)
>
> **해설:**
>
> 자바에서도 대입 연산자(<code>=</code>)는 복합 대입 연산자나 순차 연산자(<code>,</code>)를 제외하고 가장 낮은 우선순위를 가집니다. `%`는 산술, `&`는 비트 논리 연산자입니다.


운영체제와 네트워크 과목은 계산 문제와 명령어, 계층별 특징이 핵심입니다. 요청하신 **Obsidian 전용 콜아웃 형식**과 **이미지 제외**, **등호(<code>=</code>) 규칙**을 적용하여 내용을 정리해 드립니다.

### 🖥️ [운영체제] 문제 은행

> [!note]- 1. 교착 상태(Deadlock) 발생의 필요 충분 조건이 아닌 것은? (① Mutual Exclusion ② Hold and Wait ③ Circular Wait ④ Preemption)
>
> **정답:** ④ Preemption (선점)
>
> **해설:**
>
> 교착 상태 발생의 4가지 필수 조건은 **상호 배제(Mutual Exclusion), 점유와 대기(Hold and Wait), 비선점(No Preemption), 환형 대기(Circular Wait)**입니다. 선점(Preemption)이 가능하다면 교착 상태는 발생하지 않습니다.

> [!note]- 2. HRN(Highest Response-ratio Next) 스케줄링 방식에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ④ 우선순위를 계산하여 그 수치가 가장 낮은 것부터 높은 순으로 우선순위가 부여된다.
>
> **해설:**
>
> HRN 방식은 계산된 우선순위 수치가 **가장 높은 것**부터 우선순위를 부여합니다.
>
> 수식: $우선순위 = \frac{대기 시간 + 서비스 시간}{서비스 시간}$

> [!note]- 3. 유닉스 시스템에서 사용자의 계정 정보와 최근 로그인 정보 등을 출력하는 명령어는? (① cat ② finger ③ ls ④ print)

>

>
> **해설:**
>

> [!note]- 12. OSI 7계층 중 오류 수정과 흐름 제어를 수행하여 신뢰성 있는 데이터를 전달하는 계층은?
>
> **정답:** ① 전송 계층 (Transport Layer)
>
> **해설:**
>
> 전송 계층은 송신 측과 수신 측 사이의 신뢰성 있고 투명한 데이터 전송을 가능하게 하며, 흐름 제어 및 오류 복구를 담당합니다.

### 🏗️ [정보시스템 구축 관리] 문제 은행

> [!note]- 1. 인터넷의 잘 알려진 포트(Well-Known Port)로 옳지 않은 것은? (① Telnet-23 ② SMTP-25 ③ POP3-110 ④ SSH-69)
>
> **정답:** ④ SSH - 69
>
> **해설:**
>
> SSH(Secure Shell)의 표준 포트 번호는 **22번**입니다. 69번 포트는 TFTP(Trivial File Transfer Protocol)에서 사용됩니다. 암기 팁: "SS(22)H".

> [!note]- 2. 클라우드 컴퓨팅 서비스 유형 중 개발에 필요한 플랫폼(레고 블록)을 제공하는 것은? (① SaaS ② IaaS ③ PaaS ④ BaaS)
>
> **정답:** ③ PaaS (Platform as a Service)
>
> **해설:**
>
> - **IaaS:** 서버, 스토리지 등 인프라 제공 (ex. 넷플릭스 인프라)
>     
> - **PaaS:** 애플리케이션 개발/실행 플랫폼 제공 (ex. 레고 블록처럼 조립 가능)
>     
> - **SaaS:** 완성된 소프트웨어 서비스 제공 (ex. 네이버 클라우드, 구글 드라이브)
>     
> - **BaaS:** 블록체인 기술을 서비스 형태로 제공
>     

> [!note]- 3. 무선 공유기 사용 현황을 실시간 관찰하고 비인가 접속을 방지하는 시스템은?
>
> **정답:** WIPS (Wireless Intrusion Prevention System)
>
> **해설:**
>
> WIPS는 무선랜(Wi-Fi) 환경에서 허용되지 않은 접근이나 보안 취약점을 야기하는 부적절한 접속을 실시간으로 차단하는 무선 침입 방지 시스템입니다.

> [!note]- 4. 소프트웨어의 보안 취약점이 발생하는 가장 근본적인 원인은?
>
> **정답:** 코드 오류 (Programming Errors)
>
> **해설:**
>
> 보안 취약점은 주로 설계 결함이나 구현 단계에서의 코드 오류로 인해 발생하며, 공격자는 이를 이용해 시스템에 침입합니다.

> [!note]- 5. 합법적인 와이파이 제공자로 위장하여 사용자 정보를 탈취하는 공격 기법은? (① Evil Twin Attack ② Phishing ③ Logic Bomb ④ Cyberbullying)
>
> **정답:** ① Evil Twin Attack (이블 트윈 공격)
>
> **해설:**
>
> 이블 트윈은 실제 있는 AP와 동일한 이름(SSID)을 가진 가짜 AP를 설치하여 사용자의 접속을 유도한 뒤 정보를 가로채는 무선 네트워크 공격입니다.

> [!note]- 6. 리눅스 시스템에서 전체 로그인 기록을 보관하며, `last` 명령어로 확인하는 로그 파일은?
>
> **정답:** wtmp
>
> **해설:**
>
> `wtmp`는 성공한 로그인/로그아웃 기록과 시스템의 시작/종료 시간을 보관하는 바이너리 로그 파일입니다.

> [!note]- 7. 닐 스티븐슨의 소설 '스노우 크래쉬'에서 유래된 개념으로, 가상과 현실이 융합된 세계는?
>
> **정답:** 메타버스 (Metaverse)
>
> **해설:**
>
> 가상현실(VR)보다 진보된 개념으로, 아바타를 통해 현실 세계와 같은 사회, 문화, 경제 활동이 가능한 가상 세계를 의미합니다.

> [!note]- 8. 비트코인 등 블록체인에서 공개 키 암호화 방식으로 주로 사용되는 기법은?
>
> **정답:** ECC (Elliptic Curve Cryptography, 타원 곡선 암호)
>
> **해설:**
>
> ECC는 적은 키 길이로도 RSA와 대등한 보안 강도를 제공하여 연산 능력이 제한된 환경이나 블록체인 시스템에서 널리 사용됩니다.

> [!note]- 9. 대규모 디바이스 네트워크에 최적화된 기술로, 노드들이 망 형태로 연결되는 네트워크는?
>
> **정답:** 메시 네트워크 (Mesh Network)
>
> **해설:**
>
> 각 장치가 라우터 역할을 수행하여 통신 범위를 넓히고, 특정 구간 장애 시에도 우회 경로를 통해 신뢰성을 확보하는 차세대 무선 네트워크 기술입니다.

> [!note]- 10. 주요 보안 용어 개념 정리 (TLS, RSA, SHA, AES)
>
> **내용:**
>
> - **TLS:** 전송 계층 보안 프로토콜 (SSL의 후속)
>     
> - **RSA:** 소인수 분해 기반의 비대칭키(공개키) 암호 알고리즘
>     
> - **SHA:** 미국 국가안보국이 설계한 해시 함수 표준 (무결성 확인용)
>     
> - **AES:** 미국 표준 대칭키(비밀키) 암호 알고리즘
>     

> [!note]- 11. 다음 중 침입 차단 및 탐지를 위한 보안 솔루션이 아닌 것은? (① Secure Coding ② IPS ③ IDS ④ WAF)
>
> **정답:** ① Secure Coding
>
> **해설:**
>
> 시큐어 코딩(Secure Coding)은 보안 약점을 배제하며 개발하는 **코딩 기법(활동)**입니다. 2, 3, 4번은 네트워크 상에 설치되어 공격을 막거나 탐지하는 하드웨어/소프트웨어 **솔루션**입니다.

> [!note]- 12. 사용자에게 할당된 직책이나 기능에 따라 접근 권한을 부여하는 방식은?
>
> **정답:** RBAC (Role-Based Access Control, 역할기반 접근 통제)
>
> **해설:**
>
> 개인의 신분이 아닌, 조직 내에서 맡은 '역할'에 따라 권한을 관리하므로 인사 이동 시 권한 관리가 효율적입니다.

> [!note]- 13. 네트워크에 접속하는 내부 PC의 MAC 주소를 등록하여 접속을 제어하는 보안 솔루션은?
>
> **정답:** NAC (Network Access Control, 네트워크 접근 제어)
>
> **해설:**
>
> NAC는 인가되지 않은 장치나 보안 정책을 준수하지 않은 기기가 내부 네트워크에 접속하는 것을 원천적으로 차단합니다.

> [!note]- 14. 허가되지 않은 접근이나 수정을 통제하여 데이터의 정확성을 유지하는 보안 목표는? (① 신뢰성 ② 상호운용성 ③ 무결성 ④ 사용성)
>
> **정답:** ③ Integrity (무결성)
>
> **해설:**
>
> 인가된 사용자만이 정보를 수정할 수 있으며, 전송 중 데이터가 위조되거나 변조되지 않았음을 보장하는 성질입니다.

> [!note]- 15. 시큐어 코딩에서 입력 데이터 보안 약점 중 성격이 다른 것은? (① SQL 삽입 ② 크로스사이트 스크립트 ③ 충분하지 않은 키 길이 ④ 자원 삽입)
>
> **정답:** ③ 충분하지 않은 키 길이
>
> **해설:**
>
> SQL 삽입(SQLi)과 XSS, 자원 삽입은 외부 입력 값 검증 미흡으로 발생하는 보안 약점입니다. 반면, '충분하지 않은 키 길이'는 암호 알고리즘 사용 시 발생하는 **암호화 관련 보안 약점**입니다.

### 🏗️ [정보시스템 구축 관리] 문제 은행 (Part 2)

> [!note]- 16. 물리적인 사물과 컴퓨터에 동일하게 표현되는 가상 모델로 모든 과정의 효율성을 향상시키는 모델은? (① 최적화 ② 실행 시간 ③ 디지털 트윈 ④ N-Screen)
>
> **정답:** ③ 디지털 트윈 (Digital Twin)
>
> **해설:**
>
> 디지털 트윈은 실제 자산의 특성을 소프트웨어로 가상화한 모델입니다. 이를 통해 실제 자산을 가동하기 전 시뮬레이션을 수행하여 자산 최적화 및 사고 예방이 가능합니다.

> [!note]- 17. 저장장치를 호스트 버스 어댑터에 직접 연결하며 네트워크 디바이스가 중간에 없는 스토리지 방식은? (① DAS ② NAS ③ N-SCREEN ④ NFC)
>
> **정답:** ① DAS (Direct Attached Storage)
>
> **해설:**
>
> - **DAS:** 서버에 전용 케이블로 직접 연결하는 방식 (속도는 빠르나 공유가 어려움)
>     
> - **NAS:** 네트워크(LAN)를 통해 파일 단위로 접근하는 방식
>     
> - **SAN:** 광케이블 네트워크를 통해 블록 단위로 접근하는 방식
>     

> [!note]- 18. 사용자의 입력 값 등 외부 입력 값이 SQL 쿼리에 삽입되어 비정상적으로 데이터베이스를 조작하는 공격은?
>
> **정답:** SQL 주입 (SQL Injection)
>
> **해설:**
>
> 웹 애플리케이션의 입력 값을 적절히 검증하지 않아 발생하는 보안 약점입니다. 이를 방지하기 위해 **변수 바인딩(Parameterized Query)**을 사용해야 합니다.

> [!note]- 19. 파일 등을 암호화하여 열지 못하게 한 뒤, 암호 해독 조건으로 금전을 요구하는 공격 기법은?
>
> **정답:** 랜섬웨어 (Ransomware)
>
> **해설:**
>
> 몸값(Ransom)과 소프트웨어(Software)의 합성어로, 사용자의 데이터를 인질로 삼는 악성 코드의 일종입니다.

> [!note]- 20. 인증(Authentication) 유형 중 지식 기반과 소유 기반 인증의 차이는?
>
> **내용:**
>
> - **지식 기반 인증 (Something You Know):** 사용자가 기억하고 있는 정보를 이용 (ex. 패스워드, PIN, 암구어)
>     
> - **소유 기반 인증 (Something You Have):** 사용자가 가지고 있는 물건을 이용 (ex. OTP 장치, 스마트카드, 공인인증서 파일)
>     
> - **생체 기반 인증 (Something You Are):** 지문, 홍채 등 신체적 특징 이용
>     

> [!note]- 21. printf() 등 포맷 스트링 제어 함수를 부적절하게 사용하여 발생하는 보안 약점은?
>
> **정답:** 포맷 스트링 버그 (Format String Bug)
>
> **해설:**
>
> `%s`, `%x` 등의 포맷 스트링을 공격자가 조작하여 메모리 내용을 읽거나 특정 위치에 값을 쓸 수 있게 되는 취약점입니다.

> [!note]- 22. 무선 네트워크(Wi-Fi)에서 데이터 암호화를 강화하기 위해 개발된 임시 키 무결성 프로토콜은?
>
> **정답:** TKIP (Temporal Key Integrity Protocol)
>
> **해설:**
>
> 기존 WEP의 보안 취약점을 보완하기 위해 설계되었으며, 패킷당 키를 할당하여 암호 해독을 어렵게 만듭니다.

> [!note]- 23. 통신망에서 루프(Loop)를 형성하지 않으면서 연결을 설정하여 데이터 충돌을 방지하는 알고리즘은? (① Spanning Tree Algorithm ② Diffie-Hellman ③ Hash ④ Digital Signature)
>
> **정답:** ① Spanning Tree Algorithm (STP, 신조리 알고리즘)
>
> **해설:**
>
> 브리지나 스위치 환경에서 중복 경로(Loop)가 발생할 경우, 특정 포트를 차단하여 논리적으로 트리 구조를 형성함으로써 트래픽 무한 루프를 방지합니다.

> [!note]- 24. 코드 기입 과정에서 12536을 12936으로 잘못 표기했을 때 발생하는 오류 유형은? (① Addition ② Omission ③ Sequence ④ Transcription)
>
> **정답:** ④ Transcription Error (필기 오류)
>
> **해설:**
>
> - **Transcription(필기):** 한 자리를 잘못 기록 (치환 오류)
>     
> - **Transposition(전위):** 인접한 두 자리의 순서를 바꿈 (12536 $\rightarrow$ 12356)
>     
> - **Omission(생략):** 한 자리를 빠뜨림 / **Addition(첨가):** 한 자리를 더함
>     

> [!note]- 25. 국내 IT 경쟁력 강화를 위해 개발된 개방형 클라우드 컴퓨팅 플랫폼은? (① N2OS ② PaaS-TA ③ KAWS ④ Metaverse)
>
> **정답:** ② PaaS-TA (파스-타)
>
> **해설:**
>
> 과학기술정보통신부와 한국지능정보사회진흥원(NIA)이 주도하여 개발한 오픈 소스 기반의 PaaS 플랫폼입니다.

> [!note]- 26. RSA 암호에서 $n <code>=</code> 91$, $d <code>=</code> 7$일 때, 공개키 $e$의 값으로 옳은 것은? (① 13 ② 31 ③ 41 ④ 존재하지 않는다)
>
> **정답:** ② 31
>
> **해설:**
>
> 1. $n = 91 = 7 \times 13$ 이므로 $p = 7, q = 13$
>     
> 2. 오일러 피 함수 $\phi(n) = (7-1) \times (13-1) = 6 \times 12 = 72$
>     
> 3. $e \times d \equiv 1 \pmod{72}$ 조건을 만족해야 함
>     
> 4. $e \times 7 \equiv 1 \pmod{72}$ $\rightarrow$ $7 \times 31 = 217$
>     
> 5. $217 \div 72 = 3$ 나머지가 1이므로 **$e = 31$**
>     

> [!note]- 27. 매우 많은 ICMP Echo를 보내 시스템 자원을 고갈시켜 정상 동작을 방해하는 공격은? (① RBAC ② Ping Flood ③ Brute-Force ④ Trojan Horses)
>
> **정답:** ② Ping Flood
>
> **해설:**
>
> 특정 대상에게 방대한 양의 ICMP 패킷을 전송하여 네트워크 대역폭을 점유하고 시스템 자원을 소진시키는 DoS 공격입니다.

> [!note]- 28. 허용 범위 이상의 큰 ICMP 패킷을 전송하여 네트워크를 마비시키는 공격은? (① Ping of Death ② Session Hijacking ③ Piggyback ④ XSS)
>
> **정답:** ① Ping of Death
>
> **해설:**
>
> 규정된 크기 이상의 거대한 패킷을 전송하여 수신 측에서 재조합하는 과정에서 오버플로우를 발생시켜 시스템을 다운시키는 공격입니다.

> [!note]- 29. 대규모 디바이스 네트워크에 최적화된 새로운 방식의 무선 네트워크 기술은? (① SDP ② VPN ③ LAN ④ Mesh Network)

>
> **해설:**

> [!note]- 30. 컨테이너화된 애플리케이션의 배포와 스케일링을 자동화하는 관리 시스템은?

# 2회
### 📝 소프트웨어 설계 문제 은행 (Obsidian 용)

> [!note]- 1. 소프트웨어 설계 시 구축된 플랫폼의 성능 특성 분석에 사용되는 측정 항목이 아닌 것은? (① 응답시간 ② 가용성 ③ 사용률 ④ 서버 튜닝)
>
> **정답:** ④ 서버 튜닝
>
> **해설:**
>
> 서버 튜닝(Server Tuning)은 성능을 개선하기 위한 **활동**이지, 성능을 측정하는 지표(Metric)가 아닙니다. 측정 항목에는 응답시간(Response Time), 가용성(Availability), 사용률(Utilization), 처리량(Throughput) 등이 있습니다.

> [!note]- 2. 자료 흐름도(DFD)의 각 요소별 표기 형태의 연결이 옳지 않은 것은? (① Process : 원 ② Data Flow : 화살표 ③ Data Store : 삼각형 ④ Terminator : 사각형)
>
> **정답:** ③ Data Store : 삼각형
>
> **해설:**
>
> DFD에서 데이터 저장소(Data Store)는 평행선(두 줄)이나 한쪽이 트인 직사각형으로 표기합니다. 삼각형은 주로 제어 흐름이나 다른 도식에서 사용됩니다.

> [!note]- 3. UML 모델에서 사용하는 Structural Diagram에 속하지 않은 것은? (① Class Diagram ② Object Diagram ③ Component Diagram ④ Activity Diagram)
>
> **정답:** ④ Activity Diagram
>
> **해설:**
>
> Activity Diagram은 시스템의 동적인 흐름을 나타내는 **행위 다이어그램(Behavioral Diagram)**에 속합니다. 1, 2, 3번은 정적인 구조를 나타내는 구조 다이어그램입니다.

> [!note]- 4. 애자일 방법론에 해당하지 않는 것은? (① 기능 중심 개발 ② 스크럼 ③ 익스트림 프로그래밍 ④ 하둡)
>
> **정답:** ④ 하둡
>
> **해설:**
>
> 하둡(Hadoop)은 대용량 데이터를 분산 처리하기 위한 **오픈 소스 프레임워크**입니다. 애자일(Agile)은 소프트웨어 개발 방법론의 한 종류입니다.

> [!note]- 5. 리팩토링(Refactoring)을 하는 목적으로 옳은 것은? (① 산출물 버전 관리 ② 새로운 코드 설계 기술 ③ 기능 추가 ④ 내부 구조 개선)
>
> **정답:** ④ 소프트웨어의 기능 변경 없이 내부 구조만을 개선하여 소프트웨어를 보다 이해하기 쉽고, 수정하기 쉽도록 만들기 위함이다.
>
> **해설:**
>
> 리팩토링의 핵심은 **"외부적 기능 변경 없이"** 내부의 코드 구조를 효율적으로 개선(가독성 향상, 유지보수 용이)하는 것입니다.

> [!note]- 6. UML 모델에서 사용하는 Structural Diagram에 속하지 않은 것은? (① Class Diagram ② Object Diagram ③ Component Diagram ④ Activity Diagram)
>
> **정답:** ④ Activity Diagram
>
> **해설:**
>
> 3번 문제와 동일합니다. Activity Diagram은 행위(Behavioral) 다이어그램에 해당합니다.

> [!note]- 7. UI 시스템의 상태와 사용자의 지시에 대한 효과를 보여주어 명령 진행 상황을 해석할 수 있도록 도와주는 것은? (① Feedback ② Posture ③ Module ④ Hash)
>
> **정답:** ① Feedback
>
> **해설:**
>
> 피드백(Feedback)은 사용자의 작용에 대해 시스템이 반응하는 것을 의미하며, 현재 상태를 사용자에게 즉각적으로 알려주는 역할을 합니다.

> [!note]- 8. 하향식 설계 방법과 상향식 설계 방법에 대한 비교 설명으로 가장 좋지 않은 것은? (① 하향식은 통합이 간단하다 ② 하향식은 초기 단계에 세부 사항이 필요하다 ③ 상향식은 하위 모듈부터 설계한다 ④ 상향식은 기능 추가가 쉽다)
>
> **정답:** ② 하향식 설계에서 레벨이 낮은 데이터 구조의 세부 사항은 설계 초기 단계에서 필요하다.
>
> **해설:**
>
> 하향식(Top-down) 설계는 상위 레벨에서 시작하여 점진적으로 구체화하므로, 초기 단계에서는 하위의 세부 사항보다는 **전체적인 구조와 인터페이스 정의**에 집중합니다.

> [!note]- 9. 객체지향에서 정보 은닉과 가장 밀접한 관계가 있는 것은? (① Encapsulation ② Class ③ Method ④ Instance)
>
> **정답:** ① Encapsulation (캡슐화)
>
> **해설:**
>
> 캡슐화는 데이터와 데이터를 처리하는 함수를 하나로 묶는 것으로, 외부에서 직접적인 접근을 제한하여 정보를 은닉하는 목적을 가집니다.

> [!note]- 10. 객체 지향 소프트웨어 공학에서 하나 이상의 유사한 객체들을 묶어서 하나의 공통된 특성을 표현한 것은? (① 트랜잭션 ② 클래스 ③ 시퀀스 ④ 서브루틴)
>
> **정답:** ② 클래스 (Class)
>
> **해설:**
>
> 클래스는 객체들을 생성하기 위한 청사진(Template)이며, 공통된 속성과 행위를 정의한 집합체입니다.

> [!note]- 11. GoF(Gang of Four)의 디자인 패턴에서 행위 패턴에 속하는 것은? (① Builder ② Visitor ③ Prototype ④ Bridge)
>
> **정답:** ② Visitor
>
> **해설:**
>
> - Builder, Prototype: 생성 패턴
>     
> - Bridge: 구조 패턴
>     
> - Visitor: 행위 패턴
>     

> [!note]- 12. CASE 도구에 대한 설명으로 거리가 먼 것은? (① 자동화 도구 ② 문서 자동화 제공 ③ 커뮤니케이션 증대 ④ 2000년대 이후 객체지향에만 한정 활용)
>
> **정답:** ④ 2000년대 이후 소개되었으며, 객체지향 시스템에 한해 효과적으로 활용된다.
>
> **해설:**
>
> CASE(Computer Aided Software Engineering) 도구는 1980년대부터 사용되었으며, 특정 방법론(객체지향 등)에만 한정되지 않고 다양한 개발 환경에서 자동화를 위해 사용됩니다.

> [!note]- 13. UI 설계 원칙에서 누구나 쉽게 이해하고 사용할 수 있어야 한다는 것은? (① 유효성 ② 직관성 ③ 무결성 ④ 유연성)
>
> **정답:** ② 직관성 (Intuitiveness)
>
> **해설:**
>
> 직관성은 사용자가 별도의 교육 없이도 시스템의 기능을 쉽게 파악하고 사용할 수 있는 성질을 의미합니다.

> [!note]- 14. 효과적인 모듈화 설계 방법으로 가장 거리가 먼 것은? (① 결합도 강하게, 응집도 약하게 ② 복잡도 줄이기 ③ 유지보수 용이 ④ 적절한 모듈 크기)
>
> **정답:** ① Coupling은 강하게 Cohesion는 약하게 설계한다.
>
> **해설:**
>
> 좋은 소프트웨어 설계는 **결합도(Coupling)를 낮게(Loose), 응집도(Cohesion)를 높게(Strong)** 설계하는 것입니다.

> [!note]- 15. 객체 지향 기법에서 클래스에 속한 각각의 객체를 의미하는 것은? (① Instance ② Message ③ Method ④ Module)
>
> **정답:** ① Instance
>
> **해설:**
>
> 인스턴스는 추상적인 클래스로부터 실제 메모리에 할당되어 구체화된 실체를 의미합니다.

> [!note]- 16. 럼바우의 객체 지향 분석과 거리가 먼 것은? (① 기능 모델링 ② 동적 모델링 ③ 객체 모델링 ④ 정적 모델링)
>
> **정답:** ④ 정적 모델링
>
> **해설:**
>
> 럼바우(Rumbaugh)의 분석 기법(OMT)은 객체 모델링(Object), 동적 모델링(Dynamic), 기능 모델링(Functional)의 3개 단계로 이루어집니다.

> [!note]- 17. 다음 내용이 설명하는 디자인 패턴은? (객체 생성 인터페이스 정의, 인스턴스 결정은 서브클래스, Virtual-Constructor 패턴) (① Visitor ② Observer ③ Factory Method ④ Bridge)
>
> **정답:** ③ Factory Method 패턴
>
> **해설:**
>
> 팩토리 메서드 패턴은 상위 클래스에서 인터페이스를 정의하고, 실제 어떤 클래스를 생성할지는 하위 클래스에서 결정하도록 위임하는 패턴입니다.

> [!note]- 18. 정형 기술 검토(FTR)의 지침으로 틀린 것은? (① 의제 제한 ② 논쟁 제한 ③ 문제 영역 명확화 ④ 참가자 수 제한 없음)
>
> **정답:** ④ 참가자의 수를 제한하지 않는다.
>
> **해설:**
>
> FTR은 효율적인 검토를 위해 참가자의 수를 3~5명 정도로 적절히 제한해야 합니다.

> [!note]- 19. 요구사항 명세 기법에 대한 설명으로 틀린 것은? (① 비정형은 자연어 기반 ② 비정형은 Z 기법 사용 ③ 정형은 수학적 원리 사용 ④ 정형이 더 간결함)
>
> **정답:** ② 비정형 명세 기법은 사용자의 요구를 표현할 때 Z 비정형 명세 기법을 사용한다.
>
> **해설:**
>
> Z 명세 기법은 수학적 집합론과 논리를 바탕으로 하는 **정형(Formal)** 명세 기법의 대표적인 예입니다.

> [!note]- 20. 주어진 한 모듈(Module)을 제어하는 상위 모듈 수를 나타내는 것은? (① Fan-out ② Coupling ③ Fan-in ④ Cohesion)
>
> **정답:** ③ Fan-in
>
> **해설:**
>
> - Fan-in: 어떤 모듈을 사용하는(제어하는) 상위 모듈의 수
>     
> - Fan-out: 어떤 모듈이 사용하는(제어하는) 하위 모듈의 수
>     

> [!note]- 21. 자료 흐름도(DFD)를 작성하는데 지침이 될 수 없는 항목은? (① 변환 시 새 이름 부여 ② 입력이 있어야 출력 발생 ③ 저장소 입력 시 반드시 출력 표시 ④ 상위/하위 자료 흐름 일치)

> [!note]- 22. 다음 중 스크럼(Scrum) 방법론에서 일반적으로 하지 않는 활동은? (① 제품 백로그 작성 ② 사용자 스토리 기반 계획 ③ 스프린트 회고 ④ PM 단독 평가)

> [!note]- 23. 요구사항 명세서를 미리 배포하여 사전 검토한 후 짧은 회의를 통해 오류를 검출하는 검토 방법은? (① 빌드 검증 ② 동료 검토 ③ 워크스루 ④ 개발자 검토)

> [!note]- 24. 정형 기술 검토(FTR)의 지침으로 틀린 것은? (① 의제 제한 ② 논쟁 제한 ③ 문제 영역 명확화 ④ 참가자 수 제한 없음)

### 🗄️ [데이터베이스 구축] 문제 은행

> [!note]- 1. SQL의 분류 중 DDL에 해당하지 않는 것은? (① UPDATE ② ALTER ③ DROP ④ CREATE)

>
> **해설:**
>
> UPDATE는 데이터를 조작하는 **DML(Data Manipulation Language)**입니다. ALTER, DROP, CREATE는 데이터 정의어(DDL)입니다.

> [!note]- 2. "연락번호"가 Null 값이 아닌 "사원명"을 검색하는 SQL 질의로 옳은 것은? (① !＝NULL ② ＜＞＝NULL ③ IS NOT NULL ④ DON'T NULL)
>
> **정답:** ③ SELECT 사원명 FROM 회사원 WHERE 연락번호 IS NOT NULL;
>
> **해설:**
>
> SQL에서 NULL 값을 체크할 때는 비교 연산자(<code>=</code>)가 아닌 `IS NULL` 또는 `IS NOT NULL` 키워드를 사용해야 합니다.

> [!note]- 3. 트랜잭션의 연산은 모두 반영되든지 아니면 전혀 반영되지 않아야 한다는 특성은? (① Durability ② Share ③ Consistency ④ Atomicity)
>
> **정답:** ④ Atomicity (원자성)
>
> **해설:**
>
> 원자성은 트랜잭션 내의 작업들이 부분적으로 성공해서는 안 되며, "All or Nothing"의 원칙을 지켜야 함을 의미합니다.

> [!note]- 4. 병행 제어의 로킹(Locking) 단위에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ② 로킹 단위가 작아지면 로킹 오버헤드가 감소한다.
>
> **해설:**
>
> 로킹 단위가 작아지면 관리해야 할 잠금의 수가 많아지므로 **오버헤드가 증가**합니다. 대신 데이터베이스 공유도(병행성)는 높아집니다.

> [!note]- 5. 뷰(View)에 대한 설명으로 틀린 것은? (① 뷰 위에 뷰 정의 가능 ② DML 제약 따름 ③ ALTER로 변경 불가 ④ 기본 테이블 제거 시 뷰 유지)
>
> **정답:** ④ 뷰가 정의된 기본 테이블이 제거되어도 뷰는 그대로 있다.
>
> **해설:**
>
> 뷰는 실제 데이터를 갖지 않는 가상 테이블이므로, 정의 기반이 되는 **기본 테이블이 삭제되면 해당 뷰를 사용할 수 없게 됩니다.**

> [!note]- 6. 릴레이션에 대한 설명으로 거리가 먼 것은? (① 시간에 따라 변함 ② 튜플 상이함 ③ 원자 값 저장 ④ 튜플 간 순서 있음)
>
> **정답:** ④ 한 릴레이션에 포함된 튜플 사이에는 순서가 있다.
>
> **해설:**
>
> 릴레이션 내의 **튜플들 사이에는 정해진 순서가 없습니다.** 데이터의 집합으로 취급되기 때문입니다.

> [!note]- 7. 관계 대수에 대한 설명으로 틀린 것은? (① 연산 집합 ② 일반/순수 구분 ③ 연산 순서 명시 ④ 비절차적 방법)
>
> **정답:** ④ 원하는 정보와 그 정보를 어떻게 유도하는가를 기술하는 비절차적 방법이다.
>

>

> [!note]- 8. 데이터베이스 설계 과정 중 개념적 설계 단계에 대한 설명으로 옳지 않은 것은?

>

> - $r1 \Join r2$: Join (테이블 r1, r2)
>     

> [!note]- 15. 후보키가 튜플 식별을 위해 만족해야 하는 두 가지 속성은? (① 중복성 ② 최소성 ③ 참조성 ④ 동일성)
>
> **정답:** ② 최소성 (Minimality)
>
> **해설:**
>
> 후보키는 모든 튜플을 고유하게 식별하는 **유일성**과, 꼭 필요한 속성으로만 구성되는 **최소성**을 모두 만족해야 합니다.

> [!note]- 5. 지역성(Locality)에 대한 설명으로 옳지 않은 것은?
>
> **정답:** ③ 공간 지역성은 하나의 기억장소가 가까운 장래에도 참조될 가능성이 높음을 의미한다.
>
> **해설:**
>
> 설명된 내용은 **시간 지역성(Temporal Locality)**에 대한 설명입니다. **공간 지역성(Spatial Locality)**은 특정 기억장소와 **인접한 주소**들이 곧 참조될 가능성이 높음을 의미합니다.

> [!note]- 6. 기억장치 관리의 페이지 교체 기법이 아닌 것은? (① LFU ② FIFO ③ LUF ④ LRU)
>
> **정답:** ③ LUF
>
> **해설:**
>
> 주요 페이지 교체 알고리즘은 다음과 같습니다:
>
> - FIFO: First-In, First-Out
>     
> - LRU: Least Recently Used (가장 오랫동안 사용되지 않은 페이지 교체)
>     
> - LFU: Least Frequently Used (참조 횟수가 가장 적은 페이지 교체)
>     

> [!note]- 7. HRN 방식으로 스케줄링 할 경우, 처리되는 작업 순서로 옳은 것은? (A: 대기5/실행20, B: 대기40/실행20, C: 대기15/실행45, D: 대기20/실행2)
>
> **정답:** ③ D → B → C → A
>
> **해설:**
>
> HRN(Highest Response-ratio Next) 우선순위 계산식:
>
> $Priority = \frac{Wait + Service}{Service}$
>
> - A: $(5 + 20) / 20 = 1.25$
>     
> - B: $(40 + 20) / 20 = 3.0$
>     
> - C: $(15 + 45) / 45 = 1.33$
>     
> - D: $(20 + 2) / 2 = 11.0$
>     
>     우선순위 숫자가 큰 순서대로 수행됩니다 ($D > B > C > A$).
>

> [!note]- 9. 200.1.1.0/24 네트워크를 FLSM으로 10개의 서브넷으로 나눌 때, 10번째 서브넷의 broadcast IP는?

### 🏗️ [정보시스템 구축 관리] 문제 은행

> [!note]- 1. 고객과의 의사소통, 위험 분석, 구축, 평가 과정을 반복하며 대규모 프로젝트에 유리한 모형은? (① 프로토타입 ② 폭포수 ③ 나선형 ④ RAD)

>
> **해설:**
>
> 나선형 모델은 보기에 설명된 대로 **위험 분석**을 가장 중요시하며, 점진적으로 완성도를 높여가는 방식입니다. 대규모 및 고위험 시스템 개발에 적합합니다.

> [!note]- 2. 나선형 모델의 4가지 주요 활동이 순서대로 나열된 것은? (Ⓐ계획 Ⓑ평가 Ⓒ개발 Ⓓ위험분석)
>
> **정답:** ② Ⓐ-Ⓓ-Ⓒ-Ⓑ 순으로 반복
>
> **해설:**
>
> 나선형 모델의 표준 순서는 **계획 수립(Planning) $\rightarrow$ 위험 분석(Risk Analysis) $\rightarrow$ 개발 및 검증(Engineering) $\rightarrow$ 고객 평가(Customer Evaluation)**입니다.

> [!note]- 3. 소프트웨어 비용 추정 모형(Estimation Models)이 아닌 것은? (① COCOMO ② Putnam ③ Function-Point ④ PERT)
>
> **정답:** ④ PERT
>
> **해설:**
>
> PERT는 프로젝트의 **일정 관리(Scheduling)** 및 진척 관리를 위한 도구입니다. 1, 2, 3번은 비용 및 노력을 추정하는 모델입니다.

> [!note]- 4. 소프트웨어 프로젝트 관리에 대한 설명으로 가장 옳은 것은?
>
> **정답:** ④ 주어진 기간 내에 최소의 비용으로 사용자를 만족시키는 시스템을 개발
>
> **해설:**
>
> 프로젝트 관리의 궁극적인 목표는 한정된 자원(시간, 비용, 인력)을 효율적으로 활용하여 품질 요건을 만족하는 결과물을 완성하는 것입니다.

> [!note]- 5. CMM(Capability Maturity Model) 모델의 5단계 레벨로 옳지 않은 것은? (① 최적 단계 ② 관리 단계 ③ 정의 단계 ④ 계획 단계)
>
> **정답:** ④ 계획 단계
>
> **해설:**
>
> CMM 단계: 초기(Initial) $\rightarrow$ 관리(Managed) $\rightarrow$ 정의(Defined) $\rightarrow$ 정량적 관리(Quantitatively Managed) $\rightarrow$ 최적화(Optimizing). '계획 단계'는 표준 레벨 명칭에 없습니다.

> [!note]- 6. 차세대 이동통신, 홈네트워킹 등 대규모 디바이스 네트워크 생성에 최적화된 기술은? (① SDP ② VPN ③ LAN ④ Mesh Network)

>
> **해설:**
>
> 메쉬 네트워크는 각 노드가 다른 노드들과 직접 연결되어 망 형태를 이루는 기술로, 확장성이 좋고 특정 노드 장애 시에도 우회 경로를 통해 통신이 가능합니다.

> [!note]- 7. WAS(Web Application Server)가 아닌 것은? (① JEUS ② JVM ③ Tomcat ④ WebSphere)
>
> **정답:** ② JVM
>
> **해설:**
>
> JVM(Java Virtual Machine)은 자바 프로그램을 실행하기 위한 가상 머신(환경)입니다. JEUS, Tomcat, WebSphere는 동적 콘텐츠를 처리하는 웹 애플리케이션 서버입니다.

> [!note]- 8. 오픈 소스 기반 분산 컴퓨팅 플랫폼으로 빅데이터를 효율적으로 저장/처리하는 것은? (① 하둡 ② 비컨 ③ 포스퀘어 ④ 멤리스터)
>
> **정답:** ① 하둡(Hadoop)
>
> **해설:**
>
> 하둡은 여러 개의 저렴한 컴퓨터를 하나로 묶어 대용량 데이터를 처리하는 분산 파일 시스템(HDFS)과 맵리듀스(MapReduce) 프레임워크를 제공합니다.

> [!note]- 9. 정보보안의 3대 요소에 해당하지 않는 것은? (① 기밀성 ② 휘발성 ③ 무결성 ④ 가용성)
>
> **정답:** ② 휘발성
>
> **해설:**
>
> 보안의 3요소(CIA): **기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)**입니다.

> [!note]- 10. 공개키 암호화 방식에 대한 설명으로 틀린 것은?
>
> **정답:** ① 공개키로 암호화된 메시지는 반드시 공개키로 복호화해야 한다.
>
> **해설:**
>
> 공개키(Public Key)로 암호화한 데이터는 오직 그에 대응하는 **비밀키(Private Key)**로만 복호화할 수 있습니다. (비대칭성)

> [!note]- 11. 백도어 탐지 방법으로 틀린 것은? (① 무결성 검사 ② 닫힌 포트 확인 ③ 로그 분석 ④ SetUID 파일 검사)
>
> **정답:** ② 닫힌 포트 확인
>
> **해설:**
>
> 백도어는 주로 통로를 열어두기 때문에 **열린 포트(Open Port)**를 확인해야 합니다. 닫힌 포트는 외부와 연결되어 있지 않으므로 탐지와 무관합니다.

> [!note]- 12. 위험 유형이 다른 하나는? (① 스위치 재밍 ② 서버 팜 ③ 물리적 위험 ④ 기술적 위험)
>
> **정답:** ② 서버 팜 (Server Farm)
>
> **해설:**
>
> 서버 팜은 다수의 서버를 모아놓은 시설/환경을 의미하는 용어이며, 그 자체로 공격이나 위험 유형을 뜻하지 않습니다.

> [!note]- 13. 고전적 생명주기 모형으로 선형 순차적 모델이라고도 불리는 것은? (① 폭포수 모형 ② 애자일 모형 ③ 컴포넌트 기반 ④ 6GT 모형)
>
> **정답:** ① 폭포수 모형 (Waterfall Model)
>
> **해설:**
>
> 한 단계가 끝나야 다음 단계로 넘어가는 가장 전통적이고 고전적인 모델입니다.


> [!note]- 14. COCOMO 모델의 프로젝트 유형으로 거리가 먼 것은? (① Organic ② Semi-detached ③ Embedded ④ Sequential)
>
> **정답:** ④ Sequential
>
> **해설:**
>
> COCOMO의 규모별 유형: 소규모(Organic), 중규모(Semi-detached), 대규모/복잡형(Embedded) 3가지입니다.

> [!note]- 15. 가상 세계가 현실 세계에 흡수된 형태이며 진보된 개념의 가상현실 서비스는? (① AaaS ② Grid ③ Metaverse ④ Splogger)
>
> **정답:** ③ Metaverse (메타버스)
>
> **해설:**
>
> 가상, 초월을 뜻하는 'Meta'와 우주를 뜻하는 'Universe'의 합성어로, 사회·경제·문화 활동이 이루어지는 가상 세계를 의미합니다.

> [!note]- 16. 하둡(Hadoop)과 관계형 데이터베이스(RDBMS) 간 데이터를 전송하는 도구는? (① Apnic ② Topology ③ Sqoop ④ SDB)
>
> **정답:** ③ Sqoop (스쿱)
>
> **해설:**
>
> Sqoop은 **SQL-to-Hadoop**의 약자로, 구조화된 데이터를 하둡으로 가져오거나 내보내는 전송 도구입니다.

> [!note]- 17. 소프트웨어 개발 방법론의 테일러링(Tailoring) 설명으로 틀린 것은?
>
> **정답:** ① 프로젝트 수행 시 예상되는 변화를 배제하고 신속히 진행하여야 한다.
>
> **해설:**
>
> 테일러링은 프로젝트의 특성이나 상황에 맞춰 방법론을 **유연하게 조정**하는 과정이므로, 변화를 배제하는 것이 아니라 변화를 수용하고 최적화하는 활동입니다.

> [!note]- 18. 네트워크 제어부와 데이터 전달부를 분리하여 소프트웨어로 제어하는 기술은? (① SDN ② NFS ③ Network Mapper ④ AOE)
>
> **정답:** ① SDN (Software Defined Networking)
>
> **해설:**
>
> 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 분리하여 중앙 집중식으로 네트워크를 관리하는 차세대 기술입니다.

> [!note]- 19. 침입자를 유인하여 공격기법 정보를 수집하기 위해 의도적으로 설치한 시스템은? (① Apache ② Hadoop ③ Honeypot ④ MapReduce)
>

>
> **해설:**
>
> '꿀단지'라는 뜻으로, 해커를 유인해 공격을 분석하고 추적하기 위해 만든 가짜 시스템입니다.

> [!note]- 20. ICMP 특성을 악용하여 특정 사이트에 집중적으로 데이터를 보내 불능으로 만드는 공격은? (① TearDrop ② Smishing ③ Qshing ④ Smurfing)
>
> **정답:** ④ Smurfing (스머핑)
>
> **해설:**
>
> IP 브로드캐스트와 ICMP Echo Request를 이용해 수많은 응답 패킷이 대상 시스템에 쏟아지게 하는 DoS 공격의 일종입니다.

> [!note]- 21. 물리적 보안에 해당하는 내용으로 가장 적절하지 않은 것은?
>
> **정답:** ④ 조직 내 정보보안의 정책과 절차 수립
>
> **해설:**
>

> [!note]- 22. 큰 숫자를 소인수 분해하기 어렵다는 점을 이용한 공개키 암호 알고리즘은? (① DES ② ARIA ③ SEED ④ RSA)
>

>
> **해설:**
>
> RSA는 소인수 분해 문제의 수학적 복잡성을 기반으로 설계된 가장 대표적인 비대칭 암호화 알고리즘입니다. (DES, SEED 등은 대칭키 방식입니다.)

> [!note]- 23. 외부 접속 시 인가 여부를 점검하여 허용/거부하는 접근제어 유틸리티는? (① tcp wrapper ② trace checker ③ token finder ④ change detector)
>
> **정답:** ① tcp wrapper
>
> **해설:**
>
> TCP 래퍼는 호스트 기반의 네트워크 접근 제어 도구로, `/etc/hosts.allow`와 `/etc/hosts.deny` 파일을 통해 접속을 필터링합니다.

> [!note]- 24. 윈도우와 리눅스 간의 상호 운용을 돕는 소프트웨어가 아닌 것은? (① Samba ② OpenSSH ③ Cygwin ④ Microsoft Office)
>

>
> **해설:**
>
> MS Office는 문서 작성 도구입니다. Samba(파일 공유), OpenSSH(원격 접속), Cygwin(리눅스 환경 제공)은 두 운영체제 간의 기술적 호환을 돕는 도구들입니다.
