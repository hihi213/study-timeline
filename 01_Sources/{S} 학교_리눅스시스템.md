		알고리즘 강의는 자료구조의 일부 개념을 포함하여 진행됩니다. 일부 저자들은 자료구조와 알고리즘을 함께 다루기도 하고, 다른 저자들은 자료구조 부분을 제외하고 알고리즘 성능 분석부터 시작하기도 합니다. `힙(heap)`, `해시(hash)`, `그래프(graph)` 등은 자료구조의 후반부에 나오는 내용이며, 탐색 등은 이진 트리(binary tree)를 기반으로 합니다. 따라서 알고리즘을 이해하기 위해서는 자료구조에 대한 지식이 필수적입니다. 이 수업은 2학년을 기준으로 개설되었기 때문에, 첫 3주 동안은 자료구조의 핵심 내용을 빠르게 복습할 것입니다. 자료구조를 처음 듣는 2학년 학생들도 수업을 따라올 수 있도록 노력해야 합니다.
		
		본 강의의 모든 코드 구현은 `C` 언어를 기반으로 하므로, `C` 코딩 능력을 갖추는 것이 중요합니다. 수업에서는 실제 `C` 코드보다는 개념을 설명하는 의사코드(pseudocode)를 주로 사용할 것입니다. 현대 프로그래밍 교육의 핵심은 단순히 코드를 작성하는 방법을 넘어, 명령어의 순서를 어떻게 구성하여 효율적인 구조를 만들어낼 것인지에 맞춰져 있습니다.
		
		여러분은 학점 취득만을 위한 공부에서 벗어나야 합니다. 기업에서는 학점보다 코딩 테스트와 기술 면접을 통해 실제 역량을 평가합니다. 예를 들어, “메모장에서 파일이 어떻게 저장되는가?”와 같은 질문에 `블로킹(blocking)`/`논블로킹(non-blocking)`, 콜백 구조 등을 포함하여 시스템 수준에서 깊이 있게 설명할 수 있어야 합니다. 기초적인 질문에 답한 후에는, “환경이 바뀌면 어떻게 대처할 것인가?”와 같은 응용 질문에 대비해야 합니다. 암기 위주의 학습으로는 이러한 심층적인 질문에 답변하기 어렵습니다. AI가 프로그래머를 대체하기 위해 준비된 현시대에는 더욱 그렇습니다.
		
		이 수업에서는 `리스트(list)`, `스택(stack)`, `큐(queue)`, `트리(tree)`와 같은 자료구조를 간략히 다룰 것입니다. 알고리즘은 명령어 집합을 어떻게 효율적으로 나열할 것인가에 대한 개념적인 논의입니다. 여러분은 수업에서 배운 선택 정렬(Selection Sort)이나 퀵 정렬(Quick Sort)과 같은 개념을 `C`, `Java`, `Python` 등 자신 있는 언어를 사용하여 직접 구현하고 실행 시간을 비교 분석해보아야 합니다. (실습) 과제를 별도로 부여하지 않더라도, 스스로 이러한 프로그래밍 연습을 하는 것이 중요합니다.
		
		자료구조의 정의, 알고리즘의 정의, 그리고 `C` 언어에서 핵심적인 `포인터(pointer)`, `구조체(struct)`, 메모리 구성(`스택`과 `힙`의 동작 방식)에 대해 이해해야 합니다. 자료구조는 데이터를 컴퓨터 시스템에 효율적으로 저장하고 관리하는 방법입니다. 시스템이 기본적으로 제공하는 `int`, `float`, `double`, `char` 등은 단순 자료구조입니다. 여러 데이터를 혼합해서 만드는 복합 자료구조는 선형(linear) 자료구조와 비선형(non-linear) 자료구조로 나뉩니다.
		
		과거 `C` 언어가 처음 등장했을 때의 데이터는 대부분 텍스트나 이미지였습니다. 텍스트는 파일을 열어 저장하는 방식으로 처리되었습니다. 여러분은 프로그램의 결과값을 모니터에 출력하는 것뿐만 아니라, 파일 포인터를 이용해 텍스트 파일에 직접 쓰고 읽는 작업을 모두 경험해보아야 합니다. (실습)
		
		비선형 자료구조의 대표적인 예시로는 `트리(tree)`와 `그래프(graph)`가 있습니다. 여러분이 사용하는 시스템의 디렉토리 구조(폴더 구조)가 바로 `트리` 구조의 좋은 예입니다. 또한, `키(key)`와 `값(value)`으로 구성된 `해시 테이블(hash table)`도 비선형 구조에 해당합니다. 자료구조 시간에는 이러한 각 구조의 개념을 배우고, 알고리즘 시간에는 이를 기반으로 프로그램 명령어들을 어떻게 더 효율적으로 나열할지, 즉 더 나은 프로그램을 설계하는 방법을 공부합니다.
		
		모든 데이터는 시스템 메모리나 하드디스크에 결국 `0`과 `1`의 스트림으로 저장됩니다. 시스템이 이진 데이터를 의미 있는 데이터 형태로 사용하기 위해서는, 특정 '형식' 즉, 자료형(data type)이라는 틀에 맞추어 값을 읽어와야 합니다. 예를 들어, 메모리에 저장된 4바이트의 동일한 이진 데이터를 `int`형으로 읽을 때와 `float`형으로 읽을 때는 완전히 다른 값이 됩니다. `float`는 부호, 지수, 유효숫자 파트로 나누어 해석하기 때문입니다. 이러한 시스템의 근본적인 데이터 처리 방식을 이해하는 것이 중요합니다.
		
		`C` 언어에는 문자형이라는 개념이 없으며, `정수형`과 `실수형` 두 가지만 존재합니다. `char` 타입은 `%c` 서식자를 통해 문자로 변환하여 출력할 뿐, 실제로는 작은 정수형으로 취급됩니다. 이는 유니코드 기반의 문자형이 존재하는 `Java`와 같은 언어와의 차이점입니다. 또한 `C` 언어에서 `int`의 크기는 고정되어 있지 않고 시스템에 따라 달라지는 ‘시스템 의존적(system-dependent)’ 특징을 가집니다. 16비트 운영체제에서는 2바이트, 32비트나 64비트 운영체제에서는 4바이트로 처리됩니다. `C` 언어는 배열의 인덱스 범위를 벗어난 메모리에 접근해도 오류를 발생시키지 않고 값을 읽어오는 등의 보안 취약점이 발견되어, 최근 미국 국방성에서는 `C` 코드 사용을 금지하는 추세입니다.
		
		프로그램이 실행될 때 메모리는 일반적으로 `코드(Code)`, `데이터(Data)`, `힙(Heap)`, `스택(Stack)`의 네 가지 영역으로 나뉩니다. 컴파일된 기계어 코드는 코드 영역에, 전역 변수나 정적 변수는 데이터 영역에 저장됩니다. 함수 호출 시 필요한 정보는 스택 영역에, 동적 할당 메모리나 전역 변수는 힙 영역을 사용합니다. 이러한 시스템 내부 구조에 대한 이해는 비전공자와 차별화되는 여러분의 핵심 경쟁력입니다.
		
		선형 자료구조 중 배열은 프로그램 실행 중 크기가 변하지 않는 고정된 데이터를 다룰 때 유용합니다. 반면, 크기가 자주 변경되어야 하는 상황에서는 다른 자료구조가 필요합니다. 예를 들어, 공중 화장실에 대기하는 사람들의 줄을 시뮬레이션하는 프로그램을 생각해보겠습니다. 사람들이 줄을 서는 행위는 먼저 온 사람이 먼저 서비스를 받는 `큐(Queue)` 구조로 모델링할 수 있습니다. 만약 화장실 이용에 걸리는 평균 시간(예: 1분)보다 사람들이 줄을 서러 오는 평균 시간(예: 2분)이 더 길다고 해서 대기 줄이 생기지 않을 것이라고 단정할 수 없습니다. '평균'이라는 함정 때문입니다. 실제 상황은 불규칙적이므로, 대기 줄은 무한히 길어질 수도 있습니다. 이러한 상황을 분석하기 위해 `M/M/1 큐`와 같은 모델을 사용한 시뮬레이션 프로그램을 작성해봐야 합니다. (실습)
		
		결론적으로, AI 시대에는 정형화된 지식을 암기하는 방식에서 벗어나 유연하고 창의적으로 사고하는 능력이 매우 중요합니다. 시스템의 근본 원리를 이해하고, 이를 바탕으로 복잡한 문제를 모델링하고 해결하는 훈련을 해야 합니다.
		
		(2025-09-04, 1교시)
		
		여러분은 질문을 받았을 때 즉시 검색으로 답을 찾기보다, 이미 배운 지식을 기반으로 답을 유추하는 사고 훈련을 해야 합니다. 이러한 깊이 있는 사고 과정 없이는 지식이 머리에 저장되지 않고 쉽게 사라집니다.
		
		자료구조의 가장 기본적인 개념은 **배열(Array)**과 **연결 리스트(Linked List)**의 비교에서 시작합니다. 배열은 선언과 동시에 고정된 크기의 연속된 메모리 공간을 할당합니다. 이 때문에 할당된 공간을 전부 사용하지 않으면 메모리 낭비가 발생하며, 다른 프로그램이 해당 공간을 사용할 수 없습니다. 반면 연결 리스트는 데이터와 포인터로 구성된 '노드(node)'를 기본 단위로 사용합니다. 필요할 때마다 `malloc()`과 같은 함수를 통해 동적으로 메모리를 할당하므로, 메모리 공간이 비연속적이더라도 포인터로 연결하여 마치 연속된 것처럼 사용할 수 있습니다.
		
		배열의 특정 원소에 접근할 때는 인덱스를 사용하는데, 이는 CPU의 하드웨어 수준에서 효율적으로 처리됩니다. 배열의 시작 주소는 **베이스 레지스터(Base Register)**에, 인덱스 값은 **인덱스 레지스터(Index Register)**에 저장되어 주소 계산이 빠르게 이루어집니다. 이와 유사하게, CPU는 다음에 실행할 명령어의 주소를 **프로그램 카운터(Program Counter, PC)**에 저장하고, 명령을 하나 실행할 때마다 PC 값을 증가시켜 순차적으로 프로그램을 진행합니다. 이 모든 과정은 여러분이 컴퓨터 구조 시간에 배운 내용과 연결됩니다.
		
		연결 리스트는 필요한 만큼만 메모리를 할당하므로 낭비가 적습니다. 데이터가 100개 필요할 것이라 예상하고 크기 100의 배열을 선언했는데 실제로는 30개만 사용했다면, 나머지 70개 분량의 메모리는 낭비됩니다. 그러나 연결 리스트는 프로그램 실행 중에 필요에 따라 노드를 생성하고, 필요 없어지면 `free()`를 통해 메모리를 해제하므로 이러한 비효율을 줄일 수 있습니다.
		
		`C` 언어에서 `register int a = 7;`과 같이 변수를 선언하면, 해당 변수는 메모리가 아닌 CPU 레지스터에 할당될 수 있습니다. 레지스터는 메모리 주소 값을 갖지 않으며 번호로 관리됩니다. 이렇게 하면 CPU가 메모리까지 데이터를 가지러 가는 `패치(fetch)` 시간을 절약하여 연산 속도를 크게 향상시킬 수 있습니다. 하지만 레지스터 공간이 부족하면 일반 메모리에 할당되므로, 성능 향상이 항상 보장되는 것은 아닙니다.
		
		**스택(Stack)**은 LIFO(Last-In, First-Out) 구조를 가지며, 시스템에서 인터럽트(interrupt)나 함수 호출을 처리할 때 핵심적인 역할을 합니다. 예를 들어, 프로그램 실행 중 우선순위가 높은 인터럽트(예: 카카오톡 알림)가 발생하면, CPU는 현재 실행하던 명령어의 다음 주소(PC 값)를 스택에 `push`하여 저장합니다. 그 후 인터럽트 서비스 루틴으로 점프하여 해당 작업을 처리하고, 완료되면 스택에서 저장해 둔 주소를 `pop`하여 원래 프로그램의 흐름으로 복귀합니다.
		
		**큐(Queue)**는 FIFO(First-In, First-Out) 구조로, 먼저 들어온 데이터가 먼저 처리됩니다. 이는 영화관 매표소나 프린터의 스풀(spool) 메모리처럼 순서가 중요한 작업에 사용됩니다. 네트워크에서도 속도가 다른 장치 간의 데이터 전송을 조절하기 위해 큐를 사용합니다. 큐를 배열로 구현할 경우, 맨 앞의 데이터를 `dequeue`하면 뒤따르는 모든 원소를 한 칸씩 앞으로 이동시켜야 하는 비효율이 발생합니다. 이를 해결하지 않으면 배열 앞부분에 빈 공간이 누적되어, 실제로는 공간이 남아있음에도 큐가 가득 찼다고 판단하는 문제가 생길 수 있습니다. (이는 원형 큐(Circular Queue)로 해결할 수 있습니다.) 반면, 연결 리스트로 큐를 구현하면 첫 노드의 연결만 끊어주면 되므로 삽입과 삭제가 훨씬 효율적입니다.
		
		**트리(Tree)**나 **그래프(Graph)**와 같은 복잡한 비선형 구조들도 결국에는 배열이나 연결 리스트를 기반으로 구현됩니다. 예를 들어, 이진 트리는 배열의 인덱스를 이용해 부모와 자식 노드의 관계를 표현할 수 있습니다. 그래프는 내비게이션의 최단 경로 탐색(예: 벨만-포드(Bellman-Ford) 알고리즘)이나 회로 기판의 부품 연결 관계 분석 등 네트워크 형태의 문제를 모델링하는 데 사용됩니다. 그래프는 간선에 방향이 있는 방향성 그래프(예: 대학의 선수과목 체계)와 방향이 없는 무방향성 그래프(예: 집과 학교를 오가는 길)로 나뉩니다.
		
		연결 리스트에는 여러 변형이 있습니다. 단일 연결 리스트는 단방향 탐색만 가능하지만, **이중 연결 리스트(Doubly Linked List)**는 이전 노드와 다음 노드를 모두 가리키는 포인터를 가져 양방향 탐색이 가능합니다. **원형 연결 리스트(Circular Linked List)**는 마지막 노드가 첫 노드를 가리켜 순환 구조를 이룹니다.
		
		**힙(Heap)**은 **우선순위 큐(Priority Queue)**를 구현하는 데 사용되는 자료구조입니다. 일반 큐가 도착 순서대로 공평하게 처리하는 반면, 우선순위 큐는 우선순위가 높은 데이터가 나중에 도착하더라도 먼저 처리할 수 있도록 합니다. 예를 들어, 톨게이트 대기 줄(큐)에 구급차가 도착하면 다른 차들보다 먼저 보내주는 상황을 구현할 때 힙을 사용합니다.
		
		결론적으로, **알고리즘**이란 "문제를 어떻게 효율적으로 풀 것인가"에 대한 방법론입니다. 프로그램의 정답은 하나가 아니며, 정확한 결과를 내놓는다면 모두 정답입니다. 하지만 1억 년 뒤에 답이 나오는 프로그램은 '잘못된' 것이 아니라 '비효율적인' 것입니다. 알고리즘 학습의 목표는 주어진 자원을 최대한 효율적으로 사용하여, 가장 빠르게 정확한 결과를 도출하는 명령어의 순서를 설계하는 것입니다.
		
		(2025-09-04, 2교시)
		
		오늘 이 시간 이후로 포인터(pointer) 개념을 완전히 마스터하기 바랍니다. 포인터는 어려운 개념이 아닙니다. `int a;`가 정수형 데이터를 담는 변수라는 것을 모두가 알고 있듯이, 포인터 변수는 **메모리의 주소 값(address)**을 담는 변수라고 이해하면 모든 것이 해결됩니다. `int` 포인터에는 `int` 변수의 주소가, `float` 포인터에는 `float` 변수의 주소가, 구조체(structure) 포인터에는 구조체 변수의 주소가 들어갑니다.
		
		컴퓨터 내부의 동작을 더 정확히 살펴보겠습니다. 우리가 `int a;`라고 선언하면, 컴파일러는 `int`의 크기(예: 4바이트)만큼 메모리 공간을 확보하고 그 시작 **주소**를 반환합니다. 'a'라는 변수명은 우리가 이 주소를 쉽게 사용하기 위한 별명일 뿐, 하드웨어는 이름이 아닌 주소로 해당 위치를 찾아갑니다. 즉, 변수 a는 실질적으로 특정 메모리 주소를 가리키는 이름입니다. 그리고 이 주소 값을 저장하기 위해 만들어진 변수가 바로 포인터 변수입니다.
		
		포인터의 타입은 해당 주소에 저장된 데이터의 형태를 시스템에 알려주는 역할을 합니다. 예를 들어, 특정 주소 값을 `float*` 타입의 포인터에 저장하면, 시스템은 그 주소의 데이터를 `float` 형식으로 해석합니다. 따라서 어떤 타입의 데이터를 가리키든, 포인터 변수 자체는 메모리 주소 값만 저장하므로 **포인터 변수의 크기는 시스템의 주소 체계에 따라 고정**됩니다.
		
		32비트 시스템을 예로 들어봅시다. 32비트 머신에서 표현할 수 있는 주소의 개수는 $2^{32}$개입니다. 각 주소가 1바이트를 가리키므로, 직접적으로 접근할 수 있는 메모리의 총량은 4GB가 됩니다. 이 때문에 과거 32비트 운영체제에서는 4GB 이상의 RAM을 효율적으로 사용할 수 없었습니다. 이 시스템에서 주소 값은 32비트(4바이트)로 표현되므로, `int*`, `char*`, 심지어 수백 바이트 크기의 구조체를 가리키는 포인터라 할지라도 그 변수의 크기는 모두 **4바이트**입니다.
		
		포인터와 구조체를 함께 사용할 때도 이 원칙은 동일합니다. 예를 들어, `int` 멤버 2개와 `char` 배열 400바이트를 가진 구조체 변수의 총크기는 408바이트가 될 수 있지만, 이 구조체 변수를 가리키는 포인터 변수의 크기는 여전히 4바이트입니다.
		
		연결 리스트(Linked List)와 같은 자료구조를 구현할 때는 자기 참조 구조체(Self-Referential Structure) 개념이 사용됩니다. 이는 구조체의 멤버 변수로 자기 자신과 동일한 타입의 포인터를 포함하는 것입니다.
		
		struct Node { int data; struct Node* next; };
		
		위와 같이 Node 구조체 안에 다음 Node를 가리킬 수 있는 포인터 next를 정의함으로써, 여러 개의 노드를 사슬처럼 연결할 수 있습니다. 만약 이중 연결 리스트를 만든다면, 이전 노드를 가리키는 prev 포인터를 하나 더 추가하면 됩니다.
		
		포인터 연산에서 `p++`와 같은 증감 연산자는 특별한 의미를 가집니다. `p`가 `int` 포인터라면, `p++`는 주소 값을 1만큼 증가시키는 것이 아니라 `sizeof(int)`만큼, 즉 4바이트(32비트 시스템 기준)만큼 증가시켜 배열의 다음 원소를 가리키게 합니다. 만약 `char` 포인터였다면 1바이트만큼 증가합니다.
		
		`*` (역참조) 연산자와 `++` (증감) 연산자가 함께 쓰일 때는 **연산자 우선순위**를 반드시 고려해야 합니다.
		
		- `*p++` : `++`와 `*`는 우선순위가 같고 오른쪽에서 왼쪽으로 결합하므로, `*(p++)`와 같습니다. 즉, 현재 `p`가 가리키는 값을 먼저 가져온 뒤, `p`의 주소 값을 증가시킵니다.
		    
		- `(*p)++` : 괄호 안이 먼저 실행되므로, `p`가 가리키는 곳의 **값**을 1 증가시킵니다. 포인터의 주소는 변하지 않습니다.
		    
		
		배열의 이름은 그 자체로 배열의 첫 번째 원소를 가리키는 **상수 포인터(constant pointer)**입니다. 따라서 `int arr[10]; int* ptr = arr;`와 같은 할당은 가능하지만, `arr++`와 같은 연산은 `arr`이 변수가 아닌 상수이므로 컴파일 오류를 발생시킵니다. 반면, 포인터 변수인 `ptr`은 `ptr++` 연산이 가능합니다.
		
		일반 변수와 달리, 포인터는 서로 다른 타입끼리 암시적 형 변환이 일어나지 않습니다. `int*`에 `char*`의 주소 값을 직접 대입할 수 없는 이유는, 각 포인터가 가리키는 데이터의 크기와 해석 방법이 다르기 때문입니다. `C` 언어는 이러한 위험한 형 변환을 엄격히 금지합니다.
		
		이러한 타입 제약에서 유일하게 자유로운 것이 **`void` 포인터(`void*`)**입니다. `void*`는 '타입이 정해지지 않은' 범용 포인터로, 어떤 타입의 주소든 저장할 수 있습니다. `malloc()` 함수가 대표적인 예로, 할당된 메모리의 시작 주소를 `void*` 타입으로 반환합니다. 따라서 우리는 `malloc()`이 반환한 주소를 `(int*)`, `(struct Node*)`와 같이 우리가 사용하고자 하는 실제 타입으로 **명시적 형 변환(explicit casting)**을 해주어야 합니다.
