## **2025-09-05 — 최종(1~3교시 통합)**

### **하루 TL;DR (5줄)**

오늘 수업에서는 운영 체제(OS)가 하드웨어와 사용자 사이의 필수적인 **인터페이스**임을 학습했습니다. OS의 핵심 기능인 **프로세스, 메모리, 파일 시스템 관리** 원리를 이해하고, **커널 모드와 사용자 모드**의 분리 이유를 배웠습니다. 특히 서버 환경의 강자인 **Linux**는 오픈 소스이자 다중 사용자를 지원하는 Unix-like 시스템이며, **가상 머신(VM)**을 통해 안전하게 설치하여 학습할 것입니다. 최종적으로, 사용자는 **셸(Shell)**을 통해 OS의 핵심인 **커널(Kernel)**과 상호작용하는 구조를 파악했습니다.

### **📚 핵심 개념 3개**
* **운영 체제 (Operating System)**: 하드웨어 자원을 관리하고 응용 프로그램 실행 환경을 제공하는 핵심 시스템 소프트웨어.
* **커널(Kernel) & 시스템 콜(System Call)**: OS의 심장부로 모든 자원을 제어하며, 응용 프로그램은 시스템 콜을 통해서만 커널 기능에 접근 가능.
* **가상 머신 (Virtual Machine, VM)**: 물리적 컴퓨터 위에 가상의 컴퓨터를 만들어, 기존 시스템에 영향을 주지 않고 다른 OS를 설치/실행하는 기술.

`운영 체제(OS)` → `커널(Kernel) & 시스템 콜` → `가상 머신(VM)`

## **2025-09-19 — 최종(1~3교시 통합)**

### 하루 TL;DR (5줄)

리눅스 CLI(Command-Line Interface) 환경의 기초를 다진 하루였습니다. `sudo`를 통한 권한 관리의 중요성으로 시작하여, 파일 시스템의 핵심 데이터 구조인 **아이노드(Inode)**와 **`rwx` 권한 체계**의 원리를 학습했습니다. **절대 경로**와 **상대 경로**의 개념을 이해하고 `cd`, `ls` 명령어로 시스템을 자유롭게 탐색했으며, `mkdir`, `rmdir` 실습을 통해 자신의 작업 공간과 권한의 한계를 직접 체감했습니다.

### 🔥 필수 질문 Top-5

1. 파일의 '신분증'이라 불리는 **아이노드(Inode)**에는 어떤 정보가 저장되며, 저장되지 **않는** 핵심 정보는 무엇인가요?
2. Ubuntu에서 `root` 계정으로 바로 로그인할 수 없는 이유는 무엇이며, 관리자 작업은 어떻게 수행해야 하나요?
3. `ls -l` 결과에 나오는 **`rwxr-xr-x`** 와 같은 권한은 어떻게 해석하며, 이를 **`755`** 같은 숫자로 변환하는 원리는 무엇인가요?
4. `cd /etc`와 `cd etc` 명령어는 어떻게 다르게 동작하며, 각각 어떤 종류의 경로 지정 방식에 해당하나요?
5. (면접 질문) "메모장에 입력한 글이 파일로 저장되기까지 컴퓨터 내부에서는 어떤 일이 일어나나요?"라는 질문의 핵심 답변 요소는 무엇인가요?

---

### 📚 핵심 개념 3개

- **아이노드 (Inode)**: 데이터블록주소+메타데이터(파일 이름을 제외한) 저장
	- 걍 파일은 3가지 구성임 1. 슈퍼블록(요약정보저장) 2. 아이노드 3. 데이터블록(실제데이터 저장)
	- 그래서 아이노드를 포인터 개념으로 기억
	- 디렉터리는 '아이노드 번호'와 아이노드가 저장안한 '파일명'를 매핑하는 테이블 역할을 하는 특수 파일입니다.
		- 그 매핑정보를 디렉토리 엔트리 또는 파일 엔트리라고 한다.
- **파일 권한 (Permissions)**: 아이노드에 기록된 `rwx` 설정으로, 특정 파일에 대해 소유자/그룹/기타 사용자의 읽기, 쓰기, 실행 가능 여부를 제어.
- **경로 (Path)**: 사용자가 파일에 접근하기 위해 사용하는 주소 체계로, 디렉터리 계층을 거쳐 특정 아이노드를 찾아가는 길잡이 역할.
- **`rmdir`의 제약**: `Remove Directory` 명령어는 **내용이 비어 있는 디렉터리만** 삭제할 수 있습니다.
- 상위 디렉터리인 `/home`이나 다른 시스템 디렉터리에서 `mkdir` 명령을 실행하면 'Permission denied' 오류가 발생하는데, 이는 해당 공간의 소유자가 `root`이기 때문입니다.
	- 일반 사용자는 자신의 홈 디렉터리(`~`) 내에서만 파일을 생성하거나 삭제할 수 있는 권한을 가집니다.
- Linux는 대소문자를 엄격하게 구분하므로 `file.txt`와 `File.txt`는 완전히 다른 파일로 취급

---

### 💻 주요 실습 요약

- **[S1] 아이노드 및 권한 확인 — `ls -il`로 파일의 본질 보기**
    - **단계요약**: `ls -il` 명령으로 파일명 앞의 고유 ID(아이노드 번호)와 `drwxr-xr-x` 형식의 파일 종류 및 권한 문자열을 직접 확인.
- **[S2] 절대/상대 경로 이동 — `cd`로 시스템 탐색하기**
    - **단계요약**: `cd /usr/bin` (절대)과 `cd ../..` (상대)를 이용해 파일 시스템을 탐색하고, 인자 없는 `cd` 명령으로 홈 디렉터리에 한 번에 복귀.
- **[S3] 디렉터리 생성 및 삭제 — `mkdir -p`와 `rmdir` 활용**
    - **단계요약**: `mkdir -p test/sub`로 하위 디렉터리를 한 번에 만들고, `rmdir`로 비어 있는 디렉터리를 삭제하며 명령어의 규칙과 옵션을 학습.
- **[S4] 권한 오류 체험 — 내 작업 공간의 경계 확인**
    - **단계요약**: `cd /` 등 권한 없는 위치에서 `mkdir`를 시도하여 'Permission denied' 오류를 통해 소유권과 허가권의 중요성을 확인.

## **2025-10-10 — 최종(1~3교시 통합)**

### 1. 하루 TL;DR (5줄)

오늘은 Linux 파일 시스템의 핵심인 **inode**를 기반으로 동작하는 **하드 링크**와 **심볼릭 링크**의 차이점을 학습했습니다. 이어서 터미널 환경의 필수 도구인 **`vi` 편집기**의 **모드(Mode) 기반** 동작 방식을 이해했습니다. **명령/입력 모드**를 오가며 파일을 생성하고, **`h,j,k,l`** 을 이용한 커서 이동과 **`dd`,`dw`** 등 강력한 편집 명령어를 실습했습니다. 링크는 파일 관리의 유연성을, `vi`는 키보드 중심의 빠른 편집 효율을 제공합니다. 결국 두 가지 모두 CLI 환경에서의 능숙한 시스템 관리를 위한 핵심 기술입니다.

---

### 2. 🔥 필수 질문 Top-5

- **[Q1] `vi`에서 `Ctrl+Z`는 Windows의 '실행 취소'와 어떻게 다릅니까?**
    - `vi`에서 `Ctrl+Z`는 작업을 취소하는 것이 아니라, 현재 `vi` 프로세스를 **일시 중단**하고 백그라운드로 보내는 시스템 기능입니다. 작업 취소(Undo)는 반드시 명령 모드에서 **`u`** 키를 사용해야 합니다.
- **[Q2] 하드 링크와 심볼릭 링크의 가장 근본적인 차이는 무엇입니까?**
    - **하드 링크**는 원본 파일과 **동일한 inode**를 공유하는 '또 다른 이름'으로, 사실상 같은 파일입니다. **심볼릭 링크**는 원본 파일의 **경로를 가리키는** '바로 가기'와 같은 별개의 파일이며, 고유한 inode를 가집니다.
- **[Q3] `vi`를 '모드(Mode)형 편집기'라고 부르는 이유는 무엇입니까?**
    - `vi`는 사용자의 키 입력이 현재 **'명령 모드'** 인지 **'입력 모드'** 인지에 따라 각각 명령 또는 텍스트로 다르게 해석되는, 상태 기반의 작업 방식을 가지고 있기 때문입니다.
- **[Q4] `vi`의 삭제 명령어 `x`, `dw`, `dd`의 차이점과 `3dd`의 의미는 무엇입니까?**
    - **`x`**는 글자 하나, **`dw`**는 단어 하나, **`dd`**는 한 줄 전체를 삭제합니다. **`3dd`**처럼 명령어 앞에 숫자를 붙이면 해당 명령을 3번 반복하라는 의미로, 3줄을 한 번에 삭제합니다.
- **[Q5] 하드 링크는 왜 디렉토리에 생성할 수 없으며, 다른 파티션을 넘어갈 수 없습니까?**
    - 디렉토리에 허용하면 파일 시스템의 순환 구조 문제가 발생할 수 있어 금지되며, inode 번호는 각 파티션 내에서만 고유하므로 다른 파티션의 inode를 가리킬 수 없기 때문입니다.

---

### 3. 📚 핵심 개념 3개

- **inode와 링크**: 파일의 실체(메타데이터, 데이터 위치)인 inode에 여러 개의 이름(하드 링크)을 붙이거나, 그 위치를 가리키는 포인터(심볼릭 링크)를 만드는 파일 관리 기법입니다.
    - **연결맵**: **inode (데이터 본체)** → **하드 링크 (이름 추가)** → **심볼릭 링크 (경로 참조)**
- **`vi` 모드 편집**: 키보드 입력의 역할을 '명령'과 '텍스트 입력'으로 분리, `Esc` 키를 통해 두 모드를 전환하며 마우스 없이 모든 편집을 수행하는 `vi`의 핵심 작동 원리입니다.
    - **연결맵**: **명령 모드 (기본 상태)** → **`i`/`a`/`o` (입력 모드 진입)** → **`Esc` (명령 모드 복귀)**
- **`vi` 명령어 문법**: `vi`의 강력한 편집 기능은 `[반복횟수][명령어][범위]`라는 일관된 문법 구조를 따르며, 이를 통해 간단한 키 조합으로 복잡한 작업을 수행할 수 있습니다.
    - **연결맵**: **반복횟수 (e.g., `3`)** → **명령어 (e.g., `d`)** → **범위 (e.g., `w`)** = `3dw` (단어 3개 삭제)

### 4. 💻 주요 실습 요약

- **[S1] 링크 생성 및 비교**: `ln`과 `ln -s`로 하드/심볼릭 링크를 만들고, `ls -il`로 inode 번호와 링크 카운트를 비교하여 두 링크의 차이점을 확인했습니다.
    - **단계요약**: 1) `cp /etc/hosts test1` 2) `ln test1 HD_test1` 3) `ln -s test1 SB_test1` 4) `ls -il`로 비교
- **[S2] `vi` 모드 전환 및 파일 생성**: `vi`를 실행하여 명령 모드와 입력 모드를 `i`, `Esc` 키로 전환하는 법을 익히고, `:wq`로 파일을 저장 및 종료했습니다.
    - **단계요약**: 1) `vi test.txt` 2) `i`로 텍스트 입력 3) `Esc`로 명령 모드 복귀 4) `:wq`로 저장 및 종료
- **[S3] `vi` 텍스트 편집 및 삭제**: `h,j,k,l`로 커서를 이동하고, `dw`(단어 삭제), `dd`(줄 삭제), `cw`(단어 변경), `u`(되돌리기) 등 명령 모드의 핵심 편집 기능을 활용했습니다.
    - **단계요약**: 1) `j,k,w,b`로 이동 2) `dw`로 단어 삭제 3) `dd`로 줄 삭제 4) `u`로 복원

## **2025.10.17 — 최종(1~3교시 통합)**

1. 하루 TL;DR (5줄)
    
    VIM의 핵심 편집 기능인 복사(yy), 잘라내기(dd), 붙여넣기(p/P)와 '버퍼(레지스터)' 개념을 학습했습니다. 또한 VIM 고유 기능인 비주얼 모드(v/V)와 명령행 범위 지정을 실습했습니다. 2교시에는 VI 환경 설정 3가지 방식(임시 :set, 사용자 .exrc, 시스템)을 비교하고, .exrc 파일을 직접 생성/삭제하여 영구 설정을 적용하는 방법을 익혔습니다. 이 과정에서 .bashrc 등과 같은 숨김 파일(dot files)의 개념(ls -a)을 확인했습니다.
    
2. 🔥 필수 질문 Top-5
    
    [Q1] VIM 환경 설정을 적용하는 세 가지 방식은? | 태그: 편집기(vi)
    
    · 답(강의+정석): (1) :set nu처럼 현재 세션에만 적용되는 임시 설정, (2) ~/.exrc (VIM은 ~/.vimrc 우선) 파일에 저장하여 사용자에게 영구 적용되는 설정, (3) /etc/vimrc나 EXINIT 환경 변수를 이용한 시스템 전체 설정이 있습니다.
    
    [Q2] yy와 dd의 핵심 차이는 무엇인가요? | 태그: 편집기(vi)
    
    · 답(강의+정석): 둘 다 내용을 버퍼(레지스터)에 저장하지만, yy(Yank)는 Ctrl+C처럼 복사만 하고, dd(Delete/Cut)는 Ctrl+X처럼 잘라내어 현재 행을 삭제합니다. 둘 다 p로 붙여넣기 가능합니다.
    
    [Q3] 복사(yy) 후 다른 작업(dd) 시 내용이 사라지는 이유는? | 태그: 편집기(vi), 버퍼
    
    · 답(강의+정석): 기본적으로 하나의 '언네임드 버퍼(레지스터 "")'를 공유하기 때문입니다. yy 내용이 저장된 버퍼를 dd 명령이 덮어쓰므로, 이전 내용은 사라집니다. (방지: "ayy 같은 네임드 버퍼 사용)
    
    [Q4] 홈 디렉터리에 .exrc 파일을 만드는 목적은? | 태그: 편집기(vi), 파일·디렉터리
    
    · 답(강의+정석): vi 실행 시 .exrc (또는 VIM의 .vimrc) 파일을 자동으로 읽어, set nu 같은 사용자 맞춤형 설정을 매번 입력할 필요 없이 영구적으로 적용하기 위함입니다.
    
    [Q5] 파일명이 점(.)으로 시작하는 (예: .exrc) 이유는? | 태그: 파일·디렉터리, 셸/리다이렉션/FD
    
    · 답(강의+정석): 리눅스/유닉스 셸이 '숨김 파일'로 취급하여, 일반 ls 명령에 노출되지 않게 하기 위함입니다. 이는 중요한 설정 파일들이 터미널을 어지럽히거나 실수로 삭제되는 것을 방지합니다. (ls -a로 확인)
    
3. **📚 핵심 개념 3개**
    
    - **VIM 환경 설정:** `:set` 명령(임시)이나 설정 파일(영구)을 이용해 `vi`의 동작(행 번호, 모드 표시 등)을 제어하는 것입니다.
    - **`.exrc` (설정 파일):** VIM 환경 설정을 _영구적으로_ 저장하는 사용자 홈 디렉터리의 _설정 파일_입니다. (VIM은 `.vimrc` 우선)
    - **숨김 파일 (Dot files):** `.exrc`처럼 이름이 점(`.`)으로 시작하는 파일로, `ls -a`로만 보이며 주로 시스템/환경 설정 용도로 사용됩니다.
    - **연결맵:** VIM 환경 설정 → `.exrc` (설정 파일) → 숨김 파일 (Dot files)
        
4. **💻 주요 실습 요약**

    - **[S2] 비주얼 모드 복사** — VIM의 `v` 키로 블록을 지정하여 복사 / **단계요약:** 1) `v` + 방향키 2) `y` (복사) 3) `p` (붙여넣기)
    - **[S3] VI 영구 설정 적용** — `~/.exrc` 파일을 생성하여 `vi` 자동 설정(행 번호 등) / **단계요약:** 1) `vi ~/.exrc` 2) `set nu` `set list` 입력/저장 3) 새 `vi` 실행 확인
    - **[S4] VI 영구 설정 해제** — `~/.exrc` 파일을 삭제하여 설정 초기화 / **단계요액:** 1) `rm ~/.exrc` 2) 새 `vi` 실행 확인

**터미널 제어**:
- 세션종료 `Ctrl+D` 또는 `exit`
- 화면지우기`clear`
- 줄삭제 `Ctrl+U`
- 단어삭제 `Ctrl+W`
- 단어자동완성: `tab`
- **Enter**: 한 줄씩 아래로 이동합니다.
- **Spacebar**: 한 페이지씩 아래로 이동합니다.
- `/문자열`: 특정 문자열을 검색합니다.
- q: 명령을 종료합니다.
- 명령줄 맨앞로 이동`Ctrl+A`
- 명령줄 맨뒤로 이동`Ctrl+E`

명령어 정리

inux 명령어는 `명령어 [옵션] [인자]` 구조를 가진다

- **`sudo` (Super User Do)**: 일반 사용자 `$` 가 허가된 관리자 (`#`) 명령을 자신의 암호로 실행할 수 있게 하는 프로그램
- `cd .`: 현재 디렉터리를 의미합니다. (위치 변화 없음) (실습)
* `cd ..`: 현재 위치의 상위(부모) 디렉터리로 이동합니다. (실습)
- `man 명령어`:그 명령어에대한 메뉴얼 man man 하면 man에대한 메뉴얼 나옴 `q` 키로 종료합니다.
- `pwd` : 현재 위치한 디렉토리의 절대경로 표시
- `ls`: 현재 디렉터리의 파일 및 디렉터리 목록을 보여줍니다.
	-  `-a`(전체), `-l`(상세), `-F`(종류 표시), `-R`(하위 포함)
		- `-a`는 숨김 파일(이름이 `.`으로 시작)을 포함하여 보여줍니다. (실습)
		- `-l` 상세정보(Long)
		- `-F` (classify): 파일 종류에 따라 이름 뒤에 기호(`/`: 디렉터리, `*`: 실행 파일, `@`: 심볼릭 링크)를 붙여줍니다.
		- `-R` (recursive): 현재 디렉터리뿐만 아니라 모든 하위 디렉터리의 내용까지 재귀적으로 보여줍니다
		- `-i`: 아이노드 번호
		- `ls -al`은 숨김 파일을 포함한 모든 파일의 상세 정보
	- 첫번째 자리: 이 파일 유형
		- 일반 데이터 파일(`-`), 디렉터리(`d`), 바로 가기(`l`), 하드웨어 장치(`b`, `c`) 로 표시 참고로 모든 것을 파일로 취급
	- 그뒤 3자리씩 소유자, 그룹, 이외 순으로 읽기, 쓰기, 실행 권한표시
- `ls 인자(상대/절대경로)`: 해당 인자의 디렉터리의 파일 및 디렉터리 목록을 보여줌
	- Ex) `ls -al tmp`
- `passwd` : 사용자 계정의 비밀번호를 변경
파일출력:
- 파일 전체 출력 `cat`
	- `-n` 행번호표시
	- `cat /etc/services | more`
		- 전체 출력을 한뒤 `more`가 받아서 페이지 단위로 보여줌
		- 파이프라인 `|`은 앞선 명령어의 실행 결과를 뒷 명령어의 입력으로 전달하는 역할
- 페이지 단위 출력
	- 이전페이지가는 명령어 지원안함 `more`
		- +n : 파일의 **n번째 줄부터** 출력
		- 출력후 **`/문자열`** : 문자열검색
		- 화살표로 줄이동가능하지만 이건 원래 제공되는 기능
			- **이미 출력된 내용**의 기록을 위아래로 훑어보는 기능
			- 파일의 **아직 읽히지 않은 부분**을 스크롤로 불러올 수는 없습니다.
	- 명령어로 파일의 내용을 직접읽어와 표시함 `less`
		- `+F` 실시간으로 갱신가능
		- **j** 또는 **아래 화살표**: 아래로 한 줄 이동합니다.
		- **k** 또는 **위 화살표**: 위로 한 줄 이동합니다.
		- **Ctrl+B**: 한 페이지 위로 이동합니다.
		- `/패턴` (다음 검색), `?패턴` (이전 검색)
- `head /etc/services`: 파일의 첫 10줄을 보여줍니다.
- `head -3 /etc/services`: `-` 다음에 숫자를 지정하여 원하는 줄 수만큼 볼 수 있습니다.
- `tail /etc/services`: 파일의 마지막 10줄을 보여줍니다.
