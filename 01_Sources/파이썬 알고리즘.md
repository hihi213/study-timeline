## 자바와 파이썬의 차이

### 1. 문법 및 코드 구조 (Syntax & Structure)

자바 컴파일러와 파이썬 인터프리터가 코드를 해석하는 방식의 근본적인 차이입니다.

| **비교 항목**                                | **자바 (Java)**                                                              | **파이썬 (Python)**                                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **블록 구분**<br><br>  <br><br>(Scope)       | **중괄호(`{}`)**<br><br>  <br><br>자바 컴파일러는 중괄호로 블록의 시작과 끝을 인식합니다. 공백은 무시됩니다.  | **들여쓰기(tab)**<br><br>  <br><br>파이썬 인터프리터는 들여쓰기(공백)를 문법으로 인식합니다. **개발자**는 블록 시작 시 콜론(`:`)을 사용하고 들여쓰기를 유지해야 합니다. |
| **문장 종료**<br><br>  <br><br>(Termination) | **세미콜론(`;`)**<br><br>  <br><br>자바 컴파일러는 세미콜론을 문장의 끝으로 인식합니다.               | **줄바꿈(enter)**<br><br>  <br><br>파이썬 인터프리터는 줄바꿈을 문장의 끝으로 인식합니다. 세미콜론은 생략합니다.                                    |
| **진입점**<br><br>  <br><br>(Entry Point)   | **Main 메서드**<br><br>  <br><br>자바 런타임은 `public static void main`을 찾아 실행합니다. | **스크립트 실행**<br><br>  <br><br>파이썬 인터프리터는 파일의 최상단부터 순차적으로 실행합니다.                                                 |

### 2. 변수 및 타입 시스템 (Type System)

- **타입 선언:**
    - **자바 (정적 타입):** **개발자**는 `int`, `String` 등 타입을 명시해야 하며, **컴파일러**가 사전에 오류를 검사합니다.
    - **파이썬 (동적 타입):** **개발자**는 타입을 명시하지 않고 값을 할당하고, **인터프리터**가 실행 시점에 타입을 추론합니다.
- **메모리 관리:**
    - **자바:** 원시 타입(Primitive Type)은 스택에 값을 직접 저장합니다.
    - **파이썬:** 모든 변수는 객체(Object)를 가리키는 참조(Reference)입니다. 정수나 실수도 객체로 취급됩니다.
        

### 3. 자료구조 (Data Structures for Coding Test)

코딩 테스트 시 **개발자**가 체감하는 구현 편의성의 차이입니다.

- **배열/리스트:**
    - **자바:** 배열(`[]`)과 `ArrayList`를 구분하여 사용합니다.
    - **파이썬:**  `list`라는 하나의 자료구조만 사용합니다. 이 `list`는 동적 배열이며, 서로 다른 타입의 데이터도 담을 수 있고 스택(Stack)으로도 바로 사용 가능합니다.
- **해시맵:**
    - **자바:** `HashMap<Key, Value>`를 선언하고 `put`, `get` 메서드를 사용해야 합니다.
    - **파이썬:** 딕셔너리(`dict`)를 사용하며, `key`를 인덱스처럼 사용하여 접근(`dict[key]`)합니다.
- **문자열:**
    - **자바:** 불변인 `String` 조작 시 `StringBuilder`가 필요할 수 있습니다.
    - **파이썬:** str도 불변이지만, 슬라이싱(`[start:end]`)을 통해 부분 문자열을 직관적으로 추출합니다.
        

### 4. 파이썬의 줄바꿈 상세 규칙 (Multiline Rules)

파이썬 인터프리터는 줄바꿈을 명령의 끝으로 인식하므로, **개발자**가 긴 코드를 여러 줄에 작성하려면 별도의 표기가 필요합니다.

1. **명시적 연결 (Explicit Line Joining):**
    
    - 줄의 끝에 역슬래시(`\`)를 작성하여 다음 줄이 연결됨을 알립니다.
    ```Python
    s = "Line 1" + \
        "Line 2"
    ```
    
2. **암시적 연결 (Implicit Line Joining) - 권장:**
    
    - 소괄호`()`, 중괄호`{}`, 대괄호`[]` 안에서는 인터프리터가 줄바꿈을 무시합니다.
    
    ```Python
    result = (value_one +
              value_two)
    ```

## 배열
### 자바의 배열 (Array)

- **메모리 접근 원리:**
    - **CPU**는 `시작 주소 + (인덱스 × 데이터 타입의 크기)`를 계산하여 데이터의 주소에 즉시 접근한다
    - 이러한 **메모리의 연속성**을 유지해야 하므로, 중간 요소 삭제 시 **런타임**은 뒤에 있는 모든 요소를 앞으로 당기는 시프트(Shift) 연산($O(N)$)을 수행해야 합니다.
- **정적 배열 (`int[]`):**
    - **개발자**가 선언한 초기 크기가 고정됩니다. 공간이 가득 차면 더 이상 데이터를 추가할 수 없습니다.
- **동적 배열 (`ArrayList`):**
    - 공간이 가득 차면, **런타임**이 더 큰 크기의 새로운 메모리 공간을 할당하고 기존 데이터를 모두 복사(Copy)하여 이동시킵니다.
	- `add(index, value)` 사용시 뒤 요소를 당기거나 미는 작업 자동처리
### 자바의 연결 리스트 (LinkedList)

- **구조적 특징:**
    - 데이터(노드)들이 메모리에 흩어져 있고 참조(주소)로 연결되어 있습니다.
- **삽입/삭제의 효율성:**
    - 물리적인 데이터 이동 없이 앞뒤 노드의 **참조 주소만 변경**하면 되므로 구조 변경 비용은 $O(1)$입니다.
    - 단, 삽입할 위치를 찾기 위해 **CPU**가 첫 노드부터 순차적으로 탐색해야 하므로 탐색 비용은 $O(N)$입니다. (탐색이 필요 없는 양 끝단 작업은 효율적입니다.)
        
### 파이썬의 리스트 (List)

- **구조:**
    - 자바의 `ArrayList`와 동일한 **동적 배열(Dynamic Array)** 구조입니다.
- **데이터 저장 방식 (참조의 배열):**
    - 실제 데이터(값)가 아닌 **객체의 주소(Reference)** 들이 연속적으로 저장된 배열입니다.
    - 모든 주소값(포인터)의 크기는 동일하므로(예: 64bit OS에서 8byte), `int`, `str`, `bool` 등 객체의 실제 크기나 타입과 관계없이 하나의 리스트에 인덱싱 가능한 형태로 저장될 수 있습니다.
#### list 선언
L = [27, 36, True, 44, 21, "hi", 82, 11]  
L2 = [27, 36, True, 44, 21, "hi", 82, 11]
#### 1. 요소 추가 (Adding Elements)

리스트의 크기를 늘리는 작업입니다. 공간이 부족할 경우 **파이썬 런타임**은 메모리 재할당을 수행합니다.

| **문법**           | **설명**                                           | **시간 복잡도**                               | **자바 대응 (ArrayList)** |
| ---------------- | ------------------------------------------------ | ---------------------------------------- | --------------------- |
| `L.append(x)`    | 리스트의 **맨 끝**에 요소 `x`를 추가합니다.                     | **$O(1)$**                               | `add(e)`              |
| `L.insert(i, x)` | 인덱스 `i` 위치에 요소 `x`를 삽입합니다. `i` 이후의 요소들은 뒤로 밀립니다. | **$O(N)$**                               | `add(i, e)`           |
| `L.extend(L2)`   | 리스트 끝에 다른 리스트나 튜플(`iter`)의 모든 요소를 붙입니다.          | **$O(K)$**<br><br>  <br><br>(K: 추가되는 길이) | `addAll(c)`           |

> **주의:** `insert(0, x)`는 모든 요소를 뒤로 밀어야 하므로 $O(N)$입니다. 빈번한 사용 시 `collections.deque`를 사용해야 합니다.

#### 2. 요소 삭제 (Removing Elements)

리스트의 요소를 제거하고, 필요시 뒤의 요소들을 앞으로 당기는(Shift) 작업입니다.

| **문법**        | **설명**                                        | **시간 복잡도** | **자바 대응**        |
| ------------- | --------------------------------------------- | ---------- | ---------------- |
| `L.pop()`     | 리스트의 **맨 마지막** 요소를 삭제하고 그 값을 반환(Return)합니다.   | **$O(1)$** | `remove(size-1)` |
| `L.pop(i)`    | 인덱스 `i`의 요소를 삭제하고 반환합니다. 뒤의 요소들이 당겨집니다.       | **$O(N)$** | `remove(i)`      |
| `L.remove(x)` | 리스트에서 **값이 `x`인 첫 번째 요소**를 찾아 삭제합니다. (반환값 없음) | **$O(N)$** | `remove(Object)` |
| `L.clear()`   | 리스트의 모든 요소를 삭제하여 빈 리스트로 만듭니다.                 | $O(1)$     | `clear()`        |

> **주의:** `del L[i]` 키워드를 사용해서도 삭제할 수 있으며, 동작과 시간 복잡도는 `pop(i)`와 동일합니다.

### 3. 탐색 및 정보 (Searching & Information)

리스트 내부의 데이터를 확인합니다. 파이썬은 `indexOf` 대신 `index`를 사용합니다.

| **문법**       | **설명**                                                    | **시간 복잡도** | **자바 대응**      |
| ------------ | --------------------------------------------------------- | ---------- | -------------- |
| `L.index(x)` | 값이 `x`인 첫 번째 요소의 **인덱스**를 반환합니다. 없으면 `ValueError`가 발생합니다. | **$O(N)$** | `indexOf(o)`   |
| `L.count(x)` | 리스트 내에 값이 `x`인 요소가 **몇 개** 있는지 반환합니다.                     | **$O(N)$** | (직접 구현/Stream) |
| `len(L)`     | (내장 함수) 리스트의 전체 길이(요소 개수)를 반환합니다.                         | **$O(1)$** | `size()`       |
| `x in L`     | (연산자) 리스트에 `x`가 존재하는지 확인합니다. (`True`/`False`)             | **$O(N)$** | `contains(o)`  |

### 4. 정렬 및 순서 변경 (Sorting & Reordering)

코딩 테스트에서 매우 중요한 정렬 기능입니다. **원본 변경 여부**를 주의해야 합니다.

| **문법**                 | **설명**                                        | **자바 대응**                |
| ---------------------- | --------------------------------------------- | ------------------------ |
| `L.sort()`             | 리스트 자체를 오름차순으로 정렬합니다. (**원본 변경**, 반환값 `None`) | `Collections.sort(L)`    |
| `L.sort(reverse=True)` | 리스트 자체를 내림차순으로 정렬합니다.                         | `Sort` with `Comparator` |
| `L.reverse()`          | 리스트의 순서를 뒤집습니다. (정렬 아님, **원본 변경**)            | `Collections.reverse(L)` |

**[중요] `sort()` vs `sorted()` 차이점**

- `L.sort()`: 리스트 **메서드**입니다. 원본 리스트 `L`을 직접 변경합니다. 반환값이 없습니다.
- `sorted(L)`: 파이썬 **내장 함수**입니다. 원본 `L`은 그대로 두고, 정렬된 **새로운 리스트**를 반환합니다.
    

### 5. 복사 (Copying)

파이썬 리스트 변수는 주소값을 담고 있으므로, 단순 대입(<code>=</code>)은 복사가 아닙니다.

| **메서드**  | **문법**     | **설명**                                       | **시간 복잡도** | **자바 대응**            |
| -------- | ---------- | -------------------------------------------- | ---------- | -------------------- |
| **copy** | `L.copy()` | 리스트의 얕은 복사본(Shallow Copy)을 생성하여 반환합니다.       | **$O(N)$** | `new ArrayList<>(L)` |
| **슬라이싱** | `L[:]`     | (문법) 리스트 전체 범위를 슬라이싱하면 `copy()`와 동일하게 동작합니다. | **$O(N)$** | -                    |



### 1. 기본 입출력 (Standard I/O)

- **`input()`**
    - 표준 입력(stdin)에서 사용자로부터 한 줄을 읽어 들입니다.
    - 입력받은 모든 데이터는 **문자열(string)** 타입으로 반환됩니다.
    - 알고리즘 문제 풀이 시, 숫자를 입력받아도 문자열이므로 반드시 `int()`나 `float()`를 사용한 형 변환(Type Casting)이 필요합니다.
    - 예: `n = int(input())`
- **`map(function, iterable)`**
    - 두 개의 인자를 받습니다: 적용할 함수(function), 순회 가능한 객체(iterable).
    - iterable의 모든 요소(element)에 대해 function을 개별적으로 적용합니다.
    - 반환값은 `map` 객체이며, 이는 '지연 평가(lazy evaluation)'를 수행합니다.
    - `list(map(…))`처럼 `list()`로 감싸야 실제 리스트 객체를 얻을 수 있습니다.
    - 알고리즘 용도 (예: `a, b = map(int, input().split())`)
        - 1. `input().split()`: `"3 5"`와 같은 입력을 `["3", "5"]` (문자열 리스트)로 분리합니다.
        - 2. `map(int, …)`: 리스트 `["3", "5"]`의 각 요소 `elem`에 `int(elem)`을 적용합니다.
        - 3. `a, b = …`: `map` 객체가 반환하는 `3`과 `5`를 각각 변수 `a`와 `b`에 할당(unpacking)합니다.
- **`sys.stdin.readline`**
    - `import sys`를 통해 `sys` 모듈을 가져와야 사용 가능합니다.
    - `input()`과 동일하게 한 줄을 읽지만, 내부적으로 버퍼(buffer)를 사용합니다.
    - `input()`은 한 줄마다 프롬프트(prompt)를 처리하는 오버헤드가 있으나, `readline`은 버퍼에서 직접 읽어옵니다.
    - 결과: 반복문 안에서 수만, 수십만 줄의 입력을 받아야 할 때 `input()` 대비 월등히 빠른 속도를 제공합니다.
    - **주의**: `readline()`은 줄 끝의 **줄바꿈 문자(`\n`)**를 포함하여 반환합니다. `data = sys.stdin.readline().strip()`과 같이 `strip()` 메서드를 호출하여 공백 및 줄바꿈 문자를 제거해야 합니다.
- **`print()`**
    - 표준 출력(stdout)으로 인자로 넘겨받은 값을 출력합니다.
    - 기본적으로 출력 후 자동으로 줄바꿈(`\n`)을 수행합니다.
    - 줄바꿈을 원하지 않을 경우 `end` 파라미터를 사용합니다. (예: `print(x, end=" ")`는 출력 후 공백을 삽입합니다.)
    - 여러 값을 콤마(`,`)로 구분해 넘기면 공백으로 구분되어 출력됩니다. (예: `print(a, b)`는 `a` (공백) `b` (줄바꿈) 순서로 출력됩니다.)

### 2. 핵심 자료 구조 (Core Data Structures)

- **List (리스트)**
    - 파이썬의 **동적 배열(Dynamic Array)**입니다.
    - 크기가 고정되지 않고, 요소를 추가(`append`)하거나 제거(`pop`)할 때 자동으로 메모리 공간이 조절됩니다.
    - **`append(x)`**: 리스트의 맨 마지막에 요소 `x`를 추가합니다. 시간 복잡도는 평균 O(1)입니다.
    - **`pop(i)`**: `i`번 인덱스의 요소를 리스트에서 제거하고 그 값을 반환합니다. `i`를 생략하면 마지막 요소를 제거합니다.
        - `pop()` (마지막 요소 제거): O(1)
        - `pop(0)` (첫 요소 제거): O(N) (모든 요소가 한 칸씩 이동해야 함)
    - **`sort()`**: 리스트 자체를 정렬합니다(In-place sort). 반환값이 `None`이므로 `new_list = my_list.sort()`와 같이 사용하면 안 됩니다.
    - **슬라이싱 (`my_list[start:end:step]`)**
        - 리스트의 특정 구간을 **복사**하여 새로운 리스트로 반환합니다.
        - `start` 인덱스(포함)부터 `end` 인덱스(미포함)까지 추출합니다.
        - `my_list[1:3]`은 `my_list`의 인덱스 1, 2에 해당하는 요소를 반환합니다.
- **Dictionary (dict, 딕셔너리)**
    - **해시 테이블(Hash Table)** 또는 해시 맵(Hash Map)으로 구현된 자료형입니다.
    - **키(Key)**와 **값(Value)**의 쌍으로 데이터를 저장합니다.
    - 키(Key)는 반드시 **해시 가능(hashable)**하고 **불변(immutable)**한 객체여야 합니다. (예: 정수, 문자열, 튜플)
    - **O(1) 시간 복잡도**: 키를 해시 함수로 변환하여 값에 직접 접근합니다.
        - 요소 탐색: `my_dict[key]`
        - 요소 삽입: `my_dict[key] = value`
        - 요소 삭제: `del my_dict[key]`
    - 위 연산들은 평균적으로 O(1)이며, (해시 충돌이 최악으로 발생하는 경우) 드물게 O(N)이 될 수 있습니다.
- **Set (세트)**
    - 수학의 '집합'과 동일한 특성을 가집니다.
    - **중복된 요소를 허용하지 않습니다.**
    - 순서가 보장되지 않습니다 (Python 3.7+부터는 삽입 순서가 유지되지만, 알고리즘에서는 순서 없는 자료형으로 간주해야 합니다).
    - `dict`와 동일하게 해시 테이블을 기반으로 합니다.
    - **주요 용도 1 (중복 제거)**: `my_list = [1, 1, 2, 3]` -> `my_set = set(my_list)` 실행 시 `my_set`은 `{1, 2, 3}`이 됩니다.
    - **주요 용도 2 (존재 여부 확인)**: `x in my_set` 연산이 리스트(O(N))와 달리 O(1)의 시간 복잡도를 가집니다.
        

---

### 3. 제어문 (Control Flow)

- **`if-elif-else`**
    - 조건식의 결과(True/False)에 따라 코드 블록의 실행 여부를 결정합니다.
    - `if`: 첫 번째 조건. 참이면 해당 블록 실행 후 전체 `if`문 종료.
    - `elif` (else if): `if`가 거짓일 때 검사하는 두 번째(혹은 N번째) 조건.
    - `else`: 위의 모든 `if`와 `elif` 조건이 거짓일 때 실행되는 블록.
- **`for`**
    - **순회(Iteration)**를 위한 구문입니다.
    - `for item in iterable:` 구조를 가집니다.
    - `iterable` (리스트, 문자열, 튜플, `range` 등)의 요소를 처음부터 끝까지 하나씩 `item` 변수에 대입하며 블록을 반복 실행합니다.
    - `range(n)`: 0부터 `n-1`까지의 정수 시퀀스를 생성합니다. (알고리즘에서 N회 반복 시 `for _ in range(N):` 사용)
- **`while`**
    - `while condition:` 구조를 가집니다.
    - `condition` (조건식)이 참(True)인 동안 `while` 하위의 코드 블록을 **계속 반복**합니다.
    - `condition`이 거짓이 되는 시점에 반복문이 종료됩니다.
    - 반복문 내부에서 `condition`을 변경하는 로직(예: `i += 1`)이 없으면 **무한 루프(Infinite loop)**가 발생할 수 있습니다.
        

---

### 4. 함수 (Functions)

- **`def`**
    - 'Define'의 약자. 새로운 함수를 **정의**할 때 사용하는 키워드입니다.
    - 함수는 특정 작업을 수행하는 코드 블록에 이름을 붙여 재사용할 수 있게 만듭니다.
    - 구조: `def function_name(parameter1, parameter2):`
- **`return`**
    - 함수의 실행을 **즉시 종료**하고, `return` 뒤의 값을 함수가 호출된 위치로 **반환**합니다.
    - 함수 내에서 `return` 문을 만나면 그 이후의 코드는 실행되지 않습니다.
    - `return`만 단독으로 쓰거나 함수가 `return` 없이 끝나면 `None` 객체가 반환됩니다.
- **재귀 함수 (Recursive Function)**
    - 함수 정의부(body) 안에서 **자기 자신을 다시 호출**하는 함수입니다.
    - 재귀 함수는 반드시 두 부분으로 구성되어야 합니다.
        - 1. **기저 조건 (Base Case)**: 재귀 호출을 멈추고 값을 반환하는 조건. (예: `if n == 0: return 1`)
        - 2. **재귀 단계 (Recursive Step)**: 문제를 더 작은 하위 문제로 분해하여 자기 자신을 호출하는 부분. (예: `return n * factorial(n-1)`)
    - 기저 조건이 없으면 '최대 재귀 깊이 초과(RecursionError)'가 발생합니다.
    - DFS(깊이 우선 탐색), DP(동적 계획법), 분할 정복(Merge Sort, Quick Sort) 등 많은 알고리즘이 재귀로 구현됩니다.
        

---

### 5. 유용한 문법

- **리스트 컴프리헨션 (List Comprehension)**
    - `for` 루프와 `if` 조건을 한 줄에 작성하여 리스트를 생성하는 간결한 문법입니다.
    - 일반적인 `for` 루프보다 가독성이 높고 실행 속도가 미세하게 빠릅니다.
    - **구조**: `[ (표현식) for (항목) in (반복가능객체) if (조건) ]`
    - **예**: `[i*i for i in range(10) if i % 2 == 0]`
        - 1. `for i in range(10)`: 0부터 9까지 순회합니다.
        - 2. `if i % 2 == 0`: `i`가 짝수인 경우만 통과시킵니다. (0, 2, 4, 6, 8)
        - 3. `i*i`: 통과된 `i`를 제곱합니다. (0, 4, 16, 36, 64)
        - 4. 최종 결과 리스트 `[0, 4, 16, 36, 64]`가 생성됩니다.
- **람다 표현식 (Lambda Expression)**
    - 이름이 없는 **익명 함수(Anonymous Function)**를 만드는 문법입니다.
    - `def`를 사용하기에는 너무 간단하거나, 한 번만 사용되고 버려지는 함수가 필요할 때 사용합니다.
    - **구조**: `lambda (인자): (표현식)`
    - 표현식의 결과가 자동으로 반환됩니다 (`return` 키워드 불필요).
    - **예**: `lambda x: x[1]`
        - `x`라는 인자 1개를 받아서 `x[1]`(x의 1번 인덱스 값)을 반환하는 함수입니다.
    - **주요 용도**: `sort`나 `sorted` 함수의 `key` 인자로 사용됩니다.
        - `students.sort(key=lambda x: x[1])`
        - 위 코드는 `students` 리스트의 각 요소 `x`를 `lambda` 함수에 전달하고, 반환된 `x[1]` 값을 기준으로 리스트를 정렬하라는 의미입니다.

## 맵과 딕셔너리 (Map & Dictionary)

Key(키)와 Value(값) 쌍으로 데이터를 관리하는 자료구조에 대한 상세 비교입니다.

### 1. 자바와 파이썬의 구현 비교

| **비교 항목**   | **자바 (Java)**                                 | **파이썬 (Python)**                                                |
| ----------- | --------------------------------------------- | --------------------------------------------------------------- |
| **자료형**     | **`HashMap<K, V>`** (인터페이스 `Map` 구현체)         | **`dict`** (내장 자료형)                                             |
| **선언**      | `Map<String, Integer> map = new HashMap<>();` | `my_dict = {}` 또는 `my_dict = dict()`                            |
| **삽입/수정**   | `map.put("key", 100);`                        | `my_dict["key"] = 100`                                          |
| **조회**      | `map.get("key");`                             | `my_dict["key"]` (없으면 Error)<br>`my_dict.get("key")` (없으면 None) |
| **키 존재 확인** | `map.containsKey("key")`                      | `"key" in my_dict`                                              |
| **삭제**      | `map.remove("key");`                          | `del my_dict["key"]`                                            |

### 2. Key-Value로 저장되는 자료구조의 종류 (All Types)

"Key와 Value로 저장되는 자료구조"는 내부 구현 방식과 순서 보장 여부에 따라 다음과 같이 나뉩니다.

#### A. 해시 기반 (Hash Based) - $O(1)$

키를 해시 함수를 통해 주소로 변환하여 저장합니다. 가장 범용적으로 사용됩니다.

- **Java:** `HashMap`, `LinkedHashMap` (입력 순서 보장), `Hashtable` (Thread-Safe, 구형)
- **Python:** `dict` (3.7+부터 입력 순서 보장), `collections.defaultdict`
    

#### B. 트리 기반 (Tree Based) - $O(\log N)$

데이터를 저장할 때 키를 기준으로 **정렬**합니다. 범위 검색이 필요할 때 유리합니다.

- **Java:** `TreeMap` (Red-Black Tree 사용, 키 오름차순 정렬)
- **Python:** 표준 내장 `dict`는 정렬되지 않음. (필요 시 `collections.OrderedDict`나 리스트로 변환하여 정렬 사용)
    

#### C. 멀티맵 (Multimap)

하나의 키에 여러 개의 값을 허용하는 구조입니다. (아래 3번 항목 참조)

### 3. Value를 List로 저장하기 (1:N 관계)

"Value를 List로 저장할 수 있나요?" -> 네, 가능하며 매우 빈번하게 사용되는 패턴입니다.

이를 통해 하나의 키에 여러 데이터를 그룹화할 수 있습니다.

#### 파이썬 (Python)

리스트를 Value로 갖는 딕셔너리를 직관적으로 구성할 수 있습니다.

```Python
# 1. 일반 dict 사용
graph = {}
key = "A"
if key not in graph:
    graph[key] = []  # 리스트 초기화
graph[key].append(1)
graph[key].append(2)
# 결과: {'A': [1, 2]}

# 2. defaultdict 사용 (코딩테스트 추천)
from collections import defaultdict
graph = defaultdict(list) # 키가 없으면 자동으로 빈 list 생성
graph["A"].append(1)
graph["A"].append(2)
```

#### 자바 (Java)

제네릭(Generic)을 사용하여 Value 타입을 `List`로 선언합니다.

```Java
// Map의 Value 자리에 List 인터페이스 지정
Map<String, List<Integer>> graph = new HashMap<>();

// 데이터 추가 로직
String key = "A";
// 1. 키가 없으면 빈 리스트 생성 후 넣기
if (!graph.containsKey(key)) {
    graph.put(key, new ArrayList<>());
}
// 2. 리스트를 가져와서 데이터 추가
graph.get(key).add(1);
graph.get(key).add(2);
```
