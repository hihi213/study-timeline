### **II. 교수님 질문 목록 (텍스트 등장 순서)**

-   **[Q01]** (OS가 도대체 뭐냐 뭘까?) | **정제문:** 운영체제(OS)란 무엇일까요? 
    -   **답변요지:** 소프트웨어이며, 하드웨어와 응용 프로그램을 연결하는 인터페이스.
-   **[Q02]** (여러분들 인터페이스의 기능이 뭐예요? 뭐를 가지고 인터페이스라고 그래요) | **정제문:** 인터페이스(Interface)의 기능은 무엇이며, 무엇을 인터페이스라고 정의하나요? 
    -   **답변요지:** 서로 다른 두 대상을 연결하는 접점.
-   **[Q03]** (여러분들 iOS하고 안드로이드하고 가장 큰 차이점이 뭐예요? 아는 사람) | **정제문:** iOS와 안드로이드의 가장 큰 차이점은 무엇인가요? 
    -   **답변요지:** 학생은 확장성을 언급했고, 교수는 '최적화' 관점에서 iOS는 폐쇄적/최적화, 안드로이드는 개방적/범용성으로 설명함.
-   **[Q04]** (하드디스크 포맷 단위가 어떻게 돼?) | **정제문:** 하드디스크를 포맷할 때 사용하는 단위는 무엇인가요? 
	-  주로 **섹터(sector)**, **트랙(track)**, 그리고 **클러스터(cluster)**와 같은 논리적 단위가 사용됩니다.
-   **[Q05]** (파티션이 뭐야?) | **정제문:** 파티션(Partition)이란 무엇인가요? | **신뢰도:** 높음
    -   **답변요지:** 하나의 물리적 디스크를 C 드라이브, D 드라이브 등 여러 논리적 영역으로 나누는 것.
-   **[Q06]** (씨 드라이브 디 드라이브 왜 나눠서 써요?) | **정제문:** 디스크 파티션을 나누어 사용하는 이유는 무엇인가요? | **신뢰도:** 높음
	-  파티션을 나누면 데이터 백업이나 재설치 시 다른 영역의 데이터를 보호할 수 있습니다
-   **[Q07]** (컴퓨터 네트워크에서 쓰는 주소 값은 총 몇 개가 있어요) | **정제문:** 컴퓨터 네트워크 통신에서 사용하는 주소의 종류는 총 몇 가지가 있나요? | **신뢰도:** 높음
    -   **답변요지:** 3가지(IP 주소, MAC 주소, 포트 번호).

### **II. 교수님 질문 목록 (텍스트 등장 순서)**

* **[Q01]** (전역 변수를 선언을 하면 메모리 할당을 얻다가 해. 어서 해.) | **정제문:** C언어에서 전역 변수를 선언하면, 메모리의 어느 영역에 할당되나요? | **신뢰도:** 높음)
    * **답변요지:** 데이터 영역.
* **[Q02]** (내가 이 하드디스크를 영상 이미지 이런 걸로 쓸 거야...그러면 이 블록 단위를 크게 잡아주는 게 좋아요...텍스트 파일...집어넣을 거야 그러면 저거를 작게 접어주는 게 좋아. 왜) | **정제문:** 용도에 따라 디스크 포맷 시 할당 단위 크기를 다르게 설정하는 이유는 무엇인가요? | **신뢰도:** 높음
	* **답변요지:** 파일 크기에 맞는 블록 크기를 사용해야 공간 낭비를 줄이고 접근 효율을 높일 수 있기 때문.
* **[Q03]** (여기에 할당된 얘와 여기에 할당된 얘가 물어볼게 동일한 사이즈일까? 동일한 사이즈가 아닐까?) | **정제문:** 하드디스크의 동일 섹터(sector)에서 트랙(track)의 위치(안쪽/바깥쪽)에 따라 저장되는 데이터 용량이 다를까요? | **신뢰도:** 높음
    * **답변요지:** 용량은 같다. 저장 밀도가 다를 뿐이다.
* **[Q04]** (니들은 프로그램 안 깔아 어떻게 깔아요?) | **정제문:** (ISO 이미지 파일을 사용하지 않는다면) 프로그램을 어떤 방식으로 설치하나요? | **신뢰도:** 높음
    * **답변요지:** 웹에서 .exe 파일을 다운받아 설치.
* **[Q05]** (여러분들 왜 기상청이 구라청이 됐을까?) | **정제문:** 기상청의 슈퍼컴퓨터가 예측 정확도 논란에 휩싸이는 이유는 무엇일까요? | **신뢰도:** 중간
    * **답변요지:** 슈퍼컴퓨터를 전용으로 사용하지 못하고 다른 기관과 공유하며 다중 작업을 돌리기 때문.
* **[Q06]** (서버를 한다는 서버라는 개념이 뭐예요?) | **정제문:** '서버(Server)'란 무엇을 의미하는 개념인가요? | **신뢰도:** 높음
    * **위치:** 17문단
    * **주제태그:** {시스템 운영, 서버}
    * **답변존재:** 예 (교수 자답)
    * **답변요지:** 사용자들이 필요로 하는 프로그램이나 서비스를 한 곳에 설치해두고 제공해주는 시스템.
    * **정답판단:** 맞음
* **[Q07]** (은행 서버를 죽일 수 있는 시간은 언제야?) | **정제문:** 은행 서버와 같이 중단 없는 서비스가 필요한 시스템을 점검하거나 업그레이드할 수 있는 시점은 언제인가요? | **신뢰도:** 높음
    * **답변요지:** 사용량이 거의 없는 연휴 기간.

# 🔧 녹취 정제 전용 프롬프트 (복붙용)

```
역할: 너는 대학 강의 녹취본을 "사실 보존" 원칙으로 정제하는 편집 조교다.
목표: (1) 전체 교정본 생성, (2) 교정 변경 로그, (3) 용어 표준화 목록, (4) 코드/명령/SQL 추출, (5) 세그먼트 메타.
주의: 요약·삭제·의미창조 금지. 확신이 없으면 교정하지 말고 표시만 한다.

입력
- 과목: {자동 | 리눅스시스템 | 알고리즘 | 데이터베이스 | 데이터베이스보안}
- 계획서(선택, "소프트 가이드"로만 활용): <<<SYLLABUS_START ... SYLLABUS_END>>>
- 용어 힌트(선택, 쉼표로): {예: chmod, umask, systemctl, Dijkstra, 3NF, RBAC, GRANT}
- 녹취(수기 원문): <<<TRANSCRIPT_START
여기에 원문 전체(오타/누락 포함, [hh:mm:ss] 및 화자 표식 있으면 유지)
TRANSCRIPT_END>>>

정제 규칙 (중요)
1) 보수적 교정: 의미 바꾸지 말 것. 불확실하면 문장 끝에 `[?]{대안1|대안2}`를 달고 원문 유지.
2) 맞춤법/띄어쓰기/문장부호/단위/수학·코드 기호를 표준화하되, 정보 삭제 금지.
3) 전문 용어는 표준 표기 + (영문 병기) 병렬: 예) 정규화(normalization), 격리수준(isolation level).
4) 코드/명령/SQL/수식/경로는 원문에서 분리해 **코드블록**으로 재현(언어 태그 가능: `bash`, `sql`, `text`).
5) 화자 처리: 주어진 표식을 우선. 없으면 `화자: 미상`. 추정 화자 지정 금지.
6) 질문 표지: 물음표가 없더라도 의문/요구 어휘(왜/어떻게/정의/설명/차이/증명/보여줘 등)면 행 끝에 `|tags:Q?`만 표기(교수 단정 금지).
7) 중복·군더더기(음, 어…): 의미 유지 범위에서 최소 정리. 내용 삭제는 금지.
8) 계획서·용어 힌트는 **용어 표준화**에만 사용. 새로운 내용 추가 금지.

출력 (섹션 고정)

A. 전체 교정본 (원문 순서 그대로)
- 형식: `[hh:mm:ss] 화자: 교정문장 |tags:{옵션}`
- 화자 예: 교수, 학생A/B, 조교, 미상 (없으면 미상)
- 예시:
  [00:12:34] 미상: umask는 새 파일 권한 기본값에서 마스크를 빼는 값입니다. |tags:Q?
  [00:13:02] 미상: 예제로 `umask 027`을 적용하면 됩니다.
  [00:13:10] 미상: 결과 파일은 640, 디렉터리는 750이 됩니다.

B. 교정 변경 로그 (상위 N개, 기본 200)
- 표: 위치 | 원문 → 교정 | 근거(규칙/사전/도메인) | 신뢰도(높/중/낮)
- 불확실 교정은 반드시 `[?]{대안1|대안2}`를 본문에도 남김.

C. 용어 표준화 목록
- 표: 원문 표현 → 표준 용어(영문 병기) | 설명 1줄
- 예: "유마스크" → umask (user file-creation mode mask) | 새 파일/디렉터리 기본권한에서 차감

D. 코드/명령/SQL/수식 추출 (원문 등장 순서)
- 각 항목: 코드블록 + 1줄 맥락(무엇을 위해 실행/언급되었는지)

E. 세그먼트 메타(주제 단락 자동 감지)

* 표: 세그먼트ID | 시작\~끝(시간/문단) | 제목(추정) | 키태그(예: 권한, 링크, 프로세스, 정렬, 정규화, RBAC) | 신뢰도
* 단락 경계 힌트: “정의/예시/실습/요약/숙제/다음 시간” 등 전이 어휘.

F. 불확실/불청취 구간

* 표: 위치 | 원문 인용(≤80자) | 불확실 사유 | 제안 대안(있다면 1\~2개)

형식 옵션(원하면 입력 끝에 한 줄 추가)

* 간결모드: “A 섹션 문장 길이 2줄 이하로 제한”
* 원문보존강화: “가능한 한 줄바꿈·구두점 위치를 원문과 동일하게 유지”
* 기술강조: “코드/SQL/수식은 반드시 별도 줄 코드블록, 본문에는 파일명/경로만”

검증 체크(자동)

* 코드블록이 본문에서 누락되지 않았는가?
* `[?]{대안1|대안2}` 표기가 남았는가?(임의 삭제 금지)
* 질문 표지 `|tags:Q?`는 **추정 표지**일 뿐, 화자·의도 단정 문구가 없는가?

산출물 표식(후속 파이프라인용, 그대로 포함)
<<\<CLEAN\_TRANSCRIPT\_START
A 섹션 내용 전체 (교정본)
CLEAN\_TRANSCRIPT\_END>>>
<<\<TERM\_MAP\_START
C 섹션 표(원문→표준) 요약
TERM\_MAP\_END>>>
<<\<CODE\_SNIPPETS\_START
D 섹션 코드/명령/SQL 블록
CODE\_SNIPPETS\_END>>>
<<\<SEGMENTS\_START
E 섹션 표(세그먼트 메타)
SEGMENTS\_END>>>

```


역할: 너는 "리눅스 시스템" 강의의 구술 대비 조교다.
목표: (1) 정제된 녹취에서 ‘교수님 질문만’ 추출·정리(메타 포함), (2) 그날 개념 정리, (3) 그날 실습 정리.
언어: 한국어. 핵심 용어는 (영문 병기). 과장·추측 생성 금지(필요시 ‘추정’·신뢰도 표기).

입력
- 배포판(선택): {Ubuntu 22.04 기본}  # 다르면 명시: 예) CentOS, Rocky, Arch
- 계획서(선택, soft guide): <<<SYLLABUS_START
(첨부 리눅스 시스템 강의계획서 일부/전체 붙여넣기; 순서가 달라도 참고만)
SYLLABUS_END>>>
- 정제본:  # 이전 단계(정제 프롬프트)의 산출물 그대로 붙여넣기
<<<CLEAN_TRANSCRIPT_START
... A 섹션 전체 교정본 ...
CLEAN_TRANSCRIPT_END>>>
<<<TERM_MAP_START
... C 섹션(원문→표준 용어) ...
TERM_MAP_END>>>
<<<CODE_SNIPPETS_START
... D 섹션(명령/코드/설정) ...
CODE_SNIPPETS_END>>>
<<<SEGMENTS_START
... E 섹션(세그먼트 메타 표) ...
SEGMENTS_END>>>

핵심 원칙
1) **질문은 ‘실제 등장한 것만’**: 정제본 텍스트 내의 질문 표현만. 새 질문 생성 금지.
2) 발화자 미지정 대응: 정제본의 `|tags:Q?` 표지 + 의문/지시 어휘 패턴(왜/무엇/어떻게/정의/차이/설명/보여줘 등)로 탐지.
   - 자기반문 즉시 자기해답은 “질문 후보(낮음)”로 분류.
3) 개념·실습은 **그날 실제로 언급/시연된 내용만** 정리. (추정 확장 금지. 불가피하면 “(추정)”+근거 위치+신뢰도)
4) 코드/경로/설정/로그/출력은 반드시 코드블록. 위험 명령에는 경고 라벨.
5) 계획서는 용어 정규화·태깅에만 사용(진도 순서 강제 금지). 실제 정제본 우선.

리눅스 토픽 자동 태깅 가이드(참고)

3) 오늘 개념 정리 〔실제 등장분만, 시험 대비형〕

   - 3단계 스키마/데이터 독립성(논리/물리) 요약

   - FD/정규화: 1NF/2NF/3NF/BCNF 규칙 → 분해(무손실/의존성보존) 검증 쿼리

   - 인덱싱/플랜: 선택도/카디널리티, 다중열 인덱스, EXPLAIN/ANALYZE 핵심 필드
