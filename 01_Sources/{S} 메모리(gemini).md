## 📖 소스 요약 (Summary)
- 이 정보원의 핵심 내용이나 주제를 한두 문장으로 요약합니다.

### I. [기초] 메모리 계층 구조 (하드웨어 관점)

컴퓨터 시스템 설계에서 메모리는 처리 속도와 저장 용량 간의 트레이드오프(Trade-off)를 해결하기 위해 계층적으로 구성됩니다.

#### 1. 메모리의 정의와 역할

- **정의:** 컴퓨터 시스템에서 데이터와 명령어를 일시적 또는 영구적으로 저장하는 전자 회로 장치입니다.
- **역할:** 폰 노이만 구조(Von Neumann Architecture)에 따라 CPU가 연산을 수행하기 위해 필요한 프로그램 코드와 데이터를 적재(Load)합니다.
    

#### 2. 기억장치 계층 구조 (Memory Hierarchy)

상위 계층일수록 속도가 빠르고 비트당 비용이 높으며 용량이 작습니다. 하위 계층은 그 반대의 특성을 가집니다.

- **레지스터 (Register):** CPU 코어 내부에 존재하는 최상위 메모리입니다. CPU 클럭 사이클과 동기화되어 가장 빠른 접근 속도를 제공합니다. (예: PC, IR, ACC 등)
- **캐시 메모리 (Cache):** CPU와 주기억장치 사이의 속도 차이를 완충하는 고속 SRAM(Static RAM)입니다.
    - **구조:** L1(코어 내장), L2, L3(공유) 등으로 구분됩니다.
    - **적중률 (Hit Rate):** CPU가 요청한 데이터가 캐시에 존재할 확률로, 시스템 성능의 핵심 지표입니다.
- **주기억장치 (Main Memory / RAM):** 실행 중인 프로세스와 데이터가 상주하는 공간입니다. 주로 DRAM(Dynamic RAM)이 사용되며 전원 공급 중단 시 데이터가 소실되는 휘발성(Volatile) 특징을 가집니다.
- **보조기억장치 (Secondary Storage):** HDD, SSD 등 대용량 데이터를 영구 저장하는 비휘발성 장치입니다.
    

#### 3. 지역성의 원리 (Locality)

캐시 메모리가 효율적으로 동작할 수 있는 근거가 되는 프로그램의 성질입니다.

- **시간적 지역성 (Temporal Locality):** 최근에 참조된 주소의 내용은 가까운 미래에 다시 참조될 가능성이 높습니다. (예: 반복문 내의 변수, 서브루틴)
- **공간적 지역성 (Spatial Locality):** 참조된 주소와 인접한 주소의 내용이 참조될 가능성이 높습니다. (예: 배열 순회, 순차적 명령어 실행)

### II. [중급] 메모리 관리와 가상화 (운영체제 관점)

운영체제(OS)는 물리적 하드웨어의 한계를 추상화하여 각 프로세스에 독립적이고 연속적인 메모리 공간을 제공하는 것처럼 보이게 합니다.

#### 1. 주소 바인딩 (Address Binding)

프로그램이 사용하는 주소와 실제 메모리 위치를 연결하는 과정입니다.

- **논리 주소 (Logical/Virtual Address):** CPU가 생성하고 프로세스가 바라보는 가상의 주소 공간입니다. 0번지부터 시작합니다.
- **물리 주소 (Physical Address):** 실제 메모리 하드웨어 상의 고유한 주소 위치입니다.
    

#### 2. 메모리 관리 장치 (MMU: Memory Management Unit)

CPU 코어와 메모리 사이에 위치하여 논리 주소를 물리 주소로 변환(Translation)하는 하드웨어 모듈입니다.

- **동작:** CPU가 논리 주소를 요청하면 MMU가 기준 레지스터(Base Register) 값을 더해 물리 주소로 변환합니다.
- **TLB (Translation Lookaside Buffer):** 주소 변환 속도를 높이기 위해 페이지 테이블의 일부를 저장하는 전용 고속 캐시입니다.
    

#### 3. 가상 메모리 (Virtual Memory)

물리 메모리(RAM)의 크기보다 큰 프로세스를 실행할 수 있게 하는 기술입니다.

- **페이징 (Paging):**
    - 논리 주소 공간을 고정 크기의 **페이지(Page)**로, 물리 주소 공간을 동일 크기의 **프레임(Frame)**으로 분할합니다.
    - 외부 단편화(External Fragmentation)는 해결되나 내부 단편화(Internal Fragmentation)가 발생할 수 있습니다.
- **세그멘테이션 (Segmentation):**
    - 논리적 의미 단위(함수, 배열, 스택 등)인 **세그먼트(Segment)**로 메모리를 분할합니다. 크기가 가변적입니다.
        

#### 4. 페이지 교체 알고리즘 (Page Replacement)

물리 메모리가 가득 찼을 때, 새로운 페이지를 적재하기 위해 기존 페이지를 디스크(Swap Area)로 내보내는 정책입니다.

- **스와핑 (Swapping):** 프로세스 또는 페이지 단위로 메모리와 디스크 간에 데이터를 이동시키는 행위입니다. (Swap In / Swap Out)
- **페이지 폴트 (Page Fault):** CPU가 참조하려는 페이지가 현재 물리 메모리에 없을 때 발생하는 인터럽트입니다.
- **주요 알고리즘:**
    - **FIFO:** 가장 먼저 들어온 페이지를 교체.
    - **LRU (Least Recently Used):** 가장 오랫동안 참조되지 않은 페이지를 교체.
    - **LFU (Least Frequently Used):** 참조 횟수가 가장 적은 페이지를 교체.

### III. [응용] 프로세스 메모리 구조 (프로그램 관점)

운영체제로부터 메모리를 할당받아 실행되는 프로그램(프로세스)의 내부 메모리 배치입니다.

#### 1. 메모리 레이아웃 (Memory Layout)

일반적인 프로세스 주소 공간은 다음과 같이 4개의 영역으로 구분됩니다.

- **코드 (Code/Text) 영역:**
    - 실행할 기계어 명령(Machine Code)이 저장됩니다.
    - 프로그램 실행 중 수정되지 않도록 **Read-Only**로 설정됩니다.
- **데이터 (Data) 영역:**
    - 전역 변수(Global Variable)와 정적 변수(Static Variable)가 저장됩니다.
    - 프로그램 시작 시 할당되고 종료 시 해제됩니다.
    - 초기화된 데이터 영역(.data)과 초기화되지 않은 데이터 영역(.bss)으로 세분화됩니다.
- **힙 (Heap) 영역:**
    - 프로그래머가 필요에 의해 동적으로 할당하고 해제하는 공간입니다.
    - 낮은 주소에서 높은 주소 방향으로 자라납니다. (런타임 크기 결정)
- **스택 (Stack) 영역:**
    - 함수 호출 시 지역 변수(Local Variable), 매개변수(Parameter), 리턴 주소 등이 저장됩니다.
    - 높은 주소에서 낮은 주소 방향으로 자라납니다. (컴파일 타임 크기 예측 가능하나 런타임에 생성)
        

#### 2. 정적 할당 vs 동적 할당

- **정적 할당:** 컴파일 타임에 크기가 결정되는 변수들로, 데이터 영역과 스택 영역(프레임 크기)이 이에 해당합니다.
- **동적 할당:** 런타임에 필요에 따라 크기가 결정되는 메모리로, 힙 영역이 이에 해당합니다.
### IV. [심화] 스택과 힙의 동작 원리

프로그래밍 시 데이터의 생명 주기와 접근 방식을 결정짓는 핵심 영역인 스택과 힙의 세부 메커니즘입니다.

#### 1. 스택 (Stack) 상세

함수의 호출과 복귀(Return) 흐름을 제어하고 지역 데이터의 생명 주기를 관리하는 영역입니다.

- **스택 프레임 (Stack Frame):** 함수가 호출될 때마다 스택 영역에 `push` 되는 데이터 블록입니다. 일반적으로 다음과 같은 정보를 포함합니다.
    - **복귀 주소 (Return Address):** 함수 종료 후 실행할 명령어의 주소.
    - **매개변수 (Parameters):** 함수에 전달된 인자 값.
    - **지역 변수 (Local Variables):** 함수 내부에서 선언된 변수.
- **동작 방식:**
    - **LIFO (Last-In First-Out):** 가장 나중에 저장된 데이터가 가장 먼저 제거되는 구조입니다.
    - **자동 관리:** 함수가 리턴되면 해당 스택 프레임은 스택 포인터(SP)의 이동만으로 논리적으로 제거(pop)됩니다. 별도의 해제 명령이 필요 없습니다.
- **스택 오버플로 (Stack Overflow):**
    - 할당된 스택 영역의 한계를 초과하여 데이터를 `push` 하려고 할 때 발생하는 오류입니다.
    - 주로 재귀 함수(Recursive Function)의 탈출 조건이 없거나, 지역 변수로 너무 큰 배열을 선언할 때 발생합니다.
        

#### 2. 힙 (Heap) 상세

프로세스 실행 중 크기가 결정되거나 변경될 수 있는 데이터를 위해 사용자가 직접 관리하는 영역입니다.

- **동적 메모리 할당:**
    - C/C++: `malloc()` / `free()`, `new` / `delete` 연산자를 사용하여 명시적으로 요청하고 반납합니다.
    - 할당 속도가 스택에 비해 상대적으로 느리며, 메모리 포인터를 통해 접근해야 합니다.
- **메모리 단편화 (Fragmentation):** 할당과 해제가 반복되면서 메모리 공간이 효율적으로 사용되지 못하는 현상입니다.
    - **내부 단편화 (Internal Fragmentation):** 요청한 크기보다 조금 더 큰 블록이 할당되어, 블록 내부에서 낭비되는 공간이 발생하는 현상입니다.
    - **외부 단편화 (External Fragmentation):** 남은 총메모리 공간은 충분하지만, 연속된 공간이 부족하여 큰 데이터를 할당하지 못하는 현상입니다.
- **가비지 컬렉션 (Garbage Collection):**
    - Java, Python, Go 등 현대 언어 런타임이 제공하는 기능입니다.
    - 더 이상 참조되지 않는(Unreachable) 힙 객체를 탐지하여 자동으로 메모리를 회수합니다.

### V. [문제해결] 메모리 관련 문제와 최적화

시스템 안정성과 성능을 확보하기 위해 개발자가 반드시 인지하고 있어야 할 메모리 관련 이슈들입니다.

#### 1. 메모리 누수 (Memory Leak)

- **정의:** 동적으로 할당된 힙 메모리가 더 이상 사용되지 않음에도 불구하고 해제(Free)되지 않아 시스템 메모리를 점유하고 있는 상태입니다.
- **영향:** 장시간 실행되는 데몬이나 서버 프로세스에서 누수가 지속되면, 가용 메모리 고갈(OOM: Out of Memory)로 인해 프로세스가 강제 종료될 수 있습니다.
    

#### 2. 버퍼 오버플로 (Buffer Overflow)

- **정의:** 프로그램이 할당된 메모리 버퍼(주로 배열)의 경계를 넘어서 데이터를 쓰려고 할 때 발생하는 버그 또는 보안 취약점입니다.
- **위험성:** 인접한 메모리 공간의 데이터(예: 리턴 주소)를 덮어쓰게 되면 프로그램의 제어 흐름이 조작되어, 악성 코드 실행 등의 보안 사고로 이어질 수 있습니다.
    

#### 3. 스레싱 (Thrashing)

- **정의:** 프로세스의 원활한 실행을 위해 필요한 최소한의 프레임조차 확보되지 않아, CPU가 실제 연산보다 페이지 교체(I/O) 작업에 대부분의 시간을 소모하는 현상입니다.
- **원인:** 다중 프로그래밍 정도(Degree of Multiprogramming)가 지나치게 높아져 각 프로세스에 할당되는 물리 메모리가 부족할 때 발생합니다.
- **해결:** 워킹 셋(Working Set) 모델 등을 이용하여 프로세스가 자주 참조하는 페이지 집합을 메모리에 유지시켜야 합니다.
    

#### 4. 동시성 문제 (Concurrency Issues)

- **상황:** 멀티스레드 환경에서 여러 스레드가 힙 영역이나 데이터 영역의 동일한 변수에 동시에 접근하여 쓰기 작업을 수행할 때 발생합니다.
- **경쟁 상태 (Race Condition):** 접근 순서에 따라 실행 결과가 달라지는 예측 불가능한 상태입니다.
- **해결:** 뮤텍스(Mutex), 세마포어(Semaphore) 등의 동기화 메커니즘을 사용하여 임계 구역(Critical Section)에 대한 접근을 제어해야 합니다.
    

### I. [전제 지식] 메모리 공간의 이해

재귀 호출의 동작 원리를 파악하기 위해서는 스택 영역의 하드웨어적 특성을 먼저 이해해야 합니다.

- **스택(Stack) 영역의 역할:** 프로그램 실행 중 함수 호출과 관련된 문맥(Context) 정보를 저장하기 위해 예약된 메모리 공간입니다.
- **LIFO (Last-In, First-Out) 구조:** 가장 나중에 저장된 데이터가 가장 먼저 제거되는 자료구조입니다. 이는 함수의 호출 순서(A $\rightarrow$ B $\rightarrow$ C)와 반환 순서(C $\rightarrow$ B $\rightarrow$ A)가 정확히 역순인 이유입니다.
- **스택 포인터 (Stack Pointer, SP):** CPU 레지스터의 일종으로, 현재 스택의 최상단(Top) 메모리 주소를 가리킵니다. 데이터가 추가(`push`)되면 주소값이 감소하고, 제거(`pop`)되면 주소값이 증가합니다. (일반적인 x86 아키텍처 기준, 스택은 높은 주소에서 낮은 주소로 자라납니다.)
    

### II. [단위] 스택 프레임 (Stack Frame)의 구조

재귀 함수가 호출될 때마다 메모리에는 새로운 스택 프레임이 생성됩니다.

- **정의:** 단일 함수 호출을 처리하기 위해 스택 영역에 할당되는 연속적인 메모리 블록입니다.
- **구성 요소:**
    
    1. **매개변수 (Parameters):** 호출자(Caller)로부터 전달받은 인자입니다.
    2. **복귀 주소 (Return Address):** 해당 함수의 실행이 끝난 후 CPU가 다음 명령어를 실행할 메모리 주소(PC 값)입니다.
    3. **이전 프레임 포인터 (Saved Frame Pointer/Base Pointer):** 이전 스택 프레임의 기준 주소를 저장하여, 함수 종료 후 스택을 복원하는 데 사용합니다.
    4. **지역 변수 (Local Variables):** 함수 내부 블록에서 선언된 변수들이 저장됩니다.
        

### III. [전개] 재귀 호출의 진행 (Winding)

재귀 호출이 중첩될수록 스택 메모리는 다음과 같이 변화합니다.

- **프레임의 적층 (Stack Buildup):**
    - 재귀 함수 `func()`가 자신을 다시 호출할 때마다 새로운 스택 프레임이 생성되어 `push` 됩니다.
    - 스택 포인터(SP)는 메모리의 낮은 주소 방향으로 이동하며 공간을 확장합니다.
- **독립성 보장:**
    - 모든 재귀 호출은 동일한 소스 코드를 사용하지만, 메모리 상에서는 서로 다른 스택 프레임을 점유합니다.
    - $n$번째 호출의 지역 변수 `x`와 $n+1$번째 호출의 지역 변수 `x`는 서로 다른 물리 주소에 위치합니다.
- **컨텍스트 저장 (Context Save):**
    - 새로운 호출이 발생하면, 현재 실행 중이던 함수의 상태(변수 값 등)는 해당 프레임에 보존된 채로 실행 제어권이 새로운 함수 인스턴스로 넘어갑니다.
        

### IV. [반환] 기저 조건과 스택의 해제 (Unwinding)

재귀의 깊이가 한계에 도달하여 다시 돌아오는 과정입니다.

- **기저 조건 (Base Case):** 더 이상 자기 자신을 호출하지 않고 값을 반환하거나 종료하는 조건입니다. 이 조건이 충족되어야 스택 확장이 멈춥니다.
- **프레임의 소멸 (Pop):**
    - 함수가 값을 반환(return)하면, 현재 스택 프레임이 스택에서 `pop` 되어 논리적으로 삭제됩니다.
    - 스택 포인터(SP)는 이전 프레임 포인터 값을 참조하여 이전 위치로 복귀합니다.
- **제어권 반환:**
    - 복귀 주소(Return Address)에 저장된 값을 프로그램 카운터(PC)에 로드하여, 호출했던 직전 단계의 코드로 실행 흐름을 되돌립니다.
        

### V. [한계] 재귀 호출의 위험성

무분별한 재귀 사용은 시스템 리소스에 치명적인 영향을 줄 수 있습니다.

- **스택 오버플로 (Stack Overflow):**
    - 기저 조건이 없거나 재귀 깊이(Recursion Depth)가 너무 깊어, 프로세스에 할당된 스택 영역(일반적으로 수 MB 단위)을 초과하여 쓰기를 시도할 때 발생하는 예외입니다. (Segmentation Fault 유발)
- **오버헤드 (Overhead):**
    - 단순 반복문(Loop)은 분기 명령(Jump)만 수행하지만, 재귀 호출은 매 호출마다 **[프레임 생성 $\rightarrow$ 레지스터 대피 $\rightarrow$ 복귀 주소 저장]** 등의 추가 연산 비용이 발생합니다.
        

### VI. [최적화] 꼬리 재귀 (Tail Recursion)

일부 컴파일러와 언어 환경에서 지원하는 최적화 기법입니다.

> [!note]- 일반 재귀 vs 꼬리 재귀 코드 비교
>
> **1. 일반 재귀 (Factorial)**
>
> C
>
> ```Java
> int factorial(int n) {
>     if (n == 1) return 1;
>     // 반환 후 n과의 곱셈 연산이 남아있음 -> 스택 유지 필요
>     return n * factorial(n - 1);
> }
> ```
>
> **2. 꼬리 재귀 (Factorial)**
>
> C
>
> ```Java
> int factorial_tail(int n, int acc) {
>     if (n == 1) return acc;
>     // 반환값이 재귀 호출 그 자체임 (추가 연산 없음) -> 스택 재사용 가능
>     return factorial_tail(n - 1, n * acc);
> }
> ```

- **꼬리 호출 (Tail Call):** 함수의 리턴 구문이 재귀 호출 그 자체이며, 돌아와서 수행할 추가 연산이 없는 형태입니다.
- **꼬리 호출 최적화 (TCO):**
    - 컴파일러가 꼬리 재귀를 감지하면, 새로운 스택 프레임을 생성(`call` 명령어)하지 않고 현재 프레임의 값만 갱신한 뒤 시작 지점으로 이동(`jump` 명령어)하도록 코드를 변환합니다.
    - 결과적으로 반복문과 동일한 메모리 공간($O(1)$)만을 사용합니다.
