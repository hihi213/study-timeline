# Day 0 — 환경 · ADR · 관측 베이스 (6–8h)

**Infra & 설정**

* [ ] `docker compose up` 원클릭 로컬 실행 (`make dev`)
* [ ] 환경 분리: `application-{local,dev,prod}.yml` 또는 `.env.*`
* [ ] 서버/DB 타임존 정책: **저장 UTC / 표시 KST** 문서화 및 적용

**관측가능성**

* [ ] `/healthz`(liveness), `/readyz`(readiness: 필수 env·마이그 버전 체크)
* [ ] 구조화 로깅(필수 필드: `traceId, userId, endpoint, latency_ms, outcome`)
* [ ] 요청 컨텍스트에 `correlation_id` 주입(없으면 생성)

**문서/계약(ADR & OpenAPI)**

* [ ] `API.yaml` 골격(로그인/아이템/검사/벌점)
* [ ] 공통 에러 스키마(RFC7807 또는 커스텀) + 에러 카탈로그
* [ ] **ADR-001 Token-Lifecycle**: Access/Refresh, `kid`/JWKS, 회전·무효화(토큰버전)
* [ ] **ADR-002 Roles\&Zones**: RBAC, `zones[]`(층/권한 범위) 클레임 정책
* [ ] **ADR-003 Label/Uniqueness**: 라벨/번호/유일성 범위(칸 내 번호 등)
* [ ] **ADR-004 Resource-Model**: `resources` 추상화, 서브타입 전략
* [ ] **ADR-005 Allocation-Semantics**: `allocations`(RESERVATION/USAGE/LOAN) 겹침/만료
* [ ] **ADR-006 Scheduler\&Outbox**: `outbox`/`due_tasks` at-least-once·멱등키

**DB**

* [ ] `V000__baseline.sql` 생성(확장 설치, 마이그 버전 테이블, 빈 스키마)

**Gate/DoD**

* [ ] `compose up` 후 서버 기동 + Swagger/Redoc 열람 가능
* [ ] 스모크 3콜 OK: `POST /auth/login` · `GET /healthz` · `GET /me`

# Week 2 — 핵심 스키마 1차 + 아이템 등록/조회(MVP) (6–9h)

**DB(공통 토대)**

* [ ] `resources(resource_id, type{FRIDGE_COMP,WASHER,DRYER,STUDYROOM,BOOK}, label, floor_id, room_id, status)`
* [ ] (선택) 타입별 서브테이블: `resource_fridge_comp(...)`, `resource_washer(...)` 등
* [ ] `item_bundles(bundle_id, resource_id(FK), owner_user_id, item_no, expires_on, deleted_at ...)`
* [ ] **부분 유니크**: `(resource_id, item_no) WHERE deleted_at IS NULL`
* [ ] 조회 인덱스: `expires_on`, `owner_user_id`, `resource_id`

**API**

* [ ] `POST /items`(등록) · `GET /items`(mine/floor/resource/q)
* [ ] D-Day(색상) **클라이언트 계산 규칙** 문서화

**테스트/계약**

* [ ] 번호 중복 409, 삭제 후 재사용 OK 시나리오

**Gate/DoD**

* [ ] 인덱스/제약 실제 생성 확인
* [ ] OpenAPI 예시/상태코드 반영 + 스냅샷 녹색
