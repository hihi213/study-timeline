# Week 1 — 정책·흐름 정밀 설계 & 가드 깔기 (v1.1 포스트-MVP)

**A. 상태 전이/정책 설계**

* [ ] 6종 ENUM 전이 표 작성: `AVAILABLE/IN_USE/DONE/OUT_OF_SERVICE/UNAUTHORIZED_USE/ERROR_REPORTED`

  * [ ] 허용/금지 전이 매트릭스(사유 포함) 작성
  * [ ] 전이 실패 코드 매핑 정의(400/401/403/409/423/422)
* [ ] `UNAUTHORIZED_USE` 타임아웃 정책 초안(예상 종료 기준 자동 복귀 규칙)
* [ ] `ERROR_REPORTED → OUT_OF_SERVICE` 운영 플로우(사용자 신고 → 관리자 트리아지) 정의
* [ ] 알림/카피 초안 확정(국문): 미등록 사용 경고, 고장 신고 접수/차단 안내

**B. 피처 플래그 도입(코드/설정)**

* [ ] `laundry.flags.enableUnauthorizedUse=false` 기본값(Local/Dev/Prod 프로필)
* [ ] `laundry.flags.enableErrorReport=false` 기본값(Local/Dev/Prod 프로필)
* [ ] `FeatureFlags` 컴포넌트/빈 생성(환경변수·yml 바인딩)
* [ ] Actuator `/env` 또는 커스텀 `/ops/flags` 읽기 전용 엔드포인트(선택)

**C. 가드 레이어(3+1만 허용)**

* [ ] 컨트롤러 가드: 플래그 OFF 시 `UNAUTHORIZED_USE/ERROR_REPORTED` 관련 요청 **차단**
* [ ] 서비스 가드: 상태 전이 중앙 유효성(허용 전이만 승인, 나머지 409)
* [ ] 전역 예외 매핑 보강: 전이 위반/플래그 비활성/권한 불일치 메시지

**D. 권한/인가 명세 고도화**

* [ ] 액터별 권한 표 업데이트: `USER / INSPECTOR / ADMIN`
* [ ] 존 인가 재점검: 남성(2층)↔여성(3/4/5층) ↔ 담요건조기(공용) 규칙 문서화
* [ ] 스프링 메서드 보안 스텁: 신규 API에 `@PreAuthorize` 시그니처만 배선

**E. 스키마/코드 합치기 작업**

* [ ] ENUM 6종이 이미 선언되었는지 확인(또는 TEXT+CHECK) 및 리팩터링 주석 추가
* [ ] 상태 전이 헬퍼/도메인 이벤트 타입에 신규 상태 값만 반영(로직은 비활성)

**F. 문서/스키마 참조(리비전)**

* [ ] `README-ops.md`에 전이 표·권한 표·플래그 사용 가이드 추가
* [ ] Swagger/OpenAPI 설명에 “플래그 비활성 시 409/404 반환” 노트 추가

**G. 테스트 스텁(플래그 OFF 기준)**

* [ ] 컨트롤러 테스트: `UNAUTHORIZED_USE/ERROR_REPORTED` 요청 시 404/409/423 중 정책대로 반환
* [ ] 서비스 테스트: 허용 전이(3+1) 통과, 금지 전이 차단
* [ ] 보안 테스트: 잘못된 존 사용자 접근 시 403

**H. 운영 준비(라이트)**

* [ ] 프로필별 플래그 오버라이드 방법 문서화(ENV → yml 우선순위)
* [ ] 로깅 키워드 합의: `policy.guard`, `flag.disabled`, `transition.violation`

# Week 2 — 상태머신 엔진·동시성 가드 & 아웃박스 연계 (v1.1 포스트-MVP)

**A. 상태머신 엔진 구현(6종 선언, 로직은 3+1만 허용)**

* [ ] `StateMachine`/`TransitionGuard` 모듈화: 단일 서비스에서 전이 검증·적용 일원화
* [ ] 전이 규칙 소스 단일화(`TransitionRuleSpec`): Week1 전이표를 코드로 반영
* [ ] 전이 시 공통 훅: `preCheck → apply → persist → publishEvent` 파이프라인 구성
* [ ] 허용 전이(현재 단계): `AVAILABLE⇄IN_USE`, `IN_USE→DONE`, `*→OUT_OF_SERVICE`만 통과, 나머지 409
* [ ] `laundry_status_history`에 `from_status/to_status/actor/reason` 기록(필수 필드 검증)

**B. DB/Flyway 마이그레이션(V-next)**

* [ ] `laundry_status_history` 보강: `reason`, `correlation_id`, `origin`(API/CRON/ADMIN) 컬럼 추가
* [ ] `idempotency_keys` 테이블 신설: `key`, `actor`, `resource_type/id`, `request_hash`, `expires_at`, UNIQUE 제약
* [ ] 핵심 인덱스: `(device_id, created_at DESC)`, `(status)`, `idempotency_keys(key)`
* [ ] CHECK 제약: 잘못된 `to_status`로의 전이 방지(ENUM/TEXT+CHECK 중 프로젝트 표준에 맞춤)

**C. 아이템포턴시 & 동시성 가드**

* [ ] API 헤더 `Idempotency-Key` 수용(`POST /start`, `POST /finish`)
* [ ] 동일 키 재요청 시 200/409 정책 정의 및 구현(최초 결과 재사용)
* [ ] 장치 단위 락 전략 확정: JPA 버전필드(낙관락) 또는 `SELECT … FOR UPDATE`(비관락) 중 택1
* [ ] “동시 `start` 2건”/“`finish` 중복” 경합 테스트 케이스 추가

**D. 도메인 이벤트 → 알림 아웃박스 연계(스캐폴드 정리)**

* [ ] 이벤트 표준화: `LaundryCycleStarted/Finished`, `DeviceStatusChanged`(payload 스키마 확정)
* [ ] `notifications` 아웃박스 write 경로 통합(READY 기록까지, 실제 발송 로직은 기존 워커 재사용)
* [ ] 리트라이 메타 기본값: `max_attempts`, `backoff_sec` 컬럼 반영(기본 정책 문서화)
* [ ] FINISH 5분 전·완료 이벤트만 대상(추가 상태는 플래그 ON 이후 연결)

**E. 운영/관리 API(라이트)**

* [ ] `PATCH /api/laundry/devices/{id}/out-of-service`(사유 필수)
* [ ] `PATCH /api/laundry/devices/{id}/available`(복구)
* [ ] 관리자 전용 권한 가드 + 감사 로그 기록(누가/언제/왜)

**F. 관측/로깅·메트릭**

* [ ] 구조화 로그 키: `transition.apply`, `lock.contention`, `idempotency.hit/miss`
* [ ] 메트릭: 전이 카운터(`laundry_transitions_total{from,to}`), 경합 실패, 아이템포턴시 적중률
* [ ] Actuator 노출(필요 시 커스텀 `@Timed` 추가)

**G. Swagger/OpenAPI 업데이트**

* [ ] `Idempotency-Key` 헤더 명세 및 예시 추가
* [ ] 전이 실패(409/423/422) 응답 스키마·메시지 예시 정리
* [ ] 관리자 `out-of-service/available` 엔드포인트 문서화

**H. 테스트(통합/단위)**

* [ ] 허용 전이 Happy path 4건(AVAILABLE→IN\_USE→DONE, ANY→OUT\_OF\_SERVICE)
* [ ] 금지 전이 5건 이상(예: AVAILABLE→DONE, DONE→IN\_USE 등) → 409 검증
* [ ] 동시 시작 2요청 경합 테스트(한 건만 성공)
* [ ] `Idempotency-Key` 동일 재요청 시 결과 재사용 확인
* [ ] 상태이력/이벤트/아웃박스 기록 일관성 검증(트랜잭션 내 원자성)

# Week 3 — 타이머 스케줄러 & 자동 전환/알림 트리거 (v1.1 포스트-MVP)

**A. 스케줄러/타이머(멱등 잡)**

* [ ] Spring `@Scheduled` 기본 설정(시간대, 고정 delay/cron 프로퍼티화)
* [ ] **DONE→AVAILABLE(+5분)** 자동 전환 잡 구현(멱등: 한 사이클 다중 처리 금지)
* [ ] 남은시간 계산 표준화: `end_at` 기준으로 `remaining_sec` 유틸 제공
* [ ] **T-5분 사전 알림** 대상 선별 쿼리(`end_at BETWEEN now()+4m AND now()+6m`)
* [ ] 잡 실행 가드: 동시 실행 방지(락/leader-only), 실행 로그/소요시간 기록

**B. 알림 트리거 ↔ 아웃박스 연결**

* [ ] 전이 훅에서 이벤트 발행: `LaundryCycleDueSoon`, `LaundryCycleFinished`
* [ ] 이벤트→`notifications(READY)` 적재(페이로드 `{title, body, deeplink}` 규격 준수)
* [ ] 중복 방지: 동일 사이클/유형 기준 **UNIQUE 키**로 중복 READY 차단
* [ ] 실패 재시도 파라미터(기본 3회, 지수 백오프) 설정값으로 외부화
* [ ] 발송 워커가 READY→SENT/FAILED 갱신되는지 E2E 확인

**C. 도메인 API 확장**

* [ ] `GET /api/laundry/devices?zone=` 응답에 `remainingSec`, `cycleId?` 포함
* [ ] `GET /api/laundry/cycles/mine?limit=10`(최근 사용 내역)
* [ ] `GET /api/laundry/devices/{id}/history?limit=50`(상태 이력 스냅샷)
* [ ] `GET /api/laundry/overview?zone=`(가용/사용중/완료 카운터 집계)
* [ ] 공통 DTO/에러코드 정리(422 전이불가, 409 충돌, 423 잠김)

**D. 인가/존 정책 적용(실사용)**

* [ ] 남성층(2F) → **MEN\_LAUNDRY**, 여성층(3/4/5F) → **WOMEN\_LAUNDRY** 매핑 적용
* [ ] 담요건조기 → **BLANKET\_SHARED** 전층 허용(추가 제약 없음)
* [ ] 관리자/운영 API는 RBAC `ADMIN`으로 제한 + 요청자/사유 감사로그

**E. 예외 상태 경로(스캐폴드만)**

* [ ] 상태 ENUM 6종 그대로 유지: `AVAILABLE, IN_USE, DONE, UNAUTHORIZED_USE, ERROR_REPORTED, OUT_OF_SERVICE`
* [ ] **허용 전이 3+1** 외 전이는 **항상 409/422**로 차단(플래그로 향후 개방)
* [ ] `POST /api/laundry/devices/{id}/report-error`(스캐폴드, 실제 전이는 `ADMIN` 확인 시 적용)

**F. 관측/메트릭**

* [ ] 스케줄 잡 메트릭: 실행 횟수/에러/소요시간 히스토그램
* [ ] 알림 파이프라인 메트릭: READY 큐 길이, 성공/실패율, 재시도 카운터
* [ ] 전이 카운터: `laundry_transitions_total{from,to,origin}`
* [ ] 구조화 로그 필드 통일: `cycleId`, `deviceId`, `zone`, `correlationId`

**G. Swagger/OpenAPI 갱신**

* [ ] 확장된 조회 API 3종 스펙/예시 응답 추가
* [ ] 전이 실패/권한 오류 응답 사례 문서화
* [ ] 알림 딥링크 예시 경로 표기(`/laundry/cycles/{id}`)

**H. 테스트(단위/통합/E2E)**

* [ ] **자동 전환**: DONE 유지 5분 경과 후 AVAILABLE로 1회만 전환(가짜 시계로 검증)
* [ ] **T-5 알림**: 경계값(4:59/5:00/5:01) 대상 선별 정확도
* [ ] **중복 방지**: 동일 사이클 알림 READY 2회 생성 시도 → 1건만 생성
* [ ] **API 정확성**: `remainingSec` 계산과 이력/집계 응답 필드 검증
* [ ] **인가**: 남/녀 존 오남용 접근 테스트(403), BLANKET\_SHARED 접근 허용 확인

* [ ] SSE 실패 시 자동 폴링 **폴백**(토스트 1회 알림)

* [ ] `remainingSec` 를 1초 틱으로 감소(음수 방지), 0 도달 시 상태 재조회
* [ ] 진행바/카운트다운 포맷(분:초, 1시간 이상은 시:분)
* [ ] 정렬: `IN_USE` 우선(남은시간 오름차순) → `AVAILABLE` → `DONE`

**E. 권한/존 가드(프론트)**

* [ ] 2F 남 → MEN 전용, 3/4/5F 여 → WOMEN 전용 노출
* [ ] **BLANKET\_SHARED** 전원 노출(읽기/사용 허용)
