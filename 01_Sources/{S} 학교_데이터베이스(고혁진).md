## 📖 소스 요약 (Summary)

## **2025-09-05 — 최종(1~2교시 통합)**

1) **하루 TL;DR (5줄)**
오늘은 데이터베이스 설계의 기초 철학인 **과학적 모델링**부터 시작했습니다. 현실의 문제를 **개념적(ERD) → 논리적(관계 모델) → 물리적(DBMS)** 단계로 추상화하는 설계 프로세스가 핵심입니다. 데이터 구조를 정의하는 **스키마**와 실제 값인 **인스턴스**를 구분했으며, DBMS가 **데이터 독립성, 무결성, 병행 제어**를 보장하는 원리를 배웠습니다. 최종 목표는 이 모든 이론을 바탕으로 `MySQL`을 설치하고 자신만의 데이터베이스를 구축하는 것입니다.

---

2) **🔥 필수 질문 Top-5**
* **[Q1] 데이터베이스 설계의 3단계(개념적, 논리적, 물리적)는 각각 무엇을 의미하며, 주요 산출물은 무엇인가요?**
* **[Q2] 스키마(Schema)와 인스턴스(Instance)는 어떻게 다른가요?**
* **[Q3] 트랜잭션(Transaction)이란 무엇이며, 핵심 속성인 '원자성(Atomicity)'은 어떤 의미인가요?**
* **[Q4] '관계형' 데이터베이스에서 '관계(relation)'와 '관계(relationship)'는 어떻게 다른가요?**
* **[Q5] 병행(Concurrency)과 병렬(Parallelism)의 차이점은 무엇인가요?**

---

3) **📚 핵심 개념 3개**
* **과학적 모델링 (Scientific Modeling)**: 현실 문제를 추상화하여 개념적, 논리적 모델로 변환하는 체계적 접근법.
* **3-스키마 구조 (3-Schema Architecture)**: 데이터 독립성을 위해 외부(사용자)-개념(논리)-내부(물리) 스키마로 계층을 나눈 데이터베이스 구조.
* **트랜잭션 (Transaction)**: 데이터의 일관성과 신뢰성을 보장하는 논리적 작업 단위 (ACID 속성 준수).

**[연결맵]**
`과학적 모델링 (방법론)` → `3-스키마 구조 (설계 결과)` → `트랜잭션 (안정적 실행 단위)`

4) **💻 주요 실습 요약**

    * **단계요약**: 1) **문제 정의**: 주변에서 데이터로 관리할 주제 선정. 2) **DBMS 설치**: `MySQL`을 개인 PC에 설치. 3) **구축**: `SQL`을 이용해 스키마를 생성하고 실제 데이터를 입력.

## **2025-09-12 — 최종(1~2교시 통합)**

1) **하루 TL;DR (5줄)**
오늘은 데이터베이스 **개념적 설계**의 핵심인 **ER 모델링**을 집중적으로 다루었습니다. 현실 세계의 요구사항을 **엔티티(객체), 속성(정보), 관계(연관)**로 식별하고, 관계의 정확성을 정의하는 **카디널리티** 해석법을 연습했습니다. 모델의 규칙을 강제하는 **무결성 제약조건**(엔티티, 도메인 등)의 중요성을 배웠고, 최종적으로 완성된 ERD가 어떻게 테이블 구조로 변환되는지(**ER 사상**) 미리 살펴보았습니다.

---

2) **🔥 필수 질문 Top-5**
* **[Q1] ERD를 관계형 모델(테이블)로 변환하는 핵심 규칙은 무엇인가요? (`1:N`과 `N:M` 관계를 중심으로)**
* **[Q2] 관계의 제약조건인 카디널리티(Cardinality)와 참여 제약조건은 무엇이며, 왜 중요한가요?**
* **[Q3] ER 모델의 3요소(엔티티, 속성, 관계)를 설명하고, 이것이 개념적 설계에서 어떻게 사용되나요?**
* **[Q4] 약한 엔티티(Weak Entity)란 무엇이며, 소유주 엔티티와 어떤 관계를 갖나요?**
* **[Q5] 데이터베이스의 주요 무결성 제약조건은 무엇이며, 특히 엔티티 무결성이 기본 키의 `NULL`을 허용하지 않는 이유는 무엇인가요?**

---

3) **📚 핵심 개념 3개**
* **ER 모델 (Entity-Relationship Model)**: 현실 세계를 엔티티, 속성, 관계로 표현하여 데이터 구조를 시각화하는 개념적 설계 도구.
* **무결성 제약조건 (Integrity Constraints)**: 데이터의 정확성을 보장하는 규칙으로, 키(엔티티 무결성), 카디널리티, 참여 제약 등이 포함됨.
* **관계형 사상 (Relational Mapping)**: 완성된 ERD를 데이터베이스의 테이블 스키마로 변환하는 일련의 규칙.

**[연결맵]**
`ER 모델 (개념적 설계 도구)` → `무결성 제약조건 (모델링 규칙 적용)` → `관계형 사상 (논리적 모델로 변환)`

---

4) **💻 주요 실습 요약**
* 해당 일자 강의에서는 별도로 언급된 실습 과제가 없습니다.

## **2025-09-19 — 최종(1~3교시 통합)**

1. 하루 TL;DR (5줄)

    ER 모델을 관계형 데이터베이스의 테이블 스키마로 변환하는 '사상(mapping)' 규칙을 학습했습니다. 관계의 카디널리티(1:N, M:N)에 따라 테이블을 합치거나(내장 방식) 새로 만드는(교차 테이블) 전략을 적용했습니다. 관계형 모델의 키(Key)는 유일성과 최소성을 만족해야 하며, 슈퍼키-후보 키-기본 키의 명확한 계층을 가집니다. 기본 키(PK)는 개체 무결성, 외래 키(FK)는 참조 무결성이라는 핵심 제약 조건을 통해 데이터 일관성을 보장합니다. 이 모든 설계 규칙의 근간에는 비싼 연산인 조인(JOIN)을 최소화하려는 성능 최적화 목표가 있습니다.

2. **🔥 필수 질문 Top-5**
    
    - **Q1**: M:N(다대다) 관계는 왜 반드시 새로운 '교차 테이블'로 만들어야 하나요?
    - **Q2**: 슈퍼키, 후보 키, 기본 키, 대체 키의 관계를 계층 구조로 설명해주세요.
    - **Q3**: 1:N 관계에서 외래 키의 방향이 '1' 쪽에서 'N' 쪽으로 고정되는 이유는 무엇인가요?
    - **Q4**: 기본 키(PK)와 외래 키(FK)가 만족해야 할 핵심 무결성 제약 조건은 무엇인가요?
    - **Q5**: ER 모델링 단계에서 외래 키(FK)를 사용하면 안 되는 근본적인 이유는 무엇인가요?
        
3. **📚 핵심 개념 3개**
    
    - ER-관계형 사상(Mapping): ERD의 구성요소를 관계형 모델의 테이블, 키, 제약조건으로 변환하는 체계적 절차.

        연결맵: ER-관계형 사상(Mapping) → 키 계층(Key Hierarchy) → 무결성 제약(Integrity Constraint)

    - **키 계층(Key Hierarchy)**: 데이터 식별 규칙의 집합. 유일성만 만족하는 **슈퍼키**부터 유일성과 최소성을 모두 만족하는 **후보 키(기본키/대체키)**까지의 계층.
    - **무결성 제약(Integrity Constraint)**: 데이터의 정확성과 일관성을 보장하는 규칙. **개체 무결성(PK)**과 **참조 무결성(FK)**이 핵심.
        
4. **💻 주요 실습 요약**
    
    - **[S1] ER-관계형 모델 사상 규칙 적용**: ERD의 카디널리티 규칙에 따라 관계형 스키마로 변환 / **단계요약**: 1) 1:N 관계는 'N'쪽에 FK와 속성을 내장(embed). 2) M:N 관계는 양쪽 PK를 포함하는 새 교차 테이블 생성.
    - **[S2] 데이터 기반 후보 키 식별**: 키가 없는 테이블 데이터로부터 유일성과 최소성 원칙을 적용해 모든 후보 키를 역으로 찾아냄 / **단계요약**: 1) FK 의심 컬럼 제외. 2) 단일/복합 속성 조합으로 유일성+최소성 만족 조합 탐색. 3) PK/AK 선정.

끝.
