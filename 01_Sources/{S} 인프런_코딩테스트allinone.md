## 1. 코테
### 1. 제약조건으로 문제 분석 (Analysis)

- **제약조건 & 복잡도 역산**
    - 입력 크기($N$)를 보고 **허용 가능한 최대 시간복잡도** 가이드라인 설정 ($O(N)$, $O(N \log N)$ 등).
- **엣지 케이스(Edge Case) 예측**
    - 최소값(빈 배열, $N=1$, 0)과 최대값 상황을 미리 체크.
    - "답이 없으면 -1 출력" 같은 예외 조건 확인.
- **자료형 체크 (Java)**
    - 결과값이나 중간 합계가 21억(`int`)을 넘을 가능성이 1%라도 있다면 무조건 **`long`** 선언.
### 2. 시뮬레이션 & 최적화 (Simulation & Optimization)
- 복잡한 문제 유형을 단순화해서 뭐가 안되는지 찾기
	- `(){}[]`가 섞여있다 -> `()`만 있을때만 고려해서 모든 케이스 찾아 예외 찾기
		- 짝수이여야하는구나
		- 여는게 먼저와야하는구나
- **무식하게 풀기 (Brute Force Simulation)**
    - input예시를 가장 직관적인(최악의) 로직으로 머릿속 시뮬레이션.
    - 이때의 시간복잡도를 계산하고 시간 초과 여부 판단.
- **병목 구간 발견 및 해결 (Upgrade)**
    - "어디서 시간이 오래 걸리는가?" (반복문 탐색 등)를 식별.
    - **자료구조 교체:** "List 탐색($O(N)$)을 Map($O(1)$)이나 Heap($O(\log N)$)으로 바꾸자" $\rightarrow$ **최종 알고리즘 확정.**
### 3. 설계 (Blueprint)

- 확정된 최적화 로직을 바탕으로 코드에 **한글 주석** 작성.
    - `// 1. 입력 및 Map 전처리 -> 2. 조건에 따른 탐색 -> 3. 정답 출력` 순으로 뼈대 완성.
    - (이후 주석 사이사이에 실제 코드를 채워 넣음)
        
## 2. LIST (선형 자료구조)의 분류 및 비교

데이터를 **'메모리에 어떻게 저장하는가'**에 따라 크게 두 가지로 나뉩니다.
### 🏛️ 1) 배열 기반 (Array-based)

- **특징:** 메모리에 **연속적**으로 할당됨.
- **종류:**
    - **Static Array (정적 배열):** 선언 시 크기 고정.
    - **Dynamic Array (동적 배열):** 크기가 자동으로 조절됨.
### 🔗 2) 노드 기반 (Node-based)

- **특징:** 메모리에 **비연속적** 으로 흩어져 할당됨.
- **종류:**
    - **Linked List (연결 리스트):** Node(데이터+주소)들이 연결된 형태.

### 메모리 구조 및 성능 비교

| **특징**     | **배열 (Array)**               | **연결 리스트 (Linked List)**                |
| ---------- | ---------------------------- | --------------------------------------- |
| **저장 방식**  | 메모리에 **연속적**으로 할당            | 메모리에 **불연속적**으로 흩어져 할당                  |
| **접근 속도**  | 인덱스로 즉시 접근 <br>Cache Hit율 높음 | 주소를 타고 이동해야 함 <br>Cache Hit율 낮음         |
| **메모리 효율** | 데이터 크기만큼만 사용                 | 주소 저장을 위한 추가 공간 필요<br>(**Overhead 발생**) |


## 3. 상세 분석: 배열 기반 (Array-Based)

### ① Array (정적 배열)

**"선언 시 크기가 고정되는(변경 불가) 리스트"**

- **메모리 구조:** `데이터 타입 크기` $\times$ `배열 크기`만큼의 메모리를 한 번에 **연속적**으로 할당합니다.
- **접근 속도 (Random Access):**
    - 배열의 이름 = **시작 주소 (Base Address)**
    - 물리적으로 연속되어 있어 수식 한 번으로 즉시 접근 가능
    - **공식:** $\text{Target Address} = \text{Base Address} + (\text{Index} \times \text{Data Size})$
- **예시:** C언어 `int arr[10]`, Java `int[]`
    

### ② Dynamic Array (동적 배열)

**"Array의 장점에 유연함(Doubling)을 더한 리스트"**

- **정의:** Array를 기반으로 하되, **자동 크기 조절(Resizing)** 기능을 탑재
- **동작 원리 (Doubling):**
    
    1. 데이터가 가득 차면, 기존 크기의 **2배(또는 1.5배)**인 새 배열을 생성합니다.
    2. 기존 데이터를 새 배열로 **모두 복사($O(N)$)**합니다.
    3. 기존 배열을 메모리에서 해제합니다.
        
- **시간 복잡도:**
    - **접근 (Access):** $O(1)$ 인덱스로 즉시 접근
    - **추가 (Append):** 평균 $O(1)$ (Resizing 발생 시 최악 $O(N)$)
    - **삽입/삭제 (Insert/Delete):** $O(N)$ (중간 데이터를 밀거나 당겨야 함)
- **예시:** **Python `list`**, Java `ArrayList`, C++ `std::vector`

## 4. 상세 분석: 노드 기반 (Node-Based)

### ① Node (노드) 구조와 메모리

**"연결 리스트를 구성하는 기본 단위 그릇"**

- **구성:** `Data(실제 값)` + `Next Pointer(다음 노드의 주소)`
- **메모리 오버헤드 (Overhead):**
    - 배열과 달리 **주소값**을 별도로 저장해야 하므로 메모리를 더 많이 차지합니다.
    - **64bit 시스템 예시:**
        - `Data (4 Byte)` + `Pointer (8 Byte)` = **12 Byte**
        - 실제로는 패딩(Padding)으로 인해 **16 Byte**까지 차지할 수 있습니다.
            

### ② Linked List (연결 리스트) 특징

- **연결성:** 데이터가 메모리 곳곳에 흩어져 있지만, 포인터를 통해 논리적으로 연결됩니다.
- **접근 방식:** 첫 노드(Head)부터 주소를 따라가며 하나씩 확인해야 하므로 탐색 속도가 느립니다($O(N)$).


## 해시테이블
>무엇을 의미하는지도 저장하고 싶을때

- 해시 테이블은 key와 value를 한쌍으로 묶어서 저장하는 map의 구현이다.
- Key는 인덱스계산 해시충돌시 검증을 위해 저장한다.
- key에 값, value에 의미없는 값을 저장해 인덱스 접근만 사용하기도한다
	- Map은 Key와 Value를 모두 유의미하게 저장하지만, Set은 데이터를 Key 자리에 두고 Value 자리에는 더미(Dummy) 값을 채워, 일일히 값을 찾는게 아니라 해시 테이블의 인덱스를 사용하는 형태이다.(인덱스로 바로 검색)
#### **1. 데이터 저장 위치(Index) 결정 방식**

값(Value)을 저장할 인덱스를 키(Key)로부터 결정하는 방식에 따라 나뉩니다.

- **직접 주소 테이블 (Direct Address Table)**
    - **방식:** `Key` 자체가 곧 `Index`가 됩니다. (예: `3, "노정호"` $\rightarrow$ 배열의 3번 인덱스에 저장)
    - **한계:**
        - 키가 반드시 **정수**여야 합니다. 문자열 불가
        - 키 값이 연속적이지 않고 듬성듬성하다면, 사용하지 않는 공간이 많아 **메모리 낭비**가 심합니다.
- **해시 테이블 (Hash Table)**
    - **방식:** `Key`에 해시 함수를 적용한 결과를 `Index`로 사용합니다.
    - **장점:** 키가 문자열이어도 가능하며, 직접 주소 테이블의 메모리 낭비 문제를 해결합니다.
    - 이때 해싱은(함수 계산 자체)이 **$O(1)$** 이어야, 데이터가 늘어나도 전체 검색 성능 $O(1)$을 보장할 수 있음
    - key를 처음부터 끝까지 뒤지지 않는 인덱스 기반 접근
#### **2. 해시 충돌 (Hash Collision)**

- **정의:** 서로 다른 $Key$의 해싱결과(인덱스)가 동일한 경우
- 이를 해결하는 방식에 따라 언어별 구현이 달라집니다.

#### 해시테이블 구현
- 배열(array)로만 구현: 파이썬의 딕셔너리(dict)
	- 해시충돌이 나면 개방주소법: 규칙(의사 난수 탐색 등)에 따라 **다른 빈칸**을 찾아 저장.
	- 데이터가 꽉 차면 Resizing 비용 발생.
- 배열(array)+연결리스트(linkedlist)로 구현: 자바
	- 해시충돌이 나면 분리연결법: 해당 슬롯의 **리스트(또는 트리) 끝에 추가**.
	- 버킷 내 데이터 개수에 따라 자료구조를 동적으로 변경하여 성능과 메모리 효율을 확보한다.
		- 8개 이상: 검색속도 확보하자-> 트리로 변환
		- 6개 이하: 메모리 낭비 줄이자-> 연결리스트로 복귀
		- 빈번한 변경을 막기위해 8과 6으로 차이를 둠

## 큐와 스택(이건 분리하기.)
### 스택 (Stack)

**후입선출(LIFO: Last In First Out)** 원칙을 따르는 선형 자료구조입니다.

- **동작 원리:** 가장 마지막에 삽입된 데이터가 삭제 시 가장 먼저 반환됩니다.
- **주요 활용:** 함수 호출의 콜 스택(Call Stack), DFS(깊이 우선 탐색), 웹 브라우저 방문 기록, 실행 취소(Undo) 등 역순 추적이 필요한 로직에 사용됩니다.

#### **① 자바(Java)에서의 구현**

**[핵심 전략]** `Stack` 클래스 대신 **`ArrayDeque`** 사용 권장

- **`java.util.Stack`:** Java 1.0부터 존재한 레거시(Legacy) 클래스입니다. 모든 메서드에 동기화(Synchronized) 처리가 되어 있어 단일 스레드 환경에서도 불필요한 성능 저하가 발생합니다.
- **`java.util.ArrayDeque`:** 동기화 오버헤드가 없으며, 메모리 효율과 속도 면에서 더 우수합니다.

```Java
// [Java] Stack 클래스 대신 ArrayDeque 사용
import java.util.ArrayDeque;
import java.util.Deque;
// Deque 인터페이스를 ArrayDeque로 구현
Deque<Integer> stack = new ArrayDeque<>();

// 1. 삽입 (Push)
stack.push(10); 
stack.push(20);

// 2. 조회 (Peek) - 상단 데이터 확인 (삭제 X)
int top = stack.peek(); 

// 3. 삭제 (Pop) - 데이터 반환 및 제거
// ★ EmptyStackException 방지를 위해 비어있는지 확인 권장
if (!stack.isEmpty()) {
    stack.pop();
}
```

#### ② 파이썬(Python) 구현과 활용**

**[핵심 전략]** 별도 모듈 없이 **기본 `list`** 사용

- **동작 원리:** 파이썬의 리스트는 동적 배열(Dynamic Array)입니다. 리스트의 **맨 끝**에 데이터를 추가하거나 삭제하는 연산은 인덱스 재정렬이 필요 없으므로 **$O(1)$**의 시간 복잡도를 가집니다.
- **주요 메서드:**
    - `append(x)`: 삽입
    - `pop()`: 삭제 (인자 생략 시 마지막 요소 제거)
    - `stack[-1]`: 조회 (마지막 요소 접근)

```Python
# [Python] 스택 활용 
# 별도 import 없음
stack = []

# 1. 삽입
stack.append(10)
stack.append(20)

# 2. 조회 (Peek)
# 리스트가 비어있지 않은지 확인 (Pythonic한 조건문)
if stack:
    print(stack[-1]) # 20 (가장 마지막 요소 확인)

# 3. 삭제 (Pop)
top = stack.pop()    # 20 (맨 뒤에서 꺼냄) - O(1)
```

### 2. 큐 (Queue)

**선입선출(FIFO: First In First Out)** 원칙을 따르는 선형 자료구조입니다.

- **동작 원리:** 가장 먼저 삽입된 데이터가 삭제 시 가장 먼저 반환됩니다.
- **주요 활용:** 프로세스 스케줄링, 입출력 버퍼, BFS(너비 우선 탐색), 캐시 구현 등에 사용됩니다.

#### ① 자바(Java)에서의 구현**

**[핵심 전략]** `Queue` 인터페이스와 **`LinkedList`** 구현체 사용

- **구현체:** 자바에서는 큐는 인터페이스로 정의되어있어 객체 생성이 불가능하며, 일반적으로 `LinkedList`를 구현체로 사용합니다.
- **메서드 비교 (예외 처리 vs 값 반환):**
    - `add` / `remove`: 실패 시 **예외(Exception)**를 발생시켜 프로그램이 중단될 수 있습니다.
    - `offer` / `poll`: 실패 시 **`false` 또는 `null`**을 반환하므로 알고리즘 로직 제어에 유리합니다.

```Java
// [Java] LinkedList로 Queue 구현
import java.util.LinkedList;
import java.util.Queue;

// Queue 인터페이스를 LinkedList로 구현
Queue<Integer> q = new LinkedList<>();

// 1. 삽입 (Enqueue)
q.offer(10); // 성공 시 true 반환

// 2. 조회 (Peek) - ★ 맨 앞 데이터 확인
Integer front = q.peek(); 

// 3. 삭제 (Dequeue)
// 큐가 비어있으면 null 반환 (예외 발생 안 함)
q.poll();
```

#### **② 파이썬(Python) 구현과 활용**

**[핵심 전략]** `list` 사용 금지, **`collections.deque`** 필수 사용

- **`list` 사용 시 문제점 ($O(N)$):** `pop(0)`으로 맨 앞의 요소를 제거하면, 빈 공간을 채우기 위해 뒤에 있는 모든 데이터를 한 칸씩 앞으로 이동(Shifting)시켜야 합니다. 이는 데이터 크기(N)에 비례하는 시간이 소요됩니다.
- **`deque`의 장점 ($O(1)$):** 양방향 연결 리스트(Doubly Linked List)로 구현되어 있어, 양쪽 끝에서의 데이터 추가/삭제가 모두 $O(1)$에 수행됩니다.
    - _주의:_ `queue.Queue` 모듈은 멀티스레드 동기화 락(Lock)이 포함되어 있어 코딩 테스트용으로는 느립니다.- **구현:**
    - **Enqueue (삽입):** `append(x)` (뒤에 줄 서기)
    - **Dequeue (삭제):** **`popleft()`** (앞에서 나가기)

```Python
from collections import deque

# 반드시 deque로 초기화
q = deque()

# 1. 삽입 (Enqueue)
q.append(10)
q.append(20)

# 2. 조회 (Peek)
if q:
    print(q[0])    # 10 (맨 앞 요소 접근)

# 3. 삭제 (Dequeue)
first = q.popleft() # 10 (반환 및 삭제) - O(1)
# 주의: q.pop()은 스택처럼 맨 뒤 요소를 제거하므로 사용 금지
```
