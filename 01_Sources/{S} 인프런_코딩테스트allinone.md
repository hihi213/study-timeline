## 2. LIST (선형 자료구조)의 분류 및 비교

데이터를 **'메모리에 어떻게 저장하는가'**에 따라 크게 두 가지로 나뉩니다.
### 🏛️ 1) 배열 기반 (Array-based)

- **특징:** 메모리에 **연속적** 으로 할당됨.
- **종류:**
    - **Static Array (정적 배열):** 선언 시 크기 고정.
    - **Dynamic Array (동적 배열):** 크기가 자동으로 조절됨.
### 🔗 2) 노드 기반 (Node-based)

- **특징:** 메모리에 **비연속적** 으로 흩어져 할당됨.
- **종류:**
    - **Linked List (연결 리스트):** Node(데이터+주소)들이 연결된 형태.

### 메모리 구조 및 성능 비교

| **특징**     | **배열 (Array)**               | **연결 리스트 (Linked List)**                |
| ---------- | ---------------------------- | --------------------------------------- |
| **저장 방식**  | 메모리에 **연속적**으로 할당            | 메모리에 **불연속적**으로 흩어져 할당                  |
| **접근 속도**  | 인덱스로 즉시 접근 <br>Cache Hit율 높음 | 주소를 타고 이동해야 함 <br>Cache Hit율 낮음         |
| **메모리 효율** | 데이터 크기만큼만 사용                 | 주소 저장을 위한 추가 공간 필요<br>(**Overhead 발생**) |


## 3. 상세 분석: 배열 기반 (Array-Based)

### ① Array (정적 배열)

**"선언 시 크기가 고정되는(변경 불가) 리스트"**

- **메모리 구조:** `데이터 타입 크기` $\times$ `배열 크기`만큼의 메모리를 한 번에 **연속적**으로 할당합니다.
- **접근 속도 (Random Access):**
    - 배열의 이름 = **시작 주소 (Base Address)**
    - 물리적으로 연속되어 있어 수식 한 번으로 즉시 접근 가능
    - **공식:** $\text{Target Address} = \text{Base Address} + (\text{Index} \times \text{Data Size})$
- **예시:** C언어 `int arr[10]`, Java `int[]`
    

### ② Dynamic Array (동적 배열)

**"Array의 장점에 유연함(Doubling)을 더한 리스트"**

- **정의:** Array를 기반으로 하되, **자동 크기 조절(Resizing)** 기능을 탑재
- **동작 원리 (Doubling):**
    
    1. 데이터가 가득 차면, 기존 크기의 **2배(또는 1.5배)**인 새 배열을 생성합니다.
    2. 기존 데이터를 새 배열로 **모두 복사($O(N)$)**합니다.
    3. 기존 배열을 메모리에서 해제합니다.
        
- **시간 복잡도:**
    - **접근 (Access):** $O(1)$ 인덱스로 즉시 접근
    - **추가 (Append):** 평균 $O(1)$ (Resizing 발생 시 최악 $O(N)$)
    - **삽입/삭제 (Insert/Delete):** $O(N)$ (중간 데이터를 밀거나 당겨야 함)
- **예시:** **Python `list`**, Java `ArrayList`, C++ `std::vector`

## 4. 상세 분석: 노드 기반 (Node-Based)

### ① Node (노드) 구조와 메모리

**"연결 리스트를 구성하는 기본 단위 그릇"**

- **구성:** `Data(실제 값)` + `Next Pointer(다음 노드의 주소)`
- **메모리 오버헤드 (Overhead):**
    - 배열과 달리 **주소값**을 별도로 저장해야 하므로 메모리를 더 많이 차지합니다.
    - **64bit 시스템 예시:**
        - `Data (4 Byte)` + `Pointer (8 Byte)` = **12 Byte**
        - 실제로는 패딩(Padding)으로 인해 **16 Byte**까지 차지할 수 있습니다.
            

### ② Linked List (연결 리스트) 특징

- **연결성:** 데이터가 메모리 곳곳에 흩어져 있지만, 포인터를 통해 논리적으로 연결됩니다.
- **접근 방식:** 첫 노드(Head)부터 주소를 따라가며 하나씩 확인해야 하므로 탐색 속도가 느립니다($O(N)$).


## 해시테이블
>무엇을 의미하는지도 저장하고 싶을때

- 해시 테이블은 key와 value를 한쌍으로 묶어서 저장하는 map의 구현이다.
- Key는 인덱스계산 해시충돌시 검증을 위해 저장한다.
- key에 값, value에 의미없는 값을 저장해 인덱스 접근만 사용하기도한다
	- Map은 Key와 Value를 모두 유의미하게 저장하지만, Set은 데이터를 Key 자리에 두고 Value 자리에는 더미(Dummy) 값을 채워, 일일히 값을 찾는게 아니라 해시 테이블의 인덱스를 사용하는 형태이다.(인덱스로 바로 검색)
#### **1. 데이터 저장 위치(Index) 결정 방식**

값(Value)을 저장할 인덱스를 키(Key)로부터 결정하는 방식에 따라 나뉩니다.

- **직접 주소 테이블 (Direct Address Table)**
    - **방식:** `Key` 자체가 곧 `Index`가 됩니다. (예: `3, "노정호"` $\rightarrow$ 배열의 3번 인덱스에 저장)
    - **한계:**
        - 키가 반드시 **정수**여야 합니다. 문자열 불가
        - 키 값이 연속적이지 않고 듬성듬성하다면, 사용하지 않는 공간이 많아 **메모리 낭비**가 심합니다.
- **해시 테이블 (Hash Table)**
    - **방식:** `Key`에 해시 함수를 적용한 결과를 `Index`로 사용합니다.
    - **장점:** 키가 문자열이어도 가능하며, 직접 주소 테이블의 메모리 낭비 문제를 해결합니다.
    - 이때 해싱은(함수 계산 자체)이 **$O(1)$** 이어야, 데이터가 늘어나도 전체 검색 성능 $O(1)$을 보장할 수 있음
    - key를 처음부터 끝까지 뒤지지 않는 인덱스 기반 접근
#### **2. 해시 충돌 (Hash Collision)**

- **정의:** 서로 다른 $Key$의 해싱결과(인덱스)가 동일한 경우
- 이를 해결하는 방식에 따라 언어별 구현이 달라집니다.

#### 해시테이블 구현
- 배열(array)로만 구현: 파이썬의 딕셔너리(dict)
	- 해시충돌이 나면 개방주소법: 규칙(의사 난수 탐색 등)에 따라 **다른 빈칸**을 찾아 저장.
	- 데이터가 꽉 차면 Resizing 비용 발생.
- 배열(array)+연결리스트(linkedlist)로 구현: 자바
	- 해시충돌이 나면 분리 연결법: 해당 슬롯의 **리스트(또는 트리) 끝에 추가**.
	- 버킷 내 데이터 개수에 따라 자료구조를 동적으로 변경하여 성능과 메모리 효율을 확보한다.
		- 8개 이상: 검색속도 확보하자-> 트리로 변환
		- 6개 이하: 메모리 낭비 줄이자-> 연결리스트로 복귀
		- 빈번한 변경을 막기위해 8과 6으로 차이를 둠
