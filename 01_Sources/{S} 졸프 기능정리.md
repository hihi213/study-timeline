## Week 1 — 인증·기본 실시간

* 로컬 로그인(아이디/비밀번호) → 짧은 TTL의 Access JWT
* 내 정보 조회(`/me`) + 역할 가드(ADMIN/INSPECTOR/USER)
* SSE 엔드포인트(하트비트/자동 재연결) + **SSE 인증 헤더** 적용
* 상태 체크: `/healthz`, `/readyz`

## Week 2 — 자원/물품 기본 + 실시간 반영

* 칸(자원) 목록 조회(상태 포함)
* 물품(묶음) 등록/조회/검색(LIKE, 페이지네이션)
* **활성 중 (resource,label\_no) 유니크** 충돌 처리
* SSE: `items.created / items.updated / items.removed`

## Week 3 — 물품 변경 UX + 멱등성

* 물품 변경(`adjust`: 수량/유통기한/메모)
* 전량 제거(`remove-all`) → 라벨 번호 재사용 가능
* **작성계 멱등성**(Idempotency-Key 간이 지원)
* 요청 요약 로그(경로/지연/결과) 확보

## Week 4 — 2인 검사 세션 + 423 락

* 검사 세션 열기/참여/나가기(자원당 진행 1개, 동시 최대 2인)
* 검사 중 해당 칸 쓰기 **423 Locked** 처리(자동 만료 TTL/GC)
* SSE: `inspection.opened / joined / left / locked`

## Week 5 — 조치 기록 + 단일 제출 → 벌점 원본

* 조치 기록: `PASS / WARNING / DISCARD / DISCARD_WITH_PENALTY`
* **단일 제출(멱등)**, 제출 후 결과 **불변**(수정 시 리비전 누적)
* 제출 시 **원본 벌점 자동 생성**
* SSE: `inspection.action_recorded / submitted`

## Week 6 — 벌점 조정 + 집계

* 벌점 **조정(+/-)**(사유 필수)
* 사용자별/기간별 **집계**: `original / adjusted / total` 조회
* (선택) 조정 사유 프리셋

## Week 7 — 엔드투엔드 UX + 실시간 안정화

* 로그인→등록/조회→검사(2인)→제출→벌점 조회 **E2E 흐름**
* **Last-Event-ID 기반 복구(서버 링버퍼)**, **단일 탭 공유**(SSE 1개)

## Week 8 — 계약·회귀 자동화(기능 관점)

* OpenAPI 스냅샷 고정(계약 변경 시 감지)
* 네트워크 혼합(느린 SSE/빠른 HTTP) 대표 시나리오 회귀

## Week 9 — **클라우드 v1 (Staging)** 기능

* **스테이징 환경**: EC2 + RDS, 도메인(HTTPS) 접근 가능
* **SSE 프록시 튜닝**(Nginx): 버퍼링 끔/롱타임아웃
* 원클릭 배포(스테이징) + 스모크(SSE ping)
* **부하 지표** 확보: API p50/p95, 429 비율, SSE 드롭률(초판)

## Week 10 — **클라우드 v2 (Prod-like)** 기능

* 운영 도메인 HTTPS(Prod-like) + CORS 반영
* **CI/CD 파이프라인**: migrate → deploy → smoke → 자동 롤백
* **DB 성능 전후 비교**(인덱스 보강 사례 1–2건)
* **백업→복구 리허설**(RDS 스냅샷)
* 릴리즈 패키지: 태그 `v0.1.0-mvp`, 데모(1분), Postman/Bruno

# 10주 MVP+슬립온 기능 정리 (기능 설명만)
## 1) 인증·권한

* **로컬 로그인**: 아이디/비밀번호 → **짧은 TTL** 액세스 토큰 발급.
* **내 정보 조회**: 로그인 상태/역할 확인.
* **역할 가드**: `ADMIN / INSPECTOR / USER` 접근 제어.
* **계정 상태**: 비활성 계정 로그인 차단.
* **로그인 쿨다운**: 실패 누적 제한 + 대기(브루트포스 완화).
* **SSE 인증**: 스트림 연결 시 `Authorization: Bearer <JWT>` 사용, 만료 시 자동 재연결.

## 2) 자원(냉장 칸)·물품 관리

* **칸 목록 조회**: 운영 상태(사용 가능/고장) 포함.
* **물품 등록**: 칸+라벨 번호로 등록(**활성 중 중복 불가**).
* **물품 검색/필터**: 내 물품, 특정 칸, 키워드.
* **물품 변경**

  * `수정(adjust)`: 수량/유통기한/메모 갱신
  * `전량 제거(remove-all)`: 폐기/소진 처리 후 **라벨 재사용 가능**
* **목록 페이지네이션**: `?limit&cursor`, 정렬 `(created_at, id)` 고정.
* **라벨 재사용 UX**: 충돌 시 표준 오류/가이드 제공.

## 3) 검사(Inspection) — **2인 세션 + 단일 제출**

* **세션 열기/참여/나가기**: 한 칸 **동시 진행 1건** 제한.
* **동시 참여 인원**: 최대 2명(3번째는 거절).
* **검사 중 쓰기 차단**: 해당 칸 변경 요청은 **423 Locked**.
* **조치 기록**: `PASS / WARNING / DISCARD / DISCARD_WITH_PENALTY`
  (스티커 없는 물품 = 미등록 폐기 기록 가능)
* **제출(멱등, 단일)**: 제출 후 결과 **불변**(수정 시 이력+사유 저장).

## 4) 벌점

* **원본 벌점 자동 생성**: 검사 **제출 시** 위반 결과 기반 자동 반영(수정/삭제 불가).
* **조정 벌점**: 운영자 +/- (사유 필수).
* **집계 조회**: `원본 합 + 조정 합 = 최종 점수`(사용자별/기간별).

## 5) 실시간(포그라운드 = **SSE**)

* **단일 SSE 엔드포인트**: 하트비트/자동 재연결/`Last-Event-ID` **유실 복구**.
* **대표 이벤트**

  * 물품: `items.created / items.updated / items.removed`
  * 검사: `inspection.opened / joined / left / locked / action_recorded / submitted`
  * (선택) 벌점: `penalties.adjusted`
* **이벤트/응답 공통 필드**: `resource_id`, **`floor_code` 포함**(UI 탭/권역 대비).
* **단일 탭 연결**: 브라우저에서 SSE 1개 공유.
* **연결 제한**: 사용자당 동시 1–2개.

## 6) 오류·경합 처리(클라이언트 UX 기준)

* **RFC7807 표준 오류**: 필드/사유/재시도 힌트 포함.
* **상태코드 규약**:
  `409` 충돌(라벨 중복/경쟁), `422` 의미상 위반, `423` 검사 중, `429` 과다 요청.
* **작성 멱등성(간이)**: **Idempotency-Key** 수용으로 중복 제출 동일 결과.

## 7) 보안 베이스라인

* **전송 보안**: HTTPS/HSTS, 라이트 CSP 등 보안 헤더.
* **입력 검증**: 바디/쿼리 스키마 검증, 페이로드 크기 제한.
* **레이트리밋**: 사용자/IP 단위, 로그인 실패 쿨다운.
* **민감정보 마스킹 로그**: 토큰/비번/이메일 일부 마스킹.
* **상태 엔드포인트**: `/healthz`, `/readyz`.
* **JWT 정책**: Access **15–30분**, 리프레시는 포스트-MVP.

## 8) 운영·관측·배포(Week 9–10 포함)

* **클라우드 배포**: **AWS EC2 + RDS**(**스테이징/프로덕션**), 도메인(Route53) + **ACM HTTPS**.
* **트래픽 종단**: ALB 또는 Nginx 중 택1(TLS 종료).
* **CI/CD**: GitHub Actions 등으로 **테스트→빌드→배포** 자동화, 마이그 자동 적용.
* **관측 지표**: API p50/p95, 에러율, **SSE 드롭률/재연결**, `429` 비율, **DB Slow Query Top-N**.
* **부하/성과 리포트**: k6/Artillery 결과, **DB 튜닝 전후** 비교(표/그래프).
* **운영 문서**: OpenAPI 스냅샷, 에러 카탈로그, **Runbook(배포/롤백/SSE/락)**.

## 9) 핵심 사용자 여정

* **입주자**: 로그인 → 칸 선택 → 물품 등록/조회/관리 → 실시간 반영 → 벌점 조회
* **검사자**: 세션 개시/참여(2인) → 조치 기록 → **단일 제출** → 벌점 자동 반영
* **관리자**: 칸 상태 관리(사용/고장), 벌점 조정, 기본 운영 지표 확인

## 10) 포스트-MVP(명확한 비범위)

* **Items v2**: 묶음/개별 분리(개별 **이름/유통기한/제거시각**), UI “개별 변경”.
* **알림 파이프라인**: 만료 D-1/종료 5분 전 등 예약/재시도 워커.
* **PWA + Web Push**: 백그라운드 알림/오프라인 읽기.
* **권역 권한**: 층/존/거주 기반 접근 제어.
* **추가 하드닝**: 감사 로그, 키 회전/JWKS, 정식 멱등 저장소 등.
## 10주 타임라인(기능 관점 요약)

* **Day 0**: 환경/헬스체크/기본 문서 + SSE 베이스(hello 수신)
* **W1**: 로그인/권한/보안 헤더/쿨다운 + SSE 인증 흐름
* **W2**: 칸/물품 등록·조회 + 물품 이벤트 실시간 반영
* **W3**: 물품 변경(adjust/remove-all) + 번호 충돌 UX
* **W4**: 2인 검사 세션 + 검사 중 쓰기 423 락 + 이벤트
* **W5**: 조치 기록 + **단일 제출(멱등)** + 벌점 자동 생성
* **W6**: 벌점 조정/집계 조회
* **W7**: 전체 플로우 UI 통합 + SSE 안정화(유실 복구/단일 탭 연결)
* **W8**: 계약 회귀/ E2E(실시간 포함)

* **W10**: 폴리싱/문서/릴리즈(데모·런북 포함)

# 10주이후
## 공통 원칙

* **포그라운드 = SSE / 백그라운드 = Web Push(PWA SW)**.
* **기능 플래그 + 카나리**로 점진 롤아웃·즉시 롤백.
* 데이터/스키마 전환은 **확장 → 백필 → 전환 → 수축**.
* **호환 계층 유지**: 구 API는 일정 기간 읽기 가능(또는 리디렉션), 신구 병행 후 수축.

---

## R1 — 하드닝 ① (성능·신뢰성·기본 보안)

**목표:** SLO·알림 기준 확정, 멱등/레이트리밋/관측 강화.

* **SLO 알람 임계치(Week9–10 계측값 반영)**

  * API **p95 > 300ms**가 5분 지속 → 경고, 15분 지속 → 심각.
  * **429 비율 > 1%**(1분 평균) → 경고, **> 2%**(5분) → 심각.
  * **SSE 드롭률 > 0.5%**(10분) → 경고, **> 1%**(10분) → 심각.
* **멱등성 강화**: 작성계 전 엔드포인트 **Idempotency-Key** 정식 수용(중복 요청 동일 응답).
* **레이트리밋 세분화**: 사용자·엔드포인트·버스트(슬라이딩 윈도).
* **에러 카탈로그 확정**: 409/422/423/429 메시지·필드 일관화.
* **SSE 관측 대시보드**: 현재 연결 수/하트비트/재연결/드롭률·지연.
* **DoD:** 알람 정상 트리거/해제, 중복요청 스냅샷 재사용, SSE 누수 0.

---

## R2 — 알림 파이프라인 (이벤트→큐→전송)

**목표:** 예약/재시도/중복억제 가능한 알림 경로.

* **큐 선택(Week9–10 부하 결과로 결정)**

  * 기본 권장: **AWS SQS + DLQ**(운영 단순/내구성/확장성).
  * 대안 가이드: **Redis Streams**(저지연·단일존/학내망), **RabbitMQ**(복잡 라우팅 필요 시).
  * 기준: 목표 큐 지연(p95), 처리량, 운영 복잡도, 비용.
* **워커**: 준비→전송→확정, **재시도/백오프/중복억제(멱등키)**.
* **알림센터 UI**: 배지/목록/읽음, **딥링크** 진입.
* **사용 시나리오**: 유통기한 D-1, 검사 제출/벌점, (세탁) 종료 임박.
* **SSE/Push 연동**: 포그라운드=SSE 배지, 백그라운드=Push.
* **DoD:** 실패 재시도·중복억제 로그로 검증, 큐 적체 모니터링.

---

## R3 — PWA + Web Push

**목표:** 앱 유사 UX와 백그라운드 도달성.

* **도메인/HTTPS 재사용**: Week9–10에서 구축한 **Route53+ACM**/종단(TLS) 구성 그대로 활용.
* **PWA**: 설치 가능, 핵심 조회 **오프라인 캐시**, SW 업데이트 전략.
* **Push**: 구독/해지, 만료 구독 정리 잡, 권한 프롬프트 UX.
* **iOS 가이드**: 홈 화면 추가·권한 제한 안내.
* **딥링크**: 푸시 탭 → 대상 화면.
* **DoD:** 포그라운드=SSE, 백그라운드=Push 동작 교차검증.

---

## R4 — **Items v2** (개별 아이템: 이름/유통기한/제거시각)

**목표:** 묶음 내 개별 단위까지 정밀 관리.

* **기능**: 등록 시 묶음명+수량 → 기본 개별 N 생성, **개별 변경/부분 제거** UI.
* **API**: 구(묶음) **호환 읽기** 유지, 신(개별) CRUD 병행.
  SSE 이벤트 키를 **묶음ID/개별ID**로 명확화.
* **이행**: **섀도우-쓰기/백필** → 새 API 병행 → 프론트 전환 → 구 API 수축.
* **DoD:** 구·신 데이터 혼재 시 리스트/상세/실시간 정확.

---

## R5 — 세탁실 ① (기본 사용/완료)

**목표:** 사용 시작/진행/완료 흐름.

* **기능**: 사용 시작, 진행 표시, 완료 처리.
* **충돌 방지**: 동일 장비 **동시 사용 불가(409)**.
* **실시간/알림**: 시작/완료 SSE, (옵션) 종료 임박 배지/푸시.
* **DoD:** 동시 시작 차단, 진행바·상태 일치.

---

## R6 — 세탁실 ② (현장 이슈 대응)

**목표:** 운영 편의/사고 대응.

* **미등록 사용** 신고 → **자동 복귀 타이머**.
* **종료 5분 전 푸시**(권한 허용 시).
* **고장 신고/조치**: **OUT\_OF\_SERVICE** 전환 시 사용 차단.
* **DoD:** 타임아웃·알림 정상, 운영 화면에서 상태 전환 가능.

## R7 — 스터디룸 ① (예약/취소)

**목표:** 타임슬롯 예약.

* **기능**: 10분 슬롯 예약/취소, **월 09:00 자동 생성**.
* **규칙**: 시간 겹침 **409**, 취소 정책(시간 제한) 옵션.
* **UI**: 주간 타임라인, 내 예약 하이라이트.
* **DoD:** 중복 예약 차단, 슬롯 생성 멱등.

## R8 — 스터디룸 ② (운영/합석/강제예약/블록)

**목표:** 운영 통제 강화.

* **합석 옵션**, **관리자 강제예약**, **휴무/블록** 기간.
* **실시간/알림**: 강제변경·블록 즉시 반영 및 안내.
* **DoD:** 운영 규칙 적용/되돌리기 가능.

## R9 — 도서관 ① (대출/반납/연장/예약 + 연체 벌점)

**목표:** 대출 라이프사이클.

## R10 — 관측·보안·운영 폴리싱

**목표:** 운영 신뢰성·보안 레벨 업.

* **관측/대시보드**: **CloudWatch 대시보드**(p95/에러율/429/SSE/큐 길이).
  **권장 옵션**: WAF 기본 룰 세트, 탐지→차단 단계적 적용.
* **인증 보강**: **리프레시 토큰(HttpOnly/SameSite)**, **토큰 버전 무효화**, **JWKS 키 회전**.
* **감사 로그**: 고위험 액션 **append-only** 조회 UI.
* **PWA 폴리싱**: 오프라인 캐시 무효화/재검증 전략, 설치 UX 개선.
* **인증서**: **ACM 자동 갱신** 지속 점검(권장 옵션).
* **DoD:** 키 교체 리그레션, 오프라인 UX, 감사 조회 시나리오 통과.

## 가이드라인 & 컷 스위치

* **가이드라인**

  * 신규 기능은 **SSE 이벤트 정의 → API → UI** 순으로 얇게 증분.
  * **권한·에러·실시간**을 모든 DoD에 포함.
* **컷 스위치(지연 시)**

  * **R4**: 개별 수정은 **이름 또는 유통기한 중 하나**부터.
  * **R7**: 자동 슬롯 생성 실패 시 **수동 오픈 버튼** 제공.
  * **R9**: 예약 대기열은 **후속 릴리스**로 이관 가능.

## 품질 바(모든 릴리스 공통)

* **성능**: p95 < 300ms(대표 트래픽), SSE 재연결 손실 0(Last-Event-ID 복구).
* **보안**: HTTPS/HSTS/보안 헤더, 입력 검증, 레이트리밋, 비밀 노출 0.
* **테스트**: 계약 스냅샷, E2E(실시간/푸시 포함), **롤백 리허설**.
* **문서**: 릴리스노트, 운영 런북(장애/락/알림 재시도), **권한 매트릭스**.
