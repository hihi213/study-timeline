- 빌드하고 실행하기 
	- 콘솔로 이동 
	1. `./gradlew build` 
	2. `cd build/libs` 
	3. `java -jar hello-spring-0.0.1-SNAPSHOT.jar` 
	4. 실행 확인
  - java  -jar  hello-spring-0.0.1-SNAPSHOT.jar: 만들어진 Jar파일을 실제로 실행하는 명령어  
  - 지피티 탐색
	  - **1. IDE(예: 인텔리제이)에서 실행** 인텔리제이에서 실행하는 방식은 .jar 파일을 만들지 않고, 내부에서 클래스 파일을 컴파일한 뒤 메모리에 직접 올려 실행한다. 이 방식은 빠르고 개발 중 테스트나 디버깅에 적합하다. 다만 배포용으로는 적절하지 않다. 
	  - 2. Gradle 빌드 (./gradlew build)** Gradle은 프로젝트의 build.gradle 파일을 기반으로 컴파일, 테스트, 의존성 다운로드, .jar 파일 생성 등을 수행한다. 결과물로는 build/libs/ 디렉토리 아래에 실행 가능한 .jar 파일이 생성된다. 이 .jar는 필요한 설정 파일, 라이브러리, 스프링부트 자체 및 내장 톰캣까지 포함된 완성된 실행 파일이다.
		  - **1. jar파일 실행**: 생성된 .jar 파일은 다음과 같이 명령어로 실행할 수 있다. java -jar hello-spring-0.0.1-SNAPSHOT.jar Java가 설치된 어떤 환경에서든 동일하게 실행할 수 있고, 별도의 WAS 설치 없이 서버처럼 동작한다. 
		  - **2. Docker 이미지로 실행**:  Docker는 운영체제 환경과 .jar 파일을 함께 묶어서 이미지로 만든다. 이 이미지를 기반으로 컨테이너를 실행하면, 어떤 운영체제이든 동일한 환경으로 애플리케이션을 실행할 수 있다. 운영 환경에서의 일관성을 보장하고, 배포 자동화(CI/CD)에도 적합하다.

	- ### **1. 톰캣(Tomcat)은 웹서버이다**
		- HTTP 요청을 받아서, 요청 URL에 맞는 서블릿이나 컨트롤러에게 전달한다.
	    - 컨트롤러가 응답을 만들면, 그걸 다시 브라우저로 전달하는 **중간 다리** 역할을 한다.
		- 흔히 말하는 “자바 웹서버”는 Tomcat, Jetty, Undertow 같은 것들이다.
	- ### **2. 내가 만든 건 웹 애플리케이션 (Web Application)**
		- 사용자의 요청을 받아 처리하는 Controller
		- 비즈니스 로직을 담당하는 Service
		- DB에 접근하는 Repository
		→ 이런 구성요소들을 스프링으로 작성해서 만든 “웹 애플리케이션”이다.
	- ### **3. 스프링 부트는 톰캣 + 웹앱을 하나로 포장한 것**
		- 과거에는 .war 파일을 만들어 외부 Tomcat에 배포했지만,
		- 스프링 부트는 **내장 톰캣**을 .jar 파일 안에 함께 포함시킨다.
		- 따라서 .jar 파일 하나만 실행해도 톰캣이 실행되고, 웹앱도 자동으로 배치된다.
	- 출처: Gpt

- 스프링  웹  개발  기초
  - 웹 개발 방식 3가지
  - 1. 정적 콘텐츠: 파일을 고객에게 그대로 전달
  - 2. MVC와 템플릿 엔진: html를 그냥 주는게 아니라 서버에서 프로그래밍해서 동적으로 바꾸는 템플릿엔진, 그걸하기위한 컨트롤러, 모델,템플릿 엔진화면 이 3가지를 모델뷰 컨트롤러 mvc라고한다
