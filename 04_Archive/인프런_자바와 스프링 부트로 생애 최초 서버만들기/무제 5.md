

# 📚 헷갈리는 개발 용어, 맥락별 완벽 정리

단어의 뜻은 **"어디서 쓰이느냐"**에 따라 달라집니다.

## 1️⃣ 통신과 요청 (Communication)

### **서버 (Server)**

- **어원:** Serve(제공하다) + er(~하는 사람/것) = **"기능을 제공하는 주체"**
- **소프트웨어적 의미:** 회원가입, 정보 조회 등의 **기능을 제공하는 프로그램**.
- **하드웨어적 의미:** 그 프로그램을 24시간 실행하고 있는 **컴퓨터**.
### **클라이언트 (Client)**

- **정의:** 서버에게 **요청을 보내는 모든 존재**.
- **계층별 구분:**
    - **클라이언트(Client):** 가장 큰 개념. 요청을 보내는 쪽.
    - **API 클라이언트:** API를 호출하는 프로그램이나 도구 (Postman, 백엔드 서버 간 통신 등).
    - **프론트엔드 클라이언트:** **'웹 브라우저'**를 통해 API를 호출하는 주체 (React, Vue, HTML/JS 등).

### **요청 (Request) & URL**

- **요청:** 기능을 쓰기 위해 컴퓨터(서버)에게 보내는 메시지. (주로 인터넷을 통함)
- **URL:** 서버 내의 수많은 기능(Controller) 중 **"어디로 요청을 보낼지"** 결정하는 주소 역할.
- **라우팅:** 들어온 URL 요청을 **어느 컨트롤러(길)로 보낼지 연결해 주는 행위**.

### **API vs HTTP (중요!)**

- **API (Application Programming Interface):** 기능 사용을 위한 **'약속/접점'**.
    - **웹 개발:** 서버의 기능(URL)을 호출하는 것.
    - **프로그래밍:** 라이브러리나 모듈이 제공하는 함수를 호출하는 것.
- **HTTP:** 데이터를 주고받는 **'배송 방식(프로토콜)'**. (트럭)
- **차이점:**
    - 웹사이트 접속이나 외부 API 호출은 **HTTP 요청**을 사용합니다.
    - **하지만,** 서버 내부에서 DB와 통신하는 API 요청은 **HTTP를 쓰지 않습니다.** (TCP/IP 기반의 전용 프로토콜 사용)

## 2️⃣ 데이터와 로직 (Data & Logic)

### **도메인 (Domain)**

- **웹 (네트워크):** 인터넷 주소 범위 (예: `naver.com` = 네이버가 관리하는 구역). 사람이 IP 주소를 외우기 힘드니까 만든 것.
- **소프트웨어:** **"애플리케이션이 다루는 핵심 업무 영역/데이터"**.
    - _도메인 모델:_ 핵심 데이터를 표현하는 객체 (예: `User`, `Order`, `Product`).
        

### **비즈니스 로직 vs 도메인 모델**

- **비즈니스 로직 (행동):** 데이터를 처리하는 규칙, 계산, 검증.
    - _예: `calculateTotalPrice()` (할인 적용해서 계산해라)_
- **도메인 모델 (데이터):** 비즈니스 데이터를 담고 있는 객체 그 자체.
    - _예: `Order` 객체 (주문 정보)_
- **관계:** **모델**은 데이터를 저장하고, **로직**은 그 데이터를 어떻게 다룰지 정의합니다.
    

### **모듈 vs 인터페이스**

- **인터페이스:** "이런 기능이 있어야 해"라고 정의한 **설계도**.
- **모듈:** 그 설계도를 보고 실제로 동작하게 만든 **구현 코드 덩어리**.
    

### **엔티티 (Entity)**

- **소프트웨어:** 비즈니스 데이터를 담는 핵심 객체.
- **데이터베이스:** 테이블에 저장된 **한 행(Row)**, 즉 데이터의 실체.
    

### **컨트롤러 vs 서비스**

- **컨트롤러 (Controller):** **[안내 데스크]** HTTP 요청을 받아서 적절한 서비스 로직을 호출하는 역할.
- **서비스 (Service):** **[실무자]** 실제 **비즈니스 로직**을 수행하는 계층. (AWS 같은 클라우드 서비스를 의미할 때도 있음)

## 3️⃣ 저장과 상태 (Storage & State)

### **세션 vs 쿠키 vs 캐시**

- **세션 (Session):** **[서버 메모리 저장]** 로그인 상태 등 중요한 정보를 서버에서 관리.
- **쿠키 (Cookie):** **[클라이언트(브라우저) 저장]** 사용자 측에 데이터를 저장 (보안성 낮음).
- **캐시 (Cache):** **[임시 저장소]** 데이터에 빠르게 접근하기 위해 브라우저, CDN, 서버 메모리 등에 잠시 저장하는 기술.
    

### **리포지토리 (Repository)**

- **백엔드 개발:** DB와 상호작용하며 데이터를 관리하는 계층 (JPA `UserRepository` 등).
- **형상 관리:** 소스 코드를 저장하고 버전 관리하는 공간 (**Git/GitHub**).

## 4️⃣ 운영과 인프라 (Ops & Infra)

### **스펙 (Spec)**

- **개발:** **Specification(기술 명세서)**. API가 어떤 요청을 받고 무엇을 응답하는지 정의한 문서.
    - _주의:_ 취업 시장에서의 스펙(학력, 자격증)과는 완전히 다른 개념.
        

### **라우팅 (Routing)**

- **백엔드:** 특정 URL 요청을 알맞은 **컨트롤러 메서드**로 연결하는 것 (`@GetMapping`).
- **네트워크:** 데이터 패킷을 목적지까지 최적의 경로로 이동시키는 것.
    

### **빌드 vs 배포**

- **빌드 (Build):** 작성한 코드를 실행 가능한 파일(Jar 등)로 변환하는 과정.
- **배포 (Deploy):** 빌드된 파일을 실제 서버에 업로드하여 **실행**시키는 과정.
    

### **서버 부하 관리**

- **로드 밸런싱:** 들어오는 요청(Traffic)을 여러 대의 서버에 **균등하게 분산**시키는 것.
- **스케일링:** 서버의 **개수**를 늘리거나(Scale-out) 사양을 높여(Scale-up) 처리 능력을 조절하는 것.
    

### **쿼리 (Query)**

- **정의:** 시스템에 정보를 **요청하는 질문**.
- **SQL 쿼리:** DB에 데이터를 달라고 하는 문장 (`SELECT * FROM…`).
- **HTTP 쿼리 스트링:** URL 뒤에 붙여서 서버에 보조 정보를 보내는 형태 (`?key=value`).

## 🚀 전체적인 호출 흐름 (Flow)

> **사용자의 클릭 한 번이 화면에 뜨기까지**

1. 🖱️ **클릭:** 유저가 버튼 클릭 → 브라우저가 **API 클라이언트**로서 요청 생성.
2. 🚚 **전송:** HTTP 요청(`GET /users/1`)이 인터넷을 타고 서버로 날아감.
3. 📍 **라우팅:** 서버(Spring Boot)가 URL의 `/users/1`을 보고 `UserController`로 연결. (**URL 파싱**)
4. ⚙️ **로직:** **컨트롤러**가 **서비스**를 호출하고, 서비스는 **리포지토리**를 통해 DB에서 데이터를 가져옴.
5. 📦 **응답:** 서버가 데이터를 JSON 형식(`ResponseEntity`)으로 포장하여 HTTP 응답(`200 OK`) 반환.
6. 🖥️ **렌더링:** 브라우저가 응답받은 JSON 데이터를 해석해 화면에 유저 정보를 띄움.
