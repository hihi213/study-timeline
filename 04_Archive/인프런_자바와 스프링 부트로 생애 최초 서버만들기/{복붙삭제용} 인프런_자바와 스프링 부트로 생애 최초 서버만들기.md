## \<GPT와 고민>
### 단축키 정리
- 키의 의미
	- command: 명령의 중심
		- 가장 전역적
		- 사용자의 행동을 명령처럼 내릴때
	- control: 제어, 보조기능, 콘솔스타일 조작
		- 커서그대로 화면조작
		- 행단위
	- option: 선택지, 세부조정
		- 세밀조작에서 등장
		- 단어단위, 다중선택, 경로설정
	- fn: 방향/기능 보조
		- fn+지우기=>Delete 역할
- 키암기팁
	- command: 전체, 전역
		- command+ 방향키: 그방향끝으로 점프
		- command+ 지우기: 줄 전체 삭제
	- control: 화면조작/ 줄
	- option: 단어단위조작
	- fn: 방향/기능 보조
- 인텔리제이
	- 실제코드 들어가기: command클릭/command+B
	- option+f1(왼쪽에 저격수 아이콘): 현재 선택한 클래스나 파일이 **왼쪽 프로젝트 구조 창에서 어디 있는지** 보여줍니다.
	- 파일 검색 단축키: command+shift+o
	- 현재줄을 위아래로 이동: option+shift+ 방향키
	- 새로운 패키지/파일..등 만들기: cmd+n
	-  범위지정 :option+⬆️
		- 계속화살표위 누르면 범위가 커진다.
	- import문 생성: option+enter
	- 안쓰는 import문 삭제 control+option+o
	- 최근에 쓴 클래스 목록: command+E
	- 변수이름 한번에 바꾸기: shift+ f6
	- 다음줄로 넘어가기(뒤에 문장있어도) :shift+enter
	- **파라미터 정보 보기** cmd+ p
- myspl
	- 코드정리 단축기: option+command+I
- 캡쳐
	- control +shift+ cmd+ 4: 선택한영역을 클립보드에 복사 control없으면 파일형태로 저장
	- control +shift+ cmd+ 3: 화면을 클립보드에 복사 control없으면 파일형태로 저장
- 모니터전환
	-  ⌥⇧N: (next)다음 모니터으로 포커스 이동
	-  ⌥⇧P: 왼쪽 (previous)이전 모니터으로 포커스 이동
- 모니터에서 데스크탑 전환
	- **Control + 좌우 방향키**
- 지금 모니터의 데스크탑에서의 창전환
	-  ⌥⇧K (Move focus clockwise)
	-  ⌥⇧J (Move focus counter clockwise)
- 문장내 빠른커서 이동
	- **문장 맨 앞으로 이동** : control +A
	- 줄(line)의 끝으로 이동 : Control + E
	- **단어 단위로 이동**: Option + 방향키
- 삭제 단축키
	- 커서 이후 한 글자 삭제: Fn+ 지우기
	- 커서 앞의 단어단위 삭제: Option + 지우기
	- 커서 뒤의 한 단어 삭제 (일부 앱 한정): Fn + Option + 지우기
	- 커서부터 줄 앞까지 삭제: Command + 지우기
- 커서는 그대로, 화면만 이동: Control + 방향키
- 완전위, 아래로이동: command + 방향키
- cmd+n :새로운 패키지/파일..등 만들기

- ### 2. Spring Data JPA를 이용해 데이터를 조회, 수정, 삭제 할 수 있다.
	- 이때 JpaRepository<Entity, ID>인터페이스를 상속했다면 @Repository를 생략해도 된다(이미 상속만으로 빈으로 인식함)
	- spring Data JPA 주요메서드
		- 우리가 만든 인터페이스이름.**save(new 객체)**
		- List\<객체> users= 우리가 만든 인터페이스이름.**findAll()**
			- 모든 엔티티 객체들 리스트로 반환됨
			- 엔티티를 DTO로 변환해 내보내야함
				- userRepository.findAll() 모든 User 엔티티 객체들을 가져옴
				- .stream() 리스트를 스트림으로 바꿈 (반복 작업 처리 가능)
				- .map(...) 각각의 User 엔티티 → UserResponse 객체로 변환
				- .collect(Collectors.toList()) 최종 결과를 리스트로 모음 (List\<UserResponse>로 반환)
			- 하나하나씩 열어서 매핑하는 jdbc탬플릿 이용대신 User객체를 가져와서 객체간의 변환을 하는거다 (즉 매핑이 자동화)
				- **DBC Template 방식** .query
					- ResultSet → UserResponse 객체를 직접 매핑해야 했음 즉, DB에서 값을 꺼내면서 일일이 가공해서 집어넣는 작업 필요
				- JPA 방식
					- 먼저 DB에서 User 엔티티 객체들을 가져오고
					- 그걸 stream으로 DTO(UserResponse) 로 변환만 해주면 끝
				- 즉 컬럼 추가/삭제 시 **모든 SQL과 RowMapper 수정** 필요했는데, JPA 방식은 결과를 받아오는 필드를 따로 작성하지 않아서(매핑), **엔티티 클래스만 수정하면 자동으로 쿼리와 매핑이 반영**되어 **유지보수가 훨씬 간단하고 안정적**입니다.
		- Optional\<객체> user =우리가 만든 인터페이스이름.**findById(id)**
			- Optional로 반환되므로 null 처리 걱정 줄어듦
		-  인터페이스이름.**deleteName(name)** 하면 지워짐
	- spring Data JPA 사용자 정의 메서드
		- 이름을 기준으로 조회하는건 없어서 우리가 인터페이스에 들어가 findByName를 선언해준다
			- findByName- **메서드 이름 규칙만 맞추면 자동으로 SQL 생성됨**
		- 형식 구절1 by 구절2
			- 암기할필요x
		- by앞
			- find: 1건의 객체, Optional<타입>을 반봔
			- findAll : List<타입> 반환 (n건의 결과물)
			- exists : 존재여부를 boolean으로 반환
			- count: sql의 결과개수를 쓴다 반환타입은 long이다
		- by뒤
			- 각구절은 and나 or로 조합할수있다.
			- GreaterThan: 초과
			- GreaterThanEqual: 이상
			- LessThan: 미만
			- LessthanEqual: 이하
			- Between: 사이에
			- StartsWith: ~로 시작하는
			- EndsWith: ~로 끝나는
	- jpa를 활용하면 업데이트 sql를 직접 날리는게 아니라 유저의 객체를 가져와서 업데이트하게됨
		- 이때 User에 getName의 역할을하는 updateName이라는 메소드를 만들어서 가져온객체의 이름을 변경하고
		- 인터페이스이름.save(가져온객체)
			- 이는 변경 감지 (Dirty Checking)라고한다
			- > @Transactional 안에서 기존 엔티티를 조회해 수정만 했다면,  save() 없이도 트랜잭션이 끝나는 시점에 변경된 내용을 자동으로 감지해서 UPDATE SQL을 날림. 다만, 신규 저장이거나 트랜잭션이 없다면 save()가 필요하다.
	- 스프링은 JpaRepository<Entity, ID>를 구현받는 Repository에 대해 자동으로 SimpleJpaRepository 기능을 사용할 수 있게도 해준다.
	- SimpleJpaRepository 코드를 열어보면, 조금 복잡한 코드들을 확인할 수 있는데, 이게 바로JPA 코드이다. Spring Data JPA 를 사용하는 덕분에 복잡한 JPA 코드를 직접 사용하는 게 아니라 기능로써 사용할 수 있게 되는 것이다.
	- Spring Data JPA를 직접사용하지만 사실은 Spring Data JPA 안의 JPA 구현체인 Hibernate의 JDBC를 쓰고 있다
