HTTP 메시지 구조는 서버와 클라이언트 간의 약속된 **통신 규격**입니다. 제시해주신 내용을 바탕으로 기술적 상세 정보와 핵심 인사이트를 추가하여 정리해 드립니다.

---
## HTTP 프로토콜(통신규격)

HTTP 메시지는 요청(Request)과 응답(Response)에 관계없이 크게 세 부분으로 구성됩니다.

1. **시작 줄 (Start Line):** 요청인지 응답인지에 따라 **요청 라인** 혹은 **상태 라인**이라 부릅니다.
2. **헤더 (Headers):** 메시지에 대한 메타데이터(크기, 타입, 보낸 사람 등)를 담습니다.
3. **공백 줄 (Empty Line):** 헤더가 끝났음을 알리는 필수 구분선입니다.
4. **바디 (Payload / Body):** 실제 전송하려는 데이터(JSON, 이미지 등)가 실리는 곳입니다.

## 1. 첫 번째 줄: 시작 줄 (Start Line)

### **A. 요청 라인 (Request Line)**

> 예시: GET /users/1?mode=dark HTTP/1.1
> 형식: `[Method]` `[요청URL]` `[HTTP-Version]`

> [!NOTE]- **HTTP Method:** 서버가 수행해야 할 동작을 지정합니다.
> |**메서드**|**주요 용도**|**데이터 위치**|**멱등성(Idempotent)**|
> |---|---|---|---|
> |**GET**|리소스 조회 (Read)|URL (Query String)|**Yes** (여러 번 해도 결과 동일)|
> |**POST**|리소스 생성/프로세스 실행 (Create)|Body|**No** (할 때마다 데이터 생성)|
> |**PUT**|리소스 전체 교체/덮어쓰기 (Update)|Body|**Yes** (같은 데이터로 덮으면 동일)|
> |**PATCH**|리소스 부분 수정 (Update)|Body|**No** (설계에 따라 다를 수 있음)|
> |**DELETE**|리소스 삭제 (Delete)|URL (Query String)|**Yes** (삭제된 상태는 동일)|
> 
> > **💡 핵심 인사이트:** **멱등성**은 네트워크 장애로 같은 요청이 중복 전송되었을 때 시스템의 안전성을 결정하는 매우 중요한 속성입니다.
- **요청 URL (Request-Target):** 경로(Path)와 쿼리 스트링(Query String)을 포함합니다.
- **HTTP 버전:** 통신에 사용할 규격 버전을 명시합니다.

### **B. 상태 라인 (Status Line)**

> 예시: HTTP/1.1 200 OK
> 형식: `[HTTP-Version]` `[Status-Code]` `[Reason-Phrase]`

## 3️⃣ 요청 URL과 프레임워크 매핑

서버(Spring Boot 등)는 URL을 해석하여 적절한 로직으로 연결(Routing)합니다.

- **URL 구성:** `/컨트롤러경로/메서드경로?key=value`
- **Spring Annotation 매핑:**
    - `@RequestMapping("/base")`: 컨트롤러 클래스 상단에 공통 경로 지정.
    - `@GetMapping("/detail")`: 특정 메서드에 상세 경로 및 메서드 타입 지정.
- **데이터 추출 방식:**
    - **경로 변수(Path Variable):** `/users/{id}` → `@PathVariable` 사용.
    - **쿼리 스트링(Query String):** `?name=kim` → `@RequestParam` 사용.

## 4️⃣ 두 번째 줄: 헤더 (Headers)

헤더는 메시지 전송과 본문 처리에 필요한 **부가 정보**를 제공합니다.

- **Host:** 요청이 전송되는 도메인 명 (필수).
- **Content-Type:** 바디(Body)에 실린 데이터의 형식 (예: `application/json`).
- **Authorization:** 클라이언트의 인증 정보(Token 등).
- **User-Agent:** 요청을 보낸 클라이언트(브라우저, 앱)의 정보.
    

---

## 5️⃣ 세 번째 줄 이후: 공백 줄과 바디 (Body)

- **공백 줄:** HTTP 명세상 헤더와 바디를 구분하는 유일한 수단입니다. 이 줄이 누락되면 서버는 바디를 헤더의 일부로 잘못 해석하여 에러를 발생시킵니다.
- **바디 (Body):**
    - **GET/DELETE**는 관례상 바디를 사용하지 않거나 무시합니다.
    - **POST/PUT/PATCH**는 실제 가공할 데이터를 JSON 등의 형식으로 실어 보냅니다.
        

---

## 📊 요약: 핵심 체크리스트

1. **GET**은 URL에 정보를 노출하므로 보안이 필요한 데이터(비밀번호 등) 전송에 부적합하며, 반드시 **POST**를 사용해야 합니다.
2. **PATCH**는 수정할 필드만 보내고, **PUT**은 객체 전체를 보내야 합니다. (PUT 사용 시 누락된 필드는 NULL이 될 위험이 있습니다.)
3. **HTTP 상태 코드**는 응답 메시지의 시작 줄에서 가장 중요한 요소입니다. (2xx: 성공, 4xx: 클라이언트 오류, 5xx: 서버 오류)
