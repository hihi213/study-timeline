개발 현장에서 혼용되거나 맥락에 따라 의미가 변하는 주요 용어들을 정의와 역할 중심으로 재구조화하여 정리했습니다.

---

## 1. 시스템 기초 및 상호작용 (Server & Client)

### **서버 (Server)**
- **정의:** 네트워크를 통해 클라이언트에게 특정 기능이나 서비스를 제공하는 주체입니다.
- **구분:**
	* **프로그램 관점:** 기능을 수행하는 소프트웨어 자체를 의미합니다.
    - **하드웨어 관점:** 해당 소프트웨어를 실행하고 있는 물리적 컴퓨터 장치를 의미합니다.

### **클라이언트 (Client)**

- **정의:** 서버에 특정 서비스를 요청하고 그 결과를 받는 주체입니다.
- **구분:**
    - **API 클라이언트:** API 요청을 보내는 모든 도구 및 프로그램(Postman, 백엔드 서버 등)입니다.
    - **프론트엔드 클라이언트:** 사용자가 직접 사용하는 웹(React, Vue) 또는 앱 환경입니다.


---

## 2. 인터페이스 및 통신 (API & HTTP)

### **API (Application Programming Interface)**

- **정의:** 소프트웨어가 다른 소프트웨어의 기능을 호출할 수 있도록 정의한 규약입니다.
- **웹 개발:** 서버의 특정 기능을 외부에서 호출할 수 있는 접점입니다.
- **프로그래밍:** 라이브러리나 모듈의 기능을 사용하기 위한 함수 및 인터페이스입니다.
    

### **요청 방식의 차이**

|**구분**|**HTTP 요청**|**API 요청**|
|---|---|---|
|**성격**|데이터를 주고받는 **전송 프로토콜**|기능을 실행하기 위한 **호출 행위**|
|**범위**|인터넷 망을 통한 외부 통신에 필수|서버 내부 모듈 간 호출 시에는 HTTP 없이 가능|
|**데이터**|헤더, 바디 등 전송 규격 중심|파라미터, 반환값 등 기능 명세 중심|

### **라우팅 (Routing)**

- **네트워크:** 데이터 패킷을 목적지까지 최적의 경로로 전달하는 과정입니다.
- **웹 프레임워크:** 특정 URL 요청(`@GetMapping`)을 처리할 적절한 **컨트롤러** 코드로 연결하는 행위입니다.

## 3. 소프트웨어 설계 계층 (Architecture & Data)

### **컨트롤러 vs 서비스 vs 리포지토리**

- **컨트롤러(Controller):** 외부의 HTTP 요청을 가장 먼저 받아 **URL 매핑 및 파라미터 검증** 후 서비스를 호출합니다.
- **서비스(Service):** 실제 **비즈니스 로직**을 수행하는 계층입니다. 데이터의 처리 규칙과 절차를 담당합니다.
- **리포지토리(Repository):** 데이터베이스(DB)와 직접 통신하며 **데이터의 영속성(저장/관리)**을 담당합니다.
    

### **도메인(Domain)의 이중적 의미**

1. **네트워크:** `naver.com`과 같이 IP 주소를 문자로 변환한 인터넷 상의 주소 범위입니다.
2. **소프트웨어 설계:** 비즈니스의 핵심 영역과 그 안에서 다루는 데이터 모델(User, Order 등)을 의미합니다.
    

### **데이터 모델링 용어**

- **엔티티(Entity):** 고유한 식별자를 가지는 비즈니스 데이터의 실체입니다. DB 테이블의 레코드(Row)와 대응됩니다.
- **도메인 모델:** 비즈니스 데이터를 담는 객체 그 자체입니다.
- **비즈니스 로직:** 데이터 모델을 가공하거나 검증하는 **규칙(할인율 계산, 재고 확인 등)**입니다.

## 4. 데이터 저장 및 상태 관리 (Storage)

|**구분**|**쿠키 (Cookie)**|**세션 (Session)**|**캐시 (Cache)**|
|---|---|---|---|
|**저장 위치**|클라이언트(브라우저)|서버 메모리/DB|브라우저, CDN, 서버 메모리 등|
|**주 목적**|사용자 식별 및 설정 저장|로그인 상태 유지 (인증)|반복 요청에 대한 응답 속도 향상|
|**보안성**|낮음 (탈취 가능)|높음 (서버가 관리)|무관 (임시 복사본)|

## 5. 개발 공정 및 운영 (Build & Deploy)

### **빌드 vs 배포**

- **빌드(Build):** 소스 코드를 컴퓨터가 실행할 수 있는 형태(Binary, JAR 등)로 변환하고 압축하는 과정입니다.
- **배포(Deploy):** 빌드된 파일을 실제 운영 서버에 업로드하여 사용자가 접속 가능한 상태로 만드는 과정입니다.
    

### **서버 부하 관리**

- **로드 밸런싱(Load Balancing):** 여러 대의 서버에 트래픽을 균등하게 나누어 전달하는 기술입니다.
- **스케일링(Scaling):** * **Scale-up:** 서버 자체의 성능(CPU, RAM)을 강화합니다.
    - **Scale-out:** 서버의 개수를 늘려 처리 능력을 확장합니다.
        

---

## 6. 전체적인 호출 및 처리 흐름 (Sequence)

1. **이벤트 발생:** 사용자가 브라우저에서 버튼을 클릭합니다.
2. **API 호출:** 브라우저 내 **API 클라이언트**가 설정된 스펙에 맞춰 **HTTP 요청**을 생성합니다.
3. **라우팅:** 서버의 **라우터**가 URL을 확인하고 요청을 해당 **컨트롤러**로 전달합니다.
4. **로직 실행:** 컨트롤러는 **서비스**를 호출하여 **비즈니스 로직**을 실행합니다.
5. **데이터 접근:** 서비스는 **리포지토리**를 통해 DB에서 **엔티티**를 조회하거나 저장합니다.
6. **응답 반환:** 처리 결과가 JSON 형식의 **응답(Response)**으로 변환되어 클라이언트에 도달합니다.
