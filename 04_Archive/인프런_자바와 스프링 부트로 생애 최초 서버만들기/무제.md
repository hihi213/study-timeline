## 2️⃣ 데이터 변환 원리: DB부터 화면까지

데이터가 DB에서 자바 객체를 거쳐 사용자 화면(JSON)으로 변환되는 2단계 핵심 프로세스입니다.

### **1단계: DB → 자바 객체 (RowMapper & ResultSet)**

DB 테이블은 개발자마다 설계가 다르므로, 스프링은 한 행(Row)을 어떻게 객체로 바꿀지 알려주는 **지도(RowMapper)**가 필요합니다.

- **ResultSet:** DB 원본 데이터를 한 줄씩 가리키는 **화살표(포인터)**입니다. DB 연결이 유지되는 동안만 유효합니다.
- **mapRow():** `ResultSet`이 가리키는 현재 행의 데이터를 추출하여 **자바 객체**에 옮겨 담는 실제 로직입니다.

## 3️⃣ CRUD API 구현 실무

데이터 조회(`query`)를 제외한 모든 변경 작업은 `update()` 메서드로 통일됩니다.

### **📊 CRUD 작업 총괄표**

|**기능**|**HTTP Method**|**SQL 예시**|**JdbcTemplate 메서드**|
|---|---|---|---|
|**생성**|`POST /user`|`INSERT INTO user...`|`update()`|
|**조회**|`GET /user`|`SELECT * FROM user`|`query()`|
|**수정**|`PUT /user`|`UPDATE user SET...`|`update()`|
|**삭제**|`DELETE /user`|`DELETE FROM user...`|`update()`|

### **핵심 구현 코드 예시**

#### **유저 조회 (SELECT)**

Java

```sql
@GetMapping("/user")
public List<UserResponse> getUsers() {
    String sql = "SELECT * FROM user";
    return jdbcTemplate.query(sql, (rs, rowNum) -> new UserResponse(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getInt("age")
    ));
}
```

#### **유저 수정 (UPDATE)**

Java

```sql
@PutMapping("/user")
public void updateUser(@RequestBody UserUpdateRequest request) {
    String sql = "UPDATE user SET name=? WHERE id=?";
    jdbcTemplate.update(sql, request.getName(), request.getId());
}
```

## 4️⃣ 핵심 비교 및 프로 팁

### **📊 JdbcTemplate 주요 메서드 비교**

|**구분**|**query()**|**queryForObject()**|**update()**|
|---|---|---|---|
|**용도**|**다중 행** 조회|**단일 행** 조회|데이터 **변경** (C, U, D)|
|**결과 수**|0개 ~ N개 (List 반환)|**정확히 1개** (객체 반환)|영향받은 행의 수 (int)|
|**예외 상황**|결과 없으면 `[]` 반환|결과 없으면 **Exception 발생**|실패 시 0 반환|

### **💡 실무를 위한 개발 팁**

- **DTO 활용:** 자바 메서드는 하나의 타입만 반환할 수 있으므로, 여러 컬럼을 묶은 전용 객체(DTO)를 만들어 사용하세요.
- **단축키:** IntelliJ에서 `mapRow` 구현 시 `Ctrl + O`를 활용하면 편리합니다.
- **컬럼명 일치:** `rs.getString("name")`에서 문자열은 DB의 실제 컬럼명과 대소문자까지 정확히 일치해야 합니다.
