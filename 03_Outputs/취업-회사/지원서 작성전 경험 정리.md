## **1. 기숙사 환경 요약**

  

### **1-1. 구조/거주자**

- 2F~5F, 총 4개 층 / 층당 24개 호실
- 성별 분리: 2층 남, 3~5층 여
- 호실 타입
    - 3인실(TRIPLE) 22개
    - 1인실(SINGLE) 층별 1~2개 (2F: 213, 224 / 3F: 313 / 4F: 413 / 5F: 513)
- 거주자 식별: **호실번호 + 개인번호** (ex. 201-1)
- 거주 기간: 최대 1년 (중도 퇴사 가능)
    

  

### **1-2. 공용 시설**

- **냉장고**
    - 2~5층, 층당 1대(총 4대)
    - 구성: 냉장 3칸 + 냉동 1칸
    - 호실 배분 (24개 호실 기준)
        - 냉장칸 3개: 칸당 8개 호실
            - Slot1: 0108호 / Slot2: 0916호 / Slot3: 17~24호
        - 냉동칸 1개: 층 전체 공용
    - 확장 시나리오: 층당 2대(냉장 6칸) 기준, 칸당 4개 호실 배분 →
        
        **시스템에서 칸 수 변화에 따른 자동 재배분 필요**
        
    
- **세탁실**
    - 남녀 분리, 별도 건물
    - 남자: 세탁기 6대, 건조기 2대
    - 여자: 세탁기 7대, 건조기 6대
    - 공용 이불 건조기: 남자 세탁실 내 2대(남녀 공용)
- **다목적실**
    - 총 3개, 기숙사생 누구나 이용 가능
    - 공간이 넓어 **합석(공동 이용)** 가능 → 합석 배지 컨셉 도입 배경
- **도서관**
    - 1개, 기숙사생 공용
        
    

  

### **1-3. 운영/소통 구조**

## **2. 냉장고 물품 등록 시스템**

  

### **2-1. 기존 문제 (수기 스티커)**

- 호실/이름/물품명/유통기한 중 하나라도 누락 시 주인 확인 불가
- 1인 1물품 수준만 겨우 관리 가능
- 층별장이 모든 스티커를 눈으로 확인하는 **아날로그 검사**
    

  

### **2-2. 1차 시도: NFC 기반 디지털화**(구현x)

- 목표:
    - 수기 작성 → 디지털 입력 전환
    - **NFC 태그 스캔만으로 물품 등록/식별** 가능하게 설계
- 방식:
    - NFC 태그에는 고유 ID가 포함된 URL만 저장
    - 서버에서 태그 ID를 기반으로 물품 정보 매핑
        
    

  

### **2-3. 한계 및 Pivot**

- **물리적 문제**
    - 금속(냉장고, 캔) 간섭 → 인식률 저하
    - 습기·결로 → 태그 인식 오류
- **운영 문제**
    - 태그 분실·훼손·도난에 취약
    - 기숙사처럼 유동적이고 공용인 환경에 부적합
- **결론**
    - NFC를 핵심으로 쓰는 것은 **운영 리스크가 높다**고 판단
    - → **NFC 없이도 100% 동작하는 “수동 입력” 방식**을 기본으로 전환
        
    

  

### **2-4. 새 설계 방향: 최소 입력 + 빠른 조회**

- 질문: “수동 입력인데, 어떻게 덜 입력하고도 빨리 찾게 할까?”
- 답:
    - 기존 스티커에
        
        **칸 라벨(알파벳 1글자) + 식별번호(숫자 3자리)** = 4자리만 적게 설계
        
    - 실제 조회 시에는 **숫자 3자리 입력만으로 물품 찾기** 가능하게 하는 구조 설계

## **3. 세탁실 사용 등록 시스템**

  

### **3-1. Web vs App 딜레마**

- Web
    - 장점: 설치 필요 없음
    - 단점: 매번 조건 선택 등 UX 복잡, 실시간 알림 한계
- App
    - 장점: 푸시 알림 용이
    - 단점: 설치 저항, 입·퇴사가 잦은 환경과 안 맞음
        
    

  

### **3-2. 1차 개선 시도: Web + NFC + 카카오 연동**(구현x)

- UX 개선: 세탁기마다 NFC 태그 부착 → 터치 시 해당 기기 페이지로 바로 이동
- 알림 개선: 카카오 알림톡/채널톡 연동 시도
- 문제:
    - [호실+개인번호]와 [카카오 ID] 매핑 불가
    - 카카오 API 정책상 비즈니스 채널톡 **자동화 알림 시스템 구축 불가**
- 결과: 카카오톡 연동 아이디어 **전면 백지화**
    

  

### **3-3. 방향 전환: 알림 → “사용 상태 감지”로**(구현x)

- 새로운 질문:
    
    > “알림이 아니라, 애초에 세탁기 ‘사용 중’ 상태를 어떻게 정확히 알까?”
    
- 상태 감지 옵션 비교
    - 스마트 플러그(자동): 고비용, 고장 시 사용 불가
    - 진동 센서(자동): 인식 부정확
    - 수동 입력(수동): 비용 0, 즉시 상용화 유리
- **MVP 결정**:
    - **수동 입력 방식**을 기본으로 채택
    - 단, 추후 스마트 플러그 등 자동화 센서로 확장 가능한 구조로 설계
        
    

  

### **3-4. 수동 입력의 핵심 문제: 원격 선점(Race Condition)**

- 시나리오
    - 웹에서 “사용 가능” 상태 보고 갔는데 도착하니 이미 다른 사람이 사용 중
    - 방에서 원격으로 세탁기 “선점 등록” 후, 실제 세탁실 사용자는 이용 불가
- 결론: **‘도착 인증’ 없이는 등록을 허용하면 안 된다**
    

  

### **3-5. 도착 인증 방식 검토 및 NFC 채택**(구현x)

- 비콘, GPS, WiFi: 실내 정확도/안정성 한계
- QR: 사진 찍어두고 재사용 가능 → 위조 쉬움
- **NFC**: 물리 접촉 필요, **현장 인증에 적합**
- 보안 강화:
    - 단순 NFC URL은 복사·재사용 가능 → **보안 칩(NTAG 424 DNA)** 사용
    - 스캔마다 암호화된 동적 서명 포함 URL 생성
    - 서버에서 비밀 키로 서명 검증 → **“방금 찍힌 유효 스캔”만 인정**
        
    

  

### **3-6. 예약 및 슬롯 제어**(구현x)

- 기기별 상태

## **4. 다목적실 예약 시스템** (구현x)

    - 중복 예약 빈번

### **4-2. 설계 방향**

- 공간 특성: 3개 모두 넓고 **합석 가능**
    - → 합석 가능 여부를 표시하는 **배지(합석 가능 표시)** 도입
- 예약 시스템
    - 주간 캘린더, 매주 월요일 예약 오픈
    - 10분 단위 슬롯 예약
    - 시작/종료 10분 전 푸시·배지 알림
    - 진행 중 예약은 색상으로 표시
- 운영/관리
    - 관리자는 임의 날짜 예약 가능
    - 기숙사생 예약 강제 취소 가능
- 노쇼 신고
    - 예약 시간에 미사용/미체크인 시 다른 거주자가 노쇼 신고 가능
    - 운영 큐에서 관리자 검토 → 확정 시 벌점 2점 자동 부여, 이용 정지 규칙 연동

## 졸업프로젝트에서 에브리타임으로 모았던 내가 계획한 프로젝트 개요
---

### 1. QR 코드 스캔 및 회원가입

- **1.1 QR 코드 스캔**
    - 시연자는 개발자가 제공한 QR 코드를 스캔하여 웹 페이지로 이동
    - 회원가입 후 로그인 진행
- **1.2 팀/개인 참여 선택**
    - **개인 참여**: 바로 기능 선택 및 블록 코딩 진행
    - **팀 참여**:
        
        1. 빈 팀에 입장하거나 관리자에게 방 생성 신청
        2. **팀장 권한 부여**: 관리자가 팀장 권한을 부여하면 팀장이 팀을 생성하고 방 비밀번호 설정 가능
        3. **팀원 참여**: 빈 팀을 찾아 비밀번호 입력 후 입장
        4. **팀원 역할 분배**: 팀장이 팀원의 역할을 나누고, 각 팀원은 맡은 차량 제어 블록을 구현
            

---

### 2. 기능 선택 및 알고리즘 작성

- **2.1 기능 선택**
    - 개인 시연자/팀장은 **차량 제어 기능**을 선택
        - 신호등 인식
        - 정지선 인식 및 정차
        - 차선 추적
        - (추가 논의 필요)
    - 선택하지 않은 기능은 **자동 완성됨**
        - 미리 작성된 알고리즘이 자동으로 채워짐
        - **자동 완성 사용 시 점수 차감** (5점 → 10점 → 20점 순차적 증가)
- **2.2 블록 배치 및 알고리즘 작성**
    - **기본 블록 코딩**: 전진, 후진, 좌/우 회전 등 블록을 배치하여 알고리즘 작성
    - **제출 버튼 클릭**:
        - 작성한 알고리즘을 제출하면 시스템이 자동 분석
        - 미완성/부족한 부분이 있으면 경고 메시지 제공
            

---

### 3. 자동 완성 및 감점 시스템

- **3.1 자동 완성 감지**
    - 미완성 알고리즘이 있을 경우 **자동 완성 버튼 활성화**
    - 자동 완성을 사용하면 **점수 차감**
        - 첫 번째 사용: **5점** 차감
        - 두 번째 사용: **10점** 차감
        - 세 번째 사용: **20점** 차감
- **3.2 자동 완성 사용**
    - 미완성 부분 자동 채우기 가능
    - 자동 완성 후 검토 및 수정 가능
        - > 이때 자동 완성되는 코드는 초창기에 개발자가 작성해둔 코드로 **업데이트가 안된 구식 코드**이다
    - 점수 차감이 누적되므로 시연자가 **직접 알고리즘을 완성할수록 유리**
        

---

### 4. 차량 실행 및 연습 기회 제공

- **4.1 차량 실행 (선택한 기능 구현 실행 기회 1회 제공)**
    - 작성한 알고리즘을 차량 제어 시스템에 적용하여 실행
    - **실시간 동작 확인**
        - 차량이 경로를 따라가는지
        - 장애물을 회피하는지
- **4.2 차량 상태 모니터링**
    - 웹 대시보드에서 차량 상태 확인
    - **차량 속도, 경로 추적, 장애물 감지 데이터 실시간 확인**
        

---

### 5. 알고리즘 평가 및 피드백 제공

- **5.1 차량 성능 평가**
    - 자동 평가 시스템이 차량 성능을 분석
        - 속도
        - 장애물 회피 성능
        - 경로 정확도
- **5.2 피드백 제공**
    - 성능 평가 후 개선이 필요한 부분에 대한 피드백 제공
    - 예: "장애물 회피 성능을 개선하세요."
    - 예: "경로 정확도를 높이기 위해 회전 각도를 조정하세요."
        

---

### 6. 최고 알고리즘 경쟁 및 경기 결과 확인

- **6.1 알고리즘 수정 후 경기 시작**
    - 시연자는 알고리즘을 수정할 시간 부여
    - **최고 알고리즘을 기록한 차량과 경쟁 진행**
    - 경쟁 차량 프로필: 최고 알고리즘을 기록한 시연자/팀/개발자
- **6.2 경기 결과 및 순위 확인**
    - 경기 결과 및 순위 대시보드에서 **실시간 확인**
    - 다른 시연자와 비교 가능
        

---

### 7. 최고 알고리즘 달성 및 시스템 업데이트

- **7.1 최고 알고리즘 달성 알림**
    - 특정 기능에서 최고 성능을 기록하면 **축하 메시지 표시**
    - 예: "축하합니다! 경로 정확도에서 역대 최고의 알고리즘을 달성하셨습니다!"
- **7.2 최고 알고리즘 시스템 반영**
    - 최고 성능 알고리즘을 백엔드 시스템에 저장
    - **경쟁 차량의 알고리즘과 프로필(팀/개인 이름)이 자동 업데이트**
