## 🚀 1. [START HERE] 핵심 요약 및 템플릿

### 1.1. 실수 방지 체크리스트 (요약)

- 입력 많으면 **BufferedReader** **+** **StringTokenizer** **+** **StringBuilder**
- nextInt() 뒤 **nextLine()** **호출 전** **sc.nextLine()**로 개행 소비
- 문자열 비교는 **equals**, 래퍼 비교도 **equals**
- **내림차순 정렬**: `Integer[]` 또는 `Comparator` 사용
- Comparator에서는 **a - b** **대신** **Integer.compare(a,b)** (오버플로 방지)
- 루프에서 문자열 누적은 **StringBuilder**
- `Arrays.asList(arr)`는 **크기 고정** → 가변 필요 시 `new ArrayList<>(…)`
- `ArrayDeque`를 `Queue`/`Stack` 대체로 사용 (빠르고 안전)
- **추가 팁:**
    - `split`은 정규식이라 반복 호출 시 느릴 수 있음 → **StringTokenizer 권장**
    - `Collections.max/min`은 **리스트**에서만, **배열**은 직접 탐색 또는 변환 필요
    - `Integer`를 언박싱할 때 **null**이면 NPE → `getOrDefault` 등으로 방어
        

### 1.2. 자주 헷갈리는 문법 비교표

|**구분**|**올바른 사용**|**틀린 사용 (오류 원인)**|
|---|---|---|
|**문자열 비교**|`str.equals("test")`|`str == "test"` (주소 비교)|
|**배열 내림차순**|`Integer[] arr` + `reverseOrder()`|`int[] arr` (기본형은 `reverseOrder()` 불가)|
|**리스트 정렬**|`Collections.sort(list)` / `list.sort(…)`|`Arrays.sort(list)` (`Arrays`는 배열용)|
|**배열 정렬**|`Arrays.sort(arr)`|`Collections.sort(arr)` (`Collections`는 컬렉션용)|
|**문자열 누적**|`StringBuilder.append()`|`String += …` (루프 시 시간 초과)|
|**배열 길이**|`arr.length`|`arr.length()` (필드, 괄호 없음)|
|**리스트/문자열 길이**|`list.size()` / `str.length()`|(메소드, 괄호 있음)|
|**값 삭제(ArrayList)**|`list.remove(Integer.valueOf(2))`|`list.remove(2)` (인덱스 2를 삭제)|
|**래퍼 비교**|`Integer.valueOf(x).equals(y)`|`Integer == Integer` (캐시 범위(-128~127) 밖)|
|**Comparator**|`Integer.compare(a,b)`|`a - b` (오버플로 위험)|

### 1.3. Collections vs Arrays

|**항목**|**Arrays (배열용)**|**Collections (컬렉션용)**|
|---|---|---|
|**대상**|배열 (`int[]`, `String[]`)|컬렉션 (`List`, `Set`)|
|**정렬**|`Arrays.sort(arr)`|`Collections.sort(list)`|
|**역순**|`Arrays.sort(objArr, reverseOrder())`|`Collections.sort(list, reverseOrder())`|
|**최댓값**|(직접 탐색)|`Collections.max(list)`|
|**최솟값**|(직접 탐색)|`Collections.min(list)`|
|**뒤집기**|(직접 구현)|`Collections.reverse(list)`|
|**채우기**|`Arrays.fill(arr, v)`|`Collections.fill(list, v)`|
|**출력**|`Arrays.toString(arr)`|(그냥 출력 가능)|

### 1.4. 빠른 입출력 템플릿 (실전용)

> [!SUMMARY] 빠른 입출력 (Fast I/O) 템플릿
>
> `BufferedReader`로 입력을 받고 `StringTokenizer`로 파싱하는 `FastScanner` 내부 클래스를 구현한 템플릿입니다. 출력은 `StringBuilder`에 누적했다가 `System.out.print`로 한 번에 출력하여 입출력 속도를 극대화합니다.
```Java
import java.io.*;
import java.util.*;

public class Main {
    static final FastScanner fs = new FastScanner();
    static final StringBuilder out = new StringBuilder();

    public static void main(String[] args) throws Exception {
        int n = fs.nextInt(); // [읽은 정수 (int)]
        for (int i = 0; i < n; i++) {
            int a = fs.nextInt();
            int b = fs.nextInt();
            out.append(a + b).append('\n'); // [자기 자신 (StringBuilder)]을 반환하여 체이닝
        }
        System.out.print(out.toString()); // 마지막에 한번만 출력
    }

    // BufferedReader + StringTokenizer 기반
    static final class FastScanner {
        private final BufferedReader br;
        private StringTokenizer st;

        FastScanner() { br = new BufferedReader(new InputStreamReader(System.in)); }

        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) st = new StringTokenizer(br.readLine());
            return st.nextToken(); // [다음 토큰(단어) (String)]
        }
        
        int nextInt() throws IOException { return Integer.parseInt(next()); } // [파싱된 정수 (int)]
        long nextLong() throws IOException { return Long.parseLong(next()); } // [파싱된 긴 정수 (long)]
        String nextLine() throws IOException { return br.readLine(); } // [읽어들인 한 줄 (String)]
    }
}
```

## ⌨️ 2. 입출력 (I/O)

### 2.1. 입출력 방식 비교

> [!SUMMARY] Scanner vs BufferedReader
>
> - **Scanner:** 사용이 간편하나, 입력 버퍼가 작고 파싱(정규식 기반) 비용이 있어 대용량 입력 시 매우 느릴 수 있습니다. (간단한 입력에 추천)
>     
> - **BufferedReader:** 버퍼를 사용하여 한 번에 많은 데이터를 읽어(I/O 횟수 감소) 빠릅니다. (대용량 입력, 코딩 테스트 주력)
>     
> - **BufferedWriter:** `System.out.println`보다 빠릅니다. `StringBuilder`에 출력을 누적한 뒤 `BufferedWriter`로 한 번에 `write`하는 것이 가장 빠릅니다.
>     

### 2.2. Scanner 사용법 (및 `nextLine` 함정)



```Java
import java.util.*;

Scanner sc = new Scanner(System.in);
//double d = sc.nextDouble(); // [읽어들인 실수 (double)]
//long l = sc.nextLong();     // [읽어들인 긴 정수 (long)]
int a = sc.nextInt();       // [읽어들인 정수 (int)]
String word = sc.next();    // [읽어들인 단어 (String)]
String line = sc.nextLine(); // [읽어들인 한 줄 (String)]
```

> [!WARNING] `nextInt()` 이후 `nextLine()` 개행 이슈
>
> `nextInt()`와 같은 "Token" 기반 읽기는 '엔터' (개행 문자, `\n`)를 버퍼에 남겨둡니다. 이 상태에서 `nextLine()`을 호출하면, 버퍼에 남아있던 `\n`을 읽고 즉시 종료되어 빈 문자열(`""`)을 반환합니다.


```Java
// 버그 상황
int n = sc.nextInt();       // e.g.: "5\n" 입력, 5만 읽고 \n은 버퍼에 남음
String sBug = sc.nextLine(); // e.g.: "" (빈 문자열), 버퍼의 \n을 읽고 종료됨

// 해결
int n2 = sc.nextInt();
sc.nextLine();              // 버퍼의 개행(\n)을 소모시킴
String s = sc.nextLine();   // [정상적으로 읽어들인 한 줄 (String)]
```

### 2.3. BufferedReader / StringTokenizer (빠른 입력)

- **동작:** `System.in`(바이트) → `InputStreamReader`(문자 변환) → `BufferedReader`(버퍼 저장) → `readLine()`(한 줄 읽기)->, `StringTokenizer`로 토큰 단위로 분리
- `StringTokenizer`는 `split()`보다 정규식 비용이 없어, 공백 기준 단순 분리에 더 빠릅니다.


```Java
import java.io.*;
import java.util.*;

BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
String line2 = br.readLine(); // [읽어들인 한 줄 (String)], EOF 시 null

StringTokenizer st = new StringTokenizer(line2);
int x = Integer.parseInt(st.nextToken()); // [파싱된 정수 (int)]
int y = Integer.parseInt(st.nextToken()); // [파싱된 정수 (int)]

// split 사용 (정규식 비용으로 약간 느릴 수 있음)
String[] tokens = line2.split(" ");
```

> [!NOTE]- BufferedReader br = new BufferedReader(new InputStreamReader(System.in)); (펼쳐보기)
>
> 1. **`System.in` (주체: 자바 시스템)**
>     
>     - **행위:** 키보드로부터 **1바이트(byte) 단위**로 데이터를 읽습니다.
>         
>     - **문제:** '한'과 같은 2바이트 이상 문자는 깨집니다.
>         
> 2. **`new InputStreamReader(System.in)` (주체: `InputStreamReader`)**
>     
>     - **행위:** `System.in`의 바이트(byte) 데이터를 문자(char)로 **디코딩(Decoding)**합니다.
>         
>     - **한계:** 문자 1개마다 I/O를 요청하여 여전히 느립니다.
>         
> 3. **`new BufferedReader(InputStreamReader)` (주체: `BufferedReader`)**
>     
>     - **행위:** `InputStreamReader`가 변환한 문자들을 '버퍼(buffer)'에 **미리 왕창 모아 둡니다.**
>         
>     - **효과:** 100만 번의 I/O 호출을 몇 번의 '대량 읽기' I/O로 줄여 성능을 극대화합니다.
>         
> 4. **`br.readLine()` (주체: `BufferedReader`)**
>     
>     - **행위:** 시스템이 아닌, **자신의 메모리(버퍼)에** 채워둔 데이터에서 한 줄(Line)을 통째로 고속으로 읽어 `String`으로 반환합니다.
>         
> 5. **`String line2` (주체: JVM)**
>     
>     - **행위:** `br.readLine()`이 반환한 `String` 객체(예: `"10 20"`)를 `line2` 변수에 저장합니다.
>         
> 6. **`new StringTokenizer(line2)` (주체: `StringTokenizer`)**
>     
>     - **행위:** 문자열(예: `"10 20"`)을 공백 기준으로 `"10"`과 `"20"` 두 개의 토큰으로 분리하여 보관합니다.
>         
> 7. **`st.nextToken()` (주체: `StringTokenizer`)**
>     
>     - **행위:** 보관 중인 다음 토큰(예: `"10"`)을 `String` 타입으로 꺼냅니다.
>         
> 8. **`Integer.parseInt(…)` (주체: `Integer` 클래스)**
>     
>     - **행위:** 문자열 `"10"`을 실제 `int` 타입 숫자 10으로 변환합니다.
>
### 2.4. BufferedWriter / StringBuilder (빠른 출력)

- **동작:** `StringBuilder`(출력 내용 누적) → `bw.write()`(버퍼 저장) → `bw.flush()`(한 번에 출력)
- `System.out.println()`은 호출될 때마다 I/O가 발생하여 느립니다.
    


```Java
import java.io.*;

BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));
StringBuilder out = new StringBuilder();

out.append("answer").append('\n'); // 출력할 내용을 빌더에 누적

bw.write(out.toString()); // [반환값 없음 (void)] (버퍼에 쓰기)
bw.flush();               // [반환값 없음 (void)] (버퍼를 비워 실제 출력)
bw.close();               // (flush()를 포함)
```

_(이후 3. 기본 자료형 및 문자열, 4. 자료구조 … 순서로 이어집니다.)_




> [!NOTE]- 📖 BufferedWriter의 자세한 동작 원리 (펼쳐보기)
>
> 1. **`System.out` (주체: 자바 시스템)**
>     
>     - **행위:** 표준 출력장치(콘솔 화면)으로 **1바이트(byte) 단위**로 데이터를 내보냅니다.
>         
>     - **제약:** '한'과 같은 2바이트 이상 문자를 직접 처리할 수 없습니다.
>         
> 2. **`new OutputStreamWriter(System.out)` (주체: `OutputStreamWriter`)**
>     - **받음** :프로그램이 write() 메소드로 자바의 문자(char) 데이터 전달
>     - **행위:** `System.out`이 알아듣도록 전달받은 문자 데이터를 바이트(byte)단위로 **인코딩(Encoding)**합니다.
>         
>     - **한계:** `write()` 호출마다 '인코딩'과 '콘솔 I/O'가 발생하여 느립니다.
>         
> 3. **`new BufferedWriter(OutputStreamWriter)` (주체: `BufferedWriter`)**
>     
>     - **행위:** `OutputStreamWriter`가 변환할 문자(char) 데이터를 바로 보내지 않고, **'버퍼(buffer)'에 모아 둡니다.**
>         
> 4. **`StringBuilder` 조립 (주체: `StringBuilder`)**
>     
>     - **행위:** `append()`를 통해 출력할 모든 문자열을 메모리에서 고속으로 조립하여 하나의 `String`으로 만듭니다.
>         
> 5. **`bw.write(String)` (주체: `BufferedWriter`)**
>     
>     - **행위:** `StringBuilder`가 만든 `String`을 **자신의 내부 버퍼(임시 저장소)에** 씁니다. (아직 화면에 출력되지 않습니다.)
>         
> 6. **`bw.flush()` (주체: `BufferedWriter`)**
>     
>     - **행위:** "버퍼 비우기" 명령을 수행합니다.
>         
>     - **결과:** 버퍼에 모아둔 모든 데이터를 `OutputStreamWriter`로 **한 번에** 전달하고, 최종적으로 `System.out`으로 단 한 번의 I/O를 통해 출력됩니다.
>
