`String`과 `StringBuilder`의 핵심 차이는 **객체의 불변성(Immutability)** 여부입니다.

- **`String` (Immutable)**
    - `String` 객체는 **불변**합니다.
    - 객체가 한 번 생성되면, 해당 객체의 내부 값은 절대 변경할 수 없습니다.
    - 문자열 연결(`+`)이나 `concat()` 메서드 호출 시, 시스템은 기존 객체를 수정하는 대신 **새로운 `String` 객체를 생성**하여 반환합니다.
- **`StringBuilder` (Mutable)**
    - `StringBuilder` 객체는 **가변**합니다.
    - 객체 생성 후에도 `append()`, `insert()` 등의 메서드를 통해 내부 값을 변경할 수 있습니다.
    - 메서드 호출 시, 시스템은 새 객체를 생성하지 않고 **기존 객체의 내부 버퍼를 직접 수정**합니다.

## 코드 비교

두 클래스의 동작 차이는 객체의 `hashCode()`를 비교하여 명확히 확인할 수 있습니다. `hashCode()`가 변경되면 다른 객체, 동일하면 같은 객체임을 의미합니다.

> [!note]- 1. String (불변) 예시 코드
>
> String은 + 연산 시 hashCode()가 변경됩니다. 이는 새 객체가 생성되었음을 나타냅니다.
>
> Java
>
> ```Java
> // 1. String 초기화
> String str <code>=</code> "Hello";
> System.out.println("초기 문자열: " + str);
> System.out.println("초기 HashCode: " + str.hashCode());
> ```

> // 2. '+' 연산자로 문자열 추가
>
> // 이 시점에 "Hello World"라는 새 String 객체가 생성되고
>
> // str 참조 변수는 이 새 객체를 가리킵니다.
>
> str = str + " World";

> // 3. 결과 확인
>
> System.out.println("변경 후 문자열: " + str);
>
> System.out.println("변경 후 HashCode: " + str.hashCode());
>
> ```Java
> 
> **실행 결과 (예시)**
> ```

> ```Java
> 
> 초기 문자열: Hello
> 초기 HashCode: 69609650
> 변경 후 문자열: Hello World
> 변경 후 HashCode: -1930103348
> 
> ```
>
> (결론: `hashCode()`가 변경되었습니다. 즉, `str` 변수는 완전히 새로운 객체를 참조합니다.)

> [!note] 2. StringBuilder (가변) 예시 코드
>
> StringBuilder는 append() 메서드 실행 후에도 hashCode()가 동일하게 유지됩니다. 이는 기존 객체가 수정되었음을 나타냅니다.
>
> Java
>
> ```Java
> // 1. StringBuilder 초기화
> StringBuilder sb <code>=</code> new StringBuilder("Hello");
> System.out.println("초기 문자열: " + sb.toString());
> System.out.println("초기 HashCode: " + sb.hashCode());
> ```

> // 2. append() 메서드로 문자열 추가
>
> // 이 시점에 새 객체가 생성되지 않고,
>
> // sb 객체의 내부 버퍼가 직접 수정됩니다.
>
> sb.append(" World");

> // 3. 결과 확인
>
> System.out.println("변경 후 문자열: " + sb.toString());
>
> System.out.println("변경 후 HashCode: " + sb.hashCode());
>
> ```Java
> 
> **실행 결과 (예시)**
> ```

> ```Java
> 
> 초기 문자열: Hello
> 초기 HashCode: 1104106489
> 변경 후 문자열: Hello World
> 변경 후 HashCode: 1104106489
> 
> ```
>
> (결론: `hashCode()`가 동일합니다. 즉, `sb` 변수는 기존 객체를 계속 참조하며 내부 값만 변경되었습니다.)

## 요약

- **`String` 사용**
    - **용도:** 변경이 필요 없는 문자열, 상수 문자열(Literals), 맵(Map)의 키 등
    - **특징:** 불변성이 보장되므로, 객체를 안전하게 공유(Share)할 수 있으며 멀티스레드 환경에서 동기화가 필요 없습니다.
- **`StringBuilder` 사용**
    - **용도:** 루프(Loop) 안에서의 문자열 연결, 동적인 쿼리(Query) 생성 등 문자열 수정이 빈번하게 발생하는 경우
    - **특징:** 새 객체를 생성하지 않아 가비지 컬렉션(GC) 부하가 적고 성능이 우수합니다. 단, 스레드 안전성(Thread-safety)을 보장하지 않습니다.
    - (참고: `StringBuffer`는 `StringBuilder`와 기능이 동일하며 스레드 안전성을 보장하지만, 동기화 오버헤드로 인해 성능이 더 낮습니다.)
