> [!note]- String과 StringBuilder의 차이점
> 
> String과 StringBuilder는 Java에서 문자열을 다루는 클래스이며, 불변성(Immutability) 여부가 가장 큰 차이점입니다.
> 
> ### 1. String (Immutable)
> 
> - `String` 객체는 **불변(Immutable)**합니다.
>     
> - 한번 생성된 `String` 객체의 내용은 변경할 수 없습니다.
>     
> - 문자열 연산(예: `+` 결합) 시, 기존 객체를 변경하는 것이 아니라 **새로운 `String` 객체**가 메모리에 생성됩니다.
>     
> - 이 과정은 `s1 <code>=</code> s1 + "World";`와 같이 보이나, 실제로는 새 객체를 `s1`이 참조하게 됩니다.
>     
> 
> **코드 예시:**
> 
> Java
> 
> ```
> String s1 = "Hello";
> // s1의 해시코드(ID) 저장
> int originalHash = System.identityHashCode(s1);
> ```

> // s1에 문자열을 더함
> 
> s1 = s1 + " World"; // 이 시점에 새 String 객체가 생성됨

> // s1이 참조하는 객체의 해시코드(ID) 저장
> 
> int newHash = System.identityHashCode(s1);

> // 두 객체의 해시코드는 다름 (다른 객체임을 의미)
> 
> System.out.println(originalHash != newHash); // true 출력
> 
> ```
> 
> > 
> ``` 

> ### 2. StringBuilder (Mutable)

> - `StringBuilder` 객체는 **가변(Mutable)**합니다.
>     
> - 객체가 생성된 후에도 내용을 수정(추가, 삭제, 변경)할 수 있습니다.
>     
> - `append()` 메서드를 사용하면 **기존 객체**의 내부 버퍼(char 배열)에 내용을 추가합니다. 새로운 객체를 생성하지 않습니다.
>     

> **코드 예시:**

> Java
> 
> ```
> StringBuilder sb = new StringBuilder("Hello");
> // sb의 해시코드(ID) 저장
> int originalHash = System.identityHashCode(sb);
> ```

> // sb에 문자열을 추가(append)함
> 
> sb.append(" World"); // 기존 객체의 내용을 변경함

> // sb가 참조하는 객체의 해시코드(ID) 저장
> 
> int newHash = System.identityHashCode(sb);

> // 두 해시코드가 동일함 (동일한 객체임을 의미)
> 
> System.out.println(originalHash == newHash); // true 출력
> 
> ```
> 
> > 
> ``` 

> ---

> ### 3. 요약

> - **`String`**:
>     
>     - **불변(Immutable)**입니다.
>         
>     - 문자열 연산이 빈번할 경우, 새로운 객체가 계속 생성되어 성능 저하를 유발할 수 있습니다.
>         
>     - 불변이므로 **Thread-Safe**합니다.
>         
> - **`StringBuilder`**:
>     
>     - **가변(Mutable)**입니다.
>         
>     - 단일 스레드 환경에서 문자열을 동적으로, 반복적으로 수정해야 할 때(예: 반복문 내에서의 결합) `String`보다 성능상 유리합니다.
>         
>     - **Thread-Safe 하지 않습니다.** (멀티스레드 환경에서는 `StringBuffer` 사용이 권장됩니다.)
