## 🚀 1. [START HERE] 핵심 요약 및 템플릿

### 1.1. 실수 방지 체크리스트 (요약)

- 입력 많으면 **BufferedReader** **+** **StringTokenizer** **+** **StringBuilder**
- nextInt() 뒤 **nextLine()** **호출 전** **sc.nextLine()**로 개행 소비
- 문자열 비교는 **equals**, 래퍼 비교도 **equals**
- **내림차순 정렬**: `Integer[]` 또는 `Comparator` 사용
- Comparator에서는 **a - b** **대신** **Integer.compare(a,b)** (오버플로 방지)
- 루프에서 문자열 누적은 **StringBuilder**
- `Arrays.asList(arr)`는 **크기 고정** → 가변 필요 시 `new ArrayList<>(…)`
- `ArrayDeque`를 `Queue`/`Stack` 대체로 사용 (빠르고 안전)
- **추가 팁:**
    - `split`은 정규식이라 반복 호출 시 느릴 수 있음 → **StringTokenizer 권장**
    - `Collections.max/min`은 **리스트**에서만, **배열**은 직접 탐색 또는 변환 필요
    - `Integer`를 언박싱할 때 **null**이면 NPE → `getOrDefault` 등으로 방어

### 1.2. 자주 헷갈리는 문법 비교표

|**구분**|**올바른 사용**|**틀린 사용 (오류 원인)**|
|---|---|---|
|**문자열 비교**|`str.equals("test")`|`str == "test"` (주소 비교)|
|**배열 내림차순**|`Integer[] arr` + `reverseOrder()`|`int[] arr` (기본형은 `reverseOrder()` 불가)|
|**리스트 정렬**|`Collections.sort(list)` / `list.sort(…)`|`Arrays.sort(list)` (`Arrays`는 배열용)|
|**배열 정렬**|`Arrays.sort(arr)`|`Collections.sort(arr)` (`Collections`는 컬렉션용)|
|**문자열 누적**|`StringBuilder.append()`|`String += …` (루프 시 시간 초과)|
|**배열 길이**|`arr.length`|`arr.length()` (필드, 괄호 없음)|
|**리스트/문자열 길이**|`list.size()` / `str.length()`|(메소드, 괄호 있음)|
|**값 삭제(ArrayList)**|`list.remove(Integer.valueOf(2))`|`list.remove(2)` (인덱스 2를 삭제)|
|**래퍼 비교**|`Integer.valueOf(x).equals(y)`|`Integer == Integer` (캐시 범위(-128~127) 밖)|
|**Comparator**|`Integer.compare(a,b)`|`a - b` (오버플로 위험)|

### 1.3. Collections vs Arrays

|**항목**|**Arrays (배열용)**|**Collections (컬렉션용)**|
|---|---|---|
|**대상**|배열 (`int[]`, `String[]`)|컬렉션 (`List`, `Set`)|
|**정렬**|`Arrays.sort(arr)`|`Collections.sort(list)`|
|**역순**|`Arrays.sort(objArr, reverseOrder())`|`Collections.sort(list, reverseOrder())`|
|**최댓값**|(직접 탐색)|`Collections.max(list)`|
|**최솟값**|(직접 탐색)|`Collections.min(list)`|
|**뒤집기**|(직접 구현)|`Collections.reverse(list)`|
|**채우기**|`Arrays.fill(arr, v)`|`Collections.fill(list, v)`|
|**출력**|`Arrays.toString(arr)`|(그냥 출력 가능)|

### 1.4. 빠른 입출력 템플릿 (실전용)

> [!SUMMARY] 빠른 입출력 (Fast I/O) 템플릿
>
> `BufferedReader`로 입력을 받고 `StringTokenizer`로 파싱하는 `FastScanner` 내부 클래스를 구현한 템플릿입니다. 출력은 `StringBuilder`에 누적했다가 `System.out.print`로 한 번에 출력하여 입출력 속도를 극대화합니다.
>

```Java
import java.io.*;
import java.util.*;

public class Main {
    static final FastScanner fs = new FastScanner();
    static final StringBuilder out = new StringBuilder();

    public static void main(String[] args) throws Exception {
        int n = fs.nextInt(); // [읽은 정수 (int)]
        for (int i = 0; i < n; i++) {
            int a = fs.nextInt();
            int b = fs.nextInt();
            out.append(a + b).append('\n'); // [자기 자신 (StringBuilder)]을 반환하여 체이닝
        }
        System.out.print(out.toString()); // 마지막에 한번만 출력
    }

    // BufferedReader + StringTokenizer 기반
    static final class FastScanner {
        private final BufferedReader br;
        private StringTokenizer st;

        FastScanner() { br = new BufferedReader(new InputStreamReader(System.in)); }

        String next() throws IOException {
            while (st == null || !st.hasMoreTokens()) st = new StringTokenizer(br.readLine());
            return st.nextToken(); // [다음 토큰(단어) (String)]
        }
        
        int nextInt() throws IOException { return Integer.parseInt(next()); } // [파싱된 정수 (int)]
        long nextLong() throws IOException { return Long.parseLong(next()); } // [파싱된 긴 정수 (long)]
        String nextLine() throws IOException { return br.readLine(); } // [읽어들인 한 줄 (String)]
    }
}
```

## ⌨️ 2. 입출력 (I/O)

### 2.1. 입출력 방식 비교

> [!SUMMARY] Scanner vs BufferedReader
>
> - **Scanner:** 사용이 간편하나, 입력 버퍼가 작고 파싱(정규식 기반) 비용이 있어 대용량 입력 시 매우 느릴 수 있습니다. (간단한 입력에 추천)
>     
> - **BufferedReader:** 버퍼를 사용하여 한 번에 많은 데이터를 읽어(I/O 횟수 감소) 빠릅니다. (대용량 입력, 코딩 테스트 주력)
>     
> - **BufferedWriter:** `System.out.println`보다 빠릅니다. `StringBuilder`에 출력을 누적한 뒤 `BufferedWriter`로 한 번에 `write`하는 것이 가장 빠릅니다.
>     

### 2.2. Scanner 사용법 (및 `nextLine` 함정)

```Java
import java.util.*;

Scanner sc = new Scanner(System.in);
//double d = sc.nextDouble(); // [읽어들인 실수 (double)]
//long l = sc.nextLong();     // [읽어들인 긴 정수 (long)]
int a = sc.nextInt();       // [읽어들인 정수 (int)]
String word = sc.next();    // [읽어들인 단어 (String)]
String line = sc.nextLine(); // [읽어들인 한 줄 (String)]
```

> [!WARNING] `nextInt()` 이후 `nextLine()` 개행 이슈
>
> `nextInt()`와 같은 "Token" 기반 읽기는 '엔터' (개행 문자, `\n`)를 버퍼에 남겨둡니다. 이 상태에서 `nextLine()`을 호출하면, 버퍼에 남아있던 `\n`을 읽고 즉시 종료되어 빈 문자열(`""`)을 반환합니다.

```Java
// 버그 상황
int n = sc.nextInt();       // e.g.: "5\n" 입력, 5만 읽고 \n은 버퍼에 남음
String sBug = sc.nextLine(); // e.g.: "" (빈 문자열), 버퍼의 \n을 읽고 종료됨

// 해결
int n2 = sc.nextInt();
sc.nextLine();              // 버퍼의 개행(\n)을 소모시킴
String s = sc.nextLine();   // [정상적으로 읽어들인 한 줄 (String)]
```

### 2.3. BufferedReader / StringTokenizer (빠른 입력)

- **동작:** `System.in`(바이트) → `InputStreamReader`(문자 변환) → `BufferedReader`(버퍼 저장) → `readLine()`(한 줄 읽기)->, `StringTokenizer`로 토큰 단위로 분리
- `StringTokenizer`는 `split()`보다 정규식 비용이 없어, 공백 기준 단순 분리에 더 빠릅니다.
    
```Java
import java.io.*;
import java.util.*;

BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
String line2 = br.readLine(); // [읽어들인 한 줄 (String)], EOF 시 null

StringTokenizer st = new StringTokenizer(line2);
int x = Integer.parseInt(st.nextToken()); // [파싱된 정수 (int)]
int y = Integer.parseInt(st.nextToken()); // [파싱된 정수 (int)]

// split 사용 (정규식 비용으로 약간 느릴 수 있음)
String[] tokens = line2.split(" ");
```

> [!NOTE]BufferedReader br = new BufferedReader(new InputStreamReader(System.in)); (펼쳐보기)
>
> ### 1. `System.in` (최초 근원지)
>
> - **역할:** ⌨️ **데이터 근원지 (키보드)**
>     
> - **주체:** `System.in` (자바 시스템)
>     
> - **행위:** 키보드로부터 **오직 1바이트(byte) 단위**의 데이터만 읽어들입니다.
>     
> - **제약:** ''한'과 같이 2바이트 이상으로 구성된 문자를 읽을 경우, 1바이트씩 분리되어 읽히므로 글자가 손상되어 이해불가
>

> ### 2. `new InputStreamReader(System.in)` (번역기)
>
> - **역할:** 🗣️ **바이트 → 문자 번역기**
>     
> - **주체:** `InputStreamReader` 객체
>     
> - **생성자 인수:** `System.in` (1번의 '데이터 근원지')

>

>
> - **역할:** 🌊 **문자를 모으는 댐 (버퍼)**
>     
> - **주체:** `BufferedReader` 객체
>     
> - **생성자 인수:** `InputStreamReader` (2번의 '번역기')
>     
> - **행위:**
>

>         
>     2. `readLine()`이 **최초 호출**되면, **인수로 받은 '번역기'에게** **버퍼 크기(예: 8KB)만큼의 대량의 문자 데이터**를 미리 요청하여 자신의 버퍼에 채워 둡니다
>         
>     3. 이후 프로그램이 `readLine()`을 다시 호출하면, **내부 임시 저장 공간('버퍼')에** 가득 모아 둔 데이터들을 고속으로 읽어 반환합니다. (이 작업은 InputStreamReader에 접근하지 않고 메모리에서 일어나므로 매우 빠릅니다.)

>     
> - **주체:** `BufferedReader` 객체 (`br`)
>     
> - **행위:**
>     
>     1. 느린 '번역기'나 '키보드'에 접근하는 대신, **자신의 내부 버퍼(댐)에** 미리 채워둔 데이터를 고속으로 확인합니다.
>         
>     2. 개행 문자(Enter)까지의 모든 문자(예: `"10 20"`)를 **하나의 `String` 객체**로 만들어 반환합니다.
>         
>

>
> - **역할:** ✂️ **문자열 분쇄기 (토크나이저)**
>     
> - **주체:** `StringTokenizer` 객체
>

> - **행위:**

>
> - **역할:** 🔧 **부품(토큰) 꺼내기**
>     
> - **주체:** `StringTokenizer` 객체 (`st`)
>     
> - **행위:** 자신이 보관 중인 다음 순서의 토큰을 **`String` 타입**으로 꺼내어(제거) 반환합니다. (첫 번째 호출 시 `"10"`, 두 번째 호출 시 `"20"`을 반환합니다.)

### 2.4. BufferedWriter / StringBuilder (빠른 출력)

- **동작:** `StringBuilder`(출력 내용 누적) → `bw.write()`(버퍼 저장) → `bw.flush()`(한 번에 출력)
- `System.out.println()`은 호출될 때마다 I/O가 발생하여 느립니다.
    

```Java
import java.io.*;

BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));
StringBuilder out = new StringBuilder();

out.append("answer").append('\n'); // 출력할 내용을 빌더에 누적

bw.write(out.toString()); // [반환값 없음 (void)] (버퍼에 쓰기)
bw.flush();               // [반환값 없음 (void)] (버퍼를 비워 실제 출력)
bw.close();               // (flush()를 포함)
```

> [!NOTE]BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out)); (펼쳐보기)
>
> ### 1. `System.out` (최종 목적지)
>
> - **역할:** 🚚 **데이터 운반 트럭**
>     
> - **주체:** `System.out` (자바 시스템)
>     
> - **행위:** 표준 출력장치(콘솔 화면)으로 **오직 1바이트(byte) 단위**의 데이터만 내보낼 수 있습니다.
>     
> - **제약:** '한'과 같은 2바이트 이상 `char` 문자를 이해하지 못합니다.
>     
> ---
>
> ### 2. `new OutputStreamWriter(System.out)` (번역기)
>
> - **역할:** 🗣️ **문자 → 바이트 번역기**
>     
> - **주체:** `OutputStreamWriter` 객체
>     
> - **생성자 인수:** `System.out` (1번의 '데이터 운반 트럭')
>     
> - **행위:**
>     
>     1. `System.out`을 **인수로 받아** 목적지로 지정합니다.
>         
>     2. 이후 프로그램(혹은 `BufferedWriter`)으로부터 **자바 문자(char) 데이터를 전달받으면,**
>         
>     3. `System.out`이 알아듣도록 **바이트(byte) 데이터로 인코딩(번역)**합니다.
>         
> - **한계:** `write()`가 호출될 때마다 즉시 번역하고 즉시 I/O를 발생시켜 매우 느립니다.
>     
> 
> ---
>
> ### 3. `new BufferedWriter(OutputStreamWriter)` (버퍼/댐)
>
> - **역할:** 🌊 **데이터를 모으는 댐 (버퍼)**
>     
> - **주체:** `BufferedWriter` 객체
>     
> - **생성자 인수:** `OutputStreamWriter` (2번의 '번역기')
>     
> - **행위:**
>     
>     1. `OutputStreamWriter`를 **인수로 받아** 자신의 하위 목적지로 지정합니다.
>         
>     2. 이후 `bw.write()` 메소드로 문자 데이터를 전달받아도, **인수로 받은 '번역기'에게 즉시 보내지 않습니다.**
>         
>     3. 대신, 데이터를 **내부 임시 저장 공간('버퍼')에** 가득 모아 둡니다. (이 작업은 메모리에서 일어나므로 매우 빠릅니다.)
>         
> 
> ---
>
> ### 4. `StringBuilder` 조립 (데이터 조립공장)
>
> - **역할:** 🏭 **출력 데이터 조립공장**
>     
> - **주체:** `StringBuilder` 객체
>     
> - **행위:** `append()`를 통해 출력할 모든 문자열 조각(예: "answer", `\n`)을 메모리에서 고속으로 조립하여, **하나의 거대한 `String` 객체**로 만듭니다.
>     
> 
> ---
>
> ### 5. `bw.write(String)` (버퍼에 붓기)
>
> - **역할:** 🚰 **버퍼(댐)에 데이터 붓기**
>     
> - **주체:** `BufferedWriter` 객체 (`bw`)
>     
> - **메소드 인수:** `StringBuilder`가 `toString()`으로 만든 **하나의 거대한 `String` 객체.**
>     
> - **행위:** 인수로 받은 `String` 데이터를 **자신의 내부 버퍼(댐)에 한 번에** 씁니다.
>     
> - **[중요]** 이 시점까지 콘솔 화면에는 아무것도 출력되지 않습니다. 데이터는 `BufferedWriter`의 버퍼(댐)에 모여있기만 합니다.
>     
> 
> ---
>
> ### 6. `bw.flush()` (방류/출력)
>
> - **역할:** 🌊 **댐 수문 개방 (Flush)**
>     
> - **주체:** `BufferedWriter` 객체 (`bw`)
>     
> - **행위:** "버퍼 비우기" 명령을 수행합니다.
>     
> - **결과 (데이터 흐름):**
>     
>     1. **`BufferedWriter`가** (자신이) 모아둔 모든 문자 데이터를
>         
>     2. **(자신이) 생성자로 받은 `OutputStreamWriter`에게** 한 번에 전달합니다.
>         
>     3. **`OutputStreamWriter`는** 이 대량의 문자 데이터를 바이트로 인코딩(번역)하여
>         
>     4. **(자신이) 생성자로 받은 `System.out`에게** 한 번에 전달(출력)합니다.
>         
> 
> (이 과정은 수많은 `System.out.println()` 호출을 단 한 번의 I/O로 줄여줍니다.)

## 3. **🧱 기본 자료형 및 문자열**
### 3.1 int vs Integer (Wrapper 클래스)

> [!NOTE] 핵심 차이: int vs Integer
>
> - **`int` (기본형, Primitive):** 스택 메모리에 실제 값을 저장합니다. `null`을 가질 수 없으며, 기본값은 `0`입니다.
>     
> - **`Integer` (참조형, Wrapper):** 힙 메모리에 객체로 저장(참조)됩니다. `null`을 허용하며, 컬렉션(e.g., `ArrayList`)에 값을 담을 때 반드시 사용해야 합니다.
>     

기본형(int)과 참조형(Integer)의 선언

```Java
// int - 기본형 (Primitive)
int a = 10;             // e.g.: 10. 스택 메모리에 값이 직접 저장됨 (null 불가)
int[] arr1 = {1, 2, 3}; // 기본형 배열 선언

// Integer - 참조형 (Wrapper)
Integer b = 10;         // e.g.: 10. 힙 메모리에 객체로 저장됨 (null 가능)
Integer c = null;       // e.g.: null. 참조형이므로 null 할당 가능 (주의: 언박싱 시 NPE 위험)
```

자동 박싱 및 언박싱

> [!NOTE] 자동 박싱/언박싱
>
> `int`가 `Integer`로 자동 변환되는 것을 '박싱', `Integer`가 `int`로 자동 변환되는 것을 '언박싱'이라 합니다. 이는 편의를 제공하지만, `null`인 `Integer`를 `int`에 대입하려 하면 `NullPointerException`이 발생할 수 있습니다.

```Java
// 자동 박싱/언박싱
Integer boxed = 100;     // 자동 박싱 (int -> Integer)
int unboxed = boxed;     // 자동 언박싱 (Integer -> int)
```

컬렉션 사용 및 비교 연산

> [!WARNING] 래퍼 클래스 비교 (== vs equals)
>
> - `Integer`와 같은 래퍼 클래스는 객체입니다. == 연산자는 객체의 **주소 값**을 비교합니다.
>     
> - **`Integer` 캐시:** Java는 프로그램이 시작될 때 성능을 위해 -128부터 127까지의 숫자에 해당하는 `Integer` 객체 256개를 미리 전부 생성해서 "캐시 풀(cache pool)"에 보관합니다.
> - 이 범위 내에서는 == 비교가 `true`로 나올 수 있지만, 이 범위를 벗어나면 새로운 객체가 생성되므로 `false`가 나옵니다.
>     
> - **결론:** 래퍼 클래스의 '값'을 비교할 때는 반드시 `.equals()`를 사용해야 합니다.
> - 256인범위인이유: 1바이트의 표현범위(2^8)

```Java
// 컬렉션에는 기본형 불가 -> Integer 사용
ArrayList<Integer> list = new ArrayList<>();
boolean ok = list.add(1); // [추가 성공 여부 (boolean)]

// 주의: 래퍼 비교는 equals() 사용 (==는 주소/캐시 영향)
boolean bad = (Integer.valueOf(127) == Integer.valueOf(127)); // e.g.: true (캐시 구간 -128~127)
boolean bad2 = (Integer.valueOf(128) == Integer.valueOf(128)); // e.g.: false (캐시 범위 밖)
boolean good = Integer.valueOf(128).equals(Integer.valueOf(128)); // [값 일치 여부 (boolean)]
```

### 4.1 배열(Array)

> [!NOTE] 배열 (Array)

## 4.2 ArrayList (동적 배열)

> [!NOTE] ArrayList (동적 배열)
>
> 크기가 가변적인(dynamic-size) 리스트입니다. 내부적으로 배열을 사용하지만, 공간이 부족하면 자동으로 크기를 늘립니다. `int`와 같은 기본형은 저장할 수 없으며, 반드시 `Integer` 같은 래퍼 클래스를 사용해야 합니다.

| 항목     | 배열(Array)    | ArrayList          |
| ------ | ------------ | ------------------ |
| **크기** | 고정           | 가변                 |
| **타입** | 기본형(int) 가능  | 래퍼클래스(Integer)만 가능 |
| **성능** | 빠름           | 약간 느림 (크기 조정 오버헤드) |
| **길이** | `arr.length` | `list.size()`      |
| **접근** | `arr[i]`     | `list.get(i)`      |

> [!WARNING] ArrayList.remove() 함정: 인덱스(int) vs 값(Object)
>
> ArrayList\<Integer>에서 list.remove(2)를 호출하면, '값 2'를 지우는 것이 아니라 **'2번 인덱스'**의 요소를 지웁니다.
>
> '값'을 기준으로 지우려면, list.remove(Integer.valueOf(2))와 같이 객체(래퍼) 형태로 명시해야 합니다.

ArrayList 기본 연산 (추가, 조회, 수정)

```Java

// 추가

// 조회
int v = list.get(0);        // [해당 인덱스의 값 (Integer)]
int sz = list.size();       // [리스트의 크기(요소 개수) (int)]
boolean isEmp = list.isEmpty(); // [리스트가 비었는지 여부 (boolean)]

// 수정
Integer old = list.set(0, 5); // [수정되기 전의 이전 값 (Integer)]
```

배열 ↔ 리스트 변환

```Java
List<Integer> boxedList = Arrays.stream(ints).boxed().collect(Collectors.toList()); // [스트림을 통해 변환된 리스트 (List<Integer>)]

// 리스트 → 배열 (권장 패턴)
String[] back = mut.toArray(new String[0]); // [변환된 새 배열 (String[])]

// 리스트(Integer) → int 배열 (Stream 사용)
int[] back2 = boxedList.stream().mapToInt(Integer::intValue).toArray(); // [스트림을 통해 변환된 배열 (int[])]
```

## 4.3 Map, Set, Queue, Stack

> [!NOTE] HashMap (해시 맵)

### 4.4 PriorityQueue (우선순위 큐)

> [!SUMMARY] PriorityQueue (우선순위 큐)
>
> 힙(Heap) 자료구조를 기반으로 하며, 요소를 추가할 때마다 정렬 상태를 유지합니다.
>
> - **기본 (Min-Heap):** 가장 작은 값이 최상단에 위치합니다. (`poll` 시 최솟값 반환)
>     
> - **Max-Heap:** `Collections.reverseOrder()`를 통해 가장 큰 값이 최상단에 위치하도록 설정합니다. (`poll` 시 최댓값 반환)
>     

최소 힙 (Min-Heap, 기본)

```Java
import java.util.*;

// 최소 힙(기본)
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.offer(5);
minHeap.offer(2);
minHeap.offer(8);
Integer min = minHeap.poll(); // [우선순위가 가장 높은 값(최솟값) (Integer)]을 제거하며 반환  //2를 제거하며 반환 
```

최대 힙 (Max-Heap)

```Java
// 최대 힙
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
maxHeap.offer(5); 
maxHeap.offer(2); 
maxHeap.offer(8);
Integer max = maxHeap.poll(); // [우선순위가 가장 높은 값(최댓값) (Integer)]을 제거하며 반환
```

## ⚙️ 5. 정렬 (Sort & Comparator)

알고리즘에서 정렬은 데이터를 원하는 순서대로 바꾸는 핵심 로직입니다. 자바는 `Arrays.sort()` (배열용)와 `Collections.sort()` 또는 `list.sort()` (리스트용)를 제공합니다.

### 5.1. 정렬의 3요소 (Comparator의 이해)

복잡한 정렬을 하려면 '정렬 규칙'을 `Comparator`로 만들어 `sort()` 메소드에 전달해야 합니다.

1. **`Arrays.sort(arr, …)` (행위자, 메소드)**
    - "정렬해!"라고 **일을 시키는 주체(메소드)**입니다.
        
2. **`Comparator` (규칙 설명서, 인터페이스)**
    - `Arrays.sort()`에게 "어떤 기준으로 정렬할지" 알려주기 위한 **'설명서 양식'(타입)**입니다.
        
3. **`(a, b) -> …` (실제 규칙 내용, 람다식)**
    - `Comparator` 양식에 맞춰 사용자가 작성한 **'실제 내용물'(구현체)** 입니다.
    - 이 내용은 두 값(`a`, `b`)을 받아 `int` 값(부호)을 반환함으로써 정렬 순서를 지정합니다.
        

> [!WARNING] ⚠️ [필수] Comparator 정수 비교: 뺄셈(`a-b`) 금지
>
> `(a, b) -> a[0] - b[0]` 방식은 뺄셈 **결과값의 부호**로 순서를 파악합니다.
>
> 하지만 `a[0]`과 `b[0]`의 값 차이가 `Integer.MAX_VALUE`를 넘어가면 **오버플로(Overflow)**가 발생하여, **부호가 반대로** 뒤집힐 수 있습니다. (예: `20억 - (-15억)` -> `35억` (오버플로) -> **음수**가 됨)
>
> `Integer.compare(a[0], b[0])`는 뺄셈 없이 대소 관계(`<`, == , `>`)를 직접 비교하여 `-1`, `0`, `1`을 반환하므로 **절대적으로 안전**합니다.
>
> ---
>
> **[안전한 비교 메소드]**
>
> - **정수 타입:** `Integer.compare(a, b)` / `Long.compare(a, b)`
>     
> - **실수 타입:** `Double.compare(a, b)` / `Float.compare(a, b)`
>     
> - **객체 타입:** `a.compareTo(b)` (e.g., `String`)
>ay)

### 5.2. 1차원 배열 정렬 (Array)
- **오름차순:** `Arrays.sort()`를 기본으로 사용합니다.
- **내림차순:** `Collections.reverseOrder()`를 사용해야 하며, `int[]`같은 **기본형(primitive) 배열에는 작동하지 않습니다.** `Integer[]` **래퍼(Wrapper) 배열**을 사용해야 합니다.

```Java
// 1. 오름차순 (기본형 int[] 가능)
int[] arr = {5, 2, 8, 1};
Arrays.sort(arr); // [1, 2, 5, 8]

// 2. 내림차순 (래퍼 Integer[] 필요)
Integer[] arrDesc = {5, 2, 8, 1};
Arrays.sort(arrDesc, Collections.reverseOrder()); // [8, 5, 2, 1]

// (참고) int[] -> Integer[] (내림차순/컬렉션 연동 시) 
int[] a2 = {1, 5, 3}; // 예시용 int[] 
Integer[] boxed = Arrays.stream(a2).boxed().toArray(Integer[]::new); // [변환된 래퍼 타입 배열 (Integer[])]
```

### 5.3. 리스트 정렬 (ArrayList)

- `list.sort()` (권장) 또는 `Collections.sort()`를 사용합니다.
- List는 래퍼 타입만 받으므로 내림차순에 제약이 없습니다.

```java
List<Integer> list = new ArrayList<>(Arrays.asList(5, 2, 8, 1));

// 1. 오름차순
Collections.sort(list); // [1, 2, 5, 8]
// (권장) list.sort(Integer::compare);

// 2. 내림차순
Collections.sort(list, Collections.reverseOrder()); // [8, 5, 2, 1]
// (권장) list.sort(Collections.reverseOrder());

```

### 5.4. 2차원 배열 / 리스트 정렬 (Lambda 활용)

`Comparator` 람다식을 사용하여 복잡한 정렬 기준을 만듭니다.

```Java
// 예제 배열
int[][] items = {{1, 30}, {3, 10}, {2, 50}, {3, 5}};

// --- 1. 단일 기준으로 정렬(반환값없음) ---

// 1-1. 첫 번째 열(items[0]) 기준 오름차순
Arrays.sort(items, (a, b) -> Integer.compare(a[0], b[0]));
// 결과: [[1, 30], [2, 50], [3, 10], [3, 5]]

// 1-2. 두 번째 열(items[1]) 기준 내림차순
Arrays.sort(items, (a, b) -> Integer.compare(b[1], a[1]));
// 결과: [[2, 50], [1, 30], [3, 10], [3, 5]]

// --- 2. 복합 기준으로 정렬(반환값없음) ---

// 2-1. 첫 번째 열(items[0]) 오름차순,
//      같으면 두 번째 열(items[1]) 내림차순
Arrays.sort(items, (a, b) -> {
    int c = Integer.compare(a[0], b[0]); // 1. 첫 열 오름차순
    if (c != 0) {
        return c; // 첫 열이 다르면, 그걸로 정렬
    }
    // 첫 열이 같으면 (c == 0), 두 번째 열 내림차순
    return Integer.compare(b[1], a[1]); 
});
// 결과: [[1, 30], [2, 50], [3, 10], [3, 5]]
```

### 5.5. 람다를 이용한 정렬 (기본)

람다(Lambda)는 `Comparator`를 간결하게 표현하는 익명 함수입니다. (원래 7번 섹션에 있던 내용)

```Java

//오름차순 정렬(람다)
L.sort((a,b) -> Integer.compare(a,b)); // [반환값 없음 (void)]
//내라차순 정렬(람다)
L.sort((a,b) -> Integer.compare(b,a)); // [반환값 없음 (void)]

List<String> S = Arrays.asList("a","bbb","cc");
//문자열 길이 순 정렬(람다)
S.sort((s1,s2) -> Integer.compare(s1.length(), s2.length())); // [반환값 없음 (void)]
```

우선순위큐 람다 커스텀 정렬 (Lambda, 2차원 배열)

```Java
// 커스텀 비교: (value, idx) 쌍을 value 오름차순
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
pq.offer(new int[]{7, 0});
pq.offer(new int[]{3, 1});
```
