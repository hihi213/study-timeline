## **기숙사 관리 PWA 핵심 기능 요약**
- **핵심 원칙**:
    - **역할 기반 접근 제어 (RBAC)**: 최고 관리자 / 일반 관리자 / **층별장(검사자)** / 입주자
    - **로그인 필수**: 모든 기능은 로그인 후 사용
    - 모든 알림은 관련 화면으로 **딥링크** 연결
    - **감사 및 추적**: 모든 주요 활동은 로그로 기록하여 추적성 확보
	- 첫 프로젝트임을 감안해 최대한 구현요소 줄이기, 합칠수있는 요소 합치기
		- 예시: 유저의 페이지와 관리자 페이지를 분리하되, 유저의 UI를 활용해 관리자 페이지를 만든다 혹은 관리자의 UI에 몇 요소를 비활성환 UI를 유저 페이지로 만든다.
		- 과하게 세분화된 기능을 하나의 기능으로 통일
	- 난이도는 백엔드 신입정도가 구현해보면 좋은것 정도로 하지만 실무자도 까다로워하는 과한 기능, 구현들은 제외
### **1. 프로젝트 개요 및 공통 정책**

- **형태**: PWA (Progressive Web App) 모바일 웹
-  백그라운드: **PWA + FCM 는 꼭, 포그라운드: SSE**로 시작
	- FCM, VAPID모두 사파리 알림 지원함
	- 보이지 않는 푸시 알림은 불가
	- **PWA 오프라인 캐시 최소 세트**
	    - 홈·내역·상세(최근 본 항목)만 precache. “네트워크 대기 없이 열림” 체감 개선.
- **표준 Web Push(=VAPID) + Service Worker + 딥링크**  
    Spring에서 `web-push-java`로 보내고, 구독정보는 이미 있는 `user_notification_subscriptions`에 저장/관리.
- **SSE**는 “화면 열려 있을 때”만 실시간 배지/목록 동기화용.  
    (알림 도달 보장은 Push, 화면 갱신은 SSE.)

### **2. 모듈별 상세 기능**
### 2.0 관리자 기능
- **자원 관리**: 각기능의 자원을 유저에게 할당하고, 자원을 추가하거나 편집, 삭제
- 자원 상태 전환: 유저의 이용여부와 상관없이 강제 상태전환가능
	- **한 번에 상태 수정**: 관리자 화면에서 다중 선택 후 일괄 상태변경(냉장고 칸/세탁기/스터디룸 공통).
- 벌점 조정
- 층별장 임명/해제
- 스터디룸 **강제 예약**: 날짜 제한 없이 특정 시간대에 예약을 생성.
#### **2.1 냉장고**

- **핵심 개념**:
    - **검사 단위**: 검사는 '층'이 아닌 냉장고의 **'칸(Compartment)' 단위**로 진행됩니다.
    - **스티커 규격**: 현장 스티커에는 `칸번호(1자리) + 식별번호(3자리)` 형태의 **4자리 숫자**를 기입합니다.
- **사용자 기능**:
    - **물품 등록**: 단일 품목 또는 여러 품목을 한 번에 등록하는 **묶음 등록** 지원. 등록 시 단일품목/묶음일시 묶음 단위로 고유 **식별 번호** 자동 발급.
    - **번호 재사용**: 기존에 사용하던 물품을 모두 소진(`REMOVED` 상태)하면, 해당 번호를 **즉시 재사용**하여 새 물품 등록 가능.
    - **조회 및 관리**: '내 물품만 보기'를 기본으로, 유통기한 임박/만료 등 필터링 및 식별 번호로 검색 기능 제공.
    - **상태 변경**: `부분 소비`, `전량 제거`, `번호 변경`, `칸 이동` 등 다양한 관리 작업을 버튼 하나로 처리.
    - **충돌 해결**: 칸 이동 시 번호가 중복될 경우, 시스템이 자동으로 다음 빈 번호를 찾아 부여하는 **'자동 재번호(AUTORENUMBER)'** 옵션을 제공.
    - 물품 수정: 수량, 유통기한, 메모 수정가능
- **층별장(검사자) 기능**:
    - **검사 모드**: 검사 시작 시 해당 칸의 물품을 **사용자들이 수정할 수 없도록 잠금** 처리.
    - **동시 검사 지원**: **층별장 2명이 동시에 검사를 진행**할 수 있으며, 시스템은 **어떤 검사자가 어떤 물품을 처리했는지 개별적으로 이력을 기록**함.
    - **세분화된 조치**:
        - `⚠️ 경고`: 정보 불일치 / 보관상태 불량 / 스티커 미부착 (DB에는 등록된 물품)
        - `🗑️ 폐기`: 유통기한 지남 (벌점 동반 가능) / 스티커 미부착 (DB에 없는 물품)
    - **미부착 처리**: 스티커가 없는 미등록 물품도 즉시 폐기 등록 가능.
    - **결과 제출 및 수정**: 제출 시 통계 리포트가 자동 생성되고 알림이 발송됩니다. **제출 후에도 운영상 필요시, 사유를 입력하고 결과를 수정할 수 있으며 모든 변경 이력은 기록됩니다.**
#### **2.2 세탁실**

- **사용자 흐름**:
    1. **현황 확인**: 대시보드에서 **즉시 사용 가능한 기기**를 확인하고, 사용 중인 기기의 진행률과 남은 시간을 확인합니다.
    2. **대기**: 사용 중인 기기는 **'종료 알림'을 신청**하거나, 실제 남은 시간이 다를 경우 **시간을 정정**할 수 있습니다 (원사용자에게 알림 전송).
    3. **사용 등록**: 기기를 선택하고 시간을 설정한 뒤 사용을 시작합니다. '종료 5분 전 알림' 설정 및 개인별 **사용 시간 프리셋 저장**이 가능합니다.
    4. **미등록 사용 발견**: 다른 사람이 등록 없이 사용 중인 기기를 발견하면, 다른 사용자를 위해 **대신 남은 시간을 등록**해줄 수 있습니다.
    5. **종료 후 미회수 처리**: 세탁이 끝난(`DONE`) 후 5분이 지나도 세탁물이 방치된 경우, **"기다리고 있어요" 알림**을 보내거나, **"세탁물 빼놨어요" 알림**을 보내고 기기 상태를 `사용 가능`으로 변경할 수 있습니다.
    6. **고장 신고**: 누구나 고장 신고를 할 수 있으며, 신고된 기기는 `ERROR_REPORTED` 상태로 변경되어 사용이 차단됩니다.
- 세탁실 사용자 흐름
	
	1. 대시보드에서 **바로 사용 가능** 기기 최상단 그룹화, 실시간 진행바/남은시간 표시.
	2. 다른 사람이 사용 중이면 **종료 전 알림 신청** 또는 **남은시간 정정**(정정 시 원사용자에게 알림, 종료 알림도 자동 보정).
	3. **사용 등록**: 기기 상세에서 시간 설정 및 “종료 5분 전 알림” 설정 후 시작.
	    
	    - 기본시간: 세탁기 38분, 건조기 50분. **1분/10분 단위** 증감,
	    - 사용자별 **프리셋 저장** 가능(고민중)
	        
	4. **미등록 사용(UNAUTHORIZED_USE)** 발견 시 대신 남은시간 등록 가능(헛걸음 방지). 기본으로 종료 알림 **비활성**(선택 가능). 설정 시간 경과 시 자동 `AVAILABLE` 전환.
	5. **종료 이후** `DONE` 상태에서 5분 경과에도 `AVAILABLE`로 안 바뀌면:
	    
	    - 다른 사용자가 **“기다리고 있어요” 알림(1회)** 또는 **“세탁물 빼놨어요” 알림**(강제 `AVAILABLE` 전환) 전송 가능.
	    - 이전 사용자에게 **필터 청소 요청**/ **세탁물 회수 완료** 알림 전송 기능.
	    - 이때 필터 청소는 건조기에만 해당된다.
	        
	6. **고장 신고**: 누구나 신고 가능 → `ERROR_REPORTED`(사용 차단, 신고자/사유 표기). 관리자가 접수하면 `OUT_OF_SERVICE`로 전환.
        
- **상태 정의**:
    - **기본**: `AVAILABLE` (사용 가능) → `IN_USE` (사용 중) → `DONE` (완료) → `AVAILABLE`
    - **특수**: `UNAUTHORIZED_USE` (미등록 사용), `ERROR_REPORTED` (고장 신고됨), `OUT_OF_SERVICE` (사용 중지)
- 특수 상태: `UNAUTHORIZED_USE`(미등록 사용 등록: 타임스탬프 경과 시 자동 복귀), `ERROR_REPORTED`(신고됨), `OUT_OF_SERVICE`(관리자 확정 비활성).
- 관리자 수동 제어 시, 해당 기기 사용자에게 별도 알림 전송.

#### **2.3 도서관**

- **사용자 기능**:
    - **검색**: 제목/저자/도서번호로 검색.
    - 인기/신규텝 :“최근 n주 대출수/등록일 정렬”만
    - **원스톱 처리**: 상세 팝업 창에서 대출, 반납, 연장, 예약 등 모든 작업을 한 번에 처리.
    - **자동 알림 및 벌점**: 반납일 5일 전에 알림을 받고, 연체 시 자동으로 벌점 부과.
- **관리자 기능**:
    - **도서 관리**: 도서의 등록, 수정, 분실, 삭제 처리.

#### **2.4 스터디룸**

- **사용자 기능**:
    - **타임라인 뷰**: 시간대별 예약 현황을 한눈에 파악하고 예약.
    - **예약 정책**: **매주 월요일**에 해당 주간 예약이 오픈되며, **10분 단위**로 예약 가능.
    - **합석 표시**: 예약 시 '합석 가능' 여부를 뱃지로 표시하여 다른 사용자와 공간 공유 가능.
- 미등록사용, 노쇼 신고 기능
    - 원클릭 신고→ 상대방 1회 알림 + 관리자 큐 적재(벌점은 수동). 자동 제재는 보류.

#### **2.5 마이페이지**
- **간단 통계 위젯(마이페이지 상단)**
    - 이번 주 이용 횟수/시간 합계, 벌점 변화만 막대 2~3개. 쿼리·캐시 단순.
- **통합 이력**: 모든 내역을 시간순으로 조회.(전체,세탁,도서,스터디룸,냉장고,상벌점내역 필터) 이때 상벌점 다른 페이지로 분리하는게 성능상 좋을지 고민중
- **설정**: 상벌점 내역 확인 및 알림 수신 여부, 세탁 프리셋 등 개인 설정 관리

### **3. 운영 정책**

- **휴관 모드**:
    - 관리자가 휴관 모드를 활성화하면 일반 사용자의 로그인이 제한됩니다.
    - 휴관 시작 시 모든 냉장고의 물품이 일괄적으로 소프트 삭제 처리됩니다.

# **통일·단순화 제안 (도메인 공통화)**

- **리소스 모델 단일화**
    - Resource(type: FRIDGE|WASHER|DRYER|ROOM|BOOK)

        Unit(칸/기기/룸/권) – State – Reservation/Usage – Issue(고장·신고) – Action(경고·폐기·벌점).

    - 장점: 상태머신/감사로그/알림을 한 번만 구현.
- **상태머신 공통 규약**
    - 기본: AVAILABLE → IN_USE/RESERVED → DONE → AVAILABLE
    - 특수: UNAUTHORIZED_USE, ERROR_REPORTED, OUT_OF_SERVICE는 전 모듈 공통 상수로.
- **알림 이벤트 표준화**
    - RESERVATION_OPENED/REMINDER_5M/DONE/NO_SHOW_SUSPECT/ADMIN_OVERRIDE 등 공통 코드로 발행.
- **감사로그 스키마 고정**
    - who(사용자/역할) · what(이벤트코드) · target(Resource/Unit/RecordId) · when · why(메모)

        모든 화면의 “이력”은 이 로그를 그대로 필터링해서 재사용(마이페이지 통합 이력 = 감사로그 뷰).

- **역할별 UI 재사용**
    - 검사자/관리자 화면을 “사용자 상세 + 추가 액션 버튼” 패턴으로 일원화(기능 숨김/비활성화).
- **벌점 처리**
    - 벌점은 즉시 반영하되 규칙은 단순 상수(예: 연체 1회 = 1점). 규칙엔진은 이후 단계.
**모듈별 다듬기(제거/보류/경량화)**

**냉장고**

- 동시 검사: “칸 단위 잠금”만 유지(글로벌 락 X). 잠금 만료시간(예: 5분) 도입해 교착 방지.
- ‘자동 재번호’만 유지하고 수동 충돌 해결 UI는 보류(초기엔 중복 케이스 희박).

**세탁실**

- ‘남은 시간 정정’은 ±10분 범위로 제한 + 사유 필수(남용 방지, 로직 단순).
- 미등록 사용 등록 시 기본값은 종료 알림 비활성 유지(이미 설계대로 👍).
- 필터 청소 알림은 **건조기에서만** 노출(분기 간결).

**도서관**

- 예약 대기열은 1명만 허용(다중 대기열은 보류).

**스터디룸**

- 합석은 “뱃지 표시”까지만. 자동 매칭은 보류.
- 강제 예약(관리자)은 UI를 사용자 예약 다이얼로그 재사용 + “관리자용 스위치”만 추가.
