# **6주 MVP(기능 단위 · 실행 순서)배포**

1. 코어/인증/RBAC

- Spring Boot 21, JPA, Flyway, PostgreSQL 연결.
- JWT 로그인/로그아웃.
- 역할: ADMIN_ROOT, ADMIN, INSPECTOR(=층별장), RESIDENT.
- 사용자/권한 API 최소 세트.

2. DB 스키마 확정 및 마이그레이션

- users/roles/user_roles, resources(FRIDGE_COMP + position_order, comp_kind), item_bundles.
- 부분 유니크 (resource_id,label_no WHERE removed_at IS NULL).
- inspection_sessions/participants/results/revisions, penalties_*, resource_locks(expires_at DEFAULT 5m), event_log(actor_user_id,reason).

3. 냉장고: 물품 등록

- 서버에서 SNNN 라벨 발급. label_no 충돌 방지.
- 단일/묶음 등록, 메모, 유통기한.
- 시드 리소스(냉장1·2·냉동1).

4. 냉장고: 물품 관리

- “내 물품” 목록, 상세, 수정, 전량 제거.
- 식별번호 검색. 부분 소비는 **보류**(MVP는 수량 직접 수정).

5. 점검(층별장)

- 세션 생성(칸 잠금 TTL 5분). 참가자 2인.
- 결과 액션 PASS/WARNING/DISCARD(_WITH_PENALTY) + 사유.
- 제출 후 수정 시 사유 필수, 리비전 적재.
- 벌점: 원본 생성(불변), 조정 테이블, 합산 뷰.

6. 실시간(포그라운드)

- **SSE /events** 단일 스트림. 하트비트 20–30s. Last-Event-ID 지원.
- 이벤트 소스: event_log 쓰기 후 SSE fan-out.
- **폴백**: /event-log?sinceId= 폴링.

7. 마이페이지 최소

- 내 알림 인박스(읽음 플래그).
- 이번 주 이용 수, 벌점 합계 카드.

8. 관리자 최소

- 층별장 임명/해제.
- 냉장 칸 상태 변경(사용/정지).
- 벌점 수동 조정.

9. 배포/운영

- Docker Compose(backend+db+nginx).
- GitHub Actions: 빌드·테스트·배포.
- HTTPS(Nginx), 로깅, 슬로우쿼리 로그.
- 지표 최소: /actuator/health, pg_stat_statements 설치만.
- Sentry 도입은 **보류**.

데모 기준: 로그인→물품 등록→내 물품 조회/수정→층별장 점검→제출 후 수정(이력 생성)→SSE 알림 표시.

# **6주 이후(우선순위 순)**

P1) 백그라운드 알림 = **Web Push**

- Service Worker, VAPID 구독 저장(push_subscriptions).
- 워커 큐(due_tasks)로 D-1 유통기한, 점검 결과, 예약 임박 전송.
- 딥링크 라우팅, collapse key, 재시도/백오프.

P2) 세탁실

- 리소스 타입 WASHER/DRYER. 상태머신(AVAILABLE/IN_USE/DONE/OUT_OF_SERVICE).
- 사용 시작/종료, 남은 시간 추적, 고장 신고.
- 포그라운드 SSE 반영, 백그라운드 Web Push “종료 5분 전/종료”.

P3) 다목적실(예약)

- 주간 타임라인 조회. 10분 단위 예약/취소.
- 월요일 00:00 오픈 스케줄러.
- 미등록 사용 신고. EXCLUDE 제약 또는 충돌 검증.

P4) 도서관

- 검색(TRGM 인덱스 활성 시점), 대출/반납/연장, 예약 대기 1명.
- 연체 자동 벌점. 리마인더 푸시.

P5) 운영/관측 고도화

- 관리자 자원 CRUD 일괄작업. 휴관 모드.
- Prometheus + Grafana, Sentry.
- 인덱스 재평가(CONCURRENTLY), 아카이빙 설계.

- **W6**: 9, 배포·HTTPS·CI/CD, 통합 테스트, 버그픽스.

# **냉장고: 6주 제출 범위(MVP)**

핵심 목표: “스티커 라벨 기반 물품 등록·조회·점검”을 처음부터 끝까지 데모 가능하게.

**기능**

- 로그인+RBAC: ADMIN_ROOT/ADMIN/INSPECTOR/RESIDENT.
- 물품 등록: 단일/묶음, compartment 선택, label_no 자동 추천, 번호 재사용(REMOVED 즉시).
- 조회/수정: “내 물품”, 식별번호 검색, 부분 소비/전량 제거.
- 점검(층별장): 칸(Compartment) 단위 **잠금**(TTL 5분), 동시 2인 허용, 경고/폐기 기록, 제출 후 수정(사유 필수, 전체 이력).
- 알림 최소화: 점검 결과 묶음 알림, 유통기한 임박 묶음(하루 1회). 배지는 인앱만.
- 통계: 점검 결과 요약(경고/폐기 건수), 칸별 사용량.

**아키텍처**

- Spring Boot 3 + Java 21, PostgreSQL, JWT.
- 잠금: Redis(권장) 또는 DB 행 잠금+만료필드(대체).
- 마이그레이션: Flyway. 모듈 계층: domain/application/adapter.

**완료 기준**

- 모바일 웹에서 등록→스티커 기입→점검 잠금→경고/폐기→결과 요약까지 **데모 시연**.
- 동시 점검 충돌 테스트 2케이스 통과.
- 하루 1회 임박 묶음 생성 배치 동작.

## 6주 데모 구현 계획
- 6주: 인앱알림, 폴링으로 구현, 로그인, 냉장고기능구현(등록/조회/수정/1인검사)
- 6주후 계획
	- **고급 기능**: 층별장 2인 검사, 검사 중 칸 잠금(TTL), 관리자용 대시보드(휴관 모드, 강제 예약 등)
	- **실시간 알림 및 동기화**: `Web Push`,`SSE`
	- **배포 및 운영**: `AWS/OCI`, `Docker`, `CI/CD`, `모니터링` (데모는 로컬 실행으로 충분합니다)
	- **냉장고 외 모든 모듈**: `세탁실`, `도서관`, `다목적실`

## Phase 1: 기반 시스템 및 핵심 기능 (냉장고)

> **목표**: 사용자가 로그인하고 가장 중요한 기능인 '냉장고'를 사용할 수 있는 최소한의 백엔드 시스템을 완성합니다.

1. **코어 시스템: 프로젝트 설정**
    
    - Spring Boot 프로젝트 생성 (Java 21), 의존성 설정
    - PostgreSQL DB 연동 및 JPA Entity 설계
        
2. **코어 시스템: 사용자 인증 및 권한 (RBAC)**
    
    - Spring Security 및 JWT 기반의 로그인/로그아웃 API 구현
    - 역할(ADMIN_ROOT, ADMIN, INSPECTOR, RESIDENT) 기반 API 접근 제어 설정
        
3. **냉장고: 물품 등록 (입주자)**
    
    - 단일/묶음 물품 등록 API 구현
    - 서버에서 스티커 코드(`SNNN`) 자동 발급 및 `label_no` 유일성 보장 로직 구현
        
4. **냉장고: 물품 관리 (입주자)**
    
    - 내 물품 목록 조회, 상세 정보 수정, 삭제(상태 변경) API 구현
    - 식별 번호로 내 물품 검색 기능 구현
        
5. **냉장고: 점검 (층별장)**
    
    - 담당 칸의 모든 물품 조회 API 구현
    - 물품 상태 변경(`경고`, `폐기`) 및 사유 기록 API 구현
    - 점검 후 수정 기능 (사유 필수, 이력 기록) API 구현

    - 알림 읽음 처리 로직 구현 (관련 화면 진입 시 자동 처리)
        
12. **마이페이지**
    
    - 나의 통합 이용 이력 조회 API 구현
    - 간단한 통계 위젯(이번 주 이용 횟수, 벌점 변화 등) API 구현

    - 알림 클릭 시 앱의 관련 페이지로 이동하는 딥링크 기능 구현

## Phase 5: 배포 및 모니터링

> **목표**: 개발된 애플리케이션을 실제 서버에 배포하고 안정적으로 운영합니다.

16. **컨테이너화**: Docker/Docker Compose를 사용하여 애플리케이션 환경을 이미지로 관리
17. **리버스 프록시**: Nginx를 이용해 HTTPS 적용 및 서버 부하 분산 설정
18. **CI/CD 자동화**: GitHub Actions를 통해 코드 변경 시 자동으로 테스트 및 배포가 이루어지도록 파이프라인 구축
19. **배포**: AWS Lightsail 또는 OCI Always Free 등 클라우드 서버에 배포
20. **모니터링**: Prometheus, Grafana를 이용해 서버 상태 및 성능을 시각화하고, Sentry로 에러를 추적하는 시스템 구축
