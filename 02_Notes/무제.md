# 기숙사 관리 PWA – 최종 설계 요약 v1.0 (2025-10-05)

> **목표**: 첫 프로젝트로서 구현 요소를 최대한 줄이되, 실사용에 필요한 핵심만 정확히 제공. 공통화/표준화로 재사용성을 극대화하고, 역할 기반 접근 제어와 추적 가능성을 기본값으로 한다.

---

## 1) 핵심 원칙

- **RBAC**: 최고 관리자 / 일반 관리자 / **층별장(검사자)** / 입주자.
- **로그인 필수**: 모든 기능 로그인 후 사용.
- **딥링크 필수**: 모든 알림은 관련 화면으로 연결.
- **감사/추적**: 모든 주요 이벤트는 **감사로그**에 적재, 화면의 이력 뷰는 감사로그 필터 재사용.
- **단순화**: 초기 스코프에서 세분화/자동화 과도 기능은 보류. 관리자/검사자 화면은 **사용자 UI 재사용 + 추가 액션 버튼** 패턴.

---

## 2) 기술 아키텍처

### 2.1 PWA & 실시간 통신

- **형태**: 모바일 우선 PWA.
- **오프라인 캐시(최소 세트)**: `홈 / 내역 / 상세(최근 본 항목)` **precache**. 나머지는 runtime cache(네트워크 우선 + 짧은 스테일)로 체감 성능 확보.
- **백그라운드 알림: 표준 Web Push(VAPID) + Service Worker + 딥링크**
    - 서버(Spring)에서 **VAPID 공개/비밀 키**로 웹푸시 서명 후 브라우저 엔드포인트로 전송. 브라우저가 내부적으로 APNs/FCM을 중계하므로 **APNs 개발자 구독 없이** 동작.
    - **iOS 16.4+**: **홈 화면에 추가된(PWA 설치) 상태**에서만 웹푸시 수신/권한 요청 가능 → 설치 유도 배너/가이드를 제공.
    - **무음(silent) 푸시 불가**: 사용자 가시 알림을 반드시 표시. 화면 갱신은 딥링크 또는 SSE로 처리.
    - **페이로드 가이드**: ≤ **4KB**, 대형 리소스는 링크로. 공통 필드: `deeplink`, `event_code`, `target_type`, `target_id`, `meta`.
    - **신뢰성/큐 제어**: `TTL`/`Urgency`/`Topic` 헤더 활용. 응답 **410(Gone)** 시 구독 삭제, **429/5xx**는 지수 백오프 재시도.
- **포그라운드 동기화: SSE(EventSource) 고정**
    - 탭이 열려 있을 때만 서버→클라이언트 단방향 스트림으로 배지/목록/진행률 갱신.
    - **자동 재연결**, `Last-Event-ID`, **심장박동**(예: 30초마다 주석 프레임)으로 연결 상태 유지.
    - **인프라 설정**: 프록시 버퍼링 해제, `read_timeout` 연장(예: 1h), gzip off 권장.
- **포그라운드 알림 표시: Notifications API + 인앱 토스트**
    - 문서가 **보이는 상태(visible)** 에서는 **인앱 토스트/배지 우선**, 시스템 알림은 최소화해 중복 방지.
    - 권한 요청은 **사용자 제스처 이후 1회**만 노출. iOS는 설치(PWA) 후 권한 프롬프트 가능.
- **권한/설치 UX**
    - iOS 첫 방문 시 **“홈 화면에 추가” 가이드** 제공(설치 감지 후 자동 숨김).
    - 설치 직후 초기 실행에서 권한 요청 및 알림 프리뷰(딥링크 포함) 1회 송신.
    - (선택) **Declarative Web Push(iOS 최신)** 지원 시 서비스워커 로직 단순화 가능.

### 2.2 딥링크 스키마

- 웹 경로 기반: `https://<host>/{module}/{id}?t=<tab>&ref=<src>`
- 알림 Payload 공통 키: `deeplink`, `event_code`, `target_type`, `target_id`, `meta`.

### 2.3 에러/신뢰성 공통

- **락 TTL**: 검사/일괄처리 등 잠금은 기본 TTL **5분**(만료 시 자동 해제).
- **서버 시간 기준**: 남은시간/만료 계산은 서버 UTC 기준 + 클라이언트 드리프트 보정.
- **멱등성 키**: 상태전환/예약 생성은 `Idempotency-Key` 헤더 허용.

## 4) 공통 도메인 모델

### 4.1 리소스 단일화

- **Resource**(type: `FRIDGE|WASHER|DRYER|ROOM|BOOK`)
    - **Unit**(칸/기기/룸/권) – **State** – **Reservation/Usage** – **Issue**(고장·신고) – **Action**(경고·폐기·벌점)
- 장점: **상태머신/감사로그/알림 공통화**로 구현량 감소.

### 4.2 상태머신(공통 규약)

- **기본**: `AVAILABLE → IN_USE|RESERVED → DONE → AVAILABLE`
- **특수**: `UNAUTHORIZED_USE`, `ERROR_REPORTED`, `OUT_OF_SERVICE`(전 모듈 공통 상수)

### 4.3 감사로그 스키마(고정)

- `who(userId, role) · what(event_code) · target(resource/unit/recordId) · when · why(memo)`
- 화면 이력(마이페이지/관리 콘솔)은 **감사로그 뷰 재사용**.

### 4.4 알림 이벤트 표준화

- `RESERVATION_OPENED` / `REMINDER_5M` / `DONE` / `NO_SHOW_SUSPECT` / `ADMIN_OVERRIDE` 등 공통 코드 발행.

## 5) 모듈 상세

### 5.0 관리자 공통

- **자원 관리**: 유닛 추가/편집/삭제, 유저 이용권한 할당.
- **자원 상태 일괄변경**: 다중 선택 → 상태 전환(냉장고 칸/세탁기/스터디룸 공통).
- **벌점 조정**, **층별장 임명/해제**.
- **스터디룸 강제 예약**: 날짜 제한 없이 날짜 예약가능

### 5.1 냉장고
- **사용자 기능**
    - 단일 품목 또는 여러 품목을 한 번에 등록하는 묶음 등록기능-> 등록시 식별번호 발급되고 사용자는 식별번호를 적은 스티커를 물품에 부착해야한다.
    - **번호 재사용**: 해당 번호가 `REMOVED`면 즉시 재사용 가능.
    - 조회: 기본 "내 물품", 필터(임박/만료), **식별번호 검색**.
    - 상태 변경: `부분 소비`, `전량 제거`
    - 물품정보 수정
- **층별장(검사자) 기능**
    - **검사 모드**: 검사 시작 시 해당 칸 **잠금**(사용자 수정 불가, TTL 5분).
    - **동시 검사**: 2명 동시 가능, **검사자별 처리 이력** 분리 기록.
    - **조치**: `⚠️ 경고`(정보 불일치/보관 불량/스티커 미부착-DB엔 존재), `🗑️ 폐기`(유통기한 지남/DB에 없는 미부착).
    - **미부착 처리**: 미등록 물품도 즉시 폐기 등록 가능.
    - **결과 제출/수정**: 제출 시 통계/알림 발송. **제출 후 수정 가능(사유 필수, 이력 모두 기록)**.
- **경량화 결정**
    - 동시 검사는 **칸 단위 잠금**만 유지(글로벌 락 X). 잠금 만료시간 **5분**.
    - 수동 충돌해결 UI **보류**, **자동 재번호만** 지원.

### 5.2 세탁실 (상세구현에서 자세히 정의함)

### 5.3 도서관

- **사용자**: 제목/저자/도서번호 검색, 
- 인기/신규 탭(최근 N주 대출수·등록일 정렬), **원스톱 팝업**에서 대출/반납/연장/예약.
- **알림/벌점**: 반납일 **5일 전 알림**, 연체 시 **자동 벌점**.
- **관리자**: 도서 등록/수정/분실/삭제.
- **경량화**: **예약 대기열은 1명만** 허용.

### 5.4 스터디룸

- **타임라인 뷰**로 시간대별 예약 현황, **10분 단위** 예약.
- **예약 정책**: **매주 월요일** 해당 주간 예약 오픈.
- **합석**: **뱃지 표시만**(자동 매칭 보류).
- **신고**: 미등록사용/노쇼 **원클릭 신고** → 상대방 1회 알림 + **관리자 큐** 적재(벌점은 수동 처리).
- **강제 예약(관리자)**: 사용자 다이얼로그 **재사용** + 관리자 스위치.

### 5.5 마이페이지

- **간단 통계 위젯**: 이번 주 이용 횟수/시간, 벌점 변화(막대 2~3개, 쿼리/캐시 단순).
- **통합 이력**: 전체/세탁/도서/스터디룸/냉장고/상벌점 필터. (성능 필요 시 상벌점 별도 페이지 분리 고려)
- **설정**: 상벌점 내역, 알림 수신 여부, 세탁 프리셋 등.

## 7) 데이터 모델(최소 스케치)

- `users(id, name, role, ...)`
- `roles(id, code)` / `user_roles(user_id, role_id)`
- `resources(id, type, name)`
- `units(id, resource_id, label, state, meta)`
- `records(id, unit_id, type, payload)` ← 냉장고 물품/도서 대출/세탁 사용 등 **공통 레코드** 저장(유형별 payload JSON)
- `reservations(id, unit_id, user_id, starts_at, ends_at, state)` ← 스터디룸 등
- `usages(id, unit_id, user_id, started_at, expected_end_at, ended_at, state)` ← 세탁/건조 등
- `issues(id, unit_id, reporter_id, type, memo, state)` ← 고장/신고
- `actions(id, target_id, code, memo, created_by)` ← 경고/폐기/벌점 등
- `penalties(id, user_id, code, points, reason, created_at)`
- `audit_logs(id, who, role, event_code, target_type, target_id, why, created_at)`
- `notifications(id, user_id, event_code, payload, delivered_at)`
- `user_notification_subscriptions(id, user_id, endpoint, keys, ua, created_at)`

> **비고**: 초기엔 단일 DB 스키마로 시작, 모듈 분리 전까지는 공통 테이블로 운영.

## 8) API 개요(REST-ish)

- `POST /auth/login`
- `GET /me`(권한/설정)
- `GET /resources?type=` / `POST /resources`
- `GET /units?resourceId=` / `PATCH /units/{id}/state`
- `POST /reservations` / `PATCH /reservations/{id}` / `DELETE /reservations/{id}`
- `POST /usages` / `PATCH /usages/{id}`
- `POST /issues` / `PATCH /issues/{id}`
- `POST /actions` (경고/폐기/벌점)
- `GET /audit-logs?target=&who=&event=`
- `POST /push/subscribe` / `DELETE /push/subscribe`
- `GET /sse` (토큰 필요, 모듈/리소스별 채널)

## 10) UX/화면 구성(요약)

- **홈**: 내 예약/사용 요약 + 공지/휴관 배너 + 빠른 액션(세탁 등록, 스터디룸 예약).
- **내역**: 모듈 통합 타임라인(감사로그 뷰), 필터/검색.
- **상세**: 단일 상세에서 모든 원스톱 처리(대출/반납/연장/예약/사용/정정 등).
- **관리 콘솔**: 사용자 상세 + **추가 액션 버튼**(벌점/임명/일괄변경/강제예약). 검사/관리 공통 레이아웃.

## 11) 성능·보안·운영

- **권한 가드**: 라우터/서버 더블 체크.
- **레이트 리밋**: 상태전환, 정정, 신고, **푸시 전송 API**에 사용자/유닛 기준 제한.
- **VAPID 키 관리**: 서버 측 안전 저장(HSM/키보관소), **주기적 롤테이션** 및 롤백 전략.
- **푸시 신뢰성**: 410 구독 정리, 지수 백오프, 중복 방지(Topic/Tag), 알림 클릭 핸들러에서 **포커스 탭 라우팅**.
- **SSE 안정화**: 프록시 타임아웃/버퍼링 설정, 서버 keepalive, 클라이언트 백오프.
- **낙관적 UI + 충돌 처리**: 버전/ETag로 병행 수정 방지.
- **로깅/모니터링**: 감사로그 + 매트릭(푸시 성공률/만료율/SSE 재연결/알림 클릭률) 대시보드.

## 12) 출시 스코프(필수) vs 보류(필수) vs 보류

**필수(첫 배포)**

- PWA 기본 + 최소 precache
- 표준 Web Push + 딥링크, SSE(포그라운드)
- RBAC/감사로그/상태머신 공통 모듈
- 냉장고: 등록/검사(칸 잠금, 자동 재번호), 경고/폐기, 제출/수정
- 세탁실: 사용 등록/정정(±10분), 미등록 사용, 종료 후 알림, 고장 신고, 관리자 차단
- 도서관: 검색, 원스톱 처리, 반납 5일 전 알림, 연체 벌점
- 스터디룸: 타임라인, 월요일 오픈, 10분 단위, 합석 뱃지, 신고, 강제 예약(관리자)
- 마이페이지: 간단 위젯, 통합 이력, 설정

**보류/경량화**

### 메모

- Safari(iOS/macOS)는 **표준 Web Push**를 지원하며, 개발자는 **VAPID만** 사용하면 됨(별도 APNs 유료 구독 불필요).
- iOS는 **홈 화면 추가(PWA 설치)** 조건에서만 웹푸시 권한/수신 가능. 설치 가이드 UX 필수.
- **보이지 않는 푸시 금지**: 가시 알림 원칙 준수. 화면 갱신은 SSE로.
- 프록시/SSE 설정은 환경별로 차이가 크므로 사전 부하 테스트 권장.

## 구현상세 (변경해도 됨)
- **검사 단위**: 층이 아니라 **칸(Compartment) 단위**.
- **스티커 규격**: `칸번호(1자리)+식별번호(3자리)` → **4자리 숫자**.
- 단일품목일시 단일품목단위/묶음일시 묶음 단위 고유 **식별번호 자동 발급**
	- 단일품목: 이름, 메모, 유통기한 입력 수량은 1로 선택되어있음
	- 이때 수량을 증가시키면 묶음이되고 세부수정 버튼이 활성화되고 숫자만큼 물품이 생성됨
		- 기존입력했던 이름->대표이름, 기존입력했던 메모->대표메모
		- 개별이름, 개별유통기한, 기존입력했던 이름, 유통기한으로 자동 입력되고 세부수정 버튼시 수정하고 최종 등록 가능
- 물품 칸이동 기능 넣을까 말까 고민중
- 최근 검사일 이후 물품정보 수정시 다음 검사일때 자동분류됨
### 세탁실
- 사용자 흐름
    1. 세탁실 메인 페이지의 대시보드에서 **바로 사용 가능** 기기 상단 그룹 + 진행바/남은시간이 표시됨을 확인
    2. 기기클릭시 상세팝업이 뜨고: 
	    - INUSE인 경우
		    - 그 기기에대해 유저가 보낸 메세지 목록 표시
			    - 사용중인 사람이 읽음 여부가 표시됨
			- 자신이 설정에서 설정한 알림전송여부 간략히 표시
				- 종료알림을 꺼놓았습니다. 라는 간단한 텍스트만 보이고 실제 수정은 설정앱에서 수정하게 하기
		    - 타인의 사용인경우
			    - 종료 알림 신청 또는 **남은시간 정정**(정정 시 원사용자에게 알림, 종료 알림 자동 보정).
		    - 자신의 사용인경우
			    - 남은시간 정정(알림x)
	    - AVAILABLE 상태인경우
		    - **사용 등록**: 기본시간(세탁기 38분 / 건조기 50분), **1분/10분 단위 증감**, 개인 **프리셋 저장**(옵션).
		    - **미등록 사용(UNAUTHORIZED_USE)** 발견 시 대신 남은시간 등록(종료 알림 **기본 비활성**). 설정 시간 경과 시 자동 `AVAILABLE`.
		    - 이전 사용자에게 다음엔 **필터 청소 요청**(필터 청소는 **건조기만** 해당)
		- DONE인경우
	    -  `DONE` 후 5분 경과 시
	        - **"기다리고 있어요" 알림(1회성)** 또는 **"세탁물 빼놨어요" 알림**(+ 강제 `AVAILABLE`). 활성화
    3. **고장 신고**: 누구나 가능 → `ERROR_REPORTED`(사용 차단, 신고자/사유 기록). 관리자가 접수 시 `OUT_OF_SERVICE`.
        
- **상태 정의**
    - **기본**: `AVAILABLE` (사용 가능) → `IN_USE` (사용 중) → `DONE` (완료) → `AVAILABLE`
	- 특수: `UNAUTHORIZED_USE`(미등록 사용 등록: 타임스탬프 경과 시 자동 복귀), `ERROR_REPORTED`(신고됨), `OUT_OF_SERVICE`(관리자 확정 비활성). `OUT_OF_SERVICE` (사용 중지)
	- 관리자 수동 제어 시, 해당 기기 사용자에게 별도 알림 전송.
- **경량화/가드레일**
    - **남은시간 정정은 ±10분**, **사유 필수**(남용 방지).
    - 관리자 수동 제어 시, 해당 기기 사용자에게 **별도 알림**.
