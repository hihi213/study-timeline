


비동일계에서 컴퓨터학과로 편입 후 첫 학기 세 과목조차 버거워 휴학한 뒤, 사비로 참여한 부트캠프에서 처음으로 몰입을 하게됐습니다. 새벽 첫차를 타며 2주간 '공 피하기' 게임을 직접 만들고 동기들에게 보여주며 짜릿했습니다. 이후 복학해 4.0 이상의 학점으로 수료했으나 이론에만 치중해 프로젝트 경험이 부족했고, 현장 문제를 모두 반영하려던 졸업작품 DormMate는 설계만 비대해져 마감에 쫓기듯 AI에 구현을 의존했습니다.

학점 수료 후 혼자 백엔드를 처음부터 재구축하려 했으나, 마감과 동료가 없는 방 안에서는 설계와 규칙만 고치다 기능 하나도 제대로 완성하지 못하는 한계를 절감했습니다. 동료와 부딪히며 외적 압박을 받을 때 가장 빠르게 성장함을 알기에 지원했습니다.

첫 3개월은 기획서를 바탕으로 Spring 구현부터 React 전환·배포까지 내 손으로 완주하고, 이어지는 팀 프로젝트에서는 백엔드를 맡아 설계 근거를 검증하겠습니다. 수료 후에도 동료들과 커넥션을 이어가며 서로 압박하고 성장하는 환경을 만들겠습니다

올해 졸업작품 DormMate의 AI 생성 백엔드를 걷어내고 Spring 기초부터 직접 다시 짜는 학습을 시작했습니다. 그러나 학점 수료 및 자격증 준비와 겹친 데다 혼자 방대한 기능을 마주하자 막막함이 커졌고, 심할 때는 한 달에 한 번 들여다볼 만큼 학습이 사실상 끊겼습니다.

왜 손이 움직이지 않는지 돌아보니, Spring 경험이 부족한 상태에서 모든 기능을 완벽히 짜려다 시작조차 못 하고 있었고 막히면 또 AI에게 코드를 통째로 맡기게 될까 봐 주저하고 있었습니다. 이를 바꾸기 위해 무작정 코딩하기보다 진입 장벽을 낮추고 AI 의존을 막는 'AI 협업 규칙'부터 개정해 학습을 다시 시작했습니다.

첫째, AI의 역할을 개념 설명(GUIDE)과 리뷰(REVIEW)로 제한해 프로젝트와 무관한 최소 예제만 참고하고 본 코드는 제가 직접 치도록 고정했습니다. 둘째, 결정을 '직접 결정·표준 수용·보류'로 나누어 인증과 냉장고 CRUD로 범위를 좁혔습니다. 셋째, 초반 입문 Task 1–2는 완료 기준과 문서 부담을 대폭 낮춰, 거창한 설계 대신 첫 API 하나를 내 손으로 직접 작성하고 5줄 결정 메모를 남기는 단계부터 다시 밟아가고 있습니다.

2025년 2–12월 약 10개월간 개인 졸업작품 DormMate를 진행하며, 세탁실의 현장 인증 방법을 정하는 작업에서 3일간 막혔습니다. 초기에는 비용과 유지보수를 고려해 수동 등록을 기본으로 잡았으나, 사용자가 방에서 웹으로 기기를 선점해 실제 현장 이용자를 방해할 수 있다는 허점이 보였습니다.

처음에는 기기 앞에 QR이나 일반 NFC 태그를 붙이면 해결될 줄 알았습니다. 그러나 브라우저 요청 흐름을 살펴보니 QR 사진이나 일반 NFC의 고정 URL을 복사해 원격에서도 그대로 재사용할 수 있었습니다. 대안으로 GPS·Wi-Fi·비콘도 조사했지만 실내 측위 오차와 운영상 제약이 남았습니다.

원인을 파고든 끝에 문제를 '스캔하는 방법'에서 '인증정보의 복사·재사용 방지'로 다시 정의했습니다. 이후 스캔할 때마다 암호화된 동적 인증값과 읽기 카운터가 변하는 NTAG 424 DNA를 도입해 서버에서 검증하는 방식을 대안으로 도출했습니다. 비록 실제 장비 연동이나 공격 테스트까지는 못 해 보안성을 완전히 입증하진 못했지만, 정상 동작뿐 아니라 악용 가능성과 검증의 한계를 확인하며 기술 선택의 기준을 배웠습니다.

트러스트 20s 아이디어톤에서 팀 주제를 정할 때, 팀원들은 제가 제안한 주제가 각자의 관심사와 달랐다는 피드백을 주었습니다.

저는 시니어층을 공략한 제 아이디어가 더 경쟁력 있다고 생각했기에 처음에는 동의하기 어려웠습니다. 하지만 개인적으로 좋은 아이디어라고 판단하는 것과, 제한된 기간 안에 팀원 모두가 몰입해 끝까지 구체화할 수 있는 주제는 다르다고 보았습니다.

그래서 제 주장을 고집하는 대신 팀이 선택한 팩트체크 서비스로 방향을 바꾸는 데 동의하고, 이후 사용자 흐름 설계와 기획안 구체화를 주도적으로 맡아 결과물을 완성했습니다.
