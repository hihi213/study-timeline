비동일계 편입 첫 학기에는 세 과목조차 따라가기 어려워 휴학했습니다. 격차를 줄이고자 사비로 참여한 부트캠프에서 처음로 새벽 첫차를 타며 2주간 JavaScript 게임을 직접 구현했을 때, 동료들과 부딪히며 성장하는 짜릿함을 처음 배웠습니다. 그러나 복학 후 이론 공부에만 치중한탓에 구현 경험에 없었고. 그에비해 졸업프로젝트는 설계만 비대해져 결국 마감에 쫓기듯 AI에 구현을 의존했습니다.

통과 후 아쉬움이 남아 기존 백엔드를 걷어내고 혼자 Spring 기초부터 재구현을 시도했습니다. 하지만 피드백 없이 광범위한 범위를 홀로 마주하자 우선순위를 잡지 못해 발이 묶였고, 옛날 같은 몰입과 성장이 멈춘 듯한 무력감을 겪었습니다.

이를 통해 저는 명확한 이정표와 동료가 있는 환경에서 굴러야 폭발적으로 성장하는 사람임을 깨닫고 지원했습니다. 첫 3개월 개인 프로젝트에서는 기획서를 바탕으로 정해진 호흡 안에 Spring 서버부터 React 전환, 배포까지 완주하며 개발 기본기를 다지겠습니다. 이어지는 팀 프로젝트에서는 동료들과 치열하게 우선순위를 조율하며 기술적 근거를 책임지는 백엔드 개발자로 거듭나겠습니다.


#### 문항 2. 학습 지속성 (목표 600자 이내 / 공백 포함 약 538자)


비동일계 편입 후 부족한 CS 기초를 메우기 위해, 최근 1년간 매일 오전 8시부터 저녁 7시까지 전공 학습 내용을 마크다운 노트(Obsidian)로 구조화하는 학습을 이어왔습니다. 학기당 전공 5과목을 수강하며 당일 배운 개념과 실습을 그날 밤 정리하는 주기로 진행했습니다.

  

초기에는 생성형 AI로 강의록을 요약하는 데 급급해 노트가 길어지기만 했고, 학기가 끝난 뒤 흐름이 한 번 끊겼습니다. 다시 노트를 펼쳐보니 명령어와 정의만 나열되어 있어 왜 이 기술이 필요한지 기억나지 않는 시험 대비형 공부였음을 깨달았습니다.

  

이를 다시 잇기 위해 두 가지를 바꿨습니다. 첫째, 모든 주제 첫머리에 '빌드업(Why & Context)' 항목을 두어 그래프 인접 행렬이 왜 필요한지 등 기술의 등장 배경과 트레이드오프부터 내 문장으로 적었습니다. 둘째, 정보처리기사 실기 등을 준비할 때는 질문만 보이고 클릭해야 답이 펼쳐지는 접기식 콜아웃(Callout) 형식을 도입해 스스로 답을 인출하며 점검했습니다. 수동적 요약을 '원리와 검증 중심의 기록'으로 바꾼 덕분에 평점 4.33 달성과 자격증 준비까지 1년간 멈추지 않고 지속할 수 있었습니다.

  

#### 문항 3. 개발 기본기 (목표 700자 이내) — 아래 2가지 중 실제 말하기 편한 쪽 선택


졸업 프로젝트 'DormMate' 통과 후, AI에 의존해 급히 만들었던 백엔드를 걷어내고 약 3주간 혼자 Spring Boot 기초부터 재구현하던 중이었습니다. 그중 기숙사 세탁실 및 공용 냉장고 이용 상태를 관리하는 도메인과 API를 다시 짜는 작업에서 닷새 이상 진도를 나가지 못하고 막혔습니다.

  

처음에는 제 Spring 문법 지식이 부족해서 코드가 안 써지는 줄 알았습니다. 하지만 며칠간 작성하던 코드를 지우고 다시 쓰기를 반복하며 제가 막히는 순간들을 역추적해 보니 원인은 다른 곳에 있었습니다. 작은 프로젝트를 직접 완성해 본 기본기가 없는 상태에서, 기본 CRUD조차 돌아가기 전에 '실제 유저가 악용할 허점'이나 '구형 세탁기 연동 확장성' 같은 모든 예외 케이스를 초기 설계에 한꺼번에 구겨 넣으려다 보니 테이블 구조와 비즈니스 로직이 끝없이 복잡해졌던 것입니다.

  

원인을 파악한 뒤 모든 예외 상황을 한 번에 방어하려던 무거운 설계를 멈추고, 최소한의 핵심 기능만 작동하는 단위로 쪼개어 구현 순서를 다시 정의했습니다. 비록 혼자 힘으로 전체 서비스를 끝까지 재구축하지는 못했지만, 내 코드가 왜 앞으로 나아가지 못했는지 설계와 구현의 선후 관계를 뼈저리게 복기한 경험이었습니다.

방학 중 부트캠프에서 HTML과 순수 JavaScript만을 활용해 2주간 '공 피하기' 게임을 개인적으로 구현할 때였습니다. 전체 게임 제작에는 2주가 걸렸고, 그중 사방에서 날아오는 공과 플레이어 캐릭터의 충돌 판정이 간헐적으로 씹히거나 허공에서 게임이 종료되는 문제로 이틀간 막혔습니다.

  

처음에는 키보드 이벤트가 늦게 입력되어 발생하는 현상이라 추측하고 이동 속도 변수를 조정했으나 해결되지 않았습니다. 원인을 정확히 찾기 위해 프레임마다 실행되는 루프 함수를 멈추고, 캐릭터와 공의 중심 좌표, 반지름, 이동 벡터 값을 매 프레임 콘솔과 화면에 직접 출력하며 충돌 순간의 수치를 비교했습니다.

  

추적 결과 두 가지 원인을 발견했습니다. 첫째, 이미지의 왼쪽 상단 꼭짓점을 기준으로 거리를 계산해 실제 원형 이미지의 중심점과 판정 위치가 어긋나 있었고, 둘째, 공의 속도가 빨라질 때 한 프레임 이동 거리가 커지면서 캐릭터를 그대로 통과해 버리는 현상이 있었습니다. 이를 해결하기 위해 중심점 좌표를 보정하고 프레임당 이동 단위를 세분화하여 정확한 충돌 판정을 구현할 수 있었습니다.
