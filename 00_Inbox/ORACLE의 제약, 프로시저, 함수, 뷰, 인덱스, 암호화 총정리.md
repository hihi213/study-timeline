# 📜 Oracle DB 객체 정의 및 핵심 메커니즘 정리

데이터베이스 객체(Object)는 데이터의 무결성(Integrity), 보안(Security), 성능(Performance)을 보장하기 위한 핵심 구성 요소입니다. 아래 내용은 Oracle SQL 문법을 기준으로 작성되었습니다.

---

## 1. 제약 조건 (Constraints)

데이터의 **무결성(정확성 및 일관성)**을 보장하기 위한 강제 규칙입니다. 데이터 입력(`INSERT`) 및 수정(`UPDATE`) 할때 엔진 레벨에서 실시간 검증이 수행됩니다.
### 🛠️ 기본 문법 구조

```SQL
CONSTRAINT [제약조건명] [제약유형] (적용컬럼) [REFERENCES 부모테이블(컬럼) [ON DELETE 옵션]]
```
### 🧩 구성 요소 분해

- **`CONSTRAINT 제약명`**
    - 제약 조건에 **식별자**를 붙여주는 것입니다. (생략시 자동으로 부여됨)
    - 나중에 에러가 났을 때 *"fk_name 제약 조건 위배"* 라고 원인을 찾기위해 붙임
2. **`제약유형`**: (필수) 어떤 규칙을 적용할지 결정합니다.
    - `PRIMARY KEY`: 유일성 + NOT NULL (테이블당 1개), 선언 시 **Unique Index**가 자동 생성
    - `FOREIGN KEY`: 참조 무결성 (부모 테이블에 없는 값은 자식 테이블에 입력 불가합니다.).
    - `CHECK`: 사용자 정의 조건 (예: `SAL > 0`).
3. **`REFERENCES … ON DELETE [CASCADE|SET NULL]`**: (선택) **외래키(FK) 전용 옵션**입니다.
    - **`CASCADE`**: 부모 데이터 삭제 시 자식 데이터도 **자동 삭제**.
    - **`SET NULL`**: 부모 데이터 삭제 시 자식 데이터를 **NULL로 변경**.
    - 생략 시: 자식이 참조 중이면 부모 데이터 삭제 **불가** (에러 발생).
### 🛠️ 정의 방식

제약 조건은 컬럼 정의 시 바로 선언하는 **컬럼 레벨**과, 테이블 정의 마지막에 몰아서 선언하는 **테이블 레벨**이 있습니다. 기능상의 차이는 거의 없으나, **가독성과 관리의 편의성** 때문에 구분해서 사용합니다.

- **기본 문법 구조**

```SQL
CREATE TABLE 테이블명 (
    -- [1] 컬럼 레벨 정의 (컬럼 선언과 동시에)
    컬럼명1 데이터타입 [CONSTRAINT 제약명] PRIMARY KEY,
    컬럼명2 데이터타입 NOT NULL,
    컬럼명3 데이터타입 UNIQUE,

    -- [2] 테이블 레벨 정의 (모든 컬럼 선언 후 하단에)
    컬럼명4 데이터타입,
    
    -- 기본키(PK) 정의
    CONSTRAINT 제약이름표 PRIMARY KEY (컬럼명1),
    -- 외래키(FK) 정의
    CONSTRAINT 제약이름표 FOREIGN KEY (컬럼명4) 
        REFERENCES 부모테이블(참조컬럼) [ON DELETE CASCADE | SET NULL]
);
```


| **제약 조건**         | **설명 및 특징**                                                                                                                                          |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`PRIMARY KEY`** | **유일성(Unique) + `NOT NULL`**. 테이블당 1개만 존재 가능하며, 선언 시 **Unique Index**가 자동 생성됩니다.                                                                     |
| **`FOREIGN KEY`** | **참조 무결성** 보장. 부모 테이블에 없는 값은 자식 테이블에 입력 불가합니다.<br>• `ON DELETE CASCADE`: 부모 삭제 시 자식도 자동 **삭제**<br>• `ON DELETE SET NULL`: 부모 삭제 시 자식 값을 **NULL**로 변경 |
| **`UNIQUE`**      | 중복 값을 허용하지 않음. 단, **`NULL`은 중복 입력 가능**합니다.                                                                                                           |
| **`CHECK`**       | 특정 조건(도메인)을 만족해야 함. `NULL`은 검사 대상에서 제외됩니다.  <br>_(예: `CHECK (SALARY > 0)`)_                                                                          |
| **`NOT NULL`**    | 반드시 값이 입력되어야 함. (주로 컬럼 레벨에서 정의)                                                                                                                      |

## 2. 프로시저 (Procedures)
주로 데이터의 상태를 변경(DML)하는 흐름 제어를 담당합니다.
복잡한 비즈니스 로직을 DB 내에 저장하여 **여러 쿼리를 하나의 트랜잭션으로 일괄 처리**하기 위한 객체입니다. 리턴값이 없으며(파라미터로 반환), `EXEC` 명령어로 실행합니다.

### 🛠️ 기본 문법 구조

```SQL
CREATE OR REPLACE PROCEDURE 프로시저명
(
    파라미터명1  IN  VARCHAR2,    -- 입력 파라미터(변수)
    파라미터명2 OUT VARCHAR2     -- 반환 파라미터(변수)
    파라미터명3 IN OUT 데이터타입    -- 입출력 파라미터(변수)
)
IS -- (또는 AS)
    -- [변수 선언부] 내부 변수, 커서, 예외 선언
    변수명 VARCHAR2(100);
BEGIN
    -- [실행부] 비즈니스 로직 및 트랜잭션 제어
    UPDATE 테이블명 SET 컬럼 = 파라미터명1 WHERE 조건;
    COMMIT; -- 프로시저는 트랜잭션 제어(COMMIT/ROLLBACK)가 가능함
EXCEPTION
    -- [예외 처리부]
    WHEN NO_DATA_FOUND THEN
        ROLLBACK;
        p_output := 'Error';
END;
/
```

### 🔑 파라미터 모드

- **`IN` (Read-only):** 외부 값을 프로시저 내부로 전달받음. (기본값)
- **`OUT` (Write-only):** 로직 처리 후 결과를 호출 환경으로 반환합니다. 실행 중에는 값이 할당되지 않을 수 있습니다.
- **`IN OUT` (Read-Write):** 값을 받아 가공한 후 다시 반환합니다.

## 3. 함수 (Functions)
특정 연산을 수행하고 **반드시 하나의 값(Value)을 반환**하는 객체입니다. 프로시저와 달리 SQL 문장(`SELECT`, `WHERE` 절 등) 내에서 사용하기 위해 설계되었습니다.
실행부 내에 반드시 `RETURN` 문이 존재해야 합니다. ^t027yl

### 🛠️ 기본 문법 구조
```SQL
CREATE OR REPLACE FUNCTION 함수명
(
    파라미터명1 IN 데이터타입
)
RETURN 반환타입 -- [필수명시] 반환할 데이터 타입 (크기 지정 불가)
IS
    -- [선언부]
    변수명1 반환타입;
BEGIN
    -- [실행부]
    변수명1 := 파라미터명1 + 100;
    
    RETURN 결과값; -- [필수] 최종 값 반환
END;
/
```

- **DML 제한:** 함수 내부에서 테이블의 데이터를 변경(`INSERT`, `UPDATE`, `DELETE`)하는 것은 원칙적으로 금지됩니다. (단, `AUTONOMOUS_TRANSACTION` 사용 시 예외적 허용)

## 4. 뷰 (Views)

물리적인 데이터를 저장하지 않고, `AS` 키워드 뒤의 **SQL 문장(Text) 자체를 저장**하는 가상 테이블입니다. 사용자는 뷰를 테이블처럼 조회하지만, 실제로는 저장된 쿼리가 실행됩니다.

### 🎯 사용 목적 및 특징
필요한 데이터만 노출, 복잡한 조인(Join) 쿼리를 미리 정의하여 재사용성을 높, 원본 테이블 구조가 바뀌어도 뷰의 정의만 수정하면 애플리케이션에 영향을 주지 않습니다.
- **단순 뷰 vs 복합 뷰:**
    - _단순 뷰:_ 하나의 테이블로 구성. 조건 만족 시 DML 가능.
    - _복합 뷰:_ 조인, 그룹함수(`SUM`, `AVG`) 포함. 원칙적으로 **DML(수정/삭제) 불가**
### 🛠️ 기본 문법 구조

```SQL
CREATE OR REPLACE [FORCE | NOFORCE] VIEW 뷰이름
AS
SELECT 
    컬럼1 AS 별칭, 
    컬럼2
FROM 
    원본테이블
WHERE 
    조건식
[WITH READ ONLY]        -- 읽기 전용 (DML 불가)
[WITH CHECK OPTION];    -- 뷰의 조회 조건(WHERE) 위배되는 변경 방지
```

## 5. 인덱스 (Indexes)

검색 속도 향상을 위해 사용하는 **B-Tree 구조**의 검색용 객체입니다. 테이블과는 별도의 저장 공간(Segment)을 가집니다.

### ⚖️ Trade-off (성능 영향)

- **장점 (조회):** `WHERE` 절 조건 검색 시 Full Table Scan대신, **Index Range Scan**을 유도하여 속도 향상.
- **단점 (변경):** 데이터가 `INSERT`, `UPDATE`, `DELETE` 될 때마다 인덱스도 재정렬해야 하므로 **쓰기 성능 저하**.

### 🛠️ 기본 문법 구조


```SQL
-- [복합 인덱스] 컬럼 순서가 성능에 결정적 영향을 미침
CREATE [UNIQUE | BITMAP] INDEX 인덱스명 
ON 테이블명 (컬럼1 [ASC|DESC], 컬럼2 [ASC|DESC]);
	
	-- 기본 인덱스 (B-Tree)
	CREATE INDEX 인덱스명 ON 테이블명 (컬럼명 [ASC | DESC]);
	
	-- 유니크 인덱스 (중복 불가)
	CREATE UNIQUE INDEX 인덱스명 ON 테이블명 (컬럼명);
	
	-- 복합 인덱스 (두 개 이상의 컬럼 결합)
	CREATE INDEX 인덱스명 ON 테이블명 (컬럼1, 컬럼2 DESC);
	
	-- 비트맵 인덱스 (카디널리티가 낮은 경우: 성별 등)
	CREATE BITMAP INDEX 인덱스명 ON 테이블명 (컬럼명);
```

### 🔑 인덱스 종류

- **`BITMAP`:** 데이터 값의 종류(Cardinality)가 적은 경우(예: 성별, Y/N) 사용합니다. 주로 OLAP 환경에서 유리합니다.
- **`UNIQUE`:** 중복 값을 물리적으로 차단합니다. (기본키 생성 시 자동 생성됨)

## 6. 암호화 (TDE: Transparent Data Encryption)

디스크에 저장된 데이터 파일 자체를 암호화하여, OS 차원에서 파일 탈취 시 내용을 보호하는 기술입니다. 애플리케이션이나 SQL 조회 시에는 자동으로 복호화되므로 **투명(Transparent)** 하다고 표현합니다.
주로 테이블 생성 시 컬럼 정의에 암호화 옵션을 추가하거나, 테이블스페이스 생성 시 적용합니다.

### 🛠️ 기본 문법 구조
```SQL
컬럼명 데이터타입 ENCRYPT [USING '알고리즘'] [SALT | NO SALT]
```
### 🧩 구성 요소 분해

1. **`ENCRYPT`**: 암호화를 하겠다는 필수 선언입니다.
2. **`USING '알고리즘'`**: (선택) 사용할 암호화 방식을 지정합니다.
    
    - 생략 시: DB 파라미터에 설정된 기본값(주로 `AES192`)이 적용됩니다.
    - 종류: `'AES128'`, `'AES192'`, `'AES256'`, `'3DES168'` 등.
        
3. **`SALT` | `NO SALT`**: (선택) **가장 중요한 옵션**입니다.
    
    - **`SALT` (기본값):** 원본 데이터에 난수(salt)를 섞어 암호화합니다. 보안성은 높지만 계속 값이 달라지므로 **인덱스 생성 불가**.
    - **`NO SALT`:** 같은 데이터는 같은 암호문이 됩니다. 보안성은 보통이지만 **인덱스 생성 가능** -> 검색 조건으로 써야 하는 암호화 컬럼에 사용


**① 컬럼 암호화 (테이블 생성 시)**

```SQL
CREATE TABLE 테이블명 (
    -- [Salt 기본값]  (인덱스 생성 불가/보안성 높음) 
    컬럼명 데이터타입 ENCRYPT [USING '알고리즘'] [SALT | NO SALT]
    -- [No Salt] 같은 평문은 같은 암호문으로 저장 (인덱스 생성 가능)
    컬럼명 데이터타입 ENCRYPT USING 'AES256' 'NO SALT'
    

);
```

**② 테이블스페이스 암호화 (저장 공간 전체)**

```SQL
CREATE TABLESPACE 테이블스페이스명
DATAFILE '파일경로.dbf' SIZE 100M
ENCRYPTION USING 'AES256' DEFAULT STORAGE(ENCRYPT);
```

- **주요 키워드 설명**
    - `ENCRYPT`: 해당 컬럼이나 테이블스페이스를 암호화합니다.
    - `USING '알고리즘'`: 암호화에 사용할 알고리즘(AES256, AES192, AES128, 3DES168 등)을 지정합니다.
