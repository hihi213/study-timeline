# **한눈에 보는 요약 (TL;DR)**

- **규칙은 안쪽(도메인), 기술은 바깥(어댑터).**
- **도메인**은 어떤 기술에도 **의존하지 않음**(순수 모델).
- **애플리케이션**은 **트랜잭션 경계**에서 도메인을 **조립·조정**.
- **어댑터(out)**는 도메인 **포트(인터페이스) 구현**으로 JPA/메시징 등 **기술 연결**.
- **어댑터(in)**(API)는 **입·출력과 검증만** 담당, **얇게** 서비스 호출 + **DTO 반환**.

---

## **패키지 구조 & 의존 규칙**

```
com.example
 ├─ feature
 │  ├─ domain        // 규칙·상태·행위 + 포트(리포지토리 인터페이스)
 │  ├─ application   // 유스케이스(트랜잭션·오케스트레이션)
 │  └─ adapter
 │     ├─ in/...     // Controller 등 인바운드 (DTO 매핑·검증)
 │     └─ out/...    // JPA, 메시징 등 구현체
 └─ ... (bounded context 별로 반복)
```

- **의존 방향:** domain(없음) ← application ← adapter(in/out)
- 포인트: **도메인 이벤트**, **애그리거트 루트** 중심 설계.

---

## **레이어 역할 요약**

- **domain**
    - 엔티티/값 객체/도메인 서비스/도메인 이벤트.
    - **의미 있는 메서드**로 상태 전이(order.cancel() 등).
    - **리포지토리 인터페이스**만 선언.
- **application**
    - **@Transactional 경계**, 여러 도메인 객체 협력 **오케스트레이션**.
    - 규칙 넣지 말 것(규칙은 도메인으로).
- **adapter/out (infra)**
    - JPA/MyBatis/메시징 등 **구현체**로 **포트 구현**.
- **adapter/in (api)**
    - HTTP 입·출력, **DTO 매핑/검증**만. 컨트롤러는 **얇게**.

---

## **핵심 용어 스냅샷**

- **엔티티**: 식별자(@Id)로 구분, **규칙·상태·행위의 주체**(JPA 관리).
- **값 객체**: 식별자 없음, **값 동등성**, **불변 권장**, 엔티티에 **내장 저장**.
- **리포지토리(포트)**: 애그리거트 단위 영속화 **계약**(도메인에 인터페이스).
- **도메인 서비스**: 엔티티 하나에 넣기 애매한 **순수 비즈니스 연산**.
- **도메인 이벤트**: “무엇이 일어났는가”의 비즈니스 사건.
- **DTO**: **경계 간 전달**/검증 전용(비즈니스 로직·영속성 X).
- **스프링 빈**: IoC가 관리하는 **조립자/오케스트레이터(싱글톤, 무상태)**.

-----

- **Use Case**: “사용자/시스템의 목표 단위”. **하나의 업무 흐름**을 정의·실행하는 **작업 단위**. -> 트랜잭션이라는 기술을 사용해 구현
	- ex) 회원가입, 주문 생성, 비밀번호 재설정
- **Application**: 유스케이스 실행자. **트랜잭션 경계 + 오케스트레이션(흐름 제어)**.
- **Presentation**: 요청/응답 경계. **입·출력, 검증, 바인딩, 예외→HTTP 변환**.

결론: Use Case(목표)를 Application(구현)하고, Presentation/Controller(창구)를 통해 요청을 받아 Transaction(안전장치) 위에서 영속성 컨텍스트(작업대)를 이용해 처리하는 것입니다

- **"무엇을 만들어야 하지?" (목표 정의)**
    - ➡️ **Use Case**를 정의합니다. (예: "회원을 가입시킨다.")
- **"사용자가 어떻게 요청을 보내지?" (입구 설계)**
    - ➡️ **Presentation** 계층을 설계하고, `/members` 같은 URI를 담당할 **Controller**를 만듭니다.
- **"실제 일은 누가 총괄하지?" (작업 총괄자 지정)**
    - ➡️ **Application** 계층의 서비스(`MemberService`)가 Use Case를 구현하도록 합니다.
- **"일을 안전하게 처리하려면?" (안전장치 부착)**
    - ➡️ Application 서비스 메서드에 `@Transactional`을 붙여 **Transaction** 범위를 설정합니다.
- **"JPA는 어떻게 효율적으로 일하지?" (내부 동작 이해)**
    - ➡️ Transaction 범위 내에서 JPA가 **영속성 컨텍스트**를 활용해 엔티티를 관리하고 DB에 반영할 것을 인지합니다.
