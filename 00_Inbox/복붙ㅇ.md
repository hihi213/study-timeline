## 1. 원형 연결 리스트 (Circular Linked List)의 특징과 장점

단순 연결 리스트는 마지막 노드에 도달하면 탐색이 끝납니다. 만약 마지막 노드에서 첫 노드로 가고 싶다면, 반드시 헤드 포인터부터 다시 시작해야 했죠. 원형 연결 리스트는 이 문제를 해결하여 **끊김 없이 순회**할 수 있게 해줍니다.

#### **문제점: 일반적인 원형 연결 리스트**

헤드 포인터가 **첫 번째 노드**를 가리키는 일반적인 구조에서는, 리스트의 **맨 끝에** 노드를 추가하려면 첫 노드부터 마지막 노드까지 전부 순회해야 합니다. 이는 **O(n)** 의 비효율적인 연산입니다.

#### **해결책: 헤드 포인터 위치 변경**

**헤드 포인터(`Head`)가 리스트의 마지막 노드를 가리키도록** 구조를 바꿉니다.

#### **결과: O(1) 시간 복잡도 달성**

이렇게 하면 포인터 하나로 리스트의 양 끝에 즉시 접근할 수 있습니다.

- **마지막 노드 접근**: `Head` 포인터로 바로 접근 (**O(1)**)
- **첫 번째 노드 접근**: `Head`의 다음 링크(`Head->Link`)로 바로 접근 (**O(1)**)

결과적으로, 리스트의 **맨 앞**에 노드를 추가하는 것과 **맨 뒤**에 노드를 추가하는 것 모두 **O(1)의 시간 복잡도**로 매우 효율적으로 처리할 수 있게 됩니다.

| 구분          | 헤드가 첫 노드를 가리킬 때 | **헤드가 마지막 노드를 가리킬 때 (개선)** |
| ----------- | --------------- | -------------------------- |
| **맨 뒤에 삽입** | O(n)            | **O(1)**                   |
| **맨 앞에 삽입** | O(1)            | **O(1)**                   |

---
### A. 유연한 탐색 (어디서든 순회 가능)

- **장점:** 리스트의 **어떤 노드에서든** 링크를 따라가기만 하면 결국 모든 노드에 접근할 수 있습니다.
- **단점 극복:** 단순 연결 리스트에서 이전 노드로 돌아가려면 무조건 `Head` (헤드포인터) 부터 재탐색해야 하는 비효율을 해결합니다.

### B. 효율적인 삽입/삭제 (O(1) 연산)

- **구조 변경:** 헤드 포인터(`Head`)가 리스트의 첫 번째가 아닌 **마지막 노드**를 가리키도록 변형하면 효율이 극대화됩니다.
- **시간 복잡도:**
    - **단순/기존 원형 연결 리스트:** 맨 끝에 노드 삽입 시 `O(n)` (헤드부터 시작해 전체 순회 필요).
    - **(변형한) 원형 연결 리스트:** 맨 앞 노드(`Head->Link`)와 맨 뒤 노드(`Head`)에 **즉시 접근**할 수 있어 삽입 연산이 **O(1)**로 처리됩니다.

### C. 단점

- 특정 노드에서 **바로 이전 노드(선행 노드)**를 찾으려면 결국 리스트를 한 바퀴 순회해야 하므로 노드 수가 많을 경우 **O(n)**의 비효율이 발생합니다.
## 2. 이중 연결 리스트 (Doubly Linked List)의 등장과 장점

원형 연결 리스트의 선행 노드 탐색 비효율(O(n))을 해결하기 위해 **이중 연결 리스트**가 등장했습니다.

### A. 양방향 탐색 및 O(1) 선행 노드 접근

- **구조:** 각 노드가 후속 노드를 가리키는 링크(`rlink`) 외에, **선행 노드를 가리키는 링크**(`llink`)를 추가로 가집니다.
- **장점:** 양방향 탐색이 가능해져, 현재 노드에서 **선행 노드를 O(1) 시간 복잡도**로 즉시 찾을 수 있습니다.

### B. 단점

- **메모리 및 복잡성:** 링크가 하나 더 추가되므로 **노드당 더 많은 메모리**를 사용하며, 삽입/삭제 시 두 개의 링크(llink, rlink)를 모두 처리해야 하므로 **구현 로직이 복잡**해집니다.

## 3. 실제 활용 모델: 원형 이중 연결 리스트와 헤드 노드

실제 프로그래밍에서는 이중 연결 리스트의 복잡성을 줄이기 위해 **원형 이중 연결 리스트**와 **헤드 노드 (Dummy Node)**를 함께 사용하는 방식을 선호합니다.

### A. 헤드 노드(Header Node) 사용 이유

- **역할:** 데이터를 저장하지 않고, 리스트의 시작과 끝을 연결하는 역할만 수행합니다.
- **장점:** 리스트가 비어있거나, 노드가 하나일 경우 등 **경계 조건(Boundary Condition)**에서 발생하는 널 포인터(`null pointer`) 예외 처리를 크게 줄여줍니다.
    - 리스트가 비어있을 때도 헤드 노드의 `llink`와 `rlink`는 자기 자신을 가리키도록 설정합니다.

### B. 핵심 속성 (항등식)

원형 이중 연결 리스트에서는 연결 관계의 정확성을 검증하는 중요한 속성이 항상 성립합니다.

> 어떤 노드 `p`에 대하여
>
> 1. `p->llink->rlink == p` (이전 노드의 다음 노드는 `p`)
>     
> 2. `p->rlink->llink == p` (다음 노드의 이전 노드는 `p`
>

단순 연결 리스트의 한계를 극복하기 위해 원형 연결 리스트와 이중 연결 리스트를 사용합니다.

1. 원형 연결 리스트 (Circular Linked List)

단순 연결 리스트에서는 마지막 노드의 링크가 NULL을 가리키지만, 원형 연결 리스트에서는 마지막 노드의 링크가 첫 번째 노드를 가리킵니다. 이를 통해 리스트가 하나의 닫힌 고리(loop)를 형성합니다.

- 장점 1: 모든 노드로의 접근성

    단순 연결 리스트에서는 특정 노드에서 그 이전 노드로 가려면 항상 헤드 포인터부터 다시 탐색을 시작해야 합니다. 하지만 원형 연결 리스트에서는 어떤 노드에 있더라도 계속해서 링크를 따라가면 결국 모든 노드를 순회할 수 있으므로, 헤드 포인터로 돌아갈 필요 없이 탐색이 가능합니다.

- 장점 2: 효율적인 맨 앞/뒤 접근 (Head-points-to-Tail 기법)

    일반적으로 head 포인터는 첫 번째 노드를 가리킵니다. 이 경우 리스트의 맨 뒤에 원소를 추가하려면 head부터 마지막 노드까지 $O(n)$의 탐색이 필요합니다.

    이 문제를 해결하기 위해, head 포인터가 첫 번째 노드가 아닌 마지막 노드를 가리키도록 규칙을 변경할 수 있습니다.

    - **맨 마지막 노드 접근**: `head` 포인터로 $O(1)$에 즉시 접근 가능합니다.
    - 맨 처음 노드 접근: head->link를 통해 $O(1)$에 즉시 접근 가능합니다.

        이처럼 head 포인터의 역할을 바꾸는 것만으로 리스트의 양쪽 끝에 대한 삽입/삭제 연산이 매우 간단하고 효율적으로 변합니다. 이 아이디어는 실제 논문으로 발표되어 표준 알고리즘의 일부가 되었습니다.

2. 이중 연결 리스트 (Doubly Linked List)

원형 연결 리스트도 특정 노드의 '바로 이전' 노드를 찾으려면 리스트 전체를 한 바퀴 순회해야 하는 단점이 있습니다. 이 문제를 해결하는 것이 이중 연결 리스트입니다.

- **구조**: 각 노드는 다음 노드를 가리키는 포인터(`r_link`, `next`)뿐만 아니라, **이전 노드를 가리키는 포인터(`l_link`, `previous`)**도 함께 가집니다. 이를 위해 자기 참조 포인터 멤버를 구조체에 하나 더 추가합니다.
- **장점**: 양방향 탐색이 가능하여 검색이 매우 유연하고 효율적입니다.
- **단점 및 해결책**: 구조가 복잡해지고, 삽입/삭제 시 변경해야 할 포인터가 늘어납니다. 특히 리스트가 비어있거나 양쪽 끝에서 연산할 때 조건 처리가 복잡해지는데, 이를 해결하기 위해 **헤드 노드(Head Node)**, 즉 **더미 노드(Dummy Node)**를 도입합니다.
    - **헤드 노드**: 실제 데이터를 저장하지 않는 가짜 노드입니다. 이 노드는 항상 리스트에 존재하며, 리스트의 시작과 끝을 연결하는 역할을 합니다. 헤드 노드의 `r_link`는 첫 번째 실제 노드를, `l_link`는 마지막 실제 노드를 가리키는 방식(원형 구조)으로 사용됩니다.
    - **효과**: 헤드 노드 덕분에 "리스트가 비어있는 경우"나 "맨 앞에 삽입하는 경우"와 같은 예외적인 상황을 따로 처리할 필요 없이, 모든 삽입/삭제를 '어떤 노드와 노드 사이에 추가/삭제'하는 일반적인 경우로 통일할 수 있어 알고리즘이 매우 간결해집니다.
- **불변 속성(Invariant)**: 정상적인 원형 이중 연결 리스트의 어떤 노드 `p`에 대해서도, `p->r_link->l_link`는 항상 `p` 자신과 같습니다. 즉, 오른쪽으로 한 칸 이동했다가 왼쪽으로 돌아오면 원래 위치입니다. 이 속성은 리스트의 연결 상태가 올바른지 검증하는 데 사용될 수 있습니다.

구조체 포인터와 구조체 변수를 혼동해서는 안 됩니다. `p`는 노드의 주소를 담는 포인터 변수이며, `*p` 또는 `p->멤버`를 통해 그 주소에 있는 실제 노드에 접근합니다. 포인터를 이용하면 `p->l_link->r_link->r_link...` 와 같이 연속적으로 연결된 노드들을 자유롭게 탐색할 수 있습니다.

끝.
