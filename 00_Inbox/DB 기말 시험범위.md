### **[문제 4] 동시성 제어 (Concurrency Control)**

- **유형:** 주어진 스케줄(Schedule)에 대해 직렬 가능성(Serializability) 판단 및 비직렬인경우 다시 그리시오 .
- **수행 단계:**
    
    1. **직렬 가능 여부 판단:** 연산 충돌 그래프(Conflict Graph)를 그려서 사이클(Cycle) 존재 여부 확인.
        - 사이클이 있으면 '비직렬 가능', 없으면 '직렬 가능'으로 답합니다 .
    2. **리스케줄링 (Rescheduling):** 만약 비직렬 가능(사이클 존재) 스케줄이라면, 사이클을 끊는 방식으로 순서를 재조정하여 그려 직렬 가능한 스케줄로 변경. (충돌 그래프에서 확인한 **사이클을 끊을 수 있도록 그림의 연산의 순서를 이동**시키면 됩니다 이때 앞쪽으로 땡기는건 불가능하고 뒤로 미는게 가능(연산순서 유지))
    
        
- **참고:** 세마포어 등 구체적인 메커니즘을 서술할 필요는 없으며, 연산 순서를 조정하여 해결하는 과정만 보여주면 됨.
    

### **[문제 5] 데이터베이스 보안 (약 20점)** : 시스템 보안(ID/PW)을 통과했더라도 내부적으로 문서등급와 사용자 등급을 나눠 관리할 필요가 있다.

- 내용: ~에 대해 서술하시오
- **필수 문제 (무조건 출제):** **RSA 방식(비대칭키 암호화)**에 대해 설명하시오 .
	- 어떻게 운영하는지 봤죠? 시험에 나오면 쓸 수 있어야 합니다. 문서를 암호화할 때와 전자 서명할 때의 차이, 공개키와 개인키를 쌍(Pair)으로 만들고 둘이 다르다는 것, 그렇게 운영된다는 것만 서술하면 됩니다.
- **선택 문제 (둘 중 하나 출제):**
	* **MAC:** Subject/Object 등급 분류, Bell-LaPadula 모델의 원칙(Simple Property: No Read Up, Star Property: No Write Down) 포함 설명 .
		1. **Simple Security Property (No Read Up):** 낮은 등급 주체는 높은 등급 문서를 읽을 수 없다.
		2. **Star Property (*-Property) (No Write Down):** 높은 등급 주체는 낮은 등급 문서에 쓸 수 없다. (기밀 유출 및 은닉 채널 방지)
    * **RBAC:** MAC 설명에 사용자(User)와 권한 사이 'Role(역할)'이 매핑된다는 개념을 추가하여 설명 .
* **제외:** DAC(임의적 접근 제어)는 서술 양이 너무 많아 시험 범위에서 제외합니다 .
	* **DAC(선별적 접근 제어):** DB Owner가 권한을 부여(`GRANT`/`REVOKE`)하는 방식.

### **1. RSA 방식 (비대칭키 암호화) - 필수 출제**
교수님이 "무조건 나온다"고 강조했습니다. 단순히 '암호화다'라고 쓰는 것보다 **키의 생성과 사용 흐름**을 명확히 적는 것이 중요합니다.

* **핵심 키워드:** 비대칭키(Asymmetric Key), 공개키(Public Key), 개인키(Private Key), 소인수분해의 어려움
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** RSA는 공개키 암호화 알고리즘의 대표적인 표준으로, 암호화와 복호화에 서로 다른 키를 사용하는 **비대칭키** 방식이다.
    2.  **키의 구성:** 누구나 알 수 있는 **공개키(Public Key)**와 소유자만 알고 있는 **개인키(Private Key)** 쌍으로 구성된다.
    3.  **작동 원리:**
        * **암호화:** 송신자는 수신자의 **공개키**를 사용하여 평문을 암호화한다.
        * **복호화:** 수신자는 자신의 **개인키**를 사용하여 암호문을 복호화한다. (반대로 전자서명 시에는 개인키로 잠그고 공개키로 푼다.)
    4.  **보안성:** 큰 수의 소인수분해가 계산적으로 매우 어렵다는 점에 기반하여 보안성을 유지한다.

### **2. MAC (Mandatory Access Control, 강제적 접근 통제)**
DAC는 제외되었으므로, MAC이 나올 확률이 50%입니다. 시스템이 권한을 강제한다는 점을 강조해야 합니다.

* **핵심 키워드:** 보안 등급(Security Label), 중앙 집중형 관리, 사용자(Subject), 객체(Object), 관리자(System)
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** 데이터베이스 관리 시스템(DBMS)이나 관리자가 정해놓은 정책에 따라, 주체(사용자)와 객체(데이터)에 부여된 **보안 등급(Security Label)**을 비교하여 접근을 통제하는 방식이다.
    2.  **특징:**
        * 사용자는 자신의 데이터라도 마음대로 접근 권한을 다른 사람에게 양도할 수 없다(**DAC와의 차이점**).
        * 모든 접근 제어는 시스템(관리자)에 의해 강제적으로 이루어진다.
    3.  **동작 예시 (BLP 모델 등 참조):**
        * 사용자의 보안 등급이 객체의 보안 등급보다 높거나 같아야 읽을 수 있다 (No Read Up 등).
        * 군대나 정보기관처럼 기밀성이 중요한 조직에서 주로 사용된다.

### **3. RBAC (Role-Based Access Control, 역할 기반 접근 통제)**
현대적인 시스템에서 가장 많이 쓰이는 방식입니다. '사람'이 아닌 '역할'에 권한을 준다는 것이 핵심입니다.

* **핵심 키워드:** 역할(Role), 권한 할당(Permission Assignment), 사용자 할당(User Assignment), 다대다(M:N) 관계
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** 사용자 개인이 아닌, 조직 내에서 수행하는 **역할(Role)**에 따라 접근 권한을 부여하는 방식이다.
    2.  **구조:**
        * **권한(Permission) → 역할(Role):** 특정 역할(예: 인사팀장)에 필요한 권한들을 할당한다.
        * **역할(Role) → 사용자(User):** 사용자를 적절한 역할에 소속시킨다.
    3.  **장점:**
        * 인사이동이나 퇴사 시 사용자의 역할만 변경하면 되므로 관리가 매우 효율적이다.
        * 사용자와 권한 사이의 복잡성을 줄여주며, 최소 권한 원칙을 적용하기 용이하다.

교수님 설명의 핵심은 **"잠그는 키와 여는 키가 다르다"**는 점과 **"암호화" vs "전자서명"**의 작동 원리입니다.

- **키의 특징:**
    - **공개키:** 누구나 알 수 있게 공개함.
    - **개인키:** 소유자 자신만 비밀리에 보관함.
- **작동 원리 (두 가지 상황을 구분해서 서술해야 완벽함):**

    2. **전자 서명 (인증):** 송신자가 자신이 보낸 것임을 증명하기 위해 자신의 **[개인키]**로 서명(암호화)한다. $\rightarrow$ 수신자는 송신자의 **[공개키]**로 이를 확인(복호화)한다.

### **2. MAC (강제적 접근 통제) [나올 확률 50%]**

교수님이 칠판에 잘못 썼다가 고쳐주신 **'벨-라파듈라(Bell-LaPadula)' 원칙(No Read Up, No Write Down)**을 정확히 쓰는 것이 핵심입니다.

**답안 작성 포인트:**

- **정의:** 데이터(객체)와 사용자(주체)에게 **보안 등급(Security Label)**을 부여하고, 시스템이 강제적으로 접근을 통제하는 방식이다. (예: 1급 비밀, 2급 비밀 등)
- **구성 요소:** 주체(Subject), 객체(Object), 보안 등급(Class/Level).
- **핵심 원칙 (반드시 포함):**
    
    1. **No Read Up (Simple Security Property):** 낮은 등급의 사용자는 높은 등급의 문서를 **읽을 수 없다.** (기밀성 보장)
    2. **No Write Down (*-Property, Star Property):** 높은 등급의 사용자는 낮은 등급의 문서에 정보를 **쓸 수 없다.** (정보가 낮은 등급으로 유출되는 것을 방지, 은닉 채널 방지)

### **3. RBAC (역할 기반 접근 통제) [나올 확률 50%]**

MAC과 함께 나올 수 있는 또 다른 문제입니다. '사람'이 아닌 '역할'이 중심이라는 것을 강조하세요.

**답안 작성 포인트:**

- **정의:** 사용자 개인이 아니라, 조직 내에서의 **역할(Role)**에 권한을 부여하는 방식이다.
- **구조:**
    - **사용자(User) $\leftrightarrow$ 역할(Role):** 사용자에게 적절한 역할(예: 부장, 대리, 사원)을 할당한다.
    - **역할(Role) $\leftrightarrow$ 권한(Permission):** 각 역할이 수행할 수 있는 권한(읽기, 쓰기 등)을 할당한다.
- **특징:**
    - 인사 이동이나 퇴사 시 사용자의 역할만 변경하면 되므로 관리가 효율적이다.
    - 현대적인 DBMS는 대부분 MAC의 등급 개념과 RBAC의 역할 개념을 혼합하여 지원한다.
    - **"내부에 MAC의 개념(등급 나누기)을 포함하면서, 사용자 접속 시 역할(Role)을 매핑해주는 방식"**이라고 서술하면 가점 예상.

# [강의 요약] 정규화 심화 (3NF & BCNF)

## 1. 정규형의 계층과 조건

정규화는 하위 단계를 만족해야 상위 단계로 나아갈 수 있는 계층 구조를 가집니다.

- **진행 순서:** 1NF $\rightarrow$ 2NF $\rightarrow$ 3NF $\rightarrow$ BCNF
- **검증 원칙:** 상위 정규형(예: 3NF)을 만족하려면 반드시 하위 정규형(예: 2NF)을 먼저 만족해야 합니다
    

### 1.1. 제3정규형 (3NF)

- **기본 정의:** 이행적 함수 종속(Transitive FD)이 없어야 합니다.
- 공식적 정의 (Formal Definition):
    
    함수적 종속 $X \rightarrow Y$가 존재할 때, 다음 두 조건 중 하나라도 만족하면 3NF를 준수한다고 봅니다.
    
    1. $X$가 **슈퍼키(Super Key)**이다.
    2. 또는($OR$), $Y$가 **프라임 속성(Prime Attribute)**이다.
        

### 1.2. BCNF (Boyce-Codd Normal Form)

- **정의:** 3NF보다 더 엄격한 정규형입니다.
- **결정 조건:** 함수적 종속 $X \rightarrow Y$가 존재할 때, **반드시 $X$가 슈퍼키(Super Key)여야 합니다**.
    - 3NF와 달리 "또는 $Y$가 프라임 속성이다"라는 예외 조건이 없습니다
    - 따라서 모든 BCNF는 3NF이지만, 모든 3NF가 BCNF인 것은 아닙니다.
        

---

## 2. 주요 개념 설명

### 2.1. 슈퍼키 (Super Key)

- **개념:** 릴레이션 내의 튜플을 유일하게 식별할 수 있는 속성들의 집합입니다.
- **예시:** $A$가 키(Key)라면, $A$를 포함하는 모든 조합($\{A, B\}$, $\{A, C\}$, $\{A, B, C\}$ 등)은 전부 슈퍼키가 됩니다.
    

### 2.2. 프라임 속성 (Prime Attribute)

- **개념:** 후보키(Candidate Key)를 구성하는 속성입니다.
- **3NF 판별 시:** 결정자($X$)가 슈퍼키가 아니더라도, 종속자($Y$)가 프라임 속성이라면 3NF에서는 허용됩니다(BCNF에서는 불가).
    

---

## 3. 정규형 판별 실습 및 예제

### 3.1. 3NF vs BCNF 판별 예제

릴레이션 $R$에서 키(Key)가 $A$이고, FD가 다음과 같을 때:

1. $A \rightarrow B$: $A$는 키이므로 슈퍼키임. **(OK)**.
2. $C \rightarrow A$:
    
    - $C$는 슈퍼키가 아님.
    - 하지만 $A$는 프라임 속성임.
    - **결과:** 3NF는 만족하지만, BCNF는 만족하지 않음 (BCNF 위반).
        
3. $D \rightarrow E$:
    
    - $D$는 슈퍼키가 아님.
    - $E$는 프라임 속성도 아님.
    - **결과:** 3NF 위반 (분해 대상)13.

### 4.2. 제2정규형 (2NF) - 부분 종속 제거

- **전제:** 기본키(Key)가 복합키(두 개 이상의 속성으로 구성)일 때 발생 가능.
- **용어 정의:**
    - **Prime Attribute:** 키를 구성하는 속성.
    - **Non-Prime Attribute:** 키에 포함되지 않는 일반 속성.
- **부분 함수 종속 (Partial Functional Dependency):**
    - 기본키의 **일부분(진부분집합)**에만 종속되는 경우.
    - 예: 기본키가 ${X, Y}$인데, 일반 속성 $W$가 $X$에만 종속되는 경우 ($X \rightarrow W$).
- **해결:** 부분 종속을 일으키는 속성을 별도 테이블로 분리해야 2NF를 만족함.
    

### 4.3. 제3정규형 (3NF) - 이행 종속 제거

- **이행 함수 종속 (Transitive Functional Dependency):**
    - $X \rightarrow Y$ 이고 $Y \rightarrow Z$ 일 때 (단, $Y$는 키가 아님).
    - 즉, $X$를 통해 $Y$가 결정되고, $Y$를 통해 $Z$가 결정되는 "건너서 종속되는" 관계.
- **해결:** $Y \rightarrow Z$ 관계를 별도 테이블로 분리해야 3NF를 만족함.
