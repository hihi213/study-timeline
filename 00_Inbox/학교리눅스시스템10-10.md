## **2025-10-10, 1교시 — 개선본**

Windows 파일 시스템에서는 파일을 탐색할 때 여러 번 클릭하여 경로를 찾아갑니다. 자주 사용하는 폴더나 프로그램은 '바로 가기'를 바탕화면에 만들어 사용하는데, Linux의 링크는 이와 유사한 개념에서 출발합니다.

데이터 보존을 위한 미러링(mirroring) 개념도 링크와 관련이 있습니다. 예를 들어, RAID(Redundant Array of Independent Disks) 시스템에서는 원본 데이터에 변경이 발생하면, 다른 디스크에 있는 복사본에도 해당 내용이 실시간으로 반영됩니다. 이는 실수로 원본을 삭제하더라도 데이터를 보존하기 위함입니다. 이러한 개념은 모두 Unix 시스템에서 발전된 것입니다.

Linux에는 두 가지 종류의 링크가 있습니다. 하나는 **하드 링크(hard link)** 이고, 다른 하나는 **심볼릭 링크(symbolic link)** 입니다. 두 개념은 혼동하기 쉬우므로 주의해야 합니다.

파일을 백업하는 가장 간단한 방법은 `cp` 명령어를 이용한 복사입니다. 하지만 복사를 할 경우, 원본 파일(`a.txt`)을 수정해도 사본(`b.txt`)은 변경되지 않아 다시 복사해야 하는 불편함이 있습니다. 반면, 링크를 사용하면 이러한 문제를 해결할 수 있습니다.

---

### 하드 링크 (Hard Link)

하드 링크는 **기존 파일에 새로운 파일명을 추가**하는 것과 같습니다. 하드디스크에는 하나의 파일 데이터만 존재하지만, 여러 개의 파일명을 통해 동일한 데이터에 접근할 수 있습니다.

Linux는 파일명으로 파일을 직접 찾는 것이 아니라, **inode 번호**를 사용합니다. inode 테이블에는 파일의 메타데이터(크기, 권한 등)와 실제 데이터가 저장된 데이터 블록의 주소 정보가 들어 있습니다. 사용자가 파일명을 입력하면, 시스템은 해당 파일명의 inode 번호를 찾아 데이터 블록에 접근합니다.

하드 링크로 생성된 파일은 원본 파일과 **동일한 inode 번호**를 공유합니다. 즉, 시스템 관점에서는 완전히 **같은 파일**로 취급됩니다. 따라서 여러 경로로 동일한 파일에 접근할 수 있게 됩니다.

### 심볼릭 링크 (Symbolic Link)

심볼릭 링크는 원본 파일을 가리키는 **경로가 저장된 특수한 파일**입니다. Windows의 '바로 가기'와 매우 유사합니다. 심볼릭 링크는 원본 파일과 **다른 inode 번호**를 가지므로, 시스템 관점에서는 **서로 다른 파일**입니다.

정리하자면, **하드 링크는 같은 파일**이고 **심볼릭 링크는 다른 파일**입니다.

---

### 파일 시스템과 inode 구조

파일 시스템은 inode 테이블과 데이터 블록으로 구성됩니다.

- **inode 테이블**: 파일의 inode 번호, 파일 정보, 데이터 블록 주소 등을 저장합니다.
- **데이터 블록**: 실제 파일의 내용이 저장되는 물리적인 공간입니다.

사용자가 `ls -i` 명령을 실행하면 각 파일명 앞에 붙어있는 inode 번호를 확인할 수 있습니다. (실습) 시스템은 이 번호를 통해 파일의 위치를 찾아갑니다.

하드디스크의 데이터는 물리적으로 섹터(sector)와 트랙(track)으로 나뉘어 저장됩니다. inode 테이블에 기록된 블록 위치 정보를 통해 특정 섹터와 트랙에 접근하여 데이터를 읽어오는 방식입니다. 이는 과거 DOS의 FAT(File Allocation Table)와 유사한 원리입니다.

### 링크 생성 및 비교 실습

`ch03` 디렉토리에서 다음 과정을 통해 링크를 생성하고 비교해 보겠습니다.

먼저 실습용 파일을 복사합니다. (실습)

cp /etc/hosts test1

`ls -il` 명령으로 파일 목록과 inode 번호를 확인합니다. (실습)

이제 `test1` 파일을 기준으로 하드 링크와 심볼릭 링크를 생성합니다.

1. **하드 링크 생성**: `ln test1 HD_test1` (실습)
2. **심볼릭 링크 생성**: `ln -s test1 SB_test1` (실습)

다시 `ls -il` 명령으로 결과를 확인해 봅시다. (실습)

- `test1`과 `HD_test1`은 **inode 번호가 동일**합니다. 또한 파일 속성 필드 옆에 있는 **링크 카운트가 2**로 증가한 것을 볼 수 있습니다.
- `SB_test1`은 **inode 번호가 다르며**, `-> test1` 과 같이 원본 파일을 가리키는 화살표가 표시됩니다. 또한 권한 표기 맨 앞에 `l`이 붙어 링크 파일임을 나타냅니다.

이 결과는 `test1`과 `HD_test1`은 같은 파일이며, `SB_test1`은 별개의 파일이라는 점을 명확히 보여줍니다.

만약 `vi` 에디터 등으로 `test1` 파일의 내용을 수정하면, 동일한 데이터를 공유하는 `HD_test1`의 내용도 즉시 변경됩니다. 하지만 `SB_test1`은 원본이 변경되어도 파일 자체가 바뀌는 것은 아니며, 단지 변경된 원본을 가리킬 뿐입니다.

중요한 점은, 원본 파일인 `test1`을 삭제하더라도 하드 링크인 `HD_test1`이 남아있다면 파일의 본체(데이터 블록)는 삭제되지 않습니다. 데이터는 링크 카운트가 0이 될 때 비로소 물리적으로 삭제 가능한 상태가 됩니다. 이는 실수로 파일을 삭제했을 때 데이터를 복구할 수 있는 중요한 수단이 됩니다.

파일 삭제는 실제 데이터를 지우는 것이 아니라, 데이터 블록을 찾아갈 수 있는 inode 연결 정보(링크)를 끊는 행위입니다. 따라서 전문적인 복구 도구를 사용하면 삭제된 파일의 데이터를 복원할 수 있습니다. 데이터를 완전히 파기하려면 디스크를 물리적으로 파괴하거나, 의미 없는 데이터를 수만 번 덮어쓰는 과정이 필요합니다.

---

### 하드 링크와 심볼릭 링크의 주요 차이점

1. **파일 시스템 경계**:
    
    - **하드 링크**: 같은 파일 시스템(동일한 디스크 파티션) 내에서만 생성할 수 있습니다.
    - **심볼릭 링크**: 다른 파일 시스템 간에도 링크를 생성할 수 있습니다. 예를 들어, `/home` 디렉토리의 파일을 `/var` 디렉토리로 심볼릭 링크하는 것이 가능합니다.
        
2. **디렉토리 링크**:
    
    - **하드 링크**: 디렉토리에 대해서는 생성할 수 없습니다. 오직 파일만 가능합니다.
    - **심볼릭 링크**: 디렉토리에 대해서도 링크를 생성할 수 있습니다.

실제로 루트 디렉토리에서 `ls -l /` 명령을 실행해 보면, `lib`, `lib64`, `sbin` 같은 여러 디렉토리가 `/usr` 내부의 다른 위치를 가리키는 심볼릭 링크로 설정된 것을 볼 수 있습니다.

### 링크 속성 심화 확인

다음 실습을 통해 링크의 동작을 더 깊이 이해해 봅시다. (실습)

1. `test.org` 파일 생성 (내용은 `/etc/hosts` 복사)
2. `test.org`에 대한 하드 링크 2개 생성 (`test.hd1`, `test.hd2`)
3. `test.org`에 대한 심볼릭 링크 1개 생성 (`test.sb`)
4. `test.org` 파일을 복사하여 `test.bak` 파일 생성
5. `ls -il`로 모든 파일의 inode 번호 비교
    
    - `test.org`, `test.hd1`, `test.hd2`는 inode가 동일하고 링크 카운트는 3입니다.
    - `test.sb`, `test.bak`은 각각 다른 inode를 가집니다.
        
6. 원본 파일 삭제: `rm test.org`
    
    - `test.hd1`, `test.hd2`를 통해 파일 내용을 확인하면 여전히 데이터가 보존되어 있습니다. (링크 카운트는 2로 감소)
    - `test.sb`는 가리키던 원본이 사라졌으므로 **깨진 링크(broken link)**가 됩니다. 터미널에서 빨간색으로 표시될 수 있습니다.
        
7. 남은 하드 링크 파일 수정: `gedit test.hd2` (내용 수정 후 저장)
    
    - `test.hd1`의 내용을 확인하면 `test.hd2`에서 수정한 내용이 동일하게 반영되어 있습니다.
    - 복사본이었던 `test.bak` 파일은 아무런 영향을 받지 않습니다.

이러한 특성을 이해하면 Linux 시스템에서 파일을 효율적이고 안전하게 관리할 수 있습니다.

## **2025-10-10, 1교시 — 개념**

### 1. 한 줄 요약

Linux의 링크는 파일에 별명을 부여(하드 링크)하거나 경로를 가리키는 포인터(심볼릭 링크)를 만드는 기능으로, 파일 시스템의 핵심인 **inode** 개념의 이해가 필수적입니다.

---

### 2. 핵심 TL;DR

- **하드 링크 (Hard Link)**: 원본 파일과 **동일한 inode 번호**를 공유하는, 똑같은 파일에 대한 또 다른 이름입니다.
- **심볼릭 링크 (Symbolic Link)**: 원본 파일의 **경로를 저장**하는 별개의 파일로, Windows의 '바로 가기'와 유사하며 고유의 inode를 가집니다.
- **Inode**: 파일의 소유권, 권한, 크기 및 실제 데이터 위치(데이터 블록) 등 모든 메타 정보를 담고 있는 데이터 구조입니다.
- **링크 식별**: `ls -il` 명령어로 inode 번호와 링크 카운트를 확인하는 것이 가장 확실한 방법입니다.
- **하드 링크와 삭제**: 링크된 파일 중 하나를 삭제해도, 링크 카운트가 1 이상 남아있으면 실제 데이터는 삭제되지 않습니다.
- **심볼릭 링크와 삭제**: 원본 파일을 삭제하면 심볼릭 링크는 경로를 잃고 **깨진 링크(broken link)**가 되어 작동하지 않습니다.
- **제약사항**: 하드 링크는 **디렉토리에 생성할 수 없으며**, 동일 파일 시스템(파티션) 내에서만 가능합니다. 심볼릭 링크는 두 제약이 모두 없습니다.
- **데이터 일관성**: 하드 링크된 파일 중 어느 것을 수정하든 **모든 이름의 파일 내용이 함께 변경**됩니다. 원본과 사본의 개념이 없기 때문입니다.

---

### 3. 표현 = 표준 용어
- **inode**: 파일 시스템이 각 파일을 식별하고 관리하는 데 사용하는 고유한 메타데이터.
- **inode Number**: 각 inode를 구별하는 고유 식별 번호, 아이노드 번호는 각각의 파일시스템(디스크 파티션)안에서만 고유
	- 심볼릭링크가 저장하는 경로는 전체(컴퓨터)에서 통하는 주소이다.
- **Hard Link**: 동일한 inode를 공유하는 파일의 또 다른 이름.
- **Symbolic Link (symlink)**: 다른 파일이나 디렉토리의 경로를 가리키는 포인터 파일. (원본과 별개의 아이노드, 데이터블록 이때 데이터 블록에 원본파일의 string 경로를 저장)
- **Link Count**: 특정 inode에 연결된 하드 링크(파일 이름)의 총 개수.
- **Data Block**: 파일의 실제 내용이 저장되는 디스크 상의 물리적 공간.
- **Broken Link**: 원본 파일이 삭제되거나 이동하여 더 이상 존재하지 않는 경로를 가리키는 심볼릭 링크.

|   |   |   |   |
|---|---|---|---|
|구분|아이노드가 저장하는 주소|심볼릭 링크가 저장하는 주소|'그냥 주소' (파일 경로)|
|**논리적** **실체**|데이터 블록 번호 목록|경로가 담긴 문자열|디렉터리 계층 구조 명세|
|**물리적** **실체**|파일 데이터가 저장된 디스크 섹터/셀|경로 텍스트가 저장된 별도의 디스크 공간|경로상 각 디렉터리 파일들의 데이터 블록 조합|
|**참조** **방식**|**직접** **참조** (Direct Pointer):   데이터 블록 번호는 스토리지 하드웨어의 물리적 주소로 변환|**간접** **참조** (Indirect Reference) : 파일 시스템 계층 구조를 처음부터 다시 탐색|**절차적** **탐색** (Procedural Lookup)|

---

### 4. 정석 보강 (Standard Definition)

**링크(Link)**는 파일 시스템 내에서 파일에 접근하는 경로를 추가하거나 참조하는 기능입니다. **하드 링크**는 `ln target link_name` 명령으로 생성하며, 기존 파일과 **완전히 동일한 inode**를 공유합니다. 이로 인해 링크 카운트가 증가하며, 원본과 링크는 구별되지 않는 동일한 파일이 됩니다. 반면, **심볼릭 링크**는 `ln -s target link_name`으로 만들며, 원본의 경로를 가리키는 **독립적인 inode를 가진 새 파일**입니다. 이 때문에 다른 파일 시스템에 있는 파일도 가리킬 수 있습니다.

---

### 5. 실수·함정

1. **`cp`와 하드 링크 혼동**: `cp`는 완전히 새로운 inode와 데이터 블록을 할당하는 **복사**이고, 하드 링크는 inode를 **공유**하는 것입니다.
2. **디렉토리 하드 링크 시도**: 디렉토리는 하드 링크를 만들 수 없습니다. 순환 구조 문제를 방지하기 위함입니다.
3. **파일 시스템 경계 무시**: 다른 파티션(예: `/home`의 파일을 `/var`로)에 하드 링크를 생성하려 하면 "Invalid cross-device link" 오류가 발생합니다.
4. **`rm`의 오해**: `rm`은 파일 데이터를 즉시 지우는 것이 아니라, inode에 연결된 이름(링크)을 하나 제거하는 것입니다. 링크 카운트가 0이 되어야 비로소 데이터가 삭제 처리됩니다.
5. **심볼릭 링크 권한 착각**: `ls -l`에서 심볼릭 링크는 `lrwxrwxrwx`처럼 모든 권한이 열려 있는 것처럼 보이지만, 실제 적용되는 권한은 **원본 파일의 권한**입니다.
6. **상대 경로 링크의 함정**: 심볼릭 링크를 상대 경로로 생성한 뒤 링크 파일을 다른 위치로 이동시키면 경로가 틀어져 깨진 링크가 될 수 있습니다.
7. **링크 카운트 무시**: `ls -l` 출력의 두 번째 필드인 링크 카운트를 확인하지 않으면 하드 링크 존재 여부를 놓치기 쉽습니다. (1이면 링크 없음)
8. **터미널 색상에만 의존**: 보통 심볼릭 링크는 청록색, 깨진 링크는 빨간색으로 표시되지만, 이는 표준이 아닌 터미널 설정이므로 `ls -l`의 첫 글자(`l`)와 화살표(`->`)로 확인해야 합니다.

**[Q1] 하드 링크와 심볼릭 링크의 근본적인 차이는 무엇이며, 언제 사용하는 것이 적합합니까? | 태그: 링크(하드/심볼릭), inode**

- **모범답(강의 기준)**: 하드 링크는 원본과 동일한 inode를 사용하는 **'같은 파일'**이고, 심볼릭 링크는 원본 경로를 가리키는 **'다른 파일(바로 가기)'**입니다. 중요 파일의 원본 삭제를 방지할 목적이라면 하드 링크를, 다른 파티션의 파일이나 디렉터리를 연결할 때는 심볼릭 링크를 사용합니다.

**[Q2] 파일을 복사하는 `cp`와 하드 링크를 생성하는 `ln`은 결과적으로 어떻게 다릅니까? | 태그: 링크(하드/심볼릭), 셸/리다이렉션/FD**

- **정석체크(면접 30초)**: `cp`는 파일 내용을 읽어 새로운 inode와 데이터 블록에 쓰는 **'복제'** 작업입니다. `ln`(옵션 없음)은 기존 파일의 inode에 대한 새로운 디렉터리 엔트리(이름)만 추가하는 **'연결'** 작업입니다. 따라서 디스크 공간 사용량에서 `ln`은 거의 변화가 없지만, `cp`는 파일 크기만큼 공간을 추가로 사용합니다.

**[Q3] 하드 링크는 왜 디렉토리에 생성할 수 없으며, 다른 파티션을 가로질러 만들 수 없습니까? | 태그: 링크(하드/심볼릭), 파일시스템/마운트**

- **정석체크(면접 30초)**: 디렉터리에 대한 하드 링크는 파일 시스템의 **계층 구조를 파괴하고 순환 참조**를 유발할 수 있어 대부분의 Unix 계열 시스템에서 금지됩니다. 또한 inode 번호는 **파일 시스템 단위로 독립적으로 관리**되므로, 한 파티션의 inode 번호가 다른 파티션에서는 의미가 없거나 다른 파일을 가리킬 수 있어 하드 링크가 불가능합니다.

## **2025-10-10, 2교시 — 개선본**

데이터의 중앙 집중화는 관리가 용이하다는 장점이 있지만, 해당 시스템이 무너지면 모든 것이 마비되는 심각한 단점이 있습니다. 최근 데이터센터 화재 사건은 백업 시스템의 부재가 어떤 결과를 초래하는지 보여주는 사례입니다. 데이터베이스 시스템에서 미러링(mirroring)을 통해 백업을 구축하듯, 분산 시스템 개념을 적용하여 자원을 분산시키고 연결해 사용하는 것이 중요합니다. 이는 보안의 기본 개념과도 직결됩니다.

---

### Linux 텍스트 편집기: `vi` (`vim`)

Linux 환경에서는 다양한 텍스트 편집기가 사용됩니다. `gedit`과 같이 GUI 환경에 기반한 편집기는 Windows의 메모장과 유사하지만, 서버 환경에서는 터미널 기반의 편집기를 사용하는 것이 일반적입니다. 그중 가장 대표적인 것이 `vi` 편집기입니다.

현재 대부분의 Linux 배포판에는 `vi`의 향상된 버전인 `vim` (`vi` IMproved)이 기본적으로 설치되어 있습니다. 터미널에서 `vi --version | more` 명령을 실행하면 `VIM - Vi IMproved`라는 메시지를 통해 이를 확인할 수 있습니다. `(실습)` `vim`은 블록 지정이나 다양한 편의 기능을 추가하여 기존 `vi`의 불편함을 개선한 버전입니다.

### `vi`의 특징: 모드(Mode)형 편집기

`vi`는 사용자가 경험한 메모장이나 워드프로세서와는 근본적으로 다른 **모드(Mode)형 편집기**입니다. 이는 하나의 편집기 창이 **명령 모드**와 **입력 모드** 등 여러 상태를 오가며 작동한다는 의미입니다.

1. **명령 모드 (Command Mode)**
    
    - `vi`를 실행했을 때의 기본 상태입니다.
    - 키보드 입력은 텍스트로 취급되지 않고, 커서 이동, 수정, 삭제, 복사, 저장, 종료 등의 **명령**으로 인식됩니다.
    - 마우스를 사용할 수 없으므로 모든 조작을 키보드 명령으로 수행합니다.
        
2. **입력 모드 (Insert Mode)**
    
    - 실제 텍스트를 입력할 수 있는 상태입니다.
    - 명령 모드에서 `i`, `a`, `o` 등의 키를 눌러 진입합니다.
    - 입력 모드에서 `Esc` 키를 누르면 다시 명령 모드로 돌아갑니다.

이 두 가지 모드를 전환하며 문서를 편집하는 것이 `vi` 사용의 핵심입니다.

### `vi` 기본 조작 실습

`vi`를 실행하면 화면에 `~` (틸다) 문자가 각 줄의 시작에 표시되며, 이는 해당 줄이 비어있음을 의미합니다.

먼저, `vi`를 실행하고 모드 전환을 체험해 봅시다. (실습)

1. 터미널에서 `vi`를 실행합니다. 현재는 **명령 모드**입니다.
2. 소문자 `i` 키를 누르면 화면 하단에 `-- INSERT --`와 같은 표시가 나타나며 **입력 모드**로 전환됩니다.
3. "hello" 등 원하는 텍스트를 입력합니다.
4. `Esc` 키를 누르면 입력 모드 표시가 사라지고 다시 **명령 모드**로 돌아옵니다.

이제 파일을 저장하거나 종료하는 방법을 알아봅시다. 모든 저장/종료 명령은 **명령 모드**에서 콜론(`:`)을 입력하여 시작합니다.

- `:q` : 변경 사항이 없을 때 종료합니다.
- `:q!` : 변경 사항을 **저장하지 않고 강제로 종료**합니다. 작업 내용을 무시하고 싶을 때 사용합니다. (실습)
- `:w` : 현재까지의 변경 사항을 파일에 **저장(write)**합니다.
- `:wq` : 변경 사항을 **저장하고 종료**합니다.
- `ZZ` : `:wq`와 동일하게 저장 후 종료하는 명령입니다.

만약 파일을 수정한 상태에서 `:q` 명령을 내리면, 저장되지 않은 변경 사항이 있다는 경고 메시지가 출력됩니다. 이때는 `:wq`로 저장하거나 `:q!`로 변경을 포기해야 합니다.

---

### 입력 모드 진입 명령 (`i`, `a`, `o`, `O`)

명령 모드에서 입력 모드로 전환하는 키는 여러 가지가 있으며, 커서의 위치를 기준으로 텍스트가 어디에 입력될지를 결정합니다.

- `i` (insert): **커서가 있는 위치 바로 앞**에서 입력을 시작합니다.
- `a` (append): **커서가 있는 위치 바로 뒤**에서 입력을 시작합니다.
- `o` (open): **커서가 있는 줄의 바로 아래**에 새 줄을 만들고 입력을 시작합니다.
- `O` (대문자): **커서가 있는 줄의 바로 위**에 새 줄을 만들고 입력을 시작합니다.

**참고**: Linux는 파일명과 명령어에서 **대소문자를 엄격하게 구분**합니다. `test.txt`와 `Test.txt`는 서로 다른 파일이며, `o`와 `O`는 전혀 다른 명령으로 작동합니다.

### `vi` 편집 실습

`ch04` 디렉토리를 생성하고, `vi`를 사용하여 파일을 만들고 편집해 봅시다. (실습)

1. `cd ~/study` 로 이동 후 `mkdir ch04` 디렉토리를 생성합니다.
2. `cd ch04` 로 이동합니다.
3. `vi vi_test.txt` 명령으로 새 파일을 엽니다.
4. `i` 키를 눌러 입력 모드로 전환한 뒤, 첫 번째 줄 텍스트를 입력합니다.
5. `Esc` 키로 명령 모드로 돌아온 뒤, `a`, `o`, `O` 키를 각각 사용하여 나머지 텍스트를 다른 줄에 입력하며 각 키의 차이점을 확인합니다.
6. 모든 내용을 입력한 후, `Esc` 키를 눌러 명령 모드로 돌아옵니다.
7. `:w` 명령을 입력하여 파일을 저장합니다. 화면 하단에 파일 이름과 저장된 라인 수, 바이트(byte) 수가 표시됩니다.
8. 새 터미널 창을 열어 `cd ~/study/ch04` 로 이동한 뒤, `ls -al` 명령으로 `vi_test.txt` 파일이 생성되었는지, 파일 크기가 `vi`에서 본 것과 일치하는지 확인합니다. (실습)
9. `:q` 명령으로 `vi`를 종료합니다.
