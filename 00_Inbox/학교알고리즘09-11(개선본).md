## Topic 1. 배열(Array)의 본질과 메모리 구조

### 1. 🏗️ 빌드업 (Why & Context)

> 동일한 자료형을 가진 데이터 3개를 저장할 때, `int a1, a2, a3;`와 `int a[3];`은 논리적으로 같아 보이지만 물리적으로는 완전히 다르다. 왜 굳이 배열을 사용하는가?

* **문제 제기:** 개별 변수(`a1, a2, a3`)로 선언하면 메모리상에서 연속성을 보장받지 못한다.
* **핵심 아이디어:** 데이터가 물리적으로 **연속(Contiguous)**되어 있다면, 시작 주소만 알 때 나머지 데이터의 위치를 수학적 계산으로 즉시 찾아낼 수 있다.

### Concept

* **메모리 할당의 차이:**
	* **개별 변수 (`int a1, a2, a3`):** 메모리 공간 어딘가에 산발적으로 생성된다(시스템 상황에 따라 불연속적). 주소값(`&a1`, `&a2`…)을 각각 따로 알아야 접근 가능하다.
	* **배열 (`int a[3]`):** 메모리 공간에 연속적으로 3개의 공간이 할당된다.
* **배열의 핵심 가치:**
	* 시작 주소(Base Address)만 알면 **인덱스 레지스터(Index Register)**를 통해 `Base + Offset` 연산으로 모든 원소에 접근 가능하다.
	* 이는 포인터 연산이 가능한 근거가 된다.

### Code 구현

```c
#include <stdio.h>

int main() {
    // [Case 1] 개별 변수: 메모리 주소가 연속적이지 않을 수 있음 (시스템 종속)
    int a1, a2, a3;
    
    // [Case 2] 배열: 메모리 주소가 물리적으로 연속됨이 보장됨
    int b[3];
    
    // 주소값 확인을 통해 물리적 연속성 검증 필요
    printf("a1: %p, a2: %p, a3: %p\n", &a1, &a2, &a3);
    printf("b[0]: %p, b[1]: %p, b[2]: %p\n", &b[0], &b[1], &b[2]);
    
    return 0;
}

```

## Topic 2. 프로그램 실행과 OS 자원 관리

### 1. 🏗️ 빌드업 (Why & Context)

> `main` 함수의 끝에 항상 쓰는 `return 0;`는 누구에게 보내는 값인가? 프로그램 강제 종료(`Ctrl+C`)와 정상 종료는 OS 입장에서 어떻게 다른가?

* **배경:** 코드는 에디터가 아니라 **운영체제(OS)** 위에서 실행된다. OS는 프로그램 실행 시 CPU, 메모리 등 자원을 할당한다.

### Concept

* **`return 0;`의 의미:**
	* **수신자:** 운영체제(OS).
	* **메시지:** "프로그램이 정상적으로 종료되었으니, 할당된 자원을 즉시 회수해가시오."
* **강제 종료 (`Ctrl+C` 등):**
	* OS가 비정상 종료 신호(예: `-1` 등)를 감지한다.
	* OS는 프로세스가 아직 처리 중인 작업이 있을 수 있다고 판단하여, 자원 회수를 즉시 하지 않고 **일정 시간 대기(Time Wait)** 하거나 처리를 유예한 뒤 회수한다. (좀비 프로세스 방지 등의 목적)
* **메모리 접근:**
	* 사용자는 변수명(`a1`)을 쓰지만, 컴파일러와 OS는 이를 **주소값**으로 변환하여 접근한다.

## Topic 3. 포인터 연산과 자료형의 중요성

### 1. 🏗️ 빌드업 (Why & Context)

> 왜 배열은 반드시 **동일한 자료형**이어야 하는가? `int` 배열과 `char` 배열에서 `p + 1`의 결과는 왜 다른가?

* **핵심 아이디어:** 컴퓨터는 시작 주소(Base)에서 '몇 칸'을 뛰어야 다음 데이터가 나오는지 알아야 한다. 그 '보폭'을 결정하는 것이 **자료형(Data Type)**이다.

### Concept

* **주소 계산 공식:**
	$Address(A[i]) = BaseAddress + (i \times sizeof(DataType))$
* **포인터 연산 (`p + 1`)의 의미:**
	* **상대 주소(Logical):** 인덱스는 항상 증가.
	* **물리 주소(Physical):** 자료형의 크기만큼 실제 메모리 주소가 증가.
		* `int` (4 bytes): 물리 주소 증가.
		* `char` (1 byte): 물리 주소 증가.
	* **배열의 자료형 통일 이유:** 자료형이 섞여 있다면(`int`, `char`, `double`…), 인덱스 이동 시 물리적으로 몇 바이트를 건너뛰어야 할지 규칙성을 잃어버려 `Base + Offset` 계산이 불가능해진다.

### Code 구현

```c
int a[3];
char c[3];

int *p = a;
char *cp = c;

// 논리적으로는 둘 다 +1 칸 이동이지만
// 물리적으로 p는 +4 byte, cp는 +1 byte 이동함
p++;  
cp++; 

```

* **⚠️ 주의:** 서로 다른 자료형을 하나의 배열처럼 쓰고 싶다면 `struct`를 사용해야 한다.

## Topic 5. 초기화 및 C언어의 배열 취약점

### 1. 🏗️ 빌드업 (Why & Context)

> 배열을 선언만 하고 초기화하지 않으면 어떤 값이 들어있는가? 배열의 범위를 벗어난 인덱스(`Index Out of Bounds`)에 접근하면 C언어는 어떻게 반응하는가?

### Concept

* **초기화 규칙:**
	* `int a[5];` (초기화 X): **쓰레기 값(Garbage Value)**이 들어있음 (이전 메모리 잔재).
	* `int a[5] = {1, 2};` (일부 초기화): 명시된 값 외 나머지 공간은 모두 **0으로 자동 초기화**.
	* `int a[] = {1, 2, 3};`: 크기를 생략하면 초기값 개수만큼 크기 자동 지정.
* **문자열 초기화:**
	* `char s[] = "abc";` -> 배열 크기는 4 (`a`, `b`, `c`, `\0`).
	* **Null Character (`\0`):** 문자열의 끝을 알리기 위해 필수적으로 포함되며 공간을 차지함.
* **C언어의 취약점 (vs Java):**
	* C언어에서 `a[10]` 크기의 배열 선언 후 `a[11]`을 출력하면 **오류(Error)가 발생하지 않고, 인접 메모리의 쓰레기 값을 출력**한다.
	* 이는 메모리 침범 버그나 보안 취약점의 원인이 되며, 최신 시스템(미 국방성 등)에서 C언어 사용을 지양하는 이유 중 하나이다.

### Code 구현

```c
// ⚠️ 초기화 주의사항
int arr[5] = {1, 2}; // arr[0]=1, arr[1]=2, arr[2]~[4]=0

// ⚠️ 문자열 주의사항
char str[] = "abc"; // sizeof(str)은 4 (Null 문자 포함)

// ⚠️ C언어의 위험성 (Index Out of Bounds)
// 컴파일 에러 없음, 런타임 에러 없을 수 있음. 
// 단순히 다음 주소의 메모리를 읽어버림.
printf("%d", arr[10]); 

```

## 기타 핵심 (Etc & Tips) - 알고리즘 09.11

* **CPU와 메모리:** CPU는 메모리에 직접 접근하지 않고, 데이터를 레지스터(MAR, MBR 등)로 가져와서 처리한다. 배열은 Base 주소를 레지스터에 두고 인덱싱하므로 매우 빠르다.
* **공부 조언:** 학교 수업은 개념 위주다. 반드시 집에 가서 Python이나 Java로 직접 구현하고 타임스탬프를 찍어 성능을 확인해봐야 한다.

### 💡 Interview

> [!faq]- Q. 배열(Array)과 연결 리스트(Linked List)의 결정적 차이는 무엇인가?
> **🗣️ 핵심 답변**
> 배열은 물리적으로 **연속된 메모리**를 사용하여 인덱스를 통한 **임의 접근(Random Access, )**이 가능합니다. 반면 연결 리스트는 메모리에 흩어진 노드들을 주소로 연결하므로, 특정 원소 접근 시 **순차 접근(Sequential Access, )**을 해야 합니다.
> **📚 꼬리질문 대비 / 심화**
> * **Q. 그렇다면 배열이 무조건 좋은가?**
> * 아닙니다. 배열은 크기가 고정적이고 중간 삽입/삭제 시 데이터 이동 비용()이 발생합니다. 빈번한 삽입/삭제가 필요하다면 연결 리스트가 유리합니다.

> [!faq]- Q. C언어에서 배열 인덱스를 벗어났을 때(Out of Bounds) 왜 에러가 즉시 발생하지 않는가?
> **🗣️ 핵심 답변**
> C언어는 **퍼포먼스**를 최우선으로 설계되어, 런타임에 배열의 경계 검사(Boundary Check)를 강제하지 않습니다. 따라서 유효하지 않은 인덱스에 접근해도 CPU는 해당 주소의 값을 그대로 읽거나 쓰는데, 이는 **버퍼 오버플로우(Buffer Overflow)** 같은 보안 취약점의 원인이 됩니다. Java 같은 최신 언어는 이를 방지하기 위해 `ArrayIndexOutOfBoundsException`을 발생시킵니다.
> [C언어와 자바가 배열 접근을 처리하는 방식의 차이 배열인덱스를 벗어났을때](C언어와%20자바가%20배열%20접근을%20처리하는%20방식의%20차이%20배열인덱스를%20벗어났을때.md)

> [!faq]- Q. `int a[3]`와 `struct A a[3]`의 포인터 연산 시 주소 증가값의 차이는?
> **🗣️ 핵심 답변**
> 포인터 연산(`ptr + 1`)은 해당 자료형의 크기(`sizeof(type)`)만큼 물리적 주소를 증가시킵니다. `int` 배열은 4바이트씩 증가하지만, 구조체 배열은 구조체의 총 크기(멤버 변수들의 합 + 패딩 바이트)만큼 주소가 증가합니다. 즉, 보폭(Stride)이 다릅니다.

## Topic 1. 다차원 배열의 실체 (2D/3D Array)

### 1. 🏗️ 빌드업 (Why & Context)

>**문제 제기:** 2차원(평면), 3차원(공간) 데이터를 다루지만, 컴퓨터의 메모리 주소는 **1차원(선형)**이다.

- **핵심 아이디어:** 다차원 배열은 논리적으로는 행/열/층으로 나뉘지만, 물리적으로는 **1차원 배열이 계속 이어져 있는 형태(Row-Major Order)**로 구현한다.
### Concept

- **메모리 저장 방식 (Row-Major Order):**
    - 2차원 배열 `int A[2][3]` 선언 시, 메모리에는 아래 순서로 연속 저장된다.
    - $A[0][0] \rightarrow A[0][1] \rightarrow A[0][2] \rightarrow A[1][0] \rightarrow A[1][1] \rightarrow A[1][2]$
    - 즉, 2차원 배열은 **1차원 배열들의 묶음**일 뿐이며, 시작 주소만 알면 연산을 통해 위치를 찾아간다.
- **초기화 규칙 (Partial Initialization):**
    - `int A[2][3] = {{1}, {2}};` 처럼 초기값을 부족하게 주면, 명시되지 않은 뒷부분은 **모두 0으로 자동 채워진다**.
    - $A[0][0]=1, A[0][1]=0, A[0][2]=0$
    - $A[1][0]=2, A[1][1]=0, A[1][2]=0$
        
### Code 구현

```C
// 3차원 배열 초기화 예시 (불완전한 초기값)
// A[2][3][3] 크기지만, 일부 값만 할당 -> 나머지는 0
int A[2][3][3] = {
    { {1}, {2} },   // 첫 번째 면(Page 0)
    { {3} }         // 두 번째 면(Page 1)
};

// 메모리 관점에서는 A[0][0][0]=1, A[0][0][1]=0… 순으로 연속됨
```

## Topic 2. 희소 행렬 (Sparse Matrix) 최적화

### 1. 🏗️ 빌드업 (Why & Context)

> 연립방정식($Ax=B$)을 풀거나 역행렬을 구할 때 행렬을 사용한다. 만약 $100 \times 100$ 크기의 행렬인데, 실제 데이터가 10개뿐이고 나머지가 다 0이라면? 이를 일반 2차원 배열로 저장하는 것은 엄청난 낭비다.

- **문제 제기:** 데이터의 대부분이 0인 **희소 행렬(Sparse Matrix)**을 2차원 배열로 선언하면, 0을 저장하기 위해 불필요한 메모리를 소모한다.
    - 예: $100 \times 100$ `int` 배열 = 10,000개 $\times$ 4byte = 40,000 byte (약 40KB).
    - 실제 유효 데이터가 10개라면 40KB 중 40byte만 유효함.
- **해결책:** 데이터가 존재하는 요소의 **(행, 열, 값)** 정보만 따로 저장한다.

### Concept

- **구조체 배열을 이용한 압축:**
    - 0이 아닌 데이터만 저장하기 위해 `struct { int row; int col; int value; }` 형태의 구조체 배열을 사용.
    - **Trade-off (중요):**
        - **장점:** 메모리 사용량을 획기적으로 줄임 (Memory Efficiency).
        - **단점:** 특정 좌표 $(r, c)$의 값을 찾거나 행렬 연산을 할 때, 구조체 배열을 뒤져야 하므로 연산 로직이 복잡해지고 속도가 느려질 수 있음 (Computational Complexity).

### Code 구현

```C
typedef struct {
    int row;
    int col;
    int value;
} Term;

// 희소 행렬 표현 (Sparse Matrix Representation)
// 0이 아닌 데이터만 저장하여 메모리 절약
Term sparseMatrix[10]; 
sparseMatrix[0].row = 1;
sparseMatrix[0].col = 3;
sparseMatrix[0].value = 5; // (1, 3) 위치에 값 5 존재
```

## Topic 3. 다중 포인터 (Multiple Indirection)

### 1. 🏗️ 빌드업 (Why & Context)

> 포인터가 주소를 저장한다면, '주소를 저장하는 변수의 주소'는 무엇인가? 자료구조(Linked List 등)에서 이중 포인터(`**p`)는 왜 등장하는가?

### Concept

- **정의:**
    - **Single Pointer (`*p`):** 데이터의 주소를 저장 ($\text{Address} \rightarrow \text{Value}$).
    - **Double Pointer (`**p`):** 포인터 변수의 주소를 저장 ($\text{Address} \rightarrow \text{Address} \rightarrow \text{Value}$).
    - **Triple Pointer (`***p`):** 이중 포인터의 주소를 저장.
- **사용처:** 주로 연결 리스트(Linked List) 등의 자료구조에서 **헤드 포인터 자체의 값을 함수 내에서 변경**해야 하거나, 동적 2차원 배열을 할당할 때 사용된다.

## Topic 4. 동적 메모리 할당 (Dynamic Memory Allocation)

### 1. 🏗️ 빌드업 (Why & Context)

> 배열(`int a[100]`)은 컴파일 타임에 크기가 고정된다(정적 할당). 프로그램 실행 중에 필요한 만큼만 메모리를 요청하고(`malloc`), 다 쓰면 반납(`free`)할 수는 없을까?

- **핵심 아이디어:** 프로그램 실행 중(Runtime)에 운영체제에게 "나 이만큼 메모리 줘"라고 요청하는 것. 이름(변수명)이 없으므로 **주소값(포인터)**으로만 관리한다.
    

### Concept

- **`malloc` (Memory Allocation):**
    - 힙(Heap) 영역에 메모리를 할당하고 첫 주소를 반환한다.
    - **반환 타입:** `void*` (어떤 자료형이 들어올지 모르므로, 개발자가 형변환하여 사용).
    - **실패 시:** `NULL` 포인터를 반환하므로 반드시 예외 처리가 필요하다.
- **`free` (Memory Deallocation):**
    - **매우 중요:** C언어에는 가비지 컬렉터(GC)가 없다. 할당된 메모리를 `free` 하지 않고 프로그램을 종료하면, 시스템 리셋 전까지 해당 메모리 공간은 **누수(Leak)**된 채로 남을 수 있다(운영체제에 따라 프로세스 종료 시 회수되기도 하지만, 서버/임베디드 환경에서는 치명적).
        

### Code 구현



```C
#include <stdlib.h>

int main() {
    // 1. 동적 할당: int형 1개 크기만큼 요청
    // void*를 int*로 형변환(Casting)
    int *p = (int*)malloc(sizeof(int));

    if (p == NULL) {
        // 메모리 부족 등으로 할당 실패 시 처리
        return -1;
    }

    // 2. 사용: 이름이 없으므로 포인터로 접근 (*p)
    *p = 10; 

    // 3. 해제: 다 썼으면 반드시 운영체제에 반납
    free(p); 
    
    return 0;
}
```

- **C언어의 숙명:** C언어는 시스템 프로그래밍(OS, 컴파일러, 임베디드)을 위한 언어다. 자바(Java)처럼 GC가 메모리를 관리해주지 않으므로, 개발자가 `malloc`과 `free`를 완벽하게 통제해야 한다. 이는 어렵지만 시스템의 바닥(Raw Level)을 이해하는 데 필수적이다.

### 💡 Interview

> [!faq]Q. 희소 행렬(Sparse Matrix)을 일반 2차원 배열이 아닌 구조체 배열(Coordinate List)로 표현할 때의 장단점은?
>
> 🗣️ 핵심 답변
>
> 장점은 메모리 효율성입니다. 대부분이 0인 행렬에서 0이 아닌 값만 저장하므로 공간 낭비를 획기적으로 줄일 수 있습니다.
>
> 단점은 연산 복잡도입니다. 배열은 인덱스($O(1)$)로 즉시 접근하지만, 구조체 배열은 특정 좌표의 값을 찾거나 행렬 곱셈을 수행할 때 데이터를 탐색하는 과정이 추가되어 연산 속도가 느려질 수 있습니다.

> [!faq]Q. malloc으로 할당한 메모리를 free 하지 않으면 발생하는 문제(Memory Leak)에 대해 설명하시오.
>
> 🗣️ 핵심 답변
>
> 힙(Heap) 영역에 할당된 메모리가 해제되지 않고 계속 점유된 상태로 남아있는 현상을 **메모리 누수(Memory Leak)**라고 합니다.
>
> 반복적으로 누수가 발생하면 가용 메모리가 고갈되어 시스템 성능 저하를 일으키거나, 결국 OOM(Out of Memory) 오류로 프로그램 또는 시스템이 강제 종료될 수 있습니다. 데몬이나 서버처럼 장시간 실행되는 프로그램에서는 치명적입니다.

> [!faq]Q. void* 포인터란 무엇이며, 왜 malloc은 void*를 반환하는가?
>
> 🗣️ 핵심 답변
>
> void*는 자료형이 정해지지 않은 포인터로, 어떤 자료형의 주소든 담을 수 있는 범용 포인터입니다.
>
> malloc 함수 입장에서는 사용자가 그 공간에 int를 쓸지 struct를 쓸지 알 수 없으므로, 가장 일반적인 형태인 void*로 주소를 반환하고 사용자가 알맞게 형변환(Casting)하여 쓰도록 설계되었습니다.

## Topic 1. `void` 포인터와 형 변환

### 1. 🏗️ 빌드업 (Why & Context)

> `int*`는 4바이트씩, `char*`는 1바이트씩 메모리를 읽는다. 그런데 `malloc`처럼 **"일단 메모리만 줘, 타입은 나중에 정할게"** 하는 경우에는 어떤 포인터를 써야 하는가?

- **핵심 아이디어:** 포인터의 타입은 "가리키는 곳의 데이터를 몇 바이트 단위로 해석할 것인가"를 결정한다. 하지만 이 정보 없이 주소만 저장하는 **만능 컨테이너**가 필요하다.
    

### Concept

- **`void*` (보이드형 포인터):**
    - **정의:** 타입 정보(크기) 없이 **오직 주소값만** 저장하는 포인터.
    - **특징:**
        - 포인터 연산(`p+1`) 불가능 (크기를 모르므로).
        - 역참조(`*p`) 불가능 (얼마나 읽어야 할지 모르므로).
    - **용도:** `malloc`의 반환값처럼 메모리 할당 후 사용자가 원하는 타입으로 **형 변환(Casting)** 하여 사용하도록 할 때 씀.
- **형 변환 (Casting):**
    - **암시적 변환:** `int a = char_val;` (데이터 손실 없음, 자동).
    - **명시적 변환:** `char c = int_val;` (데이터 손실 경고).
    - **포인터 변환:** `void*`를 `int*`로 변환할 때는 반드시 명시적 캐스팅을 권장한다. (`(int*)ptr`)
        

### Code 구현

C

```sql
int n = 10;
void *vp = &n; // 주소는 담을 수 있음

// *vp = 20; // [Error] 크기를 몰라 대입 불가

// 명시적 형 변환 후 사용 ("이 주소를 int(4byte)로 해석해라")
*(int*)vp = 20; 
```

## Topic 2. 포인터 초기화와 치명적 오류 (Memory Corruption)

### 1. 🏗️ 빌드업 (Why & Context)

> `char *pc; *pc = 'a';` 이 코드는 왜 컴퓨터를 멈추게 하거나 블루스크린을 띄우는가?

- **문제 제기:** 포인터를 선언만 하고 초기화하지 않으면, 그 안에는 **쓰레기 값(Garbage Value)**이 들어있다.
- **위험성:** 그 쓰레기 값이 우연히 **OS 커널 영역**이나 **코드 영역(Text Segment)**의 주소라면?
    

### Concept

- **초기화되지 않은 포인터의 동작:**
    
    1. `char *pc;` -> `pc` 변수에 임의의 주소(예: `0x1234A`)가 들어있음.
    2. `*pc = 'a';` -> 메모리 `0x1234A` 위치에 값 'a'를 씀.
    3. 만약 `0x1234A`가 현재 실행 중인 CPU 명령어(Opcode)가 있는 곳이라면? -> **명령어가 오염됨.**
    4. CPU가 오염된 명령어를 인출(Fetch)하여 실행하려다 멈춤 -> **System Freeze / Segfault / Blue Screen**.
        
- **해결책:** 포인터는 선언과 동시에 유효한 주소를 주거나, `NULL`로 초기화해야 한다.

## Topic 3. Call by Value vs Reference (Stack 관점)

### 1. 🏗️ 빌드업 (Why & Context)

> `swap(a, b)`를 해도 왜 `main`의 값은 바뀌지 않는가? 스택 메모리에서 무슨 일이 일어나는가?

### Concept

- **Call by Value (값에 의한 호출):**
    - 함수 호출 시, 인자의 **값(Value)**이 복사되어 함수의 스택 프레임(Stack Frame)에 새로 생성됨.
    - 함수 내에서 값을 바꿔도, 복사본(`copy`)만 바뀌고 원본(`original`)은 유지됨.
    - 함수 종료 시 스택 프레임이 날아가며 복사본도 소멸.
- **Call by Reference (참조에 의한 호출 - Pointer 이용):**
    - 인자로 **주소(Address)**를 전달.
    - 함수는 주소를 통해 원본 메모리 공간에 직접 접근(`dereference`)하여 값을 수정.
    - 메모리 효율: 구조체(예: 40MB)를 통째로 복사하는 대신, 4Byte 주소만 넘기므로 훨씬 효율적.
        

### Code 구현

C

```sql
// [Fail] Call by Value
void swap_fail(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
    // 함수 종료 시 a, b는 Stack에서 사라짐. Main에는 영향 없음.
}

// [Success] Call by Reference
void swap_ok(int *p, int *q) {
    int temp = *p; // p가 가리키는 주소(Main의 a)의 값을 가져옴
    *p = *q;       // q가 가리키는 값(Main의 b)을 p가 가리키는 곳에 넣음
    *q = temp;
}
```

## Topic 4. 함수 원형과 `main` 인자

### 1. 🏗️ 빌드업 (Why & Context)

> 왜 `#include <stdio.h>`를 습관적으로 쓰는가? `int main(int argc, char *argv[])`는 누가 호출하는가?

### Concept

- **함수 원형 (Function Prototype):**
    - 컴파일러는 위에서 아래로(Top-down) 코드를 읽는다.
    - `main` 함수가 `swap` 함수보다 위에 있다면, 컴파일러는 `swap`의 존재(반환형, 인자 개수)를 모른다.
    - 이를 알리기 위해 상단에 `void swap(int*, int*);`와 같이 **선언(Declaration)**을 해줘야 자원을 할당할 수 있다. 헤더 파일에는 이러한 원형들이 들어있다.
- **Main Arguments (`argc`, `argv`):**
    - **호출자:** 운영체제(OS).
    - **구조:** 프로그램 실행 시 옵션을 파싱하기 위함 (예: `ls -al` 에서 `ls`, `-al`이 토큰으로 분리됨).
    - `argc`: 인자의 개수.
    - `argv`: 인자 문자열들의 배열(포인터 배열).

## Topic 5. 프로그램 실행 구조 (Memory Layout)

### 1. 🏗️ 빌드업 (Why & Context)

> 컴파일된 코드는 메모리에 어떻게 로드되는가? 함수가 끝나면 어떻게 원래 위치로 돌아오는가?

- **핵심 아이디어:** 프로그램이 실행되면 메모리는 4가지 영역으로 나뉘고, CPU의 **PC(Program Counter)**가 이들을 오가며 명령을 수행한다.
    

### Concept

- **메모리 4대 영역:**
    
    1. **Code (Text):** 기계어 코드가 저장되는 곳. (Read-only)
    2. **Data:** 전역 변수(Global), 정적 변수(Static). 프로그램 종료 시까지 유지.
    3. **Heap:** `malloc` 등 동적 할당 영역. 사용자가 관리.
    4. **Stack:** 지역 변수, 함수 매개변수. 함수 호출 시 생성, 종료 시 자동 소멸(LIFO).
        
- **함수 호출 메커니즘 (Context Switch):**
    
    1. `main` 실행 중 `swap()` 호출.
    2. 현재 PC값(돌아올 주소)과 레지스터 상태를 **Stack에 Push**.
    3. PC를 `swap` 함수의 시작 주소로 변경 (Jump).
    4. `swap` 수행 후, Stack에서 **Return Address**를 꺼내(Pop) PC에 복원.
    5. `main`의 원래 위치로 복귀.

## Topic 6. 포인터 연산 심화 (이중 포인터)

### 1. 🏗️ 빌드업 (Why & Context)

> `p1 = a + 1`일 때, `p1`이 가리키는 것은 무엇인가? `*p++`와 `(*p)++`는 어떻게 다른가?

### Concept

- **이중 포인터 (Double Pointer):**
    - `int **p3`: `p3`는 `int*` 타입 변수의 주소를 담는다.
    - 접근: `p3`(자신) $\rightarrow$ `p2`(중간 포인터) $\rightarrow$ `a`(실제 값).
- **포인터 연산 우선순위:**
    - `*p++`: 주소를 먼저 증가시키고, 그 **이전 주소**의 값을 가져옴 (후위 연산 특성).
    - `(*p)++`: 값을 먼저 가져오고, **그 값 자체**를 1 증가시킴.
        

### Code 구현 (강의 예제 복기)

C

```sql
int a[5] = {5, 4, 3, 2, 1};
int *p1 = a + 1; // a[1]의 주소 (값: 4)
int *p2 = p1;    // p2도 a[1]을 가리킴
int **p3 = &p2;  // p3는 p2의 주소를 가리킴

// [Check]
// *p1 == 4
// *p2 == 4
// **p3 == *p2 == 4

// [Operation]
// *p2++ -> p2의 주소값이 int 크기만큼 증가 (a[2]를 가리키게 됨). 값은 바뀌지 않음.
// (*p2)++ -> p2가 가리키는 값(a[1])이 4에서 5로 증가.
```

### 💡 Interview

> [!faq]Q. void* 포인터를 사용하는 이유와 주의할 점은?
>
> 🗣️ 핵심 답변
>
> void*는 타입이 정해지지 않은 범용 포인터로, malloc과 같이 다양한 타입을 반환해야 하거나 제네릭한 함수를 구현할 때 사용합니다.
>
> 주의할 점은 대상의 크기 정보가 없으므로 포인터 연산(p+1)이나 역참조(*p)가 불가능합니다. 따라서 사용 시에는 반드시 적절한 데이터 타입으로 **명시적 형 변환(Casting)**을 해야 합니다.

> [!faq]Q. 함수 호출 시 Stack 메모리와 Program Counter(PC)는 어떻게 동작하는가?
>
> 🗣️ 핵심 답변
>
> 함수가 호출되면 현재 실행 중인 명령어의 다음 주소(Return Address)를 Stack에 저장(Push)하고, PC를 호출할 함수의 시작 주소로 갱신하여 점프합니다.
>
> 함수 실행이 끝나면 Stack에서 저장해둔 복귀 주소를 꺼내(Pop) PC에 적재함으로써 원래 실행 흐름으로 돌아옵니다. 이 과정에서 매개변수와 지역변수도 Stack 프레임에 할당됩니다.

> [!faq]Q. 초기화되지 않은 포인터에 값을 대입(*p = 10)하면 어떤 문제가 발생하는가?
>
> 🗣️ 핵심 답변
>
> 초기화되지 않은 포인터는 예측할 수 없는 쓰레기 주소값을 가지고 있습니다. 이 상태에서 값을 대입하면 운영체제의 커널 영역이나 코드 영역 등 중요한 메모리를 덮어쓸 위험이 있습니다.
>
> 이는 Segmentation Fault나 시스템 멈춤(Crash)을 유발하며, 보안상 치명적인 취약점이 될 수 있습니다. 따라서 포인터는 반드시 NULL이나 유효한 주소로 초기화해야 합니다.
.
