## 정리
### 12-9) 이걸 언제 쓰나?->현업 시나리오

- **웹 폼 입력 검증**
    회원가입/로그인/주문 작성 등 **HTML 폼 값**을 서버에서 1차 검증.
    → @Valid MemberForm + BindingResult로 **같은 화면에 오류 표기**(Thymeleaf th:errors).
    
- **관리자 화면(Backoffice) 데이터 입력**
    운영자가 상품/쿠폰을 등록·수정할 때 **필수값/범위/형식**을 강제.
    → 도메인 규칙(예: 재고 ≥ 0, 할인율 0~100)을 DTO 제약으로 명시.

- **REST API 요청 본문(JSON) 검증**
    모바일·프론트에서 오는 **JSON 바디**를 검증.
    → @RequestBody @Valid CreateOrderRequest 사용(보통 BindingResult 없이 예외 → @ControllerAdvice로 표준 에러 JSON 반환).

- **서비스/도메인 계층 메서드 인자 검증**
    컨트롤러를 거치지 않고도 **서비스 메서드 파라미터**를 방어하고 싶을 때.
    → @Service @Validated + 메서드 파라미터에 제약(예: @NotNull Long memberId).
    
- **중첩 객체/컬렉션 항목 검증**
    주소, 라인아이템 등 **내부 객체** 혹은 **리스트 항목**까지 검증해야 할 때.
    → 필드에 @Valid 붙여 **검증 전파**.

### **12-1) 핵심 요약**

- **@Valid**: 파라미터 객체에 **Bean Validation 수행** 지시. 실패 시 에러를 **BindingResult**에 담아 전달.
- **BindingResult**: **바인딩/검증 에러 컨테이너**. **검증 대상 파라미터 바로 뒤**에 둬야 스프링이 자동으로 채워줌
	- public String create(@Valid MemberForm form, BindingResult result) // @Valid 붙인 파라미터바로 뒤
	- 이걸 사용하면 result.hasErrors()로 분기 처리 가능
- **@NotEmpty**: null도 빈값("")도 금지. (공백 " "은 허용)
    - 문자열은 보통 **@NotBlank**(공백만도 금지)가 더 실용적.
### **12-2) 실무 플로우**

```Java
// GET: 바인딩 대상 준비
@GetMapping("/members/new")
public String createForm(Model model) {
    model.addAttribute("memberForm", new MemberForm());
    return "members/createMemberForm";
}


// POST: 검증 → 실패 시 같은 뷰 재렌더
@PostMapping("/members/new")
public String create(@Valid MemberForm form, BindingResult result) {
    if (result.hasErrors()) { //
        return "members/createMemberForm"; // 값 + 에러 유지 후 재렌더
    }
    // 성공 로직: DTO→엔티티 변환, 서비스 호출 등
    return "redirect:/";
}
```

```html
<form th:object="${memberForm}" th:action="@{/members/new}" method="post">
  <input th:field="*{name}"/>
  <!--> @NotEmpty(message = "이안의 값이 여기에 채워져 출력함")<-->
  <div th:if="${#fields.hasErrors('name')}" th:errors="*{name}"></div> 
  <button type="submit">가입</button>
</form>
```

### **12-3) 애노테이션 비교(문자열 기준)**

|**애노테이션**|**금지 범위**|**비고**|
|---|---|---|
|@NotNull|null만|"" 허용|
|@NotEmpty|null, ""|" "(공백)은 허용|
|@NotBlank|null, "", "   "|**문자열 권장**|

### **12-4) 자주 쓰는** BindingResult API

- result.hasErrors() : 에러 존재여부
- result.hasFieldErrors("name")
- result.rejectValue("name", "코드", "기본메시지") : 수동으로 필드 에러 추가
- result.reject("글로벌코드", "기본메시지") : 폼 전체(글로벌) 에러 추가
### **12-5) 메시지 커스터마이즈 예시**

```Java
# messages.properties
NotEmpty.memberForm.name=이름은 필수입니다.
NotBlank.memberForm.name=이름은 공백일 수 없습니다.
```

> 메세지 키 우선순위:
> 제약명.objectName.field → 제약명.field → 제약명

### **12-6) 중첩 객체 검증**

- MemberForm 내부에 Address address가 있고 그 필드도 검증하려면
    **필드 선언부에 @Valid** 추가 필요.
```java
class MemberForm {
    @NotBlank private String name;
    @Valid private Address address; // 여기에 @Valid
}
```

### **12-7) REST 컨트롤러와 차이**

- @RequestBody + @Valid(JSON)에서는 보통 BindingResult 없이 **예외**가 발생 →
    @ControllerAdvice로 잡아 **에러 응답 JSON** 작성.
- 폼 바인딩(서버 템플릿)은 **같은 뷰 재렌더**, REST는 **에러 본문 반환** 전략.

### **12-8) 체크리스트**

- BindingResult를 **검증 대상 바로 뒤**에 뒀는가?
- 문자열엔 **@NotBlank**가 더 적합한가?
- **중첩 필드에 @Valid**를 붙였는가?
- 메시지 키를 messages.properties에 준비했는가?
- 실패 시 **같은 뷰**를 반환해 값/에러가 보존되는가?
