## Topic 1. 구조체(Structure)와 메모리 접근

### 1. 🏗️ 빌드업 (Why & Context)

- **문제 제기:** 현실 세계의 객체(예: 학생)는 학번(int), 이름(char array), 학점(float) 등 **서로 다른 자료형**의 속성을 동시에 가진다.
- **기존 한계:** 배열은 '같은 자료형'의 집합이므로 이를 한 번에 표현하기 어렵다.
- **해결책:** 사용자 정의 자료형인 **구조체(`struct`)**를 사용하여 이질적인 데이터를 하나의 단위로 묶는다.
    

### 2. Concept

- **구조체 정의:** 여러 변수를 묶어 새로운 자료형을 만드는 것. (자료구조의 Stack, Queue, Node 등도 결국 구조체를 기반으로 한 사용자 정의 자료형임).
- **함수 전달 방식 (중요):**
    
    1. **Call by Value:** 구조체 변수 자체를 전달. 값이 복사됨. 함수 내 변경이 원본에 영향 없음. 메모리/성능 오버헤드 발생 가능.
    2. **Call by Reference (Pointer):** 구조체의 주소값을 전달. `->` 연산자로 접근. 함수 내 변경이 원본에 반영됨. **Linked List 등 자료구조 구현의 핵심 방식.**
        

### 3. Code 구현


```C
typedef struct {
    int pips;
    char suit;
} Card;

// 1. Call by Value (원본 안 바뀜, 값 복사)
void assignValue(Card c) {
    c.pips = 1; // 복사본의 값만 변경됨
}

// 2. Call by Reference (원본 바뀜, 포인터 접근)
void assignPointer(Card* c) {
    c->pips = 1; // 원본의 값 변경 (c.pips와 동일한 의미지만 포인터이므로 -> 사용)
}

int main() {
    Card c1 = {5, 'd'};
    assignValue(c1);   // c1.pips는 여전히 5
    assignPointer(&c1); // c1.pips가 1로 변경됨
}
```

## Topic 2. 다항식(Polynomial) 표현 방식의 비교

### 1. 🏗️ 빌드업 (Why & Context)

- **목표:** $10x^5 + 6x + 3$ 같은 다항식을 컴퓨터에 저장하고 연산(덧셈)하려 한다.
- **접근법:** 어떤 자료구조를 택하느냐에 따라 공간 효율성과 알고리즘 복잡도가 달라진다.
    

### 2. Concept: 두 가지 접근법 비교

#### **Method A: 차수(Degree)를 인덱스로 사용하는 배열**

- **방식:** 배열 `coef[degree]`에 계수를 저장. 즉, `coef[5] = 10` ($10x^5$).
- **장점:** 덧셈 연산 시 같은 인덱스끼리 더하면 되므로 알고리즘이 매우 간단하다.
- **단점(치명적):** **희소 다항식(Sparse Polynomial)** 처리에 비효율적.
    - 예: $x^{100} + 1$을 저장하려면 크기 101인 배열이 필요하지만, 실제 데이터는 2개뿐. 나머지 99개는 0으로 채워져 **메모리 낭비 심각**.
 
#### **Method B: (계수, 지수) 쌍을 저장하는 구조체 배열**

- **방식:** 0이 아닌 항만 `(coef, expon)` 형태로 구조체 배열에 연속 저장.
- **장점:** 데이터가 있는 항만 저장하므로 메모리 공간 낭비가 없다.
- **단점:** 덧셈 연산 시 지수(exponent)를 비교하는 로직이 추가되어야 한다.
    

### 3. Code 구현 (Method B)

```C
typedef struct {
    float coef;  // 계수
    int expon;   // 지수
} Polynomial;

Polynomial terms[MAX_TERMS]; // 0이 아닌 항들만 순차적으로 저장
int avail = 0; // 현재 비어있는 첫 번째 인덱스
```

## Topic 3. 다항식 덧셈 알고리즘 (Method B 기반)

### 1. 🏗️ 빌드업 (Why & Context)

- **문제:** 구조체 배열 방식으로 저장된 두 다항식 $A(x)$와 $B(x)$를 더해 $C(x)$를 만들어야 한다.
- **핵심 아이디어:** 두 배열은 이미 **지수(exponent) 내림차순**으로 정렬되어 있다고 가정한다. 두 배열의 포인터를 이동하며 지수를 비교(Compare)한다.
    

### 2. Concept: Two-Pointer Logic

1. **Case 1 ($A_{exp} > B_{exp}$):** $A$의 차수가 더 크다. → $A$항을 결과 배열 $C$에 복사, $A$ 포인터 증가.
2. **Case 2 ($A_{exp} < B_{exp}$):** $B$의 차수가 더 크다. → $B$항을 결과 배열 $C$에 복사, $B$ 포인터 증가.
3. **Case 3 ($A_{exp} == B_{exp}$):** 차수가 같다. → 계수를 더함(`coef_sum = A.coef + B.coef`).
    
    - 합이 0이 아니면 $C$에 추가.
    - $A, B$ 포인터 모두 증가.
        
4. **Residuals (잔여항 처리):** 한쪽 배열이 먼저 끝나면, 나머지 배열의 남은 항들을 $C$에 몽땅 복사한다.
    

### 3. Code 구현


```C
// a와 b 다항식을 더해서 c에 저장하는 로직의 핵심
// startA, endA: A다항식의 시작과 끝 인덱스
// startB, endB: B다항식의 시작과 끝 인덱스

while (startA <= endA && startB <= endB) {
    if (terms[startA].expon > terms[startB].expon) {
        // A의 차수가 더 크면 A를 결과에 추가
        attach(terms[startA].coef, terms[startA].expon);
        startA++;
    }
    else if (terms[startA].expon == terms[startB].expon) {
        // 차수가 같으면 계수 합산
        float sum = terms[startA].coef + terms[startB].coef;
        if (sum != 0) attach(sum, terms[startA].expon);
        startA++; startB++;
    }
    else {
        // B의 차수가 더 크면 B를 결과에 추가
        attach(terms[startB].coef, terms[startB].expon);
        startB++;
    }
}
// 남은 항들 복사 (Residuals)
for (; startA <= endA; startA++) attach(terms[startA].coef, terms[startA].expon);
for (; startB <= endB; startB++) attach(terms[startB].coef, terms[startB].expon);
```



## Topic 4. 중첩 구조체 & 자기 참조 구조체 (Linked List의 서막)

### 1. 🏗️ 빌드업 (Why & Context)

- **중첩 구조체(Nested Struct):** 구조체 안에 다른 구조체를 멤버로 포함. (예: `Student` 안에 `Date` 구조체 포함). 데이터의 계층적 구조화 가능.
- **자기 참조 구조체(Self-Referential Struct):** 구조체 멤버 중 하나가 **자기 자신과 같은 형의 포인터**인 경우.
    

### 2. Concept

- **자기 참조 구조체의 의의:**
    - 데이터를 담는 공간(`data`)과 다음 데이터를 가리키는 포인터(`link`)를 묶을 수 있다.
    - 이것이 바로 **연결 리스트(Linked List)**의 노드(Node)가 된다.
    - 배열처럼 미리 크기를 정해놓지 않고, `malloc`(동적 할당)을 통해 필요할 때마다 노드를 생성하고 연결할 수 있어 메모리 관리가 유연하다.
        

### 3. Code 구현


```C
// 1. 중첩 구조체 예시
typedef struct {
    int year;
    int month;
    int day;
} Date;

typedef struct {
    char name[10];
    Date birthday; // 구조체 안에 구조체 포함
} Student;

// 2. 자기 참조 구조체 (Linked List Node)
typedef struct ListNode {
    char data[10];
    struct ListNode* link; // 자기 자신을 가리키는 포인터
} ListNode;

// 사용 예시
ListNode* head = NULL;
ListNode* node1 = (ListNode*)malloc(sizeof(ListNode)); // 동적 할당
// node1->link 에 다음 노드의 주소를 넣어 연결함
```

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.09.18

- **`strcpy` vs 대입 연산:** 문자열 배열(`char name[10]`)에는 ` =`로 문자열을 직접 대입할 수 없다. 반드시 `strcpy`를 사용해야 한다. 단, 구조체끼리의 대입(`struct1 = struct2`)은 멤버들의 타입이 같다면 통째로 복사(Copy)가 가능하다.
- **타입 정의(`typedef`):** `struct polynomial …` 처럼 매번 쓰기 귀찮으므로 `typedef`를 적극 활용하여 코드 가독성을 높인다.

> [!faq]- Q. 희소 다항식(Sparse Polynomial) 표현 시 배열보다 구조체 배열(또는 연결 리스트)이 유리한 이유는?

>
> 반면 구조체 배열이나 연결 리스트는 0이 아닌 항(Non-zero terms)의 계수와 지수만 저장하므로 메모리 공간 효율성이 월등히 높습니다.
>
> **📚 꼬리질문 대비**
>
> - **Q:** 구조체 배열 방식의 단점은?
>     
> - **A:** 덧셈 등의 연산 구현 시, 인덱스끼리 바로 더할 수 없고 두 다항식의 지수(Exponent)를 비교하며 포인터를 이동하는 별도의 로직(Two-pointer 알고리즘)이 필요해 구현 복잡도가 올라갑니다.
>     

> [!faq]- Q. C언어 구조체 전달 시 Call by Value와 Call by Reference의 차이는?
>
> 🗣️ 핵심 답변
>
> Call by Value는 구조체의 모든 멤버 값이 복사되어 전달되므로 원본 데이터가 보호되지만, 구조체 크기가 클 경우 복사 비용(Overhead)이 큽니다.
>
> Call by Reference(포인터 전달)는 주소값만 전달하므로 속도가 빠르고 함수 내에서 원본 데이터를 수정할 수 있습니다. 자료구조 구현 시에는 주로 포인터 방식이 사용됩니다.

## Topic 1. 리스트 ADT의 구현: 배열(Array) 방식

### 1. 🏗️ 빌드업 (Why & Context)

- **문제 제기:** '오늘의 할 일'처럼 순서가 있는 데이터의 집합을 관리하려면 리스트(List)가 필요하다. 가장 직관적인 구현 방법은 **배열**이다.
- **핵심 요구사항:** 리스트는 단순 조회가 아니라, 임의의 위치에 **삽입(Insert)**하고 **삭제(Delete)**하는 연산이 빈번하다.
    

### 2. Concept

- **정의:** 배열을 사용하여 리스트를 구현하되, 데이터가 들어있는 개수를 나타내는 `length` 변수를 함께 관리한다.
- **한계점 (Trade-off):**
    
    1. **정적 할당 (Static Allocation):** 선언 시 크기가 고정됨(`MAX_SIZE`). 데이터가 넘치면 수용 불가(Overflow).
    2. **오버헤드 (Overhead):** 중간 삽입/삭제 시 데이터 이동(Shifting) 비용 발생.
        
        - **삽입 시:** 삽입 위치 뒤의 모든 데이터를 **한 칸씩 뒤로 밀어야 함.**
        - **삭제 시:** 삭제 위치 뒤의 모든 데이터를 **한 칸씩 앞으로 당겨야 함.**

### 3. Code 구현 (Insertion Logic)

> **⚠️ 중요 로직:** 삽입 시 데이터를 덮어쓰지 않기 위해 반드시 **맨 뒤에서부터** 이동시켜야 한다.

```C
// 배열 기반 리스트 삽입 의사 코드 (Pseudo-logic)
// L: 리스트, pos: 삽입 위치, item: 데이터

// 1. 포화 상태 확인
if (L->length >= MAX_LIST_SIZE) error("List Full");

// 2. 유효 위치 확인
if (pos < 0 || pos > L->length) error("Invalid Position");

// 3. 데이터 이동 (Shifting) - 맨 뒤에서부터 pos까지
// i는 현재 데이터가 있는 마지막 인덱스부터 시작
for (int i = L->length - 1; i >= pos; i--) {
    L->list[i + 1] = L->list[i]; // 뒤로 한 칸 이동
}

// 4. 데이터 삽입 및 길이 증가
L->list[pos] = item;
L->length++;
```

## Topic 2. 연결 리스트 (Linked List)의 본질

### 1. 🏗️ 빌드업 (Why & Context)

- **배열의 한계 극복:** 다이어리 페이지가 꽉 찼을 때, 다음 장이 아니라 포스트잇을 붙여서 내용을 확장하듯 **동적(Dynamic)**으로 공간을 늘릴 수 없을까?
- **해결:** 물리적인 연속성을 포기하고, **논리적인 연결(Link)**을 통해 데이터를 관리하자.
    

### 2. Concept

- **구조:** **Node = Data + Link(Pointer)**
    - 데이터와 다음 데이터의 주소를 함께 저장하는 구조체.
- **특징:**
    - **동적 할당:** 필요할 때마다 `malloc`으로 노드를 생성하므로 크기 제한이 없음(메모리 허용 내).
    - **삽입/삭제 효율성:** 데이터를 밀거나 당길 필요 없이, **포인터(링크)만 변경**하면 됨 ($O(1)$, 단 위치 탐색 제외).
    - **임의 접근 불가:** 인덱스로 한 번에 접근($O(1)$)하는 배열과 달리, Head부터 순차 탐색($O(N)$)해야 함.
        

### 3. Code 구현



```C
typedef struct ListNode {
    int data;
    struct ListNode* link; // 다음 노드의 주소 저장
} ListNode;

// 개념적 연결: A -> B -> C
// A->link = B의 주소
// B->link = C의 주소
```

## Topic 3. 포인터 연산과 치명적 오류 (Memory Leak)

### 1. 🏗️ 빌드업 (Why & Context)

- **문제:** 연결 리스트는 구현이 복잡하다. 특히 포인터 연산 실수 시 프로그램이 죽거나 메모리가 샌다.
- **핵심 경고:** "삭제(Delete) 연산 시 링크만 끊으면 끝이 아니다."
    

### 2. Concept & Caution

- **삭제 메커니즘:**
    
    1. 이전 노드(`prev`)가 삭제할 노드(`cur`)의 다음 노드(`cur->link`)를 가리키게 한다. (`prev->link = cur->link`)
    2. 이 시점에서 리스트의 논리적 연결에서는 `cur`가 사라졌다.
    3. **[Critical]** 그러나 메모리 상에는 `cur`가 여전히 존재한다.
        
- **Memory Leak (메모리 누수):**
    - `malloc`으로 빌린 공간은 `free`를 하지 않으면 운영체제에 반환되지 않는다.
    - 삭제 연산의 마지막은 반드시 **`free(cur)`**여야 한다. 이를 누락하면 서버급 프로그램에서 심각한 리소스 고갈을 초래한다.
        

### 3. 구현상 주의점

- **Head Pointer:** 리스트의 시작점을 가리키는 포인터. 이 놈을 잃어버리면 리스트 전체에 접근 불가능.
- **Null Check:** 빈 리스트(`Head == NULL`)에서 삭제를 시도하거나, 끝(`NULL`)에 도달했는데 접근하려 하면 Segmentation Fault 발생.

## Topic 4. 연결 리스트의 변형 (Circular & Doubly)

### 1. 🏗️ 빌드업 (Why & Context)

- **단순 연결 리스트(Singly Linked List)의 단점:**
    - 한 방향으로만 간다. "내 앞의 노드"를 알 수 없다.
    - 뒤로 돌아가려면 다시 Head부터 와야 한다.
        

### 2. Concept: 변형 구조 비교

#### **A. 원형 연결 리스트 (Circular Linked List)**

- **구조:** 마지막 노드의 링크가 `NULL`이 아니라 **Head(첫 노드)**를 가리킴.
- **최적화 기법 (강의 강조 포인트):**
    - 보통 `Head` 포인터가 **첫 번째 노드**를 가리키게 구현한다.
    - 하지만 **`Head` 포인터가 '마지막 노드(Tail)'를 가리키게 구현**하면 효율이 극대화된다.
    - **이유:**
        - `Head`(변수명은 tail이라고 짓기도 함)는 마지막 노드를 가리킴.
        - `Head->link`는 첫 번째 노드를 가리킴.
        - 즉, **리스트의 맨 앞과 맨 뒤에 모두 $O(1)$로 접근 가능**해짐.
            

#### **B. 이중 연결 리스트 (Doubly Linked List)**

- **구조:** `Link`가 두 개. (`prev`, `next`).
- **장점:** 양방향 탐색 가능. 탐색 중 뒤로 돌아갈 수 있음.
- **구현:** 보통 **헤드 노드(Head Node)**라는 더미(Dummy) 노드를 사용하여 구현 복잡도를 낮춤 (데이터는 없고 포인터만 가진 노드).

## Topic 1. 연결 리스트의 삽입(Insertion) 메커니즘

### 1. 🏗️ 빌드업 (Why & Context)

- **핵심 과제:** 두 노드 `before`와 `after` 사이에 새로운 노드 `new`를 끼워 넣으려 한다.
- **주의사항:** 연결 리스트는 주소값(Link) 하나로 다음 노드를 찾아가는 구조다. 순서를 잘못 정하면 **뒤쪽 리스트(`after` 이후)의 주소를 영원히 잃어버리는(Lost Pointer)** 사고가 발생한다.
    

### 2. Concept

- **순서의 중요성 (Order Matters):**
    
    1. **선(先) 연결:** `new` 노드가 먼저 `after` 노드(기존 `before->link`)를 가리키게 한다.
    2. **후(後) 갱신:** 그 다음, `before` 노드가 `new` 노드를 가리키게 변경한다.
    - 반대로 하면? `before->link`를 먼저 `new`로 바꿔버리면, 원래 `before`가 가리키던 `after`의 주소를 알 방법이 없어져 리스트가 끊긴다.
- **Edge Cases (경계값 처리):**
    - **Head가 NULL일 때:** 리스트가 비어있는 상태. `new`가 첫 노드가 됨.
    - **Preceding Ptr(`p`)가 NULL일 때:** 맨 앞에 삽입하는 경우.
        

### 3. Code 구현



```C
// 노드 정의
typedef struct ListNode {
    int data;
    struct ListNode* link;
} ListNode;

// 삽입 함수 (head: 헤드 포인터의 주소, p: 선행 노드, new_node: 삽입할 노드)
void insert_node(ListNode** head, ListNode* p, ListNode* new_node) {
    // Case 1: 공백 리스트인 경우 (head가 NULL을 가리킴)
    if (*head == NULL) {
        new_node->link = NULL;
        *head = new_node;
    }
    // Case 2: 맨 앞에 삽입하는 경우 (p가 NULL)
    else if (p == NULL) {
        new_node->link = *head; // 기존 head가 가리키던 것을 new가 가리킴
        *head = new_node;       // head는 이제 new를 가리킴
    }
    // Case 3: 중간 삽입 (일반적인 경우)
    else {
        new_node->link = p->link; // 1. new가 p 다음 노드를 가리킴
        p->link = new_node;       // 2. p가 new를 가리킴
    }
}
```

## Topic 2. 연결 리스트의 삭제(Deletion) 메커니즘

### 1. 🏗️ 빌드업 (Why & Context)

- **맥락:** 특정 노드(`removed`)를 리스트에서 제거하려 한다.
- **핵심:** '나'를 삭제하려면 내 정보를 알고 있는 '내 앞 노드(`before` 혹은 `p`)'가 필요하다. 내 앞 노드의 링크를 내 뒤 노드(`removed->link`)로 연결해줘야 한다.
    

### 2. Concept

- **삭제 로직:**
    - `p->link` (앞 노드의 링크)에 `removed->link` (삭제할 노드가 가리키던 다음 노드)를 대입.
    - **메모리 해제:** 논리적 연결을 끊은 후, 반드시 `free(removed)`를 호출하여 동적 할당된 메모리를 반환해야 한다.
- **Edge Cases:**
    - **p가 NULL일 때:** 맨 앞 노드(Head Node)를 삭제하는 경우. `head` 포인터를 `head->link`(두 번째 노드)로 옮긴다.
        

### 3. Code 구현



```C
// 삭제 함수 (head: 헤드 포인터의 주소, p: 선행 노드, removed: 삭제할 노드)
void delete_node(ListNode** head, ListNode* p, ListNode* removed) {
    if (p == NULL) {
        // 맨 앞 노드 삭제
        *head = (*head)->link;
    } else {
        // 중간 노드 삭제: p의 링크를 removed 다음 노드로 연결
        p->link = removed->link;
    }
    free(removed); // 메모리 해제 (필수)
}
```

## Topic 3. 리스트 탐색(Search)과 병합(Concatenation)

### 1. 🏗️ 빌드업 (Why & Context)

- **탐색:** 특정 데이터 `x`가 있는지 확인하기 위해 첫 노드부터 순차적으로 방문(Visit)해야 한다.
- **병합:** 두 개의 리스트(List1, List2)를 하나로 합친다(`strcat`과 유사).
    

### 2. Concept

- **탐색 (Search):**
    - 포인터 `p`를 `head`부터 시작하여 `p->link`를 따라 이동.
    - `p != NULL`일 동안 반복하며 `p->data == x`인지 확인.
- **병합 (Concatenation):**
    - List1이 비어있으면 List2가 결과.
    - List1의 끝(`NULL`)까지 이동한 후, 마지막 노드의 링크를 List2의 첫 노드(`head2`)로 연결.
- **응용 (다항식 덧셈):**
    - 탐색 및 병합 로직을 응용하면, 다항식 $A$와 $B$를 순회하며 지수가 같은 항끼리 더하여 새 리스트에 연결하는 방식으로 구현 가능하다.
        

### 3. Code 구현



```C
// 리스트 탐색
ListNode* search(ListNode* head, int x) {
    ListNode* p = head;
    while (p != NULL) {
        if (p->data == x) return p; // 찾으면 노드 주소 반환
        p = p->link; // 다음 노드로 이동
    }
    return p; // 못 찾으면 NULL 반환
}

// 리스트 병합 (list1 뒤에 list2 붙이기)
ListNode* concat(ListNode* head1, ListNode* head2) {
    if (head1 == NULL) return head2;
    else if (head2 == NULL) return head1;
    
    ListNode* p = head1;
    while (p->link != NULL) { // list1의 끝까지 이동
        p = p->link;
    }
    p->link = head2; // list1의 끝을 list2의 시작과 연결
    return head1;
}
```

## Topic 4. 연결 리스트의 역순 변환 (Reverse) - **[과제/심화]**

### 1. 🏗️ 빌드업 (Why & Context)

- **문제 제기:** 리스트의 노드 순서를 거꾸로 뒤집고 싶다 ($A \to B \to C$ 를 $C \to B \to A$ 로).
- **난점:** 단일 연결 리스트는 "내 뒤"만 알지 "내 앞"을 모른다. 따라서 단순 순회로는 역순 연결이 불가능하다.
    

### 2. Concept: 3-Pointer Sliding Window

- 교수님 강조: **"p, q, r 세 개의 포인터를 사용하여 링크 방향을 뒤집는다."** (다음 시간까지 분석해 올 과제).
- **매커니즘:**
    - `p`: 현재 처리할 노드 (앞으로 전진).
    - `q`: 현재 노드의 이전 노드 (링크를 역으로 받을 노드).
    - `r`: `q`의 이전 노드 (역연결이 완료된 노드).
- **알고리즘 흐름:**
    
    1. `p`가 다음 노드로 이동하기 전에, `q`의 링크 방향을 `r`로 바꾼다.
    2. `r`, `q`, `p`를 한 칸씩 오른쪽으로 이동(Shift)시킨다.
    3. `p`가 `NULL`이 될 때까지 반복.
        

### 3. Code 구현 (분석용)



```C
ListNode* reverse(ListNode* head) {
    ListNode *p, *q, *r;
    p = head; // 현재 노드
    q = NULL; // 이전 노드 (역순 리스트의 헤드 될 예정)
    r = NULL; // 전전 노드
    
    while (p != NULL) {
        r = q;          // 1. r을 q 위치로 이동
        q = p;          // 2. q를 p 위치로 이동
        p = p->link;    // 3. p를 다음 노드로 미리 이동 (연결 끊기기 전 대피)
        q->link = r;    // 4. q의 링크를 r(이전 노드)로 역연결!
    }
    return q; // q가 새로운 헤드가 됨
}
```

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.09.18

- **이중 포인터(`ListNode**`) 사용 이유:** 함수 내에서 `head` 포인터 자체의 값(즉, `head`가 가리키는 주소)을 변경해야 할 때(예: 맨 앞에 삽입/삭제), 싱글 포인터(`ListNode*`)로 받으면 Call by Value로 인해 원본 `head`가 바뀌지 않는다. 따라서 `head`의 주소를 담는 이중 포인터가 필요하다. (강의에서는 `phead`로 표현).
- **`malloc`과 리턴 타입:** `malloc`은 `void*`를 반환하므로, 사용하려는 구조체 포인터 타입으로 명시적 형변환(Casting)을 해주는 것이 정석이다. 예: `(ListNode*)malloc(…)`.
    

### 💡 Interview

> [!faq]- Q. 연결 리스트 삽입 시 new_node->link = p->link를 p->link = new_node보다 먼저 수행해야 하는 이유는?
>
> 🗣️ 핵심 답변
>
> **주소 유실(Lost Pointer)**을 방지하기 위해서입니다.
>
> p->link = new_node를 먼저 수행하면, 기존에 p가 가리키던 다음 노드(after)의 주소값이 덮어씌워져 사라집니다. 이렇게 되면 리스트의 나머지 부분에 접근할 수 없게 되므로, 반드시 다음 노드의 주소를 new_node에 먼저 연결한 후 p의 링크를 변경해야 합니다.

> [!faq]- Q. 연결 리스트 역순(Reverse) 알고리즘에서 포인터가 3개(p, q, r) 필요한 이유는?
>
> 🗣️ 핵심 답변
>
> 단일 연결 리스트는 이전 노드로 돌아갈 수 없기 때문입니다.
>
> 현재 노드(q)의 링크를 이전 노드(r)로 바꾸는 순간, 다음 노드(p)로 갈 수 있는 연결이 끊어집니다. 따라서 다음에 갈 곳(p), 현재 처리 중인 곳(q), 연결할 대상인 이전 곳(r) 세 가지 정보를 동시에 유지하며 이동해야 안전하게 링크 방향을 뒤집을 수 있습니다.
