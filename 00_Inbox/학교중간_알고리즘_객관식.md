## **1) 비교표(핵심 정리)**

### **1-1. 메모리 4영역 요약**

|**영역**|**담기는 것**|**수명**|**비고(함정)**|
|---|---|---|---|
|**Code**|기계어 코드|프로그램 전체|실행만, 수정 X|
|**Data**|전역/static/리터럴|프로그램 전체|3.14 같은 상수도 여기|
|**Stack**|지역변수, 매개변수, 복귀주소|함수 범위|**LIFO**, 자동 생성/소멸|
|**Heap**|동적할당(malloc/free)|프로그래머 제어|**누수 주의**, 실패 시 NULL|

### **1-2. 배열 vs. 연결 리스트**

|**항목**|**배열**|**연결 리스트**|
|---|---|---|
|저장|**연속** 메모리|**비연속**, 포인터 연결|
|접근|임의 접근 **O(1)**|순차 접근 **O(n)**|
|삽입/삭제|중간 **O(n)**|위치 알면 **포인터조작 O(1)** _(탐색 별도)_|
|기타|크기 고정, 캐시 친화|크기 가변, 구현 난이도↑|

### **1-3. 스택 vs. 큐 vs. 우선순위 큐(힙)**

|**구조**|**정책**|**대표 용도**|**핵심 포인트**|
|---|---|---|---|
|**스택**|LIFO|함수 호출/인터럽트|**PC(복귀주소)** push/pop|
|**큐**|FIFO|버퍼/스풀러|배열 구현 시 **원형 큐**로 보완|
|**우선순위 큐(힙)**|우선순위|스케줄링|루트가 최고 우선, **O(log n)** 추출|

### **1-4. 포인터·배열 핵심**

|**항목**|**요지**|**함정**|
|---|---|---|
|포인터 크기|아키텍처로 결정(32비트=4B 등)|sizeof(pointer) ≠ sizeof(가리키는 대상)|
|산술|p+1 = p + sizeof(*p)|p++는 바이트 1이 아님|
|배열이름|**상수 포인터 성질**|arr++ 불가, 함수 인자 시 decay 주의|
|연산자|*p++ ≡ *(p++)|(*p)++와 구분|

### **1-5. 값/참조 호출 (C)**

|**방식**|**전달**|**효과**|
|---|---|---|
|**Call by Value**|값 복사|원본 불변, 큰 구조체 비효율|
|**Call by Reference(효과)**|**포인터(주소) 값으로 전달**|원본 수정 가능, 주소 1개만 이동|

### **1-6. 리스트 변형**

|**형태**|**구조**|**장점**|**주의**|
|---|---|---|---|
|단순|next|구현 단순|역방향 탐색 X|
|원형|마지막→첫 노드|순회 유연|이전 노드 탐색은 여전히 O(n)|
|이중|prev/next|양방향 O(1)|포인터 갱신 4곳|
|**원형·이중+더미(권장)**|센티넬|경계처리 제거|빈 리스트: head->next==head|

### **1-7. 트리 구현**

|**구현**|**장점**|**단점**|**비고**|
|---|---|---|---|
|**배열**|완전 이진트리에 효율, 인덱스 빠름|편향 트리 낭비|부모 i/2, 자식 2i, 2i+1(루트=1)|
|**연결**|유연, 동적|포인터 오버헤드|일반적 구현|

### **1-8. 정렬 요약**

|**알고리즘**|**평균/최악**|**안정성**|**특징**|
|---|---|---|---|
|선택|O(n²)/O(n²)|**불안정**|비교 많고 swap 적음(패스 당 1회)|
|삽입|O(n²)/O(n²), **최선 O(n)**|**안정**|이동(shift) 기반, 거의 정렬에 강함|
|버블|O(n²)/O(n²)|**안정**|인접교환, 구현 쉬움|
|쉘|대체로 ~O(n^1.5)|불안정|gap로 삽입 보강|
|퀵|**O(n log n)** / O(n²)|불안정|피벗 편향이 최악 유발|

### **1-9. 희소 행렬 표현**

|**방식**|**공간**|**접근**|**코멘트**|
|---|---|---|---|
|2D 배열|O(MN)|O(1)|0이 많으면 낭비|
|**(row,col,val) 목록**|**O(k)**|O(k)/정렬시 O(log k)|연산 로직 복잡, k≪MN에 유리|

## **2) “함정(오답 유도)” 체크리스트 (Top 15)**

1. int 크기 항상 4B? **시스템 의존**.
2. char는 “문자형”만? **작은 정수형**.
3. register int a; &a 가능? **불가**(주소 없음).
4. arr++ 가능? **불가**(배열이름=비수정 lvalue).
5. *p++ vs (*p)++ 혼동.
6. 연결 리스트 **삽입 순서** 뒤집어 뒷부분 유실.
7. 원형·이중·더미 리스트의 **빈 리스트 판정** 실수(head->next==head).
8. 배열 큐 **dequeue마다 당기기** → 원형 큐/링 인덱스 필요.
9. malloc 반환 **NULL 체크** 누락.
10. 동적해제 free 누락 → **메모리 누수**.
11. C 배열 **경계검사 없음** → UB.
12. **우선순위 큐=힙**(큐와 목적 다름).
13. 트리: **포화 vs 완전** 혼동.
14. 쉘 정렬 **gap** 영향 무시.
15. main의 return 0 수신자는 **OS(종료코드)**.

## **4) 문항은행 — 주관식 10문항 (각 1분, 키워드 채점)**

> 형식: **문항 → 기대 답안 핵심 → 채점 키워드**

**S1.** C의 **Call by Value**와 **Call by Reference(효과)** 차이, swap 예로 설명.

- 기대 답안: C는 값 전달만 지원, **주소(포인터)를 값으로** 넘기면 원본 수정 가능. swap(int*a,int*b)는 주소로 접근하여 교환.
- 키워드: “값 복사”, “주소 전달”, “원본 수정”.

**S2.** 배열 인덱스 주소 공식과 CPU 베이스/인덱스 레지스터의 역할.

- 기대 답안: addr(a[i]) = base + i*sizeof(T). 베이스=시작주소, 인덱스=오프셋, 하드웨어가 **O(1)** 계산.
- 키워드: base, index, sizeof.

**S3.** **헤드 포인터** vs **헤드 노드(더미)** 차이.

- 기대 답안: 포인터는 “주소를 담는 변수”, 더미는 “실제 노드(데이터 없음)”로 경계 처리를 단순화. 빈 리스트 판정은 head->next==head.
- 키워드: “주소 변수”, “센티넬”, “경계 제거”.

**S4.** 단순 연결 리스트 **중간 삽입** 2단계 순서.

- 기대 답안: new->next = prev->next; prev->next = new;(기존 연결 먼저 확보).
- 키워드: “연결 먼저”, “덮어쓰기 방지”.

**S5.** **원형 이중 연결 리스트의 ‘원형’ 의미**와 핵심 불변식 2개.

- 기대 답안: 마지막과 첫 노드가 **양방향**으로 연결. 임의 노드 p에 대해 p->prev->next==p, p->next->prev==p.
- 키워드: “마지막↔첫”, “prev/next 대칭”.

**S6.** struct card deck[10]; 의미와 struct card *p=deck;에서 포인터 크기 설명.

- 기대 답안: 구조체 10개가 **연속** 저장. 포인터 크기는 **주소 크기(아키텍처 의존)**, 구조체 크기와 무관.
- 키워드: “연속”, “주소 크기”, “무관”.

**S7.** 함수 원형(프로토타입)과 #include <stdio.h>의 관계.

- 기대 답안: 호출 전에 시그니처 알려 타입 검사. stdio.h는 printf 등 **프로토타입 선언** 제공.
- 키워드: “선언”, “시그니처”, “검사”.

**S8.** main의 return 0;의 의미.

- 기대 답안: OS로 **종료 코드(0=성공)** 반환, 스크립트/부모 프로세스가 활용.
- 키워드: “종료 코드”, “성공/실패”.

**S9.** 왜 어떤 함수는 헤드 포인터를 **이중 포인터(Node **)**로 받는가?

- 기대 답안: **포인터 자체를 변경**해야(맨 앞 삽입/삭제) 호출자 변수 갱신 가능.
- 키워드: “포인터의 주소”, “원본 포인터 수정”.

**S10.** 연결 리스트 기반 **다항식 덧셈** 절차.

- 기대 답안: 두 포인터로 지수 비교(>,<,=)하며 큰 지수 먼저, 같으면 계수 합; 한쪽 끝나면 나머지 **붙이기**.
- 키워드: “지수 비교”, “병합형”, “잔여 붙이기”.

## **5) 원형이중 연결리스트 핵심 정리(교재형 요약)**

- **정의**: 각 노드가 prev/next를 가져 양방향 연결되며, **마지막의 next가 첫 노드**, **첫 노드의 prev가 마지막**을 가리키는 구조.
- **더미(헤드) 노드**를 두면 빈 리스트도 head->next==head && head->prev==head가 되어 **모든 연산을 ‘두 노드 사이’로 통일**.
- **불변식**: 임의의 p에 대해 p->prev->next==p, p->next->prev==p.
- **주의**: “헤드 포인터가 마지막 노드를 가리키면 원형”이 **아님**. 그것은 **원형 단순 리스트**에서 편의를 위한 한 구현. **원형성은 연결 자체**의 성질.
