# 0. 신장트리, 최소신장트리

## Topic 3. 최소 비용 신장 트리 (MST, Minimum Spanning Tree): 간선들의 가중치합 가장 싸게+ 그래프의 모든 정점을 간선수를 최소화해 포함하고, 사이클이 없다, 그리디 알고리즘 쓰는

- **핵심 접근법: 그리디 알고리즘 (Greedy Algorithm)**
	- **개념:** 매 순간 가장 좋아 보이는(가장 싼) 선택을 하여 최종 해답에 도달하는 방식.
	- **검증 필요성:** 그리디는 항상 최적해를 보장하지 않으므로 증명이 필요하다. 다행히 MST 문제에서는 Kruskal과 Prim 알고리즘 모두 **최적해를 보장함**이 증명되었다.
- **대표 알고리즘 (예고):**
    1. **Kruskal Algorithm**
    2. **Prim Algorithm**

> [!faq]Q 신장 트리(Spanning Tree)와 최소 비용 신장 트리(MST)의 차이점은?
>
> 🗣️ 핵심 답변
>
> 신장 트리는 그래프의 모든 정점을 사이클 없이 $N-1$개의 간선으로 연결한 부분 그래프를 말하며, MST는 이러한 신장 트리들 중에서 간선의 가중치 합이 가장 작은 트리를 의미합니다. 즉, MST는 가중치 그래프에서 비용 효율성을 극대화한 신장 트리입니다.

## Topic 1. Kruskal 알고리즘 (Edge-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "가장 비용이 적은 다리(간선)부터 놓는다. 단, 섬(Cycle)이 고립되거나 갇히지 않게."

### Concept

- **접근법:** **간선(Edge)** 을 중심으로 동작.
- **핵심 로직:**
    1. **정렬 (Sorting):** 그래프의 모든 간선을 가중치 기준 **오름차순**으로 정렬한다.
    2. **선택 (Selection):** 가장 가중치가 작은 간선부터 선택한다.
    3. **검사 (Cycle Detection):** 선택한 간선이 사이클을 만드는지 확인한다.
        - 사이클 생성 O $\rightarrow$ 버림 (Skip).
        - 사이클 생성 X $\rightarrow$ 신장 트리에 추가.
    4. **종료:** 선택된 간선의 개수가 $N-1$개가 되면 종료.
        
### 복잡도 및 특징
- **시간 복잡도:** 간선 정렬에 $O(E \log E)$ 소요.
- **적합성:** 간선이 적은 **희소 그래프(Sparse Graph)**에 유리하다.
### 주요 알고리즘: Union-Find (Disjoint Set)

- **역할:** 간선 추가 시 사이클 발생 여부를 판단하는 알고리즘.
- **원리:**
    - `Find(x)`: 노드 x가 속한 집합의 루트(대장)를 찾는다.
    - `Union(x, y)`: 두 집합을 합친다.
    - 만약 `Find(u) == Find(v)`라면, u와 v는 이미 같은 집합(연결됨)이므로 간선을 추가하면 **사이클**이 발생한다.
        

### Code 구현 (논리 흐름)

```C
// Kruskal MST Logic
void Kruskal(GraphType* g) {
    Edge edges[] = sort_edges(g); // 1. 간선 정렬 (O(E log E))
    int edge_count = 0;
    
    set_init(g->n); // Union-Find 초기화

    for (int i = 0; i < g->e; i++) {
        // 2. 가장 작은 간선 선택
        int u = edges[i].u;
        int v = edges[i].v;

        // 3. 사이클 검사 (Find)
        if (set_find(u) != set_find(v)) {
            set_union(u, v); // 두 집합 합치기
            add_edge_to_mst(u, v);
            edge_count++;
            
            // 4. 종료 조건
            if (edge_count == g->n - 1) break;
        }
    }
}
```

## Topic 4. Prim 알고리즘 (Vertex-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "이미 개척된 땅(Tree)에서 가장 가까운 미개척지(Non-Tree)를 하나씩 병합한다."

### Concept

- **접근법:** **정점(Vertex)** 을 중심으로 동작. 시작 정점은 어디든 상관없음(결과 가중치 합은 동일).
- **핵심 로직:**
    1. **초기화:** 시작 정점 하나를 트리에 포함(`visited`). 나머지 모든 정점까지의 거리는 무한대($\infty$).
    2. **탐색:** 현재 트리 집합(Set)에서 인접한 간선 중 **가중치가 가장 작은 간선**으로 연결된 정점을 찾는다.
    3. **확장:** 해당 정점을 트리에 포함시키고, 그 정점과 연결된 간선 정보를 바탕으로 '갈 수 있는 최단 거리'를 갱신한다.
    4. **반복:** $N-1$개의 간선이 선택될 때까지 반복.
        
### 복잡도 및 특징

- **적합성:** 간선이 많은 **밀집 그래프(Dense Graph)**에 유리하다. (정렬 비용이 없으므로)
- **장점:** 시작 정점이 어디든 결과같음
### Code 구현 (논리 흐름)

```C
// Prim MST Logic
void Prim(GraphType* g, int start_node) {
    int distance[MAX_VERTICES]; // 트리에 인접한 거리
    int visited[MAX_VERTICES] = {0};
    
    // 초기화: 모든 거리 무한대, 시작점은 0
    for(int i=0; i<g->n; i++) distance[i] = INF;
    distance[start_node] = 0;

    for (int i = 0; i < g->n; i++) {
        // 1. 방문하지 않은 노드 중 distance가 가장 작은 노드 u 선택
        int u = delete_min(distance, visited); 
        visited[u] = TRUE;
        
        // 2. u에 인접한 노드들의 거리 갱신
        for (each node v connected to u) {
            if (!visited[v] && weight[u][v] < distance[v]) {
                distance[v] = weight[u][v]; // 더 짧은 거리 발견 시 갱신
            }
        }
    }
}
```

## Topic 5. 알고리즘 비교 및 정리 (Analysis)

### 1. 시간 복잡도와 적합성

| **특징**     | **Kruskal 알고리즘**                        | **Prim 알고리즘**                          |
| ---------- | --------------------------------------- | -------------------------------------- |
| **중심**     | **간선 (Edge)** 중심                        | **정점 (Vertex)** 중심                     |
| **핵심 연산**  | 간선 정렬 (Sort)                            | 최소 거리 찾기 (Priority Queue)              |
| **탐색 방식**  | 가장 싼 간선부터 툭툭 끊어서 연결 (전역적)               | 시작 정점에서 점점 영역을 넓힘                      |
| **유리한 경우** | **희소 그래프 (Sparse Graph)**<br>(간선이 적을 때) | **밀집 그래프 (Dense Graph)**<br>(간선이 많을 때) |
| **구현 난이도** | 정렬과 Union-Find 필요                       | 이중 루프 또는 우선순위 큐 필요                     |
| **시간 복잡도** | $O(E \log E)$ (정렬 시간)                   | $O(N^2)$ (배열) 또는 $O(E \log N)$ (힙)     |
|            |                                         |                                        |

### 2. 강조 포인트

### 💡 Interview

> [!faq]Q Kruskal과 Prim 알고리즘 중 어떤 상황에서 무엇을 선택해야 하는가?
>
> 🗣️ 핵심 답변
>
> 그래프 내 **간선의 밀도(Density)**에 따라 결정합니다.
>
> 간선의 개수가 적은 **희소 그래프(Sparse Graph)**에서는 간선 정렬 비용이 주도하는 Kruskal 알고리즘($O(E \log E)$)이 유리하며,
> 간선이 많은 **밀집 그래프(Dense Graph)**에서는 정점 위주로 탐색하는 Prim 알고리즘($O(N^2)$ or $O(E \log N)$)이 더 효율적일 수 있습니다.

> [!faq]Q 간선이 매우 많은 '밀집 그래프(Dense Graph)'에서 MST를 구할 때 Kruskal보다 Prim이 유리한 이유는?
>
> 🗣️ 핵심 답변
>
> Kruskal 알고리즘은 간선을 정렬하는 과정이 필수적인데, 간선 수($E$)가 많으면 정렬 비용($O(E \log E)$)이 매우 커집니다. 반면, Prim 알고리즘은 정점 개수($N$)에 비례하는 $O(N^2)$ 방식으로 구현할 수 있어, $E$가 $N^2$에 가까운 밀집 그래프에서는 정렬 오버헤드가 없는 Prim이 더 효율적입니다.

> [!faq]Q Kruskal 알고리즘에서 사이클 발생 여부를 효율적으로 판단하기 위해 사용하는 자료구조는 무엇이며, 그 원리는?
>
> 🗣️ 핵심 답변
>
> 유니온-파인드(Union-Find) 자료구조를 사용합니다. Find 연산으로 두 정점의 루트 노드를 확인하여, 만약 루트가 같다면 이미 같은 집합에 속해 있는 것(연결됨)이므로 사이클이 발생한다고 판단합니다. 다르다면 Union 연산으로 두 집합을 합칩니다.
>
> **📚 성능**
>
> - 경로 압축(Path Compression)과 랭크 기반 합치기(Union by Rank)를 적용하면 거의 상수 시간($O(\alpha(N))$)에 연산이 가능합니다.
>

# 0. 최단경로, 다익스트리아
## Topic 2. 최단 경로(Shortest Path)와 그래프 표현

### 1. 🏗️ 빌드업 (Why & Context)

> **"지도에서 서울부터 부산까지 가는 길은 무수히 많다. 그중 가장 빠른 길을 어떻게 찾을까?"**

- MST(최소 신장 트리)는 모든 노드를 연결하는 것이 목적이었다면, **최단 경로**는 두 정점 사이의 **가중치 합이 최소**가 되는 경로를 찾는 것이 목적이다.

#### 2) 최단 경로 알고리즘의 분류

- **Dijkstra (다익스트라):** **하나의 시작점** $\rightarrow$ 다른 모든 정점 (One-to-All). 음수 가중치 불가.
- **Floyd-Warshall (플로이드-워셜):** **모든 정점** $\rightarrow$ 모든 정점 (All-to-All).

### 3. Code 구현 (초기화)

```C
#define INF 1000000 // 연결되지 않음을 표현하는 무한대 값

// 가중치 그래프 초기화 예시 (adj_mat[i][j] = i에서 j로 가는 비용)
// i == j 이면 0, 간선이 없으면 INF
int weight[MAX_VERTICES][MAX_VERTICES] = {
    {0, 7, INF, INF, 3, 10, INF},
    {7, 0, 4, 10, 2, 6, INF},
    // … (생략)
};
```

## Topic 2. Dijkstra Code 구현

### 2. Code 구현 (Core Structure)

```C
// 핵심 변수
// distance[]: 시작점으로부터의 최단 거리 저장
// found[]: 방문한 정점 표시 (집합 S)
// weight[][]: 가중치 인접 행렬 (초기 그래프 정보)

void dijkstra(int start, int n) {
    // 1. 초기화: 시작점과 연결된 간선 비용으로 distance 배열 세팅
    for(int i=0; i<n; i++) {
        distance[i] = weight[start][i];
        found[i] = FALSE;
    }
    found[start] = TRUE;
    distance[start] = 0;

    // 2. 루프: 시작점을 제외한 n-1개 정점에 대해 반복
    for(int i=0; i<n-1; i++) {
        
        // [Greedy Step]
        // 방문하지 않은 정점 중 distance가 가장 작은 정점 u 반환
        int u = choose(distance, n, found);
        
        found[u] = TRUE; // 집합 S에 추가
		//플로이드이면 바깥 for문
		//for (k = 0; k < n; k++) {// k: 경유지 (반드시 가장 바깥쪽 루프)
        // [Relaxation Step]
        // 새로 추가된 정점 u를 거쳐서 가는 거리가 더 짧으면 갱신
        for(int w=0; w<n; w++) {
            if(!found[w]) { // 아직 방문 안 한 정점에 대해
                // 기존 거리 vs (u까지 거리 + u에서 w로 가는 거리)
                if(distance[u] + weight[u][w] < distance[w]) {
                    distance[w] = distance[u] + weight[u][w];
                }
            }
        }
    }
}
```

### 💡 Interview

> [!faq]Q 다익스트라 알고리즘에서 매 단계 가장 거리가 짧은 정점을 선택하는 이유는 무엇인가요? (Greedy 속성)
>
> 🗣️ 핵심 답변
>
> 현재 방문하지 않은 정점 중 가장 거리가 짧은 정점은, 다른 어떤 미방문 정점을 거쳐서 오더라도 더 짧아질 가능성이 없기 때문입니다. (간선 가중치가 양수라는 전제 하에) 따라서 그 시점에 해당 정점까지의 최단 거리를 확정지을 수 있습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **음수 가중치가 있다면?** 음수 간선이 존재하면, 더 멀리 돌아가더라도 나중에 거리가 줄어들 수 있으므로 다익스트라의 그리디 논리가 깨집니다. 이 경우 **벨만-포드(Bellman-Ford)** 알고리즘을 사용해야 합니다.
>     

> [!faq]Q 다익스트라 알고리즘의 시간 복잡도는 어떻게 되나요?
>
> 🗣️ 핵심 답변
>
> 구현 방식에 따라 다릅니다. 배열을 사용하여 선형 탐색으로 최소 정점을 찾을 경우 $O(V^2)$입니다. 하지만 **우선순위 큐(Min Heap)**를 사용하여 최소 정점을 $O(\log V)$에 찾으면 전체 복잡도는 **$O(E \log V)$**로 최적화할 수 있습니다. (V: 정점 수, E: 간선 수)

> [!faq]Q 다익스트라 알고리즘을 구현할 때 '우선순위 큐(Priority Queue)'를 사용하면 어떤 이점이 있는가?
>
> 🗣️ 핵심 답변
>
> 기본적인 배열 탐색 방식은 가장 가까운 노드를 찾기 위해 매번 $O(N)$의 탐색이 필요하여 총 $O(N^2)$의 시간이 걸립니다. 하지만 우선순위 큐(Min Heap)를 사용하면 가장 가까운 노드를 $O(\log N)$에 찾을 수 있어, 전체 시간 복잡도를 $O(E \log N)$으로 줄일 수 있습니다. 이는 간선이 적은 희소 그래프에서 매우 효율적입니다.
---

> [!faq]Q 다익스트라 알고리즘이 '그리디(Greedy)' 기법인 이유는?
>
> 🗣️ 핵심 답변
>
> 매 단계에서 현재 방문하지 않은 노드 중 가장 거리가 짧은 노드를 선택하여 방문하고, 그 선택을 번복하지 않기 때문입니다. 즉, "지금 당장 갈 수 있는 가장 가까운 곳이 최단 경로의 일부일 것이다"라는 가정하에 동작합니다.

## Topic 2. 플로이드-워셜 (Floyd-Warshall)

#### 2) 알고리즘 특징

- **입력:** 인접 행렬 (자기 자신 0, 간선 없으면 $\infty$).
- **구조:** 3중 `for`문 (Loop).
    - **가장 바깥쪽 Loop ($k$):** 경유할 정점 (0 ~ $N-1$). **(※ 가장 중요: 반드시 $k$가 가장 바깥에 있어야 함)**
    - **중간 Loop ($i$):** 출발 정점.
    - **안쪽 Loop ($j$):** 도착 정점.
- **시간 복잡도:** $O(N^3)$. (정점 개수가 적을 때 매우 효과적, 구현이 매우 간단함).
    

### 3. Code 구현 (Logic)

```C
// A[i][j]는 초기에 가중치 인접 행렬로 초기화됨 (없으면 INF)

// k: 경유지 (반드시 가장 바깥쪽 루프)
for (k = 0; k < n; k++) {
    // i: 출발지
    for (i = 0; i < n; i++) {
        // j: 도착지
        for (j = 0; j < n; j++) {
            // 기존 거리보다 k를 거쳐가는 거리가 짧으면 갱신
            if (A[i][k] + A[k][j] < A[i][j]) {
                A[i][j] = A[i][k] + A[k][j];
            }
        }
    }
}
```

## Topic 3. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Why & Context)

> **"알고리즘을 들으려면 자료구조를 먼저 들어야 한다. 이 순서를 어떻게 정할까?"**

- 대학의 **선수 과목(Prerequisite)** 시스템이 가장 대표적인 예시.
- 일의 순서가 정해져 있는 작업들을 순서대로 나열하는 알고리즘.
### 2. Concept

#### 1) 정의 및 조건

- **정의:** 방향 그래프의 모든 노드를 "선행 순서(방향성)"를 거스르지 않도록 나열하는 것.
- **필수 조건:** **사이클(Cycle)이 없어야 함.** (예: A를 하려면 B를 해야 하고, B를 하려면 A를 해야 하면 영원히 불가능)

#### 2) 작동 원리 (진입 차수, In-degree)

1. **진입 차수(In-degree)가 0**인 정점을 찾는다. (즉, 선행 조건이 없는 과목).
2. 해당 정점을 출력하고, 그래프에서 **제거**한다.
3. 제거된 정점에서 출발하는 간선들도 모두 삭제한다. (이에 따라 연결된 후행 정점들의 진입 차수가 감소함).
4. 모든 정점이 제거될 때까지 반복한다.
    
    - 만약 모든 정점을 방문하기 전에 진입 차수가 0인 정점이 없다면? $\rightarrow$ **사이클이 존재한다**는 뜻.
        

#### 3) 예시 (선수 과목)

- **상황:** 자료구조(1) $\to$ 알고리즘(3), C언어(0) $\to$ 자료구조(1).
- **초기:** C언어(0)는 진입 차수 0. $\rightarrow$ 선택 및 삭제.
- **갱신:** 자료구조(1)의 진입 차수가 0이 됨. $\rightarrow$ 선택 및 삭제.
- **결과:** C언어 $\to$ 자료구조 $\to$ 알고리즘 순서 도출.

### 💡 Interview

> [!faq]Q 모든 정점 쌍 사이의 최단 경로를 구할 때, 다익스트라를 N번 돌리는 것과 플로이드-워셜을 쓰는 것 중 언제 무엇이 유리한가?
>
> 🗣️ 핵심 답변
>
> 간선이 적은 **희소 그래프(Sparse Graph)**라면 다익스트라($O(E \log V)$)를 $N$번 수행하는 것이 $O(V E \log V)$로 더 효율적일 수 있습니다.
> 하지만 간선이 많은 **밀집 그래프(Dense Graph)**이거나 구현의 편의성이 중요할 때, 혹은 정점 개수($V$)가 적다면 **플로이드-워셜($O(V^3)$)**이 유리합니다.

> [!faq]Q 플로이드-워셜 알고리즘 구현 시 3중 반복문의 순서가 중요한 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가장 바깥쪽 루프가 반드시 **경유지($k$)**가 되어야 하기 때문입니다. 플로이드 알고리즘은 '0번 정점까지 경유 가능할 때'의 결과를 바탕으로 '1번 정점 경유 추가'를 계산하는 동적 계획법(DP) 방식입니다. 경유지 루프가 안쪽으로 들어가면, 아직 갱신되지 않은 과거의 상태를 참조하게 되어 최단 거리를 올바르게 구할 수 없습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **i, j의 순서는?** 출발지(i)와 도착지(j)의 순서는 바뀌어도 상관없습니다. 핵심은 경유지(k)가 고정된 상태에서 모든 i, j 쌍을 검사하는 것입니다.
>     

> [!faq]Q 위상 정렬(Topological Sort)이 불가능한 경우는 언제이며, 이를 어떻게 탐지하나요?
>
> 🗣️ 핵심 답변
>
> 그래프 내에 **사이클(Cycle)**이 존재하면 위상 정렬이 불가능합니다. 알고리즘 수행 중 큐(Queue)가 비어있는데 아직 방문하지 않은 정점이 남아있다면(즉, 모든 정점의 진입 차수가 0이 되지 않는다면), 사이클이 존재한다고 판단할 수 있습니다.

### 1. 🏗️ 빌드업 (Why & Context)

> "하드웨어 성능이 비약적으로 발전했는데, 왜 여전히 복잡도를 계산해야 하는가?"

- **배경:** 과거(RAM 640KB, 1MB 시대)에는 메모리 절약(공간 복잡도)이 핵심이었으나, 현재는 하드웨어 성능(RAM 32GB 등)이 충분함.
- **문제 제기:** - 하드웨어가 좋아졌음에도 사용자는 **기다려주지 않음** (웹 로딩 지연 시 '새로고침' 연타 → 서버 부하 가중).
    - 대규모 데이터 처리 및 서버 비용 절감을 위해 **실행 시간(Time Complexity)** 최적화가 필수적임.
- **측정의 한계 (Absolute Time vs Operations):**
    - `clock()` 함수 등을 이용해 절대 시간(초 단위)을 측정하는 것은 하드웨어 환경에 따라 결과가 달라지므로 객관적 지표가 될 수 없음.
    - 따라서 **연산 횟수(Operation Count)** 를 함수형태($f(n)$)로 나타내어 분석함.
        

### Concept: 시간 복잡도와 연산 횟수 비교

- **핵심 아이디어:** 입력 크기 $N$이 무한대로 커질 때, 연산 횟수가 어떻게 증가하는가(추세)를 비교.
- **최고차항의 중요성:** $N^2 + N + 1$에서 $N$이 커지면 $N$과 $1$은 무시 가능하므로 $O(N^2)$으로 취급.
    

### Code 구현: $N$을 $N$번 더하는 문제 ($N \times N$)

> 동일한 결과(1억을 1억 번 더하기)를 내는 3가지 방식의 성능 차이 비교.
#### Case A: 곱셈 연산 활용 ($O(1)$)

```C
sum = n * n;
```

- **연산:** 대입 1회, 곱셈 1회 $\rightarrow$ 총 2회.
- **특징:** 입력 $N$이 1억이든 10억이든 연산 횟수는 **상수(Constant)**로 일정하다. 가장 효율적이다.
#### Case B: 단일 반복문 ($O(N)$)

```C
sum = 0;
for(i=0; i<n; i++) {
    sum += n;
}
```

- **연산:** $N$번 반복하며 덧셈 수행 $\rightarrow$ 약 $2N + \alpha$회.
- **특징:** 입력 $N$에 비례하여 시간이 선형적으로 증가한다.
    
#### Case C: 이중 반복문 ($O(N^2)$)

```C
sum = 0;
for(i=0; i<n; i++) {
    for(j=0; j<n; j++) {
        sum += 1;
    }
}
```

- **연산:** $N \times N$번 반복하며 1을 더함 $\rightarrow$ 약 $2N^2 + \alpha$회.
- **특징:** 입력 $N$이 커지면 실행 시간이 기하급수적으로 증가한다. (가장 비효율적)
### 분석 (Analysis)

1. **Case 1 ($O(1)$):** $N$이 1억이든 10억이든 연산 횟수는 2회로 고정. 압도적으로 빠름.
2. **Case 2 ($O(N)$):** $N$에 비례하여 시간 증가.
3. **Case 3 ($O(N^2)$):** $N$이 커지면 기하급수적으로 느려짐.
 
- **결론:** 알고리즘 설계 시 입력값 $N$이 커질 것을 대비해 **Case 1**과 같은 수학적/논리적 최적화를 지향해야 함.

## Topic 1. 시간 복잡도와 Big-O (Time Complexity)

### 1. 🏗️ 빌드업 (Why & Context)

> "좋은 컴퓨터(i9)를 쓰면 알고리즘이 나빠도 빠르지 않을까? 왜 굳이 연산 횟수를 셀까?"

- **하드웨어의 한계와 연산 속도:**
    - **클럭 스피드 (Clock Speed):** CPU가 초당 실행할 수 있는 사이클 수.
	    - 예: 5GHz CPU는 1초에 $5 \times 10^9$번의 클럭이 뜀. 덧셈 연산 하나에 3~5 클럭이 소모됨.
	- **연산 속도:** 하나의 명령(Instruction)을 처리하는 데 필요한 클럭 수(CPI)와 클럭 속도가 성능을 결정한다.
	- **알고리즘의 역할:** 하드웨어 성능이 좋아도, **불필요한 연산 횟수**를 줄이는 것이 근본적인 최적화다.

### Concept: Big-O 표기법 ($O$)

- **정의:** 함수의 **상한(Upper Bound)**. "아무리 느려져도 이 추세선 위로는 올라가지 않는다"는 최악의 경우를 보장.
- **정의:** 입력 크기 $N$이 증가할 때, 연산 횟수의 증가 추세(Trend)를 나타내는 상한선.
- **핵심 규칙 (점근적 표기):**
    
    1. **최고차항만 남김:** $N^2$이 $N$보다 압도적으로 영향력이 크므로, $N^2 + N \rightarrow O(N^2)$.
    2. **상수 무시:** $2N, 100N \rightarrow O(N)$. (하드웨어 성능 향상으로 커버 가능한 영역).
### 주요 복잡도 비교 (작은 순서대로)

$$O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N) < O(N!)$$

- **$O(1)$:** 해시 테이블 조회, 배열 인덱스 접근.
- **$O(N \log N)$:** 퀵 정렬, 병합 정렬.
- **$O(N!)$:** 외판원 순회 문제(TSP) 등 (입력 크기가 작아도 계산 불가능 수준).

### 1. 실전 계산 규칙

코드를 보고 직관적으로 복잡도를 계산하는 방법론.

| **구조**            | **복잡도**         | **설명**                                                        |
| ----------------- | --------------- | ------------------------------------------------------------- |
| **단일 반복문**        | $O(N)$          | loop가 $N$번 수행됨.                                               |
| **중첩 반복문**        | $O(N^2)$        | 바깥 $N$번 $\times$ 안쪽 $N$번. (이중 loop)                           |

## Topic 3. 순환(Recursion) vs 반복(Iteration)

### 1. 🏗️ 빌드업 (Why & Context)

> "같은 기능을 하는데 왜 어떤 건 재귀로 짜고, 어떤 건 for문으로 짤까?"

- **재귀의 정의:** 함수가 수행 도중 자기 자신을 다시 호출하는 것 (예: 팩토리얼, 피보나치, 하노이 탑).
- **딜레마:** 재귀는 코드가 직관적이고 수학적 정의와 유사하지만, **시스템 스택(System Stack)**을 사용하므로 메모리와 성능상 오버헤드가 발생함.
    

### Concept: 재귀의 메모리 구조와 오버헤드

- **작동 원리:** 함수를 호출할 때마다 `Return Address`(돌아갈 주소), `Local Variables`(매개변수 등)가 **Stack 메모리**에 쌓임 (Push).
- **오버헤드(Overhead):**
    - **Context Switch:** 함수 호출 및 복귀 시 레지스터 저장/복구 비용 발생.
    - **Memory:** 깊이(Depth)가 깊어질수록 스택 메모리를 과도하게 점유 → **Stack Overflow** 위험.
    - **복사 비용:** 값에 의한 전달(Call by value) 시 데이터를 계속 복사함.
- **반복문:** 데이터 영역(Data Segment)이나 힙(Heap)만 사용.
- **재귀 함수:** **시스템 스택(System Stack)** 영역을 사용.
    - 함수가 호출될 때마다 매개변수, 리턴 주소 등을 스택에 쌓아야 하므로, 깊이가 깊어지면 **스택 오버플로우(Stack Overflow)** 위험이 있다.

### Comparison: Case Study

강의에서 다룬 3가지 예제를 통해 재귀와 반복의 유불리를 비교.

#### 1) 팩토리얼 (Factorial)

- **재귀:** $N! = N \times (N-1)!$ 점화식을 그대로 구현. ($O(N)$)
- **반복:** 1부터 N까지 곱함. ($O(N)$)
- **결론:** 시간 복잡도는 같으나, 재귀는 스택 오버헤드가 발생하므로 **반복이 더 효율적**일 수 있다.
    

#### 2) 거듭제곱 ($x^n$) - **🚨 중요 (재귀가 유리한 경우)**

- **반복문 ($O(N)$):** $x$를 $N$번 곱함.
- **재귀 (분할 정복):****
    - $x^n = (x^2)^{n/2}$ 원리를 이용.
    - 짝수일 때: $x^n \rightarrow (x^2)^{n/2}$
    - 홀수일 때: $x^n \rightarrow x \times x^{n-1}$
    - **시간 복잡도:** 문제 크기가 절반씩 줄어들으므로 **$O(\log N)$**.
- **결론:** $N$이 클 때(예: 10억 승), 재귀가 압도적으로 빠름.

#### 3) 피보나치 (Fibonacci)

- **단순 재귀 ($O(2^n)$):**
- **반복문 ($O(N)$):** 올라감. 훨씬 효율적.
- **재귀 (Naive):** $F(n) = F(n-1) + F(n-2)$
    - 중복 호출 발생: $Fib(6)$을 구하기 위해 $Fib(3)$이 여러 번 계산되어 **$O(2^N)$**의 지수 시간이 걸림. (비효율의 극치)
- **반복:** 0, 1부터 시작하여 이전 값 2개를 기억하며 $N$까지 순차적으로 계산. **$O(N)$**.
- **결론:** 피보나치는 절대 단순 재귀로 짜면 안 되며, **반복문**이나 **메모이제이션(Memoization)**을 써야 한다.

### Code 구현: 거듭제곱 ($x^n$) 최적화 (Recursive)

```C
// 반복문 버전: O(N)
double slow_power(double x, int n) {
    double r = 1.0;
    for (int i = 0; i < n; i++) r = r * x;
    return r;
}

// 재귀 버전 (분할 정복): O(log N) -> 훨씬 빠름!
double fast_power(double x, int n) {
    if (n == 0) return 1;
    
    // 짝수일 경우: 절반으로 나눠서 재귀 호출 (문제를 반으로 줄임)
    if (n % 2 == 0) {
        return fast_power(x * x, n / 2);
    } 
    // 홀수일 경우
    else {
        return x * fast_power(x * x, (n - 1) / 2);
    }
}
```

- **개발자의 선택 (Trade-off):**
    - 재귀는 **"이해하기 쉽고 코드가 간결"**하다는 강력한 장점이 있음.
    - 하드웨어 성능이 충분하고 입력 크기($N$)가 스택 오버플로우를 유발하지 않을 수준이라면, **개발 생산성**을 위해 재귀를 선택하는 것이 합리적일 수 있음.
    - 반면, 성능이 절대적으로 중요하거나 $N$이 매우 크다면 복잡하더라도 반복문으로 변환해야 함.
        

### 💡 Interview

> [!faq]Q 재귀 함수(Recursion)를 사용할 때 발생할 수 있는 잠재적 위험과 해결 방안은?
>
> 🗣️ 핵심 답변
>

> 📚 해결 방안
>
> 이를 해결하기 위해 계산한 값을 배열에 저장해두고 재사용하는 **동적 계획법(Dynamic Programming, 메모이제이션)**을 사용하거나, 단순히 **반복문(Iteration)**으로 구현하여 $O(N)$으로 최적화해야 합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 재귀를 반복문보다 선호해야 하는 경우는 언제인가요?**

> 🗣️ 핵심 답변
>

>
> 📚 컴파일러 최적화
>
> 일반 재귀와 달리, 컴파일러가 꼬리 재귀를 **반복문(Loop)으로 최적화(Tail Call Optimization)**할 수 있어 스택 오버플로우 위험을 없애고 성능을 높일 수 있다는 장점이 있습니다.

## Topic 1. 하노이의 탑 (Towers of Hanoi)

### 1. 🏗️ 빌드업 (Why & Context)

> "반복문(For)으로 짤 수 있는가? 짤 수는 있지만, $N=5$만 되어도 코드가 지옥같이 복잡해진다."

- **문제 상황:** 막대 A, B, C가 있고 크기가 다른 $N$개의 원판이 있다.
- **제약 조건:**
    
    1. 한 번에 하나의 원판만 이동 가능.
    2. 맨 위의 원판만 이동 가능.
    3. 큰 원판이 작은 원판 위에 올라갈 수 없음.
        
- **핵심 아이디어 (재귀적 사고):**
  $N$개의 원판을 A에서 C로 옮기려면, 가장 큰 원판(맨 밑)을 C로 옮겨야 한다. 이를 위해 위의 $N-1$개를 먼저 비켜줘야 한다.

1. **Step 1:** 맨 밑의 원판을 제외한 **나머지 $N-1$개 원판**을 A에서 **B(임시)**로 옮긴다.
2. **Step 2:** **가장 큰 원판(1개)**을 A에서 **C(목적지)**로 옮긴다.
3. **Step 3:** B에 두었던 **$N-1$개 원판**을 다시 **C(목적지)**로 옮긴다.

### Concept: 재귀적 이동 매커니즘

- **알고리즘 순서 (A $\to$ C 로 이동 시, B를 임시 공간으로 사용):**
    
    1. **Step 1:** $N-1$개 원판을 `From`(A)에서 `Temp`(B)로 이동. (재귀 호출)
    2. **Step 2:** 가장 큰 원판(1개)을 `From`(A)에서 `To`(C)로 이동. (실제 이동)
    3. **Step 3:** $N-1$개 원판을 `Temp`(B)에서 `To`(C)로 이동. (재귀 호출)
        
- **복잡도:** 원판이 하나 늘어날 때마다 이동 횟수는 2배씩 증가하므로 $O(2^N)$의 지수 시간 복잡도를 가짐. (매우 가파르게 증가)
    

### Code 구현

```C
#include <stdio.h>

// n: 원판 개수, from: 시작점, temp: 임시공간, to: 도착점
void hanoi_tower(int n, char from, char temp, char to) {
    // Base Case: 원판이 1개면 바로 목적지로 이동
    if (n == 1) {
        printf("원판 1을 %c에서 %c로 이동\n", from, to);
    } 
    else {
        // 1. 맨 밑 원판을 제외한 n-1개를 '임시 공간(temp)'으로 이동
        // 이때 '도착점(to)'을 임시 버퍼로 사용
        hanoi_tower(n - 1, from, to, temp);
        
        // 2. 맨 밑의 가장 큰 원판을 '도착점(to)'으로 이동
        printf("원판 %d을(를) %c에서 %c로 이동\n", n, from, to);
        
        // 3. '임시 공간(temp)'에 있던 n-1개를 다시 '도착점(to)'으로 이동
        // 이때 '시작점(from)'을 임시 버퍼로 사용
        hanoi_tower(n - 1, temp, from, to);
    }
}

int main() {
    // 3개의 원판을 A -> C 로 이동 (B를 임시 공간 활용)
    hanoi_tower(3, 'A', 'B', 'C');
    return 0;
}
```

## Topic 2. 작업 스케줄링 (Machine Scheduling)

### 1. 🏗️ 빌드업 (Why & Context)

> "솜사탕 기계가 2대 있다. 피카츄(5분), 토끼(10분), 별(1분), 기본(30초) 솜사탕 주문이 한꺼번에 들어왔을 때, 어떻게 배분해야 가장 빨리 끝낼 수 있을까?"

- **문제 정의:** $M$개의 기계와 수행 시간이 다른 $N$개의 작업(Job)이 있을 때, 모든 작업이 끝나는 시간(Makespan)을 최소화하는 배치 방법 찾기.
- **접근법:** 모든 경우의 수를 따지기보다, **그리디(Greedy)** 방식을 사용하여 근사해(Approximation)를 구함.
### 그리디 알고리즘: LPT (Longest Processing Time first)

- **알고리즘 논리:**
    
	1. **정렬:** 작업 시간이 **가장 긴 순서대로(내림차순)** 작업을 정렬한다. (8, 7, 6, 5…)
	2. **배정:** 가장 먼저 끝나는(현재 부하가 가장 적은) 기계에 순서대로 작업을 배정한다.
	3. **반복:** 모든 작업이 배정될 때까지 반복한다.
	
- **왜 가장 긴 것부터 하는가?**
    - 짧은 작업을 먼저 배정하고 긴 작업을 나중에 배정하면, 마지막에 긴 작업 하나 때문에 전체 종료 시간이 크게 지연될 수 있음(Load Imbalance).
    - 큰 돌(긴 작업)을 먼저 채우고, 작은 돌(짧은 작업)로 틈새를 메우는 원리.
        
### 구현 전략 (Min Heap 활용)

- 기계들의 현재 종료 시간을 관리하기 위해 **최소 힙(Min Heap)**을 사용하면 효율적이다.
    - 항상 Root(가장 빨리 끝나는 기계)를 꺼내서 작업을 할당하고 다시 넣는다.
    
### Code 구현 (Logic Only)

```C
// 실제 구현 시에는 Min-Heap(최소 힙)을 사용하여 
// 가장 빨리 끝나는 기계를 O(log M)으로 찾아내는 것이 핵심.

void machine_scheduling(int jobs[], int n, int machines[], int m) {
    // 1. 작업 시간을 내림차순 정렬 (Greedy: LPT)
    sort(jobs, jobs + n, descending); 

    // 2. 초기 기계 가동 시간 0으로 초기화
    for(int i=0; i<m; i++) machines[i] = 0;

    // 3. 작업을 하나씩 꺼내서 가장 부하가 적은 기계에 할당
    for(int i=0; i<n; i++) {
        // 현재 가장 빨리 끝나는 기계(min_index) 찾기 (Min-Heap 사용 권장)
        int min_idx = find_min_machine_index(machines, m);
        
        // 해당 기계에 작업 할당
        machines[min_idx] += jobs[i];
        
        printf("Job %d (시간 %d) -> Machine %d 할당 (누적 %d)\n", 
               i, jobs[i], min_idx, machines[min_idx]);
    }
}
```

>[!faq]Q 머신 스케줄링 문제에서 LPT(Longest Processing Time first) 알고리즘이 항상 최적해를 보장하는가?

> 🗣️ 핵심 답변
>
> 아니요, LPT는 그리디(Greedy) 알고리즘이므로 항상 최적해(Optimal Solution)를 보장하지는 않습니다. 하지만 최적해에 매우 근접한 **근사해(Approximation)**를 보장하며($\frac{4}{3} - \frac{1}{3M}$ 배 이내), 구현이 간단하고 빠르기 때문에 실무에서 널리 사용됩니다. NP-Hard 문제인 스케줄링에서 효율적인 대안입니다.
