# 0. 수업 개요 - DB보안 1교시_2025.10.27

### 공지사항

- 기존 시험 범위(프로시저/함수)에 **"소스 코드 암호화(Wrapping)"** 내용이 추가됨.
- 새로운 교안 및 `userTBL` 테이블 생성 스크립트 배포됨.
    

### 오늘의 Workflow

- **Step 1)** 실습 환경 구축 (`userTBL` 생성 및 데이터 삽입)
- **Step 2)** 평문 프로시저 작성 (데이터 마스킹 로직 구현)
- **Step 3)** 보안 적용 (PL/SQL 문자열 조합 및 `DBMS_DDL`을 이용한 소스 암호화)
    

### 오늘의 실습 연결고리 (Flow Summary)

- 개인정보(이름)를 조회하는 프로시저 작성 (`SUBSTR` 마스킹)
- → 실행 시 기능은 정상이나 `USER_SOURCE` 뷰를 통해 소스 코드가 평문으로 노출됨 확인
- → **보안 취약점 인지**
- → `DBMS_DDL.CREATE_WRAPPED` 패키지를 사용하여 **소스 코드를 알아볼 수 없게 암호화(Wrapping)** 하여 재생성.

## Step 1. 실습 환경 구축 - DB보안 1교시_2025.10.27

### 1) Goal

- 프로시저 실습에 필요한 `userTBL` 테이블을 생성하고 데이터를 적재한다.
    

### 2) Preconditions

- Oracle SQL Developer 접속
- 기존에 동일한 이름의 테이블(`userTBL`)이 있다면 삭제(`DROP`) 후 진행
    

### 3) Build & Execute

#### Logic

- 제공된 스크립트를 그대로 실행하되, `COMMIT`을 반드시 수행하여 데이터를 확정해야 함.
    

#### Code



```SQL
-- 접속: APP_USER (또는 실습용 계정)

-- 1. 기존 테이블 정리 (필요 시)
DROP TABLE userTBL;

-- 2. 테이블 생성
CREATE TABLE userTBL (
    userID     CHAR(8)       NOT NULL PRIMARY KEY, -- 사용자 아이디(PK)
    userName   NVARCHAR2(10) NOT NULL,             -- 이름
    birthYear  NUMBER(4)     NOT NULL,             -- 출생년도
    addr       NCHAR(2)      NOT NULL,             -- 지역
    mobile1    CHAR(3),                            -- 국번
    mobile2    CHAR(8),                            -- 뒷번호
    height     NUMBER(3),                            -- 키
    mDate      DATE                                -- 가입일
);

-- 3. 데이터 삽입 (예시 데이터)
INSERT INTO userTBL VALUES ('LSG', '이승기', 1987, '서울', '011', '11111111', 182, TO_DATE('2008-08-08', 'YYYY-MM-DD'));
INSERT INTO userTBL VALUES ('KBS', '김범수', 1979, '경남', '011', '22222222', 173, TO_DATE('2012-04-04', 'YYYY-MM-DD'));
INSERT INTO userTBL VALUES ('JYP', '조용필', 1950, '경기', '011', '44444444', 166, TO_DATE('2009-04-04', 'YYYY-MM-DD'));
-- … (나머지 데이터 생략, 카톡 내용 참조) …
INSERT INTO userTBL VALUES ('BBK', '바비킴', 1973, '서울', '010', '00000000', 176, TO_DATE('2013-05-05', 'YYYY-MM-DD'));

COMMIT;
```

#### Verify

- 🔎 확인: 데이터가 10건 정상적으로 들어갔는지 확인.
    



```SQL
SELECT * FROM userTBL; 
-- 결과: 10 rows selected.
```

## Step 2. 평문 프로시저 작성 (데이터 마스킹) - DB보안 1교시_2025.10.27

### 1) Goal

- 사용자 ID를 입력받아 이름의 첫 글자만 남기고 나머지는 마스킹('OO') 처리하여 출력하는 프로시저를 작성한다.
    

### 2) Preconditions

- `SET SERVEROUTPUT ON` (출력 확인용)
    

### 3) Build & Execute

#### Logic

- **`%TYPE` 사용**: `v_userName userTBL.userName%TYPE;` 처럼 선언하여, 테이블 컬럼의 데이터 타입이 변경되더라도 프로시저 수정 없이 유연하게 대응함 (시험 출제 포인트).
- **`SUBSTR`**: 이름의 첫 글자(`1, 1`)만 자르고 뒤에 `'OO'` 문자열을 붙여 마스킹 처리.
- **`/` (Slash)**: 워크시트에서 PL/SQL 블록 종료 및 컴파일 실행 명령.
    

#### Code


```SQL
-- 접속: APP_USER
SET SERVEROUTPUT ON;

CREATE OR REPLACE PROCEDURE pro_print_user (
    p_id IN userTBL.userID%TYPE  -- 입력 파라미터 (%TYPE 사용 권장)
)
IS
    -- 변수 선언 (%TYPE 활용)
    v_userName  userTBL.userName%TYPE;
    v_birthYear userTBL.birthYear%TYPE;
BEGIN
    -- 데이터 조회 (ID로 이름, 생년 조회)
    SELECT userName, birthYear
    INTO v_userName, v_birthYear
    FROM userTBL
    WHERE userID = p_id;

    -- 결과 출력 (마스킹 처리: 첫글자 + 'OO')
    -- 예: '조용필' -> '조OO'
    DBMS_OUTPUT.PUT_LINE('이름: ' || SUBSTR(v_userName, 1, 1) || 'OO');
    DBMS_OUTPUT.PUT_LINE('생년: ' || v_birthYear);

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('해당 ID의 사용자가 없습니다.');
END;
/
```

#### Verify

- 🔎 확인: 프로시저가 정상적으로 컴파일되고 결과가 출력되는지 확인.
    



```SQL
EXEC pro_print_user('JYP');
-- 기대 출력:
-- 이름: 조OO
-- 생년: 1950
```

#### Pitfalls

- ⚠️ **타입 불일치**: 변수 선언 시 길이를 직접 지정(`VARCHAR2(10)`)하는 것보다 `%TYPE`을 쓰는 것이 안전함. (강의 강조 사항)
- ⚠️ **컴파일 오류**: `END;` 뒤에 `/`를 빠뜨리면 워크시트에서 실행이 안 될 수 있음.
    

### 4) 💡 Interview

> [!faq]- Q. PL/SQL 변수 선언 시 %TYPE을 사용하는 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 참조하는 테이블 컬럼의 데이터 타입이나 크기가 변경되더라도, 프로시저 코드를 수정할 필요 없이 데이터 무결성과 유지보수성을 확보할 수 있기 때문입니다.
>
> **📚 꼬리질문 대비**
>
> - **Diff**: `%ROWTYPE`은 컬럼 하나가 아니라 **행 전체(레코드)** 구조를 참조할 때 사용합니다.
>

## Step 3. 소스 코드 암호화 (Wrapping) - DB보안 1교시_2025.10.27

### 1) Goal

- 앞서 만든 프로시저의 소스 코드가 `USER_SOURCE`에서 평문으로 보이는 문제를 해결하기 위해, `DBMS_DDL` 패키지를 사용하여 코드를 암호화(Wrapping)한다.
    

### 2) Preconditions

- `DBMS_DDL` 실행 권한 (일반적으로 기본 제공됨).
- 문자열 연결 연산자(`||`)와 따옴표(`'`) 이스케이프 처리에 대한 이해 필요.
    

### 3) Build & Execute

#### Logic

- **왜 하는가?**: `SELECT text FROM USER_SOURCE` 조회 시 비즈니스 로직(마스킹 방식 등)이 노출되는 것을 막기 위함.
- **구현 방식**:
    
    1. `CREATE PROCEDURE …` 전체 구문을 **하나의 긴 문자열 변수**에 담는다. (이때 따옴표 지옥 주의)
    2. `SYS.DBMS_DDL.CREATE_WRAPPED(변수명)`을 호출하여, 암호화된 상태로 프로시저를 생성한다.
        

#### Code


```SQL
-- 접속: APP_USER

-- 1. 기존 평문 프로시저 삭제 (확실한 변경 확인을 위해)
DROP PROCEDURE pro_print_user;

-- 2. 암호화된 프로시저 생성 (PL/SQL 블록 사용)
DECLARE
    v_ddl VARCHAR2(3000); -- 소스 코드를 담을 변수
BEGIN
    -- 소스 코드를 문자열로 구성 (줄바꿈이나 공백은 문자열 내에 포함)
    -- 주의: 문자열 안의 따옴표(')는 두 번('') 써서 이스케이프 처리해야 함.
    v_ddl := 'CREATE OR REPLACE PROCEDURE pro_print_user ( ' ||
             '    p_id IN userTBL.userID%TYPE ) ' ||
             'IS ' ||
             '    v_userName  userTBL.userName%TYPE; ' ||
             '    v_birthYear userTBL.birthYear%TYPE; ' ||
             'BEGIN ' ||
             '    SELECT userName, birthYear INTO v_userName, v_birthYear ' ||
             '    FROM userTBL WHERE userID = p_id; ' ||
             '    DBMS_OUTPUT.PUT_LINE(''이름: '' || SUBSTR(v_userName, 1, 1) || ''OO''); ' || -- 따옴표 주의
             '    DBMS_OUTPUT.PUT_LINE(''생년: '' || v_birthYear); ' ||
             'END;';

    -- 암호화하여 생성 실행
    SYS.DBMS_DDL.CREATE_WRAPPED(v_ddl);
END;
/
```

#### Verify

- 🔎 **기능 확인**: 암호화되었어도 실행 결과는 동일해야 함.
    

SQL

```SQL
SET SERVEROUTPUT ON;
EXEC pro_print_user('JYP');
-- 결과: 이름: 조OO / 생년: 1950 (정상 동작)
```

- 🔎 **보안 확인**: 소스 코드가 암호화되었는지 확인.
    

SQL

```SQL
SELECT text 
FROM USER_SOURCE 
WHERE name = 'PRO_PRINT_USER'
ORDER BY line;
-- 기대 결과: "wrapped" 키워드와 함께 알 수 없는 문자열들이 출력되어야 함.
-- 예: create or replace procedure pro_print_user wrapped … abcd123…
```

#### Pitfalls

- ⚠️ **따옴표 지옥 (Quote Hell)**: 문자열 변수 안에 SQL을 넣을 때, SQL 내부의 `'`는 `''`로 써야 함. (예: `'OO'` → `''OO''`). 여기서 오류가 가장 많이 발생함.
- ⚠️ **`CREATE_WRAPPED` vs `WRAP`**:
    - `WRAP`: 암호화된 문자열을 **반환**만 함 (실행 X).
    - `CREATE_WRAPPED`: 암호화된 코드를 **즉시 컴파일 및 생성**함 (이번 실습에서 사용).
        

### 4) 💡 Interview

> [!faq]- Q. DB 내 프로시저 소스 코드를 보호하기 위한 방법은?
>
> 🗣️ 핵심 답변
>
> Oracle의 DBMS_DDL.CREATE_WRAPPED 패키지나 wrap 유틸리티를 사용하여 소스 코드를 암호화(Wrapping)함으로써, USER_SOURCE 조회 시 로직이 노출되지 않도록 보호할 수 있습니다.
