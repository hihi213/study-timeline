## Core Principles (Non-negotiable)

### 1. Data Modeling
- ✅ MUST use Pydantic models for all data structures
- ❌ NEVER use plain dict for business data
- ✅ Data normalization in model validators (e.g., "1,000,000원" → int)
- ✅ Type hints on ALL functions

**Why**: Data integrity at model level prevents bugs downstream

### 2. Architecture
**Strict layering**:
```Plaintext
CLI → Service → Repository → Scraper → Domain
```

**Why**: Single responsibility → easier to test, replace, understand

### 3. Logging & Error Handling
- ❌ NEVER use `print()` (use structlog only)
- ✅ Custom exceptions with retry (tenacity)
- ✅ Graceful degradation: Skip failed items

**Why**: Production needs structured logs, retries reduce manual intervention

### 4. Configuration
- ❌ NEVER hardcode URLs, timeouts, paths
- ✅ ALL settings in `config.yaml`

**Why**: Environment changes shouldn't require code changes

### 5. Resumability (Top Priority)
- ✅ Save checkpoint after every page
- ✅ Atomic checkpoint writes (temp → rename)

**Why**: Real-world scrapers crash. Resume saves hours

### 6. Duplication Prevention
- ✅ In-memory set for O(1) existence check

**Why**: Network I/O expensive. O(1) check saves 2-3s per duplicate

### 7. "제품 수준" 구현 (우대 항목)
- ✅ 오류 중단 후 재실행 (checkpoint + resume)
- ✅ interval/cron 실행 모드 (Click CLI)
- ✅ 유지보수 관점 리팩토링
- ✅ 테스트 코드 필수 (pytest)

**Why**: 리코 CTO가 요구하는 "제품 수준" 기준

```Plaintext
src/
├── domain/          # Pydantic models ONLY
├── repository/      # ABC interface + CSV
├── scraper/         # Playwright + selectolax
├── service/         # Business logic

└── constants.py

cli.py               # Click CLI
config.yaml          # All settings
tests/               # Mirror src/
```

**Naming**: PascalCase classes, snake_case functions, UPPER_SNAKE_CASE constants

2. ❌ Plain `dict` → use Pydantic
3. ❌ Hardcoded values → use config.yaml
4. ❌ Cross-layer imports
5. ❌ Missing type hints
6. ❌ Missing checkpoint
