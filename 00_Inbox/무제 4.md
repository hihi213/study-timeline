## Topic 1. PL/SQL 데이터 마스킹 (Data Masking) - DB보안 1교시_2025.10.27

### 1) 📌 One-Liner (면접 즉답)

- 민감한 데이터(이름, 주민번호)를 조회할 때, 애플리케이션 레벨이 아닌 DB 프로시저 내부에서 `SUBSTR` 등의 함수로 변환하여 원본 노출을 원천 차단하는 기법입니다. `(Data Privacy)`
    

### 2) 📘 Theory & Policy (개념 & 정책)

- **정의**: 데이터베이스 내부 로직(Procedure)에서 데이터를 조회할 때, 일부 문자를 특수문자(`*`, `0` 등)로 치환하여 출력하는 기법.
- **Security Boundary**: **Presentation Layer**. 데이터 자체가 암호화되어 저장되는 것은 아니지만, 사용자에게 전달되는 최종 결과값(View)을 통제합니다.
- **Architecture**:
    - `%TYPE`: 테이블 컬럼의 데이터 타입을 동적으로 참조하여, 스키마 변경 시 프로시저의 안정성을 보장합니다.
        

### 3) 🛡️ Security Audit (취약점 및 권장사항)

- **Attack Surface**: 프로시저 권한이 없는 사용자가 `SELECT` 권한만으로 테이블을 직접 조회할 경우, 마스킹되지 않은 원본 데이터가 노출될 위험이 있습니다.
- **Best Practice**:
    - 테이블에 대한 직접 `SELECT` 권한은 회수(REVOKE)하고, 마스킹 로직이 포함된 **프로시저나 뷰(View)에 대한 실행 권한(EXECUTE)**만 부여해야 합니다.
        

### 4) 💻 SQL Workflow (실습 로그)

(Scenario: `userTBL`의 이름 정보를 '조OO' 형태로 마스킹하여 출력하는 프로시저 작성)



```SQL
-- 1. [환경 구성] 실습용 테이블 생성 및 데이터 삽입
-- 접속: HR 또는 TEST 계정
CREATE TABLE userTBL (
    userID     CHAR(8)      NOT NULL PRIMARY KEY,
    userName   NVARCHAR2(10) NOT NULL,
    birthYear  NUMBER(4)    NOT NULL,
    addr       NCHAR(2)     NOT NULL,
    mobile1    CHAR(3),
    mobile2    CHAR(8),
    height     NUMBER(3),
    mDate      DATE
);

-- 데이터 삽입 (생략된 데이터 포함 10건 Commit)
INSERT INTO userTBL VALUES ('JYP', '조용필', 1950, '경기', '011', '44444444', 166, TO_DATE('2009-04-04', 'YYYY-MM-DD'));
COMMIT;

-- 2. [Implementation] 데이터 마스킹 프로시저 생성
CREATE OR REPLACE PROCEDURE proc_masking_user (
    p_id IN userTBL.userID%TYPE  -- 입력: 사용자 ID
)
IS
    v_name userTBL.userName%TYPE; -- 변수: 이름 저장
    v_year userTBL.birthYear%TYPE; -- 변수: 생년 저장
BEGIN
    -- ID로 조회하여 변수에 할당
    SELECT userName, birthYear
      INTO v_name, v_year
      FROM userTBL
     WHERE userID = p_id;

    -- [Security Logic] 첫 글자만 출력하고 나머지는 '00'으로 마스킹
    DBMS_OUTPUT.PUT_LINE('이름: ' || SUBSTR(v_name, 1, 1) || '00');
    DBMS_OUTPUT.PUT_LINE('출생년도: ' || v_year);
END;
/

-- 3. [Verification] 실행 결과 확인
SET SERVEROUTPUT ON;
EXEC proc_masking_user('JYP');
```

- 🚨 Error Case / Result:
    - **정상 결과**: `이름: 조00`, `출생년도: 1950` 출력.
    - **Verification**: `SELECT * FROM userTBL` 결과와 비교하여, 프로시저를 통해서만 마스킹된 데이터가 나오는지 확인.
        

### 5) 💡 Interview Shot (신입 면접 대비)

> [!faq]- Q. DB에서 데이터를 조회할 때 개인정보를 보호하는 방법은 무엇이 있습니까?
>
> 🗣️ 핵심 답변
>
> 애플리케이션 단에서 가리는 방법도 있지만, 보안상 DB 내부의 View나 Procedure를 통해 마스킹(Masking) 처리된 결과만 반환하도록 강제하는 것이 더 안전합니다.
>
> **📚 상세 부연 (꼬리질문 대비)**
>
> - **Why**: 개발자가 실수로 마스킹 코드를 누락하더라도, DB 레벨에서 원본 접근을 차단하면 사고를 방지할 수 있습니다.
>     
> - **Example**: Oracle의 `Data Redaction` 기능을 사용하거나, `SUBSTR` 함수를 활용한 뷰를 제공합니다.
>

## Topic 2. PL/SQL 소스 코드 암호화 (Wrap) - DB보안 1교시_2025.10.27

### 1) 📌 One-Liner (면접 즉답)

- 지식재산권 보호 및 보안 로직 은닉을 위해 `DBMS_DDL` 패키지를 사용하여 프로시저의 소스 코드를 읽을 수 없는 난수 형태(Wrapped)로 변환 저장하는 기법입니다. `(Obfuscation)`
    

### 2) 📘 Theory & Policy (개념 & 정책)

- **정의**: PL/SQL 소스 코드를 평문(Plain Text)이 아닌, 컴파일된 바이너리 혹은 난독화된 16진수 코드로 변환하여 딕셔너리에 저장하는 기술.
- **Security Boundary**: **Object Security**. 관리자(DBA)나 다른 개발자가 비즈니스 로직, 암호화 키 생성 방식 등을 열람하지 못하도록 보호합니다.
- **Architecture**:
    - `DBMS_DDL`: Oracle이 제공하는 DDL 관련 유틸리티 패키지.
    - `USER_SOURCE`: 사용자가 생성한 PL/SQL 소스 코드가 저장되는 데이터 딕셔너리.
        

### 3) 🛡️ Security Audit (취약점 및 권장사항)

- **Attack Surface**: 암호화되지 않은 프로시저는 `USER_SOURCE` 뷰를 조회하는 것만으로 보안 로직(예: 패스워드 검증 방식)이 노출될 수 있습니다.
- **Best Practice**:
    - 중요한 보안 로직이나 핵심 비즈니스 로직이 포함된 패키지/프로시저는 배포 전 반드시 **Wrapping(암호화)** 처리해야 합니다.
        

### 4) 💻 SQL Workflow (실습 로그)

(Scenario: 앞서 만든 프로시저의 소스 코드를 `USER_SOURCE`에서 볼 수 없도록 암호화하여 재생성)


```SQL
-- 1. 기존 프로시저 삭제 (테스트를 위해)
DROP PROCEDURE proc_masking_user;

-- 2. [Implementation] 동적 SQL과 DBMS_DDL을 활용한 암호화 생성
DECLARE
    v_source VARCHAR2(4000); -- 소스 코드를 담을 변수
BEGIN
    -- 소스 코드를 문자열로 조합 (작은따옴표 처리 주의)
    v_source := 'CREATE OR REPLACE PROCEDURE proc_masking_user ( ' ||
                '   p_id IN userTBL.userID%TYPE ) IS ' ||
                '   v_name userTBL.userName%TYPE; ' ||
                '   v_year userTBL.birthYear%TYPE; ' ||
                'BEGIN ' ||
                '   SELECT userName, birthYear INTO v_name, v_year ' ||
                '     FROM userTBL WHERE userID = p_id; ' ||
                '   DBMS_OUTPUT.PUT_LINE(''이름: '' || SUBSTR(v_name, 1, 1) || ''00''); ' ||
                '   DBMS_OUTPUT.PUT_LINE(''출생년도: '' || v_year); ' ||
                'END;';

    -- DBMS_DDL 패키지를 사용하여 암호화(Wrap) 후 실행
    -- (강의에서는 이 과정을 'DDL 랩'이라고 표현함)
    SYS.DBMS_DDL.CREATE_WRAPPED(v_source);
END;
/

-- 3. [Verification] 딕셔너리 조회를 통한 검증
-- 결과가 평문이 아닌 난독화된 코드로 보여야 함
SELECT name, text 
  FROM user_source 
 WHERE name = 'PROC_MASKING_USER';
```

- 🚨 Error Case / Result:
    - **Before**: `SELECT text …` 조회 시 `CREATE PROCEDURE …` 등 소스 전체가 보임.
    - **After**: `SELECT text …` 조회 시 `wrapped` 키워드와 함께 읽을 수 없는 문자열(Hex/Base64 형태)이 출력됨.
    - **기능 검증**: 암호화되었더라도 `EXEC proc_masking_user('JYP');` 실행 시 결과는 정상 출력되어야 함.
        

### 5) 💡 Interview Shot (신입 면접 대비)

> [!faq]- Q. PL/SQL로 개발된 비즈니스 로직을 다른 개발자가 볼 수 없게 하려면 어떻게 해야 합니까?
>
> 🗣️ 핵심 답변
>
> Oracle의 Wrap 유틸리티나 DBMS_DDL.CREATE_WRAPPED 프로시저를 사용하여 소스 코드를 암호화(난독화)하여 저장합니다.
>
> **📚 상세 부연 (꼬리질문 대비)**
>
> - **How**: 커맨드 라인에서 `wrap` 명령어를 쓰거나, PL/SQL 내부에서 `DBMS_DDL` 패키지를 호출합니다.
>     
> - **Caution**: 암호화된 소스는 복호화하여 원본을 볼 수 없으므로(One-way), **원본 소스 파일(.sql)**은 별도로 안전하게 백업해두어야 유지보수가 가능합니다.
