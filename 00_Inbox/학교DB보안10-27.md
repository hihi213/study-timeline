## 녹취 정제 - DB보안 1교시_2025.10.27

### 1. 실습 환경 구축 및 개요
금일 수업은 지난 시험 범위였던 프로시저(PROCEDURE)와 함수(FUNCTION)의 연장선으로, 데이터베이스 보안 관점에서의 암호화 및 데이터 은닉 기술을 실습함. 이를 위해 카카오톡으로 공유된 userTBL(회원 테이블) 생성 스크립트를 실행하여 10건의 샘플 데이터(유명인 정보)를 삽입하고 실습 환경을 구축함.

### 2. 프로시저를 활용한 데이터 마스킹(Data Masking)

민감한 정보를 보호하기 위해 데이터를 조회할 때 일부를 가리는 마스킹 기법을 프로시저로 구현함.

- **로직:** 특정 사용자 ID를 입력받아 해당 사용자의 이름을 조회하되, 첫 글자만 남기고 나머지는 특수문자(예: '00' 또는 '땡땡')로 치환하여 출력함.
- **문법적 특징:** 변수 선언 시 `table_name.column_name%TYPE` 문법을 사용하여, 테이블의 스키마가 변경되더라도 프로시저의 변수 타입이 자동으로 동기화되도록 처리함. 이는 유지보수성을 높이는 중요한 코딩 관습임.
- **실행 환경:** SQL Developer 워크시트에서 프로시저 코드 끝에 슬래시(`/`)를 입력하여 즉시 컴파일되도록 처리하며, `SET SERVEROUTPUT ON` 설정을 통해 `DBMS_OUTPUT.PUT_LINE` 결과를 확인함.
### 3. PL/SQL 소스 코드 암호화 (Wrapping)

작성된 프로시저의 로직(Source Code) 자체가 노출되는 것을 방지하기 위해 코드를 암호화(Wrapping)하는 기법을 학습함.

- **구현 방식:** 기존 프로시저를 `DROP`한 후, 프로시저 생성 DDL 구문 전체를 문자열 변수에 저장함. 이때 연결 연산자(`||`)를 사용하여 긴 쿼리를 하나의 문자열로 결합함.
- **암호화 처리:** `DBMS_DDL` 패키지(강의 중 'DBMSL 랩'으로 언급된 부분)를 활용하여 평문 DDL을 암호화된 형태로 변환 및 실행함.
- **보안 효과:** 이 과정을 거치면 `USER_SOURCE`와 같은 시스템 카탈로그(데이터 사전)를 조회해도 소스 코드가 난독화된 문자열로 표시됨. 따라서 관리자 권한이 있더라도 원본 로직을 쉽게 파악할 수 없어 지적 재산권 보호 및 보안성을 강화할 수 있음.
    
## 개념 - DB보안 1교시_2025.10.27

### 1. 프로시저를 활용한 데이터 마스킹 (Data Masking)

- **한 줄 요약:** 데이터베이스 내부(Server-side)에서 로직을 통해 민감 정보(이름, 전화번호 등)의 일부를 특수문자로 치환하여 출력하는 기법입니다.
- **정확한 SQL 패턴:**
	```SQL
	-- 예: 이름의 첫 글자만 남기고 나머지 '00' 처리
	v_maskedName := SUBSTR(v_name, 1, 1) || '00';
	```
    
- **보안 원칙:** **프라이버시 보호 (Privacy Preservation)**. 사용자가 불필요한 전체 데이터를 열람하는 것을 방지하여 데이터 유출 위험을 최소화합니다.
    

---

### 2. 참조형 변수 선언 (%TYPE)

- **한 줄 요약:** 변수 선언 시 데이터 타입을 직접 지정(Hard Coding)하지 않고, 특정 테이블 컬럼의 타입을 동적으로 참조하는 방식입니다.
- **정확한 SQL 패턴:**
    ```SQL
    -- userTBL 테이블의 userName 컬럼 타입과 동일하게 선언
    v_userName userTBL.userName%TYPE;
    ```
    
- **보안 원칙:** **가용성 및 무결성 (Availability & Integrity)**. 테이블 스키마(컬럼 크기 등)가 변경되어도 프로시저 코드를 수정할 필요가 없어, 타입 불일치로 인한 런타임 에러를 예방합니다.
    

---

### 3. PL/SQL 래핑 (Wrapping / Encryption)

- **한 줄 요약:** 프로시저나 함수의 소스 코드를 알아볼 수 없는 난독화된 문자열로 변환하여 저장하는 기술입니다.
- **정확한 SQL 패턴:**
    ```SQL
    -- DBMS_DDL 패키지를 활용한 동적 암호화 생성
    EXEC DBMS_DDL.CREATE_WRAPPED('CREATE OR REPLACE PROCEDURE …');
    ```
    
- **보안 원칙:** **지적 재산권 보호 및 기밀성 (Confidentiality)**. `USER_SOURCE`와 같은 데이터 사전(Data Dictionary) 조회 시 원본 로직이 노출되지 않으므로, 악의적인 코드 분석이나 비즈니스 로직 유출을 방지합니다.

## 실습 - DB보안 1교시_2025.10.27

### S1. 실습 환경 구축 (테이블 생성 및 데이터 삽입)

가장 먼저 카카오톡으로 공유된 회원 테이블(`userTBL`)을 생성하고 데이터를 입력합니다.

```SQL
-- (AI 주석: 기존 테이블이 있다면 삭제 후 재생성)
DROP TABLE userTBL CASCADE CONSTRAINTS;

-- 1. 테이블 생성
CREATE TABLE userTBL (
    userID    CHAR(8)       NOT NULL PRIMARY KEY, -- 사용자 아이디
    userName  NVARCHAR2(10) NOT NULL,             -- 이름
    birthYear NUMBER(4)     NOT NULL,             -- 출생년도
    addr      NCHAR(2)      NOT NULL,             -- 지역
    mobile1   CHAR(3),                            -- 휴대폰 국번
    mobile2   CHAR(8),                            -- 휴대폰 번호
    height    NUMBER(3),                          -- 키
    mDate     DATE                                -- 가입일
);

-- 2. 데이터 삽입 (샘플 10건)
INSERT INTO userTBL VALUES ('LSG', '이승기', 1987, '서울', '011', '11111111', 182, TO_DATE('2008-08-08', 'YYYY-MM-DD'));
INSERT INTO userTBL VALUES ('JYP', '조용필', 1950, '경기', '011', '44444444', 166, TO_DATE('2009-04-04', 'YYYY-MM-DD'));
-- (…생략: 나머지 데이터도 동일하게 삽입…)
COMMIT;
```

---

### S2. 데이터 마스킹 프로시저 생성 (평문)

입력받은 ID에 해당하는 사용자의 이름 첫 글자만 남기고 나머지를 가리는(Masking) 프로시저를 작성합니다.


```SQL
-- (AI 주석: DBMS_OUTPUT 출력을 위해 설정 필요)
SET SERVEROUTPUT ON;

CREATE OR REPLACE PROCEDURE proc_mask_name (
    p_id IN userTBL.userID%TYPE  -- (AI 주석: 테이블 컬럼 타입 참조)
) 
IS
    -- 변수 선언: 테이블의 컬럼 타입과 동기화
    v_name userTBL.userName%TYPE;
    v_year userTBL.birthYear%TYPE;
BEGIN
    -- 1. 데이터 조회
    SELECT userName, birthYear
    INTO v_name, v_year
    FROM userTBL
    WHERE userID = p_id;

    -- 2. 마스킹 처리 및 출력 (예: 조용필 -> 조00)
    -- SUBSTR(문자열, 1, 1): 첫 글자만 추출
    DBMS_OUTPUT.PUT_LINE('-----------------------------');
    DBMS_OUTPUT.PUT_LINE('ID : ' || p_id);
    DBMS_OUTPUT.PUT_LINE('Name (Masked): ' || SUBSTR(v_name, 1, 1) || '00');
    DBMS_OUTPUT.PUT_LINE('Birth Year   : ' || v_year);
    DBMS_OUTPUT.PUT_LINE('-----------------------------');
    
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('존재하지 않는 ID입니다.');
END;
/
-- (AI 주석: 슬래시(/)는 즉시 컴파일 명령)

-- 실행 테스트
EXEC proc_mask_name('JYP');
```

---

### S3. 소스 코드 암호화 (Wrapping)

위에서 작성한 프로시저 소스 코드가 관리자나 해커에게 노출되지 않도록 `DBMS_DDL`을 사용하여 암호화(Wrapping)하여 재생성합니다.

```SQL
DECLARE
    v_source VARCHAR2(3000); -- DDL 문장을 담을 변수
BEGIN
    -- (AI 주석: 전체 쿼리를 문자열로 생성. 작은따옴표(') 처리에 주의)
    v_source := 'CREATE OR REPLACE PROCEDURE proc_mask_name ( ' ||
                '   p_id IN userTBL.userID%TYPE ) IS ' ||
                '   v_name userTBL.userName%TYPE; ' ||
                '   v_year userTBL.birthYear%TYPE; ' ||
                'BEGIN ' ||
                '   SELECT userName, birthYear INTO v_name, v_year ' ||
                '   FROM userTBL WHERE userID = p_id; ' ||
                '   DBMS_OUTPUT.PUT_LINE(''Name: '' || SUBSTR(v_name, 1, 1) || ''00''); ' ||
                'END;';

    -- (AI 주석: 평문 DDL을 암호화하여 컴파일 실행)
    DBMS_DDL.CREATE_WRAPPED(v_source);
END;
/
```

### S4. 결과 분석 및 검증

실제로 소스 코드가 암호화되었는지 시스템 뷰(`USER_SOURCE`)를 통해 확인합니다.

```SQL
-- 소스 코드 확인 쿼리
SELECT name, text 
FROM USER_SOURCE 
WHERE name = 'PROC_MASK_NAME'
ORDER BY line;
```

- **분석:** * **실행 전:** `TEXT` 컬럼에 `CREATE PROCEDURE…` 등의 소스 코드가 그대로 보입니다.
    - **실행 후:** `TEXT` 컬럼 내용이 `wrapped` 키워드와 함께 알 수 없는 난수 문자열로 변경되어 있습니다.
- **주의/에러:** * `PLS-00103`: 문자열 연결 시 작은따옴표 개수(`''`)나 연결 연산자(`||`) 누락을 확인하세요.
    - 암호화된 프로시저는 **복호화가 불가능**하므로, 원본 소스 코드는 별도 파일로 백업해두어야 합니다.
        
## 녹취 - DB보안 2교시_2025.10.27

### 1. 커서(CURSOR) 개요

커서는 SELECT 문으로 반환된 여러 행(Record)의 결과 집합을 한 줄씩 처리하기 위한 포인터 메커니즘임. 파일 입출력 시스템에서의 파일 포인터와 유사하게 OPEN, FETCH, CLOSE 단계를 거쳐 동작함. 실무에서는 응용 프로그램 개발 시 빈번하게 사용되나, 금일 수업에서는 데이터베이스 보안 수업의 특성상 개념만 짚고 실습은 생략함.

### 2. 트리거(TRIGGER)의 개념 및 보안적 활용

트리거는 테이블이나 뷰에 INSERT, UPDATE, DELETE 이벤트가 발생할 때 DBMS에 의해 자동으로 실행되는 저장 프로그램임.

- **활용 목적:** 데이터 무결성 유지, 업무 규칙 자동 적용, 그리고 가장 중요한 **보안 감사(Auditing)** 및 로그 기록에 활용됨.
- **동작 시점:** 이벤트 실행 전(`BEFORE`), 실행 후(`AFTER`)로 나뉘며, 뷰의 경우 `INSTEAD OF`를 사용함. 보안 로직은 주로 `AFTER`를 사용하여 변경 완료 후 로그를 남기는 방식을 택함.
    

### 3. 감사(Audit) 로그 시스템 구축 실습

사용자 정보가 변경될 때 변경 이력을 남기는 보안 시스템을 구축함.

- **백업 테이블 구성:** `backup_userTBL`을 생성하여 기존 회원 정보 외에 `modType`(수정/삭제), `modDate`(변경일시), `modUser`(변경 수행자) 컬럼을 추가함.
- **가상 레코드 참조:** 트리거 내부에서 `:OLD` 키워드를 사용하여 변경 전 데이터를, `:NEW` 키워드를 사용하여 변경 후 데이터를 참조함. 이를 통해 누가 언제 데이터를 수정하거나 삭제했는지 추적 가능함.
    


### 4. 강제 예외 처리를 통한 방어 기법

특정 테이블에 데이터 삽입(INSERT)을 원천적으로 차단하는 보안 트리거를 실습함.

- **구현:** `RAISE_APPLICATION_ERROR` 프로시저를 사용하여 데이터 삽입 시도 시 사용자 정의 에러 메시지를 출력하고 트랜잭션을 강제 롤백(Rollback)시킴.
- **성능 고려:** 트리거는 이벤트마다 매번 호출되므로 과도한 사용은 시스템 오버헤드를 유발할 수 있음. 따라서 테스트 후 불필요한 트리거는 삭제(`DROP TRIGGER`)하는 것이 원칙임.
