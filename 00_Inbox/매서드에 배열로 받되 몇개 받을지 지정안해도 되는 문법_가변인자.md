## 정리

네, `...` 문법은 **가변인자(Varargs)**라고 부르며, 말씀하신 것처럼 **메서드를 호출할 때 넘겨주는 요소의 개수를 고정하고 싶지 않을 때** 사용하는 것이 맞습니다.

`List`를 사용하지 않은 이유는, 이 메서드를 **더 편리하게 호출**할 수 있도록 만들기 위해서입니다.

---

### 1) 부족 포인트 스캔 (놓쳤을 수 있는 관점)

- **메서드 호출의 편의성:** `...` (가변인자)가 개발자가 메서드를 호출하는 입장에서 얼마나 편리한 문법인지 체감하지 못하고 있습니다. `List`를 사용하려면 호출 전에 `List` 객체를 만들고 `add`하는 과정이 추가로 필요합니다.
- **컴파일러의 역할:** 개발자가 `...`를 사용해서 코드를 짜면, 컴파일러가 알아서 그 부분을 **배열(`[]`)로 변환**해준다는 내부 동작 원리를 모르고 있습니다. 개발자는 배열의 불편함을 피하고, 컴파일러가 대신 처리해주는 것입니다.
- **문법과 자료구조의 혼동:** `...`는 메서드에 파라미터를 넘기는 **문법(Syntax)**의 한 종류이고, `List`는 데이터를 담는 **자료구조(Data Structure)**입니다. 둘의 역할과 사용되는 계층이 다릅니다.

### 2) 핵심 개념 요약

- **가변인자 (Varargs - Variable Arguments) `...`**:
    - **정의:** 메서드에 넘겨주는 인자의 개수를 **0개 이상** 자유롭게 지정할 수 있도록 하는 자바 문법입니다.
    - **동작:** 메서드 내부에서는 이 파라미터가 **배열(`[]`)**로 처리됩니다. 즉, 개발자의 편의를 위해 컴파일러가 배열 문법을 감춰준 것입니다.
    - **규칙:** 가변인자는 반드시 메서드의 **마지막 파라미터**에만 위치할 수 있습니다.
- **배열 (Array) `[]`**:
    - **특징:** 길이가 고정된 동일한 타입의 요소들을 저장하는 자료구조입니다.
    - **메서드 호출 시:** `new OrderItem[]{item1, item2}` 와 같이 항상 배열 객체를 생성해서 넘겨줘야 합니다.
- **리스트 (List)**:
    - **특징:** 크기가 동적으로 변할 수 있는 객체들의 컬렉션입니다.
    - **메서드 호출 시:** `List<OrderItem> items = new ArrayList<>(); items.add(item1);` 와 같이 리스트 객체를 만들고 요소를 추가한 뒤, 그 리스트를 넘겨줘야 합니다.

### 3) 용어 매핑

- **`...`**: **가변인자(Varargs)**. 메서드 호출 시 인자의 개수를 유연하게 만들어주는 **문법적 설탕(Syntactic Sugar)**
- **`[]`**: **배열(Array)**. 길이가 고정된 자료구조.
- **"요소 개수를 어떻게 설정하는거야?"**:
    - **`...` (가변인자):** 메서드를 **호출하는 쪽에서** 원하는 만큼 콤마(`,`)로 구분하여 인자를 나열하면, 그 개수가 자동으로 설정됩니다. 개발자가 직접 개수를 설정할 필요가 없습니다.

### 4) 사고 틀 & 판단 기준

`createOrder` 메서드를 호출하는 개발자의 입장에서 세 가지 방식을 비교해 보세요.

**목표:** `orderItem1`, `orderItem2` 두 개를 넘겨서 주문 생성하기

- **1. 가변인자 (`...`) 사용 시 (현재 코드)**
    - **장점: 가장 편리하고 직관적입니다.**

        ``` Java
        createOrder(member, delivery, orderItem1, orderItem2);
        ```
        
- **2. 배열 (`[]`) 사용 시**
    - **단점: 항상 배열을 새로 생성(`new`)해야 해서 번거롭습니다.**

        ``` Java
        createOrder(member, delivery, new OrderItem[]{orderItem1, orderItem2});
        ```
        
- **3. 리스트 (`List`) 사용 시**
    - **단점: 호출 전에 List 객체를 만들고 `add`하는 과정이 필요해 코드가 길어집니다.**

        ``` Java
        List<OrderItem> items = new ArrayList<>();
        items.add(orderItem1);
        items.add(orderItem2);
        createOrder(member, delivery, items);
        ```

> 판단 기준:
>
> 메서드를 설계할 때, "이 메서드를 사용하는 다른 개발자가 얼마나 편하게 호출할 수 있을까?"를 기준으로 생각하면 됩니다. 여러 개의 однотипных 인자를 받아야 하고 그 개수가 유동적이라면, 가변인자(...)가 가장 편리한 선택지입니다.
