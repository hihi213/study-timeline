### 1. JDBC 연동 보안 및 리소스 관리 (Resource Management)

데이터베이스 연동은 **연결(Open) → 사용(Work) → 해제(Close)**의 라이프사이클을 가집니다. 특히 다수의 사용자가 DB를 공유하는 환경에서는 리소스 관리가 가용성(Availability) 보안 측면에서 매우 중요합니다.

- **연결 설정 (`Connection`):** `OracleDataSource` 객체를 통해 URL, User, Password를 설정합니다. 강의 예제에서는 편의상 소스 코드에 계정 정보를 하드코딩했으나, 실무에서는 보안상 별도의 설정 파일이나 암호화된 방식으로 관리해야 합니다.
- **예외 처리 (`try-catch-finally`):** DB 연결은 네트워크나 서버 상태에 따라 실패할 수 있으므로 반드시 예외 처리가 필요합니다.
- **자원 해제 (`close`):** 사용이 끝난 `Connection`, `Statement`, `ResultSet` 객체는 `finally` 블록에서 반드시 `close()` 해야 합니다. 이를 누락할 경우 세션 누수로 인해 DB 성능 저하 또는 서비스 거부(DoS) 상태가 발생할 수 있습니다.
    

### 2. SQL 실행 인터페이스와 보안성 (`Statement` vs `PreparedStatement`)

SQL 문을 실행하는 방식에는 두 가지가 있으며, 보안 및 유지보수 측면에서 명확한 차이가 존재합니다.

- **`Statement`:**
    - 쿼리문에 변수를 넣을 때 문자열 결합 연산자(`+`)를 사용합니다.
    - **문제점:** 코드가 복잡해지고(가독성 저하), 입력값 검증이 어려워 **SQL Injection** 공격에 취약할 수 있습니다.
- **`PreparedStatement`:**
    - 쿼리의 변수 들어갈 자리를 물음표(`?`) 파라미터로 대체하여 미리 컴파일합니다.
    - **장점:** `setString(1, val)`, `setInt(2, val)` 등의 메서드로 타입을 강제하므로 입력값 오류를 방지하고 보안성이 높습니다. 실무 및 복잡한 쿼리에서는 이 방식이 권장됩니다.
        

### 3. 데이터 조작 및 결과 처리 (CRUD Implementation)

애플리케이션단에서 DB 데이터를 처리할 때, SQL의 성격에 따라 사용하는 메서드가 구분됩니다.

- **조회 (`SELECT`):** `executeQuery()` 메서드를 사용하며, 반환값은 `ResultSet` 객체입니다. 커서(Cursor)의 개념인 `next()` 메서드를 사용하여 레코드를 한 줄씩 탐색하며 데이터를 추출합니다.
- **변경 (`INSERT`, `UPDATE`, `DELETE`):** `executeUpdate()` 메서드를 사용하며, 반환값은 **영향받은 행(Row)의 개수(`int`)**입니다.
- **GUI 연동 로직:**
    - **추가(Insert):** 텍스트 필드의 값을 받아 `PreparedStatement`로 DB에 저장하고, JTable(화면)에도 행을 추가합니다.
    - **삭제(Delete):** 화면에서 선택된 행의 Primary Key(학번)를 식별하여 DB에서 `DELETE`를 수행합니다. 실수 방지를 위해 삭제 전 확인 팝업(Confirm Dialog)을 띄우는 것이 안전합니다.
    - **수정(Update):** Primary Key(학번)는 무결성을 위해 수정을 제한하고, 나머지 정보(이름, 주소)만 수정하도록 `UPDATE` 쿼리를 구성합니다.
        
## 개념 - DB보안 1교시_2025.11.24

### 1. 핵심 용어 (Terminology)

- **JDBC (Java Database Connectivity):** 자바 애플리케이션이 DBMS와 통신할 수 있도록 해주는 표준 API입니다.
- **Connection (세션 수립):** DB 서버와의 연결 통로입니다. 보안 관점에서 연결은 값비싼 자원이므로, 사용 후 반드시 반환(`close`)하여 가용성을 확보해야 합니다.
- **PreparedStatement (보안 실행 객체):** SQL 문을 미리 컴파일하여 DB에 전송하는 객체입니다.
    - **특징:** 변수 위치를 `?` (Placeholders)로 지정하여 처리합니다.
    - **보안 이점:** 입력값을 단순 데이터로 취급하므로, 해커가 악의적인 SQL 구문을 주입하는 **SQL Injection** 공격을 원천적으로 차단합니다.
- **ResultSet (결과 집합):** `SELECT` 쿼리의 실행 결과를 저장하는 객체입니다. 내부 포인터(Cursor)를 이동(`next()`)시키며 데이터를 한 행씩 읽어옵니다.
    

### 2. JDBC 패턴 & SQL 문법 (Syntax Pattern)

#### **A. Secure Query Execution Pattern**

`Statement` 대신 `PreparedStatement`를 사용하는 표준 패턴입니다.

Java

```Java
// 1. SQL 정의 (변수는 ? 로 처리)
String sql = "UPDATE student SET name = ?, address = ? WHERE stu_id = ?";

// 2. PreparedStatement 객체 생성
PreparedStatement pstmt = con.prepareStatement(sql);

// 3. 파라미터 바인딩 (인덱스는 1부터 시작)
pstmt.setString(1, "홍길동"); // 첫 번째 ? 에 매핑
pstmt.setString(2, "서울");   // 두 번째 ? 에 매핑
pstmt.setString(3, "202301"); // 세 번째 ? 에 매핑

// 4. 실행 (DML은 executeUpdate)
int rowsAffected = pstmt.executeUpdate(); 
// 반환값: 수정된 행의 개수 (0이면 실패 혹은 대상 없음)
```

#### **B. Result Processing Pattern (SELECT)**

`executeQuery`와 `ResultSet`을 사용하는 패턴입니다.

Java

```Java
String sql = "SELECT * FROM student";
PreparedStatement pstmt = con.prepareStatement(sql);
ResultSet rs = pstmt.executeQuery(); // SELECT는 executeQuery 사용

// Cursor 이동 (데이터가 있는 동안 반복)
while (rs.next()) {
    String id = rs.getString("stu_id"); // 컬럼명으로 추출
    String name = rs.getString(2);      // 또는 컬럼 인덱스(1-based)로 추출
}
```

### 3. Standard Check 보안성 검증

|**구분**|**강의 중 사용 방식 (Statement)**|**표준 보안 권고안 (PreparedStatement)**|
|---|---|---|
|**쿼리 구성**|`"SELECT … WHERE id = '" + id + "'"`<br><br>  <br><br>(문자열 결합)|`"SELECT … WHERE id = ?"`<br><br>  <br><br>(파라미터 바인딩)|
|**보안 위협**|**SQL Injection 취약**<br><br>  <br><br>(예: `id`에 `' OR '1'='1` 입력 시 전체 조회됨)|**안전함**<br><br>  <br><br>(특수문자도 단순 값으로 이스케이프 처리됨)|
|**성능**|실행 시마다 컴파일 (반복 실행 시 느림)|미리 컴파일(Pre-compile) 후 캐싱 (반복 실행 시 빠름)|
|**가독성**|따옴표와 `+` 연산자로 인해 복잡함|`?`로 구조가 명확하고 유지보수 용이|

> ⚠️ 보안 감사 포인트:
>
> 실무 코드 리뷰 시, 사용자 입력값이 포함되는 모든 SQL 구문은 반드시 PreparedStatement를 사용해야 합니다. 문자열 결합(+)을 사용한 동적 쿼리는 보안 감사에서 Critical Issue로 분류됩니다.

### **S#1. 자바 GUI 기반 회원정보 CRUD 구현**

#### **1. Scenario & Goal**

- **Who:** 보안 관리자 (또는 DB 사용자)
- **What:** 자바 Swing GUI 애플리케이션을 통해 Oracle DB의 `student` 테이블을 조작(CRUD)합니다.
- **Why:** SQL 클라이언트(Toad, SQL Developer) 없이, **애플리케이션 계층**에서 데이터를 안전하게 제어하는 로직을 구현합니다.
- **Key Policy:**
    - **입력값 검증:** `PreparedStatement`를 사용하여 SQL Injection을 방지합니다.
    - **무결성 유지:** 삭제(`DELETE`) 전 사용자 확인 절차를 거치며, 수정(`UPDATE`) 시 PK(학번) 변경은 차단합니다.
        

#### **2. Java Implementation (Methods)**

> 아래 코드는 `DB_MemTable` 클래스 내부의 미구현 메서드(`//구현하기` 주석 부분)에 들어갈 정답 코드입니다.



```Java
// 1. 데이터 추가 (INSERT) - PreparedStatement 사용 (보안 권장)
void funAdd() {
    try {
        DBConn(); // DB 연결 수립
        
        // 1. 쿼리 템플릿 작성 (SQL Injection 방지)
        String sql = "INSERT INTO student(stu_id, name, address) VALUES(?, ?, ?)";
        pstmt = con.prepareStatement(sql);
        
        // 2. 파라미터 바인딩 (GUI 텍스트필드 값 -> SQL)
        pstmt.setString(1, tfs[0].getText().trim()); // 학번
        pstmt.setString(2, tfs[1].getText().trim()); // 이름
        pstmt.setString(3, tfs[2].getText().trim()); // 주소
        
        // 3. 실행 및 UI 반영
        int result = pstmt.executeUpdate();
        if(result > 0) {
            String[] rowData = {tfs[0].getText(), tfs[1].getText(), tfs[2].getText()};
            DefaultTableModel model = (DefaultTableModel)table.getModel();
            model.addRow(rowData); // JTable에도 즉시 추가
            
            // 입력 필드 초기화
            for(JTextField tf : tfs) tf.setText(""); 
        }
    } catch(SQLException e) {
        System.out.println("Insert Error: " + e.getMessage());
        // PK 중복 에러(ORA-00001) 처리 가능
    } finally {
        DBClose(); // 자원 해제
    }
}

// 2. 데이터 삭제 (DELETE) - 선택된 행 기반 삭제
void funDel() {
    // 선택된 행이 없는 경우 예외 처리
    if(row < 0) {
        JOptionPane.showMessageDialog(this, "삭제할 레코드를 선택하세요.");
        return;
    }
    
    // 삭제 확인 팝업 (실수 방지 UX)
    int choice = JOptionPane.showConfirmDialog(this, "정말로 삭제하시겠습니까?", "삭제 확인", JOptionPane.YES_NO_OPTION);
    if(choice != JOptionPane.YES_OPTION) return;

    try {
        DBConn();
        // JTable 모델에서 현재 선택된 행의 PK(학번) 가져오기
        DefaultTableModel model = (DefaultTableModel)table.getModel();
        String targetId = (String)model.getValueAt(row, 0); 
        
        String sql = "DELETE FROM student WHERE stu_id = ?";
        pstmt = con.prepareStatement(sql);
        pstmt.setString(1, targetId);
        
        int result = pstmt.executeUpdate();
        if(result > 0) {
            model.removeRow(row); // DB 성공 시 화면에서도 제거
            row = -1; // 선택 상태 초기화
        }
    } catch(SQLException e) {
        System.out.println("Delete Error: " + e.getMessage());
    } finally {
        DBClose();
    }
}

// 3. 전체 조회 (SELECT) - 목록 갱신
void funSelect() {
    try {
        DBConn();
        String sql = "SELECT * FROM student ORDER BY stu_id ASC"; // 정렬 포함
        pstmt = con.prepareStatement(sql); // Statement 대신 PreparedStatement 사용 권장
        rs = pstmt.executeQuery();
        
        // 기존 테이블 내용 초기화 (새로고침 효과)
        DefaultTableModel model = (DefaultTableModel)table.getModel();
        model.setRowCount(0); 
        
        // ResultSet 순회하며 UI에 추가
        while(rs.next()) {
            String[] record = new String[3];
            record[0] = rs.getString("stu_id");
            record[1] = rs.getString("name");
            record[2] = rs.getString("address");
            model.addRow(record);
        }
    } catch(SQLException e) {
        System.out.println("Select Error: " + e.getMessage());
    } finally {
        DBClose();
    }
}

// 4. 데이터 수정 (UPDATE) - 다이얼로그 호출
void funUpdate() {
    if(row < 0) {
        JOptionPane.showMessageDialog(this, "수정할 레코드를 선택하세요.");
        return;
    }
    // 수정 로직은 별도 클래스(UpdateDialog)에 위임되어 있으므로 객체만 생성
```

<summary>Q1. 보안 관점에서 Statement보다 PreparedStatement를 반드시 사용해야 하는 이유는 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
PreparedStatement는 쿼리를 미리 컴파일(Pre-compile)하고 입력값을 단순 데이터(Parameter)로 바인딩하기 때문에, 해커가 악의적인 SQL 구문을 삽입하는 SQL Injection 공격을 원천적으로 차단할 수 있습니다.
<br><br>
[📚 상세 설명]
<br>
- **Statement:** 쿼리와 데이터를 문자열 결합(`&quot;…&quot; + id + &quot;…&quot;`)으로 처리합니다. 이 과정에서 특수문자(`&#39; OR &#39;1&#39;=&#39;1`)가 SQL 명령어로 인식되어 보안 취약점이 발생합니다.
<br>
- **PreparedStatement:**
<br>
    1. **Pre-compilation:** 쿼리의 문법을 먼저 분석해 둡니다.
<br>
    2. **Binding:** 입력값은 단순 리터럴 값으로만 취급되며, 절대 실행 가능한 코드로 변환되지 않습니다.
<br>
    3. Performance: 반복 실행 시 캐싱 효과로 성능도 더 우수합니다.

<summary>Q2. JDBC 코딩 시 close()를 finally 블록에서 수행해야 하는 이유는 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
DB 연결 자원(Connection)은 한정되어 있기 때문에, 예외(Error) 발생 여부와 관계없이 반드시 자원을 해제하여 메모리 누수(Memory Leak) 및 서비스 거부(DoS) 상황을 방지하기 위함입니다.
<br><br>
[📚 상세 설명]
<br>
- **Resource Leak:** `close()`를 하지 않으면 DB 세션이 계속 열려있게 되어, 허용된 최대 접속자 수(Max Connections)를 초과하게 됩니다. 이로 인해 새로운 사용자가 접속하지 못하는 장애가 발생합니다.
<br>
- Why Finally?: try 블록 내에서 에러가 발생하면 그 아래 코드는 실행되지 않지만, finally 블록은 무조건 실행되므로 자원 해제에 가장 안전한 위치입니다.
<br>
</details>
    

<details>

<summary>Q3. executeQuery()와 executeUpdate()의 차이점은 무엇인가요?</summary>
<br>
[🗣️ 핵심 요약]
<br>
수행하는 SQL의 성격과 반환(Return) 타입이 다릅니다. executeQuery()는 데이터 **조회(SELECT)**용으로 ResultSet을 반환하며, executeUpdate()는 데이터 **변경(INSERT, UPDATE, DELETE)**용으로 **변경된 행의 개수(int)**를 반환합니다.
<br><br>
[📚 상세 설명]
<br>
- **executeQuery():** `SELECT` 문 실행 시 사용. 결과 집합(`ResultSet`)을 리턴하므로 `next()` 메서드로 데이터를 탐색해야 합니다.
<br>
- executeUpdate(): DML(Data Manipulation Language) 실행 시 사용. 실행 결과 몇 개의 행이 영향을 받았는지 정수형(int)으로 알려주므로, 성공 여부(result &gt; 0)를 판단하는 데 사용됩니다.

</details>
    

<details>

<summary>Q4. ResultSet의 next() 메서드의 역할과 동작 방식은?</summary>
<br>
[🗣️ 핵심 요약]
<br>
next()는 **커서(Cursor)**를 다음 행(Row)으로 이동시키는 역할을 합니다. 데이터가 존재하면 true를 반환하여 루프를 돌게 하고, 더 이상 데이터가 없으면 false를 반환하여 조회를 종료합니다.
<br><br>
[📚 상세 설명]
<br>
- **초기 상태:** 커서는 첫 번째 데이터의 '이전(Before First)'을 가리키고 있습니다.
    <br>
- 동작: rs.next()를 호출해야 비로소 첫 번째 실제 데이터(Row 1)를 가리키게 되며, 이때 getInt()나 getString()으로 데이터를 꺼낼 수 있습니다. 이를 File Pointer와 유사한 개념으로 이해하면 쉽습니다.
    
</details>
