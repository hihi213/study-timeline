## 주관식 10문항

### S1. 자료구조와 알고리즘을 함께 배워야 하는 이유를 2문장으로 설명하라.

<details>
<summary>정답 보기</summary>
자료구조는 데이터의 **형태와 연산 비용**을, 알고리즘은 그 위에서의 **절차와 성능**을 규정한다. 같은 알고리즘이라도 선택한 자료구조에 따라 시간·공간 복잡도가 달라지므로 두 영역은 불가분이다.
</details>

------

### S2. float a = 3.14; 실행 시 코드/데이터/스택/힙 중 어디에 무엇이 놓이는가?

<details>
<summary>정답 보기</summary>
기계어는 **코드**, 리터럴/상수는 **데이터**, 지역변수 `a`는 **스택**에 위치한다. 동적할당이 없으므로 **힙**은 사용하지 않는다.
</details>

------

S3. 선형 vs 비선형 자료구조의 차이와 각 대표 예 2개씩.

<details>
<summary>정답 보기</summary>
선형은 순차 구조(예: 배열, 연결 리스트/스택/큐), 비선형은 계층·관계 구조(예: 트리, 그래프/해시)를 표현한다.
</details>

------

### S4. 배열 vs 연결 리스트 선택 기준을 “데이터 규모/변동성/접근 패턴” 관점에서 요약하라.

<details>
<summary>정답 보기</summary>
규모 고정·임의접근 많으면 **배열**, 크기 가변·중간 삽입/삭제 빈번하면 **연결 리스트**가 유리하다(단, 위치 탐색 비용은 별도).
</details>

------

### S5. 원형 큐로 배열 큐의 비효율을 어떻게 제거하는가?

<details>
<summary>정답 보기</summary>
`front/rear`를 모듈러로 회전시켜 물리적 이동 없이 **논리적 이동**만 수행하므로 `dequeue`가 O(1)이 된다.
</details>

------

### S6. 힙이 일반 큐와 다른 정책과 그 장점 1가지.

<details>
<summary>정답 보기</summary>
FIFO가 아닌 **우선순위 기반** 처리다. 가장 중요한 작업을 먼저 처리해 **응답 지연**을 줄인다.
</details>

------

### S7. 포인터의 타입 정보가 중요한 이유를 한 문단으로 설명하라.

<details>
<summary>정답 보기</summary>
타입은 역참조 시 **얼마나 읽고(크기)** **어떻게 해석**할지를 규정한다. 같은 주소도 `int *`와 `char *`로 읽으면 결과가 달라져, 잘못된 타입은 메모리 오독·오류를 야기한다.
</details>

------

### S8. 아래 코드가 오류인 이유를 설명하고, 올바르게 바꿔라.

register int a = 7;
int *p = &a;

<details>
<summary>정답 보기</summary>
`register` 변수는 주소 존재가 보장되지 않아 `&a`가 허용되지 않는다. 해결: `register` 제거(또는 별도 포인터 초기화) → `int a=7; int *p=&a;`.
</details>

------

### S9. *p++와 (*p)++의 의미 차이를 정확히 기술하라.

<details>
<summary>정답 보기</summary>
`*p++`는 현재 `*p` 값을 사용한 뒤 **포인터**를 다음 원소로 이동(`*(p++)`). `(*p)++`는 포인터는 그대로 두고 **가리키는 값**을 1 증가.
</details>

------

### S10. 태그 없는 익명 구조체 두 개의 타입 동일성에 대해 설명하라.

## **주관식 10문항**

### **S1. 연속 메모리와 배열의 주소 계산을 짧게 설명하라.**

<details><summary>정답 보기</summary>

- 배열은 동일 타입 원소가 **연속 메모리**에 저장된다.  
- 주소 공식: `addr(a[i]) = base + i * sizeof(T)` → 임의 접근 O(1).

</details>

-----

### **S2. int a1,a2,a3; 대신 int a[3];을 쓰면 포인터 순회가 쉬운 이유를 설명하라.**

<details><summary>정답 보기</summary>

- 배열은 연속이 보장되어 `p=a; p+1, p+2`로 순회 가능.  
- 개별 변수는 연속 보장X → 각 주소를 따로 알아야 함.

</details>

-----

### **S3. C의 2차원 배열 a[m][n]에서 a[i][j]의 주소를 식으로 써라.**

<details><summary>정답 보기</summary>

- **행 우선**: `addr(a[i][j]) = base + (i*n + j) * sizeof(T)`.

</details>

-----

### **S4. malloc이 **void***를 반환하는 이유와 C에서 캐스팅이 선택사항인 이유를 설명하라.**

<details><summary>정답 보기</summary>

- 어떤 타입의 블록인지 알 수 없으므로 **타입 미정 주소**(`void*`) 반환.  
- C에서는 `void*` → `T*` **암시적 변환 허용**(대입 가능), 필요 시 명시 캐스팅 사용.

</details>

-----

### **S5. 이중 포인터가 실무에서 필요한 대표 상황 2가지를 써라.**

<details><summary>정답 보기</summary>

- (1) 포인터 자체를 수정해야 할 때(예: 리스트 **헤드** 변경).  
- (2) 동적 2D 구조/포인터 배열 관리 시(주소→주소→값).

</details>

-----

### **S6. 함수 호출 스택에서 복귀 주소가 어떻게 관리되는지 2–3문장으로 요약하라.**

<details><summary>정답 보기</summary>

- 호출 시 **복귀 주소/매개변수/지역변수**가 스택 프레임으로 push.  
- 함수가 `return`하면 프레임이 pop되고 **복귀 주소**가 PC에 복원되어 호출 지점 다음 명령으로 복귀.

</details>

-----

### **S7. 초기화되지 않은 포인터를 역참조하면 위험한 이유와 예방 방법을 쓰라.**

<details><summary>정답 보기</summary>

- 임의(쓰레기) 주소를 가리켜 **미정의 동작/세그폴트/데이터 훼손** 유발.  
- 예방: 선언과 동시에 **유효 주소로 초기화**(객체 주소/`malloc`)하거나 `NULL`로 초기화 후 체크.

</details>

-----

### **S8. 값 호출 vs 참조(포인터) 호출의 차이를 swap으로 설명하라.**

<details><summary>정답 보기</summary>

- 값 호출: 복사본을 바꾸어도 **원본 불변**.  
- 포인터 전달: **주소**를 넘겨 `*p`로 원본 메모리를 직접 교체 → 원본 변경.

</details>

-----

### **S9. 희소 행렬을 공간 효율적으로 저장하는 구조와 장단점을 쓰라.**

<details><summary>정답 보기</summary>

- 구조: `(row, col, value)`의 **구조체 배열**(비영 항목만 저장).  
- 장점: 공간 O(k)로 절약. 단점: 특정 (i,j) 접근 시 탐색 필요 → 시간 증가.

</details>

-----

### **S10. 다음 중 왜 가능한지/불가능한지 설명하라: a = p; vs a[2] = 7; (int a[5];)**

<details><summary>정답 보기</summary>

- `a`는 **시작 주소 상수**라 재대입 불가(컴파일 오류).  
- `a[2]`는 유효한 **L-value(메모리 공간)** → 값 저장 가능.

</details>
