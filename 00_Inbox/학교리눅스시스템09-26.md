## 정리
## **2025-09-26, 1교시 — 개선본**

지난 시간까지 홈 디렉터리 안에 `d1`, `d2`, `temp` 디렉터리가 생성되어 있어야 합니다. `d1`과 `d2`는 같은 레벨에 있어야 합니다. 지난 시간에 `TMP`가 아닌 `temp`로 생성했는데, 시스템 디렉터리인 `/tmp`와 혼동을 피하기 위함이었습니다.

우리가 생성한게 아닌 원래 존재하는 `/tmp` 디렉터리를 확인해 봅시다. `cd /` 명령으로 루트 디렉터리로 이동한 후 `ls -al`을 실행하면 `tmp` 디렉터리를 볼 수 있습니다. (실습) 이 디렉터리의 권한을 보면 다른 디렉터리와 달리 맨 끝에 `t` 권한이 설정된 것을 볼 수 있습니다. 이것은 '스티키 비트(sticky bit)'라는 특수 권한입니다.

`/tmp` 디렉터리는 여러 사용자가 함께 사용하는 공간입니다. 스티키 비트가 설정되어 있으면, 파일을 생성한 소유자만 해당 파일을 삭제할 수 있도록 제한됩니다. 다른 디렉터리의 경우, 쓰기(`w`) 권한이 있으면 다른 사용자의 파일도 삭제할 수 있지만, `/tmp`에서는 소유권이 중요하게 작용합니다.

용어에 대해 정리하고 넘어가겠습니다. 리눅스 시스템에서 최상위 디렉터리인 `/`를 **루트 디렉터리(root directory)**라고 부릅니다. 반면, 슈퍼유저(root)의 홈 디렉터리는 `/root`입니다. 혼동을 피하기 위해 강의에서는 `/`를 '루트 디렉터리', `/root`는 '슬래시 루트'라고 지칭하겠습니다.

또한, 사용자의 개인 작업 공간인 `/home/username`을 **홈 디렉터리**라고 부르겠습니다. `cd` 명령을 아무 옵션 없이 실행하면 이 홈 디렉터리로 즉시 이동합니다. (실습) `/home` 디렉터리는 '슬래시 홈'이라고 부르겠습니다. 현재 작업 중인 디렉터리 위치가 헷갈릴 때는 `pwd` 명령으로 확인할 수 있습니다. (실습)

지난 시간에 `mkdir -p` 옵션을 사용하면 중간 경로의 디렉터리까지 한 번에 생성할 수 있다고 배웠습니다. `rmdir` 명령어는 디렉터리 내부에 파일이나 다른 디렉터리가 있으면 삭제를 거부합니다. 강제로 삭제하는 옵션이 있지만, 이는 나중에 다루겠습니다.

다음 예제를 통해 디렉터리 관련 명령어를 복습해 보겠습니다. (실습)

1. 사용자 홈 디렉터리에서 `study` 디렉터리를 생성하세요. (`mkdir study`) (실습)
2. 명령 한 번만 실행하여 `study` 아래에 `ch03`을, `ch03` 아래에 `one` 디렉터리를 생성하세요. (`mkdir -p study/ch03/one`) (실습)
3. `ch03` 디렉터리로 이동하세요. 현재 위치가 홈 디렉터리이므로 상대 경로를 사용합니다. (`cd study/ch03`) (실습)
4. `ch03` 디렉터리에서 `one` 디렉터리가 보이는지 확인하세요. (`ls`) (실습)
5. `one` 디렉터리 아래에 `me`와 `new` 디렉터리를 한 번에 생성하세요. (`mkdir one/me one/new`) (실습)
6. `new` 디렉터리를 삭제하고, `one` 디렉터리도 삭제해 보세요. `one` 디렉터리는 내부에 `me`가 남아있어 삭제되지 않을 것입니다. (실습)
7. 홈 디렉터리로 이동하세요. (`cd`) (실습)

이제 파일 내용을 화면에 출력하는 명령어를 알아보겠습니다. `cat` 명령어는 텍스트 파일의 전체 내용을 한 번에 보여줍니다. 예를 들어, `cat /etc/hosts`를 실행하면 호스트 파일의 내용을 볼 수 있습니다. (실습) 이 파일에는 `127.0.0.1` 주소가 `localhost`로 지정되어 있는데, 이는 루프백(loopback) 주소로 자기 자신을 가리키며 네트워크 테스트 등에 사용됩니다.

`cat`에 `-n` 옵션을 주면 각 줄 앞에 행 번호를 붙여서 출력합니다. (`cat -n /etc/hosts`) (실습) 이는 파일 자체를 수정하는 것이 아니라 화면에 보여줄 때만 적용됩니다. 명령어 입력 시, 파일명의 일부를 입력하고 `Tab` 키를 누르면 자동 완성이 되니 적극적으로 활용하세요. (실습)

내용이 긴 파일을 볼 때는 cat보다 more나 less 명령어가 유용합니다.

more /etc/services를 실행하면 파일 내용이 화면 단위로 끊어서 출력됩니다. (실습)

- **Enter**: 한 줄씩 아래로 이동합니다.
- **Spacebar**: 한 페이지씩 아래로 이동합니다.
- `/문자열`: 특정 문자열을 검색합니다.
- q: 명령을 종료합니다.

    more는 이전 내용으로 돌아갈 수 없는 단점이 있습니다.

`less /etc/services`는 `more`의 개선된 버전으로, 양방향 탐색이 가능합니다. (실습)

- **j** 또는 **아래 화살표**: 아래로 한 줄 이동합니다.
- **k** 또는 **위 화살표**: 위로 한 줄 이동합니다.
- **Spacebar**: 한 페이지 아래로 이동합니다.
- **Ctrl+B**: 한 페이지 위로 이동합니다.
- `q`: 종료합니다.

과거 화살표 키가 없는 키보드 환경 때문에 `j`, `k`와 같은 키가 이동에 사용되었으며, 이는 나중에 배울 `vi` 편집기에서도 동일하게 사용됩니다.

## **2025-09-26, 1교시 — 개념**

### 한 줄 요약

리눅스의 기본 디렉터리 구조와 경로 개념을 이해하고, `cd`, `mkdir` 등 디렉터리 조작 명령어와 `cat`, `less` 등 파일 내용을 확인하는 명령어를 학습합니다.

### 핵심 TL;DR

- **경로**: `/`로 시작하면 **절대 경로**, 그렇지 않으면 현재 위치 기준인 **상대 경로**입니다.
- **주요 디렉터리 약어**: `~` (홈 디렉터리), `.` (현재 디렉터리), `..` (부모 디렉터리).
- **`cd` 명령어**: 인수 없이 `cd`만 입력하면 어디서든 홈 디렉터리(`~`)로 즉시 이동합니다.
- **`mkdir -p`**: `-p` 옵션은 경로상의 존재하지 않는 부모 디렉터리까지 한 번에 생성합니다.
- **스티키 비트(Sticky Bit)**: `/tmp` 같이 공용 디렉터리에 설정되며, 파일 소유자만 삭제할 수 있도록 권한을 제한합니다. 권한 표기 시 `t`로 나타납니다.
- **`cat` vs. `less`**: `cat`은 파일 전체를 한 번에 출력해 짧은 파일에 적합하고, `less`는 긴 파일을 페이지 단위로 탐색(상/하 이동 가능)하는 데 유용합니다.
- **`Tab` 키**: 명령어 또는 파일/디렉터리 이름 입력 시 자동 완성을 지원하여 오타를 줄여줍니다.
- **명령어 히스토리**: 위/아래 화살표 키를 이용해 이전에 실행했던 명령어를 다시 불러올 수 있습니다.

### 표현 = 표준 용어

- **루트 디렉터리 (`/`)**: 파일 시스템의 최상위 시작점.
- **홈 디렉터리 (`~`)**: 각 사용자의 개인 작업 공간 (`/home/username`).
- **작업 디렉터리 (Working Directory)**: 현재 명령어를 실행하고 있는 위치. `pwd`로 확인.
- **스티키 비트 (Sticky Bit)**: 공용 디렉터리의 파일 삭제 권한을 소유자로 제한하는 특수 권한.
- **루프백 주소 (Loopback Address)**: `127.0.0.1`. 시스템이 자기 자신을 가리키는 특수 IP 주소. `/etc/hosts` 파일에 정의되어 있음.
- **`cat (concatenate)`**: 파일 내용을 연결하여 표준 출력으로 보여주는 명령어.
- **`more` / `less`**: 텍스트 파일 내용을 페이지 단위로 보여주는 프로그램 (Pager). `less`가 `more`의 상위 호환.

### 정석 보강 (canon-std)

**디렉터리 탐색과 경로**: 리눅스에서 위치를 이동하는 핵심은 경로(path)의 이해입니다. **절대 경로**는 항상 루트(`/`)에서 시작하여 목적지까지의 전체 경로를 명시하므로 현재 위치와 무관하게 항상 동일하게 동작합니다. 반면 **상대 경로**는 현재 작업 디렉터리를 기준으로 경로를 지정합니다. 디렉터리 이동에는 `cd` (Change Directory), 현재 위치 확인에는 `pwd` (Print Working Directory) 명령어를 사용하며, 디렉터리에 진입하기 위해서는 해당 디렉터리에 대한 실행(`x`) 권한이 필요합니다.

### 실수·함정

- `cd /home`과 `cd ~`는 다른 목적지로 이동합니다. 전자는 모든 사용자의 홈 디렉터리가 모여있는 곳으로, 후자는 현재 로그인한 자신의 홈 디렉터리로 이동합니다.
- 절대 경로를 써야 할 곳에 상대 경로를 사용하면 `No such file or directory` 에러가 발생하기 쉽습니다.
- `rmdir`은 비어있지 않은 디렉터리를 삭제할 수 없습니다.
- `cat`으로 매우 큰 로그 파일을 열면 터미널이 응답하지 않을 수 있습니다. `less`나 `tail`을 사용하는 것이 안전합니다.
- `/etc/hosts` 파일이 악성코드에 의해 변조되면 특정 사이트 접속 시 피싱 사이트로 연결될 수 있습니다.
- 명령어와 옵션, 인자 사이에는 반드시 공백(space)으로 구분해야 합니다.

## **2025-09-26, 1교시 — 질문**

**[Q1] 리눅스에서 절대 경로와 상대 경로는 어떻게 다르며, 언제 각각 사용해야 하나요? | 태그: 셸/리다이렉션/FD, 파일·디렉터리**

- **모범답(강의 기준)**: `/` 문자로 시작하는 절대 경로는 현재 위치와 상관없이 항상 루트 디렉터리부터의 전체 경로를 나타냅니다. 반면, 상대 경로는 현재 작업 디렉터리를 기준으로 경로를 지정하므로, `study/ch03` 처럼 현재 위치의 하위 디렉터리로 이동할 때 더 간결합니다.
- **정석체크(면접 30초)**: 파일시스템 탐색 시, 슬래시(`/`)로 시작하는 **절대 경로**는 루트부터의 고유한 전체 주소이며, **상대 경로**는 현재 디렉터리(`.`)를 기준으로 한 상대적 주소입니다. 스크립트 등에서는 현재 위치에 따라 실패할 수 있는 상대 경로보다 절대 경로를 사용하는 것이 더 안정적입니다.

**[Q2] 리눅스의 `~`, `/home`, `/`, `/root` 디렉터리는 각각 무엇을 의미하며 어떻게 다른가요? | 태그: 파일·디렉터리, 사용자/그룹/쿼터**

- **모범답(강의 기준)**: `/`는 시스템 전체의 최상위 루트 디렉터리, `/root`는 root 관리자 계정의 홈 디렉터리입니다. `/home`은 일반 사용자들의 홈 디렉터리가 모여있는 상위 폴더이며, `~`는 현재 로그인한 '나'의 홈 디렉터리(`cd` 명령의 기본 목적지)를 가리키는 약어입니다.
- **정석체크(면접 30초)**: 리눅스 파일시스템 계층구조(FHS)에서 `/`는 모든 것의 시작점인 **루트 디렉터리**이며 `~`는 환경변수 `$HOME`을 참조하는 **현재 사용자의 홈 디렉터리**입니다. `/home`은 사용자 홈들의 상위 폴더일 뿐이므로, `cd /home`과 `cd ~`는 다른 위치로 이동하니 혼동해서는 안 됩니다.

**[Q3] `/tmp` 디렉터리의 권한 마지막에 붙는 `t`(스티키 비트)는 어떤 특별한 역할을 하나요? | 태그: 권한/UMASK/특수비트, 파일·디렉터리**

- **모범답(강의 기준)**: 스티키 비트(`t`)는 `/tmp`처럼 여러 사용자가 함께 쓰는 공용 디렉터리에 설정됩니다. 이 권한이 있으면, 디렉터리 내에 파일을 생성한 소유자만이 해당 파일을 삭제할 수 있도록 제한하여 다른 사용자가 임의로 파일을 지우는 것을 방지합니다.
- **정석체크(면접 30초)**: 디렉터리의 특수 권한 중, **스티키 비트**(권한값: `1000`, 표기: `t`)는 해당 디렉터리 내의 파일이나 하위 디렉터리 삭제 권한을 해당 객체의 소유자, 디렉터리의 소유자, 그리고 root에게만 허용합니다. 이는 공용 디렉터리의 파일을 보호하는 핵심적인 보안 기능입니다.

**[Q4] `rmdir` 명령어로 디렉터리를 삭제하려고 할 때, 왜 "디렉터리가 비어있지 않다"는 오류가 발생하며 실패하나요? | 태그: 파일·디렉터리, 셸/리다이렉션/FD**

- **모범답(강의 기준)**: `rmdir` 명령어는 실수로 내용물이 있는 디렉터리를 삭제하는 것을 방지하기 위해, 내부에 파일이나 다른 하위 디렉터리가 하나라도 있으면 삭제를 거부하도록 설계되었기 때문입니다.
- **정석체크(면접 30초)**: `rmdir` 명령어는 오직 **비어 있는(empty) 디렉터리**만 삭제하도록 설계된 안전장치입니다. 내용이 있는 디렉터리를 재귀적으로 강제 삭제하려면 `rm -r` 명령어를 사용해야 하지만, 복구가 거의 불가능하므로 대상 경로를 명확히 확인하고 신중하게 사용해야 합니다.

## **2025-09-26, 1교시 — 실습**

**[S1] `/tmp` 디렉터리 특수 권한(스티키 비트) 확인**

- **목적**: `ls` 명령어를 사용하여 시스템의 공용 임시 폴더인 `/tmp`에 설정된 `t` 권한(스티키 비트)을 직접 관찰합니다.
- **단계요약**: 1) `cd /` 명령으로 루트 디렉터리로 이동합니다. 2) `ls -al` 명령을 실행하여 상세 목록을 출력합니다. 3) 출력 결과에서 `tmp` 디렉터리 권한 필드의 마지막 글자가 `t`인지 확인합니다.

**[S2] 디렉터리 생성, 이동, 확인, 삭제 종합 실습**

- **목적**: `mkdir`, `cd`, `ls`, `rmdir` 등 핵심 디렉터리 관리 명령어의 옵션을 포함한 종합적인 사용법을 익힙니다.

## **2025-09-26, 2교시 — 개선본**

지난 시간에 `cat` 명령어로 긴 파일을 보면 내용이 빠르게 지나가 전부 확인하기 어렵다고 했습니다. 이럴 때 **파이프라인(pipeline)**을 사용할 수 있습니다. `cat /etc/services`를 실행한 후, `|` (Shift + 원화() 키) 기호를 입력하고 `more`를 붙여 실행해 보세요. (`cat /etc/services | more`) (실습)

파이프라인 `|`은 앞선 명령어의 실행 결과를 뒷 명령어의 입력으로 전달하는 역할을 합니다. 즉, `cat`이 출력한 파일 전체 내용을 `more`가 받아서 페이지 단위로 보여주는 것입니다. 이렇게 두 가지 이상의 명령을 조합하여 사용할 수 있습니다.

파일의 앞부분이나 뒷부분만 간단히 확인할 때는 `head`와 `tail` 명령어를 사용합니다.

- `head /etc/services`: 파일의 첫 10줄을 보여줍니다. (실습)
- `head -3 /etc/services`: `-` 다음에 숫자를 지정하여 원하는 줄 수만큼 볼 수 있습니다. (실습)
- `tail /etc/services`: 파일의 마지막 10줄을 보여줍니다. (실습)

다음은 파일 복사 명령어인 `cp(copy)`입니다. 기본 형식은 `cp [원본파일] [대상파일]` 이며, 원본 파일을 새로운 대상 파일 이름으로 복사합니다.

리눅스를 배울 때는 항상 "왜 그럴까?"라는 질문을 습관화하는 것이 중요합니다. 단순히 명령어를 따라 치는 것을 넘어, 왜 특정 상황에서 복사가 되고 다른 상황에서는 이동이 되는지(Windows의 경우 드라이브가 다를 때 복사, 같을 때 이동), 왜 이 옵션이 필요한지 등을 스스로 탐구해야 합니다. 주어진 기능만 수동적으로 사용하지 말고, 시스템의 동작 원리를 이해하려는 노력이 필요합니다. 이것이 자기주도 학습의 시작입니다.

`cp` 명령어 사용 시, 만약 대상 파일의 이름이 이미 존재한다면 파일을 덮어쓸지 물어보도록 하는 `-i` 옵션이 있습니다.

이제 실습을 통해 cp 명령어를 익혀봅시다. study/ch03 디렉터리로 이동하세요. (실습)

cp /etc/profile test1 명령을 실행하여 시스템 설정 파일 중 하나인 /etc/profile을 현재 디렉터리에 test1이라는 이름으로 복사하세요. (실습) ls로 확인하면 test1 파일이 생성된 것을 볼 수 있습니다.

이번에는 디렉터리에 파일을 복사해 보겠습니다. mkdir temp로 temp 디렉터리를 생성하세요. (실습)

cp test1 temp 명령을 실행하면, test1 파일이 temp 디렉터리 안으로 동일한 이름으로 복사됩니다. (실습)

여기서 경로의 중요성이 다시 드러납니다. `temp` 앞에 `/`가 없으므로 이는 현재 디렉터리 아래에 있는 상대 경로입니다. 만약 `./temp`와 같이 명시적으로 표현할 수도 있습니다. 리눅스는 Windows와 달리 파일 및 디렉터리 이름의 **대소문자를 구분**하므로 항상 정확하게 입력해야 합니다.

파일을 복사하는 대신 이동(move)하거나 이름을 바꿀 때는 `mv` 명령어를 사용합니다. `mv test1 one`을 실행하면 `test1` 파일이 `one` 디렉터리 안으로 이동합니다. (실습) `ls`로 확인하면 현재 디렉터리에서 `test1`이 사라진 것을 볼 수 있습니다.

디렉터리 전체를 복사할 때는 -r (recursive, 재귀적) 옵션을 반드시 사용해야 합니다.

cp -r temp temp2 명령은 temp 디렉터리와 그 안의 모든 내용을 temp2라는 새 디렉터리로 복사합니다. (실습) 만약 -r 옵션 없이 cp temp temp2를 시도하면, temp를 파일로 인식하여 디렉터리를 복사할 수 없다는 오류가 발생합니다.

`ls -R` 옵션은 현재 디렉터리부터 시작하여 모든 하위 디렉터리의 내용까지 트리 구조로 보여줍니다. 내용이 길 경우 `ls -R | more`와 같이 파이프라인을 활용할 수 있습니다. (실습) 또한, `ls temp2`처럼 `ls` 명령어에 인자로 디렉터리 경로를 주면, 현재 위치를 바꾸지 않고도 해당 디렉터리의 내용을 확인할 수 있습니다.

## **2025-09-26, 2교시 — 개념**

### 한 줄 요약

파이프라인(`|`)을 이용한 명령어 조합, `head`/`tail`로 파일 미리보기, `cp`/`mv`를 이용한 파일 및 디렉터리 복사와 이동 등 리눅스 파일 관리 핵심을 학습합니다.

### 핵심 TL;DR

- **파이프라인 (`|`)**: 한 명령어의 출력 결과를 다른 명령어의 입력으로 연결하여, 여러 명령을 조합하는 강력한 기능입니다. (`ls -R | more`)
- **`head` & `tail`**: 전체 파일을 열지 않고 앞/뒷부분의 내용만 빠르게 확인할 때 사용하며, `-n` 옵션으로 줄 수를 지정할 수 있습니다.
- **`cp` (Copy)**: 파일이나 디렉터리를 복사합니다. 원본은 그대로 유지되고 사본이 생성됩니다.
- **`mv` (Move)**: 파일이나 디렉터리를 다른 위치로 옮기거나 이름을 변경합니다. 원본이 이동되므로 원래 위치에서는 사라집니다.
- **디렉터리 복사**: 디렉터리를 복사할 때는 반드시 `-r` (Recursive) 옵션을 사용해야 내부의 모든 항목까지 함께 복사됩니다.
- **덮어쓰기 확인**: `cp`나 `mv` 사용 시 `-i` (Interactive) 옵션을 주면, 대상 위치에 같은 이름의 파일이 있을 경우 덮어쓸지 사용자에게 물어봅니다.
- **대소문자 구분**: 리눅스는 파일, 디렉터리, 명령어, 옵션 모두 대소문자를 엄격하게 구분합니다. (`temp`와 `Temp`는 완전히 다른 파일입니다.)
- **자기주도 학습**: "왜?"라는 질문을 통해 명령어의 동작 원리를 이해하고, 책이나 `man` 페이지를 참고하여 스스로 탐구하는 자세가 중요합니다.

### 표현 = 표준 용어

- **파이프라인 (Pipeline `|`)**: 한 프로세스의 표준 출력(stdout)을 다른 프로세스의 표준 입력(stdin)으로 연결하는 셸 기능.
- **`head` / `tail`**: 파일의 시작 또는 끝 부분을 출력하는 유틸리티.
- **`cp` (Copy)**: 파일 및 디렉터리 복사 명령어.
- **`mv` (Move)**: 파일 및 디렉터리 이동 또는 이름 변경 명령어.
- **재귀적 (Recursive)**: 어떤 작업(복사, 삭제 등)을 특정 디렉터리뿐만 아니라 그 안에 포함된 모든 하위 디렉터리와 파일에 대해 반복적으로 적용하는 방식. `-r` 또는 `-R` 옵션으로 지정.
- **상대 경로 (Relative Path)**: 현재 위치를 기준으로 목적지를 표현하는 경로. (`temp`, `./temp`)

### 정석 보강 (canon-std)

**파일 및 디렉터리 복사 (`cp`)**: `cp` 명령어는 리눅스에서 파일과 디렉터리를 복제하는 핵심 도구입니다. 기본적으로 `cp [원본] [대상]` 형태로 사용되며, 대상이 디렉터리면 원본을 그 안으로 복사하고, 대상이 파일 이름이면 해당 이름으로 사본을 생성합니다. 가장 중요한 규칙은 **디렉터리를 복사할 때** 반드시 `-r` (recursive) 옵션을 명시해야 한다는 점입니다. 이 옵션이 없으면 `cp`는 디렉터리를 복사하지 못하고 오류를 반환합니다.

### 실수·함정

- `-r` 옵션 없이 디렉터리를 복사하려고 시도하면 "omitting directory" 관련 오류가 발생합니다.
- `cp file1 file2` 와 `mv file1 file2`의 차이를 혼동하는 것. `cp`는 사본을 만들고, `mv`는 원본을 이동시킵니다.
- 대소문자를 구분하지 않는 Windows 습관대로 파일명을 입력하여 "No such file or directory" 오류를 마주하는 경우.
- 절대 경로와 상대 경로를 혼용하여 의도치 않은 위치에 파일이 복사되거나, 원본을 찾지 못하는 실수.
- 파이프라인(`|`)과 리다이렉션(`>`)의 역할을 혼동하는 것. 파이프라인은 명령어 간 데이터 전달, 리다이렉션은 출력을 파일로 저장합니다.

**[Q2] 디렉터리를 복사할 때 `cp` 명령어에 `-r` 옵션을 반드시 사용해야 하는 이유는 무엇인가요? | 태그: 파일·디렉터리, 셸/리다이렉션/FD**

- **모범답(강의 기준)**: `-r` 옵션이 없으면 `cp`는 복사 대상을 파일로만 인식하기 때문입니다. 디렉터리와 그 안의 모든 파일 및 하위 디렉터리까지 '재귀적으로' 전부 복사하라는 의미를 명시적으로 전달하기 위해 `-r` 옵션을 반드시 사용해야 합니다.
- **정석체크(면접 30초)**: **전제**: 파일과 디렉터리의 구별을 위해, **핵심 규칙**: `cp` 명령어는 기본적으로 파일 단위로 동작하도록 설계되었습니다. `-r` 옵션은 명령어에게 "대상이 디렉터리이니, 그 안으로 들어가 모든 하위 항목에 대해 복사 작업을 재귀적으로 수행하라"고 명시적으로 지시하는 역할을 합니다.

**[Q3] 파일을 복사하는 `cp`와 이동시키는 `mv`의 근본적인 차이점은 무엇인가요? | 태그: 파일·디렉터리**

- **모범답(강의 기준)**: `cp`는 원본 파일을 그대로 남겨둔 채 동일한 내용의 사본을 새로 만드는 명령어입니다. 반면 `mv`는 원본 파일을 다른 위치로 옮기거나 파일 이름을 변경하는 것으로, 작업 후에는 원래 위치에 원본 파일이 남지 않습니다.
- **정석체크(면접 30초)**: **전제**: 파일시스템 inode 관점에서, **핵심 규칙**: `cp`는 새로운 inode를 할당하고 데이터 블록을 복제하여 별개의 파일을 생성합니다. 하지만 같은 파일시스템 내의 `mv`는 데이터는 그대로 둔 채 파일명과 연결된 inode 포인터 정보만 변경하여 매우 빠릅니다. **주의**: 다른 파일시스템 간의 `mv`는 사실상 복사 후 원본 삭제 방식으로 동작합니다.

## **2025-09-26, 3교시 — 개선본**

리눅스의 핵심 철학 중 하나는 **모든 것을 파일(File)로 취급한다**는 것입니다. 디렉터리 역시 특별한 종류의 파일로 간주됩니다. 이 때문에 `cp -r temp3 temp4` 명령을 내렸을 때, `temp4` 디렉터리가 존재하지 않아도 `cp`는 `temp4`라는 이름의 '파일'(즉, 디렉터리)을 새로 생성한 후 `temp3`의 내용을 그 안에 복사합니다. 이는 `cp file1 file2` 명령이 `file2`가 없을 때 새로 생성하는 원리와 같습니다. 이러한 철학은 CD-ROM 드라이브나 USB 장치 등 하드웨어 장치에도 적용되어, 시스템에 연결 시 파일처럼 접근하고 다룰 수 있게 합니다.

`ls` 명령만 사용하면 `.`으로 시작하는 숨겨진 파일이나 디렉터리는 보이지 않습니다. 이는 사용자가 실수로 중요한 시스템 파일을 수정하거나 삭제하는 것을 방지하기 위함입니다. `ls -a` 옵션을 사용하면 현재 디렉터리(`.`)와 부모 디렉터리(`..`)를 포함한 모든 숨겨진 항목을 볼 수 있습니다. (실습)

---

### `mv` 명령어의 동작 방식

`mv`는 파일을 이동시키거나 이름을 변경하는 명령어로, 대상(destination)이 존재하는지 여부에 따라 동작이 달라집니다.

1. **대상이 존재하지 않을 때 (이름 변경)**: `mv temp3 temp4`에서 `temp4`가 없다면, `temp3`의 이름이 `temp4`로 변경됩니다. `temp3`는 사라지며, 이는 사실상 '이름 바꾸기(rename)'와 동일한 작업입니다.
2. **대상이 디렉터리일 때 (이동)**: `mv temp4 temp`에서 `temp`가 이미 존재하는 디렉터리라면, `temp4` 디렉터리 전체가 `temp` 디렉터리 _안으로_ 이동합니다.

이것이 `cp`와의 결정적인 차이입니다. `cp`는 원본을 남기고 사본을 만들지만, `mv`는 원본 자체를 옮깁니다.

---

### `rm` 명령어와 데이터 삭제

파일 및 디렉터리 삭제는 매우 신중해야 하며, 명령어의 특성을 정확히 이해해야 합니다.

- **`rm [파일명]`**: 파일을 삭제합니다. 기본적으로는 확인 절차 없이 즉시 삭제되므로 매우 위험합니다.
- **`rm -i [파일명]`**: 파일을 삭제하기 전에 정말로 지울 것인지 사용자에게 **한 번 더 물어봅니다**(interactive). 중요한 파일을 실수로 삭제하는 것을 방지하기 위해, `rm` 사용 시에는 `-i` 옵션을 습관적으로 사용하는 것이 안전합니다. (실습)
- **`rm [디렉터리명]`**: 실패합니다. `rm`은 기본적으로 파일을 삭제하는 명령어이므로, 디렉터리를 지정하면 "디렉터리입니다"라는 메시지를 출력하며 작업을 거부합니다.
- **`rmdir [디렉터리명]`**: **비어 있는** 디렉터리만 삭제합니다. 내부에 파일이나 다른 디렉터리가 있으면 삭제에 실패합니다.
- **`rm -r [디렉터리명]`**: 디렉터리와 그 안에 포함된 **모든 내용(파일, 하위 디렉터리)을 재귀적으로 강제 삭제**합니다. (실습) 이 명령어는 매우 강력하고 위험하므로, 삭제하려는 디렉터리의 내용을 `ls`로 반드시 확인한 후 사용해야 합니다.

삭제된 파일은 일반적인 방법으로는 복구하기 거의 불가능합니다. 따라서 삭제 명령어, 특히 `rm -r`을 사용할 때는 각별한 주의가 필요합니다.

### 한 줄 요약

리눅스의 "모든 것은 파일" 철학을 바탕으로 `mv`의 이동/이름변경 동작과 `rm`의 삭제 메커니즘을 이해하고, `-i`, `-r` 옵션을 이용한 안전하고 강력한 파일 관리법을 배웁니다.

### 핵심 TL;DR

- **"모든 것은 파일" 철학**: 리눅스에서는 디렉터리, 하드웨어 장치(USB, 스피커) 등 모든 것을 파일로 취급하므로 파일 명령어(`cp`, `mv` 등)가 일관성 있게 적용됩니다.
- **`mv`의 두 가지 동작**: `mv source dest`에서 `dest`가 없으면 `source`의 **이름이 변경**됩니다. `dest`가 존재하는 디렉터리면 `source`가 그 안으로 **이동**합니다.
 ### **삭제 명령어의 안전 단계**:
    
1. `rmdir`: 가장 안전. 비어있는 디렉터리만 삭제.
2. `rm -i`: 차선책. 삭제 전 사용자에게 확인. **습관화**가 권장됩니다.
3. `rm`: 기본. 확인 없이 파일을 삭제하여 위험.
4. `rm -r`: 가장 위험. 디렉터리와 내부 모든 내용을 강제 삭제.
        
- **숨김 파일**: 이름이 `.`으로 시작하는 파일은 시스템 설정 등 중요 파일일 수 있어 `ls`에 기본적으로 표시되지 않습니다. `ls -a` 명령어로 모두 볼 수 있습니다.
- **`rm`은 복구 불가**: `rm`으로 삭제된 파일은 휴지통으로 가지 않고 즉시 제거되므로, 일반적인 방법으로는 복구가 거의 불가능합니다.
- **다중 터미널 사용**: 리눅스는 다중 사용자 환경에 기반하므로, 여러 터미널 창을 동시에 열어두고 작업하면 효율성을 크게 높일 수 있습니다.

### 표현 = 표준 용어

- **"Everything is a file"**: 모든 시스템 자원(하드웨어, 디렉터리 등)을 파일 시스템 내의 파일로 표현하는 유닉스/리눅스의 핵심 설계 철학.
- **`mv` (Move)**: 파일/디렉터리를 이동시키거나 이름을 변경하는 명령어.
- **`rm` (Remove)**: 파일/디렉터리를 영구적으로 삭제하는 명령어.
- **`rmdir` (Remove Directory)**: 비어 있는 디렉터리를 삭제하는 명령어.
- **`-i` (Interactive)**: `cp`, `mv`, `rm` 등에서 덮어쓰거나 삭제하기 전에 사용자에게 확인을 요청하는 옵션.
- **`-r` (Recursive)**: 디렉터리 대상 명령어(`cp`, `rm`)에서 해당 디렉터리뿐만 아니라 내부의 모든 하위 항목에 대해 작업을 반복 적용하는 옵션.
- **숨김 파일 (Hidden File)**: 파일명이 `.`으로 시작하여 `ls`와 같은 일반적인 목록 조회에서 숨겨지는 파일. 주로 설정 파일에 사용.

### 정석 보강 (canon-std)

**파일 및 디렉터리 삭제 (`rm`)**: `rm`은 파일을 영구적으로 제거하는 강력한 명령어입니다. 가장 중요한 점은 리눅스에는 기본적으로 '휴지통' 개념이 없어, `rm`으로 삭제된 파일은 복구가 매우 어렵다는 것입니다. 디렉터리와 그 내용을 재귀적으로 삭제하기 위해서는 `-r` 옵션이 필수이며, `-i` 옵션은 삭제 전 확인 과정을 거쳐 실수를 방지하는 안전장치 역할을 합니다. 특히 `rm -rf`는 확인 절차 없이 강제로 모든 것을 삭제하므로, 대상 경로를 명확히 확인하지 않고 사용할 경우 시스템에 치명적인 손상을 줄 수 있습니다.

### 실수·함정

- `rm` 명령어가 파일을 휴지통으로 옮길 것이라고 착각하는 것.
- `rm -r *` 와 같은 와일드카드 명령을 경로 확인 없이 실행하여 현재 디렉터리의 모든 것을 삭제하는 실수.
- `mv file1 file2` 실행 시, `file2`가 이미 존재한다면 `-i` 옵션 없이는 경고 없이 덮어쓰므로 데이터가 유실될 수 있습니다.
- 디렉터리 안에 내용이 있는데 `rmdir`로 삭제하려다 실패하는 경우. (이때 `rm -r`을 써야 함)
- 공장 초기화만 믿고 중고 저장장치(HDD, SSD, 휴대폰)를 판매하는 것. 전문적인 데이터 복구 툴로 개인정보가 복원될 수 있습니다.

그니까 컴퓨터는 루트디랙토리의 하나만 있는 아이노드번호를 알고있으니 루트 디렉토리의 데이터블록에 저장되어있는 루트 디랙토리 내의 파일의 아이노드번호랑 파일이름 매핑정보들을 조회해서 탐색해나가는거라는것 상대 경로는 .과 ..으로 아이노드번호를 아니 그걸 기준으로 탐색하는거래
파티션은 드라이브의 파티션을 말한다
(하나의 저장공간을 관리쉽게 논리적으로 나눈 관리 단위)
- 같은 파티션인경우: 디렉토리 엔트리만 수정
	- 데이터 블록, inode그대로 둔다
- 다른 파티션인경우: cp 후 rm
	- 새 **inode** 배정 + **데이터 블록 복제**⇒ 원본은 삭제(unlink)
- 인자여러개: 여러 파일 → **한 디렉터리**로만 이동하는 경우만 가능.

> **디렉토리 엔트리**: **파일 이름 ↔ inode 번호**의 매핑 정보, 파일 엔트리라고도 한다. **부모 디렉토리의 데이터 블록 내부**에 저장이된다
>
> inode 자체에는 이름이 없고, 이름은 반드시 “상위 디렉토리의 데이터 블록에 저장된 엔트리”를 통해서만 연결된다.
> 일반 파일의 데이터블록에는 사용자가 저장한 실제 데이터가 저장되는데, 특수한 파일인 폴더의 데이터블록에는 하위 항목들의 디렉토리 엔트리 목록을 저장한다( .과 ..도)
>
> 데이터 블록에는 유저가 매핑하지 않은 기본적인 2개의 매핑정보가있는데
> 자기 자신의 inode번호에 . 이라는 이름의 매핑,
> 부모 디렉토리의 inode번호에 ..이라는 이름의 매핑이다
> 그래서 다른 폴더로 이동하는것처럼 cd ..은 ..이름에 매핑된 부모로 이동하는거다
>
> 우리가 터미널에서 확인하는 폴더구조는 매핑된 파일 이름의 나열이다
>
> 예시, /B/c.txt 구조라면:
> - c.txt의 **inode**: 소유자/권한/타임스탬프와 **데이터 블록 포인터(내용물 위치)** 를 가짐. **이름은 없음.**
> - c.txt라는 **이름 매핑**: ** 디렉터리 B의 데이터 블록** 안에 ("c.txt" → inode#1234) 같은 **엔트리**로 존재.

---
### **3) 삭제 명령 세트**

- **rm file**: 디렉토리 **엔트리 제거(unlink)**
	- **rm -r dir**: 하위 디렉토리부터 디렉토리 엔트리를 하나씩 제거(강력·위험).
- **rmdir dir**: 해당 디렉토리 내부에 .와 .. 만 존재하는경우 디렉토리 엔트리 제거
- 리눅스 기본은 **휴지통 없음** → 실수 방지에 -i 적극 사용.

> 대상 파일의 이름과 Inode 번호를 잇는 디렉토리 엔트리를 제거한다-> 파일 이름이 사라져 사용자가 해당 파일에 접근할 수 없게된다
>
> Inode를 가리키는 이름이 더 이상 없다면, 파일 시스템은 해당 Inode와 연결된 **데이터 블록을 해제**하고 Inode를 '사용 가능' 상태로 만듭니다. 이 시점에 파일이 사실상 삭제됩니다.
>

## **2025-09-26, 3교시 — 질문**

**[Q1] `mv` 명령어로 파일을 이동할 때, 대상(destination)이 존재하지 않는 경우와 존재하는 디렉터리인 경우에 각각 어떻게 동작하나요? | 태그: 파일·디렉터리, 셸/리다이렉션/FD**

- **모범답(강의 기준)**: 대상 경로가 존재하지 않으면, 원본 파일 또는 디렉터리의 이름이 대상 경로의 이름으로 변경됩니다(이름 바꾸기). 대상 경로가 이미 존재하는 디렉터리면, 원본 파일 또는 디렉터리가 그 디렉터리 안으로 이동합니다.
- **정석체크(면접 30초)**: **전제**: `mv` 명령어는, **핵심 규칙**: 대상 경로의 존재 유무를 먼저 확인하여 동작을 결정합니다. 대상이 없으면 inode 정보에서 파일 이름만 변경(rename)하고, 대상이 디렉터리면 해당 디렉터리의 내용 목록에 파일의 inode 포인터를 추가(move)합니다.

**[Q2] 파일/디렉터리 삭제 시 `rm`, `rmdir`, `rm -i`, `rm -r`을 각각 어떤 상황에 사용해야 하며, 안전을 위해 가장 먼저 고려할 옵션은 무엇인가요? | 태그: 파일·디렉터리, 권한/UMASK/특수비트**

- **모범답(강의 기준)**: 비어있는 디렉터리는 `rmdir`, 파일은 `rm`으로 지웁니다. 안전을 위해 항상 `-i` 옵션을 붙여 삭제 전 확인하는 습관을 들여야 합니다. 디렉터리 안의 내용까지 전부 지워야 할 때만 신중하게 `rm -r`을 사용합니다.
- **정석체크(면접 30초)**: **전제**: 데이터 무결성을 위해, **핵심 규칙**: `rmdir`은 빈 디렉터리만, `rm`은 파일만 삭제하는 것을 원칙으로 합니다. `-i`는 실수를 방지하는 사용자 확인(interactive) 안전장치이며, `-r`은 디렉터리 트리를 재귀적으로 순회하며 모든 항목을 삭제하는 강력한 옵션이므로 사용에 각별한 주의가 필요합니다.

**[Q3] 리눅스에서 '모든 것은 파일'이라는 철학은 `cp`나 `mv` 같은 명령어 동작에 구체적으로 어떤 영향을 주나요? | 태그: 파일·디렉터리, 부팅/systemd**

- **모범답(강의 기준)**: 리눅스는 디렉터리도 파일의 일종으로 보기 때문에 파일 명령어의 동작이 일관성 있게 적용됩니다. 예를 들어, 존재하지 않는 파일(`file2`)에 복사하면 `file2`가 새로 생성되듯이, 존재하지 않는 디렉터리(`temp4`)로 `cp -r`을 실행하면 `temp4` 디렉터리가 파일처럼 먼저 생성되고 그 안으로 내용물이 복사됩니다.
- **정석체크(면접 30초)**: **전제**: 유닉스 계열 OS의 설계 원칙상, **핵심 규칙**: 디렉터리는 "파일들의 이름과 inode 번호 목록을 담고 있는" 특수 파일입니다. 따라서 `cp`와 같은 파일 유틸리티가 디렉터리를 생성하거나 조작할 수 있는 것은, 모든 것을 파일로 취급하는 일관된 시스템 처리 메커니즘 덕분입니다.

**[Q4] 시스템 설정 파일처럼 중요한 파일들이 `ls` 명령에 기본적으로 보이지 않는 이유는 무엇이며, 어떻게 확인할 수 있나요? | 태그: 파일·디렉터리, 권한/UMASK/특수비트**

- **모범답(강의 기준)**: 사용자가 실수로 중요한 시스템 설정 파일들을 삭제하거나 수정하는 것을 방지하기 위해 기본적으로 숨겨져 있습니다. `ls -a` 명령어를 사용하면 `.`으로 시작하는 숨김 처리된 모든 파일과 디렉터리를 확인할 수 있습니다.
- **정석체크(면접 30초)**: **전제**: 셸의 파일명 처리 관례상, **핵심 규칙**: `.`으로 시작하는 파일명은 "숨김" 속성으로 간주되어 `ls`나 와일드카드 확장(`*`) 시 기본적으로 제외됩니다. 이는 사용자의 작업 공간을 깔끔하게 유지하고 설정 파일의 의도치 않은 변경을 막기 위함이며, `-a` 옵션으로 명시적 조회가 가능합니다.

- **⚠️ 주의**: `rm -r` 옵션은 매우 강력하므로, 실제 사용 시에는 삭제할 디렉터리의 내용을 `ls`로 반드시 먼저 확인하는 습관을 들여야 합니다.
