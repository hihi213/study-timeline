# **파일 1 — 주관식 핵심 정리**

### **0) 사용법(1분)**

- 각 카드에서 **굵은 문장(정의·규칙)**만 우선 암기 → **전제/예외** 확인 → **빈칸 한 줄**로 자가점검.
- 주관식은 **정의 1문장 + 핵심어 2개**만 정확히 쓰면 대부분 득점.

## **[자료구조 정의·분류]**

- **정의(1문장)**: 자료구조는 데이터를 **효율적으로 저장·접근·수정**하기 위한 조직/형식이며, 선형(배열·리스트·스택·큐)과 비선형(트리·그래프)로 분류된다.
- 키워드(3): ▢ 효율성 ▢ 선형/비선형 ▢ 접근·수정
- 필요조건/전제: 문제의 요구(크기·변동성·접근패턴)에 맞춰 구조를 선택.
- 예외·함정: 힙을 “순서 큐”로 혼동(핵심은 **우선순위**).
- 핵심 아이디어(2문장): 메모리는 비트열이므로 해석의 틀(자료형/구조)이 필요하다. 구조 선택이 알고리즘의 복잡도를 사실상 결정한다.
- 유사개념 대비: **선형**=순차 나열 / **비선형**=관계·계층.
- 주관식 예상: “자료구조를 정의하고 분류하라.”, “선형과 비선형의 차이 2줄”.
- 빈칸: 자료구조 선택 기준은 **{{데이터 변동성·접근 패턴}}**이다.

## **[C 메모리 4영역]**

- **정의(1문장)**: 실행 시 메모리는 **코드/데이터/힙/스택** 영역으로 나뉘어 코드·정적데이터·동적할당·호출스택을 각각 저장한다.
- 키워드(3): ▢ 코드 ▢ 힙 ▢ 스택
- 필요조건/전제: 지역변수=스택, malloc=힙, 전역/정적=데이터.
- 예외·함정: 스택/힙 생명주기 혼동, register 변수는 주소 연산 불가.
- 핵심 아이디어(2문장): 인터럽트/호출 복귀는 스택의 LIFO로 관리된다. 동적 객체 수명은 프로그래머가 free로 통제한다.
- 유사개념 대비: **스택**=자동 수명 / **힙**=수동 수명.
- 주관식 예상: “PC(프로그램 카운터)와 스택의 관계”, “float a=3.14의 배치”.
- 빈칸: 인터럽트 복귀 주소는 **{{스택}}**에 push된다.

## **[배열 주소계산]**

- **정의(1문장)**: 배열은 **동일 타입 원소를 연속 메모리**에 저장하며 주소는 base + i*sizeof(T)로 산출된다.
- 키워드(3): ▢ 연속성 ▢ base/index 레지스터 ▢ O(1) 접근
- 필요조건/전제: 모든 원소 **동일 타입**.
- 예외·함정: C는 **경계검사 없음**→ UB, arr++ 불가(식별자).
- 핵심 아이디어(2문장): 하드웨어가 base/index로 주소를 즉시 계산하므로 임의 접근이 O(1)이다. 구조체 배열도 동일 원리다.
- 유사개념 대비: 개별변수 vs 배열(연속성 보장).
- 주관식 예상: “배열 O(1)인 이유”, “sizeof("abc")==4 이유”.
- 빈칸: 주소 공식은 **{{base + i*sizeof(element)}}**.

## **[구조체배열·문자열]**

- **정의(1문장)**: struct T arr[n]은 **T 객체 n개가 연속**된 블록이고, C 문자열은 마지막에 **널(’\0’)**을 가진다.
- 키워드(3): ▢ 구조체 배열 ▢ 널 종료 ▢ bounds 없음
- 필요조건/전제: 동일 타입, 초기화 부족분은 0 채움.
- 예외·함정: char[]에 = 대입 불가→ strcpy 사용.
- 핵심 아이디어(2문장): 배열 이름은 시작주소로 **디케이**하나 수정 불가. 문자열 길이는 '\0'로 판정한다.
- 유사개념 대비: 포인터 변수 vs 배열 식별자.
- 주관식 예상: “"abc" 크기가 4인 이유”, “구조체 배열 메모리 배치”.
- 빈칸: C 문자열 끝은 **{{’\0’}}** 로 표시한다.
- 출처: 2025-09-11 1교시 — 개념

## **[포인터 본질·타입]**

- **정의(1문장)**: 포인터는 **메모리 주소**를 값으로 가지며 **타입은 역참조 크기/해석**을 규정한다.
- 키워드(3): ▢ 주소 ▢ 역참조 ▢ 타입의미
- 필요조건/전제: 유효 주소 가리켜야 함.
- 예외·함정: 크기는 **아키텍처 고정(32b=4B, 64b=8B)**, 대상 크기와 무관.
- 핵심 아이디어(2문장): 자기참조 구조체로 동적 구조를 연결한다. void*는 범용 주소이며 사용 시 명시 캐스팅.
- 유사개념 대비: 값 vs 주소(참조).
- 주관식 예상: “포인터 타입이 왜 필요한가”, “포인터 크기와 대상 크기의 관계”.
- 빈칸: sizeof(int*)는 **{{대상 크기와 무관}}**하다.
- 출처: 2025-09-04 3교시 — 개념

## **[포인터 연산]**

- **정의(1문장)**: p+1은 주소를 1이 아닌 **sizeof(*p)****만큼** 이동하며 *p++는 *(p++)이다.
- 키워드(3): ▢ pointer arithmetic ▢ 우선순위 ▢ 상수포인터
- 필요조건/전제: 동일 타입 배열 구간에서 의미 있음.
- 예외·함정: *p++ vs (*p)++ 혼동 금지, arr++ 불가.
- 핵심 아이디어(2문장)**:** 타입이 곧 증분 단위다. 연산자 결합·우선순위로 의미가 바뀐다.
- 유사개념 대비: 상수 포인터(배열 이름) vs 포인터 변수.
- 주관식 예상: “p++가 4 증가하는 이유”, “*p++ 해석”.
- 빈칸: *p++는 **{{현재 값 역참조 후 p 증가}}**이다.

## **[자기참조·연결리스트]**

- **정의(1문장)**: 자기 참조 구조체는 **자신과 같은 타입의 포인터 멤버**로 다음 노드를 연결해 리스트·트리를 구성한다.
- 키워드(3): ▢ self-referential ▢ node ▢ link
- 필요조건/전제: malloc/free 동반, 유효 연결 유지.
- 예외·함정: 포인터 멤버는 **주소**이며 노드 자체가 아님.
- 핵심 아이디어(2문장)**:** 비연속 메모리를 논리적으로 연결해 가변 크기를 얻는다. 연산은 링크 갱신이 본질.
- 유사개념 대비: 배열(연속·고정) vs 리스트(비연속·가변).
- 주관식 예상: “왜 자기참조가 필요한가”, “노드 삭제 시 주의”.
- 빈칸: 리스트의 가변성은 **{{포인터 링크}}**로 얻는다.
- 출처: 2025-09-18 1교시 — 개념

## **[값·참조 호출]**

- **정의(1문장)**: C는 값 호출만 지원하지만 **포인터를 값으로 전달**해 참조 호출 효과를 낸다.
- 키워드(3): ▢ call by value ▢ pointer param ▢ swap
- 필요조건/전제: 원본 수정은 **주소 전달** 필수.
- 예외·함정: 큰 구조체 값 전달은 복사 오버헤드.
- 핵심 아이디어(2문장): swap(int*,int*)로 원본 교환. 주소는 작아 효율적이다.
- 유사개념 대비: 값 복사 vs 주소 전달.
- 주관식 예상: “값 호출로 swap 실패 이유”, “포인터 전달 원리”.
- 빈칸: 원본 수정을 위해서는 **{{주소를 전달}}**해야 한다.

## **[함수원형·argc/argv]**

- **정의(1문장)**: 함수 원형은 컴파일러에 **시그니처 선선언**이고, main(int argc,char* argv[])는 명령줄 인자 인터페이스다.
- 키워드(3): ▢ prototype ▢ argc ▢ argv
- 필요조건/전제: 호출 이전에 타입 검사 가능해야 함.
- 예외·함정: 표준 함수 원형은 헤더에 존재.
- 핵심 아이디어(2문장): 단일 패스 컴파일에서 원형이 타입 안정성을 보장. 인자 벡터는 프로그램 외부 설정을 전달.
- 유사개념 대비: 선언 vs 정의.
- 주관식 예상: “원형이 필요한 이유”, “argv[0] 의미”.
- 빈칸: argc는 **{{인자의 개수}}**를 뜻한다.
- 출처: 2025-09-11 3교시 — 개념

## **[다차원·Row-major]**

- **정의(1문장)**: C의 다차원 배열은 메모리에 **행 우선(Row-major)**으로 1차원 나열된다.
- 키워드(3): ▢ 2D=1D ▢ 오프셋 ▢ 내적 인덱스
- 필요조건/전제: 안쪽 차원 크기 명시 필요.
- 예외·함정: a[i][j]가 포인터 배열이라고 오인.
- 핵심 아이디어(2문장): 주소= base + (i*cols + j)*sizeof(T). 초기화 시 바깥 차원 생략 가능.
- 유사개념 대비: 포인터배열 vs 진 2차원 배열.
- 주관식 예상: “주소계산식”, “차원 생략 규칙”.
- 빈칸: C는 **{{Row-major}}** 순서로 저장한다.
- 출처: 2025-09-11 2교시 — 개념

## **[희소행렬 표현]**

- **정의(1문장)**: 희소 행렬은 0이 아닌 원소만 **(row,col,value)**로 저장해 공간을 **O(k)**로 줄인다.
- 키워드(3): ▢ sparse ▢ 구조체배열 ▢ O(k)
- 필요조건/전제: 0이 대부분인 경우 유리.
- 예외·함정: 접근/연산 복잡도 증가(탐색).
- 핵심 아이디어(2문장)**:** 메모리를 절약하되 접근은 선형/로그가 된다. 밀집 행렬에는 역효과.
- 유사개념 대비: Dense vs Sparse.
- 주관식 예상: “왜 O(k)인가”, “트레이드오프”.
- 빈칸: 희소 표현의 핵심 저장 단위는 **{{(행,열,값)}}**이다.
- 출처: 2025-09-11 2교시 — 개념

## **[동적할당·double-pointer]**

- **정의(1문장)**: malloc은 **힙**에 메모리를 할당해 void*를 돌려주며, 필요 시 (T*)로 캐스팅하고 free로 해제한다.
- 키워드(3): ▢ malloc/free ▢ NULL체크 ▢ 이중포인터
- 필요조건/전제: 실패 시 **NULL** 검사, 소유권 관리.
- 예외·함정: 해제 누락=메모리 누수, 해제 후 사용=dangling.
- 핵심 아이디어(2문장): 포인터 자체를 바꾸려면 **포인터의 주소**(double pointer)를 전달한다. 가비지 컬렉션이 없어 개발자가 책임.
- 유사개념 대비: 값 변경 vs 포인터 변경.
- 주관식 예상: “왜 double pointer가 필요한가”, “malloc 실패 처리”.
- 빈칸: 포인터 변수 자체를 바꾸려면 **{{포인터의 주소}}**가 필요하다.
- 출처: 2025-09-11 2교시 — 개념

## **[리스트 ADT 비교]**

- **정의(1문장)**: 배열 리스트는 **연속·고정**, 연결 리스트는 **비연속·가변**으로, 접근/삽입·삭제의 트레이드오프가 명확하다.
- 키워드(3): ▢ O(1) 접근 ▢ O(1) 삽입/삭제 ▢ 가변성
- 필요조건/전제: 탐색 빈도 vs 변동 빈도 고려.
- 예외·함정: 리스트 삽입 시 이동 방향(뒤→앞/앞→뒤) 착오.
- 핵심 아이디어(2문장): 배열은 임의 접근 빠름, 삽입/삭제 비쌈. 연결은 반대.
- 유사개념 대비: is_full/is_empty(배열) vs 동적 확장(연결).
- 주관식 예상: “언제 배열/연결이 유리한가”.
- 빈칸: 배열은 **{{임의 접근 O(1)}}**, 연결은 **{{삽입/삭제 O(1)}}**.
- 출처: 2025-09-18 2교시 — 개념

## **[단순연결 삽입·삭제]**

- **정의(1문장)**: 단순 연결 삽입은 new->link=prev->link; prev->link=new;, 삭제는 prev->link=del->link; free(del); 순서를 지킨다.
- 키워드(3): ▢ prev 필수 ▢ 순서보존 ▢ free
- 필요조건/전제: 선행 노드(prev) 확보.
- 예외·함정: 순서 역전→뒷부분 유실, head 갱신 누락.
- 핵심 아이디어(2문장): 연결 **먼저 만들고** 기존 연결을 끊는다. 빈 리스트/앞 삽입은 별도 처리.
- 유사개념 대비: 논리 삭제 vs 물리 해제.
- 주관식 예상: “삽입 2단계 순서”, “삭제 2단계와 메모리”.
- 빈칸: 삽입은 **{{연결을 먼저 만들고}}** 기존 링크를 바꾼다.
- 출처: 2025-09-18 3교시 — 개념

## **[원형연결·헤드=tail]**

- **정의(1문장)**: 원형 리스트는 마지막 노드가 첫 노드를 가리키며, 헤드가 **마지막 노드**를 가리키면 head와 head->link로 양 끝 O(1) 접근이 가능하다.
- 키워드(3): ▢ 순환 ▢ tail-head ▢ O(1) 끝삽입
- 필요조건/전제: 순회 종료 조건 필요(무한루프 방지).
- 예외·함정: 이전 노드 탐색은 여전히 O(n).
- 핵심 아이디어(2문장): 임의 시작점에서 전 노드 탐색 없이 전체 순회 가능. 끝 삽입 성능 개선.
- 유사개념 대비: 일반 단순 연결 vs 원형.
- 주관식 예상: “head→tail 기법의 장점”, “원형 순회 종료 조건”.
- 빈칸: 첫 노드 접근은 **{{head->link}}** 로 한다.
- 출처: 2025-10-02 1교시 — 개념

## **[이중연결·더미노드]**

- **정의(1문장)**: 이중 연결은 prev/next 양방향 링크를 가지며, **원형+더미(헤드) 노드**를 쓰면 모든 연산을 **일반화**하고 경계 처리를 제거한다.
- 키워드(3): ▢ prev/next ▢ sentinel ▢ invariant
- 필요조건/전제: 정상 상태에서 p->next->prev==p 성립.
- 예외·함정: 4개 포인터 갱신 순서 오류, 빈 리스트 판정(head->next==head).
- 핵심 아이디어(2문장): 더미 노드로 “맨 앞/뒤/빈 리스트” 예외를 통합한다. 삽입은 기존 이웃을 먼저 연결한 뒤 기준 노드를 갱신.
- 유사개념 대비: 헤드 **포인터** vs 헤드 **노드**.
- 주관식 예상: “왜 더미 노드가 유리한가”, “불변식 1개 제시”.
- 빈칸: 빈 리스트는 **{{head->next==head}}** 로 판정한다.
- 출처: 2025-10-02 2교시 — 개념

## **[트리·이진트리]**

- **정의(1문장)**: 트리는 계층 관계 비선형 구조이며, **이진 트리**는 각 노드가 최대 두 자식(좌/우)을 갖는 표준화된 형태다.
- 키워드(3): ▢ 루트/리프 ▢ 높이 ▢ 서브트리
- 필요조건/전제: 이진은 서브트리도 이진.
- 예외·함정: 완전 vs 포화 혼동, 배열 구현의 낭비(편향).
- 핵심 아이디어(2문장): 배열 구현은 완전 트리에 유리(부모/자식 인덱스). 연결 구현은 일반적이고 유연.
- 유사개념 대비: 포화(모든 레벨 만석) vs 완전(마지막만 좌→우 채움).
- 주관식 예상: “배열 인덱스 규칙”, “완전/포화 차이”.
- 빈칸: 배열 구현에서 왼쪽 자식 인덱스는 **{{2*i}}** 이다.
- 출처: 2025-10-02 3교시 — 개념

## **[정렬 총론]**

- **정의(1문장)**: 정렬은 **키** 기준으로 순서를 부여하는 작업이며, 내부/외부·비교/분배·안정성/제자리성 기준으로 분류된다.
- 키워드(3): ▢ 키 ▢ 안정성 ▢ in-place
- 필요조건/전제: 데이터 특성·규모에 맞는 선택.
- 예외·함정: “항상 최적 정렬은 없다”, 편향 입력의 worst-case.
- 핵심 아이디어(2문장): 시간은 비교·이동 횟수로 측정한다. 분할정복·버킷·힙 등 패턴 이해가 핵심.
- 유사개념 대비: 내부 vs 외부, 비교식 vs 분산식.
- 주관식 예상: “외부 정렬 정의”, “안정/제자리 의미”.
- 빈칸: 외부 정렬은 **{{보조기억장치}}**를 활용한다.
- 출처: 2025-10-16 1교시 — 개념

## **[선택정렬]**

- **정의(1문장)**: 매 패스마다 **최솟값을 선택**해 현재 위치와 **한 번 교환**하는 O(n²) **불안정** 정렬이다.
- 키워드(3): ▢ selection ▢ 한 번 swap ▢ 불안정
- 필요조건/전제: 항상 n(n-1)/2 비교.
- 예외·함정: 이미 정렬되어도 O(n²), 중복값 순서 깨짐.
- 핵심 아이디어(2문장): 비교는 많지만 교환은 적다. 단순·제자리라 교육용/소규모에 적합.
- 유사개념 대비: 버블(인접다교환) vs 선택(패스당 1교환).
- 주관식 예상: “왜 불안정인가?”, “비교/교환 횟수”.
- 빈칸: 선택정렬은 **{{패스당 최대 1회}}** 교환한다.
- 출처: 2025-10-16 1교시 — 개념

## **[삽입정렬]**

- **정의(1문장)**: 정렬된 부분에 **키를 끼워 넣기** 위해 큰 원소들을 **오른쪽으로 이동**시키는 안정적 O(n²) 정렬이며 **최선 O(n)**을 가진다.
- 키워드(3): ▢ shift ▢ stable ▢ best O(n)
- 필요조건/전제: key 임시 보관, 뒤에서 앞으로 비교.
- 예외·함정: swap로 구현해 비효율, key 유실.
- 핵심 아이디어(2문장): 거의 정렬된 데이터에 매우 강하다. 이동 중심이라 교환 비용이 낮다.
- 유사개념 대비: 선택(탐색+1교환) vs 삽입(이동 중심).
- 주관식 예상: “왜 최선 O(n)인가”, “shift의 역할”.
- 빈칸: 이미 정렬이면 각 원소는 **{{한 번 비교}}**만 한다.
- 출처: 2025-10-16 2교시 — 개념

## **[버블정렬]**

- **정의(1문장)**: 인접 원소를 반복 비교·교환하여 큰 값이 뒤로 **떠오르는** 가장 단순한 O(n²) **안정** 정렬이다.
- 키워드(3): ▢ adjacent swap ▢ pass ▢ 안정
- 필요조건/전제: 조기종료 최적화 가능(교환 없음).
- 예외·함정: 실무 비권장(느림), 범위 설정 오류.
- 핵심 아이디어(2문장): 구현이 가장 쉬워 교육용으로 적합. 인접 비교만 수행한다.
- 유사개념 대비: 선택(패스1교환) vs 버블(빈번교환).
- 주관식 예상: “왜 항상 O(n²)로 보는가”, “조기종료 조건”.
- 빈칸: 버블은 **{{인접 원소}}**만 비교/교환한다.
- 출처: 2025-10-16 2교시 — 개념

## **[쉘정렬]**

- **정의(1문장)**: 삽입정렬을 **간격(gap)**으로 일반화해 멀리 떨어진 원소를 먼저 정렬, 간격을 줄여가며 최종 간격 1에서 빠르게 마무리하는 **불안정** 정렬이다.
- 키워드(3): ▢ gap sequence ▢ 부분리스트 삽입 ▢ O(n^1.5±)
- 필요조건/전제: 간격 수열 선택이 성능 좌우.
- 예외·함정: 부분리스트를 연속 블록으로 오해.
- 핵심 아이디어(2문장): 큰 이동을 먼저 수행해 무질서를 급감시킨다. 평균은 O(n²)보다 훨씬 낮다.
- 유사개념 대비: 삽입(간격1) vs 쉘(감소 간격).
- 주관식 예상: “gap의 역할”, “불안정 이유”.
- 빈칸: 쉘정렬의 핵심은 **{{간격을 줄이며 반복}}**이다.

## **3) 문항은행 — 객관식 20문항 (각 1분)**

> 형식: **문항 → 보기 A–D → 정답/근거/함정**

**Q1.** float a = 3.14; 실행 시 적합한 매핑은?
A) 코드:3.14, 데이터:기계어, 스택:a
B) 코드:기계어, 데이터:3.14, 스택:a
C) 코드:a, 힙:3.14, 데이터:없음

## **4) 문항은행 — 주관식 10문항 (각 1분, 키워드 채점)**

> 형식: **문항 → 기대 답안 핵심 → 채점 키워드**

**S1.** C의 **Call by Value**와 **Call by Reference(효과)** 차이, swap 예로 설명.

- 기대 답안: C는 값 전달만 지원, **주소(포인터)를 값으로** 넘기면 원본 수정 가능. swap(int*a,int*b)는 주소로 접근하여 교환.
- 키워드: “값 복사”, “주소 전달”, “원본 수정”.

**S2.** 배열 인덱스 주소 공식과 CPU 베이스/인덱스 레지스터의 역할.

- 기대 답안: addr(a[i]) = base + i*sizeof(T). 베이스=시작주소, 인덱스=오프셋, 하드웨어가 **O(1)** 계산.
- 키워드: base, index, sizeof.

**S3.** **헤드 포인터** vs **헤드 노드(더미)** 차이.

- 기대 답안: 포인터는 “주소를 담는 변수”, 더미는 “실제 노드(데이터 없음)”로 경계 처리를 단순화. 빈 리스트 판정은 head->next\==head.
- 키워드: “주소 변수”, “센티넬”, “경계 제거”.

**S4.** 단순 연결 리스트 **중간 삽입** 2단계 순서.

- 기대 답안: new->next = prev->next; prev->next = new;(기존 연결 먼저 확보).
- 키워드: “연결 먼저”, “덮어쓰기 방지”.

**S5.** **원형 이중 연결 리스트의 ‘원형’ 의미**와 핵심 불변식 2개.

- 기대 답안: 마지막과 첫 노드가 **양방향**으로 연결. 임의 노드 p에 대해 p->prev->next==p, p->next->prev==p.
- 키워드: “마지막↔첫”, “prev/next 대칭”.

**S6.** struct card deck[10]; 의미와 struct card *p=deck;에서 포인터 크기 설명.

- 기대 답안: 구조체 10개가 **연속** 저장. 포인터 크기는 **주소 크기(아키텍처 의존)**, 구조체 크기와 무관.
- 키워드: “연속”, “주소 크기”, “무관”.

**S7.** 함수 원형(프로토타입)과 #include <stdio.h>의 관계.

- 기대 답안: 호출 전에 시그니처 알려 타입 검사. stdio.h는 printf 등 **프로토타입 선언** 제공.
- 키워드: “선언”, “시그니처”, “검사”.

**S8.** main의 return 0;의 의미.

- 기대 답안: OS로 **종료 코드(0=성공)** 반환, 스크립트/부모 프로세스가 활용.
- 키워드: “종료 코드”, “성공/실패”.

**S9.** 왜 어떤 함수는 헤드 포인터를 **이중 포인터(Node **)**로 받는가?

- 기대 답안: **포인터 자체를 변경**해야(맨 앞 삽입/삭제) 호출자 변수 갱신 가능.
- 키워드: “포인터의 주소”, “원본 포인터 수정”.

**S10.** 연결 리스트 기반 **다항식 덧셈** 절차.

- 기대 답안: 두 포인터로 지수 비교(>,<,=)하며 큰 지수 먼저, 같으면 계수 합; 한쪽 끝나면 나머지 **붙이기**.
- 키워드: “지수 비교”, “병합형”, “잔여 붙이기”.

## **5) 원형이중 연결리스트 핵심 정리(교재형 요약)**

- **정의**: 각 노드가 prev/next를 가져 양방향 연결되며, **마지막의 next가 첫 노드**, **첫 노드의 prev가 마지막**을 가리키는 구조.
- **더미(헤드) 노드**를 두면 빈 리스트도 head->next\==head && head->preV\==head가 되어 **모든 연산을 ‘두 노드 사이’로 통일**.
- **불변식**: 임의의 p에 대해 p->prev->next\==p, p->next->prev\==p.
- **주의**: “헤드 포인터가 마지막 노드를 가리키면 원형”이 **아님**. 그것은 **원형 단순 리스트**에서 편의를 위한 한 구현. **원형성은 연결 자체**의 성질.

2. 배열이름: 비수정 lvalue ⇒ arr++/대입 불가

6. 배열 큐는 **원형 큐**로
7. 원형·이중+더미: 빈 리스트 head->next==head
