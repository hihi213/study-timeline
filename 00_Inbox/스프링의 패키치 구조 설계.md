# **스프링 도메인형(기능 기준) 폴더 구조 — Obsidian 정리**

> [!summary] TL;DR

> **규칙은 안쪽(도메인), 기술은 바깥(어댑터)**.

> 요청 흐름은 **API(in) → Application → Domain → (Port) → Adapter(out)**.

> Application은 **트랜잭션 경계 + 오케스트레이션**, Domain은 **규칙/상태/행위**, Adapter는 **기술 구현**.

---

## **00. 폴더 트리**

```
com.example
 ├─ order
 │   ├─ domain
 │   │   ├─ Order.java                // 애그리거트 루트
 │   │   ├─ OrderLine.java            // 엔티티/값 객체
 │   │   ├─ OrderId.java              // 값 객체(식별자)
 │   │   ├─ OrderRepository.java      // 도메인 인터페이스(포트)
 │   │   └─ OrderPlaced.java          // 도메인 이벤트
 │   ├─ application
 │   │   └─ PlaceOrderService.java    // 유스케이스(트랜잭션, 도메인 조립)
 │   ├─ adapter
 │   │   ├─ in
 │   │   │   └─ web
 │   │   │       └─ OrderController.java // 인바운드 어댑터(REST/GraphQL 등)
 │   │   └─ out
 │   │       └─ jpa
 │   │           └─ JpaOrderRepository.java // 포트 구현(JPA)
 │   └─ config                            // (선택) 스프링 설정/빈 구성
 └─ book
     ├─ domain
     ├─ application
     ├─ adapter
     └─ config
```

---

## **01. 의존 규칙**

- **domain → (없음)**
- **application → domain**
- **adapter/out(인프라) → domain** (도메인 포트 **구현**)
- **adapter/in(API) → application** (+ DTO 매핑/검증)

> [!tip] 규칙

> 역방향 의존 금지. **도메인은 어떤 기술에도 의존하지 않는다.**

---

## **02. 레이어 역할**

### **[[Domain]]**

- **규칙·상태·행위** + **포트(인터페이스)** 선언
- 엔티티/값 객체/도메인 서비스/도메인 이벤트/애그리거트
- 의미 있는 행위 메서드(예: order.cancel()), **리포지토리 인터페이스만** 보유

### **[[Application]]**

- **유스케이스 실행자**: 트랜잭션 경계 + 도메인 객체/리포지토리 **오케스트레이션**
- **비즈니스 규칙은 두지 않음**(규칙은 도메인으로)

### **[[Adapter In (API)]]**

- HTTP/메시지 인바운드: **입력 검증(@Valid), DTO 매핑, 서비스 호출, 응답 DTO 변환**
- **엔티티를 직접 다루지 않음**, 규칙 두지 않음

### **[[Adapter Out (Infra)]]**

- 도메인 포트 **구현체**(JPA/MyBatis/메시징/외부 API)
- 영속성·통신 등 **구체 기술** 접착 계층

---

## **03. 도메인 모델 구성요소**

- **엔티티(Entity)**: 식별자(@Id)로 구분되는 **도메인 규칙의 주체**(상태+행위). @Entity
- **값 객체(Value/임베디드)**: **값 동등성**, 대개 **불변**. @Embeddable / @Embedded
- **도메인 서비스**: 한 엔티티에 넣기 애매한 **순수 비즈니스 연산**
- **도메인 이벤트**: “주문완료됨(OrderPlaced)” 같은 **비즈니스 사건**
- **리포지토리(포트)**: 애그리거트 단위 **영속화 계약**(인터페이스). 구현은 어댑터(out)
- **DTO**: **계층 경계 전달용**(검증/직렬화). 비즈니스 로직·영속성 X
- **스프링 빈**: IoC 관리 컴포넌트(@Service/@Component/@Repository). **기본 싱글톤 → 상태 없음 권장**
- **Model**(스프링 MVC): addAttribute()로 **DTO 등 데이터를 담아** 뷰/응답으로 전달하는 운반 도구

## **04. 비교 표**

|**구분**|**엔티티 (Entity)**|**스프링 빈 (Bean)**|**DTO**|**값 객체 (Value/임베디드)**|
|---|---|---|---|---|
|**목적**|DB에 저장되는 **도메인 모델**(규칙·상태·행위)|**유스케이스/인프라 조립·조정**|**계층 경계 데이터 전달**|**개념적 값**(주소/기간/돈 등)|
|**관리 주체**|**JPA/영속성 컨텍스트**|**Spring IoC 컨테이너**|컨트롤러/매퍼|엔티티에 **내장(JPA가 함께 관리)**|
|**저장 위치**|**DB Row**|메모리(컨테이너)|HTTP/메시지/뷰모델|**엔티티 테이블 컬럼**|
|**식별/동등성**|@Id 동일성(보통 ID 기반 equals/hashCode)|빈 이름/타입|**값 동등성**|**값 동등성**, **불변 권장**|
|**생성/관리**|JPA가 생성/프록시, 기본 생성자 필요|스프링 생성·주입(DI)|수동 생성/매핑|엔티티가 포함해 생성(생성자/팩토리)|
|**생명주기**|트랜잭션/영속성 컨텍스트 경계|앱 시작~종료(**싱글톤**)|요청/응답 단발|**소유 엔티티 생명주기** 종속|
|**스레드**|개별 인스턴스: 스레드-세이프 보장 없음|**싱글톤 → 상태 없음** 설계|공유 안 함|**불변이면 안전**|
|**대표 애노테이션**|@Entity, @Id, @Table|@Component, @Service, @Repository|(검증용 @NotNull 등)|@Embeddable / 필드에 @Embedded|
|**책임**|**도메인 규칙/상태/행위**|**오케스트레이션/유스케이스/인프라**|**표현·전달·검증**|**개념·불변성·자기 검증**|

## **05. 요청 흐름(회원가입 유스케이스)**

> [!example] 시나리오 개요

1. > **GET /members/new**: 빈 **Form DTO**를 뷰로 전달
2. > **POST /members**: 요청 DTO 검증 → **서비스 register() 호출**
3. > **Application**: @Transactional 시작 → **Member.create(...)**로 엔티티 생성/검증 → **리포지토리** 저장 → (선택) **도메인 이벤트 발행**
4. > **Infra(JPA)**: INSERT, 커밋
5. > **Controller**: **Response DTO**로 응답/리다이렉트

```
sequenceDiagram
    participant U as User
    participant C as Controller(API in)
    participant A as Application(Service)
    participant D as Domain
    participant O as Adapter Out(JPA)

    U->>C: POST /members (Request DTO, @Valid)
    C->>A: register(requestDto)
    A->>D: Member.create(...)
    A->>O: MemberRepository.save(member) // Port 구현 호출
    O-->>A: saved member
    A-->>C: result (Response DTO)
    C-->>U: 201 Created / Redirect
```

> [!tip] 원칙

> 컨트롤러는 **DTO만 다룬다**.

> 엔티티 생성/검증은 **도메인(정적 팩토리/메서드)**.

> 트랜잭션 경계는 **Application**.

---

## **06. 용어 정리(간단 요약)**

- **Use Case**: “회원가입/주문생성/비번재설정” 같은 **업무 목표 단위**
- **Application**: **Use Case 실행자**(트랜잭션 + 오케스트레이션)
- **Presentation**: **입·출력/검증/바인딩/예외→HTTP 변환**
- **영속성 컨텍스트(JPA)**: 1차 캐시/변경 감지/flush/commit 로 **SQL 생성·반영**

---

## **07. 설계 체크리스트**

- 도메인 모듈에서 **외부 프레임워크 의존 제거**(JPA 애노테이션 최소화 또는 도메인 순수성 유지)
- **리포지토리 인터페이스**는 도메인에, **구현**은 어댑터(out)에
- **DTO↔엔티티** 매핑은 **API(in)** 또는 **Application** 경계에서 수행
- **도메인 규칙**은 엔티티/도메인 서비스에 위치(애플리케이션에 두지 않음)
- **서비스 메서드 = 유스케이스 이름**으로 명확히 표현(register, placeOrder, …)
- @Transactional은 **Application 서비스**(쓰기) 중심에 배치
- **도메인 이벤트**로 후속 작업(알림/쿠폰/적립금) 비동기 분리

---

## **08. 안티패턴(Do/Don’t)**

- ❌ 컨트롤러에서 **엔티티 직접 조작/검증**
- ❌ Application에 **비즈니스 규칙** 두기
- ❌ 도메인이 **구체 기술(JPA, MQ, 외부 API)**에 의존
- ❌ 리포지토리 구현체를 **도메인에 배치**
- ✅ **의미 메서드**로 도메인 행위 노출(cancel, changeAddress, applyCoupon)

---

## **09. 기억 포인트(요약)**

- **엔티티** = 비즈니스 규칙의 **주체**
- **빈** = **오케스트레이터**(싱글톤, 상태 없음)
- **DTO** = **전달/검증용**(로직 X, 영속 X)
- **값 객체** = **불변·값 동등성**, 엔티티에 **내장**

## **10. 빠른 스타터(템플릿 스니펫)**

> [!abstract] Port (Domain)

```
// domain/OrderRepository.java
public interface OrderRepository {
    Order save(Order order);
    Optional<Order> findById(OrderId id);
}
```

> [!note] Use Case (Application)

```
@Service
@Transactional
public class PlaceOrderService {
    private final OrderRepository orders;
    public OrderId handle(PlaceOrderCommand cmd) {
        Order order = Order.create(cmd.customerId(), cmd.lines());
        orders.save(order);
        order.registerEvent(new OrderPlaced(order.getId()));
        return order.getId();
    }
}
```

> [!info] Inbound Adapter (API)

```
@RestController
@RequestMapping("/orders")
public class OrderController {
  private final PlaceOrderService placeOrder;
  @PostMapping
  public ResponseEntity<OrderResponse> place(@Valid @RequestBody PlaceOrderRequest req){
    OrderId id = placeOrder.handle(req.toCommand());
    return ResponseEntity.created(URI.create("/orders/"+id)).build();
  }
}
```

> [!success] Outbound Adapter (Infra/JPA)

```
@Repository
class JpaOrderRepository implements OrderRepository {
  private final SpringDataOrderJpa jpa; // extends JpaRepository<OrderJpaEntity, Long>
  @Override public Order save(Order order){ /* 매핑 & 저장 */ return order; }
  @Override public Optional<Order> findById(OrderId id){ /* 조회 */ }
}
```
