## Step 2. 기본 보안 프로시저 작성 (Masking) - DB보안 1교시_2025.10.27

### 1) 🎯 Goal

- 사용자 ID를 입력받아 **이름의 첫 글자만 노출하고 나머지는 마스킹(`*` or `00`)** 처리하며, 출생년도를 함께 출력하는 프로시저(`proc_secure_user`)를 생성한다.
    

### 2) ✅ Preconditions / Setup

- `SET SERVEROUTPUT ON`: DBMS_OUTPUT 결과를 화면에 출력하기 위해 필수.
    

### 3) 🧱 Build Log

- **%TYPE 사용**: `userTBL.userName%TYPE` 형식을 사용하여 테이블 스키마 변경 시 프로시저 수정 소요를 최소화한다. (시험 출제 포인트)
- **SUBSTR & Concatenation**: `SUBSTR(변수, 1, 1)`로 성만 추출하고, `||` 연산자로 마스킹 문자(`'00'`)를 결합한다.
- **IN/OUT 파라미터**: 입력값(`p_id`)을 받아 내부 로직 처리 후 출력.
- **Slash(/)**: 워크시트에서 PL/SQL 블록의 종료 및 컴파일 실행을 알리는 구분자.
    

### 4) 💻 Commands / SQL



```SQL
-- 접속: APP_USER
SET SERVEROUTPUT ON;

CREATE OR REPLACE PROCEDURE proc_secure_user(
    p_id IN userTBL.userID%TYPE -- 입력받을 ID (참조 타입 사용)
)
IS
    -- 내부 변수 선언 (%TYPE 활용)
    v_name userTBL.userName%TYPE;
    v_year userTBL.birthYear%TYPE;
BEGIN
    -- ID로 조회하여 이름과 생년을 변수에 할당
    SELECT userName, birthYear
    INTO v_name, v_year
    FROM userTBL
    WHERE userID = p_id;

    -- 마스킹 및 출력 로직
    -- 예: '이승기' -> '이00', 생년 출력
    DBMS_OUTPUT.PUT_LINE('이름: ' || SUBSTR(v_name, 1, 1) || '00'); 
    DBMS_OUTPUT.PUT_LINE('생년: ' || v_year);
    
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('해당 ID의 사용자가 없습니다.');
END;
/
-- 슬래시(/)는 PL/SQL 컴파일 실행 명령
```

### 5) 🔎 Verify

- 컴파일 완료 메시지 확인: `Procedure PROC_SECURE_USER compiled`
    

### 6) ⚠️ Pitfalls

- **`%TYPE` 미사용**: `VARCHAR2(10)` 등으로 하드코딩 시, 원본 테이블 컬럼 크기가 늘어나면 에러 발생 가능성 있음.
- **문자열 연결(`||`)**: SQL Server(`+`)와 다름. 오라클은 파이프(`||`) 사용. 강의 중 "엔 퍼센트", "오아"라고 언급된 부분은 이 연결 연산자를 의미함.
    

### 7) 💡 Interview (0~2)

> [!faq]- Q. PL/SQL에서 %TYPE을 사용하는 이유는 무엇인가?
>
> 🗣️ 핵심 답변
>
> %TYPE은 특정 테이블 컬럼의 데이터 타입을 그대로 참조하는 키워드입니다. 이를 사용하면 테이블 스키마(컬럼 크기나 타입)가 변경되더라도 프로시저 코드를 수정할 필요가 없어 유지보수성과 코드 안정성이 높아집니다.
>
> **📚 꼬리질문 대비**
>
> - **Ex**: `v_name userTBL.userName%TYPE`
>     
> - **Diff**: `%ROWTYPE`은 로우(행) 전체 구조를 참조할 때 사용합니다.
>

## Step 4. 소스 코드 보호 (Wrapping) - DB보안 1교시_2025.10.27

### 1) 🎯 Goal

- 관리자나 다른 개발자가 `USER_SOURCE`를 조회했을 때, **비즈니스 로직(마스킹 방식 등)이 보이지 않도록 프로시저 소스 코드를 암호화(Wrapping)**하여 재생성한다.
    

### 2) ✅ Preconditions / Setup

- `DBMS_DDL` 패키지 사용 권한 필요 (일반적으로 기본 제공).
- 기존 프로시저 삭제 (`DROP`) 후 재생성 방식 사용.
    

### 3) 🧱 Build Log

- **필요성**: 보안 프로시저의 내부 로직(어떻게 암호화하는지) 자체가 노출되면 보안 의미가 퇴색됨.
- **Dynamic SQL**: 소스 코드 전체를 문자열(`VARCHAR2`) 변수에 담는다. 따옴표(`'`) 처리에 주의(Quote quoting).
- **DBMS_DDL.CREATE_WRAPPED**: 입력된 PL/SQL 소스 문자열을 암호화된 형태로 컴파일하여 DB에 생성한다. (강의에서는 `EXECUTE IMMEDIATE` 맥락과 혼용 설명했으나, 핵심은 `CREATE_WRAPPED` 기능).
    

### 4) 💻 Commands / SQL

```SQL
-- 기존 일반 프로시저 삭제
DROP PROCEDURE proc_secure_user;

-- 익명 블록을 사용하여 암호화된 프로시저 생성
DECLARE
    v_source VARCHAR2(32767);
BEGIN
    -- 소스 코드를 문자열로 구성 (줄바꿈 및 따옴표 주의)
    v_source := 'CREATE OR REPLACE PROCEDURE proc_secure_user(p_id IN userTBL.userID%TYPE) IS ' ||
                '  v_name userTBL.userName%TYPE; ' ||
                '  v_year userTBL.birthYear%TYPE; ' ||
                'BEGIN ' ||
                '  SELECT userName, birthYear INTO v_name, v_year ' ||
                '  FROM userTBL WHERE userID = p_id; ' ||
                '  DBMS_OUTPUT.PUT_LINE(''이름: '' || SUBSTR(v_name, 1, 1) || ''00''); ' ||
                '  DBMS_OUTPUT.PUT_LINE(''생년: '' || v_year); ' ||
                'END;';

    -- 암호화하여 생성 (WRAP)
    SYS.DBMS_DDL.CREATE_WRAPPED(v_source);
END;
/
```

### 5) 🔎 Verify (검증)

- 생성된 프로시저가 정상 동작하는지, 그리고 소스 코드가 암호화되었는지 확인.
    

```SQL
-- 1. 기능 동작 확인
EXEC proc_secure_user('LSG'); 
-- 결과: 이름: 이00 … (정상 동작)

-- 2. 소스 코드 암호화 확인 (중요)
SELECT text 
FROM USER_SOURCE 
WHERE name = 'PROC_SECURE_USER'
ORDER BY line;
-- 결과: wrapped … (알 수 없는 16진수/암호문으로 표시됨)
```

### 6) ⚠️ Pitfalls

- **Quoting Error**: 소스 코드 내부에 작은따옴표(`'`)가 들어갈 경우, 문자열 리터럴 안에서는 `''` (따옴표 2개)로 이스케이프 처리해야 함. (예: `DBMS_OUTPUT` 부분).
- **길이 제한**: `VARCHAR2`는 PL/SQL에서 최대 32KB. 소스가 매우 길면 `CLOB`을 사용하거나 `DBMS_SQL`을 써야 함.
    

### 7) 💡 Interview (0~2)

> [!faq]- Q. DB에서 소스 코드 Wrapping(Obfuscation)은 왜 필요한가?
>
> 🗣️ 핵심 답변
>
> 지적 재산권 보호와 보안 로직 은폐를 위해서입니다. 솔루션 개발사의 경우 핵심 알고리즘 유출을 막기 위해 사용하며, 보안 측면에서는 공격자가 데이터 마스킹 방식이나 암호화 키 생성 로직을 파악하지 못하도록 소스 코드를 읽을 수 없는 형태로 변환하여 저장합니다.

## **기타 핵심 (Etc & Tips) - DB보안 2025.10.27**

### **🧩 Residual Knowledge**

- **`USER_SOURCE` (Data Dictionary)**: 사용자가 생성한 프로시저, 함수, 패키지 등의 소스 코드가 저장되는 시스템 뷰(Catalog).
    - `WRAP` 처리 전: `TEXT` 컬럼에 원본 소스가 그대로 노출됨 (보안 취약).
    - `WRAP` 처리 후: `TEXT` 컬럼에 암호화된 16진수 형태의 문자열이 저장됨.
- **`DBMS_DDL.CREATE_WRAPPED`**: PL/SQL 코드를 동적으로 생성하면서 동시에 암호화(Wrapping)하는 오라클 내장 패키지.
    - 과거에는 OS 터미널에서 `wrap` 유틸리티(exe)를 썼으나, DB 내부에서 바로 처리할 때 유용함.
- **연결 연산자(`||`) 발음 주의**:
    - 강의 중 교수님이 "엔 퍼센트", "오아(OR)" 등으로 지칭한 부분은 SQL의 문자열 연결 연산자인 파이프(`||`)를 의미함. (실제 코드 문맥상 Concatenation).

## **최종 요약 - DB보안 2025.10.27**

### **1) 하루 TL;DR**

중간고사 이후 첫 수업으로, 기존에 배운 **PL/SQL 프로시저** 문법을 **DB 보안(Data Masking)**에 적용하는 실습을 진행함. 회원 테이블(`userTBL`)을 생성하고, 개인정보(이름)를 가리는 마스킹 프로시저를 작성함. 특히, 작성된 프로시저의 로직 자체가 노출되지 않도록 **`DBMS_DDL`을 이용해 소스 코드를 암호화(Wrapping)**하는 기법을 핵심적으로 다룸.

### **2) 🔥 핵심 Workflow 요약**

- **Step 1) 실습 환경 구축**: `userTBL` 생성 및 더미 데이터 10건 적재 (기반 데이터 마련).
- **Step 2) 마스킹 프로시저 작성**: `SUBSTR`과 `||`를 사용해 이름 일부를 '00'으로 치환하는 로직 구현. (`%TYPE` 활용 강조).
- **Step 3) 실행 및 검증**: `EXEC` 명령어로 프로시저 실행, `SERVEROUTPUT`으로 마스킹 된 결과 확인.
- **Step 4) 소스 코드 보호(Wrapping)**: `DBMS_DDL.CREATE_WRAPPED`를 사용해 프로시저 소스 자체를 암호화하여 재생성 (정보 은폐).
    

### **3) 💻 SQL Cheatsheet**

|**명령/객체**|**핵심 포인트**|**용도**|
|---|---|---|
|**`%TYPE`**|`Table.Column%TYPE`|컬럼 타입 참조 (유지보수성↑)|
|**`||`**|
|**`DBMS_DDL`**|`CREATE_WRAPPED`|프로시저 소스 코드 암호화|
|**`USER_SOURCE`**|`SELECT text …`|소스 코드 노출/암호화 여부 확인|
|**`/` (Slash)**|블록 종료 및 실행|워크시트에서 PL/SQL 컴파일|

### **4) ⚠️ 오늘의 함정 Top**

1. **동적 SQL 내 따옴표 처리**: `CREATE_WRAPPED`에 전달할 SQL 문자열 내부의 작은따옴표(`'`)는 반드시 `''`로 이스케이프 해야 함. (가장 빈번한 에러)
2. **연산자 혼동**: 강의 중 언급된 "오아/엔퍼센트"는 논리연산자가 아니라 연결 연산자(`||`)임.
