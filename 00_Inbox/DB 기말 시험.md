### **[문제 1] O/X 퀴즈 및 오답 수정 (약 20점)**

- **형식:** 문장이 맞는지 틀린지 판별(True/False)하고, **틀린 문장은 반드시 올바르게 수정**해야 함.
- **출제 범위:**
    - 정규화 관련 (약 3문제)
    - 보안(Security) 관련 (1문제)
    - 동시성 제어(CC, Concurrency Control) 관련 (1문제)
- **주의사항:**
    - 틀린 문장을 수정할 때 단순히 "**~은 ~가 아니다**"라고 부정형으로 쓰면 **점수 없음**.
    - 반드시 "**~은 ~이다**"와 같이 구체적이고 올바른 사실로 고쳐 써야 함.
    - 난이도가 있어 대충 공부하면 쓰기 어려움.
        

### **[문제 2] 데이터베이스 설계 (모델링)**

- **내용:** 주어진 요구사항(Requirements)을 바탕으로 데이터베이스 설계 수행.
- **수행 단계:**
    
    1. 요구사항 분석
    2. **ER 모델링 (ER Diagram 그리기)**
    3. **관계형 모델(Relational Model)로 매핑 (변환)**
        

### **[문제 3] 정규화 (Normalization)**

- **내용:** 주어진 릴레이션을 정규화 수행.
- **범위:** **제2정규형(2NF)** 및 **제3정규형(3NF)** 위주로 출제.
    - 부분 함수 종속, 이행 함수 종속 등의 개념을 명확히 알고 있어야 함.
    - BCNF 등은 복잡한 구성을 요구하므로 잘 출제되지 않음 (2NF, 3NF에 집중할 것).
    - **제2정규형(2NF):** 부분 함수 종속 제거.
    - **제3정규형(3NF):** 이행 함수 종속 제거.
    - _BCNF:_ 개념은 알되, 분해(Decomposition) 문제는 2NF, 3NF 위주로 나올 확률 높음.
        

### **[문제 4] 동시성 제어 (Concurrency Control)**

- **내용:** 특정 스케줄(Schedule)을 제시하고 직렬 가능성(Serializability) 판단 및 조정.
- **수행 단계:**
    
    1. **직렬 가능 여부 판단:** 연산 충돌 그래프(Conflict Graph)를 그려서 사이클(Cycle) 존재 여부 확인.
        
        - 사이클 있음 = 비직렬 가능 (Non-serializable)
        - 사이클 없음 = 직렬 가능 (Serializable)
            
    2. **리스케줄링 (Rescheduling):** 만약 비직렬 가능(사이클 존재) 스케줄이라면, 사이클을 끊는 방식으로 순서를 조정하여 직렬 가능한 스케줄로 변경.
        
- **참고:** 세마포어 등 구체적인 메커니즘을 서술할 필요는 없으며, 연산 순서를 조정하여 해결하는 과정만 보여주면 됨.

    - _(참고: DAC는 서술 내용이 너무 많아 제외됨)_

### **1. RSA 방식 (비대칭키 암호화) - 필수 출제**
교수님이 "무조건 나온다"고 강조했습니다. 단순히 '암호화다'라고 쓰는 것보다 **키의 생성과 사용 흐름**을 명확히 적는 것이 중요합니다.

* **핵심 키워드:** 비대칭키(Asymmetric Key), 공개키(Public Key), 개인키(Private Key), 소인수분해의 어려움
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** RSA는 공개키 암호화 알고리즘의 대표적인 표준으로, 암호화와 복호화에 서로 다른 키를 사용하는 **비대칭키** 방식이다.
    2.  **키의 구성:** 누구나 알 수 있는 **공개키(Public Key)**와 소유자만 알고 있는 **개인키(Private Key)** 쌍으로 구성된다.
    3.  **작동 원리:**
        * **암호화:** 송신자는 수신자의 **공개키**를 사용하여 평문을 암호화한다.
        * **복호화:** 수신자는 자신의 **개인키**를 사용하여 암호문을 복호화한다. (반대로 전자서명 시에는 개인키로 잠그고 공개키로 푼다.)
    4.  **보안성:** 큰 수의 소인수분해가 계산적으로 매우 어렵다는 점에 기반하여 보안성을 유지한다.

### **2. MAC (Mandatory Access Control, 강제적 접근 통제)**
DAC는 제외되었으므로, MAC이 나올 확률이 50%입니다. 시스템이 권한을 강제한다는 점을 강조해야 합니다.

* **핵심 키워드:** 보안 등급(Security Label), 중앙 집중형 관리, 사용자(Subject), 객체(Object), 관리자(System)
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** 데이터베이스 관리 시스템(DBMS)이나 관리자가 정해놓은 정책에 따라, 주체(사용자)와 객체(데이터)에 부여된 **보안 등급(Security Label)**을 비교하여 접근을 통제하는 방식이다.
    2.  **특징:**
        * 사용자는 자신의 데이터라도 마음대로 접근 권한을 다른 사람에게 양도할 수 없다(**DAC와의 차이점**).
        * 모든 접근 제어는 시스템(관리자)에 의해 강제적으로 이루어진다.
    3.  **동작 예시 (BLP 모델 등 참조):**
        * 사용자의 보안 등급이 객체의 보안 등급보다 높거나 같아야 읽을 수 있다 (No Read Up 등).
        * 군대나 정보기관처럼 기밀성이 중요한 조직에서 주로 사용된다.

### **3. RBAC (Role-Based Access Control, 역할 기반 접근 통제)**
현대적인 시스템에서 가장 많이 쓰이는 방식입니다. '사람'이 아닌 '역할'에 권한을 준다는 것이 핵심입니다.

* **핵심 키워드:** 역할(Role), 권한 할당(Permission Assignment), 사용자 할당(User Assignment), 다대다(M:N) 관계
* **답안 작성 포인트 (서술 흐름):**
    1.  **정의:** 사용자 개인이 아닌, 조직 내에서 수행하는 **역할(Role)**에 따라 접근 권한을 부여하는 방식이다.
    2.  **구조:**
        * **권한(Permission) → 역할(Role):** 특정 역할(예: 인사팀장)에 필요한 권한들을 할당한다.
        * **역할(Role) → 사용자(User):** 사용자를 적절한 역할에 소속시킨다.
    3.  **장점:**
        * 인사이동이나 퇴사 시 사용자의 역할만 변경하면 되므로 관리가 매우 효율적이다.
        * 사용자와 권한 사이의 복잡성을 줄여주며, 최소 권한 원칙을 적용하기 용이하다.

#### 5. 데이터베이스 보안 (서술형) (20점)

- **유형:** 오늘 수업 내용(보안)에 대한 서술형 문제. (두 가지 주제 모두 준비 필요)
- **주제 A: RSA 암호화 방식 (비대칭키/공개키)**
    - **개념:** 암호화 키(공개키)와 복호화 키(개인키)가 서로 다른 '비대칭키' 시스템.
    - **운영 방식 (필수 암기):**
        
        1. **암호화 전송:** 수신자의 **공개키(Public Key)**로 암호화 $\rightarrow$ 수신자의 **개인키(Private Key)**로 복호화. (기밀성 보장)
        2. **전자 서명(인증):** 송신자의 **개인키**로 서명 $\rightarrow$ 송신자의 **공개키**로 확인. (부인 방지 및 인증)
            
- **주제 B: 내부 보안 (MAC 또는 RBAC)**
    - **DAC(선별적 접근 제어):** DB Owner가 권한을 부여(`GRANT`/`REVOKE`)하는 방식. _쓰는 내용이 너무 많아 시험 문제에서는 제외될 확률 높음(단, 개념은 인지)._
    - **MAC (강제적 접근 제어) & RBAC (역할 기반):**
        - **핵심 모델:** **Bell-LaPadula 모델**
        - **구성:** 주체(Subject, 사용자)와 객체(Object, 데이터)에 **등급(Level)** 부여 (예: 1급~4급).
        - **두 가지 원칙 (핵심):**
            
            1. **Simple Security Property (No Read Up):** 낮은 등급 주체는 높은 등급 문서를 읽을 수 없다.
            2. **Star Property (*-Property) (No Write Down):** 높은 등급 주체는 낮은 등급 문서에 쓸 수 없다. (기밀 유출 및 은닉 채널 방지)
                
        - **RBAC:** 사용자와 등급 사이에 '역할(Role)'을 매핑하여 관리하는 방식.
            
- **보안 문제 답안:**
    - RSA 설명 시: 키 2개(공개/개인) 생성, 암호화/복호화 키가 다르다는 점, 누가 누구의 키로 암호화/서명하는지 정확히 명시.
    - MAC 설명 시: 주체/객체 등급 분류, 벨-라파듈라 모델의 2가지 원칙(No Read Up, No Write Down)을 명확히 서술.
