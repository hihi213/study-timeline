## Topic 1. 분할 정복 (Divide and Conquer)

### 1. 🏗️ 빌드업 (Why & Context)

> **"거대한 문제는 작게 쪼개서 각개격파한다."**

- **동기/배경**: 40명의 학생 중 가위바위보 1등을 뽑아야 한다고 가정해 보자. 40명이 동시에 덤비면 판정이 불가능하다. 하지만 그룹을 반으로 계속 쪼개서 2명씩 붙게 만들면 판정이 매우 쉬워진다.
- **역사적 유래**: 나폴레옹이 소규모 병력으로 대규모 적을 상대할 때, 적을 소규모로 분산시킨 뒤 각개격파(Divide)하고 정복(Conquer) 했던 전술에서 유래했다.
    

### Concept

- **핵심 메커니즘 3단계**:
    
    1. **분할 (Divide)**: 해결하기 쉽도록 문제를 2개 이상의 하위 문제(Sub-problem)로 쪼갠다. (보통 $N/2$)
    2. **정복 (Conquer)**: 하위 문제가 더 이상 쪼개지지 않을 때까지 재귀적으로 호출하여 해결한다. (Atomic level, size=1일때까지)
    3. **결합 (Combine)**: 해결된 하위 문제의 답을 모아서 전체 문제의 해답을 구한다.
        
- **디버깅 예시**: 100줄짜리 코드에서 에러를 찾을 때, 위에서부터 구간을 나누어 `printf`를 찍으며 범위를 좁혀가는 과정도 일종의 분할 정복 사고방식이다.

## Topic 2. 합병 정렬 (Merge Sort)의 논리

### 1. 🏗️ 빌드업 (Why & Context)

> **"이미 정렬된 두 개의 그룹을 합치는 것은 쉽다."**

- **핵심 아이디어**: 무작위 데이터 $N$개를 바로 정렬하는 건 어렵다. 하지만 데이터가 1개가 될 때까지 쪼개면, 그 자체로 '정렬된 상태'가 된다. 이때부터 두 개의 정렬된 리스트를 합치며(Merge) 올라오면 전체가 정렬된다.
### Concept

이 알고리즘은 **분할 정복(Divide and Conquer)** 방식을 따르며, 재귀 호출의 특성상 **DFS(깊이 우선 탐색, 끝까지 갔다가 돌아와 다른쪽을 가는)** 순서로 실행됩니다.

**1. `MergeSort` 함수: 분할 및 실행 제어**

- **기저 조건 (Stop)**: `left < right`일 때만 진행한다. `left==right`(데이터가 1개)가 되면 멈춤)
- **DFS 실행 순서**:
    1. `MergeSort(Left)`를 호출하여 왼쪽 끝까지 파고든다.
    2. 왼쪽이 완벽히 정렬되어 반환된 후에야 `MergeSort(Right)`가 실행된다.
    3. 좌/우가 모두 정렬된 상태에서 비로소 `Merge()`가 실행된다. 

**2.`Merge` 함수: 병합 및 정렬 수행**

1. 비교: 두 부분 리스트(Left, Right)의 맨 앞 값(포인터)을 비교한다.
2. **저장**: **더 작은 값**을 임시 배열(Sorted Array)에 넣고, 해당 리스트의 포인터를 한 칸 전진시킨다.
3.  **잔여 처리**: 경쟁이 끝나고(한쪽이 바닥남) 남은 리스트의 데이터는 그대로 뒤에 복사해 붙인다.

## Topic 3. 구현 및 복잡도 (Implementation & Complexity)

### Code 구현 (C언어)

> **핵심**: 데이터를 담을 `sorted` 임시 배열이 반드시 필요하며, 재귀 호출을 통해 분할 후 `merge` 함수로 정복한다.
- **`left`**: 현재 살피고 있는 덩어리의 **시작 인덱스**
- **`right`**: 현재 살피고 있는 덩어리의 **끝 인덱스**
```C
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 정렬된 데이터를 임시 저장할 추가 공간 (필수)

// 2. 병합 함수 (Conquer & Combine)
void merge(int list[], int left, int mid, int right) {
    int i, j, k, l;
    i = left;     // 왼쪽 리스트 시작 인덱스
    j = mid + 1;  // 오른쪽 리스트 시작 인덱스
    k = left;     // 임시 배열(sorted)의 인덱스

    // 두 리스트의 데이터를 비교하여 작은 순서대로 sorted에 삽입
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) {
            sorted[k++] = list[i++];
        } else {
            sorted[k++] = list[j++];
        }
    }

    // 남은 데이터 일괄 복사
    if (i > mid) { // 왼쪽 리스트가 먼저 끝난 경우
        for (l = j; l <= right; l++)
            sorted[k++] = list[l];
    } else { // 오른쪽 리스트가 먼저 끝난 경우
        for (l = i; l <= mid; l++)
            sorted[k++] = list[l];
    }

    // 임시 배열의 내용을 원본 배열로 재복사
    for (l = left; l <= right; l++) {
        list[l] = sorted[l];
    }
}
```


### ⚠️ 중요 분석 및 주의사항

1. **시간 복잡도**:
    
    - 분할 단계: $\log_2 N$ 단계 (트리의 높이)
    - 병합 단계: 각 단계에서 모든 요소를 비교하므로 $N$
    - **Total**: $O(N \log N)$
    - **특징**: 데이터의 초기 상태(정렬 여부)와 상관없이 **항상** $O(N \log N)$을 보장한다. (Best, Average, Worst 동일)
        
2. **공간 복잡도 (치명적 단점)**:
    
    - **$O(N)$의 추가 메모리**가 필요하다. (`sorted` 배열)
    - 원본 데이터 크기만큼의 메모리가 더 필요하므로, 메모리 제한이 타이트한 임베디드 환경 등에서는 사용이 꺼려질 수 있다.
        
3. **데이터 이동**:
    
    - 임시 배열로 복사했다가 다시 가져오는 과정에서 $2N \log N$ 수준의 이동 연산이 발생한다.
    - 이 때문에 일반적인 배열 정렬에서는 **퀵 정렬(Quick Sort)**보다 실제 속도가 느린 경우가 많다.
    - 단, **연결 리스트(Linked List)**를 정렬할 때는 인덱스 접근이 필요 없고 링크만 바꾸면 되므로 퀵 정렬보다 효율적일 수 있다.

## Topic 1. 퀵 정렬 (Quick Sort)의 핵심 논리

### 1. 🏗️ 빌드업 (Why & Context)

> **"합병 정렬은 '위치(크기)'로 쪼개지만, 퀵 정렬은 '값'으로 쪼갠다."**

- **비교 분석**:
    - **합병 정렬 (Merge Sort)**: 무조건 리스트의 정중앙을 잘라 반반씩(Size) 나눈다. 분할은 단순하지만, 나중에 합칠 때(Merge) 정렬 연산이 일어난다.
    - **퀵 정렬 (Quick Sort)**: 리스트 내의 특정 **값(Pivot)**을 기준으로, 이보다 작은 그룹과 큰 그룹으로 나눈다. 분할 단계에서 이미 대략적인 정렬(Partitioning)이 일어나며, 피벗은 자기 자리를 찾아간다.
        

### Concept

- **핵심 메커니즘**:
    
    1. **Pivot 선정**: 리스트에서 기준이 될 원소 하나를 선택한다. (강의에서는 주로 '첫 번째 원소' 또는 '중간값' 사용)
    2. **분할 (Partitioning)**:
        
        - Pivot보다 작은 값은 왼쪽으로($< Pivot$), 큰 값은 오른쪽으로($> Pivot$) 몰아넣는다.
        - 이 과정이 끝나면 Pivot은 정렬된 최종 위치에 고정된다.
            
    3. **재귀 (Recursion)**: Pivot을 제외한 왼쪽 부분 집합과 오른쪽 부분 집합에 대해 동일한 과정을 반복한다.

## Topic 2. 파티션(Partition) 알고리즘 상세

### 1. 🏗️ 빌드업 (Why & Context)

> **"어떻게 피벗을 기준으로 작은 놈과 큰 놈을 가를 것인가?"**

- **동기**: 단순히 새로운 배열을 만들어 담는다면 쉽겠지만, 퀵 정렬의 장점(In-place sort)을 살리기 위해 기존 배열 내에서 자리를 교환(Swap)하는 방식을 사용해야 한다. 이를 위해 두 개의 포인터(`low`, `high`)가 필요하다.
    

### Concept (Low & High Pointer)

- **동작 원리**:
    - **Pivot**: 왼쪽 첫 번째 원소(`List[Left]`)라고 가정.
    - **`low` (Left → Right)**: 왼쪽에서 출발하여 Pivot보다 **큰 값**을 찾을 때까지 이동한다.
    - **`high` (Right → Left)**: 오른쪽 끝에서 출발하여 Pivot보다 **작은 값**을 찾을 때까지 이동한다.
    - **교환 (Swap)**:
        - `low`와 `high`가 멈췄을 때, 아직 서로 교차하지 않았다면(`low < high`) 두 값을 맞바꾼다.
        - `low`와 `high`가 교차했다면(`low > high`), 분할이 끝난 것이다. 이때 **Pivot과 `high`가 가리키는 값을 교환**한다. (Pivot이 중앙으로 이동하며 고정됨)

## Topic 3. C언어 구현 및 코드 분석

### Code 구현

> **핵심**: `partition` 함수 내의 `do-while` 루프 구조와 초기값 세팅에 주의해야 한다.



```C
#include <stdio.h>

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 분할 함수 (핵심 로직)
int partition(int list[], int left, int right) {
    int pivot, temp;
    int low, high;

    low = left;                 // low는 왼쪽 시작점
    high = right + 1;           // high는 오른쪽 끝 + 1 (do-while 감소 대응)
    pivot = list[left];         // 피벗은 가장 왼쪽 요소로 설정

    do {
        // 1. low 이동: pivot보다 큰 값을 만날 때까지 증가
        // (do-while을 쓰기 때문에 일단 증가시키고 비교함)
        do {
            low++;
        } while (list[low] < pivot && low <= right); // 범위 체크 필수

        // 2. high 이동: pivot보다 작은 값을 만날 때까지 감소
        do {
            high--;
        } while (list[high] > pivot);

        // 3. 교차하지 않았다면 swap
        if (low < high) {
            swap(&list[low], &list[high]);
        }
    } while (low < high);

    // 4. 교차했다면(분할 종료), pivot과 high 위치 교환
    // pivot(list[left])을 자신의 올바른 위치(high)로 보냄
    swap(&list[left], &list[high]);

    return high; // pivot의 확정된 위치 반환
}

// 퀵 정렬 재귀 함수
void quick_sort(int list[], int left, int right) {
    if (left < right) {
        // q: 피벗이 위치한 인덱스 (정렬 확정된 위치)
        int q = partition(list, left, right); 
        
        // 피벗을 제외한 왼쪽/오른쪽 부분 리스트 재귀 호출
        quick_sort(list, left, q - 1);
        quick_sort(list, q + 1, right);
    }
}
```

### ⚠️ Critical Point: 왜 `do-while`을 쓰고, `high`는 `right + 1`인가?

- **교수님 강조 포인트**: 강의 중 학생들이 대답하지 못한 부분이다.
- **이유**: `low`는 `left`(피벗 위치)부터 시작하지만, 피벗 자기 자신과 비교할 필요 없이 바로 다음 칸부터 검사해야 한다.
- **메커니즘**:
    - `do { low++; }` 구조를 사용하면 비교 전에 무조건 인덱스가 1 증가한다.
    - 따라서 `low`는 `left`에서 시작해도 `left+1`부터 비교하게 된다.
    - 대칭성을 맞추기 위해 `high`도 `right`가 아닌 `right + 1`에서 시작하여, 감소 후(`high--`) `right`부터 비교하도록 설계된 것이다.

### 💡 Interview

> [!faq]- Q. 퀵 정렬이 최악의 성능 $O(N^2)$을 내는 경우는 언제이며, 해결책은?
>
> 🗣️ 핵심 답변
>
> 이미 정렬된 배열(오름차순 또는 내림차순)에서 첫 번째 원소를 피벗으로 잡을 때 최악의 성능이 나옵니다. 이 경우 분할이 1:N-1로 극단적으로 일어나 트리 높이가 $N$이 되기 때문입니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 이를 방지하기 위한 방법은?**
>     
>     - 피벗을 **중간값(Median)**으로 잡거나, **난수(Random)** 인덱스로 잡아서 확률적으로 분할의 불균형을 막는 방법을 사용합니다. (Median-of-three 기법 등)
>         

> [!faq]- Q. 퀵 정렬이 합병 정렬보다 일반적으로 빠른 이유는? (추가 메모리 관점 제외)
>
> 🗣️ 핵심 답변
>
> 퀵 정렬은 **참조 지역성(Locality of Reference)**이 좋기 때문입니다. 배열 내에서 인접한 데이터를 교환하며 처리하므로 CPU 캐시 히트율이 높아, 물리적인 수행 시간이 더 빠릅니다. 반면 합병 정렬은 임시 배열로 데이터를 복사하고 이동하는 과정이 많습니다.

## Topic 1. 퀵 정렬의 최악의 경우 (Worst Case)

### 1. 🏗️ 빌드업 (Why & Context)

> **"왜 이미 정렬된 데이터를 다시 정렬할 때 퀵 정렬은 느려지는가?"**

- **문제 제기**: 퀵 정렬은 일반적으로 매우 빠르지만($O(N \log N)$), 특정 상황에서는 $O(N^2)$까지 성능이 떨어진다.
- **최악의 시나리오**: 데이터가 이미 **오름차순** 또는 **내림차순**으로 정렬되어 있고, **피벗(Pivot)을 가장 왼쪽(또는 오른쪽) 값으로 고정**했을 때 발생한다.
    

### Concept & Mechanism

- **논리적 원인**:
    
    1. **불균형 분할 (Unbalanced Partitioning)**: 정렬된 상태에서 피벗을 첫 번째 요소로 잡으면, 피벗보다 작은 값(혹은 큰 값)이 아예 없거나 전부이다.
    2. **트리의 편향**: 리스트가 반($N/2$)으로 쪼개지지 않고, `1`개와 `N-1`개로 계속 쪼개진다.
    3. **깊이 증가**: 재귀 호출의 깊이가 $\log N$이 아니라 $N$이 되며, 각 단계의 비교 연산도 $N$에 비례하므로 총 복잡도는 $N \times N = O(N^2)$가 된다.
        
- **비교**: 랜덤 데이터에서는 피벗을 기준으로 좌우가 균등하게 나뉘어 효율적이지만, 정렬된 데이터에서는 최악의 효율을 보인다.

## Topic 2. 힙 (Heap) 자료구조의 이해

### 1. 🏗️ 빌드업 (Why & Context)

> **"돈을 더 낸 사람을 먼저 태워주는 놀이공원 큐패스(Q-Pass)처럼, 우선순위가 높은 데이터를 먼저 처리하자."**

- **동기**: 일반적인 큐(Queue)는 선입선출(FIFO)이지만, 현실 세계(응급실, VIP 서비스 등)에서는 **우선순위(Priority)**가 높은 순서대로 처리해야 하는 경우가 많다. 이를 효율적으로 구현하기 위한 자료구조가 힙(Heap)이다.
    

### Concept: 완전 이진 트리 (Complete Binary Tree)

- **정의**: 우선순위 큐를 위해 만들어진 **완전 이진 트리** 형태의 자료구조.
    - **최대 힙 (Max Heap)**: 부모 노드의 키 값 $\ge$ 자식 노드의 키 값. (루트가 가장 큼)
    - **최소 힙 (Min Heap)**: 부모 노드의 키 값 $\le$ 자식 노드의 키 값. (루트가 가장 작음)
- **특징**:
    - **중복 허용**: 이진 탐색 트리(BST)와 달리 중복된 값을 허용한다.
    - **배열 구현**: 1번 인덱스를 루트로 사용하면 수식으로 자식/부모 접근이 가능하다.
        - 왼쪽 자식: $index \times 2$
        - 오른쪽 자식: $index \times 2 + 1$
        - 부모 노드: $index / 2$

## Topic 3. 힙 정렬 (Heap Sort)과 삭제 알고리즘

### 1. 🏗️ 빌드업 (Why & Context)

> **"힙에서 가장 큰 값(루트)을 계속 꺼내서 뒤로 보내면 자동으로 정렬된다."**

- **핵심 아이디어**:
    
    1. 주어진 배열을 **최대 힙(Max Heap)**으로 변환한다. (Make Heap)
    2. 루트(최대값)를 삭제(Pop)하여 배열의 맨 뒤로 보낸다.
    3. 남은 데이터로 다시 힙을 구성하고 이를 반복하면 오름차순 정렬이 완성된다.
        

### Concept: 삭제(Delete) 및 재구성 알고리즘

- **개념적 삭제 vs 실제 알고리즘**:
    - **개념적**: 루트가 빠지면 자식들끼리 경쟁해서 2인자가 올라오고, 그 빈자리를 또 자식이 채우는 방식.
    - **실제 구현 (Re-heapify)**:
        
        1. **Swap**: 루트(최대값)와 힙의 **가장 마지막 노드**를 교환한다. (루트는 정렬 완료 영역으로 이동)
        2. **Size 감소**: 힙의 크기를 1 줄여서 최대값을 힙에서 제외한다.
        3. **Bubble Down (Sift Down)**: 루트로 올라온 '마지막 노드(작은 값)'를 자식들과 비교하며 제자리를 찾아 내려보낸다.
            
            - 자식 중 **더 큰 값**과 비교 및 교환해야 한다.
            - 완전 이진 트리 속성을 유지하면서 효율적으로($O(\log N)$) 힙을 복구하는 핵심 로직이다.
### Code 구현 (논리 분석)

- **Make Heap**: 배열 전체를 힙 성질에 맞게 구성.
- **Sorting Loop**:
    ```C
    // 1. 루트(1번)와 마지막 노드(i번) 교환
    swap(a[1], a[i]);
    // 2. 힙 크기를 줄이고(i-1), 1번 노드부터 다시 힙 구조 맞추기
    make_heap(a, 1, i-1); 
    ``` 
    
- **시간 복잡도**: 힙 구성 $O(N)$ + $N$번의 삭제($\log N$) = 전체 **$O(N \log N)$**.

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.10.30

### 💡 Interview

> [!faq]- Q. 이진 탐색 트리(BST)와 힙(Heap)의 차이점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 목적과 느슨함의 차이입니다. BST는 탐색을 위해 모든 왼쪽 자식은 부모보다 작고 오른쪽은 커야 하는 엄격한 정렬 상태를 유지하며 중복을 허용하지 않습니다. 반면, 힙은 최대/최소값을 빠르게 찾기 위해 부모가 자식보다 크기만 하면 되는 느슨한 정렬(반정렬) 상태를 가지며 중복 값을 허용합니다.

> [!faq]- Q. 힙 정렬 구현 시 배열의 0번 인덱스를 비우고 1번부터 사용하는 이유는?
>
> 🗣️ 핵심 답변
>
> 완전 이진 트리의 인덱스 연산을 단순화하기 위해서입니다. 1번을 루트로 두면 왼쪽 자식 = i * 2, 부모 = i / 2로 비트 연산 등을 통해 매우 빠르게 접근 위치를 계산할 수 있습니다. 0번부터 시작하면 수식이 복잡해집니다.
