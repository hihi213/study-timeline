## Topic 1. 분할 정복 (Divide and Conquer)

### 1. 🏗️ 빌드업 (Why & Context)

> 복잡한 문제를 한 번에 해결하기 어려울 때 사용하는 접근법

- **문제 제기/동기**: 40명이 한꺼번에 가위바위보를 해서 1등을 뽑으려면 경우의 수가 너무 많아 복잡해진다. 어떻게 효율적으로 승자를 가려낼 것인가?
- **핵심 아이디어의 단초**:
    - **나폴레옹의 전쟁 전략**: 소규모의 병력으로 대군을 상대할 때, 적을 소규모로 쪼개어 각개격파하는 전술에서 유래.
    - **가위바위보 토너먼트**: 40명을 20명 vs 20명으로, 다시 10명 vs 10명으로 계속 반으로 쪼개(Divide) 승부를 낸 뒤 올라오면서(Merge) 최종 승자를 가린다.
        

### Concept

> **"문제를 더 이상 쪼갤 수 없을 때까지 나누고(Divide), 작은 문제에서 답을 구한 뒤(Conquer), 이를 다시 합친다(Combine)."**

1. **분할 (Divide)**: 해결하기 쉽도록 문제를 2개 이상의 하위 문제(Sub-problem)로 나눈다.
	>예: 배열을 반으로 쪼갬
2. **정복 (Conquer)**: 하위 문제가 충분히 작으면 해결하고, 그렇지 않으면 다시 재귀적으로 분할한다.
	- Base Case: 원소가 1개면 그 자체로 정렬된 상태
3. **결합 (Combine)**: 해결된 하위 문제의 답을 모아 원래 문제의 해답을 만든다.
	> 예: 정렬된 두 리스트를 합침

## Topic 2. 합병 정렬 (Merge Sort) 메커니즘과 구현

### 1. 🏗️ 빌드업 (Why & Context)

> 분할 정복 기법을 정렬 알고리즘에 적용한 케이스

- **디버깅 비유**: 100라인 코드에서 에러를 찾을 때, 전체를 다 보는 대신 코드를 반으로 나누어 `printf`를 찍으며 범위를 좁혀가는 것과 유사하다.
- **작동 원리**:
    - 정렬되지 않은 리스트를 계속 반으로 쪼갠다. ($N \to N/2 \to \dots \to 1$)
    - 원소가 1개가 되면 그루핑(Grouping)하면서 정렬을 수행한다.
    - **핵심**: "이미 정렬된 두 개의 부분 리스트를 합치는 것(Merge)"은 매우 빠르고 쉽다.
        

### Concept

- **순환 호출 (Recursive Call)**: 분할 과정에서 자기 자신을 다시 호출한다.
- **Merge Process**:
    - 두 개의 정렬된 리스트(Left, Right)가 있을 때, 각각의 첫 번째 원소를 비교한다.
    - 더 작은 값을 결과 배열(Sorted Array)에 넣고, 해당 리스트의 포인터를 한 칸 이동시킨다.
    - 한쪽 리스트가 먼저 끝나면, 나머지 리스트의 잔여 데이터를 그대로 복사한다.
        

### Code 구현 (C언어)

```C
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 정렬된 데이터를 담을 임시 전역 배열 (추가 메모리 필요)

// 1. 합병 (Merge) 함수: 정렬된 두 리스트를 하나로 합침
void merge(int list[], int left, int mid, int right) {
    int i, j, k, l;
    i = left;     // 왼쪽 리스트 시작 인덱스
    j = mid + 1;  // 오른쪽 리스트 시작 인덱스
    k = left;     // 임시 배열(sorted)의 인덱스

    // 분할된 두 리스트를 비교하며 작은 순서대로 sorted에 삽입
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) {
            sorted[k++] = list[i++];
        } else {
            sorted[k++] = list[j++];
        }
    }

    // 남아있는 데이터 일괄 복사
    if (i > mid) { // 왼쪽 리스트가 먼저 끝난 경우 -> 오른쪽 잔여 데이터 복사
        for (l = j; l <= right; l++)
            sorted[k++] = list[l];
    } else { // 오른쪽 리스트가 먼저 끝난 경우 -> 왼쪽 잔여 데이터 복사
        for (l = i; l <= mid; l++)
            sorted[k++] = list[l];
    }

    // 임시 배열의 데이터를 다시 원본 배열로 복사
    for (l = left; l <= right; l++) {
        list[l] = sorted[l];
    }
}

// 2. 합병 정렬 (Merge Sort) 함수: 재귀적 분할 수행
void merge_sort(int list[], int left, int right) {
    int mid;
    if (left < right) {
        mid = (left + right) / 2;     // 중간 위치 계산
        merge_sort(list, left, mid);      // 앞쪽 부분 리스트 정렬 (재귀)
        merge_sort(list, mid + 1, right); // 뒤쪽 부분 리스트 정렬 (재귀)
        merge(list, left, mid, right);    // 정렬된 2개의 부분 리스트를 합병
    }
}
```

- **⚠️ 재귀 호출 순서의 이해 (중요)**:
    - 코드를 보면 `merge_sort(left, mid)`가 먼저 호출된다. 이 함수가 완전히 끝나야(즉, 왼쪽 절반이 1개 단위까지 쪼개지고 다시 합쳐져서 정렬이 완료되어야) 비로소 `merge_sort(mid+1, right)`가 실행된다.
    - 동시에 쪼개지는 것이 아니라, **왼쪽 깊이 우선 탐색(DFS) 형태**로 진행됨을 오해하면 안 된다.

## Topic 3. 성능 분석 및 퀵 정렬과의 비교

### 1. 🏗️ 빌드업 (Why & Context)

> "그래서 이 알고리즘은 얼마나 빠르고, 언제 써야 하는가?"

- **안정성**: 입력 데이터의 분포에 상관없이 일정한 성능을 보장한다.
- **Trade-off**: 속도는 빠르지만 공간(메모리)을 더 쓴다.
    

### Concept: 복잡도 및 특성

1. **시간 복잡도**: $O(N \log N)$
    
    - **분할 단계**: $\log N$번 (계속 반으로 나누므로 트리의 높이가 $\log N$).
    - **합병 단계**: 각 단계에서 모든 원소($N$)를 한 번씩 비교하고 이동함.
    - **총합**: 최선(Best), 평균(Avg), 최악(Worst) 모두 **$O(N \log N)$** 으로 동일하다.
        
2. **공간 복잡도**: $O(N)$
    
    - 정렬을 수행하기 위해 원본 데이터 크기만큼의 **임시 배열(`sorted[]`)** 이 반드시 필요하다. (In-place Sorting이 아님)
        
3. **이동 연산**: $2N \log N$
    
    - 임시 배열에 썼다가 다시 원본으로 복사하는 과정 때문에 이동 연산이 많다. 이는 레코드 크기가 클 경우 오버헤드가 될 수 있다.
        

### 💡 Interview: Merge Sort vs Quick Sort

> [!faq]Q. 퀵 정렬(Quick Sort)이 일반적으로 더 빠름에도 불구하고 합병 정렬(Merge Sort)을 사용하는 이유는 무엇인가?
>
> 🗣️ 핵심 답변
>
> 퀵 정렬은 최악의 경우(이미 정렬된 데이터 등) $O(N^2)$의 시간이 걸리지만, 합병 정렬은 어떤 경우에도 $O(N \log N)$을 보장하기 때문입니다. 또한, 합병 정렬은 Stable Sort(안정 정렬) 이므로 동일한 값의 순서가 유지되어야 할 때 유리합니다.
>
> **📚 심화: Linked List 정렬에서의 이점**
>
> - 배열(Array) 정렬 시에는 합병 정렬이 임시 배열 생성($O(N)$ 공간)과 데이터 이동 오버헤드 때문에 퀵 정렬보다 느릴 수 있습니다.
>     
> - 하지만 **Linked List**를 정렬할 때는 인덱스 접근이 아닌 포인터 변경만으로 병합이 가능하므로, 데이터 이동 오버헤드가 사라지고 임시 메모리도 거의 필요 없어 **퀵 정렬보다 훨씬 효율적**입니다.
>

## Topic 1. 퀵 정렬 (Quick Sort) 개념과 원리

### 1. 🏗️ 빌드업 (Why & Context)

> 합병 정렬(Merge Sort)과 비슷해 보이지만 결정적인 차이가 있다.

- **비교**:
    - **합병 정렬**: 물리적 크기(Size)를 기준으로 무조건 반으로 쪼갠다. (위치 중심)
    - **퀵 정렬**: 리스트 내의 **특정 값(Pivot)**을 기준으로 쪼갠다. (값 중심)
- **핵심 아이디어**: "기준(Pivot)을 세우고, 기준보다 작은 건 왼쪽으로, 큰 건 오른쪽으로 몰아넣으면 어떨까?"
    - 키 순서대로 줄을 설 때, 선생님(Pivot)이 서고 "나보다 작은 사람 왼쪽, 큰 사람 오른쪽"이라고 외치는 것과 같다.
        

### Concept

> **"Pivot을 기준으로 파티셔닝(Partitioning)을 수행하여 분할과 정복을 동시에 진행한다."**

1. **Pivot 선정**: 리스트의 원소 중 하나(왼쪽 끝, 중간, 또는 랜덤)를 기준값으로 정한다.
2. **분할 (Partitioning)**:
    
    - Pivot보다 작은 값들은 왼쪽 부분 리스트로 이동.
    - Pivot보다 큰 값들은 오른쪽 부분 리스트로 이동.
    - 이 과정이 끝나면 Pivot은 자기 자리를 확정(Fix) 짓게 된다.
        
3. **재귀 (Recursion)**: 확정된 Pivot을 제외하고, 왼쪽 덩어리와 오른쪽 덩어리에 대해 다시 1~2번 과정을 반복한다.
4. **종료**: 부분 리스트의 크기가 1 이하가 되면 정렬이 완료된 것이다.

## Topic 2. 파티션(Partition) 알고리즘 상세

### 1. 🏗️ 빌드업 (Why & Context)

> 컴퓨터가 직관적으로 "작은 거 왼쪽"을 실행하려면 포인터 두 개가 필요하다.

- **메커니즘**: 왼쪽 끝(`low`)과 오른쪽 끝(`high`)에서 출발하여 서로 좁혀오면서 Pivot과 비교한다.
    

### Concept: `low`와 `high`의 이동 규칙

(Pivot을 **가장 왼쪽 원소(`left`)**로 잡았을 경우)

1. **초기화**:
    
    - **Pivot**: `list[left]`
    - **`low`**: `left + 1`에서 출발하여 오른쪽으로 이동.
    - **`high`**: `right`에서 출발하여 왼쪽으로 이동.
        
2. **탐색 및 정지**:
    
    - **`low`**: Pivot보다 **큰 값**을 만날 때까지 `index` 증가 (작으면 통과).
    - **`high`**: Pivot보다 **작은 값**을 만날 때까지 `index` 감소 (크면 통과).
        
3. **교환 (Swap)**:
    
    - `low`와 `high`가 멈췄을 때, 아직 서로 교차하지 않았다면(`low < high`) 두 값을 맞바꾼다.
    - 이렇게 하면 큰 값은 오른쪽으로, 작은 값은 왼쪽으로 보내진다.
        
4. **Pivot 확정**:
    
    - `low`와 `high`가 교차(`low > high`)하면 더 이상 교환할 대상이 없다는 뜻.
    - 이때 **Pivot(`list[left]`)과 `list[high]`를 교환**한다.
    - 이제 `high` 위치가 Pivot의 최종 정렬 위치가 된다.

## Topic 3. C언어 구현 및 Critical Point

### 1. 🏗️ 빌드업 (Why & Context)

> "알고리즘을 코드로 옮길 때 디테일한 인덱스 처리가 중요하다."

- **강조사항**: AI(ChatGPT 등)가 짜주는 코드를 복사해서 제출하지 말고, 직접 한 줄씩 분석하며 짜봐야 한다. (현업 포럼 이슈: AI 코드를 분석/검증할 능력이 없으면 도태됨)
    

### Code 구현 (C언어)

```C
#include <stdio.h>

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 분할 함수 (핵심 로직)
int partition(int list[], int left, int right) {
    int pivot, temp;
    int low, high;

    low = left;            // 초기값 설정 (do-while 사용을 위해 left로 시작)
    high = right + 1;      // 초기값 설정 (do-while 사용을 위해 right+1로 시작)
    pivot = list[left];    // 가장 왼쪽 요소를 피벗으로 설정

    do {
        // 1. low 이동: 피벗보다 큰 값을 찾을 때까지 증가
        // boundary check(low <= right)와 값 비교를 동시에 수행
        do {
            low++; 
        } while (low <= right && list[low] < pivot);

        // 2. high 이동: 피벗보다 작은 값을 찾을 때까지 감소
        do {
            high--;
        } while (high >= left && list[high] > pivot);

        // 3. 교차하지 않았다면 두 값을 교환
        if (low < high) {
            swap(&list[low], &list[high]);
        }
    } while (low < high); // low와 high가 교차할 때까지 반복

    // 4. 피벗을 제자리(high)로 이동 (Partitioning 완료)
    swap(&list[left], &list[high]);

    return high; // 피벗의 확정된 위치 반환
}

// 퀵 정렬 재귀 함수
void quick_sort(int list[], int left, int right) {
    if (left < right) {
        // q: 피벗이 위치한 인덱스 (이미 정렬된 위치)
        int q = partition(list, left, right); 

        // 피벗을 제외한 왼쪽 부분 리스트 정렬
        quick_sort(list, left, q - 1);
        
        // 피벗을 제외한 오른쪽 부분 리스트 정렬
        quick_sort(list, q + 1, right);
    }
}
```

### ⚠️ Critical Analysis (교수님 강조 포인트)

1. **왜 `do-while` 문을 사용하는가?**
    
    - `low`는 `left`부터, `high`는 `right+1`부터 시작한다.
    - `do-while`은 **"먼저 실행(증가/감소)하고 나서 비교"**한다.
    - `low`를 예로 들면, `left`에는 Pivot이 있으므로 비교할 필요 없이 바로 `low++`를 수행하여 `left+1`부터 비교를 시작하기 위함이다.
    - 만약 `while`문을 쓴다면 초기값과 증감 위치를 다르게 조정해야 한다.
        
2. **재귀 호출의 범위**:
    
    - `partition` 함수가 리턴하는 `q`는 Pivot의 위치다.
    - 재귀 호출 시 `q`는 이미 정렬이 끝난 상태이므로 포함하지 않는다.
    - Left: `left` ~ `q - 1`
    - Right: `q + 1` ~ `right`
        
3. **코드 분석의 중요성**:
    
    - `low`가 `right`를 벗어나지 않도록 하는 조건(`low <= right`), `high`가 `left`보다 작아지지 않게 하는 조건 등이 없으면 메모리 오류가 발생한다. 이를 한 줄 한 줄 따져보는 연습이 필수적이다.

## 기타 핵심 (Etc & Tips) - 알고리즘 10.30

- **표준 라이브러리 비교**: C언어 `<stdlib.h>`의 `qsort` 함수와 직접 짠 코드를 비교해보는 것이 좋은 공부법이다.
- **성능 특성**:
    - 평균 시간 복잡도: $O(N \log N)$ (매우 빠름)
    - 최악 시간 복잡도: $O(N^2)$ (이미 정렬된 데이터에서 첫 번째 원소를 Pivot으로 잡을 때 계속 불균형 분할 발생)
    - 불균형 분할 방지: Pivot을 중간값(Median)이나 랜덤값으로 잡으면 완화됨.
        

### 💡 Interview: Quick Sort 심화

> [!faq]Q. 퀵 정렬(Quick Sort)이 최악의 경우 $O(N^2)$임에도 불구하고 가장 널리 쓰이는 이유는?
>
> 🗣️ 핵심 답변
>
> 퀵 정렬은 **평균적으로 $O(N \log N)$**의 매우 빠른 속도를 가지며, **추가적인 메모리 공간(Auxiliary Space)을 거의 사용하지 않는 제자리 정렬(In-place Sort)**이기 때문입니다. 합병 정렬과 달리 배열 내부에서 교환만으로 정렬되므로 Cache Locality(캐시 지역성) 효율이 좋아 실질적인 실행 속도가 더 빠릅니다.
>
> **📚 꼬리질문: 최악의 경우($O(N^2)$)를 피하기 위한 전략은?**
>
> - 피벗(Pivot)을 단순히 '가장 왼쪽 값'이 아닌, **'리스트의 중간값(Median-of-three)'**을 선택하거나 **'무작위(Random)'**로 선택하여 분할의 불균형을 방지할 수 있습니다.
>
