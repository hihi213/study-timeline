### **2. 💡 리눅스 관련 개념 정리**

- **쉘(Shell)의 역할과 중요성**
    - **정의**: 사용자와 리눅스 커널(Kernel)을 연결해 주는 인터페이스이자 명령어 해석기.
    - **기능**: 사용자의 명령을 해석하여 커널에 전달하고, 결과를 다시 사용자에게 보여줌. 프로그래밍 기능(쉘 스크립트) 및 초기화 파일(`.bashrc` 등)을 통한 환경 설정 가능.
    - _교수님 강조_: 개발자나 시스템 엔지니어는 윈도우(GUI) 환경뿐만 아니라 텍스트(CLI) 환경에 익숙해져야 함. (서버 관리, 라우터 설정 등은 대부분 텍스트 기반임)
- **로그인 쉘 vs 서브 쉘(Sub-shell)**
    - **로그인 쉘**: 로그인 시 자동으로 실행되는 기본 쉘 (우분투는 기본적으로 `bash` 사용).
    - **서브 쉘**: 로그인 쉘 안에서 다른 쉘을 실행한 상태 (예: bash 안에서 sh 실행). `exit` 명령어로 서브 쉘을 종료하면 이전 쉘로 돌아감.
- **내장 명령어(Internal) vs 외장 명령어(External)**
    - **내장 명령어**: 쉘 자체에 포함된 기능. 별도 실행 파일이 없으며 즉시 실행됨 (예: `cd`, `alias`). `whereis`로 찾으면 경로가 안 나옴.
    - **외장 명령어**: 별도의 실행 파일(`/bin`, `/usr/bin` 등)로 존재하는 프로그램. 실행 시 자식 프로세스를 생성하여 동작 (예: `ls`, `pwd`).
    - _실습 포인트_: 실행 파일(바이너리)을 `cat`으로 열면 깨진 글자가 나옴.
- **자동 완성 기능 (Tab Key)**
    - 명령어나 파일명의 일부만 입력하고 `Tab` 키를 누르면 자동 완성되거나 목록을 보여줌.
    - _교수님 강조_: 오타를 줄이고 작업 속도를 높이기 위해 적극적으로 활용할 것.
- **특수문자(Metacharacter)와 경로 이동**
    - **물결(`~`)**: 사용자의 **홈 디렉터리**를 의미. `~user2` 처럼 다른 사용자의 ID를 붙이면 그 사용자의 홈 디렉터리를 가리킴. (단, 권한이 없으면 파일 내용을 볼 수는 없음)
    - **대시(`-`)**: **이전 작업 디렉터리**로 이동. `cd ~`와 `cd -`는 명확히 다른 개념임.
    - **와일드카드 활용**: `*`는 모든 것, `?`는 한 글자, `[]`는 범위 내 한 글자를 의미하여 파일을 찾거나 복사할 때 유용함.

### **2. 💡 리눅스 관련 개념 정리**

- **인용 부호(Quotation Marks)의 차이**
    - **작은따옴표 (`' '`)**: 그 안의 모든 문자($, * 등)를 **단순 문자열**로 취급. 변수 치환이 일어나지 않음.
    - **큰따옴표 (`" "`)**: 대부분 문자로 취급하지만, **`$`(변수), `` ` ``(명령어), `\`(이스케이프)**는 해석하여 기능이 작동함.
    - **백쿼트 (`` ` ` ``)**: 내부에 있는 내용을 **명령어로 실행**하고 그 결과를 반환함 (예: `date` 명령 결과를 변수에 담거나 출력할 때).
    - **역슬래시 (`\`)**: 바로 뒤에 오는 특수문자의 속성을 제거(Escape). 예를 들어 `*`를 와일드카드가 아닌 별표 문자 자체로 쓰고 싶을 때 사용.
- **쉘 변수(Shell Variable) vs 환경 변수(Environment Variable)**
    - **쉘 변수 (지역)**: 현재 로그인한 쉘(Shell)에서만 유효. 자식 프로세스(서브 쉘)에는 상속되지 않음. 소문자 사용도 가능하나 관례상 대문자 사용.
    - **환경 변수 (전역)**: `export` 명령어로 설정. 현재 쉘뿐만 아니라 파생된 자식 쉘에서도 유효함. 시스템 설정(`PATH`, `USER` 등)에 주로 사용.
    - _주의사항_: 변수 선언 시 `변수명=값` 사이에 **공백(띄어쓰기)을 넣으면 안 됨**.
    - _터미널 간 독립성_: 한 터미널에서 변수를 바꿔도 다른 터미널에는 영향이 없음. 영구 적용하려면 `.bashrc`나 `.profile` 파일에 저장해야 함.
- **표준 입출력과 파일 디스크립터(File Descriptor)**
    - 리눅스는 장치도 파일로 취급하며, 번호(Descriptor)로 관리함.
    - **0번 (stdin)**: 표준 입력 (기본: 키보드)
    - **1번 (stdout)**: 표준 출력 (기본: 모니터)
    - **2번 (stderr)**: 표준 에러 (기본: 모니터)
- **리다이렉션(Redirection)**
    - 표준 입출력의 방향을 파일로 변경하는 것.
    - `>` : 명령의 결과를 화면 대신 파일에 저장. (파일이 없으면 생성, 있으면 **덮어쓰기**)
    - `noclobber`: 중요한 파일을 실수로 덮어쓰는 것을 방지하기 위한 옵션. (`set -o noclobber`로 켬)

### **2. 💡 리눅스 관련 개념 정리**

- **리다이렉션 심화 (`>>` vs `>`)**
    - `>`: 파일의 내용을 덮어씀 (Overwrite). 기존 내용은 사라짐.
    - `>>`: 파일의 맨 끝에 내용을 **추가 (Append)**. 기존 내용을 보존하면서 로그를 쌓을 때 유용함.
- **표준 출력(1) vs 표준 에러(2) 분리**
    - 리눅스는 정상적인 출력(stdout, 1번)과 오류 메시지(stderr, 2번)를 구분하여 처리함.
    - 명령어 실행 시 화면에는 둘 다 보이지만, 리다이렉션(`>`)은 기본적으로 **1번(표준 출력)만** 파일로 보냄.
    - 에러 메시지를 파일로 저장하려면 `2>`를 명시적으로 사용해야 함.
    - `2>&1`: 표준 에러(2)를 표준 출력(1)이 가리키는 곳으로 함께 보낼 때 사용 (예: `ls > result.txt 2>&1`).
- **`/dev/null` (Null Device)**
    - 일명 "데이터의 블랙홀" 또는 "휴지통".
    - 이곳으로 리다이렉션된 데이터는 어디에도 저장되지 않고 즉시 삭제됨. 불필요한 출력이나 에러 메시지를 보고 싶지 않을 때 사용함.
- **Alias (별칭)**
    - 복잡하거나 긴 명령어(옵션 포함)를 짧은 단어로 줄여서 사용하는 기능.
    - `rm` 명령에 `-i` 옵션(삭제 전 확인)을 붙여서 `alias rm='rm -i'`로 설정해두면 실수를 방지할 수 있음.
    - 설정 시 `변수='값'` 형태이며, 값에 공백이 포함될 경우 반드시 **작은따옴표('')**로 감싸야 함.
- **History (명령어 기록)**
    - 사용자가 입력한 명령어들을 저장해두는 기능.
    - `history` 명령어로 목록 확인 가능하며, 방향키(↑, ↓)를 이용해 이전 명령어를 불러와 수정하거나 재실행할 수 있어 오타 수정 및 반복 작업에 효율적임.

- **프롬프트 설정 (PS1 환경 변수)**
    - **정의**: 터미널에서 명령 입력을 기다리는 프롬프트의 모양을 결정하는 변수.
    - **주요 이스케이프 문자**:
        - `\u`: 사용자 이름 (User)
        - `\h`: 호스트 이름 (Host)
        - `\w`: 현재 디렉터리 전체 경로
        - `\W`: 현재 디렉터리 중 마지막 이름만
        - `\$`: 일반 사용자는 `$`, 루트 사용자는 `#` 표시
    - _실습 포인트_: `PS1` 변수 설정 시 공백이 포함되면 반드시 **작은따옴표('')**로 감싸야 함.
- **환경 설정 파일과 실행 순서**
    - **시스템 전역 (Global)**: `/etc/profile` → `/etc/bash.bashrc` (모든 사용자에게 공통 적용, 관리자만 수정 가능)
    - **사용자별 (Local)**: `~/.profile` → `~/.bashrc` (사용자 홈 디렉터리 내 존재, 사용자별 커스터마이징 가능)
    - **실행 시점**: 로그인 시 전역 설정 실행 후 사용자 설정 실행. (`source` 명령으로 로그아웃 없이 즉시 적용 가능)
    - **임시 vs 영구**: 터미널에서 `export`, `alias` 명령으로 설정한 내용은 **해당 세션(창)에서만 유효**함. 영구적으로 쓰려면 `.bashrc`나 `.profile` 등 **파일에 저장**해야 함.
- **파일 속성 및 권한 (Permission)**
    - `ls -l` 실행 시 출력되는 10자리 문자열의 의미:
        - **첫 글자**: 파일 유형 (`-`: 일반 파일, `d`: 디렉터리)
        - **나머지 9자리**: 소유자(User) / 그룹(Group) / 기타 사용자(Other) 순서로 3자리씩 권한 표시.
        - **권한 종류**:
            - `r` (Read, 4): 읽기 권한
            - `w` (Write, 2): 쓰기 권한 (파일 수정/삭제)
            - `x` (Execute, 1): 실행 권한 (디렉터리의 경우 진입 가능 여부)
    - **권한 해석 예시**: `rw-r--r--` (소유자는 읽기/쓰기 가능, 그룹과 기타는 읽기만 가능)
    - _주의사항_: `chmod 000` 등으로 모든 권한을 제거하면 소유자 자신도 접근 불가능해짐.
- **Umask (유마스크)**
    - 파일이나 디렉터리 생성 시 부여되는 **기본 권한을 제한**하는 값.
    - 예: 기본 파일 권한 666에서 umask가 002이면, 생성된 파일은 664 (`rw-rw-r--`)가 됨.

### **2. 💡 리눅스 관련 개념 정리**

- **생산자(Producer) 마인드**
    - _교수님 강조_: 개발자는 소비자(단순 사용자)가 아닌 생산자가 되어야 함. 눈으로만 코딩하지 말고 직접 타이핑하며 익숙해져야 함. AI가 발전해도 이를 활용해 무언가를 만들어내는 능력이 필요함.
- **파일 접근 권한 (Permission) 표기**
    - `ls -l` 시 나타나는 10자리 문자열 중 첫 글자는 파일 타입(`d`, `-`), 나머지 9자리는 3자리씩 끊어서 **소유자(User) / 그룹(Group) / 기타(Other)**의 권한을 나타냄.
    - 권한 종류: **R**(Read, 4), **W**(Write, 2), **X**(Execute, 1).
- **chmod (Change Mode)**
    - **문자 모드**: `u`, `g`, `o`, `a`(All)와 연산자 `+`(추가), `-`(제거), `=` (설정) 사용. (직관적이나 타이핑이 김)
    - **숫자 모드**: 8진수 사용. r(4)+w(2)+x(1)의 합계로 표현. (예: `rwx`=7, `rw-`=6, `r--`=4). 실무에서 가장 많이 사용됨.
- **Umask (유마스크)**
    - **정의**: 파일/디렉터리 생성 시 **"주지 않을 권한"**을 설정하는 마스크 값.
    - **계산법**:
        - 파일 최대 권한 **666** - Umask 값 = 최종 권한
        - 디렉터리 최대 권한 **777** - Umask 값 = 최종 권한
    - _예시_: Umask가 `002`면, 파일은 664(`rw-rw-r--`), 디렉터리는 775(`rwxrwxr-x`)로 생성됨.
    - _목적_: 다중 사용자 환경에서 내 파일의 보안을 기본적으로 유지하기 위함.
- **특수 권한 (Special Permissions)**
    - **SetUID (4000)**: 실행 파일에 설정. 실행하는 동안 **파일 소유자(Root 등)의 권한**으로 실행됨.
        - _예시_: `passwd` 명령어 (일반 사용자도 `/etc/shadow`를 수정해야 하므로 루트 권한이 잠시 필요함).
        - _표기_: 소유자 권한 자리에 `x` 대신 `s` (`rws------`).
    - **SetGID (2000)**: 실행 시 **파일 소유 그룹의 권한**으로 실행됨.
    - **Sticky Bit (1000)**: **디렉터리**에 설정. 누구나 파일을 만들 수 있지만, **삭제는 파일 소유자만** 가능함.
        - _예시_: `/tmp` 디렉터리 (공용 공간이지만 남의 파일을 함부로 지우면 안 됨).
        - _표기_: 기타 사용자 권한 자리에 `x` 대신 `t` (`rwxrwxrw**t**`).
    - _주의_: 실행 권한(x)이 없는 상태에서 특수 권한을 주면 대문자 `S`, `T`로 표시되며 동작하지 않음 (설정 오류).

### **2. 💡 리눅스 및 CS 관련 개념 정리**

- **문자 코드 (Character Code)**
    - **ASCII (아스키)**: 7비트 체계(128개 문자). 영어 대소문자, 숫자, 제어 문자 등을 표현.
        - _주요 제어 문자_: `0x00`(Null), `0x07`(Bell, 비프음 발생), `ACK/NAK`(통신 수신 확인용 비인쇄 문자).
        - _주요 16진수 값_: `'A'`(`0x41`), `'a'`(`0x61`), `'0'`(`0x30`). 대소문자 변환 시 비트 연산에 활용됨.
    - **Unicode (유니코드)**: 전 세계 모든 문자를 통합한 표준. `UTF-8`은 가변 길이(1~4바이트) 인코딩 방식으로 리눅스 표준으로 사용됨.
    - **한글 코드 체계**:
        - **조합형**: 초성(5bit)+중성(5bit)+종성(5bit)+여분(1bit)으로 구성. 현대 한글 외 고어 표현 가능. (과거 아래아한글 방식)
        - **완성형**: 완성된 글자 자체에 코드를 부여. (과거 MS 워드 방식, 호환성 문제 있었음)
        - _현재_: 유니코드를 통해 통합됨.
- **그레이 코드 (Gray Code)**
    - 인접한 숫자 간에 **단 1개의 비트만 변경**되는 코드 체계.
    - 디지털 논리 회로의 카르노맵(K-Map) 간소화나 오류 검출 등에 사용됨.
- **`find` 명령어의 동작 원리**
    - 지정한 디렉터리 하위를 재귀적으로 탐색함.
    - **`-exec` 구문 해석**:
        - `{}`: 검색된 파일의 경로가 들어가는 자리.
        - `\;`: 명령어의 끝을 알리는 기호(쉘이 해석하지 못하게 `\`를 붙임).
    - _활용_: 단순히 찾는 것을 넘어, 찾은 파일을 이동(`mv`), 복사(`cp`), 삭제(`rm`)하는 자동화 작업에 필수적임.

### **2. 💡 리눅스 관련 개념 정리**

- **파일 검색 명령어의 차이 (`find` vs `whereis` vs `which`)**
    - `find`: 사용자가 지정한 디렉터리 하위를 샅샅이 뒤져서 찾음 (범용적).
    - `whereis`: 시스템이 미리 지정한 표준 디렉터리(바이너리, 매뉴얼 경로 등)에서만 빠르게 찾음.
    - `which`: 사용자가 명령어를 입력했을 때 실제 실행되는 파일의 위치를 `$PATH`에서 찾음 (Alias 설정 확인 가능).
- **정규 표현식 (Regular Expression)**
    - **기본 정규식 (`grep`)**:
        - `.`: 임의의 한 문자 (`a..b` → a와 b 사이 두 글자)
        - `^`: 행의 시작 (`^a` → a로 시작하는 행)
        - `$`: 행의 끝 (`a$` → a로 끝나는 행)
        - `*`: 앞 문자가 **0번 이상** 반복 (`a*t` → t, at, aat, aaat 등) [**주의**: 파일 와일드카드 `*`와 다름]
        - `[]`: 괄호 안의 문자 중 하나 (`[Ll]` → L 또는 l)
    - **확장 정규식 (`egrep` 또는 `grep -E`)**:
        - `?`: 앞 문자가 **0번 또는 1번** 존재 (`p?le` → le, ple)
        - `+`: 앞 문자가 **1번 이상** 반복 (`o+` → o, oo, ooo …)
        - `|`: OR 연산 (`a|b` → a 또는 b)
        - `()`: 그룹화 (`(to)+` → to, toto, tototo …)
- **정렬과 중복 제거 (`sort` & `uniq`)**
    - `sort`는 기본적으로 문자를 텍스트(ASCII) 순서로 정렬함. (숫자 정렬 시 `-n` 옵션 필요)
    - **중요**: `uniq` 명령어는 **인접한(연속된) 중복만 제거**함. 떨어져 있는 중복은 제거하지 못함.
    - 따라서 중복을 완벽히 제거하려면 **반드시 정렬을 먼저 수행**해야 함.
    - _파이프라인 활용_: `sort sample.txt | uniq` (정렬 후 중복 제거가 정석 패턴).
- **리다이렉션 주의사항 (`>`)**
    - `sort data.txt > data.txt` 처럼 입력 파일을 그대로 출력 파일로 지정하면, 쉘이 파일을 먼저 비워버리기 때문에 **내용이 다 날아감**.
    - 이를 방지하기 위해 `sort -o data.txt data.txt` 옵션을 사용하거나 다른 이름으로 저장해야 함.

### **2. 💡 리눅스 관련 개념 정리**

- **파일 비교 (`diff` vs `cmp`)**
    - **`diff`**: 텍스트 파일의 **내용(행)**이 어떻게 다른지 알려줌.
        - 출력 기호: `c` (Change), `d` (Delete), `a` (Add).
        - `<`: 첫 번째 파일 내용, `>`: 두 번째 파일 내용.
    - **`cmp`**: 두 파일이 **몇 번째 바이트**부터 다른지 알려줌. 텍스트가 아닌 **바이너리 파일(실행 파일, 이미지 등) 비교**에 주로 사용됨.
- **파일 분할과 병합 (`split` & `paste`)**
    - **`split`**: 대용량 로그 파일이나 데이터를 처리하기 쉽게 쪼갤 때 사용. 접두어(Prefix)를 지정하지 않으면 `xaa`, `xab`… 형태로 생성됨.
    - **`paste`**: `cat` 명령어가 파일을 **세로(위아래)**로 합친다면, `paste`는 파일을 **가로(옆)**로 합침. (엑셀에서 열을 붙이는 것과 유사)
- **데이터 추출 (`cut`)**
    - 텍스트 파일이나 명령어 출력 결과에서 **원하는 열(Column)만 뽑아낼 때** 필수적인 명령어.
    - _예시_: `/etc/passwd` 파일에서 사용자 아이디만 뽑고 싶을 때 → 구분자(`:`)와 필드 번호(`1`)를 사용 (`cut -d: -f1`).
    - _역사적 배경_: 과거 `vi` 편집기 등은 "블록 지정 복사/잘라내기" 기능이 약했기 때문에, 이러한 명령어로 데이터를 가공하는 것이 중요했음.

이번 강의에서는 **프로세스(Process)와 스레드(Thread)의 차이점**, **시스템 프로세스(Systemd, kthreadd)**, 그리고 **프로세스 간 통신(IPC)과 네트워크 주소 체계**에 대한 심화 이론이 다뤄졌습니다.

---

### **💡 핵심 개념 정리**

- **프로세스(Process) vs 스레드(Thread)**
    

|**구분**|**프로세스 (Process)**|**스레드 (Thread)**|
|---|---|---|
|**정의**|실행 중인 프로그램의 인스턴스. 운영체제로부터 자원을 할당받는 단위.|프로세스 내에서 실행되는 흐름의 단위.|
|**자원 할당**|독립된 메모리 영역(Code, Data, Heap, Stack)을 할당받음.|프로세스의 자원(Code, Data, Heap)을 **공유**함. (Stack만 독립적)|
|**통신**|서로 독립적이므로 IPC(Inter-Process Communication)가 필요함.|자원을 공유하므로 변수 등을 통해 직접 통신 가능.|
|**비유**|크롬 브라우저를 실행하는 것 (작업 관리자에서 여러 개 보임).|크롬 내에서 탭(Tab)을 여러 개 여는 것.|
|**특징**|안정성이 높음 (하나가 죽어도 다른 프로세스에 영향 적음). 오버헤드 큼.|문맥 교환(Context Switch)이 빠름. 하나가 죽으면 전체 프로세스 종료 위험.|

- **리눅스 시스템 프로세스 (System Process)**
    - **systemd (PID 1)**:
        - 리눅스 부팅 시 **최초로 실행되는 프로세스**. (모든 프로세스의 조상)
        - 시스템 초기화, 서비스 관리, 부팅 과정 병렬 처리 등을 담당. (과거 `init` 프로세스를 대체)
    - **kthreadd (PID 2)**:
        - **커널 스레드(Kernel Thread)의 부모** 프로세스.
        - 커널 공간에서만 실행되며, 메모리 관리, 디스크 동기화 등 백그라운드 작업을 처리하는 스레드들을 생성 및 관리.
- **프로세스의 생명 주기 (Life Cycle)**
    - **생성 (fork)**: 부모 프로세스가 `fork()` 시스템 콜을 통해 자식 프로세스를 생성. (자신을 복제)
    - **실행 (exec)**: 생성된 자식 프로세스가 `exec()`를 통해 새로운 프로그램 코드를 실행.
    - **종료 (exit)**: 자식 프로세스가 `exit()`를 호출하여 종료 신호(Return Code)를 보냄.
    - **회수 (wait)**: 부모 프로세스는 `wait()` 상태에서 자식의 종료 신호를 기다림. 신호를 받으면 자원을 회수함.
    - _좀비 프로세스 (Zombie)_: 자식이 종료되었으나, 부모가 `wait()`를 하지 않아 자원이 회수되지 않고 종료 상태만 남아 있는 프로세스.
    - _고아 프로세스 (Orphan)_: 부모가 자식보다 먼저 종료되어 버린 프로세스. (보통 `systemd`가 입양하여 처리함)
- **네트워크 통신과 프로세스**
    - **프로세스 간 통신 (IPC)**: 독립적인 프로세스들이 데이터를 주고받기 위한 메커니즘 (파이프, 소켓, 공유 메모리 등).
    - **통신 주소 3단계**:
        
        1. **물리 주소 (MAC)**: 랜카드 고유 번호 (하드웨어 식별).
        2. **논리 주소 (IP)**: 네트워크 상의 호스트 식별 (`127.0.0.1`은 자기 자신을 가리키는 루프백 주소).
        3. **포트 번호 (Port)**: 호스트 내에서 실행 중인 **특정 프로세스 식별** (예: 웹 서버는 80번).
            
    - _핵심_: 네트워크 통신(TCP/IP)은 결국 서로 다른 컴퓨터에 있는 **프로세스 간의 통신**임.

### **2. 💡 리눅스 관련 개념 정리**

- **프로세스 모니터링 (`ps` 명령어의 주요 항목)**
    - **PID (Process ID)**: 프로세스 고유 식별 번호. (예: `kill` 명령어로 종료할 때 필요)
    - **PPID (Parent PID)**: 부모 프로세스의 ID. (누가 이 프로세스를 실행했는지 확인 가능)
    - **TTY**: 프로세스가 실행된 터미널 번호. (`?`는 터미널 없이 실행되는 데몬이나 시스템 프로세스)
    - **TIME**: 프로세스가 사용한 누적 CPU 시간.
    - **CMD**: 실행된 명령어 이름.
    - **%CPU / %MEM**: CPU와 메모리 사용률 (부하 원인 파악 시 중요).
    - **STAT (상태)**:
        - `R` (Running): 실행 중.
        - `S` (Sleeping): 대기 중 (대부분의 프로세스 상태).
        - `Z` (Zombie): 종료되었으나 부모가 회수하지 않은 상태.
        - `T` (Stopped): 정지됨.
- **멀티 태스킹과 Time Slicing (시분할)**
    - CPU는 한 번에 하나의 명령만 처리할 수 있음.
    - 하지만 **Quantum Time(아주 짧은 시간 슬롯)** 단위로 여러 프로세스를 번갈아 가며 빠르게 실행함으로써, 사용자는 동시에 여러 프로그램이 실행되는 것처럼 느낌. (Context Switching)
- **데몬(Daemon) 프로세스**
    - 백그라운드에서 실행되며 특정 요청을 기다리는 서비스 프로세스.
    - 예: `httpd` (웹 요청 대기), `sshd` (원격 접속 요청 대기).
    - 보통 시스템 부팅 시 자동 실행되며 터미널(`TTY`)이 할당되지 않음.
- **고아(Orphan) & 좀비(Zombie) 프로세스**
    - **고아**: 부모가 먼저 죽어버린 자식 프로세스. 보통 `init(systemd)` 프로세스(PID 1)가 입양하여 관리함.
    - **좀비**: 자식이 죽었는데 부모가 종료 상태를 회수(`wait`)하지 않아, 프로세스 테이블에 껍데기만 남아있는 상태. 시스템 리소스(PID 번호 등)를 낭비하므로 관리가 필요함.
- **네트워크와 로컬 통신 (Loopback)**
    - **127.0.0.1 (Localhost)**: 자기 자신을 가리키는 IP 주소.
    - 외부 네트워크를 거치지 않고 내부 프로세스 간 통신 테스트(예: 웹 서버 개발) 시 사용됨.

|`pgrep`|`-u [사용자]`|특정 사용자의 프로세스만 검색|`pgrep -u user1 bash`|
|`tty`|(없음)|현재 연결된 터미널의 파일명 확인 (`/dev/pts/0` 등)|`tty`|
|`kill`|`[PID]`|PID를 지정하여 해당 프로세스 종료|`kill 1234`|
|`kill`|`-9 [PID]`|(강제 종료) 프로세스를 즉시 강제로 종료|`kill -9 1234`|
|`pkill`|`[패턴]`|프로세스 **이름(패턴)**을 사용하여 종료 (정규식 가능)|`pkill bash`|
|`killall`|`[이름]`|프로세스 **이름이 정확히 일치**하는 모든 프로세스 종료|`killall bash`|
|**조합**|`ps -fp $(pgrep -x bash)`|`pgrep`으로 찾은 PID를 `ps`에 전달하여 상세 정보 확인|`ps -fp $(pgrep -x bash)`|

### **3. 💡 리눅스 관련 개념 정리**

- **터미널의 종류 (`TTY` vs `PTS`)**
    - **TTY (TeleTypewriter)**: 서버 본체에 직접 연결된 물리적 콘솔(키보드/모니터)이나 가상 콘솔. (`/dev/tty1` ~ `/dev/tty6`)
        - _접근_: `Ctrl + Alt + F1` ~ `F6` 키로 전환 가능.
    - **PTS (Pseudo Terminal Slave)**: 네트워크(SSH, Telnet)나 GUI 터미널 창(xterm)을 통해 원격/가상으로 연결된 터미널. (`/dev/pts/0`, `/dev/pts/1` …)
        - _특징_: 여러 개의 창을 띄울 때마다 번호가 증가함.
- **프로세스 종료 명령어 비교 (`kill` vs `pkill` vs `killall`)**
    - **`kill`**: **PID(숫자)**를 알아야 종료 가능. 가장 기본적이고 정확함.
    - **`pkill`**: **이름(문자열)**로 종료. 이름의 일부만 맞아도 되며 정규 표현식 사용 가능. (예: `pkill firefox` 하면 열려있는 모든 파이어폭스 창 종료)
    - **`killall`**: **이름(문자열)**로 종료하되, **정확한 전체 이름**을 입력해야 함. 같은 이름으로 실행 중인 모든 프로세스를 한 번에 종료할 때 유용.
- **프로세스 제어 권한**
    - 일반 사용자는 **자신이 실행한 프로세스만** 종료(`kill`)할 수 있음.
    - 다른 사용자의 프로세스나 시스템 프로세스를 종료하려면 `root` 권한(`sudo`)이 필요함.
- **실습 팁**
    - `man` 명령어를 실행해 둔 상태여야 프로세스 목록에 `man`이 보이고 종료 실습이 가능함. `man` 창을 닫으면 프로세스도 사라지므로 검색되지 않음.
    - 명령어 조합(`$()`)을 사용하면 `pgrep`의 결과(PID)를 바로 `ps`나 `kill`의 인자로 넘겨 효율적으로 작업할 수 있음.

### **3. 💡 리눅스 관련 개념 정리**

- **시그널 (Signal)**
    - 운영체제가 프로세스에게 특정 이벤트(종료, 정지 등)를 알리는 메시지.
    - **주요 시그널 번호**:
        - **2번 (SIGINT)**: 인터럽트 신호. 키보드 `Ctrl + C` 입력 시 발생. (정상 종료 요청)
        - **9번 (SIGKILL)**: **강제 종료**. 프로세스가 무시하거나 차단할 수 없음. 좀비 프로세스 정리 등에 사용.
        - **15번 (SIGTERM)**: 종료 신호. `kill` 명령어의 기본값. 프로세스가 정상적으로 정리하고 종료하도록 요청함.
- **`nohup` (No Hang Up)**
    - **목적**: 터미널 세션이 끊어지거나 로그아웃을 해도 백그라운드 작업이 중단되지 않고 계속 실행되게 함.
    - **출력**: 실행 결과는 기본적으로 `nohup.out` 파일에 저장됨.
- **계정 관리 파일 (`/etc/passwd` vs `/etc/shadow`)**
    - **`/etc/passwd`**:
        - 사용자 계정 정보(ID, UID, GID, 홈 디렉터리, 쉘 등)를 담고 있음.
        - **보안 취약점**: 과거에는 암호도 여기에 저장되었으나, 누구나 읽을 수 있어 보안상 위험했음. 현재는 암호 자리에 `x`로 표시됨.
    - **`/etc/shadow`**:
        - 실제 **암호화된 비밀번호**와 암호 만료일, 계정 잠금일 등의 보안 정보를 담고 있음.
        - **보안 강화**: `root` 사용자(또는 `shadow` 그룹)만 읽을 수 있도록 권한이 제한됨 (`r--------`).
        - _필드 의미_: 암호화된 암호, 마지막 변경일(1970.1.1 기준 일수), 변경 최소/최대 기간, 만료 경고 기간 등.

### **3. 💡 리눅스 관련 개념 정리**

- **사용자 전환 (`su` vs `sudo`)**
    - **`su` (Switch User)**: 로그아웃 하지 않고 다른 사용자로 로그인하는 것. `su -`를 사용해야 환경 변수까지 완벽하게 전환됨. (루트 암호를 공유해야 하므로 보안상 비권장)
    - **`sudo` (SuperUser Do)**: 일반 사용자가 자신의 암호로 **일시적으로 관리자 권한**을 빌려 쓰는 것. `/etc/sudoers` 파일에 등록된 사용자만 가능하며, 보안 추적(로깅)이 용이함.
- **아카이브 vs 압축 (`tar`)**
    - **아카이브 (Archive)**: 여러 개의 파일과 디렉터리를 **하나의 파일로 묶는 것**. 용량은 줄어들지 않음. (예: `tar`)
    - **압축 (Compress)**: 데이터의 중복을 제거하여 **용량을 줄이는 것**. (예: `gzip`, `bzip2`)
    - _리눅스 관례_: 보통 `tar`로 묶고 `gzip`으로 압축하여 `.tar.gz` (또는 `.tgz`) 확장자를 많이 사용함.
- **디스크와 램(RAM)의 속도 차이**
    - 하드디스크(HDD)는 물리적인 회전(RPM)을 통해 데이터를 읽으므로 속도가 느림.
    - 운영체제는 속도 향상을 위해 자주 쓰는 데이터를 **램(RAM)에 캐싱(Caching)**하거나, 램의 일부를 디스크처럼 사용하는 **램 디스크(Ramdisk, `/run` 등)** 기법을 사용함. (단, 전원 꺼지면 데이터 소멸)
