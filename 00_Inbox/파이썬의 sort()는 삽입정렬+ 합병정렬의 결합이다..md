## 정리
파이썬의 `list.sort()`와 내장 함수 `sorted()`는 **팀 정렬 (Timsort)**이라는 알고리즘을 사용합니다.

이것은 2002년 파이썬의 핵심 개발자인 **팀 피터스(Tim Peters)**가 만든 알고리즘으로, 앞서 배우신 정렬 알고리즘들의 장점만을 결합한 **하이브리드(Hybrid)** 방식입니다.

---

### 1. 팀 정렬 (Timsort)의 핵심 원리

팀 정렬은 **삽입 정렬(Insertion Sort)**과 **합병 정렬(Merge Sort)**을 결합했습니다.

1. **현실 데이터의 특성 활용:**
    
    - 완전 무작위 데이터보다는, **"이미 부분적으로 정렬된 데이터(Run)"**가 현실 세계에 더 많다는 점에 착안했습니다.
        
2. **삽입 정렬의 장점 활용:**
    
    - 데이터가 **작거나(Small chunk)**, **거의 정렬되어 있을 때($O(N)$)** 가장 빠르다는 점을 이용합니다.
        
3. **합병 정렬의 장점 활용:**
    
    - 데이터를 분할하고 합칠 때 안정적인 $O(N \log N)$ 성능을 낸다는 점을 이용합니다.
        

### 2. 동작 과정 (요약)

1. 전체 배열을 작은 덩어리(Run)로 자릅니다. (보통 32개~64개 단위)
2. 각 작은 덩어리는 **삽입 정렬**로 정렬합니다. (작은 단위에서는 퀵/합병보다 삽입 정렬이 빠르기 때문)
3. 정렬된 덩어리들을 **합병 정렬**의 메커니즘을 사용하여 하나로 병합(Merge)합니다.
    

### 3. 성능 및 시간 복잡도

| **케이스**          | **시간 복잡도**        | **설명**                                    |
| ---------------- | ----------------- | ----------------------------------------- |
| **최선 (Best)**    | **$O(N)$**        | 이미 정렬된 데이터인 경우 (삽입 정렬의 장점)                |
| **평균 (Average)** | $O(N \log N)$     | 일반적인 무작위 데이터                              |
| **최악 (Worst)**   | **$O(N \log N)$** | 역순 정렬 등 최악의 경우에도 퀵 정렬($O(N^2)$)과 달리 성능 보장 |
| **공간 복잡도**       | $O(N)$            | 합병 정렬 기반이므로 추가 메모리 필요                     |
| **안정성**          | **Stable**        | 값이 같을 때 기존 순서가 유지됨                        |

### 4. 왜 퀵 정렬(Quick Sort)을 안 쓰나요?

C언어의 `qsort`나 C++의 `std::sort`(인트로 정렬: 퀵+힙+삽입)는 퀵 정렬 기반이지만, 파이썬은 **안정성(Stable)**과 **최선 경우의 효율성**을 더 중시했기 때문입니다.

- **퀵 정렬:** 빠르지만 불안정 정렬(Unstable)이고, 최악의 경우 $O(N^2)$입니다.
- **팀 정렬:** 안정 정렬(Stable)이면서, **이미 정렬된 데이터에 대해 압도적으로 빠릅니다.** (코딩 테스트나 실무에서 정렬된 데이터에 자료를 추가하고 다시 정렬하는 경우가 잦음)
    

> **참고:** Timsort의 성능이 워낙 뛰어나서 현재는 **Java (Arrays.sort 객체 정렬), Android, Google Chrome (V8 엔진), Swift** 등 수많은 언어와 플랫폼에서 표준 정렬 알고리즘으로 채택되었습니다.
