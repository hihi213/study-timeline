## Topic 1. DFS (Depth First Search) 복습 & 구현 기준

### 1. 🏗️ 빌드업 (Why & Context)

> 지난 시간 개념 복습 및 프로그래밍 구현 시의 표준화 필요성

- **핵심 메커니즘:** 방문한 노드를 `visited`로 표시하고, 인접 노드 중 방문하지 않은 곳으로 깊게 들어간다. 더 이상 갈 곳이 없으면(Dead-end), **스택(Stack)**을 `pop`하여 이전 분기점으로 되돌아온다(Backtracking).
- **자료구조:** **스택(Stack)** (또는 재귀 호출).
### Concept

- **정의:** 시작 정점에서 한 방향으로 갈 수 있는 데까지 깊게 탐색하다가 막히면 가장 가까운 갈림길로 돌아와 다른 방향을 탐색하는 방식.
- **구현 규칙 (교수님 강조):**
    - 방문 순서의 **일관성(Standardization)**을 위해 인접 노드가 여러 개일 경우 **오름차순(Ascending Order)**으로 방문한다.
    - 예: A에서 B, C로 갈 수 있다면 B를 먼저 방문.
    - 이는 `for(i=0; i<N; i++)` 형태의 반복문 구조와 자연스럽게 매핑되어 코딩 실수(Human Error)를 줄인다.
        

### Code 구현 (논리적 흐름)



```C
// DFS 논리적 구조 (재귀 or 스택)
void DFS(int v) {
    visited[v] = TRUE; // 1. 현재 노드 방문 처리
    printf("%d ", v);

    // 2. 인접 노드 탐색 (오름차순)
    for (node w = start; w < end; w++) {
        // 인접해 있고(connected) && 방문하지 않았다면(!visited)
        if (is_connected(v, w) && !visited[w]) {
            DFS(w); // 3. 재귀 호출 (깊게 들어감)
        }
    }
    // 4. 더 이상 갈 곳이 없으면 함수 종료(=Stack Pop, Backtrack)
}
```

## Topic 2. BFS (Breadth First Search) 개념 & 원리

### 1. 🏗️ 빌드업 (Why & Context)

> "여행을 갈 때 서울 주변(수원, 인천, 김포)을 먼저 다 보고, 그 다음 단계로 넘어가는 방식"

- **문제 제기:** DFS는 한 우물만 파기 때문에 최단 경로(간선 개수 기준)를 보장하지 않음. 시작점에서 가까운 순서대로 탐색할 필요성 존재.
- **핵심 아이디어:** 퍼저나간다. 시작점 기준 거리(간선 수)가 1인 노드들을 모두 방문 후, 거리가 2인 노드들을 방문한다.
    

### Concept

- **핵심 자료구조:** **큐 (Queue)** (FIFO - 먼저 들어온 놈이 먼저 나간다).
- **작동 원리:**
    
    1. 시작 노드를 큐에 넣고(Enqueue), 방문 표시.
    2. 큐에서 노드를 하나 꺼냄(Dequeue) -> `V`.
    3. `V`와 인접한 노드 중 방문하지 않은 **모든** 노드를 큐에 넣고 방문했다고 표시.
    4. 큐가 빌 때까지(Empty) 반복.
        
- **특징:** 깊게 들어가는 것이 아니라 옆으로(너비로) 먼저 퍼짐.

## Topic 3. BFS 순회 시뮬레이션 (함정 주의)

### 1. 🏗️ 빌드업 (Why & Context)

> "시험 문제 내면 다 틀리는 포인트: 시작점이 A가 아닐 때"

- **경고:** 시작점이 루트(A)일 때는 직관적으로 풀기 쉽지만, 중간 노드(예: E, F)에서 시작하면 DFS와 혼동하여 순서를 틀리는 경우가 많음.
- **오개념 경계:** 방금 큐에 넣은 노드에서 바로 다시 출발하려 하면 안 됨(이건 DFS임). 반드시 **큐에서 Dequeue한 노드**를 기준으로 인접 노드를 찾아야 함.
    

### Concept: Node 'E' 시작 시뮬레이션

- **그래프 상황 가정:** (구두 설명 기반 재구성)
    - E와 인접한 노드: B, C, G
    - B와 인접: A, D … 등등
- **Trace (추적 과정):**
    
    1. **Start E:** `Queue: [E]`, `Visited: {E}`
    2. **Dequeue E:** E의 인접 노드(B, C, G) 확인.
        
        - `Queue: [B, C, G]`, `Visited: {E, B, C, G}`
            
    3. **Dequeue B:** B의 인접 노드 중 안 가본 곳(A, D) 확인.
        
        - `Queue: [C, G, A, D]`, `Visited: {…, A, D}` (⚠️ 중요: C나 G로 바로 점프하는 게 아니라 B의 이웃을 큐 뒤에 붙임)
            
    4. **Dequeue C:** C의 인접 노드 확인 (이미 다 갔다면 패스).
    5. **Dequeue G:** G의 인접 노드(F) 확인.
        
        - `Queue: […, F]`, `Visited: {…, F}`
    - **최종 순서:** E -> B -> C -> G -> A -> D -> F (그래프 연결 상태에 따라 달라지나, 핵심은 **레벨 단위 방문**)
        

### Code 구현



```C
void bfs_mat(GraphType* g, int v) {
    int w;
    QueueType q;
    init_queue(&q);     // 큐 초기화
    
    visited[v] = TRUE;  // 1. 시작점 방문
    printf("%d ", v);
    enqueue(&q, v);     // 2. 큐에 삽입
    
    while (!is_empty(&q)) {
        v = dequeue(&q); // 3. 큐에서 기준점 꺼냄
        
        // 4. 꺼낸 정점(v)의 모든 인접 정점(w) 탐색
        for (w = 0; w < g->n; w++) {
            if (g->adj_mat[v][w] && !visited[w]) {
                visited[w] = TRUE; // 방문 표시
                printf("%d ", w);
                enqueue(&q, w);    // 큐에 삽입
            }
        }
    }
}
```

## Topic 4. 그래프 구현과 시간 복잡도

### 1. 🏗️ 빌드업 (Why & Context)

> "인접 행렬로 짤래? 인접 리스트로 짤래?"

- **Context:** 그래프를 코드로 표현하는 방식에 따라 알고리즘의 성능($O$)이 달라진다.
    

### Concept: 시간 복잡도 비교

- **인접 행렬:** $O(N^2)$ (모든 정점 $N$ $\times$ 행 검사 $N$)
	- 정점 $V$ 하나에 대해 모든 정점($N$개)을 다 찔러봐야 연결 여부를 알 수 있음.
- **인접 리스트:** $O(N + E)$ (모든 정점 $N$ + 모든 간선 $E$)
	- 정점 $V$에 연결된 간선($E$)만큼만 확인하면 됨.
    - 희소 그래프(Sparse Graph)일수록 인접 리스트가 유리하다.

### 💡 Interview

> [!faq]- Q. DFS와 BFS의 결정적 차이와 각각의 적합한 사용처는?
>
> 🗣️ 핵심 답변
>
> DFS는 **스택(또는 재귀)**을 사용하여 깊이 우선으로 탐색하며, 미로 찾기나 모든 경로를 탐색해야 할 때 적합합니다.
>
> 반면, BFS는 큐를 사용하여 너비 우선으로 탐색하며, 가중치가 없는 그래프에서 최단 경로를 찾을 때 필수적으로 사용됩니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q: 왜 BFS가 최단 경로를 보장하는가?**
>     
> - A: BFS는 시작점에서 간선 1개 거리의 노드를 모두 방문한 뒤 간선 2개 거리로 넘어가므로, 목적지에 처음 도달했을 때가 가장 적은 간선을 거친 상태임이 보장됩니다.
>     

> [!faq]- Q. 인접 행렬과 인접 리스트 중 어떤 것이 효율적인가?
>
> 🗣️ 핵심 답변
>
> 그래프의 간선 밀도(Density)에 따라 다릅니다. 간선이 적은 **희소 그래프(Sparse Graph)**에서는 메모리와 탐색 속도 면에서 $O(N+E)$인 인접 리스트가 훨씬 효율적입니다. 반면, 모든 노드가 연결된 밀집 그래프에서는 구현이 간단한 인접 행렬($O(N^2)$)을 고려할 수 있습니다.

> [!faq]- Q. 그래프 탐색 시 방문 여부(visited 배열)를 체크하지 않으면 어떤 문제가 발생하는가?
>
> 🗣️ 핵심 답변
>
> 그래프에 **사이클(Cycle)**이 존재할 경우, 이미 방문한 노드를 계속해서 다시 방문하게 되어 **무한 루프(Infinite Loop)**에 빠지게 됩니다. 이는 프로그램의 종료를 막고 스택 오버플로우(DFS)나 메모리 초과(BFS)를 유발합니다.

## Topic 1. 연결 성분 (Connected Component)

### 1. 🏗️ 빌드업 (Why & Context)

> 그래프가 하나로 다 연결되어 있지 않고, 여러 개의 섬(Island)처럼 끊어져 있다면 어떻게 구분할 것인가?

- **문제 제기:** 단순히 `DFS(0)`만 호출하면, 0번 노드와 연결되지 않은 다른 노드들은 방문할 수 없다. 그래프 전체가 몇 개의 덩어리로 이루어져 있는지 파악해야 한다.
- **해결 아이디어:** 반복문을 통해 모든 정점을 순회하며, 아직 방문하지 않은 정점에 대해 탐색(DFS/BFS)을 새롭게 시작한다.
    

### Concept

- **정의:** 그래프 상에서 정점들이 서로 연결되어 있는 부분 그래프 중 크기가 가장 큰 것(Maximally Connected).
- **탐색 로직:**
    
    1. `visited` 배열을 단순 `Boolean`이 아닌 **그룹 ID(Counter)** 등을 저장하도록 변경 (선택 사항).
    2. 모든 정점 $V$에 대해 `for` 루프를 돌며 방문 여부 확인.
    3. 방문하지 않은 정점이 발견되면, 그곳을 시작점으로 DFS/BFS 수행 $\rightarrow$ 하나의 연결 성분 발견.
    4. 모든 정점을 방문할 때까지 반복.
        

### Code 구현


```C
// 연결 성분 찾는 전체 로직
void find_connected_components(GraphType* g) {
    int count = 0; // 연결 성분 개수 (Group ID)
    
    // 1. 모든 정점에 대해 순회
    for (int i = 0; i < g->n; i++) {
        if (!visited[i]) { // 2. 아직 방문 안 한 정점 발견 (새로운 섬)
            count++;
            printf("Connected Component %d: ", count);
            DFS(g, i); // 3. 해당 정점과 연결된 모든 노드 방문 처리
            printf("\n");
        }
    }
}
```

## Topic 2. 신장 트리 (MST)

### 1. 🏗️ 빌드업 (Why & Context)

> "도시의 모든 건물을 연결하되, 도로 건설 비용(간선 수)을 최소화하려면?"

- **핵심 아이디어:** 모든 노드를 방문해야 하지만, 굳이 중복 경로(Cycle)를 만들 필요는 없다.
- **필요성:** 통신 네트워크 구축, 배관 설계 등에서 모든 지점을 연결하면서도 자원을 최소로 써야 하는 상황.
### Concept

- **최소비용신장트리:** 그래프 $G$의 모든 정점($V$)을 포함하는 부분 그래프(Subgraph)이자, **트리(Tree)** 의 속성을 갖는 형태.
- **핵심 조건:**
    
    1. **모든 정점**이 연결되어야 함 (Connected).
    2. **사이클(Cycle) 없음** (트리의 필수 조건.)
    3. 정점이 $N$개일 때, 간선은 정확히 $N-1$개여야 함.
        
- **종류:**
    - **DFS 신장 트리:** 깊이 우선 탐색을 수행하며 사용된 간선들로 구성.
    - **BFS 신장 트리:** 너비 우선 탐색을 수행하며 사용된 간선들로 구성.
        

### Code 구현 (개념적 수정)

```C
// DFS를 이용한 신장 트리 간선 표시
void DFS_SpanningTree(int v) {
    visited[v] = TRUE;
    
    for (node w = start; w < end; w++) {
        if (is_connected(v, w) && !visited[w]) {
            // v와 w를 연결하는 간선은 신장 트리의 구성 요소임
            printf("Tree Edge: (%d, %d)\n", v, w); 
            DFS_SpanningTree(w);
        }
    }
}
```

## Topic 3. 최소 비용 신장 트리 (MST, Minimum Spanning Tree)

### 1. 🏗️ 빌드업 (Why & Context)

> "그냥 연결하는 게 아니라, '가장 싸게' 연결해야 한다."

- **Context:** 현실 세계의 간선은 똑같지 않다. 가중치(Weight)가 존재한다 (비용, 거리, 시간 등).
- **문제 제기:** 단순히 간선 수만 $N-1$개라고 최적이 아니다. 간선의 **가중치 합**이 최소가 되어야 한다.
- **예시:**
    - 도로 건설: 직선이 짧지만 토지 보상비(알박기)가 비싸면 우회하는 게 더 저렴할 수 있음.
    - 내비게이션: 최단 거리 vs 최단 시간 vs 무료 도로 (가중치 기준의 차이).
    - PCB 설계: 회로 연결 시 금(Gold) 와이어 길이를 최소화해야 원가 절감.
        

### Concept

- **최소비용신장트리(MST):** 무방향 가중치 그래프에서 신장 트리를 구성하는 간선들의 **가중치 합이 최소**인 트리.
- **핵심 접근법: 그리디 알고리즘 (Greedy Algorithm)**
	- **개념:** 매 순간 가장 좋아 보이는(가장 싼) 선택을 하여 최종 해답에 도달하는 방식.
	- **검증 필요성:** 그리디는 항상 최적해를 보장하지 않으므로 증명이 필요하다. 다행히 MST 문제에서는 Kruskal과 Prim 알고리즘 모두 **최적해를 보장함**이 증명되었다.
- **대표 알고리즘 (예고):**
    1. **Kruskal Algorithm**
    2. **Prim Algorithm**

### 💡 Interview

> [!faq]- Q. 신장 트리(Spanning Tree)와 최소 비용 신장 트리(MST)의 차이점은?
>
> 🗣️ 핵심 답변
>
> 신장 트리는 그래프의 모든 정점을 사이클 없이 $N-1$개의 간선으로 연결한 부분 그래프를 말하며, MST는 이러한 신장 트리들 중에서 간선의 가중치 합이 가장 작은 트리를 의미합니다. 즉, MST는 가중치 그래프에서 비용 효율성을 극대화한 신장 트리입니다.

> [!faq]- Q. 그리디 알고리즘(Greedy Algorithm)이란 무엇이며, MST에서 어떻게 적용되는가?
>
> 🗣️ 핵심 답변
>
> 그리디 알고리즘은 매 순간 최적이라고 생각되는 선택을 하는 방식입니다. MST를 구하는 Kruskal 알고리즘의 경우, 전체 간선 중 가중치가 가장 작은 간선부터 차례대로 선택(사이클이 생기지 않는다면)하는 방식으로 작동하며, Prim 알고리즘은 현재 연결된 트리에 인접한 간선 중 가장 비용이 적은 것을 선택하며 트리를 확장해 나갑니다.

## Topic 1. Kruskal 알고리즘 (Edge-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "가장 비용이 적은 다리(간선)부터 놓는다. 단, 섬(Cycle)이 고립되거나 갇히지 않게."

### Concept

- **접근법:** **간선(Edge)** 을 중심으로 동작.
- **핵심 로직:**
    1. **정렬 (Sorting):** 그래프의 모든 간선을 가중치 기준 **오름차순**으로 정렬한다.
    2. **선택 (Selection):** 가장 가중치가 작은 간선부터 선택한다.
    3. **검사 (Cycle Detection):** 선택한 간선이 사이클을 만드는지 확인한다.
        - 사이클 생성 O $\rightarrow$ 버림 (Skip).
        - 사이클 생성 X $\rightarrow$ 신장 트리에 추가.
    4. **종료:** 선택된 간선의 개수가 $N-1$개가 되면 종료.
        
### 복잡도 및 특징
- **시간 복잡도:** 간선 정렬에 $O(E \log E)$ 소요.
- **적합성:** 간선이 적은 **희소 그래프(Sparse Graph)**에 유리하다.
### 주요 알고리즘: Union-Find (Disjoint Set)

- **역할:** 간선 추가 시 사이클 발생 여부를 판단하는 알고리즘.
- **원리:**
    - `Find(x)`: 노드 x가 속한 집합의 루트(대장)를 찾는다.
    - `Union(x, y)`: 두 집합을 합친다.
    - 만약 `Find(u) == Find(v)`라면, u와 v는 이미 같은 집합(연결됨)이므로 간선을 추가하면 **사이클**이 발생한다.
        

### Code 구현 (논리 흐름)


```C
// Kruskal MST Logic
void Kruskal(GraphType* g) {
    Edge edges[] = sort_edges(g); // 1. 간선 정렬 (O(E log E))
    int edge_count = 0;
    
    set_init(g->n); // Union-Find 초기화

    for (int i = 0; i < g->e; i++) {
        // 2. 가장 작은 간선 선택
        int u = edges[i].u;
        int v = edges[i].v;

        // 3. 사이클 검사 (Find)
        if (set_find(u) != set_find(v)) {
            set_union(u, v); // 두 집합 합치기
            add_edge_to_mst(u, v);
            edge_count++;
            
            // 4. 종료 조건
            if (edge_count == g->n - 1) break;
        }
    }
}
```

## Topic 4. Prim 알고리즘 (Vertex-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "이미 개척된 땅(Tree)에서 가장 가까운 미개척지(Non-Tree)를 하나씩 병합한다."

### Concept

- **접근법:** **정점(Vertex)** 을 중심으로 동작. 시작 정점은 어디든 상관없음(결과 가중치 합은 동일).
- **핵심 로직:**
    1. **초기화:** 시작 정점 하나를 트리에 포함(`visited`). 나머지 모든 정점까지의 거리는 무한대($\infty$).
    2. **탐색:** 현재 트리 집합(Set)에서 인접한 간선 중 **가중치가 가장 작은 간선**으로 연결된 정점을 찾는다.
    3. **확장:** 해당 정점을 트리에 포함시키고, 그 정점과 연결된 간선 정보를 바탕으로 '갈 수 있는 최단 거리'를 갱신한다.
    4. **반복:** $N-1$개의 간선이 선택될 때까지 반복.
        
### 복잡도 및 특징

- **적합성:** 간선이 많은 **밀집 그래프(Dense Graph)**에 유리하다. (정렬 비용이 없으므로)
- **장점:** 시작 정점이 어디든 결과(총 비
### Code 구현 (논리 흐름)



```C
// Prim MST Logic
void Prim(GraphType* g, int start_node) {
    int distance[MAX_VERTICES]; // 트리에 인접한 거리
    int visited[MAX_VERTICES] = {0};
    
    // 초기화: 모든 거리 무한대, 시작점은 0
    for(int i=0; i<g->n; i++) distance[i] = INF;
    distance[start_node] = 0;

    for (int i = 0; i < g->n; i++) {
        // 1. 방문하지 않은 노드 중 distance가 가장 작은 노드 u 선택
        int u = delete_min(distance, visited); 
        visited[u] = TRUE;
        
        // 2. u에 인접한 노드들의 거리 갱신
        for (each node v connected to u) {
            if (!visited[v] && weight[u][v] < distance[v]) {
                distance[v] = weight[u][v]; // 더 짧은 거리 발견 시 갱신
            }
        }
    }
}
```

## Topic 5. 알고리즘 비교 및 정리 (Analysis)

### 1. 시간 복잡도와 적합성

| **특징**     | **Kruskal 알고리즘**                        | **Prim 알고리즘**                          |
| ---------- | --------------------------------------- | -------------------------------------- |
| **중심**     | **간선 (Edge)** 중심                        | **정점 (Vertex)** 중심                     |
| **핵심 연산**  | 간선 정렬 (Sort)                            | 최소 거리 찾기 (Priority Queue)              |
| **탐색 방식**  | 가장 싼 간선부터 툭툭 끊어서 연결 (전역적)               | 시작 정점에서 점점 영역을 넓힘                      |
| **유리한 경우** | **희소 그래프 (Sparse Graph)**<br>(간선이 적을 때) | **밀집 그래프 (Dense Graph)**<br>(간선이 많을 때) |
| **구현 난이도** | 정렬과 Union-Find 필요                       | 이중 루프 또는 우선순위 큐 필요                     |
| **시간 복잡도** | $O(E \log E)$ (정렬 시간)                   | $O(N^2)$ (배열) 또는 $O(E \log N)$ (힙)     |
|            |                                         |                                        |

### 2. 강조 포인트

- **Kruskal:** 반드시 **정렬**이 선행되어야 함. 정렬 비용이 전체 성능을 좌우함.
- **Prim:** 정점이 많고 간선이 매우 많은 경우(Complete Graph 등)에는 정렬 비용이 없는 Prim이 유리할 수 있음 ($O(N^2)$ 구현 시).

### 💡 Interview

> [!faq]- Q. Kruskal과 Prim 알고리즘 중 어떤 상황에서 무엇을 선택해야 하는가?
>
> 🗣️ 핵심 답변
>
> 그래프 내 **간선의 밀도(Density)**에 따라 결정합니다.
>
> 간선의 개수가 적은 **희소 그래프(Sparse Graph)**에서는 간선 정렬 비용이 주도하는 Kruskal 알고리즘($O(E \log E)$)이 유리하며,
> 간선이 많은 **밀집 그래프(Dense Graph)**에서는 정점 위주로 탐색하는 Prim 알고리즘($O(N^2)$ or $O(E \log N)$)이 더 효율적일 수 있습니다.

> [!faq]- Q. 간선이 매우 많은 '밀집 그래프(Dense Graph)'에서 MST를 구할 때 Kruskal보다 Prim이 유리한 이유는?
>
> 🗣️ 핵심 답변
>
> Kruskal 알고리즘은 간선을 정렬하는 과정이 필수적인데, 간선 수($E$)가 많으면 정렬 비용($O(E \log E)$)이 매우 커집니다. 반면, Prim 알고리즘은 정점 개수($N$)에 비례하는 $O(N^2)$ 방식으로 구현할 수 있어, $E$가 $N^2$에 가까운 밀집 그래프에서는 정렬 오버헤드가 없는 Prim이 더 효율적입니다.

> [!faq]- Q. Kruskal 알고리즘에서 사이클 발생 여부를 효율적으로 판단하기 위해 사용하는 자료구조는 무엇이며, 그 원리는?
>
> 🗣️ 핵심 답변
>
> 유니온-파인드(Union-Find) 자료구조를 사용합니다. Find 연산으로 두 정점의 루트 노드를 확인하여, 만약 루트가 같다면 이미 같은 집합에 속해 있는 것(연결됨)이므로 사이클이 발생한다고 판단합니다. 다르다면 Union 연산으로 두 집합을 합칩니다.
>
> **📚 성능**
>
> - 경로 압축(Path Compression)과 랭크 기반 합치기(Union by Rank)를 적용하면 거의 상수 시간($O(\alpha(N))$)에 연산이 가능합니다.
