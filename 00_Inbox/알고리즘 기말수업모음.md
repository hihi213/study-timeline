## Topic 1. 분할 정복 (Divide and Conquer)

### 1. 🏗️ 빌드업 (Why & Context)

> 복잡한 문제를 한 번에 해결하기 어려울 때 사용하는 전략

- **기원:** 나폴레옹 전쟁 전략에서 유래. 소규모의 병력으로 대규모 적을 상대할 때, 적을 소규모로 쪼개어 각개격파하는 전술.
- **직관적 예시 (가위바위보 토너먼트):**
    - 40명이 한 번에 가위바위보를 해서 1등을 뽑기는 어렵다.
    - **분할:** 40명을 20명 vs 20명, 다시 10명 vs 10명… 최종적으로 1명 vs 1명이 될 때까지 쪼갠다.
    - **정복:** 1:1 상황에서는 승패를 가리기 쉽다.
    - **결합:** 승자끼리 다시 붙여서 올라간다.
        

### Concept

> "문제를 더 이상 쪼갤 수 없을 때까지(Atomic) 나눈 뒤 해결하고, 다시 합친다."

- **3단계 메커니즘:**
    
    1. **Divide (분할):** 해결하기 쉽도록 문제를 2개 이상의 하위 문제(Sub-problem)로 나눈다.
    2. **Conquer (정복):** 하위 문제가 충분히 작으면 해결하고, 그렇지 않으면 재귀적으로 다시 분할한다.
    3. **Combine (결합):** 하위 문제의 해답을 모아 원래 문제의 해답을 도출한다.
        
- **특징:** 주로 **순환 호출 (Recursion)**을 사용하여 구현한다.

## Topic 2. 합병 정렬 (Merge Sort)

### 1. 🏗️ 빌드업 (Why & Context)

> 분할 정복 기법을 정렬 알고리즘에 적용한 케이스

- **핵심 아이디어:**
    - 정렬되지 않은 리스트를 반으로 계속 쪼갠다 (분할).
    - 데이터가 1개가 남으면 그 자체로 '정렬된 상태'이다 (정복).
    - 정렬된 두 개의 부분 리스트를 **비교하며 합친다** (결합/Merge).
- **디버깅 비유:** 100줄짜리 코드에서 에러를 찾을 때, 코드를 반으로 나누어 `printf`를 찍으며 범위를 좁혀가는 과정(Binary Search 적 접근)과 유사한 사고방식.
    

### Concept

- **정의:** 하나의 리스트를 두 개의 균등한 크기로 분할하고, 분할된 부분 리스트를 정렬한 다음, 두 개의 정렬된 리스트를 합하여 전체를 정렬하는 방식.
- **Logic 흐름 (재귀적 순서 중요):**
    
    1. `MergeSort` 호출 (Left, Right 절반 분할).
    2. **Left** 파트 재귀 호출 (더 이상 못 쪼갤 때까지).
    3. **Right** 파트 재귀 호출.
    4. **Merge** 수행 (두 정렬된 리스트를 하나로 합침).
        
- **Merge 프로세스:**
    - 이미 정렬된 두 리스트 A, B가 있다고 가정.
    - A의 첫 번째 값과 B의 첫 번째 값을 비교.
    - 더 작은 값을 결과 리스트에 넣고 포인터를 이동.
    - 한쪽 리스트가 끝날 때까지 반복 후, 남은 데이터는 그대로 복사.
        

### Code 구현

- C언어 기준, 재귀적 분할(`merge_sort`)과 병합 로직(`merge`) 분리 구현.
    

C

```sql
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 정렬된 데이터를 임시 저장할 배열 (추가 공간 필요)

// 병합 함수 (Conquer & Combine)
void merge(int list[], int left, int mid, int right) {
    int i, j, k, l;
    i = left;     // 왼쪽 리스트 시작 인덱스
    j = mid + 1;  // 오른쪽 리스트 시작 인덱스
    k = left;     // 임시 배열(sorted)의 인덱스

    // 분할된 두 리스트를 비교하며 병합
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) {
            sorted[k++] = list[i++];
        } else {
            sorted[k++] = list[j++];
        }
    }

    // 남아 있는 값들을 일괄 복사
    if (i > mid) { // 왼쪽 리스트가 먼저 끝난 경우
        for (l = j; l <= right; l++)
            sorted[k++] = list[l];
    } else { // 오른쪽 리스트가 먼저 끝난 경우
        for (l = i; l <= mid; l++)
            sorted[k++] = list[l];
    }

    // 임시 배열의 내용을 원본 배열로 재복사
    for (l = left; l <= right; l++) {
        list[l] = sorted[l];
    }
}

// 합병 정렬 함수 (Divide)
void merge_sort(int list[], int left, int right) {
    int mid;
    if (left < right) {
        mid = (left + right) / 2; // 중간 위치 계산
        merge_sort(list, left, mid);      // 왼쪽 부분 리스트 분할 (재귀)
        merge_sort(list, mid + 1, right); // 오른쪽 부분 리스트 분할 (재귀)
        merge(list, left, mid, right);    // 병합 (Combine)
    }
}
```

- **⚠️ 주의사항 (재귀 순서):** 코드가 실행될 때 `merge` 함수가 호출되는 시점은 **가장 작은 단위로 쪼개진 직후**부터이다. (Depth-First 방식으로 왼쪽 끝까지 내려간 뒤 올라오며 병합).

## Topic 3. 성능 분석 및 퀵 정렬과의 비교

### 1. 🏗️ 빌드업 (Why & Context)

> "항상 빠를까? 퀵 정렬(Quick Sort)보다 좋을까?"

- **문제 제기:** 재귀 호출과 추가적인 배열 사용이 성능에 어떤 영향을 미치는가?
    

### Concept

- **시간 복잡도:**
    - 분할 단계: $O(\log N)$ (트리의 높이).
    - 병합 단계: 최대 $N$번 비교.
    - **Total:** $O(N \log N)$ (최선, 평균, 최악 모두 동일).
- **공간 복잡도 (단점):**
    - **임시 배열 (`sorted`)**이 반드시 필요함.
    - $N$개의 데이터를 정렬하려면 $N$만큼의 추가 공간이 필요.
- **이동 연산 (Overhead):**
    - 원소가 $N$개일 때 약 $2N \log N$번의 이동이 발생 (임시 배열로 복사 + 원본으로 복구).
    - 이로 인해 일반적인 경우 **퀵 정렬(Quick Sort)보다 물리적인 시간이 조금 더 느림.**
        

### 💡 Interview

> [!faq]Q. 합병 정렬(Merge Sort)이 퀵 정렬(Quick Sort)보다 느린 이유와, 그럼에도 사용하는 이유는?
>
> 🗣️ 핵심 답변
>
> 합병 정렬은 임시 배열을 사용하는 추가적인 메모리 접근과 데이터 이동(Copy) 오버헤드 때문에 일반적으로 퀵 정렬보다 느립니다.
>
> 하지만 최악의 경우에도 $O(N \log N)$을 보장하며, **안정 정렬(Stable Sort)**이라는 장점 때문에 데이터의 순서 유지가 중요하거나 연결 리스트(Linked List)를 정렬할 때 유리합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 연결 리스트(Linked List) 정렬 시에는 왜 효율적인가?**
>     
>     - 배열과 달리 인덱스 이동이 아닌 링크(Pointer)만 변경하면 되므로 데이터 이동 오버헤드가 획기적으로 줄어들어 퀵 정렬보다 효율적일 수 있습니다.
>         
> - **Q. 공간 복잡도 한계를 극복하려면?**
>     
>     - In-place Merge Sort 구현이 가능하지만, 구현이 매우 복잡하여 실무에서는 잘 쓰이지 않거나 다른 정렬을 사용합니다.
>

## Topic 1. 퀵 정렬 (Quick Sort)의 개념과 동작 원리

### 1. 🏗️ 빌드업 (Why & Context)

> 합병 정렬(Merge Sort)과의 결정적 차이: **"무엇을 기준으로 쪼개는가?"**

- **비교:**
    - **합병 정렬:** 물리적인 **크기(Size)**를 기준으로 무조건 반으로 쪼갠 뒤 정복한다. (위치 중심)
    - **퀵 정렬:** 데이터의 **값(Value)**을 기준으로 쪼갠다. 특정 값(Pivot)보다 작으면 왼쪽, 크면 오른쪽으로 보낸다.
- **직관적 비유 (키 순서 줄 세우기):**
    - 합병 정렬이 그냥 반 뚝 잘라 줄 세우는 것이라면,
    - 퀵 정렬은 "175cm인 사람 나와봐. 너를 기준으로 작은 사람 왼쪽, 큰 사람 오른쪽 서!"라고 하는 것과 같다.
        

### Concept

> **"Pivot(기준값)을 정하고, Partition(분할)을 수행하여 제자리를 찾아준다."**

- **핵심 메커니즘 (Partitioning):**
    
    1. **Pivot 선정:** 리스트의 원소 중 하나(주로 맨 왼쪽, 중간, 또는 랜덤)를 기준값으로 잡는다.
    2. **두 개의 포인터(L, R) 이동:**
        
        - **Left (Low):** 왼쪽에서 출발하여 Pivot보다 **큰 값**을 찾을 때까지 이동.
        - **Right (High):** 오른쪽에서 출발하여 Pivot보다 **작은 값**을 찾을 때까지 이동.
            
    3. **Swap (교환):** L과 R이 멈춘 지점의 값을 서로 교환한다. (작은 건 왼쪽으로, 큰 건 오른쪽으로 보내기 위함).
    4. **Cross & Fix:** L과 R이 서로 교차(엇갈림)하게 되면, Pivot과 R(또는 상황에 맞는 위치)의 값을 교환하여 Pivot의 최종 위치를 확정(Fix) 짓는다.
        
- **재귀적 수행:** Pivot이 제자리를 찾으면, Pivot을 제외한 왼쪽 부분 집합과 오른쪽 부분 집합에 대해 동일한 작업을 반복한다.

## Topic 2. 퀵 정렬 구현 (Code Analysis)

### 1. 🏗️ 빌드업 (Code Context)

> "단순히 ChatGPT가 짜준 코드를 복사하지 말고, 인덱스가 왜 그렇게 움직이는지 분석해야 한다."

- **핵심 질문:** `while`문이 아닌 `do-while`문을 사용하는 이유는? 비교하기 전에 `low`를 왜 먼저 증가(`++low`)시키는가?
    

### Code 구현

- **전략:** 가장 왼쪽 값(`list[left]`)을 Pivot으로 설정하는 방식.
    

C

```sql
#include <stdio.h>

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 분할 함수 (Partition)
int partition(int list[], int left, int right) {
    int pivot, low, high;
    
    low = left;             // 왼쪽 포인터 시작점 (Pivot 위치)
    high = right + 1;       // 오른쪽 포인터 시작점 (범위 밖에서 시작하여 감소 예정)
    pivot = list[left];     // 가장 왼쪽 값을 Pivot으로 설정

    do {
        // low를 증가시키며 Pivot보다 큰 값 찾기
        // ⚠️ 중요: do-while을 쓴 이유 -> low가 현재 Pivot(left)을 가리키므로
        // 비교하기 전에 먼저 한 칸 이동해야 자기 자신과의 비교를 피하고 다음 값부터 검사함.
        do {
            low++; 
        } while (low <= right && list[low] < pivot);

        // high를 감소시키며 Pivot보다 작은 값 찾기
        do {
            high--;
        } while (high >= left && list[high] > pivot);

        // low와 high가 교차하지 않았다면 swap
        if (low < high) {
            swap(&list[low], &list[high]);
        }
    } while (low < high); // low와 high가 교차할 때까지 반복

    // Pivot(list[left])과 high 위치의 값 교환 (Pivot의 제자리 찾기)
    swap(&list[left], &list[high]);

    return high; // 확정된 Pivot의 위치 반환
}

// 퀵 정렬 함수
void quick_sort(int list[], int left, int right) {
    if (left < right) {
        // q: 피벗이 제자리를 찾은 위치 (Partition의 결과)
        int q = partition(list, left, right); 
        
        // 피벗을 제외한 왼쪽 리스트 재귀 호출
        quick_sort(list, left, q - 1);
        
        // 피벗을 제외한 오른쪽 리스트 재귀 호출
        quick_sort(list, q + 1, right);
    }
}
```

### ⚠️ Code Analysis (교수님 강조 포인트)

- **`low`의 시작과 선증가(`++low`)의 이유:**
    - Pivot을 `list[left]`(맨 왼쪽)로 잡았기 때문에, 탐색은 그 다음 칸(`left + 1`)부터 시작해야 한다.
    - `do { low++ } while(…)` 구조를 사용함으로써, 비교 연산을 수행하기 전에 인덱스를 먼저 증가시켜 **Pivot 자신과의 불필요한 비교를 건너뛰고** 바로 다음 원소부터 탐색하게 만든다.
- **재귀 호출의 순서:**
    - `partition` 함수가 실행되면 Pivot 하나는 무조건 자기 자리를 찾아 고정된다.
    - 이후 `q-1`(왼쪽), `q+1`(오른쪽)로 나뉘어 재귀적으로 들어간다. 이 호출 스택(Stack)의 순서를 머릿속으로 그릴 수 있어야 한다.

## Topic 3. AI 시대 개발자의 태도 & 기타 핵심

### 1. 🏗️ 빌드업 (Why & Context)

> "코드는 AI가 짜줄 수 있다. 하지만 그 코드를 분석하고 수정하는 건 사람의 몫이다."

- **배경:** 최근 포럼에서 언급된 바와 같이, 앞으로는 코딩 자체보다 **'시스템에 맞게 코드를 분석하고 검증하는 능력'**이 생존 조건이 될 것이다.
    

### Concept & Advice

- **학습 방법:** - 챗GPT에게 코드를 달라고 하는 것은 쉽다. 하지만 그것을 그대로 베껴서 과제를 내는 것은 본인에게 아무런 도움이 되지 않는다.
    - **Action:** 자신이 자신 있는 언어(C, Java, Python 등)로 퀵 정렬을 직접 구현해보고, 언어별 표준 라이브러리(`qsort` 등)와 내부 구현을 비교해 볼 것.
- **퀵 정렬 vs 합병 정렬:**
    - **속도:** 일반적으로 퀵 정렬이 합병 정렬보다 빠르다. (불필요한 데이터 이동이 적고, 먼 거리의 데이터를 교환하기 때문).
    - **공간:** 합병 정렬은 임시 배열($O(N)$)이 필요하지만, 퀵 정렬은 추가 메모리가 거의 필요 없다(Stack 공간 제외).

## Topic 1. 퀵 정렬의 최악의 경우 (Worst Case)

### 1. 🏗️ 빌드업 (Why & Context)

> "퀵 정렬은 일반적으로 가장 빠르지만, 특정 상황에서는 치명적으로 느려진다."

- **문제 제기:** 이미 정렬된 데이터(오름차순 `1, 2, 3…` 또는 내림차순 `9, 8, 7…`)를 퀵 정렬할 때, 피벗(Pivot)을 **가장 앞의 원소**로 잡으면 무슨 일이 벌어지는가?
    

### Concept

- **최악의 시나리오 ($O(N^2)$):**
    - 이미 정렬된 데이터에서 첫 번째 원소를 Pivot으로 선정하면, 분할(Partition)이 5:5로 되는 것이 아니라 **1 : (N-1)**로 극단적으로 치우치게 된다.
    - **예시:** `1, 2, 3, 4, 5`가 있을 때 `1`을 Pivot으로 잡으면, `1`보다 작은 값은 없고 나머지 `2, 3, 4, 5`가 모두 오른쪽 부분 집합이 된다.
    - 다음 단계에서 `2`를 Pivot으로 잡으면 또다시 `3, 4, 5`가 한쪽으로 몰린다.
    - 결과적으로 트리 높이가 $N$이 되고, 각 단계마다 $N$번 비교하므로 시간 복잡도는 $O(N^2)$이 된다.
- **해결책:** (이번 강의에서 구체적으로 다루진 않았으나 2교시 맥락상) Pivot을 랜덤하게 잡거나 중간값(Median)을 사용하는 방법을 쓴다.

## Topic 2. 힙 (Heap) 자료구조의 이해

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 데이터가 평등하지 않다. 급한 놈(우선순위) 먼저 처리해야 한다."

- **동기:** 줄 선 순서대로 처리하는 큐(Queue, FIFO)와 달리, 응급환자나 VIP(Q-Pass)처럼 **우선순위(Priority)**가 높은 데이터를 먼저 꺼내야 하는 상황이 있다. 이를 구현하기 위한 자료구조가 **힙(Heap)**이다.
    

### Concept

- **정의:** 우선순위 큐(Priority Queue)를 구현하기 위한 **완전 이진 트리(Complete Binary Tree)** 형태의 자료구조.
- **종류:**
    
    1. **최대 힙 (Max Heap):** 부모 노드의 키 값이 자식 노드보다 항상 크거나 같다. (Root = 최댓값)
    2. **최소 힙 (Min Heap):** 부모 노드의 키 값이 자식 노드보다 항상 작거나 같다. (Root = 최솟값)
        
- **특징:**
    - **중복 허용:** 이진 탐색 트리(BST)와 달리 중복된 값을 허용한다.
    - **느슨한 정렬:** 부모가 자식보다 크다는 조건만 만족하며, 형제 노드 간의 대소 관계는 신경 쓰지 않는다 (반정렬 상태).

## Topic 3. 힙 정렬 (Heap Sort)

### 1. 🏗️ 빌드업 (Why & Context)

> "힙에서 가장 큰 값(Root)을 계속 꺼내면, 그게 바로 정렬이다."

- **핵심 아이디어:**
    - 데이터를 힙으로 구성(`Make Heap`)한다.
    - 힙의 Root(최댓값)를 꺼내서 배열의 맨 뒤로 보낸다.
    - 힙의 구조가 깨졌으므로 다시 힙으로 만든다.
    - 이를 반복하면 뒤에서부터 차곡차곡 정렬된 데이터가 쌓인다.
        

### Concept

- **정렬 메커니즘 (Max Heap 이용 시 -> 오름차순 정렬):**
    
    1. **Build Heap:** 주어진 배열을 최대 힙으로 변환한다.
    2. **Delete (Extract Max):**
        
        - Root(최댓값)와 힙의 **가장 마지막 노드**를 교환한다.
        - 가장 마지막 노드(원래 Root였던 값)를 힙 사이즈에서 제외(Fix)시킨다. (배열의 끝에 정렬 완료).
            
    3. **Re-heapify (Sift Down):**
        
        - Root로 올라온 뜬금없는 값(원래 마지막에 있던 값)을 제자리로 보내기 위해 자식들과 비교하며 내려보낸다.
        - 자식 중 **더 큰 값**과 교환하며 내려간다.
- **배열을 이용한 트리 구현 (1-based Index 기준):**
    - 왼쪽 자식 인덱스 = `부모 인덱스 * 2`
    - 오른쪽 자식 인덱스 = `부모 인덱스 * 2 + 1`
    - 부모 인덱스 = `자식 인덱스 / 2`
    - _실제 구현 시 0번 인덱스를 비우고 1번부터 쓰면 계산이 편하다._
        

### Code 구현 (삭제 및 재구조화 로직)

> 힙 정렬의 핵심은 '삭제(Delete)' 연산의 응용이다.

C

```sql
// 힙의 삭제 연산 로직 (정렬의 한 단계)
// n: 힙의 크기
void delete_max_heap(int heap[], int *n) {
    int first, temp, parent, child;
    
    // 1. 루트(최댓값)와 마지막 노드 교환 (정렬 과정에서는 배열 끝으로 보냄)
    int max_val = heap[1]; 
    heap[1] = heap[*n]; // 마지막 노드를 루트로 올림
    (*n)--; // 힙 크기 감소
    
    // 2. Re-heapify (위에서 아래로 자리 찾기)
    parent = 1;
    child = 2; // 왼쪽 자식부터 시작

    while (child <= *n) {
        // 왼쪽 자식 vs 오른쪽 자식 중 큰 놈 선택
        if ((child < *n) && (heap[child] < heap[child + 1])) {
            child++;
        }
        
        // 부모가 자식보다 크면 OK (힙 구조 만족 -> 중단)
        if (heap[parent] >= heap[child]) {
            break;
        }
        
        // 부모가 자식보다 작으면 교환 (아래로 내려감)
        temp = heap[parent];
        heap[parent] = heap[child];
        heap[child] = temp;
        
        // 인덱스 갱신 (더 아래로)
        parent = child;
        child = child * 2;
    }
    // (정렬 시에는 max_val을 배열의 끝 빈 공간에 배치)
}
```

- **⚠️ 주의사항:**
    - 삭제 시 루트가 비었다고 자식들을 바로 올리는 게 아니다. **맨 마지막 노드를 루트로 올린 뒤** 비교하며 내려보내는 것이 알고리즘적으로 훨씬 효율적이고 구현이 쉽다. (완전 이진 트리 형태 유지 때문).

## 최종 요약 - 알고리즘 10.30

### 1) 오늘의 TOPIC (Pattern Link)

> **"어떻게 쪼개고(Divide), 무엇을 기준으로 정렬(Sort)할 것인가?"**

오늘 수업은 효율적인 정렬 알고리즘의 3대장인 **합병 정렬(Merge Sort)**, **퀵 정렬(Quick Sort)**, **힙 정렬(Heap Sort)**을 관통하는 논리적 흐름을 다루었습니다.

1. **분할 정복(Divide & Conquer)의 토대**: 복잡한 문제를 쪼개서 해결한다는 대원칙 아래, **합병 정렬**은 '물리적인 크기(반반)'를 기준으로 쪼개고, **퀵 정렬**은 '논리적인 값(Pivot)'을 기준으로 쪼갠다는 차이점을 명확히 했습니다.
2. **효율성과 최악의 상황(Trade-off)**:
    
    - **합병 정렬**: 항상 안정적($O(N \log N)$)이지만, 임시 배열 사용으로 메모리와 이동 연산 비용이 큼.
    - **퀵 정렬**: 평균적으로 가장 빠르지만, 이미 정렬된 데이터에 대해 피벗 선정 실패 시 $O(N^2)$로 성능이 급락하는 치명적 약점 존재.
        
3. **자료구조의 응용(Heap)**: 단순 비교를 넘어 **힙(Heap)**이라는 자료구조(완전 이진 트리)를 활용해, '우선순위(최댓값)'를 뽑아내는 방식으로도 $O(N \log N)$ 정렬이 가능함을 배웠습니다.
    

### 2) 강조포인트

- **퀵 정렬의 구현 디테일**: 단순 코딩이 아니라, `do-while`문을 사용하여 `low` 포인터를 선증가시키는 이유(자기 자신과의 비교 회피) 등 **코드 레벨의 정밀한 분석 능력**이 요구됩니다.
- **최악의 시나리오 방어**: 퀵 정렬에서 정렬된 데이터(Sorted Data)가 들어올 때의 취약점을 이해하고, 이를 방지하기 위해 Pivot을 랜덤이나 중간값으로 설정하는 전략이 필요합니다.
- **힙(Heap)의 메커니즘**: 힙 정렬은 '삭제 연산(Delete Max)'의 반복입니다. 루트(최댓값)를 맨 뒤로 보내고, 깨진 힙 구조를 다시 맞추는(Re-heapify) 과정을 시각적으로 그릴 수 있어야 합니다.
- **개발자의 태도**: AI가 코드를 짜주는 시대지만, 그 코드가 '왜' 그렇게 동작하는지 한 줄 한 줄 분석할 수 있는 능력만이 생존 경쟁력이 됨을 강조했습니다.
