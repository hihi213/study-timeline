## Topic 1. MST vs 최단 경로 (Comparison)

### 1. 🏗️ 빌드업 (Concept)

> "MST는 도로를 최소한으로 깔아서 모든 도시를 잇는 것이고, 최단 경로는 이미 깔린 도로에서 가장 빨리 가는 길을 찾는 것이다."

- **MST (Minimum Spanning Tree):**
    - 목적: 모든 노드를 연결하되 간선 가중치의 합이 최소가 되도록 함.
    - 결과: 트리 (Tree) 형태. 사이클 없음.
    - 알고리즘: Kruskal, Prim.
- **최단 경로 (Shortest Path):**
    - 목적: 특정 출발지에서 목적지까지 가는 경로의 가중치 합이 최소가 되도록 함.
    - 결과: 경로 (Path).
    - 알고리즘: Dijkstra, Bellman-Ford, Floyd-Warshall.

## Topic 2. 다익스트라 알고리즘 심화 (Tracing)

### 1. 🏗️ 시뮬레이션 설정 (0번 노드 시작)

- **초기 상태:**
    - **집합 $S$ (방문 확정):** `{0}`
    - **`distance` 배열:** `[0, 7, INF, INF, 3, 10, INF]` (0번 행의 초기 가중치)
        

### 2. 단계별 추적 (Step-by-Step)

1. **Step 1 (최소 거리 선택):** `distance` 중 방문하지 않은 가장 작은 값은 **4번 노드(3)**.
    
    - $S = \{0, 4\}$
    - **갱신 (Relaxation):** 4번을 거쳐갈 때 더 빠른 곳이 있는가?
        - $0 \to 1$: 기존 7 vs $(0 \to 4 \to 1)$ $3 + \text{weight}[4][1]$ (예: 2) = 5. **갱신 (7 $\to$ 5)**.
        - $0 \to 2$: 기존 INF vs $(0 \to 4 \to 2)$ $3 + \text{weight}[4][2]$.
        - $0 \to 3$: 기존 INF vs $(0 \to 4 \to 3)$ $3 + 11 = 14$. **갱신 (INF $\to$ 14)**.
    - **결과:** `[0, 5, INF, 14, 3, 10, 18]` (가정된 값 포함)
        
2. **Step 2 (다음 최소 선택):** `distance` 중 가장 작은 **1번 노드(5)** 선택.
    
    - $S = \{0, 4, 1\}$
    - **갱신:** 1번을 거쳐갈 때 더 빠른 곳이 있는가?
        - $0 \to 2$: 기존 INF vs $(0 \to 1 \to 2)$ $5 + \text{weight}[1][2]$ (예: 4) = 9. **갱신 (INF $\to$ 9)**.
    - **결과:** `[0, 5, 9, 14, 3, 10, 18]`
        
3. **반복:** 이 과정을 모든 노드가 $S$에 포함될 때까지 반복한다.

## Topic 3. 핵심 수식과 원리

### 1. Relaxation (이완/갱신)

$$D[w] = \min(D[w], D[u] + W[u][w])$$

- **$D[w]$:** 시작점에서 $w$까지 가는 기존 최단 거리.
- **$D[u]$:** 시작점에서 $u$까지 가는 확정된 최단 거리.
- **$W[u][w]$:** $u$에서 $w$로 가는 간선의 가중치.
- **의미:** "지금까지 알고 있던 길보다, **새로 확정된 $u$를 거쳐서 가는 길**이 더 빠르다면 그 값으로 업데이트한다."
    

### 2. 주의사항

- **$S$ 집합의 의미:** $S$에 들어간 노드는 최단 거리가 **이미 확정**된 상태이다. 이후에는 그 값이 더 작아질 수 없다. (음수 간선이 없다는 전제하에)
- **무한대(INF) 처리:** 코드 구현 시 `INT_MAX` 등을 사용하여, 갱신 전에는 갈 수 없음을 명확히 해야 한다. `0`을 쓰면 안 된다.

## Topic 2. Floyd-Warshall 알고리즘 (All-Pairs Shortest Path)

### 1. 🏗️ 빌드업 (Concept)

> "다익스트라는 서울에서 출발하는 것만 안다. 플로이드는 전국의 모든 도시에서 출발하는 경로를 한 방에 안다."

- **목적:** 그래프 내의 **모든 정점 쌍(All Pairs)** 사이의 최단 경로를 구한다.
- **핵심 아이디어:** **거쳐가는 정점(경유지, $k$)**을 기준으로 최단 거리를 갱신한다.
    - "정점 $i$에서 $j$로 바로 가는 것보다, $k$를 거쳐서 가는 게 더 빠르면 갱신한다."
        

### 2. 점화식 (Recurrence Relation)

$$A^k[i][j] = \min(A^{k-1}[i][j], A^{k-1}[i][k] + A^{k-1}[k][j])$$

- $A^k[i][j]$: 정점 $0$부터 $k$까지만 경유지로 사용할 수 있을 때, $i$에서 $j$로 가는 최단 거리.
- **직관적 의미:** `Distance[i][j] = min(Distance[i][j], Distance[i][k] + Distance[k][j])`
    

### 3. 동작 원리 및 3중 반복문

C

```C
// k: 거쳐가는 노드 (경유지)
for (k = 0; k < n; k++) {
    // i: 출발 노드
    for (i = 0; i < n; i++) {
        // j: 도착 노드
        for (j = 0; j < n; j++) {
            if (adj[i][k] + adj[k][j] < adj[i][j]) {
                adj[i][j] = adj[i][k] + adj[k][j];
            }
        }
    }
}
```

- **시간 복잡도:** 3중 반복문이므로 **$O(N^3)$**이다. 정점 개수가 적을 때(약 500개 이하) 유용하다.

## Topic 3. Dijkstra vs Floyd-Warshall 비교

|**특징**|**Dijkstra (다익스트라)**|**Floyd-Warshall (플로이드-워셜)**|
|---|---|---|
|**목표**|**하나의 시작점** $\to$ 다른 모든 정점|**모든 정점** $\to$ 모든 정점|
|**핵심 로직**|가장 가까운 정점 선택 (Greedy)|경유지를 거쳐가는 경로 갱신 (DP)|
|**시간 복잡도**|$O(E \log V)$ (우선순위 큐)|$O(V^3)$|
|**음수 간선**|처리 불가|처리 가능 (단, 음수 사이클은 불가)|
|**구현 난이도**|중간 (힙 필요)|매우 쉬움 (3중 for문)|
|**적용 예시**|내비게이션 (출발지 고정)|전체 네트워크 경로 분석|

## Topic 4. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Application)

> "선수 과목(Prerequisite) 구조: C언어를 들어야 자료구조를 듣고, 그래야 알고리즘을 듣는다."

- **정의:** **방향성 그래프(DAG)**에서 간선으로 주어진 정점 간의 선후 관계를 위배하지 않도록 나열하는 것.
- **제약 조건:** **사이클(Cycle)**이 존재하면 위상 정렬을 수행할 수 없다. (닭이 먼저냐 알이 먼저냐 모순 발생)
    

### 2. 알고리즘 프로세스 (Indegree 방식)

1. **진입 차수(Indegree) 계산:** 모든 정점의 진입 차수(들어오는 간선 수)를 계산한다.
2. **큐 삽입:** 진입 차수가 **0**인(선행 조건이 없는) 정점을 모두 큐에 넣는다.
3. **반복:**
    
    - 큐에서 정점 $u$를 꺼내 출력한다 (정렬 결과 추가).
    - $u$에서 나가는 간선을 모두 제거한다 (연결된 정점 $v$의 진입 차수를 1 감소).
    - 새롭게 진입 차수가 0이 된 정점 $v$를 큐에 넣는다.
        
4. **종료:** 큐가 비었을 때 모든 정점을 방문했다면 정렬 성공, 못 했다면 사이클 존재.

>
> 🗣️ 핵심 답변
>
> 그래프에 **사이클(Cycle)**이 존재하면 위상 정렬을 수행할 수 없습니다. 사이클에 포함된 정점들은 서로가 서로의 선행 조건이 되어, 진입 차수가 결코 0이 될 수 없기 때문에 큐에 들어갈 수 없어 정렬 과정에서 누락됩니다.

오늘 수업은 **'최적화 문제(Optimization Problem)'**의 연장선에서 **최소 비용 연결(MST)**과 **최단 경로(Shortest Path)**의 개념적 차이를 이해하고, 이를 해결하는 다양한 알고리즘의 스펙트럼을 넓혔습니다.

1. **MST vs 최단 경로**: MST(Kruskal, Prim)는 **'모든 정점의 연결 비용 최소화'**가 목적이지만, 최단 경로(Dijkstra)는 **'출발지에서 목적지까지의 이동 비용 최소화'**가 목적임을 명확히 구분했습니다.
2. **Dijkstra (One-to-All)**: **그리디(Greedy)** 전략을 사용하여 시작점으로부터 다른 모든 정점까지의 거리를 **갱신(Relaxation)**해 나가는 과정을 손으로 추적(Tracing)하며 학습했습니다.
3. **Floyd-Warshall (All-to-All)**: 다익스트라를 N번 반복하는 대신, **3중 반복문**을 통해 모든 정점 쌍 간의 최단 거리를 한 번에 구하는 **동적 계획법(DP)** 접근 방식을 다루었습니다.
4. **위상 정렬 (Topological Sort)**: 가중치나 경로가 아닌, **순서(Dependency)**가 있는 작업(예: 선수과목)을 정렬하는 방법을 학습했습니다. (진입 차수 0 제거 방식)
    

### 2) 강조포인트

- **개발자의 시야**: 단순히 코딩만 하는 것이 아니라, AI(Gemini 등)를 분석 도구로 활용하고 금융/제조업 등 다양한 도메인에서 시스템을 이해하는 개발자가 되어야 합니다.
- **다익스트라의 핵심**: **방문 확정 집합(S)**과 **거리 배열(Distance)**의 갱신 과정을 직접 시뮬레이션할 수 있어야 합니다. 특히 **`D[w] = min(D[w], D[u] + W[u][w])`**라는 갱신 공식이 핵심입니다.

    - **1:N 경로** & **양수 가중치**: 다익스트라 (우선순위 큐 활용 시 희소 그래프에 유리).

## Topic 4. 시간 복잡도 비교 예시 ($N \times N$)

### 1. 문제: 1부터 N까지 N번 더하기 (혹은 N * N 계산)

#### Case A: 곱셈 연산 활용 ($O(1)$)

C

```C
sum = n * n;
```

- **연산:** 대입 1회, 곱셈 1회 $\rightarrow$ 총 2회.
- **특징:** 입력 $N$이 1억이든 10억이든 연산 횟수는 **상수(Constant)**로 일정하다. 가장 효율적이다.
    

#### Case B: 단일 반복문 ($O(N)$)

C

```C
sum = 0;
for(i=0; i<n; i++) {
    sum += n;
}
```

- **연산:** $N$번 반복하며 덧셈 수행 $\rightarrow$ 약 $2N + \alpha$회.
- **특징:** 입력 $N$에 비례하여 시간이 선형적으로 증가한다.
    

#### Case C: 이중 반복문 ($O(N^2)$)

C

```C
sum = 0;
for(i=0; i<n; i++) {
    for(j=0; j<n; j++) {
        sum += 1;
    }
}
```

- **연산:** $N \times N$번 반복하며 1을 더함 $\rightarrow$ 약 $2N^2 + \alpha$회.
- **특징:** 입력 $N$이 커지면 실행 시간이 기하급수적으로 증가한다. (가장 비효율적)
    

### 2. 결론 (Big-O)

- $N$이 작을 때는 큰 차이가 없지만, $N$이 커질수록 **최고차항의 차수**가 성능을 지배한다.
- 따라서 상수항이나 계수를 무시하고 가장 큰 영향을 미치는 항만 표기하는 **Big-O 표기법**($O(1), O(N), O(N^2)$)을 사용한다.

## Topic 2. 시간 복잡도 (Time Complexity) 심화

### 1. Big-O 표기법 (상한, Upper Bound)

- **정의:** 입력 크기 $N$이 증가할 때, 연산 횟수의 증가 추세(Trend)를 나타내는 상한선.
- **계산 규칙:**
    
    1. **단일 반복문:** $O(N)$
    2. **중첩 반복문:** $O(N^2)$
    3. **분할 정복/이진 탐색:** $O(\log N)$
    4. **순차적 명령:** $O(f(n)) + O(g(n)) \rightarrow O(\max(f(n), g(n)))$ (가장 큰 항만 남김)
        

### 2. 주요 복잡도 비교 (작은 순서대로)

$$O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N) < O(N!)$$

- **$O(1)$:** 해시 테이블 조회, 배열 인덱스 접근.
- **$O(N \log N)$:** 퀵 정렬, 병합 정렬.
- **$O(N!)$:** 외판원 순회 문제(TSP) 등 (입력 크기가 작아도 계산 불가능 수준).

## Topic 3. 재귀(Recursion) vs 반복(Iteration)

### 1. 🏗️ 빌드업 (Comparison)

> "재귀는 코드가 예쁘지만 비싸고, 반복은 투박하지만 빠르다."

|**특징**|**재귀 (Recursion)**|**반복 (Iteration)**|
|---|---|---|
|**메모리 사용**|**비효율적** (스택 프레임 생성, Context Switching 오버헤드 발생)|**효율적** (추가 메모리 거의 없음)|
|**속도**|함수 호출 비용으로 인해 상대적으로 느림|빠름|
|**가독성**|**좋음** (점화식 표현에 직관적)|복잡할 수 있음 (변수 관리 필요)|
|**구현 난이도**|하노이 탑, 트리 순회 등에서 유리|피보나치 등에서 유리|

### 2. 메모리 구조 분석

- **반복문:** 데이터 영역(Data Segment)이나 힙(Heap)만 사용.
- **재귀 함수:** **시스템 스택(System Stack)** 영역을 사용.
    - 함수가 호출될 때마다 매개변수, 리턴 주소 등을 스택에 쌓아야 하므로, 깊이가 깊어지면 **스택 오버플로우(Stack Overflow)** 위험이 있다.

## Topic 4. 사례 연구 (Case Study)

### 1. 팩토리얼 (Factorial)

- **재귀:** $N! = N \times (N-1)!$ 점화식을 그대로 구현. ($O(N)$)
- **반복:** 1부터 N까지 곱함. ($O(N)$)
- **결론:** 시간 복잡도는 같으나, 재귀는 스택 오버헤드가 발생하므로 **반복이 더 효율적**일 수 있다.
    

### 2. 거듭제곱 ($x^n$) 계산

- **반복:** $x$를 $n$번 곱함 $\rightarrow O(N)$.
- **재귀 (분할 정복):**
    - $x^n = (x^{n/2})^2$ (짝수일 때)
    - $x^n = x \times (x^{(n-1)/2})^2$ (홀수일 때)
    - **시간 복잡도:** 문제 크기가 절반씩 줄어들으므로 **$O(\log N)$**.
- **결론:** 이 경우 **재귀(분할 정복)**가 반복보다 훨씬 빠르다.
    

### 3. 피보나치 수열 (Fibonacci)

- **재귀 (Naive):** $F(n) = F(n-1) + F(n-2)$
    - 중복 호출(Overlapping Subproblems)이 발생하여 **$O(2^N)$**의 지수 시간이 걸림. (비효율의 극치)
- **반복:** 0, 1부터 시작하여 $N$까지 순차적으로 계산. **$O(N)$**.
- **결론:** 피보나치는 절대 단순 재귀로 짜면 안 되며, **반복문**이나 **메모이제이션(Memoization)**을 써야 한다.

## Topic 1. 하노이 탑 (Hanoi Tower)

### 1. 🏗️ 빌드업 (Why & Context)

> "반복문(For)으로 짜려고 하면 머리 터진다. 재귀(Recursion)로 짜면 3줄이면 끝난다."

- **문제 정의:** 막대 A에 있는 $N$개의 원판을 막대 C로 옮겨라.
- **제약 조건:**
    
    1. 한 번에 하나의 원판만 옮길 수 있다.
    2. 큰 원판이 작은 원판 위에 올라갈 수 없다.
    3. 중간 막대(B)를 임시로 사용할 수 있다.
        

### 2. 논리적 분해 (Recursive Step)

$N$개의 원판을 A에서 C로 옮기려면, 가장 큰 원판(맨 밑)을 C로 옮겨야 한다. 이를 위해 위의 $N-1$개를 먼저 비켜줘야 한다.

1. **Step 1:** 맨 밑의 원판을 제외한 **나머지 $N-1$개 원판**을 A에서 **B(임시)**로 옮긴다.
2. **Step 2:** **가장 큰 원판(1개)**을 A에서 **C(목적지)**로 옮긴다.
3. **Step 3:** B에 두었던 **$N-1$개 원판**을 다시 **C(목적지)**로 옮긴다.
    

### 3. 알고리즘 구현 (Pseudo Code)

C

```C
// n: 원판 개수, from: 시작, temp: 보조, to: 목적지
void hanoi(int n, char from, char temp, char to) {
    if (n == 1) {
        // 원판이 1개면 바로 목적지로 이동
        move(from, to); 
    } else {
        // 1. N-1개를 A -> B로 이동 (C를 보조로 사용)
        hanoi(n - 1, from, to, temp);
        
        // 2. 가장 큰 원판을 A -> C로 이동
        move(from, to);
        
        // 3. N-1개를 B -> C로 이동 (A를 보조로 사용)
        hanoi(n - 1, temp, from, to);
    }
}
```

### 4. 복잡도 분석

- 점화식: $T(N) = 2T(N-1) + 1$
- 시간 복잡도: **$O(2^N)$**. 원판 하나 늘어날 때마다 이동 횟수가 2배씩 폭증한다. (반복문으로 구현하기 매우 난해함)

## Topic 2. 머신 스케줄링 (Job Scheduling)

### 1. 🏗️ 빌드업 (Optimization)

> "솜사탕 기계 2대가 있다. 피카츄(5분), 토끼(10분), 별(1분), 원(0.5분) 솜사탕 주문이 동시에 들어왔다. 어떻게 배분해야 가장 빨리 끝날까?"

- **목표:** $M$개의 기계(Machine)에 $N$개의 작업(Job)을 배정하여, 모든 작업이 끝나는 시간(Makespan)을 최소화하라.
- **알고리즘:** **LPT (Longest Processing Time first)** 방식 사용. (Greedy 기법)
    

### 2. LPT 알고리즘 (Greedy Approach)

1. **정렬:** 작업 시간이 **가장 긴 순서대로(내림차순)** 작업을 정렬한다. (8, 7, 6, 5…)
2. **배정:** 가장 먼저 끝나는(현재 부하가 가장 적은) 기계에 순서대로 작업을 배정한다.
3. **반복:** 모든 작업이 배정될 때까지 반복한다.
    

### 3. 구현 전략 (Min Heap 활용)

- 기계들의 현재 종료 시간을 관리하기 위해 **최소 힙(Min Heap)**을 사용하면 효율적이다.
    - 항상 Root(가장 빨리 끝나는 기계)를 꺼내서 작업을 할당하고 다시 넣는다.
