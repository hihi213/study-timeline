## Topic 4. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Application)

> "선수 과목(Prerequisite) 구조: C언어를 들어야 자료구조를 듣고, 그래야 알고리즘을 듣는다."

- **정의:** **방향성 그래프(DAG)**에서 간선으로 주어진 정점 간의 선후 관계를 위배하지 않도록 나열하는 것.
- **제약 조건:** **사이클(Cycle)**이 존재하면 위상 정렬을 수행할 수 없다. (닭이 먼저냐 알이 먼저냐 모순 발생)
    

### 2. 알고리즘 프로세스 (Indegree 방식)

1. **진입 차수(Indegree) 계산:** 모든 정점의 진입 차수(들어오는 간선 수)를 계산한다.
2. **큐 삽입:** 진입 차수가 **0**인(선행 조건이 없는) 정점을 모두 큐에 넣는다.
3. **반복:**
    
    - 큐에서 정점 $u$를 꺼내 출력한다 (정렬 결과 추가).
    - $u$에서 나가는 간선을 모두 제거한다 (연결된 정점 $v$의 진입 차수를 1 감소).
    - 새롭게 진입 차수가 0이 된 정점 $v$를 큐에 넣는다.
        
4. **종료:** 큐가 비었을 때 모든 정점을 방문했다면 정렬 성공, 못 했다면 사이클 존재.

## Topic 1. 분할 정복의 메커니즘과 실행 흐름 (Divide & Conquer)

### 1. 🏗️ 빌드업 (Context)

> **"거대한 문제는 작게 쪼개서 각개격파한다."**

- **개념:** 문제를 더 이상 쪼갤 수 없는 단위까지 나누어 해결한 뒤, 다시 합쳐서 답을 구하는 전략입니다.
- **유래:** 나폴레옹이 대규모 적을 소규모로 분산시킨 뒤 각개격파(Divide)하고 정복(Conquer) 했던 전술에서 유래했습니다.
    

### 2. 🔄 3단계 메커니즘 및 실행 흐름 (The "V" Shape Flow)

이 알고리즘은 **DFS(깊이 우선 탐색)** 순서로 작동하며, **"위에서 호출하고(Call), 아래에서 결과를 Return하는"** 체계적인 흐름을 가집니다.

#### ① 분할 (Divide) : 📉 내려가는 흐름 (Top-down)

- **주어 (Subject):** **함수의 호출 (Command)**
- **행위:** 문제를 해결하기 쉽도록 반으로 쪼개라는 **명령**이 위에서 아래로 전달됩니다.
- **상태:** 이 단계에서는 아직 **데이터가 정렬되지 않은 상태**로 쪼개지기만 합니다.
#### ② 정복 (Conquer) : 🛑 바닥 찍기 (Base Case)

- **시점:** 더 이상 쪼개지지 않는 원자 단위(Atomic Level, Size=1)에 도달했을 때입니다.
- **역할:** 재귀 호출이 멈추고(Stop), **반환(Return)의 기점**이 됩니다.

#### ③ 결합 (Combine) : 📈 올라오는 흐름 (Bottom-up)

- **주어 (Subject):** **실제 데이터의 처리 (Execution)**
- **행위:** 바닥에서 처리된 **결과물(데이터)**이 정렬/병합되어 위로 보고됩니다.
- **핵심:** **"호출 순서는 위에서 아래로 깊어지며 내려왔지만, 실제 정렬(해결)은 깊은 바닥에서부터 올라오며 완성됩니다."**

## Topic 3. 합병 정렬 (Merge Sort) 상세 구현

### 1. 🏗️ 빌드업 (Logic)

> **"이미 정렬된 두 개의 그룹을 합치는 것은 쉽다."**

- **전략:** 데이터가 1개가 될 때까지 쪼개면(Divide) 그 1개 자체로 '정렬된 상태'가 됩니다. 이 상태에서 두 그룹을 합치며(Merge/Combine) 올라오면 전체가 정렬됩니다.

### 2. 코드 구현 (C Language)

**Step 1. 분할 및 제어 (`merge_sort` 함수)**

- **역할 (Manager):** 전체 숲을 보며 나무를 쪼개는 관리자입니다.
- **흐름:** `Left`(📉) $\rightarrow$ `Right`(📉) $\rightarrow$ 정렬된 좌우 `Merge`(📈).

```C
//분할 함수 ("left ~ right 범위"를 반으로 쪼개라)
void merge_sort(int list[], int left, int right) {//list는 원본의 전체 배열
    int mid; //분할 기준점
    
//데이터가 2개이상일때만 진행,(left==right면 1개이므로 쪼개지 않고 리턴)
    if (left < right) {
	    // 1. 중간 지점 계산(Divide 기준점)
        mid = (left + right) / 2;
        
        // 2. 왼쪽을 바닥 끝까지 쪼개고 올라와! (재귀호출)
        merge_sort(list, left, mid);

        // 3. 오른쪽을 바닥 끝까지 쪼개고 올라와! (재귀호출)
        merge_sort(list, mid + 1, right);

        // 4. 둘 다 바닥을 찍고 정렬된채 올라오면 병합하라! (실제 작업)
        merge(list, left, mid, right);
    }
}
```

**Step 2. 병합 및 정렬 (`merge` 함수)**

- **역할 (Worker):** 정렬된 두 리스트를 합칩니다.
- **메모리:** 배열 내부에서 직접 위치를 바꾸는 것은 복잡하므로 `sorted`라는 추가 공간(임시 배열)이 반드시 필요합니다.
- **과정:**
    
    1. **비교(Two Pointers):** `i`(왼쪽팀), `j`(오른쪽팀) 값을 비교해 작은 것을 `sorted`에 넣음.
    2. **잔여 처리:** 먼저 끝난 팀을 놔두고, 남은 팀의 데이터를 몽땅 옮김.
    3. **반영:** `sorted`의 내용을 원본 `list`에 덮어씌움.

```C
#include <stdio.h>
#define MAX_SIZE 100

// 지역 변수로 선언하면 재귀 호출마다 배열이 생성됨(스택 오버플로우)
int sorted[MAX_SIZE]; 

// 병합함수(mid를 기준으로 나뉜 "left ~ right 범위"를 정렬하며 합쳐라)
// - 왼쪽 덩어리: left ~ mid 
// - 오른쪽 덩어리: mid+1 ~ right
// int list[]는 원본의 전체 배열
void merge(int list[], int left, int mid, int right) {
    int i = left;     //i: 시작인덱스 (왼쪽덩어리)
    int j = mid + 1;  //j: 시작인덱스 (오른쪽덩어리)
    int k = left;     //k: 저장할 인덱스 (임시배열)
    int l; // l: 복사 For문용 변수
    
// 1. 왼쪽, 오른쪽 덩어리 중 작은 값을 임시 배열에 넣음 (한쪽이 바닥날 때까지)

	// 증가하는 i, j가 각자 끝을 넘지 않도록
    while (i <= mid && j <= right) {
	    //i가 가리키는게 작다면, 그값을 넣고 i, k 포인터 전진
        if (list[i] <= list[j]) sorted[k++] = list[i++];
        //j가 가리키는게 작다면, 그값을 넣고 j, k 포인터 전진
        else sorted[k++] = list[j++];
    }
    
//2. 한 덩어리가 먼저 바닥났으니, 다른 덩어리의 남은 값들을 일괄 복사
	
	//왼쪽 덩어리의 인덱스 i가 끝(mid)을 넘었을 때 (왼쪽이 바닥남)
    if (i > mid) {
	    // 끝까지 못 간 인덱스 j부터 끝(right)까지 복사
        for (l = j; l <= right; l++) sorted[k++] = list[l];
    } else {
	    // 끝까지 못 간 인덱스(i)부터 끝(쪼갠 기준 mid)까지 복사
        for (l = i; l <= mid; l++) sorted[k++] = list[l];
    }

    // 정렬된 임시 배열 내용을 원본범위(left~right)에 반영 (Update)
    for (l = left; l <= right; l++) list[l] = sorted[l];
}
```

### ⚠️ 중요 분석 및 주의사항

| **구분**     | **내용**             | **비고**                            |
| ---------- | ------------------ | --------------------------------- |
| **시간 복잡도** | **$O(N \log N)$**  | 데이터 상태와 무관하게 항상 일정. (안정적)         |
| **공간 복잡도** | **$O(N)$**         | `sorted` 배열 필요. 메모리가 적은 환경에선 치명적. |
| **활용**     | **Linked List 정렬** | 배열과 달리 연결 리스트 정렬 시에는 퀵 정렬보다 강력함.  |
- 임시 배열로 복사했다가 다시 가져오는 과정에서 $2N \log N$ 수준의 이동 연산이 발생한다.
    - 이 때문에 일반적인 배열 정렬에서는 **퀵 정렬(Quick Sort)**보다 실제 속도가 느린 경우가 많다.
    - 단, **연결 리스트(Linked List)**를 정렬할 때는 인덱스 접근이 필요 없고 링크만 바꾸면 되므로 퀵 정렬보다 효율적일 수 있다.

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.10.30

### 💡 Interview

> [!faq]- Q. 퀵 정렬(Quick Sort)과 합병 정렬(Merge Sort)의 결정적 차이는 무엇인가?
>
> 🗣️ 핵심 답변
>
> 퀵 정렬은 최악의 경우 $O(N^2)$이 될 수 있지만 추가 메모리가 거의 필요 없고(In-place), 합병 정렬은 항상 $O(N \log N)$을 보장하지만 $O(N)$의 추가 메모리가 필요합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 그렇다면 합병 정렬은 언제 사용하는 게 좋은가?**
>     
>     - 데이터의 정렬 상태에 상관없이 안정적인 성능이 필요할 때, 혹은 배열이 아닌 **Linked List**를 정렬할 때(임의 접근 오버헤드가 없고 링크 조작만으로 병합 가능) 유리합니다. Stable Sort(안정 정렬) 성질을 유지해야 할 때도 사용합니다.
>         

> [!faq]- Q. 합병 정렬에서 재귀 호출의 순서를 설명하시오.
>
> 🗣️ 핵심 답변
>
> 합병 정렬은 Depth-First(깊이 우선) 방식으로 동작합니다. 왼쪽 자식 노드(left ~ mid)에 대한 분할과 병합이 완전히 끝난 후에야 오른쪽 자식 노드(mid+1 ~ right)의 분할이 시작됩니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 왜 이런 순서가 중요한가?**
>     
>     - 병합(`merge`) 함수가 호출되는 시점에는 반드시 병합 대상인 두 개의 하위 리스트가 이미 정렬되어 있어야 하기 때문입니다.
>         

> [!faq]- Q. 합병 정렬의 시간 복잡도가 최악의 경우에도 $O(N \log N)$인 이유는?
>
> 🗣️ 핵심 답변
>
> 합병 정렬은 피벗(Pivot) 같은 특정 요소에 의존하지 않고, 리스트를 무조건 물리적 절반으로 나누기 때문입니다.
>
> **📚 논리적 근거**
>
> - 데이터가 정렬되어 있든 역순이든 상관없이 항상 트리 높이가 $\log_2 N$으로 유지되며, 각 단계에서의 병합 비용은 $N$이므로 전체 연산량은 항상 $N \log N$이 됩니다.
>

## Topic 1. 퀵 정렬 (Quick Sort)의 핵심 논리

### 1. 🏗️ 빌드업 (Why & Context)

> **"합병 정렬은 '물리적인 위치(크기의 절반)'로 쪼개지만, 퀵 정렬은 '값'으로 쪼갠다."**

- **비교 분석**:
    - **합병 정렬 (Merge Sort)**: 무조건 리스트의 정중앙을 잘라 반반씩(Size) 나눈다. 분할은 단순하지만, 나중에 합칠 때(Merge) 정렬 연산이 일어난다.
    - **퀵 정렬 (Quick Sort)**: 리스트 내의 특정 **값(Pivot)** 을 기준으로, 이보다 작은 그룹과 큰 그룹으로 나눈다.
        - 퀵 정렬의 분할 과정은 단순한 쪼개기가 아니라, 내부에서 **자리 바꿈(Swap)과 정렬**이 일어나기 때문에 **'파티셔닝(Partitioning)'** 이라는 고유 명사를 붙여서 부른다.

### Concept

- **핵심 메커니즘**:
    1. **Pivot 선정**: 리스트에서 기준이 될 원소 하나를 선택한다. (강의에서는 주로 '첫 번째 원소' 또는 '중간값' 사용)
    2. 분할(파티션):
        - Pivot보다 작은 값은 정렬된 부분의 왼쪽 그룹 끝으로, 큰 값은 정렬된 부분의 오른쪽 그룹 끝으로 몰아넣는다.
        - 이 과정이 끝나면 Pivot을 두그룹 가운데에 넣는다.
        - 결과: pivot의 왼쪽은 피벗보다 작은집합, 오른쪽은 피벗보다 큰 집단이 된다. 이로서 pivot만 정렬된 정확한 위치에 자리잡게 된다
    3. **재귀 (Recursion)**: Pivot을 제외한 왼쪽 부분 집합과 오른쪽 부분 집합에 대해 동일한 과정을 반복한다.

## Topic 2. 퀵정렬의 분할: 파티션(Partition) 상세

### 1. 🏗️ 빌드업 (Why & Context)

> **"어떻게 피벗을 기준으로 작은 놈과 큰 놈을 가를 것인가?"**

- **동기**: 단순히 새로운 배열을 만들어 담는다면 쉽겠지만, 퀵 정렬의 장점인 **제자리 정렬(In-place sort)** 을 살리기 위해 기존 배열 내에서 자리를 교환(Swap)하는 방식을 사용해야 한다. 이를 위해 두 개의 포인터(`low`, `high`)가 필요하다.

### Concept (Low & High Pointer)
- **동작 원리**:
    - **Pivot**: 왼쪽 첫 번째 원소(`List[Left]`)라고 가정.
    - **`low` (Left → Right)**: 배열 시작에서 출발하여 Pivot보다 **큰 값**을 찾을 때까지 오른쪽으로 이동한다.
    - **`high` (Right → Left)**: 베열 끝에서 출발하여 Pivot보다 **작은 값**을 찾을 때까지 왼쪽으로 이동한다.
    - **교환 (Swap)**:
        - `low`와 `high`가 멈췄을 때, 아직 서로 교차하지 않았다면(`low < high`) 두 값을 맞바꾼다.
        - `low`와 `high`가 교차했다면(`low > high`), 분할이 끝난 것이다. 이때 **Pivot과 `high`가 가리키는 값을 교환**한다. (Pivot이 중앙으로 이동하며 고정됨)

## Topic 3. C언어 구현 및 코드 분석

**Step 1. 재귀 호출 및 제어 (`quick_sort` 함수)**
>
> - **핵심:** `partition` 함수가 끝나면 반환값 `q`(피벗의 위치)는 **이미 정렬이 끝난 상태(Fixed)** 입니다. 따라서 재귀 호출 시 `q`는 포함하지 않습니다.
> 
```C
//퀵정렬 재귀(정렬된 피벗이 제외된 "left ~ right 범위"를 반으로 쪼개라)
void quick_sort(int list[], int left, int right) {
//데이터가 2개 이상일때만 진행,(left==right면 1개이니 쪼개지 않고 리턴)
    if (left < right) {
	    
	//1. 영구적으로 자리가 확정된 피벗의 인덱스를 파티션이 반환.
        int q = partition(list, left, right); 
        
	//2. 피벗기준 왼쪽 덩어리 정렬(재귀) 
        quick_sort(list, left, q - 1);
        
	//3. 피벗기준 왼쪽 덩어리 정렬(재귀) 
        quick_sort(list, q + 1, right);
    }
}
```

**Step 2. 파티션 (`partition` 함수)**

### ⚠️ 중요 분석 (Professor's Emphasis)

- **Q. 왜 `low`를 비교하기 전에 먼저 증가(`low++`)시키는가?**
    - **A:** 피벗을 `list[left]`(첫 번째 원소)로 잡았기 때문이다. `low`를 `left`로 초기화했으므로, 자기 자신(피벗)과의 비교를 건너뛰고 바로 다음 원소(`left + 1`)부터 비교해야한다.
    - 그래서 do-while로 선증가 방식을 쓴다.
	- high도 do-while로 맞춰주기 위해서, 초기값을 right+1로 설정한다.
    - 하지 않으면 피벗 값과 피벗 값을 비교하는 불필요한 연산이 발생하거나, 루프 조건 설정이 까다로워진다.
- **재귀 호출 순서의 이해:** 위에 서술한 분할의 매커니즘이다
    - `partition`이 실행되면 피벗 하나가 제자리를 찾는다.
    - 그 후 `quick_sort(left)`가 먼저 호출되므로, 트리의 왼쪽 가지를 끝까지 타고 내려가며 정렬을 수행한 뒤에야 오른쪽 가지(`quick_sort(right)`)로 넘어온다. 이 순서를 놓치지 말 것.

```C
#include <stdio.h>
//값 교환 함수
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 분할 함수 ()
int partition(int list[], int left, int right) {
    int pivot, temp;
    int low, high;
    
    low = left;      //low는 왼쪽 시작점
    high = right + 1;//high는 오른쪽 끝 (do-while 감소때문에 +1)
	pivot = list[left]; // 피벗이 첫번째 요소가 기준인 경우
	
	
	//목적: 피벗보다 작은놈들이 왼쪽부분, 큰놈들이 오른쪽부분에 있어야함
	// 교차하기 전까지 반복 (low와 high가 엇갈리면 종료)
    do { 
        do { //1. 범위 제한안에서 low 증가한뒤, low위치에 큰놈 확인
            low++; 
        } while (list[low] < pivot && low <= right); 
        
		/*low가 큰놈을 발견해서 while의 반복 중단, 다음 코드 실행*/
		
        do {//2. 범위 제한안에서 high 감소한뒤, high위치에 작은놈확인
            high--; 
        } while (list[high] > pivot);
        //끝까지가기전 pivot과의 크기 비교로 종료되니 범위 제한 안함

        if (low < high) {//3.low,high 잘못된놈 찾았으니 자리서로 바꿔(서로 바꾸기만하면 위치는 부정확해도 범주일치하게됨)
            swap(&list[low], &list[high]);
        }
    } while (low < high); //low와 high가 교차된다면 반복하지 않음
    //반복하지 않는거지 중간에 break;하는게 아님 끝까지 수행함 그래서 3번에 조건을 low<high로 한것. 
    
    // 4. 교차했다면, pivot을 자신의 올바른 위치(high)로 보냄
	    // 현재 low: 오른쪽 범위의 시작 high: 왼쪽 구역의 끝
	    // 피벗은 작은값의 바로 뒤에 와야하므로, high와 바꾸어야함
    swap(&list[left], &list[high]); 

    return high; // pivot의 확정된 위치 반환
}
```
#### 실제 시나리오 (Low가 High를 역전하는 순간)

1. **`do { low++ }`**: `low`가 계속 가다가 피벗보다 큰 놈을 찾았습니다. 그런데 이 위치가 이미 `high`보다 오른쪽(역전)일 수 있습니다.
2. **그래도 아래 줄로 갑니다.** (`high` 루프 실행)
3. **`do { high-- }`**: `high`도 자기 할 일을 합니다(작은 놈 찾기). (보통 금방 멈춥니다.)
4. **`if (low < high)` 체크**:
    - 여기서 확인해 보니 `low`가 `high`보다 큽니다(역전됨).
    - **그래서 `swap`을 "안 하고" 지나갑니다.** (이 `if` 문이 방어막 역할을 함)
5. **`while (low < high)` (바깥 루프 조건 확인)**:
    - 이제서야 바깥 루프의 조건을 봅니다.
    - "어? 너네 역전됐네?" $\rightarrow$ **이제 바깥 `do-while` 루프 종료.**

## Topic 1. 퀵 정렬의 최악의 경우 (Worst Case)

### 1. 🏗️ 빌드업 (Why & Context)

> **"왜 이미 정렬된 데이터를 다시 정렬할 때 퀵 정렬은 느려지는가?"**

- **문제 제기**: 퀵 정렬은 일반적으로 매우 빠르지만($O(N \log N)$), 특정 상황에서는 $O(N^2)$까지 성능이 떨어진다.
- **최악의 시나리오**: 데이터가 이미 **오름차순** 또는 **내림차순**으로 정렬되어 있고, **피벗(Pivot)을 가장 왼쪽(또는 오른쪽) 값으로 고정**했을 때 발생한다.
    

### Concept & Mechanism

- **논리적 원인**:
    
    1. **불균형 분할 (Unbalanced Partitioning)**: 정렬된 상태에서 피벗을 첫 번째 요소로 잡으면, 피벗보다 작은 값(혹은 큰 값)이 아예 없거나 전부이다.
    2. **트리의 편향**: 리스트가 반($N/2$)으로 쪼개지지 않고, `1`개와 `N-1`개로 계속 쪼개진다.
    3. **깊이 증가**: 재귀 호출의 깊이가 $\log N$이 아니라 $N$이 되며, 각 단계의 비교 연산도 $N$에 비례하므로 총 복잡도는 $N \times N = O(N^2)$가 된다.
        
- **비교**: 랜덤 데이터에서는 피벗을 기준으로 좌우가 균등하게 나뉘어 효율적이지만, 정렬된 데이터에서는 최악의 효율을 보인다.

## Topic 2. 힙 (Heap) 자료구조의 이해

### 1. 🏗️ 빌드업 (Why & Context)

> **"돈을 더 낸 사람을 먼저 태워주는 놀이공원 큐패스(Q-Pass)처럼, 우선순위가 높은 데이터를 먼저 처리하자."**

- **동기**: 일반적인 큐(Queue)는 선입선출(FIFO)이지만, 현실 세계(응급실, VIP 서비스 등)에서는 **우선순위(Priority)가** 높은 순서대로 처리해야 하는 경우가 많다. 이를 효율적으로 구현하기 위한 자료구조가 힙(Heap)이다.

### Concept: 완전 이진 트리 (Complete Binary Tree)

- **정의**: 우선순위 큐를 위해 만들어진 **완전 이진 트리** 형태의 자료구조.
    - **최대 힙 (Max Heap)**: 부모 노드의 키 값 $\ge$ 자식 노드의 키 값. (루트가 가장 큼)
    - **최소 힙 (Min Heap)**: 부모 노드의 키 값 $\le$ 자식 노드의 키 값. (루트가 가장 작음)
- **특징**:
    - **중복 허용**: 이진 탐색 트리(BST)와 달리 중복된 값을 허용한다.
    - **배열 구현**: 1번 인덱스를 루트로 사용하면 수식으로 자식/부모 접근이 가능하다.
		- **부모 인덱스:** `i / 2`
		- **왼쪽 자식:** `i * 2`
		- **오른쪽 자식:** `i * 2 + 1`

## Topic 3. 힙 정렬 (Heap Sort)과 삭제 알고리즘

### 1. 🏗️ 빌드업 (Why & Context)

> 힙에서는 가장 큰 값(Max Heap 기준)이 항상 **루트(Root)** 에 있다. 이 루트를 계속 꺼내서 배열의 뒤쪽으로 보내면 자연스럽게 정렬이 된다.

- **핵심 아이디어**:
    
    1. 정렬되지 않은 배열을 **최대 힙(Max Heap)** 으로 변환한다. (Make Heap)
    2. 루트(최대값)를 삭제(Pop)하여 배열의 맨 뒤로 보낸다.
    3. 남은 데이터로 다시 힙을 구성하고 이를 반복하면 오름차순 정렬이 완성된다.
```C
// 힙 정렬 메인 로직
void heap_sort(int a[], int n) {
    int i, temp;

    // 1. 초기 최대 힙 구성 (Build Heap)
    // 자식이 있는 마지막 노드부터 거슬러 올라가며 힙을 만든다.
    for (i = n / 2; i >= 1; i--) {
        make_heap(a, i, n); 
    }

    // 2. 정렬 과정 (Extract Max & Re-heapify)
    for (i = n; i > 1; i--) {
        // 루트(최댓값)와 마지막 노드 교환
        SWAP(a[1], a[i], temp);
        
        // 힙 크기를 하나 줄이고(i-1), 루트를 다시 힙 성질에 맞게 내림
        make_heap(a, 1, i - 1);
    }
}
```
## Concept: 삭제(Delete) 및 재구성 알고리즘
### 1. 🏗️ 빌드업 (Why & Context)

- **문제:** 루트(최댓값)가 빠져나가면 트리가 끊어진다. 2인자(자식들) 중 누구를 올릴 것인가?
- **해결책:** 빈자리를 채우기 위해 자식들을 한 칸씩 당기는 방식은 복잡하다. 대신 **트리의 가장 마지막 노드**를 루트로 강제 이동시킨 후, 아래로 내려보내는(Sift Down) 방식이 훨씬 효율적이다.
- **개념적 삭제 구현**:
	1. **Move Last to Root:** 힙의 가장 마지막 노드(트리의 우측 하단 말단)를 루트 자리로 옮긴다.
	2. **Compare Children:** 현재 노드와 왼쪽/오른쪽 자식 중 **더 큰 자식**을 찾는다.
	3. **Swap & Descent:** 자식이 나보다 크다면 교환(Swap)하고 그 위치로 내려간다.
	4. **Terminate:** 자식이 나보다 작거나, 리프 노드에 도달하면 멈춘다.

### 힙 삭제 및 재구조화

```C
void make_heap(int a[], int root, int n) {
    int child, temp;
    temp = a[root]; // 루트 값을 임시 저장
    child = root * 2; // 왼쪽 자식

    while (child <= n) {
        // 더 큰 자식 선택 (오른쪽 자식이 있고, 왼쪽보다 크다면)
        if (child < n && a[child] < a[child + 1]) {
            child++; 
        }

        // 부모가 자식보다 크면 중단 (힙 속성 만족)
        if (temp >= a[child]) break;

        // 자식이 더 크면 부모 위치로 올림
        a[child / 2] = a[child];
        
        // 아래 레벨로 이동
        child *= 2;
    }
    
    // 최종 위치에 저장해둔 값 삽입
    a[child / 2] = temp;
}
```

- **⚠️ 주의사항:** 코딩 시 인덱스 계산(`child * 2`)과 경계 조건(`child <= n`)을 꼼꼼히 확인해야 한다. 이 로직이 힙 정렬의 핵심 엔진이다.

> 🗣️ 핵심 답변

> 🗣️ 핵심 답변
>

>
> 🗣️ 핵심 답변

> 퀵 정렬은 최악의 경우 $O(N^2)$까지 성능이 저하될 수 있지만, 힙 정렬은 데이터 상태와 무관하게 항상 **$O(N \log N)$**을 보장합니다.

## Topic 1. 기수 정렬 (Radix Sort) 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 상황에 쓸 수 있는 범용 정렬은 아니지만, 조건만 맞으면 가장 빠른 정렬"

- **기존 방식의 한계:** 퀵 정렬, 합병 정렬 등은 **비교 연산(Comparison)** 을 필수로 하며, 이론적 하한선이 $O(N \log N)$이다.
- **발상의 전환:** "비교하지 않고 정렬할 수는 없을까?" → 데이터의 **자릿수(Digit)** 값을 그대로 활용하여 버킷에 담았다 빼는 방식 고안.

### Concept

- **정의:** 레코드 키의 값(자릿수)을 이용하여 해당 버킷에 원소를 분배(Distribute)하고 순서대로 수집(Collect)하는 과정을 반복하는 정렬 기법.
- **시간 복잡도:** $O(dN)$ (d: 자릿수, n: 데이터 개수).
    - 자릿수가 작다면 사실상 선형 시간($O(N)$)에 가까운 매우 빠른 속도를 자랑한다.
- **제약 조건 (Trade-off):**
    1. **키의 길이가 동일해야 함:** 자릿수가 일정하지 않으면 적용이 어렵다.
    2. **특정 데이터 타입:** 정수나 문자열처럼 자릿수/문자 위치가 명확한 경우에만 사용 가능하다. (실수는 적용 난해)
    3. **추가 메모리 필요:** 각 자릿수 값을 담을 **버킷(Bucket)** 공간이 추가로 필요하다. (공간 복잡도 증가)

## Topic 2. 기수 정렬 메커니즘 (LSD & Buckets)

### 1. 🏗️ 빌드업 (Logic)

- **접근법:** 100자리 숫자를 정렬하려면 버킷이 몇 개 필요한가?
    - 0~99… 까지 만들면 메모리가 부족하다.
    - 대신 **0~9까지 10개의 버킷**만 만들고, 낮은 자릿수부터 높은 자릿수까지 반복해서 재활용하는 방식을 사용한다.
- **순서의 중요성 (LSD vs MSD):**
    - 일반적으로 **LSD (Least Significant Digit)** 방식을 사용한다. 즉, **가장 낮은 자릿수(1의 자리)** 부터 정렬하고, 점차 높은 자릿수로 이동해야 한다.
    - _이유:_ 높은 자릿수(예: 10의 자리)를 먼저 정렬하면, 나중에 1의 자리를 정렬할 때 이미 정렬된 10의 자리 순서가 섞여버린다. 반대로 LSD는 낮은 자릿수의 정렬 상태를 유지하며(Stable) 높은 자릿수 정렬을 수행한다.
        

### Concept & Process (예시: 10진수)

1. **준비:** 0부터 9까지 인덱스를 가진 10개의 **버킷(Queue)** 준비.
2. **1단계 (1의 자리):** 각 숫자의 1의 자리를 보고 해당 버킷에 넣음(Enqueue) → 버킷 순서대로 뺌(Dequeue).
3. **2단계 (10의 자리):** 1단계 결과 리스트에서 10의 자리를 보고 해당 버킷에 넣음 → 버킷 순서대로 뺌.
4. **반복:** 최대 자릿수($d$)만큼 반복하면 최종 정렬 완료.
    

### 자료구조 (Why Queue?)

- **핵심 질문:** 왜 버킷을 **큐(Queue)**로 구현해야 하는가?
- **이유:** **안정 정렬(Stable Sort)** 속성을 유지하기 위함이다.
    - 같은 자릿수 값을 가진 데이터들 사이에서도, **이전 단계(더 낮은 자릿수)에서 정렬된 순서**가 유지되어야 한다. 따라서 먼저 들어온 데이터가 먼저 나가는 **FIFO(First-In First-Out)** 구조가 필수적이다.

## Topic 3. 32비트 정수 최적화 구현

### 1. 🏗️ 빌드업 (Optimization)

- 컴퓨터는 2진수를 사용하므로 버킷 2개(0, 1)만 있으면 된다.
- 그러나 32비트 정수(`int`)를 1비트씩(버킷 2개) 처리하면 **32번의 루프(Pass)**를 돌아야 한다. 이는 비효율적이다.

### Concept

- **8비트 단위 처리 (256 Buckets):**
    - 32비트를 8비트씩 4덩어리로 쪼갠다. ($2^8 = 256$)
    - 버킷을 **256개** 만들면, 루프를 **4번(Pass)** 만 돌면 정렬이 완료된다.
    - **효과:** 메모리를 조금 더 쓰고(버킷 256개), 속도를 비약적으로 향상시킨다. (비트 연산 활용)

### Code 구현 (Structure Idea)

```C
#define BUCKETS 10 // 10진수의 경우
#define DIGITS 4   // 최대 자릿수

// 기수 정렬 의사 코드 (LSD 방식)
void radix_sort(int list[], int n) {
    Queue buckets[BUCKETS]; // 큐 배열 생성
    int factor = 1; // 1, 10, 100… 자릿수 계산용
	
    // 자릿수만큼 반복 (d회)
    for (int d = 0; d < DIGITS; d++) {
        // 1. 분배 (Distribute)
        for (int i = 0; i < n; i++) {
	        // 현재 자릿수의 값에 해당하는 버킷에 넣음
            int digit = (list[i] / factor) % 10;
            enqueue(&buckets[digit], list[i]);
        }
			
        // 2. 수집 (Collect)
        int i = 0;
        for (int b = 0; b < BUCKETS; b++) {
            while (!is_empty(&buckets[b])) {
                list[i++] = dequeue(&buckets[b]);
            }
        }
        
        factor *= 10; // 다음 자릿수로 이동
    }
}
```

## Topic 2. CS Basics: 부동소수점 (Floating Point)

### 1. 🏗️ 빌드업 (Why & Context)

> "기수 정렬은 왜 실수(Float)에는 적용하기 어려운가? 컴퓨터는 실수를 어떻게 저장하는가?"

- **문제 제기:** 정수는 비트 패턴이 값의 크기와 직결되지만, 실수는 **IEEE 754 표준**에 따라 부호, 지수, 가수로 나뉘어 저장되므로 단순한 자릿수 비교가 불가능하다.

### Concept: 부동소수점 (Floating Point) 이슈

- **저장 방식 (IEEE 754):** `부호(1bit)` + `지수(8bit/11bit)` + `가수(23bit/52bit)`
- **정밀도 문제 (Precision):**
    - $0.1$을 2진수로 표현하면 무한 소수(순환 소수)가 된다. ($0.00011001100…$)
    - 컴퓨터는 이를 유한한 비트에 욱여넣으면서 잘라내므로, $0.1 + 1.1 \neq 1.2$와 같은 오차가 발생한다.
- **기수 정렬 적용의 어려움:**
    - 부동소수점은 비트 전체를 단순 정수처럼 해석해서 정렬하기 어렵다 (지수부와 가수부의 가중치가 다름).
    - 음수 처리(부호 비트) 및 지수 바이어스(Bias) 처리가 복잡하다.

## Topic 1. 그래프의 정의와 모델링 (Why & What)

### 1. 🏗️ 빌드업 (Why?)

> **"선형 리스트나 트리(Tree)만으로는 표현할 수 없는 복잡한 관계는 어떻게 다룰 것인가?"**

- **현실의 복잡성:** 단순한 계층(Hierarchy)이나 순서(Linear)가 아닌, 복잡하게 얽힌 망(Network) 구조를 표현해야 합니다.
    - _예: 지하철 노선도, 선수 과목(Prerequisite), SNS 친구 관계, 전력망 등._
- **모델링(Modeling):** 현실 세계의 **객체(Object)**와 그들 간의 **관계(Relationship)**를 컴퓨터가 이해할 수 있도록 추상화하는 과정입니다.
    

### 2. 핵심 개념 (Concept)

- **정의:** 정점($V$)의 집합과 간선($E$)의 집합으로 구성된 비선형 자료구조 ($G = (V, E)$).
- **트리(Tree)와의 관계:** 트리는 그래프의 특수한 형태(부분 집합)입니다.
    - **트리의 조건:** 사이클(Cycle)이 없음, 계층 구조, $N$개 노드일 때 항상 $N-1$개의 간선 존재.
        

---

## Topic 2. 그래프의 구조와 핵심 용어

### 1. 구성 요소

- **정점 (Vertex, Node):** 객체 그 자체를 표현 ($V_i$).
- **간선 (Edge, Link):** 정점들 사이의 연결 관계.
    - **인접 (Adjacency):** 간선으로 직접 연결된 두 **정점** 간의 관계. (예: 정점 A와 B는 인접하다)
    - **부속 (Incidence):** **간선**이 특정 정점에 연결된 상태. (예: 간선 e는 정점 A에 부속된다)
        

### 2. 경로와 연결성

- **경로 (Path):** 간선을 따라 갈 수 있는 길(정점들의 나열).
- **단순 경로 (Simple Path):** 중복 방문 없이 진행하는 경로.
- **사이클 (Cycle):** 시작점과 도착점이 동일한 단순 경로.
- **연결 그래프 (Connected Graph):** 모든 정점 쌍 사이에 경로가 존재하는(끊어지지 않은) 그래프.
    

---

## Topic 3. 그래프의 유형 및 차수 (Degree)

그래프의 형태에 따라 **간선의 최대 개수**와 **차수(Degree)** 계산법이 달라집니다.

### 1. 무방향 그래프 (Undirected Graph)

- **정의:** 간선에 방향이 없음 (양방향 통행). $(A, B) = (B, A)$.
- **차수 (Degree):** 정점에 연결된 간선의 총개수.
- **최대 간선 수:** $\frac{n(n-1)}{2}$개. (양방향 중복을 2로 나눔)
> 인접행렬로 구현시 대각선 기준 대칭 행렬이며, 차수는 행+열의 합
>
### 2. 방향 그래프 (Directed Graph)

- **정의:** 간선에 화살표 방향 존재 (일방통행). $<A, B> \neq <B, A>$
- **구조:** 시작점(Tail) $\to$ 도착점(Head).
- **차수 (Degree):** 진입차수 + 진출차수
    - **진입 차수 (In-degree):** 들어오는 화살표 수 (Head).
    - **진출 차수 (Out-degree):** 나가는 화살표 수 (Tail).
- **최대 간선 수:** $n(n-1)$개.
>인접행렬로 구현시 비대칭행렬, 진출차수: 행의합, 진입차수: 열의합
### 3. 완전 그래프 (Complete Graph)

- **정의:** 모든 정점이 서로 빠짐없이 연결된 그래프.
- **특징:** 가능한 최대 간선 수를 가짐. (네트워크의 **Mesh형** 구조)
    

### 4. 가중치 그래프 (Weighted Graph / Network)

- **정의:** 간선에 비용(Cost), 거리(Distance) 등의 **가중치(Weight)**가 할당된 그래프.
- **활용:** 내비게이션(최단 경로), 다익스트라(Dijkstra) 알고리즘 등.
    
> [!faq]Q. 그래프(Graph)와 트리(Tree)의 결정적인 차이점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 트리는 **사이클(Cycle)이 없는** 연결 그래프이며, 부모-자식의 **계층(Hierarchical)** 구조를 가지고 루트(Root)가 존재합니다.
> 반면 그래프는 사이클이 존재할 수 있고 계층이나 루트 개념이 없는 망(Network) 구조입니다.
>

> [!faq]Q. 방향 그래프에서 최대 간선 수가 $n(n-1)$인 이유는?
>
> 🗣️ 핵심 답변
>
> 한 정점이 자기 자신을 제외한 나머지 $n-1$개 정점에 화살표를 쏠 수 있고, 정점이 총 $n$개이므로 $n(n-1)$입니다. 무방향과 달리 왕복($A \to B, B \to A$)을 별개로 치므로 2로 나누지 않습니다.

## Topic 1. 인접 행렬(Adjacency Matrix)의 구현

### 1. 🏗️ 빌드업 (Why & Context)
> **"사람은 그림으로 이해하지만, 컴퓨터 메모리는 주소와 공간만 존재한다. 화살표 개념이 없는 메모리에 어떻게 저장할 것인가?"**

- **구조:** $N$개의 정점을 $N \times N$ 크기의 **2차원 배열**로 표현.
- **값의 의미:** `1` (연결됨), `0` (연결 안 됨),
	- 가중치 인접행렬의 경우 간선이 없으면 `0` 대신 **`무한대`** 로 표시.
- **장점:**
    - **간선 조회:** 두 정점 $u, v$가 연결되었는지 확인하려면 `M[u][v]`만 보면 되므로 **$O(1)$**로 매우 빠르다.
    - **차수 계산:** 특정 행(또는 열) 전체를 더하면 되므로 $O(N)$이다.
- **단점:**
    - **전체 간선 탐색:** 모든 간선을 찾으려면 행렬 전체를 훑어야 하므로 **$O(N^2)$**의 시간이 걸린다.
	- **희소 행렬(Sparse Matrix)**: 정점 수에 비해 간선이 매우 적은 경우, 행렬의 대부분이 `0`으로 채워져 메모리가 심각하게 낭비된다.
        

### Code 구현

배열을 이용한 그래프 초기화 및 정점/간선 삽입 로직이다.

```C
#define MAX_VERTICES 50

typedef struct GraphType {
    int n; // 정점의 개수
    int adj_mat[MAX_VERTICES][MAX_VERTICES];
} GraphType;

// 그래프 초기화
void init(GraphType* g) {
    int r, c;
    g->n = 0; // 정점 개수 0으로 초기화
    for (r = 0; r < MAX_VERTICES; r++)
        for (c = 0; c < MAX_VERTICES; c++)
            g->adj_mat[r][c] = 0; // 모든 값을 0으로 채움
}

// 정점 삽입 (Vertex Insertion)
void insert_vertex(GraphType* g, int v) {
    if (((g->n) + 1) > MAX_VERTICES) {
        printf("Graph: 정점 개수 초과\n");
        return;
    }
    g->n++; // 단순히 카운트만 증가시킴 (배열 인덱스 확장 개념)
}

// 간선 삽입 (Edge Insertion)
void insert_edge(GraphType* g, int start, int end) {
    if (start >= g->n || end >= g->n) {
        printf("Graph: 정점 번호 오류\n");
        return;
    }
    // 무방향 그래프 가정 (대칭)
    g->adj_mat[start][end] = 1;
    g->adj_mat[end][start] = 1;
}
```

- **⚠️ 주의사항**: `insert_vertex` 호출 시 실제로 메모리를 할당하는 것이 아니라, `g->n` 카운터를 늘려 배열의 유효 범위를 확장하는 개념이다. 50개를 넘어가는 51번째 정점이 들어오면 배열 크기 제한(Static allocation)으로 인해 오버플로우 처리를 해야 한다.

## Topic 2. 인접 리스트(Adjacency List)의 핵심 개념

### 1. 🏗️ 빌드업 (Why & Context)
> "정점은 100개인데 간선은 5개뿐이라면, $100 \times 100$ 행렬을 만드는 것은 낭비 아닌가?" ( $10,000 \times 4$Byte = 40KB)가 필요하다.
> "연결된 놈들만 리스트로 엮자"

- **헤더 노드 배열 :** 정점의 개수($N$)만큼의 **포인터 배열**을 만듭니다. 각 칸은 정점연결리스트의 **주소**를 가리킵니다.
- **정점 연결 리스트:** 각 정점 포인터 뒤에, 해당 정점과 **실제로 연결된(인접한) 정점들만** 노드로 만들어 연결합니다.

```C
    // 행(Row): 출발(From), 열(Col): 도착(To) -> 진출 차수 기준
    int graph[N][N] = {
        {0, 1, 0, 1}, // 정점 0: 1, 3으로 진출
        {0, 0, 1, 1}, // 정점 1: 2, 3으로 진출 (예시)
        {0, 0, 0, 1}, // 정점 2: 3으로 진출
        {0, 0, 0, 0}  // 정점 3: 진출 없음
    };
```
### 2. ⚠️ 핵심 오개념 교정 (Crucial Misconception)

> [!warning] **학생들이 많이 틀림** 리스트 $A \to B \to C$
> - **잘못된 해석:**"A에서 B로 가고, B에서 C로 가는구나"라고 **경로(Path)**로 해석하면 절대 안 된다.
> - **올바른 해석**: "A는 B와 연결되어 있고, A는 (또한) C와도 연결되어 있다." 즉, 순서는 구현 편의상 오름차순 정렬할 뿐이다.
>     

### 3. 그래프 종류별 인접리스트 특징

- **무방향 그래프**: 간선 하나당 노드가 2개씩 생성된다
	- 간선 $(A, B)$가 있으면, $A$의 리스트에 $B$가 있어야 하고, $B$의 리스트에도 반드시 $A$가 있어야 한다. (중복 저장됨)
- **방향 그래프:** 총 노드 수 = 간선 수.
	- $A \rightarrow B$라면, $A$의 리스트(진출 차수 기준)에만 $B$가 저장된다. $B$의 리스트에는 $A$가 없다.

## Topic 4. 인접 리스트 구현 (C Code Analysis)

### 1. 자료구조 정의

```C
// 연결 리스트의 노드 구조체
typedef struct GraphNode {
    int vertex;             // 연결된 정점 번호
    int weight; // 가중치 필요 시 추가
    struct GraphNode* next; // 다음 노드 포인터
} GraphNode;

// 그래프 구조체 (포인터 배열 사용)
typedef struct GraphType {
    int n; // 정점의 개수
    GraphNode* adj_list[MAX_VERTICES]; // 헤드 노드 포인터 배열
} GraphType;
```

### 2. 포인터 배열에 대한 이해 (Professor's Emphasis)

- `GraphNode* adj_list[MAX_VERTICES]`의 의미:
    - 각 칸에 저장되는 값이 **`GraphNode`형 데이터의 주소값(포인터)** 인 배열이다.
    - 즉, `adj_list[0]`은 0번 정점에 연결된 첫 번째 노드의 주소를 담고 있다.
    - 포인터 변수 자체의 크기는 무조건 **4바이트(32bit) 또는 8바이트(64bit)** 이다. 가리키는 데이터가 아무리 커도 포인터 변수의 크기는 일정하다는 점을 명심할 것.
 
### Code 구현 (초기화 및 간선 삽입)

```C
// 초기화
void init(GraphType* g) {
    int v;
    g->n = 0;
    for (v = 0; v < MAX_VERTICES; v++) {
        g->adj_list[v] = NULL; // 모든 헤드 포인터를 NULL로 초기화
    }
}

// 간선 삽입 (방향 그래프: u -> v)
// 무방향일 경우 insert_edge(g, u, v); insert_edge(g, v, u); 두 번 호출
void insert_edge(GraphType* g, int u, int v) {
    if (u >= g->n || v >= g->n) return;
    
    // 1. 새로운 노드 생성(동적할당)
    GraphNode* node;
    node = (GraphNode*)malloc(sizeof(GraphNode));
    node->vertex = v;
    
    // 2. 리스트의 맨 앞에 삽입 (가장 쉬운 방법)
    // 기존 헤드가 가리키던 놈을 새 노드의 뒤에 붙임
    node->link = g->adj_list[u];
    // 새 노드를 헤드로 설정
    g->adj_list[u] = node;
    
    // ※ 주의: 위 코드는 역순으로 저장됨 (나중에 넣은게 앞에 옴).
    // 오름차순 유지를 원한다면 순회하여 위치를 찾는 로직이 추가로 필요함.
}
```

## 기타 핵심 (Etc & Tips) - 알고리즘 11.13

- **시험 및 과제 팁**:
    - 인접 리스트 그림을 그리거나 해석할 때, $A-B-C$ 연결을 $A \to B \to C$ 이동 경로로 착각하면 점수가 날아간다.
    - 방향 그래프를 그릴 때 $A \to B$ 화살표가 있으면 A의 리스트에 B를 적어야 한다. (B의 리스트에 A를 적지 않도록 주의).

### 💡 Interview
> [!faq]Q. 인접 행렬 vs 인접 리스트, 언제 무엇을 쓰는가?**
>
> 🗣️ 핵심 답변
>
> 간선이 많은 **밀집 그래프(Dense Graph)**라면 인접 행렬이 구현이 쉽고 간선 조회($O(1)$)가 빨라 유리합니다.
> 반면, 간선이 적은 **희소 그래프(Sparse Graph)** 라면 인접 리스트가 메모리를 훨씬 적게 차지하므로 효율적입니다. 인접리스트의 단점은 연결 여부를 확인할때 리스트를 모두 탐색해야합니다.
>
> **📚 공간 복잡도 비교**
>
> - 인접 행렬: $O(V^2)$ (무조건 $N \times N$ 할당)
> - 인접 리스트: $O(V + E)$ (실제 존재하는 간선만큼만 할당)
>

> [!faq]Q. 인접 행렬에서 방향/무방향 그래프의 차이는?
>
> 🗣️ 핵심 답변
>
> 가장 큰 차이는 **대칭보장**입니다.
>
> 무방향 그래프는 $A \to B$와 $B \to A$가 같으므로 행렬이 **대칭(Symmetric)**입니다. 방향 그래프는 대칭이 보장되지 않으며, 행의 합은 나가는 간선(Out-degree), 열의 합은 들어오는 간선(In-degree)을 의미합니다.
>
> **📚 꼬리질문 대비**
>
> - **Q. 방향 그래프의 인접 행렬에서 행(Row)의 합과 열(Column)의 합은 각각 무엇을 의미하는가?**
>     
>     - 행의 합은 해당 정점에서 나가는 간선의 수인 **진출 차수(Out-degree)**를, 열의 합은 해당 정점으로 들어오는 간선의 수인 **진입 차수(In-degree)**를 의미합니다.

> [!faq]Q. 인접 리스트(Adjacency List)에서 $A$ 정점의 리스트가 $B \to C$ 순서로 되어 있다면, 이것은 $A$에서 $B$를 거쳐 $C$로 간다는 뜻인가?
>
> 🗣️ 핵심 답변
>
> 아닙니다. 인접 리스트의 순서는 경로(Path)가 아니라 **단순한 인접 집합(Neighbor Set)**의 저장 순서일 뿐입니다.
>
> 즉, $A$는 $B$와 연결되어 있고, $A$는 $C$와도 연결되어 있다는 뜻이며, $B$와 $C$ 사이의 연결 관계는 이 리스트만으로는 알 수 없습니다.
>
> **📚 꼬리질문 대비**
>
> - **Q. 그렇다면 인접 리스트 방식은 언제 유리한가?**
>     
>     - 정점의 개수($V$)에 비해 간선의 개수($E$)가 적은 **희소 그래프(Sparse Graph)**일 때 메모리를 $O(V+E)$만큼만 사용하여 효율적입니다. 또한 특정 정점에 연결된 모든 이웃을 탐색할 때 행렬($O(V)$)보다 빠른 실제 간선 수($O(Degree(v))$)만큼의 시간이 소요됩니다.
>         

> [!faq]Q. 인접 리스트 구현 시 GraphNode* list[MAX]와 같은 포인터 배열을 사용하는 이유는?
>
> 🗣️ 핵심 답변
>
> 각 정점마다 연결된 리스트의 **시작 주소(Head Pointer)**를 관리하기 위함입니다. 배열의 인덱스를 정점 번호로 사용하여 $O(1)$에 해당 정점의 리스트에 접근할 수 있습니다.

## Topic 1. 그래프 탐색(Graph Traversal)의 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "그래프가 끊어져 있는지, A에서 B로 갈 수 있는지 어떻게 아는가?"

- **그래프 탐색 정의**: 하나의 시작 정점에서 출발하여, 연결된 모든 정점들을 **빠짐없이, 중복 없이 한 번씩 방문**하는 연산.
- **응용 사례**:
    - **연결성 검사**: 모든 정점을 방문할 수 있는가? (중간에 끊긴 네트워크 확인).
    - **회로 기판 검사**: 특정 단자와 단자가 설계대로 연결되어 있는지 불량 검출.
    - **경로 탐색**: 네비게이션, 미로 찾기 등.
        
### 2. 탐색의 두 가지 전략

1. **깊이 우선 탐색 (DFS, Depth First Search):** 한 방향으로 갈 수 있을 때까지 깊게 파고들다가 막히면 돌아온다. (스택 사용)
2. **너비 우선 탐색 (BFS, Breadth First Search):** 시작점 주변부터 얕고 넓게 훑으며 퍼져나간다. (큐 사용)

## Topic 2. 깊이 우선 탐색 (DFS: Depth First Search)

### 1. 🏗️ 빌드업 (Analogy)

> "우물을 팔 때 물이 나올 때까지 한 곳만 계속 파는 방식."

- **전략:**
    1. 현재 정점에서 갈 수 있는 인접 정점 중 하나를 골라 이동한다.
    2. 이동한 곳에서 또다시 깊게 들어간다.
    3. 더 이상 갈 곳이 없는 **막다른 길(Leaf)** 에 도달하면, 가장 마지막에 만났던 **갈림길(Branch)** 로 되돌아온다. (**Backtracking**)

### Concept

#### 1) 동작 메커니즘

1. 시작 정점 $V$를 방문하고, **방문 표시(Visited Mark)**를 남긴다.
2. $V$에 인접한 정점 중 **방문하지 않은 정점 $W$**가 있다면:
    - 현재 정점 $V$를 스택에 저장(나중에 돌아오기 위해).
    - $W$로 이동하여 방문. (이제 $W$가 새로운 $V$가 됨).
3. 인접한 모든 정점을 이미 방문했다면:
    - 스택에서 하나를 꺼내(Pop) 이전 위치로 되돌아감.
4. 스택이 빌 때까지 반복.

#### 2) [Diagram] DFS 탐색 순서 예시

`Start: A` | `Graph: A-B, A-C, B-D, D-G, G-E, G-F`

- **탐색 순서:** $A \rightarrow B \rightarrow D \rightarrow G \rightarrow E \rightarrow (Back) \rightarrow G \rightarrow F \rightarrow (Back) \dots$
- **중요:** 시작 정점이 달라지거나, 인접 노드 선택 순서(오름차순 등)가 달라지면 방문 순서도 달라진다.
---

## Topic 3. DFS의 구현 (Code Implementation)

- **구현 방식**:
    1. **재귀(Recursion)**: 함수 호출 자체가 스택 프레임에 쌓이는 원리를 이용 (코드가 간결함).
    2. **반복문 + 스택**: 명시적으로 스택 자료구조를 사용하여 구현.
- **방문 배열 (`visited[]`)**: 무한 루프(사이클)에 빠지지 않기 위해 반드시 방문 여부를 기록해야 한다 (`True/False` or `1/0`).
    

### Code 구현 (C언어 - 재귀 방식)

#### 1) 인접 행렬(Adjacency Matrix) 기반

- **특징**: `adj_mat[v][w]`가 1인지 확인하기 위해 $W$를 0부터 $N$까지 모두 훑어야 한다.
- **시간복잡도**: $O(V^2)$ (모든 정점에서 모든 정점을 스캔하므로).

```C
#define TRUE 1
#define FALSE 0

// visited 배열: 방문했으면 1(TRUE), 아니면 0(FALSE)
int visited[MAX_VERTICES];

// 인접 행렬용 DFS(g: 그래프 포인터, v: 현재 방문 중인 정점)
void dfs_mat(GraphType* g, int v) {
    visited[v] = TRUE;      // 1. 현재 정점 방문 표시
    printf("%d -> ", v);   // 2. 정점 처리 (출력)

    // 3. 인접 정점 탐색 (0부터 N-1까지 순회)
    for (int w = 0; w < g->n; w++) {
		// g->adj_mat[v][w]: 간선이 존재하고
        // !visited[w]: 아직 방문하지 않은 정점이라면
        if (g->adj_mat[v][w] && !visited[w]) {
            dfs_mat(g, w);// 4. 재귀 호출 (깊이 우선 탐색)
        }
    }
}
```

#### 2) 인접 리스트(Adjacency List) 기반

- **특징**: `g->adj_list[v]`에 연결된 노드만 따라가면 된다. 0인(연결 안 된) 구간을 검사할 필요가 없다.
- **시간복잡도**: $O(V + E)$ (모든 정점 방문 + 모든 간선 확인).

```C
// 인접 리스트용 DFS
void dfs_list(GraphType* g, int v) {
    GraphNode* w;
    visited[v] = TRUE;      // 1. 방문 처리
    printf("%d -> ", v);

    // 2. 연결 리스트 순회 (해당 정점에 연결된 것만 봄)
    for (w = g->adj_list[v]; w; w = w->link) {
        // 방문하지 않은 정점이라면
        if (!visited[w->vertex]) {
            dfs_list(g, w->vertex); // 3. 재귀 호출
        }
    }
}
```

### ⚠️ (놓치기 쉬운 포인트)

- **논리적 동치성**: 인접 행렬로 짜든 인접 리스트로 짜든, 그래프의 모양이 같다면 **DFS 탐색 결과(방문 순서)**는 동일하게 나와야 한다. (단, 인접 리스트가 오름차순 정렬되어 있다는 가정하에).
- **재귀의 흐름**: `dfs(v)` 함수가 끝나서 리턴된다는 것은, "더 이상 갈 곳이 없어서 이전 갈림길로 돌아간다의 백트래킹"는 의미와 같다.

### 💡 Interview

> [!faq]Q. DFS와 BFS의 가장 큰 차이점과 각각의 사용 사례는?
>
> 🗣️ 핵심 답변
>
> 가장 큰 차이는 탐색 순서와 사용하는 자료구조입니다.
>
> DFS는 '깊이'를 우선하여 한 경로를 끝까지 탐색하며 **스택(Stack)**을 사용하고, BFS는 '너비'를 우선하여 인접한 노드를 모두 방문한 뒤 나아가며 **큐(Queue)**를 사용합니다.
>
> DFS는 미로 찾기나 위상 정렬 등에 주로 쓰이고, BFS는 최단 경로(Shortest Path) 보장이 필요한 문제(가중치 없는 그래프)에 주로 사용됩니다.

> [!faq]Q. 인접 행렬과 인접 리스트로 DFS를 구현할 때의 시간 복잡도 차이는?
>
> 🗣️ 핵심 답변
>
> 정점의 수를 $V$, 간선의 수를 $E$라고 할 때,
>
> 인접 행렬은 연결 여부와 상관없이 모든 정점을 확인해야 하므로 **$O(V^2)$**의 시간이 소요됩니다.
>
> 반면 인접 리스트는 실제로 연결된 간선만 확인하면 되므로 **$O(V + E)$**의 시간이 소요됩니다. 따라서 **희소 그래프(Sparse Graph)**에서는 인접 리스트가 훨씬 효율적입니다.

> [!faq]Q. DFS를 재귀(Recursion)로 구현할 때 발생할 수 있는 잠재적 문제점은?
>
> 🗣️ 핵심 답변
>
> 그래프의 깊이가 매우 깊을 경우(노드가 많을 경우), 시스템 스택(System Stack) 영역을 과도하게 사용하여 **스택 오버플로우(Stack Overflow)**가 발생할 수 있습니다.
>
> **📚 해결 방안**
>
> - 재귀 대신 명시적인 스택 자료구조(`std::stack` 등)를 사용하여 반복문(Iterative) 형태로 구현하면 힙 메모리를 쓰므로 오버플로우 위험을 줄일 수 있습니다.

## Topic 1. DFS (Depth First Search) 복습 & 구현 기준

### 1. 🏗️ 빌드업 (Why & Context)

> 지난 시간 개념 복습 및 프로그래밍 구현 시의 표준화 필요성

- **핵심 메커니즘:** 방문한 노드를 `visited`로 표시하고, 인접 노드 중 방문하지 않은 곳으로 깊게 들어간다. 더 이상 갈 곳이 없으면(Dead-end), **스택(Stack)**을 `pop`하여 이전 분기점으로 되돌아온다(Backtracking).
- **자료구조:** **스택(Stack)** (또는 재귀 호출).
### Concept

- **정의:** 시작 정점에서 한 방향으로 갈 수 있는 데까지 깊게 탐색하다가 막히면 가장 가까운 갈림길로 돌아와 다른 방향을 탐색하는 방식.
- **구현 규칙 (교수님 강조):**
    - 방문 순서의 **일관성(Standardization)**을 위해 인접 노드가 여러 개일 경우 **오름차순(Ascending Order)**으로 방문한다.
    - 예: A에서 B, C로 갈 수 있다면 B를 먼저 방문.
    - 이는 `for(i=0; i<N; i++)` 형태의 반복문 구조와 자연스럽게 매핑되어 코딩 실수(Human Error)를 줄인다.
        

### Code 구현 (논리적 흐름)

```C
// DFS 논리적 구조 (재귀 or 스택)
void DFS(int v) {
    visited[v] = TRUE; // 1. 현재 노드 방문 처리
    printf("%d ", v);

    // 2. 인접 노드 탐색 (오름차순)
    for (node w = start; w < end; w++) {
        // 인접해 있고(connected) && 방문하지 않았다면(!visited)
        if (is_connected(v, w) && !visited[w]) {
            DFS(w); // 3. 재귀 호출 (깊게 들어감)
        }
    }
    // 4. 더 이상 갈 곳이 없으면 함수 종료(=Stack Pop, Backtrack)
}
```

## Topic 2. BFS (Breadth First Search) 개념 & 원리

### 1. 🏗️ 빌드업 (Why & Context)

> "여행을 갈 때 서울 주변(수원, 인천, 김포)을 먼저 다 보고, 그 다음 단계로 넘어가는 방식"

- **문제 제기:** DFS는 한 우물만 파기 때문에 최단 경로(간선 개수 기준)를 보장하지 않음. 시작점에서 가까운 순서대로 탐색할 필요성 존재.
- **핵심 아이디어:** 퍼저나간다. 시작점 기준 거리(간선 수)가 1인 노드들을 모두 방문 후, 거리가 2인 노드들을 방문한다.
    

### Concept

- **핵심 자료구조:** **큐 (Queue)** (FIFO - 먼저 들어온 놈이 먼저 나간다).
- **작동 원리:**
    
    1. 시작 노드를 큐에 넣고(Enqueue), 방문 표시.
    2. 큐에서 노드를 하나 꺼냄(Dequeue) -> `V`.
    3. `V`와 인접한 노드 중 방문하지 않은 **모든** 노드를 큐에 넣고 방문했다고 표시.
    4. 큐가 빌 때까지(Empty) 반복.
        
- **특징:** 깊게 들어가는 것이 아니라 옆으로(너비로) 먼저 퍼짐.
    

---

## Topic 3. BFS 순회 시뮬레이션 (함정 주의)

### 1. 🏗️ 빌드업 (Why & Context)

> "시험 문제 내면 다 틀리는 포인트: 시작점이 A가 아닐 때"

- **경고:** 시작점이 루트(A)일 때는 직관적으로 풀기 쉽지만, 중간 노드(예: E, F)에서 시작하면 DFS와 혼동하여 순서를 틀리는 경우가 많음.
- **오개념 경계:** 방금 큐에 넣은 노드에서 바로 다시 출발하려 하면 안 됨(이건 DFS임). 반드시 **큐에서 Dequeue한 노드**를 기준으로 인접 노드를 찾아야 함.
    

### Concept: Node 'E' 시작 시뮬레이션

- **그래프 상황 가정:** (구두 설명 기반 재구성)
    - E와 인접한 노드: B, C, G
    - B와 인접: A, D … 등등
- **Trace (추적 과정):**
    
    1. **Start E:** `Queue: [E]`, `Visited: {E}`
    2. **Dequeue E:** E의 인접 노드(B, C, G) 확인.
        
        - `Queue: [B, C, G]`, `Visited: {E, B, C, G}`
            
    3. **Dequeue B:** B의 인접 노드 중 안 가본 곳(A, D) 확인.
        
        - `Queue: [C, G, A, D]`, `Visited: {…, A, D}` (⚠️ 중요: C나 G로 바로 점프하는 게 아니라 B의 이웃을 큐 뒤에 붙임)
            
    4. **Dequeue C:** C의 인접 노드 확인 (이미 다 갔다면 패스).
    5. **Dequeue G:** G의 인접 노드(F) 확인.
        
        - `Queue: […, F]`, `Visited: {…, F}`
    - **최종 순서:** E -> B -> C -> G -> A -> D -> F (그래프 연결 상태에 따라 달라지나, 핵심은 **레벨 단위 방문**)
        

### Code 구현

```C
void bfs_mat(GraphType* g, int v) {
    int w;
    QueueType q;
    init_queue(&q);     // 큐 초기화
    
    visited[v] = TRUE;  // 1. 시작점 방문
    printf("%d ", v);
    enqueue(&q, v);     // 2. 큐에 삽입
    
    while (!is_empty(&q)) {
        v = dequeue(&q); // 3. 큐에서 기준점 꺼냄
        
        // 4. 꺼낸 정점(v)의 모든 인접 정점(w) 탐색
        for (w = 0; w < g->n; w++) {
            if (g->adj_mat[v][w] && !visited[w]) {
                visited[w] = TRUE; // 방문 표시
                printf("%d ", w);
                enqueue(&q, w);    // 큐에 삽입
            }
        }
    }
}
```

## Topic 4. 그래프 구현과 시간 복잡도

### 1. 🏗️ 빌드업 (Why & Context)

> "인접 행렬로 짤래? 인접 리스트로 짤래?"

- **Context:** 그래프를 코드로 표현하는 방식에 따라 알고리즘의 성능($O$)이 달라진다.
    

### Concept: 시간 복잡도 비교

- **인접 행렬:** $O(N^2)$ (모든 정점 $N$ $\times$ 행 검사 $N$)
	- 정점 $V$ 하나에 대해 모든 정점($N$개)을 다 찔러봐야 연결 여부를 알 수 있음.
- **인접 리스트:** $O(N + E)$ (모든 정점 $N$ + 모든 간선 $E$)
	- 정점 $V$에 연결된 간선($E$)만큼만 확인하면 됨.
    - 희소 그래프(Sparse Graph)일수록 인접 리스트가 유리하다.

## 기타 핵심 (Etc & Tips) - 알고리즘 11.20

- **시험 출제 예고:** 중간 노드(예: E, F)에서 시작하는 DFS/BFS 탐색 순서 문제가 반드시 출제된다. A(0번)에서 시작하는 건 누구나 맞추지만, 중간 시작은 오답률이 높으니 반드시 연습할 것.

### 💡 Interview

> [!faq]Q. DFS와 BFS의 결정적 차이와 각각의 적합한 사용처는?
>
> 🗣️ 핵심 답변
>
> DFS는 **스택(또는 재귀)**을 사용하여 깊이 우선으로 탐색하며, 미로 찾기나 모든 경로를 탐색해야 할 때 적합합니다.
>
> 반면, BFS는 큐를 사용하여 너비 우선으로 탐색하며, 가중치가 없는 그래프에서 최단 경로를 찾을 때 필수적으로 사용됩니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q: 왜 BFS가 최단 경로를 보장하는가?**
>     
> - A: BFS는 시작점에서 간선 1개 거리의 노드를 모두 방문한 뒤 간선 2개 거리로 넘어가므로, 목적지에 처음 도달했을 때가 가장 적은 간선을 거친 상태임이 보장됩니다.
>     

> [!faq]Q. 인접 행렬과 인접 리스트 중 어떤 것이 효율적인가?
>
> 🗣️ 핵심 답변
>
> 그래프의 간선 밀도(Density)에 따라 다릅니다. 간선이 적은 **희소 그래프(Sparse Graph)**에서는 메모리와 탐색 속도 면에서 $O(N+E)$인 인접 리스트가 훨씬 효율적입니다. 반면, 모든 노드가 연결된 밀집 그래프에서는 구현이 간단한 인접 행렬($O(N^2)$)을 고려할 수 있습니다.

> [!faq]Q. 그래프 탐색 시 방문 여부(visited 배열)를 체크하지 않으면 어떤 문제가 발생하는가?
>
> 🗣️ 핵심 답변
>
> 그래프에 **사이클(Cycle)**이 존재할 경우, 이미 방문한 노드를 계속해서 다시 방문하게 되어 **무한 루프(Infinite Loop)**에 빠지게 됩니다. 이는 프로그램의 종료를 막고 스택 오버플로우(DFS)나 메모리 초과(BFS)를 유발합니다.

## Topic 1. 연결 성분 (Connected Component)

### 1. 🏗️ 빌드업 (Why & Context)

> 그래프가 하나로 다 연결되어 있지 않고, 여러 개의 섬(Island)처럼 끊어져 있다면 어떻게 구분할 것인가?

- **문제 제기:** 단순히 `DFS(0)`만 호출하면, 0번 노드와 연결되지 않은 다른 노드들은 방문할 수 없다. 그래프 전체가 몇 개의 덩어리로 이루어져 있는지 파악해야 한다.
- **해결 아이디어:** 반복문을 통해 모든 정점을 순회하며, 아직 방문하지 않은 정점에 대해 탐색(DFS/BFS)을 새롭게 시작한다.
    

### Concept

- **정의:** 그래프 상에서 정점들이 서로 연결되어 있는 부분 그래프 중 크기가 가장 큰 것(Maximally Connected).
- **탐색 로직:**
    
    1. `visited` 배열을 단순 `Boolean`이 아닌 **그룹 ID(Counter)** 등을 저장하도록 변경 (선택 사항).
    2. 모든 정점 $V$에 대해 `for` 루프를 돌며 방문 여부 확인.
    3. 방문하지 않은 정점이 발견되면, 그곳을 시작점으로 DFS/BFS 수행 $\rightarrow$ 하나의 연결 성분 발견.
    4. 모든 정점을 방문할 때까지 반복.
        

### Code 구현

```C
// 연결 성분 찾는 전체 로직
void find_connected_components(GraphType* g) {
    int count = 0; // 연결 성분 개수 (Group ID)
    
    // 1. 모든 정점에 대해 순회
    for (int i = 0; i < g->n; i++) {
        if (!visited[i]) { // 2. 아직 방문 안 한 정점 발견 (새로운 섬)
            count++;
            printf("Connected Component %d: ", count);
            DFS(g, i); // 3. 해당 정점과 연결된 모든 노드 방문 처리
            printf("\n");
        }
    }
}
```

## Topic 2. 신장 트리 (MST)

### 1. 🏗️ 빌드업 (Why & Context)

> "도시의 모든 건물을 연결하되, 도로 건설 비용(간선 수)을 최소화하려면?"

- **핵심 아이디어:** 모든 노드를 방문해야 하지만, 굳이 중복 경로(Cycle)를 만들 필요는 없다.
- **필요성:** 통신 네트워크 구축, 배관 설계 등에서 모든 지점을 연결하면서도 자원을 최소로 써야 하는 상황.
### Concept

- **최소비용신장트리:** 그래프 $G$의 모든 정점($V$)을 포함하는 부분 그래프(Subgraph)이자, **트리(Tree)** 의 속성을 갖는 형태.
- **핵심 조건:**
    
    1. **모든 정점**이 연결되어야 함 (Connected).
    2. **사이클(Cycle) 없음** (트리의 필수 조건.)
    3. 정점이 $N$개일 때, 간선은 정확히 $N-1$개여야 함.
        
- **종류:**
    - **DFS 신장 트리:** 깊이 우선 탐색을 수행하며 사용된 간선들로 구성.
    - **BFS 신장 트리:** 너비 우선 탐색을 수행하며 사용된 간선들로 구성.
        

### Code 구현 (개념적 수정)

```C
// DFS를 이용한 신장 트리 간선 표시
void DFS_SpanningTree(int v) {
    visited[v] = TRUE;
    
    for (node w = start; w < end; w++) {
        if (is_connected(v, w) && !visited[w]) {
            // v와 w를 연결하는 간선은 신장 트리의 구성 요소임
            printf("Tree Edge: (%d, %d)\n", v, w); 
            DFS_SpanningTree(w);
        }
    }
}
```

## Topic 3. 최소 비용 신장 트리 (MST, Minimum Spanning Tree)

### 1. 🏗️ 빌드업 (Why & Context)

> "그냥 연결하는 게 아니라, '가장 싸게' 연결해야 한다."

- **Context:** 현실 세계의 간선은 똑같지 않다. 가중치(Weight)가 존재한다 (비용, 거리, 시간 등).
- **문제 제기:** 단순히 간선 수만 $N-1$개라고 최적이 아니다. 간선의 **가중치 합**이 최소가 되어야 한다.
- **예시:**
    - 도로 건설: 직선이 짧지만 토지 보상비(알박기)가 비싸면 우회하는 게 더 저렴할 수 있음.
    - 내비게이션: 최단 거리 vs 최단 시간 vs 무료 도로 (가중치 기준의 차이).
    - PCB 설계: 회로 연결 시 금(Gold) 와이어 길이를 최소화해야 원가 절감.
        

### Concept

- **최소비용신장트리(MST):** 무방향 가중치 그래프에서 신장 트리를 구성하는 간선들의 **가중치 합이 최소**인 트리.
- **핵심 접근법: 그리디 알고리즘 (Greedy Algorithm)**
	- **개념:** 매 순간 가장 좋아 보이는(가장 싼) 선택을 하여 최종 해답에 도달하는 방식.
	- **검증 필요성:** 그리디는 항상 최적해를 보장하지 않으므로 증명이 필요하다. 다행히 MST 문제에서는 Kruskal과 Prim 알고리즘 모두 **최적해를 보장함**이 증명되었다.
- **대표 알고리즘 (예고):**
    1. **Kruskal Algorithm**
    2. **Prim Algorithm**

## Topic 1. Kruskal 알고리즘 (Edge-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "가장 비용이 적은 다리(간선)부터 놓는다. 단, 섬(Cycle)이 고립되거나 갇히지 않게."

### Concept

- **접근법:** **간선(Edge)** 을 중심으로 동작.
- **핵심 로직:**
    1. **정렬 (Sorting):** 그래프의 모든 간선을 가중치 기준 **오름차순**으로 정렬한다.
    2. **선택 (Selection):** 가장 가중치가 작은 간선부터 선택한다.
    3. **검사 (Cycle Detection):** 선택한 간선이 사이클을 만드는지 확인한다.
        - 사이클 생성 O $\rightarrow$ 버림 (Skip).
        - 사이클 생성 X $\rightarrow$ 신장 트리에 추가.
    4. **종료:** 선택된 간선의 개수가 $N-1$개가 되면 종료.
        
### 복잡도 및 특징
- **시간 복잡도:** 간선 정렬에 $O(E \log E)$ 소요.
- **적합성:** 간선이 적은 **희소 그래프(Sparse Graph)**에 유리하다.
### 주요 알고리즘: Union-Find (Disjoint Set)

- **역할:** 간선 추가 시 사이클 발생 여부를 판단하는 알고리즘.
- **원리:**
    - `Find(x)`: 노드 x가 속한 집합의 루트(대장)를 찾는다.
    - `Union(x, y)`: 두 집합을 합친다.
    - 만약 `Find(u) == Find(v)`라면, u와 v는 이미 같은 집합(연결됨)이므로 간선을 추가하면 **사이클**이 발생한다.
        

### Code 구현 (논리 흐름)

```C
// Kruskal MST Logic
void Kruskal(GraphType* g) {
    Edge edges[] = sort_edges(g); // 1. 간선 정렬 (O(E log E))
    int edge_count = 0;
    
    set_init(g->n); // Union-Find 초기화

    for (int i = 0; i < g->e; i++) {
        // 2. 가장 작은 간선 선택
        int u = edges[i].u;
        int v = edges[i].v;

        // 3. 사이클 검사 (Find)
        if (set_find(u) != set_find(v)) {
            set_union(u, v); // 두 집합 합치기
            add_edge_to_mst(u, v);
            edge_count++;
            
            // 4. 종료 조건
            if (edge_count == g->n - 1) break;
        }
    }
}
```

## Topic 4. Prim 알고리즘 (Vertex-centric)

### 1. 🏗️ 빌드업 (Mechanism)

> "이미 개척된 땅(Tree)에서 가장 가까운 미개척지(Non-Tree)를 하나씩 병합한다."

### Concept

- **접근법:** **정점(Vertex)** 을 중심으로 동작. 시작 정점은 어디든 상관없음(결과 가중치 합은 동일).
- **핵심 로직:**
    1. **초기화:** 시작 정점 하나를 트리에 포함(`visited`). 나머지 모든 정점까지의 거리는 무한대($\infty$).
    2. **탐색:** 현재 트리 집합(Set)에서 인접한 간선 중 **가중치가 가장 작은 간선**으로 연결된 정점을 찾는다.
    3. **확장:** 해당 정점을 트리에 포함시키고, 그 정점과 연결된 간선 정보를 바탕으로 '갈 수 있는 최단 거리'를 갱신한다.
    4. **반복:** $N-1$개의 간선이 선택될 때까지 반복.
        
### 복잡도 및 특징

- **적합성:** 간선이 많은 **밀집 그래프(Dense Graph)**에 유리하다. (정렬 비용이 없으므로)
- **장점:** 시작 정점이 어디든 결과(총 비
### Code 구현 (논리 흐름)

```C
// Prim MST Logic
void Prim(GraphType* g, int start_node) {
    int distance[MAX_VERTICES]; // 트리에 인접한 거리
    int visited[MAX_VERTICES] = {0};
    
    // 초기화: 모든 거리 무한대, 시작점은 0
    for(int i=0; i<g->n; i++) distance[i] = INF;
    distance[start_node] = 0;

    for (int i = 0; i < g->n; i++) {
        // 1. 방문하지 않은 노드 중 distance가 가장 작은 노드 u 선택
        int u = delete_min(distance, visited); 
        visited[u] = TRUE;
        
        // 2. u에 인접한 노드들의 거리 갱신
        for (each node v connected to u) {
            if (!visited[v] && weight[u][v] < distance[v]) {
                distance[v] = weight[u][v]; // 더 짧은 거리 발견 시 갱신
            }
        }
    }
}
```

### 1. 시간 복잡도와 적합성

| **구현 난이도** | 정렬과 Union-Find 필요                       | 이중 루프 또는 우선순위 큐 필요                     |
| **시간 복잡도** | $O(E \log E)$ (정렬 시간)                   | $O(N^2)$ (배열) 또는 $O(E \log N)$ (힙)     |
|            |                                         |                                        |

### 2. 강조 포인트

- **Kruskal:** 반드시 **정렬**이 선행되어야 함. 정렬 비용이 전체 성능을 좌우함.
- **Prim:** 정점이 많고 간선이 매우 많은 경우(Complete Graph 등)에는 정렬 비용이 없는 Prim이 유리할 수 있음 ($O(N^2)$ 구현 시).

### 💡 Interview

> [!faq]Q. Kruskal과 Prim 알고리즘 중 어떤 상황에서 무엇을 선택해야 하는가?
>
> 🗣️ 핵심 답변
>
> 그래프 내 **간선의 밀도(Density)**에 따라 결정합니다.
>
> 간선의 개수가 적은 **희소 그래프(Sparse Graph)**에서는 간선 정렬 비용이 주도하는 Kruskal 알고리즘($O(E \log E)$)이 유리하며,
> 간선이 많은 **밀집 그래프(Dense Graph)**에서는 정점 위주로 탐색하는 Prim 알고리즘($O(N^2)$ or $O(E \log N)$)이 더 효율적일 수 있습니다.

> [!faq]Q. 간선이 매우 많은 '밀집 그래프(Dense Graph)'에서 MST를 구할 때 Kruskal보다 Prim이 유리한 이유는?
>
> 🗣️ 핵심 답변
>
> Kruskal 알고리즘은 간선을 정렬하는 과정이 필수적인데, 간선 수($E$)가 많으면 정렬 비용($O(E \log E)$)이 매우 커집니다. 반면, Prim 알고리즘은 정점 개수($N$)에 비례하는 $O(N^2)$ 방식으로 구현할 수 있어, $E$가 $N^2$에 가까운 밀집 그래프에서는 정렬 오버헤드가 없는 Prim이 더 효율적입니다.

> [!faq]Q. Kruskal 알고리즘에서 사이클 발생 여부를 효율적으로 판단하기 위해 사용하는 자료구조는 무엇이며, 그 원리는?
>
> 🗣️ 핵심 답변
>
> 유니온-파인드(Union-Find) 자료구조를 사용합니다. Find 연산으로 두 정점의 루트 노드를 확인하여, 만약 루트가 같다면 이미 같은 집합에 속해 있는 것(연결됨)이므로 사이클이 발생한다고 판단합니다. 다르다면 Union 연산으로 두 집합을 합칩니다.
>
> **📚 성능**
>
> - 경로 압축(Path Compression)과 랭크 기반 합치기(Union by Rank)를 적용하면 거의 상수 시간($O(\alpha(N))$)에 연산이 가능합니다.
>

## Topic 1. MST 복습 & Greedy Algorithm

### 1. 🏗️ 빌드업 (Why & Context)

> **"그리디 알고리즘은 항상 최적해를 보장하는가?"**

- 지난 시간에 배운 **Kruskal**과 **Prim** 알고리즘은 모두 **탐욕 기법(Greedy Algorithm)**을 기반으로 한다.
- 하지만 모든 문제에서 눈앞의 최선(Greedy)이 전체의 최선(Global Optimum)이 되는 것은 아니다. 이를 증명하기 위해 **'동전 거스름돈 문제'** 를 반례로 든다.

### 2. Concept

#### 1) Greedy Algorithm (탐욕 기법)

- **정의:** 결정을 해야 할 때마다 **'그 순간에 가장 좋다고 생각하는 것'**을 해답으로 선택하는 방식.
- **특징:**
    - 계산 속도가 빠르고 직관적이다.
    - 항상 **최적해(Optimal Solution)**를 보장하지 않으므로 반드시 **검증**이 필요하다.
    - _참고:_ Kruskal과 Prim은 그리디를 사용하지만 수학적으로 최적해가 증명된 케이스다.
        

#### 2) 동전 거스름돈 예시 (반례 증명)

- **상황 A (우리나라 화폐):** 500원, 100원, 50원, 10원 단위.
    - 큰 단위가 작은 단위의 배수이므로 그리디 적용 시 최적해 보장.
- **상황 B (반례):** 500원, **400원**, 100원 단위가 있다고 가정.
    - **목표:** 800원 거슬러 주기.
    - **Greedy 접근:** 500원(1개) → 남은 300원은 100원(3개) ⇒ **총 4개**.
    - **최적해(Optimal):** 400원(2개) ⇒ **총 2개**.
    - **결론:** 그리디가 항상 최적의 동전 개수를 보장하지 않는다.

## Topic 2. 최단 경로(Shortest Path)와 그래프 표현

### 1. 🏗️ 빌드업 (Why & Context)

> **"지도에서 서울부터 부산까지 가는 길은 무수히 많다. 그중 가장 빠른 길을 어떻게 찾을까?"**

- MST(최소 신장 트리)는 모든 노드를 연결하는 것이 목적이었다면, **최단 경로**는 두 정점 사이의 **가중치 합이 최소**가 되는 경로를 찾는 것이 목적이다.
- 내비게이션(최단 시간, 최단 거리, 고속도로 우선 등)이나 지하철 환승 앱이 대표적인 응용 사례다.

### 2. Concept

#### 1) 가중치 인접 행렬 (Weighted Adjacency Matrix)

- 일반적인 그래프 표현과 달리, **연결되지 않음(No Edge)**을 표현할 때 주의가 필요하다.
- **일반 인접 행렬:** 연결 안 되면 `0`으로 표현.
- **가중치 인접 행렬:**
    - 연결 안 됨 $\rightarrow$ **$\infty$ (무한대)**. (0은 가중치가 0, 즉 거리가 없다는 뜻이 되므로 사용할 수 없음)
    - 자기 자신(Self-loop) $\rightarrow$ **$0$**.
        

#### 2) 최단 경로 알고리즘의 분류

- **Dijkstra (다익스트라):** **하나의 시작점** $\rightarrow$ 다른 모든 정점 (One-to-All). 음수 가중치 불가.
- **Floyd-Warshall (플로이드-워셜):** **모든 정점** $\rightarrow$ 모든 정점 (All-to-All).
- **Bellman-Ford (벨만-포드):** 음수 가중치가 있을 때 사용 (네트워크 수업 등에서 다룸).
    

### 3. Code 구현 (초기화)

```C
#define INF 1000000 // 연결되지 않음을 표현하는 무한대 값

// 가중치 그래프 초기화 예시 (adj_mat[i][j] = i에서 j로 가는 비용)
// i == j 이면 0, 간선이 없으면 INF
int weight[MAX_VERTICES][MAX_VERTICES] = {
    {0, 7, INF, INF, 3, 10, INF},
    {7, 0, 4, 10, 2, 6, INF},
    // … (생략)
};
```

## Topic 3. 다익스트라(Dijkstra) 알고리즘

### 1. 🏗️ 빌드업 (Why & Context)

> **"시작점에서 갈 수 있는 가장 가까운 곳부터 확정 짓고, 그곳을 징검다리 삼아 더 먼 곳을 갱신한다."**

- 네트워크 상에서 하나의 시작 정점(Source)으로부터 모든 다른 정점까지의 최단 경로를 구한다.
- 집합 $S$를 사용하여 **'이미 최단 거리가 확정된 정점'**들을 관리한다.
    

### 2. Concept

#### 1) 핵심 로직

1. **초기화:** 시작 정점 $v$에서 다른 정점들로 가는 직접 거리를 `distance` 배열에 저장한다. (연결 없으면 $\infty$)
2. **선택 (Greedy Step):**
    
    - 방문하지 않은 정점(집합 $S$에 없는 정점) 중 `distance` 값이 **가장 작은 정점 $u$를** 선택한다.
    - 정점 $u$를 집합 $S$에 추가한다(방문 처리).
        
3. **갱신 (Relaxation):**
    
    - 새로 확정된 정점 $u$를 거쳐서 다른 정점 $w$로 가는 경로가, 기존에 알고 있던 $w$까지의 경로보다 짧다면 값을 갱신한다.
    - 수식: $distance[w] = \min(distance[w], \ distance[u] + weight[u][w])$
        

#### 2) 논리적 흐름 예시

- 시작점이 0번 노드일 때:
    - 0번과 직접 연결된 노드들(4, 1, 5) 중 가중치가 가장 작은 노드(예: 4번)를 선택.
    - 이제 0번에서 4번까지의 최단 거리는 확정됨.
    - 4번을 거쳐서 갈 수 있는 새로운 경로들(4 $\to$ 2, 4 $\to$ 6 등)의 거리를 계산하여 기존 값과 비교 후 갱신.
    - 이 과정을 모든 노드를 방문할 때까지 반복.
        

### 3. Code 구현 (Core Logic)

```C
// distance[]: 시작점에서 각 정점까지의 최단 거리
// found[]: 방문 여부 (집합 S)

void dijkstra(int start, int n) {
    int i, u, w;
    
    // 1. 초기화
    for (i = 0; i < n; i++) {
        distance[i] = weight[start][i]; // 시작점과 연결된 간선 비용으로 초기화
        found[i] = FALSE;
    }
    
    found[start] = TRUE; // 시작 정점 방문 표시
    distance[start] = 0;
    
    // 2. n-1번 반복 (시작점 제외 나머지 정점들)
    for (i = 0; i < n - 1; i++) {
        
        // 현재 미방문 정점 중 distance가 가장 작은 정점 u 선택
        u = choose(distance, n, found); 
        
        found[u] = TRUE; // 집합 S에 추가
        
        // 3. Relaxation (거리 갱신)
        for (w = 0; w < n; w++) {
            if (!found[w]) { // 아직 방문하지 않은 정점 w에 대해
                // 기존 거리 vs (u를 거쳐가는 거리) 비교
                if (distance[u] + weight[u][w] < distance[w]) {
                    distance[w] = distance[u] + weight[u][w];
                }
            }
        }
    }
}
```

### 💡 Interview
> [!faq]Q. 그리디 알고리즘(Greedy Algorithm)을 사용할 때 주의할 점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 그리디 알고리즘은 매 순간의 지역적 최선(Local Optimum)을 선택하기 때문에, 그 결과가 반드시 **전역 최적해(Global Optimum)**라는 보장이 없습니다.
>
> **📚 꼬리질문 대비**
>
> - 따라서 동전 거스름돈 문제(특수 동전 단위)나 배낭 문제(Knapsack)처럼 그리디가 실패하는 케이스를 인지하고, 적용 전 반드시 수학적 **검증(Proof)**을 거치거나 근사해(Approximation)로 만족해야 할 때 사용해야 합니다.
>
>     
> - **대안:** 최적해가 반드시 필요한 경우 **동적 계획법(DP)** 등을 사용하거나, 그리디 사용 후 검증 과정을 거쳐야 합니다. Kruskal과 Prim은 그리디를 쓰지만 매트로이드 구조에 의해 최적해가 증명된 알고리즘입니다.
>     

> [!faq]Q. 가중치 그래프를 인접 행렬로 표현할 때, 간선이 없는 경우 0이 아닌 무한대($\infty$)로 초기화하는 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가중치 그래프에서 0은 '거리가 0임(즉, 자기 자신)'을 의미할 수 있기 때문입니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - 최단 경로 알고리즘에서 '0'은 비용이 들지 않는다는 의미로 해석되어, 연결되지 않은 상태와 구분이 불가능하기 때문입니다. 따라서 계산 결과(최솟값 찾기)에 영향을 주지 않도록 아주 큰 값(무한대)으로 설정하여 '갈 수 없음'을 명시해야 합니다.
>     

> [!faq]Q. 다익스트라(Dijkstra)와 플로이드-워셜(Floyd-Warshall) 알고리즘의 결정적 차이는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가장 큰 차이는 해결 범위입니다. 다익스트라는 **'하나의 정점'**에서 다른 모든 정점까지의 최단 경로(One-to-All)를 구하지만, 플로이드-워셜은 '모든 정점 쌍' 간의 최단 경로(All-to-All)를 구합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **시간 복잡도:** 다익스트라는 $O(E \log V)$ (우선순위 큐 사용 시), 플로이드-워셜은 $O(V^3)$입니다.
>     
> - **음수 가중치:** 다익스트라는 음수 가중치가 있으면 사용할 수 없으나, 플로이드-워셜은 음수 사이클만 없다면 음수 가중치 처리가 가능합니다. (단, 벨만-포드가 음수 가중치 처리에 더 특화됨)
>

## Topic 1. 다익스트라 알고리즘 상세 시뮬레이션

### 1. 🏗️ 빌드업 (Why & Context)

- MST(최소 신장 트리)는 간선을 선택하는 것이 목적이지만, 최단 경로 알고리즘은 **경로의 값(Distance)** 이 계속해서 변한다(갱신된다).
- 직접 연결되지 않아 `INF`(무한대)였던 곳이, 다른 정점을 거쳐가면서 구체적인 값으로 바뀌는 과정(Relaxation)을 이해해야 한다.

### 1) 거리 갱신 (Relaxation) 논리

-  "지금 알고 있는 $w$까지의 거리"보다 "새로 확정된 정점 $u$를 거쳐서 $w$로 가는 거리"가 더 짧다면 값을 갱신한다.
- distance의 d
### `d[w] = min(d[w], d[u] + weight[u][w])`

### 2) [실습 1] 정점 0에서 시작하는 경우

- **초기 상태:**
    - **집합 $S$ (방문 확정):** `{0}`
    - **`distance` 배열:** `[0, 7, 무한, 무한, 3, 10, 무한]` (0번 행의 초기 가중치)
- **Step 1 (정점 4 선택):**
    - $D[4]=3$이 가장 작으므로 $S={0, 4}$로 확장.
    - **갱신:** 정점 4를 거쳐갈 수 있는 곳들 확인.
        - $0 \to 1$: 기존 7 vs ($0 \to 4 \to 1$: $3+2=5$). **5로 갱신**.
        - $0 \to 3$: 기존 $\infty$ vs ($0 \to 4 \to 3$: $3+11=14$). **14로 갱신**.
        - $0 \to 6$: 기존 $\infty$ vs ($0 \to 4 \to 6$: $3+5=8$). **8로 갱신**.
- **Step 2 (정점 1 선택):**
    - 남은 $D$값 중 가장 작은 5(정점 1) 선택. $S=\{0, 4, 1\}$.
    - **갱신:** 정점 1을 거쳐갈 수 있는 곳들 확인.
        - $0 \to 2$: 기존 $\infty$ vs ($0 \to 1 \to 2$: $5+4=9$). **9로 갱신**.
- **(이후 반복):** 위 과정을 모든 정점이 $S$에 포함될 때까지 반복하여 최종 최단 거리 배열을 완성.
    

#### 3) [실습 2] 정점 3에서 시작하는 경우

- **목표:** 시작점이 바뀌었을 때 "One-to-All"의 개념을 이해하는지 확인.
- **초기 상태 ($S=\{3\}$):**
    - $D[3]=0$
    - 연결된 간선: $3 \to 1(10)$, $3 \to 2(2)$, $3 \to 4(11)$, $3 \to 5(9)$, $3 \to 6(4)$.
    - $3 \to 0$은 연결 없음($\infty$).
- **진행 과정:**
    
    1. 가장 작은 비용인 **정점 2(비용 2)** 선택.
    2. 정점 2를 거쳐서 갈 수 있는 곳 갱신 (예: $3 \to 2 \to 1$ 등 비교).
    3. 그 다음 작은 비용 선택… (반복)
        
- **최종 결과 예시:**
    - 배열 형태: `[INF, 6, 2, 0, 8, 9, 4]` (※ 강의 중 학생들과 맞춰본 값)
- **$S$ 집합의 의미:** $S$에 들어간 노드는 최단 거리가 **이미 확정**된 상태이다. 이후에는 그 값이 더 작아질 수 없다. (음수 간선이 없다는 전제하에)
- **무한대(INF) 처리:** 코드 구현 시 `INT_MAX` 등을 사용하여, 갱신 전에는 갈 수 없음을 명확히 해야 한다. `0`을 쓰면 안 된다.

## Topic 2. Dijkstra Code 구현

### 1. 🏗️ 빌드업 (Why & Context)

> **"수학적 논리를 그대로 코드로 옮긴 것이다."**

- 앞서 손으로 계산한 과정을 프로그램은 `weight` 행렬을 참조하여 반복문으로 수행한다.
- 방문하지 않은 노드 중 최소값을 찾는 `choose` 함수와, 값을 갱신하는 루프가 핵심이다.
    

### 2. Code 구현 (Core Structure)

```C
// 핵심 변수
// distance[]: 시작점으로부터의 최단 거리 저장
// found[]: 방문한 정점 표시 (집합 S)
// weight[][]: 가중치 인접 행렬 (초기 그래프 정보)

void dijkstra(int start, int n) {
    // 1. 초기화: 시작점과 연결된 간선 비용으로 distance 배열 세팅
    for(int i=0; i<n; i++) {
        distance[i] = weight[start][i];
        found[i] = FALSE;
    }
    found[start] = TRUE;
    distance[start] = 0;

    // 2. 루프: 시작점을 제외한 n-1개 정점에 대해 반복
    for(int i=0; i<n-1; i++) {
        
        // [Greedy Step]
        // 방문하지 않은 정점 중 distance가 가장 작은 정점 u 반환
        int u = choose(distance, n, found);
        
        found[u] = TRUE; // 집합 S에 추가

        // [Relaxation Step]
        // 새로 추가된 정점 u를 거쳐서 가는 거리가 더 짧으면 갱신
        for(int w=0; w<n; w++) {
            if(!found[w]) { // 아직 방문 안 한 정점에 대해
                // 기존 거리 vs (u까지 거리 + u에서 w로 가는 거리)
                if(distance[u] + weight[u][w] < distance[w]) {
                    distance[w] = distance[u] + weight[u][w];
                }
            }
        }
    }
}
```

- **⚠️ 주의사항 (Code Level):**
    - `weight` 배열 초기화 시 연결되지 않은 구간은 반드시 `INF`(무한대)로 설정해야 `choose` 함수나 `min` 비교 로직이 정상 작동한다.
    - 출력문(`printf`)이 없으면 내부 메모리 상에서만 값이 바뀌고 끝나므로, 루프 종료 후 `distance` 배열을 출력하는 코드를 추가해야 결과를 확인할 수 있다.

## Topic 3. Dijkstra vs Floyd-Warshall

### 1. 🏗️ 빌드업 (Why & Context)

> - 다익스트라는 "한 놈(Source)"만 팬다.
> - 플로이드는 "모든 놈(All-Pairs)"을 한 방에 팬다. (3중 반복문 사용)

- 다익스트라 알고리즘을 반복하면 모든 쌍의 최단 거리를 구할 수 있지만, 이를 한 번에 수행하는 알고리즘이 플로이드-워셜이다.
    

### 2. Concept 비교

|**구분**|**Dijkstra (다익스트라)**|**Floyd-Warshall (플로이드-워셜)**|
|---|---|---|
|**시작점**|**단일 시작점 (Single Source)**|**모든 정점 (All Pairs)**|
|**개념**|시작점 $S$에서 다른 모든 정점까지의 거리 구하기|모든 정점 $i$에서 모든 정점 $j$까지의 거리 구하기|
|**비유**|"서울에서 출발해서 부산, 대구, 광주 가는 최단 거리"|"전국 모든 도시 간의 최단 거리표 만들기"|
|**특징**|매 단계 최단 거리 정점 확정 ($S$ 집합 확장)|3중 반복문을 통해 거쳐가는 정점을 기준으로 행렬 전체 갱신|
|**관계**|다익스트라를 모든 정점에 대해 $N$번 수행 $\approx$ 플로이드|(다음 시간에 자세히 다룰 예정)|

### 💡 Interview

> [!faq]Q. 다익스트라 알고리즘에서 매 단계 가장 거리가 짧은 정점을 선택하는 이유는 무엇인가요? (Greedy 속성)
>
> 🗣️ 핵심 답변
>
> 현재 방문하지 않은 정점 중 가장 거리가 짧은 정점은, 다른 어떤 미방문 정점을 거쳐서 오더라도 더 짧아질 가능성이 없기 때문입니다. (간선 가중치가 양수라는 전제 하에) 따라서 그 시점에 해당 정점까지의 최단 거리를 확정지을 수 있습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **음수 가중치가 있다면?** 음수 간선이 존재하면, 더 멀리 돌아가더라도 나중에 거리가 줄어들 수 있으므로 다익스트라의 그리디 논리가 깨집니다. 이 경우 **벨만-포드(Bellman-Ford)** 알고리즘을 사용해야 합니다.
>     

> [!faq]Q. 다익스트라 알고리즘의 시간 복잡도는 어떻게 되나요?
>
> 🗣️ 핵심 답변
>
> 구현 방식에 따라 다릅니다. 배열을 사용하여 선형 탐색으로 최소 정점을 찾을 경우 $O(V^2)$입니다. 하지만 **우선순위 큐(Min Heap)**를 사용하여 최소 정점을 $O(\log V)$에 찾으면 전체 복잡도는 **$O(E \log V)$**로 최적화할 수 있습니다. (V: 정점 수, E: 간선 수)

> [!faq]Q. 다익스트라 알고리즘을 구현할 때 '우선순위 큐(Priority Queue)'를 사용하면 어떤 이점이 있는가?
>
> 🗣️ 핵심 답변
>
> 기본적인 배열 탐색 방식은 가장 가까운 노드를 찾기 위해 매번 $O(N)$의 탐색이 필요하여 총 $O(N^2)$의 시간이 걸립니다. 하지만 우선순위 큐(Min Heap)를 사용하면 가장 가까운 노드를 $O(\log N)$에 찾을 수 있어, 전체 시간 복잡도를 $O(E \log N)$으로 줄일 수 있습니다. 이는 간선이 적은 희소 그래프에서 매우 효율적입니다.
---

> [!faq]Q. 다익스트라 알고리즘이 '그리디(Greedy)' 기법인 이유는?
>
> 🗣️ 핵심 답변
>
> 매 단계에서 현재 방문하지 않은 노드 중 가장 거리가 짧은 노드를 선택하여 방문하고, 그 선택을 번복하지 않기 때문입니다. 즉, "지금 당장 갈 수 있는 가장 가까운 곳이 최단 경로의 일부일 것이다"라는 가정하에 동작합니다.

## Topic 2. 플로이드-워셜 (Floyd-Warshall)

### 1. 🏗️ 빌드업 (Why & Context)

> **"다익스트라를 N번 돌릴 것인가? 3중 반복문 한 번으로 끝낼 것인가?"**

- **문제 제기:** 다익스트라(Dijkstra)는 '하나의 시작점'에서만 최단 경로를 구한다. 만약 지도상의 **모든 도시 간의 최단 거리**를 표로 만들고 싶다면 어떻게 해야 하는가?
- **목적:** 그래프 내의 **모든 정점 쌍(All Pairs)** 사이의 최단 경로를 구한다.

### 2. Concept

#### 1) **핵심 아이디어:** "정점 $i$에서 $j$로 바로 가는 것보다, 경유지 $k$를 거쳐서 가는 게 더 빠르면 갱신한다."
`Distance[i][j] = min(Distance[i][j], Distance[i][k] + Distance[k][j])`
- **의미:** "$k$번 정점을 거치지 않고 가는 기존 거리"와 "$k$번 정점을 거쳐서 가는 거리" 중 더 짧은 것을 선택.
- $k$가 0부터 $N-1$까지 증가하면서, 경유 가능한 정점이 하나씩 늘어날 때마다 최단 거리를 갱신한다.
        

#### 2) 알고리즘 특징

- **입력:** 인접 행렬 (자기 자신 0, 간선 없으면 $\infty$).
- **구조:** 3중 `for`문 (Loop).
    - **가장 바깥쪽 Loop ($k$):** 경유할 정점 (0 ~ $N-1$). **(※ 가장 중요: 반드시 $k$가 가장 바깥에 있어야 함)**
    - **중간 Loop ($i$):** 출발 정점.
    - **안쪽 Loop ($j$):** 도착 정점.
- **시간 복잡도:** $O(N^3)$. (정점 개수가 적을 때 매우 효과적, 구현이 매우 간단함).
    

### 3. Code 구현 (Logic)

```C
// A[i][j]는 초기에 가중치 인접 행렬로 초기화됨 (없으면 INF)

// k: 경유지 (반드시 가장 바깥쪽 루프)
for (k = 0; k < n; k++) {
    // i: 출발지
    for (i = 0; i < n; i++) {
        // j: 도착지
        for (j = 0; j < n; j++) {
            // 기존 거리보다 k를 거쳐가는 거리가 짧으면 갱신
            if (A[i][k] + A[k][j] < A[i][j]) {
                A[i][j] = A[i][k] + A[k][j];
            }
        }
    }
}
```

## Topic 3. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Why & Context)

> **"알고리즘을 들으려면 자료구조를 먼저 들어야 한다. 이 순서를 어떻게 정할까?"**

- 대학의 **선수 과목(Prerequisite)** 시스템이 가장 대표적인 예시.
- 일의 순서가 정해져 있는 작업들을 순서대로 나열하는 알고리즘.
    

### 2. Concept

#### 1) 정의 및 조건

- **정의:** 방향 그래프의 모든 노드를 "선행 순서(방향성)"를 거스르지 않도록 나열하는 것.
- **필수 조건:** **사이클(Cycle)이 없어야 함.** (예: A를 하려면 B를 해야 하고, B를 하려면 A를 해야 하면 영원히 불가능)

#### 2) 작동 원리 (진입 차수, In-degree)

1. **진입 차수(In-degree)가 0**인 정점을 찾는다. (즉, 선행 조건이 없는 과목).
2. 해당 정점을 출력하고, 그래프에서 **제거**한다.
3. 제거된 정점에서 출발하는 간선들도 모두 삭제한다. (이에 따라 연결된 후행 정점들의 진입 차수가 감소함).
4. 모든 정점이 제거될 때까지 반복한다.
    
    - 만약 모든 정점을 방문하기 전에 진입 차수가 0인 정점이 없다면? $\rightarrow$ **사이클이 존재한다**는 뜻.
        

#### 3) 예시 (선수 과목)

- **상황:** 자료구조(1) $\to$ 알고리즘(3), C언어(0) $\to$ 자료구조(1).
- **초기:** C언어(0)는 진입 차수 0. $\rightarrow$ 선택 및 삭제.
- **갱신:** 자료구조(1)의 진입 차수가 0이 됨. $\rightarrow$ 선택 및 삭제.
- **결과:** C언어 $\to$ 자료구조 $\to$ 알고리즘 순서 도출.

> [!faq]Q. 모든 정점 쌍 사이의 최단 경로를 구할 때, 다익스트라를 N번 돌리는 것과 플로이드-워셜을 쓰는 것 중 언제 무엇이 유리한가?
>
> 🗣️ 핵심 답변
>
> 간선이 적은 **희소 그래프(Sparse Graph)**라면 다익스트라($O(E \log V)$)를 $N$번 수행하는 것이 $O(V E \log V)$로 더 효율적일 수 있습니다.
> 하지만 간선이 많은 **밀집 그래프(Dense Graph)**이거나 구현의 편의성이 중요할 때, 혹은 정점 개수($V$)가 적다면 **플로이드-워셜($O(V^3)$)**이 유리합니다.

> [!faq]Q. 플로이드-워셜 알고리즘 구현 시 3중 반복문의 순서가 중요한 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가장 바깥쪽 루프가 반드시 **경유지($k$)**가 되어야 하기 때문입니다. 플로이드 알고리즘은 '0번 정점까지 경유 가능할 때'의 결과를 바탕으로 '1번 정점 경유 추가'를 계산하는 동적 계획법(DP) 방식입니다. 경유지 루프가 안쪽으로 들어가면, 아직 갱신되지 않은 과거의 상태를 참조하게 되어 최단 거리를 올바르게 구할 수 없습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **i, j의 순서는?** 출발지(i)와 도착지(j)의 순서는 바뀌어도 상관없습니다. 핵심은 경유지(k)가 고정된 상태에서 모든 i, j 쌍을 검사하는 것입니다.
>     

> [!faq]Q. 위상 정렬(Topological Sort)이 불가능한 경우는 언제이며, 이를 어떻게 탐지하나요?
>
> 🗣️ 핵심 답변
>
> 그래프 내에 **사이클(Cycle)**이 존재하면 위상 정렬이 불가능합니다. 알고리즘 수행 중 큐(Queue)가 비어있는데 아직 방문하지 않은 정점이 남아있다면(즉, 모든 정점의 진입 차수가 0이 되지 않는다면), 사이클이 존재한다고 판단할 수 있습니다.

## Topic 2. 알고리즘 성능 분석 (Time Complexity)

### 1. 🏗️ 빌드업 (Why & Context)

> "하드웨어 성능이 비약적으로 발전했는데, 왜 여전히 복잡도를 계산해야 하는가?"

- **배경:** 과거(RAM 640KB, 1MB 시대)에는 메모리 절약(공간 복잡도)이 핵심이었으나, 현재는 하드웨어 성능(RAM 32GB 등)이 충분함.
- **문제 제기:** - 하드웨어가 좋아졌음에도 사용자는 **기다려주지 않음** (웹 로딩 지연 시 '새로고침' 연타 → 서버 부하 가중).
    - 대규모 데이터 처리 및 서버 비용 절감을 위해 **실행 시간(Time Complexity)** 최적화가 필수적임.
- **측정의 한계 (Absolute Time vs Operations):**
    - `clock()` 함수 등을 이용해 절대 시간(초 단위)을 측정하는 것은 하드웨어 환경에 따라 결과가 달라지므로 객관적 지표가 될 수 없음.
    - 따라서 **연산 횟수(Operation Count)** 를 함수형태($f(n)$)로 나타내어 분석함.
        

### Concept: 시간 복잡도와 연산 횟수 비교

- **핵심 아이디어:** 입력 크기 $N$이 무한대로 커질 때, 연산 횟수가 어떻게 증가하는가(추세)를 비교.
- **최고차항의 중요성:** $N^2 + N + 1$에서 $N$이 커지면 $N$과 $1$은 무시 가능하므로 $O(N^2)$으로 취급.
    

### Code 구현: $N$을 $N$번 더하는 문제 ($N \times N$)

> 동일한 결과(1억을 1억 번 더하기)를 내는 3가지 방식의 성능 차이 비교.
#### Case A: 곱셈 연산 활용 ($O(1)$)

```C
sum = n * n;
```

- **연산:** 대입 1회, 곱셈 1회 $\rightarrow$ 총 2회.
- **특징:** 입력 $N$이 1억이든 10억이든 연산 횟수는 **상수(Constant)**로 일정하다. 가장 효율적이다.
#### Case B: 단일 반복문 ($O(N)$)

```C
sum = 0;
for(i=0; i<n; i++) {
    sum += n;
}
```

- **연산:** $N$번 반복하며 덧셈 수행 $\rightarrow$ 약 $2N + \alpha$회.
- **특징:** 입력 $N$에 비례하여 시간이 선형적으로 증가한다.
    
#### Case C: 이중 반복문 ($O(N^2)$)

```C
sum = 0;
for(i=0; i<n; i++) {
    for(j=0; j<n; j++) {
        sum += 1;
    }
}
```

- **연산:** $N \times N$번 반복하며 1을 더함 $\rightarrow$ 약 $2N^2 + \alpha$회.
- **특징:** 입력 $N$이 커지면 실행 시간이 기하급수적으로 증가한다. (가장 비효율적)
### 분석 (Analysis)

1. **Case 1 ($O(1)$):** $N$이 1억이든 10억이든 연산 횟수는 2회로 고정. 압도적으로 빠름.
2. **Case 2 ($O(N)$):** $N$에 비례하여 시간 증가.
3. **Case 3 ($O(N^2)$):** $N$이 커지면 기하급수적으로 느려짐.
 
- **결론:** 알고리즘 설계 시 입력값 $N$이 커질 것을 대비해 **Case 1**과 같은 수학적/논리적 최적화를 지향해야 함.

## Topic 1. 시간 복잡도와 Big-O (Time Complexity)

### 1. 🏗️ 빌드업 (Why & Context)

> "좋은 컴퓨터(i9)를 쓰면 알고리즘이 나빠도 빠르지 않을까? 왜 굳이 연산 횟수를 셀까?"

- **하드웨어의 한계와 연산 속도:**
    - **클럭 스피드 (Clock Speed):** CPU가 초당 실행할 수 있는 사이클 수.
	    - 예: 5GHz CPU는 1초에 $5 \times 10^9$번의 클럭이 뜀. 덧셈 연산 하나에 3~5 클럭이 소모됨.
	- **연산 속도:** 하나의 명령(Instruction)을 처리하는 데 필요한 클럭 수(CPI)와 클럭 속도가 성능을 결정한다.
	- **알고리즘의 역할:** 하드웨어 성능이 좋아도, **불필요한 연산 횟수**를 줄이는 것이 근본적인 최적화다.

### Concept: Big-O 표기법 ($O$)

- **정의:** 함수의 **상한(Upper Bound)**. "아무리 느려져도 이 추세선 위로는 올라가지 않는다"는 최악의 경우를 보장.
- **정의:** 입력 크기 $N$이 증가할 때, 연산 횟수의 증가 추세(Trend)를 나타내는 상한선.
- **핵심 규칙 (점근적 표기):**
    
    1. **최고차항만 남김:** $N^2$이 $N$보다 압도적으로 영향력이 크므로, $N^2 + N \rightarrow O(N^2)$.
    2. **상수 무시:** $2N, 100N \rightarrow O(N)$. (하드웨어 성능 향상으로 커버 가능한 영역).
### 주요 복잡도 비교 (작은 순서대로)

$$O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N) < O(N!)$$

- **$O(1)$:** 해시 테이블 조회, 배열 인덱스 접근.
- **$O(N \log N)$:** 퀵 정렬, 병합 정렬.
- **$O(N!)$:** 외판원 순회 문제(TSP) 등 (입력 크기가 작아도 계산 불가능 수준).

## Topic 2. 복잡도 계산 가이드

### 1. 실전 계산 규칙

코드를 보고 직관적으로 복잡도를 계산하는 방법론.

| **구조**            | **복잡도**         | **설명**                                                        |
| ----------------- | --------------- | ------------------------------------------------------------- |
| **단일 반복문**        | $O(N)$          | loop가 $N$번 수행됨.                                               |
| **중첩 반복문**        | $O(N^2)$        | 바깥 $N$번 $\times$ 안쪽 $N$번. (이중 loop)                           |
| **비율 감소 (분할)**    | $O(\log N)$     | 루프마다 탐색 범위가 절반($1/2$)으로 줄어드는 경우 (예: 이진 탐색).                   |
| **순차 실행**         | $O(\text{Max})$ | $O(N)$ 실행 후 $O(N^2)$ 실행 시 $\rightarrow$ 더 큰 $O(N^2)$가 전체 복잡도. |
| **조건문 (If-Else)** | $O(\text{Max})$ | If 블록과 Else 블록 중 **더 느린 쪽**을 기준으로 함 (최악의 경우).                 |

## Topic 3. 순환(Recursion) vs 반복(Iteration)

### 1. 🏗️ 빌드업 (Why & Context)

> "같은 기능을 하는데 왜 어떤 건 재귀로 짜고, 어떤 건 for문으로 짤까?"

- **재귀의 정의:** 함수가 수행 도중 자기 자신을 다시 호출하는 것 (예: 팩토리얼, 피보나치, 하노이 탑).
- **딜레마:** 재귀는 코드가 직관적이고 수학적 정의와 유사하지만, **시스템 스택(System Stack)**을 사용하므로 메모리와 성능상 오버헤드가 발생함.
    

### Concept: 재귀의 메모리 구조와 오버헤드

- **작동 원리:** 함수를 호출할 때마다 `Return Address`(돌아갈 주소), `Local Variables`(매개변수 등)가 **Stack 메모리**에 쌓임 (Push).
- **오버헤드(Overhead):**
    - **Context Switch:** 함수 호출 및 복귀 시 레지스터 저장/복구 비용 발생.
    - **Memory:** 깊이(Depth)가 깊어질수록 스택 메모리를 과도하게 점유 → **Stack Overflow** 위험.
    - **복사 비용:** 값에 의한 전달(Call by value) 시 데이터를 계속 복사함.
- **반복문:** 데이터 영역(Data Segment)이나 힙(Heap)만 사용.
- **재귀 함수:** **시스템 스택(System Stack)** 영역을 사용.
    - 함수가 호출될 때마다 매개변수, 리턴 주소 등을 스택에 쌓아야 하므로, 깊이가 깊어지면 **스택 오버플로우(Stack Overflow)** 위험이 있다.

### Comparison: Case Study

강의에서 다룬 3가지 예제를 통해 재귀와 반복의 유불리를 비교.

#### 1) 팩토리얼 (Factorial)

- **재귀:** $N! = N \times (N-1)!$ 점화식을 그대로 구현. ($O(N)$)
- **반복:** 1부터 N까지 곱함. ($O(N)$)
- **결론:** 시간 복잡도는 같으나, 재귀는 스택 오버헤드가 발생하므로 **반복이 더 효율적**일 수 있다.
    

#### 2) 거듭제곱 ($x^n$) - **🚨 중요 (재귀가 유리한 경우)**

- **반복문 ($O(N)$):** $x$를 $N$번 곱함.
- **재귀 (분할 정복):****
    - $x^n = (x^2)^{n/2}$ 원리를 이용.
    - 짝수일 때: $x^n \rightarrow (x^2)^{n/2}$
    - 홀수일 때: $x^n \rightarrow x \times x^{n-1}$
    - **시간 복잡도:** 문제 크기가 절반씩 줄어들으므로 **$O(\log N)$**.
- **결론:** $N$이 클 때(예: 10억 승), 재귀가 압도적으로 빠름.

#### 3) 피보나치 (Fibonacci)

- **단순 재귀 ($O(2^n)$):**
- **반복문 ($O(N)$):** 올라감. 훨씬 효율적.
- **재귀 (Naive):** $F(n) = F(n-1) + F(n-2)$
    - 중복 호출 발생: $Fib(6)$을 구하기 위해 $Fib(3)$이 여러 번 계산되어 **$O(2^N)$**의 지수 시간이 걸림. (비효율의 극치)
- **반복:** 0, 1부터 시작하여 이전 값 2개를 기억하며 $N$까지 순차적으로 계산. **$O(N)$**.
- **결론:** 피보나치는 절대 단순 재귀로 짜면 안 되며, **반복문**이나 **메모이제이션(Memoization)**을 써야 한다.

### Code 구현: 거듭제곱 ($x^n$) 최적화 (Recursive)

```C
// 반복문 버전: O(N)
double slow_power(double x, int n) {
    double r = 1.0;
    for (int i = 0; i < n; i++) r = r * x;
    return r;
}

// 재귀 버전 (분할 정복): O(log N) -> 훨씬 빠름!
double fast_power(double x, int n) {
    if (n == 0) return 1;
    
    // 짝수일 경우: 절반으로 나눠서 재귀 호출 (문제를 반으로 줄임)
    if (n % 2 == 0) {
        return fast_power(x * x, n / 2);
    } 
    // 홀수일 경우
    else {
        return x * fast_power(x * x, (n - 1) / 2);
    }
}
```

- **개발자의 선택 (Trade-off):**
    - 재귀는 **"이해하기 쉽고 코드가 간결"**하다는 강력한 장점이 있음.
    - 하드웨어 성능이 충분하고 입력 크기($N$)가 스택 오버플로우를 유발하지 않을 수준이라면, **개발 생산성**을 위해 재귀를 선택하는 것이 합리적일 수 있음.
    - 반면, 성능이 절대적으로 중요하거나 $N$이 매우 크다면 복잡하더라도 반복문으로 변환해야 함.
        

### 💡 Interview

> [!faq]Q. 재귀 함수(Recursion)를 사용할 때 발생할 수 있는 잠재적 위험과 해결 방안은?
>
> 🗣️ 핵심 답변
>

> 📚 해결 방안
>
> 이를 해결하기 위해 계산한 값을 배열에 저장해두고 재사용하는 **동적 계획법(Dynamic Programming, 메모이제이션)**을 사용하거나, 단순히 **반복문(Iteration)**으로 구현하여 $O(N)$으로 최적화해야 합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **Q. 재귀를 반복문보다 선호해야 하는 경우는 언제인가요?**

> [!faq]Q. 꼬리 재귀(Tail Recursion)란 무엇이며, 일반 재귀와 어떤 차이가 있는가?
>
> 🗣️ 핵심 답변
>
> 꼬리 재귀는 재귀 호출이 함수 실행의 가장 마지막 단계에서 이루어지는 형태입니다.
>
> 📚 컴파일러 최적화
>
> 일반 재귀와 달리, 컴파일러가 꼬리 재귀를 **반복문(Loop)으로 최적화(Tail Call Optimization)**할 수 있어 스택 오버플로우 위험을 없애고 성능을 높일 수 있다는 장점이 있습니다.

## Topic 1. 하노이의 탑 (Towers of Hanoi)

### 1. 🏗️ 빌드업 (Why & Context)

> "반복문(For)으로 짤 수 있는가? 짤 수는 있지만, $N=5$만 되어도 코드가 지옥같이 복잡해진다."

- **문제 상황:** 막대 A, B, C가 있고 크기가 다른 $N$개의 원판이 있다.
- **제약 조건:**
    
    1. 한 번에 하나의 원판만 이동 가능.
    2. 맨 위의 원판만 이동 가능.
    3. 큰 원판이 작은 원판 위에 올라갈 수 없음.
        
- **핵심 아이디어 (재귀적 사고):**
  $N$개의 원판을 A에서 C로 옮기려면, 가장 큰 원판(맨 밑)을 C로 옮겨야 한다. 이를 위해 위의 $N-1$개를 먼저 비켜줘야 한다.

1. **Step 1:** 맨 밑의 원판을 제외한 **나머지 $N-1$개 원판**을 A에서 **B(임시)**로 옮긴다.
2. **Step 2:** **가장 큰 원판(1개)**을 A에서 **C(목적지)**로 옮긴다.
3. **Step 3:** B에 두었던 **$N-1$개 원판**을 다시 **C(목적지)**로 옮긴다.

### Concept: 재귀적 이동 매커니즘

- **알고리즘 순서 (A $\to$ C 로 이동 시, B를 임시 공간으로 사용):**
    
    1. **Step 1:** $N-1$개 원판을 `From`(A)에서 `Temp`(B)로 이동. (재귀 호출)
    2. **Step 2:** 가장 큰 원판(1개)을 `From`(A)에서 `To`(C)로 이동. (실제 이동)
    3. **Step 3:** $N-1$개 원판을 `Temp`(B)에서 `To`(C)로 이동. (재귀 호출)
        
- **복잡도:** 원판이 하나 늘어날 때마다 이동 횟수는 2배씩 증가하므로 $O(2^N)$의 지수 시간 복잡도를 가짐. (매우 가파르게 증가)
    

### Code 구현

```C
#include <stdio.h>

// n: 원판 개수, from: 시작점, temp: 임시공간, to: 도착점
void hanoi_tower(int n, char from, char temp, char to) {
    // Base Case: 원판이 1개면 바로 목적지로 이동
    if (n == 1) {
        printf("원판 1을 %c에서 %c로 이동\n", from, to);
    } 
    else {
        // 1. 맨 밑 원판을 제외한 n-1개를 '임시 공간(temp)'으로 이동
        // 이때 '도착점(to)'을 임시 버퍼로 사용
        hanoi_tower(n - 1, from, to, temp);
        
        // 2. 맨 밑의 가장 큰 원판을 '도착점(to)'으로 이동
        printf("원판 %d을(를) %c에서 %c로 이동\n", n, from, to);
        
        // 3. '임시 공간(temp)'에 있던 n-1개를 다시 '도착점(to)'으로 이동
        // 이때 '시작점(from)'을 임시 버퍼로 사용
        hanoi_tower(n - 1, temp, from, to);
    }
}

int main() {
    // 3개의 원판을 A -> C 로 이동 (B를 임시 공간 활용)
    hanoi_tower(3, 'A', 'B', 'C');
    return 0;
}
```

## Topic 2. 작업 스케줄링 (Machine Scheduling)

### 1. 🏗️ 빌드업 (Why & Context)

> "솜사탕 기계가 2대 있다. 피카츄(5분), 토끼(10분), 별(1분), 기본(30초) 솜사탕 주문이 한꺼번에 들어왔을 때, 어떻게 배분해야 가장 빨리 끝낼 수 있을까?"

- **문제 정의:** $M$개의 기계와 수행 시간이 다른 $N$개의 작업(Job)이 있을 때, 모든 작업이 끝나는 시간(Makespan)을 최소화하는 배치 방법 찾기.
- **접근법:** 모든 경우의 수를 따지기보다, **그리디(Greedy)** 방식을 사용하여 근사해(Approximation)를 구함.
### 그리디 알고리즘: LPT (Longest Processing Time first)

- **알고리즘 논리:**
    
	1. **정렬:** 작업 시간이 **가장 긴 순서대로(내림차순)** 작업을 정렬한다. (8, 7, 6, 5…)
	2. **배정:** 가장 먼저 끝나는(현재 부하가 가장 적은) 기계에 순서대로 작업을 배정한다.
	3. **반복:** 모든 작업이 배정될 때까지 반복한다.
	
- **왜 가장 긴 것부터 하는가?**
    - 짧은 작업을 먼저 배정하고 긴 작업을 나중에 배정하면, 마지막에 긴 작업 하나 때문에 전체 종료 시간이 크게 지연될 수 있음(Load Imbalance).
    - 큰 돌(긴 작업)을 먼저 채우고, 작은 돌(짧은 작업)로 틈새를 메우는 원리.
        
### 구현 전략 (Min Heap 활용)

- 기계들의 현재 종료 시간을 관리하기 위해 **최소 힙(Min Heap)**을 사용하면 효율적이다.
    - 항상 Root(가장 빨리 끝나는 기계)를 꺼내서 작업을 할당하고 다시 넣는다.
    
### Code 구현 (Logic Only)

```C
// 실제 구현 시에는 Min-Heap(최소 힙)을 사용하여 
// 가장 빨리 끝나는 기계를 O(log M)으로 찾아내는 것이 핵심.

void machine_scheduling(int jobs[], int n, int machines[], int m) {
    // 1. 작업 시간을 내림차순 정렬 (Greedy: LPT)
    sort(jobs, jobs + n, descending); 

    // 2. 초기 기계 가동 시간 0으로 초기화
    for(int i=0; i<m; i++) machines[i] = 0;

    // 3. 작업을 하나씩 꺼내서 가장 부하가 적은 기계에 할당
    for(int i=0; i<n; i++) {
        // 현재 가장 빨리 끝나는 기계(min_index) 찾기 (Min-Heap 사용 권장)
        int min_idx = find_min_machine_index(machines, m);
        
        // 해당 기계에 작업 할당
        machines[min_idx] += jobs[i];
        
        printf("Job %d (시간 %d) -> Machine %d 할당 (누적 %d)\n", 
               i, jobs[i], min_idx, machines[min_idx]);
    }
}
```

>[!faq]Q. 머신 스케줄링 문제에서 LPT(Longest Processing Time first) 알고리즘이 항상 최적해를 보장하는가?

> 🗣️ 핵심 답변
>
> 아니요, LPT는 그리디(Greedy) 알고리즘이므로 항상 최적해(Optimal Solution)를 보장하지는 않습니다. 하지만 최적해에 매우 근접한 **근사해(Approximation)**를 보장하며($\frac{4}{3} - \frac{1}{3M}$ 배 이내), 구현이 간단하고 빠르기 때문에 실무에서 널리 사용됩니다. NP-Hard 문제인 스케줄링에서 효율적인 대안입니다.
