## Topic 1. 퀵 정렬의 최악의 경우 (Worst Case Analysis)

### 1. 🏗️ 빌드업 (Why & Context)

> "퀵 정렬이 항상 빠를까? 언제 가장 느려질까?"

- **문제 제기:** 퀵 정렬은 평균적으로 매우 빠르지만($O(N \log N)$), 특정 상황에서는 버블 정렬만큼 느려질 수 있다.
- **최악의 시나리오:** 데이터가 이미 **오름차순** 혹은 **내림차순**으로 정렬되어 있는 경우.
    

### Concept

- **원인 분석:**
    
    1. **피벗(Pivot) 선정의 실패:** 보통 첫 번째 원소를 피벗으로 잡는다. 정렬된 데이터에서는 피벗이 항상 **최솟값**이나 **최댓값**이 된다.
    2. **불균형 분할 (Unbalanced Partition):** 리스트가 절반으로 나뉘지 않고, `1개`와 `N-1개`로 나뉜다.
    3. **재귀 깊이 증가:** 트리 높이가 $\log N$이 아니라 $N$이 된다.
        
- **결과:** 비교 횟수가 $N + (N-1) + \dots + 1$이 되어 시간 복잡도가 **$O(N^2)$**로 급격히 저하된다.

## Topic 2. 힙 (Heap) 자료구조 기초

### 1. 🏗️ 빌드업 (Context)

- 힙 정렬을 이해하려면 **힙(Heap)**과 **우선순위 큐(Priority Queue)**의 개념이 선행되어야 한다.
- **비유 (에버랜드 큐패스):** 줄을 선 순서(FIFO)가 아니라, 돈을 더 냈거나 급한 사람(우선순위)을 먼저 처리해 주는 시스템과 같다.
    

### Concept

- **정의:** 우선순위 큐를 구현하기 위한 **완전 이진 트리(Complete Binary Tree)** 형태의 자료구조.
- **종류:**
    - **최대 힙 (Max Heap):** 부모 노드의 키 값 $\ge$ 자식 노드의 키 값 (루트가 가장 큰 값).
    - **최소 힙 (Min Heap):** 부모 노드의 키 값 $\le$ 자식 노드의 키 값 (루트가 가장 작은 값).
- **특징:**
    - **중복 허용:** 이진 탐색 트리와 달리 중복된 값을 허용한다.
    - **반정렬 상태:** 부모-자식 간의 대소 관계만 유지하며, 형제 노드 간의 순서는 신경 쓰지 않는다.
        

### 배열 인덱싱 (Array Implementation)

- 힙은 완전 이진 트리이므로 배열로 효율적인 구현이 가능하다. (인덱스 1부터 시작 가정)
    - **부모 인덱스:** `i / 2`
    - **왼쪽 자식:** `i * 2`
    - **오른쪽 자식:** `i * 2 + 1`

## Topic 3. 힙 정렬 (Heap Sort) 메커니즘

### 1. 🏗️ 빌드업 (Logic)

- **핵심 아이디어:** 힙에서는 가장 큰 값(Max Heap 기준)이 항상 **루트(Root)**에 있다. 이 루트를 계속 꺼내서 배열의 뒤쪽으로 보내면 자연스럽게 정렬이 된다.
    

### Concept & Process

1. **Build Heap:** 정렬되지 않은 배열을 **최대 힙(Max Heap)**으로 변환한다. (초기화)
2. **Extract Max (Delete):**
    
    - 루트(최댓값)와 힙의 **맨 마지막 요소**를 교환한다.
    - 루트였던 값(이제 배열 끝에 있음)을 힙에서 제외(Sorted 확정)한다.
        
3. **Re-heapify:** 루트로 올라온 '마지막 요소'가 제자리를 찾도록 자식들과 비교하며 내려보낸다.
4. **Repeat:** 힙의 크기가 1이 될 때까지 2~3번 과정을 반복한다.
    

### Code 구현 (Structure)

C

```C
// 힙 정렬 메인 로직
void heap_sort(int a[], int n) {
    int i, temp;

    // 1. 초기 최대 힙 구성 (Build Heap)
    // 자식이 있는 마지막 노드부터 거슬러 올라가며 힙을 만든다.
    for (i = n / 2; i >= 1; i--) {
        make_heap(a, i, n); 
    }

    // 2. 정렬 과정 (Extract Max & Re-heapify)
    for (i = n; i > 1; i--) {
        // 루트(최댓값)와 마지막 노드 교환
        SWAP(a[1], a[i], temp);
        
        // 힙 크기를 하나 줄이고(i-1), 루트를 다시 힙 성질에 맞게 내림
        make_heap(a, 1, i - 1);
    }
}
```

## Topic 4. 힙 삭제 및 재구조화 (Deletion Logic)

### 1. 🏗️ 빌드업 (Why & Context)

- **문제:** 루트(최댓값)가 빠져나가면 트리가 끊어진다. 2인자(자식들) 중 누구를 올릴 것인가?
- **해결책:** 빈자리를 채우기 위해 자식들을 한 칸씩 당기는 방식은 복잡하다. 대신 **트리의 가장 마지막 노드**를 루트로 강제 이동시킨 후, 아래로 내려보내는(Sift Down) 방식이 훨씬 효율적이다.
    

### Concept (Sift Down / Sink)

1. **Move Last to Root:** 힙의 가장 마지막 노드(트리의 우측 하단 말단)를 루트 자리로 옮긴다.
2. **Compare Children:** 현재 노드와 왼쪽/오른쪽 자식 중 **더 큰 자식**을 찾는다.
3. **Swap & Descent:** 자식이 나보다 크다면 교환(Swap)하고 그 위치로 내려간다.
4. **Terminate:** 자식이 나보다 작거나, 리프 노드에 도달하면 멈춘다.
    

### Code 구현 (Make Heap / Adjust)

C

```C
void make_heap(int a[], int root, int n) {
    int child, temp;
    temp = a[root]; // 루트 값을 임시 저장
    child = root * 2; // 왼쪽 자식

    while (child <= n) {
        // 더 큰 자식 선택 (오른쪽 자식이 있고, 왼쪽보다 크다면)
        if (child < n && a[child] < a[child + 1]) {
            child++; 
        }

        // 부모가 자식보다 크면 중단 (힙 속성 만족)
        if (temp >= a[child]) break;

        // 자식이 더 크면 부모 위치로 올림
        a[child / 2] = a[child];
        
        // 아래 레벨로 이동
        child *= 2;
    }
    
    // 최종 위치에 저장해둔 값 삽입
    a[child / 2] = temp;
}
```

- **⚠️ 주의사항:** 코딩 시 인덱스 계산(`child * 2`)과 경계 조건(`child <= n`)을 꼼꼼히 확인해야 한다. 이 로직이 힙 정렬의 핵심 엔진이다.

## 기타 핵심 (Etc & Tips) - 알고리즘 2025.10.30

- **기수 정렬 (Radix Sort):** 교수님이 잠깐 언급하심. 비교 연산을 하지 않아 이론적으로 더 빠르지만, 구현이 복잡하고 메모리를 많이 사용해서 다음 시간에 다룰 예정.

### 💡 Interview

> [!faq]Q. 힙 정렬에서 최댓값(루트) 삭제 시, 왜 자식 노드를 바로 올리지 않고 '맨 마지막 노드'를 루트로 가져오는가?
>
> 🗣️ 핵심 답변
>
> **완전 이진 트리(Complete Binary Tree)**의 형태를 유지하기 위해서입니다.
>
> **📚 심화 설명**
>
> - 중간 노드를 삭제하고 자식들을 당겨오면 트리의 구조가 깨지거나(구멍이 생김), 다시 완전 이진 트리로 맞추기 위해 많은 이동 비용이 발생합니다.
>     
> - 가장 끝에 있는 노드를 가져오면 트리의 구조(Shape Property)는 즉시 만족되므로, 값의 대소 관계(Heap Property)만 $O(\log N)$만에 수정하면 되어 효율적입니다.
>     

> [!faq]Q. 힙 정렬과 퀵 정렬의 결정적인 차이는 무엇인가? (안정성 및 최악의 경우 관점)
>
> 🗣️ 핵심 답변
>
> 퀵 정렬은 최악의 경우 $O(N^2)$까지 성능이 저하될 수 있지만, 힙 정렬은 데이터 상태와 무관하게 항상 **$O(N \log N)$**을 보장합니다.
>
> **📚 추가 비교**
>
> - 하지만 일반적인 무작위 데이터에서는 퀵 정렬이 더 빠릅니다. 힙 정렬은 배열의 인덱스를 2배씩 건너뛰며 접근하므로 **참조 지역성(Locality of Reference)**이 떨어지기 때문입니다. 두 정렬 모두 **Unstable Sort(불안정 정렬)**입니다.
>

## 최종 요약 - 알고리즘 2025.10.30

### 1) 오늘의 TOPIC (Pattern Link)

오늘 수업은 **'분할 정복(Divide and Conquer)'** 기법을 시작으로, 이를 응용한 대표적인 정렬 알고리즘들의 진화 과정을 다루었습니다.

1. **분할 정복의 기초**: 나폴레옹의 전술과 가위바위보 예시를 통해 문제를 쪼개서(Divide) 해결하고(Conquer) 합치는(Combine) 기본 철학을 학습했습니다.
2. **합병 정렬 (Merge Sort)**: 리스트를 **물리적인 절반**으로 나누는 방식입니다. 안정적이고 항상 $O(N \log N)$을 보장하지만, 추가 메모리($O(N)$)가 필요하다는 한계가 있습니다.
3. **퀵 정렬 (Quick Sort)**: 물리적 위치가 아닌 **피벗(값)을 기준**으로 나누는 방식으로 진화했습니다. 평균적으로 가장 빠르지만, 이미 정렬된 데이터에 대해서는 $O(N^2)$로 성능이 저하되는 **최악의 경우(Worst Case)**가 존재함을 분석했습니다.
4. **힙 정렬 (Heap Sort)**: 퀵 정렬의 불안정성을 극복하기 위해 **우선순위 큐(힙 자료구조)**를 도입했습니다. **완전 이진 트리** 구조를 활용해 항상 $O(N \log N)$을 보장하며, 최댓값 삭제 시 '마지막 노드'를 이용한 재구조화(Re-heapify) 로직이 핵심입니다.
    

### 2) 강조포인트

- **알고리즘의 재귀적 흐름**: 합병 정렬과 퀵 정렬 모두 재귀 호출(Recursive Call)을 사용하지만, **'쪼개고 호출하느냐(Merge)'** vs **'정리하고 호출하느냐(Quick)'**의 순서 차이를 명확히 이해해야 합니다.
- **퀵 정렬의 파티션 로직**: `Low`와 `High` 포인터가 교차하는 지점을 찾고 피벗을 안착시키는 `Partition` 함수의 상세 구현(특히 `do-while` 선증가 이유)을 반드시 손으로 추적할 수 있어야 합니다.
- **힙의 삭제 메커니즘**: 루트(최댓값)를 삭제한 뒤, **가장 마지막 노드를 루트로 올리고** 자식들과 경쟁하며 내려가는 방식이 완전 이진 트리의 형태를 유지하는 가장 효율적인 방법임을 강조했습니다.
- **개발자의 태도**: AI(ChatGPT 등)가 짜준 코드를 그대로 사용하는 것을 경계하고, 라인 단위로 분석하여 내 것으로 만드는 능력이 미래 개발자의 생존 요건임을 당부했습니다.

## Topic 1. 기수 정렬 (Radix Sort) 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 상황에 쓸 수 있는 범용 정렬은 아니지만, 조건만 맞으면 가장 빠른 정렬"

- **기존 방식의 한계:** 퀵 정렬, 합병 정렬 등은 **비교 연산(Comparison)**을 기반으로 하며, 이론적 하한선이 $O(N \log N)$이다.
- **발상의 전환:** "비교하지 않고 정렬할 수는 없을까?" → 데이터의 **자릿수(Digit)** 값을 그대로 활용하여 버킷에 담았다 빼는 방식 고안.
    

### Concept

- **정의:** 레코드 키의 값(자릿수)을 이용하여 해당 버킷에 원소를 분배(Distribute)하고 순서대로 수집(Collect)하는 과정을 반복하는 정렬 기법.
- **시간 복잡도:** $O(dN)$ (d: 자릿수, n: 데이터 개수).
    - $d$가 작다면 사실상 선형 시간($O(N)$)에 가까운 매우 빠른 속도를 자랑한다.
- **제약 조건 (Trade-off):**
    
    1. **키의 길이가 동일해야 함:** 자릿수가 일정하지 않으면 적용이 어렵다.
    2. **특정 데이터 타입:** 정수나 문자열처럼 자릿수/문자 위치가 명확한 경우에만 사용 가능하다. (실수는 적용 난해)
    3. **추가 메모리 필요:** 각 자릿수 값을 담을 **버킷(Bucket)** 공간이 추가로 필요하다. (공간 복잡도 증가)

## Topic 2. 기수 정렬 메커니즘 (LSD & Buckets)

### 1. 🏗️ 빌드업 (Logic)

- **접근법:** 100자리 숫자를 정렬하려면 버킷이 몇 개 필요한가?
    - 0~99… 까지 만들면 메모리가 부족하다.
    - 대신 **0~9까지 10개의 버킷**만 만들고, 낮은 자릿수부터 높은 자릿수까지 반복해서 재활용하는 방식을 사용한다.
- **순서의 중요성 (LSD vs MSD):**
    - 일반적으로 **LSD (Least Significant Digit)** 방식을 사용한다. 즉, **가장 낮은 자릿수(1의 자리)**부터 정렬하고, 점차 높은 자릿수로 이동해야 한다.
    - _이유:_ 높은 자릿수(예: 10의 자리)를 먼저 정렬하면, 나중에 1의 자리를 정렬할 때 이미 정렬된 10의 자리 순서가 섞여버린다. 반대로 LSD는 낮은 자릿수의 정렬 상태를 유지하며(Stable) 높은 자릿수 정렬을 수행한다.
        

### Concept & Process (예시: 10진수)

1. **준비:** 0부터 9까지 인덱스를 가진 10개의 **버킷(Queue)** 준비.
2. **1단계 (1의 자리):** 각 숫자의 1의 자리를 보고 해당 버킷에 넣음(Enqueue) → 버킷 순서대로 뺌(Dequeue).
3. **2단계 (10의 자리):** 1단계 결과 리스트에서 10의 자리를 보고 해당 버킷에 넣음 → 버킷 순서대로 뺌.
4. **반복:** 최대 자릿수($d$)만큼 반복하면 최종 정렬 완료.
    

### 자료구조 (Why Queue?)

- **핵심 질문:** 왜 버킷을 **큐(Queue)**로 구현해야 하는가?
- **이유:** **안정 정렬(Stable Sort)** 속성을 유지하기 위함이다.
    - 같은 자릿수 값을 가진 데이터들 사이에서도, **이전 단계(더 낮은 자릿수)에서 정렬된 순서**가 유지되어야 한다. 따라서 먼저 들어온 데이터가 먼저 나가는 **FIFO(First-In First-Out)** 구조가 필수적이다.

## Topic 3. 32비트 정수 최적화 구현

### 1. 🏗️ 빌드업 (Optimization)

- 컴퓨터는 2진수를 사용하므로 버킷 2개(0, 1)만 있으면 된다.
- 그러나 32비트 정수(`int`)를 1비트씩(버킷 2개) 처리하면 **32번의 루프(Pass)**를 돌아야 한다. 이는 비효율적이다.
    

### Concept

- **8비트 단위 처리 (256 Buckets):**
    - 32비트를 8비트씩 4덩어리로 쪼갠다. ($2^8 = 256$)
    - 버킷을 **256개** 만들면, 루프를 **4번(Pass)**만 돌면 정렬이 완료된다.
    - **효과:** 메모리를 조금 더 쓰고(버킷 256개), 속도를 비약적으로 향상시킨다. (비트 연산 활용)
        

### Code 구현 (Structure Idea)

C

```C
// 기수 정렬 의사 코드 (LSD 방식)
#define BUCKETS 10 // 10진수의 경우
#define DIGITS 4   // 최대 자릿수

void radix_sort(int list[], int n) {
    Queue buckets[BUCKETS]; // 큐 배열 생성
    int factor = 1; // 1, 10, 100… 자릿수 계산용

    // 자릿수만큼 반복 (d회)
    for (int d = 0; d < DIGITS; d++) {
        // 1. 분배 (Distribute)
        for (int i = 0; i < n; i++) {
            int digit = (list[i] / factor) % 10; // 해당 자릿수 추출
            enqueue(&buckets[digit], list[i]);
        }

        // 2. 수집 (Collect)
        int i = 0;
        for (int b = 0; b < BUCKETS; b++) {
            while (!is_empty(&buckets[b])) {
                list[i++] = dequeue(&buckets[b]);
            }
        }
        
        factor *= 10; // 다음 자릿수로 이동
    }
}
```

## Topic 4. 부동소수점과 정렬의 한계

### 1. 🏗️ 빌드업 (Limitations)

- "왜 실수는 기수 정렬을 잘 안 쓸까?"
- 실수는 정수와 달리 표현 방식이 복잡하고(부호, 지수, 가수), 근사값을 사용하기 때문이다.
    

### Concept: 부동소수점 (Floating Point) 이슈

- **저장 방식 (IEEE 754):** `부호(1bit)` + `지수(8bit/11bit)` + `가수(23bit/52bit)`
- **정밀도 문제 (Precision):**
    - $0.1$을 2진수로 표현하면 무한 소수(순환 소수)가 된다. ($0.00011001100…$)
    - 컴퓨터는 이를 유한한 비트에 욱여넣으면서 잘라내므로, $0.1 + 1.1 \neq 1.2$와 같은 오차가 발생한다.
- **기수 정렬 적용의 어려움:**
    - 부동소수점은 비트 전체를 단순 정수처럼 해석해서 정렬하기 어렵다 (지수부와 가수부의 가중치가 다름).
    - 음수 처리(부호 비트) 및 지수 바이어스(Bias) 처리가 복잡하다.
        

### 정렬 알고리즘 성능 비교 Summary

|**알고리즘**|**최선(Best)**|**평균(Avg)**|**최악(Worst)**|**특징**|
|---|---|---|---|---|
|**삽입 정렬**|$O(N)$|$O(N^2)$|$O(N^2)$|이미 정렬된 경우 가장 빠름|
|**선택/버블**|$O(N^2)$|$O(N^2)$|$O(N^2)$|구현 단순, 성능 낮음|
|**퀵 정렬**|$O(N \log N)$|$O(N \log N)$|$O(N^2)$|일반적인 경우 가장 빠름 (단, 정렬된 데이터 최악)|
|**기수 정렬**|$O(dN)$|$O(dN)$|$O(dN)$|비교 연산 X, 조건부 가장 빠름, 메모리 소모|

> [!faq]Q. 기수 정렬(Radix Sort)이 시간 복잡도상 $O(N)$에 가까워 가장 빠른데, 왜 퀵 정렬보다 널리 쓰이지 않는가?
>
> 🗣️ 핵심 답변
>

>
> **📚 심화 설명**
>
> - **범용성 부족:** 퀵 정렬은 비교 연산만 가능하다면 실수, 객체 등 모든 타입에 적용 가능하지만, 기수 정렬은 자릿수가 있는 정수나 문자열 등 특정 타입에만 적용 가능합니다.
>     
> - **공간 복잡도:** 기수 정렬은 버킷을 위한 추가 메모리가 필수적인 반면, 퀵 정렬은 제자리 정렬(In-place Sort)이 가능하여 메모리 효율이 좋습니다.
>     
> - **상수항:** $d$(자릿수)가 커질 경우 $O(dN)$의 실제 연산 횟수가 퀵 정렬의 $O(N \log N)$보다 많아질 수 있습니다.

> **📚 꼬리 질문 대비**
>
> - 메모리(가수부)의 한계로 인해 무한 소수의 뒷부분을 잘라내서 저장(근사값 처리)하므로, 연산 시 미세한 오차가 발생합니다. 이를 해결하기 위해 금융권 등에서는 고정 소수점 방식이나 별도의 라이브러리를 사용합니다.

## Topic 1. 기수 정렬 (Radix Sort) 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 상황에 쓸 수 있는 범용 정렬은 아니지만, 조건만 맞으면 가장 빠른 정렬"

- **기존 방식의 한계:** 퀵 정렬, 합병 정렬 등은 **비교 연산(Comparison)**을 기반으로 하며, 이론적 하한선이 $O(N \log N)$이다.
- **발상의 전환:** "비교하지 않고 정렬할 수는 없을까?" → 데이터의 **자릿수(Digit)** 값을 그대로 활용하여 버킷에 담았다 빼는 방식 고안.
    

### Concept

- **정의:** 레코드 키의 값(자릿수)을 이용하여 해당 버킷에 원소를 분배(Distribute)하고 순서대로 수집(Collect)하는 과정을 반복하는 정렬 기법.
- **시간 복잡도:** $O(dN)$ (d: 자릿수, n: 데이터 개수).
    - $d$가 작다면 사실상 선형 시간($O(N)$)에 가까운 매우 빠른 속도를 자랑한다.
- **제약 조건 (Trade-off):**
    
    1. **키의 길이가 동일해야 함:** 자릿수가 일정하지 않으면 적용이 어렵다.
    2. **특정 데이터 타입:** 정수나 문자열처럼 자릿수/문자 위치가 명확한 경우에만 사용 가능하다. (실수는 적용 난해)
    3. **추가 메모리 필요:** 각 자릿수 값을 담을 **버킷(Bucket)** 공간이 추가로 필요하다. (공간 복잡도 증가)

## Topic 2. 기수 정렬 메커니즘 (LSD & Buckets)

### 1. 🏗️ 빌드업 (Logic)

- **접근법:** 100자리 숫자를 정렬하려면 버킷이 몇 개 필요한가?
    - 0~99… 까지 만들면 메모리가 부족하다.
    - 대신 **0~9까지 10개의 버킷**만 만들고, 낮은 자릿수부터 높은 자릿수까지 반복해서 재활용하는 방식을 사용한다.
- **순서의 중요성 (LSD vs MSD):**
    - 일반적으로 **LSD (Least Significant Digit)** 방식을 사용한다. 즉, **가장 낮은 자릿수(1의 자리)**부터 정렬하고, 점차 높은 자릿수로 이동해야 한다.
    - _이유:_ 높은 자릿수(예: 10의 자리)를 먼저 정렬하면, 나중에 1의 자리를 정렬할 때 이미 정렬된 10의 자리 순서가 섞여버린다. 반대로 LSD는 낮은 자릿수의 정렬 상태를 유지하며(Stable) 높은 자릿수 정렬을 수행한다.
        

### Concept & Process (예시: 10진수)

1. **준비:** 0부터 9까지 인덱스를 가진 10개의 **버킷(Queue)** 준비.
2. **1단계 (1의 자리):** 각 숫자의 1의 자리를 보고 해당 버킷에 넣음(Enqueue) → 버킷 순서대로 뺌(Dequeue).
3. **2단계 (10의 자리):** 1단계 결과 리스트에서 10의 자리를 보고 해당 버킷에 넣음 → 버킷 순서대로 뺌.
4. **반복:** 최대 자릿수($d$)만큼 반복하면 최종 정렬 완료.
    

### 자료구조 (Why Queue?)

- **핵심 질문:** 왜 버킷을 **큐(Queue)**로 구현해야 하는가?
- **이유:** **안정 정렬(Stable Sort)** 속성을 유지하기 위함이다.
    - 같은 자릿수 값을 가진 데이터들 사이에서도, **이전 단계(더 낮은 자릿수)에서 정렬된 순서**가 유지되어야 한다. 따라서 먼저 들어온 데이터가 먼저 나가는 **FIFO(First-In First-Out)** 구조가 필수적이다.

## Topic 5. 부동소수점 상세 구조 (IEEE 754 & Hidden Bit)

### 1. 🏗️ 빌드업 (Context)

> "왜 6.25는 컴퓨터에 저장될 때 맨 앞의 '1'을 버릴까?"

- 교수님께서는 실수 연산의 오차 원인을 설명하시며, **패트리어트 미사일 요격 실패 사례**를 언급하셨습니다. 이는 부동소수점의 저장 방식(정규화, 히든 비트)을 이해하는 것이 단순 이론을 넘어 실무(Mission Critical System)에서 얼마나 중요한지 강조하기 위함입니다.
    

### Concept: 정규화(Normalization)와 히든 비트(Hidden Bit)

- **정규화:** 2진수 실수를 $1.xxxx \times 2^n$ 형태로 변환하는 과정.
    - 예: $6.25_{(10)} \rightarrow 110.01_{(2)} \rightarrow 1.1001 \times 2^2$
- **히든 비트 (Hidden Bit):**
    - 정규화를 하면 맨 앞자리는 무조건 **'1'**이 된다. (0이 아닌 수라면)
    - **핵심 아이디어:** 어차피 항상 '1'이라면, 굳이 메모리에 저장할 필요가 있을까?
    - **절약:** 맨 앞의 1을 저장하지 않고 소수점 아래($1001$)만 가수부(Mantissa)에 저장함으로써, **1비트의 정밀도를 공짜로 더 확보**한다.
    - 데이터를 읽어올 때는 자동으로 앞에 1을 붙여서($1.1001$) 복원한다.
        

### Concept: 지수 바이어스 (Exponent Bias)

- **문제:** 지수($n$)가 음수일 수도 있다. (예: $2^{-3}$)
- **해결:** 지수부에 부호 비트를 또 만들면 복잡해지므로, **특정 값(Bias)을 더해서 무조건 양수로 저장**한다.
    - **32비트(float) 기준:** Bias는 **127**이다.
    - 실제 지수가 $2$라면 $\rightarrow 2 + 127 = 129$를 저장.
    - 실제 지수가 $-3$이라면 $\rightarrow -3 + 127 = 124$를 저장.
    - 이를 통해 지수부의 대소 비교를 단순한 정수 비교처럼 빠르게 수행할 수 있다.

### 💡 Interview (Deep-Dive)

> [!faq]Q. IEEE 754 부동소수점 표준에서 'Hidden Bit'를 사용하는 이유와 그 효과는?
>
> 🗣️ 핵심 답변
>
> 정규화된 2진수는 항상 $1.xxxx$ 형태를 가지므로, 정수 부분의 1을 저장하지 않고 생략하여 가수부(Mantissa)의 1비트를 추가로 확보하기 위함입니다.
>
> 📚 효과
>
> 이를 통해 32비트 float 자료형 기준, 유효 숫자를 23비트가 아닌 24비트의 정밀도로 표현할 수 있어 미세한 오차를 줄이는 데 기여합니다.

> [!faq]Q. 32비트 float의 지수부(Exponent)에 127을 더하는 'Bias' 방식을 사용하는 이유는?
>
> 🗣️ 핵심 답변
>
> 지수부 값을 항상 양의 정수(Unsigned Integer) 형태로 저장하여, 부동소수점끼리의 대소 비교 연산을 단순화하고 가속화하기 위함입니다.
>
> 📚 상세 설명
>
> 만약 2의 보수법 등을 사용하면 지수 비교 시 부호를 따로 따져야 하지만, Bias 방식을 쓰면 지수부 비트 패턴 자체가 클수록 더 큰 수임이 보장되므로 정렬이나 비교 로직이 훨씬 단순해집니다.

## Topic 1. 그래프(Graph)의 필요성 및 정의

### 1. 🏗️ 빌드업 (Why & Context)

> "선형 리스트나 트리(Tree)만으로는 세상의 복잡한 관계를 다 담을 수 없다."

- **문제 제기:**
    - **수강 신청:** '자료구조'를 들어야 '알고리즘'을 들을 수 있고, 'C언어'를 들어야 '자료구조'를 들을 수 있다. 이런 **선후수 관계(Dependency)**는 단순한 순서 나열로는 표현하기 어렵다.
    - **현실 세계:** 지하철 노선도, 친구 관계(SNS), 도로망 등은 계층적(Tree)이지 않고 서로 얽혀 있는 **망(Network) 구조**이다.
        

### Concept

- **정의:** 객체를 나타내는 **정점(Vertex, Node)**과 객체 간의 관계를 나타내는 **간선(Edge, Link)**의 집합으로 이루어진 비선형 자료구조.
    - 수식 표현: $G = (V, E)$
        - $V(G)$: 그래프 G의 정점들의 집합
        - $E(G)$: 그래프 G의 간선들의 집합
- **트리(Tree)와의 관계:** 트리는 그래프의 특수한 형태(사이클이 없고, 모든 노드가 연결된 계층적 그래프)일 뿐, 그래프가 훨씬 더 포괄적인 개념이다.

## Topic 3. 그래프의 종류와 특징

### 1. 무방향 그래프 (Undirected Graph)

- **개념:** 간선에 방향이 없는 그래프. 양방향 통행이 가능한 도로와 같다.
- **표현:** 정점 쌍 $(u, v)$로 표현하며, $(u, v)$와 $(v, u)$는 **동일한 간선**이다.
- **최대 간선 수:** 정점이 $n$개일 때, $\frac{n(n-1)}{2}$개.
    - _예: 친구 관계 (내가 너의 친구면, 너도 나의 친구)_
        

### 2. 방향 그래프 (Directed Graph, Digraph)

- **개념:** 간선에 방향이 존재하는 그래프. 일방통행 도로와 같다.
- **표현:** 화살표로 표현하며, $<u, v>$는 $u$에서 $v$로 가는 간선을 의미한다. $<u, v>$와 $<v, u>$는 **서로 다른 간선**이다.
    - $u$: 꼬리(Tail, 시점)
    - $v$: 머리(Head, 종점)
- **최대 간선 수:** 정점이 $n$개일 때, $n(n-1)$개. (무방향의 2배)
    - _예: 인스타그램 팔로우 (나는 팔로우했지만, 상대는 안 할 수 있음), 선수 과목_
        

### 3. 완전 그래프 (Complete Graph)

- 모든 정점이 서로 연결되어 있는 그래프. 가능한 최대의 간선을 가진 상태.
    - 네트워크 토폴로지에서 **Mesh형** 연결과 유사 (비용이 가장 비싸지만 신뢰성 최고).

## Topic 4. 가중치 그래프 (Weighted Graph)

### 1. 🏗️ 빌드업 (Deep-dive)

> "단순히 '연결되었다'는 정보만으로는 부족하다. '얼마나 효율적인가?'를 따져야 한다."

- **비유:** 인천에서 대구로 가는 길은 여러 개다. 단순 연결 정보만 있으면 아무 길이나 알려주겠지만, 우리는 **최단 시간** 또는 **최소 비용** 경로를 원한다.
    

### Concept

- **정의:** 간선에 **비용(Cost)**, **가중치(Weight)** 등의 값을 부여한 그래프. '네트워크(Network)'라고도 부른다.
- **활용:**
    - **최단 경로 알고리즘 (Dijkstra, Bellman-Ford):** 가중치의 합이 최소가 되는 경로 찾기.
    - **최소 신장 트리 (MST - Kruskal, Prim):** 모든 노드를 가장 적은 비용으로 연결하기.
- **실무적 의미:**
    - 지도 앱의 '최단 시간' vs '무료 도로' 옵션.
    - 네트워크 대역폭(Bandwidth) 차이 (전용선 vs 일반 인터넷).
    - 하드웨어 버스 속도 차이 (USB 2.0 vs 3.0 vs Thunderbolt).
        

### Code 구현 (개념적 구조 - 인접 행렬 vs 인접 리스트)

> _(강의에서 깊게 다루진 않았으나, 자료구조 기초로 언급됨)_

C

```C
// 1. 인접 행렬 (Adjacency Matrix)
// 정점 간의 연결 관계를 2차원 배열로 표현
// adj[i][j] = 1 (연결됨) 또는 가중치 값, 0 (연결 안 됨)
int graph[N][N] = {
    {0, 1, 0},
    {1, 0, 5}, // 가중치 5
    {0, 5, 0}
};

// 2. 인접 리스트 (Adjacency List)
// 각 정점에 연결된 간선들만 리스트로 관리 (메모리 효율적)
typedef struct Node {
    int vertex;
    int weight;
    struct Node* next;
} Node;
Node* adj[N];
```

> 트리는 사이클(Cycle)이 없는 연결 그래프로, 계층적(Hierarchical) 구조를 가집니다. 반면, 그래프는 사이클을 포함할 수 있으며, 계층이 없는 망(Network) 구조로 훨씬 포괄적인 개념입니다. (트리는 그래프의 부분 집합)
>
> **📚 심화: 루트 노드 유무**
>
> - 트리는 반드시 하나의 루트(Root) 노드가 존재하고 부모-자식 관계가 명확하지만, 그래프는 루트의 개념이 없고 모든 노드가 평등한 관계입니다.
>     

> [!faq]Q. 인접 행렬(Adjacency Matrix)과 인접 리스트(Adjacency List) 중 어떤 것을 언제 사용하는 것이 유리한가?
>
> 🗣️ 핵심 답변
>
> 간선이 많은 **밀집 그래프(Dense Graph)**라면 인접 행렬이 구현이 쉽고 간선 조회($O(1)$)가 빨라 유리합니다. 반면, 간선이 적은 **희소 그래프(Sparse Graph)**라면 인접 리스트가 메모리를 훨씬 적게 차지하므로 효율적입니다.
>
> **📚 공간 복잡도 비교**
>
> - 인접 행렬: $O(V^2)$ (무조건 $N \times N$ 할당)
>     
> - 인접 리스트: $O(V + E)$ (실제 존재하는 간선만큼만 할당)
>

## Topic 2. 그래프 핵심 용어 및 차수 (Degree)

### 1. 기본 용어 정의

- **정점 (Vertex, Node):** 객체를 표현 ($V_i, V_j$).
- **간선 (Edge, Link):** 정점 간의 관계.
    - **인접 (Adjacency):** 간선으로 직접 연결된 두 **정점** 사이의 관계. (예: $A$와 $B$는 인접하다)
    - **부속 (Incidence):** **간선**이 정점에 연결된 상태. (예: 간선 $(A, B)$는 정점 $A$에 부속되어 있다)
        

### 2. 차수 (Degree)의 개념

정점에 연결된 간선의 수를 의미하며, 그래프의 종류에 따라 계산법이 다름.

#### A. 무방향 그래프 (Undirected Graph)

- **정의:** 정점에 연결된 간선의 총개수.
- **특징:** 방향이 없으므로 들어오는 것과 나가는 것을 구분하지 않음.
    

#### B. 방향 그래프 (Directed Graph)

- **구분:** 간선의 화살표 방향(Head/Tail)에 따라 진입/진출로 나뉨.
    - **진입 차수 (In-degree):** 외부에서 해당 정점으로 들어오는 화살표의 수. (Head가 해당 정점일 때)
    - **진출 차수 (Out-degree):** 해당 정점에서 외부로 나가는 화살표의 수. (Tail이 해당 정점일 때)
- **전체 차수 (Total Degree):** $\text{In-degree} + \text{Out-degree}$
- **주의:** 그림 없이 텍스트로 표현될 때 $V_i \to V_j$ 관계에서 시점($V_i$)과 종점($V_j$)을 명확히 구분해야 함.

    - **트리 (Tree):** 사이클이 없는 연결 그래프 (그래프의 특수한 부분집합).

## Topic 4. 그래프의 표현: 인접 행렬 (Adjacency Matrix)

### 1. 🏗️ 빌드업 (Implementation)

> "그림으로 그려진 그래프를 컴퓨터 메모리에 어떻게 저장할 것인가?"

- **접근법:**
    
    1. **배열 (Array):** 2차원 배열 사용 $\rightarrow$ **인접 행렬**
    2. **연결 리스트 (Linked List):** 포인터 사용 $\rightarrow$ **인접 리스트**
        

### 2. 인접 행렬 (Adjacency Matrix) 구조

- **정의:** $N$개의 정점을 가진 그래프를 $N \times N$ 크기의 2차원 배열(정방 행렬)로 표현.
- **값의 의미:**
    - `M[i][j] = 1`: 정점 $i$와 $j$가 연결됨 (간선 존재).
    - `M[i][j] = 0`: 연결되지 않음.
    - (가중치 그래프의 경우 1 대신 가중치 값을 저장)
- **대각 성분 (Diagonal):** `M[i][i]`는 자기 자신으로의 루프(Self-loop)가 없는 한 **0**으로 채워짐.
    

### 3. 그래프 종류별 행렬 특징

|**구분**|**무방향 그래프 (Undirected)**|**방향 그래프 (Directed)**|
|---|---|---|
|**대칭 여부**|**대칭 행렬 (Symmetric)**<br><br>  <br><br>(`M[i][j] == M[j][i]`)|**비대칭** (일반적으로)|
|**행(Row)의 합**|해당 정점의 **차수 (Degree)**|해당 정점의 **진출 차수 (Out-degree)**|
|**열(Col)의 합**|해당 정점의 **차수 (Degree)**|해당 정점의 **진입 차수 (In-degree)**|

### Code 구현 (C언어 예시)

C

```C
#define MAX_VERTICES 50
// 인접 행렬 구조체 정의
typedef struct GraphType {
    int n; // 정점의 개수
    int adj_mat[MAX_VERTICES][MAX_VERTICES];
} GraphType;

// 정점 삽입, 간선 삽입 함수 등을 통해 0과 1로 채움
// 방향 그래프인 경우: adj_mat[start][end] = 1;
// 무방향 그래프인 경우: adj_mat[start][end] = 1; adj_mat[end][start] = 1;
```

## Topic 1. 인접 행렬 (Adjacency Matrix)의 한계와 특성

### 1. 🏗️ 빌드업 (Why & Context)

> "정점은 100개인데 간선은 2개뿐이라면? 100x100 행렬을 다 만드는 건 낭비다."

- **문제 제기:** 정점이 $N$개일 때 인접 행렬은 무조건 $N \times N$ 크기의 메모리를 할당해야 한다.
    - 예: 정점 100개 $\rightarrow$ $10,000$개 공간 필요. (`int`형 기준 약 40KB)
    - 만약 간선이 거의 없다면(**희소 행렬, Sparse Matrix**), 대부분의 공간이 `0`으로 채워져 **메모리 낭비**가 심각해진다.
        

### 2. 성능 분석 (Time Complexity)

- **장점:**
    - **간선 조회:** 두 정점 $u, v$가 연결되었는지 확인하려면 `M[u][v]`만 보면 되므로 **$O(1)$**로 매우 빠르다.
    - **차수 계산:** 특정 행(또는 열) 전체를 더하면 되므로 $O(N)$이다.
- **단점:**
    - **전체 간선 탐색:** 모든 간선을 찾으려면 행렬 전체를 훑어야 하므로 **$O(N^2)$**의 시간이 걸린다.

## Topic 2. 인접 행렬 구현 (C Code Analysis)

### Code 구현 (초기화 및 삽입)

C

```C
#define MAX_VERTICES 50

typedef struct GraphType {
    int n; // 정점의 개수
    int adj_mat[MAX_VERTICES][MAX_VERTICES];
} GraphType;

// 그래프 초기화
void init(GraphType* g) {
    int r, c;
    g->n = 0; // 정점 개수 0으로 초기화
    for (r = 0; r < MAX_VERTICES; r++)
        for (c = 0; c < MAX_VERTICES; c++)
            g->adj_mat[r][c] = 0; // 모든 값을 0으로 채움
}

// 정점 삽입 (Vertex Insertion)
void insert_vertex(GraphType* g, int v) {
    if (((g->n) + 1) > MAX_VERTICES) {
        printf("Graph: 정점 개수 초과\n");
        return;
    }
    g->n++; // 단순히 카운트만 증가시킴 (배열 인덱스 확장 개념)
}

// 간선 삽입 (Edge Insertion)
void insert_edge(GraphType* g, int start, int end) {
    if (start >= g->n || end >= g->n) {
        printf("Graph: 정점 번호 오류\n");
        return;
    }
    // 무방향 그래프 가정 (대칭)
    g->adj_mat[start][end] = 1;
    g->adj_mat[end][start] = 1;
}
```

## Topic 3. 인접 리스트 (Adjacency List)의 구조와 이해

### 1. 🏗️ 빌드업 (Concept)

> "연결된 놈들만 리스트로 엮자."

- **구조:** 각 정점마다 연결된 간선들만 **연결 리스트(Linked List)** 형태로 매달아 관리한다.
- **헤드 노드 배열:** 정점의 개수($N$)만큼의 **포인터 배열**(`adj_list[N]`)을 만들고, 각 배열의 요소가 해당 정점의 연결 리스트 시작점(Head)을 가리킨다.
    

### 2. ⚠️ 핵심 오개념 교정 (Crucial Misconception)

> [!warning] **주의: 시각적 표현 vs 논리적 의미**
>
> - **잘못된 해석:** $A \rightarrow B \rightarrow C$ 리스트를 보고 "$A$에서 $B$로 가고, $B$에서 다시 $C$로 가는 경로(Path)"라고 생각하면 안 된다.
>     
> - **올바른 해석:** $A$ 정점에 **$B$도 연결되어 있고, $C$도 연결되어 있다**는 뜻이다. (즉, $A \rightarrow B$ 간선과 $A \rightarrow C$ 간선이 존재함). 리스트의 순서는 구현 편의상(보통 오름차순) 정렬된 것일 뿐, 경로 순서가 아니다.
>     

### 3. 그래프 종류별 특징

- **무방향 그래프:** 간선 $(A, B)$가 있으면, $A$의 리스트에 $B$가 있어야 하고, **$B$의 리스트에도 반드시 $A$가 있어야 한다.** (중복 저장됨)
- **방향 그래프:** $A \rightarrow B$라면, $A$의 리스트(진출 차수 기준)에만 $B$가 저장된다. $B$의 리스트에는 $A$가 없다.

## Topic 4. 인접 리스트 구현 (C Code Analysis)

### 1. 자료구조 정의

C

```C
// 연결 리스트의 노드 구조체
typedef struct GraphNode {
    int vertex;             // 연결된 정점 번호
    struct GraphNode* link; // 다음 노드 포인터
} GraphNode;

// 그래프 구조체 (포인터 배열 사용)
typedef struct GraphType {
    int n; // 정점의 개수
    GraphNode* adj_list[MAX_VERTICES]; // 헤드 노드 포인터 배열
} GraphType;
```

### 2. 포인터 배열에 대한 이해 (Professor's Emphasis)

- `GraphNode* adj_list[MAX_VERTICES]`의 의미:
    - **배열**인데, 각 칸에 저장되는 값이 **`GraphNode`형 데이터의 주소값(포인터)**이다.
    - 즉, `adj_list[0]`은 0번 정점에 연결된 첫 번째 노드의 주소를 담고 있다.
    - 포인터 변수 자체의 크기는 무조건 **4바이트(32bit) 또는 8바이트(64bit)**이다. 가리키는 데이터가 아무리 커도 포인터 변수의 크기는 일정하다는 점을 명심할 것.
        

### Code 구현 (초기화 및 간선 삽입)

C

```C
// 초기화
void init(GraphType* g) {
    int v;
    g->n = 0;
    for (v = 0; v < MAX_VERTICES; v++) {
        g->adj_list[v] = NULL; // 모든 헤드 포인터를 NULL로 초기화
    }
}

// 간선 삽입 (u -> v)
void insert_edge(GraphType* g, int u, int v) {
    GraphNode* node;
    
    // 1. 새로운 노드 생성 (동적 할당)
    node = (GraphNode*)malloc(sizeof(GraphNode));
    node->vertex = v;
    
    // 2. 리스트의 맨 앞에 삽입 (Insert at Head)
    // 기존 헤드가 가리키던 것을 새 노드의 다음으로 연결
    node->link = g->adj_list[u]; 
    // 새 노드를 헤드로 설정
    g->adj_list[u] = node; 
}
```

- **Insert Logic:** 위 코드는 리스트의 **맨 앞**에 삽입하는 방식($O(1)$)이다. 만약 오름차순 정렬을 유지하려면 순차 탐색 후 삽입($O(E)$)해야 한다.

## Topic 1. 그래프 탐색 (Graph Search) 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "그래프를 만들었으면 돌아다녀봐야 한다."

- **정의:** 하나의 시작 정점(Start Vertex)에서 출발하여, 연결된 모든 정점들을 **빠짐없이, 중복 없이 한 번씩 방문**하는 연산.
- **활용 사례:**
    - **연결성 확인:** 네트워크가 끊어진 곳은 없는가? (특정 노드 도달 불가능 여부)
    - **회로 검사:** 회로 기판(PCB) 상에서 $A$ 지점과 $B$ 지점이 연결되어야 하는데 끊어져 있다면 불량 판정.
    - **경로 찾기:** 특정 도시에서 다른 도시로 갈 수 있는가?
        

### 2. 탐색의 두 가지 전략

1. **깊이 우선 탐색 (DFS, Depth First Search):** 한 방향으로 갈 수 있을 때까지 깊게 파고들다가 막히면 돌아온다. (스택 사용)
2. **너비 우선 탐색 (BFS, Breadth First Search):** 시작점 주변부터 얕고 넓게 훑으며 퍼져나간다. (큐 사용)

## Topic 2. 깊이 우선 탐색 (DFS) 동작 원리

### 1. 🏗️ 빌드업 (Analogy)

> "우물을 팔 때 물이 나올 때까지 한 곳만 계속 파는 방식."

- **전략:**
    
    1. 현재 정점에서 갈 수 있는 인접 정점 중 하나를 골라 이동한다.
    2. 이동한 곳에서 또다시 깊게 들어간다.
    3. 더 이상 갈 곳이 없는 **막다른 길(Leaf)**에 도달하면, 가장 마지막에 만났던 **갈림길(Branch)**로 되돌아온다. (**Backtracking**)
        

### 2. 핵심 자료구조

- **스택 (Stack):** 되돌아올 갈림길의 위치를 기억하기 위해 **LIFO(Last-In First-Out)** 구조가 필요하다.
    - 실제 구현에서는 명시적인 스택 자료구조를 쓰기도 하지만, **함수 호출 스택(System Stack)을 이용한 재귀(Recursion)**가 훨씬 코드가 간결하여 자주 사용된다.
- **방문 배열 (`visited[]`):** 그래프는 사이클(Cycle)이 있을 수 있으므로, 이미 방문한 노드를 다시 방문하지 않도록 체크(Marking)해야 무한 루프를 방지할 수 있다.
    

### 3. [Diagram] DFS 탐색 순서 예시

`Start: A` | `Graph: A-B, A-C, B-D, D-G, G-E, G-F`

- **탐색 순서:** $A \rightarrow B \rightarrow D \rightarrow G \rightarrow E \rightarrow (Back) \rightarrow G \rightarrow F \rightarrow (Back) \dots$
- **중요:** 시작 정점이 달라지거나, 인접 노드 선택 순서(오름차순 등)가 달라지면 방문 순서도 달라진다.

## Topic 3. DFS 구현 코드 분석 (Recursion)

### 1. 인접 행렬 (Adjacency Matrix) 기반

C

```C
// visited 배열: 방문했으면 1(TRUE), 아니면 0(FALSE)
int visited[MAX_VERTICES];

// g: 그래프 포인터, v: 현재 방문 중인 정점
void dfs_mat(GraphType* g, int v) {
    int w;
    visited[v] = TRUE;      // 1. 현재 정점 방문 표시
    printf("%d ", v);       // 2. 정점 처리 (출력)

    // 3. 인접 정점 탐색 (0부터 N-1까지 순회)
    for (w = 0; w < g->n; w++) {
        // g->adj_mat[v][w]: 간선이 존재하고
        // !visited[w]: 아직 방문하지 않은 정점이라면
        if (g->adj_mat[v][w] && !visited[w]) {
            dfs_mat(g, w); // 4. 재귀 호출 (깊이 우선 탐색)
        }
    }
}
```

- **Time Complexity:** 모든 정점을 방문하고($N$), 각 정점마다 행 전체를 검사($N$)하므로 **$O(N^2)$**이다.
    

### 2. 인접 리스트 (Adjacency List) 기반

C

```C
void dfs_list(GraphType* g, int v) {
    GraphNode* w;
    visited[v] = TRUE;
    printf("%d ", v);

    // 인접 리스트 순회 (포인터 따라가기)
    for (w = g->adj_list[v]; w; w = w->link) {
        // w->vertex: 인접 정점 번호
        if (!visited[w->vertex]) {
            dfs_list(g, w->vertex); // 재귀 호출
        }
    }
}
```

- **Time Complexity:** 모든 정점을 방문($N$)하고, 실제 존재하는 간선($E$)만 검사하므로 **$O(N + E)$**이다. 희소 그래프에서 훨씬 효율적이다.

## Topic 4. 코드 추적 (Tracing) 및 주의사항

### 1. 재귀 호출의 흐름 (Stack Frame)

- `dfs(A)` 호출 $\rightarrow$ `visited[A]=1` $\rightarrow$ 인접한 `B` 발견 $\rightarrow$ `dfs(B)` 호출 (A는 대기 상태)
- `dfs(B)` 실행 중 $\rightarrow$ 인접한 `D` 발견 $\rightarrow$ `dfs(D)` 호출 (B도 대기)
- …
- 막다른 곳에서 함수가 리턴되면, 대기하고 있던 이전 함수의 `for` 루프로 돌아와서 **다음 인접 정점(`w++`)**을 찾는다. 이 과정이 **Backtracking**이다.
    

### 2. ⚠️ 시험/과제 주의사항

- **시작 정점:** 문제에서 "C에서 시작하라"고 했는데 습관적으로 A(0번)부터 탐색하면 오답이다.
- **방문 순서:** 인접 정점이 여러 개일 때(예: B, C), 보통 **오름차순(번호가 작은 순서)**으로 방문한다고 가정하지만, 문제 조건을 잘 봐야 한다.
- **단절된 그래프:** `dfs` 함수 하나만 호출해서는 연결되지 않은 다른 컴포넌트를 방문할 수 없다. 전체 탐색을 하려면 `main`에서 반복문을 돌며 방문하지 않은 정점에 대해 `dfs`를 재호출해야 한다.

> DFS는 **스택(또는 재귀)**을 사용하여 깊게 탐색하며, 미로 찾기나 위상 정렬, 백트래킹 문제에 적합합니다.

>

> - BFS: Queue (FIFO) - 퍼져나감.

## Topic 3. BFS (너비 우선 탐색) 개념 및 원리

### 1. 🏗️ 빌드업 (Analogy)

> "서울에서 여행을 간다면? 일단 가까운 수원, 인천, 김포부터 다 찍고, 그 다음에 수원 너머 천안, 인천 너머 섬으로 확장해 나간다."

- **전략:** 시작 정점으로부터 **거리가 1인 모든 노드**를 먼저 방문하고, 그 다음 거리가 2인 노드들을 방문하는 **레벨(Level) 단위 탐색** 방식.
- **핵심 자료구조:** **큐 (Queue)** (FIFO - 먼저 들어온 놈이 먼저 나간다).
    

### 2. [Diagram] BFS 탐색 순서 (Logic)

`Start: V`

1. **Level 0:** 시작 정점 $V$ 방문 & 큐에 삽입(Enqueue).
2. **Level 1:** $V$를 꺼내고(Dequeue), $V$와 연결된(인접한) 모든 미방문 정점 $A, B, C$를 방문 & 큐에 삽입.
3. **Level 2:** $A$를 꺼내고 $A$의 이웃 방문, $B$를 꺼내고 $B$의 이웃 방문… (큐에 들어간 순서대로 처리되므로 거리 순서가 보장됨).
    

### 3. 검산 팁 (시험 꿀팁)

- **거리(Depth) 체크:** 시작점으로부터 간선을 몇 번 타고 가야 하는지 세어보면 BFS 방문 순서 그룹을 알 수 있다.
    - _예:_ 시작점(0) $\rightarrow$ 거리 1인 노드들(1차 그룹) $\rightarrow$ 거리 2인 노드들(2차 그룹) …
- **정보처리기사 필수 문제:** DFS와 BFS 방문 순서를 묻는 문제는 1분 30초 안에 풀어야 하는 단골 문제다. 눈으로만 풀지 말고 직접 그려봐야 한다.

## Topic 4. BFS 구현 및 코드 분석

### 1. 알고리즘 흐름 (Pseudo Code)

Plaintext

```C
BFS(v):
    v 방문 표시;
    Queue.enqueue(v);
    
    while (Queue is not Empty):
        v = Queue.dequeue();
        for all u adjacent to v:
            if (u is not visited):
                u 방문 표시;
                Queue.enqueue(u);
```

### 2. C언어 구현 (인접 행렬 기반)

C

```C
void bfs_mat(GraphType* g, int v) {
    int w;
    QueueType q;
    init_queue(&q);     // 큐 초기화
    
    visited[v] = TRUE;  // 1. 시작점 방문
    printf("%d ", v);
    enqueue(&q, v);     // 2. 큐에 삽입
    
    while (!is_empty(&q)) {
        v = dequeue(&q); // 3. 큐에서 하나 꺼냄
        
        // 4. 꺼낸 정점(v)의 인접 정점(w) 탐색
        for (w = 0; w < g->n; w++) {
            if (g->adj_mat[v][w] && !visited[w]) {
                visited[w] = TRUE; // 방문 표시
                printf("%d ", w);
                enqueue(&q, w);    // 큐에 삽입
            }
        }
    }
}
```

### 3. 복잡도 분석

- **인접 행렬:** $O(N^2)$ (모든 정점 $N$ $\times$ 행 검사 $N$)
- **인접 리스트:** $O(N + E)$ (모든 정점 $N$ + 모든 간선 $E$)
    - 희소 그래프(Sparse Graph)일수록 인접 리스트가 유리하다.

## Topic 3. Kruskal 알고리즘 (Edge-centric)

### 1. 알고리즘 프로세스

1. **정렬 (Sorting):** 그래프의 모든 간선을 가중치 기준 **오름차순**으로 정렬한다.
2. **선택 (Selection):** 가장 가중치가 낮은 간선부터 하나씩 선택한다.
3. **검증 (Cycle Check):** 선택한 간선을 연결했을 때 **사이클이 형성되는지** 확인한다.
    
    - 사이클이 생기면? $\rightarrow$ 버린다 (Skip).
    - 사이클이 안 생기면? $\rightarrow$ 트리에 추가한다.
        
4. **종료:** 선택된 간선의 개수가 $N-1$개가 되면 종료한다.
    

### 2. 핵심 기술: Union-Find (Disjoint Set)

- **용도:** 간선 추가 시 사이클 발생 여부를 $O(1)$에 가깝게 확인하기 위함.
- **원리:**
    - `Find(u)`: 정점 u가 속한 집합의 루트(대표)를 찾는다.
    - `Union(u, v)`: 두 집합을 하나로 합친다.
    - 만약 `Find(u) == Find(v)`라면 이미 같은 집합(연결됨)이므로, 간선을 추가하면 **사이클**이 된다.
        

### 3. 복잡도 및 특징

- **시간 복잡도:** 간선 정렬에 $O(E \log E)$ 소요.
- **적합성:** 간선이 적은 **희소 그래프(Sparse Graph)**에 유리하다.

## Topic 4. Prim 알고리즘 (Vertex-centric)

### 1. 알고리즘 프로세스

1. **시작:** 임의의 시작 정점(Start Node) 하나를 선택하여 트리에 포함시킨다.
2. **확장:** 현재 트리에 포함된 정점들과 인접한 간선들 중 **가장 가중치가 낮은 간선**을 선택하여 연결된 새로운 정점을 트리에 포함시킨다.
    
    - _(단, 이미 트리에 포함된 정점끼리 연결하는 간선은 제외 - 사이클 방지)_
        
3. **반복:** 모든 정점($N$개)이 트리에 포함될 때까지(간선 $N-1$개) 반복한다.
    

### 2. 복잡도 및 특징

- **시간 복잡도:** 구현 방식(배열 vs 힙)에 따라 다르지만 보통 $O(N^2)$ 또는 $O(E \log N)$.
- **적합성:** 간선이 많은 **밀집 그래프(Dense Graph)**에 유리하다. (정렬 비용이 없으므로)
- **장점:** 시작 정점이 어디든 결과(총 비용)는 항상 동일하다.
    

---

## Topic 5. Kruskal vs Prim 비교 분석

|**특징**|**Kruskal 알고리즘**|**Prim 알고리즘**|
|---|---|---|
|**중심 관점**|**간선 (Edge)** 중심|**정점 (Vertex)** 중심|
|**초기 상태**|간선 정렬 필요|시작 정점 하나로 시작|
|**탐색 방식**|가장 싼 간선부터 툭툭 끊어서 연결 (전역적)|시작점에서 점점 영역을 넓혀감 (국소적)|
|**사이클 처리**|Union-Find로 검사 필수|`visited` 배열로 검사 (이미 방문한 정점 제외)|
|**시간 복잡도**|$O(E \log E)$ (정렬 비용 지배적)|$O(N^2)$ (배열) / $O(E \log N)$ (우선순위 큐)|
|**유리한 경우**|**희소 그래프 (Sparse)**|**밀집 그래프 (Dense)**|

## Topic 2. 그리디 알고리즘 (Greedy Algorithm)

### 1. 🏗️ 빌드업 (Concept)

> "지금 당장 가장 좋아 보이는 것을 선택한다. 하지만 그게 항상 정답일까?"

- **정의:** 매 순간 최적이라고 생각되는 선택을 해나가며 최종 해답에 도달하는 방식.
    

### 2. 동전 거스름돈 예시 (Counter-Example)

- **상황 A (정상):** 동전이 500원, 100원, 50원, 10원일 때.
    - 800원 거슬러 주기 $\rightarrow$ 500원 1개 + 100원 3개 (총 4개). **(최적해 보장)**
- **상황 B (반례):** 동전이 500원, **400원**, 100원일 때.
    - **그리디 선택:** 800원 $\rightarrow$ 500원 1개 + 100원 3개 (총 4개).
    - **실제 최적해:** 400원 2개 (총 2개).
- **결론:** 그리디 알고리즘은 **항상 최적해(Optimal Solution)를 보장하지 않는다.** 따라서 반드시 **검증(Proof)** 과정이 필요하다. (다행히 MST의 Kruskal, Prim은 최적해가 수학적으로 증명됨).

## Topic 3. MST (최소 신장 트리) 핵심 복습

### 1. Kruskal 알고리즘

- **기준:** **간선(Edge)** 중심.
- **로직:** 가중치가 낮은 간선부터 정렬(Sorting)하여 선택하되, **사이클(Cycle)**이 생기지 않도록 한다.
- **필수:** Union-Find 자료구조 (사이클 검사).
    

### 2. Prim 알고리즘

- **기준:** **정점(Vertex)** 중심.
- **로직:** 시작 정점에서 출발하여, 현재 트리에 인접한 간선 중 가장 가중치가 낮은 것을 선택하며 확장한다.
- **특징:** 정렬 과정이 필요 없고, 시작점이 어디든 결과 비용은 동일하다.

## Topic 4. 최단 경로 (Shortest Path) - 다익스트라 도입

### 1. 🏗️ 빌드업 (Difference)

- **MST와의 차이:** MST는 '모든 노드 연결'이 목적이지만, 최단 경로는 **'두 정점 사이의 비용 최소화'**가 목적이다. 경우에 따라 MST에 포함되지 않은 간선이 최단 경로에는 사용될 수 있다.
    

### 2. 가중치 인접 행렬의 표현

- **연결 없음:** 가중치 그래프에서는 `0`이 아닌 **`무한대(INF)`**로 표현해야 한다.
    - 이유: `0`은 비용이 0이라는 뜻(즉시 이동)이 될 수 있기 때문.
- **자기 자신:** $0$으로 표현.
    

### 3. 다익스트라 (Dijkstra) 알고리즘 개요

- **목표:** 하나의 시작 정점(Start Node)에서 **다른 모든 정점**까지의 최단 거리를 구한다.
- **자료구조:**
    - `S`: 최단 거리가 확정된 정점 집합.
    - `distance[]`: 시작점에서 각 정점까지 가는 현재까지의 최단 거리.
- **원리:**
    - 아직 방문하지 않은 정점 중 `distance`가 가장 작은 정점을 선택하여 `S`에 넣고, 그 정점을 거쳐가는 경로가 더 짧다면 `distance`를 갱신(Relaxation)한다.
        

### 💡 Interview

> [!faq]Q. 그리디 알고리즘(Greedy Algorithm)을 사용할 때 주의할 점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 그리디 알고리즘은 매 순간의 지역적 최선(Local Optimum)을 선택하기 때문에, 그 결과가 반드시 **전역 최적해(Global Optimum)**라는 보장이 없습니다.
>
> **📚 꼬리질문 대비**
>
> - 따라서 동전 거스름돈 문제(특수 동전 단위)나 배낭 문제(Knapsack)처럼 그리디가 실패하는 케이스를 인지하고, 적용 전 반드시 수학적 **검증(Proof)**을 거치거나 근사해(Approximation)로 만족해야 할 때 사용해야 합니다.
>     

> [!faq]Q. 가중치 그래프의 인접 행렬 초기화 시, 연결되지 않은 간선을 0이 아닌 무한대(INF)로 설정하는 이유는?
>
> 🗣️ 핵심 답변
>
> 최단 경로 알고리즘에서 '0'은 비용이 들지 않는다는 의미로 해석되어, 연결되지 않은 상태와 구분이 불가능하기 때문입니다. 따라서 계산 결과(최솟값 찾기)에 영향을 주지 않도록 아주 큰 값(무한대)으로 설정하여 '갈 수 없음'을 명시해야 합니다.

## Topic 1. MST vs 최단 경로 (Comparison)

### 1. 🏗️ 빌드업 (Concept)

> "MST는 도로를 최소한으로 깔아서 모든 도시를 잇는 것이고, 최단 경로는 이미 깔린 도로에서 가장 빨리 가는 길을 찾는 것이다."

- **MST (Minimum Spanning Tree):**
    - 목적: 모든 노드를 연결하되 간선 가중치의 합이 최소가 되도록 함.
    - 결과: 트리 (Tree) 형태. 사이클 없음.
    - 알고리즘: Kruskal, Prim.
- **최단 경로 (Shortest Path):**
    - 목적: 특정 출발지에서 목적지까지 가는 경로의 가중치 합이 최소가 되도록 함.
    - 결과: 경로 (Path).
    - 알고리즘: Dijkstra, Bellman-Ford, Floyd-Warshall.

## Topic 2. 다익스트라 알고리즘 심화 (Tracing)

### 1. 🏗️ 시뮬레이션 설정 (0번 노드 시작)

- **초기 상태:**
    - **집합 $S$ (방문 확정):** `{0}`
    - **`distance` 배열:** `[0, 7, INF, INF, 3, 10, INF]` (0번 행의 초기 가중치)
        

### 2. 단계별 추적 (Step-by-Step)

1. **Step 1 (최소 거리 선택):** `distance` 중 방문하지 않은 가장 작은 값은 **4번 노드(3)**.
    
    - $S = \{0, 4\}$
    - **갱신 (Relaxation):** 4번을 거쳐갈 때 더 빠른 곳이 있는가?
        - $0 \to 1$: 기존 7 vs $(0 \to 4 \to 1)$ $3 + \text{weight}[4][1]$ (예: 2) = 5. **갱신 (7 $\to$ 5)**.
        - $0 \to 2$: 기존 INF vs $(0 \to 4 \to 2)$ $3 + \text{weight}[4][2]$.
        - $0 \to 3$: 기존 INF vs $(0 \to 4 \to 3)$ $3 + 11 = 14$. **갱신 (INF $\to$ 14)**.
    - **결과:** `[0, 5, INF, 14, 3, 10, 18]` (가정된 값 포함)
        
2. **Step 2 (다음 최소 선택):** `distance` 중 가장 작은 **1번 노드(5)** 선택.
    
    - $S = \{0, 4, 1\}$
    - **갱신:** 1번을 거쳐갈 때 더 빠른 곳이 있는가?
        - $0 \to 2$: 기존 INF vs $(0 \to 1 \to 2)$ $5 + \text{weight}[1][2]$ (예: 4) = 9. **갱신 (INF $\to$ 9)**.
    - **결과:** `[0, 5, 9, 14, 3, 10, 18]`
        
3. **반복:** 이 과정을 모든 노드가 $S$에 포함될 때까지 반복한다.

## Topic 3. 핵심 수식과 원리

### 1. Relaxation (이완/갱신)

$$D[w] = \min(D[w], D[u] + W[u][w])$$

- **$D[w]$:** 시작점에서 $w$까지 가는 기존 최단 거리.
- **$D[u]$:** 시작점에서 $u$까지 가는 확정된 최단 거리.
- **$W[u][w]$:** $u$에서 $w$로 가는 간선의 가중치.
- **의미:** "지금까지 알고 있던 길보다, **새로 확정된 $u$를 거쳐서 가는 길**이 더 빠르다면 그 값으로 업데이트한다."
    

### 2. 주의사항

- **$S$ 집합의 의미:** $S$에 들어간 노드는 최단 거리가 **이미 확정**된 상태이다. 이후에는 그 값이 더 작아질 수 없다. (음수 간선이 없다는 전제하에)
- **무한대(INF) 처리:** 코드 구현 시 `INT_MAX` 등을 사용하여, 갱신 전에는 갈 수 없음을 명확히 해야 한다. `0`을 쓰면 안 된다.

## Topic 2. Floyd-Warshall 알고리즘 (All-Pairs Shortest Path)

### 1. 🏗️ 빌드업 (Concept)

> "다익스트라는 서울에서 출발하는 것만 안다. 플로이드는 전국의 모든 도시에서 출발하는 경로를 한 방에 안다."

- **목적:** 그래프 내의 **모든 정점 쌍(All Pairs)** 사이의 최단 경로를 구한다.
- **핵심 아이디어:** **거쳐가는 정점(경유지, $k$)**을 기준으로 최단 거리를 갱신한다.
    - "정점 $i$에서 $j$로 바로 가는 것보다, $k$를 거쳐서 가는 게 더 빠르면 갱신한다."
        

### 2. 점화식 (Recurrence Relation)

$$A^k[i][j] = \min(A^{k-1}[i][j], A^{k-1}[i][k] + A^{k-1}[k][j])$$

- $A^k[i][j]$: 정점 $0$부터 $k$까지만 경유지로 사용할 수 있을 때, $i$에서 $j$로 가는 최단 거리.
- **직관적 의미:** `Distance[i][j] = min(Distance[i][j], Distance[i][k] + Distance[k][j])`
    

### 3. 동작 원리 및 3중 반복문

C

```C
// k: 거쳐가는 노드 (경유지)
for (k = 0; k < n; k++) {
    // i: 출발 노드
    for (i = 0; i < n; i++) {
        // j: 도착 노드
        for (j = 0; j < n; j++) {
            if (adj[i][k] + adj[k][j] < adj[i][j]) {
                adj[i][j] = adj[i][k] + adj[k][j];
            }
        }
    }
}
```

- **시간 복잡도:** 3중 반복문이므로 **$O(N^3)$**이다. 정점 개수가 적을 때(약 500개 이하) 유용하다.

## Topic 3. Dijkstra vs Floyd-Warshall 비교

|**특징**|**Dijkstra (다익스트라)**|**Floyd-Warshall (플로이드-워셜)**|
|---|---|---|
|**목표**|**하나의 시작점** $\to$ 다른 모든 정점|**모든 정점** $\to$ 모든 정점|
|**핵심 로직**|가장 가까운 정점 선택 (Greedy)|경유지를 거쳐가는 경로 갱신 (DP)|
|**시간 복잡도**|$O(E \log V)$ (우선순위 큐)|$O(V^3)$|
|**음수 간선**|처리 불가|처리 가능 (단, 음수 사이클은 불가)|
|**구현 난이도**|중간 (힙 필요)|매우 쉬움 (3중 for문)|
|**적용 예시**|내비게이션 (출발지 고정)|전체 네트워크 경로 분석|

## Topic 4. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Application)

> "선수 과목(Prerequisite) 구조: C언어를 들어야 자료구조를 듣고, 그래야 알고리즘을 듣는다."

- **정의:** **방향성 그래프(DAG)**에서 간선으로 주어진 정점 간의 선후 관계를 위배하지 않도록 나열하는 것.
- **제약 조건:** **사이클(Cycle)**이 존재하면 위상 정렬을 수행할 수 없다. (닭이 먼저냐 알이 먼저냐 모순 발생)
    

### 2. 알고리즘 프로세스 (Indegree 방식)

1. **진입 차수(Indegree) 계산:** 모든 정점의 진입 차수(들어오는 간선 수)를 계산한다.
2. **큐 삽입:** 진입 차수가 **0**인(선행 조건이 없는) 정점을 모두 큐에 넣는다.
3. **반복:**
    
    - 큐에서 정점 $u$를 꺼내 출력한다 (정렬 결과 추가).
    - $u$에서 나가는 간선을 모두 제거한다 (연결된 정점 $v$의 진입 차수를 1 감소).
    - 새롭게 진입 차수가 0이 된 정점 $v$를 큐에 넣는다.
        
4. **종료:** 큐가 비었을 때 모든 정점을 방문했다면 정렬 성공, 못 했다면 사이클 존재.

2. **Dijkstra (One-to-All)**: **그리디(Greedy)** 전략을 사용하여 시작점으로부터 다른 모든 정점까지의 거리를 **갱신(Relaxation)**해 나가는 과정을 손으로 추적(Tracing)하며 학습했습니다.
3. **Floyd-Warshall (All-to-All)**: 다익스트라를 N번 반복하는 대신, **3중 반복문**을 통해 모든 정점 쌍 간의 최단 거리를 한 번에 구하는 **동적 계획법(DP)** 접근 방식을 다루었습니다.
4. **위상 정렬 (Topological Sort)**: 가중치나 경로가 아닌, **순서(Dependency)**가 있는 작업(예: 선수과목)을 정렬하는 방법을 학습했습니다. (진입 차수 0 제거 방식)
    

### 2) 강조포인트

- **개발자의 시야**: 단순히 코딩만 하는 것이 아니라, AI(Gemini 등)를 분석 도구로 활용하고 금융/제조업 등 다양한 도메인에서 시스템을 이해하는 개발자가 되어야 합니다.
- **다익스트라의 핵심**: **방문 확정 집합(S)**과 **거리 배열(Distance)**의 갱신 과정을 직접 시뮬레이션할 수 있어야 합니다. 특히 **`D[w] = min(D[w], D[u] + W[u][w])`**라는 갱신 공식이 핵심입니다.
- **알고리즘 선택 가이드**:
    - **1:N 경로** & **양수 가중치**: 다익스트라 (우선순위 큐 활용 시 희소 그래프에 유리).
    - **N:N 경로** & **구현 편의성**: 플로이드-워셜 ($O(N^3)$, 정점 개수가 적을 때).
    - **순서 정렬**: 위상 정렬 (사이클이 없어야 함).
- **기말고사 대비**: 중간 노드에서 시작하는 탐색 순서, 다익스트라의 단계별 갱신 값 추적 문제가 출제될 가능성이 높으므로 반드시 손으로 풀어보아야 합니다.

## Topic 4. 시간 복잡도 비교 예시 ($N \times N$)

### 1. 문제: 1부터 N까지 N번 더하기 (혹은 N * N 계산)

#### Case A: 곱셈 연산 활용 ($O(1)$)

C

```C
sum = n * n;
```

- **연산:** 대입 1회, 곱셈 1회 $\rightarrow$ 총 2회.
- **특징:** 입력 $N$이 1억이든 10억이든 연산 횟수는 **상수(Constant)**로 일정하다. 가장 효율적이다.
    

#### Case B: 단일 반복문 ($O(N)$)

C

```C
sum = 0;
for(i=0; i<n; i++) {
    sum += n;
}
```

- **연산:** $N$번 반복하며 덧셈 수행 $\rightarrow$ 약 $2N + \alpha$회.
- **특징:** 입력 $N$에 비례하여 시간이 선형적으로 증가한다.
    

#### Case C: 이중 반복문 ($O(N^2)$)

C

```C
sum = 0;
for(i=0; i<n; i++) {
    for(j=0; j<n; j++) {
        sum += 1;
    }
}
```

- **연산:** $N \times N$번 반복하며 1을 더함 $\rightarrow$ 약 $2N^2 + \alpha$회.
- **특징:** 입력 $N$이 커지면 실행 시간이 기하급수적으로 증가한다. (가장 비효율적)
    

### 2. 결론 (Big-O)

- $N$이 작을 때는 큰 차이가 없지만, $N$이 커질수록 **최고차항의 차수**가 성능을 지배한다.
- 따라서 상수항이나 계수를 무시하고 가장 큰 영향을 미치는 항만 표기하는 **Big-O 표기법**($O(1), O(N), O(N^2)$)을 사용한다.

## Topic 2. 시간 복잡도 (Time Complexity) 심화

### 1. Big-O 표기법 (상한, Upper Bound)

- **정의:** 입력 크기 $N$이 증가할 때, 연산 횟수의 증가 추세(Trend)를 나타내는 상한선.
- **계산 규칙:**
    
    1. **단일 반복문:** $O(N)$
    2. **중첩 반복문:** $O(N^2)$
    3. **분할 정복/이진 탐색:** $O(\log N)$
    4. **순차적 명령:** $O(f(n)) + O(g(n)) \rightarrow O(\max(f(n), g(n)))$ (가장 큰 항만 남김)
        

### 2. 주요 복잡도 비교 (작은 순서대로)

$$O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N) < O(N!)$$

- **$O(1)$:** 해시 테이블 조회, 배열 인덱스 접근.
- **$O(N \log N)$:** 퀵 정렬, 병합 정렬.
- **$O(N!)$:** 외판원 순회 문제(TSP) 등 (입력 크기가 작아도 계산 불가능 수준).

## Topic 3. 재귀(Recursion) vs 반복(Iteration)

### 1. 🏗️ 빌드업 (Comparison)

|**특징**|**재귀 (Recursion)**|**반복 (Iteration)**|
|---|---|---|
|**메모리 사용**|**비효율적** (스택 프레임 생성, Context Switching 오버헤드 발생)|**효율적** (추가 메모리 거의 없음)|

|**구현 난이도**|하노이 탑, 트리 순회 등에서 유리|피보나치 등에서 유리|

### 2. 메모리 구조 분석

- **반복문:** 데이터 영역(Data Segment)이나 힙(Heap)만 사용.
- **재귀 함수:** **시스템 스택(System Stack)** 영역을 사용.
    - 함수가 호출될 때마다 매개변수, 리턴 주소 등을 스택에 쌓아야 하므로, 깊이가 깊어지면 **스택 오버플로우(Stack Overflow)** 위험이 있다.

## Topic 4. 사례 연구 (Case Study)

### 1. 팩토리얼 (Factorial)

- **재귀:** $N! = N \times (N-1)!$ 점화식을 그대로 구현. ($O(N)$)
- **반복:** 1부터 N까지 곱함. ($O(N)$)
- **결론:** 시간 복잡도는 같으나, 재귀는 스택 오버헤드가 발생하므로 **반복이 더 효율적**일 수 있다.
    

### 2. 거듭제곱 ($x^n$) 계산

- **반복:** $x$를 $n$번 곱함 $\rightarrow O(N)$.
- **재귀 (분할 정복):**
    - $x^n = (x^{n/2})^2$ (짝수일 때)
    - $x^n = x \times (x^{(n-1)/2})^2$ (홀수일 때)
    - **시간 복잡도:** 문제 크기가 절반씩 줄어들으므로 **$O(\log N)$**.
- **결론:** 이 경우 **재귀(분할 정복)**가 반복보다 훨씬 빠르다.
    

### 3. 피보나치 수열 (Fibonacci)

- **재귀 (Naive):** $F(n) = F(n-1) + F(n-2)$
    - 중복 호출(Overlapping Subproblems)이 발생하여 **$O(2^N)$**의 지수 시간이 걸림. (비효율의 극치)
- **반복:** 0, 1부터 시작하여 $N$까지 순차적으로 계산. **$O(N)$**.
- **결론:** 피보나치는 절대 단순 재귀로 짜면 안 되며, **반복문**이나 **메모이제이션(Memoization)**을 써야 한다.

## Topic 1. 하노이 탑 (Hanoi Tower)

### 1. 🏗️ 빌드업 (Why & Context)

> "반복문(For)으로 짜려고 하면 머리 터진다. 재귀(Recursion)로 짜면 3줄이면 끝난다."

- **문제 정의:** 막대 A에 있는 $N$개의 원판을 막대 C로 옮겨라.
- **제약 조건:**
    
    1. 한 번에 하나의 원판만 옮길 수 있다.
    2. 큰 원판이 작은 원판 위에 올라갈 수 없다.
    3. 중간 막대(B)를 임시로 사용할 수 있다.
        

### 2. 논리적 분해 (Recursive Step)

$N$개의 원판을 A에서 C로 옮기려면, 가장 큰 원판(맨 밑)을 C로 옮겨야 한다. 이를 위해 위의 $N-1$개를 먼저 비켜줘야 한다.

1. **Step 1:** 맨 밑의 원판을 제외한 **나머지 $N-1$개 원판**을 A에서 **B(임시)**로 옮긴다.
2. **Step 2:** **가장 큰 원판(1개)**을 A에서 **C(목적지)**로 옮긴다.
3. **Step 3:** B에 두었던 **$N-1$개 원판**을 다시 **C(목적지)**로 옮긴다.
    

### 3. 알고리즘 구현 (Pseudo Code)

C

```C
// n: 원판 개수, from: 시작, temp: 보조, to: 목적지
void hanoi(int n, char from, char temp, char to) {
    if (n == 1) {
        // 원판이 1개면 바로 목적지로 이동
        move(from, to); 
    } else {
        // 1. N-1개를 A -> B로 이동 (C를 보조로 사용)
        hanoi(n - 1, from, to, temp);
        
        // 2. 가장 큰 원판을 A -> C로 이동
        move(from, to);
        
        // 3. N-1개를 B -> C로 이동 (A를 보조로 사용)
        hanoi(n - 1, temp, from, to);
    }
}
```

### 4. 복잡도 분석

- 점화식: $T(N) = 2T(N-1) + 1$
- 시간 복잡도: **$O(2^N)$**. 원판 하나 늘어날 때마다 이동 횟수가 2배씩 폭증한다. (반복문으로 구현하기 매우 난해함)

## Topic 2. 머신 스케줄링 (Job Scheduling)

### 1. 🏗️ 빌드업 (Optimization)

> "솜사탕 기계 2대가 있다. 피카츄(5분), 토끼(10분), 별(1분), 원(0.5분) 솜사탕 주문이 동시에 들어왔다. 어떻게 배분해야 가장 빨리 끝날까?"

- **목표:** $M$개의 기계(Machine)에 $N$개의 작업(Job)을 배정하여, 모든 작업이 끝나는 시간(Makespan)을 최소화하라.
- **알고리즘:** **LPT (Longest Processing Time first)** 방식 사용. (Greedy 기법)
    

### 2. LPT 알고리즘 (Greedy Approach)

1. **정렬:** 작업 시간이 **가장 긴 순서대로(내림차순)** 작업을 정렬한다. (8, 7, 6, 5…)
2. **배정:** 가장 먼저 끝나는(현재 부하가 가장 적은) 기계에 순서대로 작업을 배정한다.
3. **반복:** 모든 작업이 배정될 때까지 반복한다.
    

### 3. 구현 전략 (Min Heap 활용)

- 기계들의 현재 종료 시간을 관리하기 위해 **최소 힙(Min Heap)**을 사용하면 효율적이다.
    - 항상 Root(가장 빨리 끝나는 기계)를 꺼내서 작업을 할당하고 다시 넣는다.
