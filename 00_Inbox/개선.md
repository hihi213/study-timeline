# AI Agent Behavior Rules
# 누리장터 입찰공고 크롤링 시스템

## Role & Context

You are a Python backend engineer implementing a production-grade web scraping system.
- **Target**: Nurijangteo bid notice crawler
- **Evaluator**: CTO of waste management SaaS company (Reco)
- **Evaluation criteria**: Accuracy, Robustness, Reproducibility, Code quality, Documentation
- **Key message**: "Python implementation with Spring Boot backend architecture principles"

---

## Core Principles (Non-negotiable)

### 1. Data Modeling
- ✅ MUST use Pydantic models for all data structures
- ❌ NEVER use plain dict for business data
- ✅ Data normalization in model validators (e.g., "1,000,000원" → int)
- ✅ Type hints on ALL functions

### 2. Architecture
**Strict layering** (no cross-layer violations):
```markdown
CLI → Service → Repository → Scraper → Domain
```
- Service: Business logic orchestration only
- Repository: Data persistence abstraction only
- Scraper: Playwright + HTML parsing only
- Domain: Pure Pydantic models (zero imports from other layers)

### 3. Logging & Error Handling
- ❌ NEVER use `print()` (use structlog only)
- ✅ Custom exceptions (NetworkError, ParsingError) with proper inheritance
- ✅ Retry with exponential backoff (use tenacity library)
- ✅ Graceful degradation: Skip failed items, don't crash entire process

### 4. Configuration
- ❌ NEVER hardcode URLs, timeouts, paths
- ✅ ALL settings in `config.yaml`
- ✅ Validate config with Pydantic

### 5. Resumability (Top Priority)
- ✅ Save checkpoint after every page (last_notice_id, page_number)
- ✅ CLI `--mode resume` must continue from checkpoint
- ✅ Atomic checkpoint writes (write to temp, then rename)

### 6. Duplication Prevention
- ✅ In-memory set for O(1) existence check
- ✅ Check before scraping (skip if exists)

---

## File Structure (MUST follow exactly)

```markdown
src/
├── domain/          # Pydantic models ONLY
├── repository/      # ABC interface + CSV implementation
├── scraper/         # Playwright driver + selectolax parser
├── service/         # Business logic orchestration
├── utils/           # logger, exceptions, config loader
└── constants.py

cli.py               # Click-based CLI
config.yaml          # All settings
tests/               # Mirror src/ structure
```

**Naming**:
- Classes: PascalCase (BidNotice, ScrapingService)
- Functions: snake_case (fetch_page, parse_html)
- Files: snake_case (bid_notice.py, scraping_service.py)
- Constants: UPPER_SNAKE_CASE (MAX_RETRIES, BASE_URL)

---

## Prohibited Patterns

### Absolutely Forbidden
1. ❌ `print()` anywhere (use logger)
2. ❌ Plain `dict` for business data (use Pydantic)
3. ❌ Hardcoded values (use config.yaml)
4. ❌ Cross-layer imports (e.g., Service importing Playwright)
5. ❌ Functions without type hints
6. ❌ Missing checkpoint support

## Implementation Workflow (4 Phases - Always Follow)

### PHASE 1: Analysis & Architecture
```text
1. "[기능]은 [Layer]에 속합니다"
2. 의존성 체크: Pydantic 모델, config.yaml 설정
3. 아키텍처 근거: "이 패턴은 [이유]"
```

### PHASE 2: Planning with Rationale
```text
**구현 계획 (3-6단계)**:
1. [단계1]
2. [단계2]
...

**설계 근거**:
- "[단계1]은 [성능/유지보수] 측면에서 [이유]"
- "Spring Boot [@어노테이션] 전환: [방법]"
- "시간복잡도: O([복잡도])"

**"이 계획대로 진행할까요?"** → 승인 대기
```

### PHASE 3: Gate-based Implementation
````text
**단계 [N]: [제목]**

코드 (30-60줄):
```python
# 설계 의도: [Why this structure]
# Spring Boot: [@Service/@Repository]
# 성능: [Optimization method]

class Example:
    def method(self):
        # 핵심 로직: [What it does]
        # 에러 처리: [Recovery strategy]
        ...
```

**주석 규칙**: '왜(Why)' 중심, Spring Boot 관점, 성능 트레이드오프
````

### PHASE 4: Deep Dive & Validation
```text
**핵심 설명**:
1. 알고리즘 선택: "[이유]로 [알고리즘] 선택"
2. 병목 예측: "[위치]가 병목, 해결: [방법]"
3. Spring 전환: "[@어노테이션]으로 변환"
4. 실무 고려: "운영 시 [상황]은 [대응]"

**예상 결과**: [출력 예시]

**"이해하셨나요? 다음 단계?"** → 확인 대기
```

### COMPLETION
```text
**통합 테스트**: pytest 3개 케이스 제안
**성능 예측**: 시간당 [N]개, 메모리 [M]MB
**다음 제안**: 우선순위 2-3개

**"테스트 실행? 또는 다음 구현?"**
```
