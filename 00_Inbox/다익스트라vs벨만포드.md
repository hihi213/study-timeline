## 정리

요청하신 형식에 맞춰, **특정 시작 정점(Source)**에서 **특정 도착 정점(Destination)**까지의 최단 거리와 경로를 구하는 다익스트라 알고리즘을 설명해 드리겠습니다.

전체 정점을 구하는 방식과 로직은 동일하지만, **'목표 도달 시 조기 종료'**와 **'경로 추적'** 과정이 추가되는 것이 핵심 차이점입니다.

---

### 1. 정의 및 전제 조건

- **정의**: 음의 가중치가 없는 그래프에서, **특정 시작 정점**으로부터 **특정 도착 정점**까지의 최단 거리 및 그 이동 경로를 구하는 알고리즘입니다.
    
- **주체 (Subject)**: 다익스트라 알고리즘 (컴퓨터 연산 과정).
    
- **대상 (Object)**:
    
    - **정점 ($V$)**: 위치. (시작 정점 $S$, 도착 정점 $D$)
        
    - **최단 거리 테이블 (Distance Table)**: $S$로부터의 거리를 기록.
        
    - **우선순위 큐 (Priority Queue)**: 방문 후보 관리.
        
    - **이전 정점 목록 (Predecessor/Parent Map)**: 경로 복원을 위해 **'어디서 왔는지'**를 기록하는 배열 또는 해시맵.
        

---

### 2. 단계별 상세 과정 (Step-by-Step)

#### 1단계: 초기화 (Initialization)

- **주체**: 알고리즘
    
- **행동**:
    
    1. **최단 거리 테이블**의 모든 값을 '무한대($\infty$)'로, **이전 정점 목록**을 '비음(Null)'으로 설정합니다.
        
    2. **시작 정점($S$)**의 거리 값을 `0`으로 설정합니다.
        
    3. **시작 정점($S$)**과 거리(`0`)를 **우선순위 큐**에 삽입합니다.
        

#### 2단계: 최단 거리 정점 선택 및 목표 확인 (Selection & Check)

- **주체**: 알고리즘
    
- **행동**:
    
    1. **우선순위 큐**에서 거리가 가장 짧은 정점(이하 **현재 정점**)을 추출합니다.
        
    2. **[핵심] 목표 도달 검사**: 만약 추출된 **현재 정점**이 **도착 정점($D$)**과 일치한다면, 최단 거리가 확정되었으므로 탐색 루프를 **즉시 종료**합니다.
        
    3. **유효성 검증**: (도착점이 아니라면) 추출된 거리가 **최단 거리 테이블**의 기록보다 큰 경우 무시(Skip)합니다.
        

#### 3단계: 인접 정점 탐색 및 거리 계산 (Relaxation)

- **주체**: 알고리즘 (현재 정점 기준)
    
- **행동**:
    
    1. **현재 정점**의 인접 정점들을 확인합니다.
        
    2. 이동 비용을 계산합니다: `새로운 거리` = `현재 정점까지의 누적 거리` + `간선 가중치`
        

#### 4단계: 거리 갱신 및 경로 기록 (Update & Record)

- **주체**: 알고리즘
    
- **행동**:
    
    1. `새로운 거리` < `인접 정점의 기존 거리` 인 경우:
        
        - **최단 거리 테이블**을 갱신합니다.
            
        - **[핵심] 이전 정점 목록 갱신**: 인접 정점의 부모(직전 방문 노드)를 **현재 정점**으로 기록합니다. (경로 추적용)
            
        - 갱신된 정보를 **우선순위 큐**에 삽입합니다.
            

#### 5단계: 경로 역추적 (Path Reconstruction)

- **주체**: 알고리즘 (탐색 종료 후)
    
- **행동**:
    
    1. **도착 정점($D$)**에서 시작하여 **이전 정점 목록**을 참조해 **시작 정점($S$)**이 나올 때까지 거슬러 올라갑니다(Backtracking).
        
    2. 역추적된 정점들의 순서를 뒤집으면(Reverse), $S$에서 $D$까지의 **최단 경로**가 완성됩니다.
        

---

### 3. 핵심 요약

특정 구간 다익스트라의 핵심은 **"우선순위 큐에서 도착 정점($D$)이 나오는 순간이 해당 정점까지의 최단 거리가 확정되는 시점이므로 연산을 멈추는 것(Pruning)"**과 **"갱신이 일어날 때마다 어디서 왔는지를 기록하여 최종 경로를 복원하는 것"**입니다.
요청하신 형식에 맞춰, **특정 시작 정점(Source)**에서 **특정 도착 정점(Destination)**까지의 최단 거리와 경로를 구하는 벨만-포드 알고리즘을 설명해 드리겠습니다.

다익스트라와 달리, 특정 정점이 목표라 하더라도 **음의 가중치** 가능성 때문에 **연산을 조기에 종료할 수 없다**는 점이 가장 결정적인 차이입니다.

---

### 1. 정의 및 전제 조건

- **정의**: 음의 가중치가 포함된 그래프에서, **특정 시작 정점**으로부터 **특정 도착 정점**까지의 최단 거리 및 그 이동 경로를 구하는 알고리즘입니다.
    
- **주체 (Subject)**: 벨만-포드 알고리즘 (컴퓨터 연산 과정).
    
- **대상 (Object)**:
    
    - **정점 ($V$)**: 위치. (시작 정점 $S$, 도착 정점 $D$)
        
    - **간선 ($E$)**: 모든 연결 선.
        
    - **최단 거리 테이블 (Distance Table)**: $S$로부터의 거리를 기록.
        
    - **직전 정점 목록 (Predecessor Map)**: 경로 복원을 위해 **'어디서 왔는지'**를 기록하는 배열.
        

---

### 2. 단계별 상세 과정 (Step-by-Step)

#### 1단계: 초기화 (Initialization)

- **주체**: 알고리즘
    
- **행동**:
    
    1. **최단 거리 테이블**의 모든 값을 '무한대($\infty$)'로, **직전 정점 목록**을 '비음(Null)'으로 설정합니다.
        
    2. **시작 정점($S$)**의 거리 값을 `0`으로 설정합니다.
        

#### 2단계: 간선 완화 반복 (Edge Relaxation Loop)

- **주체**: 알고리즘
    
- **대상**: 그래프 내의 **모든 간선 ($E$개)**
    
- **행동**:
    
    1. 전체 간선을 하나씩 확인하며 거리 갱신을 시도합니다.
        
    2. **검증**: `출발점까지의 거리` + `간선 가중치`가 `도착점의 기존 거리`보다 작은지 확인합니다.
        
    3. **갱신 및 기록**: 작다면,
        
        - **최단 거리 테이블**의 값을 `새로운 거리`로 갱신합니다.
            
        - **[핵심] 직전 정점 목록 갱신**: 해당 도착점의 부모(직전 방문 노드)를 **현재 간선의 출발점**으로 기록합니다.
            
- **반복 횟수**: 위 과정을 **($V$ - 1)**번 반복합니다.
    
    - **주의**: 특정 도착 정점($D$)의 거리가 갱신되었다 하더라도, 다른 곳에 존재하는 음수 간선이 추후에 더 짧은 경로를 만들어낼 수 있으므로 **루프를 중단하지 않고 끝까지 수행**해야 합니다.
        

#### 3단계: 음수 사이클 탐지 (Negative Cycle Detection)

- **주체**: 알고리즘
    
- **대상**: 그래프 내의 **모든 간선 ($E$개)**
    
- **행동**:
    
    1. 모든 간선에 대해 한 번 더 완화 과정을 시도합니다.
        
    2. **판단**: 만약 값이 더 줄어드는 갱신이 발생한다면, **음수 사이클**이 존재하므로 최단 경로 산출이 불가능함을 알리고 종료합니다.
        

#### 4단계: 경로 역추적 (Path Reconstruction)

- **주체**: 알고리즘 (음수 사이클이 없는 경우)
    
- **행동**:
    
    1. **도착 정점($D$)**에서 시작하여 **직전 정점 목록**을 참조해 **시작 정점($S$)**이 나올 때까지 거슬러 올라갑니다(Backtracking).
        
    2. 이 과정에서 경로가 끊겨있다면(직전 정점이 Null 등) 도달 불가능한 경우입니다.
        
    3. 역추적된 정점들을 뒤집어(Reverse) 최종 경로를 완성합니다.
        

---

### 3. 핵심 요약

특정 구간을 구하는 벨만-포드의 핵심은 **"특정 목적지가 있더라도 음수 간선의 변수 때문에 전체 그래프를 ($V-1$)번 모두 훑어야만 최단 거리가 보장된다는 점(No Early Exit)"**과, **"갱신이 일어날 때마다 직전 정점을 기록하여 마지막에 역추적하는 것"**입니다.


결론부터 말씀드리면, **그래프에 '음수 간선(마이너스 비용)'이 있느냐 없느냐**에 따라 결과물의 차이가 발생합니다.

결과물의 **형태**는 둘 다 **'최단 거리 테이블(1차원 배열)'**로 똑같지만, 그 안에 적히는 **값(숫자)**의 정확도가 달라집니다.

---

### 1. 양수 간선만 있는 경우 (일반적인 그래프)

**결과물 차이: 없음 (100% 동일)**

두 알고리즘 모두 수학적으로 완벽하게 최단 경로를 찾아냅니다.

- **다익스트라:** 빠르게 정답 도출.
    
- **벨만-포드:** 느리게 (여러 번 확인해서) 정답 도출.
    
- **비유 없는 설명:**
    
    - 서울에서 부산 가는 길을 찾는데, 다익스트라는 "KTX 직통"을 바로 찾았고, 벨만-포드는 "국도, 고속도로 다 뒤져보고 KTX가 제일 빠르네"라고 결론 내렸습니다. 결국 답은 같습니다.
        

---

### 2. 음수 간선이 있는 경우 (특수한 그래프)

**결과물 차이: 있음 (다익스트라는 오답, 벨만-포드는 정답)**

여기서 결과가 갈립니다. 다익스트라는 '한 번 확정하면 끝'이라는 성질 때문에 뒤늦게 등장하는 마이너스 비용을 반영하지 못해 **틀린 값**을 내놓습니다.

**[예시 상황]**

- A → B (비용 10)
    
- A → C (비용 50)
    
- C → B (비용 -45) _핵심: C를 거쳐서 B로 가면 50 - 45 = 5가 됨._
    

**[알고리즘별 결과물 비교]**

**A. 다익스트라의 결과물 (오답)**

1. A에서 갈 수 있는 B(10)와 C(50) 중 **B(10)**이 더 작네?
    
2. **B의 최단 거리는 10으로 확정!** (방문 완료 처리)
    
3. C(50)를 나중에 방문해서 C → B(-45)를 발견함.
    
4. 하지만 B는 이미 확정됐으므로 **갱신 안 함.**
    
5. **최종 결과:** B까지 거리 = **10** (틀림)
    

**B. 벨만-포드의 결과물 (정답)**

1. 모든 간선을 다 확인해서 일단 B=10, C=50으로 적어둠.
    
2. 다음 라운드에 또 모든 간선을 확인하다가 C → B(-45)를 발견.
    
3. "어? C 거쳐서 가면 50 - 45 = 5네? 아까 적은 10보다 작네?"
    
4. **B의 값을 5로 갱신.**
    
5. **최종 결과:** B까지 거리 = **5** (정답)
    

---

### 3. 음수 순환(Cycle)이 있는 경우

**결과물 차이: 있음 (다익스트라는 엉뚱한 값, 벨만-포드는 에러 메시지)**

계속 돌면 비용이 무한히 줄어드는 '블랙홀' 같은 구간이 있을 때입니다.

- **다익스트라:**
    
    - 순환에 빠져 무한 루프를 돌거나, 말도 안 되는 작은 값(오버플로우)을 결과로 내놓고 끝납니다. (통제 불능)
        
- **벨만-포드:**
    
    - "이 그래프는 문제가 있습니다(Negative Cycle Detected)"라는 **에러 메시지(False)**를 결과물로 줍니다. (통제 가능)

| ------------- | --------------- | --------------- | ------------------ |
| **양수 간선만 있음** | `[0, 10, 3, 5]` | `[0, 10, 3, 5]` | **동일 (둘 다 정답)**    |
| **음수 간선 있음**  | `[0, 10, 3, 5]` | `[0, 5, 3, 5]`  | **다름 (벨만-포드만 정답)** |
| **음수 순환 있음**  | (엉뚱한 값 or 멈춤)   | `Error: 순환 감지`  | **다름 (벨만-포드만 감지)** |
|               |                 |                 |                    |

결론:

일반적인 네비게이션(거리=양수)에서는 결과물이 똑같으므로 더 빠른 다익스트라를 쓰고, 타임머신이나 금융 차익거래(비용=음수 가능) 같은 특수 상황에서는 느려도 정확한 벨만-포드를 씁니다.
네, 정확합니다. 두 알고리즘은 **입력 데이터(그래프)**와 **출력 데이터(최단 거리 테이블)**가 같기 때문에 코드의 뼈대는 동일하지만, **'최단 거리를 확정 짓는 반복문의 논리'**가 완전히 다릅니다.

C언어로 구현했을 때의 **[공통 부분]**과 **[차이 부분]**을 대조하여 설명해 드리겠습니다.

### 1. 전체 구조 비교

|**구분**|**다익스트라 (Dijkstra)**|**벨만-포드 (Bellman-Ford)**|
|---|---|---|
|**준비물 (대상)**|`dist[]` (거리표), **`visited[]` (방문표)**|`dist[]` (거리표) (**방문표 없음**)|
|**반복 횟수**|노드 개수(V)만큼 반복|노드 개수 - 1 (V-1)번 반복|
|**핵심 로직**|**가장 가까운 노드 1개** 골라서 주변 갱신|**모든 간선**을 무조건 전부 확인해서 갱신|

### 2. 코드 대조 (핵심 로직)

두 코드 모두 `graph[5][5]`라는 인접 행렬을 사용한다고 가정합니다.

#### [공통 부분] 1. 초기화 (Initialization)

**주체(알고리즘)**가 **대상(거리 테이블)**을 준비하는 과정은 100% 동일합니다.



```C
#define INF 1000000
int dist[V]; // 최단 거리 테이블

// 공통: 시작점은 0, 나머지는 무한대로 초기화
for (int i = 0; i < V; i++) {
    dist[i] = INF;
}
dist[start_node] = 0;
```

---

#### [차이 부분] 2. 메인 반복문 (The Engine)

여기서 알고리즘의 성격이 갈립니다.

**A. 다익스트라 구현 (Greedy)**

- **특징:** `visited` 배열을 사용하여 **"한 번 방문하면 끝(확정)"**이라는 논리를 적용합니다.
    

C

```C
int visited[V] = {0}; // 방문 여부 체크 배열 (벨만포드엔 없음)

for (int i = 0; i < V; i++) {
    // [차이점 1] "방문하지 않은 노드 중" 가장 거리가 짧은 노드(u) 선택
    int u = get_smallest_node(dist, visited); 
    
    visited[u] = 1; // [차이점 2] 방문 '확정' 처리 (다시는 안 봄)

    // [차이점 3] 선택된 노드(u)와 연결된 간선만 확인
    for (int v = 0; v < V; v++) {
        if (graph[u][v] != INF) {
            // 갱신 로직 (Relaxation)
            if (dist[u] + graph[u][v] < dist[v]) {
                dist[v] = dist[u] + graph[u][v];
            }
        }
    }
}
```

**B. 벨만-포드 구현 (Brute Force)**

- **특징:** `visited` 없이 횟수(`V-1`)를 채울 때까지 **"계속 다시 확인"**합니다.
    

C

```C
// 방문 여부 배열 없음

// [차이점 1] 전체 노드 개수 - 1 만큼 반복 (라운드 진행)
for (int k = 0; k < V - 1; k++) {
    
    // [차이점 2] 별도의 선택 과정 없이 "모든 간선"을 다 확인
    // (인접 행렬의 모든 칸을 훑음)
    for (int u = 0; u < V; u++) {
        for (int v = 0; v < V; v++) {
            
            if (graph[u][v] != INF && dist[u] != INF) {
                // [공통 로직] 갱신 로직 자체는 동일함
                if (dist[u] + graph[u][v] < dist[v]) {
                    dist[v] = dist[u] + graph[u][v]; 
                    // [차이점 3] 확정 짓지 않고 값만 바꿈 (다음 라운드에 또 바뀔 수 있음)
                }
            }
        }
    }
}
```

---

### 3. 단계별 상세 설명

#### 1) 대상을 고르는 방식

- **다익스트라:** `get_smallest_node()` 함수가 필요합니다.
    
    - "지금 내가 모르는 애들 중에 제일 유망한 놈 누구야?"라고 묻습니다.
        
    - **비용:** 매번 최소값을 찾아야 하므로 탐색 비용이 듭니다.
        
- **벨만-포드:** 선택 함수가 필요 없습니다.
    
    - "그냥 있는 거 다 가져와."라며 2중 for문(`u`, `v`)으로 모든 연결선을 긁어옵니다.
        

#### 2) 값을 대하는 태도 (확정 vs 임시)

- **다익스트라:** `visited[u] = 1;`
    
    - "너는 이제 계산 끝났어. 최솟값 확정이야. 다신 보지 말자."
        
- **벨만-포드:** 확정 코드가 없습니다.
    
    - "일단 줄어들었네? 기록해둬. 근데 다음 라운드에 더 좋은 길 나오면 또 바꿔줄게."
        

#### 3) 갱신 공식 (Relaxation) - **[공통]**

재미있는 점은, 값을 갱신하는 수식 자체는 두 알고리즘이 똑같습니다.

C

```C
if (dist[u] + weight < dist[v]) {
    dist[v] = dist[u] + weight;
}
```

- **의미:** "지금 알고 있는 `v`까지의 거리보다, `u`를 거쳐서 가는 게 더 빠르면 갱신해라."
    
- 이 핵심 로직은 **모든 최단 경로 알고리즘의 공통 분모**입니다. 단지 이 코드를 **"언제, 얼마나 자주 실행하느냐"**의 차이일 뿐입니다.
    

### 요약

C언어로 구현할 때 가장 큰 차이는 **`visited` 배열의 유무**와 **반복문의 구조(선택적 탐색 vs 전체 반복 탐색)**입니다.

네, 가장 명확한 차이를 보여드리기 위해 **'음수 간선'이 포함된 그래프**를 예시로 `dist[]` 배열의 변화를 순차적으로 대조해 보겠습니다.

**양수 간선만 있는 경우**는 두 알고리즘의 `dist[]` 갱신 순서가 거의 비슷하여 차이가 잘 안 보이지만, **음수 간선**이 끼어들면 **주체(알고리즘)**가 **대상(dist 배열)**을 다루는 방식의 결정적 차이가 드러납니다.

---

### 1. 예시 시나리오 설정

**그래프 상황 (A → B로 가는 길)**

1. **A → B** (비용: **10**) : 직통 경로 (하지만 멉니다)
    
2. **A → C** (비용: **50**) : 돌아가는 길
    
3. **C → B** (비용: **-45**) : **핵심 함정** (C를 거치면 비용이 대폭 감소)
    

- **정답:** A → C → B = $50 + (-45)$ = **5**
    
- **오답:** A → B = **10**
    

---

### 2. `dist[]` 배열 변화 대조 (순차 진행)

- 배열 순서: `[ A, B, C ]`
    
- 초기 상태: `[ 0, ∞, ∞ ]`
    

|**단계**|**다익스트라 (Dijkstra)**|**벨만-포드 (Bellman-Ford)**|**설명 (차이점)**|
|---|---|---|---|
|**Step 1**<br><br>  <br><br>(시작점 처리)|**`dist`: [ 0, 10, 50 ]**<br><br>  <br><br>• A에서 갈 수 있는 B(10), C(50) 갱신.<br><br>  <br><br>• **방문리스트:** `{A}`|**`dist`: [ 0, 10, 50 ]**<br><br>  <br><br>• Round 1에서 모든 간선을 확인하여 갱신함.<br><br>  <br><br>• (아직은 똑같음)|초반 탐색은 두 알고리즘 모두 연결된 곳을 갱신하므로 결과가 같습니다.|
|**Step 2**<br><br>  <br><br>(선택의 순간)|**주체:** "B(10)가 C(50)보다 작네?"<br><br>  <br><br>**행동:** **B를 방문 확정(Finished) 처리.**<br><br>  <br><br>• **방문리스트:** `{A, B}`|**주체:** "Round 2 시작. 다시 모든 간선 확인."<br><br>  <br><br>**행동:** 확정 짓지 않고 다시 계산 준비.|**[결정적 차이]**<br><br>  <br><br>다익스트라는 **B=10**을 **최종값**으로 못 박아버립니다. (더 줄어들 리 없다고 판단)|
|**Step 3**<br><br>  <br><br>(함정 발견)|**주체:** 남은 C(50) 선택.<br><br>  <br><br>**행동:** C에서 B로 가는 간선(-45) 발견.<br><br>  <br><br>• 계산: $50 + (-45) = 5$<br><br>  <br><br>• 비교: 현재 B(10) > 5|**주체:** C → B 간선 확인.<br><br>  <br><br>**행동:**<br><br>  <br><br>• 계산: $50 + (-45) = 5$<br><br>  <br><br>• 비교: 현재 B(10) > 5|여기서 C를 통해 B로 가는 '더 빠른 길(지름길)'을 둘 다 발견합니다.|
|**Step 4**<br><br>  <br><br>(갱신 여부)|**`dist`: [ 0, 10, 50 ]** (변화 없음)<br><br>  <br><br>**이유:** B는 이미 **Step 2에서 방문 확정**되었음.<br><br>  <br><br>• **주체:** "이미 확정된 놈은 건드리지 않는다."<br><br>  <br><br>• 결과: **10 (오답)**|**`dist`: [ 0, 5, 50 ]** (갱신됨)<br><br>  <br><br>**이유:** 방문 확정 개념이 없음.<br><br>  <br><br>• **주체:** "어? 더 작네? 그럼 바꿔야지."<br><br>  <br><br>• 결과: **5 (정답)**|**다익스트라의 실패.**<br><br>  <br><br>이미 닫힌 문(Visited)을 열지 않습니다.<br><br>  <br><br>**벨만-포드의 성공.**<br><br>  <br><br>언제든 값을 고쳐 씁니다.|

---

### 3. 코드 레벨에서의 `dist[]` 접근 차이

C언어 코드로 보면 이 차이가 `if`문 하나에서 갈립니다.

#### A. 다익스트라의 시선

C

```C
// B 노드를 꺼내옴 (비용 10)
if (visited[B]) continue; // [차단] "너 이미 확정됐잖아. 돌아가."

visited[B] = 1; // 도장 쾅!
// 이후 C를 통해 B가 5가 되는 경로가 발견되어도, 
// 위 visited 체크 때문에 B를 갱신하는 로직에 도달하지 못하거나 무시함.
```

#### B. 벨만-포드의 시선

C

```C
// Round 2 루프 중…
// C -> B 간선을 확인 (-45)

// [허용] 방문 여부 묻지도 따지지도 않음
if (dist[C] + (-45) < dist[B]) {
    dist[B] = 5; // "어? 더 싸네? 갱신!"
}
```

### 4. 요약

- **다익스트라의 `dist[]`:** 한 번 값이 확정(방문 처리)되면, 그 값은 **상수(Constant)**처럼 취급되어 절대 변하지 않습니다. (그래서 뒤늦게 온 음수 간선이 무시됨)
    
- **벨만-포드의 `dist[]`:** 알고리즘이 끝날 때까지 계속 지웠다 썼다 할 수 있는 **변수(Variable)** 취급을 받습니다. (그래서 음수 간선 반영 가능)
