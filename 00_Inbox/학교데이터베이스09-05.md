## **2025-09-05, 1교시 — 개선본**

데이터베이스 설계의 기초가 되는 과학적 모델링(Scientific Modeling) 개념부터 시작하겠습니다. 데이터베이스 설계는 데이터를 어떻게 잘 구조화할 것인지 다루며, 이는 개념적, 논리적, 물리적 설계 단계를 따릅니다. 이 단계들을 이해하기 위해 먼저 과학적 모델링의 원리를 살펴보겠습니다.

과학적 모델링이란 현실 세계(real-world)의 복잡한 문제를 여러 단계를 거쳐 해결하는 방식입니다. 간단한 예로, 주어진 문제 상황에서 불필요한 정보(예: 버스 번호, 가게 이름)를 제거하고 문제 해결에 필요한 핵심 요소(예: 사과 5개, 바나나 5개, 파인애플 5개, 먹은 사과 3개)만 추출하는 과정이 포함됩니다. 이처럼 문제의 본질만 남기는 과정을 추상화(abstraction)라고 합니다. 공학에서 추상화는 핵심만 정확히 추출하는 것을 의미합니다.

추상화된 문제는 최종적으로 수학적 모델로 변환하여 해결합니다. 이 수학적 결과를 다시 원래 문제의 맥락에 맞게 해석(interpretation)하여 최종 답을 도출합니다.

문제가 복잡할 경우, 현실 세계의 문제를 바로 수학적 형태인 물리적 단계(physical level)로 변환하기 어렵습니다. 따라서 중간 단계들을 추가하는데, 이것이 바로 개념적 단계(conceptual level)와 논리적 단계(logical level)입니다.

1.  **개념적 단계 (Conceptual Level)**: 현실 문제를 사람이 이해하기 쉬운 표, 그림, 모형 등으로 정리하는 단계입니다. 여전히 자연어 기반의 설명이 많아 비전문가도 이해할 수 있습니다.
2.  **논리적 단계 (Logical Level)**: 개념 모델을 보다 수학에 가까운 형태로 변환하는 단계입니다. 아직 완전한 수식은 아니지만, 특정 교육을 받은 사람만 이해할 수 있는 정형화된 표현이 사용됩니다.
3.  **물리적 단계 (Physical Level)**: 완전한 수학적, 형식적(formal) 모델로 표현되는 단계입니다. 컴퓨터 공학에서는 하드웨어나 운영체제의 자원까지 고려하는 실제 구현 단계에 해당합니다.

이 세 가지 모델링 단계(개념적 → 논리적 → 물리적)는 데이터베이스 설계 과정에 그대로 적용됩니다. 데이터베이스 설계의 목표는 데이터 검색(`SELECT`), 삽입(`INSERT`), 삭제(`DELETE`), 수정(`UPDATE`) 연산의 성능을 극대화하도록 데이터를 조직화하는 것입니다.

* **개념적 설계**: 이 단계의 산출물은 **ERD (Entity-Relationship Diagram)**입니다. ERD는 데이터의 주요 요소(entity)와 그들 간의 관계(relationship)를 그림으로 표현하여 사람이 이해하기 쉽게 만듭니다.
* **논리적 설계**: ERD를 컴퓨터가 처리할 수 있는 논리적 구조로 변환하며, 그 결과물이 바로 **관계형 모델(Relational Model)**입니다. 관계형 모델은 모든 데이터를 `relation`, 즉 수학 용어인 표(table) 형태로 표현합니다. 현재 사용되는 대부분의 데이터베이스는 관계형 데이터베이스입니다.
* **물리적 설계**: 관계형 모델을 실제 DBMS(Database Management System)에 저장하는 방법을 다룹니다. 이 단계는 대부분 DBMS가 자동으로 처리하므로, 설계자는 주로 개념적, 논리적 설계에 집중합니다.

최종적으로 설계된 모델은 `SQL`이라는 언어를 통해 DBMS와 소통하며 데이터를 입력하고 관리하게 됩니다. `SQL`은 파이썬과 같은 범용 프로그래밍 언어보다 훨씬 간단하며, 핵심적인 몇 가지 명령어(`SELECT`, `INSERT` 등)만 알면 충분합니다.

참고로, 데이터베이스 시스템(DBS)은 DBMS와 실제 데이터(DB)의 조합으로 구성됩니다. DBMS는 `MySQL`, `Oracle`, `PostgreSQL`과 같은 데이터 관리 소프트웨어 패키지를 의미하며, DB는 이 시스템 위에서 관리되는 설계된 데이터 자체를 뜻합니다. 여러분은 앞으로 각자 주변의 데이터를 조직화하는 문제를 찾아 데이터베이스를 직접 설계하고 구축하는 과제를 수행하게 될 것입니다. (실습)

## **2025-09-05, 1교시 — 개념**

1. **한 줄 요약**
데이터베이스 설계는 현실 세계의 문제를 개념적(ERD), 논리적(관계 모델), 물리적(DBMS 구현) 단계로 변환하는 '과학적 모델링' 과정이며, 핵심은 문제의 본질을 추출하는 '추상화'입니다.

---

1. **핵심 TL;DR**
* **설계의 흐름**: 데이터베이스 설계는 **과학적 모델링** 절차(현실 세계 → 개념 → 논리 → 물리)를 따릅니다.
* **추상화의 역할**: 문제의 핵심만 남기고 불필요한 세부사항을 제거하는 과정이 설계의 첫걸음입니다.
* **개념 단계**: 사람이 이해하기 쉬운 **ERD(Entity-Relationship Diagram)**를 통해 데이터의 구조를 그림으로 나타냅니다.
* **논리 단계**: ERD를 컴퓨터가 이해할 수 있는 정형화된 **관계형 모델(Relational Model)**, 즉 표(Table)의 집합으로 변환합니다.
* **물리 단계**: 실제 데이터를 디스크에 어떻게 저장하고 접근할지를 다루며, 이 부분은 대부분 **DBMS**가 담당합니다.
* **설계 목표**: 데이터의 삽입, 수정, 삭제, 검색(`INSERT`, `UPDATE`, `DELETE`, `SELECT`) 연산을 효율적으로 수행하는 구조를 만드는 것입니다.
* **'관계(Relation)'의 의미**: 관계형 모델에서 '관계'는 사람 사이의 '관계(Relationship)'가 아닌, 수학적 용어인 **'표(Table)'**를 의미합니다.
* **SQL의 위치**: `SQL`은 설계된 논리적 모델(표)을 DBMS에 생성하고 조작하기 위해 사용하는 표준 언어입니다.
* **시스템 구성**: 데이터베이스 시스템(DBS)은 데이터를 관리하는 소프트웨어(**DBMS**)와 실제 데이터의 집합(**DB**)으로 구성됩니다.

---

1. **표현 = 표준 용어**
* **Scientific Modeling (과학적 모델링)**: 현실의 복잡한 문제를 단계별로 단순화, 정형화하여 해결하는 접근법.
* **Abstraction (추상화)**: 문제 해결에 필요한 핵심 요소만 식별하고 나머지는 생략하는 과정.
* **Conceptual Model (개념 모델)**: 데이터베이스의 전체적인 논리적 구조를 사용자가 이해하기 쉽게 표현한 상위 수준의 모델. (예: `ERD`).
* **Logical Model (논리 모델)**: 개념 모델을 특정 DBMS에 독립적인 논리적 데이터 구조로 변환한 모델. (예: `Relational Model`).
* **Physical Model (물리 모델)**: 데이터가 실제 저장장치에 저장되는 방식과 접근 경로를 정의하는 하위 수준의 모델.
* **ERD (Entity-Relationship Diagram)**: 데이터(Entity), 속성(Attribute), 관계(Relationship)를 이용해 현실 세계를 개념적으로 표현하는 다이어그램.
* **Relational Model (관계형 모델)**: 모든 데이터를 2차원 표(`Relation`)의 집합으로 표현하는 논리 모델.
* **Relation (릴레이션)**: 관계형 모델의 기본 구성 요소로, 행(Tuple)과 열(Attribute)으로 구성된 표(Table).
* **SQL (Structured Query Language)**: 관계형 데이터베이스를 정의, 조작, 제어하기 위한 표준 질의 언어.
* **DBMS (Database Management System)**: 사용자와 데이터베이스 사이에서 데이터의 저장, 검색, 관리를 중재하는 소프트웨어.
* **Domain (도메인)**: 문제의 컨텍스트(context) 또는 범위.

---

1. **정석 보강 (canon-std)**
강의에서 설명한 설계 단계는 데이터베이스의 **3-스키마 아키텍처(3-Schema Architecture)**와 밀접한 관련이 있습니다. 이 구조는 **데이터 독립성(Data Independence)**을 보장하는 핵심 원리입니다.
* **외부 스키마 (External Schema)**: 개별 사용자가 보는 데이터베이스의 뷰(View).
* **개념 스키마 (Conceptual Schema)**: 데이터베이스 전체의 논리적 구조를 정의. 강의의 '논리적 단계'에 해당하며, `CREATE TABLE`문이 이 스키마를 정의합니다.
* **내부 스키마 (Internal Schema)**: 데이터가 물리적으로 어떻게 저장되는지를 정의. 강의의 '물리적 단계'에 해당하며, 인덱스 생성(`CREATE INDEX`) 등이 여기에 속합니다.

---

1. **실수·함정**
* `Relation`(표)과 `Relationship`(관계)을 혼동하는 것. 전자는 데이터 구조이고 후자는 ERD에서 개체 간의 연관성입니다.
* 추상화를 '모호하게 만들기'로 오해하는 것. 공학에서 추상화는 오히려 '핵심을 정밀하게 정의하기'입니다.
* ERD가 데이터베이스 자체라고 생각하는 것. ERD는 설계도일 뿐, 실제 데이터베이스는 관계형 모델을 통해 DBMS에 구현됩니다.
* 논리적 모델과 물리적 모델을 동일시하는 것. 논리적으로는 단순한 표라도, 물리적으로는 복잡한 인덱스 구조를 가질 수 있습니다.
* `SQL`을 절차적 언어로 착각하는 것. `SQL`은 '무엇을 원하는지'를 선언하며, '어떻게 찾을지'는 DBMS 옵티마이저가 결정합니다.
* 엑셀(Excel)을 데이터베이스로 여기는 것. 엑셀은 대용량 데이터 처리, 동시성 제어, 정교한 무결성 제약 기능이 부족합니다.

## **2025-09-05, 1교시 — 질문**

**[Q1] 데이터베이스 설계를 배우기 전, 과학적 모델링을 먼저 이해해야 하는 이유는 무엇인가요? | 태그: 모델링, 설계 철학**
* **모범답(강의 기준)**: 데이터베이스 설계는 현실 세계의 복잡한 요구사항을 컴퓨터가 처리할 수 있는 정형화된 데이터 구조로 변환하는 과정이며, 이는 과학적 모델링의 문제 해결 방식(추상화 → 정형화)을 그대로 따르기 때문입니다.
* **정석체크(면접 30초)**: 과학적 모델링은 문제의 본질을 파악하는 **추상화(abstraction)** 능력과 이를 정형화된 모델로 표현하는 역량을 길러줍니다. 데이터베이스 설계 역시 요구사항 분석(`real-world`)부터 ERD(`conceptual`), 관계 모델(`logical`)로 구체화하는 과정을 거치므로, 모델링의 원리를 이해하는 것이 설계의 기초가 됩니다.

---

**[Q2] 데이터베이스 설계의 3단계(개념적, 논리적, 물리적)는 각각 무엇을 의미하며, 주요 산출물은 무엇인가요? | 태그: 3-스키마, 데이터 독립성, ERD**
* **모범답(강의 기준)**: **개념적 설계**는 ERD를 통해 사람이 이해하기 쉬운 모델을 만들고, **논리적 설계**는 이를 DBMS에 독립적인 관계 모델(표 구조)로 변환하며, **물리적 설계**는 실제 저장 방식과 성능을 고려하는 단계입니다.
* **정석체크(면접 30초)**: 이 3단계는 **3-스키마 아키텍처**에 대응하여 데이터 독립성을 보장합니다. 개념적 설계의 산출물은 `ERD`, 논리적 설계의 산출물은 `관계 스키마(CREATE TABLE)`이며, 물리적 설계는 DBMS가 주로 처리하지만 인덱스(`CREATE INDEX`) 설정 등으로 성능에 관여할 수 있습니다.

---

**[Q3] '관계형' 데이터베이스에서 '관계(relation)'라는 용어는 무엇을 의미하며, '관계(relationship)'와 어떻게 다른가요? | 태그: 관계대수, 용어 정의, ERD**
* **모범답(강의 기준)**: '관계(relation)'는 수학 용어로, 행과 열로 구성된 **표(table)** 자체를 의미합니다. 반면 '관계(relationship)'는 ERD에서 개체(entity)들 간의 상호작용이나 연관성을 나타내는 개념입니다.
* **정석체크(면접 30초)**: `Relation`은 집합론에 기반한 수학적 개념으로 테이블의 구조와 데이터를 지칭하는 정적인 용어입니다. 반면 `Relationship`은 ERD에서 테이블 간의 연결고리, 즉 외래 키(`FOREIGN KEY`)로 구현될 의미적 연결을 표현하며 테이블 간의 상호작용을 나타냅니다.

---

**[Q4] 데이터베이스 설계의 궁극적인 목표는 무엇인가요? | 태그: 성능, 데이터 조직화, DML**
* **모범답(강의 기준)**: 데이터의 검색, 삽입, 수정, 삭제(`SELECT`, `INSERT`, `UPDATE`, `DELETE`)와 같은 핵심 연산들이 빠르고 효율적으로 수행되도록 데이터를 잘 조직화하는 것입니다.
* **정석체크(면접 30초)**: 목표는 **데이터 중복 최소화**와 **무결성 유지**를 통해 갱신 이상(anomaly)을 방지하고, 효율적인 쿼리 처리를 위한 최적의 구조를 만드는 것입니다. 이는 정규화(normalization)와 인덱싱(indexing) 같은 기법을 통해 달성됩니다.

---

**[Q5] 데이터베이스 시스템(DBS)을 구성하는 요소는 무엇인가요? | 태그: DBMS, DB, 시스템 아키텍처**
* **모범답(강의 기준)**: 데이터베이스 시스템(DBS)은 데이터를 관리하고 조작하는 소프트웨어인 **DBMS(Database Management System)**와, 그 DBMS 위에서 관리되는 실제 데이터의 집합인 **DB(Database)**로 구성됩니다.

## **2025-09-05, 2교시 — 개선본**

데이터베이스 시스템(DBS)은 DBMS 소프트웨어와 실제 데이터베이스(DB)의 조합을 의미합니다. 여러분은 `MySQL`과 같은 DBMS를 설치하고, 직접 설계한 데이터 구조(스키마)와 실제 데이터(인스턴스)를 그 안에 담아 데이터베이스 시스템을 구축하게 됩니다. (실습)

DBMS를 사용하는 주된 이유는 다음과 같습니다.

1.  **데이터 독립성 (Data Independence)**: 애플리케이션과 데이터를 분리하는 개념입니다. 데이터의 물리적 저장 구조가 변경되어도 응용 프로그램은 수정할 필요가 없도록 하는 것이 핵심입니다. 한 부분의 수정이 다른 부분의 연쇄적인 수정을 유발하지 않는 상태를 독립성이 보장된다고 합니다.
2.  **데이터 무결성 (Data Integrity)**: 데이터베이스의 값이 현실 세계의 실제 값과 일치해야 함을 의미합니다. 예를 들어, 은행 계좌의 잔액이 전산 시스템에서도 정확하게 반영되어야 하며, 오류로 인해 값이 변해서는 안 됩니다.
3.  **보안 (Security)**: DBMS는 접근 제어, 암호화 등 내장된 보안 기능을 통해 데이터를 안전하게 보호합니다.
4.  **병행 제어 (Concurrency Control)**: 여러 사용자가 동시에 데이터베이스에 접근할 때 발생할 수 있는 문제를 제어하는 기능입니다. 여기서 병행과 병렬의 차이를 이해해야 합니다.
    * **병행 (Concurrency)**: **하나의 CPU**가 여러 작업을 짧은 시간 간격으로 번갈아 처리하여 동시에 실행되는 것처럼 보이게 하는 기술입니다. 윈도우와 같은 대부분의 운영체제나 DBMS는 병행 시스템입니다. 운영체제에서는 이를 **멀티프로세싱(Multi-processing)** 또는 **타임 셰어링(Time-sharing)**이라고 부릅니다.
    * **병렬 (Parallelism)**: **여러 개의 CPU**가 실제로 동시에 여러 작업을 처리하는 방식입니다. 주로 슈퍼컴퓨터에서 사용됩니다.

이처럼 동일한 개념이라도 데이터베이스, 운영체제 등 학문 분야(subject)에 따라 다른 용어를 사용하는 경우가 많습니다. 예를 들어, DB의 `concurrency`는 OS의 `multi-processing`과 거의 같은 개념입니다.

데이터베이스의 핵심 용어는 다음과 같습니다.

* **스키마 (Schema)와 인스턴스 (Instance)**
    * **스키마**: 데이터의 구조, 즉 뼈대나 설계도를 의미합니다. 테이블의 열(column) 구조(예: 학번, 이름, 성적)를 정의하는 것이 스키마에 해당합니다.
    * **인스턴스**: 스키마라는 틀 안에 채워진 실제 데이터 값들의 집합입니다. 특정 시점의 데이터 전체를 의미하기도 하고, 테이블의 한 행(row)을 지칭하기도 합니다.
* **데이터 용어의 동의어**
    * 테이블의 한 **행(row)**을 가리키는 용어: `인스턴스(instance)`, `레코드(record)`, `튜플(tuple)`은 거의 동일한 의미로 사용됩니다.
    * 테이블의 **열(column)**을 가리키는 용어: `필드(field)`, `속성(attribute)`이라고 부릅니다. 머신러닝 분야에서는 `피처(feature)`라고도 합니다.
* **트랜잭션 (Transaction)**
    * 데이터베이스에서 수행되는 **하나의 작업 단위**를 의미하며, 운영체제의 `프로세스(process)`와 유사한 개념입니다.
    * 트랜잭션의 가장 중요한 특성은 **원자성(Atomicity)**입니다. 이는 'All or Nothing' 원칙으로, 작업 단위 내의 모든 연산이 전부 성공적으로 완료되거나, 하나라도 실패하면 모두 처음 상태로 되돌아가는 것을 보장합니다. ATM에서 돈을 인출하다 중간에 오류가 발생하면 모든 과정이 취소되고 원상태로 돌아가는 것이 대표적인 예입니다.

마지막으로, 데이터베이스 관련 직무는 시스템 관리자와 데이터베이스 관리자로 나뉩니다.

* **시스템 관리자 (System Administrator)**: 서버 하드웨어, 운영체제 설치 및 계정 관리 등 시스템 전반을 책임집니다.
* **데이터베이스 관리자 (DBA, Database Administrator)**: DBMS를 설치, 운영하고 데이터베이스를 설계, 백업, 복구하는 등 데이터베이스에 특화된 전문가입니다.

## **2025-09-05, 2교시 — 개념**

1. **한 줄 요약**
DBMS는 데이터 독립성, 무결성, 병행 제어를 보장하며, 데이터베이스는 스키마(구조)와 인스턴스(실제 값)로 구성되고, 모든 작업은 원자성을 지키는 트랜잭션 단위로 처리됩니다.

---

1. **핵심 TL;DR**
* **스키마 vs. 인스턴스**: **스키마(Schema)**는 데이터의 뼈대(열 구조)이고, **인스턴스(Instance)**는 그 뼈대에 채워진 실제 데이터(행 집합)입니다.
* **데이터 독립성**: 데이터의 물리적 저장 방식이 바뀌어도 응용 프로그램은 영향을 받지 않아야 합니다.
* **데이터 무결성**: 데이터는 현실 세계를 정확히 반영해야 하며, 오류나 비논리적인 값이 없어야 합니다.
* **병행(Concurrency) vs. 병렬(Parallelism)**: **병행**은 1개의 CPU가 여러 일을 번갈아 하는 것이고, **병렬**은 여러 개의 CPU가 동시에 여러 일을 처리하는 것입니다.
* **트랜잭션(Transaction)**: 'All or Nothing' 원칙을 따르는 하나의 논리적 작업 단위입니다.
* **원자성(Atomicity)**: 트랜잭션의 핵심 속성으로, 작업 전체가 성공하거나 전체가 실패하는 것을 보장합니다. (`All or Nothing`)
* **행(Row)의 동의어**: `튜플(Tuple)`, `레코드(Record)`, `인스턴스(Instance)`는 문맥에 따라 거의 같은 의미로 쓰입니다.
* **열(Column)의 동의어**: `속성(Attribute)`, `필드(Field)`, `피처(Feature)` 역시 분야에 따라 같은 대상을 지칭합니다.
* **DBA vs. 시스템 관리자**: **DBA**는 DBMS와 데이터를 관리하고, **시스템 관리자**는 서버의 하드웨어와 운영체제를 관리합니다.

---

1. **표현 = 표준 용어**
* **Data Independence (데이터 독립성)**: 응용 프로그램과 데이터의 물리적 구조를 분리하는 원칙.
* **Data Integrity (데이터 무결성)**: 데이터의 정확성, 일관성, 유효성이 유지되는 상태.
* **Schema (스키마)**: 데이터베이스의 구조와 제약 조건에 대한 명세. 공식 용어로는 **내포(Intension)**라고도 합니다.
* **Instance (인스턴스)**: 특정 시점의 데이터베이스에 존재하는 실제 값들의 집합. 공식 용어로는 **외연(Extension)**이라고도 합니다.
* **Tuple / Record (튜플 / 레코드)**: 테이블에서 하나의 행(row)을 구성하는 데이터의 집합.
* **Attribute / Field (속성 / 필드)**: 테이블에서 하나의 열(column)을 의미하며, 데이터의 가장 작은 논리적 단위.
* **Concurrency (병행성)**: 다수의 사용자가 동시에 트랜잭션을 실행하는 환경.
* **Transaction (트랜잭션)**: 데이터베이스의 상태를 변화시키는 하나의 논리적 작업 단위.
* **ACID**: 트랜잭션이 안전하게 수행되기 위해 갖춰야 할 4가지 속성(원자성, 일관성, 고립성, 지속성).
* **Atomicity (원자성)**: 트랜잭션의 연산들이 모두 정상적으로 실행되거나 하나도 실행되지 않음을 보장하는 속성.
* **Log (로그)**: 데이터베이스의 모든 변경 이력을 순차적으로 기록하는 파일로, 회복(Recovery)의 핵심 요소.
* **DBA (Database Administrator)**: 데이터베이스 시스템을 총괄하고 책임지는 전문가 또는 그룹.

---

1. **정석 보강 (canon-std)**
강의에서 강조된 트랜잭션(Transaction)은 데이터베이스의 신뢰성을 보장하기 위해 **ACID** 속성을 반드시 만족해야 합니다.
* **A (Atomicity)**: **원자성**. 작업이 전부 실행되거나(COMMIT), 전혀 실행되지 않아야(ROLLBACK) 함을 보장합니다.
* **C (Consistency)**: **일관성**. 트랜잭션 실행 후에도 데이터베이스는 항상 유효한 상태(미리 정의된 규칙, 제약조건을 위반하지 않는 상태)를 유지해야 합니다.
* **I (Isolation)**: **격리성(고립성)**. 여러 트랜잭션이 동시에 실행될 때, 각 트랜잭션은 다른 트랜잭션의 연산에 영향을 받지 않고 독립적으로 실행되는 것처럼 보여야 합니다.
* **D (Durability)**: **지속성**. 성공적으로 완료된 트랜잭션의 결과는 시스템에 장애가 발생하더라도 영구적으로 반영되어야 합니다. 이는 로그(Log)를 통해 보장됩니다.
    * `BEGIN TRANSACTION; ... COMMIT;` 구문은 트랜잭션의 시작과 성공적인 종료를 명시합니다.

---

1. **실수·함정**
* **병행성(Concurrency)**과 **병렬성(Parallelism)**을 혼동하는 것. (1개 CPU의 시간 분할 vs 다수 CPU의 동시 작업)
* **스키마**를 실제 데이터로, **인스턴스**를 데이터 구조로 착각하는 것.
* **트랜잭션**을 단일 `SQL` 쿼리로만 한정하는 것. (여러 쿼리가 하나의 논리적 작업 단위일 수 있음)
* **원자성(Atomicity)**과 **격리성(Isolation)**을 혼동하는 것. 원자성은 '단일 트랜잭션'의 완전성에 대한 것이고, 격리성은 '여러 트랜잭션' 간의 간섭 문제에 대한 것입니다.
* **로그(Log)**를 단순 접속 기록으로만 생각하는 것. 데이터베이스에서 로그는 장애 발생 시 데이터 복구를 위한 핵심 장치입니다.
* **데이터 무결성**을 '데이터가 틀리지 않는 것'으로만 소극적으로 이해하는 것. 제약조건을 통해 '유효한' 데이터만 허용하는 적극적인 개념입니다.

**[Q2] 트랜잭션(Transaction)이란 무엇이며, 핵심 속성인 '원자성(Atomicity)'은 어떤 의미인가요? | 태그: 트랜잭션, ACID, 원자성**

**[Q3] 병행(Concurrency)과 병렬(Parallelism)의 차이점은 무엇인가요? | 태그: 동시성, CPU, 성능**
* **모범답(강의 기준)**: 병행은 **하나의 CPU**가 여러 작업을 매우 빠르게 번갈아 처리해 동시에 실행되는 것처럼 보이게 하는 기술입니다. 반면 병렬은 **여러 개의 CPU**가 실제로 동시에 여러 작업을 처리하는 것입니다.
* **정석체크(면접 30초)**: **병행성(Concurrency)**은 논리적인 개념으로, 한정된 자원을 여러 작업이 나누어 쓰는 것입니다. OS의 멀티태스킹이 대표적 예입니다. **병렬성(Parallelism)**은 물리적인 개념으로, 여러 개의 처리 장치(코어, CPU)를 이용해 작업을 동시에 실행하여 처리량을 높이는 것입니다.

**[Q4] DBMS를 사용하는 핵심적인 이유 4가지를 설명해주세요. | 태그: DBMS, 데이터 독립성, 무결성**
* **모범답(강의 기준)**: **데이터 독립성**(앱과 데이터 분리), **데이터 무결성**(데이터의 정확성 유지), **보안**(접근 제어), 그리고 **병행 제어**(동시 사용자 문제 해결)를 효율적으로 관리할 수 있기 때문입니다.
* **정석체크(면접 30초)**: DBMS는 데이터의 **중복을 최소화**하고, **일관성을 유지**하며, **독립성을 보장**하여 유지보수 비용을 절감합니다. 또한 **회복(Recovery)** 및 **병행 제어(Concurrency Control)** 기능을 내장하여 데이터의 신뢰성과 안정성을 극대화합니다.

**[Q5] 데이터베이스 관리자(DBA)와 시스템 관리자의 역할은 어떻게 다른가요? | 태그: 역할, DBA, 시스템 관리**
* **모범답(강의 기준)**: 시스템 관리자는 서버의 하드웨어, OS 설치, 네트워크 등 시스템 인프라 전반을 관리합니다. 반면 DBA는 `MySQL` 같은 DBMS 소프트웨어를 설치하고, 그 안의 데이터베이스를 설계, 운영, 백업, 튜닝하는 등 데이터 관리에 집중합니다.
* **정석체크(면접 30초)**: 시스템 관리자는 시스템의 **가용성(Availability)**과 **성능**을 보장하는 넓은 역할을 맡습니다. DBA는 그 시스템 위에서 동작하는 DBMS의 **성능, 보안, 데이터 무결성, 회복**을 책임지는 데이터 전문가로서 더 특화된 역할을 수행합니다.
