## 2) 파일시스템 경계와 `mv`의 동작 원리

`mv` 명령은 파일 시스템(FS, 즉 파티션)의 경계에 따라 **작동 방식이 완전히 달라집니다.**

| 상황           | 동작 방식              | 설명                                                                        | 효율성                  |
| ------------ | ------------------ | ------------------------------------------------------------------------- | -------------------- |
| **같은 파티션 내** | **Rename** (링크 수정) | 파일의 내용(데이터 블록)은 그대로 두고, 파일 이름과 위치를 가리키는 **Inode 정보만 수정**합니다.              | **매우 빠름** (파일 크기 무관) |
| **다른 파티션 간** | **Copy + Delete**  | 대상 FS에 파일 전체를 복사(**새로운 inode 할당**, 데이터블록 복제)한 후, 원본 FS에서 파일을 삭제(`rm`)합니다. | **느림** (데이터 I/O 발생)  |

## 3) 삭제 명령어의 구분과 안전 옵션

삭제 명령어는 대상에 따라 기능과 위험도가 명확하게 구분됩니다.

리눅스에는 기본적으로 '휴지통' 개념이 없어, `rm`으로 삭제된 파일은 복구가 매우 어렵다

| 명령어         | 대상                      | 상태 조건            | 안전성/필수 옵션                        |
| ----------- | ----------------------- | ---------------- | -------------------------------- |
| **`rm`**    | **파일**                  | 제한 없음            | `-i` (실수방지)                      |
| **`rmdir`** | **디렉토리**                | **반드시 비어 있어야 함** | **가장 안전** (빈 디렉토리만 삭제 가능)        |
| **`rm -r`** | **디렉토리 트리** (즉 하위 요소까지) | **비어 있지 않아도 됨**  | **`-r`** (재귀) 옵션 필수, `-i` (실수방지) |

- rm은 파일 이름과 inode의 연결(디렉터리 엔트리)을 제거합니다. 해당 inode를 가리키는 모든 연결(링크 카운트)이 사라지면 **데이터 블록이 해제**되어 파일이 실제로 삭제됩니다.
	- rm -r 은 가장 깊은 하위 디렉토리부터 시작하여 **파일의 디렉토리 엔트리**를 하나씩 제거(`unlink`)합니다-> Inode의 링크 카운트가 0이 되어 데이터 블록이 해제됨
- **`rmdir`**: 삭제하려는 디렉터리가 **비어 있음**을 확인한 후, 부모 디렉토리에 있는 해당 디렉토리의 **엔트리**를 제거합니다.
	- `rmdir`은 디렉토리 내부에 **`.` (현재 디렉토리)**와 **`..` (상위 디렉토리)** 두 엔트리 외에 다른 파일이나 폴더가 존재하면 삭제를 **거부**하고 오류를 반환
- **`cp` 및 `rm`의 `-r` (Recursive) 옵션**: 대상파일을 디렉토리로 인식하고 **내부의 모든 하위 항목을 재귀적으로 처리**하도록 지시하는 필수 옵션입니다.
	- `-r` 이없다면 디렉토리를 **목록 파일**이 아닌 일반 파일 로 인식해 처리하려해 오류를 반환
- **`-i` (Interactive) 옵션**: `cp`, `mv`, `rm` 사용 시 파일 덮어쓰기나 삭제 전에 사용자에게 확인을 요청하여 **실수를 방지**하는 안전장치입니다.

여기 핵심만 쏙—현업용 치트시트로 정리했어요.

# **cp / mv / rm 한눈에 정리**

### 1)`cp` 복사
- **`cp [원본] [사본]`**
- 새 **inode** 배정 + **데이터 블록 복제** ⇒ 원본은 그대로 유지
- 디렉터리 복사 시 **-r 필수**.
- 인자여러개: 여러 파일을 **한 디렉터리**로만 복사하는 경우만 가능.
### 2) `mv` **위치 이동/이름 변경**
- **`mv [원본] [목적지/새이름]`**
    - 같은 파티션인경우: 디렉토리 엔트리만 수정
		- 데이터 블록, inode그대로 둔다
	- 다른 파티션인경우: cp 후 rm
		- 새 **inode** 배정 + **데이터 블록 복제**⇒ 원본은 삭제(unlink)
- 인자여러개: 여러 파일 → **한 디렉터리**로만 이동하는 경우만 가능.


> **디렉토리 엔트리**: **파일 이름 ↔ inode 번호**의 1:1 매핑 정보, 파일 엔트리라고도 한다. **자신의 부모 폴더의 데이터 블록 내부**에 저장이된다
> 우리가 터미널에서 확인하는 폴더구조는 매핑된 파일 이름의 나열이다
> 데이터 블록에는 유저가 매핑하지 않은 기본적인 2개의 매핑정보가있는데
> 자기 자신의 inode번호와  . 이라는 이름으로 한 매핑,
> 부모 디렉토리의 inode번호와 ..이라는 이름으로 한 매핑이다
> 그래서 ..
> 
> 즉, /B/c.txt 라면:
	- c.txt의 **inode**: 소유자/권한/타임스탬프와 **데이터 블록 포인터(내용물 위치)** 를 가짐. **이름은 없음.**
	- c.txt라는 **이름 매핑**: **부모 디렉터리 B의 데이터 블록** 안에 ("c.txt" → inode#1234) 같은 **엔트리**로 존재.
	
> .(자기 자신의 inode 번호를 저장하는 )
> ..(부모 디렉토리의 inode 번호를 저장) cd .. 가 “부모로 이동”이 되는 이유.
>

## **3) 삭제 명령 세트**

- **rm file**: 디렉토리 **엔트리 제거(unlink)**
	- **rm -r dir**: 하위 디렉토리부터 디렉토리 엔트리를 하나씩 제거(강력·위험).
- **rmdir dir**: 해당 디렉토리 내부에 .와 .. 만 존재하는경우 디렉토리 엔트리 제거
- 리눅스 기본은 **휴지통 없음** → 실수 방지에 -i 적극 사용.

> 대상 파일의 이름과 Inode 번호를 잇는 디렉토리 엔트리를 제거한다-> 파일 이름이 사라져 사용자가 해당 파일에 접근할 수 없게된다 
> 
> Inode를 가리키는 이름이 더 이상 없다면, 파일 시스템은 해당 Inode와 연결된 **데이터 블록을 해제**하고 Inode를 '사용 가능' 상태로 만듭니다. 이 시점에 파일이 사실상 삭제됩니다.
>

## 1)`cp` 복사 vs. `mv` 이동/이름 변경

두 명령어의 근본적인 차이는 **파일의 inode(메타데이터)**와 **데이터 블록** 처리 방식에 있습니다.

| 명령어                   | 핵심 기능        | 원본 파일 처리  | Inode 처리                                          | 데이터 블록 처리 |
| --------------------- | ------------ | --------- | ------------------------------------------------- | --------- |
| `cp [원본명] [사본명]`      | **사본 생성**    | **원본 유지** | 새로운 inode를 할당하고 데이터 블록을 복제하여 별개의 파일을 생성           | 원본 내용을 복제 |
| `mv [원본명] [목적지/변경할명]` | **위치/이름 변경** | **원본 제거** | 같은 파티션내인경우 데이터는 그대로 둔 채 파일명과 연결된 inode 포인터 정보만 변경 | 데이터 이동 없음 |

- 인자가 여러개인경우
	- cp: 여러개를 하나의 디렉토리로 복사하는 경우만 가능
	- mv: 여러개를 하나의 디렉토리로 옮기는 경우만 가능
- `cp`는 원본을 남기고 사본을 만들지만, `mv`는 원본 자체를 옮깁니다.
	-  원본이 이동되므로 원래 위치에서는 사라집니다.
