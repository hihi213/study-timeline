- **cp vs mv inode 차이**: cp는 **새 inode** + 데이터 블록 복제. mv는 **같은 FS**에선 **rename(링크 수정)** 만 하여 빠름. **다른 FS**면 **복사+삭제**.
- **디렉터리 복사**: **반드시 -r**(또는 -a).
- **삭제**: 파일→rm, 빈 디렉터리→rmdir, 트리 전체→rm -r(주의).
- **안전 옵션**: -i로 덮어쓰기/삭제 전 확인.

`cp`는 원본을 남기고 사본을 만들지만, `mv`는 원본 자체를 옮깁니다.

**`cp` (Copy)**: 파일이나 디렉터리를 복사합니다. 원본은 그대로 유지되고 사본이 생성됩니다. 새로운 inode를 할당하고 데이터 블록을 복제하여 별개의 파일을 생성
- 	`cp [원본파일] [대상파일]`
- 대상파일이 디렉터리: 원본을 그 디렉토리 안에다가 원본이름으로 복사
- 대상 파일이 파일이름
- 대상파일/디렉토리가 없다: 해당 이름으로 사본을 생성합니다.
	- 디렉토리 또한 파일취급해서 **디렉터리를 복사함**
		- 이때 반드시 `-r` (recursive) 옵션을 명시해야 한다는 점입니다. 이 옵션이 없으면 `cp`는 다른 파일 및 디렉토리의 목록과 위치(inode) 담긴 \ **디렉토리를 일반 파일과 동일하게 처리하려 하기 때문에 디렉터리를 복사하지 못하고 오류를 반환합니다.

**`mv` (Move)**: 파일이나 디렉터리를 다른 위치로 옮기거나 이름을 변경합니다. 원본이 이동되므로 원래 위치에서는 사라집니다.
- 같은 파티션 내의 `mv`는 데이터는 그대로 둔 채 파일명과 연결된 inode 포인터 정보만 변경하여 매우 빠릅니다. **주의**: 다른 파티션 간의 `mv`는 사실상 복사 후 원본 삭제 방식으로 동작합니다.
1. **대상이 디렉터리일 때 (이동)**: `mv temp4 temp`에서 `temp`가 이미 존재하는 디렉터리라면, `temp4` 디렉터리 전체가 `temp` 디렉터리 _안으로_ 이동합니다.
2. **대상이 존재하지 않을 때 (이름 변경)**: `mv temp3 temp4`에서 `temp4`가 없다면, `temp3`의 이름이 `temp4`로 변경됩니다. `temp3`는 사라지며, 이는 사실상 '이름 바꾸기(rename)'와 동일한 작업입니다.

- **`mv` (Move)**: 파일/디렉터리를 이동시키거나 이름을 변경하는 명령어.
- **`rm` (Remove)**: 파일/디렉터리를 영구적으로 삭제하는 명령어.
- **`rmdir` (Remove Directory)**: 비어 있는 디렉터리를 삭제하는 명령어.
- **`-i` (Interactive)**: `cp`, `mv`, `rm` 등에서 덮어쓰거나 삭제하기 전에 사용자에게 확인을 요청하는 옵션.
- **`-r` (Recursive)**: 디렉터리 대상 명령어(`cp`, `rm`)에서 해당 디렉터리뿐만 아니라 내부의 모든 하위 항목에 대해 작업을 반복 적용하는 옵션.

**파일 및 디렉터리 삭제 (`rm`)**: `rm`은 파일을 영구적으로 제거하는 강력한 명령어입니다. 가장 중요한 점은 리눅스에는 기본적으로 '휴지통' 개념이 없어, `rm`으로 삭제된 파일은 복구가 매우 어렵다는 것입니다. 디렉터리와 그 내용을 재귀적으로 삭제하기 위해서는 `-r` 옵션이 필수이며, `-i` 옵션은 삭제 전 확인 과정을 거쳐 실수를 방지하는 안전장치 역할을 합니다.

아래만 딱 기억해도 충분해요 — **cp = 사본 만들기**, **mv = 위치/이름 바꾸기**, **rm = 지우기**, **rmdir = 빈 디렉터리 지우기**. rm -r = 디렉토리와 그 하위 내용 모두 제거

## **3) 파일시스템 경계**

- **같은 파티션**: mv는 **메타데이터만 수정**(빠름, 데이터 이동 없음)
- **다른 파티션**: mv는 **복사 후 원본 삭제**(느림, 공간 필요)

# **실습 흐름(축약)**

```
cd ~/study/ch03

# 1) 파일 복사
cp /etc/profile test1
ls -l test1

# 2) 디렉터리 만들고 복사
mkdir -p temp
cp test1 temp/

# 3) 이동/이름변경 예시
mkdir -p one
mv test1 one/     # test1 → one/ 로 이동

# 4) 디렉터리 통째 복사
cp -r temp temp2  # 또는 속성보존: cp -a temp temp2
```

## 1) 복사 vs. 이동/이름 변경 (`cp` vs. `mv`)

두 명령어의 근본적인 차이는 **파일의 inode(메타데이터)**와 **데이터 블록** 처리 방식에 있습니다.

| 명령어                    | 핵심 기능        | 원본 파일 처리  | Inode 처리                         | 데이터 블록 처리 |
| ---------------------- | ------------ | --------- | -------------------------------- | --------- |
| **`cp` (Copy)**        | **사본 생성**    | **원본 유지** | **새로운 inode 할당**, 데이터블록 복제       | 원본 내용을 복제 |
| **`mv` (Move/Rename)** | **위치/이름 변경** | **원본 제거** | 같은 파티션인경우  링크만 수정해 기존 inode를 재사용 | 데이터 이동 없음 |

## 2) 파일시스템 경계와 `mv`의 동작 원리

`mv` 명령은 파일 시스템(FS, 즉 파티션)의 경계에 따라 **작동 방식이 완전히 달라집니다.**

| 상황           | 동작 방식              | 설명                                                                        | 효율성                  |
| ------------ | ------------------ | ------------------------------------------------------------------------- | -------------------- |
| **같은 파티션 내** | **Rename** (링크 수정) | 파일의 내용(데이터 블록)은 그대로 두고, 파일 이름과 위치를 가리키는 **Inode 정보만 수정**합니다.              | **매우 빠름** (파일 크기 무관) |
| **다른 파티션 간** | **Copy + Delete**  | 대상 FS에 파일 전체를 복사(**새로운 inode 할당**, 데이터블록 복제)한 후, 원본 FS에서 파일을 삭제(`rm`)합니다. | **느림** (데이터 I/O 발생)  |

---

## 3) 삭제 명령어의 구분과 안전 옵션

삭제 명령어는 대상에 따라 기능과 위험도가 명확하게 구분됩니다.

|명령어|대상|상태 조건|안전성/필수 옵션|
|---|---|---|---|
|**`rm`**|**파일**|제한 없음|`-i` (확인), **휴지통 없음** (영구 삭제 주의)|
|**`rmdir`**|**디렉토리**|**반드시 비어 있어야 함**|**가장 안전** (빈 디렉토리만 삭제 가능)|
|**`rm -r`**|**디렉토리 트리**|**비어 있지 않아도 됨**|**`-r`** (재귀) 옵션 필수, **`-i`** 옵션으로 실수 방지|

- **`cp` 및 `rm`의 `-r` (Recursive) 옵션**: 디렉토리를 일반 파일이 아닌 **목록 파일**로 인식하고, **내부의 모든 하위 항목을 재귀적으로 처리**하도록 지시하는 필수 옵션입니다.
- **`-i` (Interactive) 옵션**: `cp`, `mv`, `rm` 사용 시 파일 덮어쓰기나 삭제 전에 사용자에게 확인을 요청하여 **실수를 방지**하는 안전장치입니다.
