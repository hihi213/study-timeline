## 정리
## **2025-09-12, 1교시 — 개선본**

여러분 PC에 설치한 Ubuntu 계정은 해당 PC에 종속적입니다. 각 PC가 하나의 독립된 서버 역할을 하므로, 다른 자리에 앉으면 이전에 만든 계정과 암호로 로그인할 수 없습니다. Linux나 Unix 운영 체제는 계정 보안이 강화되어 있어 관리자 암호가 있어도 다른 사용자의 접근이 어렵습니다. 따라서 되도록 자신의 고정 좌석에서 실습을 진행해야 합니다.

지난 시간에 VMware만 설치하고 Ubuntu 설치는 진행하지 않았습니다. 지금부터 그 과정을 이어가겠습니다. 이 설명은 Linux를 처음 접하는 분들을 기준으로 진행되므로, 경험이 있는 분들은 이미 아는 내용일 수 있습니다.

먼저, 설치된 VMware를 실행해 봅시다. (실습) 초기 화면에 'Create a New Virtual Machine', 'Open a Virtual Machine', 'Connect to a Remote Server' 세 가지 옵션이 보일 것입니다. 우리는 새로운 가상 머신을 만들어야 하므로, 맨 왼쪽에 있는 **'Create a New Virtual Machine'**을 클릭합니다. (실습)

VMware는 현재 사용 중인 Windows 운영 체제 내에, 독립된 가상의 컴퓨터를 새로 만드는 소프트웨어입니다. 즉, 물리적인 PC 안에 논리적으로 또 하나의 PC를 생성하는 것입니다. 'Create a New Virtual Machine'을 누르는 것은 바로 이 가상의 PC를 만드는 첫 단계입니다.

설정 마법사가 나타나면 'Typical(권장)'과 'Custom(고급)' 중 선택하게 됩니다. 우리는 권장 설정인 **'Typical'**을 선택하고 'Next'를 누릅니다. (실습) 다음으로 운영 체제 설치 방법을 선택해야 합니다. 실제 설치 디스크가 아닌 다운로드한 **이미지 파일(ISO)**을 사용할 것이므로, 'Installer disc image file (iso)' 옵션을 선택합니다. (실습) 그리고 'Browse...' 버튼을 눌러 지난 시간에 다운로드한 Ubuntu 24.04 LTS 버전의 ISO 파일 위치를 지정해 줍니다. (실습)

이제 가상 머신의 전원을 켜봅시다. 부팅 과정이 진행되지만, 곧 'Operating system not found'라는 메시지가 나타날 것입니다. 이는 비어 있는 가상 PC의 전원을 켠 것과 같기 때문입니다. ROM BIOS가 하드웨어를 점검한 후 부팅할 운영 체제가 없다고 알려주는 정상적인 과정입니다.

다음은 Ubuntu 설치 과정에서 사용자 계정을 만드는 단계입니다. 컴퓨터 이름, 사용자 이름, 암호를 설정해야 합니다. (실습) 다른 Linux 배포판들은 별도의 관리자(`root`) 계정이 있지만, Ubuntu는 생성된 첫 번째 사용자 계정에 `sudo` 명령어를 통해 관리자 권한을 부여하는 방식을 사용합니다. 계정 설정 화면까지 진행한 후 잠시 대기합니다.

설치 진행이 막혔다면 가상 머신의 설정을 확인해야 합니다. 가상 머신 창에서 **'Edit virtual machine settings'** 메뉴로 들어갑니다. (실습) 좌측 'Hardware' 탭에서 **'CD/DVD (SATA)'** 장치를 선택합니다. (실습) 우측 'Connection' 항목에서 'Use ISO image file'이 제대로 선택되어 있는지, 그리고 파일 경로가 올바른지 다시 한번 확인합니다.

## **2025-09-12, 1교시 — 개념**

### 1. 한 줄 요약

VMware를 사용하여 Windows OS 위에 독립된 가상 머신(VM)을 생성하고, Ubuntu 설치를 위해 ISO 이미지를 가상 CD/DVD 드라이브에 연결하는 실습 준비 과정에 대해 학습합니다.

---
### 2. 핵심 TL;DR
* **가상 머신(Virtual Machine)**: 물리적 PC(Host OS) 내부에 소프트웨어로 구현된 별개의 가상 PC(Guest OS)로, 시스템을 격리하여 안전하게 다른 OS를 설치하고 테스트할 수 있습니다.
* **VM 생성 과정**: VMware에서 가상 하드웨어를 설정하고, 운영 체제를 설치할 원본으로 **ISO 이미지 파일**을 지정하는 절차를 따릅니다.
* **"OS를 찾을 수 없음"**: 운영 체제가 설치되지 않은 빈 가상 머신을 부팅하면, 실제 PC처럼 **ROM BIOS**가 하드웨어 점검 후 부팅 소스를 찾지 못해 "Operating system not found" 오류를 출력합니다.
* **Ubuntu의 `sudo` 정책**: 전통적인 Linux와 달리 별도의 `root` 계정을 비활성화하고, 설치 시 생성한 첫 일반 사용자에게 `sudo` 명령어로 관리자 권한을 임시 획득하도록 하여 보안을 강화합니다.
* **ISO 이미지 마운트**: 가상 머신이 ISO 파일을 인식하고 부팅하려면, 해당 파일을 가상 머신의 CD/DVD 드라이브 설정에 연결(**마운트**)해야 합니다.
* **로컬 계정**: 각 PC의 가상 머신은 독립된 서버이므로, 한 PC에서 만든 사용자 계정은 다른 PC의 가상 머신에서 사용할 수 없습니다.

---
### 3. 표현 = 표준 용어
* **가상 머신 (Virtual Machine, VM)**: 물리적 하드웨어 리소스를 가상화하여 논리적으로 분리된 컴퓨팅 환경을 제공하는 소프트웨어.
* **VMware**: 가상 머신을 생성하고 관리하는 대표적인 하이퍼바이저 소프트웨어.
* **ISO 이미지 (ISO Image)**: CD나 DVD 같은 광학 디스크의 모든 내용을 담고 있는 단일 아카이브 파일. OS 설치 미디어로 주로 사용됨.
* **루트 계정 (root account)**: Linux/Unix 시스템에서 모든 권한을 가진 최고 관리자 계정.
* **`sudo` (superuser do)**: 일반 사용자가 `root` 등 다른 사용자의 권한으로 특정 명령어를 실행할 수 있도록 허용하는 명령어.
* **ROM BIOS**: 부팅 시 하드웨어를 초기화하고 점검하며, 운영 체제를 로드하는 역할을 하는 펌웨어.

---
### 4. 정석 보강 (canon-std)
**Ubuntu의 `sudo` 정책**은 시스템 보안을 강화하기 위한 핵심적인 설계 철학입니다. 기본적으로 최고 관리자인 **`root` 계정의 암호를 설정하지 않아 직접적인 로그인을 비활성화**합니다. 대신, 설치 과정에서 생성된 첫 번째 사용자를 `sudo` 그룹에 포함시켜, 필요할 때마다 자신의 암호를 입력하여 일시적으로 관리자 권한을 얻도록 합니다. 이 방식은 항상 최고 권한으로 작업하는 위험을 줄이고, `sudo`를 통한 모든 관리 작업이 해당 사용자 계정으로 기록(`log`)에 남아 책임 추적을 용이하게 합니다.

---
### 5. 실수·함정
* 한 PC의 VM에서 만든 **사용자 계정**이 다른 PC의 VM에서도 동작할 것이라고 착각하는 것.
* 가상 머신을 켜기 전에 **ISO 이미지를 가상 CD/DVD 드라이브에 연결**하는 것을 잊는 것.
* Ubuntu 설치 후, 습관적으로 `su` 명령어로 **`root` 계정으로 직접 전환**하려는 시도. (기본적으로 비활성화되어 있음)
* **호스트 OS(Windows)**와 **게스트 OS(Ubuntu)**의 개념을 혼동하는 것.
* `sudo` 명령어가 **영구적인 관리자 권한**을 부여한다고 오해하는 것. (기본적으로 명령어 단위 또는 짧은 시간 동안만 유효함)

## **2025-09-12, 1교시 — 질문**

**[Q1] Windows가 이미 설치된 PC에 Linux를 설치할 때, 파티션을 나누지 않고 가상 머신(VM)을 사용하는 이유는 무엇인가? | #파일시스템/마운트**
* **모범답(강의 기준):** 가상 머신은 기존 Windows 시스템에 전혀 영향을 주지 않고, 그 안에 독립된 가상 PC를 만들어 주기 때문입니다. 이를 통해 실제 디스크를 변경하는 위험 없이 안전하게 Linux를 설치하고 사용할 수 있습니다.
* **정석체크(면접 30초):** VM은 호스트 OS 위에 논리적으로 격리된 샌드박스 환경을 제공하여 시스템 안정성을 보장합니다. 또한, 스냅샷 기능으로 특정 상태를 쉽게 저장하고 복원할 수 있어, 설정 오류 시 복구가 용이하고 반복적인 테스트 환경 구축에 매우 효율적입니다.

---
**[Q2] Ubuntu는 왜 다른 Linux처럼 `root` 계정을 직접 사용하지 않고 `sudo` 명령어를 사용하는가? | #권한/UMASK/특수비트**
* **모범답(강의 기준):** `root`라는 최고 관리자 계정으로 항상 작업하는 것의 위험을 줄이기 위해서입니다. 일반 사용자 계정으로 작업하다가 필요할 때만 `sudo`를 통해 임시로 관리자 권한을 얻는 것이 더 안전합니다.
* **정석체크(면접 30초):** `root` 계정 로그인을 기본적으로 비활성화하여 시스템 공격 표면을 줄이고, 모든 관리자 권한 작업이 특정 사용자 계정의 활동으로 기록되도록 하여 책임 추적성을 강화하는 보안 모델입니다. 이는 최소 권한 원칙(Principle of Least Privilege)을 적용한 것입니다.

---
**[Q3] 빈 가상 머신을 처음 켰을 때 "Operating system not found" 오류가 나타나는 이유는 무엇인가? | #부팅/systemd**
* **모범답(강의 기준):** 이는 실제 PC를 조립만 하고 Windows를 설치하지 않은 상태와 같습니다. 가상 머신의 BIOS가 부팅을 시도했지만, 설치된 운영체제가 없어 부팅할 수 없다는 정상적인 메시지입니다.
* **정석체크(면접 30초):** 부팅 과정은 펌웨어(BIOS/UEFI)가 POST(Power-On Self-Test)를 거친 후, 지정된 부팅 순서에 따라 MBR이나 EFI 파티션에서 부트로더를 찾는 순서로 진행됩니다. 이 과정에서 유효한 부트로더를 찾지 못하면 해당 오류를 출력하며, 이는 OS 설치가 필요함을 의미합니다.

---
**[Q4] 수업 환경에서 옆자리 PC에 내 Ubuntu 계정으로 로그인할 수 없는 이유는 무엇인가? | #사용자/그룹/쿼터**
* **모범답(강의 기준):** 각 PC에 설치된 가상 머신은 하나의 독립적인 서버와 같기 때문입니다. 계정 정보는 중앙 서버가 아닌 각자의 로컬 가상 머신 내에 저장되므로, 다른 PC에서는 해당 계정을 인식할 수 없습니다.
* **정석체크(면접 30초):** 현재 구성은 각 노드가 독립적으로 인증하는 분산 환경입니다. 중앙 인증 서버(예: LDAP, Kerberos)를 사용하는 중앙 집중식 환경에서는 어느 PC에서든 동일 계정으로 로그인이 가능하지만, 현재는 각 VM이 자신의 로컬 사용자 데이터베이스(`/etc/passwd`, `/etc/shadow`)만을 참조하여 인증을 수행합니다.

## **2025-09-12, 2교시 — 개선본**

이 수업의 모든 작업은 마우스를 거의 사용하지 않고 **터미널(Terminal)** 창에서 이루어집니다. 처음에는 마우스로 손이 가겠지만, 터미널 사용에 익숙해져야 합니다.

터미널을 열고 다음 명령어를 입력해 봅시다. `cd /` (실습)

`cd /`는 **절대 경로**를 사용하여 최상위 디렉터리인 **루트(/)**로 이동하라는 의미입니다. 명령을 실행하면 프롬프트의 `~` (물결 표시, 홈 디렉터리)가 `/` (루트 디렉터리)로 바뀐 것을 확인할 수 있습니다.

이제 루트 디렉터리의 내용을 확인해 봅시다. `ls -al` (실습)

이 명령어는 현재 위치의 모든 파일과 디렉터리를 상세 정보와 함께 보여줍니다. 출력된 목록을 보면 다음과 같은 형식의 줄들을 볼 수 있습니다.

`drwxr-xr-x 23 root root 4096 9월 12 10:30 .`

`lrwxrwxrwx 1 root root 7 9월 12 10:20 bin -> usr/bin`

* **첫 글자 (파일 종류)**: `d`는 디렉터리, `l`은 **심볼릭 링크(Symbolic Link)**를 의미합니다. 심볼릭 링크는 Windows의 '바로 가기'와 같은 개념으로, 실제 경로는 `/usr/bin`이지만 루트에서 `bin`으로 바로 접근할 수 있게 연결해 줍니다.
* **권한**: `rwx`는 각각 읽기(Read), 쓰기(Write), 실행(Execute) 권한을 나타냅니다.
* **소유자/그룹**: 현재 디렉터리의 모든 파일과 디렉터리가 `root` 소유임을 알 수 있습니다.

이제 다시 여러분의 홈 디렉터리로 돌아가 봅시다. `cd` (실습)

어느 위치에 있든 `cd` 명령어만 입력하면 자신의 홈 디렉터리(`~`)로 즉시 이동합니다. 여기서 다시 `ls -al`을 실행하면, 파일 소유자가 `root`가 아닌 여러분이 생성한 사용자 계정으로 표시되는 것을 볼 수 있습니다.

파일 시스템 탐색에는 절대 경로 외에 **상대 경로**도 사용됩니다.

* `cd .`: 현재 디렉터리를 의미합니다. (위치 변화 없음) (실습)
* `cd ..`: 현재 위치의 상위(부모) 디렉터리로 이동합니다. (실습)
* `cd /etc`: `/`(루트) 아래에 있는 `etc` 디렉터리로 이동하는 절대 경로 방식입니다. (실습)

Linux는 Windows와 달리 모든 장치(HDD, CD-ROM 등)를 파일 시스템의 일부로 취급하며, 이를 사용하기 위해 특정 디렉터리에 연결하는 **마운트(mount)** 과정이 필요합니다. 우리가 설치 시 사용한 ISO 파일도 가상의 CD-ROM 장치를 `/media` 같은 곳에 마운트하여 사용한 것입니다.

`/boot` 디렉터리에는 Linux 부팅에 필요한 커널 파일 등이 저장되어 있습니다. 우리는 설치 시 자동 파티션 설정을 사용했기 때문에 Ubuntu가 알아서 `/boot` 파티션을 만들었지만, 수동 설치 시에는 사용자가 직접 파티션(루트, 부트, 스왑 등)을 나누고 크기를 할당해야 합니다.

`sudo` 명령어는 매우 강력하고 위험하므로 사용할 때 각별한 주의가 필요합니다. `sudo`는 'superuser do'의 약자로, 일반 사용자가 `root` 관리자의 권한을 빌려 명령을 실행하게 해줍니다. 만약 `sudo rm -rf /` 와 같은 명령어를 실행하면 시스템 전체가 복구 불가능하게 삭제될 수 있습니다. `sudo`를 사용하여 시스템 파일을 변경하거나 삭제할 때는 그 결과가 무엇일지 두세 번 고민해야 합니다.

GNOME 데스크톱 환경에서는 Windows처럼 GUI로 파일 탐색이 가능합니다. '홈' 아이콘을 클릭하여 파일 관리자를 열 수 있습니다. (실습) 가끔 VM 환경에서 마우스 클릭이 되지 않을 때가 있는데, 이는 마우스 제어권이 호스트 OS(Windows)에 있기 때문입니다. 이때는 `Ctrl` + `Alt` 키를 함께 누르면 제어권이 게스트 OS(Ubuntu)로 전환됩니다.

### 1. 한 줄 요약

Linux 터미널을 이용해 파일 시스템의 절대/상대 경로 개념을 익히고, `ls -al` 명령으로 파일 권한과 소유권, 심볼릭 링크를 이해하며, `sudo` 명령어의 위험성을 배웁니다.

---
### 2. 핵심 TL;DR
* **터미널(Terminal)**: Linux 시스템과 상호작용하는 기본적인 명령줄 인터페이스(CLI)로, 대부분의 작업을 이곳에서 수행합니다.
* **파일 시스템 경로**: 파일 위치를 나타내는 주소이며, 최상위(`/`)에서 시작하는 **절대 경로**와 현재 위치(`.`, `..`)를 기준으로 하는 **상대 경로**가 있습니다.
* **핵심 탐색 명령어**: `cd`는 디렉터리를 이동하고, `ls -al`은 현재 디렉터리의 파일과 하위 디렉터리 목록을 권한, 소유자 등 상세 정보와 함께 보여줍니다.
* **`ls -al` 출력 이해**: 첫 글자는 파일 종류(`d`: 디렉터리, `l`: 심볼릭 링크)를, 이어지는 9자는 소유자/그룹/기타 사용자의 읽기(`r`), 쓰기(`w`), 실행(`x`) 권한을 나타냅니다.
* **심볼릭 링크(Symbolic Link)**: 원본 파일을 가리키는 포인터로, Windows의 '바로 가기'와 유사하여 긴 경로를 단축하는 데 사용됩니다.
* **`sudo` 명령어**: 'superuser do'의 약자로, 일반 사용자가 `root` 관리자의 권한을 일시적으로 빌려 명령을 실행하게 해주는 강력하지만 매우 위험한 명령어입니다.
* **가상 머신과 레거시 호환성**: 가상 머신(VM)은 구형 OS(예: Windows XP)에서만 동작하는 오래된 프로그램을 최신 하드웨어에서 구동시키는 중요한 해결책이 됩니다.

---
### 3. 표현 = 표준 용어
* **터미널 (Terminal)**: 사용자가 텍스트 기반 명령어를 입력하여 시스템과 소통하는 인터페이스.
* **절대 경로 (Absolute Path)**: 파일 시스템의 최상위 디렉터리(`/`, root)부터 시작하는 전체 경로.
* **상대 경로 (Relative Path)**: 현재 작업 디렉터리를 기준으로 대상 파일까지의 경로. (`.`은 현재, `..`은 상위 디렉터리)
* **루트 디렉터리 (root directory, `/`)**: 파일 시스템 계층 구조의 최상위 시작점.
* **홈 디렉터리 (home directory, `~`)**: 각 사용자의 개인 파일이 저장되는 기본 디렉터리.
* **파일 권한 (File Permissions)**: 파일이나 디렉터리에 대해 읽기(`r`), 쓰기(`w`), 실행(`x`) 작업을 할 수 있는 권한.
* **심볼릭 링크 (Symbolic Link)**: 다른 파일이나 디렉터리를 가리키는 특별한 종류의 파일.

---
### 4. 정석 보강 (canon-std)
**Linux 파일 시스템 경로**는 특정 파일이나 디렉터리의 위치를 지정하는 유일한 주소 체계입니다. **절대 경로**는 항상 슬래시(`/`)로 시작하며, 루트 디렉터리부터 목표까지의 전체 경로를 명시하므로 현재 위치와 상관없이 항상 동일한 대상을 가리킵니다(예: `/home/user/documents`). 반면, **상대 경로**는 현재 작업 디렉터리(`pwd` 명령으로 확인)를 기준으로 하며, `.`(현재 디렉터리)와 `..`(상위 디렉터리)를 사용하여 경로를 표현합니다(예: `../pictures`). 스크립트 작성 시 이식성을 높이거나 가까운 파일을 빠르게 참조할 때 유용합니다.

---
### 5. 실수·함정
* **`/` (루트 디렉터리)**와 **`/root` (root 사용자의 홈 디렉터리)**를 혼동하는 것.
* 불필요하게 모든 명령어에 **`sudo`를 붙여** 실행하는 습관.
* **심볼릭 링크 파일을 삭제**하면 원본 파일도 삭제될 것이라고 오해하는 것. (링크만 사라짐)
* 가상 머신에서 마우스 포인터가 먹통일 때 **`Ctrl` + `Alt` 키**로 호스트-게스트 전환을 시도하지 않는 것.
* `sudo`와 `rm -rf` 명령어를 조합했을 때의 **파괴적인 결과**를 간과하는 것.

## **2025-09-12, 3교시 — 개선본**

Linux 터미널에서 명령어의 사용법이 궁금할 때는 **매뉴얼 페이지**를 활용할 수 있습니다. 예를 들어, `man ls`를 입력하면 `ls` 명령어에 대한 상세한 설명이 나타납니다. (실습) 매뉴얼 페이지 내에서는 스페이스바를 누르면 한 페이지씩, 엔터키를 누르면 한 줄씩 아래로 이동할 수 있으며, `q` 키를 누르면 빠져나올 수 있습니다. (실습)

Linux 시스템은 본래 다중 사용자가 원격으로 접속하여 사용하는 **서버**를 목적으로 설계되었습니다. 이는 개인이 외부에서 NAS(Network Attached Storage)에 접속하여 파일을 관리하는 것과 유사한 개념입니다. 사용자는 계정 정보만 있으면 부산에 있는 서버에 수원에서 원격으로 접속하여 작업을 수행할 수 있습니다.

오늘은 Windows 환경에서 이 원격 접속을 실습해 보겠습니다. 이를 위해 **SSH(Secure Shell)** 프로토콜을 사용하며, 접속 클라이언트로는 **PuTTY**라는 프로그램을 사용할 것입니다.

먼저, Ubuntu VM에 SSH 서버를 설치해야 합니다. 터미널에 다음 명령어를 입력하세요. `sudo apt install ssh` (실습)

암호를 묻는 메시지가 나타나면 여러분의 사용자 계정 암호를 입력하면 됩니다. (실습) 설치가 진행될 것입니다.

SSH 서버 설치가 완료되면, 이제 접속할 클라이언트를 준비합니다. 가상 머신 창을 잠시 내려두고 **호스트 OS인 Windows**로 나와, 웹 브라우저를 열어 **PuTTY**를 검색하고 다운로드하여 설치합니다. (실습)

다시 Ubuntu VM으로 돌아와, 원격으로 접속할 서버의 IP 주소를 확인해야 합니다. IP 주소를 확인하는 `ifconfig` 명령어는 기본적으로 설치되어 있지 않으므로, 관련 도구를 먼저 설치해야 합니다. `sudo apt install net-tools` (실습)

설치가 완료되면 `ifconfig`를 입력합니다. (실습) 출력된 내용 중 `ens33` 또는 유사한 항목 아래에 있는 `inet` 주소(예: `192.168.92.168`)가 현재 가상 머신의 IP 주소입니다.

이제 마지막 단계입니다. Windows에서 PuTTY를 실행하고, 'Host Name (or IP address)' 필드에 방금 확인한 Ubuntu VM의 IP 주소를 입력한 후 'Open' 버튼을 클릭합니다. (실습) 검은 터미널 창이 나타나면서 'login as:' 프롬프트가 보이면, 여러분의 Ubuntu 사용자 이름과 암호를 입력하여 로그인합니다. (실습) 이제 Windows의 PuTTY 창에서 실행하는 모든 명령어는 원격으로 Ubuntu VM에서 실행됩니다. 접속을 종료하려면 `exit`를 입력하면 됩니다. (실습)

방금 우리가 한 작업은 원격 접속 프로토콜인 **텔넷(Telnet)**과 유사하지만, 통신 내용이 암호화되는 **SSH**를 이용한 것입니다. 텔넷은 23번 포트를, SSH는 22번 포트를 기본으로 사용하며, SSH가 훨씬 안전하여 현재 표준으로 사용됩니다. 이처럼 원격으로 서버를 관리하고 개발하는 것은 시스템 관리자(SM)나 개발자(SI)의 기본적인 업무 중 하나입니다.

### 1. 한 줄 요약

Linux 서버에 SSH 서비스를 설치하고, Windows에서 PuTTY 클라이언트를 사용하여 VM의 IP 주소로 원격 접속함으로써 클라이언트-서버 모델의 기본을 실습합니다.

---
### 2. 핵심 TL;DR
* **`man` 페이지**: `man ls`와 같이 명령어를 입력하면, 터미널에서 해당 명령어의 공식 사용 설명서를 바로 확인할 수 있는 기능입니다.
* **원격 접속(Remote Access)**: Linux가 다중 사용자 서버로 기능하기 위한 핵심 개념으로, 사용자가 물리적으로 멀리 떨어진 서버에 네트워크를 통해 접속하여 제어하는 것을 의미합니다.
* **SSH (Secure Shell)**: 원격 접속 시 모든 통신 내용을 암호화하여 중간에서 데이터를 가로채도 안전하게 보호하는 보안 프로토콜입니다. 현재 원격 터미널 접속의 표준입니다.
* **클라이언트-서버 모델**: 이번 실습에서는 **PuTTY(클라이언트)**가 설치된 Windows PC가 **SSH 서버**가 설치된 Ubuntu VM(서버)에 접속하는 역할을 수행합니다.
* **IP 주소와 `ifconfig`**: 서버에 접속하기 위해 필요한 고유한 네트워크 주소로, `ifconfig` 명령어를 통해 현재 시스템의 IP 주소를 확인할 수 있습니다. (`net-tools` 패키지 필요)
* **`apt` 패키지 관리자**: `sudo apt install <패키지명>` 형태로 Ubuntu에 SSH 서버, `net-tools` 등 새로운 소프트웨어를 설치하는 도구입니다.
* **네트워크 접근 제어**: 서버 관리자는 방화벽을 통해 특정 포트(예: SSH의 22번 포트)를 차단하여 원격 접속을 막을 수 있습니다. 이 경우, 서버실에 직접 들어가는 **물리적 접근** 외에는 제어할 방법이 없습니다.

---
### 3. 표현 = 표준 용어
* **`man` 페이지 (man page)**: Unix-like 시스템에서 제공하는 온라인 명령어 매뉴얼.
* **원격 접속 (Remote Access)**: 네트워크를 통해 다른 컴퓨터에 연결하여 제어하는 것.
* **SSH (Secure Shell)**: 암호화 기술을 사용해 원격지 컴퓨터에 안전하게 접속하기 위한 프로토콜. (기본 포트: 22)
* **PuTTY**: Windows에서 사용되는 대표적인 SSH 및 Telnet 클라이언트 프로그램.
* **클라이언트-서버 모델 (Client-Server Model)**: 서비스를 요청하는 클라이언트와 서비스를 제공하는 서버로 역할을 나누는 네트워크 아키텍처.
* **IP 주소 (IP Address)**: 네트워크에 연결된 각 장치를 식별하기 위한 고유한 번호.
* **`ifconfig`**: 네트워크 인터페이스의 설정 정보를 확인하고 변경하는 명령어.
* **Telnet**: 암호화 기능이 없는 초기의 원격 접속 프로토콜. (기본 포트: 23)

---
### 4. 정석 보강 (canon-std)
**SSH (Secure Shell)**는 안전하지 않은 네트워크를 통해 원격지 컴퓨터를 안전하게 제어하기 위한 암호화 기반 네트워크 프로토콜입니다. 클라이언트-서버 구조로 동작하며, **SSH 클라이언트**(예: PuTTY)가 **SSH 서버**(예: Ubuntu의 OpenSSH-server)에 접속을 요청합니다. 연결 과정에서 **공개키 암호 방식**을 사용하여 서버의 신원을 인증하고, 이후 세션 동안의 모든 데이터(로그인 정보, 명령어, 출력 등)를 암호화하여 도청(eavesdropping)이나 데이터 변조(tampering)로부터 통신을 보호합니다. 이 강력한 보안 기능 덕분에 기존의 평문 전송 방식인 **Telnet**을 완전히 대체하게 되었습니다.

---
### 5. 실수·함정
* Ubuntu VM에 **SSH 서버를 설치하지 않고** PuTTY로 접속을 시도하는 것.
* PuTTY에 가상 머신의 **IP 주소를 잘못 입력**하는 것.
* **PuTTY를 Ubuntu 안에 설치**하려고 하거나, **SSH 서버를 Windows에 설치**하려는 등 클라이언트와 서버의 역할을 혼동하는 것.
* `ifconfig` 명령어가 기본적으로 설치되어 있지 않다는 사실을 모르고, **`net-tools` 패키지를 먼저 설치**하지 않는 것.
* **Telnet과 SSH를 동일한 것**으로 생각하는 것. (SSH는 Telnet의 보안이 강화된 현대적인 대체 프로토콜임)

## **2025-09-12, 3교시 — 질문**

**[Q1] Linux 터미널에서 모르는 명령어의 사용법을 확인하는 가장 기본적인 방법은 무엇인가? | #셸/리다이렉션/FD**
* **모범답(강의 기준):** `man <명령어>` (예: `man ls`)를 입력하면 해당 명령어의 공식 매뉴얼 페이지를 바로 볼 수 있습니다. 매뉴얼 안에서는 스페이스바로 페이지를 넘기고 `q` 키로 종료합니다.
* **정석체크(면접 30초):** `man`은 시스템에 설치된 매뉴얼 페이지를 보여주는 명령어입니다. 명령어의 구문, 옵션, 관련 파일 등 상세한 정보를 제공하므로, 인터넷 검색 전에 가장 먼저 확인해야 할 공식 문서(Official Document)입니다.

---
**[Q2] 원격지에 있는 Linux 서버에 안전하게 접속하기 위해 SSH를 사용하는 이유는 무엇인가? | #네트워킹/SSH**
* **모범답(강의 기준):** SSH는 'Secure Shell'의 약자로, 로그인 정보와 모든 통신 내용을 암호화하여 전송하기 때문입니다. 이를 통해 Telnet과 같은 기존의 비암호화 방식과 달리, 중간에서 데이터를 가로채도 내용을 알 수 없어 안전합니다.
* **정석체크(면접 30초):** SSH는 클라이언트와 서버 간의 모든 트래픽을 암호화하여 기밀성(Confidentiality)과 무결성(Integrity)을 보장하는 보안 프로토콜입니다. 또한, 공개키 기반 인증을 통해 서버와 클라이언트의 신원을 확인하므로, 중간자 공격(Man-in-the-Middle Attack)을 방지할 수 있습니다.

---
**[Q3] 이번 원격 접속 실습에서 Windows의 PuTTY와 Ubuntu의 SSH 서비스는 각각 어떤 역할을 하는가? | #네트워킹/SSH**
* **모범답(강의 기준):** Windows에 설치된 PuTTY는 접속을 요청하는 '클라이언트'의 역할을 하고, Ubuntu에 설치된 SSH 서비스는 접속 요청을 받아들여 서버를 제어하게 해주는 '서버'의 역할을 합니다.
* **정석체크(면접 30초):** 이는 전형적인 클라이언트-서버 모델입니다. SSH 서버(sshd 데몬)는 22번 포트에서 클라이언트의 접속 요청을 항상 기다리고(listen), PuTTY와 같은 SSH 클라이언트는 서버의 IP 주소와 포트 정보를 이용해 TCP 연결을 수립한 후 인증 절차를 거쳐 원격 세션을 시작합니다.

---
**[Q4] `ifconfig` 명령어는 무엇을 위해 필요하며, 왜 `net-tools` 패키지를 먼저 설치해야 하는가? | #네트워킹/SSH**
* **모범답(강의 기준):** `ifconfig`는 서버의 IP 주소를 확인하기 위해 필요합니다. 최신 Ubuntu 버전에서는 이 명령어가 기본으로 포함되어 있지 않아, 해당 명령어가 포함된 `net-tools`라는 패키지를 `apt`로 먼저 설치해야 사용할 수 있습니다.
* **정석체크(면접 30초):** `ifconfig`는 네트워크 인터페이스의 정보를 확인하고 설정하는 전통적인 도구입니다. 최신 Linux 배포판에서는 `ip` 명령어가 이를 대체하고 있지만(`ip addr show`), 여전히 널리 사용되므로 `net-tools` 패키지를 설치하여 호환성을 확보하는 경우가 많습니다.

* **단계요약**: 1) 터미널에 `man ls`를 입력하여 `ls` 명령어의 매뉴얼을 엽니다. 2) 스페이스바로 페이지를 내리고, `q` 키를 눌러 종료합니다.

---
**[S2] SSH 원격 접속 설정 및 실행** — Ubuntu VM에 SSH 서버를 구축하고, Windows Host에서 PuTTY 클라이언트를 이용해 원격으로 접속하는 전체 과정을 실습합니다.
* **단계요약**: 1) **[Ubuntu]** `sudo apt install ssh`를 입력하여 SSH 서버 설치 2) **[Ubuntu]** `sudo apt install net-tools`를 입력하여 네트워크 도구 설치 3) **[Ubuntu]** `ifconfig`를 실행하여 `inet` IP 주소 확인 및 기록 4) **[Windows]** PuTTY 다운로드 및 설치 5) **[Windows]** PuTTY 실행 후 'Host Name'에 확인한 IP 주소 입력 및 접속 6) PuTTY 창에 Ubuntu 사용자 이름과 암호를 입력하여 로그인 7) `exit`를 입력하여 원격 접속 종료.
* **⚠️ 주의**: SSH 서버는 Ubuntu(게스트)에, PuTTY는 Windows(호스트)에 설치해야 합니다. 역할을 혼동하지 않도록 주의합니다.
