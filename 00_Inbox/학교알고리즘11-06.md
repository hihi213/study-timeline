## Topic 1. 기수 정렬 (Radix Sort) 개요

### 1. 🏗️ 빌드업 (Why & Context)

> "모든 상황에 쓸 수 있는 범용 정렬은 아니지만, 조건만 맞으면 가장 빠른 정렬"

- **기존 방식의 한계:** 퀵 정렬, 합병 정렬 등은 **비교 연산(Comparison)** 을 필수로 하며, 이론적 하한선이 $O(N \log N)$이다.
- **발상의 전환:** "비교하지 않고 정렬할 수는 없을까?" → 데이터의 **자릿수(Digit)** 값을 그대로 활용하여 버킷에 담았다 빼는 방식 고안.

### Concept

- **정의:** 레코드 키의 값(자릿수)을 이용하여 해당 버킷에 원소를 분배(Distribute)하고 순서대로 수집(Collect)하는 과정을 반복하는 정렬 기법.
- **시간 복잡도:** $O(dN)$ (d: 자릿수, n: 데이터 개수).
    - 자릿수가 작다면 사실상 선형 시간($O(N)$)에 가까운 매우 빠른 속도를 자랑한다.
- **제약 조건 (Trade-off):**
    1. **키의 길이가 동일해야 함:** 자릿수가 일정하지 않으면 적용이 어렵다.
    2. **특정 데이터 타입:** 정수나 문자열처럼 자릿수/문자 위치가 명확한 경우에만 사용 가능하다. (실수는 적용 난해)
    3. **추가 메모리 필요:** 각 자릿수 값을 담을 **버킷(Bucket)** 공간이 추가로 필요하다. (공간 복잡도 증가)

## Topic 2. 기수 정렬 메커니즘 (LSD & Buckets)

### 1. 🏗️ 빌드업 (Logic)

- **접근법:** 100자리 숫자를 정렬하려면 버킷이 몇 개 필요한가?
    - 0~99… 까지 만들면 메모리가 부족하다.
    - 대신 **0~9까지 10개의 버킷**만 만들고, 낮은 자릿수부터 높은 자릿수까지 반복해서 재활용하는 방식을 사용한다.
- **순서의 중요성 (LSD vs MSD):**
    - 일반적으로 **LSD (Least Significant Digit)** 방식을 사용한다. 즉, **가장 낮은 자릿수(1의 자리)** 부터 정렬하고, 점차 높은 자릿수로 이동해야 한다.
    - _이유:_ 높은 자릿수(예: 10의 자리)를 먼저 정렬하면, 나중에 1의 자리를 정렬할 때 이미 정렬된 10의 자리 순서가 섞여버린다. 반대로 LSD는 낮은 자릿수의 정렬 상태를 유지하며(Stable) 높은 자릿수 정렬을 수행한다.
        

### Concept & Process (예시: 10진수)

1. **준비:** 0부터 9까지 인덱스를 가진 10개의 **버킷(Queue)** 준비.
2. **1단계 (1의 자리):** 각 숫자의 1의 자리를 보고 해당 버킷에 넣음(Enqueue) → 버킷 순서대로 뺌(Dequeue).
3. **2단계 (10의 자리):** 1단계 결과 리스트에서 10의 자리를 보고 해당 버킷에 넣음 → 버킷 순서대로 뺌.
4. **반복:** 최대 자릿수($d$)만큼 반복하면 최종 정렬 완료.
    

### 자료구조 (Why Queue?)

- **핵심 질문:** 왜 버킷을 **큐(Queue)**로 구현해야 하는가?
- **이유:** **안정 정렬(Stable Sort)** 속성을 유지하기 위함이다.
    - 같은 자릿수 값을 가진 데이터들 사이에서도, **이전 단계(더 낮은 자릿수)에서 정렬된 순서**가 유지되어야 한다. 따라서 먼저 들어온 데이터가 먼저 나가는 **FIFO(First-In First-Out)** 구조가 필수적이다.

## Topic 3. 32비트 정수 최적화 구현

### 1. 🏗️ 빌드업 (Optimization)

- 컴퓨터는 2진수를 사용하므로 버킷 2개(0, 1)만 있으면 된다.
- 그러나 32비트 정수(`int`)를 1비트씩(버킷 2개) 처리하면 **32번의 루프(Pass)**를 돌아야 한다. 이는 비효율적이다.

### Concept

- **8비트 단위 처리 (256 Buckets):**
    - 32비트를 8비트씩 4덩어리로 쪼갠다. ($2^8 = 256$)
    - 버킷을 **256개** 만들면, 루프를 **4번(Pass)** 만 돌면 정렬이 완료된다.
    - **효과:** 메모리를 조금 더 쓰고(버킷 256개), 속도를 비약적으로 향상시킨다. (비트 연산 활용)

### Code 구현 (Structure Idea)

```C
#define BUCKETS 10 // 10진수의 경우
#define DIGITS 4   // 최대 자릿수

// 기수 정렬 의사 코드 (LSD 방식)
void radix_sort(int list[], int n) {
    Queue buckets[BUCKETS]; // 큐 배열 생성
    int factor = 1; // 1, 10, 100… 자릿수 계산용
	
    // 자릿수만큼 반복 (d회)
    for (int d = 0; d < DIGITS; d++) {
        // 1. 분배 (Distribute)
        for (int i = 0; i < n; i++) {
	        // 현재 자릿수의 값에 해당하는 버킷에 넣음
            int digit = (list[i] / factor) % 10;
            enqueue(&buckets[digit], list[i]);
        }
			
        // 2. 수집 (Collect)
        int i = 0;
        for (int b = 0; b < BUCKETS; b++) {
            while (!is_empty(&buckets[b])) {
                list[i++] = dequeue(&buckets[b]);
            }
        }
        
        factor *= 10; // 다음 자릿수로 이동
    }
}
```

## Topic 2. CS Basics: 부동소수점 (Floating Point)

### 1. 🏗️ 빌드업 (Why & Context)

> "기수 정렬은 왜 실수(Float)에는 적용하기 어려운가? 컴퓨터는 실수를 어떻게 저장하는가?"

- **문제 제기:** 정수는 비트 패턴이 값의 크기와 직결되지만, 실수는 **IEEE 754 표준**에 따라 부호, 지수, 가수로 나뉘어 저장되므로 단순한 자릿수 비교가 불가능하다.

### Concept: 부동소수점 (Floating Point) 이슈

- **저장 방식 (IEEE 754):** `부호(1bit)` + `지수(8bit/11bit)` + `가수(23bit/52bit)`
- **정밀도 문제 (Precision):**
    - $0.1$을 2진수로 표현하면 무한 소수(순환 소수)가 된다. ($0.00011001100…$)
    - 컴퓨터는 이를 유한한 비트에 욱여넣으면서 잘라내므로, $0.1 + 1.1 \neq 1.2$와 같은 오차가 발생한다.
- **기수 정렬 적용의 어려움:**
    - 부동소수점은 비트 전체를 단순 정수처럼 해석해서 정렬하기 어렵다 (지수부와 가수부의 가중치가 다름).
    - 음수 처리(부호 비트) 및 지수 바이어스(Bias) 처리가 복잡하다.

## Topic 3. 정렬 알고리즘 총정리

### 1. 정렬 알고리즘 성능 비교

|**알고리즘**|**최선(Best)**|**평균(Avg)**|**최악(Worst)**|**특징**|
|---|---|---|---|---|
|**삽입 정렬**|$O(N)$|$O(N^2)$|$O(N^2)$|이미 정렬된 경우 가장 빠름.|
|**선택 정렬**|$O(N^2)$|$O(N^2)$|$O(N^2)$|데이터 이동 횟수는 적지만 비교 횟수 많음.|
|**버블 정렬**|$O(N^2)$|$O(N^2)$|$O(N^2)$|구현 단순, 실제 성능은 가장 낮음.|
|**퀵 정렬**|$O(N \log N)$|$O(N \log N)$|**$O(N^2)$**|일반적으로 가장 빠름. **(주의) 오름/내림차순 정렬 시 최악 성능.**|
|**기수 정렬**|$O(dN)$|$O(dN)$|$O(dN)$|비교 없음, 가장 빠르나 메모리 소모 큼.|

### 2. 결론 (Case by Case)

- "무조건 퀵 정렬이 좋은 게 아니다."
- 데이터가 이미 어느 정도 정렬되어 있다면 **삽입 정렬**이, 정수 데이터가 많고 메모리가 충분하다면 **기수 정렬**이 유리하다. **Case by Case**가 핵심.
- 예: 한글 사전 편찬(Merge Sort 적합), 거의 정렬된 데이터(Insertion Sort 적합), 일반적인 대량 데이터(Quick Sort 적합).

### 💡 Interview

> [!faq]- Q. 기수 정렬(Radix Sort)이 $O(N)$의 시간 복잡도를 가짐에도 불구하고 퀵 정렬보다 범용적으로 쓰이지 않는 이유는?
>
> 🗣️ 핵심 답변
>
> 기수 정렬은 데이터 타입이 자릿수가 있는 정수나 문자열로 제한되며, 기수(Radix) 크기만큼의 추가 메모리(Bucket) 가 필요하기 때문입니다. 또한 데이터의 길이가 길어질 경우 $O(dN)$에서 $d$값이 커져 계수가 붙기 때문에, 일반적인 상황에서는 캐시 지역성이 좋고 제자리 정렬(In-place Sort)이 가능한 퀵 정렬이 더 효율적입니다.
>
> **📚 꼬리질문 대비**
>
> - **Q. 실수(Float)도 기수 정렬이 가능한가?**
>     
>     - 불가능하진 않으나, IEEE 754 부동소수점 표준의 지수/가수 구조와 부호 비트 처리를 위한 복잡한 전처리 과정이 필요하여 효율이 떨어집니다.
>         
> - **Q. 버킷 내부 자료구조로 Stack을 쓰면 안 되는 이유는?**
>     
>     - 스택(LIFO)을 사용하면 입력 순서가 역순이 되어 **정렬의 안정성(Stability)** 이 깨지기 때문입니다. 이전 자릿수에서 정렬된 순서를 유지하려면 반드시 큐(FIFO)를 써야 합니다.
>         

> [!faq]- Q. 컴퓨터에서 $0.1 + 0.2 == 0.3$ 이 False인 이유는 무엇인가? (카카오 기술면접 기출)
>
> 🗣️ 핵심 답변
>
> 10진수 0.1과 0.2는 2진수로 변환 시 무한 순환 소수가 됩니다. 컴퓨터의 부동소수점(Floating Point) 방식은 가수부(Mantissa)의 비트 수 제한(32bit 기준 23bit)으로 인해 값을 잘라내어 근사치로 저장하므로, 이를 더한 결과가 정확히 0.3과 일치하지 않는 미세한 오차가 발생하기 때문입니다.
>
> **📚 꼬리질문 대비**
>
> - **Q. 그럼 이 문제를 코딩에서 어떻게 해결해야 하는가?**
>     
>     - `Epsilon`이라는 아주 작은 임계값을 정의하여, 두 수의 차이가 엡실론보다 작은지 비교하는 방식을 사용하거나, 금융권 등 정밀도가 중요한 분야에서는 `BigDecimal`(Java) 같은 고정 소수점 라이브러리를 사용합니다.

## Topic 1. 그래프의 정의와 모델링 (Graph & Modeling)

### 1. 🏗️ 빌드업 (Why & Context)

> "선형 리스트나 트리(Tree)만으로는 표현할 수 없는 복잡한 관계(N:M)는 어떻게 다룰 것인가?"

- **현실의 복잡성:** 수강 신청 시의 선수 과목 관계(Prerequisite), 지하철 노선도, 도시 간의 도로망, 전기 회로, OS의 상태 천이도(State Transition) 등은 단순한 순서나 계층 구조가 아니다.
- **필요성:** 현실 세계의 객체(Object)와 그 객체들 간의 연결 관계(Relationship)를 컴퓨터 세계로 옮겨오기 위한 **모델링(Modeling)** 도구가 필요하다.
    

### 2. Concept

- **정의:** 객체를 나타내는 **정점(Vertex, Node)** 과 객체 사이의 연결을 나타내는 **간선(Edge, Link)** 의 집합으로 구성된 비선형 자료구조.
    - 수식 표현: $G = (V, E)$
        - $V(G)$: 정점들의 집합
        - $E(G)$: 간선들의 집합
- **모델링(Modeling)의 본질:**
    - 현실 세계의 문제를 컴퓨터가 이해하고 해결할 수 있는 형태로 추상화하는 과정.
    - 예: "모든 다리를 한 번씩만 건너 돌아올 수 있는가?" (현실) $\rightarrow$ "모든 간선을 중복 없이 순회하는 경로가 존재하는가?" (수학/컴퓨터 모델)
    - **핵심:** 모델링이 정확해야 알고리즘의 결과가 현실 문제를 해결할 수 있다. 이를 증명하는 도구가 바로 **수학**이다.
        

### 3. Real-world Examples

- **선수 과목:** 방향성이 있는 그래프 (A를 들어야 B를 들을 수 있음).
- **내비게이션:** 교차로(Node)와 도로(Edge), 그리고 거리/시간(Weight).
- **전기 회로:** 소자(Node)와 와이어링(Edge).
- **운영체제(OS):** 프로세스 상태 천이, 자원 할당 그래프.

## Topic 2. 그래프의 구조와 오일러 정리

### 1. 🏗️ 빌드업 (Why & Context)

> "그래프 이론은 어디서 시작되었는가?"

- **쾨니히스베르크의 다리 문제:** 수학자 오일러(Euler)는 "7개의 다리를 한 번씩만 건너서 원래 위치로 돌아올 수 있는가?"라는 문제를 해결하기 위해 지도를 도식화(모델링)했다.
    

### 2. Concept

- **오일러 경로 (Eulerian Path):** 그래프의 모든 간선을 한 번씩만 통과하는 경로.
- **오일러의 증명:**
    - 모든 정점에 연결된 간선의 개수(차수, Degree)가 **짝수(Even)** 일 때만 출발점으로 돌아오는 경로가 존재한다.
    - 홀수 차수를 가진 정점이 있다면 들어갔다가 나올 수 없는 상황이 발생한다.
        

### 3. 시각적 표현

- **정점(Vertex):** 원으로 표현.
- **간선(Edge):** 정점을 연결하는 선으로 표현.
- **주의사항:** 그래프의 시각적 배치(위치)가 달라도, **정점과 간선의 연결 관계(집합)가 동일하면 같은 그래프**이다. 시각적 표현은 이해를 돕기 위한 수단일 뿐이다.

## Topic 3. 그래프의 유형 (Types of Graphs)

### 1. 무방향 그래프 (Undirected Graph)

- **정의:** 간선에 방향이 없는 그래프. 양방향 통행 가능.
- **표현:** $(A, B)$와 $(B, A)$는 동일한 간선.
- 최대 간선 수 (완전 그래프): $n$개의 정점이 있을 때:
    
    $$\frac{n(n-1)}{2}$$
    
    - (이유: 모든 정점이 서로 연결되나, 양방향이므로 중복을 2로 나눔)
        

### 2. 방향 그래프 (Directed Graph)

- **정의:** 간선에 방향이 존재하는 그래프 (일방통행).
- **표현:** $<A, B> \neq <B, A>$.
    - $<A, B>$: A에서 출발하여 B로 감.
    - **Tail (꼬리):** 시작점 ($V_i$)
    - **Head (머리):** 도착점 ($V_j$) $\rightarrow$ 화살표의 머리 부분.
- 최대 간선 수:
    
    $$n(n-1)$$
    
    - (이유: 왕복이 서로 다른 간선이므로 2로 나누지 않음)
        

### 3. 가중치 그래프 (Weighted Graph, Network)

- **정의:** 간선에 비용, 거리, 시간 등의 **가중치(Weight)** 가 할당된 그래프.
- **활용:** 단순한 '연결 유무'를 넘어 '연결 강도'나 '비용'을 분석.
    - 예: 최단 경로(거리 우선) vs 최소 비용(통행료 우선).
    - 예: 네트워크 대역폭(전용선 vs 공용 인터넷).
- **의사결정:** 가중치를 통해 더 복잡한 문제(Time vs Cost Trade-off)를 해결하는 알고리즘(예: 다익스트라)의 기초가 됨.

### 4. Code 구현 (C언어 - 구조체 정의)

```C

#include <stdlib.h>

#define MAX_VERTICES 50

// 1. 인접 행렬(Adjacency Matrix) 방식

    int adj_mat[MAX_VERTICES][MAX_VERTICES];
} GraphMatrix;

// 2. 인접 리스트(Adjacency List) 방식
typedef struct GraphNode {
    int vertex;
    struct GraphNode* link;
} GraphNode;

typedef struct GraphList {
    int n; // 정점의 개수
    GraphNode* adj_list[MAX_VERTICES]; // 각 정점의 헤드 포인터 배열
```

## 기타 핵심 (Etc & Tips) - 알고리즘 2025-11-06

- **트리(Tree)와 그래프의 관계:** 트리는 그래프의 특수한 형태(부분 집합)이다. 사이클(Cycle)이 없고, 계층적 구조를 가지며 $N$개의 노드에 대해 항상 $N-1$개의 간선을 가진다.
- **모델링의 중요성:** 대학원/연구 레벨에서는 현실 문제를 수학적으로 모델링하고, 이를 코드로 구현하여 증명하는 능력이 필수적이다.
    

### 💡 Interview

> [!faq]- Q. 그래프(Graph)와 트리(Tree)의 결정적인 차이점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 트리는 사이클(Cycle)이 없는 연결 그래프로, 계층(Hierarchical) 구조를 가지며 루트(Root)가 존재합니다. 반면 그래프는 사이클을 가질 수 있고, 부모-자식 관계가 없는 망(Network) 구조이며 루트 노드의 개념이 없습니다. 트리는 그래프의 특수한 부분 집합(DAG의 일종 등)으로 볼 수 있습니다.
>
> **📚 꼬리질문 대비**
>
> - **Q. 그래프를 구현하는 두 가지 방법(인접 행렬 vs 인접 리스트)의 장단점은?**
>     
>     - **인접 행렬:** 구현이 쉽고 두 정점의 연결 확인이 $O(1)$로 빠르지만, 희소 그래프(Sparse Graph)일 경우 메모리 낭비가 심합니다($O(V^2)$).
>         
>     - **인접 리스트:** 연결된 간선만 저장하므로 메모리가 효율적($O(V+E)$)이지만, 두 정점의 연결 여부를 확인하려면 리스트를 탐색해야 하므로 시간이 더 걸릴 수 있습니다.
>         

> [!faq]- Q. 방향 그래프에서 최대 간선 수가 $n(n-1)$인 이유는?
>
> 🗣️ 핵심 답변
>
> 방향 그래프에서는 하나의 정점에서 자기 자신을 제외한 나머지 $n-1$개의 정점으로 간선을 보낼 수 있습니다. 정점이 총 $n$개이므로, $n \times (n-1)$개의 간선이 존재할 수 있습니다. 무방향 그래프와 달리 $A \to B$와 $B \to A$가 서로 다른 간선이므로 2로 나누지 않습니다.
