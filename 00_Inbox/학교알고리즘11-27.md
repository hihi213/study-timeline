## Topic 1. MST 복습 & Greedy Algorithm

### 1. 🏗️ 빌드업 (Why & Context)

> **"그리디 알고리즘은 항상 최적해를 보장하는가?"**

- 지난 시간에 배운 **Kruskal**과 **Prim** 알고리즘은 모두 **탐욕 기법(Greedy Algorithm)**을 기반으로 한다.
- 하지만 모든 문제에서 눈앞의 최선(Greedy)이 전체의 최선(Global Optimum)이 되는 것은 아니다. 이를 증명하기 위해 **'동전 거스름돈 문제'** 를 반례로 든다.

### 2. Concept

#### 1) Greedy Algorithm (탐욕 기법)

- **정의:** 결정을 해야 할 때마다 **'그 순간에 가장 좋다고 생각하는 것'**을 해답으로 선택하는 방식.
- **특징:**
    - 계산 속도가 빠르고 직관적이다.
    - 항상 **최적해(Optimal Solution)**를 보장하지 않으므로 반드시 **검증**이 필요하다.
    - _참고:_ Kruskal과 Prim은 그리디를 사용하지만 수학적으로 최적해가 증명된 케이스다.
        

#### 2) 동전 거스름돈 예시 (반례 증명)

- **상황 A (우리나라 화폐):** 500원, 100원, 50원, 10원 단위.
    - 큰 단위가 작은 단위의 배수이므로 그리디 적용 시 최적해 보장.
- **상황 B (반례):** 500원, **400원**, 100원 단위가 있다고 가정.
    - **목표:** 800원 거슬러 주기.
    - **Greedy 접근:** 500원(1개) → 남은 300원은 100원(3개) ⇒ **총 4개**.
    - **최적해(Optimal):** 400원(2개) ⇒ **총 2개**.
    - **결론:** 그리디가 항상 최적의 동전 개수를 보장하지 않는다.

## Topic 2. 최단 경로(Shortest Path)와 그래프 표현

### 1. 🏗️ 빌드업 (Why & Context)

> **"지도에서 서울부터 부산까지 가는 길은 무수히 많다. 그중 가장 빠른 길을 어떻게 찾을까?"**

- MST(최소 신장 트리)는 모든 노드를 연결하는 것이 목적이었다면, **최단 경로**는 두 정점 사이의 **가중치 합이 최소**가 되는 경로를 찾는 것이 목적이다.
- 내비게이션(최단 시간, 최단 거리, 고속도로 우선 등)이나 지하철 환승 앱이 대표적인 응용 사례다.

### 2. Concept

#### 1) 가중치 인접 행렬 (Weighted Adjacency Matrix)

- 일반적인 그래프 표현과 달리, **연결되지 않음(No Edge)**을 표현할 때 주의가 필요하다.
- **일반 인접 행렬:** 연결 안 되면 `0`으로 표현.
- **가중치 인접 행렬:**
    - 연결 안 됨 $\rightarrow$ **$\infty$ (무한대)**. (0은 가중치가 0, 즉 거리가 없다는 뜻이 되므로 사용할 수 없음)
    - 자기 자신(Self-loop) $\rightarrow$ **$0$**.
        

#### 2) 최단 경로 알고리즘의 분류

- **Dijkstra (다익스트라):** **하나의 시작점** $\rightarrow$ 다른 모든 정점 (One-to-All). 음수 가중치 불가.
- **Floyd-Warshall (플로이드-워셜):** **모든 정점** $\rightarrow$ 모든 정점 (All-to-All).
- **Bellman-Ford (벨만-포드):** 음수 가중치가 있을 때 사용 (네트워크 수업 등에서 다룸).
    

### 3. Code 구현 (초기화)



```C
#define INF 1000000 // 연결되지 않음을 표현하는 무한대 값

// 가중치 그래프 초기화 예시 (adj_mat[i][j] = i에서 j로 가는 비용)
// i == j 이면 0, 간선이 없으면 INF
int weight[MAX_VERTICES][MAX_VERTICES] = {
    {0, 7, INF, INF, 3, 10, INF},
    {7, 0, 4, 10, 2, 6, INF},
    // … (생략)
};
```

## Topic 3. 다익스트라(Dijkstra) 알고리즘

### 1. 🏗️ 빌드업 (Why & Context)

> **"시작점에서 갈 수 있는 가장 가까운 곳부터 확정 짓고, 그곳을 징검다리 삼아 더 먼 곳을 갱신한다."**

- 네트워크 상에서 하나의 시작 정점(Source)으로부터 모든 다른 정점까지의 최단 경로를 구한다.
- 집합 $S$를 사용하여 **'이미 최단 거리가 확정된 정점'**들을 관리한다.
    

### 2. Concept

#### 1) 핵심 로직

1. **초기화:** 시작 정점 $v$에서 다른 정점들로 가는 직접 거리를 `distance` 배열에 저장한다. (연결 없으면 $\infty$)
2. **선택 (Greedy Step):**
    
    - 방문하지 않은 정점(집합 $S$에 없는 정점) 중 `distance` 값이 **가장 작은 정점 $u$를** 선택한다.
    - 정점 $u$를 집합 $S$에 추가한다(방문 처리).
        
3. **갱신 (Relaxation):**
    
    - 새로 확정된 정점 $u$를 거쳐서 다른 정점 $w$로 가는 경로가, 기존에 알고 있던 $w$까지의 경로보다 짧다면 값을 갱신한다.
    - 수식: $distance[w] = \min(distance[w], \ distance[u] + weight[u][w])$
        

#### 2) 논리적 흐름 예시

- 시작점이 0번 노드일 때:
    - 0번과 직접 연결된 노드들(4, 1, 5) 중 가중치가 가장 작은 노드(예: 4번)를 선택.
    - 이제 0번에서 4번까지의 최단 거리는 확정됨.
    - 4번을 거쳐서 갈 수 있는 새로운 경로들(4 $\to$ 2, 4 $\to$ 6 등)의 거리를 계산하여 기존 값과 비교 후 갱신.
    - 이 과정을 모든 노드를 방문할 때까지 반복.
        

### 3. Code 구현 (Core Logic)



```C
// distance[]: 시작점에서 각 정점까지의 최단 거리
// found[]: 방문 여부 (집합 S)

void dijkstra(int start, int n) {
    int i, u, w;
    
    // 1. 초기화
    for (i = 0; i < n; i++) {
        distance[i] = weight[start][i]; // 시작점과 연결된 간선 비용으로 초기화
        found[i] = FALSE;
    }
    
    found[start] = TRUE; // 시작 정점 방문 표시
    distance[start] = 0;
    
    // 2. n-1번 반복 (시작점 제외 나머지 정점들)
    for (i = 0; i < n - 1; i++) {
        
        // 현재 미방문 정점 중 distance가 가장 작은 정점 u 선택
        u = choose(distance, n, found); 
        
        found[u] = TRUE; // 집합 S에 추가
        
        // 3. Relaxation (거리 갱신)
        for (w = 0; w < n; w++) {
            if (!found[w]) { // 아직 방문하지 않은 정점 w에 대해
                // 기존 거리 vs (u를 거쳐가는 거리) 비교
                if (distance[u] + weight[u][w] < distance[w]) {
                    distance[w] = distance[u] + weight[u][w];
                }
            }
        }
    }
}
```

## 기타 핵심 (Etc & Tips) - 알고리즘 11.27

### 💡 Interview
> [!faq]- Q. 그리디 알고리즘(Greedy Algorithm)을 사용할 때 주의할 점은 무엇인가?
>
> 🗣️ 핵심 답변
>
> 그리디 알고리즘은 매 순간의 지역적 최선(Local Optimum)을 선택하기 때문에, 그 결과가 반드시 **전역 최적해(Global Optimum)**라는 보장이 없습니다.
>
> **📚 꼬리질문 대비**
>
> - 따라서 동전 거스름돈 문제(특수 동전 단위)나 배낭 문제(Knapsack)처럼 그리디가 실패하는 케이스를 인지하고, 적용 전 반드시 수학적 **검증(Proof)**을 거치거나 근사해(Approximation)로 만족해야 할 때 사용해야 합니다.
>
>     
> - **대안:** 최적해가 반드시 필요한 경우 **동적 계획법(DP)** 등을 사용하거나, 그리디 사용 후 검증 과정을 거쳐야 합니다. Kruskal과 Prim은 그리디를 쓰지만 매트로이드 구조에 의해 최적해가 증명된 알고리즘입니다.
>     

> [!faq]- Q. 가중치 그래프를 인접 행렬로 표현할 때, 간선이 없는 경우 0이 아닌 무한대($\infty$)로 초기화하는 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가중치 그래프에서 0은 '거리가 0임(즉, 자기 자신)'을 의미할 수 있기 때문입니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - 최단 경로 알고리즘에서 '0'은 비용이 들지 않는다는 의미로 해석되어, 연결되지 않은 상태와 구분이 불가능하기 때문입니다. 따라서 계산 결과(최솟값 찾기)에 영향을 주지 않도록 아주 큰 값(무한대)으로 설정하여 '갈 수 없음'을 명시해야 합니다.
>     

> [!faq]- Q. 다익스트라(Dijkstra)와 플로이드-워셜(Floyd-Warshall) 알고리즘의 결정적 차이는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가장 큰 차이는 해결 범위입니다. 다익스트라는 **'하나의 정점'**에서 다른 모든 정점까지의 최단 경로(One-to-All)를 구하지만, 플로이드-워셜은 '모든 정점 쌍' 간의 최단 경로(All-to-All)를 구합니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **시간 복잡도:** 다익스트라는 $O(E \log V)$ (우선순위 큐 사용 시), 플로이드-워셜은 $O(V^3)$입니다.
>     
> - **음수 가중치:** 다익스트라는 음수 가중치가 있으면 사용할 수 없으나, 플로이드-워셜은 음수 사이클만 없다면 음수 가중치 처리가 가능합니다. (단, 벨만-포드가 음수 가중치 처리에 더 특화됨)
>

## Topic 1. 다익스트라 알고리즘 상세 시뮬레이션

### 1. 🏗️ 빌드업 (Why & Context)

- MST(최소 신장 트리)는 간선을 선택하는 것이 목적이지만, 최단 경로 알고리즘은 **경로의 값(Distance)** 이 계속해서 변한다(갱신된다).
- 직접 연결되지 않아 `INF`(무한대)였던 곳이, 다른 정점을 거쳐가면서 구체적인 값으로 바뀌는 과정(Relaxation)을 이해해야 한다.

### 1) 거리 갱신 (Relaxation) 논리

-  "지금 알고 있는 $w$까지의 거리"보다 "새로 확정된 정점 $u$를 거쳐서 $w$로 가는 거리"가 더 짧다면 값을 갱신한다.
- distance의 d
### `d[w] = min(d[w], d[u] + weight[u][w])`

### 2) [실습 1] 정점 0에서 시작하는 경우

- **초기 상태:**
    - **집합 $S$ (방문 확정):** `{0}`
    - **`distance` 배열:** `[0, 7, 무한, 무한, 3, 10, 무한]` (0번 행의 초기 가중치)
- **Step 1 (정점 4 선택):**
    - $D[4]=3$이 가장 작으므로 $S={0, 4}$로 확장.
    - **갱신:** 정점 4를 거쳐갈 수 있는 곳들 확인.
        - $0 \to 1$: 기존 7 vs ($0 \to 4 \to 1$: $3+2=5$). **5로 갱신**.
        - $0 \to 3$: 기존 $\infty$ vs ($0 \to 4 \to 3$: $3+11=14$). **14로 갱신**.
        - $0 \to 6$: 기존 $\infty$ vs ($0 \to 4 \to 6$: $3+5=8$). **8로 갱신**.
- **Step 2 (정점 1 선택):**
    - 남은 $D$값 중 가장 작은 5(정점 1) 선택. $S=\{0, 4, 1\}$.
    - **갱신:** 정점 1을 거쳐갈 수 있는 곳들 확인.
        - $0 \to 2$: 기존 $\infty$ vs ($0 \to 1 \to 2$: $5+4=9$). **9로 갱신**.
- **(이후 반복):** 위 과정을 모든 정점이 $S$에 포함될 때까지 반복하여 최종 최단 거리 배열을 완성.
    

#### 3) [실습 2] 정점 3에서 시작하는 경우

- **목표:** 시작점이 바뀌었을 때 "One-to-All"의 개념을 이해하는지 확인.
- **초기 상태 ($S=\{3\}$):**
    - $D[3]=0$
    - 연결된 간선: $3 \to 1(10)$, $3 \to 2(2)$, $3 \to 4(11)$, $3 \to 5(9)$, $3 \to 6(4)$.
    - $3 \to 0$은 연결 없음($\infty$).
- **진행 과정:**
    
    1. 가장 작은 비용인 **정점 2(비용 2)** 선택.
    2. 정점 2를 거쳐서 갈 수 있는 곳 갱신 (예: $3 \to 2 \to 1$ 등 비교).
    3. 그 다음 작은 비용 선택… (반복)
        
- **최종 결과 예시:**
    - 배열 형태: `[INF, 6, 2, 0, 8, 9, 4]` (※ 강의 중 학생들과 맞춰본 값)
- **$S$ 집합의 의미:** $S$에 들어간 노드는 최단 거리가 **이미 확정**된 상태이다. 이후에는 그 값이 더 작아질 수 없다. (음수 간선이 없다는 전제하에)
- **무한대(INF) 처리:** 코드 구현 시 `INT_MAX` 등을 사용하여, 갱신 전에는 갈 수 없음을 명확히 해야 한다. `0`을 쓰면 안 된다.

## Topic 2. Dijkstra Code 구현

### 1. 🏗️ 빌드업 (Why & Context)

> **"수학적 논리를 그대로 코드로 옮긴 것이다."**

- 앞서 손으로 계산한 과정을 프로그램은 `weight` 행렬을 참조하여 반복문으로 수행한다.
- 방문하지 않은 노드 중 최소값을 찾는 `choose` 함수와, 값을 갱신하는 루프가 핵심이다.
    

### 2. Code 구현 (Core Structure)

```C
// 핵심 변수
// distance[]: 시작점으로부터의 최단 거리 저장
// found[]: 방문한 정점 표시 (집합 S)
// weight[][]: 가중치 인접 행렬 (초기 그래프 정보)

void dijkstra(int start, int n) {
    // 1. 초기화: 시작점과 연결된 간선 비용으로 distance 배열 세팅
    for(int i=0; i<n; i++) {
        distance[i] = weight[start][i];
        found[i] = FALSE;
    }
    found[start] = TRUE;
    distance[start] = 0;

    // 2. 루프: 시작점을 제외한 n-1개 정점에 대해 반복
    for(int i=0; i<n-1; i++) {
        
        // [Greedy Step]
        // 방문하지 않은 정점 중 distance가 가장 작은 정점 u 반환
        int u = choose(distance, n, found);
        
        found[u] = TRUE; // 집합 S에 추가

        // [Relaxation Step]
        // 새로 추가된 정점 u를 거쳐서 가는 거리가 더 짧으면 갱신
        for(int w=0; w<n; w++) {
            if(!found[w]) { // 아직 방문 안 한 정점에 대해
                // 기존 거리 vs (u까지 거리 + u에서 w로 가는 거리)
                if(distance[u] + weight[u][w] < distance[w]) {
                    distance[w] = distance[u] + weight[u][w];
                }
            }
        }
    }
}
```

- **⚠️ 주의사항 (Code Level):**
    - `weight` 배열 초기화 시 연결되지 않은 구간은 반드시 `INF`(무한대)로 설정해야 `choose` 함수나 `min` 비교 로직이 정상 작동한다.
    - 출력문(`printf`)이 없으면 내부 메모리 상에서만 값이 바뀌고 끝나므로, 루프 종료 후 `distance` 배열을 출력하는 코드를 추가해야 결과를 확인할 수 있다.

## Topic 3. Dijkstra vs Floyd-Warshall

### 1. 🏗️ 빌드업 (Why & Context)

> - 다익스트라는 "한 놈(Source)"만 팬다.
> - 플로이드는 "모든 놈(All-Pairs)"을 한 방에 팬다. (3중 반복문 사용)

- 다익스트라 알고리즘을 반복하면 모든 쌍의 최단 거리를 구할 수 있지만, 이를 한 번에 수행하는 알고리즘이 플로이드-워셜이다.
    

### 2. Concept 비교

|**구분**|**Dijkstra (다익스트라)**|**Floyd-Warshall (플로이드-워셜)**|
|---|---|---|
|**시작점**|**단일 시작점 (Single Source)**|**모든 정점 (All Pairs)**|
|**개념**|시작점 $S$에서 다른 모든 정점까지의 거리 구하기|모든 정점 $i$에서 모든 정점 $j$까지의 거리 구하기|
|**비유**|"서울에서 출발해서 부산, 대구, 광주 가는 최단 거리"|"전국 모든 도시 간의 최단 거리표 만들기"|
|**특징**|매 단계 최단 거리 정점 확정 ($S$ 집합 확장)|3중 반복문을 통해 거쳐가는 정점을 기준으로 행렬 전체 갱신|
|**관계**|다익스트라를 모든 정점에 대해 $N$번 수행 $\approx$ 플로이드|(다음 시간에 자세히 다룰 예정)|

### 💡 Interview

> [!faq]- Q. 다익스트라 알고리즘에서 매 단계 가장 거리가 짧은 정점을 선택하는 이유는 무엇인가요? (Greedy 속성)
>
> 🗣️ 핵심 답변
>
> 현재 방문하지 않은 정점 중 가장 거리가 짧은 정점은, 다른 어떤 미방문 정점을 거쳐서 오더라도 더 짧아질 가능성이 없기 때문입니다. (간선 가중치가 양수라는 전제 하에) 따라서 그 시점에 해당 정점까지의 최단 거리를 확정지을 수 있습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **음수 가중치가 있다면?** 음수 간선이 존재하면, 더 멀리 돌아가더라도 나중에 거리가 줄어들 수 있으므로 다익스트라의 그리디 논리가 깨집니다. 이 경우 **벨만-포드(Bellman-Ford)** 알고리즘을 사용해야 합니다.
>     

> [!faq]- Q. 다익스트라 알고리즘의 시간 복잡도는 어떻게 되나요?
>
> 🗣️ 핵심 답변
>
> 구현 방식에 따라 다릅니다. 배열을 사용하여 선형 탐색으로 최소 정점을 찾을 경우 $O(V^2)$입니다. 하지만 **우선순위 큐(Min Heap)**를 사용하여 최소 정점을 $O(\log V)$에 찾으면 전체 복잡도는 **$O(E \log V)$**로 최적화할 수 있습니다. (V: 정점 수, E: 간선 수)

> [!faq]- Q. 다익스트라 알고리즘을 구현할 때 '우선순위 큐(Priority Queue)'를 사용하면 어떤 이점이 있는가?
>
> 🗣️ 핵심 답변
>
> 기본적인 배열 탐색 방식은 가장 가까운 노드를 찾기 위해 매번 $O(N)$의 탐색이 필요하여 총 $O(N^2)$의 시간이 걸립니다. 하지만 우선순위 큐(Min Heap)를 사용하면 가장 가까운 노드를 $O(\log N)$에 찾을 수 있어, 전체 시간 복잡도를 $O(E \log N)$으로 줄일 수 있습니다. 이는 간선이 적은 희소 그래프에서 매우 효율적입니다.
---

> [!faq]- Q. 다익스트라 알고리즘이 '그리디(Greedy)' 기법인 이유는?
>
> 🗣️ 핵심 답변
>
> 매 단계에서 현재 방문하지 않은 노드 중 가장 거리가 짧은 노드를 선택하여 방문하고, 그 선택을 번복하지 않기 때문입니다. 즉, "지금 당장 갈 수 있는 가장 가까운 곳이 최단 경로의 일부일 것이다"라는 가정하에 동작합니다.

## Topic 2. 플로이드-워셜 (Floyd-Warshall)

### 1. 🏗️ 빌드업 (Why & Context)

> **"다익스트라를 N번 돌릴 것인가? 3중 반복문 한 번으로 끝낼 것인가?"**

- **문제 제기:** 다익스트라(Dijkstra)는 '하나의 시작점'에서만 최단 경로를 구한다. 만약 지도상의 **모든 도시 간의 최단 거리**를 표로 만들고 싶다면 어떻게 해야 하는가?
- **목적:** 그래프 내의 **모든 정점 쌍(All Pairs)** 사이의 최단 경로를 구한다.

### 2. Concept

#### 1) **핵심 아이디어:** "정점 $i$에서 $j$로 바로 가는 것보다, 경유지 $k$를 거쳐서 가는 게 더 빠르면 갱신한다."
`Distance[i][j] = min(Distance[i][j], Distance[i][k] + Distance[k][j])`
- **의미:** "$k$번 정점을 거치지 않고 가는 기존 거리"와 "$k$번 정점을 거쳐서 가는 거리" 중 더 짧은 것을 선택.
- $k$가 0부터 $N-1$까지 증가하면서, 경유 가능한 정점이 하나씩 늘어날 때마다 최단 거리를 갱신한다.
        

#### 2) 알고리즘 특징

- **입력:** 인접 행렬 (자기 자신 0, 간선 없으면 $\infty$).
- **구조:** 3중 `for`문 (Loop).
    - **가장 바깥쪽 Loop ($k$):** 경유할 정점 (0 ~ $N-1$). **(※ 가장 중요: 반드시 $k$가 가장 바깥에 있어야 함)**
    - **중간 Loop ($i$):** 출발 정점.
    - **안쪽 Loop ($j$):** 도착 정점.
- **시간 복잡도:** $O(N^3)$. (정점 개수가 적을 때 매우 효과적, 구현이 매우 간단함).
    

### 3. Code 구현 (Logic)



```C
// A[i][j]는 초기에 가중치 인접 행렬로 초기화됨 (없으면 INF)

// k: 경유지 (반드시 가장 바깥쪽 루프)
for (k = 0; k < n; k++) {
    // i: 출발지
    for (i = 0; i < n; i++) {
        // j: 도착지
        for (j = 0; j < n; j++) {
            // 기존 거리보다 k를 거쳐가는 거리가 짧으면 갱신
            if (A[i][k] + A[k][j] < A[i][j]) {
                A[i][j] = A[i][k] + A[k][j];
            }
        }
    }
}
```

## Topic 3. 위상 정렬 (Topological Sort)

### 1. 🏗️ 빌드업 (Why & Context)

> **"알고리즘을 들으려면 자료구조를 먼저 들어야 한다. 이 순서를 어떻게 정할까?"**

- 대학의 **선수 과목(Prerequisite)** 시스템이 가장 대표적인 예시.
- 일의 순서가 정해져 있는 작업들을 순서대로 나열하는 알고리즘.
    

### 2. Concept

#### 1) 정의 및 조건

- **정의:** 방향 그래프의 모든 노드를 "선행 순서(방향성)"를 거스르지 않도록 나열하는 것.
- **필수 조건:** **DAG (Directed Acyclic Graph)** 여야 한다.
    - **사이클(Cycle)이 없어야 함.** (예: A를 하려면 B를 해야 하고, B를 하려면 A를 해야 하면 영원히 불가능)
        

#### 2) 작동 원리 (진입 차수, In-degree)

1. **진입 차수(In-degree)가 0**인 정점을 찾는다. (즉, 선행 조건이 없는 과목).
2. 해당 정점을 출력하고, 그래프에서 **제거**한다.
3. 제거된 정점에서 출발하는 간선들도 모두 삭제한다. (이에 따라 연결된 후행 정점들의 진입 차수가 감소함).
4. 모든 정점이 제거될 때까지 반복한다.
    
    - 만약 모든 정점을 방문하기 전에 진입 차수가 0인 정점이 없다면? $\rightarrow$ **사이클이 존재한다**는 뜻.
        

#### 3) 예시 (선수 과목)

- **상황:** 자료구조(1) $\to$ 알고리즘(3), C언어(0) $\to$ 자료구조(1).
- **초기:** C언어(0)는 진입 차수 0. $\rightarrow$ 선택 및 삭제.
- **갱신:** 자료구조(1)의 진입 차수가 0이 됨. $\rightarrow$ 선택 및 삭제.
- **결과:** C언어 $\to$ 자료구조 $\to$ 알고리즘 순서 도출.

> [!faq]Q. 플로이드-워셜 알고리즘 구현 시 3중 반복문의 순서가 중요한 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 가장 바깥쪽 루프가 반드시 **경유지($k$)**가 되어야 하기 때문입니다. 플로이드 알고리즘은 '0번 정점까지 경유 가능할 때'의 결과를 바탕으로 '1번 정점 경유 추가'를 계산하는 동적 계획법(DP) 방식입니다. 경유지 루프가 안쪽으로 들어가면, 아직 갱신되지 않은 과거의 상태를 참조하게 되어 최단 거리를 올바르게 구할 수 없습니다.
>
> **📚 꼬리질문 대비 / 심화**
>
> - **i, j의 순서는?** 출발지(i)와 도착지(j)의 순서는 바뀌어도 상관없습니다. 핵심은 경유지(k)가 고정된 상태에서 모든 i, j 쌍을 검사하는 것입니다.
>     

> [!faq]Q. 위상 정렬(Topological Sort)이 불가능한 경우는 언제이며, 이를 어떻게 탐지하나요?
>
> 🗣️ 핵심 답변
>
> 그래프 내에 **사이클(Cycle)**이 존재하면 위상 정렬이 불가능합니다. 알고리즘 수행 중 큐(Queue)가 비어있는데 아직 방문하지 않은 정점이 남아있다면(즉, 모든 정점의 진입 차수가 0이 되지 않는다면), 사이클이 존재한다고 판단할 수 있습니다.
