## **2025-09-11, 1교시 — 개선본**

알고리즘 수업에서는 개념을 설명하는 데 중점을 둡니다. 예를 들어, 퀵 정렬(Quick Sort)이 왜 다른 정렬 방식보다 빠른지를 피벗(pivot)을 이용한 원리로 설명하지만, 실제 구현은 다루지 않습니다. 따라서 여러분은 배운 알고리즘을 `Python`이나 `Java` 등 익숙한 언어로 직접 코딩해보아야 합니다. (실습)

### 배열(Array)의 본질과 사용 이유

배열을 사용하는 근본적인 이유는 **동일한 자료형(type)을 갖는 여러 데이터를 연속된 메모리 공간에 그룹화**하여 효율적으로 다루기 위함입니다.

int a1, a2, a3; 와 int a[3]; 를 비교해봅시다.

두 방식 모두 3개의 정수를 저장하지만, 전자는 각 변수가 메모리상에 연속적으로 위치한다고 보장할 수 없습니다. 설령 컴파일러가 연속적으로 배치하더라도, 각 변수의 주소는 독립적이어서 포인터 연산을 통한 순회가 불가능합니다.

반면, `int a[3];` 선언은 **연속된 메모리 공간을 보장**하며, `a`라는 배열의 이름은 그 시작 주소를 가리키는 **상수 포인터** 역할을 합니다. 따라서 시작 주소만 알면 포인터 연산(`a+1`, `a+2` 등)을 통해 모든 원소에 효율적으로 접근할 수 있습니다.

컴퓨터 내부적으로는 배열의 시작 주소를 **베이스 레지스터(Base Register)**에, 인덱스를 **인덱스 레지스터(Index Register)**에 저장한 뒤 하드웨어 수준에서 빠르게 실제 주소를 계산합니다. 이것이 배열의 인덱스 접근이 $O(1)$으로 빠른 이유이며, 개별 변수에 각각 접근하는 것보다 훨씬 효율적인 이유입니다.

이러한 포인터 연산은 포인터의 타입 크기를 기준으로 동작합니다. `int*` 포인터를 1 증가시키면 실제 주소는 4바이트, `char*` 포인터는 1바이트만큼 이동합니다. 이 원리가 일관되게 적용되려면 배열의 모든 원소는 반드시 동일한 자료형이어야 합니다. 그래서 배열은 동일한 자료형인거임

---

### 구조체 배열

`int a[10];` 와 `struct card deck[10];` 는 개념적으로 완전히 동일합니다. 후자는 `struct card` 타입의 객체 10개를 연속된 메모리 공간에 할당한 것입니다. 이때 `deck`이라는 배열의 이름은 10개 객체 묶음의 시작 주소를 가리키는 상수 포인터입니다.

`struct card *k = deck;` 와 같이 포인터를 선언해도, 포인터 변수 `k` 자체의 크기는 구조체의 크기와 무관하게 시스템의 주소 크기(예: 4바이트)를 따릅니다. 포인터에는 오직 주소 값만 저장되기 때문입니다.

---

### 배열의 초기화와 문자열

배열을 초기화할 때, 지정한 크기보다 적은 수의 원소를 제공하면 나머지 공간은 모두 0으로 자동 초기화됩니다.

char s[] = "abc"; 와 같이 문자열 리터럴로 char 배열을 초기화하면, 문자열의 끝을 나타내는 **널(Null) 문자 \0**가 자동으로 추가됩니다. 따라서 이 배열 s의 크기는 3이 아닌 4가 됩니다.

### C언어 배열의 취약점: 경계 검사 부재

`C`언어는 배열의 인덱스가 범위를 벗어나는지 확인하지 않습니다. 예를 들어 `int arr[5];` 로 선언된 배열에 `arr[5]`나 `arr[10]`으로 접근해도 오류가 발생하지 않고, 해당 메모리 위치의 쓰레기 값을 읽거나 다른 데이터를 덮어쓰게 됩니다. 이는 심각한 버그와 보안 취약점의 원인이 되며, Java처럼 예외(Exception)를 발생시키는 언어와의 큰 차이점입니다.

여러분들이 직접 `int a1, a2, a3;` 와 `int b[3];` 를 선언하고 각 변수의 주소를 출력해보면, 두 방식 모두 연속적으로 할당될 수 있음을 볼 수 있습니다. 하지만 배열만이 포인터 연산을 통한 효율적인 순회를 보장한다는 점이 핵심입니다. (실습)

## **2025-09-11, 1교시 — 개념**

### 1) 한 줄 요약

동일 자료형의 데이터를 연속된 메모리에 저장하는 배열의 본질과, 포인터 연산을 통한 효율적인 접근 원리 및 C언어에서의 특징을 학습한다.

### 2) 핵심 TL;DR
* **배열의 존재 이유**: 배열은 **동일한 자료형**의 데이터들을 **연속된 메모리 공간**에 저장함을 **보장**하여, 그룹 단위의 효율적인 접근과 관리를 가능하게 한다.
* **효율성의 비밀**: CPU는 배열의 시작 주소를 **베이스 레지스터**에, 인덱스를 **인덱스 레지스터**에 담아 하드웨어 수준에서 주소를 빠르게 계산하므로, 임의의 원소 접근이 $O(1)$으로 매우 빠르다.
* **포인터 연산의 기반**: 메모리의 연속성이 보장되기 때문에, 시작 주소를 기준으로 포인터 연산(`p+1`, `p+2`...)을 통해 모든 원소를 순회할 수 있다.
* **구조체 배열**: `int a[10]`와 `struct card deck[10]`은 개념적으로 동일하다. `struct`와 같은 사용자 정의 자료형도 배열로 묶어 관리할 수 있다.
* **C언어 문자열**: `char s[] = "abc";`로 선언된 배열의 크기는 3이 아닌 4이다. 문자열의 끝을 알리는 **널(Null) 종료 문자(`\0`)**가 자동으로 포함되기 때문이다.
* **C언어의 치명적 약점**: C는 배열의 **경계 검사(Bounds Checking)**를 수행하지 않는다. 범위를 벗어난 인덱스에 접근해도 오류 없이 쓰레기 값을 읽거나 메모리를 오염시켜 심각한 버그의 원인이 된다.
* **함수 호출 방식**: 함수에 인자를 전달하는 방식에는 값을 복사하는 **Call by Value**와 주소를 전달하여 원본을 다루게 하는 **Call by Reference**가 있다.

### 3) 표현 = 표준 용어
* **Contiguous Memory (연속 메모리)**: 데이터가 메모리상에 물리적으로 끊김 없이 연달아 위치하는 상태. 배열의 핵심 속성이다.
* **Base Register / Index Register (베이스 / 인덱스 레지스터)**: CPU 내에서 배열의 시작 주소와 오프셋(인덱스)을 각각 저장하여 주소 계산을 가속하는 하드웨어.
* **Constant Pointer (상수 포인터)**: 가리키는 주소를 변경할 수 없는 포인터. 배열의 이름이 대표적이다.
* **Null Terminator (`\0`) (널 종료 문자)**: C언어 스타일 문자열의 끝을 표시하기 위해 사용되는 특수 문자.
* **Bounds Checking (경계 검사)**: 배열 접근 시 인덱스가 유효한 범위 내에 있는지 확인하는 작업. C언어에는 이 기능이 없다.
* **Call by Value / Call by Reference (값에 의한 호출 / 참조에 의한 호출)**: 함수에 인자를 전달할 때, 값을 복사해서 넘기는지(Value) 주소를 넘겨 원본에 접근하게 하는지(Reference)의 차이.

### 4) 정석 보강 (canon-std)
* **주제**: 배열의 메모리 모델과 주소 계산 (Array Memory Model and Address Calculation)
* **정의**: 배열은 동일한 타입의 원소들을 **연속된 메모리 공간**에 순서대로 저장하는 자료구조이다.
* **전제 조건**: 모든 원소는 반드시 **동일한 자료형**이어야 한다. 이 전제가 깨지면 일정한 규칙으로 주소를 계산할 수 없다.
* **복잡도**: 임의의 원소에 대한 접근(Access) 및 수정 시간 복잡도는 $O(1)$이다.
* **핵심 공식 (주소 계산)**: `address(arr[i]) = base_address + i * sizeof(element_type)`
* **하드웨어 패턴**: CPU는 이 계산을 위해 **베이스 레지스터**(base\_address)와 **인덱스 레지스터**(i)를 활용하여 하드웨어 수준에서 빠르게 주소를 계산한다.
* **흔한 오해**: 2차원 배열 `arr[i][j]`가 '포인터의 배열'이라고 착각하는 것. 실제로는 `(가로길이 * i + j)`만큼의 오프셋을 갖는 1차원 배열을 2차원처럼 계산하여 접근하는 방식이다.

### 5) 실수·함정
* `int a,b,c;`와 `int arr[3];`이 메모리상에서 동일하다고 가정하는 것 (전자는 연속성을 보장하지 않는다).
* C 문자열의 크기를 계산할 때 마지막 **널 종료 문자(`\0`)**를 빼먹는 것 (`"abc"`의 메모리 크기는 4바이트이다).
* C언어에서 배열의 범위를 벗어난 인덱스 접근이 항상 프로그램을 즉시 충돌시킬 것이라고 예상하는 것 (대부분의 경우 쓰레기 값을 읽고 조용히 넘어간다).
* `sizeof(배열이름)`이 항상 포인터 크기일 것이라고 착각하는 것 (함수에 인자로 전달된 경우를 제외하면, 배열 전체의 바이트 크기를 반환한다).
* 배열의 이름 `arr`에 `arr = 다른주소;` 와 같은 대입 연산을 시도하는 것 (배열 이름은 주소값을 바꿀 수 없는 상수 포인터이다).

## 2025-09-11, 1교시 — 질문

**[Q1] 배열을 사용하는 근본적인 이유는 무엇이며, `int a1, a2;` 처럼 변수를 개별 선언하는 방식에 비해 어떤 결정적인 장점을 갖는가? | 태그: 배열, 메모리, 포인터**

- **모범답(강의 기준)**: 동일한 타입의 데이터를 **연속된 메모리**에 저장함을 보장하여, 포인터 연산을 통한 효율적인 순회가 가능하기 때문입니다. 개별 변수는 연속성이 보장되지 않아 이러한 연산이 불가능합니다.
- **정석체크(면접 30초)**: 배열은 **메모리 연속성**을 보장하여 $O(1)$의 임의 접근(random access)을 가능하게 합니다. 전제는 모든 원소가 동일 타입이라는 것이며, 이 덕분에 `시작주소 + 인덱스 * 타입크기`라는 주소 계산이 성립합니다.

**[Q2] 크기가 5인 배열 `arr`에 대해 `arr[10]`에 접근하면 C언어에서는 어떤 결과가 발생하는가? 이는 Java와 같은 언어의 동작 방식과 어떻게 다른가? | 태그: C언어, 오류, 메모리**

- **모범답(강의 기준)**: C언어에서는 오류나 예외가 발생하지 않고, 배열 경계를 넘어선 메모리 위치의 **쓰레기 값을 읽거나 해당 메모리를 오염**시킵니다. Java는 `ArrayIndexOutOfBoundsException` 예외를 발생시켜 프로그램을 즉시 중단시킵니다.
- **정석체크(면접 30초)**: C는 경계 검사를 수행하지 않아 **미정의 동작(Undefined Behavior)**이 발생합니다. 이는 성능을 우선시한 설계 철학 때문이며, Java는 안정성을 위해 JVM이 경계 검사를 수행하고 위반 시 예외를 던지는 차이가 있습니다.

**[Q3] `char s[] = "abc";`로 선언된 C언어 문자열 배열의 크기가 3이 아닌 4인 이유는 무엇인가? | 태그: C언어, 문자열, 널문자**

- **모범답(강의 기준)**: C언어 스타일의 문자열은 문자열의 끝을 표시하기 위한 **널(Null) 종료 문자(`\0`)**를 맨 뒤에 자동으로 추가하기 때문입니다. 이 문자가 있어야 `printf` 같은 함수가 어디까지 출력해야 할지 알 수 있습니다.
- **정석체크(면접 30초)**: C의 표준 라이브러리 함수들은 문자열의 길이를 따로 저장하지 않고, `\0` 문자를 만날 때까지 처리하도록 설계되었습니다. 따라서 `sizeof("abc")`는 `'a', 'b', 'c', '\0'` 네 문자를 포함한 4바이트가 됩니다.

**[Q4] `int a[10];`와 `struct card deck[10];`는 개념적으로 어떻게 동일하며, 메모리상에서는 어떻게 표현되는가? | 태그: 구조체, 배열, 메모리**

- **모범답(강의 기준)**: `int`가 기본 자료형이듯 `struct card`는 사용자 정의 자료형일 뿐, 특정 자료형의 원소들을 연속된 메모리에 나열한다는 **배열의 기본 원리는 동일**합니다. `int`가 4바이트씩 나열된다면, `struct card`는 `sizeof(struct card)` 바이트씩 나열됩니다.
- **정석체크(면접 30초)**: 두 선언 모두 '특정 타입의 객체를 N개만큼 연속된 메모리에 할당한다'는 배열의 정의를 따릅니다. 메모리에서는 `deck[0]`, `deck[1]`, ... 순서로 각 `struct card` 객체가 통째로 연이어 배치되는 구조를 가집니다.

**[Q5] 함수 호출 시 사용되는 '값에 의한 호출(Call by Value)'과 '참조에 의한 호출(Call by Reference)'의 핵심적인 차이점은 무엇인가? | 태그: 함수, 매개변수, 포인터**

- **모범답(강의 기준)**: **Call by Value**는 함수에 인자의 값을 **복사**해서 전달하므로 함수 내에서 값을 변경해도 원본은 바뀌지 않습니다. **Call by Reference**는 인자의 **주소**를 전달하므로 함수 내에서 원본 값을 직접 수정할 수 있습니다.
- **정석체크(면접 30초)**: Call by Value는 독립적인 복사본을, Call by Reference는 원본에 대한 별칭(alias) 또는 주소를 전달합니다. C언어는 엄밀히는 Call by Value만 지원하지만, 포인터를 값으로 전달함으로써 Call by Reference의 효과를 낼 수 있습니다.

**[Q6] `main` 함수 마지막의 `return 0;`는 누구에게 값을 반환하는 것이며, 이 값은 운영체제(OS)에게 어떤 의미를 전달하는가? | 태그: C언어, 운영체제, 프로세스**

### 다차원 배열 (Multi-dimensional Array)

2차원 및 3차원 배열은 1차원 배열의 확장으로, 각각 평면(행과 열)과 공간(층, 행, 열) 데이터를 표현하는 데 사용됩니다. 하지만 메모리에는 1차원 배열과 마찬가지로 **선형적인 순서**로 저장됩니다. 예를 들어, `int a[2][3]` 배열은 메모리에 `a[0][0], a[0][1], a[0][2], a[1][0], a[1][1], a[1][2]` 순서로 연속적으로 배치됩니다. 다차원 배열의 핵심은 특정 위치 `a[i][j]`의 주소 값을 정확히 계산하고 찾아갈 수 있다는 점입니다.

다차원 배열을 선언과 동시에 초기화할 때, 가장 바깥쪽 차원의 크기는 생략할 수 있습니다. 컴파일러가 중괄호 `{}`의 구조를 보고 크기를 유추하기 때문입니다. 하지만 안쪽 차원들의 크기는 반드시 명시해야 합니다.

`int a[][2][3] = { ... };` // 가능

`int a[2][][3] = { ... };` // 불가능

---

### 희소 행렬 (Sparse Matrix) 과 메모리 효율

2차원 배열은 행렬을 표현하는 데 자연스러운 자료구조입니다. 하지만 대부분의 원소가 0인 **희소 행렬**의 경우, 2차원 배열을 그대로 사용하면 심각한 메모리 낭비가 발생합니다. 예를 들어 100x100 `int` 행렬은 40,000바이트의 메모리를 차지하는데, 만약 0이 아닌 값이 10개뿐이라면 40바이트의 유효한 데이터를 위해 나머지 39,960바이트를 0으로 채우는 셈입니다.

이 문제를 해결하기 위해, 0이 아닌 원소들의 **(행, 열, 값)** 정보만을 저장하는 새로운 자료구조를 설계할 수 있습니다. 보통 구조체 배열을 사용합니다:

`struct Term { int row; int col; int value; };`

`struct Term sparse_matrix[11];`

이 방식은 행렬이 희소할수록 메모리를 크게 절약하지만, 특정 위치의 값을 찾거나 행렬 연산을 수행하는 로직은 더 복잡해진다는 **트레이드오프(trade-off)**가 존재합니다.

---

### 이중 포인터 (Double Pointer) 와 동적 메모리 할당

포인터가 변수의 '주소'를 저장하는 것처럼, **이중 포인터(`int **p`)**는 다른 '포인터의 주소'를 저장합니다. 값에 접근하려면 주소를 두 번 따라가야(`**p`) 합니다.

**동적 메모리 할당**은 프로그램 실행 중에 필요한 만큼 메모리를 힙(Heap) 영역에 할당하는 기능입니다.
* **`malloc(size)`**: `size` 바이트만큼의 메모리 공간을 할당하고, 그 시작 주소를 `void *` 타입으로 반환합니다. 할당된 공간은 이름이 없으며, 오직 주소(포인터)를 통해서만 접근할 수 있습니다.
* **`free(ptr)`**: `malloc`으로 할당받았던 메모리 공간을 시스템에 반환합니다. `free`를 호출하지 않으면 **메모리 누수(Memory Leak)**가 발생하여, 프로그램이 종료될 때까지 해당 메모리를 아무도 사용할 수 없게 됩니다.

`malloc`이 반환하는 `void *`는 범용 포인터이므로, `(int *)`, `(struct Term *)` 등 실제 사용하려는 타입으로 반드시 **명시적 형 변환(casting)**을 해주어야 합니다.

Java와 같은 현대 언어는 **가비지 컬렉터(Garbage Collector)**가 자동으로 사용하지 않는 메모리를 회수해주지만, `C`언어에서는 프로그래머가 `malloc`과 `free`를 통해 직접 메모리를 관리해야 합니다. 이것이 `C`가 어렵지만 시스템을 정밀하게 제어할 수 있는 이유입니다.

### 1) 한 줄 요약

다차원 배열의 메모리 저장 방식과 희소 행렬의 효율적 표현법을 배우고, 이중 포인터와 동적 메모리 할당(`malloc`/`free`)의 개념을 이해한다.

### 2) 핵심 TL;DR
* **다차원 배열의 실체**: 2차원 배열 `a[2][3]`은 논리적으로는 격자 형태이지만, 실제 메모리에는 `a[0][0]`부터 `a[1][2]`까지 **1차원으로 연속되게**(행 우선 순서) 저장된다.
* **희소 행렬(Sparse Matrix)**: 대부분의 원소가 0인 행렬을 2차원 배열로 저장하면 심각한 메모리 낭비가 발생한다.
* **희소 행렬의 해결책**: 0이 아닌 원소의 **`(행, 열, 값)`** 정보만을 따로 저장(주로 구조체 배열 사용)하여 메모리 사용량을 크게 줄일 수 있다. 단, 연산 로직은 더 복잡해진다.
* **이중 포인터 (`int **p`)**: '포인터의 주소'를 저장하는 포인터이다. 값에 접근하려면 주소를 두 번(`**p`) 찾아가야 한다.
* **동적 메모리 할당**: `malloc()`은 프로그램 실행 중 힙(Heap) 영역에 필요한 크기의 메모리를 할당하고 그 시작 주소를 `void*`로 반환한다.
* **메모리 누수(Memory Leak)**: `malloc()`으로 할당한 메모리를 `free()`로 해제해주지 않으면, 해당 메모리는 프로그램이 끝날 때까지 사용할 수 없는 상태로 남아 시스템 자원을 낭비하게 된다.
* **`malloc()`의 실패 처리**: 메모리 할당에 실패하면 `malloc()`은 `NULL` 포인터를 반환하므로, 사용 전 반드시 `NULL` 여부를 확인해야 한다.

### 3) 표현 = 표준 용어
* **Row-Major Order (행 우선 순서)**: 다차원 배열을 1차원 메모리에 저장할 때, 행을 기준으로 원소를 순서대로 나열하는 방식. C언어의 표준 방식이다.
* **Sparse Matrix (희소 행렬)**: 대부분의 원소가 0인 행렬.
* **Trade-off (트레이드오프)**: 하나를 얻으면 다른 하나를 잃는 관계. (e.g., 희소 행렬 표현의 메모리 절약 vs. 연산 복잡성)
* **Double Pointer (이중 포인터)**: 포인터의 주소를 값으로 갖는 포인터 (`int **p`).
* **Dynamic Memory Allocation (동적 메모리 할당)**: 프로그램 실행 중에 필요한 메모리를 힙(Heap) 영역에서 할당하고 해제하는 것.
* **`malloc() / free()`**: C언어에서 동적 메모리를 할당하고 해제하는 표준 라이브러리 함수.
* **Memory Leak (메모리 누수)**: 할당된 메모리를 해제하지 않아 프로그램이 더 이상 사용할 수 없게 되는 현상.

### 4) 정석 보강 (canon-std)
* **주제**: 희소 행렬의 표현과 트레이드오프 (Sparse Matrix Representation and Trade-offs)
* **정의**: 희소 행렬은 대부분의 원소가 0인 행렬로, 0이 아닌 원소의 개수가 전체 크기에 비해 매우 적은 경우를 말한다.
* **핵심 아이디어**: 0인 원소는 저장하지 않고, **0이 아닌 원소의 위치(행, 열)와 값**만을 튜플`(row, col, value)` 형태로 저장한다.
* **대표 구현**: 0이 아닌 원소들을 저장하기 위해 주로 **구조체 배열**이나 **연결 리스트**를 사용한다.
* **공간 복잡도**: 일반 2D 배열은 $O(M \times N)$ 이지만, 희소 행렬 표현법은 0이 아닌 원소의 개수를 $k$라 할 때 $O(k)$ 의 공간만 필요로 한다.
* **트레이드오프**: 공간 효율성은 뛰어나지만, 특정 원소에 접근하거나 행렬 연산을 수행할 때 원하는 위치를 찾아야 하므로 시간 복잡도는 증가한다. (e.g., 접근: $O(1)$ → $O(k)$ 또는 $O(\log k)$)
* **흔한 오해**: 희소 행렬 표현법이 항상 우수하다고 생각하는 것. 행렬에 0이 별로 없다면(Dense Matrix), 이 방식은 오히려 더 많은 메모리(행, 열 인덱스 저장)와 연산 시간을 소모한다.

### 5) 실수·함정
* `malloc()`의 반환값이 항상 유효한 주소일 것이라고 가정하고 **`NULL` 체크를 생략**하는 것. (프로그램 비정상 종료의 원인)
* `malloc()`으로 할당한 메모리를 `free()`하는 것을 잊어 **메모리 누수**를 발생시키는 것.
* 이중 포인터 `p`에 대해, 포인터 값 `*p`와 최종 값 `**p`의 의미를 혼동하는 것.
* 희소 행렬 표현법이 0이 많은 않은 일반 행렬(Dense Matrix)에서도 유리할 것이라고 착각하는 것.
* 다차원 배열 `a[i][j]`의 메모리 주소를 `a[i]`가 가리키는 곳의 `j`번째라고 오해하는 것 (실제로는 `a`의 시작점에서 `i * (열의 개수) + j` 만큼 떨어진 단일 오프셋이다).

### 포인터의 형 변환 (Type Casting)

일반 변수에서는 `char`를 `int`에 대입하는 것처럼 작은 타입이 큰 타입으로 **자동 형 변환**이 일어납니다. 반대의 경우 데이터 손실이 발생할 수 있다는 경고가 나타납니다.

하지만 포인터는 타입 간 자동 형 변환이 엄격히 금지됩니다. `char*`와 `int*`는 모두 주소를 저장하는 4바이트(32비트 시스템 기준) 변수이지만, 가리키는 대상의 크기(각각 1바이트, 4바이트)를 다르게 해석하기 때문입니다.

이러한 타입 제한을 해결하는 유일한 방법은 **`void*` 포인터**를 이용하는 것입니다. `void*`는 타입을 정하지 않은 범용 주소 저장소 역할을 하므로, 어떤 타입의 포인터 주소든 담을 수 있습니다. `malloc` 함수의 반환값을 원하는 타입의 포인터로 받을 때처럼, 명시적인 캐스트 연산자 `(int *)`를 사용하여 타입을 지정해주어야 합니다.

---

### 함수 호출 방식과 포인터의 활용 (`swap` 예제)
* **값에 의한 호출 (Call by Value)**: `swap(int a, int b)`
    * 함수를 호출할 때 인자의 **값**을 복사하여 새로운 메모리 공간에 전달합니다.
    * `swap` 함수 내에서 값을 교환해도, 호출한 `main` 함수의 원본 변수에는 아무런 영향을 미치지 않습니다.
    * 인자가 큰 구조체일 경우, 전체를 복사하는 데 비용이 많이 들어 비효율적입니다.
* **참조에 의한 호출 (Call by Reference)**: `swap(int *a, int *b)`
    * 함수를 호출할 때 인자의 **주소**를 포인터에 전달합니다.
    * `swap` 함수는 전달받은 주소를 이용해 `main` 함수에 있는 원본 변수의 값에 직접 접근하여 수정할 수 있습니다.
    * 데이터 크기와 상관없이 주소(4 또는 8바이트)만 전달하므로 매우 효율적입니다.

---

### 초기화되지 않은 포인터의 위험성

`char *pc;` 와 같이 포인터를 선언만 하고 초기화하지 않으면, `pc`는 임의의 쓰레기 값(garbage value)을 주소로 갖게 됩니다. 이 상태에서 `*pc = 'e';` 와 같이 포인터를 역참조하여 값을 대입하는 것은 매우 위험합니다.

`pc`가 가리키는 임의의 주소가 운영체제의 핵심 코드 영역이나 다른 프로그램의 데이터 영역일 수 있기 때문입니다. 이 경우, 해당 메모리 공간의 값이 의도치 않게 변경되어 시스템 전체가 불안정해지거나 멈추는 심각한 오류를 초래할 수 있습니다.

---

### 함수 원형 (Function Prototype)

`C`언어에서는 함수를 사용하기 전에 반드시 그 존재를 컴파일러에 알려주어야 합니다(선언). 만약 `main` 함수보다 뒤에 `swap` 함수가 정의되어 있다면, `main` 함수는 `swap`을 인식하지 못합니다.

이때 파일 상단에 `void swap(int*, int*);` 와 같이 함수의 형태를 미리 알려주는 것을 **함수 원형** 선언이라고 합니다. 우리가 `#include <stdio.h>`를 사용하는 이유도, `printf`와 같은 표준 라이브러리 함수들의 원형이 해당 헤더 파일에 선언되어 있기 때문입니다.

### main 함수의 인자 (`argc`, `argv`)

`main` 함수는 운영체제로부터 **명령줄 인자(Command-line Arguments)**를 받을 수 있습니다.

`int main(int argc, char *argv[])`

* `argc`: 프로그램 실행 시 전달된 인자의 개수.
* `argv`: 각 인자(문자열)를 가리키는 포인터 배열. `argv[0]`은 프로그램의 이름입니다.

### 1) 한 줄 요약

포인터의 형 변환 규칙과 위험성을 이해하고, 함수 호출 시 값과 주소 전달 방식(Call by Value/Reference)의 차이와 원리를 학습한다.

### 2) 핵심 TL;DR
* **포인터 형 변환**: 일반 변수와 달리, 포인터는 가리키는 데이터의 크기가 달라지므로 타입이 다른 포인터 간의 자동 형 변환은 금지된다. **`void*`**를 이용한 명시적 캐스팅이 필요하다.
* **값에 의한 호출 (Call by Value)**: 함수에 인자의 **값**을 복사해서 전달한다. 원본 변수는 안전하지만, 큰 구조체 등을 복사할 때 비효율적이다.
* **참조에 의한 호출 (Call by Reference)**: 함수에 인자의 **주소**를 전달한다. 원본 변수를 직접 수정할 수 있으며, 데이터 크기와 무관하게 주소만 전달하므로 효율적이다.
* **초기화되지 않은 포인터의 위험성**: 주소를 할당하지 않은 포인터를 역참조(`*p = ...`)하면, 임의의 메모리 공간을 오염시켜 시스템 전체를 멈추게 할 수 있는 치명적인 오류를 유발한다.
* **함수 원형(Prototype)**: 함수는 호출되기 전에 반드시 그 형태(시그니처)가 컴파일러에 알려져야 한다. `<stdio.h>`와 같은 헤더 파일은 `printf` 같은 표준 함수들의 원형을 모아놓은 것이다.
* **함수 호출 스택**: 함수가 호출될 때, 돌아올 위치(주소)를 스택에 저장(push)한다. 함수 실행이 끝나면 스택에서 주소를 꺼내(pop) 원래 흐름으로 복귀한다. 이 LIFO 방식 덕분에 중첩된 함수 호출이 가능하다.
* **`main` 함수 인자**: `int main(int argc, char *argv[])`를 통해 프로그램 실행 시 전달된 **명령줄 인자**를 받아 처리할 수 있다.

### 3) 표현 = 표준 용어
* **Type Casting (형 변환)**: 한 데이터 타입을 다른 타입으로 강제 변환하는 것.
* **Call by Value (값에 의한 호출)**: 함수에 인자의 값을 복사해서 전달하는 방식.
* **Call by Reference (참조에 의한 호출)**: 함수에 인자의 주소를 전달하여 원본에 접근하게 하는 방식. C에서는 포인터를 이용해 구현한다.
* **Uninitialized Pointer (초기화되지 않은 포인터)**: 선언 후 유효한 주소로 초기화되지 않아 쓰레기 값을 갖는 포인터.
* **Function Prototype (함수 원형)**: 함수의 시그니처(이름, 반환형, 매개변수)를 미리 선언하는 것.
* **Command-line Arguments (명령줄 인자)**: 프로그램을 실행할 때 함께 전달하는 문자열 데이터. `argc`, `argv`로 받는다.
* **Call Stack (호출 스택)**: 함수 호출 관계와 지역 변수 등을 관리하기 위한 LIFO 구조의 메모리 영역.

### 4) 정석 보강 (canon-std)
* **주제**: 함수 호출 방식: Call by Value vs. Call by Reference
* **정의**: **Call by Value**는 함수에 인자로 **값의 복사본**을 전달하고, **Call by Reference**는 **원본의 주소**를 전달한다.
* **핵심 차이**: Call by Value는 함수 내에서 인자를 수정해도 원본에 영향을 주지 않지만, Call by Reference는 원본을 직접 수정할 수 있다.
* **비용**: Call by Value는 데이터 크기가 클 경우 복사 오버헤드가 크다. Call by Reference는 데이터 크기와 무관하게 주소 크기만큼의 오버헤드만 발생하여 효율적이다.
* **C언어 구현**: C언어는 엄밀히 **Call by Value**만 지원한다. Call by Reference는 **포인터를 값으로 전달**하는 방식으로 흉내 낸다 (`pass a pointer by value`).
* **대표 예시**: `swap` 함수 구현 시, 값 교환을 위해서는 반드시 포인터를 이용한 Call by Reference 방식을 사용해야 한다.
* **흔한 오해**: C에서 `int arr[]`를 함수의 인자로 넘기는 것이 Call by Reference라고 생각하는 것. 실제로는 배열의 시작 주소(포인터)가 '값'으로 복사되어 전달되는 Call by Value의 일종이다.

### 5) 실수·함정
* `char*`와 `int*`는 크기가 같으므로 그냥 대입해도 된다고 생각하는 것 (타입이 달라 금지됨).
* `swap(i, j)`처럼 값만 넘겨서 원본 변수 `i`, `j`가 바뀌기를 기대하는 것.
* 포인터 변수 선언 후, 주소를 할당하지 않은 채 역참조(`*p = ...`)를 시도하는 것 (가장 위험한 실수 중 하나).
* `main` 함수 위에 함수를 정의했으면서, 별도의 함수 원형을 또 선언하는 것 (불필요함).
* C 함수가 여러 개의 값을 `return`할 수 있다고 착각하는 것 (하나의 값만 반환 가능하다).

**[Q1] `swap` 함수 구현 시, 왜 '값에 의한 호출' 방식으로는 원본이 바뀌지 않으며, '참조에 의한 호출(포인터 전달)' 방식을 사용해야만 하는가? | 태그: 함수, 포인터, Call_by_Value**
* **모범답(강의 기준)**: '값에 의한 호출'은 변수의 값을 복사해서 전달하므로, 함수 안에서 복사본을 바꿔도 원본은 그대로입니다. '참조에 의한 호출'은 변수의 주소를 전달하여, 함수가 그 주소로 직접 찾아가 원본 값을 수정할 수 있기 때문입니다.
* **정석체크(면접 30초)**: Call by Value는 함수 스택 프레임에 독립된 지역 변수를 생성하지만, Call by Reference(포인터 전달)는 원본 변수에 대한 접근 권한(주소)을 넘겨줍니다. 원본 데이터 수정을 위해서는 반드시 주소를 전달해야 합니다.

**[Q2] 초기화되지 않은 포인터 `char *pc;`에 값을 대입(`*pc = 'e';`)하는 코드가 시스템 전체를 멈추게 할 수도 있는 이유는 무엇인가? | 태그: 포인터, 메모리, 오류**
* **모범답(강의 기준)**: 초기화되지 않은 포인터는 임의의 쓰레기 값을 주소로 갖고 있습니다. 이 주소가 만약 운영체제의 중요 코드 영역이라면, 해당 코드를 훼손시켜 시스템 전체에 치명적인 오류를 발생시킬 수 있습니다.
* **정석체크(면접 30초)**: 이는 **미정의 동작(Undefined Behavior)**의 대표적 사례입니다. 포인터가 가리키는 주소가 유효한 사용자 공간이 아닐 수 있으며, 보호된 메모리(Protected Memory) 영역을 침범하여 세그멘테이션 폴트(Segmentation Fault)를 유발할 수 있습니다.

**[Q3] C언어가 `int *`를 `char *`로 자동 형 변환하는 것을 금지하는 이유는 무엇이며, `void *` 포인터는 이 규칙에서 어떤 특별한 역할을 하는가? | 태그: 포인터, 형변환, void**
* **모범답(강의 기준)**: 가리키는 데이터의 크기가 다르기 때문입니다. `int *`는 4바이트를 다루는데, 이를 1바이트를 다루는 `char *`로 바꾸면 데이터 해석에 심각한 오류가 발생할 수 있어 컴파일러가 막는 것입니다. `void *`는 이런 타입 검사를 일시적으로 보류하는 범용 주소 저장소 역할을 합니다.
* **정석체크(면접 30초)**: 포인터의 강타입(strong typing) 시스템은 메모리 접근 오류를 방지합니다. `void *`는 타입 정보가 없는 순수한 주소로, `malloc`처럼 어떤 타입의 메모리든 할당할 수 있게 해주고, 사용자가 명시적 형변환을 통해 타입 안전성을 책임지게 합니다.

**[Q4] 함수를 호출하기 전에 그 함수의 '원형(Prototype)'을 선언해야 하는 이유는 무엇이며, `#include <stdio.h>`는 이와 어떤 관계가 있는가? | 태그: 함수, 컴파일러, 헤더파일**
* **모범답(강의 기준)**: 컴파일러가 함수를 호출하는 코드를 만났을 때, 그 함수의 이름, 매개변수 타입, 반환형이 올바르게 사용되었는지 검사하기 위해 원형 정보가 미리 필요합니다. `#include <stdio.h>`는 `printf`와 같은 표준 함수의 원형을 미리 선언해주는 역할을 합니다.
* **정석체크(면접 30초)**: C 컴파일러는 파일을 위에서 아래로 한 번만 읽습니다(single-pass). 따라서 함수 호출 시점에 해당 함수의 정보를 모르면 타입 검사를 할 수 없으므로, 사전에 원형을 선언하여 함수의 존재와 형태를 알려주어야 합니다.

**[Q5] 함수가 다른 함수를 호출할 때 프로그램의 실행 흐름이 어떻게 유지되는지 시스템 스택(System Stack)의 역할을 중심으로 설명하시오. | 태그: 시스템, 스택, 함수호출**
* **모범답(강의 기준)**: `main`이 `swap`을 호출하면, `swap` 실행 후 돌아와야 할 `main`의 다음 명령어 주소(복귀 주소)를 시스템 스택에 저장(push)합니다. `swap`이 끝나면 스택에서 이 주소를 꺼내(pop) `main`의 실행을 이어나갑니다.
* **정석체크(면접 30초)**: 함수 호출 시, 복귀 주소, 매개변수, 지역 변수 등이 포함된 스택 프레임(Stack Frame)이 호출 스택에 생성됩니다. 함수가 반환되면 해당 프레임이 제거되며, LIFO 구조 덕분에 중첩된 함수 호출이 정확하게 복귀될 수 있습니다.

**[Q6] `main(int argc, char *argv[])`의 두 인자는 각각 어떤 의미를 가지며, 어떤 목적으로 사용되는가? | 태그: main, 명령줄인자, 운영체제**
* **모범답(강의 기준)**: `argc`는 실행 시 입력된 명령줄 인자의 '개수'이고, `argv`는 각 인자(문자열)의 '내용'을 가리키는 포인터 배열입니다. 이를 통해 프로그램 외부에서 옵션이나 파일 경로 같은 정보를 전달받을 수 있습니다.
* **정석체크(면접 30초)**: `argc`(argument count)와 `argv`(argument vector)는 운영체제가 프로세스를 생성할 때 명령줄 문자열을 파싱하여 전달해주는 표준 인터페이스입니다. `argv[0]`은 프로그램 이름이며, `argv[1]`부터 실제 인자가 시작됩니다.
