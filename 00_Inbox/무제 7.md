# 📜 Oracle DB 객체 정의 및 핵심 메커니즘 정리

데이터베이스 객체(Object)는 데이터의 **무결성(Integrity), 보안(Security), 성능(Performance)**을 보장하기 위한 핵심 구성 요소입니다. 아래 내용은 Oracle SQL 및 PL/SQL을 기준으로 작성되었습니다.

---

## 1. 제약 조건 (Constraints)

데이터의 **무결성(정확성 및 일관성)**을 보장하기 위한 강제 규칙입니다. 데이터 입력(`INSERT`) 및 수정(`UPDATE`) 시 엔진 레벨에서 실시간 검증이 수행됩니다.

### 🛠️ 정의 방식

제약 조건은 컬럼 정의 시 바로 선언하는 **컬럼 레벨**과, 테이블 정의 마지막에 몰아서 선언하는 **테이블 레벨**이 있습니다.



```SQL
CREATE TABLE EMP (
    -- [컬럼 레벨] 컬럼 정의와 동시에 선언 (간단한 제약 조건)
    EMP_ID    NUMBER       CONSTRAINT PK_EMP PRIMARY KEY,
    EMP_NAME  VARCHAR2(20) NOT NULL, 

    -- [테이블 레벨] 모든 컬럼 정의 후 하단 선언 (복합키, 외래키 권장)
    DEPT_ID   NUMBER,
    CONSTRAINT FK_DEPT FOREIGN KEY (DEPT_ID) 
        REFERENCES DEPT(DEPT_ID) ON DELETE SET NULL
);
```

### 🔑 주요 키워드 및 핵심 동작

| **제약 조건**         | **설명 및 특징**                                                                                                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`PRIMARY KEY`** | **유일성(Unique) + `NOT NULL`**. 테이블당 1개만 존재 가능하며, 선언 시 **Unique Index**가 자동 생성됩니다.                                                                                                 |
| **`FOREIGN KEY`** | **참조 무결성** 보장. 부모 테이블에 없는 값은 자식 테이블에 입력 불가합니다.<br><br>  <br><br>• `ON DELETE CASCADE`: 부모 삭제 시 자식도 자동 **삭제**<br><br>  <br><br>• `ON DELETE SET NULL`: 부모 삭제 시 자식 값을 **NULL**로 변경 |
| **`UNIQUE`**      | 중복 값을 허용하지 않음. 단, **`NULL`은 중복 입력 가능**합니다.                                                                                                                                       |
| **`CHECK`**       | 특정 조건(도메인)을 만족해야 함. `NULL`은 검사 대상에서 제외됩니다.<br><br>  <br><br>_(예: `CHECK (SALARY > 0)`)_                                                                                          |
| **`NOT NULL`**    | 반드시 값이 입력되어야 함. (주로 컬럼 레벨에서 정의)                                                                                                                                                  |

## 2. 프로시저 (Procedures)

복잡한 비즈니스 로직을 DB 내에 저장하여, **여러 쿼리를 하나의 트랜잭션으로 일괄 처리**하기 위한 객체입니다. 리턴값이 없으며(파라미터로 반환), 주로 `EXEC` 명령어로 실행합니다.

### 🛠️ 기본 문법 구조

SQL

```Java
CREATE OR REPLACE PROCEDURE SP_UPDATE_SALARY
(
    p_emp_id IN  NUMBER,   -- [입력] 외부에서 받는 값
    p_rate   IN  NUMBER,
    p_result OUT VARCHAR2  -- [출력] 실행 후 반환할 값
)
IS
    -- [선언부] 내부 변수
    v_current_sal NUMBER;
BEGIN
    -- [실행부] 로직 수행
    SELECT SALARY INTO v_current_sal FROM EMP WHERE EMP_ID = p_emp_id;
    
    UPDATE EMP SET SALARY = v_current_sal * (1 + p_rate)
    WHERE EMP_ID = p_emp_id;

    COMMIT; -- 프로시저는 트랜잭션 제어(COMMIT/ROLLBACK)가 가능함
    p_result := 'Success';

EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        p_result := 'Error: ' || SQLERRM;
END;
/
```

### 🔑 파라미터 모드 3가지

1. **`IN` (Read-only):** 값을 전달받기만 함. (Default)
2. **`OUT` (Write-only):** 프로시저 내부에서 값을 할당하여 호출자에게 반환.
3. **`IN OUT` (Read-Write):** 값을 받아 가공한 뒤 다시 반환.

## 3. 함수 (Functions)

특정 연산을 수행하고 **반드시 하나의 값(Value)을 반환**하는 객체입니다. 프로시저와 달리 SQL 문장(`SELECT`, `WHERE` 절 등) 내에서 사용하기 위해 설계되었습니다.

### 🛠️ 기본 문법 구조

SQL

```Java
CREATE OR REPLACE FUNCTION FN_GET_TAX
(
    p_salary IN NUMBER
)
RETURN NUMBER -- [필수] 반환 데이터 타입 명시 (크기 지정 X)
IS
    v_tax NUMBER;
BEGIN
    v_tax := p_salary * 0.1;
    RETURN v_tax; -- [필수] RETURN 문이 실행되어야 함
END;
/
```

### 💡 핵심 차이점 (vs 프로시저)

- **목적:** 값을 계산해서 반환 (프로시저는 로직 수행이 목적).
- **호출:** `SELECT FN_GET_TAX(3000) FROM DUAL;` 처럼 SQL 문에 포함 가능.
- **제약:** 함수 내부에서 테이블 내용을 바꾸는 **DML(`INSERT`/`UPDATE`/`DELETE`) 사용이 원칙적으로 금지**됩니다.

## 4. 뷰 (Views)

물리적인 데이터를 저장하지 않고, **SQL 쿼리문(Text) 그 자체를 저장**하는 가상 테이블입니다. 사용자는 뷰를 테이블처럼 조회하지만, 실제로는 저장된 쿼리가 실행됩니다.

### 🎯 사용 목적

1. **보안(Security):** 민감 정보(주민번호, 연봉 등)를 제외한 컬럼만 공개.
2. **편의성:** 복잡한 `JOIN` 쿼리를 미리 뷰로 만들어두고 간단히 조회.
    

### 🛠️ 기본 문법 구조

SQL

```Java
CREATE OR REPLACE FORCE VIEW V_EMP_DEPT
AS
SELECT E.NAME, D.DNAME
FROM EMP E
JOIN DEPT D ON E.DEPT_ID = D.DEPT_ID
WITH READ ONLY; -- [옵션] 읽기 전용으로 설정 (DML 불가)
```

### 🔑 주요 옵션

- `FORCE`: 기본 테이블이 존재하지 않아도 뷰를 (컴파일 오류 상태로) 생성.
- `WITH CHECK OPTION`: 뷰의 `WHERE` 조건에 위배되는 데이터 변경(`UPDATE`/`INSERT`)을 차단.
- **단순 뷰 vs 복합 뷰:**
    - _단순 뷰:_ 하나의 테이블로 구성. 조건 만족 시 DML 가능.
    - _복합 뷰:_ 조인, 그룹함수(`SUM`, `AVG`) 포함. 원칙적으로 **DML(수정/삭제) 불가**

## 5. 인덱스 (Indexes)

검색 속도 향상을 위한 **포인터(Pointer)** 역할을 하는 객체입니다. 주로 **B-Tree** 구조를 가지며, 별도의 저장 공간(Segment)을 차지합니다.

### ⚖️ 성능 Trade-off (양날의 검)

- **장점 (조회):** `WHERE` 절 조건 검색 시 Full Table Scan을 방지하고 **Index Range Scan**을 유도하여 속도 향상.
- **단점 (변경):** 데이터가 `INSERT`, `UPDATE`, `DELETE` 될 때마다 인덱스도 재정렬해야 하므로 **쓰기 성능 저하**.
    

### 🛠️ 기본 문법 구조

SQL

```Java
-- [Unique Index] 중복 불가 (PK 생성 시 자동 생성됨)
CREATE UNIQUE INDEX IDX_EMP_EMAIL ON EMP(EMAIL);

-- [Composite Index] 복합 인덱스 (컬럼 순서가 중요함)
CREATE INDEX IDX_EMP_JOB_DEPT ON EMP(JOB, DEPT_ID);
```

### 🔑 인덱스 종류 및 선택 기준

| **종류**     | **구조**       | **특징 및 사용처**                                                         |
| ---------- | ------------ | -------------------------------------------------------------------- |
| **B-Tree** | Tree 구조      | **Cardinality가 높은(값의 종류가 많은)** 컬럼 유리.<br>_(예: 주민번호, 이름, ID)_         |
| **Bitmap** | Bit Map(0,1) | **Cardinality가 낮은(중복도가 높은)** 컬럼 유리.  <br>_(예: 성별, 결혼여부)_ OLAP 환경 사용. |

## 6. 암호화 (TDE: Transparent Data Encryption)

디스크에 저장된 데이터 파일 자체를 암호화하여, OS 차원에서 파일 탈취 시 내용을 보호하는 기술입니다. 애플리케이션이나 SQL 조회 시에는 자동으로 복호화되므로 **투명(Transparent)**하다고 표현합니다.

### 🛠️ 기본 문법 구조

SQL

```Java
CREATE TABLE MEMBERS (
    ID VARCHAR2(50),
    
    -- [No Salt] 인덱스 생성이 필요한 경우 필수 지정
    SSN VARCHAR2(20) ENCRYPT USING 'AES256' 'NO SALT', 
    
    -- [Salt] 기본값. 보안성 높음 (인덱스 생성 불가)
    PASSWORD VARCHAR2(100) ENCRYPT -- 기본 알고리즘/Salt 적용
);
```

### ⚠️ Salt vs No Salt (핵심 제약)

- **Salt (기본값):** 동일한 평문 데이터라도 매번 다른 암호문으로 저장됩니다. 보안성이 강력하지만, 값이 변하므로 **인덱스 생성이 불가능**합니다.
- **No Salt:** 동일한 평문은 항상 동일한 암호문으로 저장됩니다. 보안성은 상대적으로 낮으나, **인덱스(Index) 생성이 가능**합니다. (검색 조건으로 써야 하는 암호화 컬럼에 사용)
