### 📝 실전 코드 예시

SQL

```SQL
CREATE TABLE T_USER (
    USER_ID  VARCHAR2(20) PRIMARY KEY,
    
    -- [1] 기본형 (가장 강력한 보안)
    -- 알고리즘 생략(기본값 적용), SALT 생략(기본값 SALT 적용) -> 인덱스 불가
    ADDRESS  VARCHAR2(100) ENCRYPT,

    -- [2] 인덱스용 (검색이 필요한 컬럼)
    -- 주민번호로 검색(WHERE절)을 해야 한다면 반드시 'NO SALT' 명시
    SSN      VARCHAR2(14)  ENCRYPT USING 'AES256' 'NO SALT',

    -- [3] 특정 알고리즘 지정
    CARD_NO  VARCHAR2(20)  ENCRYPT USING 'AES256' -- SALT는 자동 적용됨
);
```

## 2. 인덱스 문법의 기본값 (Default)

인덱스를 생성할 때 옵션을 생략하면 적용되는 **두 가지 핵심 기본값**이 있습니다.

### ① 정렬 순서의 기본값: `ASC` (오름차순)

인덱스는 데이터를 정렬해서 저장하는데, 방향을 지정하지 않으면 무조건 **오름차순(1→10, A→Z, ㄱ→ㅎ)**으로 생성됩니다.

- **문법:** `CREATE INDEX 인덱스명 ON 테이블명 (컬럼명);`
- **실제 동작:** `CREATE INDEX 인덱스명 ON 테이블명 (컬럼명 ASC);` 와 100% 동일.
    

### ② 인덱스 유형의 기본값: `B-Tree` (Normal)

`UNIQUE`나 `BITMAP` 같은 키워드 없이 생성하면, 가장 일반적인 **Non-Unique B-Tree 인덱스**가 생성됩니다. (중복 값 허용)

### 🧐 비교표

|**구분**|**문법 예시**|**실제 적용되는 값 (Default)**|**설명**|
|---|---|---|---|
|**정렬 순서**|`ON EMP(SAL)`|**`ASC`** (오름차순)|낮은 값에서 높은 값 순서로 정렬|
|**인덱스 유형**|`CREATE INDEX …`|**`NORMAL`** (B-Tree)|가장 범용적인 트리 구조 인덱스|
|**중복 여부**|`CREATE INDEX …`|**`NON-UNIQUE`**|중복된 데이터 값 저장 허용|

### 📝 실전 코드 예시



```SQL
-- [1] 아무 옵션도 주지 않은 경우
CREATE INDEX IDX_EMP_SAL ON EMP(SAL);
-- 결과: SAL 컬럼을 기준으로 [오름차순] 정렬된 [B-Tree] 인덱스 생성

-- [2] 옵션을 명시한 경우 (내림차순이 필요할 때만 명시)
CREATE INDEX IDX_EMP_SAL_DESC ON EMP(SAL DESC);
-- 결과: SAL 컬럼을 기준으로 [내림차순] 정렬
```

**요약하자면:**

- 암호화의 `SALT` 여부 기본값은 **`SALT`** (인덱스 불가)입니다.
- 인덱스 정렬의 기본값은 **`ASC`** (오름차순)입니다.



요청하신 포맷(문법 구조 + 구성 요소 분해)에 맞춰 **제약 조건, 프로시저, 함수, 뷰, 인덱스**를 깔끔하게 정리해 드립니다.

## 1. 제약 조건 (Constraints)

### 🛠️ 기본 문법 구조

```SQL
CONSTRAINT [제약조건명] [제약유형] (적용컬럼) [REFERENCES 부모테이블(컬럼) [ON DELETE 옵션]]
```

### 🧩 구성 요소 분해

1. **`CONSTRAINT`**: (선택) 제약 조건에 이름표를 붙이는 키워드입니다.
    
    - 생략 시: Oracle이 자동으로 `SYS_C00xxxxx` 같은 식별자를 부여합니다.
    - 권장: 에러 발생 시 원인 파악을 위해 명시하는 것이 좋습니다 (예: `PK_EMP_ID`).
        
2. **`제약유형`**: (필수) 어떤 규칙을 적용할지 결정합니다.
    
    - `PRIMARY KEY`: 유일성 + NOT NULL (테이블당 1개).
    - `FOREIGN KEY`: 참조 무결성 (부모 테이블의 값만 허용).
    - `CHECK`: 사용자 정의 조건 (예: `SAL > 0`).
        
3. **`REFERENCES … ON DELETE`**: (선택) **외래키(FK) 전용 옵션**입니다.
    
    - **`CASCADE`**: 부모 데이터 삭제 시 자식 데이터도 **자동 삭제**.
    - **`SET NULL`**: 부모 데이터 삭제 시 자식 데이터를 **NULL로 변경**.
    - 생략 시: 자식이 참조 중이면 부모 데이터 삭제 **불가** (에러 발생).

## 2. 프로시저 (Procedures)

### 🛠️ 기본 문법 구조

SQL

```SQL
CREATE PROCEDURE 프로시저명 ( 파라미터명 [IN | OUT | IN OUT] 데이터타입 )
IS
    [변수 선언부]
BEGIN
    [실행부 (DML, 트랜잭션)]
EXCEPTION
    [예외 처리부]
END;
```

### 🧩 구성 요소 분해

1. **`IN` | `OUT`**: (선택) 데이터의 흐름을 결정합니다.
    
    - **`IN` (기본값):** 외부 값을 프로시저 내부로 읽어옵니다 (Read Only).
    - **`OUT`:** 내부에서 처리된 결과를 외부로 내보냅니다 (Write Only).
        
2. **`IS` (또는 `AS`)**: (필수) 선언부의 시작을 알립니다.
    
    - 이 키워드와 `BEGIN` 사이에서 내부 변수(`v_name`)나 커서 등을 선언합니다.
        
3. **`COMMIT` / `ROLLBACK`**: (가능) 프로시저의 가장 큰 특징입니다.
    
    - 함수와 달리 내부에서 트랜잭션을 확정하거나 취소할 수 있어, 복잡한 일괄 작업 처리에 적합합니다.

## 3. 함수 (Functions)

### 🛠️ 기본 문법 구조

SQL

```SQL
CREATE FUNCTION 함수명 ( 파라미터명 IN 데이터타입 )
RETURN 반환타입 -- [헤더]
IS
    [변수 선언부]
BEGIN
    [실행부]
    RETURN 반환값; -- [바디]
END;
```

### 🧩 구성 요소 분해

1. **`RETURN 반환타입`**: (필수) **헤더 부분**에 위치합니다.
    
    - 반환할 데이터의 타입만 명시합니다. **크기(Size)는 지정할 수 없습니다.**
    - (O) `RETURN VARCHAR2` / (X) `RETURN VARCHAR2(100)`
        
2. **`RETURN 반환값`**: (필수) **실행부(BEGIN~END)** 내부에 위치합니다.
    
    - 로직 처리가 끝난 후, 호출한 곳으로 실제 값을 돌려주는 명령어입니다.
        
3. **DML 제약**: (주의) 원칙적으로 함수 내부에서는 `INSERT`, `UPDATE`, `DELETE`를 사용할 수 없습니다. (조회 전용 목적)

## 4. 뷰 (Views)

### 🛠️ 기본 문법 구조

SQL

```SQL
CREATE [OR REPLACE] [FORCE | NOFORCE] VIEW 뷰이름
AS
SELECT 쿼리문…
[WITH READ ONLY] [WITH CHECK OPTION]
```

### 🧩 구성 요소 분해

1. **`OR REPLACE`**: (선택) 뷰가 이미 존재하면 덮어쓰고(수정), 없으면 새로 만듭니다. (실무 필수 옵션)
2. **`FORCE`**: (선택) **원본 테이블 유무와 상관없이** 뷰를 생성합니다.
    
    - **`NOFORCE` (기본값):** 원본 테이블이 없으면 에러가 발생하며 뷰가 생성되지 않습니다.
    - **`FORCE`:** 원본 테이블이 없어도 뷰가 생성됩니다(단, 상태는 INVALID). 테이블이 나중에 생성되면 뷰도 정상 작동합니다.
        
3. **`WITH READ ONLY`**: (선택) 뷰를 통한 데이터 조작(DML)을 완벽히 차단합니다. 단순히 조회만 가능하게 할 때 사용합니다.

## 5. 인덱스 (Indexes)

### 🛠️ 기본 문법 구조

SQL

```SQL
CREATE [UNIQUE | BITMAP] INDEX 인덱스명
ON 테이블명 ( 컬럼명 [ASC | DESC] )
```

### 🧩 구성 요소 분해

1. **`UNIQUE`**: (선택) 중복 값을 허용하지 않습니다.
    
    - 생략 시: **`NON-UNIQUE` (기본값)**가 적용되어 중복 값이 저장될 수 있습니다.
        
2. **`BITMAP`**: (선택) 데이터의 종류(Cardinality)가 적을 때 사용합니다.
    
    - 예: 성별(남/여), 결혼여부(Y/N).
    - 생략 시: 가장 일반적인 **`B-TREE` (기본값)** 인덱스가 생성됩니다.
        
3. **`ASC` | `DESC`**: (선택) 정렬 순서를 결정합니다.
    
    - **`ASC` (기본값):** 오름차순 (작은 값 → 큰 값, A → Z).
    - **`DESC`:** 내림차순. 최신 날짜부터 조회하거나 높은 점수부터 조회해야 할 때 성능상 유리합니다.
