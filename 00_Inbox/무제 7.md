## 📜 정리: SQL, 로직, 그리고 옵티마이저

### 종합 요약 (Logic Flow)

> [!note]- 데이터베이스 작동 메커니즘의 핵심
>
> 1. **역할의 분리:** 사용자가 작성한 **SQL**은 데이터 요구사항을, **함수와 프로시저**는 구체적인 비즈니스 로직을 정의하며, **DBMS의 옵티마이저**는 이를 수행하기 위한 방법(최적의 실행 순서와 접근 경로)을 결정하여 데이터 처리를 실행합니다.
>     
> 2. **로직의 구현 (User):** 사용자는 **연산 중심의 읽기(Read)** 로직은 **함수**로, **상태 변경 및 트랜잭션 제어(Write)** 로직은 **프로시저**로 구분하여 구현합니다.
>     
> 3. **실행의 최적화 (System):** 옵티마이저는 전달받은 로직(Target)을 분석하고, 인덱스 등(Tool)을 활용하여 비용이 가장 낮은 경로(Plan)를 수립해 실행합니다.
>

## 1. 사용자의 영역: 요구사항과 로직의 정의 (What & Logic)

사용자는 데이터베이스에게 "무엇을(What)" 원하고 "어떤 로직(Logic)"으로 처리할지를 정의합니다.

### A. SQL (요구사항 정의)

- **역할:** 데이터의 추출, 조작, 제어에 대한 최종 **결과물(Requirement)**을 명세합니다.
- **특징:** 선언형 언어이므로 구체적인 탐색 경로(How)는 기술하지 않습니다.
    

### B. 함수와 프로시저 (비즈니스 로직 정의)

SQL만으로 표현하기 힘든 절차적 흐름이나 복잡한 연산을 정의합니다. **'상태 변경 필요성'** 에 따라 두 가지 컨테이너로 나뉩니다.

#### 1) 함수 (Function) - 계산 및 조회 보조

- **배경:** 초기에는 데이터를 조회(`SELECT`)할 때 값을 가공하는 것이 주 목적이었습니다.
- **특징:**
    - **읽기 전용 (Read-Only):** 옵티마이저가 데이터를 읽어들이는(Fetch) 도중에 호출되므로, 데이터 무결성을 위해 테이블 상태 변경이 차단됩니다.
    - **종속성:** 독립적으로 실행되지 않고 항상 SQL 문장(`SELECT`, `WHERE` 절 등) 내부에 포함되어 실행됩니다.
        

#### 2) 프로시저 (Procedure) - 트랜잭션 및 흐름 제어

- **도입 이유 (함수의 한계 극복):** 조회 중 연산을 넘어, 실제 값을 변경하고 작업의 완결성(트랜잭션)을 보장해야 할 필요성이 대두되었습니다.
- **특징:**
	- **독립 실행:** 옵티마이저가 데이터를 읽고 있는 도중 즉, 조회과정에는 데이터의 무결성을 해치는 값 변경이 차단되므로 프로시저는 `SELECT` 문 내부에서 호출 불가하고, `CALL` 또는 `EXECUTE` 명령어로 단독 실행됩니다.
    - **트랜잭션 소유:** `SELECT`와 독립적으로 실행되므로, 내부에서 `COMMIT`, `ROLLBACK`을 명시하여 데이터 상태를 확정하거나 취소할 수 있습니다.
    - **반환값 생략:** 값을 산출하는 것이 목적이 아닌 '행위(Action)'가 목적이므로, 반환값(Return)을 생략할 수 있습니다.

## 2. DBMS의 영역: 실행 경로의 결정 (How & Optimization)

옵티마이저는 사용자가 정의한 SQL과 로직을 받아, 실제 하드웨어 리소스를 어떻게 사용할지 결정합니다. 이 과정에서 **'처리 대상'**과 **'사용 도구'**가 엄격히 구분됩니다.

### A. 옵티마이저의 대상 (Targets)

옵티마이저가 분석하고 비용(Cost)을 계산해야 할 **작업물**입니다.

- **SQL 문장:** 처리해야 할 기본 요청 단위입니다.
- **프로시저 (Container):**
    - 옵티마이저는 프로시저 생성(컴파일) 시점에 내부에 포함된 SQL들을 미리 분석하여 **실행 계획을 수립(Pre-compile)**해 둡니다.
    - 실행 시에는 저장된 계획을 재사용하여 파싱 부하를 줄입니다.
- **함수 (Workload):**
    - 옵티마이저 입장에서 함수는 **"행(Row)마다 CPU를 사용하여 계산해야 하는 비용"**으로 간주됩니다.
        

### B. 옵티마이저의 도구 (Tools)

옵티마이저가 "어떻게 하면 데이터를 가장 빠르게 가져올까?"를 판단할 때 **참조하는 자원**입니다.

- **인덱스 (Index):** 데이터를 빠르게 찾기 위한 지도(B-Tree 등).
- **통계 정보 (Statistics):** 데이터의 분포도, 행의 개수, 블록 수 등 판단의 근거.
- **시스템 지표 (System Metrics):** CPU 속도, 디스크 I/O 속도 등 하드웨어 환경 정보.
    

### 🚨 주의: 로직(대상)이 도구(인덱스)를 방해하는 경우

사용자가 정의한 로직(함수)이 부적절하게 사용되면, 옵티마이저는 도구(인덱스)를 사용할 수 없게 됩니다.

- **Index Suppression (인덱스 억제):**
    - **상황:** `WHERE YEAR(date) = '2024'`와 같이 컬럼을 함수로 감싸는 경우(좌변 가공).
    - **원인:** 인덱스는 원본 `date` 값 순서로 정렬되어 저장되어 있습니다. 함수로 가공된 `YEAR(date)` 값은 인덱스 트리에 존재하지 않습니다.
    - **결과:** 옵티마이저는 인덱스 매칭에 실패하고, 결국 **전체 테이블 스캔(Full Table Scan)**을 수행하여 성능 저하를 유발합니다.
