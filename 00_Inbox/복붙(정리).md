**2025-10-02, 1교시 — 개념**

## 한 줄 요약

단순 연결 리스트의 한계를 극복하기 위해 마지막 노드와 처음을 잇는 **원형 연결 리스트**, 그리고 양방향 탐색이 가능한 **이중 연결 리스트**의 구조와 장점을 학습합니다.

---

## 핵심 TL;DR

- **원형 연결 리스트**: 마지막 노드가 첫 노드를 가리켜, 어떤 노드에서든 전체 순회가 가능합니다. 🔄
- **Head-points-to-Tail 기법**: 원형 리스트의 `head` 포인터가 **마지막 노드**를 가리키게 하면, 리스트의 맨 앞(`head->link`)과 맨 뒤(`head`)에 모두 $O(1)$로 접근 가능해져 연산이 효율적입니다.
- **이중 연결 리스트**: 각 노드가 이전 노드(`prev`)와 다음 노드(`next`)를 모두 가리켜, ?? 시간에 이전 노드로 즉시 접근할 수 있습니다.
- **더미 노드 (Dummy Node)**: 데이터를 담지 않는 가짜 노드를 리스트의 시작점에 두어, 빈 리스트나 양 끝에서의 삽입/삭제 등 예외 케이스 처리를 없애고 알고리즘을 단순화합니다.
- **실용적인 구현**: 실제로는 **원형 이중 연결 리스트에 더미 노드를 추가**한 형태가 가장 보편적으로 사용되며, 알고리즘의 일관성과 안정성이 높습니다.
- **이중 연결 리스트의 불변성**: 정상적인 리스트의 어떤 노드 `p`에서도 `p->next->prev == p`가 항상 성립하며, 이는 리스트 연결의 무결성을 보장합니다.

---

## 표현 = 표준 용어

- **`Circular Linked List`** (원형 연결 리스트)
- **`Doubly Linked List`** (이중 연결 리스트)
- **`Head Pointer`** (헤드 포인터): 리스트의 특정 노드(첫 노드 또는 마지막 노드)를 가리키는 외부 포인터.
- **`Dummy Node`** (더미 노드): 알고리즘 단순화를 위해 사용하는 데이터가 없는 가짜 노드. `Head Node`라고도 불림.
- **`Invariant`** (불변 속성): 자료구조가 정상 상태일 때 항상 참이 되는 조건.
- **`Previous / Next Pointer`** (이전 / 다음 포인터): 이중 연결 리스트 노드의 양방향 링크.

---

## 정석 보강 (canon-std): 더미 헤드 노드

**더미 헤드 노드(Dummy Head Node)**는 실제 데이터를 저장하지 않고 리스트의 시작과 끝을 표기하는 역할을 하는 특수 노드입니다.

이 노드를 사용하면 모든 삽입/삭제 연산을 **'두 노드 사이'에서 일어나는 단일 케이스로 일반화**할 수 있습니다. 따라서 빈 리스트 처리, 맨 앞/뒤 노드 처리 등 **복잡한 조건 분기를 제거**하여 코드의 간결성과 안정성을 크게 높일 수 있습니다.

원형 이중 연결 리스트에서 리스트가 비어있을 때 더미 노드의 `next`와 `prev`는 자기 자신을 가리키며, 데이터가 추가되면 더미 노드는 항상 **첫 노드와 마지막 노드 사이에 위치**하게 됩니다.

---

## 실수·함정

- 원형 리스트 순회 시, 시작점으로 돌아왔는지 확인하지 않아 **무한 루프**에 빠지는 오류.
- 'Head-points-to-Tail' 기법에서 `head`가 마지막 노드임을 잊고 **`head` 자체를 첫 노드로 착각**하는 실수.
- 이중 연결 리스트에서 삽입/삭제 시 **`next` 포인터만 수정하고 `prev` 포인터를 수정하지 않아** 연결이 깨지는 오류.
- 더미 노드가 있을 때 리스트가 비어있는지 확인할 때 `head == NULL`로 검사하는 실수 (정답: **`head->next == head`**).
- 단순 원형 리스트에서 이전 노드를 **$O(1)$에 접근할 수 있다고 착각**하는 것 (접근은 가능하나 순회가 필요해 $O(n)$이 소요됨).

### Q1: 원형 연결 리스트의 탐색 장점

**원형 연결 리스트**는 단순 연결 리스트에 비해 **'탐색' 관점**에서 어떤 핵심적인 장점을 가지는가?

- 강의 기준 모범 답:

    어떤 노드에서든 링크를 계속 따라가면 모든 노드를 방문할 수 있으므로, 특정 노드 이전을 탐색하기 위해 head 포인터부터 다시 시작할 필요가 없습니다.

- 정석 체크 (30초 답변):

    장점은 **'임의 노드에서의 전체 순회 가능성'**입니다. 이로 인해 head 포인터에 대한 의존성이 줄어들어 탐색 알고리즘이 더 유연해집니다.

---

### Q2: Head-points-to-Tail 기법

원형 연결 리스트에서 `head` 포인터가 첫 노드가 아닌 **'마지막 노드'를 가리키게 하면** 어떤 연산이 얼마나 효율적으로 개선되는가?

- 강의 기준 모범 답:

    리스트의 맨 뒤에 접근하는 연산이 $O(n)$에서 $O(1)$로 개선됩니다. 동시에, 리스트의 맨 앞 접근 역시 head->link를 통해 $O(1)$을 유지하므로 리스트 양 끝단에서의 연산이 모두 매우 효율적이게 됩니다.

- 정석 체크 (30초 답변):

    이 기법은 리스트의 맨 앞 접근(head->link)과 맨 뒤 접근(head)을 모두 O(1) 시간 복잡도로 가능하게 합니다. 이는 큐(Queue)와 같은 자료구조를 연결 리스트로 구현할 때 특히 유용합니다.

---

### Q3: 더미 노드 사용 이유

이중 연결 리스트에서 실제 데이터를 담지 않는 **'더미 노드(Dummy Node)'**를 사용하는 주된 이유는 무엇인가?

- 강의 기준 모범 답:

    더미 노드를 사용하면 리스트가 비어있을 때, 혹은 맨 앞이나 맨 뒤에 노드를 삽입/삭제할 때와 같은 예외적인 경우를 따로 처리할 필요가 없어집니다. 모든 연산을 '두 노드 사이'의 일반적인 연산으로 통일시켜 알고리즘을 간결하게 만듭니다.

- 정석 체크 (30초 답변):

    목적은 **'알고리즘의 일반화(generalization)'**입니다. 더미 노드는 경계 조건(boundary condition)을 제거하여, 모든 삽입/삭제 로직을 단일 케이스로 처리할 수 있게 해 코드의 복잡도를 낮추고 안정성을 높입니다.

---

### Q4: 더미 노드와 빈 리스트 확인

더미 노드를 사용하는 원형 이중 연결 리스트에서 리스트가 **비어있는지 여부**는 어떻게 확인할 수 있는가?

- 강의 기준 모범 답:

    더미 노드(head)의 다음(next 또는 r_link) 포인터가 자기 자신을 가리키고 있는지 확인하면 됩니다. 즉, head->next == head 조건이 참이면 리스트는 비어있는 것입니다.

- 정석 체크 (30초 답변):

    빈 리스트의 조건은 **'더미 노드만 존재하는 상태'**입니다. 원형 구조에서 이는 더미 노드의 next와 prev 포인터가 모두 자기 자신을 가리키는 것으로 표현되므로, **head->next == head**로 검사합니다.

---

### Q5: 이중 연결 리스트의 불변 속성

정상적인 이중 연결 리스트의 임의의 노드 `p`에 대해 **`p->next->prev == p`** 라는 불변 속성(invariant)이 항상 성립하는 이유는 무엇이며, 이 속성은 무엇을 의미하는가?

- 강의 기준 모범 답:

    모든 노드의 next 포인터는 다음 노드를, prev 포인터는 이전 노드를 정확히 가리키기 때문입니다. 이 속성은 리스트의 양방향 연결이 깨지지 않고 온전한 상태(무결성)를 유지하고 있음을 의미합니다.

- 정석 체크 (30초 답변):

    이 불변식은 **'양방향 링크의 대칭성'**을 보장합니다. 노드 A가 B를 next로 가리키면, 노드 B는 반드시 A를 prev로 가리켜야 한다는 관계를 수학적으로 표현한 것으로, 자료구조의 정합성을 검증하는 데 사용될 수 있습니다.

**2025-10-02, 2교시 — 개선본**

1. 이중 연결 리스트 삽입 (Doubly Linked List Insertion)

before 노드 뒤에 new_node를 삽입하는 연산은 총 4개의 포인터 연결을 변경해야 하며, 수행 순서가 매우 중요합니다. before 노드를 기준으로 연산을 수행한다고 가정합니다.

올바른 포인터 변경 순서는 다음과 같습니다.

1. `new_node->l_link = before;`
    
    - 새 노드의 왼쪽(previous) 포인터가 `before` 노드를 가리키게 합니다.
        
2. `new_node->r_link = before->r_link;`
    
    - 새 노드의 오른쪽(next) 포인터가 `before` 노드의 기존 다음 노드를 가리키게 합니다.
        
3. `before->r_link->l_link = new_node;`
    
    - `before`의 **기존** 다음 노드의 왼쪽(previous) 포인터가 새 노드를 가리키게 합니다.
        
4. `before->r_link = new_node;`
    
    - `before` 노드의 오른쪽(next) 포인터가 새 노드를 가리키게 합니다.

여기서 **3번과 4번의 순서는 바뀌면 안 됩니다.** 만약 4번을 먼저 수행하면 `before->r_link`의 참조값이 `new_node`로 덮어써집니다. 그 상태에서 3번을 수행하면, `new_node`의 왼쪽 포인터가 자기 자신을 가리키는 잘못된 순환이 발생합니다. 따라서 반드시 기존 노드들의 연결을 먼저 수정한 후(`3번`), 기준 노드의 연결을 변경해야(`4번`) 합니다.

2. 이중 연결 리스트 삭제 (Doubly Linked List Deletion)

삭제 연산은 삽입보다 간단합니다. 삭제할 노드를 removed라고 할 때, removed의 양 옆 노드가 서로를 직접 가리키도록 연결을 변경합니다.

- **삭제 전제 조건**: 리스트가 비어있으면 안 됩니다. 또한, 알고리즘을 단순화하기 위해 사용한 더미 헤드 노드(dummy head node) 자체는 삭제할 수 없습니다.

삭제 절차는 다음과 같습니다.

1. `removed->l_link->r_link = removed->r_link;`
    
    - 삭제할 노드의 이전 노드가, 삭제할 노드의 다음 노드를 가리키게 합니다.
        
2. `removed->r_link->l_link = removed->l_link;`
    
    - 삭제할 노드의 다음 노드가, 삭제할 노드의 이전 노드를 가리키게 합니다.
        
3. `free(removed);`
    
    - `removed` 노드에 할당된 메모리를 반드시 해제하여 메모리 누수를 방지합니다.

4. 응용: 연결 리스트를 이용한 다항식 덧셈

연결 리스트는 다항식 연산과 같은 복잡한 문제에 효과적으로 사용될 수 있습니다. 각 노드의 데이터 필드를 계수(coefficient)와 지수(exponent)를 담는 구조체로 정의하여 다항식의 각 항을 표현합니다.

두 다항식 A와 B를 더하는 알고리즘은 다음과 같습니다.

- 두 개의 포인터 `p`와 `q`가 각각 다항식 A와 B의 첫 항부터 순회를 시작합니다.
- `p`와 `q`가 가리키는 항의 **지수를 비교**합니다.
    - **`p->지수 > q->지수`**: `p`가 가리키는 항을 결과 다항식 C에 추가하고, `p`만 다음 항으로 이동합니다.
    - **`p->지수 < q->지수`**: `q`가 가리키는 항을 결과 다항식 C에 추가하고, `q`만 다음 항으로 이동합니다.
    - **`p->지수 == q->지수`**: 두 항의 계수를 더한 새 항을 결과 다항식 C에 추가하고, `p`와 `q` 모두 다음 항으로 이동합니다. (단, 합이 0이면 새 항을 추가하지 않습니다.)
- 한쪽 다항식의 끝(`NULL`)에 도달하면, 다른 쪽에 남아있는 모든 항을 결과 다항식 C의 뒤에 그대로 이어 붙입니다.

이처럼 연결 리스트를 사용하면 배열 기반 구현의 크기 제한 문제 없이 유연하게 다항식을 처리할 수 있습니다. 제공될 예제 코드를 분석하고, 직접 자료구조를 코딩하여 실행해 보시기 바랍니다. (실습)

    이중 연결 리스트의 핵심 연산인 삽입과 삭제 시 발생하는 복잡한 포인터 변경 순서를 학습하고, 연결 리스트를 응용한 다항식 덧셈 알고리즘을 다룹니다.

2. **핵심 TL;DR**

- **이중 연결 리스트 삽입**: 총 **4개의 포인터 연결**을 변경해야 하며, 기존 리스트의 연결을 먼저 수정한 후 기준 노드의 연결을 변경하는 **순서**가 매우 중요합니다.
- **삽입 정보의 유연성**: 단순 연결 리스트와 달리, 이중 연결 리스트는 삽입할 위치의 **앞 노드와 뒤 노드 중 어느 쪽을 기준으로 삼아도** 연산이 가능합니다.
- **이중 연결 리스트 삭제**: 삭제할 노드의 **양 옆 노드가 서로를 가리키도록 2개의 포인터를 변경**하고, 삭제된 노드의 메모리를 `free()`로 반드시 해제해야 합니다.
- **삭제의 전제조건**: 리스트가 비어 있거나, 삭제 대상이 **더미 헤드 노드**인 경우 삭제 연산을 수행할 수 없습니다.
- **응용: 다항식 덧셈**: 두 다항식 리스트를 포인터로 순회하며 **지수를 비교**하고, 비교 결과(큼, 작음, 같음)에 따라 항을 결과 리스트에 추가하는 방식으로 덧셈을 구현합니다.
- **알고리즘 종료 처리**: 다항식 덧셈에서 한쪽 리스트가 먼저 끝나면, 다른 쪽에 **남아있는 모든 항들을 결과 리스트 뒤에 그대로 이어 붙여** 연산을 마무리합니다.

3. **표현 = 표준 용어**

- `Pointer Reassignment` (포인터 재할당/변경): 포인터 변수가 가리키는 주소 값을 바꾸는 연산.
- `Insertion Order` (삽입 순서): 연결 리스트 삽입 시 포인터를 변경하는 순서.
- `Precondition` (전제 조건): 특정 연산이 유효하기 위해 반드시 만족해야 하는 조건.
- `Polynomial Addition` (다항식 덧셈): 두 다항식을 더하는 연산.
- `Coefficient` (계수): 다항식에서 각 항의 상수 부분.
- `Exponent` (지수): 다항식에서 각 항의 차수.

4. **정석 보강(고정: canon-std)**

- **주제**: 이중 연결 리스트 삽입 (노드 `p` 뒤에 `new_node` 삽입)
- **전제**: `p`는 삽입 위치의 선행 노드, `p_next`는 `p`의 기존 다음 노드이다.
- **핵심 의사코드 (4-steps)**:
    
    1. `new_node->prev = p;`
    2. `new_node->next = p_next;`
    3. `p_next->prev = new_node;`
    4. `p->next = new_node;`
        
- **주의**: 3번과 4번의 순서는 바뀔 수 없다. 4번을 먼저 실행하면 `p_next`에 대한 참조를 잃게 될 위험이 있다.

5. **실수·함정**

- 이중 연결 리스트 삽입 시, 4개의 포인터 중 일부만 변경하여 리스트의 연결을 깨뜨리는 오류.
- 삽입/삭제 시 `prev`와 `next` 포인터를 반대로 연결하는 실수.
- 다항식 덧셈에서 한쪽 리스트가 끝났을 때, 남은 항들을 이어 붙이는 로직을 누락하는 것.
- 계수의 합이 0이 되는 항을 결과 리스트에 그대로 추가하는 비효율적인 처리.
- `free()` 호출 누락으로 인한 메모리 누수 발생.
- 제공된 코드를 분석하거나 직접 구현해보지 않고 개념만 이해했다고 넘어가는 것.

**2025-10-02, 3교시 — 개선본**

스택, 큐와 같은 선형 구조(Linear Structure)로는 표현하기 어려운 계층적 데이터를 다루기 위해 **비선형 구조(Non-linear Structure)**를 사용하며, 그 대표적인 예가 **트리(Tree)**와 **그래프(Graph)**입니다.

1. 트리의 필요성 및 이진 트리의 도입

가계도, 조직도, 파일 시스템의 디렉터리 구조와 같이 계층적인 관계를 표현하기 위해서는 트리가 필수적입니다.

일반 트리(General Tree)는 하나의 부모 노드가 여러 개의 자식 노드를 가질 수 있습니다. 하지만 이 경우, 노드마다 자식의 수가 달라 일관된 구조체(`struct`)를 정의하기 어렵습니다. 노드를 추가하거나 삭제할 때 구조체 타입 자체가 변경될 수 있어 구현이 매우 복잡해지기 때문입니다.

이러한 복잡성을 해결하기 위해, 학부 수준에서는 자식 노드가 최대 2개인 **이진 트리(Binary Tree)**에 집중합니다. 이진 트리는 구조가 규격화되어 있어 구현과 연산이 훨씬 용이하며, 일반 트리의 개념을 학습하는 기초가 됩니다.

**2. 트리 기본 용어**

- **노드(Node)**: 트리를 구성하는 각 요소.
- **루트(Root)**: 트리의 최상위 노드.
- **간선(Edge)**: 노드 간의 연결선.
- **단말 노드(Terminal Node) / 리프(Leaf)**: 자식 노드가 없는 노드.
- **차수(Degree)**: 특정 노드에 연결된 자식 노드의 수. 트리의 차수는 모든 노드의 차수 중 최댓값입니다.
- **레벨(Level)**: 루트를 레벨 1(또는 0)으로 시작하여, 아래로 내려갈수록 1씩 증가하는 층.
- **높이(Height)**: 루트에서 가장 깊은 단말 노드까지의 경로 길이.

**3. 이진 트리의 종류**

- **포화 이진 트리(Full Binary Tree)**: 모든 레벨에 노드가 꽉 차 있는 트리. 높이가 `h`일 때 노드의 개수는 2^h-1개입니다.
- **완전 이진 트리(Complete Binary Tree)**: 마지막 레벨을 제외한 모든 레벨이 꽉 차 있으며, 마지막 레벨의 노드들은 왼쪽부터 순서대로 채워진 트리입니다. 포화 이진 트리는 완전 이진 트리의 특수한 경우입니다.
- **편향 이진 트리(Skewed Binary Tree)**: 모든 노드가 왼쪽 또는 오른쪽 자식 노드만 가지는 트리로, 연결 리스트와 유사한 형태를 띱니다.

**4. 이진 트리의 구현**

A. 배열을 이용한 구현

완전 이진 트리나 포화 이진 트리의 경우, 노드 사이에 빈 공간이 없어 배열로 효율적으로 표현할 수 있습니다. 루트 노드를 인덱스 1에 저장하면 부모/자식 관계를 간단한 수식으로 계산할 수 있습니다.

- 노드 `i`의 **부모 노드** 인덱스: `i / 2`
- 노드 `i`의 **왼쪽 자식** 인덱스: `2 * i`
- 노드 `i`의 **오른쪽 자식** 인덱스: `2 * i + 1`
- **장점**: 구현이 간단하고, 수식을 통해 부모/자식 관계를 빠르게 찾을 수 있습니다.
- **단점**: 편향 트리처럼 비효율적인 경우 메모리 낭비가 심하며, 크기가 고정되어 삽입/삭제가 어렵습니다.

B. 연결 리스트를 이용한 구현

각 노드를 구조체로 정의하고 포인터로 연결하는 방식은 모든 종류의 트리에 유연하게 적용할 수 있습니다.

- **구조체 정의**: `struct TreeNode { struct TreeNode *left; Element data; struct TreeNode *right; };` 와 같이 데이터 필드와 왼쪽/오른쪽 자식을 가리키는 두 개의 자기 참조 포인터로 구성됩니다.
- **노드 생성 및 연결**: `malloc`으로 각 노드를 동적으로 생성하고, 부모 노드의 `left` 또는 `right` 포인터에 자식 노드의 주소 값을 할당하여 연결합니다.
    - `n1->left = n2;` 구문은 `n1`의 `left` 포인터가 `n2` 포인터 변수 자체가 아닌, `n2`가 가리키고 있는 **노드의 주소**를 가리키게 하는 것임을 명확히 이해해야 합니다.

개념이 어려울 때는 직접 그림을 그려가며 포인터의 움직임을 따라가는 것이 이해에 큰 도움이 됩니다.

- **주요 용어**: 트리는 루트(최상위), 리프(최하위), 차수(자식 수), 높이(최대 레벨) 등의 용어로 구성됩니다.
- **완전 이진 트리**: 마지막 레벨을 제외하고 모든 노드가 채워져 있으며, 마지막 레벨은 왼쪽부터 채워진 트리로, 배열 구현에 효율적입니다.
- **배열 구현**: 루트를 인덱스 1에 저장 시, 노드 `i`의 부모는 `i/2`, 왼쪽 자식은 `2*i`, 오른쪽 자식은 `2*i+1`로 쉽게 계산할 수 있습니다.
- **연결 리스트 구현**: 노드를 `데이터`, `왼쪽 자식 포인터`, `오른쪽 자식 포인터`를 갖는 구조체로 정의하고 동적으로 연결합니다.

3. **표현 = 표준 용어**

- `Tree` (트리): 계층적 구조를 나타내는 비선형 자료구조.
- `Binary Tree` (이진 트리): 모든 노드의 차수가 2 이하인 트리.
- `Root` (루트): 트리의 시작점이 되는 최상위 노드.
- `Leaf Node` (단말 노드): 자식 노드가 없는 노드.
- `Complete Binary Tree` (완전 이진 트리): 마지막 레벨을 제외하고 왼쪽부터 채워진 트리.
- `Array Representation` (배열 표현법): 배열을 사용하여 트리를 구현하는 방식.
- `Linked Representation` (연결 리스트 표현법): 포인터를 사용하여 트리를 구현하는 방식.

4. **정석 보강(고정: canon-std)**

- **주제**: 배열을 이용한 이진 트리 표현법
- **전제**: 루트 노드를 배열의 인덱스 `1`에 저장한다. (인덱스 `0`은 비워둠)
- **핵심 수식/규칙**:
    - `Parent(i) = floor(i / 2)` (단, `i > 1`)
    - `Left_Child(i) = 2 * i`
    - `Right_Child(i) = 2 * i + 1`
- **적용**: 이 방식은 노드 간격이 없는 완전 이진 트리에 가장 메모리 효율적이다.

5. **실수·함정**

- 일반 트리의 각기 다른 자식 수를 처리하는 구현의 복잡성을 간과하는 것.
- 포화 이진 트리와 완전 이진 트리의 차이를 혼동하는 것 (포화는 완전의 부분집합).
- 배열로 편향 트리를 구현할 때 발생하는 심각한 메모리 낭비.
- 연결 리스트 구현 시, `n1->left = n2`가 `n1`이 `n2` 포인터 변수 자체를 가리키는 것으로 오해하는 것.
- 배열 구현 시 루트를 인덱스 `0`에서 시작하여 부모/자식 계산 수식이 복잡해지는 경우.
- 트리가 비선형 구조임에도 선형 구조(리스트 등)로만 해결하려는 시도.

**[Q1] 일반 트리 대신 자식 노드가 최대 2개인 '이진 트리'를 주로 학습하는 이유는 무엇인가? | #자료구조 #추상화**

- **· 모범답(강의 기준, 1–2문장)**: 일반 트리는 노드마다 자식의 수가 달라 일관된 구조체(`struct`)로 규격화하기 어렵고, 삽입/삭제 시 구조의 변경이 매우 복잡하기 때문입니다. 이진 트리는 구조가 통일되어 있어 구현과 연산이 훨씬 용이합니다.
- **· 정석체크(면접 30초 대답분량)**: 이유는 '구현의 표준화'입니다. 이진 트리는 `left`, `right` 두 개의 포인터만으로 모든 노드를 일관되게 표현할 수 있어 범용적인 알고리즘 설계가 가능하지만, 일반 트리는 그렇지 않아 복잡도가 크게 증가합니다.

**[Q2] 이진 트리를 배열로 구현할 때(루트=인덱스 1), 특정 노드 `i`의 부모와 자식 노드를 인덱스 계산만으로 빠르게 찾는 방법은 무엇인가? | #배열_표현법 #알고리즘**

- **· 모범답(강의 기준, 1–2문장)**: 부모 노드의 인덱스는 `i/2`의 정수 값으로, 왼쪽 자식은 `2*i`, 오른쪽 자식은 `2*i+1`로 계산할 수 있습니다.
- **· 정석체크(면접 30초 대답분량)**: 노드 `i`의 부모는 `floor(i/2)`, 왼쪽 자식은 `2*i`, 오른쪽 자식은 `2*i+1` 입니다. 이 공식은 완전 이진 트리에서 메모리 낭비 없이 효율적으로 동작합니다.

**[Q3] 이진 트리를 구현하는 두 가지 방식인 '배열'과 '연결 리스트'의 장단점을 비교 설명하라. | #구현 #비교**

- **· 모범답(강의 기준, 1–2문장)**: 배열은 완전 이진 트리에서 메모리 효율이 좋고 부모/자식 계산이 빠르지만, 크기가 고정되고 편향 트리에서 공간 낭비가 심합니다. 연결 리스트는 유연한 크기 조절과 삽입/삭제가 용이하지만, 추가적인 포인터 공간이 필요하고 구현이 더 복잡합니다.
- **· 정석체크(면접 30초 대답분량)**: 배열은 정적이고 공간 효율이 데이터 형태에 따라 좌우되지만 특정 관계 계산이 $O(1)$입니다. 연결 리스트는 동적이고 유연하지만 관계 탐색에 순회가 필요하고 포인터 오버헤드가 있습니다.

**[Q4] '포화 이진 트리(Full Binary Tree)'와 '완전 이진 트리(Complete Binary Tree)'의 정의상 차이점은 무엇인가? | #용어 #정의**

- **· 모범답(강의 기준, 1–2문장)**: 포화 이진 트리는 모든 레벨에 노드가 꽉 차 있는 트리입니다. 완전 이진 트리는 마지막 레벨을 제외하고는 꽉 차 있으며, 마지막 레벨은 왼쪽부터 순서대로 노드가 채워진 트리입니다.
- **· 정석체크(면접 30초 대답분량)**: 포화 이진 트리는 높이가 `h`일 때 2^h-1개의 노드를 가진 완벽한 삼각형 형태의 트리입니다. 완전 이진 트리는 마지막 레벨이 왼쪽부터 채워져 있기만 하면 되므로, 포화 이진 트리는 완전 이진 트리의 특수한 경우(부분집합)입니다.

**[Q5] 연결 리스트로 트리를 구현하는 C 코드 `n1->left = n2;`에서, `n1->left`에 실제 할당되는 값은 무엇이며, 이 구문이 의미하는 바는 무엇인가? | #포인터 #메모리**

- **· 모범답(강의 기준, 1–2문장)**: `n2` 포인터 변수 자체가 아니라, `n2`가 담고 있는 '주소 값'이 `n1->left` 포인터에 복사됩니다. 이는 `n1` 노드의 왼쪽 자식이 `n2`가 가리키는 노드를 가리키도록 연결하는 것을 의미합니다.
- **· 정석체크(면접 30초 대답분량)**: 할당되는 값은 `n2` 포인터가 저장하고 있는 메모리 주소입니다. 이 구문은 `n1` 노드와 `n2`가 가리키는 노드 사이에 '부모-왼쪽 자식' 관계를 설정하는 포인터 연결 작업입니다.
