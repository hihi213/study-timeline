## **2025-09-18, 1교시 — 개선본**

오늘 리스트(List) 개념을 마무리하겠습니다.

지난 시간에 구조체에 대해 간단히 이야기했습니다. 알고리즘과 구조체가 직접적인 연관은 적지만, 결국 여러분이 모두 코딩을 해야 하므로 리스트에 들어가기 전 관련 개념을 잡아야 합니다.

`struct card`와 같은 구조체를 만든다고 가정해 봅시다. 구조체란, 하나의 변수가 여러 속성의 자료형을 한 번에 포함하는 형태입니다. 현실의 객체를 컴퓨터 세계로 가져오기 위해 변수를 만드는데, 이 변수가 배열처럼 동일한 자료형의 묶음이 아닐 때 사용합니다. 예를 들어 '학생'이라는 데이터를 시스템에 넣으려면 학번, 이름, 학과, 학년 등 다양한 타입의 정보가 하나의 단위로 움직여야 합니다.

이럴 때 만드는 것이 바로 사용자 정의 자료형입니다. `구조체(struct)`는 결국 사용자 정의 자료형의 일종이며, 자료구조 시간에 배우는 `큐(Queue)`나 `스택(Stack)` 또한 마찬가지입니다. 구조체는 멤버(member)를 갖고, 그 구조체 타입의 변수명을 선언하여 사용합니다. `c1`이라는 변수를 선언하고 초기값을 직접 할당한 뒤, `c1.pips`, `c1.suit`처럼 멤버에 접근할 수 있습니다.

함수에 구조체를 전달하는 방식에는 두 가지가 있습니다. 첫째는 값에 의한 호출(`call-by-value`)입니다. 함수 내에서 전달받은 구조체 멤버의 값을 변경해도, 함수가 종료되면 그 변경 사항은 사라지고 원본 변수에는 아무런 영향을 미치지 않습니다. 이는 함수의 매개변수가 원본의 복사본이기 때문입니다.

둘째는 참조에 의한 호출(`call-by-reference`)로, 변수의 주소값을 전달하는 방식입니다. 함수에서는 이 주소값을 포인터로 받아 작업을 수행합니다. 포인터를 통해 원본 메모리 위치에 직접 접근하므로, 함수 내에서의 변경 사항이 함수 종료 후에도 그대로 유지됩니다. 나중에 다룰 연결 리스트(Linked List)는 `malloc`으로 동적 할당을 하므로, 모두 이 참조에 의한 호출 방식을 사용하게 됩니다. 이 차이를 헷갈리면 안 됩니다.

다항식을 구조체와 배열로 표현하는 방법을 알아봅시다. 예를 들어 10x5+6x1+3x0 라는 다항식이 있다면, 첫 번째 방법은 최고 차수+1 크기의 배열을 만들어 계수만 저장하는 것입니다. 인덱스를 차수로 대응시키는 방식이죠. 이 방법의 장점은 덧셈 같은 연산을 할 때, 같은 인덱스(차수)의 값만 확인하면 되므로 알고리즘이 매우 간단해진다는 점입니다.

하지만 1x1000+6 과 같이 항의 개수는 적지만 최고 차수가 매우 높은 '희소 다항식(sparse polynomial)'의 경우, 실제 데이터는 두 개뿐인데도 1001개의 배열 공간을 할당해야 하므로 메모리 낭비가 심각하다는 단점이 있습니다.

이런 단점을 보완하는 두 번째 방법은 0이 아닌 항의 '계수'와 '지수' 쌍만을 배열에 저장하는 것입니다. 예를 들어 A=8x3+7x1+1, B=10x3+3x2+1 이라는 두 다항식을 더하는 알고리즘을 생각해 봅시다.

두 다항식 A와 B의 항들을 순차적으로 비교하며 진행합니다.

1. 두 다항식의 현재 항의 지수를 비교합니다.
2. 만약 `A.지수 > B.지수`이면, A의 항을 결과 다항식에 넣고 A의 다음 항으로 이동합니다.
3. 만약 `A.지수 < B.지수`이면, B의 항을 결과 다항식에 넣고 B의 다음 항으로 이동합니다.
4. 만약 `A.지수 == B.지수`이면, 두 계수를 더한 새로운 항을 결과 다항식에 넣고, A와 B 모두 다음 항으로 이동합니다.
5. 한쪽 다항식의 모든 항을 처리했다면, 다른 쪽에 남아있는 모든 항을 결과 다항식에 순서대로 추가합니다.

    이 다항식 덧셈 로직을 구조체를 활용하여 C언어로 직접 프로그래밍 해보시길 바랍니다. (실습)

다음으로 구조체 안에 또 다른 구조체가 멤버로 포함되는 중첩 구조체에 대해 알아보겠습니다. `struct person_name` 이라는 이름 구조체와, 이 구조체 변수를 멤버로 갖는 `struct student` 라는 학생 구조체를 정의할 수 있습니다. 학생 구조체 변수 `student1`에서 이름의 `first`(이름) 멤버에 접근하려면 `student1.name.first` 와 같이 연쇄적으로 접근하면 됩니다. 구조체 멤버가 배열일 수도 있는 등, 구조체는 여러분이 필요한 형태로 자유롭게 설계할 수 있습니다.

문자열을 멤버로 가지는 구조체에 값을 할당할 때, 해당 멤버가 `char` 배열이라면 `strcpy` 함수를 사용해야 합니다. 배열의 이름은 그 자체로 상수 포인터(constant pointer)이므로, 문자열 리터럴을 직접 대입할 수 없고 복사 함수를 써야 합니다. 반면, 멤버가 단일 `char` 변수라면 직접 문자를 대입할 수 있습니다. 또한, 동일한 타입의 구조체 변수끼리는 대입 연산(=)이 가능하며, 이 경우 모든 멤버의 값이 복사됩니다. 이러한 구조체의 자료형과 멤버의 타입을 정확히 이해하고 값을 할당해야 오류를 피할 수 있습니다.

이제 오늘 배울 연결 리스트의 핵심인 **자기 참조 구조체(self-referential structure)**에 대해 알아보겠습니다. 이는 구조체 자기 자신의 타입을 가리키는 포인터를 멤버로 갖는 구조체를 말합니다.

`struct list_node { char data[10]; struct list_node *link; };`

위 정의에서 `link`라는 멤버는 `struct list_node` 타입을 가리키는 포인터입니다. 이 구조를 통해, 하나의 노드(node)가 다음 노드의 메모리 주소를 가리키게 하여 데이터들을 사슬처럼 연결할 수 있습니다.

배열은 크기가 고정되어 있지만, 자기 참조 구조체를 사용하면 필요할 때마다 `malloc` 함수로 메모리를 동적으로 할당하여 새로운 노드를 만들고, 이 노드를 기존 리스트에 연결하여 데이터의 개수를 자유자재로 늘리거나 줄일 수 있습니다. 데이터가 10개 필요하면 노드를 하나 생성하고, 또 10개가 더 필요하면 새 노드를 동적으로 생성하여 이전 노드의 `link`에 연결하면 됩니다.

끝.

## **2025-09-18, 1교시 — 개념**

### 1. 한 줄 요약

C언어의 구조체(struct)를 사용자 정의 자료형으로 이해하고, 값/참조 호출 방식의 차이와 다항식 표현법을 학습하며, 연결 리스트의 기반이 되는 자기 참조 구조체와 동적 할당의 개념을 소개합니다.

### 2. 핵심 TL;DR

- **구조체(struct)**는 여러 타입의 변수들을 하나의 논리적 단위로 묶는 사용자 정의 자료형입니다.
- **값에 의한 호출(Call-by-value)**은 함수에 구조체 전체의 복사본을 전달하므로, 함수 내 수정이 원본에 영향을 주지 않습니다.
- **참조에 의한 호출(Call-by-reference)**은 구조체의 메모리 주소(포인터)를 전달하여, 함수 내에서 원본 데이터를 직접 수정할 수 있게 합니다.
- **다항식의 배열 표현**은 최고 차수 크기의 배열을 사용하며, 알고리즘은 간단하지만 항이 적고 차수가 높으면 메모리 낭비가 심합니다.
- **다항식의 구조체 표현**은 0이 아닌 항의 (계수, 지수) 쌍만 저장하여 메모리 효율성을 높입니다.
- **중첩 구조체**는 구조체 안에 다른 구조체를 멤버로 포함하는 것으로, `변수.내부변수.멤버`처럼 연쇄적으로 접근합니다.
- **자기 참조 구조체**는 구조체 멤버로 자기 자신과 동일한 타입의 포인터를 가지며, 동적 자료구조의 기본 단위가 됩니다.
- **동적 할당**은 `malloc` 등을 사용해 프로그램 실행 중에 필요한 만큼 메모리(노드)를 생성하며, 자기 참조 구조체를 통해 이들을 연결합니다.

### 3. 표현 = 표준 용어

- **`struct`**: A composite data type that groups variables of potentially different types under a single name.
- **`typedef`**: Creates a synonym (alias) for an existing data type, often used to simplify complex struct declarations. e.g., `typedef struct Node Node;`
- **Call-by-value**: A function argument passing strategy where a copy of the argument's value is passed to the function.
- **Call-by-reference**: A function argument passing strategy where the argument's memory address (a pointer to it) is passed.
- **Self-referential Structure**: A structure that includes a member that is a pointer to another structure of the same type.
- **Dynamic Memory Allocation**: The process of allocating memory at runtime (e.g., using `malloc()`), rather than at compile time.

### 4. 정석 보강 (canon-std)

자기 참조 구조체는 구조체의 멤버 중 하나가 자기 자신과 같은 타입의 구조체를 가리키는 포인터 변수인 구조입니다. 이는 정적인 배열과 달리, 런타임에 데이터의 개수가 변하는 연결 리스트, 트리 등 동적 자료구조를 구현하기 위한 핵심 전제입니다. 기본 형태는 `struct Node { int data; struct Node* next; };` 와 같으며, `next` 포인터는 또 다른 `Node` 객체의 주소를 저장하여 데이터들을 사슬처럼 연결합니다.

### 5. 실수·함정

- 원본 구조체를 수정할 의도임에도 불구하고, 포인터 대신 구조체 변수 자체를 함수에 넘겨 값에 의한 호출을 하는 실수.
- `strcpy()` 함수를 사용하지 않고 문자열 배열 멤버에 문자열 리터럴을 직접 대입하려는 시도. (예: `student.name = "Kim";` (X))
- 구조체 포인터를 통해 멤버에 접근할 때 마침표(`.`) 연산자를 사용하는 오류. (`ptr.member` (X)가 아니라 `ptr->member` (O)가 맞음)
- `malloc()`으로 메모리 할당 후 반환값이 `NULL`인지 확인하는 과정을 생략하여 발생하는 런타임 오류.
- 동적으로 할당한 메모리를 `free()`로 해제하지 않아 발생하는 메모리 누수(memory leak).
- 중첩 구조체 멤버에 접근할 때, `student.first`처럼 중간 경로(`name`)를 생략하고 접근하려는 실수.
- `typedef`를 사용하여 자기 참조 구조체를 정의할 때, 구조체 내부에서 아직 완전히 정의되지 않은 별칭(alias)을 참조하려는 오류.

**[Q1] 함수에 구조체를 전달할 때, 값에 의한 호출(call-by-value)과 참조에 의한 호출(call-by-reference)의 차이점은 무엇이며, 원본 데이터 수정이 가능한 경우는 언제인가요? | 태그: #구조체 #포인터 #함수**

- **모범답(강의 기준)**: 값으로 전달하면 구조체의 복사본이 넘어가므로 함수 내 변경이 원본에 영향을 주지 않습니다. 반면, 주소값을 포인터로 전달하는 참조 호출 방식은 원본 메모리에 직접 접근하므로 수정이 가능합니다.
- **정석체크(면접 30초 대답분량)**: Call-by-value는 실제 값의 복사본을 전달하여 원본을 보호하고, call-by-reference는 메모리 주소를 전달하여 함수가 원본 데이터를 직접 읽고 쓸 수 있게 합니다. 원본 수정이 필요하면 반드시 포인터를 이용한 참조 방식으로 전달해야 합니다.

**[Q2] 다항식을 표현할 때, 배열의 인덱스를 차수로 사용하는 방식과 (계수, 지수) 쌍의 배열로 저장하는 방식의 장단점을 비교 설명하세요. | 태그: #자료구조 #다항식 #메모리효율**

- **모범답(강의 기준)**: 인덱스를 차수로 쓰면 덧셈 알고리즘이 간단하지만, x1000+1 같은 희소 다항식의 경우 메모리 낭비가 심합니다. (계수, 지수) 쌍으로 저장하면 0이 아닌 항만 다루므로 메모리가 효율적입니다.
- **정석체크(면접 30초 대답분량)**: 전자는 Dense Polynomial에 적합한 간단한 방식이지만, 후자는 Sparse Polynomial에서 메모리 사용량을 크게 줄일 수 있는 효율적인 방식입니다. 자료의 특성에 따라 적합한 표현법을 선택해야 합니다.

**[Q3] (계수, 지수) 쌍으로 표현된 두 희소 다항식 A, B를 더하는 알고리즘의 핵심 로직은 무엇인가요? | 태그: #알고리즘 #다항식덧셈**

- **모범답(강의 기준)**: 두 다항식의 항을 처음부터 순차적으로 비교하며, 지수가 큰 쪽의 항을 결과에 추가합니다. 지수가 같으면 계수를 더해 추가하고, 한쪽이 끝나면 남은 쪽의 항들을 모두 결과에 붙입니다.
- **정석체크(면접 30초 대답분량)**: 두 포인터를 사용해 각 다항식의 항을 가리키며 지수를 비교하는 Three-way comparison (A>B, A<B, A\==B)을 기반으로 동작합니다. 이는 정렬된 두 리스트를 병합하는 로직과 매우 유사하며, 시간 복잡도는 $O(m+n)$입니다.

## **2025-09-18, 2교시 — 개선본**

알고리즘을 공부하려면 자료구조에 대한 이해가 선행되어야 합니다. 특히 정렬, 우선순위 큐, 힙, 해시 테이블, 그래프 등의 개념을 알아야 알고리즘 코드 분석이 수월해집니다. 알고리즘 수업 후반부에서는 코드 자체를 상세히 분석하기보다 개념 중심으로 빠르게 넘어갑니다. 개념은 들어서 이해하기 쉽지만, 그것을 직접 코드로 구현하는 것은 전혀 다른 문제입니다. 따라서 C++, Java, Python 등 여러 언어로 직접 구현해보는 연습을 반드시 하셔야 합니다. 눈으로만 코드를 따라가는 '눈 코딩'이나 ChatGPT 같은 도구에 의존하는 방식은 피해야 합니다. 머릿속에서 로직이 정리되지 않으면 한 줄의 코드도 작성하기 어렵습니다.

오늘은 리스트(List)의 개념을 마스터하고, 배열 기반 리스트와 세 종류의 연결 리스트(단순, 원형, 이중)의 차이점을 중점적으로 다루겠습니다.

리스트는 순서가 있는 항목의 모임으로, 첫 번째 노드를 `헤드(head)`, 마지막 노드를 `테일(tail)`이라 부릅니다. 리스트의 기본 연산에는 새로운 노드를 추가(삽입)하거나 기존 노드를 제거(삭제)하는 것, 특정 위치의 항목을 탐색하는 것 등이 포함됩니다.

---

### 배열을 이용한 리스트 구현

배열로 리스트를 구현할 수 있습니다. 예를 들어 '오늘의 할 일' 목록을 배열에 저장하는 것을 생각해 봅시다.

- **삽입(Insertion)**: 항목을 맨 끝에 추가하는 것은 인덱스를 하나 늘려 값을 넣으면 되므로 가장 간단합니다. 하지만 맨 앞에 삽입하려면, 기존의 모든 항목을 뒤로 한 칸씩 이동시킨 후에야 0번 인덱스에 새 항목을 넣을 수 있습니다. 이때, 맨 뒤 항목부터 옮기지 않고 앞에서부터 옮기면 데이터가 덮어씌워져 유실되므로 **이동 순서가 매우 중요**합니다. 중간에 삽입할 경우에도 해당 위치 뒤의 모든 항목을 한 칸씩 뒤로 밀어야 합니다.
- **삭제(Deletion)**: 특정 위치의 항목을 삭제한 후에는, 그 뒤에 있는 모든 항목을 앞으로 한 칸씩 당겨와 빈 공간을 메워야 합니다.
- **기타 연산**: 이 외에도 리스트 전체 삭제, 특정 항목 대체, 항목 탐색, 전체 개수 반환, 리스트가 비었는지(`is_empty`) 또는 꽉 찼는지(`is_full`) 확인하는 연산이 필요합니다.

배열 기반 리스트의 장점은 구현이 비교적 간단하다는 것입니다. 하지만 단점은 명확합니다.

1. **삽입/삭제 시 오버헤드**: 데이터를 추가하거나 삭제할 때마다 불필요한 데이터 이동 작업이 발생하여 비효율적입니다.
2. **고정된 크기**: 배열은 선언 시 크기가 정해지는 정적 메모리 할당 방식이므로, 리스트의 크기가 고정됩니다. 이로 인해 공간이 부족하거나 반대로 낭비될 수 있습니다.

---

### 연결 리스트(Linked List)를 이용한 구현

연결 리스트는 이러한 배열의 단점을 극복하기 위해 고안되었습니다.

- **구조**: 연결 리스트의 각 요소는 **노드(Node)**라고 부르며, 각 노드는 **데이터(data)**와 다음 노드를 가리키는 **포인터(link)**로 구성된 자기 참조 구조체입니다.
- **동적 크기 조절**: 필요할 때마다 `malloc`을 통해 노드를 동적으로 생성하고 리스트에 연결하므로 크기 제한이 없습니다. 따라서 삽입 시 리스트가 꽉 찼는지 검사할 필요가 없습니다.
- **효율적인 삽입/삭제**: 데이터 이동 없이 포인터 몇 개만 변경하면 되므로 매우 빠릅니다. 예를 들어 A-B-C 연결에서 B를 삭제하려면, A의 `link`가 C를 가리키도록 바꾸기만 하면 됩니다. B는 더 이상 어떤 노드로부터도 참조되지 않으므로 사실상 리스트에서 사라진 것과 같습니다.

물론 연결 리스트에도 단점이 있습니다.

1. **복잡한 구현**: 구조체와 포인터를 사용해야 하므로 구현이 배열보다 복잡합니다.
2. **오류 발생 가능성**: 포인터 연산은 실수를 유발하기 쉽습니다. 특히, 노드를 삭제한 후에 해당 메모리를 `free()` 함수로 해제하지 않으면 **메모리 누수(memory leak)**가 발생하는데, 이는 동적 할당의 장점을 심각하게 훼손하는 치명적인 오류입니다.

---

### 연결 리스트의 종류

연결 리스트는 구조에 따라 세 가지로 나눌 수 있습니다.

1. **단순 연결 리스트(Singly Linked List)**: 각 노드가 다음 노드만 가리키는 단방향 구조입니다. 가장 큰 단점은 특정 노드에서 이전 노드로 돌아갈 수 없다는 것입니다. 검색 시 항상 `헤드 포인터`부터 다시 시작해야 합니다.
2. **원형 연결 리스트(Circular Linked List)**: 마지막 노드가 첫 번째 노드를 가리키는 순환 구조입니다. 이를 통해 리스트의 어느 노드에서든 순회를 시작할 수 있습니다. 보통 `헤드 포인터`가 첫 노드가 아닌 **마지막 노드**를 가리키게 구현하는데, 이렇게 하면 마지막 노드(`head`)와 첫 노드(`head->link`) 모두에 O(1) 시간 복잡도로 접근할 수 있어 연산이 편리해집니다.
3. **이중 연결 리스트(Doubly Linked List)**: 각 노드가 이전 노드(`l-link`)와 다음 노드(`r-link`)를 모두 가리키는 양방향 구조입니다. 양방향 탐색이 가능하여 매우 유연하지만, 포인터를 위한 추가 공간이 필요합니다. 보통 원형 구조와 결합하고, 데이터가 없는 **헤드 노드(head node, dummy node)**를 두어 삽입/삭제 시 발생할 수 있는 예외 상황(예: 비어있는 리스트에 삽입)을 간단하게 처리합니다.

이러한 개념들을 오늘 모두 정리해 드릴 테니, 핵심을 파악하고 직접 공부해 보시길 바랍니다.

## **2025-09-18, 2교시 — 개념**

### 1. 한 줄 요약

배열 기반 리스트와 연결 리스트의 구현 방식을 비교하며 삽입/삭제 오버헤드와 메모리 관리의 차이점을 분석하고, 단순/원형/이중 연결 리스트의 구조와 특징을 학습합니다.

### 2. 핵심 TL;DR

- **리스트 ADT(Abstract Data Type)**는 순서가 있는 데이터의 모음과 그에 대한 연산(삽입, 삭제, 탐색 등)을 정의한 명세입니다.
- **배열 리스트**는 구현이 간단하지만, 크기가 고정되며 삽입/삭제 시 데이터를 한 칸씩 옮겨야 하는 **오버헤드**가 발생합니다.
- 배열 리스트에서 삽입 시에는 데이터 유실을 막기 위해 **맨 뒤 요소부터** 옮겨야 하고, 삭제 시에는 **삭제 위치 다음 요소부터** 앞으로 당겨와야 합니다.
- **연결 리스트**는 동적 메모리 할당으로 크기가 유연하며, 포인터 참조만 변경하므로 삽입/삭제가 $O(1)$로 매우 빠릅니다.
- 연결 리스트에서 노드를 삭제한 후 **`free()`를 호출하지 않으면** 해당 메모리를 재사용할 수 없는 **메모리 누수(Memory Leak)**가 발생합니다.
- **단순 연결 리스트**는 다음 노드만 가리키므로 단방향 탐색만 가능하며, 이전 노드로 돌아갈 수 없습니다.
- **원형 연결 리스트**는 마지막 노드가 첫 노드를 가리켜 순환 구조를 이루며, 리스트의 어느 지점에서든 순회를 시작할 수 있습니다.
- **이중 연결 리스트**는 이전/다음 노드를 모두 가리켜 양방향 탐색이 가능해 매우 유연합니다.
- **헤드 포인터**는 리스트의 첫 번째 노드 '주소'를 담는 변수인 반면, **헤드 노드(더미 노드)**는 리스트 맨 앞에 두는 데이터 없는 '실제 노드'로, 코드의 예외 처리를 간소화합니다.

### 3. 표현 = 표준 용어

- **`List ADT (Abstract Data Type)`**: A specification of a collection of ordered data and the operations that can be performed on it.
- **`Array-based List`**: An implementation of a list using a static array.
- **`Linked List`**: An implementation of a list using nodes connected by pointers.
- **`Overhead`**: Extra computational work, such as shifting elements in an array during insertion or deletion.
- **`Memory Leak`**: A memory management failure where dynamically allocated memory is not freed after use, rendering it inaccessible.
- **`Singly / Circular / Doubly Linked List`**: Variations of linked lists based on pointer structure (unidirectional, circular, bidirectional).
- **`Head Pointer`**: A pointer that stores the memory address of the first node in a list.
- **`Head Node (Dummy Node)`**: A non-data sentinel node at the beginning of a list to simplify insertion/deletion logic.

### 4. 정석 보강 (canon-std)

배열 리스트와 연결 리스트는 순차 데이터를 저장하는 대표적인 선형 자료구조입니다. 둘 사이의 선택은 **접근(Access)**과 **삽입/삭제(Insertion/Deletion)** 연산의 빈도에 따라 결정됩니다. 배열은 인덱스를 통한 임의 접근이 $O(1)$로 매우 빠르지만 삽입/삭제는 $O(n)$이 걸립니다. 반면 연결 리스트는 특정 노드 탐색에 $O(n)$이 걸리지만, 일단 위치를 알면 삽입/삭제는 $O(1)$에 가능합니다. 따라서 데이터 조회가 잦고 크기 변동이 적으면 **배열 리스트**, 데이터 삽입/삭제가 빈번하고 크기 예측이 어려우면 **연결 리스트**가 적합합니다.

### 5. 실수·함정

- 배열 리스트에 원소 삽입 시, 앞에서부터 데이터를 이동시켜 기존 데이터를 덮어쓰는 실수.
- 연결 리스트에서 노드를 삭제한 후 `free()`를 호출하는 것을 잊어 메모리 누수를 유발하는 것.
- 비어있는 리스트(`head == NULL`)에 원소를 삽입하거나 삭제하려는 경우에 대한 예외 처리를 누락하는 문제.
- 이중 연결 리스트에서 노드를 조작할 때, 이전(`prev`) 포인터와 다음(`next`) 포인터 중 하나만 갱신하여 리스트의 연결을 깨뜨리는 오류.
- 원형 연결 리스트를 순회할 때, 종료 조건을 잘못 설정하여 무한 루프에 빠지는 실수.
- 헤드 포인터(주소를 담는 변수)와 헤드 노드(데이터 없는 실제 노드)의 개념을 혼동하여 잘못 사용하는 경우.
- 포인터가 가리키는 노드의 멤버(`p->link`)를 바꿔야 하는데, 포인터 변수 자체(`p`)에 다른 값을 할당하여 연결을 끊어버리는 실수.

## **2025-09-18, 3교시 — 개선본**

단순 연결 리스트(Singly Linked List)에서 마지막 노드의 `link` 값은 항상 `NULL`이며, 리스트의 시작은 `헤드 포인터(head pointer)`가 가리킵니다. 여기서 가장 중요한 연산인 삽입과 삭제를 살펴보겠습니다.

### 연결 리스트 삽입 (Insertion)

`before` 노드와 `after` 노드 사이에 새로운 `new_node`를 삽입한다고 가정해 봅시다. 각 노드는 `malloc`으로 동적으로 생성되므로, 우리는 이 노드들을 가리키는 포인터 변수(`before`, `after`, `new_node`)를 통해 작업합니다.

이때 **연결 순서가 매우 중요**합니다.

1. **잘못된 순서**: 만약 `before->link = new_node;`를 먼저 실행하면, `before`가 기존에 가리키고 있던 `after` 노드의 주소 정보가 사라집니다. 이렇게 되면 `after` 노드와 그 뒤에 연결된 모든 노드에 접근할 방법을 잃게 됩니다.
2. **올바른 순서**: 따라서 반드시 `new_node->link = before->link;`를 먼저 실행하여 `new_node`가 `after`를 가리키게 해야 합니다. 그 후에 `before->link = new_node;`를 실행하여 `before`가 `new_node`를 가리키도록 연결을 변경합니다.

이를 코드로 표현하면 다음과 같습니다.

1. `new_node->link = before->link;` // 삽입할 노드가 기존 다음 노드를 가리키게 함
2. `before->link = new_node;` // 이전 노드가 삽입할 노드를 가리키게 함

### 연결 리스트 삭제 (Deletion)

`before` 노드 다음에 있는 `removed` 노드를 삭제하는 과정은 더 간단합니다. `removed` 노드가 가리키고 있던 다음 노드의 주소(`removed->link`)를 `before` 노드의 `link`에 저장하면 됩니다.

1. `before->link = removed->link;` // 이전 노드가 삭제할 노드의 다음 노드를 가리키게 함
2. `free(removed);` // 삭제된 노드의 메모리를 반드시 해제함

---

### C언어 구현 및 삽입의 세 가지 경우

실제 구현 시에는 `malloc`을 사용하여 노드를 위한 메모리 공간을 할당받습니다. `malloc`은 성공 시 할당된 메모리의 시작 주소를, 실패 시 `NULL`을 반환합니다. 할당받은 메모리는 포인터 변수로 다루게 되며, 멤버 접근 시에는 `p1->data = 10;`, `p1->link = NULL;` 과 같이 화살표 연산자(`->`)를 사용합니다.

리스트의 맨 앞에 노드를 삽입하면 기존의 헤드를 가리키던 포인터가 더 이상 첫 번째 노드를 가리키지 않게 됩니다. 이러한 혼동을 막기 위해, 리스트의 시작점을 항상 일정하게 가리키는 전용 `헤드 포인터`를 사용합니다.

삽입 연산은 다음 세 가지 경우로 나누어 처리해야 합니다.

1. **`head == NULL`인 경우**: 리스트가 완전히 비어있을 때입니다. 새로 추가하는 노드가 리스트의 첫 번째이자 마지막 노드가 됩니다.
2. **`p == NULL`인 경우**: 리스트는 존재하지만, 맨 앞에 삽입하는 경우입니다. 여기서 `p`는 삽입할 위치의 '이전' 노드를 가리키는 포인터인데, 맨 앞에는 이전 노드가 없으므로 `p`가 `NULL`이 됩니다.
3. **`p != NULL`인 경우**: 리스트의 중간이나 끝에 삽입하는 경우입니다. `p`가 가리키는 노드 뒤에 새로운 노드를 삽입합니다.

### 기타 주요 연산

- **삭제(Deletion)**: 삭제할 노드가 첫 번째 노드인 경우(`p == NULL`)와 중간 노드인 경우(`p != NULL`) 두 가지로 나뉩니다. 첫 노드를 삭제할 때는 `헤드 포인터`를 다음 노드로 업데이트해야 합니다.
- **탐색(Search)**: `헤드 포인터`에서 시작하여 `p = p->link;` 연산을 반복하며 리스트를 순회하다가 원하는 데이터를 찾으면 해당 노드의 포인터를 반환합니다.
- **합병(Concatenate)**: 두 리스트를 연결하는 연산입니다. 첫 번째 리스트의 마지막 노드까지 순회한 뒤, 그 노드의 `link`가 두 번째 리스트의 `헤드 포인터`를 가리키게 하면 됩니다. 배열보다 훨씬 간편하게 처리할 수 있습니다.
- **역순(Reverse)**: 리스트의 노드 순서를 뒤집는 연산입니다. 3개의 포인터(`p`, `q`, `r`)를 사용하여 순회하면서 `link`의 방향을 반대로 바꾸는 방식으로 구현할 수 있습니다. 이 알고리즘의 메커니즘을 다음 시간까지 분석해 오세요. (실습)

### 응용: 다항식의 표현

연결 리스트는 다양하게 응용될 수 있습니다. 예를 들어, 노드의 데이터 부분을 `int` 하나 대신 `계수(coefficient)`와 `지수(exponent)`를 멤버로 갖는 구조체로 정의하면, 연결 리스트를 이용해 다항식을 효율적으로 표현하고 연산할 수 있습니다.

## **2025-09-18, 3교시 — 개념**

### 1. 한 줄 요약

단일 연결 리스트의 핵심 연산인 삽입/삭제의 포인터 변경 순서와 C언어 구현을 학습하고, 빈 리스트, 맨 앞, 중간 삽입 등 경우의 수를 나누어 처리하는 로직을 분석합니다.

---

### 2. 핵심 TL;DR

- **삽입 순서의 중요성**: 노드 삽입 시, **1) 새 노드가 기존 다음 노드를 먼저 가리키게 한 후, 2) 이전 노드가 새 노드를 가리키도록** 연결해야 리스트의 뒷부분을 잃어버리지 않습니다.
- **삭제와 메모리 해제**: 노드 삭제는 포인터 연결을 변경하여 리스트에서 노드를 논리적으로 분리(`bypass`)하고, `free()` 함수로 해당 메모리를 시스템에 물리적으로 반환하는 두 단계로 구성됩니다.
- **선행 노드의 역할**: 단일 연결 리스트에서 특정 노드의 위치 정보는 오직 그 노드의 **'바로 앞 노드(선행 노드)'**만이 알고 있습니다. 모든 연산은 이 선행 노드를 기준으로 이루어집니다.
- **헤드 포인터(Head Pointer)**: 리스트의 시작 위치를 고정하는 역할을 합니다. 맨 앞 노드가 변경되는 연산에서 리스트 전체의 참조를 잃지 않도록 하는 안정적인 진입점입니다.
- **삽입 Case 1 (빈 리스트)**: `head`가 `NULL`일 때, 새 노드가 유일한 노드가 되도록 `head` 포인터가 새 노드를 가리키게 합니다.
- **삽입 Case 2 (맨 앞)**: 리스트는 존재하지만 맨 앞에 삽입할 때, 새 노드가 기존의 첫 번째 노드를 가리키게 하고, `head` 포인터가 새 노드를 가리키도록 갱신합니다.
- **삽입 Case 3 (중간/끝)**: `p` 노드 뒤에 삽입하며, `p`와 `p`가 가리키던 노드(`p->link`) 사이에 새 노드를 연결합니다.
- **응용 (다항식)**: 노드의 데이터 필드를 `{계수, 지수}`를 담는 구조체로 정의하면, 연결 리스트로 희소 다항식을 효과적으로 구현하고 연산할 수 있습니다.

---

### 3. 표현 = 표준 용어

- **`Pointer Assignment`**: 메모리 주소를 포인터 변수에 저장하는 행위. (예: `p->link = new_node;`)
- **`Dynamic Allocation`**: 프로그램 실행 중 `malloc()` 같은 함수를 사용해 메모리를 할당하는 것.
- **`Deallocation`**: `free()` 함수를 사용해 동적으로 할당된 메모리를 시스템에 반환하는 것.
- **`Traversal`**: 리스트의 모든 노드를 한 번씩 방문하는 과정. 보통 헤드에서 시작하여 `p = p->link`로 이동합니다.
- **`Concatenation`**: 두 개의 연결 리스트를 하나로 합치는 연산.
- **`Reversal`**: 연결 리스트의 노드 순서를 역으로 뒤집는 연산.

---

### 4. 정석 보강 (canon-std)

연결 리스트의 **중간 삽입(Insertion)**은 가장 일반적인 연산입니다. 삽입할 위치의 이전 노드를 가리키는 포인터 `p`와 새로 생성된 `new_node`가 주어졌을 때, 연산은 리스트의 길이에 상관없이 **$O(1)$의 시간 복잡도**를 가집니다. 핵심 로직은 두 단계의 포인터 할당으로 구성됩니다. 이 절차는 모든 노드 기반 자료구조에서 기본이 되는 중요한 개념입니다.

- **핵심 의사코드**:
    
    1. `new_node->link = p->link;`
    2. `p->link = new_node;`

---

### 5. 실수·함정

- 노드 삽입 시 포인터 할당 순서를 바꿔(`p->link = new_node;`를 먼저 수행), 기존 리스트의 뒷부분에 대한 참조를 잃어버리는 치명적인 실수.
- 리스트의 맨 앞 노드를 삽입하거나 삭제한 후, `head` 포인터의 값을 갱신하는 것을 잊는 오류.
- `malloc()` 함수가 메모리 할당에 실패하여 `NULL`을 반환했을 경우에 대한 예외 처리를 누락하는 문제.
- C언어 함수 선언 `Node* func()`를 '함수 포인터'로 오해하는 경우. 이는 'Node 포인터를 반환하는 함수'를 의미합니다.
- 리스트를 순회하는 반복문에서 `p = p->link;` 코드의 위치가 잘못되어 노드를 건너뛰거나 무한 루프에 빠지는 실수.
- 리스트의 마지막 노드를 삭제한 후, 그 이전 노드의 `link` 포인터를 `NULL`로 설정하지 않아 리스트의 끝이 불분명해지는 오류.

끝.

**[Q1] 연결 리스트에 새 노드를 삽입할 때, 포인터 할당 순서가 중요한 이유는 무엇이며, 올바른 순서는 무엇인가요? | 태그: #연결리스트 #포인터 #구현**

- **정석체크(면접 30초 대답분량)**: `before->link = new_node`를 먼저 수행하면 `before`가 가리키던 나머지 리스트의 주소값을 잃게 되어 리스트가 끊어집니다. 따라서 `new_node->link = before->link`를 통해 새 노드가 먼저 뒷부분을 가리키도록 연결을 확보한 후, `before->link = new_node`를 수행해야 합니다.

**[Q2] 연결 리스트의 삽입 함수를 구현할 때, '빈 리스트', '맨 앞 삽입', '중간 삽입'의 세 가지 경우를 나누어 처리해야 하는 이유는 무엇인가요? | 태그: #연결리스트 #알고리즘 #엣지케이스**

**[Q3] 단일 연결 리스트에서 특정 노드를 삭제하기 위해 반드시 알아야 하는 정보는 무엇이며, 이 정보는 어느 노드가 가지고 있나요? | 태그: #단일연결리스트 #삭제 #선행노드**

- **정석체크(면접 30초 대답분량)**: 단일 연결 리스트는 단방향 구조이므로, 특정 노드 `target` 자체의 주소만으로는 `target`을 가리키던 `previous` 노드를 찾을 수 없습니다. `previous->link = target->link` 연산을 수행하려면 반드시 `previous` 노드의 포인터가 필요합니다.

**[Q4] C언어 함수 선언 `ListNode* search(...)`가 '함수 포인터' 선언과 어떻게 다른지 설명하세요. | 태그: #C언어 #함수포인터 #문법**

- **모범답(강의 기준)**: `ListNode* search(...)`는 `search`라는 이름의 함수가 실행된 후 `ListNode` 타입의 포인터를 '반환'한다는 의미입니다. 반면 함수 포인터는 함수 자체가 저장된 메모리 주소를 가리키는 변수로, 보통 `반환형 (*포인터이름)(매개변수)` 형태로 선언됩니다.
- **정석체크(면접 30초 대답분량)**: 해당 선언은 함수의 '반환 타입(return type)'이 포인터임을 명시하는 것입니다. 함수 포인터는 함수의 주소를 저장하는 변수이며, `int (*fp)()` 와 같이 포인터 변수명에 괄호가 붙는 형태로 구분됩니다.
