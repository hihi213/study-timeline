## **2025-09-18, 1교시 — 개선본**

알고리즘과 구조체는 직접적인 연관성은 적지만, 앞으로의 코딩 실습을 위해 리스트에 들어가기 전 몇 가지 개념을 잡고 가겠습니다. 구조체(struct)는 하나의 변수가 여러 자료형의 속성을 동시에 포함하는 사용자 정의 자료형입니다. 예를 들어 '학생'이라는 변수는 학번, 이름, 학과, 학년 등 다양한 타입의 정보를 가지는데, 이를 하나의 단위로 묶을 때 구조체를 사용합니다. 이는 배열처럼 동일한 자료형의 묶음과는 다릅니다.

구조체를 정의하고 변수를 선언하며 초기 값을 직접 할당할 수 있습니다. 예를 들어 `c1`이라는 구조체 변수가 있다면, 그 멤버에는 `c1.member`와 같이 점(.) 연산자로 접근합니다.

함수에 구조체를 전달하는 방식에는 크게 두 가지가 있습니다. 첫째는 값에 의한 호출(Call by Value)로, 구조체 전체를 복사하여 전달합니다. 이 경우 함수 내에서 멤버 값을 변경해도 원본 변수에는 영향이 없습니다.

둘째는 참조에 의한 호출(Call by Reference)로, 구조체의 주소 값을 포인터로 전달합니다. 이 경우 함수 내에서 포인터를 통해 멤버를 변경하면(`c->member` 형태), 원본 변수의 값이 바뀌게 됩니다. 연결 리스트(Linked List)에서는 동적 할당(malloc)을 사용하므로 대부분 참조에 의한 호출 방식을 사용하게 될 것입니다.

구조체 활용의 예로 다항식 표현을 보겠습니다. 첫 번째 방법은 배열을 사용하는 것입니다. 다항식 `10x^5 + 6x + 3`이 있다면, 최고 차수(`5`)에 맞춰 6개의 공간을 가진 배열을 선언하고, 각 인덱스를 차수에 대응시켜 계수를 저장할 수 있습니다. `coef[5] = 10`, `coef[1] = 6`, `coef[0] = 3`과 같이 저장하는 방식입니다. 이 방법은 다항식 덧셈 시 같은 인덱스(차수)의 계수를 더하면 되므로 알고리즘이 매우 간단해집니다.

하지만 `x^1000 + 1`과 같이 항의 개수는 적지만 최고 차수가 매우 큰 경우, 대부분의 배열 공간이 0으로 채워져 메모리 낭비가 심각해지는 단점이 있습니다.

두 번째 방법은 0이 아닌 항의 계수(coefficient)와 지수(exponent)만 쌍으로 저장하는 것입니다. 이 경우 메모리 효율은 높아지지만, 덧셈 알고리즘은 더 복잡해집니다. 두 다항식 A와 B를 더하려면, 각 다항식의 현재 항의 지수를 비교해야 합니다.

1. A의 지수 > B의 지수: A의 항을 결과에 추가하고 A의 다음 항으로 이동합니다.
2. A의 지수 < B의 지수: B의 항을 결과에 추가하고 B의 다음 항으로 이동합니다.
3. A의 지수 == B의 지수: 두 계수를 더해 결과에 추가하고, A와 B 모두 다음 항으로 이동합니다.

    한쪽 다항식의 모든 항을 처리했다면, 다른 쪽에 남아있는 모든 항을 결과에 그대로 추가합니다. 이 다항식 덧셈 프로그램을 구조체를 이용해 직접 C언어로 구현해 보시길 바랍니다. (실습)

구조체 안에는 다른 구조체가 멤버로 포함될 수 있습니다. 예를 들어, 이름(`first`, `middle`, `last`)을 담는 `struct person_name`을 정의하고, 이 구조체 변수를 학생 정보를 담는 `struct student`의 멤버로 사용할 수 있습니다. 이 경우 학생 변수 `s1`의 이름에 접근하려면 `s1.name.first`와 같이 연쇄적으로 접근해야 합니다.

또한 구조체 멤버가 배열일 경우, 문자열 복사 함수인 `strcpy`를 사용해 값을 할당할 수 있습니다. `name.first`가 문자 배열이라면, `strcpy(s1.name.first, "Gildong")`과 같이 사용하는 것이 가능합니다. 이는 배열의 이름이 상수 포인터(constant pointer)로 취급되기 때문입니다.

또한, 동일한 타입의 구조체 변수끼리는 대입 연산(=)이 가능하며, 이 경우 모든 멤버의 값이 복사됩니다.

마지막으로 연결 리스트 구현의 핵심인 자기 참조 구조체(Self-referential structure)가 있습니다. 이는 구조체의 멤버로 자기 자신과 동일한 타입의 구조체를 가리키는 포인터를 갖는 형태입니다.

struct list_node { char data[10]; struct list_node* link; };

위와 같이 list_node 구조체는 데이터 필드와 다음 노드를 가리킬 link 포인터 필드를 가집니다. 이를 통해 malloc으로 노드를 필요할 때마다 동적으로 생성하고, link 포인터로 이전 노드와 연결하여 데이터의 개수를 유동적으로 조절할 수 있습니다. 이것이 배열 기반 리스트와 차별화되는 연결 리스트의 핵심 원리입니다.

## 2025-09-18, 1교시 — 개념

### 1. 한 줄 요약

C언어 구조체(struct)를 사용자 정의 자료형으로 이해하고, 값/참조 호출 함수 전달 방식, 중첩 구조, 다항식 표현과 같은 활용법을 다루고, 연결 리스트의 기반이 되는 자기 참조 구조체를 소개합니다.

### 2. **핵심 TL;DR**

- **구조체(struct)**: 서로 다른 타입의 변수들을 하나의 논리적 단위로 묶는 사용자 정의 자료형입니다.
- **멤버 접근**: 구조체 변수는 점 연산자(`.`)로, 구조체 포인터는 화살표 연산자(`->`)로 멤버에 접근합니다.
- **값 vs. 참조 호출**: 함수에 구조체를 값(Call by Value)으로 넘기면 복사본이 전달되어 원본이 불변하지만, 주소(Call by Reference)로 넘기면 원본 수정이 가능합니다.
---
- **`typedef`**: `struct <구조체_이름>`과 같은 긴 자료형 선언을 사용자가 지정한 짧은 별칭으로 대체하여 코드 가독성을 높입니다.
- **다항식 표현(배열)**: 배열의 인덱스를 다항식의 지수로 직접 매핑하는 방식으로, 알고리즘은 간단하나 항이 적고 차수만 높은 경우 메모리 낭비가 심합니다.
- **다항식 표현(구조체)**: 0이 아닌 항의 `계수`와 `지수`만을 구조체로 묶어 저장하여 메모리 효율성을 높입니다.
---
- **중첩 구조체**: 구조체 내부에 또 다른 구조체를 멤버 변수로 포함하는 구조로, `student.name.first`처럼 멤버 접근을 연쇄적으로 수행합니다.
- **자기 참조 구조체**: 구조체 자기 자신과 동일한 타입의 포인터를 멤버로 포함하는 구조로, 다음 데이터 노드를 가리키는 '연결 고리' 역할을 합니다.
- **동적 자료구조의 기반**: 자기 참조 구조체와 `malloc`을 결합하면 필요에 따라 데이터 노드를 생성하고 연결하여, 크기가 고정되지 않은 연결 리스트(Linked List) 등을 구현할 수 있습니다.

### 3. **표현 = 표준 용어**

- `struct`: 여러 타입의 데이터를 묶는 키워드 (구조체).
- `Member`: 구조체를 구성하는 각각의 변수.
- `Call by Value`: 값을 복사하여 함수에 전달하는 방식.
- `Call by Reference`: 메모리 주소(포인터)를 함수에 전달하는 방식.
- `typedef`: 기존 자료형에 새로운 이름(별칭)을 부여하는 키워드.
- `Nested Structure`: 다른 구조체를 멤버로 갖는 구조체 (중첩 구조체).
- `Self-referential Structure`: 자신과 같은 타입의 포인터를 멤버로 갖는 구조체 (자기 참조 구조체).

### 4. 정석 보강(canon-std)

자기 참조 구조체는 멤버 중 하나가 자기 자신과 동일한 구조체 타입을 가리키는 포인터 변수인 구조를 말합니다. 이는 논리적으로 연속된 데이터를 물리적으로는 흩어진 메모리 공간에 저장하고, 포인터를 통해 연결하여 리스트, 트리 등 동적 자료구조를 구현하는 핵심 요소입니다.

- **핵심 의사코드:** `struct node { int data; struct node* next_node; };`
- **전제:** 일반적으로 동적 메모리 할당(`malloc`)과 해제(`free`)를 통해 노드를 생성하고 삭제하는 방식과 함께 사용됩니다.

### 5. **실수·함정**

- 구조체 포인터의 멤버에 접근할 때 `.`을 사용하여 발생하는 컴파일 오류 (`p.member` → `p->member`).
- 값(Call by Value)으로 전달된 구조체는 사본이므로, 함수 내에서 멤버를 수정해도 원본에 반영되지 않음을 간과하는 것.
- `typedef`으로 별칭을 만들지 않았을 때, 변수 선언 시 `struct` 키워드를 생략하는 실수.
- 문자 배열 멤버에 문자열을 대입할 때 \`=\` 연산자를 사용하려는 오류 (정답: `strcpy()` 함수 사용).
- 중첩 구조체 멤버에 접근할 때 `student.name`처럼 최종 멤버까지 명시하지 않는 실수.
- 자기 참조 구조체의 포인터 멤버(`link`)가 다음 노드 '자체'가 아닌 '주소'를 저장한다는 개념 혼동.

끝.

## 2025-09-18, 1교시 — 질문

**[Q1] 함수에 구조체를 전달할 때, 값으로 전달(Call by Value)하는 것과 주소(포인터)로 전달(Call by Reference)하는 것은 어떤 차이를 만들며, 그 결과는 어떻게 달라지는가? | #포인터 #함수_인자**

- **모범답(강의 기준)**: 값으로 전달하면 구조체의 복사본이 생성되어 함수 내 변경이 원본에 영향을 주지 않습니다. 주소로 전달하면 원본의 메모리에 직접 접근하므로 함수 내에서 멤버를 변경하면 원본 구조체도 변경됩니다.
- **정석체크(면접 30초 대답분량)**: Call by Value는 데이터의 불변성을 보장하지만 구조체 크기가 클 경우 복사 오버헤드가 발생합니다. Call by Reference는 오버헤드가 적고 원본 수정이 가능하지만, 의도치 않은 데이터 변경의 위험이 있습니다.

**[Q2] 다항식을 표현할 때, 모든 차수를 배열 인덱스에 대응시키는 방식과 0이 아닌 항의 계수/지수만 구조체로 저장하는 방식의 장단점은 무엇인가? | #자료구조 #효율성**

- **모범답(강의 기준)**: 배열 방식은 인덱스로 차수를 바로 알 수 있어 덧셈 같은 연산 알고리즘이 간단합니다. 반면, 구조체 방식은 `x^1000 + 1`과 같이 최고 차수는 크지만 항이 적을 때 메모리 공간을 효율적으로 사용할 수 있습니다.
- **정석체크(면접 30초 대답분량)**: 전제는 다항식의 밀도(density)입니다. 항이 촘촘한 다항식(dense polynomial)은 배열이, 항이 드문 희소 다항식(sparse polynomial)은 구조체나 연결 리스트 방식이 메모리 효율성 측면에서 유리합니다.

**[Q3] 구조체 멤버가 `char name[10]`과 같은 문자 배열일 때, = 연산자가 아닌 `strcpy()` 함수로 문자열을 복사해야 하는 이유는 무엇인가? | #배열 #포인터**

- **모범답(강의 기준)**: C언어에서 배열의 이름은 그 배열의 시작 메모리 주소를 가리키는 '상수 포인터'로 취급되기 때문입니다. `strcpy`는 도착지 주소 값을 인자로 받으므로, 배열의 이름을 전달하여 문자열을 복사할 수 있습니다.
- **정석체크(면접 30초 대답분량)**: C언어의 배열-포인터 관계가 전제입니다. 배열 이름은 주소 상수이므로 대입 연산자(=)의 좌변에 올 수 없습니다. 따라서 주소를 인자로 받아 내용을 복사하는 `strcpy()`와 같은 함수를 사용해야 합니다.

**[Q4] 구조체 변수 A의 모든 멤버 값을 다른 구조체 변수 B에 한 번에 복사(`B = A;`)하려면 어떤 조건이 충족되어야 하는가? | #구조체 #타입_호환성**

- **모범답(강의 기준)**: 두 구조체 변수의 자료형이 완벽히 동일해야 합니다. 예를 들어 `struct student s1, s2;`로 선언되었다면 `s2 = s1;`과 같이 멤버별로 값을 복사하는 대입 연산이 가능합니다.
- **정석체크(면접 30초 대답분량)**: 대입 연산의 전제는 '동일한 타입'입니다. 이 연산은 멤버별 복사(member-wise copy)로 동작하는데, 포인터 멤버가 있다면 주소 값만 복사하는 얕은 복사(shallow copy)가 일어나므로 주의해야 합니다.

**[Q5] '자기 참조 구조체'란 무엇이며, 연결 리스트 같은 동적 자료구조를 구현하는 데 왜 필수적인가? | #연결_리스트 #핵심_개념**

- **모범답(강의 기준)**: 자기 참조 구조체는 자기 자신과 똑같은 타입의 포인터를 멤버로 갖는 구조체입니다. 이 포인터가 다음 데이터 노드의 주소를 저장하는 '연결 고리' 역할을 하여, 데이터들을 순차적으로 엮을 수 있게 해줍니다.
- **정석체크(면접 30초 대답분량)**: 정의는 '자신과 같은 타입의 포인터를 멤버로 포함하는 구조체'입니다. 이를 통해 물리적으로 떨어진 메모리 공간에 할당된 데이터 노드들을 논리적으로 연결하여, 크기를 동적으로 변경할 수 있는 자료구조를 만들 수 있습니다.

## **2025-09-18, 2교시 — 개선본**

알고리즘을 제대로 공부하려면 자료구조에 대한 이해가 필수적입니다. 특히 정렬, 우선순위 큐, 힙, 해시 테이블, 그래프 등의 개념은 반드시 숙지해야 합니다. 알고리즘 수업 후반부에서는 코드 분석보다는 핵심 개념 위주로 빠르게 진행되는데, 개념은 들어서 이해할 수 있지만 이를 직접 코드로 구현하는 것은 전혀 다른 차원의 문제입니다.

따라서 눈으로만 코드를 따라가는 '눈 코딩'이나 ChatGPT와 같은 도구에 의존하는 방식은 지양해야 합니다. 직접 코드를 작성하며 머릿속의 논리를 정리하는 연습이 반드시 필요합니다. 이러한 자료구조와 알고리즘 개념들은 C, C++, Java, Python 등 다양한 언어로 직접 구현해봐야 합니다. (실습)

오늘은 리스트(List)에 대해 집중적으로 다루겠습니다. 리스트는 순서가 있는 항목들의 모임으로, 첫 번째 노드를 헤드(head), 마지막 노드를 테일(tail)이라고 부릅니다. 리스트의 기본 연산에는 맨 앞, 중간, 맨 뒤에 새 항목을 추가(insertion)하는 연산, 특정 위치의 항목을 삭제(deletion)하는 연산, 그리고 특정 항목을 탐색(search)하는 연산 등이 포함됩니다.

리스트를 구현하는 방식은 크게 배열과 연결 리스트로 나뉩니다.

### 1. 배열 기반 리스트 (Array-based List)

배열을 사용한 구현은 간단하지만, 삽입과 삭제 시 비효율적인 오버헤드가 발생합니다.

- **삽입(Insertion)**: 특정 위치에 원소를 삽입하려면, 해당 위치부터 맨 마지막 원소까지 모든 데이터를 한 칸씩 뒤로 이동시켜야 공간을 확보할 수 있습니다. 이때 반드시 맨 뒤 원소부터 옮겨야 데이터 유실을 막을 수 있습니다.
- **삭제(Deletion)**: 특정 위치의 원소를 삭제한 후에는, 그 뒤에 있는 모든 원소를 한 칸씩 앞으로 당겨 빈 공간을 메워야 합니다. 이때는 삭제된 위치 바로 다음 원소부터 순서대로 앞으로 이동시킵니다.
- **단점**: 삽입/삭제 시 발생하는 원소 이동 오버헤드가 크며, 배열 선언 시 크기가 고정되므로 동적으로 크기를 조절하기 어렵습니다. 리스트가 꽉 찼는지(`is_full`) 또는 비었는지(`is_empty`)를 항상 검사해야 합니다.

예를 들어, 삽입 함수 `add(position, item)`는 먼저 리스트가 꽉 찼는지, 삽입 위치가 유효한 범위(`0 <= position <= length`) 내에 있는지 검사합니다. 유효하다면, `length-1` 인덱스부터 `position` 인덱스까지의 모든 원소를 루프를 통해 한 칸씩 뒤로 이동시킵니다. 이후 지정된 `position`에 새 항목(`item`)을 삽입하고 `length`를 1 증가시킵니다.

### 2. 연결 리스트 (Linked List)를 이용한 구현

연결 리스트는 구조체와 포인터를 사용하여 구현이 복잡하지만, 삽입과 삭제가 매우 효율적입니다.

- **구조**: 연결 리스트의 각 요소는 **노드(Node)** 라고 부르며 연결 리스트의 각 요소는 **노드(Node)** 라고 부르며, 각 노드는 **데이터(data)** 와 다음 노드를 가리키는 **포인터(link)** 로 구성됩니다. 이 노드들은 `malloc`을 통해 필요할 때마다 동적으로 생성됩니다. 따라서 삽입 시 리스트가 꽉 찼는지 검사할 필요가 없습니다.
- **삽입/삭제**: 데이터를 물리적으로 이동시킬 필요 없이, 이전 노드의 포인터가 새 노드를 가리키게 하거나 다음 노드를 가리키도록 연결만 변경하면 됩니다. 따라서 오버헤드가 거의 없습니다.
- **장점**: 동적으로 크기를 조절할 수 있어 메모리 사용이 유연하고, 삽입/삭제가 빠릅니다.
- **단점**: 구현이 복잡하고, 포인터 연산 시 오류가 발생하기 쉽습니다. 특히 동적으로 할당(`malloc`)된 노드를 삭제한 후 메모리를 해제(`free`)하지 않으면 메모리 누수(memory leak)가 발생할 수 있습니다.

구조체 포인터와 구조체 변수를 혼동해서는 안 됩니다. 구조체 변수는 내부에 여러 멤버를 갖지만, 구조체 포인터는 단지 특정 구조체 변수의 '주소'만을 담는 변수일 뿐입니다.

### 연결 리스트의 종류

1. **단순 연결 리스트 (Singly Linked List)**: 각 노드가 다음 노드만 가리키는 단방향 구조입니다. 이전 노드로 돌아갈 수 없어, 특정 노드 앞에서 탐색하려면 항상 헤드부터 다시 시작해야 합니다.
2. **원형 연결 리스트 (Circular Linked List)**: 마지막 노드의 링크가 `NULL`이 아닌 헤드 노드를 가리켜 리스트가 원형으로 연결된 구조입니다. 이를 통해 어떤 노드에서든 순회를 계속할 수 있습니다.
3.  **이중 연결 리스트 (Doubly Linked List)**: 각 노드가 다음 노드(next)뿐만 아니라 이전 노드(previous)에 대한 포인터도 가집니다. 양방향 탐색이 가능하여 효율성이 높지만, 구조가 더 복잡합니다.

이러한 각 리스트의 특성을 이해하고 상황에 맞는 자료구조를 선택하는 것이 중요합니다.

끝.

보통 `헤드 포인터`가 첫 노드가 아닌 **마지막 노드**를 가리키게 구현하는데, 이렇게 하면 마지막 노드(`head`)와 첫 노드(`head->link`) 모두에 O(1) 시간 복잡도로 접근할 수 있어 연산이 편리해집니다.

- **헤드 포인터**는 리스트의 첫 번째 노드 '주소'를 담는 변수인 반면, **헤드 노드(더미 노드)**는 리스트 맨 앞에 두는 데이터 없는 '실제 노드'로, 코드의 예외 처리를 간소화합니다.

- `Memory Leak` (메모리 누수): 동적 할당된 메모리를 해제하지 않아 발생하는 메모리 낭비.

### 4. **정석 보강(canon-std)**

- **주제:** 배열 리스트 vs. 연결 리스트 핵심 비교
- **접근 시간:** 배열은 인덱스를 통한 임의 접근(Random Access)이 $O(1)$로 빠르나, 연결 리스트는 헤드부터 순차 접근(Sequential Access)만 가능하여 특정 원소 탐색에 최악 $O(n)$이 소요됩니다.
- **삽입/삭제:** 배열은 원소 이동 때문에 평균 $O(n)$이 걸리지만, 연결 리스트는 포인터 재연결만으로 $O(1)$에 가능합니다 (단, 삽입/삭제 위치를 찾는 시간은 별도).
- **메모리:** 배열은 연속된 메모리 공간을 정적으로 할당하며, 연결 리스트는 필요한 만큼만 동적으로 할당하여 비연속적 공간에 저장하므로 메모리 유연성이 높습니다.

## 5. **실수·함정**

- 배열 리스트 삽입 시, 앞에서부터 원소를 옮겨 데이터가 덮어써지는 논리 오류.
- 연결 리스트에서 노드를 삭제한 후 `free()` 호출을 누락하여 메모리 누수를 발생시키는 것.
- 헤드 포인터 자체를 첫 번째 노드로 착각하는 오류 (헤드는 노드를 '가리키는' 포인터일 뿐).
- 포인터 변수(`p`)와 그 포인터가 가리키는 노드의 멤버(`p->data`)를 혼동하는 것.
- 헤드 포인터(주소를 담는 변수)와 헤드 노드(데이터 없는 실제 노드)의 개념을 혼동하여 잘못 사용하는 경우.
- 단순 연결 리스트에서 현재 노드의 '이전' 노드에 접근하려는 잘못된 시도.
- 빈 리스트(`head == NULL`)에 대해 삭제 연산을 시도하여 발생하는 런타임 에러.
- '눈 코딩'으로 개념을 이해했다고 착각하고 실제 구현을 생략하는 학습 태도.

## 2025-09-18, 2교시 — 질문

**[Q1] 리스트를 구현할 때, 배열을 사용하는 것과 연결 리스트를 사용하는 것의 핵심적인 차이점은 무엇이며, 각각 어떤 상황에 더 유리한가? | #자료구조 #비교**

- **모범답(강의 기준)**: 배열은 크기가 고정되고 삽입/삭제 시 원소 이동 오버헤드가 큰 대신 구현이 간단합니다. 연결 리스트는 크기가 동적이고 삽입/삭제가 효율적이지만, 포인터 사용으로 구현이 복잡하고 메모리 누수 위험이 있습니다.
- **정석체크(면접 30초 대답분량)**: 데이터의 임의 접근(random access) 속도가 중요하다면 인덱스로 O(1) 접근이 가능한 배열이 유리합니다. 데이터의 추가/삭제가 빈번하다면 포인터 조작만으로 $O(1)$에 처리 가능한 연결 리스트가 유리합니다.

**[Q2] 배열 기반 리스트의 중간에 원소를 삽입할 때, 데이터 유실을 막기 위해 반드시 '맨 뒤 원소부터' 옮겨야 하는 이유는 무엇인가? | #배열_리스트 #알고리즘**

- **모범답(강의 기준)**: 만약 앞에서부터 뒤로 옮기면(`list[i+1] = list[i]`), 기존의 `list[i+1]`의 값이 `list[i]`의 값으로 덮어써져 유실됩니다. 이 과정이 반복되면 삽입 위치 뒤의 모든 원소가 하나의 값으로 복제되는 오류가 발생합니다.
- **정석체크(면접 30초 대답분량)**: 전제는 '순차적 덮어쓰기' 문제입니다. 뒤에서부터(`list[i+1] = list[i]` where `i` decreases) 옮겨야만, 아직 처리되지 않은 원본 데이터가 보존된 상태에서 비어있는 다음 칸으로 안전하게 복사될 수 있습니다.

**[Q3] C언어에서 `struct node n;`과 `struct node* p;`는 어떻게 다른가? 특히 멤버(member)의 관점에서 설명하라. | #구조체 #포인터**

- **모범답(강의 기준)**: `struct node n`은 `data`, `link`와 같은 멤버를 포함하는 실체 메모리 공간을 가진 '구조체 변수'입니다. 반면 `struct node* p`는 자체적으로 멤버가 없으며, 다른 구조체 변수의 '주소'만을 저장할 수 있는 '구조체 포인터 변수'입니다.
- **정석체크(면접 30초 대답분량)**: `n`은 구조체 실체이며 `n.data`로 멤버에 접근합니다. `p`는 주소 값이며, `p->data`와 같이 포인터가 가리키는 대상의 멤버에 접근하는 데 사용됩니다. `sizeof(n)`은 구조체 전체 크기지만, `sizeof(p)`는 포인터의 크기입니다.

**[Q4] 연결 리스트에서 특정 노드를 논리적으로 삭제(포인터 연결 해제)한 후, `free()`를 호출하여 물리적 메모리를 해제해야 하는 이유는 무엇인가? | #메모리_관리 #오류**

- **모범답(강의 기준)**: `malloc`으로 할당받은 메모리 공간을 `free` 함수로 해제하지 않으면, 해당 메모리는 시스템에 반환되지 않아 프로그램이 점유한 채로 낭비됩니다. 이를 '메모리 누수'라 하며, 장시간 실행 시 시스템 전체의 가용 메모리가 고갈될 수 있습니다.
- **정석체크(면접 30초 대답분량)**: 이유는 동적 할당된 메모리의 소유권을 운영체제에 명시적으로 반환하기 위함입니다. `free()`를 생략하면 메모리 누수가 발생하며, 이는 자원 낭비일 뿐만 아니라 서버처럼 계속 실행되는 프로그램에서는 결국 시스템 장애의 원인이 됩니다.

## **2025-09-18, 3교시 — 개선본**

단순 연결 리스트(Singly Linked List)에서 마지막 노드의 `link` 값은 항상 `NULL`이며, `head` 포인터가 첫 번째 노드를 가리킵니다. 여기서 가장 중요한 연산은 삽입과 삭제입니다.

### 1. 연결 리스트 삽입(Insertion)

before 노드와 after 노드 사이에 새로운 new_node를 삽입하는 상황을 가정해 봅시다. 이때 포인터 연결 순서가 매우 중요합니다.

만약 `before->link = new_node;`를 먼저 수행하면, `before`가 가리키던 기존의 `after` 노드에 대한 연결 정보(`after`의 주소 값)가 사라집니다. 따라서 `after` 노드의 주소를 찾을 수 없게 되어 `new_node`를 `after`에 연결할 수 없게 됩니다.

따라서 올바른 순서는 다음과 같습니다.

1. `new_node->link = before->link;` : 새 노드가 먼저 기존의 다음 노드(`after`)를 가리키게 합니다. `before->link`에 저장되어 있던 `after`의 주소 값을 `new_node->link`에 복사하는 것입니다.
2. `before->link = new_node;` : 이전 노드가 새 노드를 가리키도록 연결을 변경합니다.

### 삽입의 3가지 시나리오

삽입 연산은 리스트의 상태에 따라 세 가지 경우로 나눌 수 있습니다. 여기서 p는 삽입할 위치의 '이전 노드'를 가리키는 포인터입니다.

- Case 1: **`head == NULL`인 경우** (빈 리스트에 삽입)

    리스트가 아예 생성되지 않은 상태입니다. 이때는 새로 추가되는 노드가 리스트의 첫 번째이자 마지막 노드가 됩니다. head는 새 노드를 가리키고, 새 노드의 link는 NULL이 됩니다.

- Case 2: 선행노드 **`p == NULL`인 경우** (기존 리스트의 맨 앞에 삽입)

    head가 NULL이 아니므로 리스트는 존재하지만, 맨 앞에 삽입하려는 경우입니다.여기서 `p`는 삽입할 위치의 '이전' 노드를 가리키는 포인터인데, 맨 앞에는 이전 노드가 없으므로 `p`가 `NULL`이 됩니다. 새 노드의 link가 기존의 head가 가리키던 노드를 가리키게 하고, head 포인터를 새 노드를 가리키도록 갱신합니다.

- Case 3: **`p != NULL`인 경우** (리스트의 중간 또는 끝에 삽입)

    head와 p가 모두 NULL이 아닌 가장 일반적인 경우입니다. 이는 p가 가리키는 노드 뒤에 새 노드를 삽입하는 것을 의미하며, 앞서 설명한 2단계 연결 순서를 따릅니다.

### 2. 연결 리스트 삭제(Deletion)

삭제할 노드를 removed, 그 이전 노드를 before라고 할 때, 삭제는 더 간단합니다.

1. `before->link = removed->link;` : `before` 노드가 `removed` 노드가 가리키고 있던 다음 노드를 직접 가리키도록 연결을 변경합니다.
2. `free(removed);` : `removed` 노드에 할당되었던 메모리를 `free` 함수로 반드시 해제하여 메모리 누수를 방지합니다.
3. 노드의 동적 생성 및 초기화

연결 리스트의 각 노드는 malloc 함수를 통해 동적으로 메모리를 할당받아 생성됩니다.

p1 = (ListNode*)malloc(sizeof(ListNode));

malloc은 할당에 성공하면 해당 메모리의 시작 주소를, 실패하면 NULL을 반환합니다. 할당 후에는 포인터를 통해 멤버에 접근하여 값을 초기화합니다.

p1->data = 10;

p1->link = NULL;

### **4. 연결 리스트의 기타 연산**

- **탐색(Search)**: `head`, 헤드포인터 부터 시작하여 `p = p->link` 코드를 반복 실행하면서 각 노드를 방문(순회)합니다. `p`가 `NULL`이 되면 리스트의 끝에 도달한 것입니다.
- **합병(Concatenate)**: 두 연결 리스트(list1, list2)를 합치려면, list1의 마지막 노드를 찾아 그 노드의 `link`가 list2의 `head`를 가리키게 하면 됩니다. 배열보다 훨씬 간편하게 수행할 수 있습니다.
- **응용: 다항식 연산**: 1교시의 다항식 덧셈을 연결 리스트로 구현할 수 있습니다. 노드의 데이터 필드를 계수(`coef`)와 지수(`exp`)를 담는 구조체로 정의하면, 배열의 한계를 극복하는 효율적인 다항식 표현이 가능합니다.
- **역순(Reverse)**: 단순 연결 리스트는 단방향 구조이므로 역순으로 만드는 것은 다소 복잡합니다. 일반적으로 3개의 포인터(`p`, `q`, `r`)를 사용하여 노드의 연결 방향을 하나씩 바꾸어 나가는 방식으로 구현합니다. 이 메커니즘을 다음 시간까지 분석해 오세요. (실습)

ListNode* search( ... ) 와 같은 함수 선언에서 ListNode\*는 함수 포인터가 아니라, 함수가 실행된 후 반환하는 값의 타입이 'ListNode에 대한 포인터'임을 의미합니다. 즉, int main()이 정수 값을 반환하는 것과 같은 원리입니다.

## 2025-09-18, 3교시 — 개념

### 1. 한 줄 요약

단순 연결 리스트의 핵심 연산인 삽입과 삭제의 포인터 조작 순서와 세부 시나리오를 학습하고, 탐색, 합병, 역순 등 다양한 활용법을 다룹니다.

### 2. **핵심 TL;DR**

- **삽입의 핵심 순서**:
1. 새 노드가 기존 다음 노드를 먼저 가리키게 하고(`new->link = prev->link`),
2. 이전 노드가 새 노드를 가리키도록(`prev->link = new`) 연결해야 데이터 유실이 없습니다.
- **삭제의 핵심 순서**:
1. 이전 노드가 삭제할 노드의 다음 노드를 가리키게 하여(`prev->link = del->link`) 논리적으로 분리한 후,
2. 삭제할 노드의 메모리를 반드시 `free(del)` 해줘야 합니다.
- **선행 노드의 중요성**: 연결 리스트에서 특정 노드의 위치 정보는 오직 **선행 노드(preceding node)** 의 `link` 포인터만이 가지고 있으므로, 삽입/삭제 연산은 항상 선행 노드를 기준으로 수행됩니다.
- **삽입의 3가지 경우**: 세 가지 경우를 구분하여 처리해야 합니다.
1. 빈 리스트(`head==NULL`),`head`가 `NULL`일 때, 새 노드가 유일한 노드가 되도록 `head` 포인터가 새 노드를 가리키게 합니다
2. 맨 앞(`선행노드==NULL`), 리스트는 존재하지만 맨 앞에 삽입할 때, 새 노드가 기존의 첫 번째 노드를 가리키게 하고, `head` 포인터가 새 노드를 가리키도록 갱신합니다.
3. 중간/끝(`선행노드!=NULL`)`p` 노드 뒤에 삽입하며, `p`와 `p`가 가리키던 노드(`p->link`) 사이에 새 노드를 연결합니다.
- **동적 생성과 접근**: 모든 노드는 `malloc`으로 생성하며, 변수명이 없으므로 항상 포인터(`p->data`)를 통해 멤버에 접근합니다.
- **탐색과 순회**: `p = p->link` 연산을 반복하여 리스트의 모든 노드를 순차적으로 방문할 수 있습니다.
- **응용 확장성**: 노드의 `data` 필드는 정수뿐만 아니라 \[계수, 지수]와 같은 다른 구조체를 담을 수 있어, 다항식 표현 등 복잡한 데이터 표현이 가능합니다.
- **헤드 포인터(Head Pointer)**: 리스트의 시작 위치를 고정하는 역할을 합니다. 맨 앞 노드가 변경되는 연산에서 리스트 전체의 참조를 잃지 않도록 하는 안정적인 진입점입니다.

### 1. **표현 = 표준 용어**

- `Insertion` (삽입): 리스트에 새로운 노드를 추가하는 연산.
- `Deletion` (삭제): 리스트에서 특정 노드를 제거하는 연산.
- `Traversal` (순회): 리스트의 모든 노드를 한 번씩 방문하는 것.
- `Concatenate` (합병/연결): 두 리스트를 하나의 리스트로 이어 붙이는 연산.
- `Reverse` (역순): 리스트의 노드 순서를 뒤집는 연산.
- `Preceding Node` (선행 노드): 특정 노드의 바로 앞에 위치한 노드.
- `Dynamic Allocation` (동적 할당): `malloc`, `free`를 이용한 메모리 관리.

### 4. **정석 보강(canon-std)**

- **주제:** 연결 리스트 중간 삽입 알고리즘
- **전제:** `p`는 삽입할 위치의 바로 앞 노드를 가리키는 포인터, `new_node`는 새로 삽입할 노드를 가리키는 포인터이다.
- **핵심 의사코드 (2-steps):**
    
    1. `new_node->link = p->link;` // 새 노드가 p의 기존 다음 노드를 가리키게 함
    2. `p->link = new_node;` // p가 새 노드를 가리키도록 변경
        
- **주의:** 이 두 단계의 순서가 바뀌면 `p` 이후의 모든 노드에 대한 연결이 끊어지게 되어 리스트가 유실됩니다.

### 5. **실수·함정**

- 삽입 시 포인터 연결 순서를 반대로 하여 리스트의 뒷부분을 유실하는 실수.
- `head`가 변경되는 경우(맨 앞에 삽입/삭제)에 `head` 포인터 값을 갱신하는 것을 잊는 오류.
- `malloc`으로 노드를 생성한 후 `NULL`인지 확인하지 않고 사용하여 발생하는 런타임 에러.
- 삭제 연산 후 `free()`를 호출하지 않아 메모리 누수를 발생시키는 것.
- 함수에서 `ListNode*`가 반환 타입임을 이해하지 못하고 함수 포인터로 오해하는 것.
- 노드의 데이터 필드는 단일 값만 저장할 수 있다고 생각하여 응용 가능성을 제한하는 것.

끝.

- **모범답(강의 기준)**: 만약 이전 노드(`prev`)가 새 노드(`new`)를 먼저 가리키게 하면(`prev->link = new`), 기존 뒷부분 리스트에 대한 주소 값을 잃어버리게 됩니다. 따라서 1) 새 노드가 기존 뒷부분을 먼저 가리키게 하고(`new->link = prev->link`), 2) 그 다음에 이전 노드가 새 노드를 가리키도록(`prev->link = new`) 해야 합니다.
- **정석체크(면접 30초 대답분량)**: 이유는 '연결 정보 유실 방지'입니다. 순서가 바뀌면 `prev` 이후의 모든 노드에 접근할 방법이 사라집니다. 올바른 순서는 새 노드의 `link`를 먼저 설정하여 기존 연결을 확보한 뒤, `prev` 노드의 `link`를 갱신하는 것입니다.

- **정석체크(면접 30초 대답분량)**: 1단계는 'Bypass'(우회), 2단계는 'Deallocation'(할당 해제)입니다. 2단계를 생략하면 해당 메모리 영역은 프로그램이 계속 점유하지만 접근은 불가능한 상태가 되어, 가용 메모리가 점차 줄어드는 심각한 문제를 일으킵니다.

## **2025-09-18, 3교시 — 실습**

**[S1] 연결 리스트 역순(Reverse) 알고리즘 분석 — 목적**: 3개의 포인터(`prev`, `curr`, `next` 등)를 사용하여 단순 연결 리스트의 순서를 뒤집는 알고리즘의 동작 원리를 단계별로 추적하고 이해한다.

- **단계요약**: 1) 3개의 포인터를 초기화한다 (`prev = NULL`, `curr = head`). 2) `curr` 포인터가 리스트의 끝에 도달할 때까지 반복하는 루프를 가정한다. 3) 루프의 각 단계에서 다음 노드를 임시 저장하고(`next = curr->link`), 현재 노드의 링크 방향을 이전 노드로 변경(`curr->link = prev`)한 뒤, `prev`와 `curr` 포인터를 한 칸씩 앞으로 전진시키는 과정을 분석한다. 4) 3~4개 노드를 가진 예시 리스트를 그린 후, 각 반복마다 포인터와 `link` 값이 어떻게 변하는지 직접 따라가며 도식화해본다. 5) 반복이 끝난 후, 어떤 포인터가 새로운 `head`가 되어야 하는지 확인한다.
- **⚠️ 주의**: 포인터들의 대입 순서가 매우 중요합니다. 특히 다음 노드(`next`)의 위치를 미리 저장해두지 않으면, 현재 노드의 링크 방향을 바꾸는 순간 나머지 리스트 전체에 대한 연결을 잃어버리게 됩니다.
