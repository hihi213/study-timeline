컴파일러 당시에 제네릭으로 담을 타입을 보장해 형변환을 안전하게 붙여준 코드를 jvm가 제네릭이 역할을 다했으니 제네릭대신 범용적인 object타입으로 받아들여 코드실행

1. **컴파일 시점 (Compile-Time):**
    
    - 컴파일러는 제네릭(`List<Integer>`)을 통해 **타입 검사(Type Checking)**를 수행하여, 지정된 타입(`Integer`) 외의 객체가 컬렉션에 추가되는 것을 원천적으로 차단합니다.
    - 이 검사를 통해 **'컴파일 시 타입 안정성(Compile-Time Type Safety)'**이 확보됩니다.
    - 동시에, 컴파일러는 원소를 조회하는 코드(`list.get(0)`)에 **안전하다고 보장된 명시적 형변환(Casting) 코드를 바이트코드에 자동으로 삽입**합니다.
        
2. **실행 시점 (Runtime / JVM):**
    
    - 바이트코드가 JVM에서 실행될 때, **'타입 소거(Type Erasure)'**에 의해 제네릭 타입 정보( `<Integer>`)는 사라집니다.
    - JVM은 해당 컬렉션을 `Object`를 다루는 범용적인 **원시 타입(Raw Type)으로 인식**하고 코드를 실행합니다.
    - 원소 조회 시, JVM은 컴파일러가 삽입해 둔 형변환 코드를 실행합니다. 이미 컴파일 시점에 타입이 보장되었으므로, 이 형변환은 런타임 오류( `ClassCastException` ) 없이 안전하게 성공합니다.
        

요약하자면, **컴파일러**는 제네릭을 이용해 **'미리' 타입을 검증**하고 **'안전한 형변환'을 준비**하며, **JVM**은 제네릭 정보가 **'소거된'** 범용 `Object` 코드를 **'준비된 형변환'**과 함께 실행하는 것입니다.

## '원시타입' (Primitive Type)은 '기본형 타입' (Basic Type)과 **완전히 같은 말**입니다.

### 📚 자바의 원시타입 (Primitive Type)이란? ^8ht5el

컴퓨터 메모리에 **'값 자체'** 를 직접 저장하는 가장 기본적인 데이터 타입 8가지를 말합니다. 

- 이들은 **객체(Object)가 아닙니다.**
- 메서드(기능)를 가지고 있지 않습니다.
- `null` 값을 가질 수 없습니다.
- 메모리의 '스택(Stack)' 영역에 값이 직접 저장되어 접근 속도가 매우 빠릅니다.

[[00_Inbox/'자바'에서의 NULL의 의미와 다른언어에서의 의미 차이.md|'자바'에서의 NULL의 의미와 다른언어에서의 의미 차이]] 

#### 8가지 원시타입 (기본형)

- **논리형:** `boolean`
- **문자형:** `char`
- **정수형:** `byte`, `short`, `int`, `long`
- **실수형:** `float`, `double`
    

### ⚖️ 원시타입 vs. 참조형

님이 이미 알고 계신 '참조형'과 비교하면 차이가 명확합니다.

|**비교 기준**|**💎 원시타입 (Primitive Type)**|**📄 참조형 (Reference Type)**|
|---|---|---|
|**저장하는 것**|**'값(Value)' 자체**|객체의 **'주소값(Reference)'**|
|**저장 위치**|**스택 (Stack)** 영역에 값이 저장됨|**스택(Stack)**에 주소값이, **힙(Heap)**에 실제 객체 데이터가 저장됨|
|**`null` 저장**|불가능 (기본값이 있음. 예: `int`는 0)|**가능** (가리키는 객체가 없다는 의미)|
|**객체 여부**|객체가 아님|**객체(Object)**임 (메서드를 가짐)|
|**예시**|`int`, `long`, `char`, `boolean`… (8개)|`String`, `List`, `Integer`, `MyClass`… (8개를 제외한 모든 것)|

간단히 말해, int a = 10;은 a라는 이름표가 붙은 상자에 **10**이 들어있는 것이고,

String s = "hello";는 s라는 상자에 "hello" 객체가 저장된 **'힙(Heap) 메모리 102번지'**라는 주소쪽지가 들어있는 것입니다.




## JVM(자바 가상 머신)의 메모리 영역을 기준으로 스택과 힙의 역할과 특징을 정확하게 설명해 드리겠습니다.

### 스택 (Stack) 메모리 (자료구조: 스택)

**1. 생성 및 소유 주체: 스레드 (Thread) / JVM**

- **JVM**은 **스레드**가 시작될 때마다, 해당 스레드**만을 위한** 고유한 스택 메모리 영역을 생성(할당)합니다. 스택은 스레드 간에 절대 공유되지 않습니다.
    

**2. 할당(Push) 주체: JVM**

- 한 **스레드**가 특정 메서드를 호출할 때, **JVM**은 해당 메서드 실행에 필요한 정보(매개변수, 로컬 변수, 반환 주소 등)를 담는 **'스택 프레임(Stack Frame)'을** 생성하여, 그 스레드의 스택 최상단에 쌓습니다(Push).
    

**3. 저장 대상 (JVM이 저장하는 데이터)**

- **JVM**은 스택 프레임 내부에 다음 데이터를 저장합니다.
    - **기본형(Primitive) 변수:** `int`, `boolean` 등 변수의 **실제 값(value)**이 **JVM**에 의해 직접 저장됩니다.
    - **참조형(Reference) 변수:** 객체 변수의 **'힙(Heap) 주소값'**이 **JVM**에 의해 저장됩니다. (객체 본체는 힙에 있습니다.)
        

**4. 해제(Pop) 주체: JVM**

- 메서드 실행이 종료되거나(return), **JVM**이 예외를 처리하는 시점에, **JVM**은 해당 스택 프레임을 스택에서 즉시 제거(Pop)합니다.
- 이 제거 행위와 동시에 프레임 내의 모든 로컬 변수(기본형 값, 참조형 주소)는 소멸하며, 메모리 공간은 즉시 반환됩니다. 이 과정은 **JVM**에 의해 자동으로, 결정론적으로(즉시) 일어납니다.
    

---

### 힙 (Heap) 메모리 (자료구조의 heap의 구현이 아님)

**1. 생성 및 소유 주체: JVM**

- **JVM**은 시작될 때(프로세스 시작 시) **단 하나**의 힙 메모리 영역을 생성합니다.
- 이 힙 영역은 **JVM** 내의 **모든 스레드**가 공유하는 공용 공간입니다.
    

**2. 할당 주체: JVM (스레드의 요청)**

- 한 **스레드**가 코드(`new MyObject()`)를 실행하여 객체 생성을 **요청**하면, **JVM**이 힙 영역에서 해당 객체를 저장할 만큼의 공간을 찾아 동적으로 할당합니다.
- **JVM**은 이 할당된 힙 주소값을 **요청한 스레드**에게 반환하며, **스레드**는 이 주소값을 자신의 스택 프레임 내 참조 변수에 저장합니다.
    

**3. 저장 대상 (JVM이 저장하는 데이터)**

- **JVM**은 `new` 키워드로 생성된 모든 **객체 인스턴스**와 **배열**의 본체를 힙에 저장합니다.
    

**4. 해제 주체: 가비지 컬렉터 (Garbage Collector, GC)**

- 힙 메모리의 해제는 **JVM**의 구성요소인 **GC**가 전담합니다.
- **GC**는 주기적으로 또는 특정 조건(메모리 부족 등)이 충족될 때 실행됩니다.
- **GC**는 힙을 스캔하여, 현재 실행 중인 **모든 스레드**의 스택에서 더 이상 참조(주소값)되지 않는 '쓰레기 객체'를 식별합니다.
- 식별된 객체들의 메모리는 **GC**에 의해 회수(해제)됩니다. 이 과정은 **JVM**이 관리하므로 비결정론적(언제 일어날지 정확히 예측 힘듦)입니다.

### 주체별 핵심 차이 요약

| **행위** | **스택 (Stack)**                  | **힙 (Heap)**                          |
| ------ | ------------------------------- | ------------------------------------- |
| **생성** | **JVM**이 **스레드** 시작 시 (스레드별 생성) | **JVM**이 프로세스 시작 시 (전체 공유 1개)         |
| **할당** | **JVM**이 메서드 호출 시 (자동 Push)     | **JVM**이 **스레드**의 `new` 요청 시 (동적 할당)  |
| **해제** | **JVM**이 메서드 종료 시 (자동 Pop)      | **가비지 컬렉터(GC)**가 참조 없는 객체 식별 후 (비결정적) |
| **사용** | **스레드**가 자신의 스택만 단독 사용          | **모든 스레드**가 힙 전체를 공유                  |
