JPA(Java Persistence API)를 사용하여 엔티티 간의 관계를 설정하기 전, 데이터베이스의 물리적 구조와 객체지향 모델 간의 간극을 해결하기 위해 반드시 이해해야 할 **4가지 핵심 기술 개념**을 정리해 드립니다.

---

### 1. 객체 식별자 정의 (`@Id` 및 생성 전략)

데이터베이스의 PK(Primary Key)와 엔티티의 필드를 매핑하는 단계입니다. PostgreSQL을 사용하므로 해당 DB의 특성에 맞는 전략을 선택해야 합니다.

- **`@Id`**: 해당 필드가 테이블의 기본 키임을 명시합니다.
- **`@GeneratedValue`**: PK 값의 생성 방식을 결정합니다.
    - **IDENTITY**: PostgreSQL의 `SERIAL` 또는 `IDENTITY` 컬럼을 사용하여 DB가 값을 자동 생성합니다.
    - **SEQUENCE**: DB 시퀀스 오브젝트를 사용하여 값을 생성합니다. (PostgreSQL 권장 방식 중 하나)
    - **UUID**: 앞서 설계하신 대로 UUID를 사용할 경우, 자바의 `UUID` 타입을 사용하며 별도의 생성 로직이나 Hibernate의 `@GenericGenerator`를 설정합니다.
        

---

### 2. 연관관계의 주인 (Ownership)

JPA 관계 설정에서 가장 중요한 개념입니다. 두 객체가 서로 참조할 때, **데이터베이스의 외래 키(FK)를 누가 관리할지**를 정해야 합니다.

- **주인(Owner)**: 외래 키를 직접 가지고 있는 테이블과 매핑되는 엔티티입니다. 보통 `@ManyToOne`이 붙은 쪽이 주인이 됩니다.
- **비주인(Non-Owner)**: 주인이 설정한 외래 키에 의해 매핑되는 쪽입니다. `@OneToMany` 설정 시 `mappedBy` 속성을 사용하여 주인이 누구인지 명시해야 합니다.
    
> [!IMPORTANT]
>
> `mappedBy`가 선언된 곳은 DB의 컬럼을 변경할 수 없으며, 오직 읽기만 가능합니다.
    

---

### 3. 방향성 (Directionality)

객체 수준에서 한쪽만 상대방을 참조할지, 양쪽 모두 서로를 참조할지를 결정합니다.

- **단방향 (Unidirectional)**: 한 엔티티만 상대 엔티티를 참조합니다. (예: `Bundle` -> `Slot`)
- **양방향 (Bidirectional)**: 양쪽 엔티티가 서로를 참조합니다. 자바 코드상에서는 양방향이지만, DB 테이블은 외래 키 하나로 관리되므로 **연관관계의 주인** 설정이 필수적입니다.
    - 양방향 설정 시 편의 메서드(양쪽 객체의 상태를 한 번에 업데이트하는 로직) 작성이 권장됩니다.
        

---

### 4. 페치 전략 (Fetch Type)

연관된 엔티티를 **언제** 메모리에 올릴지 결정하는 성능 최적화 설정입니다.

|**전략**|**설명**|**기본값**|**비고**|
|---|---|---|---|
|**EAGER (즉시 로딩)**|엔티티 조회 시 연관된 객체도 함께 JOIN하여 조회|`@ManyToOne`, `@OneToOne`|성능 저하 위험(N+1 문제)이 큼|
|**LAZY (지연 로딩)**|실제 연관 객체를 사용할 때 쿼리 실행|`@OneToMany`, `@ManyToMany`|**실무 권장 전략**|

---

### 📋 요약 체크리스트

|**항목**|**핵심 규칙**|
|---|---|
|**Multiplicity**|1:N 관계에서 외래 키는 항상 N(Many) 쪽에 존재함|
|**@ManyToOne**|항상 연관관계의 주인이 되며, FK 컬럼과 매핑됨|
|**mappedBy**|양방향 관계에서 주인이 아닌 쪽(`@OneToMany`)에 사용|
|**Fetch Strategy**|모든 연관관계는 우선적으로 `FetchType.LAZY` 설정을 권장|

### 🛠️ 구현 예시 가이드

작성하신 `USERS`, `FRIDGE_SLOT`, `SLOT_USER` 관계를 코드로 옮길 때의 구조입니다.



```Java
@Entity
public class SlotUser { // 조인 테이블 (N:1 관계의 주인)
    @Id
    private UUID id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id") // DB의 FK 컬럼명
    private User user;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "slot_id") // DB의 FK 컬럼명
    private FridgeSlot fridgeSlot;
}
```
