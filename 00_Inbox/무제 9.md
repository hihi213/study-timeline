좋습니다. 지금까지 논의한 내용을 바탕으로 \*\*[3시간 완성 도서 대여 시스템]\*\*의 최종 청사진을 정리해 드리겠습니다.

\*\*기능 요구사항(What)\*\*에서 시작하여 \*\*데이터베이스 설계(How)\*\*로 이어지는 논리적 흐름을 확인해 보세요.

-----

### 1\. 최종 요구사항 정의 (Requirements)

우리는 \*\*"관리자 기능은 SQL로 대체하고, 사용자 핵심 로직(대여/반납)에 집중"\*\*합니다.

-----

### 2\. 데이터베이스 설계 흐름 (DB Design Flow)

이 시스템이 돌아가기 위해 데이터가 어떻게 구성되는지 **3단계**로 설명해 드릴게요.

#### 1단계: 마스터 데이터 (주체 정의)

가장 먼저 시스템의 **주인공**들을 만듭니다. 이 데이터는 시스템 시작 전에 미리 채워둡니다.

  * **회원(TBL\_MEMBER):** 책을 빌리는 사람. (누가?)
  * **도서(TBL\_BOOK):** 빌려줄 물건. (무엇을?)

#### 2단계: 트랜잭션 데이터 (행위 정의)

주인공들이 만드는 **사건**을 기록합니다.

  * **대여(TBL\_RENT):** 회원이 책을 빌리고 돌려주는 행위 전체.
      * **전략:** 대여와 반납을 **단일 테이블**로 통합 관리.
      * **구분:** `RTN_DATE`(반납일) 컬럼이 `NULL`이면 대여 중, 날짜가 있으면 반납 완료.

#### 3단계: 성능 및 무결성 제어 (최적화)

데이터가 쌓여도 문제없도록 장치를 둡니다.

  * **FK(외래키):** 없는 회원이나 없는 책이 대여되지 않도록 강제.
  * **Index(인덱스):** `TBL_RENT`의 반납일 컬럼에 인덱스를 걸어, 수천 건의 이력이 쌓여도 \*\*"지금 미반납된 책"\*\*은 0.01초 만에 찾도록 설정.

-----

### 3\. 물리적 모델링 & SQL (바로 사용 가능)

아래 코드를 복사해서 오라클 DB에 순서대로 실행하시면 설계가 끝납니다.

#### ① 초기화 (기존 테이블 삭제)

```sql
-- 혹시 모를 기존 테이블 삭제 (순서 중요)
DROP TABLE TBL_RENT;
DROP TABLE TBL_BOOK;
DROP TABLE TBL_MEMBER;
DROP SEQUENCE SEQ_MEM;
DROP SEQUENCE SEQ_BOOK;
DROP SEQUENCE SEQ_RENT;
```

#### ② 테이블 및 시퀀스 생성

```sql
-- 1. 회원 테이블 (암호화된 비번 저장을 위해 크기 넉넉하게)
CREATE TABLE TBL_MEMBER (
    MEM_NO    NUMBER          PRIMARY KEY, -- 내부 관리 번호
    MEM_ID    VARCHAR2(30)    UNIQUE NOT NULL,
    MEM_PW    VARCHAR2(200)   NOT NULL,    -- 암호화된 비밀번호 들어감
    MEM_NAME  VARCHAR2(20)    NOT NULL,
    MEM_TEL   VARCHAR2(20)
);

CREATE SEQUENCE SEQ_MEM; -- 회원번호 자동생성기

-- 2. 도서 테이블
CREATE TABLE TBL_BOOK (
    BOOK_NO   NUMBER          PRIMARY KEY,
    TITLE     VARCHAR2(100)   NOT NULL,
    AUTHOR    VARCHAR2(50),
    RENT_YN   CHAR(1)         DEFAULT 'N' CHECK (RENT_YN IN ('Y', 'N')) -- Y:대여중, N:대여가능
);

CREATE SEQUENCE SEQ_BOOK; -- 도서번호 자동생성기

-- 3. 대여 테이블 (핵심 트랜잭션)
CREATE TABLE TBL_RENT (
    RENT_NO   NUMBER          PRIMARY KEY,
    MEM_NO    NUMBER          NOT NULL,
    BOOK_NO   NUMBER          NOT NULL,
    RENT_DATE DATE            DEFAULT SYSDATE, -- 대여일 (오늘)
    RTN_DUE   DATE            DEFAULT SYSDATE+7, -- 반납예정일 (기본 7일)
    RTN_DATE  DATE,           -- 실반납일 (반납 전엔 NULL)
    
    -- 관계 설정 (FK)
    CONSTRAINT FK_RENT_MEM FOREIGN KEY (MEM_NO) REFERENCES TBL_MEMBER(MEM_NO),
    CONSTRAINT FK_RENT_BOOK FOREIGN KEY (BOOK_NO) REFERENCES TBL_BOOK(BOOK_NO)
);

CREATE SEQUENCE SEQ_RENT; -- 대여번호 자동생성기
```

#### ③ 성능 최적화 (인덱스)

이 부분이 아까 고민하셨던 \*\*"데이터가 많아져도 속도를 유지하는 비결"\*\*입니다.

```sql
-- 반납 안 된 책(NULL)을 빨리 찾기 위한 인덱스
CREATE INDEX IDX_RENT_RETURN ON TBL_RENT(RTN_DATE);
```

#### ④ 기초 데이터 입력 (테스트용)

```sql
-- 회원 등록 (비밀번호는 아직 암호화 전, 평문 '1234'로 가정)

INSERT INTO TBL_MEMBER VALUES (SEQ_MEM.NEXTVAL, 'user2', '1234', '이영희', '010-3333-4444');

-- 도서 등록

INSERT INTO TBL_BOOK (BOOK_NO, TITLE, AUTHOR) VALUES (SEQ_BOOK.NEXTVAL, '오라클 성능 고도화', '조시형');
INSERT INTO TBL_BOOK (BOOK_NO, TITLE, AUTHOR) VALUES (SEQ_BOOK.NEXTVAL, '해리포터와 마법사의 돌', '롤링');
INSERT INTO TBL_BOOK (BOOK_NO, TITLE, AUTHOR) VALUES (SEQ_BOOK.NEXTVAL, '어린왕자', '생텍쥐페리');
INSERT INTO TBL_BOOK (BOOK_NO, TITLE, AUTHOR) VALUES (SEQ_BOOK.NEXTVAL, '인공지능의 미래', '샘 알트만');

COMMIT;
```
