## `props`: 부모에서 자식으로의 데이터 전달

React에서 데이터는 단방향으로, 즉 **부모 컴포넌트에서 자식 컴포넌트로** 흐릅니다. 이때 데이터를 전달하는 매개체가 바로 **`props`** 입니다.

`props`(properties의 줄임말)는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 **데이터가 담긴 객체(Object)** 입니다. 자식 컴포넌트는 `props`를 통해 외부로부터 데이터를 받아 동적으로 UI를 구성할 수 있습니다.

**'Props'**는 **'Properties(속성들)'**의 줄임말입니다. HTML 태그에 `src`나 `href` 같은 속성을 부여하여 그 동작이나 내용을 바꾸는 것처럼, 리액트 컴포넌트에 **데이터를 속성처럼 전달**한다는 핵심 의미를 담고 있습니다

컴포넌트는 재사용이 가능해야 합니다. 하지만 모든 버튼이 똑같이 '확인'이라는 글자만 보여주거나, 모든 프로필 카드가 홍길동의 정보만 보여준다면 재사용성이 없습니다.

각각의 컴포넌트가 **서로 다른 데이터를 가지고 다르게 보이도록** 만드는 방법이 필요했습니다. 이 문제를 해결하기 위해, 컴포넌트를 사용하는 **부모가 컴포넌트를 사용하는 자식에게 데이터를 '속성(props)'처럼 내려주는** 방식이 도입되었습니다. 이를 통해 하나의 `<Button>` 컴포넌트로 '확인 버튼', '취소 버튼' 등 다양한 버튼을 만들어낼 수 있게 되었습니다.

### 사용하지 않을 경우 (The Consequence)

컴포넌트의 재사용이 거의 불가능해집니다.

- '확인 버튼'과 '취소 버튼'이 필요하다면, 내용만 다른 `<ConfirmButton>`, `<CancelButton>` 컴포넌트를 각각 따로 만들어야 합니다. 이는 엄청난 코드 중복을 유발합니다.
- 부모 컴포넌트가 가진 데이터를 자식 컴포넌트에게 전달할 방법이 없어, 모든 컴포넌트가 고립된 상태로 존재하게 됩니다.

`props`는 **부모 컴포넌트가 자식 컴포넌트를 렌더링하는 시점**에 전달됩니다.

1. **전달 (부모)**: 부모 컴포넌트의 JSX 안에서, 자식 컴포넌트에 마치 HTML 속성처럼 `prop이름="값"` 형태로 데이터를 전달합니다.
2. **패키징 (리액트)**: 리액트는 전달된 모든 `props`를 **하나의 자바스크립트 객체**로 묶습니다.
3. **수신 (자식)**: 묶인 `props` 객체는 자식 컴포넌트 함수의 **첫 번째 인자**로 전달됩니다.
4. **사용 (자식)**: 자식 컴포넌트는 인자로 받은 `props` 객체의 속성에 접근하여(예: `props.name`) 데이터를 사용합니다.

> **[핵심 규칙]** `props`는 부모가 주는 값이며, 자식은 **절대 직접 수정할 수 없습니다 (Read-only).**
---

### `props` 사용법: 전달, 수신, 활용

#### **1단계: 부모 컴포넌트에서 데이터 전달**

부모 컴포넌트에서 자식 컴포넌트를 호출할 때, HTML의 속성(attribute)과 유사한 `key={value}` 형태로 데이터를 전달합니다.

```JavaScript
// 👩‍👦 Parent Component: App.js
import UserProfile from './UserProfile';

function App() {
  const userData = {
    name: '홍길동',
    age: 30,
  };

  return (
    <div>
      {/* name과 age라는 이름으로 자식에게 데이터 전달 */}
      <UserProfile name={userData.name} age={userData.age} />
    </div>
  );
}
```

#### **2단계: 자식 컴포넌트에서 데이터 수신 (비구조화 할당)**

자식 컴포넌트는 함수의 첫 번째 인자로 부모가 전달한 `props`를 객체 형태로 받습니다. 이때 **객체 비구조화 할당(Object Destructuring)**을 사용하여 필요한 값만 명시적으로 추출하는 방식이 권장됩니다.

> **객체 비구조화 할당(Destructuring)이란?** ✨ `props` 객체 전체가 아닌, `{ name, age }`처럼 중괄호를 사용해 필요한 프로퍼티만 변수로 직접 추출하는 JavaScript 문법입니다. 코드가 간결해지고, 해당 컴포넌트가 어떤 `props`를 필요로 하는지 명확히 보여주는 장점이 있습니다.

```JavaScript
// 🧒 Child Component: UserProfile.js

// 권장 방식: 비구조화 할당으로 필요한 props만 직접 받기
function UserProfile({ name, age }) {
  return (
    <div>
      <h2>이름: {name}</h2>
      <p>나이: {age}세</p>
    </div>
  );
}
```

### 특별한 `prop`: `children`

컴포넌트의 여는 태그와 닫는 태그 사이에 위치하는 모든 요소들은, `children`이라는 이름의 `prop`으로 자식 컴포넌트에 자동으로 전달됩니다.

이 기능은 특정 컴포넌트가 다른 요소나 컴포넌트들을 포함하여 레이아웃이나 스타일을 일괄적으로 적용해야 할 때 유용합니다.
```JavaScript
// Card 컴포넌트
function Card({ children }) {
  // Card 컴포넌트는 자식으로 받은 내용을 div로 감싸 스타일을 적용
  const cardStyle = {
    border: '1px solid gray',
    padding: '16px',
    margin: '8px'
  };

  return (
    <div style={cardStyle}>
      {children} {/* 부모에게서 받은 내용을 그대로 렌더링 */}
    </div>
  );
}

// 부모 컴포넌트
function App() {
  return (
    <Card>
      {/* 이 H1과 p 태그가 Card 컴포넌트의 children prop으로 전달됨 */}
      <h1>Card Title</h1>
      <p>This is the content inside the card.</p>
    </Card>
  );
}
```
---
### 핵심 규칙: `props`는 읽기 전용 (Read-Only)

자식 컴포넌트는 전달받은 `props`를 **절대 직접 수정해서는 안 됩니다.** `props`는 부모 컴포넌트가 소유하고 관리하는 데이터이므로, 자식은 항상 **'읽기 전용(Read-Only)'**으로 취급해야 합니다.

- **이유**: 이 원칙은 React의 **하향식(Top-down) 데이터 흐름**을 유지하여 애플리케이션의 동작을 예측 가능하게 만듭니다. 만약 자식 컴포넌트가 `props`를 변경할 수 있다면, 데이터의 출처를 추적하기 어려워져 애플리케이션의 복잡도가 증가하고 디버깅이 어려워지기 때문입니다.

### ## `props`: 컴포넌트 재사용성을 위한 데이터 전달 ⚙️

`props`(properties의 줄임말)는 **부모 컴포넌트가 자식 컴포넌트에게 전달하는 데이터**가 담긴 객체입니다. `props`의 핵심 목적은 **컴포넌트의 재사용성**을 극대화하는 것입니다.

`props`가 없다면, 우리는 내용만 약간 다른 '확인 버튼'과 '취소 버튼'을 위해 `<ConfirmButton>`, `<CancelButton>` 컴포넌트를 각각 따로 만들어야 합니다. 이는 엄청난 코드 중복을 유발합니다.

`props`를 사용하면, 하나의 `<Button>` 컴포넌트를 만들고, 부모가 어떤 데이터를 전달하느냐에 따라 다르게 보이도록 만들 수 있습니다.

JavaScript

```Java
// props를 사용해 하나의 컴포넌트를 재사용
<Button text="확인" color="blue" />
<Button text="취소" color="gray" />
```

### ### `props` 기본 사용법

`props`는 **부모가 전달 → 자식이 수신하여 사용**하는 간단한 흐름을 따릅니다.

#### **1단계: 부모 컴포넌트에서 데이터 전달**

부모 컴포넌트(`App`)에서 자식 컴포넌트(`UserProfile`)를 호출할 때, HTML의 속성(attribute)과 유사한 `key={value}` 형태로 데이터를 전달합니다.

#### **2단계: 자식 컴포넌트에서 데이터 수신 (비구조화 할당)**

자식 컴포넌트는 함수의 첫 번째 인자로 부모가 전달한 `props`를 객체 형태로 받습니다. 이때 **객체 비구조화 할당(Object Destructuring)**을 사용하여 필요한 값만 명시적으로 추출하는 방식이 권장됩니다.

#### **전체 예시 코드**

JavaScript

```Java
// 👩‍👦 Parent Component: App.js
import UserProfile from './UserProfile';

function App() {
  const userData = {
    name: '홍길동',
    age: 30,
  };

  return (
    <div>
      {/* 1. name과 age라는 이름으로 자식에게 데이터 전달 */}
      <UserProfile name={userData.name} age={userData.age} />
    </div>
  );
}

// 🧒 Child Component: UserProfile.js

// 2. 비구조화 할당으로 필요한 props만 직접 받기
function UserProfile({ name, age }) {
  // 3. 전달받은 props를 사용해 UI 렌더링
  return (
    <div>
      <h2>이름: {name}</h2>
      <p>나이: {age}세</p>
    </div>
  );
}
```

> **객체 비구조화 할당(Destructuring)이란?** ✨ `props` 객체 전체가 아닌, `{ name, age }`처럼 중괄호를 사용해 필요한 프로퍼티만 변수로 직접 추출하는 JavaScript 문법입니다. 코드가 간결해지고, 해당 컴포넌트가 어떤 `props`를 필요로 하는지 명확히 보여주는 장점이 있습니다.

## 잠만 딴거 정리

### ## 1단계: 최초 렌더링 (컴포넌트가 처음 화면에 나타날 때)

1. **`App` 함수 호출**: 리액트가 `App` 컴포넌트를 화면에 그리기 위해 함수를 처음으로 호출합니다.
2. **상태 초기화**: `const [count, setCount] = useState(0);`
    
    - `useState(0)`이 실행되어 `count`라는 이름의 상태 변수가 생성되고, 초기값 `0`이 할당됩니다.
    - **이 첫 번째 렌더링 과정 동안 `count`의 값은 항상 `0`입니다.**
        
3. **이벤트 핸들러 함수 정의**:
    
    - `handlePrimaryClick`과 `handleSecondaryClick`이라는 두 개의 함수가 메모리에 정의됩니다. **이때 함수가 실행되는 것이 아니라, 이런 기능을 가진 함수가 만들어지기만 합니다.**
        
4. **JSX 반환 및 렌더링**: `return (...)`
    
    - `return` 안의 JSX 코드가 평가됩니다.
    - `<p>카운트: {count}</p>`: `count`의 현재 값은 `0`이므로, 화면에는 **"카운트: 0"**이 표시됩니다.
    - 세 개의 `<Button>` 자식 컴포넌트가 렌더링됩니다.
    - 첫 번째 `Button`의 `onClick` **prop**으로는 `handlePrimaryClick` **함수 자체가 전달**됩니다. (함수가 실행되는 것이 아님)
    - 리액트는 이 JSX 구조를 바탕으로 실제 브라우저 화면(DOM)을 그립니다.

---

### ## 2단계: 이벤트 발생 ("카운트 올리기" 버튼 클릭)

1. **사용자 클릭**: 사용자가 "카운트 올리기" 버튼을 클릭합니다.
2. **이벤트 핸들러 실행**: 리액트는 이 버튼의 `onClick` prop으로 전달받았던 `handlePrimaryClick` 함수를 호출하여 실행합니다.

---

### ## 3단계: 상태 업데이트 및 재렌더링

1. **상태 변경 요청**: `handlePrimaryClick` 함수 내부의 `setCount(count + 1)` 코드가 실행됩니다.
    
    - 현재 `count` 값은 `0`이므로, `setCount(1)`이 호출됩니다.
    - 리액트는 이 요청을 받고, `App` 컴포넌트를 **재렌더링(re-render)하도록 예약**합니다.
        
2. **`App` 함수 재호출**: 리액트가 `App` 컴포넌트를 다시 렌더링하기 위해 함수를 두 번째로 호출합니다.
3. **상태값 업데이트**: `const [count, setCount] = useState(0);`
    
    - 이 줄이 다시 실행되지만, 리액트는 이미 `count`의 값이 `1`로 변경되어야 함을 알고 있습니다.
    - 따라서 이번 렌더링에서 `count` 변수는 `1`의 값을 가집니다.
        
4. **JSX 재계산 및 렌더링**:
    
    - `return` 안의 JSX 코드가 새로운 `count` 값(`1`)으로 다시 평가됩니다.
    - `<p>카운트: {count}</p>`: 화면에는 **"카운트: 1"**이 표시됩니다.
    - 리액트는 이전 화면과 바뀐 부분(`0` -> `1`)만 **효율적으로 찾아내어 실제 브라우저 화면을 업데이트**합니다.
