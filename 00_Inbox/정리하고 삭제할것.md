## 1. React란 무엇인가?

### 리액트 핵심 정의

리액트는 사용자 인터페이스(UI)를 만들기 위한 **자바스크립트 라이브러리**입니다. 특히 사용자와의 상호작용이 많은 현대적인 **싱글 페이지 애플리케이션(SPA)**을 효율적으로 개발하는 데 주된 목적이 있습니다.

### 라이브러리 vs. 프레임워크

리액트는 공식적으로 **라이브러리(Library)** 입니다. 가장 큰 차이는 **'코드의 제어권'**이 누구에게 있느냐입니다.

- **라이브러리 (React)**
    
    - **제어권**: 개발자
        
    - **설명**: 개발자가 필요할 때마다 라이브러리의 기능을 가져와 사용하는 방식입니다. 코드의 전체적인 흐름은 개발자가 직접 관리합니다.
        
- **프레임워크 (Spring Boot, Vue)**
    
    - **제어권**: 프레임워크
        
    - **설명**: 프레임워크가 정해놓은 규칙과 흐름 안에서 개발자가 코드를 작성하는 방식입니다. 프레임워크가 코드를 호출하고 실행합니다.
        

### SPA vs. MPA: 왜 리액트가 필요한가?

리액트의 필요성을 이해하려면, 웹 페이지를 구성하는 두 가지 방식을 알아야 합니다.

|구분|**MPA (Multi Page Application)**|**SPA (Single Page Application)**|
|---|---|---|
|**개념**|여러 개의 HTML 파일로 구성된 전통적인 방식|**단 하나의 HTML 파일**로 구성된 현대적인 방식|
|**동작**|페이지 이동 시, 서버에서 새 HTML을 받아와 **페이지 전체를 새로고침**|변경이 필요한 데이터만 서버에서 받아와, **화면의 특정 부분만 동적으로 업데이트**|
|**단점**|잦은 새로고침으로 인한 비효율 및 좋지 않은 사용자 경험|초기 로딩이 상대적으로 느릴 수 있고, 구조가 복잡해짐|

과거 **MPA** 방식의 단점을 보완하고 더 나은 사용자 경험을 제공하기 위해 **SPA**가 등장했습니다. 하지만 바닐라 자바스크립트만으로 복잡한 SPA를 만드는 것은 매우 어려웠고, **리액트는 바로 이 SPA를 더 쉽고 효율적으로 만들기 위해 등장했습니다.**

## 2. React의 4가지 핵심 특징

리액트는 아래 4가지 특징을 통해 복잡한 SPA를 효율적으로 만들고 관리합니다.

#### 1. 컴포넌트(Component) 기반 구조

- **개념**: 웹사이트의 UI를 **독립적인 부품(퍼즐 조각)으로** 나누어 개발하는 방식입니다.
    
- **장점**: 컴포넌트들을 조립하여 웹 페이지를 완성하므로 코드의 **재사용성**이 높아지고, 기능별 수정 및 관리가 매우 용이해집니다.
    

#### 2. 가상돔(Virtual DOM)과 성능 최적화

- **문제점**: 자바스크립트로 실제 DOM(웹페이지 구조)을 직접 조작하는 것은 매우 느린 작업입니다.
    
- **해결 방식**:
    
    1. 데이터 변경 시, 실제 DOM이 아닌 **가상 DOM**에 먼저 변경 사항을 적용합니다.
        
    2. 리액트는 이전 가상 DOM과 변경된 가상 DOM을 **비교(Diffing)**하여 바뀐 부분을 찾아냅니다.
        
    3. 마지막으로, 이 **바뀐 부분만 실제 DOM에 딱 한 번 적용**합니다.
        
- **핵심 목표**: 불필요한 DOM 수정을 최소화하여 **애플리케이션의 성능을 최적화**합니다.
    

#### 3. 선언형(Declarative) 프로그래밍

- **개념**: "어떻게" 처리할지 과정을 명령하는 것이 아니라, "어떤 모습이어야 하는지(결과)"를 코드로 **선언**하면 리액트가 그 과정을 알아서 처리하는 방식입니다.
    
- **장점**: 개발자는 데이터 상태에 따른 UI의 모습만 정의하면 되므로, 코드가 훨씬 간결하고 예측 가능해집니다.
    

#### 4. 단방향 데이터 바인딩 (One-way Data Binding)

- **개념**: 데이터는 항상 **부모 컴포넌트에서 자식 컴포넌트로만 (위에서 아래로)** 전달됩니다.
    
- **장점**: 데이터 흐름을 추적하기 쉬워 **예측 가능성**이 높고, 자식 컴포넌트가 부모 상태를 임의로 변경할 수 없어 코드의 **안정성**이 향상됩니다.

## 3. 개발 환경 설정 및 프로젝트 생성

#### 1단계: Node.js 설치

- **Node.js란?**: 자바스크립트를 브라우저 밖(PC, 서버 등)에서도 실행할 수 있게 해주는 **런타임 환경**입니다. Node.js를 설치하면 패키지 관리 도구인 **npm**이 함께 설치되어 리액트 등 수많은 라이브러리를 쉽게 관리할 수 있습니다.
    
- **설치 방법**:
    
    1. **[Node.js 공식 웹사이트](https://nodejs.org/)** 접속 후 **LTS 버전** 다운로드 및 설치.
        
    2. 터미널에서 `node -v`와 `npm -v` 명령어로 버전이 출력되는지 확인.
        

#### 2단계: React 프로젝트 생성

현재 리액트 공식 문서에서는 **Vite**를 사용한 프로젝트 생성을 권장합니다.

- **방법 1: Vite 사용 (공식 추천)**
    
    Bash
    
    ```
    # 'my-react-app' 이름으로 React 프로젝트 생성
    npm create vite@latest my-react-app -- --template react
    
    # 폴더 이동 및 의존성 설치
    cd my-react-app
    npm install
    
    # 개발 서버 실행
    npm run dev
    ```
    
- **방법 2: Create React App (CRA) 사용 (전통적)**
    
    Bash
    
    ```
    npx create-react-app my-react-app
    ```
    

#### 간단한 문제 해결 (Troubleshooting)

- **`npm` 명령어 오류**: Node.js 설치 오류 또는 터미널 재시작이 필요한 경우입니다. 터미널을 완전히 껐다가 다시 켜보세요.
    
- **의존성 충돌**: 프로젝트 폴더 내에서 `rm -rf node_modules` 명령어로 기존 라이브러리를 삭제한 후, `npm install`로 재설치합니다.

## 4. React 프로젝트의 기본 구조

Vite와 CRA는 동일한 React를 사용하지만, 프로젝트의 초기 구조와 설정 방식에 차이가 있습니다.

### Vite 프로젝트 구조 (최신)

- `index.html`: **프로젝트 최상위(루트)에 위치**하며, `<div id="root"></div>`를 포함합니다.
    
- `src/main.jsx`: **JavaScript 진입점**. `index.html`의 `#root`에 React 앱을 렌더링합니다.
    
- `src/App.jsx`: 최상위 루트 컴포넌트.
    
- `vite.config.js`: Vite 관련 설정 파일. 플러그인 추가, 빌드 옵션 등을 여기서 관리합니다.
    
- **특징**: CRA 대비 구조가 매우 단순하고, 개발 서버가 훨씬 빠릅니다.
    

### Create React App (CRA) 프로젝트 구조 (전통적)

- `public/index.html`: `public` 폴더 안에 위치하며, `<div id="root"></div>`를 포함합니다.
    
- `src/index.js`: **JavaScript 진입점**. `public/index.html`의 `#root`에 React 앱을 렌더링합니다.
    
- `src/App.js`: 최상위 루트 컴포넌트.
    
- `node_modules`: `npm install`로 설치된 라이브러리 저장소.
    
- `package.json`: 프로젝트 정보와 의존성 목록을 관리하는 파일.
    

#### CRA 렌더링 과정 상세

1. **HTML 파싱 및 DOM 생성**: 브라우저가 `public/index.html`을 읽어 DOM을 생성. (`#root`는 비어있음)
    
2. **JavaScript 실행**: `<script>` 태그를 만나 `src/index.js`를 시작점으로 하는 번들 파일을 실행.
    
3. **React 컴포넌트 렌더링**:
    
    - `index.js`가 `document.getElementById('root')`로 DOM 요소를 선택.
        
    - `ReactDOM.createRoot()`로 해당 요소를 React가 제어할 루트로 만듦.
        
    - `root.render(<App />)`를 호출하여 `<App>` 컴포넌트와 그 자식들을 실제 DOM에 그려넣음.

## 5. React 핵심 개발 규칙

React 개발에는 강제는 아니지만, 거의 모든 개발자가 따르는 중요한 규칙이 있습니다.

> **하나의 컴포넌트 파일(예: `App.js`)에는 반드시 하나의 컴포넌트 함수만 작성한다.**

이 규칙을 지키면 코드의 구조가 명확해지고, 특정 컴포넌트를 찾거나 수정하기가 매우 쉬워져 유지보수성이 크게 향상됩니다.

## 결론: React, 효율적인 연결을 위한 기술

지금까지의 과정을 통해 우리는 개발이란 기존 기술들을 바탕으로 **'어떻게 하면 데이터와 화면을 더 안정적이고 효율적으로 연결할까?'** 라는 고민을 해결해 나가는 과정임을 엿볼 수 있습니다.

React와 같은 라이브러리는 바로 그 고민에 대한 훌륭한 해답입니다. 복잡한 데이터의 변화를 예측 가능하게 화면에 반영하여, 개발자가 더 안정적으로 프로그램을 만들 수 있도록 돕는 고도로 설계된 '연결 기술'인 셈입니다.
