### React 컴포넌트 작성 규칙 (JSX 문법)

#### 1. 하나의 최상위 요소만 반환

컴포넌트가 `return` 하는 JSX는 반드시 **하나의 최상위 태그**로 감싸져 있어야 합니다.

- **잘못된 예시 (Error):**
    
    ```JavaScript
    return (
      <div>첫 번째</div>
      <div>두 번째</div> // 두 개의 태그를 반환할 수 없음
    );
    ```
    
- **올바른 예시:**
    
    ```JavaScript
    return (
      <div> {/* 하나의 div로 감싸기 */}
        <div>첫 번째</div>
        <div>두 번째</div>
      </div>
    );
    ```
    
- **팁**: 불필요한 `div`를 추가하고 싶지 않다면, **빈 태그인 Fragment (`<>...</>`)**를 사용할 수 있습니다.
    

---

#### 2. CSS 클래스는 `className`으로

JSX에서 CSS 클래스를 지정할 때는 `class`가 아닌 **`className`** 속성을 사용해야 합니다.

- **이유**: `class`는 JavaScript에서 클래스를 만드는 **예약어(reserved keyword)**이기 때문입니다. `className`은 일반 HTML의 `class` 속성과 동일한 역할을 합니다.
    ```JavaScript
    // App.js 파일
    <div className="App">안녕 리액트!</div>
    
    // App.css 파일
    .App {
      text-align: center;
    }
    ```
    

---

#### 3. JavaScript 코드는 중괄호`{}` 안에

JSX 내부에서 변수나 JavaScript 코드를 사용하고 싶을 때는, **중괄호 `{}`**로 감싸주어야 합니다.
- **주석 처리:** 주석 또한 JavaScript 코드이므로, 중괄호 안에 JavaScript의 블록 주석 형태`{/* 주석내용 */}`,`{// 주석내용}`로 작성합니다.

- **예시 (변수 사용):**
    ```JavaScript
	function Calculator() {
	  const a = 10;
	  const b = 20;
	
	  return (
	    <p>
	    {/* 표시한다 */}
	      {a} + {b} = {a + b}
	    </p>
	  );
	}
    ```
    

### ### React의 상태(State) 관리와 `useState`

#### 1. 상태(State)란 무엇인가?

React에서 **상태(State)는** 컴포넌트가 가지고 있는 **'바뀔 수 있는 데이터'입니다.** 예를 들어, 사용자가 입력하는 값, 로딩 상태, 서버에서 받아온 데이터 등이 모두 상태에 해당합니다.

React는 이 **상태가 변경되면, 화면을 자동으로 다시 그려서(리렌더링)** 변경 사항을 사용자에게 보여줍니다.

#### 2. `useState` 사용법
`useState`는 함수형 컴포넌트에서 이러한 **'상태'를 만들고 관리**할 수 있게 해주는 React의 기본 기능(Hook)입니다.

- **기본 문법:**
    ```JavaScript
    const [state, setState] = useState(initialValue);
    ```
    - `useState`를 호출하면 길이가 2인 배열이 반환되며, 이 배열을 **배열 디스트럭처링(Array Destructuring)** 문법으로 편리하게 `state`와 `setState` 변수에 할당하는 것입니다.
	    - **`useState(initialValue)`**: `useState`를 호출하면, React는 상태를 저장할 공간을 만들고 `initialValue`로 초기값을 설정합니다.
	    - **`state`**: 현재 상태 값을 담고 있는 변수입니다. (읽기 전용)
	    - **`setState`**: 상태 값을 변경(업데이트)할 때 사용하는 **전용 '함수'**입니다. 
        
#### 3. 코드 예시
```JavaScript
// const [변수명, 이 변수를 바꿀 함수] = useState(초기값);
const [name, setName] = useState('');
```
- **`useState('')`**: `name`이라는 상태를 만들고, 그 초기값을 빈 문자열(`''`)로 설정합니다.
- **`name`**: `name` 변수를 읽으면, 현재 상태 값(초기에는 `''`)을 조회할 수 있습니다(Read)
- **`setName`**: setName('새로운 값') 형식으로 `name`의 값을 변경하는 함수입니다.  이 함수를 사용해야만 React가 상태 변경을 감지하고 화면을 리렌더링합니다.
    

### ## React `useState`의 비동기 동작과 무한 렌더링

### 핵심 원칙: 상태 업데이트는 '예약'이다

`useState`의 상태 변경 함수(예: `setName`)는 **즉시 상태를 바꾸지 않습니다.** 대신, **"다음 렌더링 때 이 값으로 바꿔주세요"** 라고 리액트에게 **예약**하는 역할을 합니다.

따라서 현재 실행 중인 렌더링의 상태 값은 그 렌더링이 시작될 때의 값으로 **고정**되어 절대 변하지 않습니다.

---

### 무한 렌더링이 발생하는 과정

아래 코드는 컴포넌트가 렌더링될 때마다 상태 변경을 예약하여, 무한 재렌더링 루프에 빠집니다.


```JavaScript
function App() {
  const [name, setName] = useState('');
  setName('리액트'); // 렌더링 시 항상 호출됨
  return <div>{name}</div>;
}
```

1. **첫 번째 렌더링**
    
    - `name`의 값은 초기값인 `''`입니다.
        
    - `setName('리액트')`가 호출되어, 다음 렌더링을 `'리액트'` 값으로 예약합니다.
        
    - 화면에는 현재 값인 `''`이 그려집니다.
        
2. **두 번째 렌더링**
    
    - 예약된 대로 `name`의 값은 `'리액트'`가 됩니다.
        
    - 하지만 렌더링 과정에서 `setName('리액트')`가 **또다시 호출**되어, 다음 렌더링을 또 예약합니다.
        
    - 화면에는 현재 값인 `'리액트'`가 그려집니다.
        
3. **무한 반복**
    
    - 이 과정이 계속 반복되다가, 리액트는 무한 루프를 방지하기 위해 "Too many re-renders" 에러를 발생시킵니다.
        

> **[결론]** 상태 변경 함수는 컴포넌트 본문에서 직접 호출하는 것이 아니라, **이벤트 핸들러(`onClick` 등)나 `useEffect` 훅 내부**에서 호출해야 합니다.

### React의 상태(State) 관리와 `useState`

#### 1. 상태(State)란 무엇인가?

React에서 **상태(State)**는 컴포넌트가 가지는 **'바뀔 수 있는 데이터'**입니다. React는 이 상태가 변경되면, 화면을 자동으로 다시 그려서(리렌더링) 변경 사항을 사용자에게 보여줍니다.

#### 2. `useState` 사용법

`useState`는 함수형 컴포넌트에서 **'상태'를 만들고 관리**하게 해주는 React의 기본 기능(Hook)입니다.

- **기본 문법:**
    ```JavaScript
    const [state, setState] = useState(initialValue);
    ```
    `useState`를 호출하면 `[현재값, 값을_변경하는_함수]` 형태의 배열이 반환되며, 이를 **배열 디스트럭처링**으로 `state`와 `setState` 변수에 할당합니다.
    - **`state`**: 현재 상태 값을 담고 있는 변수입니다. (읽기 전용)
    - **`setState`**: 상태 값을 변경(업데이트)할 때 사용하는 **전용 함수**입니다.

### `useState`의 동작 원리: 비동기 업데이트

#### 핵심 원칙: 상태 업데이트는 '예약'이다

`useState`의 상태 변경 함수(예: `setName`)는 **즉시 상태를 바꾸지 않습니다.** 대신, **"다음 렌더링 때 이 값으로 바꿔주세요"** 라고 리액트에게 **예약**하는 역할을 합니다.

#### 잘못된 사용법: 무한 렌더링

이러한 '예약' 시스템 때문에, 컴포넌트 본문에서 `setName`과 같은 함수를 직접 호출하면 무한 렌더링 루프에 빠집니다.

JavaScript

```
function App() {
  const [name, setName] = useState('');
  setName('리액트'); // 렌더링될 때마다 상태 변경을 '예약'함
  return <div>{name}</div>;
}
```

- **무한 렌더링 과정**
    
    1. **첫 렌더링**: `setName('리액트')`이 호출되어, 다음 렌더링을 예약합니다.
        
    2. **두 번째 렌더링**: 예약된 대로 `name`이 '리액트'가 되지만, 렌더링 과정에서 `setName('리액트')`이 **또다시 호출**되어 다음 렌더링을 또 예약합니다.
        
    3. **무한 반복**: 이 과정이 계속 반복되다가, 리액트는 "Too many re-renders" 에러를 발생시킵니다.
        

> **[결론]** 상태 변경 함수는 컴포넌트 본문에서 직접 호출하는 것이 아니라, **이벤트 핸들러(`onClick` 등)나 `useEffect` 훅 내부**와 같이 특정 조건 하에서만 호출해야 합니다.
