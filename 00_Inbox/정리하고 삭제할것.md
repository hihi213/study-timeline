### React 컴포넌트 작성 규칙 (JSX 문법)

#### 1. 하나의 최상위 요소만 반환
컴포넌트가 `return` 하는 JSX는 반드시 **하나의 최상위 태그**로 감싸져 있어야 합니다.
- **잘못된 예시 (Error):**
    ```JavaScript
    return (
      <div>첫 번째</div>
      <div>두 번째</div> // 두 개의 태그를 반환할 수 없음
    );
    ```
- **올바른 예시:**
    ```JavaScript
    return (
      <div> {/* 하나의 div로 감싸기 */}
        <div>첫 번째</div>
        <div>두 번째</div>
      </div>
    );
    ```
- **팁**: 불필요한 `div`를 추가하고 싶지 않다면, **빈 태그인 Fragment (`<>...</>`)**를 사용할 수 있습니다.
---
#### 2. CSS 클래스는 `className`으로
JSX에서 CSS 클래스를 지정할 때는 `class`가 아닌 **`className`** 속성을 사용해야 합니다.
- **이유**: `class`는 JavaScript에서 클래스를 만드는 **예약어(reserved keyword)**이기 때문입니다. `className`은 일반 HTML의 `class` 속성과 동일한 역할을 합니다.
    ```JavaScript
    // App.js 파일
    <div className="App">안녕 리액트!</div>
    
    // App.css 파일
    .App {
      text-align: center;
    }
    ```
---

#### 3. JavaScript 코드는 중괄호`{}` 안에
JSX 내부에서 변수나 JavaScript 코드를 사용하고 싶을 때는, **중괄호 `{}`**로 감싸주어야 합니다.
- **주석 처리:** 주석 또한 JavaScript 코드이므로, 중괄호 안에 JavaScript의 블록 주석 형태`{/* 주석내용 */}`으로 작성합니다.
- **예시 (변수 사용):**
    ```JavaScript
	function Calculator() {
	  const a = 10;
	  const b = 20;
	
	  return (
	    <p>
	    {/* 표시한다 */}
	      {a} + {b} = {a + b}
	    </p>
	  );
	}
    ```

### React의 상태(State) 관리와 `useState`

#### 1. 상태(State)란 무엇인가?
React에서 **상태(State)**는 컴포넌트가 가지는 **'바뀔 수 있는 데이터'**입니다. React는 이 상태가 변경되면, 화면을 자동으로 다시 그려서(리렌더링) 변경 사항을 사용자에게 보여줍니다.

#### 2. `useState` 사용법
`useState`는 함수형 컴포넌트에서 **'상태'를 만들고 관리**하게 해주는 React의 기본 기능(Hook)입니다.
- **기본 문법:**
    ```JavaScript
    const [state, setState] = useState(initialValue);
    ```
- ##### **호출 순서에 따른 과정**
	1. **`useState(initialValue)` 실행**: 컴포넌트가 렌더링될 때 `useState` 함수가 먼저 호출됩니다. React는 이 함수를 통해 상태를 저장할 공간을 만들고, 인자로 받은 `initialValue`를 그 공간의 **초기값**으로 설정합니다.
    
	2. **배열 반환**: `useState`는 `[ 현재값, 상태변경함수 ]` 형태의 배열을 반환합니다.
	    - **최초 렌더링 시**: `[ initialValue, 상태변경함수 ]`
	    - **이후 렌더링 시**: `[ 현재_상태값, 상태변경함수 ]`
        
	3. **배열 디스트럭처링**: 반환된 배열의 요소들이 `state`와 `setState` 변수에 순서대로 할당됩니다.
	    - `state` 변수에는 **현재 렌더링 시점의 상태 값**이 담깁니다. (읽기 전용)
	    - `setState` 변수에는 **상태를 변경(업데이트)하는 함수**가 담깁니다.
---

### `useState`의 동작 원리: 비동기 업데이트

#### 핵심 원칙: 상태 업데이트는 '예약'이다
 현재 실행 중인 렌더링의 상태 값은 그 렌더링이 시작될 때의 값으로 **고정**되어 절대 변하지 않습니다. `useState`의 상태 변경 함수(예: `setName`)는 **즉시 상태를 바꾸는 대신, "다음 렌더링 때 이 값으로 바꿔주세요"** 라고 리액트에게 **예약**하는 역할을 합니다.
 
브라우저에서 DOM(Document Object Model)을 변경하는 작업은 상대적으로 많은 연산이 필요한, 비용이 비싼 작업입니다.
`setState`가 즉시, 동기적으로 상태를 변경한다면, 하나의 함수가 실행되는 도중에 상태 값이 계속해서 바뀌게 됩니다. 이는 코드의 동작을 예측하기 어렵게 만들고, 데이터의 일관성을 해쳐 버그를 유발합니다.
리액트는 이벤트 핸들러 내에서 발생한 여러 상태 변경 요청을 하나의 배열이나 리스트에 모아둡니다. 그리고 해당 함수 실행이 모두 끝난 뒤, 모아둔 변경 사항을 종합하여 **단 한 번의 리렌더링**만 수행합니다
#### 잘못된 사용법: 무한 렌더링
이러한 '예약' 시스템 때문에, 컴포넌트 본문에서 `setName`과 같은 함수를 직접 호출하면 컴포넌트가 렌더링될 때마다 상태 변경을 예약하여, 무한 렌더링 루프에 빠집니다.

```JavaScript
function App() {
  const [name, setName] = useState('');
  setName('리액트'); // 렌더링될 때마다 상태 변경을 '예약'함
  return <div>{name}</div>;
}
```
- **무한 렌더링 과정**
    1. **첫 렌더링**: `setName('리액트')`이 호출되어, 다음 렌더링을 예약합니다.
    2. **두 번째 렌더링**: 예약된 대로 `name`이 '리액트'가 되지만, 렌더링 과정에서 `setName('리액트')`이 **또다시 호출**되어 다음 렌더링을 또 예약합니다.
    3. **무한 반복**: 이 과정이 계속 반복되다가, 리액트는 "Too many re-renders" 에러를 발생시킵니다.
> 	**[결론]** 상태 변경 함수는 컴포넌트 본문에서 직접 호출하는 것이 아니라, **이벤트 핸들러(`onClick` 등)나 `useEffect` 훅 내부**와 같이 특정 조건 하에서만 호출해야 합니다.
### React 이벤트: `onClick`, `onChange`로 사용자 반응 처리
앞서 `useState`의 상태 변경 함수는 **이벤트 핸들러** 안에서 호출해야 한다고 배웠습니다. 이벤트 핸들러는 사용자의 클릭이나 입력 같은 특정 행동에 반응하여 코드를 실행하는 함수입니다.

#### 1. `onChange`: 입력 값 변경 감지
`onChange`는 `<input>`, `<textarea>` 등 입력 요소의 **값이 변경될 때마다** 발생하는 이벤트입니다. (eventlistener로 사용시이름은 'change'임)
- **핵심**: 사용자의 입력을 실시간으로 상태(State)에 반영할 때 사용됩니다.
- **코드 예시:** 먼저 `name`을 저장할 상태와, 그 상태를 변경할 함수(`handleInputChange`)를 준비합니다.
    ```JavaScript
    const [name, setName] = useState(''); // 이름을 입력할 수 있는 상태
    const handleInputChange = (e) => {
      // e.target.value는 사용자가 입력한 최신 텍스트 값입니다.
      setName(e.target.value);
    };
    ```
- **JSX 적용:** `<input>` 태그의 `onChange` 속성에 위에서 만든 함수를 연결합니다.
    ```JavaScript
    <input type="text" value={name} onChange={handleInputChange} />
    ```
    이제 사용자가 입력창에 글자를 입력할 때마다 `handleInputChange`가 실행되어 `name` 상태가 실시간으로 업데이트됩니다.
---
#### 2. `onClick`: 클릭 이벤트 감지
`onClick`은 `<button>`, `<div>` 등 특정 요소를 사용자가 **마우스로 클릭**했을 때 발생하는 이벤트입니다.
- **핵심**: 특정 행동을 실행하는 버튼을 만들 때 주로 사용됩니다.
- **코드 예시:** 최종 인사말을 저장할 `greeting` 상태와, 그 상태를 변경할 `handleGreetClick` 함수를 준비합니다.
    ```JavaScript
    const [name, setName] = useState(''); // 이름을 입력받는 상태
    const [greeting, setGreeting] = useState(''); // 인사 메시지를 저장하는 상태
    // 버튼 클릭 시, greeting이라는 상태에 인사말을 만들어서 저장합니다.
    const handleGreetClick = () => {
      setGreeting(`${name}님, 리액트 세계에 오신 걸 환영합니다!`);
    };
    ```
- **JSX 적용:** `<button>` 태그의 `onClick` 속성에 위에서 만든 함수를 연결합니다. 
    ```JavaScript
    <button onClick={handleGreetClick}>인사하기</button>
    ```
    이 버튼을 클릭하면 `handleGreetClick`이 실행되고, 현재 `name` 상태 값을 이용해 `greeting` 상태를 업데이트하여 화면에 환영 메시지를 표시합니다.
