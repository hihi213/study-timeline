## 정리 기술적정리
### **제목: Create React App(CRA)의 동작 원리 분석**

#### **서문: CRA 프로젝트의 실행과 렌더링 과정** 

`npm start` 명령어로 CRA 프로젝트를 실행하면 브라우저에 React 애플리케이션이 표시됩니다. 이 과정은 **`public/index.html`**, **`src/index.js`**, **`src/App.js`** 세 파일이 어떻게 협력하는지 이해하는 것을 중심으로 이루어집니다. 이 세 파일의 관계를 이해하면 React의 동작 방식이 명확하게 보이기 시작할 것입니다.

-  **컴포넌트**: 웹 페이지의 UI를 구성하는 **독립적이고 재사용 가능한 부품**

### **1부: React 앱의 핵심 파일 및 폴더 구조**

React 애플리케이션의 동작을 이해하기 위해서는 먼저 프로젝트를 구성하는 핵심 디렉터리와 파일의 용도를 알아야 합니다.  React 앱은 크게 세 가지 핵심 영역으로 나뉘어 각자의 역할을 수행합니다.

#### **1-1. `public` 폴더와 진입점 `index.html`**
 
 `public` 폴더
- 이미지, 폰트 등 **별도의 처리 없이 원본 그대로** 사용될 정적 파일(static assets)을 저장한다.
- 이 폴더의 파일들은 웹 서버에 배포 시, `https://내웹사이트.com/파일이름`처럼 직접 URL로 접근할 수 있습니다.

**`index.html`**
- **역할**: React 애플리케이션의 유일한 HTML 문서이자 브라우저가 최초로 불러오는 진입점(Entry Point)이다.
- 이 파일의 가장 핵심적인 역할은 내부에 포함된 아래의 `div` 요소 하나를 제공하는 것입니다.
    ```HTML
    <div id="root"></div>
    ```
	- 위 `div` 요소가 바로  루트 DOM 노드(Root DOM Node) ,React가 제어할 DOM의 최상위 요소가 됨니다
	

#### **1-2. `src` 폴더와 애플리케이션 소스 코드**

`src`(Source) 폴더는 **애플리케이션의 핵심 소스 코드**가 위치하는 공간입니다. 개발자는 컴포넌트, 스타일, 로직 등 대부분의 파일을 이곳에서 작성합니다.
	JavaScript, CSS, 컴포넌트 등 애플리케이션의 모든 로직과 UI를 구성하는 파일들이 이곳에 담깁니다.

- **`App.js`**: 최상위 컴포넌트
	- 애플리케이션 UI의 가장 큰 틀을 구성하는 **루트 컴포넌트(Root Component)** 입니다
    - 모든 하위 컴포넌트들은 이 `App` 컴포넌트 내부에 조립되어 하나의 완성된 UI를 형성합니다다.
    
- **`index.js`**:  애플리케이션의 진입점
	- JavaScript 코드의 실행이 시작되는 **시작점(Entry Point)** 으로, 텅 빈 HTML 뼈대에 동적인 React 컴포넌트들을 조립하는 **연결고리** 역할을 합니다
	- `public/index.html`의 `<div id="root">`를 찾아, 그 안에 `<App />` 컴포넌트를 그려 넣으라고(렌더링) 명령합니다.
	- 이 파일의 코드는 크게 두 부분으로 나뉩니다.
		1. 상단부분 **`import`**: `React`, `ReactDOM`, `<App />` 등 필요한 기능들을 불러옵니다.
		2. 본문부분 **렌더링**: 불러온 `ReactDOM`을 사용하여 `<App />` 컴포넌트를 실제 웹 페이지에 그립니다.
		- 코드예시
			```JavaScript
			// 1. 필요한 라이브러리 불러오기
			import React from 'react';
			import ReactDOM from 'react-dom/client'; // React를 DOM에 연결하는 도구
			import App from './App'; // 우리가 만든 최상위 컴포넌트
			
			// 2. HTML 요소 선택
			// public/index.html 파일에 있는 <div id="root"></div>를 찾습니다.
			const rootElement = document.getElementById('root');
			
			// 3. React Root 생성
			// 찾은 HTML 요소를 React가 제어할 수 있는 공간(Root)으로 만듭니다.
			const root = ReactDOM.createRoot(rootElement);
			
			// 4. 컴포넌트 렌더링
			// 생성된 React Root에 최상위 컴포넌트인 <App />을 그려 넣습니다.
			root.render(
			  <React.StrictMode>
			    <App />
			  </React.StrictMode>
			);
			```
#### **1-3. `node_modules` 폴더와 `package.json`**

- `package.json` (주문서역할) 
	- 프로젝트의 이름, 버전 같은 기본 정보(메타정보)와, 실행에 필요한 **모든 라이브러리(의존성) 목록**을 기록하는 설정 파일입니다.
- `node_modules` 폴더
	- `package.json`대로, `npm install` 명령어를 통해 **실제 라이브러리 파일들이 설치되는 폴더**입니다.
- **특징**: `node_modules`는 용량이 매우 크기 때문에 Git으로 관리하지 않고(`.gitignore`에 추가), `package.json` 파일만 공유합니다.
	- 코드를 받은 다른 개발자는 `npm install` 명령어 하나로 `package.json`을 참조하여 `node_modules`를 똑같이 복원할 수 있습니다.

### **2부: React 렌더링 과정**

1부에서 각 파일의 역할을 확인했습니다. 이제 이 파일들이 어떻게 상호작용하여 화면을 렌더링(HTML과 React의 연결)하는지 그 과정을 단계별로 살펴보겠습니다.

#### **2-1. 브라우저의 `index.html` 로드와 DOM 생성**

모든 것은 사용자가 브라우저를 통해 우리 웹사이트에 접속하는 순간 시작됩니다.

1. **HTML 파일 요청 및 수신**:  
	브라우저는 서버에 웹페이지를 요청하고, 가장 먼저 **`public/index.html`** 파일을 내려받습니다.
    
2. **DOM(문서 객체 모델) 생성**: 브라우저의 렌더링 엔진은 수신한 HTML 문서를 파싱(parsing)하여, 메모리에 문서의 구조를 메모리에 객체 모델로 표현한 **DOM**을 생성합니다.
	-  파싱: 브라우저가 HTML 텍스트 파일을 한 줄씩 읽어 내려가며, 메모리 안에 자바스크립트가 이해하고 조작할 수 있는 객체 구조, 즉 **DOM**을 만드는 과정
	- 이 단계에서 `<div id="root"></div>`를 포함한 DOM 구조가 생성되지만, 내부는 비어있어 화면에는 아무것도 표시되지 않습니다.

#### **2-2. JavaScript 진입점 `index.js` 실행**

3. 브라우저가 `index.html`을 파싱하다가 `<script>` 태그를 만나면, 웹팩(Webpack) 같은 번들러에 의해 `src` 폴더의 모든 자바스크립트 파일이 하나로 합쳐진 **번들(bundle) 파일**을 로드하여 실행합니다. 이 번들 파일의 시작점이 바로 **`src/index.js`** 입니다
```JavaScript
// 1. 필요한 라이브러리 로드
import React from 'react';//JSX 문법을 해석하는 등 React의 핵심 기능
import ReactDOM from 'react-dom/client';// React 컴포넌트를 브라우저의 실제 DOM에 연결(렌더링)
import App from './App'; // 우리가 만든 애플리케이션의 최상위 컴포넌트
```

#### **2-3. `ReactDOM`을 이용한 컴포넌트 렌더링**

4. DOM이 생성된 후, `index.js` 파일은  `import` 구문을 통해 렌더링에 필요한 핵심 도구들을 불러오고 `ReactDOM` 라이브러리를 사용하여, React 컴포넌트를 실제 브라우저 DOM에 연결(렌더링)하는 역할을 합니다.

- **1단계: DOM 요소 선택**  `document.getElementById('root')` 메서드를 사용하여 렌더링의 기준점이 될 `index.html`의 `<div id="root"></div>` 요소를 선택한다.
    ```JavaScript
    const rootElement = document.getElementById('root');
    ```
- **2단계: React Root 생성** 
	선택한 DOM 요소를 `ReactDOM.createRoot()`에 전달하여, React가 컴포넌트를 관리하고 렌더링할 **전용 공간(React Root)** 을 생성합니다. 
	이 `createRoot()` 함수가 반환하는 `root` 객체에는 컴포넌트를 화면에 그리는 `render()` 메서드가 포함되어 있습니다.
    ```JavaScript
    // 찾은 HTML 요소를 React가 제어할 수 있는 공간(Root)으로 만듭니다.
    const root = ReactDOM.createRoot(rootElement);
    ```
-  **3단계: 컴포넌트 렌더링 (`root.render()`)**
	마지막으로, 생성된 `root` 객체의 `.render()` 메서드를 호출하고 최상위 컴포넌트인 `<App />`을 인자로 전달합니다. 
	이 명령을 통해 React는 `<App />`과 그 모든 자식 컴포넌트들을 실제 DOM에 그려 넣어 화면에 UI를 표시합니다.
    ```JavaScript
    root.render(
      <React.StrictMode>
        <App />
      </React.StrictMode>
    );
    ```

### **3부: 핵심 문법과 도구**
JavaScript 파일(`App.js`) 안에서 HTML과 비슷한 코드를 자유롭게 작성할 수 있는 이유는 다음과 같은 핵심 문법과 도구 덕분입니다.

#### **3-1. JSX: JavaScript를 위한 구문 확장**

JSX는 JavaScript 파일 내에서 UI 구조를 시각적으로 표현하기 위해 HTML과 유사한 마크업을 사용할 수 있게 하는 특별한 문법입니다.

```JavaScript
function App() {// in App.js
  return (
    <div className="App">Hello, React!</div>
  );
}
```

- **주요 기능**:
    1. JavaScript 함수 안에서 HTML과 비슷한 코드를 `return` 할 수 있게 합니다.
    2. `App.js`와 같은 컴포넌트 파일을 `<App />` 형태의 태그로 사용할 수 있게 합니다.
- **특징**: JSX는 코드의 가독성을 높이고 UI 구조를 직관적으로 파악하게 해주지만, 브라우저가 직접 실행할 수는 없습니다. 실행 전에 반드시 '바벨'을 통해 순수 JavaScript로 변환되어야 합니다.
#### **3-2. 바벨(Babel): JavaScript 컴파일러**

웹 브라우저는 JSX나 최신 JavaScript 문법(ES6+)을 직접 해석하지 못할 수 있습니다. **바벨(Babel)은** 이러한 코드를 구형 브라우저에서도 호환되는 표준 JavaScript 코드로 변환(컴파일)해주는 도구입니다.

- **역할**:
    1. **JSX 변환**: `<div />`와 같은 JSX 코드를 브라우저가 이해할 수 있는 `React.createElement()` 함수 호출로 변환합니다
	2. **버전 호환성**: 화살표 함수, `const/let` 등 최신 JavaScript 문법을 구형 브라우저에서도 동작하는 이전 버전(ES5) 코드로 변환하여 호환성을 확보합니
- **동작 방식**: Create React App이나 Vite 같은 개발 환경에서는 코드를 저장하거나 실행할 때마다 바벨이 자동으로 동작합니다. 개발자는 별도의 설정 없이 편리하게 최신 문법을 사용할 수 있습니다.

## 💭 정리할 정보들

#### 1. 컴포넌트(Component): 리액트의 기본 단위

리액트에서 **컴포넌트**는 웹 페이지의 UI를 구성하는 **독립적이고 재사용 가능한 부품**입니다. `App.js` 파일이 바로 `<App />`이라는 이름의 최상위 컴포넌트이며, 모든 컴포넌트는 이 아래에 조립됩니다.

- **역할**: 화면에 보여질 특정 부분의 모양과 동작을 JavaScript 함수 또는 클래스로 정의합니다.
    

웹브라우저가 `index.html`이라는 설계도 파일을 읽어들이면, 메모리 안에 **DOM(문서 객체 모델)** 이라는 살아있는 구조물을 만듭니다. DOM은 자바스크립트와 같은 프로그래밍 언어가 문서의 콘텐츠와 구조, 스타일을 조작할 수 있도록 하는 인터페이스(API)입니다. 이 DOM 덕분에 우리는 자바스크립트를 이용해 HTML 문서의 요소를 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)하는 등 동적인 제어가 가능해집니다.

이제 우리의 목표는 이 DOM과 React 애플리케이션의 심장부인 `index.js` 파일을 'React 방식'으로 연결하는 것입니다.

이 중요한 연결 작업을 위해, 우리는 `node_modules` 폴더에 있는 `react-dom` 라이브러리의 힘을 빌립니다. 최신 React(버전 18 이상)에서는 `react-dom/client`가 제공하는 `createRoot`라는 함수를 사용합니다. 이 함수가 바로 `index.js` 안의 React 컴포넌트들을 `index.html`의 특정 지점(예: `<div id="root"></div>`)에 아주 효과적으로 연결해주는 접착제 역할을 합니다.

이러한 과정을 통해 우리는 프로그래밍 개발의 본질을 엿볼 수 있습니다. 개발이란 아무것도 없는 상태에서 무언가를 창조하는 것이 아니라, HTML, DOM, JavaScript 같은 기존 기술들을 바탕으로 **'어떻게 하면 데이터와 화면(파일)을 더 안정적이고 효율적으로 연결할까?'** 라는 고민을 해결해 나가는 과정입니다.

**React 같은 라이브러리는 바로 그 고민에 대한 인간의 해답입니다.** 복잡한 데이터의 변화를 예측 가능하게 화면에 반영하여, 개발자가 더 안정적으로 프로그램을 만들 수 있도록 돕는 고도로 설계된 '연결 기술'인 셈입니다.

`index.js` 파일에서 React 애플리케이션을 구동시키려면 먼저 필요한 두 가지 핵심 라이브러리를 불러와야 합니다.

1. `import React from 'react';` : 컴포넌트를 정의하고 JSX(JavaScript XML) 문법을 처리하는 등 React의 핵심 기능을 제공합니다.
    
2. `import ReactDOM from 'react-dom/client';` : React 컴포넌트를 실제 DOM에 연결하고 렌더링하기 위해 필요합니다.
    

이제 이 라이브러리들을 사용해 React 앱과 브라우저를 연결해 보겠습니다.

먼저, `ReactDOM` 라이브러리에 내장된 `createRoot()` 함수를 사용해 '연결 고리'를 만듭니다. 이 함수의 인자(데이터)로 `document.getElementById('root')` 코드를 넣어주는데, 이는 "HTML 문서에서 id가 'root'인 요소를 찾아라"라는 뜻입니다.

`const root = ReactDOM.createRoot(document.getElementById('root'));`

위 코드가 실행되면, `root`라는 상수 변수에는 **React가 제어할 DOM의 최상위 루트(root)에 대한 정보와 제어 기능이 담긴 객체**가 저장됩니다.

이제 `root` 변수는 특별한 능력을 갖게 되었습니다. 바로 `render()`라는 함수를 사용할 수 있는 능력입니다. 왜 갑자기 `render()` 함수를 쓸 수 있을까요? 이것은 React를 만든 개발자들이 우리와 한 **'약속'**입니다. `createRoot()`를 사용하면 `render()` 함수가 포함된 객체를 주기로 규칙을 정해놓았기 때문입니다.

우리는 이 `render()` 함수 안에 우리가 만든 React 컴포넌트를 넣어주면, 비로소 화면에 앱이 그려지게 됩니다.

### 1. `export default App;`

이 코드는 `App.js` 파일에서 만든 `App` 컴포넌트(함수)를 **다른 파일에서 `import`하여 사용할 수 있도록 외부로 내보내는** 역할을 합니다.

- **`export` (내보내기)**: `App` 컴포넌트를 "공개" 상태로 만듭니다.
    
- **`default`**: 이 파일에서는 `App` 컴포넌트가 **대표**라는 의미입니다.
    

이 `export` 구문이 있기 때문에, `index.js` 파일에서 `import App from './App';` 코드로 `<App />` 컴포넌트를 불러와 사용할 수 있는 것입니다.

---

### 2. React 개발 규칙: "하나의 파일, 하나의 컴포넌트"

React 개발에는 강제는 아니지만, 거의 모든 개발자가 따르는 중요한 규칙이 있습니다.

> **하나의 컴포넌트 파일(예: `App.js`)에는 반드시 하나의 컴포넌트 함수만 작성한다.**

이 규칙을 지키면 코드의 구조가 명확해지고, 특정 컴포넌트를 찾거나 수정하기가 매우 쉬워져 유지보수성이 크게 향상됩니다.

---

### 3. `package.json`과 `package-lock.json`

- **`package.json`**
    
    - 프로젝트의 이름, 버전 같은 **기본 정보**와 `react`, `react-dom` 등 실행에 필요한 **라이브러리 목록(의존성)**을 기록하는 **설정 파일**입니다.
        
    - 개발자가 직접 확인하고 수정할 수 있습니다.
        
- **`package-lock.json`**
    
    - `package.json`을 바탕으로, 실제로 설치된 라이브러리들의 **정확한 버전과 그 하위 의존성까지 모두 기록**하는 파일입니다.
        
    - **역할**: 다른 개발자가 `npm install`을 실행했을 때, 버전에 따른 충돌 없이 **모두가 동일한 환경의 라이브러리를 설치하도록 보장**하는 역할을 합니다.
        
    - **주의**: 이 파일은 개발자가 직접 수정해서는 안 되며, npm이 자동으로 관리합니다.

- **브라우저의 `index.html` 로드와 DOM 생성** 브라우저는 서버에서 **`public/index.html`** 파일을 내려받아 파싱(해석)하고, 메모리에 **DOM(문서 객체 모델)**을 생성합니다. 이 단계에서 `<div id="root">`가 포함된 DOM 구조가 만들어지지만, 내부는 아직 비어있습니다.
    
- **JavaScript 진입점 `index.js` 실행** 브라우저가 `index.html`을 파싱하다 `<script>` 태그를 만나면, 번들링된 JavaScript 파일을 실행합니다. 이 파일의 시작점이 바로 **`src/index.js`**입니다.
    
- **`ReactDOM`을 이용한 컴포넌트 렌더링** `index.js` 코드가 실행되면서 `ReactDOM` 라이브러리가 동작합니다.
    
    - **1단계: DOM 요소 선택**: `document.getElementById('root')`로 React 앱을 그릴 기준점을 찾습니다.
        
    - **2단계: React Root 생성**: `ReactDOM.createRoot()`로 선택된 요소를 React가 제어할 수 있는 전용 공간으로 만듭니다.
        
    - **3단계: 컴포넌트 렌더링**: 생성된 `root` 객체의 `.render()` 메서드에 최상위 컴포넌트인 `<App />`을 전달하여, 실제 DOM에 그려 넣어 화면을 완성합니다.
