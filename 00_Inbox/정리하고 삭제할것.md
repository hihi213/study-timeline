## 정리 기술적정리
### **제목: Create React App(CRA)의 동작 원리 분석**

#### **서문: CRA 프로젝트의 실행과 렌더링 과정**

`npm start` 명령어로 CRA(Create React App) 프로젝트를 실행하면 브라우저에 React 애플리케이션이 표시된다.  즉 브라우저에 "Edit `src/App.js` and save to reload."라는 문구가 적힌 페이지가 나타납니다. 이 과정은 여러 파일과 도구들이 정해진 순서에 따라 상호작용하며 이루어집니다.

이 글의 목적은 CRA 프로젝트의 기본 파일 구조를 이해하고, 브라우저가 HTML 파일을 로드하는 시점부터 React 컴포넌트가 화면에 렌더링되기까지의 기술적인 동작 원리를 설명하는 것이다. 이 과정의 이해는 **`public/index.html`**, **`src/index.js`**, **`src/App.js`** 세 파일의 역할을 중심으로 이루어진다.
이 세 파일이 어떻게 협력하는지 이해하는 순간, React의 동작 방식이 명확하게 보이기 시작할 것이다

---

### **1부: React 앱의 핵심 파일 및 폴더 구조**

React 애플리케이션의 동작을 이해하기 위해서는 먼저 프로젝트를 구성하는 핵심 디렉터리와 파일의 용도를 알아야 합니다.  React 앱은 크게 세 가지 핵심 영역으로 나뉘어 각자의 역할을 수행합니다.

#### **1-1. `public` 폴더와 진입점 `index.html`**

 
 `public` 폴더
- 이미지, 폰트 등 **별도의 처리 없이 원본 그대로** 사용될 정적 파일(static assets)을 저장한다.
- 이 폴더의 파일들은 웹 서버에 배포 시, `https://내웹사이트.com/파일이름`처럼 직접 URL로 접근할 수 있습니다.

**`index.html`**
- **역할**: React 애플리케이션의 유일한 HTML 문서이자 브라우저가 최초로 불러오는 진입점(Entry Point)이다.
- 이 파일의 가장 핵심적인 역할은 내부에 포함된 아래의 `div` 요소 하나를 제공하는 것입니다.
- **핵심**: `index.html` 파일의 `<body>` 내부에는 아래와 같은 `div` 요소가 포함되어 있습니다.
    
    ```HTML
    <div id="root"></div>
    ```
	- 위 `div` 요소가 바로  루트 DOM 노드(Root DOM Node) ,React가 제어할 DOM의 최상위 요소가 된다
	- JavaScript(`index.js`)가 `document.getElementById('root')`를 통해 이 요소를 찾아, 그 안에 모든 컴포넌트를 렌더링하여 우리가 보는 동적인 웹 화면을 완성합니다

#### **1-2. `src` 폴더와 애플리케이션 소스 코드**

`src`(Source) 폴더는 **애플리케이션의 핵심 소스 코드**가 위치하는 공간입니다. 개발자는 컴포넌트, 스타일, 로직 등 대부분의 파일을 이곳에서 작성합니다.
	JavaScript, CSS, 컴포넌트 등 애플리케이션의 모든 로직과 UI를 구성하는 파일들이 이곳에 담깁니다.

- **`App.js`**: 최상위 컴포넌트
	- 애플리케이션 UI의 가장 큰 틀을 구성하는 **루트 컴포넌트(Root Component)** 입니다
    - 모든 하위 컴포넌트들은 이 `App` 컴포넌트 내부에 중첩되는 트리 구조를 형성한다.
    - `App.js`는 전체 UI를 구성하는 가장 큰 부품(컨포넌트)이며, 이 안에 작은 컴포넌트들을 조립하여 전체 UI를 완성합니다.
    
- **`index.js`**: 애플리케이션의 JavaScript 실행 **시작점(Entry Point)** 입니다.
	- `public/index.html` 파일의 **루트 DOM 노드**와 최상위 컴포넌트인 `<App />`을 연결하는 역할을 합니다.
	- 이 파일을 통해 React가 HTML 문서에 애플리케이션 UI를 렌더링하도록 지시합니다.
	- 쉽게 말해, 텅빈 HTML의 뼈대에 동적인 React 컴포넌트들을 조립하는 연결고리 역할을 합니다.
    - `public/index.html`에 정의된 루트 DOM 노드를 선택하고, 그곳에 루트 컴포넌트인 `App`을 렌더링하여 React 애플리케이션을 시작시키는 것이다.

#### **1-3. `node_modules` 폴더와 `package.json`**

`node_modules` 폴더는 프로젝트가 의존하는 모든 외부 패키지(라이브러리)들이 설치되는 디렉터리입니다.

- **역할**: `react`, `react-dom`을 포함하여 `package.json` 파일에 명시된 모든 의존성 패키지들이 저장됩니다. `package.json`은 프로젝트의 메타데이터와 의존성 목록을 관리하는 주문서 역할을 하는 설정 파일이며, `npm install` 명령어는 이 파일을 참조하여 필요한 패키지들을 `node_modules`에 설치합니다.
    
- **특징**: 수많은 파일로 구성되어 용량이 매우 크므로, 일반적으로 `.gitignore` 파일에 추가하여 버전 관리 시스템(Git)에서 제외합니다.  다른 개발자는 `package.json` 파일만 있으면 `npm install` 명령을 통해 동일한 의존성을 재설치할 수 있습니다.

### **2부: React 렌더링 과정**

1부에서 각 파일의 역할을 확인했습니다. 이제 이 파일들이 어떻게 상호작용하여 화면을 렌더링(HTML과 React의 연결)하는지 그 과정을 단계별로 살펴보겠습니다.

#### **2-1. 브라우저의 `index.html` 로드와 DOM 생성**

모든 것은 사용자가 브라우저를 통해 우리 웹사이트에 접속하는 순간 시작됩니다.

1. **HTML 파일 요청 및 수신**:  브라우저는 서버에 웹페이지를 요청하고, 가장 먼저 **`public/index.html`** 파일을 내려받습니다.
    
2. **DOM(문서 객체 모델) 생성**: 브라우저의 렌더링 엔진은 수신한 HTML 문서를 파싱(parsing)하여, 메모리에 문서의 구조를 객체 모델로 표현한 **DOM**을 생성합니다.
	-  파싱: 브라우저가 HTML 텍스트 파일을 한 줄씩 읽어 내려가며, 메모리 안에 자바스크립트가 이해하고 조작할 수 있는 객체 구조, 즉 **DOM**을 만드는 과정

이 단계에서 `<div id="root"></div>`를 포함한 DOM 구조가 생성되지만, 내부는 비어있어 화면에는 아무것도 표시되지 않습니다.

#### **2-2. JavaScript 진입점 `index.js` 실행**

브라우저가 `index.html` 파싱 중 `<script>` 태그를 만나면, 해당 JavaScript 파일을 로드하여 실행합니다. CRA 프로젝트에서는 번들링된 JavaScript 파일이 실행되며, 그 시작점은 **`src/index.js`** 입니다.

`index.js` 파일은 `import` 구문을 통해 렌더링에 필요한 모듈들을 로드합니다.

```JavaScript
// 1. 필요한 라이브러리 로드
import React from 'react';// React의 핵심 기능(예: JSX)을 사용하기 위한 도구
import ReactDOM from 'react-dom/client';// React 컴포넌트를 DOM에 연결하기 위한 도구
import App from './App'; // 루트 컴포넌트 로드
```

#### **2-3. `ReactDOM`을 이용한 컴포넌트 렌더링**

DOM이 생성된 후, **`index.js`** 파일의 JavaScript가 실행되면서 `ReactDOM` 라이브러리가 동작합니다. 이 과정은 **`public/index.html`** 파일의 특정 DOM 요소를 React 애플리케이션의 시작점으로 지정하고, 그곳에 최상위 컴포넌트를 렌더링하는 순서로 진행됩니다.

- **1단계: DOM 요소 선택** 먼저 `document.getElementById('root')`를 이용해 `index.html` 파일에 있는 `<div id="root"></div>`를 찾습니다. 이 요소가 React가 UI를 그려 넣을, 렌더링의 **기준점**이 됩니다.
    
    ```JavaScript
    // public/index.html 파일에 있는 <div id="root"></div>를 찾습니다.
    const rootElement = document.getElementById('root');
    ```
    
- **2단계: React Root 생성** 
	선택한 `rootElement`를 `ReactDOM.createRoot()` 함수의 인자로 전달하여 **React Root**를 생성합니다. 
	- React Root는 React가 컴포넌트를 관리하고 렌더링할 수 있도록 **준비된 공간**입니다. 
	- 이 단계는 "이 영역은 React가 독점적으로 관리하겠다"고 선언하는 것과 같습니다.
    
    ```JavaScript
    // 찾은 HTML 요소를 React가 제어할 수 있는 공간(Root)으로 만듭니다.
    const root = ReactDOM.createRoot(rootElement);
    ```
    
    `createRoot()` 함수가 반환하는 `root` 객체에는 컴포넌트를 화면에 그리는 `render()` 메서드가 포함되어 있습니다.
    
-  컴포넌트 렌더링 (`root.render()`)
	- 마지막으로, 생성된 `root` 객체의 `render()` 메서드을 최상위 컴포넌트인 `<App />`을 인자로 전달하여 호출합니다. 
	- 이때 React는 `<App />` 컴포넌트와 그에 속한 모든 자식 컴포넌트를 렌더링하여 실제 DOM에 반영합니다.
    
    ```JavaScript
    // 생성된 React Root에 최상위 컴포넌트인 <App />을 그려 넣습니다.
    root.render(
      <React.StrictMode>
        <App />
      </React.StrictMode>
    );
    ```

### **3부: 핵심 문법과 도구**
어떻게 JavaScript 파일(`App.js`) 안에서 HTML과 비슷한 코드를 자유롭게 작성할 수 있었을까요?
React의 렌더링 과정을 가능하게 하는 주요 문법과 도구는 다음과 같습니다.

#### **3-1. JSX: JavaScript를 위한 구문 확장**

`App.js` 파일 내에서 사용된 HTML 유사 코드는 순수 JavaScript 문법이 아닌 **JSX(JavaScript XML)** 입니다.

```JavaScript
// in App.js
function App() {
  return (
    <div className="App">{/* ... */}</div>
  );
}
```

JSX는 JavaScript 코드 내에서 UI의 구조를 HTML과 유사한 마크업으로 시각적으로 표현할 수 있게 해주는 문법 확장입니다.

- **UI 작성의 편의성**: JSX를 사용하면 `React.createElement()` 함수를 직접 호출하는 방식보다 더 간결하고 직관적으로 컴포넌트의 UI 구조를 작성할 수 있습니다.
- **컴포넌트의 태그 기반 사용**: JSX는 `App.js`와 같은 JavaScript 컴포넌트 파일을 `<App />` 형태의 태그로 사용할 수 있도록 합니다.
    
JSX는 JavaScript의 모든 기능을 활용하면서 UI 개발의 생산성을 높여주는 역할을 합니다.

#### **3-2. 바벨(Babel): JavaScript 컴파일러**

그런데 웹 브라우저는 JSX 문법을 직접 해석할 수 없습니다. 따라서 JSX 코드가 브라우저에서 실행되기 위해서는 변환 과정이 필요하며, 이 역할을 **바벨(Babel)** 이 수행합니다.

- **역할**: 바벨은 **트랜스파일러(Transpiler)** 로서, JSX나 최신 사양의 JavaScript 코드를 다양한 브라우저에서 호환되는 표준 JavaScript 코드로 변환(번역)합니다.
    
- **동작 방식**: 우리가 코드를 저장하고 `npm start`를 실행하면, CRA 프로젝트 환경에서는 개발 서버가 실행될 때 바벨이 자동으로 동작합니다. `src` 폴더 내의 파일에 포함된 JSX 구문은 브라우저가 이해할 수 있는 `React.createElement()` 함수 호출로 변환됩니다. 브라우저는 이렇게 변환이 완료된 순수 JavaScript 코드를 최종적으로 실행하게 됩니다.
---
#### **1-2. `src` 폴더와 애플리케이션 소스 코드**

`src`(Source) 폴더는 컴포넌트, 스타일, 로직 등 애플리케이션을 구성하는 모든 소스 코드가 위치하는 메인 개발 디렉터리다.

- **`App.js`**: 애플리케이션의 최상위 컴포넌트, 즉 루트 컴포넌트(Root Component)다. 모든 하위 컴포넌트들은 이 `App` 컴포넌트 내부에 중첩되는 트리 구조를 형성한다.
    
- **`index.js`**: 애플리케이션의 JavaScript 실행 진입점이다. 이 파일의 주요 역할은 `public/index.html`에 정의된 루트 DOM 노드를 선택하고, 그곳에 루트 컴포넌트인 `App`을 렌더링하여 React 애플리케이션을 시작시키는 것이다.
    

#### **1-3. `node_modules` 폴더와 의존성 관리**

`node_modules` 폴더는 프로젝트가 의존하는 모든 외부 패키지(라이브러리)가 설치되는 디렉터리다.

- **역할**: `react`, `react-dom` 등 `package.json` 파일의 `dependencies`와 `devDependencies`에 명시된 모든 패키지들이 저장된다. 패키지 매니저(npm, yarn 등)가 `npm install` 명령어를 통해 `package.json`을 참조하여 필요한 파일들을 다운로드하고 이 폴더에 위치시킨다.
    
- **특징**: 프로젝트의 의존성을 모두 포함하므로 용량이 매우 크다. 따라서 `.gitignore` 파일에 의해 버전 관리 시스템(Git)의 추적 대상에서 제외된다.

### **2부: React 애플리케이션 렌더링 과정**

#### **2-1. 브라우저의 HTML 파싱과 DOM 생성**

1. **HTML 로드**: 사용자가 웹사이트에 접속하면 브라우저는 서버로부터 `public/index.html` 파일을 다운로드한다.
    
2. **DOM 생성**: 브라우저의 렌더링 엔진은 HTML 문서를 파싱(parsing)하여, 문서의 구조를 메모리에 객체 모델로 표현한 DOM(Document Object Model)을 생성한다. 이 단계에서 `<div id="root"></div>`는 DOM 트리에 포함되지만 내부는 비어있는 상태다.
    

#### **2-2. JavaScript 번들 실행**

`index.html` 파일이 파싱되는 과정에서 브라우저는 `<script>` 태그를 만나게 된다. 이 태그는 웹팩(Webpack)에 의해 번들링된 JavaScript 파일(주로 `bundle.js`)을 가리킨다. 브라우저는 이 파일을 로드하고 실행하며, 이 번들 파일의 시작점은 `src/index.js`이다.

`index.js` 파일은 `import` 문을 통해 애플리케이션 구동에 필요한 모듈들을 가져온다.

JavaScript

```
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
```

#### **2-3. React DOM 마운트 과정**

JavaScript가 실행되면서 `ReactDOM` 라이브러리가 React 컴포넌트를 실제 DOM에 연결(마운트)하는 작업을 수행한다.

- **1단계: DOM 요소 선택**: `document.getElementById('root')` 메서드를 사용하여 렌더링의 기준점이 될 `index.html`의 `<div id="root"></div>` 요소를 선택한다.
    
    JavaScript
    
    ```
    const rootElement = document.getElementById('root');
    ```
    
- **2단계: React Root 생성**: `ReactDOM.createRoot()` 함수에 선택된 DOM 요소를 인자로 전달하여 React Root를 생성한다. 이 객체는 React가 해당 DOM 노드의 렌더링을 관리하는 인터페이스를 제공한다.
    
    JavaScript
    
    ```
    const root = ReactDOM.createRoot(rootElement);
    ```
    
- **3단계: 컴포넌트 렌더링**: 생성된 `root` 객체의 `render()` 메서드를 호출하고, 최상위 컴포넌트인 `<App />`을 인자로 전달한다. 이 시점에 React는 `App` 컴포넌트와 그 모든 자식 컴포넌트들을 렌더링하여 그 결과를 실제 DOM에 반영한다.
    
    JavaScript
    
    ```
    root.render(<App />);
    ```
    
    이 과정이 완료되면 사용자는 브라우저 화면을 통해 렌더링된 UI를 볼 수 있다.
    

---

### **3부: React 구동을 위한 핵심 기술**

#### **3-1. JSX (JavaScript XML)**

JSX는 JavaScript를 확장한 문법으로, JavaScript 파일 내에서 UI 구조를 시각적으로 표현하기 위해 HTML과 유사한 마크업을 사용할 수 있게 한다.

JavaScript

```
function App() {
  return <div className="App">Hello, React!</div>;
}
```

JSX는 브라우저에서 직접 실행되지 않는다. 코드 실행 전에 바벨(Babel)과 같은 트랜스파일러에 의해 순수한 JavaScript의 `React.createElement()` 함수 호출로 변환된다. JSX는 복잡한 `createElement` 호출을 사용하는 것보다 코드의 가독성을 높이고 UI 구조를 직관적으로 파악할 수 있게 한다.

#### **3-2. 바벨 (Babel)**

바벨은 JavaScript 트랜스파일러(Transpiler)다. CRA 프로젝트에서 바벨의 주된 역할은 두 가지다.

1. **JSX 변환**: 위에서 설명한 JSX 코드를 브라우저가 이해할 수 있는 `React.createElement()` 함수로 변환한다.
    
2. **JavaScript 버전 호환성**: 화살표 함수, `const/let` 등 최신 JavaScript(ES6+) 문법을 구형 브라우저에서도 동작할 수 있는 이전 버전(ES5)의 코드로 변환하여 크로스 브라우징 호환성을 확보한다.
    

이러한 변환 과정은 개발 환경에 통합되어 있어 개발자는 별도의 설정 없이 최신 문법과 JSX를 사용하여 개발할 수 있다.

### **결론: 모든 길은 `index.html`의 `#root`로 통한다

지금까지의 긴 여정을 요약하면 React 앱의 동작 원리는 다음과 같은 흐름으로 정리할 수 있습니다.

1. **(설계도)** 브라우저는 가장 먼저 `public/index.html` 파일을 읽어, React 앱이 그려질 텅 빈 무대인 `<div id="root"></div>`를 포함한 **DOM**을 생성합니다.
    
2. **(연결)** `index.js` 파일이 실행되면서 이 `id='root'`인 요소를 찾아내고, `ReactDOM`을 통해 이곳을 React가 제어할 수 있는 특별한 공간으로 지정합니다.
    
3. **(조립)** `index.js`는 `root.render()` 명령을 통해 주연 배우인 `<App />` 컴포넌트를 무대 위에 올리라고 명령합니다. 이때 우리가 JSX로 작성한 코드는 **바벨**에 의해 이미 브라우저가 이해하는 JavaScript 코드로 번역된 상태입니다.
    
4. **(완성)** `<App />`을 시작으로 그 안의 모든 자식 컴포넌트들이 차례대로 조립되어 `#root` 안을 가득 채우고, 마침내 사용자는 동적인 웹 애플리케이션 화면을 보게 됩니다.
    

이처럼 React 프로젝트의 구조는 복잡한 마법이 아니라, 각자의 역할에 충실한 파일들이 정해진 약속에 따라 유기적으로 상호작용하는 하나의 잘 짜인 시스템입니다. 이 기본 동작 원리를 이해하는 것은 앞으로 마주할 React의 다양한 개념들을 받아들일 튼튼한 기반이 되어줄 것입니다.

## 💭 정리할 정보들

#### 1. 컴포넌트(Component): 리액트의 기본 단위

리액트에서 **컴포넌트**는 웹 페이지의 UI를 구성하는 **독립적이고 재사용 가능한 부품**입니다. `App.js` 파일이 바로 `<App />`이라는 이름의 최상위 컴포넌트이며, 모든 컴포넌트는 이 아래에 조립됩니다.

- **역할**: 화면에 보여질 특정 부분의 모양과 동작을 JavaScript 함수 또는 클래스로 정의합니다.
    

#### 2. JSX: 컴포넌트를 만드는 특별한 문법

JSX는 JavaScript 파일 안에서 **HTML과 유사한 문법으로 UI를 작성**할 수 있게 해주는 문법 확장입니다.

- **주요 특징**:
    
    1. JavaScript 함수(`function App()`) 안에서 HTML 구조를 직접 `return` 할 수 있습니다.
        
    2. `App.js` 같은 JavaScript 파일을 `<App />`이라는 HTML 태그처럼 사용할 수 있게 합니다.
        

#### 3. 바벨(Babel): JSX를 브라우저 언어로

브라우저는 JSX를 직접 이해할 수 없습니다. 우리가 JSX를 사용할 수 있는 이유는 **바벨(Babel)**이라는 변환 도구가 JSX 코드를 브라우저가 이해할 수 있는 **순수 JavaScript 코드로 자동 변환**해주기 때문입니다.

------
##### `index.js`의 역할: React와 HTML의 연결

`index.js` 파일은 React 애플리케이션의 **진입점(Entry Point)**으로, **HTML 파일과 React 컴포넌트를 연결하는 '다리'** 역할을 합니다.

이 파일의 코드는 크게 두 부분으로 나뉩니다.
1. **`import`**: React 라이브러리 등 필요한 기능들을 불러옵니다.
2. **렌더링**: 불러온 기능으로 React 컴포넌트를 실제 웹 페이지에 그립니다.

---

##### 코드 상세 설명

```JavaScript
// 1. 필요한 라이브러리 불러오기
import React from 'react';
import ReactDOM from 'react-dom/client'; // React를 DOM에 연결하는 도구
import App from './App'; // 우리가 만든 최상위 컴포넌트

// 2. HTML 요소 선택
// public/index.html 파일에 있는 <div id="root"></div>를 찾습니다.
const rootElement = document.getElementById('root');

// 3. React Root 생성
// 찾은 HTML 요소를 React가 제어할 수 있는 공간(Root)으로 만듭니다.
const root = ReactDOM.createRoot(rootElement);

// 4. 컴포넌트 렌더링
// 생성된 React Root에 최상위 컴포넌트인 <App />을 그려 넣습니다.
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

코드 흐름 요약

1. **`import`**: `react`, `react-dom/client`, 그리고 우리가 만든 `App.js` 컴포넌트를 불러옵니다.
2. **`document.getElementById('root')`**: `index.html`에 있는 React 앱의 "바탕"이 될 `<div>`를 찾습니다.
3. **`ReactDOM.createRoot(...)`**: 찾은 `<div>`를 React 앱을 그릴 수 있는 공간으로 지정합니다.
4. **`root.render(<App />)`**: 지정된 공간에 최상위 컴포넌트인 `<App />`을 실제로 그려 넣어, 우리가 보는 웹 화면을 완성합니다.

> **JSX란?** `<App />`처럼 JavaScript 파일 안에서 HTML 태그와 유사한 형태로 코드를 작성하는 문법을 **JSX**라고 합니다. 이는 React에서 UI를 더 직관적으로 작성하기 위해 사용됩니다.
 
 요약: 어떻게 연결되는가?
1. 최상위 조상파일인 **`public/index.html`** 은 `<div id="root"></div>` 라는 뼈대를 제공합니다.
2. **`src/index.js`** 는 "id가 'root'인 요소를 찾아, 그 안에 `<App />` 컴포넌트를 그려라" 라고 명령합니다.
3. **`src/App.js`** 를 시작으로 모든 컴포넌트가 `#root` 안에 차례대로 그려지며 우리가 보는 웹 페이지가 완성됩니다.

### **React 기본 구조 핵심 요약**

1. **`index.js` 파일의 역할**
    - 파일 상단(`import`)에서는 필요한 기능(React 등)을 불러옵니다.
    - 파일 본문에서는 이 기능들을 사용해 실제 앱을 구동하는 코드를 작성합니다.
        
2. **`index.html` 파일의 역할**
    - React 앱 전체의 '시작점' 또는 '껍데기' 역할을 합니다.
    - 브라우저가 가장 먼저 불러오는 파일이며, 내부는 거의 비어있습니다.
        
3. **두 파일의 연결 관계**
    - `index.html` 파일이 `<script>` 태그를 통해 `index.js` 파일을 불러옵니다.
    - `index.js`는 `index.html` 안에 있는 특정 공간(예: `<div id="root"></div>`)을 찾아 그 안에 React 컴포넌트들을 그려 넣어 앱을 완성합니다.
        

**결론: `index.html`이 뼈대를 제공하면, `index.js`가 그 안을 동적인 콘텐츠로 채우는 방식으로 둘은 긴밀하게 연결되어 있습니다.**

웹브라우저가 `index.html`이라는 설계도 파일을 읽어들이면, 메모리 안에 **DOM(문서 객체 모델)**이라는 살아있는 구조물을 만듭니다. 이 DOM 덕분에 우리는 자바스크립트를 이용해 HTML 문서의 요소를 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)하는 등 동적인 제어가 가능해집니다.

이제 우리의 목표는 이 DOM과 React 애플리케이션의 심장부인 `index.js` 파일을 'React 방식'으로 연결하는 것입니다.

이 중요한 연결 작업을 위해, 우리는 `node_modules` 폴더에 있는 `react-dom` 라이브러리의 힘을 빌립니다. 최신 React(버전 18 이상)에서는 `react-dom/client`가 제공하는 `createRoot`라는 함수를 사용합니다. 이 함수가 바로 `index.js` 안의 React 컴포넌트들을 `index.html`의 특정 지점(예: `<div id="root"></div>`)에 아주 효과적으로 연결해주는 접착제 역할을 합니다.

이러한 과정을 통해 우리는 프로그래밍 개발의 본질을 엿볼 수 있습니다. 개발이란 아무것도 없는 상태에서 무언가를 창조하는 것이 아니라, HTML, DOM, JavaScript 같은 기존 기술들을 바탕으로 **'어떻게 하면 데이터와 화면(파일)을 더 안정적이고 효율적으로 연결할까?'** 라는 고민을 해결해 나가는 과정입니다.

**React 같은 라이브러리는 바로 그 고민에 대한 인간의 해답입니다.** 복잡한 데이터의 변화를 예측 가능하게 화면에 반영하여, 개발자가 더 안정적으로 프로그램을 만들 수 있도록 돕는 고도로 설계된 '연결 기술'인 셈입니다.

`index.js` 파일에서 React 애플리케이션을 구동시키려면 먼저 필요한 두 가지 핵심 라이브러리를 불러와야 합니다.

1. `import React from 'react';` : JSX 사용 등 React의 핵심 기능을 사용하기 위해 필수입니다.
    
2. `import ReactDOM from 'react-dom/client';` : React 컴포넌트를 실제 DOM에 연결하고 렌더링하기 위해 필요합니다.
    

이제 이 라이브러리들을 사용해 React 앱과 브라우저를 연결해 보겠습니다.

먼저, `ReactDOM` 라이브러리에 내장된 `createRoot()` 함수를 사용해 '연결 고리'를 만듭니다. 이 함수의 인자(데이터)로 `document.getElementById('root')` 코드를 넣어주는데, 이는 "HTML 문서에서 id가 'root'인 요소를 찾아라"라는 뜻입니다.

`const root = ReactDOM.createRoot(document.getElementById('root'));`

위 코드가 실행되면, `root`라는 상수 변수에는 **React가 제어할 DOM의 최상위 루트(root)에 대한 정보와 제어 기능이 담긴 객체**가 저장됩니다.

이제 `root` 변수는 특별한 능력을 갖게 되었습니다. 바로 `render()`라는 함수를 사용할 수 있는 능력입니다. 왜 갑자기 `render()` 함수를 쓸 수 있을까요? 이것은 React를 만든 개발자들이 우리와 한 **'약속'**입니다. `createRoot()`를 사용하면 `render()` 함수가 포함된 객체를 주기로 규칙을 정해놓았기 때문입니다.

우리는 이 `render()` 함수 안에 우리가 만든 React 컴포넌트를 넣어주면, 비로소 화면에 앱이 그려지게 됩니다.

### **React 렌더링의 기술적 과정**

React 애플리케이션이 사용자에게 표시되는 과정은 여러 단계의 명확한 기술적 절차를 따릅니다. 이 과정은 브라우저가 HTML 파일을 요청하는 것에서 시작하여 React 컴포넌트가 화면에 출력되는 것으로 마무리됩니다.

#### **1. HTML 문서와 DOM(Document Object Model) 생성**

1. **HTML 파일 로드**: 사용자가 웹사이트에 접속하면, 브라우저는 서버에 `index.html` 파일을 요청하고 수신합니다. 이 파일은 React 애플리케이션이 마운트(mount)될 기본 구조를 포함하는 텍스트 문서입니다.
    
2. **DOM 생성**: 브라우저는 수신한 `index.html` 파일을 파싱(parsing)하여, 문서의 구조를 메모리에 객체 형태로 표현하는 **DOM**을 생성합니다. DOM은 자바스크립트와 같은 프로그래밍 언어가 문서의 콘텐츠와 구조, 스타일을 조작할 수 있도록 하는 인터페이스(API)입니다.
    
3. **타겟 요소**: `index.html` 내부에는 일반적으로 `<div id="root"></div>`와 같이 React 컴포넌트가 렌더링될 특정 DOM 요소가 정의되어 있습니다.
    

#### **2. JavaScript 진입점과 라이브러리 로드**

1. **JavaScript 실행**: `index.html`은 `<script>` 태그를 통해 `index.js` 파일을 로드하고 실행합니다. 이 `index.js` 파일이 React 애플리케이션의 **진입점(Entry Point)**입니다.
    
2. **라이브러리 임포트(Import)**: `index.js` 파일 상단에서는 `import` 키워드를 통해 애플리케이션 구동에 필요한 라이브러리들을 `node_modules` 폴더로부터 불러옵니다.
    
    - `import React from 'react';`: 컴포넌트를 정의하고 JSX(JavaScript XML) 문법을 처리하는 등 React의 핵심 기능을 제공합니다.
        
    - `import ReactDOM from 'react-dom/client';`: React 컴포넌트를 실제 DOM에 연결하고 렌더링하는 기능을 담당합니다.
        

#### **3. React Root 생성 및 DOM 연결**

1. **루트(Root) 생성**: `ReactDOM.createRoot()` 함수가 호출됩니다. 이 함수는 React 애플리케이션을 렌더링할 DOM의 최상위 컨테이너, 즉 루트를 생성하는 역할을 합니다.
    
2. **DOM 요소 지정**: `createRoot()` 함수의 인자로 `document.getElementById('root')`가 전달됩니다. 이는 React에게 렌더링을 시작할 DOM의 특정 위치를 알려주는 것입니다.
    
3. **Root 객체 반환**: `createRoot()` 함수는 **React Root 객체**를 반환합니다. 이 객체는 지정된 DOM 노드에 대한 렌더링을 관리하는 메서드를 포함하고 있습니다.
    
    ```JavaScript
    // DOM에서 id가 'root'인 요소를 선택하여 React Root를 생성합니다.
    const root = ReactDOM.createRoot(document.getElementById('root'));
    ```
    

#### **4. React 컴포넌트 렌더링**

1. **`render` 메서드 호출**: 앞에서 생성된 `root` 객체는 `render()` 메서드를 제공합니다. 이 메서드는 React 엘리먼트(일반적으로 `<App />`과 같은 최상위 컴포넌트)를 인자로 받습니다.
    
2. **가상 DOM과 렌더링**: `root.render(<App />);`가 호출되면, React는 `<App />` 컴포넌트와 그 모든 자식 컴포넌트들을 렌더링하기 시작합니다. React는 내부적으로 가상 DOM(Virtual DOM)을 사용하여 변경 사항을 계산하고, 최종 결과를 실제 DOM에 효율적으로 업데이트하여 화면에 UI를 표시합니다.
    

이와 같이 React는 HTML 문서를 기반으로 생성된 DOM에, `ReactDOM` 라이브러리를 통해 컴포넌트를 체계적으로 연결하고 렌더링하는 기술적인 절차를 통해 동작합니다.
