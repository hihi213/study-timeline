## 웹 애플리케이션의 구조와 동작 원리 ⚙️

현대 웹 애플리케이션은 사용자가 보는 화면부터 데이터 저장까지, 명확하게 역할이 나뉜 여러 기술들의 조합으로 이루어집니다.

---

### 1. 웹 애플리케이션의 기본 구조: 3-Tier 아키텍처
- **데이터 관리의 기본, CRUD**
	- 데이터를 저장하고 관리하게 된다면, 대부분의 프로그래밍 작업은 **CRUD(Create, Read, Update, Delete)** 개념을 기반으로 이루어집니다.  
현대 웹 서비스는 역할에 따라 **프론트엔드, 백엔드, 데이터베이스**의 세 가지 영역으로 독립적으로 나뉘어 동작합니다. 이를 **3-Tier 아키텍처**라고 합니다.

- **💻 프론트엔드 (Frontend - 사용자 인터페이스)**
    - **역할**: 사용자가 직접 보고 상호작용하는 화면(UI)을 담당합니다.
    - **주요 기술**: HTML, CSS, **JavaScript** (주로 React, Vue 같은 라이브러리/프레임워크 사용)
    - **개발 환경 주소 예시**: `localhost:3000` (React)
- **⚙️ 백엔드 (Backend - 서버)**
    - **역할**: 화면 뒤에서 데이터를 처리하고 비즈니스 로직을 수행하며, 데이터베이스와의 통신을 책임집니다. 사용자의 요청을 해석하고 어떤 데이터를 보여줄지 결정하는 '두뇌' 역할을 합니다.
    - **주요 기술**: **Java** (SpringBoot), Python (Django), Node.js (Express) 등
    - **개발 환경 주소 예시**: `localhost:8080` (SpringBoot)
        
- **📦 데이터베이스 (Database - 데이터 저장소)**
    - **역할**: 모든 데이터를 영구적으로 저장하고 관리합니다. 데이터의 생성, 조회, 수정, 삭제(CRUD)가 이곳에서 일어납니다.
    - **주요 기술**: **SQL** 언어, **MySQL** 또는 PostgreSQL 같은 데이터베이스 관리 시스템(DBMS)
    - **개발 환경 주소 예시**: `localhost:3306` (MySQL)
        
---

### 2. 영역 간의 통신 방식: API와 SQL

독립된 세 영역은 정해진 규칙에 따라 데이터를 주고받습니다.

#### **프론트엔드 ↔ 백엔드 통신: API**

두 영역은 웹의 공용어인 **HTTP 프로토콜**을 통해 통신하며, 이때 **API(Application Programming Interface)** 라는 구체적인 통신 규칙을 따릅니다.

> **HTTP와 API의 관계** **HTTP**가 '한국어'라는 언어의 문법이라면, **API**는 그 언어로 작성된 '카페 주문 메뉴판'과 같습니다. API는 복잡한 내부 시스템을 숨기고, 약속된 방식으로만 소통하게 해주는 명확한 인터페이스입니다.

API는 다음과 같은 세부 규칙을 정의합니다.

1. **엔드포인트 (Endpoint)**: 어디로 요청할지 (`https://api.example.com/users` 같은 고유 주소).
    
2. **메소드 (Method)**: 무엇을 할지 (`GET` 조회, `POST` 생성 등).
    
3. **데이터 형식 (Data Format)**: 무엇을 주고받을지 (주로 **JSON** 형식 사용).
    

#### **백엔드 ↔ 데이터베이스 통신: SQL**

백엔드와 데이터베이스는 **'데이터베이스 커넥션'** 이라는 보안된 전용 통로를 통해 연결되며, **SQL(Structured Query Language)** 이라는 언어로 직접 데이터를 요청하고 조작합니다.

### 3. 렌더링 방식과 데이터 흐름: CSR vs. SSR

프론트엔드와 백엔드가 API로 통신할 때, 서버가 브라우저에 무엇을 보내주는지에 따라 렌더링 방식이 나뉩니다.

- **CSR (Client-Side Rendering)**: **데이터(JSON)**를 받아 브라우저가 직접 그린다.
    
    - **동작 방식**: 서버는 API를 통해 **JSON 형태의 순수 데이터**만 보냅니다. 브라우저는 이 데이터를 받아 JavaScript(주로 React)를 사용해 직접 HTML을 그려 화면을 완성합니다.
        
    - **특징**: 프론트엔드와 백엔드가 명확히 분리되며, 현대적인 웹 앱에서 주로 사용됩니다. (React, Vue 등)
        
- **SSR (Server-Side Rendering)**: 서버가 **완성된 HTML 페이지**를 보낸다.
    
    - **동작 방식**: 서버가 데이터베이스 조회와 데이터 가공을 모두 마친 후, **완성된 HTML 문서**를 만들어 브라우저에 전달합니다.
        
    - **특징**: 첫 페이지 로딩 속도가 빠르며, 전통적인 웹 개발 방식에서 많이 사용됩니다.

### 4. 개발과 배포 환경: 로컬호스트와 서버

- **로컬 환경 (Private Server)**
    
    - 개발자 개인의 컴퓨터를 의미하며, **`localhost`** 라는 주소로 접근합니다.
        
    - 이곳에서 프론트엔드, 백엔드, 데이터베이스 서버를 모두 설치하여 웹 애플리케이션을 개발하고 테스트합니다.
        
- **배포 환경 (Public Server)**
    
    - AWS, Cafe24 같은 전문 호스팅 업체의 서버를 의미합니다.
        
    - 개발이 완료된 웹 서비스를 이곳에 배포하여 전 세계 사용자들이 접근할 수 있도록 운영합니다.
        

---

### 5. 백엔드 개발의 핵심 설계: 객체 지향 프로그래밍 (OOP)

백엔드에서 주로 사용하는 Java와 같은 언어는 **객체 지향 프로그래밍(OOP)** 이라는 설계 철학을 따릅니다.

> **객체 지향 프로그래밍(OOP)이란?** 현실 세계의 사물이나 개념을 **'객체(Object)'**로 모델링하여 프로그램을 만드는 방식입니다. 이때 객체는 관련된 **데이터(속성)와 행동(메서드)을** 하나로 묶은 단위입니다. '붕어빵 틀'이 **클래스(Class, 설계도)**이고, 그 틀로 찍어낸 '붕어빵'이 **객체(Object, 실제 제품)**라고 비유할 수 있습니다.

OOP는 코드 재사용성을 높이고 관련 기능들을 덩어리로 묶어 관리를 쉽게 하며, 프로그램을 더 안정적이고 논리적으로 만들기 위해 사용됩니다.
