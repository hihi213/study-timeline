| **장소 (Layer)** | **특징**                                      |
| -------------- | ------------------------------------------- |
| **API URL**    | 소문자 + 하이픈(`-`)                              |

| **PostgreSQL** | 소문자 + 언더바(`_`)                              |

## 1. Database (PostgreSQL): **snake_case**

PostgreSQL은 식별자에서 대소문자를 구분하지 않는 것이 기본이므로, 가독성을 위해 **언더바(`_`)**로 구분해 **소문자**만 사용하는 `snake_case`를 채택합니다.
>대문자 사용시 쌍따옴표로 감싸야한다

| **대상 (Target)** | **규칙**                                    |
| --------------- | ----------------------------------------- |
| **Table**       | 복수형 명사<br>(데이터의 집합이므로)                    |
| **Column**      | `snake_case`                              |
| **Primary Key** | id 또는 `테이블명`_id                           |
| **Foreign Key** | `참조테이블명의 단수형`_id                          |
| **Index**       | idx_`테이블명`\_`컬럼명`                         |
| **Constraint**  | 제약조건 접두어 사용<br>`pk_`, `fk_`, `uk_`, `ck_` |
### 2. Spring Backend (Java): **camelCase**
> **대문자**로 구분하고 나머진 **소문자**

#### A. 메서드 작명 (Methods)

| **대상 (Target)**          | **규칙**: 동사+명사                                   |
| ------------------------ | ----------------------------------------------- |
| **단건조회**<br>(반드시 존재시 사용) | `get` + `명사`<br>(데이터가 없으면 Exception 발생을 전제)     |
| **조회**<br>(존재여부가 불확실시)   | `find` + `명사`<br>(`Optional` 객체를 반환하여 존재 여부 확인) |
| **저장 (Repository)**      | `save` + `명사`<br>(DB에 물리적으로 저장할 때 사용)           |
| **생성 (Service)**         | `create` + `명사`<br>(비즈니스 로직을 포함한 생성 프로세스)       |
| **수정**                   | `update` + `명사` 또는 <br>`change` + `명사`          |
| **삭제**                   | `delete` + `명사` 또는 <br>`deleteBy` + `필드명`       |
| **존재 여부 확인**             | `existsBy` + `필드명`<br>(`boolean` 값을 반환)         |

#### B. 변수 및 불리언 작명 (Variables)
> 불리언 타입은 질문에 대한 답(`true/false`)이 될수있게 구성

| **대상 (Target)**        | **규칙**                                          |
| ---------------------- | ----------------------------------------------- |
| **일반 변수**              | `명사`<br>(해당 데이터의 의미를 담은 명확한 이름)                 |
| **날짜/시간**              | `명사` + `At` (시점) 또는 <br>`명사` + `Date` (날짜)      |
| **객체의 상태 여부(boolean)** | `is` + `상태(형용사/과거분사)`                           |
| **포함 여부(boolean)**     | `has` + `객체명`                                   |
| **가능 여부(boolean)**     | `can` + `동사`                                    |
| **컬렉션**                | `명사`의 복수형 사용<br>(`List`, `Set` 등 여러개 담는 자료구조일때) |

### 3. 계층에 따른 클래스 종류 (PascalCase)

> 클래스: 모든 단어의 첫 글자를 대문자로 표기

| **계층(Layer)**                            | **접미사 (Suffix)**     | **예시**             |
| ---------------------------------------- | -------------------- | ------------------ |
| **Controller**<br>외부 HTTP 요청 수신 및 응답 처리  | `Controller`         | `FridgeController` |
| **Service**<br>핵심 비즈니스 로직 및 트랜잭션 관리      | `Service`            | `FridgeService`    |
| **Repository**<br>DB 직접 접근 (JPA 인터페이스 등) | `Repository`         | `FridgeRepository` |
| **Entity**<br>DB 테이블과 1:1 매핑되는 도메인 모델    | (없음)                 | `Fridge`           |
| **DTO**<br>계층 간 데이터 이동 및 API 스펙 정의       | `Request`/`Response` | `FridgeResponse`   |

## 3. Web & API (Communication)

클라이언트(프론트엔드)와 서버 간의 데이터를 주고받을 때 사용하는 통신 규약입니다.

| **대상 (Target)** | **규칙**                                                    |
| --------------- | --------------------------------------------------------- |
| **URL Path**    | `/api/v1/` + `리소스명(복수형)`<br>(**kebab-case**: 소문자와 하이픈 사용) |
| **JSON Key**    | camelCase식 `필드명`                                          |
| **Query Param** | camelCase식 `필드명`                                          |

### 📋 REST API 설계 원칙 (Best Practice)

API 설계 시 리소스의 상태와 행위를 분리하여 정의합니다.

| **구분**             | **규칙**                                    | **예시**                         |
| ------------------ | ----------------------------------------- | ------------------------------ |
| **행위 (Action)**    | **HTTP Method**로 표현<br>(URL에 동사를 포함하지 않음) | `GET`, `POST`, `PUT`, `DELETE` |
| **리소스 (Resource)** | **명사(복수형)**로 표현                           | `/fridge-slots`, `/users`      |

- 잘못된 예: `GET /get-slots`, `POST /create-user`
- 올바른 예: `GET /slots`, `POST /users`

### 💡 요약

1. **URL Path:** 주소창에 나타나는 경로는 `kebab-case`를 사용하며, 무엇(What)인지 나타내는 **명사**만 사용합니다.
2. **Data (JSON/Param):** 실제 전달되는 데이터의 키 값은 자바 및 자바스크립트 표준인 `camelCase`를 사용합니다.
3. **Method:** '가져오기', '생성하기' 등의 **동사** 역할은 URL 이름이 아닌 HTTP Method가 담당하도록 설계합니다.


## 자동화 설정 (Spring Boot)

Spring Data JPA를 사용할 경우, `application.yml`에 다음 설정을 추가하면 Java의 `camelCase`를 DB의 `snake_case`로 자동 매핑합니다.

```YAML
jpa:
  hibernate:
    naming:
      physical-strategy: org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy
```
