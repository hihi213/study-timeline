## 정리
`@JoinTable`을 사용해서 생긴 결과물이 엔티티가 아닌 이유는, JPA가 **테이블을 매핑하는 방식**과 **엔티티의 정의**가 다르기 때문입니다.

### 1) JPA의 역할과 매핑 방식

JPA는 객체와 관계형 데이터베이스를 매핑하는 기술(ORM)입니다. 이 매핑은 두 가지 차원에서 이루어집니다.

- **객체 모델**: 비즈니스 로직을 담는 자바 객체(엔티티). 개발자가 직접 코드로 작성합니다.
- **데이터베이스 모델**: 데이터를 저장하는 테이블. JPA가 객체 모델을 바탕으로 테이블을 생성하거나 기존 테이블에 매핑합니다.

`@JoinTable`은 이 중에서 데이터베이스 모델, 즉 **테이블 구조를 정의**하기 위한 것입니다. `Member` 엔티티와 `Product` 엔티티 간의 다대다 관계를 DB에서 구현하기 위해 **중간에 필요한 연결 테이블의 이름과 외래 키 컬럼을 알려주는 역할**만 합니다. 이는 개발자가 별도의 자바 클래스 파일(`.java`)로 엔티티를 직접 생성한 것이 아니기 때문에, JPA 내부에서는 엔티티로 인식되지 않습니다. ^0webyt

### 2) 엔티티의 정의와 역할

엔티티는 단순한 테이블이 아니라, **비즈니스 로직과 상태를 포함하는 객체**입니다. 즉, 우리가 `Member.java`, `Product.java`와 같이 직접 코드를 작성하고 `@Entity` 어노테이션을 붙여서 관리하는 클래스입니다.

`@JoinTable`이 생성하는 연결 테이블은 다음과 같은 특징을 가집니다.

- **비즈니스 로직 없음**: 이 테이블은 단순히 `member_id`와 `product_id`를 연결하는 역할을 할 뿐, 별도의 비즈니스 로직을 가질 필요가 없습니다.
- **고유한 식별자 없음**: 주 엔티티들처럼 단일 기본 키(Primary Key)를 가지는 것이 아니라, 두 외래 키의 조합으로 이루어진 복합 키(Composite Key)를 가집니다.
- **직접적인 조작 대상이 아님**: 개발자가 코드로 `join_table` 객체를 생성하거나 수정하는 경우는 없습니다. JPA가 자동으로 관리하며, `Member` 객체에서 `Product` 객체를 추가/제거할 때 간접적으로 조작됩니다.

요약하자면, `@JoinTable`은 **데이터베이스 구조를 정의하는 설정**이지, 비즈니스 로직을 담는 **객체(엔티티)를 정의하는 코드**가 아닙니다. 엔티티는 개발자가 직접 만들어서 관리하는 비즈니스 객체이고, `@JoinTable`은 그런 객체들을 DB에 어떻게 매핑할지를 JPA에게 알려주는 역할을 합니다.
