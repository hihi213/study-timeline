## 정리

람다(Lambda)는 **이름이 없는 일회용 함수**이며, 코드를 훨씬 간결하게 만들어주는 문법입니다.

'함수'는 보통 이름이 있지만(`doSomething()`), 람다는 이름 없이 **"이러한 입력이 들어오면, 이러한 처리를 해"** 라는 로직(Logic)만 있는 작은 코드 조각입니다.

---

### 1) 부족 포인트 스캔 (놓쳤을 수 있는 관점)

- **'함수'를 값처럼 취급:** 함수나 로직 자체를 **변수에 저장하거나, 다른 함수의 인자로 전달**할 수 있다는 함수형 프로그래밍(Functional Programming)의 핵심 개념을 놓치고 있습니다. 람다는 이 개념을 구현하는 도구입니다.
- **익명 클래스(Anonymous Class)의 불편함:** 람다가 등장하기 전에는 일회용 로직을 구현하기 위해 매번 '익명 클래스'라는 길고 복잡한 문법을 사용해야 했습니다. 람다가 이 불편함을 해결하기 위해 나왔다는 배경을 모르고 있습니다.
- **선언형 vs. 명령형:** 람다와 스트림은 "무엇을(What) 원하는지"에 집중하는 **선언형** 코드 스타일을 가능하게 합니다. `for`문으로 "어떻게(How) 할지" 절차를 하나하나 지시하는 **명령형** 스타일과의 차이점을 인지하지 못하고 있습니다.

### 2) 핵심 개념 요약

- **람다 표현식 (Lambda Expression) 🐑:**
    - **정의:** 이름 없이 실행할 수 있는 코드 블록(함수)입니다. 다른 함수의 인자로 전달하거나 변수에 저장할 수 있습니다.
    - **기본 구조:** `(파라미터) -> { 실행할 코드 }`
        - `( )`: 함수에 전달될 입력값(파라미터) 목록.
        - `->`: "이 파라미터를 가지고 오른쪽 코드를 실행하라"는 의미의 화살표.
        - `{ }`: 실제 실행될 로직.
- **익명 함수 (Anonymous Function):**
    - 람다의 다른 이름입니다. `doSomething()`처럼 이름이 정해진 함수가 아니라, 이름이 없는 일회용 함수라는 의미를 강조합니다.
- **함수형 인터페이스 (Functional Interface):**
    - 람다를 사용하기 위한 '틀'의 역할을 하는 인터페이스입니다. **단 하나의 추상 메서드만**을 가지고 있어야 한다는 규칙이 있습니다.
    - `Runnable`의 `run()`, `Comparator`의 `compare()` 등이 대표적인 예입니다. 람다 표현식은 이 단 하나의 메서드를 구현하는 코드가 됩니다.

---

### 3) 용어 매핑

- **람다 (Lambda)**: **"이름 없는 함수(Anonymous Function)"**를 간결하게 표현하는 문법.
- **`->`**: 람다 표현식의 핵심 기호로, **"goes to"** 라고 읽기도 합니다. 파라미터와 실행부를 구분합니다.
- **람다를 사용하는 이유**: **불필요한 클래스 선언 없이 로직(코드 조각)만 깔끔하게 전달**하기 위함입니다.

---

### 4) 사고 틀 & 판단 기준 (람다의 진화 과정)

"버튼을 클릭하면 'Hello'를 출력한다"는 간단한 로직을 예로 들어보겠습니다.

- **1. 람다 이전 (익명 클래스 방식)**
    - **문제점:** 단지 `System.out.println("Hello");` 한 줄을 실행하기 위해 너무 많은 부가적인 코드가 필요해 지저분합니다.

    ``` Java

    button.setOnClickListener(new OnClickListener() {
        @Override
        public void onClick(View view) {
            System.out.println("Hello");
        }
    });
    ```
    
- **2. 람다 사용 방식**
    - **장점:** 불필요한 클래스 선언과 메서드 이름을 모두 생략하고, **오직 핵심 로직만** 남겨 매우 간결하고 직관적입니다.

    ```Java
    button.setOnClickListener(view -> System.out.println("Hello"));
    ```

> 판단 기준:
>
> 다른 메서드의 인자로 **'실행 가능한 코드 조각(로직)'**을 넘겨줘야 하는 상황인가?
>
> → 그렇다면, 길고 복잡한 익명 클래스 대신 람다를 사용하는 것이 거의 항상 더 좋은 선택입니다.

### 5) 체크 질문 (자가 점검)

1. 람다는 고유한 이름을 가지고 있나요?
2. `x -> x * 2` 라는 람다 표현식이 있다면, 이것은 어떤 일을 하는 코드 조각일까요?
3. `for`문을 사용하는 것과 비교했을 때, 리스트의 데이터를 처리하기 위해 람다와 스트림을 사용하는 것의 가장 큰 장점은 무엇일까요? (힌트: 가독성, 선언형)
4. 람다 표현식을 사용하려면, 그 람다가 구현해야 할 인터페이스는 몇 개의 추상 메서드를 가져야 하나요?
