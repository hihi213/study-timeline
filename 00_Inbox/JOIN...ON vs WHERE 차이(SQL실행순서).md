## 정리
### 1) 부족 포인트 스캔

- **실행 순서:** SQL(JPQL)의 실행 순서를 머릿속에 그리지 않고, 두 키워드를 단순히 ‘조건을 거는 곳’이라고만 생각하고 있습니다. **`ON`이 `WHERE`보다 먼저 실행**된다는 점이 핵심입니다.
- **키워드의 역할:** `ON`은 **‘테이블을 어떻게 붙일지(Join)’**에 대한 규칙이고, `WHERE`는 그렇게 붙여서 완성된 **‘결과물 전체를 어떻게 필터링할지’**에 대한 규칙입니다. 역할 자체가 다릅니다.
- **`NULL`의 생성과 소멸:** `LEFT JOIN`은 `ON` 조건에 맞는 짝이 없을 때 `NULL`을 **생성**하는 단계입니다. 반면 `WHERE`는 그렇게 생성된 `NULL`을 조건으로 평가하고, 조건에 맞지 않으면 해당 행을 **제거(소멸)**하는 단계입니다.
- **임시 결과물:** `FROM`과 `JOIN`(+`ON`)을 거쳐 하나의 거대한 가상 테이블(임시 결과물)이 만들어지고, `WHERE`는 이 가상 테이블을 상대로 동작한다는 개념을 놓치고 있습니다.

### 2) 핵심 개념 요약

- **`ON` 절 (Join Condition):** 테이블을 ‘연결하는 시점’에 사용되는 조건입니다. `LEFT JOIN`에서는 왼쪽 테이블의 모든 행을 일단 살려두고, `ON` 조건을 만족하는 오른쪽 테이블의 행만 가져와 붙입니다. 만족하는 행이 없으면 `NULL`을 붙입니다.
- **`WHERE` 절 (Filtering Condition):** 테이블 연결이 **모두 끝난 후**, 최종 결과 집합에 대한 필터링 조건입니다. `FROM`과 `JOIN`으로 만들어진 결과 전체를 대상으로 조건을 검사하며, `false`나 `unknown`(주로 `NULL`과의 비교)으로 판정되는 행을 버립니다.
- **논리적 실행 순서 (Logical Query Processing Order):** SQL이 쿼리를 해석하고 실행하는 논리적인 순서는 다음과 같습니다.
    
    1. `FROM`: 대상 테이블을 가져온다.
    2. `ON`: `JOIN`할 테이블을 `ON` 조건에 맞춰 연결한다. (`LEFT JOIN`은 이때 `NULL`을 생성)
    3. `JOIN`: `ON` 조건에 따라 테이블을 합친다.
    4. `WHERE`: 합쳐진 결과물에서 조건에 맞지 않는 행을 버린다.
    5. `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` ... (이후 단계 생략)
        
- **3치 논리 (Three-Valued Logic):** SQL의 조건절은 `TRUE`, `FALSE` 외에 `UNKNOWN`이라는 제3의 값을 가집니다. `WHERE t.name = 'Dev'` 같은 조건에서 `t.name`이 `NULL`이면, 이 비교의 결과는 `FALSE`가 아닌 `UNKNOWN`이 되고, `WHERE` 절은 `TRUE`인 행만 남기므로 결국 해당 행은 탈락합니다.

### 3) 용어 매핑

- **"ON에서 필터"**: 정확히는 **조인 대상을 한정하는 조건**입니다. "어떤 행을 옆에 붙일 것인가"를 결정합니다.
- **"WHERE에 조건"**: 조인이 끝난 **최종 결과 집합에 대한 필터링 조건**입니다. "어떤 행을 최종적으로 남길 것인가"를 결정합니다.
- **"내부 조인처럼 줄어든다"**: `LEFT JOIN`으로 생성된 `NULL`을 포함한 행이, `WHERE` 절의 필터 조건(`t.name = 'Dev'`)을 통과하지 못해 **결과적으로 제거되는 현상**을 의미합니다.

### 4) 사고 틀 & 판단 기준

쿼리를 짤 때, 이렇게 생각하세요.

1. **1단계 (연결): "일단, 모든 멤버(왼쪽)는 다 보여줘야지."**
    
    - 어떤 멤버 옆에는 팀 정보를 붙이고, 어떤 멤버 옆에는 안 붙일 건가? 이 **'붙이는 규칙'**을 `ON`에 적습니다.
    - 예: `ON t.name = 'Dev'` → "팀 이름이 'Dev'인 팀만 옆에 붙일 자격이 있다. 나머지는 `NULL` 처리해."
        
2. **2단계 (필터링): "이제, 그렇게 연결된 목록 전체에서 최종적으로 보고 싶은 것만 고르자."**
    
    - `NULL`이 포함된 거대한 중간 결과물이 나왔습니다. 여기서 **'최종적으로 탈락시킬 조건'**을 `WHERE`에 적습니다.
    - 예: `WHERE t.name = 'Dev'` → "팀 이름 컬럼(t.name)이 'Dev'가 아닌 행은 전부 버려라." (`NULL`인 행도 당연히 버려집니다.)

| **판단 기준**                                   | **어디에 쓸까?**          |
| ------------------------------------------- | -------------------- |
| `LEFT JOIN`의 기준 테이블(왼쪽)은 모두 유지하고 싶다.        | 조건을 **`ON`**에 쓴다.    |
| 조인 결과와 상관없이, 최종 결과물에서 특정 조건을 만족하는 행만 보고 싶다. | 조건을 **`WHERE`**에 쓴다. |
