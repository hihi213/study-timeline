# 오라클 DB 기반 도서 관리 시스템 구축

## 1. 프로젝트 개요 (Introduction)

- **프로젝트명:** Oracle DB와 Java Swing을 연동한 도서 관리 시스템 (Library Management System)
- **개발 목적:**
    - 관계형 데이터베이스(RDBMS)의 정규화된 테이블 설계 및 구현
    - PL/SQL(Function, Procedure, Trigger)을 활용한 비즈니스 로직의 DB 계층 구현
    - JDBC를 이용한 Java 애플리케이션과 오라클 DB 간의 연동 실습
- **개발 환경:**
    - OS: macOS (or Windows)
    - DB: Oracle Database 11g XE (or 18c/21c)
    - Language: Java (JDK 17), SQL, PL/SQL
    - Tool: Oracle SQL Developer, IntelliJ (or Eclipse)

### 2.2. 테이블 명세서 (Physical Data Model)

> 구현한 3개의 테이블에 대한 상세 정의입니다. 보고서 표로 만드세요.

#### 1. 회원 테이블 (TBL_MEMBER)

| 컬럼 ID    | 컬럼명(한글) | 데이터 타입        | Null 여부 | KEY | 설명               |
| :------- | :------ | :------------ | :------ | :-- | :--------------- |
| MEM_NO   | 회원번호    | NUMBER        | N       | PK  | 시퀀스 자동생성         |
| MEM_ID   | 아이디     | VARCHAR2(30)  | N       | UQ  | 로그인 ID           |
| MEM_PW   | 비밀번호    | VARCHAR2(200) | N       |     | 암호화 저장 (SHA-256) |
| MEM_NAME | 이름      | VARCHAR2(20)  | N       |     |                  |
| MEM_TEL  | 전화번호    | VARCHAR2(20)  | Y       |     |                  |

#### 2. 도서 테이블 (TBL_BOOK)

| 컬럼 ID   | 컬럼명(한글) | 데이터 타입        | Null 여부 | KEY | 설명                          |
| :------ | :------ | :------------ | :------ | :-- | :-------------------------- |
| BOOK_NO | 도서번호    | NUMBER        | N       | PK  | 시퀀스 자동생성                    |
| TITLE   | 제목      | VARCHAR2(100) | N       |     |                             |
| AUTHOR  | 저자      | VARCHAR2(50)  | Y       |     |                             |
| RENT_YN | 대여상태    | CHAR(1)       | N       |     | Default 'N', Check('Y','N') |

#### 3. 대여 테이블 (TBL_RENT)

| 컬럼 ID     | 컬럼명(한글) | 데이터 타입 | Null 여부 | KEY | 설명                |
| :-------- | :------ | :----- | :------ | :-- | :---------------- |
| RENT_NO   | 대여번호    | NUMBER | N       | PK  | 시퀀스 자동생성          |
| MEM_NO    | 회원번호    | NUMBER | N       | FK  | TBL_MEMBER 참조     |
| BOOK_NO   | 도서번호    | NUMBER | N       | FK  | TBL_BOOK 참조       |
| RENT_DATE | 대여일     | DATE   | N       |     | Default SYSDATE   |
| RTN_DUE   | 반납예정일   | DATE   | N       |     | Default SYSDATE+7 |
| RTN_DATE  | 실반납일    | DATE   | Y       |     | 반납 전 NULL         |

## 3. 주요 기능 구현 및 DB 객체 설명 (Implementation Logic)

> 단순 SQL이 아니라 **PL/SQL을 사용한 이유**를 적는 것이 핵심 포인트입니다.

**1) 보안 및 유틸리티 (Function)**

- **비밀번호 암호화 (`FUNC_ENCRYPT_PW`):**
    - `DBMS_CRYPTO` 패키지를 사용하여 SHA-256 알고리즘으로 단방향 암호화 적용.
    - 보안성을 높이기 위해 평문 저장을 방지함.
- **연체료 계산 (`FUNC_CALC_LATE_FEE`):**
    - 반납 여부(NULL)에 따라 `NVL` 함수를 사용해 현재 날짜와 반납 예정일을 비교.
    - 연체가 아닐 경우(음수) 0을 반환하도록 로직 처리.
        

**2) 비즈니스 로직 처리 (Procedure & Transaction)**

- **도서 대여 (`PROC_RENT_BOOK`):**
    - 도서 상태 변경(`UPDATE`)과 대여 이력 생성(`INSERT`)이 동시에 이루어져야 하므로 **트랜잭션(Transaction)**으로 묶어 데이터 무결성 보장.
- **도서 반납 (`PROC_RETURN_BOOK`):**
    - `TBL_RENT`에서 현재 대여 중(반납일이 NULL)인 기록을 찾아 반납 처리.
    - 반납과 동시에 연체일수를 계산하여 **OUT 파라미터**로 반환.
        

**3) 데이터 조회 (View)**

- **도서 목록 뷰 (`V_BOOK_LIST`):**
    - `TBL_BOOK`과 `TBL_RENT`를 `LEFT JOIN`하여 도서 정보와 대여 정보를 결합.
    - 복잡한 조인 쿼리를 뷰로 캡슐화하여 애플리케이션에서는 단순 조회(`SELECT *`)만 하도록 설계.

1. **"왜 굳이 프로시저를 썼는가?"**
    
    - "대여 기능은 `UPDATE`와 `INSERT`가 반드시 같이 성공해야 하는 작업이므로, 자바에서 두 번 쿼리를 날리는 것보다 DB 내에서 **트랜잭션(COMMIT)**까지 한 번에 처리하는 것이 데이터 무결성에 안전하다고 판단했습니다." (이 멘트 들어가면 A+입니다.)
        
2. **"뷰(View)의 사용 이유"**
    
    - "자바 코드 내에 복잡한 JOIN 쿼리가 들어가면 가독성이 떨어지므로, DB에 뷰를 생성하여 자바 코드를 간결하게 유지했습니다."
