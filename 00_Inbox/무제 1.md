## Topic 1. 기초 정렬 알고리즘 (Basic Sorts)

효율적인 정렬을 배우기 전, 가장 직관적이고 구현이 쉬운 **기초 정렬($O(N^2)$)** 3대장과 이를 개선한 쉘 정렬을 먼저 이해해야 합니다.

|**알고리즘**|**평균 시간**|**최악 시간**|**공간 복잡도**|**핵심 전략**|**비고**|
|---|---|---|---|---|---|
|**선택 (Selection)**|$O(N^2)$|$O(N^2)$|$O(1)$|**최솟값 선택** 후 맨 앞과 교환|교환 횟수가 가장 적음 (데이터 이동 비용 클 때 유리)|
|**삽입 (Insertion)**|$O(N^2)$|$O(N^2)$|$O(1)$|적절한 위치를 찾아 **끼워 넣기**|**거의 정렬된 데이터에서 최강 ($O(N)$)**|
|**버블 (Bubble)**|$O(N^2)$|$O(N^2)$|$O(1)$|**인접 요소 비교** 및 교환|구현이 제일 쉬우나 교환이 너무 빈번함|
|**쉘 (Shell)**|$O(N^{1.5})$|$O(N^2)$|$O(1)$|**간격(Gap)**을 두고 삽입 정렬 수행|삽입 정렬의 약점(역순 이동) 보완|

### 1. 선택 정렬 (Selection Sort)

> **"가장 작은 놈을 찾아 맨 앞으로 보낸다."**

- **원리:**
    
    1. 리스트 전체를 훑어 **최솟값(Min)**을 찾는다.
    2. 그 최솟값을 리스트의 **맨 앞(Current)** 값과 교환(Swap)한다.
    3. 맨 앞을 제외한 나머지 영역에서 이를 반복한다.
        
- **특징:** 비교 횟수는 많지만, **교환(Swap) 횟수가 $N-1$번으로 고정**되어 있어 쓰기(Write) 비용이 비싼 경우 유리합니다.
    

C

```c
void selection_sort(int list[], int n) {
    int i, j, least, temp;
    // 마지막 원소 하나 남을 때까지 반복 (n-1)
    for (i = 0; i < n - 1; i++) {
        least = i; // 현재 위치를 최솟값 인덱스로 가정
        // 진짜 최솟값 탐색
        for (j = i + 1; j < n; j++) {
            if (list[j] < list[least]) least = j;
        }
        // 최솟값과 현재 위치(i) 교환
        if (i != least) SWAP(list[i], list[least], temp);
    }
}
```

### 2. 삽입 정렬 (Insertion Sort)

> **"카드 게임할 때 손에 쥔 카드를 정리하는 방법."**

- **원리:**
    
    1. 두 번째 원소부터 시작하여, 앞(왼쪽)의 정렬된 부분과 비교한다.
    2. 자신이 들어갈 위치를 찾을 때까지 앞의 원소들을 **뒤로 한 칸씩 민다(Shift).**
    3. 빈 자리에 자신을 꽂아 넣는다.
        
- **특징:** **이미 정렬된 상태**라면 `while`문이 돌지 않아 **$O(N)$**의 성능을 냅니다.
    

C

```c
void insertion_sort(int list[], int n) {
    int i, j, key;
    // 1번 인덱스(두 번째)부터 시작
    for (i = 1; i < n; i++) {
        key = list[i]; // 현재 삽입할 값 복사
        // 정렬된 앞부분(i-1)부터 역순으로 비교하며 밀어내기
        for (j = i - 1; j >= 0 && list[j] > key; j--) {
            list[j + 1] = list[j]; // 오른쪽으로 한 칸 이동
        }
        list[j + 1] = key; // 빈 자리에 삽입
    }
}
```

### 3. 버블 정렬 (Bubble Sort)

> **"인접한 두 놈끼리 싸워서 큰 놈이 뒤로 간다."**

- **원리:** 인접한 두 원소를 비교하여 앞의 원소가 크다면 교환합니다. 한 스캔이 끝나면 가장 큰 원소가 맨 뒤에 고정됩니다.
- **특징:** 구현은 가장 단순하지만, 교환(Swap)이 너무 빈번해 성능이 떨어집니다.
    

C

```c
void bubble_sort(int list[], int n) {
    int i, j, temp;
    for (i = n - 1; i > 0; i--) { // 고정될 뒷부분부터 줄여나감
        for (j = 0; j < i; j++) {
            // 인접 요소 비교 및 교환
            if (list[j] > list[j + 1]) 
                SWAP(list[j], list[j + 1], temp);
        }
    }
}
```

### 4. 쉘 정렬 (Shell Sort)

> **"삽입 정렬의 업그레이드 버전: 멀리 있는 것부터 정리하자."**

- **빌드업 (Why?):** 삽입 정렬은 작은 값이 맨 뒤에 있으면, 맨 앞까지 오기 위해 $N$번의 이동(Shift)을 해야 하는 치명적 단점이 있습니다.
- **원리:**
    
    1. **간격(Gap)**을 설정하여 리스트를 듬성듬성 나눕니다. (예: Gap = N/2)
    2. 나눠진 부분 리스트들에 대해 **삽입 정렬**을 수행합니다.
    3. 간격을 절반으로 줄여가며 반복하다가, Gap=1이 되면 일반 삽입 정렬로 마무리합니다.
        
- **효과:** Gap=1이 되었을 때, 데이터는 이미 **'거의 정렬된 상태'**가 되어 있으므로 삽입 정렬의 효율이 극대화됩니다.
    

C

```c
// 간격(gap)만큼 떨어진 요소들을 삽입 정렬하는 함수
void inc_insertion_sort(int list[], int first, int last, int gap) {
    int i, j, key;
    for (i = first + gap; i <= last; i = i + gap) {
        key = list[i];
        // gap만큼 점프하며 비교 및 이동
        for (j = i - gap; j >= first && list[j] > key; j = j - gap) {
            list[j + gap] = list[j];
        }
        list[j + gap] = key;
    }
}

void shell_sort(int list[], int n) {
    int i, gap;
    // 간격을 절반씩 줄여가며 수행
    for (gap = n / 2; gap > 0; gap = gap / 2) {
        if ((gap % 2) == 0) gap++; // 간격은 홀수가 좋다는 경험적 법칙
        // 각 부분 리스트에 대해 삽입 정렬 수행
        for (i = 0; i < gap; i++) {
            inc_insertion_sort(list, i, n - 1, gap);
        }
    }
}
```

### 💡 Interview (기초 정렬 편)

> [!faq]Q. 삽입 정렬(Insertion Sort)이 가장 효율적인 경우는 언제인가?
>
> 🗣️ **핵심 답변**
>
> 데이터가 **이미 거의 정렬되어 있을 때(Nearly Sorted)** 입니다. 이때는 비교만 하고 이동(Shift) 연산이 거의 발생하지 않아 시간 복잡도가 **$O(N)$**에 가까워집니다. 따라서 데이터 개수가 적거나 정렬 상태가 좋을 때는 퀵 정렬보다 빠를 수 있습니다.

> [!faq]Q. 선택 정렬(Selection Sort)과 버블 정렬(Bubble Sort) 중 실제 성능이 더 좋은 것은?
>
> 🗣️ **핵심 답변**
>
> 둘 다 $O(N^2)$이지만, 일반적으로 선택 정렬이 더 좋습니다.
>
> 버블 정렬은 매번 자료 교환(Swap)이 발생하지만, 선택 정렬은 최솟값을 찾은 후 한 번만 교환하기 때문입니다. 쓰기(Write) 동작이 읽기(Read)보다 비용이 큰 시스템(예: Flash Memory)에서는 선택 정렬이 선호됩니다.

## Topic 2. 분할 정복(Divide & Conquer) 전략

$O(N^2)$의 한계를 넘기 위해, 문제를 잘게 쪼개서 해결하는 **분할 정복** 기법이 도입되었습니다. 대표적인 두 정렬 알고리즘은 **"어디에 힘을 주는가?"**에 따라 구분됩니다.

|**알고리즘**|**핵심 전략**|
|---|---|
|**1. 합병 정렬**<br><br>  <br><br>(Merge Sort)|**Combine이 핵심:**<br><br>  <br><br>일단 끝까지 쪼갠(Divide) 뒤, **올라오면서(Combine)** 작은 값을 먼저 넣는 정렬을 수행함.|
|**2. 퀵 정렬**<br><br>  <br><br>(Quick Sort)|**Divide가 핵심:**<br><br>  <br><br>미리 기준(Pivot)을 잡아 **나누고(Divide)** 들어감. (이미 정리되어 내려가므로 Combine 과정이 거의 없음)<br><br>  <br><br>pivot 왼쪽은 작은 집합, 오른쪽은 큰 집합이 됨.|

## Topic 3. 효율적인 정렬 알고리즘 ($O(N \log N)$)

분할 정복과 자료구조(Heap)를 활용하여 성능을 최적화한 정렬들입니다.

|**알고리즘**|**평균 시간**|**최악 시간**|**공간 복잡도**|**핵심 메커니즘**|**비고**|
|---|---|---|---|---|---|
|**합병 (Merge)**|$O(N \log N)$|**$O(N \log N)$**|$O(N)$|**분할 정복** (물리적 절반 분할)|**Stable**, 추가 메모리 필요|
|**퀵 (Quick)**|$O(N \log N)$|**$O(N^2)$**|$O(\log N)$|**피벗(Pivot)** 기준 분할|이미 정렬된 경우 최악, **Unstable**|
|**힙 (Heap)**|$O(N \log N)$|$O(N \log N)$|$O(1)$|**완전 이진 트리** (Heapify)|추가 메모리 X, **Unstable**|
|**기수 (Radix)**|**$O(dN)$**|$O(dN)$|$O(N+R)$|**자릿수(Digit)** 기준 버킷|**비교 연산 X**, 큐(Queue) 사용|

### 🔍 주요 포인트 및 주의사항

- **합병 정렬 (Merge Sort)**
    - 임시 배열(`sorted`)로 데이터를 복사/이동하는 과정에서 오버헤드가 발생하여, 일반 배열에서는 퀵 정렬보다 느린 경우가 많습니다.
    - 단, **연결 리스트(Linked List)** 정렬 시에는 인덱스 접근 없이 링크만 바꾸면 되므로 퀵 정렬보다 효율적일 수 있습니다.
- **퀵 정렬 (Quick Sort)**
    - **최악의 경우:** 이미 정렬된 데이터에서 첫 번째 요소를 피벗으로 잡으면 분할이 `1 : N-1`로 일어나 재귀 깊이가 깊어지고 시간 복잡도가 $O(N^2)$이 됩니다.
- **힙 정렬 (Heap Sort)**
    - 삭제 로직(Tip): 루트(최댓값)를 빼고 **맨 마지막 노드를 루트로 올린 뒤** 자식과 비교하며 내려가는 과정(Down-Heap)을 기억해야 합니다.
- **재귀 vs 반복**
    - **재귀(Recursion):** 코드가 간결(퀵, 합병)하지만 스택 오버헤드 발생.
    - **반복(Iteration):** 성능이 좋고 메모리 효율적이지만 구현이 복잡할 수 있음.
