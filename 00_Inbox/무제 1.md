### 1. 컴퓨터 시스템의 3계층 구조:
소프트웨어의 실행 환경은 역할에 따라 계층화되어 있습니다.

| **계층**        | **구성 요소**              | **주요 역할**                           |
| ------------- | ---------------------- | ----------------------------------- |
| **애플리케이션**    | 웹 브라우저, CGI 프로그램 등     | 사용자의 특정 목적(비즈니스 로직)을 수행하는 최상위 소프트웨어 |
| **시스템 소프트웨어** | 운영체제(OS), 컴파일러 등       | 하드웨어 자원을 관리하고 애플리케이션에 실행 환경을 제공     |
| **하드웨어**      | CPU(Machine), Memory 등 | 물리적 연산 및 데이터 저장을 수행하는 기계 장치         |


>  애플리케이션과 운영체제는 모두 '소프트웨어'에 해당하지만, 운영체제는 하드웨어를 직접 제어한다는 점에서 애플리케이션과 차이가 있습니다.
> cpu는 Machine, 운영체제는 Os라고도 한다.
> **기계어(Machine Code):** CPU가 직접 해석하고 실행할 수 있는 유일한 언어입니다.
### 2. 플랫폼 (Platform): 하드웨어+ 시스템 소프트웨어
애플리케이션이 실행되기 위해 필요한 두 계층, 하드웨어(CPU)와 시스템 소프트웨어(OS)을 의미한다. 프로그램의 코드가 실제 하드웨어 자원(메모리, 연산 장치 등)을 사용할 수 있도록 인터페이스를 제공합니다.
- **CPU** : 하드웨어의 핵심
	- **기계어(Machine Code):** CPU가 직접 해석하고 실행할 수 있는 유일한 언어입니다. (cpu를 marchine이라고 부른다)
	- **ISA(Instruction Set Architecture):** CPU 아키텍처(x86, ARM 등)에 따라 인식할 수 있는 기계어 명령어 집합이 다릅니다.
- **운영체제 (OS):** 시스템소프트웨어의 핵심
	- 하드웨어 자원을 관리하고 응용 프로그램에 **API(System Call)**를 제공합니다.
	- **추상화:** 복잡한 하드웨어 제어 로직을 소프트웨어적으로 단순화하여 제공합니다.
	- **시스템 호출 (System Call):** 애플리케이션이 하드웨어 자원(파일 읽기, 메모리 할당 등)을 사용하기 위해 OS에 요청하는 인터페이스입니다.
	- **플랫폼 차이:** 설령 동일한 CPU를 사용하더라도, **Windows와 Linux는 시스템 호출의 규격과 API가 완전히 다르기 때문**에 프로그램의 호환성이 보장되지 않습니다.


### 3. 네이티브 코드 (Native Code)

특정 플랫폼(CPU+OS)의 기계어로 번역되어, 별도의 해석기 없이 **즉시 실행 가능한 이진 코드(Binary Code)**입니다.

- **특징:** 실행 속도가 가장 빠르지만, 해당 플랫폼에 **강하게 결합(Tightly Coupled)**되어 있습니다.
- **종속성:** 특정 OS의 시스템 호출과 특정 CPU의 명령어 셋을 직접 포함합니다.




C언어는 **네이티브 코드(기계어)**를 생성합니다.
