## 🚀 웹 서비스의 진화: 정적 문서에서 동적 프로세스로

### 1. 패러다임의 전환: 리소스 요청에서 기능 호출로

초기 웹과 현대 웹은 서버가 클라이언트의 요청을 처리하는 목적과 방식에서 근본적인 차이를 보입니다.

- **정적 웹 (Static Web):** 클라이언트가 서버 하드디스크에 존재하는 특정 파일의 경로를 요청하면, 서버는 해당 파일을 가공 없이 복사하여 전송합니다. (데이터의 1:1 매핑)
- **현대 웹 (Dynamic Service):** 클라이언트가 특정 매개변수(Parameter)와 함께 기능을 요청하면, 서버는 내부의 로직을 작동시켜 실시간으로 생성된 **결과값**을 응답합니다. (데이터의 실시간 생성)
    

---

### 2. 서버 사이드 로직(Server-side Logic)의 도입

단순 송수신을 넘어선 '서비스'를 구현하기 위해 서버 환경에 실행 로직이 배치되었습니다.

- **프로세스 중심의 통신:** 서버는 이제 파일 시스템(File System)뿐만 아니라 **데이터베이스(DBMS)** 및 **런타임 엔진(Runtime Engine)**과 상호작용합니다.
- **실행 흐름:**
    
    1. **Input:** 클라이언트로부터 전달된 데이터(Query String, Form Data 등)를 수신합니다.
    2. **Processing:** 서버 내부 로직이 수신된 데이터를 바탕으로 연산, 검증, 데이터베이스 조회 등을 수행합니다.
    3. **Output:** 연산 결과를 규격화된 문서 형식(HTML, JSON 등)으로 즉석에서 생성(Generation)하여 반환합니다.
        

---

### 3. CGI (Common Gateway Interface): 동적 웹의 기술적 시초

웹 서버가 외부 프로그램과 통신하여 동적인 결과물을 생성하기 위해 정의된 최초의 표준 인터페이스 규격입니다.

- **기술적 정의:** 웹 서버(Web Server)와 외부 애플리케이션 간에 데이터를 주고받는 통로 역할을 수행합니다.
- **작동 메커니즘:**
    - **표준 입력/출력 (Standard I/O):** 웹 서버는 클라이언트의 요청 정보를 환경 변수나 표준 입력을 통해 외부 프로그램에 전달합니다.
    - **프로세스 생성:** 외부 프로그램은 요청을 처리한 후 결과물을 표준 출력으로 웹 서버에 되돌려줍니다.
- **의의:** 웹 서버 자체가 모든 기능을 수행할 필요 없이, 외부의 C, Perl, Python 등의 언어로 작성된 프로그램을 호출하여 기능을 확장할 수 있게 되었습니다.
    

---

### 4. 확장된 기능적 특징 (핵심 추가)

- **상태 비저장(Stateless)의 극복:** 정적 웹은 매 요청이 독립적이었으나, 서버 측 로직이 도입되면서 세션(Session)이나 데이터베이스를 활용해 사용자의 상태를 유지하고 관리할 수 있게 되었습니다.
- **입력 기반의 가변성:** 동일한 URL 주소라도 클라이언트가 전달하는 입력값에 따라 서버가 매번 다른 결과물을 생성하여 응답합니다.
- **데이터의 동적 결합:** 서버 하드디스크에 저장된 '완성된 문서'가 아니라, 데이터베이스의 정보와 로직이 결합된 '실시간 문서'가 전송됩니다.
    

---

### 💡 학습 포인트 요약

1. **변화의 핵심:** 웹 서버의 역할이 **파일 전달자(File Provider)**에서 **애플리케이션 실행기(Application Executor)**로 확장되었습니다.
2. **CGI의 역할:** 웹 서버가 독립적인 외부 프로그램을 실행할 수 있도록 연결해 주는 **표준 인터페이스**입니다.
3. **결과물:** 이제 서버는 저장된 파일을 주는 것이 아니라, 코드를 실행한 **연산 결과**를 응답으로 생성합니다.
