교수님께서 **"VPD와 FGA 같은 고급 기능은 XE 버전에서 안 되니, 뷰와 트리거로 이렇게 구현한다"**라고 설명하신 부분은 **서술형이나 코드 빈칸 채우기 문제**로 출제될 확률이 매우 높습니다.
### 1. 🔐 VPD 대체 구현: "내 정보만 보고, 내 정보만 수정하자"

**핵심:** Oracle Enterprise의 VPD(행 단위 보안)를 **뷰(조회 제한)**와 **트리거(수정 제한)** 조합으로 흉내 내는 것입니다

#### **① 조회 제한 (View)**

- **원리:** `WHERE` 절에 현재 접속한 사용자(`USER`)와 테이블의 주인 ID(`login_id`)가 같은지 비교합니다.
- **시험 포인트:** `USER` 키워드와 `WHERE` 절 조건.

```SQL
CREATE OR REPLACE VIEW vw_my_profile AS
SELECT * FROM employee2
WHERE login_id = USER; -- 현재 접속자(USER)와 login_id가 같은 행만 노출 [cite: 1462]
```

#### **② 수정 제한 (Trigger)**

- **원리:** 뷰를 통해 조회를 막아도, SQL로 직접 `UPDATE`를 시도할 수 있습니다. 이를 막기 위해 **트리거**에서 `:OLD.login_id` (데이터 주인)와 `USER` (접속자)를 비교합니다.
- **시험 포인트:** `IF` 조건문과 `RAISE_APPLICATION_ERROR` (강제 에러 발생).

```SQL
CREATE OR REPLACE TRIGGER trg_emp_self_update
    BEFORE UPDATE OR DELETE ON employee2 -- 수정/삭제 시도 전
    FOR EACH ROW
BEGIN
    -- 접속자(USER)가 데이터 주인(:OLD.login_id)이 아니면 에러 발생
    IF USER <> :OLD.login_id THEN
        RAISE_APPLICATION_ERROR(-20001, '자신의 정보만 수정할 수 있습니다.');
    END IF;
END;
/
```

### 2. 🕵️‍♀️ FGA 대체 구현: "특정 조건일 때만 몰래 기록하자"

**핵심:** Oracle Enterprise의 FGA(정밀 감사)를 **로그 테이블**과 **조건부 트리거**로 흉내 내는 것입니다

#### **① 로그 테이블 (Audit Log)**

- 감사 기록을 담을 그릇입니다.
- **필수 컬럼:** 누가(`username`), 언제(`access_time`), 무슨 짓을(`action_type`), 어떤 데이터를(`accessed_data`) 4.
    

#### **② 조건부 감시 트리거 (Smart Trigger)**

- **원리:** 모든 변경을 기록하면 로그가 너무 커집니다. **"연봉이 10,000을 넘을 때"** 처럼 특정 조건에서만 트리거가 발동하도록 합니다.
- **시험 포인트:** **`WHEN` 절** 사용법 (매우 중요). 트리거 내부 `IF`문이 아니라, 트리거 선언부의 `WHEN`을 써야 성능이 좋습니다.

```SQL
CREATE OR REPLACE TRIGGER trg_audit_salary_update
    AFTER UPDATE OF salary ON users -- 급여 컬럼이 변경된 후에만
    FOR EACH ROW
    WHEN (NEW.salary > 10000)       -- ★ 핵심: 변경 후 급여가 1만 초과일 때만 실행 [cite: 1855]
BEGIN
    -- 로그 테이블에 기록 (이전 값 -> 새로운 값)
    INSERT INTO audit_log (username, access_time, action_type, accessed_data)
    VALUES (USER, SYSDATE, 'UPDATE', :OLD.salary || ' -> ' || :NEW.salary);
END;
/
```

### 📝 시험장 가져갈 체크리스트 (이것만 외우세요!)

1. **VPD 대체 (View):** `WHERE login_id = USER`
2. **VPD 대체 (Trigger):** `IF USER <> :OLD.login_id THEN RAISE_APPLICATION_ERROR…`
3. **FGA 대체 (Trigger):** `WHEN (NEW.컬럼명 > 값)` (괄호 필수!)
4. **변수 구분:**
    
    - `:OLD.컬럼`: 변경 **전** 값 (누가 내 데이터를 건드리기 전 주인 확인용)
    - `:NEW.컬럼`: 변경 **후** 값 (연봉을 1억으로 올리는지 감시용)
