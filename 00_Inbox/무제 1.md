# 📘 Chapter 7: 고급 DB 오브젝트 (트리거, 뷰, 인덱스)

> [!NOTE]- 문제: 트리거 기본 생성 문법
> 
> SQL
> 
> ```
> CREATE OR REPLACE TRIGGER 트리거명
>     [BEFORE | AFTER] [INSERT | UPDATE | DELETE] ON 테이블명
>     FOR EACH ROW  -- :OLD, :NEW 사용 시 필수
> BEGIN
>     -- 로직 작성
> END;
> /
> ```

> [!NOTE]- 문제: 데이터 참조 변수 (:OLD, :NEW)
> 
> - **`:OLD.컬럼명`** : 변경 전 데이터
>     
> - **`:NEW.컬럼명`** : 변경 후 데이터
>     

> [!NOTE]- 문제: 작업 유형 조건문 (IF)
> 
> SQL
> 
> ```
> IF UPDATING THEN … END IF;
> IF DELETING THEN … END IF;
> IF INSERTING THEN … END IF;
> ```

> [!NOTE]- 문제: 조건부 트리거 (WHEN)
> 
> SQL
> 
> ```
> -- NEW에 콜론(:)을 붙이지 않는 것이 핵심
> … FOR EACH ROW WHEN (NEW.컬럼명 > 값)
> ```

> [!NOTE]- 문제: 강제 예외 발생 (차단)
> 
> SQL
> 
> ```
> RAISE_APPLICATION_ERROR(-20000, '에러 메시지');
> ```

> [!NOTE]- 문제: 행 수준 보안 뷰 (본인 데이터만 조회)
> 
> SQL
> 
> ```
> CREATE OR REPLACE VIEW 뷰이름 AS
> SELECT * FROM 테이블명
> WHERE 컬럼명 = USER; -- 접속한 유저와 일치하는 행만 조회
> ```

> [!NOTE]- 문제: 함수 기반 인덱스 (일부만 인덱싱)
> 
> SQL
> 
> ```
> CREATE INDEX 인덱스명 ON 테이블명(함수(컬럼명, 인자));
> -- 예: SUBSTR(주민번호, 1, 6)
> ```

> [!NOTE]- 문제: 부분 인덱스 (특정 조건만 인덱싱)
> 
> SQL
> 
> ```
> CREATE INDEX 인덱스명 ON 테이블명(컬럼명) WHERE 조건;
> -- 예: WHERE 전화번호 IS NOT NULL
> ```

> [!NOTE]- 문제: 리버스 키 인덱스 (값 분산)
> 
> SQL
> 
> ```
> CREATE INDEX 인덱스명 ON 테이블명(컬럼명) REVERSE;
> ```

# 📚 Chapter 8: 사용자 및 권한 관리

> [!NOTE]- 문제: 사용자 생성
> 
> SQL
> 
> ```
> CREATE USER 유저명 IDENTIFIED BY 비번 DEFAULT TABLESPACE 테이블스페이스명;
> ```

> [!NOTE]- 문제: 사용자 정보 조회 (관리자)
> 
> SQL
> 
> ```
> SELECT * FROM DBA_USERS WHERE account_status = 'OPEN';
> ```

> [!NOTE]- 문제: 자원 제한 활성화 (선행 작업)
> 
> SQL
> 
> ```
> ALTER SYSTEM SET RESOURCE_LIMIT = true;
> ```

> [!NOTE]- 문제: 프로파일 생성 (암호/자원 제한)
> 
> SQL
> 
> ```
> CREATE PROFILE 프로파일명 LIMIT
>     FAILED_LOGIN_ATTEMPTS 횟수
>     PASSWORD_LOCK_TIME 일수
>     PASSWORD_LIFE_TIME 일수
>     CPU_PER_SESSION 값
>     IDLE_TIME 분;
> ```

> [!NOTE]- 문제: 프로파일 적용
> 
> SQL
> 
> ```
> ALTER USER 유저명 PROFILE 프로파일명;
> ```

> [!NOTE]- 문제: 계정 잠금 해제
> 
> SQL
> 
> ```
> ALTER USER 유저명 ACCOUNT UNLOCK;
> ```

> [!NOTE]- 문제: 시스템 권한 부여 (접속, 생성 등)
> 
> SQL
> 
> ```
> GRANT 시스템권한 TO 유저명 [WITH ADMIN OPTION];
> ```

> [!NOTE]- 문제: 객체 권한 부여 (테이블 조회, 수정 등)
> 
> SQL
> 
> ```
> GRANT 객체권한 ON 객체명 TO 유저명 [WITH GRANT OPTION];
> ```

> [!NOTE]- 문제: 권한 회수
> 
> SQL
> 
> ```
> REVOKE 권한 FROM 유저명;
> -- 객체 권한 회수 시: REVOKE 객체권한 ON 객체명 FROM 유저명;
> ```

> [!NOTE]- 문제: 타 계정 객체 조회
> 
> SQL
> 
> ```
> SELECT * FROM 소유자명.테이블명;
> ```

> [!NOTE]- 문제: 롤 생성
> 
> SQL
> 
> ```
> CREATE ROLE 롤이름;
> ```

> [!NOTE]- 문제: 롤에 권한 추가
> 
> SQL
> 
> ```
> GRANT 권한 TO 롤이름;
> ```

> [!NOTE]- 문제: 사용자에게 롤 부여
> 
> SQL
> 
> ```
> GRANT 롤이름 TO 유저명;
> ```

> [!NOTE]- 문제: 권한/롤 확인 (데이터 사전)
> 
> - **`DBA_TAB_PRIVS`** : 테이블 권한 확인
>     
> - **`DBA_ROLE_PRIVS`** : 부여된 롤 확인
>

# 📘 Chapter 9: 감사(Audit) 및 암호화

> [!NOTE]- 문제: 감사 기능 활성화 (확장 모드)
> 
> SQL
> 
> ```
> ALTER SYSTEM SET AUDIT_TRAIL=DB,EXTENDED SCOPE=SPFILE;
> -- (설정 후 DB 재시작 필요)
> ```

> [!NOTE]- 문제: 감사 설정 (로그인 실패 감시)
> 
> SQL
> 
> ```
> AUDIT SESSION WHENEVER NOT SUCCESSFUL;
> ```

> [!NOTE]- 문제: 감사 설정 (특정 객체 감시)
> 
> SQL
> 
> ```
> AUDIT 명령어 ON 객체명 BY 유저명;
> -- 예: AUDIT SELECT ON 테이블명 BY 유저명;
> ```

> [!NOTE]- 문제: 감사 로그 조회 (필수 암기 뷰)
> 
> SQL
> 
> ```
> SELECT * FROM DBA_AUDIT_TRAIL;
> ```

> [!NOTE]- 문제: 감사 해제
> 
> SQL
> 
> ```
> NOAUDIT 명령어 …;
> ```

> [!NOTE]- 문제: 암호화 함수 (패키지)
> 
> SQL
> 
> ```
> DBMS_CRYPTO.encrypt(
>     src => UTL_RAW.cast_to_raw(평문),
>     typ => DBMS_CRYPTO.encrypt_aes256 + …,
>     key => 키값
> )
> ```

> [!NOTE]- 문제: 데이터 타입 변환 (자동화 실습)
> 
> - **`RAWTOHEX(암호화된값)`**: RAW → 16진수 문자열 (저장용)
>     
> - **`HEXTORAW(16진수문자열)`**: 16진수 문자열 → RAW (복호화 전)
>     

> [!NOTE]- 문제: 저장 컬럼 타입
> 
> - **`RAW`** 또는 **`BLOB`**

# 📘 Chapter 7 심화: 로그 기록(Audit Log) 직접 구현

> [!NOTE]- 문제: 감사 로그용 테이블 생성 (시퀀스 포함)
> ```SQL
> -- 1) 시퀀스 생성
> CREATE SEQUENCE 시퀀스명 START WITH 1 INCREMENT BY 1;
> -- 2) 로그 테이블 생성
> 
> CREATE TABLE 로그테이블명 (
> 
> log_id NUMBER PRIMARY KEY,
> 
> 작업자 VARCHAR2(50),
> 
> 작업일시 DATE,
> 
> 작업유형 VARCHAR2(10), -- INSERT/UPDATE/DELETE
> 
> 변경데이터 VARCHAR2(200)
> 
> );

> [!NOTE]- 문제: 로그 ID 자동 입력 트리거 (INSERT 시)
> 
> SQL
> 
> ```
> CREATE OR REPLACE TRIGGER 트리거명
> BEFORE INSERT ON 로그테이블명
> FOR EACH ROW
> BEGIN
>     :NEW.log_id := 시퀀스명.NEXTVAL;
> END;
> /
> ```

> [!NOTE]- 문제: 민감 정보(주민번호) 변경 감시 트리거
> 
> SQL
> 
> ```
> CREATE OR REPLACE TRIGGER 트리거명
> AFTER UPDATE OF 주민번호컬럼 ON 타겟테이블명
> FOR EACH ROW
> BEGIN
>     INSERT INTO 로그테이블명 (작업자, 작업일시, 작업유형, 변경데이터)
>     VALUES (USER, SYSDATE, 'UPDATE', :OLD.주민번호컬럼 || ' -> ' || :NEW.주민번호컬럼);
> END;
> /
> ```

# 📚 Chapter 10: 보안 종합 실습 (시나리오 문제)

> [!NOTE]- 문제: 뷰(View)를 활용한 마스킹(Masking) 처리
> 
> 시나리오: 주민번호 뒷자리를 별표(*)로 가려서 조회하는 뷰 생성
> 
> SQL
> 
> ```
> CREATE OR REPLACE VIEW 뷰이름 AS
> SELECT
>     이름,
>     SUBSTR(주민번호, 1, 6) || '-*******' AS 주민번호_마스킹
> FROM 테이블명;
> ```

> [!NOTE]- 문제: 권한의 연쇄 회수 (WITH GRANT OPTION)
> 
> 시나리오: A가 B에게 권한을 줄 때 WITH GRANT OPTION을 썼다면, A의 권한을 뺏으면 B도 같이 뺏기는가?
> 
> - **정답:** **YES** (Cascade, 연쇄 회수됨)
>     
> - 비교: 시스템 권한의 `WITH ADMIN OPTION`은 연쇄 회수되지 않음.
>     

> [!NOTE]- 문제: ORA-01031 (권한 불충분) 유발 테스트
> 
> 시나리오: 조회(SELECT) 권한만 가진 유저가 수정을 시도할 때
> 
> SQL
> 
> ```
> UPDATE 소유자명.테이블명 SET 컬럼명 = 값;
> -- 결과: ORA-01031: 권한이 불충분합니다.
> ```

> [!NOTE]- 문제: 접속 건별 감사 (BY ACCESS)
> 
> 시나리오: employees 테이블 조회 시, 실행 횟수마다 모두 기록
> 
> SQL
> 
> ```
> AUDIT SELECT ON employees BY ACCESS;
> -- 기본값은 BY SESSION (접속당 1번만 기록)이나, 상세 기록 시 BY ACCESS 사용
> ```

# ✅ 핵심 키워드/빈칸 점검 (시험 직전용)

> [!NOTE]- 문제: 트리거 내 시스템 변수 (이벤트 구분)
> 
> - `INSERT` 중일 때: **`INSERTING`**
>     
> - `UPDATE` 중일 때: **`UPDATING`**
>     
> - `DELETE` 중일 때: **`DELETING`**
>     

> [!NOTE]- 문제: 암호화 필수 패키지 및 타입
> 
> - 암호화 패키지명: **`DBMS_CRYPTO`**
>     
> - 암호화 알고리즘: **`AES256`** (주로 사용)
>     
> - 암호화된 데이터 저장 타입: **`RAW`**
>     

> [!NOTE]- 문제: 뷰 생성 시 옵션 (읽기 전용/조건 체크)
> 
> - `INSERT/UPDATE/DELETE` 금지: **`WITH READ ONLY`**
>     
> - `WHERE` 조건에 위배되는 데이터 입력 차단: **`WITH CHECK OPTION`**
>     

> [!NOTE]- 문제: 감사(Audit) 로그 확인용 데이터 사전
> 
> - **`DBA_AUDIT_TRAIL`**
>
