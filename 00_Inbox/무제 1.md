# 0. 수업 개요 - DB보안 1교시_2025.10.27

### 오늘의 Workflow

- **Step 1) 환경 구축**: 실습용 회원 테이블(`userTBL`) 생성 및 데이터 적재
- **Step 2) 데이터 마스킹 프로시저**: `SUBSTR`을 이용해 이름 일부를 숨기는 프로시저 작성 (`user_proc`)
- **Step 3) 소스 코드 암호화 (Wrapping)**: `DBMS_DDL.CREATE_WRAPPED`를 사용하여 프로시저 소스 자체를 숨기기
    

### 오늘의 실습 연결고리 (Flow Summary)

- **"데이터 보호에서 로직 보호까지"**
- (1) 평문 데이터가 있는 테이블을 준비하고 → (2) 데이터를 조회할 때 일부를 가리는(Masking) 프로시저를 만들었으나, **프로시저 소스 코드를 조회하면 마스킹 로직이 다 보인다**는 취약점 발견 → (3) 따라서 **DDL 자체를 암호화(Wrapping)** 하여 관리자조차 소스를 볼 수 없게 만드는 과정.

## Step 1. 실습 환경 구축 (userTBL) - DB보안 1교시_2025.10.27

### 2) Preconditions

- `SYS` 혹은 `SCOTT`, `HR` 등 실습 가능한 계정 접속.
### 3) Build & Execute

#### Logic

- **기존 테이블 정리**: 재실행 가능하도록 `DROP` 먼저 수행(선택).

## Step 2. 데이터 마스킹 프로시저 생성 (user_proc) - DB보안 1교시_2025.10.27

### 1) Goal

- 사용자 ID를 입력받아 이름의 첫 글자만 남기고 나머지는 `**`로 마스킹하여 출력하는 프로시저 작성.
- 예: `조용필` -> `조**`

### 2) Preconditions

- `SET SERVEROUTPUT ON` (결과 출력을 위해 필수)

### 3) Build & Execute

#### Logic

- **`%TYPE` 사용**: `v_userName userTBL.userName%TYPE;`
    - 테이블 컬럼 타입이 변경되어도 프로시저를 수정할 필요가 없도록 참조형 변수 사용.
- **마스킹 로직**: `SUBSTR(변수, 1, 1)`로 첫 글자 추출 + `|| '**'` 문자열 연결.
- **컴파일 트리거**: SQL Developer 워크시트에서 `/`(슬래시)를 사용하여 블록 종료 및 컴파일.

#### Code

```SQL
-- 접속: APP_USER

CREATE OR REPLACE PROCEDURE user_proc (
    p_userID IN userTBL.userID%TYPE -- 입력 변수
) 
IS
    -- 변수 선언부 (테이블 컬럼 타입 참조)
    v_userName userTBL.userName%TYPE;
    v_birthYear userTBL.birthYear%TYPE;
BEGIN
    -- 1. 입력받은 ID로 이름과 생년 조회
    SELECT userName, birthYear
    INTO v_userName, v_birthYear
    FROM userTBL
    WHERE userID = p_userID;

    -- 2. 마스킹 및 출력 (이름 첫글자 + 00)
    DBMS_OUTPUT.PUT_LINE('--------------------');
    DBMS_OUTPUT.PUT_LINE('이름: ' || SUBSTR(v_userName, 1, 1) || '00'); -- 강의에선 '00'이나 '땡땡' 언급
    DBMS_OUTPUT.PUT_LINE('생년: ' || v_birthYear);
    DBMS_OUTPUT.PUT_LINE('--------------------');
    
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('해당 ID의 회원이 없습니다.');
END;
/ 
-- 슬래시(/)는 워크시트에서 컴파일 실행 명령
```

#### Verify

- 🔎 확인: 프로시저 실행 및 마스킹 결과 확인.

```SQL
SET SERVEROUTPUT ON; -- 출력 켜기
EXEC user_proc('JYP');
-- 기대 출력:
-- 이름: 조00
-- 생년: 1950
```

#### Pitfalls

- ⚠️ **`SERVEROUTPUT` 미설정**: `EXEC` 했는데 "PL/SQL 처리가 정상적으로 완료되었습니다"만 뜨고 결과가 안 보임. -> `SET SERVEROUTPUT ON` 실행.
- ⚠️ **컴파일 오류**: `END;` 뒤에 `/`를 안 쓰면 SQL Developer 워크시트에서 명령어가 안 끝난 것으로 인식할 수 있음.
    

### 4) 💡 Interview

> [!faq]- Q. 변수 선언 시 %TYPE을 사용하는 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 유지보수성과 안정성 때문입니다. 테이블의 컬럼 속성(크기, 타입)이 변경되더라도 프로시저 코드를 수정하지 않아도 자동으로 동기화되므로 런타임 오류를 예방할 수 있습니다.
>
> **📚 꼬리질문 대비**
>
> - **Diff**: `%ROWTYPE`은 컬럼 하나가 아니라 **행 전체**의 구조를 참조할 때 사용합니다.
>

## Step 3. 소스 코드 암호화 (Wrapping) - DB보안 1교시_2025.10.27

### 1) Goal

- 방금 만든 프로시저의 로직(소스 코드)이 `USER_SOURCE` 뷰에서 평문으로 보이는 문제를 해결.
- `DBMS_DDL.CREATE_WRAPPED`를 사용해 소스 코드를 난독화/암호화(Wrapping)하여 재생성.

### 2) Preconditions

- `DBMS_DDL` 패키지 실행 권한 (오라클 기본 제공).
### 3) Build & Execute

#### Logic (Wrapping Process)

1. **소스 노출 확인**: `SELECT text FROM USER_SOURCE…`로 코드가 다 보이는지 먼저 확인.
2. **동적 SQL 구성**: 프로시저 생성 구문(`CREATE …`) 전체를 하나의 긴 **문자열 변수**에 담음.
    
    - 이때 따옴표(`'`) 안에 코드를 넣어야 하므로, 코드 내의 따옴표 처리가 중요.
    - 줄바꿈이나 긴 코드는 `||` (연결 연산자)를 사용해 이어 붙임.
        
3. **암호화 생성 실행**: `SYS.DBMS_DDL.CREATE_WRAPPED(문자열변수)`를 호출. 이 함수는 파싱 -> 암호화 -> 컴파일을 수행함.
    
#### Code

**1. 평문 노출 확인 (Before)**


```SQL
SELECT text FROM USER_SOURCE WHERE NAME = 'USER_PROC';
-- 결과: CREATE OR REPLACE PROCEDURE … (소스가 다 보임)
```

**2. Wrapping 수행 (암호화하여 재생성)**

```SQL
-- 접속: APP_USER
DECLARE
    v_ddl VARCHAR2(3000); -- 소스 코드를 담을 변수
BEGIN
    -- 전체 소스를 문자열로 구성 (|| 연산자로 연결)
    v_ddl := 'CREATE OR REPLACE PROCEDURE user_proc ( ' ||
             '    p_userID IN userTBL.userID%TYPE ' ||
             ') IS ' ||
             '    v_userName userTBL.userName%TYPE; ' ||
             '    v_birthYear userTBL.birthYear%TYPE; ' ||
             'BEGIN ' ||
             '    SELECT userName, birthYear INTO v_userName, v_birthYear ' ||
             '    FROM userTBL WHERE userID = p_userID; ' ||
             '    DBMS_OUTPUT.PUT_LINE(''이름: '' || SUBSTR(v_userName, 1, 1) || ''** Wrapped''); ' ||
             '    DBMS_OUTPUT.PUT_LINE(''생년: '' || v_birthYear); ' ||
             'END;';
             
    -- ⭐️ 핵심: DDL 구문을 암호화하여 실행
    SYS.DBMS_DDL.CREATE_WRAPPED(v_ddl);
END;
/
```

#### Verify

- 🔎 확인: `USER_SOURCE`를 다시 조회했을 때 코드가 깨진 문자열(Hex값 등)로 보이는지 확인.

```SQL
SELECT text FROM USER_SOURCE WHERE NAME = 'USER_PROC';
-- 기대 결과: wrapped … abcd1234… (알 수 없는 문자열)
```

- 🔎 기능 확인: 암호화되어도 실행은 정상적으로 되어야 함.
    
```SQL
EXEC user_proc('JYP'); 
-- 정상 출력 되어야 함.
```

#### Pitfalls

- ⚠️ **따옴표 지옥 (Quote Hell)**: 문자열 변수 안에 SQL 코드를 넣을 때, 코드 안에 있는 작은따옴표(`'`)는 두 번(`''`) 써서 이스케이프 처리해야 함.
    - 예: `DBMS_OUTPUT.PUT_LINE('Hello')` -> `'…PUT_LINE(''Hello'')…'`
- ⚠️ **문자열 길이 제한**: 코드가 매우 길 경우 `VARCHAR2(3000)`으로 부족할 수 있음. 이 경우 `CLOB`을 사용하거나 `DBMS_SQL` 패키지의 다른 방식 고려 필요.
    

### 4) 💡 Interview

> [!faq]- Q. DB에서 소스 코드를 Wrapping(랩핑)하는 이유는 무엇인가요?
>
> 🗣️ 핵심 답변
>
> 지적 재산권 보호와 보안 강화를 위해서입니다. 개발한 비즈니스 로직(알고리즘)을 숨기거나, 테이블 구조 및 민감한 처리 방식이 해커나 내부자에게 노출되는 것을 방지하기 위해 DBMS_DDL.CREATE_WRAPPED 등을 사용해 소스를 난독화합니다.

## 기타 핵심 (Etc & Tips) - DB보안 1교시_2025.10.27

### 1) SQL Developer 실습 팁

- **새로고침(Refresh)**: 프로시저나 테이블 생성 후 왼쪽 객체 탐색기(Object Browser)에 바로 안 뜰 수 있습니다. 반드시 `새로고침` 버튼을 누르거나, 접속을 재설정해야 보일 때가 있습니다.
- **워크시트 실행**:
    - 블록 지정 후 실행(`Ctrl+Enter`)도 가능하지만, 프로시저 끝에 `/`(슬래시)를 넣고 **스크립트 실행(`F5`)**을 하는 것이 컴파일 오류를 줄이는 정석입니다.
        

### 2) 용어 및 개념 정리

- **Wrapping (랩핑)**:
    - 사전적 의미는 "포장하다"이지만, DB 보안에서는 **"코드를 암호화 포장하여 내용을 숨기는 기술"** 을 뜻합니다.
    - 실행 권한은 유지되지만, 조회 권한(`SELECT text FROM USER_SOURCE`)이 있어도 내용을 볼 수 없습니다.
- **Data Dictionary (데이터 사전)**:
    - `USER_SOURCE`, `USER_TABLES` 처럼 오라클이 관리하는 시스템 테이블.
    - 우리가 작성한 프로시저 소스도 결국은 이 딕셔너리에 텍스트 형태로 저장됩니다.
        

### 3) Prof’s Comment (시험/실무 관련)

> **"시험에 이거(%TYPE) 냈는데…"**
>
> - 교수님께서는 변수 선언 시 `userTBL.userID%TYPE`처럼 **참조형**을 쓰는 것을 원칙으로 가르치셨습니다.
>     
> - 다만, 지난 시험에서 `VARCHAR2(10)` 처럼 직접 타입을 쓴 경우도 정답 처리는 해주셨다고 합니다. (하지만 실무/보안 관점에서는 `%TYPE`이 유지보수에 훨씬 유리합니다.)
>     

> **"오늘부터는 배우는 내용들이 다 보안에 사용할 수 있는…"**
>
> - 지금까지 배운 SQL 기초(Create, Insert, Procedure)가 "재료"라면, 오늘부터는 이를 **"어떻게 보안(암호화, 접근제어)에 응용하느냐"**가 핵심입니다.
>
