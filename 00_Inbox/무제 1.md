## Topic. 구조체 배열과 포인터 (Struct Array & Pointer)

구조체 문법의 핵심은 **"선언된 변수가 실체(Value)인가, 주소(Address)인가?"**를 파악하는 것입니다. 이 선언 형태가 접근 연산자, 메모리 관리, 그리고 연산 방식 전체를 지배합니다.

### 1. 🚦 핵심 원칙: 선언이 연산자를 결정한다

변수가 메모리에 존재하는 **데이터 덩어리**인지, 그것을 가리키는 **참조자**인지에 따라 사용하는 연산자가 달라집니다.

| **기준**     | **Case A: 구조체 변수 (Value)**           | **Case B: 구조체 포인터 (Address)**                            |
| ---------- | ------------------------------------ | -------------------------------------------------------- |
| **선언 형태**  | **`struct Type var;`**               | **`struct Type *ptr;`**                                  |
| **성격**     | 데이터 덩어리 (실체)                         | 메모리 주소값 (참조)                                             |
| **접근 연산자** | **점 (`.`)**                          | **화살표 (`->`)**                                           |
| **접근 방식**  | **Direct Access**<br>(Base + Offset) | **Indirect Access**<br>(Dereference $\to$ Base + Offset) |
| **코드 예시**  | `var.age = 20;`                      | `ptr->age = 20;`                                         |

> **Note:** `ptr->age`는 `(*ptr).age`의 문법적 설탕(Syntactic Sugar)입니다. 원래는 역참조(`*`) 후 접근(`.`)해야 하지만, 편의를 위해 `->`를 제공합니다.

---

### 2. 🏗️ 메모리 구조와 크기 (Memory & Size)

#### ① 오개념 경계: 포인터 크기의 불변성

> **"구조체 덩어리가 커지면, 포인터 변수의 크기도 커지는가?" $\to$ NO!**

- **구조체 포인터:** 구조체 멤버가 아무리 많아도(100Byte든 1GB든), 포인터는 **'시작 주소'**만 담으므로 크기가 고정됩니다.
    - **32bit 시스템:** 4 Byte
    - **64bit 시스템:** 8 Byte

#### ② 배열 선언 시 메모리 배치 비교

1. **구조체 배열 (`struct Card c[20]`)**
    
    - **내용:** 실제 구조체 덩어리 20개.
    - **할당:** 구조체 크기($S$) $\times 20$만큼의 공간이 **물리적으로 연속 할당**됩니다.
    - **접근:** `c[0].name`, `c[1].name` 배열의 인덱스로 접근
        
2. **구조체 포인터 (`struct Card *k`)**
    
    - **내용:** 주소값 1개.
    - **할당:** 4 Byte (32bit 기준)만 할당됩니다. 실제 구조체 데이터는 별도로 존재해야 합니다.
    - **접근:** `k->name`
---

### 3. ⚠️ 문법: 연산자 우선순위 (Operator Precedence)

C언어 포인터 연산에서 실수가 가장 잦은 부분입니다. **점(`.`)과 화살표(`->`)는 별(`*`)보다 강력합니다.**

|**순위**|**연산자**|**설명**|**결합 방향**|
|---|---|---|---|
|**1순위**|`.` `->` `()` `[]`|**멤버 접근**, 함수, 인덱스|좌 $\to$ 우|
|**2순위**|`*` `++` `--` `&`|**역참조**, 증감, 주소|**우 $\to$ 좌**|

#### 접근 문법 정리

- **❌ 틀린 표현:** `*k.name` (점이 `*`보다 먼저 실행되어 주소가 아닌 멤버를 역참조하려 함)
- **✅ 맞는 표현:** `(*k).name` (괄호로 순서 강제)
- **⭐ 추천 표현:** **`k->name`** ((`(*k).`을 축약한 직관적인 문법)
    
---

### 4. ⚔️ 실무 패턴: 임시 포인터 활용 (Iterator Strategy)

배열을 포인터로 순회(`ptr++`)할 때 가장 중요한 원칙은 **"원본 시작 주소(Base Address)를 잃어버리지 않는 것"**입니다.

- **Bad Case (원본 유실):** `head` 자체를 움직이면 리스트의 처음으로 돌아갈 수 없습니다.
- **Good Case (임시 포인터 사용):** `head`는 고정하고, `cur`를 복사해서 움직입니다.

```C
struct Card *head = list;    // [Anchor] 기준점 (절대 이동 금지)
struct Card *cur = head;     // [Cursor] 순회용 (복사본)

// cur가 움직여도 head는 안전함
while(cur->name != NULL) {
    printf("%s", cur->name);
    cur++; 
}
```

---

### 5. 🔍 심화: 복합 연산 정복 (Value vs Pointer)

임시 포인터 `d`가 있고, `d->name`이 `"Alice"`(`0x100`)를 가리키고 있을 때의 동작 차이입니다.

#### (1) `*(d->name++)` : 주소 이동 (순회용)

> **"현재 글자를 읽고, 포인터를 다음 칸으로 이동하라"**

1. **`d->name`**: 멤버 접근 (`0x100`).
2. **`++` (후위)**: `name`이 가리키는 **주소**를 `0x101`로 증가 (값은 변하지 않음).
3. **`*` (역참조)**: 증가 전 주소(`0x100`)의 값 **'A'**를 반환.
    - **결과:** 반환값 `'A'`, `name` 포인터는 이제 `'l'`(`0x101`)을 가리킴.
        

#### (2) `(*d->name)++` : 값 변경 (조작용)

> **"현재 위치의 글자 자체를 +1 하라"**

1. **`(*d->name)`**: `d->name`(`0x100`)의 **값 `'A'`**를 가져옴.
2. **`++` (후위)**: 가져온 문자 `'A'`(65)를 `'B'`(66)로 변경.
    
    - **결과:** 메모리의 문자열이 `"Alice"` $\to$ **`"Blice"`**로 변경됨. 주소는 그대로임.
