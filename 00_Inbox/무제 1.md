### 2) 핵심 개념 요약

SQL 쿼리는 거대한 데이터를 **'요리'**하는 과정과 같습니다. 각 절은 요리의 한 단계에 해당하며, 정해진 순서대로 진행해야 맛있는 결과(데이터)가 나옵니다.

**SQL 논리적 실행 순서 (10단계)**

1. **`FROM`**: **(1. 재료 준비)** 가장 먼저, 어떤 테이블에서 데이터를 가져올지 지정합니다. 여러 테이블이면 여기서 `JOIN`을 통해 모든 데이터를 연결하여 거대한 가상의 테이블을 만듭니다.
    
2. **`ON`**: **(2. 재료 연결 규칙)** `JOIN`을 할 때, 어떤 규칙(예: `user.id = order.user_id`)으로 테이블을 붙일지 정합니다.
    
3. **`WHERE`**: **(3. 재료 손질)** 준비된 재료(가상 테이블)에서 필요 없는 행(Row)들을 **걸러냅니다.** (예: '2025년 이전 주문은 제외')
    
4. **`GROUP BY`**: **(4. 재료 묶기)** 손질된 재료들을 특정 기준(예: 사용자별, 월별)으로 **그룹을 만듭니다.** 이 시점부터는 개별 행이 아닌 그룹 단위로 데이터를 다룹니다.
    
5. **`HAVING`**: **(5. 묶음 손질)** 만들어진 그룹들 중에서 **필요 없는 그룹을 걸러냅니다.** (예: '주문 총액이 10,000원 미만인 그룹은 제외')
    
6. **`SELECT`**: **(6. 접시에 담을 것 고르기)** 이제 최종적으로 어떤 컬럼(Column)을 결과로 보여줄지 **선택합니다.** `AS`를 이용한 별칭이 이때 확정됩니다.
    
7. **`DISTINCT`**: **(7. 중복 제거)** 접시에 담은 결과물 중에서 중복된 행이 있다면 제거합니다.
    
8. **`ORDER BY`**: **(8. 예쁘게 정렬)** 최종 결과물을 어떤 순서(오름차순 `ASC`, 내림차순 `DESC`)로 **정렬할지 결정합니다.**
    
9. **`LIMIT` / `OFFSET`**: **(9. 원하는 만큼만 덜기)** 정렬된 결과물 중에서 **특정 개수만큼만** 잘라냅니다. (예: '상위 5개만 보여줘')
    

### 3) 용어 매핑

- **"SQL 모든 논리적인 순서"**: **SQL 논리적 쿼리 처리 순서 (Logical Query Processing Order)** 또는 **실행 순서(Order of Execution)**라고 부릅니다.
    
- **"쿼리 짜는 순서"**: **코드 작성 순서(Code Writing Order)**입니다. `SELECT`, `FROM`, `WHERE`... 순으로 작성하지만 실제 실행 순서와는 매우 다릅니다.
    
- **"가상의 테이블"**: `FROM`과 `JOIN` 절을 통해 메모리에 생성되는 **중간 결과 집합(Intermediate Result Set)**을 의미합니다.
    

### 4) 사고 틀 & 판단 기준

쿼리를 작성하거나 읽을 때, 머릿속으로 아래의 단계를 따라가며 데이터가 어떻게 변하는지 상상해야 합니다.

1. **데이터 소스 확정 (`FROM`, `JOIN`):** "어떤 테이블들을 가지고 시작하는가?" → 거대한 표가 하나 만들어집니다.
    
2. **행(Row) 필터링 (`WHERE`):** "이 표에서 어떤 '가로줄'을 지워야 하는가?" → 표의 키가 줄어듭니다.
    
3. **그룹화 (`GROUP BY`):** "남은 가로줄들을 어떤 기준으로 '묶음'으로 만들 것인가?" → 표가 여러 그룹으로 나뉩니다.
    
4. **그룹 필터링 (`HAVING`):** "이 그룹들 중 어떤 '묶음'을 통째로 버릴 것인가?" → 그룹의 개수가 줄어듭니다.
    
5. **열(Column) 선택 (`SELECT`):** "남은 그룹들에서 어떤 '세로줄'을 최종적으로 보여줄 것인가?" → 표의 폭이 결정됩니다.
    
6. **최종 가공 (`ORDER BY`, `LIMIT`):** "완성된 표를 어떻게 정렬하고 잘라낼 것인가?" → 최종 결과가 나옵니다.
    

**판단 기준:**

- **개별 행**에 대한 조건인가? → `WHERE` 절에 써야 합니다.
    
- **그룹(집계 결과)**에 대한 조건인가? → `GROUP BY` 이후이므로 `HAVING` 절에 써야 합니다.
    
- **`SELECT`에서 만든 별칭(Alias)**을 쓰고 싶은가? → 그 별칭이 확정되는 `SELECT` 단계 이후인 `ORDER BY` 절에서는 쓸 수 있지만, 그 이전인 `WHERE`나 `GROUP BY`에서는 쓸 수 없습니다.
    

### 5) 체크 질문 (자가 점검)

1. `SELECT` 절에서 만든 컬럼 별칭(예: `SELECT user_id AS u_id`)을 `WHERE` 절에서 사용할 수 없는 이유는 무엇인가요?
    
2. `WHERE`와 `HAVING`은 둘 다 필터링을 하지만, 가장 큰 차이점은 무엇인가요?
    
3. 전체 직원 중 '연봉이 5,000 이상인 직원들'을 대상으로 '부서별 평균 연봉'을 계산할 때, '연봉 5,000 이상'이라는 조건은 어디에 들어가야 할까요?
    
4. 위에서 계산한 '부서별 평균 연봉'이 '7,000 이상인 부서'만 보고 싶다면, 이 조건은 어디에 들어가야 할까요?
    
5. `ORDER BY`는 `GROUP BY`보다 먼저 실행되나요, 나중에 실행되나요?
