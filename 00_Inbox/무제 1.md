### 1. 컴퓨터 시스템의 3계층 구조:
소프트웨어의 실행 환경은 역할에 따라 계층화되어 있습니다.

| **계층**        | **구성 요소**              | **주요 역할**                           |
| ------------- | ---------------------- | ----------------------------------- |
| **애플리케이션**    | 웹 브라우저, CGI 프로그램 등     | 사용자의 특정 목적(비즈니스 로직)을 수행하는 최상위 소프트웨어 |
| **시스템 소프트웨어** | 운영체제(OS), 컴파일러 등       | 하드웨어 자원을 관리하고 애플리케이션에 실행 환경을 제공     |
| **하드웨어**      | CPU(Machine), Memory 등 | 물리적 연산 및 데이터 저장을 수행하는 기계 장치         |


>  애플리케이션과 운영체제는 모두 '소프트웨어'에 해당하지만, 운영체제는 하드웨어를 직접 제어한다는 점에서 애플리케이션과 차이가 있습니다.
> cpu는 Machine, 운영체제는 Os라고도 한다.
> **기계어(Machine Code):** CPU가 직접 해석하고 실행할 수 있는 유일한 언어입니다.
### 2. 플랫폼 (Platform): 하드웨어+ 시스템 소프트웨어
애플리케이션이 실행되기 위해 필요한 두 계층, 하드웨어(CPU)와 시스템 소프트웨어(OS)을 의미한다. 프로그램의 코드가 실제 하드웨어 자원(메모리, 연산 장치 등)을 사용할 수 있도록 인터페이스를 제공합니다.
- **CPU** : 하드웨어의 핵심
	- **기계어(Machine Code):** CPU가 직접 해석하고 실행할 수 있는 유일한 언어입니다. (cpu를 marchine이라고 부른다)
	- **ISA(Instruction Set Architecture):** CPU 아키텍처(x86, ARM 등)에 따라 인식할 수 있는 기계어 명령어 집합이 다릅니다.
- **운영체제 (OS):** 시스템소프트웨어의 핵심
	- 하드웨어 자원을 관리하고 응용 프로그램에 **API(System Call)**를 제공합니다.
	- **추상화:** 복잡한 하드웨어 제어 로직을 소프트웨어적으로 단순화하여 제공합니다.
	- **시스템 호출 (System Call):** 애플리케이션이 하드웨어 자원(파일 읽기, 메모리 할당 등)을 사용하기 위해 OS에 요청하는 인터페이스입니다.
	- **플랫폼 차이:** 설령 동일한 CPU를 사용하더라도, **Windows와 Linux는 시스템 호출의 규격과 API가 완전히 다르기 때문**에 프로그램의 호환성이 보장되지 않습니다.


### 3. 네이티브 코드 (Native Code)

특정 플랫폼(CPU+OS)의 기계어로 번역되어, 별도의 해석기 없이 **즉시 실행 가능한 이진 코드(Binary Code)**입니다.

- **특징:** 실행 속도가 가장 빠르지만, 해당 플랫폼에 **강하게 결합(Tightly Coupled)**되어 있습니다.
- **종속성:** 특정 OS의 시스템 호출과 특정 CPU의 명령어 셋을 직접 포함합니다.




C언어는 **네이티브 코드(기계어)**를 생성합니다.


작성해주신 내용을 바탕으로 중복된 정보를 통합하고, 기술적 메커니즘을 중심으로 논리적 순서에 따라 재구조화했습니다.

## 1. 컴퓨터 시스템의 3계층 구조

컴퓨터 시스템은 실행 권한과 역할에 따라 하드웨어부터 소프트웨어까지 계층적으로 구성됩니다.

|**계층**|**구성 요소**|**주요 역할 및 특징**|
|---|---|---|
|**애플리케이션**|웹 브라우저, CGI 등|특정 비즈니스 로직을 수행하는 최상위 소프트웨어|
|**시스템 소프트웨어**|운영체제(OS), 컴파일러 등|하드웨어 자원 관리 및 애플리케이션 실행 환경 제공|
|**하드웨어**|CPU, 메모리, 스토리지 등|물리적 연산 수행 및 데이터를 저장하는 기계 장치|

> **핵심 차이:** 운영체제는 하드웨어 자원에 직접 접근하여 제어할 수 있는 특권 권한을 가지나, 애플리케이션은 반드시 시스템 소프트웨어를 통해서만 자원에 접근할 수 있습니다.

## 2. 플랫폼(Platform)과 인터페이스

플랫폼은 **하드웨어(CPU)**와 **시스템 소프트웨어(OS)**의 결합체로, 애플리케이션이 물리적 자원을 사용할 수 있도록 규격화된 인터페이스를 제공합니다.

### A. 하드웨어 인터페이스: ISA (Instruction Set Architecture)

CPU가 직접 해석하고 실행할 수 있는 명령어 집합입니다.

- **기계어(Machine Code):** ISA에 정의된 규격에 따라 작성된 유일한 이진 코드입니다.
- **하드웨어 종속성:** CPU 아키텍처(x86, ARM 등)에 따라 ISA가 다르므로, 특정 CPU를 위해 생성된 기계어는 다른 아키텍처에서 동작하지 않습니다.
    

### B. 소프트웨어 인터페이스: 시스템 호출 (System Call)

운영체제가 하드웨어 자원을 제어하기 위해 애플리케이션에 제공하는 통로입니다.

- **자원 추상화:** 복잡한 하드웨어 제어 로직을 함수 형태의 API로 단순화하여 제공합니다.
- **운영체제 종속성:** 동일한 CPU를 사용하더라도 OS(Windows, Linux 등)에 따라 시스템 호출 규격이 다르므로 바이너리 수준의 호환성이 제한됩니다.

## 3. 플랫폼의 역할: 추상화 및 자원 변환

플랫폼은 애플리케이션의 논리적 요청을 하드웨어의 물리적 동작으로 변환하는 중계 역할을 수행합니다.

|**구분**|**실제 하드웨어 자원**|**플랫폼 제공 인터페이스 (추상화)**|
|---|---|---|
|**연산**|트랜지스터의 전기적 신호 흐름|**ISA** (ADD, MOVE 등 명령어)|
|**저장**|RAM의 물리적 주소 및 전하 상태|**가상 메모리 주소** (OS 관리 논리 주소)|
|**장치 제어**|디스크 헤드 이동 및 전압 제어|**파일 시스템** (Open, Read 등 함수)|

### 자원 실행 프로세스

1. **요청:** 애플리케이션이 플랫폼 규격(System Call, ISA)에 맞춰 명령 전달
2. **변환:** 플랫폼이 논리적 요청을 물리적 주소 및 제어 신호(Control Signal)로 변환
3. **실행:** 하드웨어(ALU, 메모리 소자 등)가 전기적 연산 및 데이터 기록 수행

## 4. 네이티브 코드 (Native Code)

특정 플랫폼의 규격(ISA + System Call)에 직접 맞춰 번역된 실행 파일입니다.

- **실행 방식:** 별도의 해석기(Interpreter) 없이 CPU에서 즉시 실행됩니다.
- **성능:** 플랫폼 환경에 최적화되어 실행 속도가 가장 빠릅니다.
- **결합도:** 특정 플랫폼에 강하게 결합(Tightly Coupled)되어 있어, 타 플랫폼에서 실행하기 위해서는 해당 환경에 맞는 재컴파일 과정이 필수적입니다.
- **대표 언어:** C, C++, Rust 등은 컴파일 결과물로 네이티브 코드를 생성합니다.
