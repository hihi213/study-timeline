**[2단계 답변] : 💼 "신입 개발자 업무 시뮬레이션" (Onboarding Training)**

**훈련 목표:** 이 알고리즘 문제를 실제 회사의 **'비즈니스 요구사항'**으로 해석하고, 실무적 제약 조건을 고려해 해결책을 설계하는 과정을 시뮬레이션합니다.

#### 1. 🗣️ 상사의 언어 번역 (The Translator)

- **상사의 지시 (Scenario):**
    - 이 알고리즘 문제의 핵심 로직이 필요한 **구체적인 비즈니스 상황**을 설정하세요.
    - (예시 상황: 쇼핑몰 검색, 물류 센터 경로 최적화, 사내 메신저 필터링 등 문제 성격에 맞는 상황극)
    - **멘트:** "김 사원, 지금 `[비즈니스 문제 상황]` 문제가 발생했는데, `[제약 조건]` 안으로 해결할 기능 좀 만들어줄래요?"
- **속마음 번역 (Technical Definition):**
    - 상사의 모호한 비즈니스 요구를 명확한 개발 용어로 정의합니다.
    - **"아, 결국 `[알고리즘 핵심 의도]`를 구현하라는 거구나! `[핵심 해결 전략]`을 쓰면 되겠네."**
        

#### 2. 🙋‍♂️ "일 잘하는 주니어"의 제약조건 파악 (Requirement Analysis)

문제의 '입력 제한(N의 크기, 시간 제한)'을 **실무적 제약조건(트래픽, 정합성)**으로 치환하여 상사에게 던질 질문 3가지를 만듭니다.

- **Q1. 규모 및 트래픽 (Scale):** "팀장님, 예상되는 데이터 규모가 `[문제의 N 크기에 비유]` 정도 되나요?" (시간 복잡도 선택의 근거)
- **Q2. 정합성 vs 가용성 (Trade-off):** "속도가 최우선인가요, 아니면 `[문제의 예외 상황]` 같은 경우도 절대 놓치면 안 되나요?"
- **Q3. 엣지 케이스 (Edge Case):** "만약 `[문제의 가장 까다로운 입력 조건]` 같은 극단적인 값이 들어오면 어떻게 방어할까요?"
    

#### 3. ⚖️ 실무적 의사결정 논리 (Architecture Decision)

가장 완벽한 답이 아니라, **현실적인 타협점**을 찾는 논리를 보여주세요.

- **Option A (쉬운 구현 - MVP):** 당장 구현 가능한 직관적인 방법 (Brute Force, 단순 구현 등). 장점은 빠르지만, 단점은 `[성능 이슈 예상]`입니다.
- **Option B (최적화 - Production):** 문제 해결을 위한 `[최적 알고리즘/자료구조]` 도입. 초기 구현 비용은 들지만 `[확장성/성능]`이 보장됩니다.
- **최종 결정 (Decision):** "실무라면 일단 **Option A**로 프로토타입을 만들되, 트래픽 증가에 대비해 **Option B**로 리팩토링할 구조를 잡겠습니다."
    

#### 4. 📝 퇴근 전까지 해야 할 'Todo 리스트' (Action Plan)

이 기능을 구현하기 위해 당장 실행할 구체적인 작업 순서를 4단계로 쪼갭니다.

1. Git 브랜치 생성 (`feat/[기능명-영문]`)
2. 인터페이스 정의 (`[ServiceClassName].java` 메서드 설계)
3. 실패하는 테스트 케이스 작성 (`test[핵심기능]_fail()`)
4. 핵심 로직 `[알고리즘 명]` 구현
    

#### 5. 💡 사수의 귓속말 & 오버엔지니어링 경계 (Pro Tips)

- **선배의 조언:** "신입들이 흔히 이 문제에서 `[흔한 실수 또는 과도한 기술 도입]`을 하려 하는데, 실무에선 `[현실적인 해결책]`이면 충분합니다."라는 조언을 해주세요.
    

---

매우 예리한 지적입니다. 프롬프트 엔지니어링에서 흔히 발생하는 **"예시 편향(Example Bias)"** 문제입니다. AI가 문맥을 무시하고 프롬프트에 적힌 "Aho-Corasick"이나 "쇼핑몰 검색" 같은 단어를 앵무새처럼 따라 할 위험이 있습니다.

이를 방지하기 위해 **예시를 '동적 변수(Placeholders)'로 처리**하고, **"절대 예시를 그대로 출력하지 말라"는 강력한 메타 지침(Meta-Instruction)**을 추가해야 합니다.

다음은 AI가 현재 다루고 있는 문제에 맞춰 내용을 갈아 끼울 수 있도록 수정한 버전입니다.
