## 정리

- 도메인 엔티티(Member)가 아니라 **폼 DTO**(MemberForm)를 씁니다.

    이유: 검증/바인딩 범위 분리, 보안(과바인딩 방지), 화면 전용 필드 포함 가능.

```java
public class MemberForm {
    @NotBlank private String name;
    private String city;
    private String street;
    private String zipcode;
}
```

---

# **1) GET: 새 회원 폼 화면 열기**

```java
@GetMapping("/members/new")
public String createForm(Model model) {
    model.addAttribute("memberForm", new MemberForm()); // [A]
    return "members/createMemberForm";                  // 템플릿
}
```

## **[A]** **Model#addAttribute("memberForm", …)**

- **뷰에 내려줄 모델 데이터**를 넣습니다.
- 키 이름 "memberForm"으로 비어있는 MemberForm 인스턴스를 전달.
- 목적:
    - 템플릿에서 th:object="${memberForm}"로 **바인딩 대상 객체**를 잡기 위함.
    - 초기 렌더링 시 th:field="*{...}"가 name/id 값을 **자동 생성**하고 값도 세팅함(초깃값이 있으면 보여줌).
- 참고: 다음과 같이 써도 같은 효과 (이름은 타입에서 유추 → memberForm)

```java
model.addAttribute(new MemberForm());
```

- 혹은 파라미터 자체를 @ModelAttribute로 받아도 모델에 자동 추가:

```java
@GetMapping("/members/new")
public String createForm(@ModelAttribute("memberForm") MemberForm form) { return "..."; }
```

# **2) View(Thymeleaf): 폼 바인딩**

```java
<form role="form"
      action="/members/new"          <!-- 실무에선 th:action="@{/members/new}" 권장 -->
      th:object="${memberForm}"
      method="post">

  <input type="text" th:field="*{name}"/>
  <input type="text" th:field="*{city}"/>
  <input type="text" th:field="*{street}"/>
  <input type="text" th:field="*{zipcode}"/>

  <!-- 검증 에러 표시 예시 -->
  <div th:if="${#fields.hasErrors('name')}" th:errors="*{name}"></div>

  <button type="submit">가입</button>
</form>
```

## **th:object="${memberForm}"**

- 이 폼의 **기준 객체**를 지정합니다.
- 하위의 th:field="*{name}" 같은 별표(*{}) 경로는 **위에서 지정한 객체** 기준으로 동작.
- th:field는 다음을 자동 처리:
    - name/id 속성 생성(예: name="name").
    - 값 바인딩(초깃값, 에러 시 재입력 값 유지).
    - 에러 클래스 적용(스프링 바인딩 결과 연계).

> 액션은 /members/new를 하드코딩하기보다 **th:action="@{/members/new}"**로 쓰면 컨텍스트 경로 변동(배포 환경)에 안전해요.

# **3) POST: 제출 처리(바인딩 + 검증 + 저장)**

```java
@PostMapping("/members/new")
public String create(
        @Valid @ModelAttribute("memberForm") MemberForm form, // [B]
        BindingResult bindingResult) {                        // [C]

    if (bindingResult.hasErrors()) {
        return "members/createMemberForm"; // 같은 모델키로 다시 렌더 → 에러 메시지 표시
    }

    // DTO → 도메인 변환/조립
    Address address = new Address(form.getCity(), form.getStreet(), form.getZipcode());
    Member member = Member.create(form.getName(), address);

    memberService.join(member); // 트랜잭션 내 저장
    return "redirect:/";        // PRG 패턴
}
```

## **[B]** **@ModelAttribute("memberForm")**

- 요청 파라미터를 MemberForm에 **바인딩**합니다.
- 이름을 생략하면 파라미터 타입명에서 유추(memberForm)하지만, 뷰의 th:object와 **이름을 맞추는 것**이 실무에서 안전합니다.
- @Valid로 Bean Validation 적용(폼 DTO의 애노테이션 검사).

## **[C]**  **BindingResult**

- 검증/바인딩 오류가 담기는 객체. @Valid 파라미터 **바로 다음**에 둬야 함.
- 에러가 있으면 같은 화면을 그대로 리턴 → th:errors, #fields로 메시지 표시.

# **4) 왜 이렇게 나누나? (실무 포인트)**

- **모델(Model)**
    뷰 렌더링에 필요한 데이터 컨테이너.
    GET에서 **초기 폼 객체**를 넣고, POST 실패 시에도 같은 키로 돌려주면 화면이 에러와 함께 안전하게 재렌더링.

- **폼 DTO + th:object**
    화면 전용 스키마(필드/검증/마스킹 등)를 **엔티티와 분리**.
    th:object로 바인딩 대상을 고정해 **폼 필드 작성이 짧고 안전**해짐.

- **POST 처리**

    @ModelAttribute 바인딩 → @Valid 검증 → 실패 시 **같은 뷰로 반환**, 성공 시 **서비스 호출** 후 **PRG(redirect)**.

    이 패턴이 **중복 제출 방지**, **뒤로가기 안전**, **검증 메시지 연동**까지 한 번에 해결.

---

# **5) 요약 흐름 한 줄씩**

1. **Controller(GET)**: model.addAttribute("memberForm", new MemberForm())
2. **View**: \<form th:object="${memberForm}"> + th:field="*{...}"로 안전 바인딩
3. **Controller(POST)**: @Valid @ModelAttribute("memberForm") MemberForm form, BindingResult
4. **성공** → 서비스 저장 → redirect:/ / **실패** → 같은 뷰로 리턴(에러 표시)

이렇게 쓰면 **안전하고 유지보수 쉬운 폼 처리**가 됩니다.
