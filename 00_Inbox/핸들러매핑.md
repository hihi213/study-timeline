## 정리
- 
짧게: 핸들러 매핑(HandlerMapping) 은 들어온 HTTP 요청을 어떤 핸들러(컨트롤러 메서드)가 처리할지 찾아주는 스프링 MVC의 전략 컴포넌트야.

뭔데 정확히?
	•	역할: DispatcherServlet이 요청을 받으면 여러 HandlerMapping을 순서대로 조회 → 매칭 규칙(URL 패턴, HTTP 메서드, 헤더/파라미터, consumes/produces 등)에 맞는 핸들러를 찾아 **HandlerExecutionChain(핸들러 + 인터셉터들)**을 돌려줘.
	•	그 다음: HandlerAdapter가 그 핸들러를 실제로 호출하고, 결과는 뷰/바디로 응답됨.

무엇이 ‘핸들러’인가?
	•	보통 컨트롤러의 메서드(예: @GetMapping("/users/{id}")).
	•	경우에 따라 기타 핸들러 객체(리소스 핸들러 등)도 포함.

매칭에 쓰는 대표 규칙
	•	경로 패턴: /users/{id}, /assets/** (Spring 5.3+는 PathPattern 기반 가능)
	•	HTTP 메서드: GET/POST/PUT/DELETE …
	•	헤더/파라미터/콘텐츠 타입: headers=, params=, consumes=, produces=

- 주요 구현체(알아두면 끝)
	-	RequestMappingHandlerMapping: 애노테이션 기반(@RequestMapping, @GetMapping 등) — 대부분 이거 씀.
		- RequestMapping: “경로 + 조건”을 지정하는 **범용 매핑**.
		- @GetMapping: RequestMapping에서 조건없다고 설정한거의 축약버전
	•	SimpleUrlHandlerMapping: 명시적 URL→핸들러 매핑 테이블.
	•	BeanNameUrlHandlerMapping: 빈 이름을 URL로 매칭(요즘은 드묾).

동작 순서(마인드맵)
	1.	DispatcherServlet → 2) HandlerMapping이 “누가 처리할지” 결정 → 3) HandlerAdapter가 호출 → 4) 결과 렌더링.

용어 매핑
	•	“핸들러 매핑” = Spring MVC HandlerMapping
	•	“핸들러” = 컨트롤러 메서드(또는 기타 처리자)
	•	“실행 체인” = HandlerExecutionChain(핸들러 + 인터셉터)

포인트만 기억: 요청→(HandlerMapping) 누구?→(HandlerAdapter) 어떻게 호출?
