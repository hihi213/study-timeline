# 백엔드 프롬프트

> 목적: **전체 계획 진행(PM/운영) AI**와 **백엔드 개발 보조 AI**가 동일한 기준으로 일하고, 7주 내 MVP 1분 데모를 확실히 완주하도록 학습 자료·프롬프트·체크리스트를 제공한다.

---

## **0) 미션·범위·원칙**

- **미션:** 로그인 → 자원/아이템 → 검사(2인/423) → 제출(불변/리비전) → 벌점(원본/조정/요약) **엔드투엔드 데모** 완주.
- **실시간:** 폴링 최소형(주기 5s, 실패시 10→20→30s 백오프, **in-memory lastId 커서**).
- **절대 원칙:**
    
    1. **라벨 교체**(remove→create)는 한 트랜잭션.
    2. **423 락:** DB엔 근거만(locks 테이블), 차단 판단은 **앱 미들웨어**.

- **이번 스코프에서 의도적으로 제외:** SSE, BroadcastChannel 탭공유, 오프라인 복구/재동기, TRGM/고급검색, 본격 CI/CD/부하.

---

## **1) 타임라인(요약 DoD 포함)**

- **W1:** 부트스트랩(헬스/로그), 인증(/auth/login, /me, RBAC), /events/poll 스텁 → **헬스200, 폴링 hello 수신**
- **W2:** 리소스/아이템 목록·등록·검색(LIKE), **event_log.append**(items.*), 응답에 floor_code → **폴링에 신규 이벤트 노출**
- **W3:** 조정/제거, **Idempotency-Key(10m)**, **GUC 주입**(app.user_id,app.change_reason) → **중복요청 동일응답**
- **W4:** 2인 검사 세션(≤2/자원당 1건), 423 락 + TTL/GC → **3번째 참여 409/422, 락 상태 폴링 확인**
- **W5:** 조치 기록 + **단일 제출**(INSERT/DELETE 금지, UPDATE=리비전) + 원본 벌점 자동 생성 → **재제출 동일응답, version+1**
- **W6:** 벌점 조정(≠0) + 집계 뷰(API) → **사용자별 original/adjusted/total 정확**
- **W7:** 프런트 E2E 데모 + 폴링 규약 고정(/events/poll sinceId/limit/payload) → **1분 데모 녹화**

## **2) 운영/PM AI 가이드 (Plan Runner)**

### **2.1 책임**

- **계획 실행 관리:** 주·일 단위 체크리스트 자동 전개/완료 추적
- **리스크 관리:** 블로커/지연 징후 탐지, **컷 스위치** 제안
- **증빙팩 운영:** OpenAPI 스냅샷, 에러 카탈로그, 데모 스크립트/영상, p50/p95·429 샘플 수집

### **2.2 상태 모델(칸반)**

```
STATE := BACKLOG | READY | IN_PROGRESS | BLOCKED | REVIEW | DONE
SEVERITY := LOW | MEDIUM | HIGH
RISK := ON_TRACK | AT_RISK | OFF_TRACK
```

**판정 규칙(자동화 지표):**

- AT_RISK: 해당 주 DoD 항목 중 미완료 ≥ 1이고, 남은 근무시간 < 50%.
- OFF_TRACK: 주말(일) 20:00 KST 기준 핵심 DoD 미달.
- BLOCKED: 외부 의존/DDL 락/스키마 충돌로 4h 이상 진행 불가.

## **3) 백엔드 AI 가이드 (Dev Tutor/Codegen)**

### **3.1 기술 스택·규약**

- **언어/런타임:** TypeScript + Node.js
- **프레임워크:** **Fastify**(권장) _또는_ NestJS (컨트롤러/서비스 분리)
- **DB:** PostgreSQL(서버 타임 UTC), 마이그는 **idempotent SQL 스크립트**
- **보안:** bcrypt≥12 _또는_ Argon2id, Access JWT TTL 15–30m
- **오류 규격:** **RFC7807(JSON)**

### **3.2 공통 미들웨어**

- 요청 요약 로그: method, path, status, latency(ms), user(옵션)
- 에러 매핑: 409(UNIQUE/경합), 422(CHECK/FK), 423(논리락), 429(rate)
- 컨텍스트 주입: SET LOCAL app.user_id, SET LOCAL app.change_reason (필요시)

### **3.3 이벤트 로그 & 폴링 규약**

- **append 함수**(트랜잭션 안에서 호출):

```
type EventData = Record<string, unknown>
async function appendEvent(client, type:string, resourceId:number|null, floor:string|null, corrId:string|null, data:EventData) {
  await client.query(
    'INSERT INTO event_log(type,resource_id,floor_code,correlation_id,data) VALUES ($1,$2,$3,$4,$5)',
    [type, resourceId, floor, corrId, JSON.stringify(data)]
  )
}
```
    
- **폴링 쿼리(예시)**:

```
SELECT event_id, created_at, type, resource_id, floor_code, correlation_id, data
FROM event_log
WHERE event_id > $1
  AND ($2::bigint IS NULL OR resource_id=$2)
  AND ($3::text  IS NULL OR floor_code=$3)
ORDER BY event_id ASC
LIMIT $4;
```
    
- **응답 스키마**: { lastId:number, events: Event[] } (마지막 행의 event_id를 lastId로)

### **3.4 트랜잭션 패턴(핵심)**

- **라벨 교체(원자적)**: BEGIN; UPDATE old SET removed_at=now(); INSERT new(label_no 동일); COMMIT; 실패 시 전부 롤백.
- **검사 세션**: 자원당 진행중 단일(부분 UNIQUE). 3번째 참여 시 409/422.
- **423 락 판단**: resource_locks를 근거로 앱 미들웨어에서 **쓰기 요청을 차단**.
- **제출 후 불변**: 결과 INSERT/DELETE 금지, UPDATE는 리비전 트리거로 version +1.
- **벌점 조정**: delta_points <> 0 체크, 집계는 뷰로(카티전 곱 방지).

### **3.5 엔드포인트 DoD(샘플)**

- /auth/login: 실패 401, 성공 시 httpOnly 쿠키(또는 Bearer) + /me 반환 일관성
- /items: LIKE 검색, 페이징, 활성 라벨 UNIQUE 위반 시 409, 모든 응답에 floor_code
- /inspections/*: 2인 제약/423 락 적용, action_recorded 이벤트 발생
- /inspections/:id/submit: 멱등(재요청 동일 응답), 결과 불변, 원본 벌점 생성 이벤트
- /penalties/summary: 사용자별 original/adjusted/total

### **3.6 테스트 최소 세트**

- **계약 테스트** /events/poll: sinceId/limit/순서/중복 없음
- **속성 테스트** 라벨 교체: remove→create 원자성, 충돌 시 전부 롤백
- **E2E(슈퍼테스트)**: 로그인→등록→검사→제출→벌점 경로 1개

### **3.7 성능·관측(라이트)**

- p50/p95(ms) 콘솔 집계(5분 롤업) 또는 로그 파서
- 429 비율 출력(분당)

## **3) API 계약 (MVP v0)**

> **RFC7807 오류 규격** 사용. 공통 에러 매핑: 401 인증, 403 권한, 409 경합(UNIQUE/세션 좌석), 422 유효성·CHECK/FK, 423 논리 락(세션 중 쓰기 차단), 429 레이트.

### **3.1 인증/유저**

- **POST /auth/login** { username, password } → { token, user }
- **GET /me** → { user:{user_id, display_name, roles:string[], region?}, token_ttl }

### **3.2 자원/아이템**

- **GET /resources?type=FRIDGE_COMP&floor=F1&page&size** → { items:[{resource_id,label,floor_code,status}], total }
- **GET /items?query=&page=&size=&resourceId** → { items:[ItemBundle], total }
- **POST /items** { resource_id,label_no,name,quantity,expires_on,memo? } → { bundle_id, ... }
- **PATCH /items/:id/adjust** { quantityDelta|name|expires_on|memo } → { ok:true }

## **4) 네트워킹 규칙(클라이언트)**

- **토큰**: httpOnly 쿠키 가정 → 클라에서 토큰 저장/전송 로직 없음.
- **에러 변환**: 모든 오류를 AppError { status, code, title, detail, problems? }로 표준화.
- **재시도**: 5xx는 지수 백오프 최대 3회. 409/422/423은 **재시도 금지**.
- **권한/세션**: 401 → 로그인 리다이렉트, 403 → 접근 차단 배너.
