# 리코 인턴십 과제 B: 누리장터 입찰공고 크롤링 프로젝트 설계 및 구현

## 프로젝트 컨텍스트
- **목표**: 동적 렌더링 입찰공고 페이지에서 목록·상세 수집 → 표준 스키마 저장
- **평가 기준**: 정확성, 견고함(예외처리), 재현성, 코드품질(모듈화), 문서/테스트
- **제품 수준 요구**: 재시작 지원, 중복 방지, interval/cron 모드, 로그
- **최종 목표**: Python으로 구현하되 Spring Boot 백엔드 아키텍처 원칙 적용
- **기술 선택**: Python 3.11+ / Playwright (Tank Stack) / selectolax / pytest

## 당신의 4가지 역할 통합 미션

당신은 이제 **아키텍트 + 구현자 + 테스터 + 문서 작성자** 역할을 동시에 수행합니다.

---

## 🏗️ ROLE 1: 아키텍트 (Architecture Design)

### 요구사항
백엔드 원칙(Repository 패턴, Dependency Injection, SRP, Open/Closed)을 적용한 디렉토리 구조와 핵심 클래스 인터페이스를 설계하세요.

### 필수 산출물
1. **디렉토리 구조**
```markdown
nurijangteo-crawler/
├── README.md
├── requirements.txt
├── config/
│   └── settings.yaml          # 키워드, 페이지수, 저장경로
├── src/
│   ├── domain/                # BidNotice 도메인 모델
│   ├── repository/            # 추상 인터페이스 + CSV구현
│   ├── parser/                # HTML 파서 인터페이스
│   ├── driver/                # Playwright 드라이버
│   ├── service/               # ScrapingService (오케스트레이터)
│   └── utils/                 # 로깅, 예외 정의
├── cli.py                     # 실행 진입점
├── tests/                     # pytest 테스트
├── data/                      # 결과 저장
└── logs/                      # 실행 로그
```

2. **핵심 클래스 시그니처** (Python 타입힌트 포함)
```python
# domain/bid_notice.py
@dataclass
class BidNotice:
    notice_id: str
    title: str
    organization: str
    date: datetime
    region: str
    # … 기타 필드

# repository/bid_repository.py
class BidRepository(ABC):
    @abstractmethod
    def save(self, notice: BidNotice) -> None: …
    @abstractmethod
    def exists(self, notice_id: str) -> bool: …
    @abstractmethod
    def get_last_processed_id(self) -> Optional[str]: …

# service/scraping_service.py
class ScrapingService:
    def __init__(self, 
                 driver: PlaywrightDriver, 
                 parser: HtmlParser,
                 repository: BidRepository):
        …
    async def scrape(self, keyword: str, max_pages: int) -> int: …
```

3. **Spring Boot 마이그레이션 가이드**
- Repository → JpaRepository 교체 방안
- Service → @Service + @Async 적용 방안
- 설정 → application.yml 변환 가이드

## 💻 ROLE 2: 코드 구현자 (Implementation)

### 요구사항
위 설계를 바탕으로 실제 동작하는 코드를 구현하세요.

### 필수 구현 기능
1. **PlaywrightDriver** (driver/playwright_driver.py)
   - 브라우저 초기화, 페이지 이동, HTML 추출
   - 타임아웃 처리, 재시도 로직 (3회)
   - Context manager 패턴 적용

2. **SelectolaxParser** (parser/selectolax_parser.py)
   - HTML → BidNotice 객체 변환
   - CSS Selector로 핵심 필드 추출
   - 노이즈 처리 (공백 제거, None 체크)

3. **CSVRepository** (repository/csv_repository.py)
   - pandas 사용해서 CSV 저장
   - 중복 체크 (notice_id 기준)
   - 마지막 처리 ID 저장/로드 (재시작 지원)

4. **ScrapingService** (service/scraping_service.py)
   - 목록 페이지 순회
   - 각 공고 상세 진입
   - 파싱 → 중복체크 → 저장
   - 진행률 로깅

5. **CLI** (cli.py)
   - argparse로 `--keyword`, `--pages`, `--mode` 옵션
   - 모드: once / resume (재시작)

### 코드 품질 기준
- 타입힌트 필수
- docstring 작성
- 매직넘버 제거 (상수화)
- 에러 발생 시 구체적 메시지

## 🧪 ROLE 3: 테스터 (Testing & Validation)

### 요구사항
pytest로 핵심 기능 검증 및 엣지 케이스 체크

### 필수 테스트 케이스
1. **test_repository.py**
   - 저장 후 중복 체크 시 exists() True 반환
   - 마지막 ID 저장/로드 정확성
   - CSV 파일 없을 때 초기화

2. **test_parser.py**
   - 정상 HTML → BidNotice 객체 변환
   - 필드 누락된 HTML 처리 (None 또는 기본값)
   - 빈 HTML 입력 시 예외 발생

3. **test_service.py** (Mock 사용)
   - Mock Repository/Driver로 전체 플로우 검증
   - 중복 공고 들어왔을 때 스킵
   - 네트워크 에러 시 재시도

### 엣지 케이스 체크리스트
- [ ] 누리장터 접속 실패 (타임아웃)
- [ ] 중간에 프로세스 강제 종료 후 재시작
- [ ] 공고 번호 중복
- [ ] 페이지 끝 도달 (다음 버튼 없음)
- [ ] 상세 페이지 404
