### 스택 알고리즘의 해결 트리거: Identity vs Condition
스택을 사용하는 알고리즘에서 `push`는 데이터를 '임시 저장'하는 행위이며, **`pop`은 문제가 '해결'되었음을 의미**합니다. 이 해결의 기준(Trigger)은 크게 두 가지로 나뉩니다

#### **1. Identity 기반: 고유 정체성 매칭 (Fixed Entity Matching)**

스택의 최상단(`Top`)에 저장된 **'대기 데이터'**가, 현재 입력된 **'비교 데이터'**와 **미리 정의된 짝(Pair)**을 이룰 때, 비로소 **해결(`Pop`)**

- **핵심 메커니즘:** **구조적 정합성** 검증
- **동작 특징:**
    - **단발성 해결:** 조건이 맞으면 즉시 1개의 해당 요소를 `pop` 합니다.
    - **저장 데이터:** 주로 **값** 자체를 스택에 저장합니다.
- **구현 로직:** `if` 문을 사용한 단순 비교.
- **활용:** 유효 괄호, 문자열 폭발, 후위 표기법 계산.

```Python
# [Identity 기반 패턴]
# 1:1 매칭이 확인되면 즉시 1개 해결
if stack and stack[-1] == pair_map[char]:
    stack.pop()
```

#### **2. Condition 기반: 상대적 속성 매칭 (Relative Property Matching)**

데이터의 종류가 아닌, 스택 내부 원소와 현재 원소 간의 **대소 관계(Inequality)**가 성립할 때 로직이 실행됩니다. 이를 **단조 스택(Monotonic Stack)** 알고리즘이라 부릅니다.

- **핵심 메커니즘:** **선형 탐색 최적화(Optimization)**
- **트리거 조건:** `stack.peek()`와 `current_value` 사이의 **특정 부등식(>, <)**이 깨지는가?
- **동작 특징:**
    - **연쇄적 해결:** 조건이 만족되는 한, 스택에 쌓인 과거의 데이터들을 **연속적(`while`)**으로 `pop` 해 일괄적으로 정산합니다
    - **저장 데이터:** 위치 계산을 위해 주로 **인덱스(Index)**를 스택에 저장합니다.
- **구현로직:** `while` 루프를 사용한 지속적 비교.
- **활용:** 일일 온도(NGE: Next Greater Element), 오큰수, 히스토그램 최대 넓이.

```Python
# [Condition 기반 패턴]
# 조건(더 큰 값이 옴)을 만족하는 모든 과거 데이터 해결
while stack and stack[-1][0] < current_val:
    value, index = stack.pop()
    # 인덱스 차이 계산 등 후처리 로직
```

### **3. 심층 비교 (Technical Comparison)**

|**구분**|**Identity 기반 (정체성)**|**Condition 기반 (조건/단조스택)**|
|---|---|---|
|**판단 기준**|**Equality ($==$)**<br><br>  <br><br>(값이 일치하는가?)|**Inequality ($>, <$)**<br><br>  <br><br>(단조성이 깨졌는가?)|
|**스택 데이터**|**값 (Value)**<br><br>  <br><br>(예: `(`, `{`)|**인덱스 (Index)**<br><br>  <br><br>(거리 계산을 위해 필수)|
|**제어문**|**`if`** (1회성 검사)|**`while`** (연쇄적 검사)|
|**해결 범위**|**1:1** (현재 값 1개가 과거 1개를 해결)|**1:N** (현재 값 1개가 과거 N개를 해결)|
|**시간 복잡도**|$O(N)$ (단순 순회)|$O(N)$ (모든 요소는 최대 1번 push/pop)|
|**목적**|**Parsing / Validation**<br><br>  <br><br>(문법이나 구조가 맞는가?)|**Search Optimization**<br><br>  <br><br>($O(N^2)$ 탐색을 $O(N)$으로 단축)|

### **4. 요약 및 결론**

두 방식 모두 **"현재의 데이터(Current)가 과거의 데이터(Stack Top)를 처리한다"**는 대전제는 같습니다.

1. **Identity 기반:**
    
    - **"맞는 짝인가?"**를 묻습니다.
    - 데이터의 **무결성(Integrity)**을 검증하는 것이 목표입니다.
        
2. **Condition 기반:**
    
    - **"나보다 작거나 큰가?"**를 묻습니다.
    - 이중 루프를 없애고 **탐색 효율(Efficiency)**을 극대화하는 것이 목표입니다. 이것이 바로 **단조 스택**의 정체입니다.
