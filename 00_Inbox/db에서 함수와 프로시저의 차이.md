## 정리

사용자가 작성한 **SQL**은 데이터 요구사항을, **함수와 프로시저**는 구체적인 비즈니스 로직을 정의하며, **DBMS의 옵티마이저**는 이를 수행하기 위한 최적의 실행 순서와 접근 경로를 결정하여 데이터 처리를 실행합니다.

---

## 📜 정리: SQL, 로직, 그리고 옵티마이저

### 종합 요약 (Logic Flow)

> [!note]- 데이터베이스 작동 메커니즘의 핵심
>
> 1. **역할의 분리:** 사용자가 작성한 **SQL**은 데이터 요구사항을, **함수와 프로시저**는 구체적인 비즈니스 로직을 정의하며, **DBMS의 옵티마이저**는 이를 수행하기 위한 방법(최적의 실행 순서와 접근 경로)을 결정하여 데이터 처리를 실행합니다.
>     
> 2. **로직의 구현 (User):** 사용자는 조회(Read) 로직은 **함수**로, 상태 변경작업+트랜잭션 제어(Write)의 로직은 **프로시저**로 구현하여 DBMS에 전달합니다.
>     
> 3. **실행의 최적화 (System):** 옵티마이저는 전달받은 로직(Target)을 분석하고, 인덱스 등(Tool)을 활용하여 비용이 가장 낮은 경로(Plan)를 수립해 실행합니다.
>     

## 1. 사용자의 영역: 요구사항과 로직의 정의 (What & Logic)

사용자는 데이터베이스에게 "무엇을(What)" 원하고 "어떤 로직(Logic)"으로 처리할지를 정의합니다.

### A. SQL (요구사항 정의)

- **역할:** 데이터의 추출, 조작, 제어에 대한 최종 **결과물(Requirement)**을 명세합니다.
- **특징:** 선언형 언어이므로 구체적인 탐색 경로(How)는 기술하지 않습니다.
    

### B. 함수와 프로시저 (비즈니스 로직 정의)

SQL만으로 표현하기 힘든 절차적 흐름이나 복잡한 연산을 정의합니다. 목적에 따라 두 가지 컨테이너로 나뉩니다.
처음엔 조회용으로 함수를 쓰다가, 값변경이 필요하자 트랜잭션제어기능을 넣은 프로시저를 도입했습니다
- select랑 독립적으로 실행되는 commit, rollback를 내부에 명시하는 프로시저를 도입했습니다
- 옵티마이저가 데이터를 읽고 있는 도중 즉, 조회과정에는 데이터의 무결성을 해치는 값 변경이 차단되므로 프로시저는 `SELECT` 문 내부에서 호출 불가하며 ㅇㅇ이렇게 쓰입니다
- 반환값이 핵심이 아닌 프로시저는 반환값 생략이 가능합니다.
---

## 2. DBMS의 영역: 실행 경로의 결정 (How & Optimization)

옵티마이저는 사용자가 정의한 SQL과 로직을 받아, 실제 하드웨어 리소스를 어떻게 사용할지 결정합니다. 이 과정에서 **'대상(Target)'**과 **'도구(Tool)'**가 엄격히 구분됩니다.

### A. 옵티마이저의 대상 (Targets)

옵티마이저가 분석하고 처리해야 할 **작업물**입니다.

- **SQL 문장:** 처리해야 할 기본 요청.
- **프로시저 & 함수:** 사용자가 정의한 로직의 집합. 옵티마이저는 이 안에 포함된 SQL들을 분석하여 비용(Cost)을 계산합니다. (좀더 상세 설명 추가)
    

### B. 옵티마이저의 도구 (Tools)

옵티마이저가 "어떻게 하면 데이터를 가장 빠르게 가져올까?"를 판단할 때 **참조하는 자원**입니다.

- **인덱스 (Index):** 데이터를 빠르게 찾기 위한 자료구조 (B-Tree 등).
- **통계 정보 (Statistics):** 데이터의 분포, 행의 개수, 블록 수 등 판단의 근거.
- **시스템 지표 (System Metrics):** CPU 속도, 디스크 I/O 속도 등 하드웨어 환경 정보.
    

### 🚨 주의: 로직(대상)이 도구(인덱스)를 방해하는 경우

사용자가 정의한 로직(함수)이 부적절할 경우, 옵티마이저는 도구(인덱스)를 사용할 수 없습니다.

- **Index Suppression:** `WHERE YEAR(date) = '2024'`와 같이 컬럼을 함수로 감싸면(좌변 가공), 옵티마이저는 변형된 `YEAR(date)` 값을 원본 `date`가 정렬된 인덱스에서 찾을 수 없습니다(인덱스 매칭 실패). 결국 옵티마이저는 인덱스를 포기하고, **전체 테이블 스캔(Full Table Scan)** 을 수행합니다.
