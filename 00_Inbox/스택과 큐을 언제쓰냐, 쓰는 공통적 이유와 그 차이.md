## 해결할 짝을 찾을 때까지 대기시키기 위해 스택과 큐을 사용한다.

데이터를 잠시 대기시켜야 할 때, **'어떤 순서로 꺼낼 것인가'**가 자료구조 선택의 기준이 됩니다.

### **① 스택 (Stack): 의존성 해결 (Dependency Resolution)**

나중에 발생한 사건이 해결되어야, 이전에 발생한 사건도 비로소 해결될 수 있는 구조입니다.

- **논리:** **사건 간의 종속성(Dependency)**이 존재합니다. 최근(안쪽)의 작업이 완료되지 않으면, 과거(바깥쪽)의 작업은 영원히 대기 상태에 머물게 됩니다.
- **대표적 상황:**
    - **유효 괄호:** 가장 안쪽 괄호가 닫혀야 바깥쪽 괄호가 완성됩니다.
    - **함수 호출 (Call Stack):** 호출된 자식 함수가 종료되어야 부모 함수로 제어권이 돌아갑니다.
    - **DFS (깊이 우선 탐색):** 더 이상 갈 곳이 없을 때까지 깊게 들어갔다가 나옵니다.
### **② 큐 (Queue): 순차적 처리 (Sequential Processing)**

먼저 발생한 사건을 순서대로 처리해야 하는 구조입니다.

- **논리:** **시간적 공정성(Fairness)**을 보장합니다. 발생한 순서대로 데이터를 처리하며, 사건 간의 종속성보다는 순서 자체가 중요합니다.
- **대표적 상황:**
    - **BFS (너비 우선 탐색):** 시작점에서 가까운 노드부터 계층적으로 방문합니다.
    - **프로세스 관리:** CPU 스케줄링, 프린터 대기열 등 자원 할당 순서를 관리합니다.
    - **메시지 큐:** 비동기 시스템에서 이벤트를 발생 순서대로 처리합니다.

## 2. 스택의 해결 트리거 (Identity vs Condition)

스택 알고리즘에서 `push`는 **결정의 유보(Deferral)**를, `pop`은 **문제의 해결(Resolution)**을 의미합니다. 해결을 촉발하는 트리거(Trigger)는 크게 두 가지 패턴으로 나뉩니다.

>[!IMPORTANT] **💡 핵심 원리: $O(N)$의 비밀 (Single-pass)**
> 두 패턴 모두 **"한 번 해결(pop)된 데이터는 다시는 연산에 관여하지 않는다"**는 원칙을 공유합니다. 이 '일방향성' 덕분에 매 순간 과거를 전수 조사해야 하는 $O(N^2)$의 중복 탐색을 **단 한 번의 순회($O(N)$)**로 압축할 수 있습니다.
### **① Identity 기반: 고유 정체성 매칭 (Validation)**
> **핵심 질문:** "지금 들어온 데이터(`Current`)가 스택 `Top`의 **유일한 짝(Pair)**인가?"

스택의 **`Top`(최우선 대기자)** 데이터가 가진 고유한 값(Value)이, 진입하는 데이터와 사전에 정의된 **일대일 대응 관계**를 이룰 때 즉각적으로 정산합니다.

- **메커니즘:** **구조적 무결성 검증** (위계와 문법이 올바른가?)
- **동작 특징:**
    - **단발성 해결:** `if` 문을 통해 1:1 매칭 확인 시 즉시 1개의 요소를 `pop` 합니다.
    - **데이터:** 연산을 위해 주로 **값(Value)** 자체를 저장합니다.
- **활용 예시:** 유효 괄호 검사, HTML/XML 태그 매칭, 문자열 폭발.

```Python
# [Identity Pattern]
# 1:1 정체성 확인 즉시 1개 해결
if stack and stack[-1] == pair_map[current_val]:
    stack.pop()
```

### **② Condition 기반: 상대적 속성 매칭 (Optimization)**

> **핵심 원리:** "지금 들어온 한 데이터가 **과거의 보류된 정답들을 도미노처럼 해결**한다."

원소 간의 **대소 관계(Inequality)**가 성립할 때 로직이 실행됩니다. 이를 **단조 스택(Monotonic Stack)**이라 부릅니다.

- **메커니즘:** **선형탐색 최적화** (불필요한 중복 탐색을 $O(N)$으로 단축)
- **동작 특징:**
    - **연쇄적 해결:** Top이 조건이 만족되지 않을때까지 **연속적(`while`)**으로 `pop` 을 반복해 처리합니다.
    - **데이터:** 거리나 기간 계산을 위해 주로 **인덱스(Index)**를 저장합니다.
- **활용 예시:** 일일 온도, 주식 가격 변동, 히스토그램 최대 넓이.

```Python
# [Condition Pattern]
# 조건을 만족하는 모든 과거 데이터 연쇄 정산 (Cascade)
while stack and temperatures[stack[-1]] < current_temp:
    prev_index = stack.pop()
    answer[prev_index] = current_index - prev_index
```

## 3. 비교 분석 (Comparison)

> [!TIP] **💡 핵심 인사이트**
>
> - **Identity 기반**은 "누가(Who)" 왔는지가 중요하며, 이는 **구조적 정합성(틀린곳찾기)** 검증 문제입니다.
> - **Condition 기반**은 "어떤 상태(Status)"인가가 중요하며, 이는 **탐색의 최적화(가장빠른답찾기)** 문제입니다.
### **기술적 속성 비교**

| **구분**    | **Identity (정체성)** | **Condition (조건/단조)** |
| --------- | ------------------ | --------------------- |
| **판단 기준** | **동등성 ($==$)**     | **부등성 ($>, <$)**      |
| **핵심 목적** | **무결성검증** (틀린곳 찾기) | **효율성극대** (빠른 정답찾기)   |
| **제어 흐름** | **`if`** (1회성 검사)  | **`while`** (연쇄적 검사)  |
| **해결 범위** | **1 : 1** 대응       | **1 : N** 대응 (다대일)    |
| **해결 조건** | 고유한 짝이 맞아야 함       | 특정 임계치를 넘어야 함         |
| **저장 정보** | **값 (Value)** 위주   | **위치 (Index)** 위주     |

### **실제 문제 적용 예시**

| **구분**      | **유효 괄호 (Identity)**      | **일일 온도 (Condition)**                  |
| ----------- | ------------------------- | -------------------------------------- |
| **스택 저장 값** | 여는 괄호 문자 (`(`, `{`, `[` ) | 더 따뜻한 날을 못 만난 **인덱스**                  |
| **대기 이유**   | 자신과 맞는 **'짝'**을 찾기 위해     | 자신보다 **'높은 온도'**를 찾기 위해                |
| **해결 시점**   | 일치하는 닫는 괄호가 등장할 때         | 현재 온도가 스택 `top` 온도보다 높을 때              |
| **해결 후 동작** | `pop()`으로 제거 (짝 맞춤 완료)    | `pop()` + **인덱스 차이(날짜) 기록**            |
| **핵심 로직**   | `if stack.pop() == pair:` | `while stack and T[stack[-1]] < T[i]:` |

## 4. 요약 및 결론

두 방식은 **"미래의 데이터가 과거의 보류된 작업(Pending Tasks)을 해결한다"**는 스택의 본질을 공유하지만, 그 해결의 성격은 명확히 구분됩니다.

1. **Identity 기반**: **구조의 완결성**
	- 데이터 간의 **1:1 짝**이 맞는지 검증합니다. 짝이 맞지 않으면 구조 전체가 무효화되는 '정답이 정해진' 문제를 다룹니다.
2. **Condition 기반**: **탐색의 최적화**
	- 특정 조건을 만족하는 '가장 가까운 미래의 값'을 찾습니다.현재 데이터 하나가 스택 속의 여러 과거 데이터를 **연쇄적으로 해결(Cascade)**하는 데 집중합니다.
