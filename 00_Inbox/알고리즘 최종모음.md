# 📚 알고리즘 핵심 노트: 분할 정복 & 합병 정렬

## Topic 1. 분할 정복의 메커니즘과 실행 흐름 (Divide & Conquer)

### 1. 🏗️ 빌드업 (Context)

> **"거대한 문제는 작게 쪼개서 각개격파한다."**

- **개념:** 문제를 더 이상 쪼갤 수 없는 단위까지 나누어 해결한 뒤, 다시 합쳐서 답을 구하는 전략입니다.
- **유래:** 나폴레옹이 대규모 적을 소규모로 분산시킨 뒤 각개격파(Divide)하고 정복(Conquer) 했던 전술에서 유래했습니다.
    

### 2. 🔄 3단계 메커니즘 및 실행 흐름 (The "V" Shape Flow)

이 알고리즘은 **DFS(깊이 우선 탐색)** 순서로 작동하며, **"위에서 호출하고(Call), 아래에서 결과를 Return하는"** 체계적인 흐름을 가집니다.

#### ① 분할 (Divide) : 📉 내려가는 흐름 (Top-down)

- **주어 (Subject):** **함수의 호출 (Command)**
- **행위:** 문제를 해결하기 쉽도록 반으로 쪼개라는 **명령**이 위에서 아래로 전달됩니다.
- **상태:** 이 단계에서는 아직 **데이터가 정렬되지 않은 상태**로 쪼개지기만 합니다.
#### ② 정복 (Conquer) : 🛑 바닥 찍기 (Base Case)

- **시점:** 더 이상 쪼개지지 않는 원자 단위(Atomic Level, Size=1)에 도달했을 때입니다.
- **역할:** 재귀 호출이 멈추고(Stop), **반환(Return)의 기점**이 됩니다.

#### ③ 결합 (Combine) : 📈 올라오는 흐름 (Bottom-up)

- **주어 (Subject):** **실제 데이터의 처리 (Execution)**
- **행위:** 바닥에서 처리된 **결과물(데이터)**이 정렬/병합되어 위로 보고됩니다.
- **핵심:** **"호출 순서는 위에서 아래로 깊어지며 내려왔지만, 실제 정렬(해결)은 깊은 바닥에서부터 올라오며 완성됩니다."**

이 논리(**Divide** $\leftrightarrow$ **Combine**)를 사용하는 대표적인 알고리즘 목록입니다.

| **알고리즘**                        | **핵심 전략 (어디에 힘을 주는가?)**                                                                 |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| **1. 합병 정렬**(Merge Sort)        | **Combine이 핵심:** 일단 끝까지 쪼갠 뒤, **올라오면서(Combine)** 정렬을 수행함.                               |

| **3. 이진 탐색**<br>(Binary Search) | **선택적 정복:** 둘 중 답이 있는 **한쪽만** 파고듦. (합치는 과정 없음)                                          |

## Topic 3. 합병 정렬 (Merge Sort) 상세 구현

### 1. 🏗️ 빌드업 (Logic)

> **"이미 정렬된 두 개의 그룹을 합치는 것은 쉽다."**

- **전략:** 데이터가 1개가 될 때까지 쪼개면(Divide) 그 자체로 '정렬된 상태'가 됩니다. 이 상태에서 두 그룹을 합치며(Merge/Combine) 올라오면 전체가 정렬됩니다.
    

### 2. 코드 구현 (C Language)

**Step 1. 분할 및 제어 (`merge_sort` 함수)**

- **역할 (Manager):** 전체 숲을 보며 나무를 쪼개는 관리자입니다.
- **흐름:** `Left` 명령(📉) $\rightarrow$ `Right` 명령(📉) $\rightarrow$ 보고 받으면 `Merge` 실행(📈).
    

C

```sql
// 분할 함수 (Divide)
void merge_sort(int list[], int left, int right) {
    int mid;

    // Base Case: 데이터가 1개일 때 멈춤 (Conquer)
    if (left < right) {
        mid = (left + right) / 2;

        // 1. 왼쪽을 쪼개라! (명령 하달 -> 깊게 들어감)
        merge_sort(list, left, mid);

        // 2. 오른쪽을 쪼개라! (명령 하달 -> 깊게 들어감)
        merge_sort(list, mid + 1, right);

        // 3. 둘 다 바닥을 찍고 결과가 올라오면 병합하라! (실제 작업)
        merge(list, left, mid, right);
    }
}
```

**Step 2. 병합 및 정렬 (`merge` 함수)**

- **역할 (Worker):** 실무를 담당하는 일꾼입니다. 정렬된 두 리스트를 합칩니다.
- **메모리:** `sorted`라는 추가 공간(임시 배열)이 반드시 필요합니다.
    

C

```sql
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 추가 메모리 공간 (필수)

// 병합 함수 (Combine Logic)
void merge(int list[], int left, int mid, int right) {
    int i = left, j = mid + 1, k = left;
    int l;

    // 두 리스트(Left Part, Right Part)를 비교하여 작은 순서대로 sorted에 삽입
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) sorted[k++] = list[i++];
        else sorted[k++] = list[j++];
    }

    // 남은 데이터 처리 (나머지 일괄 복사)
    if (i > mid) {
        for (l = j; l <= right; l++) sorted[k++] = list[l];
    } else {
        for (l = i; l <= mid; l++) sorted[k++] = list[l];
    }

    // 임시 배열 내용을 원본에 반영 (Update)
    for (l = left; l <= right; l++) list[l] = sorted[l];
}
```

# 📚 알고리즘 핵심 노트: 분할 정복 & 합병 정렬

## Topic 1. 분할 정복의 메커니즘과 실행 흐름 (Divide & Conquer)

### 1. 🏗️ 빌드업 (Context)

> **"거대한 문제는 작게 쪼개서 각개격파한다."**

- **개념:** 문제를 더 이상 쪼갤 수 없는 단위까지 나누어 해결한 뒤, 다시 합쳐서 답을 구하는 전략입니다.
- **핵심 특징:** **재귀(Recursion)**를 사용하므로 필연적으로 **DFS(깊이 우선 탐색)** 순서로 작동합니다.
    

### 2. 🔄 3단계 메커니즘 및 실행 흐름 (The "V" Shape Flow)

알고리즘은 **"위에서 쪼개고(Divide) $\rightarrow$ 바닥을 찍고(Conquer) $\rightarrow$ 올라오며 합치는(Combine)"** U자형(혹은 V자형) 흐름을 탑니다.

#### ① 분할 (Divide) : 📉 위에서 아래로 (Top-down)

문제를 해결하기 쉽도록 하위 문제(Sub-problem)로 쪼개며 들어가는 단계입니다.

- **실행 흐름 (Call):** 함수가 자기 자신을 계속 호출하며 스택(Stack)을 쌓습니다.
- **방향:** 뿌리(Root) $\rightarrow$ 잎(Leaf). (전위 순회)
- **비유:** 마트료시카 인형을 계속 열어서 더 작은 인형을 꺼내는 과정.
    

#### ② 정복 (Conquer) : 🛑 바닥 찍기 (Base Case)

더 이상 쪼개지지 않는 원자 단위(Atomic Level, Size=1)에 도달했을 때입니다.

- **실행 흐름 (Return):** 재귀 호출이 멈추고(Stop), 값을 반환(Return)하기 시작하는 반환점입니다.
- **역할:** 여기서부터 문제가 실제로 '해결'되기 시작합니다.
    

#### ③ 결합 (Combine) : 📈 아래에서 위로 (Bottom-up)

반환된 하위 문제의 해답을 모아서 전체 문제의 답을 구합니다.

- **실행 흐름 (Merge):** 자식 함수들이 리턴되어야만 부모 함수가 깨어나서 이 단계를 실행합니다.
- **방향:** 잎(Leaf) $\rightarrow$ 뿌리(Root). (후위 순회)
- **중요:** **"코드는 위에서 아래로 작성했지만, 실제 답은 가장 깊은 곳에서부터 완성되어 수면 위로 올라옵니다."**

## Topic 3. 합병 정렬 (Merge Sort) 상세 구현

### 1. 🏗️ 빌드업 (Logic)

> **"이미 정렬된 두 개의 그룹을 합치는 것은 쉽다."**

- **전략:** 데이터가 1개가 될 때까지 쪼개면(Divide) 그 자체로 '정렬된 상태'가 됩니다. 이 상태에서 두 그룹을 합치며(Merge/Combine) 올라오면 전체가 정렬됩니다.
    

### 2. 코드 구현 (C Language)

**Step 1. 분할 및 제어 (`merge_sort` 함수)**

- **역할:** 전체 숲을 보며 나무를 쪼개는 관리자.
- **흐름:** `Left` 호출(📉) $\rightarrow$ `Right` 호출(📉) $\rightarrow$ 둘 다 돌아오면 `Merge` 수행(📈).
    

C

```sql
// 분할 함수 (Divide)
void merge_sort(int list[], int left, int right) {
    int mid;

    // Base Case: 데이터가 1개일 때 멈춤 (Conquer)
    if (left < right) {
        mid = (left + right) / 2;

        // 1. 왼쪽으로 깊게 파고듬 (Divide Left)
        merge_sort(list, left, mid);

        // 2. 오른쪽으로 깊게 파고듬 (Divide Right)
        merge_sort(list, mid + 1, right);

        // 3. 둘 다 바닥을 찍고 리턴되면 병합 (Combine)
        // *실제 실행은 가장 깊은 곳(Leaf)부터 시작됨*
        merge(list, left, mid, right);
    }
}
```

**Step 2. 병합 및 정렬 (`merge` 함수)**

- **역할:** 실무를 담당하는 일꾼. 정렬된 두 리스트를 합칩니다.
- **메모리:** `sorted`라는 추가 공간(임시 배열)이 반드시 필요합니다.
    

C

```sql
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 추가 메모리 공간 (필수)

// 병합 함수 (Combine Logic)
void merge(int list[], int left, int mid, int right) {
    int i = left, j = mid + 1, k = left;
    int l;

    // 두 리스트(Left Part, Right Part)를 비교하여 작은 순서대로 sorted에 삽입
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) sorted[k++] = list[i++];
        else sorted[k++] = list[j++];
    }

    // 남은 데이터 처리 (나머지 일괄 복사)
    if (i > mid) {
        for (l = j; l <= right; l++) sorted[k++] = list[l];
    } else {
        for (l = i; l <= mid; l++) sorted[k++] = list[l];
    }

    // 임시 배열 내용을 원본에 반영 (Update)
    for (l = left; l <= right; l++) list[l] = sorted[l];
}
```

### 3. 🔄 실행 흐름 (DFS & Recursion)

모든 분할 정복 알고리즘은 **재귀(Stack 메모리)**를 사용하므로 필연적으로 **DFS(깊이 우선 탐색)** 흐름을 따릅니다.

#### 1️⃣ 코드의 작성 순서 (What logic says)

우리가 작성한 코드는 단순히 위에서 아래로 읽힙니다.

1. **Divide Left:** 왼쪽을 쪼개라.
2. **Divide Right:** 오른쪽을 쪼개라.
3. **Merge:** 다 쪼개졌으면 합쳐라.
    

#### 2️⃣ 실제 실행 시점 (When it happens)

하지만 컴퓨터가 이 코드를 실행할 때는 **"가장 깊은 바닥(Base Case)"**을 볼 때까지 3번(Merge)을 실행하지 못하고 대기합니다.

- **📉 호출 (Divide / 전위 순회):**
    - `merge_sort` 함수가 호출되면 즉시 실행되는 것이 아니라, 계속해서 자기 자신을 호출하며 **스택(Stack)을 쌓으며 내려갑니다.**
    - 마치 "상자 안에 상자가 계속 있는 구조"처럼 가장 안쪽 상자(데이터가 1개)가 나올 때까지 계속 들어갑니다.
- **📈 완료 및 결합 (Combine / 후위 순회):**
    - **"부모는 자식이 일을 끝내고 돌아올 때까지 기다립니다."**
    - 가장 깊은 바닥(데이터 1개)에서 함수가 리턴(종료)되어야만, 비로소 대기하고 있던 그 윗단계 함수가 깨어나서 **`merge()`(3번)**를 실행합니다.
    - 즉, **코드는 위에서 아래로 썼지만, 실제 정렬(Merge)은 가장 깊은 곳에서부터 완료되어 수면 위로 올라옵니다.**
        

> **요약:** `merge()` 함수는 코드상으로는 바로 아랫줄에 있지만, 실제로는 **좌/우의 모든 재귀 호출이 바닥을 찍고 리턴된 후에야** 비로소 실행 기회를 얻습니다.

Plaintext

```sql
    … (바닥 찍고 리턴!) …
    -> 1번 완료

2. merge_sort(Right) --> 호출! (아직 안 끝남, 더 깊이 들어감)
    … (재귀 깊숙이 들어가는 중) …
    … (바닥 찍고 리턴!) …
    -> 2번 완료

3. merge(Combine)    --> 1번과 2번이 모두 "완료된 후"에야 드디어 실행!
```

# 📚 알고리즘 핵심 노트: 분할 정복 & 합병 정렬

## Topic 1. 분할 정복 (Divide and Conquer)

### 1. 🏗️ 빌드업 (Why & Context)

> **"거대한 문제는 작게 쪼개서 각개격파한다."**

- **동기:** 40명의 학생 중 '가위바위보 1등'을 뽑아야 한다면? 40명이 한꺼번에 붙으면 판정이 불가능합니다. 그룹을 계속 반으로 쪼개 2명씩 승부하게 하면 판정이 쉬워집니다.
- **유래:** 나폴레옹이 대규모 적을 소규모로 분산시킨 뒤 **각개격파(Divide)**하고 **정복(Conquer)**했던 전술에서 유래했습니다.
    

### 2. 💡 핵심 메커니즘 (3단계)

1. **분할 (Divide):** 문제를 해결하기 쉽도록 하위 문제(Sub-problem)로 쪼갭니다.
2. **정복 (Conquer):** 더 이상 쪼개지지 않는 원자 단위(Atomic level)까지 재귀적으로 파고들어 해결합니다.
3. **결합 (Combine):** 해결된 하위 문제의 답을 합쳐서 전체 문제의 해답을 구합니다.
    

### 3. 🔄 실행 흐름 (DFS & Recursion)

모든 분할 정복 알고리즘은 **재귀(Stack 메모리)**를 사용하므로 필연적으로 **DFS(깊이 우선 탐색)** 흐름을 따릅니다.

- **📉 호출(Divide)은 위에서 아래로:**
    - 문제는 계속 쪼개지며 깊이(Depth)가 깊어집니다. (Pre-order, 전위 순회)
- **📈 결합(Combine)은 아래에서 위로:**
    - 가장 작은 문제(바닥)가 해결되어야만 그 위 단계가 해결될 수 있습니다. (Post-order, 후위 순회)
    - 즉, **"호출은 뿌리에서 잎으로 가지만, 답은 잎에서 뿌리로 완성되어 올라옵니다."**

## Topic 2. 대표적인 분할 정복 알고리즘들

이 논리(쪼개고 $\rightarrow$ 깊게 들어가고 $\rightarrow$ 나오면서 해결)를 사용하는 대표적인 알고리즘들입니다.

### 1. 합병 정렬 (Merge Sort)

- **특징:** **"결합(Combine)" 단계가 핵심**인 알고리즘입니다.
- **논리:** 일단 끝까지 쪼갠 뒤, 올라오면서 **'정렬하며 합치는(Merge)'** 과정에서 실제 정렬이 이루어집니다.
    

### 2. 퀵 정렬 (Quick Sort)

- **특징:** **"분할(Divide)" 단계가 핵심**인 알고리즘입니다.
- **논리:** 기준값(Pivot)을 정해 **'미리 나누고(Partition)'** 들어갑니다. 내려가면서 정리가 되기 때문에, 합병 정렬과 달리 별도의 결합(Combine) 과정이 거의 필요 없습니다.
    

### 3. 이진 탐색 (Binary Search)

- **특징:** 하위 문제 중 **하나만 선택**하여 들어갑니다.
- **논리:** 범위를 반으로 쪼개지만, 답이 없는 쪽은 버리고 답이 있는 쪽으로만 깊게 들어갑니다. (결합 과정 없음)

## Topic 3. 합병 정렬 (Merge Sort) 상세 구현

### 1. 🏗️ 빌드업 (Logic)

> **"이미 정렬된 두 개의 그룹을 합치는 것은 쉽다."**

- **핵심 아이디어:** 무작위 데이터 $N$개를 바로 정렬하는 건 어렵지만, 데이터가 1개가 될 때까지 쪼개면 그 자체로 **'정렬된 상태'**가 됩니다. 이 상태에서 두 그룹을 합치며(Merge) 올라오면 전체가 정렬됩니다.
    

### 2. 코드 구현 (C Language)

**Step 1. 분할 및 제어 (`merge_sort` 함수)**

- **역할:** 전체 숲을 보며 나무를 쪼개는 관리자.
- `Left`를 끝까지 파고든 뒤(재귀), `Right`를 파고들고, 둘 다 돌아오면 `Merge`를 시킵니다.
    

C

```sql
// 분할 함수 (Divide)
void merge_sort(int list[], int left, int right) {
    int mid;

    // left == right일 때(데이터가 1개) 종료
    if (left < right) {
        mid = (left + right) / 2;

        // 1. 왼쪽으로 깊게 파고듬 (Divide Left)
        merge_sort(list, left, mid);

        // 2. 오른쪽으로 깊게 파고듬 (Divide Right)
        merge_sort(list, mid + 1, right);

        // 3. 둘 다 바닥을 찍고 올라오면 병합 (Conquer & Combine)
        merge(list, left, mid, right);
    }
}
```

**Step 2. 병합 및 정렬 (`merge` 함수)**

- **역할:** 실무를 담당하는 일꾼. 정렬된 두 리스트를 합칩니다.
- **필수:** `sorted`라는 임시 배열이 반드시 필요합니다.
    

C

```sql
#include <stdio.h>
#define MAX_SIZE 100

int sorted[MAX_SIZE]; // 추가 메모리 공간 (필수)

// 병합 함수 (Conquer & Combine)
void merge(int list[], int left, int mid, int right) {
    int i = left, j = mid + 1, k = left;
    int l;

    // 두 리스트를 비교하여 작은 순서대로 sorted에 삽입
    while (i <= mid && j <= right) {
        if (list[i] <= list[j]) sorted[k++] = list[i++];
        else sorted[k++] = list[j++];
    }

    // 남은 데이터 처리 (나머지 일괄 복사)
    if (i > mid) {
        for (l = j; l <= right; l++) sorted[k++] = list[l];
    } else {
        for (l = i; l <= mid; l++) sorted[k++] = list[l];
    }

    // 임시 배열 내용을 원본에 반영
    for (l = left; l <= right; l++) list[l] = sorted[l];
}
```

## 4. 📊 중요 분석 (Analysis)

|**구분**|**내용**|**비고**|
|---|---|---|
|**시간 복잡도**|**$O(N \log N)$**|데이터 상태와 무관하게 항상 일정. (안정적)|
