## Topic. 구조체: 선언 형태에 따른 접근과 확장

구조체 문법의 핵심은 **"선언된 변수가 값(Value)인가, 주소(Address)인가?"**를 파악하는 것입니다. 이 선언 형태가 접근 연산자를 결정하며, 나아가 메모리 관리와 연산 방식까지 지배합니다.

### 1. 🚦 핵심 원칙: 선언이 연산자를 결정한다

변수가 메모리에 존재하는 **실체**인지, 그 실체를 가리키는 **참조자**인지에 따라 사용하는 연산자가 달라집니다.

| **기준**      | **Case A: 구조체 변수 (Value)**           | **Case B: 구조체 포인터 (Address)**                            |
| ----------- | ------------------------------------ | -------------------------------------------------------- |
| **선언 형태**   | **`struct Type var;`**               | **`struct Type *ptr;`**                                  |
| **변수의 성격**  | 데이터 덩어리 (실체)                         | 메모리 주소값 (참조)                                             |
| **접근 연산자**  | **점 (`.`)**                          | **화살표 (`->`)**                                           |
| **접근 메커니즘** | **Direct Access**<br>(Base + Offset) | **Indirect Access**<br>(Dereference $\to$ Base + Offset) |
| **코드 예시**   | `var.age = 20;`                      | `ptr->age = 20;`                                         |

> **Note:** `ptr->age`는 `(*ptr).age`의 문법적 설탕(Syntactic Sugar)입니다. 포인터는 원칙적으로 역참조(`*`) 후 접근(`.`)해야 하지만, 편의를 위해 `->`를 제공합니다.

---
### 2. 💾 메모리 확장: 크기와 할당의 차이

선언 형태의 차이는 메모리 할당 방식과 크기 계산에도 그대로 적용됩니다.

#### 1) 구조체 변수 (`var`) 접근 시

- **메모리 실체:** 구조체 정의에 포함된 **모든 멤버의 크기 합**(Padding 포함)만큼 연속된 메모리가 할당됩니다.
- **배열 선언 시:** `struct Type arr[10];`은 구조체 덩어리 10개를 물리적으로 연속 배치합니다.
    

#### 2) 구조체 포인터 (`ptr`) 접근 시

- **메모리 실체:** 구조체의 크기와 무관하게, **주소를 담을 공간(32bit: 4B, 64bit: 8B)**만 할당됩니다.
- **배열 선언 시:** 포인터 배열 `struct Type *arr[10];`은 주소값 10개를 저장할 공간만 할당합니다. 실제 구조체는 별도로 연결(`malloc` 등)해야 합니다.
    

---

### 3. ⚔️ 함수 확장: 복사 비용 vs 참조 효율

함수에 구조체를 전달할 때도 선언 형태(접근 연산자)에 따라 성능과 동작이 갈립니다.

|**구분**|**Call by Value (값 전달)**|**Call by Reference (주소 전달)**|
|---|---|---|
|**매개변수 선언**|`void func(struct Type v)`|`void func(struct Type *p)`|
|**함수 내 연산자**|**점 (`.`)** 사용|**화살표 (`->`)** 사용|
|**데이터 처리**|구조체 전체를 **복사** (Stack 할당)|주소값(4/8B)만 **복사**|
|**특징**|원본 수정 불가, 오버헤드 큼|**원본 수정 가능**, 오버헤드 작음|

---

### 4. 🔍 심화 확장: 포인터 순회와 연산자 우선순위

실무에서 구조체 배열을 포인터로 다룰 때 가장 중요한 것은 **"원본 주소의 보존"**과 **"연산자 우선순위의 이해"**입니다.

#### 1) [실무 패턴] 임시 포인터를 활용한 순회 (Iterator Strategy)

구조체 포인터(`ptr`)를 직접 증감(`ptr++`)하면 **배열의 시작 주소(Base Address)를 잃어버리는 문제**가 발생합니다. 이를 방지하기 위해 반드시 **순회용 임시 포인터(Cursor)**를 복사하여 사용해야 합니다.

- **Bad Case (원본 유실):**
    ```C
    struct Point *head = list;
    // head가 이동해버리면, 리스트의 처음으로 돌아갈 방법이 없음
    while(head->x != 0) { head++; } 
    ``` 
    
- **Good Case (임시 포인터 사용):**
    
    ```C
    struct Point *head = list;      // [기준점] 절대 이동시키지 않음
    struct Point *cur = head;       // [순회용] head의 주소를 복사
    
    // cur만 이동, head는 유지됨
    while(cur->x != 0) { cur++; }   
    ```   
    

#### 2) 값의 변경 vs 주소의 이동 (복합 연산 분석)

임시 포인터 `cur`가 구조체 내부의 포인터 멤버 `name`을 가리킨다고 가정했을 때의 동작 차이입니다.

| **구분**    | **값의 변경 (Value Modification)**                                    | **주소의 이동 (Pointer Arithmetic)**                                             |
| --------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **코드**    | `(*cur->name)++`                                                  | `*(cur->name++)`                                                            |
| **동작 순서** | 1. `cur->name` (멤버 접근)<br>2. `*` (데이터 값 가져오기)<br>3. `++` (값 1 증가) | 1. `cur->name` (멤버 접근)<br>2. `++` (**주소**를 다음 칸으로 이동)<br>3. `*` (이동 전 값 반환) |
| **변화 대상** | 메모리에 저장된 **실제 데이터 값**<br>(예: 'A' $\to$ 'B')                       | 포인터 멤버가 가리키는 **위치**<br><br>(예: 0x100 $\to$ 0x101)                           |

### 🎯 요약

1. **선언 확인:** 변수형(`Type v`)이면 점(`.`), 포인터형(`Type *p`)이면 화살표(`->`)를 사용합니다.
2. **순회 전략:** 포인터로 배열을 순회할 때는 원본 포인터를 직접 움직이지 말고, **`struct Type *cur = head;`**와 같이 **복사본(임시 포인터)**을 만들어 사용하십시오.
3. **심화 연산:** `ptr->member++`는 멤버의 값을 바꾸지만, 포인터 연산이 섞이면 `()` 유무에 따라 **값 변경**인지 **주소 이동**인지가 달라지므로 주의가 필요합니다.
