## Topic. 구조체: 선언 형태에 따른 접근과 확장

구조체 문법의 핵심은 **"선언된 변수가 값(Value)인가, 주소(Address)인가?"**를 파악하는 것입니다. 이 선언 형태가 접근 연산자를 결정하며, 나아가 메모리 관리와 연산 방식까지 지배합니다.

### 1. 🚦 핵심 원칙: 선언이 연산자를 결정한다

변수가 메모리에 존재하는 **실체**인지, 그 실체를 가리키는 **참조자**인지에 따라 사용하는 연산자가 달라집니다.

| **기준**      | **Case A: 구조체 변수 (Value)**           | **Case B: 구조체 포인터 (Address)**                            |
| ----------- | ------------------------------------ | -------------------------------------------------------- |
| **선언 형태**   | **`struct Type var;`**               | **`struct Type *ptr;`**                                  |
| **변수의 성격**  | 데이터 덩어리 (실체)                         | 메모리 주소값 (참조)                                             |
| **접근 연산자**  | **점 (`.`)**                          | **화살표 (`->`)**                                           |
| **접근 메커니즘** | **Direct Access**<br>(Base + Offset) | **Indirect Access**<br>(Dereference $\to$ Base + Offset) |
| **코드 예시**   | `var.age = 20;`                      | `ptr->age = 20;`                                         |

> **Note:** `ptr->age`는 `(*ptr).age`의 문법적 설탕(Syntactic Sugar)입니다. 포인터는 원칙적으로 역참조(`*`) 후 접근(`.`)해야 하지만, 편의를 위해 `->`를 제공합니다.

---

### 2. 💾 메모리 확장: 크기와 할당의 차이

선언 형태의 차이는 메모리 할당 방식과 크기 계산에도 그대로 적용됩니다.

#### 1) 구조체 변수 (`var`) 접근 시

- **메모리 실체:** 구조체 정의에 포함된 **모든 멤버의 크기 합**(Padding 포함)만큼 연속된 메모리가 할당됩니다.
- **배열 선언 시:** `struct Type arr[10];`은 구조체 덩어리 10개를 물리적으로 연속 배치합니다.
    

#### 2) 구조체 포인터 (`ptr`) 접근 시

- **메모리 실체:** 구조체의 크기와 무관하게, **주소를 담을 공간(32bit: 4B, 64bit: 8B)**만 할당됩니다.
- **배열 선언 시:** 포인터 배열 `struct Type *arr[10];`은 주소값 10개를 저장할 공간만 할당합니다. 실제 구조체는 별도로 연결(`malloc` 등)해야 합니다.
    

---

### 3. ⚔️ 함수 확장: 복사 비용 vs 참조 효율

함수에 구조체를 전달할 때도 선언 형태(접근 연산자)에 따라 성능과 동작이 갈립니다.

|**구분**|**Call by Value (값 전달)**|**Call by Reference (주소 전달)**|
|---|---|---|
|**매개변수 선언**|`void func(struct Type v)`|`void func(struct Type *p)`|
|**함수 내 연산자**|**점 (`.`)** 사용|**화살표 (`->`)** 사용|
|**데이터 처리**|구조체 전체를 **복사** (Stack 할당)|주소값(4/8B)만 **복사**|
|**특징**|원본 수정 불가, 오버헤드 큼|**원본 수정 가능**, 오버헤드 작음|

---

### 4. 🔍 심화 확장: 포인터 연산과 우선순위

포인터(`->`)를 사용할 때 가장 혼동되는 부분은 증감 연산자(`++`, `--`)와의 결합입니다. **"무엇을 변화시키는가?"**를 기준으로 구분해야 합니다.

- 가정: `ptr`은 구조체 포인터, `val`은 멤버 변수(int/char*)

#### 1) 값의 변경 (Value Modification)

구조체 멤버가 가진 **실제 데이터**를 조작합니다.

- **코드:** `ptr->val++` 또는 `(*ptr->val)++`
- **해석:**
    
    1. `ptr->val`: 화살표가 먼저 실행되어 멤버 위치로 이동.
    2. `++`: 해당 위치의 **데이터 값(Value)**을 1 증가.
        
- **결과:** 메모리에 저장된 값이 변함 (예: 10 $\to$ 11).
    

#### 2) 주소의 이동 (Pointer Arithmetic)

포인터가 가리키는 **위치**를 조작합니다.

- **코드:** `ptr++`
    - **해석:** 구조체 포인터 자체를 다음 구조체 위치로 이동 (구조체 크기만큼 주소 증가).
- **코드:** `*(ptr->val++)` (멤버가 포인터일 경우)
    - **해석:**
        
        1. `ptr->val`: 멤버(포인터)에 접근.
        2. `++`: 멤버가 가리키던 **주소(Address)**를 다음 칸으로 이동.
        3. `*`: (후위 연산이므로) 이동 전의 값을 반환.
            
    - **결과:** 멤버 포인터가 가리키는 대상이 옆으로 이동함.
        

### 🎯 요약

1. **선언 확인:** 변수형(`Type v`)이면 점(`.`), 포인터형(`Type *p`)이면 화살표(`->`)를 씁니다.
2. **메모리:** 변수형은 구조체 전체 크기를, 포인터형은 주소 크기(고정)를 가집니다.
3. **심화 연산:** `->` 연산자는 `*`나 `++`보다 우선순위가 높습니다. 따라서 `ptr->val++`은 **"멤버의 값을 증가"**시키는 것이고, 주소를 이동시키려면 괄호나 별도의 포인터 연산이 필요합니다.
