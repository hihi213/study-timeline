## 정리
### ## 👩‍💻 힙 (Heap) 자료구조

이것은 **'알고리즘'**의 한 종류이며, **프로그래머**가 `PriorityQueue` 등의 클래스를 통해 직접 사용하는 데이터 타입입니다.

- **1. 목적 (Purpose):**
    - 데이터 집합 중 **'우선순위가 가장 높은'** 원소(최대/최소값)를 항상 O(1)로 조회하고, O(log N)의 속도로 빠르게 삽입/삭제하기 위해 고안된 '우선순위 큐'를 구현하는 데 사용됩니다.
- **2. 실제 자료구조 (Actual Data Structure):**
    - **배열 (Array)**입니다.
    - 논리적으로는 '완전 이진 트리' 구조를 따르지만, 물리적으로는 **배열 하나**로 구현됩니다.
    - **구현 로직**은 배열의 인덱스 계산(예: 부모 = `(i-1)/2`, 자식 = `2i+1`, `2i+2`)을 통해 트리 관계를 효율적으로 탐색합니다.
- **3. 행위의 주체 (Actors):**
    - **요청 주체: 프로그래머 (Programmer)**
        - **프로그래머**는 `PriorityQueue.add(data)` 또는 `PriorityQueue.poll()`을 호출하여 데이터 추가/삭제를 **요청**합니다.
    - **관리 주체: 힙 구현 로직 (Implementation Logic)** (예: `PriorityQueue` 클래스의 내부 코드)
        - `add` 요청 시: **구현 로직**은 데이터를 배열의 맨 끝에 추가한 뒤, '힙 속성'(부모-자식 간 크기 규칙)을 만족시키기 위해 부모 노드와 비교하며 위로 올립니다(Sift-up/Heapify-up).
        - `poll` 요청 시: **구현 로직**은 배열의 첫 번째 원소(루트)를 제거하고, 맨 끝 원소를 루트로 가져온 뒤, '힙 속성'을 만족시키기 위해 자식 노드와 비교하며 아래로 내립니다(Sift-down/Heapify-down).

### ## 🖥️ JVM 힙 (Heap) 메모리의 실제 자료구조

이것은 **'메모리 관리 시스템'**이며, **JVM**과 **GC(가비지 컬렉터)**가 내부적으로 사용합니다. 프로그래머가 이 자료구조를 직접 제어하지 않습니다.

JVM 힙은 **단 하나의 자료구조로 이루어져 있지 않습니다.** 대신, **가비지 컬렉터(GC)**라는 복잡한 시스템이 메모리 '할당'과 '해제'를 관리하기 위해 여러 자료구조를 조합하여 사용합니다.

- **1. 목적 (Purpose):**
    - `new` 키워드로 생성된 객체 인스턴스에 **메모리를 동적으로 할당**하고, 더 이상 사용되지 않는 객체의 **메모리를 자동으로 회수**하는 것입니다.
- **2. 실제 사용되는 주요 자료구조:**
    - **A) 자유 목록 (Free Lists)**
        - **설명:** 힙 영역 내에서 현재 '사용 가능(비어있음)'한 메모리 블록(Chunk)들의 **'연결 리스트(Linked List)'**입니다.
        - **관리 주체:** **JVM 할당자(Allocator)** 및 **GC(Sweeper)**
        - **할당 시 (by JVM Allocator):**
            - **스레드**가 `new Object()`로 메모리를 **요청**합니다.
            - **JVM 할당자**는 **Free List**를 탐색하여 요청된 크기에 맞는 블록을 찾습니다.
            - **JVM 할당자**는 찾은 블록을 리스트에서 제거하고, 필요하면 쪼갠 뒤 남은 조각을 다시 Free List에 넣고, 할당된 블록의 주소를 스레드에 반환합니다.
        - **해제 시 (by GC Sweeper):**
            - **GC**가 쓰레기(Unreachable) 객체를 식별한 후, **GC**는 이 객체가 차지하던 메모리 블록을 다시 **Free List**에 연결하여 '사용 가능' 상태로 만듭니다.
    - **B) 비트맵 (Bitmap)**
        - **설명:** 힙 메모리 전체 영역을 아주 작은 단위로 매핑하는 거대한 '비트(Bit) 배열'입니다. (예: 1비트가 8바이트를 대표)
        - **관리 주체:** **GC(Marker)**
        - **표시(Mark) 단계:** **GC**가 힙을 스캔하며 '살아있는(Reachable)' 객체를 찾을 때, 해당 객체에 대응하는 **비트맵**의 비트를 1로 설정(Marking)합니다.
        - **수거(Sweep) 단계:** **GC**가 비트맵을 0부터 쭉 스캔하며, 비트가 0인(표시되지 않은) 영역을 '쓰레기'로 식별하고 이 영역을 **Free List**에 추가합니다.
    - **C) 객체 그래프 (Object Graph)** (논리적 구조)
        - **설명:** 힙에 저장된 객체들이 서로를 '참조'하는 관계 그 자체를 **'그래프'** 자료구조로 볼 수 있습니다. (스택의 변수 등이 '루트(Root)'가 됨)
        - **관리 주체:** **GC(Marker)**
        - **표시(Mark) 단계:** **GC**는 'GC Roots'(스택 변수 등)에서 시작하여 이 **객체 그래프**를 **순회(Traverse)**합니다. (DFS/BFS와 유사) 이 순회 중에 만나는 모든 객체가 '살아있는' 객체입니다.

### 📊 핵심 요약

| **구분**     | **힙 (Heap) 자료구조**             | **JVM 힙 (Heap) 메모리**                                       |
| ---------- | ----------------------------- | ---------------------------------------------------------- |
| **정체**     | 단일 **알고리즘** / 데이터 타입          | 복합 **메모리 관리 시스템**                                          |
| **주 사용처**  | 우선순위 큐 (by **프로그래머**)         | 객체 저장소 (by **JVM / GC**)                                   |
| **실제 구조**  | **배열 (Array)** (트리처럼 동작)      | **자유 목록 (Linked List)**, **비트맵 (Array)**, **객체 그래프** 등의 조합 |
| **핵심 행위자** | **구현 로직** (Sift-up/Sift-down) | **JVM 할당자** (할당), **GC** (Mark & Sweep)                    |
| **관련성**    | **전혀 없음 (이름만 같음)**            | **전혀 없음 (이름만 같음)**                                         |
