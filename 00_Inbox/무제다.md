## Topic 5. 퀵 정렬 (Quick Sort) 상세 구현

### 1. 🏗️ 빌드업 (Code Structure)

> **"반장을 뽑고(Partition), 반장 빼고 나머지끼리 다시 모여(Recursion)!"**

- **`quick_sort` (관리자):** 피벗의 자리가 확정되면, 그 피벗을 **제외하고** 좌우로 나누어 다시 지시를 내립니다.
- **`partition` (일꾼):** 실제 **"땅따먹기(자리 확정)"**를 수행합니다. 피벗보다 큰 놈은 오른쪽으로, 작은 놈은 왼쪽으로 보내고 피벗을 가운데에 꽂아 넣습니다.
    

### 2. 코드 구현 (C Language)

**Step 1. 재귀 호출 및 제어 (`quick_sort` 함수)**

- **핵심:** `partition` 함수가 끝나면 반환값 `q`(피벗의 위치)는 **이미 정렬이 끝난 상태(Fixed)**입니다. 따라서 재귀 호출 시 `q`는 포함하지 않습니다.
    

C

```sql
// 재귀 함수 (정렬된 피벗을 제외하고, 좌우 덩어리를 다시 쪼개라)
void quick_sort(int list[], int left, int right) {
    // 데이터가 2개 이상일 때만 진행 (left < right)
    if (left < right) {
        
        // 1. 파티션 실행: 피벗(반장)의 자리를 확정 짓고 그 위치(index)를 받아옴
        // (이 시점에서 q 위치의 값은 정렬이 영구적으로 완료됨)
        int q = partition(list, left, right); 

        // 2. 왼쪽 덩어리 정렬 (피벗 q 제외: left ~ q-1)
        quick_sort(list, left, q - 1);

        // 3. 오른쪽 덩어리 정렬 (피벗 q 제외: q+1 ~ right)
        quick_sort(list, q + 1, right);
    }
}
```

**Step 2. 값 교환 및 파티션 (`swap` & `partition` 함수)**

- **역할:** 피벗(기준)보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 몰아넣습니다.
- **투 포인터 전략:**
    - `low`: 왼쪽에서 출발, **피벗보다 큰 값**을 찾으러 다님. (찾으면 멈춤)
    - `high`: 오른쪽에서 출발, **피벗보다 작은 값**을 찾으러 다님. (찾으면 멈춤)
    - 둘 다 멈추면? **교환(Swap)!**
        

C

```sql
#include <stdio.h>

// 유틸리티: 두 변수의 값을 맞바꾸는 함수
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

// 분할 함수 (피벗을 기준으로 헤쳐모여! -> 피벗의 최종 위치 반환)
int partition(int list[], int left, int right) {
    int pivot;
    int low, high;

    low = left;         // low는 왼쪽 시작점 (피벗 바로 다음부터 탐색 예정)
    high = right + 1;   // high는 오른쪽 끝 (do-while문에서 감소부터 하므로 +1에서 시작)
    pivot = list[left]; // 피벗 선정 (여기서는 맨 왼쪽 값을 기준값으로 잡음)

    // 교차하기 전까지 반복 (low와 high가 엇갈리면 종료)
    do {
        // 1. [Low의 임무] 피벗보다 '큰 값'을 찾을 때까지 오른쪽으로 전진
        // (작은 값들은 왼쪽에 잘 있으니 통과, 큰 놈 발견하면 정지!)
        do {
            low++; 
        } while (list[low] < pivot && low <= right); // 범위 체크(low <= right) 필수

        // 2. [High의 임무] 피벗보다 '작은 값'을 찾을 때까지 왼쪽으로 전진
        // (큰 값들은 오른쪽에 잘 있으니 통과, 작은 놈 발견하면 정지!)
        do {
            high--;
        } while (list[high] > pivot);

        // 3. 아직 교차하지 않았다면? (잘못 서 있는 두 놈을 발견했으니 맞바꿈)
        // low는 큰 놈 잡고 있고, high는 작은 놈 잡고 있음 -> Swap!
        if (low < high) {
            swap(&list[low], &list[high]);
        }
    } while (low < high); 

    // 4. 교차했다면? (low와 high가 엇갈림 = 분류 작업 끝)
    // 현재 high가 가리키는 곳은 '피벗보다 작은 값' 중 가장 오른쪽에 있는 놈임.
    // 따라서 피벗(list[left])과 high 위치를 바꿈 -> 피벗이 정가운데(자신의 자리)로 안착!
    swap(&list[left], &list[high]);

    return high; // 피벗이 안착한 확정된 인덱스(high)를 보고함
}
```

### 3. 🔍 파티션 로직의 핵심 Q&A (심화)

**Q1. 왜 `high`와 피벗을 바꿀까요? (`low`가 아니라)**

> `do-while` 문이 끝나고 `low`와 `high`가 교차되면(`low > high`),
>
> - **`low`**: 피벗보다 **큰 값**을 가리키고 있습니다. (오른쪽 구역의 시작)
>     
> - **`high`**: 피벗보다 **작은 값**을 가리키고 있습니다. (왼쪽 구역의 끝)
>     
> - 피벗은 **자신보다 작은 값들의 바로 뒤**에 와야 하므로, `high` 위치와 바꿔야 올바르게 정렬됩니다.
>     

**Q2. `quick_sort` 재귀 호출 범위가 왜 `q`를 뺍니까?**

> partition 함수가 끝난 후 반환된 q 인덱스에 있는 값(피벗)은 **"전체 배열에서 자신이 있어야 할 최종 위치"**에 박힌 상태입니다.
>
> 이미 정렬이 끝난 녀석을 또 건드릴 필요가 없기 때문에 q-1, q+1로 범위를 좁히는 것입니다.

### 4. 📊 중요 분석 (Analysis)

|**구분**|**합병 정렬 (Merge Sort)**|**퀵 정렬 (Quick Sort)**|
|---|---|---|
|**쪼개는 방식**|무조건 절반 (`mid`)|**피벗(Pivot)** 기준 (랜덤)|
|**정렬 시점**|다 쪼개고 **올라올 때 (Merge)**|쪼개면서 **내려갈 때 (Partition)**|
|**추가 메모리**|필수 (`sorted` 배열, $O(N)$)|**불필요** (제자리 정렬, $O(\log N)$ Stack)|
|**속도**|항상 일정함|일반적으로 가장 빠름 (Cache Hit율 높음)|
|**최악의 경우**|없음 ($N \log N$ 보장)|**이미 정렬된 경우** ($O(N^2)$)|
