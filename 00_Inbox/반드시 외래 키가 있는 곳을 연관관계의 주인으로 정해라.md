## 정리* 
주인: JPA에서 양방향 관계를 설정할때 DB에서의 fk를 어느 객체가 관리할지 결정하는 개념. 
- 주인: **FK 값을 실제로 쓰는 쪽**(INSERT/UPDATE 대상)
	- JPA/Hibernate가 FK를 가지는 주인의 변경시**DB의 FK 컬럼 값**을 INSERT/UPDATE한다.
- **비주인**: **해당 관계의 FK를 가지지 않는 객체 모델에서의 탐색 편의성을 위해 존재하는 필드.
	- 단, “조회용”이란 건 **DB 반영 관점**의 표현일 뿐, **자바 객체 필드 자체는 수정 가능**하다(다만 DB로는 안 간다).

야매이해
- 내가 관계를 생성하거나 변경을 해야할때 화살표로 비유를 들자면 끝점을 수정하는게 아니라, 시작점을 바꿔야 DB에 반영이 된다. 그러니 JPA에게 시작점을 알려주자
- @JoinColumn : “여기가 시작점(주인). 이 FK 컬럼을 써서 조인/INSERT/UPDATE 하라.”
- mappedBy : “여긴 시작점 아님(FK 없음). 진짜 주인은 저쪽 필드다.”
- (@JoinTable : “FK가 중간 ‘연결 테이블’에 있다. 그 테이블의 행을 INSERT/DELETE 하라.” — N:N 또는 특수 1:N)

```java
class Member {
  @ManyToOne
  @JoinColumn(name = "team_id")   // ← FK 컬럼과 연결(주인)
  private Team team;
}

class Team {
  @OneToMany(mappedBy = "team")   // ← FK 없음(거울)
  private List<Member> members = new ArrayList<>();
}
```
	•	@JoinColumn이 붙은 주인 필드만 FK 컬럼과 1:1로 매핑됨 → 어느 컬럼을 UPDATE할지 JPA가 정확히 앎
	•	mappedBy 쪽은 FK가 없어서 “어느 컬럼을 고칠지” 정보가 없음 → 여기만 바꿔선 SQL을 만들 수 없음

⸻

3) flush 때 JPA가 실제로 하는 일
	- JPA는 트랜잭션 끝에 스냅샷 비교(Dirty Checking) 로 “바뀐 필드”를 찾고 SQL을 생성함.
	- 주인 필드(Member.team) 가 바뀌면:
→ “team_id가 A→B로 바뀌었네” →

UPDATE member SET team_id = :B WHERE id = :memberId;

	•	역방향(Team.members)만 바꾸면:
→ FK 컬럼 정보가 없으니 어떤 UPDATE를 해야 할지 확정 못 함 → SQL 안 나감

⸻

4) 똑 떨어지는 예시

// ✅ 시작점(주인) 수정 → DB 반영
member.setTeam(usa);
// flush 시
// UPDATE member SET team_id = :usaId WHERE id = :memberId;

// ❌ 끝점(거울)만 수정 → DB 변화 없음
korea.getMembers().add(member);
// flush 시 SQL 없음 (불일치 위험)

그래서 실무에선 편의 메서드로 둘 다 맞추되, 반드시 주인 필드를 변경해:

```java
	class Team {
	  void addMember(Member m) {
	    members.add(m);   // 거울 유지
	    m.setTeam(this);  // ★ 주인 변경 → FK 반영 근거
	  }
	}
```
⸻

5) 한 줄 규칙
	- 관계 = FK 한 컬럼
	- 그 컬럼과 매핑된 필드 = 주인(@JoinColumn)
	- DB에 반영되려면 → 주인 필드를 바꿔라 (거울만 바꾸면 SQL 안 나감)

이러면 “왜 시작점을 바꿔야 DB에 반영되나?”가 딱 정리돼!

- 외래키: 다른테이블의 pk
	- 한테이블에는 외래키가 여러개일수있다. (다른테이블과 관계 많이 맺을수있다,)
- 외래키가 있는곳을 연관관계의 주인으로 정한다: 참조하는 테이블을 주인으로 정한다
- 주인으로 정한다: 주인 테이블을 `@JoinColumn`어노테이션을 붙여준다.
	- DB 필드는 하나인데 객체 필드는 두 개(관계를 바꿀수있는 곳이 두군데)이니, DB와 동기화할 필드 하나를 정하는 원칙이 바로 '연관관계의 주인'이다
	- 그리고 **오직 '주인'으로 지정된 쪽의 객체 필드가 변경될 때만 DB의 외래 키(FK) 값을 업데이트**
- 주인이 아닌 테이블은 mappedBy="주인테이블명" 속성을 붙여준다

## 💭 나의 추가적 생각/질문
   
- 둘다 자신을의 필드를 수정하라고 JPA에게 알려주는것
	- **@JoinColumn**: **한쪽 테이블에 FK 컬럼이 있을 때** 그 **FK 컬럼**을 직접 매핑.-> “내 테이블의 FK 컬럼”
	- **@JoinTable**: 두 엔티티 사이에 **중간 조인 테이블**(연결 테이블)이 있을 때 그 **연결 테이블**을 매핑. -> “**연결(조인) 테이블의 행**”
- 저쪽이 주인이야
	- mappedby
