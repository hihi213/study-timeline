## 문제 1: 부서 테이블 (`my_dept`) 생성하기

'부서' 정보를 저장하기 위한 `my_dept` 테이블을 생성하려고 합니다.

1. **테이블과 컬럼 생성:**
    
    - 테이블 이름은 `my_dept`입니다.
    - `deptno`: 부서 번호를 저장할 **숫자** 타입의 컬럼입니다.
    - `dname`: 부서 이름을 저장할 **문자열(텍스트)** 타입의 컬럼입니다.
    - `loc`: 위치를 저장할 **문자열(텍스트)** 타입의 컬럼입니다.
    - (여기까지의 기본 `CREATE TABLE` 문을 작성해 보세요.)
        
2. **`NOT NULL` 제약조건 (필수 입력):**
    
    - `dname` (부서 이름)과 `loc` (위치)는 _절대 비어 있으면 안 됩니다._ (값이 필수로 입력되어야 합니다.)
    - (1번에서 만든 쿼리에 이 '필수 입력' 제약조건을 추가해 보세요.)
        
3. **`PRIMARY KEY` (기본 키) 제약조건 (고유 식별):**
    
    - `deptno` (부서 번호)는 각 부서를 유일하게 구별하는 **대표 값(기본 키)** 이어야 합니다. (즉, 중복되거나 비어있을 수 없습니다.)
    - (2번에서 만든 쿼리에 이 '기본 키' 제약조건을 추가하여 `my_dept` 테이블 생성을 완료하세요.)

  dname  VARCHAR2(14) NOT NULL,

## 문제 2: 직원 테이블 (`my_emp`) 생성하기

'직원' 정보를 저장하기 위한 `my_emp` 테이블을 생성합니다. 이 테이블은 **`my_dept` 테이블과 관계가 있습니다.**

1. **테이블과 기본 제약조건 생성:**
    
    - 테이블 이름은 `my_emp`입니다.
    - `empno` (직원 번호): **숫자** 타입이며, 이 테이블의 **대표 값(기본 키)**입니다.
    - `ename` (직원 이름): **텍스트** 타입이며, **필수 입력(`NOT NULL`)**입니다.
    - `job` (직무): **텍스트** 타입이며, **필수 입력(`NOT NULL`)**입니다.
    - `hiredate` (입사일): **날짜** 타입이며, **필수 입력(`NOT NULL`)**입니다.
    - `sal` (급여): **소수점을 포함할 수 있는 숫자** 타입이며, **필수 입력(`NOT NULL`)**입니다.
    - `deptno` (부서 번호): 직원이 소속된 부서의 번호를 저장할 **숫자** 타입의 컬럼입니다.
    - (여기까지의 `CREATE TABLE` 문을 작성해 보세요.)
        
2. **`FOREIGN KEY` (외래 키) 제약조건 (관계 맺기):**
    
    - `my_emp` 테이블의 `deptno`는 _반드시 `my_dept` 테이블에 존재하는 부서 번호 중 하나_여야 합니다. (즉, `my_dept`를 참조해야 합니다.)
    - (1번에서 만든 쿼리에 `my_emp`의 `deptno`가 `my_dept`의 `deptno`를 참조하도록 '외래 키' 관계를 설정해 보세요.)
        
3. **참조 옵션 (연쇄 삭제):**
    
    - 만약 `my_dept` 테이블에서 어떤 부서(예: 10번 부서)가 **삭제**되면, `my_emp` 테이블에 소속되어 있던 10번 부서의 모든 직원 정보도 **함께 자동으로 삭제**되어야 합니다.
    - (2번에서 만든 '외래 키' 설정에 이 '연쇄 삭제' 옵션을 추가하여 `my_emp` 테이블 생성을 완료하세요.)

CREATE TABLE my_dept (
  deptno NUMBER(2),

  loc    VARCHAR2(13) NOT NULL,
  CONSTRAINT pk_my_dept PRIMARY KEY (deptno)

이전에 만들었던 `my_emp` 테이블에 다음과 같은 3가지 변경 사항이 발생했습니다. 테이블의 구조를 변경하는 SQL 문을 작성해 보세요.

1. **휴대폰 번호 컬럼 추가 (고유 값):**
    
    - `cell_phone`이라는 이름의 컬럼을 **추가**합니다.
    - 이 컬럼은 하이픈(-) 없는 휴대폰 번호 11자리를 저장하며, **항상 11자리의 고정된 길이**를 갖는 **문자열** 타입입니다.

3. **성별 컬럼 추가 (기본값):**

	ALTER TABLE my_emp ADD CONSTRAINT uk_my_emp_phone UNIQUE (cell_phone);
	
	ALTER TABLE my_emp MODIFY ename VARCHAR2(25);
	
	ALTER TABLE my_emp ADD gender CHAR(1) DEFAULT 'M';
	```

### **[실습 7] (PL/SQL/IF) 신규 사원 등록 프로시저**

**문제:** 부서가 존재하면 INSERT, 없으면 예외 발생하는 프로시저 p_hire 작성.

매개변수: (p_empno, p_ename, p_job, p_hiredate, p_sal, p_deptno)

**모범답안(핵심):**

```
CREATE OR REPLACE PROCEDURE p_hire(
  p_empno    IN NUMBER,
  p_ename    IN VARCHAR2,
  p_job      IN VARCHAR2,
  p_hiredate IN DATE,
  p_sal      IN NUMBER,
  p_deptno   IN NUMBER
) AS
  v_cnt NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_cnt FROM my_dept WHERE deptno = p_deptno;

  IF v_cnt = 0 THEN
    RAISE_APPLICATION_ERROR(-20001, '부서가 존재하지 않습니다.');
  ELSE
    INSERT INTO my_emp(empno, ename, job, hiredate, sal, deptno)
    VALUES(p_empno, p_ename, p_job, p_hiredate, p_sal, p_deptno);
    COMMIT; -- 시험 환경에 따라 생략 가능
  END IF;
END;
/
```

### **[실습 8] (PL/SQL/FOR) 부서별 일괄 인상 프로시저 + 분류 함수**

**문제 A:** p_raise(p_deptno IN NUMBER, p_percent IN NUMBER) – 해당 부서 직원 급여를 p_percent% 인상. FOR UPDATE와 WHERE CURRENT OF 활용.

**문제 B:** f_grade(in_value NUMBER) RETURN VARCHAR2 – 2500 초과면 'High salary' 아니면 'Low salary'.

**모범답안(핵심):**

```
-- A) 부서별 인상
CREATE OR REPLACE PROCEDURE p_raise(
  p_deptno  IN NUMBER,
  p_percent IN NUMBER
) AS
  CURSOR c_emp IS
    SELECT empno, sal FROM my_emp
    WHERE deptno = p_deptno
    FOR UPDATE;
BEGIN
  FOR r IN c_emp LOOP
    UPDATE my_emp
       SET sal = r.sal * (1 + p_percent/100)
     WHERE CURRENT OF c_emp;
  END LOOP;
  COMMIT;
END;
/

-- B) 연봉 등급 함수
CREATE OR REPLACE FUNCTION f_grade(in_value NUMBER)
RETURN VARCHAR2 AS
  v_grade VARCHAR2(20);
BEGIN
  v_grade := 'Low salary';
  IF in_value > 2500 THEN
    v_grade := 'High salary';
  END IF;
  RETURN v_grade;
END;
/

-- 사용 예시
SELECT ename, sal, f_grade(sal) AS grade
FROM my_emp;
```

> **함수 작성 주의:** 함수 시그니처의 매개변수/반환형에는 **자리수 쓰지 않음** (NUMBER, VARCHAR2만). RETURN 값과 반환형 **일치**해야 컴파일됨.

### **보안/정보보안/컴퓨터보안/DB보안**

###  **구분 서술**

**모범답안(핵심):**

- **보안(Security)**: 위험으로부터 안전한 상태 유지/보호.
- **정보보안(Information Security)**: 정보와 정보시스템을 **비인가 접근·사용·노출·변경·파기**로부터 보호. **데이터의 기밀성·무결성·가용성** 중심.
- **컴퓨터보안(Computer Security)**: 컴퓨터 시스템의 **가용성과 정확한 동작** 보장에 초점.
- **DB보안(Database Security)**: DB 내 주요 기밀정보를 **비인가 접근/변경/파괴/노출**로부터 보호(데이터 보호 초점). **접근기록·변경추적·암호화·취약점 보완** 등 포함.

### **[이론 12] (단답)** 

### **PRIMARY KEY vs UNIQUE**

###  **차이 + ON DELETE**

**모범답안(핵심):**

- **공통**: 중복 방지.
- **차이**: **PK는 NULL 불가**, **UNIQUE는 NULL 허용(여러 NULL 가능)**.
- **FK의 ON DELETE**: **CASCADE**(부모 삭제 시 자식 자동 삭제) 등. _(Oracle은 ON UPDATE 미지원)_

    UPDATE t SET col = col+1 WHERE CURRENT OF c;
  END LOOP;
  COMMIT;
END;
/
```

## **3) 20분 만에 보는** 

## **오류 방지 체크리스트**

- **세미콜론** **;** / 블록 끝 **슬래시** **/** 붙였는가?
- **함수 시그니처 타입에 자리수 미기재**(OK: VARCHAR2, NG: VARCHAR2(20)).
- **RETURN 타입 = 반환 변수 타입** 일치.
- **PK/UK/FK 제약 이름** 붙였는가(없어도 되지만 깔끔한 가점 요소).
- **FK에 ON DELETE CASCADE** 요구 시 반드시 명시(ON UPDATE 쓰지 않기).
- **DATE 리터럴**은 DATE 'YYYY-MM-DD' 형태 사용.
- **COMMIT 위치**(DDL은 자동 커밋, DML/PLSQL은 환경에 따라 명시).
- **JOIN 조건** 빠뜨리지 않기(카티전 곱 방지).
- **ALTER MODIFY/ADD** 구분 정확히.
- **NULL/NOT NULL** 요구 여부 확인.

## **5) 스스로 점수 올리는 팁 (서술형/코딩)**

- **코딩**: 문제 문장 **키워드**를 코드에 정확히 **매핑**(예: “일괄 인상” → FOR UPDATE + WHERE CURRENT OF).
- **서술형**: **정의 → 핵심 키워드 2개 → 예시 1개** 구조(3문장 내).
- **시간 분배**: 먼저 **확실한 DDL/DML**로 점수 확보 → 그다음 PL/SQL.
- **오타 방지**: 제약조건/식별자 **짧게**(pk_x, fk_x_y).
